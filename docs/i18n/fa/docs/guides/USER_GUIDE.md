## 🎯 موارد استفاده

### مورد ۱: «اشتراک Claude Pro دارم»

**مشکل:** سهمیه بدون استفاده منقضی میشود و هنگام کدنویسی سنگین با محدودیت نرخ مواجه میشوم

```
ترکیب: "maximize-claude"
  1. cc/claude-opus-4-7        (استفاده کامل از اشتراک)
  2. glm/glm-4.7               (پشتیبان ارزان هنگام اتمام سهمیه)
  3. if/qwen3.8-max-preview       (گزینه جایگزین رایگان برای مواقع اضطراری)

هزینه ماهانه: $20 (اشتراک) + حدود $5 (پشتیبان) = در مجموع $25
در مقایسه با $20 + برخورد با محدودیتها = کلافگی
```

### مورد ۲: «هزینه صفر میخواهم»

**مشکل:** توان پرداخت هزینه اشتراکها را ندارم و به هوش مصنوعی قابلاعتماد برای کدنویسی نیاز دارم

```
ترکیب: "zero-cost"
  1. if/kimi-k2.7-code          (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)
  2. kr/qwen3-coder-next        (گزینه جایگزین رایگان Kiro)

هزینه ماهانه: $0
کیفیت: مدل، محدودیتها، حریم خصوصی و SLA را برای حجم کاری خود بررسی کنید
```

### مورد ۳: «به کدنویسی شبانهروزی و بدون وقفه نیاز دارم»

**مشکل:** مهلتهای تحویل دارم و نمیتوانم قطعی سرویس را تحمل کنم

```
ترکیب: "always-on"
  1. cc/claude-opus-4-7        (بهترین کیفیت)
  2. cx/gpt-5.5                (اشتراک دوم)
  3. glm/glm-4.7               (ارزان، بازنشانی روزانه)
  4. minimax/MiniMax-M2.1      (ارزانترین، بازنشانی ۵ ساعته)
  5. if/deepseek-v4-flash       (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)

نتیجه: ۵ لایه جایگزین، تابآوری را افزایش میدهند؛ در دسترس بودن سرویسهای بالادستی تضمینشده نیست
هزینه ماهانه: $20-200 (اشتراکها) + $10-20 (پشتیبان)
```

### مورد ۴: «در OpenClaw هوش مصنوعی رایگان میخواهم»

**مشکل:** به یک دستیار هوش مصنوعی در برنامههای پیامرسان نیاز دارم که کاملاً رایگان باشد

```
ترکیب: "openclaw-free"
  1. if/qwen3.8-max-preview     (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)
  2. if/deepseek-v4-flash       (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)
  3. if/kimi-k2.7-code          (دسترسی رایگان فهرستشده؛ ممکن است محدودیت نرخ اعمال شود)

هزینه ماهانه: $0
دسترسی از طریق: WhatsApp، Telegram، Slack، Discord، iMessage، Signal...
```

## 📖 راهاندازی ارائهدهنده

برای افزودن گروهی اتصالهای کلید API از یک فایل CSV یا JSON، از مسیر **داشبورد → ارائهدهندگان → وارد کردن از فایل** استفاده کنید. ترتیب ستونها ثابت است (`provider,name,apiKey,baseUrl,priority`)؛ مقدار `provider` باید از قبل بهعنوان یک ارائهدهنده مدیریتشده یا یک گره سازگار وجود داشته باشد. به [وارد کردن ارائهدهندگان از یک فایل CSV یا JSON](../providers/CSV-IMPORT.md) مراجعه کنید.

### 🔐 ارائهدهندگان اشتراکی

#### Claude Code (Pro/Max)

```bash
داشبورد → ارائهدهندگان → اتصال Claude Code
→ ورود با OAuth → نوسازی خودکار توکن
→ پایش سهمیه ۵ ساعته و هفتگی

مدلها:
  cc/claude-opus-4-7
  cc/claude-sonnet-4-6
  cc/claude-haiku-4-5-20251001
```

**نکته حرفهای:** برای وظایف پیچیده از Opus و برای سرعت از Sonnet استفاده کنید. OmniRoute سهمیه را بهازای هر مدل پایش میکند!

مسیرهای سازگار با Claude و Claude Code، سطح تلاش تفکر `max` را برای مدلهای Opus و Sonnet حفظ میکنند. مدلهای Haiku سطح تلاش `max` را نمیپذیرند؛ بنابراین OmniRoute پیش از ارسال درخواست به سرویس بالادستی، آن را به بودجه تفکر بالا تنزل میدهد.

#### OpenAI Codex (Plus/Pro)

```bash
داشبورد → ارائهدهندگان → اتصال Codex
→ ورود با OAuth (درگاه 1455)
→ بازنشانی ۵ ساعته و هفتگی

مدلها:
  cx/gpt-5.5
  cx/gpt-5.4
  cx/gpt-5.3-codex
  cx/gpt-5.3-codex-spark
```

#### GitHub Copilot

```bash
داشبورد → ارائهدهندگان → اتصال GitHub
→ OAuth از طریق GitHub
→ بازنشانی ماهانه (روز اول ماه)

مدلها:
  gh/gpt-5.5
  gh/gpt-5.4
  gh/claude-sonnet-4.6
  gh/claude-opus-4.7
  gh/gemini-3.1-pro-preview
```

### 💰 ارائهدهندگان ارزان

#### GLM-4.7 (بازنشانی روزانه، $0.6/1M)

1. ثبتنام کنید: [Zhipu AI](https://open.bigmodel.cn)
2. کلید API را از Coding Plan دریافت کنید
3. داشبورد → افزودن کلید API: ارائهدهنده: `glm`، کلید API: `your-key`

**استفاده:** `glm/glm-4.7` — **نکته حرفهای:** Coding Plan با یکهفتم هزینه، ۳ برابر سهمیه ارائه میدهد! بازنشانی روزانه ساعت ۱۰:۰۰ صبح انجام میشود.

#### MiniMax M2.1 (بازنشانی ۵ ساعته، $0.20/1M)

1. ثبتنام کنید: [MiniMax](https://www.minimax.io)
2. کلید API را دریافت کنید → داشبورد → افزودن کلید API

**استفاده:** `minimax/MiniMax-M2.1` — **نکته حرفهای:** ارزانترین گزینه برای زمینههای طولانی (۱ میلیون توکن)!

#### Kimi K2 (هزینه ثابت $9/ماه)

1. اشتراک تهیه کنید: [Moonshot AI](https://platform.kimi.ai?aff=omniroute)
2. کلید API را دریافت کنید → داشبورد → افزودن کلید API

**استفاده:** `kimi/kimi-k2.5` — **نکته حرفهای:** هزینه ثابت $9/ماه برای ۱۰ میلیون توکن، یعنی هزینه مؤثر $0.90/1M!

## 🚀 استقرار

### نصب سراسری npm (توصیهشده)

```bash
npm install -g omniroute

# ایجاد پوشهٔ پیکربندی
mkdir -p ~/.omniroute

# ایجاد فایل .env (به .env.example مراجعه کنید)
cp .env.example ~/.omniroute/.env

# راهاندازی سرور
omniroute
# یا با درگاه سفارشی:
omniroute --port 3000
```

CLI بهطور خودکار `.env` را از `~/.omniroute/.env` یا `./.env` بارگذاری میکند.

### حالت سینی سیستم

OmniRoute را در سینی سیستم اجرا کنید:

```bash
omniroute serve --tray
```

پس از آمادهشدن سرور و سینی سیستم، فرمان خاتمه مییابد.

سرور بدون ترمینال به کار خود ادامه میدهد.

حالت سینی سیستم از macOS، Windows و نشستهای گرافیکی Linux پشتیبانی میکند. حالت سینی سیستم داشبورد را بهطور خودکار باز نمیکند.

برای انجام اقدامات زیر از منوی سینی سیستم استفاده کنید:

- بازکردن داشبورد.
- بازکردن `/dashboard/logs`.
- تغییر راهاندازی خودکار.
- توقف OmniRoute.

از `--tray` همراه با گزینههای زیر استفاده نکنید:

- `--daemon`
- `--log`
- `--no-recovery`

این حالتها به مالکیت فرایند متفاوتی نیاز دارند.

راهاندازی در ورود بعدی به سیستم را فعال کنید:

```bash
omniroute autostart enable
```

راهاندازی خودکار در macOS، Windows و نشستهای گرافیکی Linux از حالت سینی سیستم استفاده میکند. Linux بدون رابط گرافیکی از سرویس کاربری systemd موجود استفاده میکند.

راهاندازی در هنگام ورود را غیرفعال کنید:

```bash
omniroute autostart disable
```

### حذف نصب

هنگامی که دیگر به OmniRoute نیاز ندارید، دو اسکریپت سریع برای حذف کامل ارائه میکنیم:

| فرمان                    | عملکرد                                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | برنامهٔ سیستم را حذف میکند، اما **پایگاه داده و پیکربندیهای شما** را در `~/.omniroute` نگه میدارد. |
| `npm run uninstall:full` | برنامه را حذف میکند و همچنین **تمام پیکربندیها، کلیدها و پایگاههای داده را برای همیشه پاک میکند**. |

> نکته: برای اجرای این فرمانها، به پوشهٔ پروژهٔ OmniRoute بروید (اگر آن را کلون کردهاید) و فرمانها را اجرا کنید. در غیر این صورت، اگر بهصورت سراسری نصب شده است، میتوانید بهسادگی `npm uninstall -g omniroute` را اجرا کنید.

| متغیر                                   | مقدار پیشفرض                         | توضیحات                                                                                                                                  |
| --------------------------------------- | ------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`                            | `omniroute-default-secret-change-me` | کلید محرمانه امضای JWT (**در محیط عملیاتی تغییر دهید**)                                                                                  |
| `INITIAL_PASSWORD`                      | `CHANGEME`                           | رمز عبور اولین ورود                                                                                                                      |
| `DATA_DIR`                              | `~/.omniroute`                       | دایرکتوری دادهها (پایگاه داده، میزان استفاده، گزارشها)                                                                                   |
| `PORT`                                  | پیشفرض چارچوب                        | درگاه سرویس (`20128` در مثالها)                                                                                                          |
| `HOSTNAME`                              | پیشفرض چارچوب                        | میزبان اتصال (مقدار پیشفرض Docker برابر با `0.0.0.0` است)                                                                                |
| `NODE_ENV`                              | پیشفرض زمان اجرا                     | برای استقرار روی `production` تنظیم کنید                                                                                                 |
| `NEXT_PUBLIC_BASE_URL`                  | `http://localhost:20128`             | URL پایه عمومی که در داشبورد نمایش داده شده و در اختیار سرور قرار میگیرد (جایگزین `BASE_URL` قدیمی)                                      |
| `NEXT_PUBLIC_CLOUD_URL`                 | `https://omniroute.dev`              | URL پایه نقطه پایانی همگامسازی ابری (جایگزین `CLOUD_URL` قدیمی)                                                                          |
| `API_KEY_SECRET`                        | `endpoint-proxy-api-key-secret`      | کلید محرمانه HMAC برای کلیدهای API تولیدشده                                                                                              |
| `REQUIRE_API_KEY`                       | `false`                              | الزام کلید API از نوع Bearer برای `/v1/*`                                                                                                |
| `ALLOW_API_KEY_REVEAL`                  | `false`                              | اجازه به کاربران احراز هویتشده داشبورد برای نمایش مقادیر کامل کلیدهای API ذخیرهشده در صورت درخواست                                       |
| `PROVIDER_LIMITS_SYNC_INTERVAL_MINUTES` | `70`                                 | تناوب بهروزرسانی سمت سرور برای دادههای ذخیرهشده محدودیتهای ارائهدهنده؛ دکمههای تازهسازی رابط کاربری همچنان همگامسازی دستی را آغاز میکنند |
| `DISABLE_SQLITE_AUTO_BACKUP`            | `false`                              | غیرفعالسازی اسنپشاتهای خودکار SQLite پیش از نوشتن/درونریزی/بازیابی؛ پشتیبانگیری دستی همچنان کار میکند                                    |
| `APP_LOG_TO_FILE`                       | `true`                               | خروجی گزارشهای برنامه و ممیزی روی دیسک را فعال میکند                                                                                     |
| `AUTH_COOKIE_SECURE`                    | `false`                              | اجبار ویژگی `Secure` برای کوکی احراز هویت (پشت پراکسی معکوس HTTPS)                                                                       |
| `CLOUDFLARED_BIN`                       | تنظیمنشده                            | استفاده از باینری موجود `cloudflared` بهجای دانلود مدیریتشده                                                                             |
| `CLOUDFLARED_PROTOCOL`                  | `http2`                              | روش انتقال برای Quick Tunnels مدیریتشده (`http2`، `quic` یا `auto`)                                                                      |
| `OMNIROUTE_MEMORY_MB`                   | `512`                                | محدودیت حافظه heap در Node.js بر حسب MB                                                                                                  |
| `PROMPT_CACHE_MAX_SIZE`                 | `50`                                 | حداکثر تعداد ورودیهای کش پرامپت                                                                                                          |
| `SEMANTIC_CACHE_MAX_SIZE`               | `100`                                | حداکثر تعداد ورودیهای کش معنایی                                                                                                          |

## 🧩 قابلیتهای پیشرفته

### مدلهای سفارشی

بدون نیاز به منتظر ماندن برای بهروزرسانی برنامه، هر شناسهٔ مدلی را به هر ارائهدهندهای اضافه کنید:

```bash
# از طریق API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# فهرست: curl http://localhost:20128/api/provider-models?provider=openai
# حذف: curl -X DELETE "http://localhost:20128/api/provider-models?provider=openai&model=gpt-5.2"
```

یا از داشبورد استفاده کنید: **ارائهدهندگان → [ارائهدهنده] → مدلهای سفارشی**.

نکات:

- ارائهدهندگان OpenRouter و سازگار با OpenAI/Anthropic فقط از طریق **مدلهای موجود** مدیریت میشوند. افزودن دستی، وارد کردن و همگامسازی خودکار همگی به همان فهرست مدلهای موجود وارد میشوند؛ بنابراین برای این ارائهدهندگان بخش جداگانهای با عنوان مدلهای سفارشی وجود ندارد.
- بخش **مدلهای سفارشی** برای ارائهدهندگانی در نظر گرفته شده است که امکان وارد کردن مدیریتشدهٔ مدلهای موجود را ارائه نمیکنند.

### ارائهدهندگان سفارشی سازگار با OpenAI

هر درگاهی که با API مربوط به OpenAI کار میکند (یک پراکسی خودمیزبان، vLLM یا یک تجمیعکنندهٔ شخص ثالث)
میتواند بهعنوان گره ارائهدهندهٔ مستقل خود اضافه شود:

1. **ارائهدهندگان → افزودن ارائهدهندهٔ سازگار با OpenAI**.
2. **نام**: برچسب نمایشی گره.
3. **پیشوند**: نام مسیریابی. کلاینتها مدلها را بهصورت `<prefix>/<model>` فراخوانی میکنند؛ بنابراین گرهی با
   پیشوند `mygw`، مدل `mygw/gpt-4o-mini` را ارائه میدهد. این مورد الزامی است و هیچ محدودیت نویسهای ندارد.
4. **نوع API**: خانوادهٔ نقاط پایانی که درگاه ارائه میدهد (تکمیلهای چت، پاسخها،
   تعبیهسازیها، صوت و تصاویر).
5. **نشانی پایه**: ریشهٔ API تا و با احتساب `/v1` (برای مثال
   `https://gateway.example.com/v1`)، نه مسیر کامل `/chat/completions`. برای درگاههایی با
   مسیرهای غیراستاندارد، آنها را در **تنظیمات پیشرفته** مشخص کنید (مسیر چت، مسیر مدلها).
6. فیلد **کلید API (برای بررسی)** فقط اتصال را آزمایش میکند. پس از ایجاد گره،
   آن را باز کنید و برای ذخیرهٔ کلیدی که درخواستها از آن استفاده خواهند کرد، از **افزودن اتصال** استفاده کنید.

گره یک شناسهٔ داخلی با قالب `openai-compatible-<apiType>-<uuid>` دریافت میکند؛ هرگز
لازم نیست آن را تایپ کنید، زیرا پیشوند همان نام عمومی است.

#### پیشوندهای رزروشده

یک پیشوند نمیتواند شناسه یا نام مستعار یک ارائهدهندهٔ داخلی (برای مثال `openai` یا `cf`) و همچنین
شناسهٔ یک ارائهدهندهٔ بازنشسته باشد. تفکیککنندهٔ مدل پیش از گرههای سفارشی،
شناسهها و نامهای مستعار داخلی را بررسی میکند؛ بنابراین گرهی که یکی از این پیشوندها را داشته باشد هرگز ترافیکی دریافت نمیکند:
`<prefix>/model` در عوض به ارائهدهندهٔ داخلی میرود، یا اگر آن ارائهدهنده
بازنشسته شده باشد، بهصورت بسته شکست میخورد. ایجاد یا ویرایش گره با چنین پیشوندی با پیام زیر رد میشود:

```text
prefix: "<prefix>" یک پیشوند رزروشدهٔ ارائهدهنده است — پیشوند دیگری انتخاب کنید (شناسهها/نامهای مستعار رزروشده را نمیتوان برای گرههای سفارشی استفاده کرد، زیرا درخواستهایی مانند <prefix>/model به یک ارائهدهندهٔ داخلی هدایت میشوند یا در صورت بازنشسته بودن آن، بهصورت بسته شکست میخورند)
```

یک پیشوند متمایز انتخاب کنید (`mygw`، `acme-proxy`). اگر درخواستهای ارسالی به یک گره سفارشی با
خطایی مواجه میشوند که نام یک ارائهدهندهٔ داخلی یا اطلاعات احراز هویت آن را ذکر میکند، بررسی کنید که آیا پیشوند گره
رزروشده است یا خیر: گرههایی که پیش از ایجاد این قانون ذخیره شدهاند همچنان باقی میمانند، اما پیشوندشان به
ارائهدهندهٔ داخلی هدایت میشود. گره را ویرایش کنید و یک پیشوند جدید به آن بدهید.

### زنجیرهسازی همتایان OmniRoute

یک درگاه OmniRoute دیگر را میتوان بهعنوان ارائهدهندهٔ **سفارشی سازگار با OpenAI** اضافه کرد. از
نشانی پایهٔ `/v1` همتا و یک کلید API اختصاصی با حداقل سطح دسترسی که همان همتا صادر کرده است استفاده کنید.

برای زنجیرههای متقابل یا چندمرحلهای، محافظ حلقهٔ اختیاری را در هر درگاه فعال کنید:

```bash
# gateway-a
OMNIROUTE_INSTANCE_ID=gateway-a
OMNIROUTE_PEER_URLS=http://gateway-b:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

```bash
# gateway-b
OMNIROUTE_INSTANCE_ID=gateway-b
OMNIROUTE_PEER_URLS=http://gateway-a:20128/v1
OMNIROUTE_PEER_MAX_HOPS=4
```

فقط درخواستهایی که به نشانی یک همتای صراحتاً قرارگرفته در فهرست مجاز ارسال شوند،
هدر `X-OmniRoute-Peer-Trace` را دریافت میکنند. درگاه، شناسهٔ نمونهٔ تکراری یا بودجهٔ گام
تمامشده را با HTTP `508 Loop Detected` رد میکند؛ ارائهدهندگان بالادستی معمولی هیچ فرادادهای دربارهٔ همتا دریافت نمیکنند.

زنجیرهسازی همتا، تکثیر پایگاه داده یا جایگزینی میزبان هنگام خرابی نیست. هر درگاه
وضعیت SQLite، کشها، شمارندههای نرخ و نشستهای مستقلی دارد. برای دسترسپذیری فعال/غیرفعال یا فعال/فعال،
از یک پراکسی معکوس مجهز به بررسی سلامت یا سازوکار جایگزینی کلاینت استفاده کنید و هرگز یک پایگاه دادهٔ SQLite را
در چند نمونهٔ در حال اجرای OmniRoute مونت نکنید.

### تونل سریع Cloudflare

- برای Docker و سایر استقرارهای میزبانیشده توسط خودتان، در **داشبورد ← نقاط پایانی** در دسترس است
- یک URL موقت `https://*.trycloudflare.com` ایجاد میکند که درخواستها را به نقطه پایانی فعلی سازگار با OpenAI شما در `/v1` هدایت میکند
- در نخستین فعالسازی، `cloudflared` فقط در صورت نیاز نصب میشود؛ راهاندازیهای مجدد بعدی از همان فایل اجرایی مدیریتشده استفاده میکنند
- Quick Tunnelها پس از راهاندازی مجدد OmniRoute یا کانتینر بهطور خودکار بازیابی نمیشوند؛ در صورت نیاز، آنها را دوباره از داشبورد فعال کنید
- URLهای تونل موقتی هستند و هر بار که تونل را متوقف/راهاندازی میکنید تغییر میکنند
- Quick Tunnelهای مدیریتشده بهطور پیشفرض از انتقال HTTP/2 استفاده میکنند تا در کانتینرهای دارای محدودیت، از هشدارهای مزاحم مربوط به بافر UDP در QUIC جلوگیری شود
- اگر میخواهید انتخاب انتقال مدیریتشده را بازنویسی کنید، `CLOUDFLARED_PROTOCOL=quic` یا `auto` را تنظیم کنید
- اگر ترجیح میدهید بهجای دانلود مدیریتشده از فایل اجرایی ازپیشنصبشده `cloudflared` استفاده کنید، `CLOUDFLARED_BIN` را تنظیم کنید
- پنلهای Cloudflare Quick Tunnel، Tailscale Funnel و ngrok Tunnel را میتوان در **تنظیمات ← ظاهر** نمایش داد یا پنهان کرد. پنهانکردن یک پنل، تونل در حال اجرا را متوقف نمیکند.

### هوشمندی درگاه LLM (فاز 9)

- **کش معنایی** — پاسخهای غیرجریانی با temperature=0 را بهطور خودکار کش میکند (برای عبور از کش از `X-OmniRoute-No-Cache: true` استفاده کنید)
- **همتوانی درخواست** — درخواستها را در بازه 5s از طریق سرآیند `Idempotency-Key` یا `X-Request-Id` تکرارزدایی میکند
- **ردیابی پیشرفت** — رویدادهای اختیاری SSE از نوع `event: progress` را از طریق سرآیند `X-OmniRoute-Progress: true` ارائه میدهد

### محیط آزمایشی مترجم

از طریق **داشبورد ← مترجم** به آن دسترسی پیدا کنید. نحوه ترجمه درخواستهای API میان ارائهدهندگان توسط OmniRoute را اشکالزدایی و بصریسازی کنید.

| حالت               | هدف                                                                                     |
| ------------------ | --------------------------------------------------------------------------------------- |
| **محیط آزمایشی**   | قالبهای مبدأ/مقصد را انتخاب کنید، یک درخواست بچسبانید و خروجی ترجمهشده را فوراً ببینید  |
| **آزمایشگر گفتگو** | پیامهای گفتگوی زنده را از طریق پروکسی ارسال کنید و چرخه کامل درخواست/پاسخ را بررسی کنید |
| **میز آزمون**      | آزمونهای دستهای را روی چندین ترکیب قالب اجرا کنید تا درستی ترجمه را تأیید کنید          |
| **پایشگر زنده**    | هنگام عبور درخواستها از پروکسی، ترجمههای بلادرنگ را مشاهده کنید                         |

**موارد استفاده:**

- اشکالزدایی علت شکست یک ترکیب مشخص کلاینت/ارائهدهنده
- بررسی ترجمه صحیح برچسبهای تفکر، فراخوانی ابزارها و پرامپتهای سیستم
- مقایسه تفاوت قالبها میان OpenAI، Claude، Gemini و قالبهای Responses API

### راهبردهای مسیریابی

از طریق **داشبورد ← تنظیمات ← مسیریابی** پیکربندی کنید. داشبورد شش راهبرد پرکاربرد را نمایش میدهد؛ ترکیبها و مسیریاب خودکار در داخل از مجموعه گستردهتری پشتیبانی میکنند.

**راهبردهای قابلمشاهده در داشبورد (مسیریابی در سطح حساب):**

| راهبرد                      | توضیحات                                                                                                          |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| **پرکردن حساب اول**         | از حسابها بر اساس ترتیب اولویت استفاده میکند — حساب اصلی تا زمانی که در دسترس باشد همه درخواستها را مدیریت میکند |
| **نوبتگردشی**               | با یک محدودیت چسبندگی قابلپیکربندی میان همه حسابها میچرخد (پیشفرض: 3 فراخوانی برای هر حساب)                      |
| **P2C (قدرت دو انتخاب)**    | 2 حساب تصادفی را انتخاب کرده و درخواست را به حساب سالمتر هدایت میکند — بار را با درنظرگرفتن سلامت متعادل میکند   |
| **تصادفی**                  | با استفاده از درهمسازی Fisher-Yates، برای هر درخواست یک حساب را بهصورت تصادفی انتخاب میکند                       |
| **کماستفادهترین**           | درخواست را به حسابی با قدیمیترین مُهر زمانی `lastUsedAt` هدایت میکند و ترافیک را بهطور یکنواخت توزیع میکند       |
| **بهینهسازیشده برای هزینه** | درخواست را به حسابی با کمترین مقدار اولویت هدایت میکند و ارائهدهندگان را بر اساس کمترین هزینه بهینه میکند        |

**راهبردهای پیشرفته ترکیبی و خودکار** (قابلپیکربندی برای هر ترکیب یا از طریق پیشوندهای `auto/*` — به [AUTO-COMBO.md](../routing/AUTO-COMBO.md) مراجعه کنید):

- `priority` — ترتیب سختگیرانه، بدون نوبتگردشی
- `weighted` — تقسیم متناسب ترافیک بر اساس وزنهای هر مدل
- `fill-first` — استفاده از مدل اول تا رسیدن به محدودیتها
- `round-robin` / `strict-random` / `random`
- `p2c` (قدرت دو انتخاب)
- `least-used` و `cost-optimized`
- `auto` — مبتنی بر امتیاز در میان همه گزینهها
- `lkgp` (آخرین ارائهدهنده سالم شناختهشده) — درخواستها را به آخرین ارائهدهنده موفق متصل میکند و سپس به قوانین جایگزین رجوع میکند
- `context-optimized` — مدلی را با بزرگترین پنجره زمینه آزاد انتخاب میکند
- `context-relay` — مدلهای دارای زمینه طولانی را برای نوبتهای پیگیری بهصورت زنجیرهای به هم متصل میکند

#### سرآیند خارجی نشست چسبنده

برای وابستگی خارجی نشست (برای مثال، عاملهای Claude Code/Codex پشت پروکسیهای معکوس)، این سرآیند را ارسال کنید:

```http
X-Session-Id: your-session-key
```

OmniRoute همچنین `x_session_id` را میپذیرد و کلید مؤثر نشست را در `X-OmniRoute-Session-Id` بازمیگرداند.

اگر از Nginx استفاده میکنید و سرآیندهای دارای نویسه زیرخط ارسال میکنید، این گزینه را فعال کنید:

```nginx
underscores_in_headers on;
```

#### نامهای مستعار مدل با نویسه عام

برای بازنگاشت نام مدلها، الگوهای دارای نویسه عام ایجاد کنید:

```
الگو: claude-sonnet-*     →  مقصد: cc/claude-sonnet-4-6
الگو: gpt-*               →  مقصد: gh/gpt-5.3-codex
```

نویسههای عام از `*` (هر تعداد نویسه) و `?` (یک نویسه) پشتیبانی میکنند.

#### زنجیرههای جایگزین

زنجیرههای جایگزین سراسری را تعریف کنید که روی همه درخواستها اعمال میشوند:

```
زنجیره: production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### تابآوری و قطعکنندههای مدار

از طریق **داشبورد ← تنظیمات ← تابآوری** پیکربندی کنید.

OmniRoute تابآوری در سطح ارائهدهنده را با پنج مؤلفه پیادهسازی میکند:

1. **صف درخواست و تنظیم آهنگ** — شکلدهی درخواستها در سطح سیستم:
   - **درخواست در دقیقه (RPM)** — حداکثر تعداد درخواست در دقیقه برای هر حساب
   - **حداقل زمان بین درخواستها** — حداقل فاصله زمانی بر حسب میلیثانیه میان درخواستها
   - **حداکثر درخواستهای همزمان** — حداکثر تعداد درخواستهای همزمان برای هر حساب
2. **وقفهٔ اتصال** — پیکربندی بر اساس نوع احراز هویت برای هر اتصال پس از خطاهای قابل تلاش مجدد:
   - **وقفهٔ پایه** — بازهٔ پیشفرض وقفه برای خطاهای قابل تلاش مجدد در سرویس بالادستی
   - **استفاده از راهنمای تلاش مجدد سرویس بالادستی** — در صورت ارائه، از `Retry-After` معتبر یا راهنمای بازنشانی پیروی میکند
   - **حداکثر مراحل عقبنشینی** — حداکثر سطح عقبنشینی نمایی برای خطاهای تکراری

3. **قطعکنندهٔ مدار ارائهدهنده** — خطاهای سرتاسری ارائهدهنده را ردیابی میکند، در آستانهٔ هشدار پیکربندیشده ارائهدهنده را در وضعیت افت عملکرد قرار میدهد و با رسیدن به آستانهٔ خطای پیکربندیشده، مدار را باز میکند:
   - **آستانهٔ افت عملکرد** — تعداد خطاهای متوالی ارائهدهنده پیش از ورود به وضعیت `DEGRADED`
   - **آستانهٔ خطا** — تعداد خطاهای متوالی ارائهدهنده پیش از ورود به وضعیت `OPEN`
   - **مهلت بازنشانی** — بازهٔ زمانی پیش از آزمایش مجدد ارائهدهنده
   - **CLOSED** (سالم) — درخواستها بهطور عادی جریان مییابند
   - **DEGRADED** — در حین ردیابی افزایش خطاها، درخواستها همچنان جریان مییابند
   - **OPEN** — ارائهدهنده پس از خطاهای تکراری بهطور موقت مسدود میشود
   - **HALF_OPEN** — بررسی میشود که آیا ارائهدهنده بازیابی شده است یا خیر

   محدودیتهای نرخ `429` مختص اتصال در **وقفهٔ اتصال** باقی میمانند و در قطعکنندهٔ مدار ارائهدهنده محاسبه نمیشوند.

   وضعیت زمان اجرای قطعکنندهٔ مدار ارائهدهنده فقط در **داشبورد ← سلامت** نمایش داده میشود.

4. **انتظار برای پایان وقفه** — اگر همهٔ اتصالهای کاندید از قبل در وضعیت وقفه باشند، OmniRoute میتواند تا پایان نزدیکترین وقفه منتظر بماند و همان درخواست کلاینت را بهطور خودکار دوباره امتحان کند.

5. **تشخیص خودکار محدودیت نرخ** — هنگامی که ارائهدهندگان بالادستی بازههای انتظار مشخصی را برمیگردانند، در صورت فعال بودن این تنظیم، آن راهنماها جایگزین وقفهٔ محلی اتصال میشوند.

**نکتهٔ حرفهای:** برای بررسی و بازنشانی قطعکنندههای مدار فعال ارائهدهندگان پس از یک قطعی، از صفحهٔ **سلامت** استفاده کنید. صفحهٔ تابآوری فقط پیکربندی را تغییر میدهد.

### برونبری / درونریزی پایگاه داده

نسخههای پشتیبان پایگاه داده را در **داشبورد ← تنظیمات ← سیستم و فضای ذخیرهسازی** مدیریت کنید.

| عملیات                    | توضیحات                                                                                                                                                                          |
| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **برونبری پایگاه داده**   | پایگاه دادهٔ SQLite فعلی را بهصورت یک فایل `.sqlite` دانلود میکند                                                                                                                |
| **برونبری همه (.tar.gz)** | یک بایگانی پشتیبان کامل شامل پایگاه داده، تنظیمات، ترکیبها، اتصالهای ارائهدهنده (بدون اطلاعات احراز هویت) و فرادادهٔ کلیدهای API را دانلود میکند                                 |
| **درونریزی پایگاه داده**  | یک فایل `.sqlite` را برای جایگزینی پایگاه دادهٔ فعلی بارگذاری میکند. مگر اینکه `DISABLE_SQLITE_AUTO_BACKUP=true` باشد، پیش از درونریزی یک نسخهٔ پشتیبان بهطور خودکار ایجاد میشود |

```bash
# API: برونبری پایگاه داده
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API: برونبری همه (بایگانی کامل)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API: درونریزی پایگاه داده
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**اعتبارسنجی درونریزی:** فایل درونریزیشده از نظر یکپارچگی (بررسی pragma در SQLite)، جدولهای الزامی (`provider_connections`، `provider_nodes`، `combos`، `api_keys`) و اندازه (حداکثر 100MB) اعتبارسنجی میشود.

**موارد استفاده:**

- انتقال OmniRoute بین دستگاهها
- ایجاد نسخههای پشتیبان خارجی برای بازیابی پس از فاجعه
- اشتراکگذاری پیکربندیها میان اعضای تیم (برونبری همه ← اشتراکگذاری بایگانی)

### داشبورد تنظیمات

صفحهٔ تنظیمات برای پیمایش آسان در **7 زبانه** سازماندهی شده است:

| زبانه          | محتوا                                                                                                                                                                         |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **عمومی**      | ابزارهای ذخیرهسازی سیستم، رفتار پیشفرض، قابلیت مشاهدهٔ تونل نقطهٔ پایانی                                                                                                      |
| **ظاهر**       | کنترلهای پوسته (روشن/تیره/سیستم)، نمایش نوار کناری، کلیدهای تغییر وضعیت پنل برای کارتهای تونل Cloudflare/Tailscale/ngrok                                                      |
| **هوش مصنوعی** | بودجهٔ تفکر (عبور بدون تغییر / حذف خودکار / سفارشی / تطبیقی — به [THINKING_BUDGET.md](./THINKING_BUDGET.md) مراجعه کنید)، پرامپت سراسری سیستم، آمار کش پرامپت                 |
| **امنیت**      | تنظیمات ورود/گذرواژه، کنترل دسترسی IP، احراز هویت API برای `/models`، مسدودسازی ارائهدهنده، محافظ تزریق پرامپت                                                                |
| **مسیریابی**   | راهبرد مسیریابی سراسری (پر کردن اول / نوبتگردشی / P2C / تصادفی / کمترین استفاده / بهینهشده از نظر هزینه)، نامهای مستعار مدل با نویسهٔ عام، زنجیرههای جایگزین، پیشفرضهای ترکیب |
| **تابآوری**    | صف درخواست، وقفهٔ اتصال، پیکربندی قطعکنندهٔ مدار ارائهدهنده و رفتار انتظار برای پایان وقفه                                                                                    |
| **پیشرفته**    | پیکربندی پراکسی سراسری (HTTP/SOCKS5)، بازنویسیهای پراکسی برای هر ارائهدهنده                                                                                                   |

بخش عمومی دیگر یادداشتهای فقطخواندنی مربوط به گزارشگیری و کش را تکرار نمیکند. تنظیمات نگهداری و
بهینهسازی پایگاه داده از طریق `/api/settings/database` ذخیره میشوند؛ پاکسازی دستی کش از
`DELETE /api/cache` استفاده میکند. سقف تعداد ردیفهای گزارش درخواست و پراکسی توسط
`CALL_LOGS_TABLE_MAX_ROWS` و `PROXY_LOGS_TABLE_MAX_ROWS` کنترل میشود.

### مدیریت هزینهها و بودجه

از طریق **داشبورد ← هزینهها** قابل دسترسی است.

| زبانه         | هدف                                                                                             |
| ------------- | ----------------------------------------------------------------------------------------------- |
| **بودجه**     | تعیین محدودیت هزینه برای هر کلید API با بودجههای روزانه/هفتگی/ماهانه و ردیابی بلادرنگ           |
| **قیمتگذاری** | مشاهده و ویرایش ورودیهای قیمتگذاری مدل — هزینه بهازای هر 1K توکن ورودی/خروجی برای هر ارائهدهنده |

```bash
# API: تعیین بودجه
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API: دریافت وضعیت فعلی بودجه
curl http://localhost:20128/api/usage/budget
```

**ردیابی هزینه:** هر درخواست، میزان استفاده از توکن را ثبت و هزینه را با استفاده از جدول قیمتگذاری محاسبه میکند. جزئیات تفکیکی را در **داشبورد ← مصرف** بر اساس ارائهدهنده، مدل و کلید API مشاهده کنید.

### رونویسی صوتی

OmniRoute از رونویسی صوتی از طریق نقطه پایانی سازگار با OpenAI پشتیبانی میکند:

```bash
POST /v1/audio/transcriptions
Authorization: Bearer your-api-key
Content-Type: multipart/form-data

# نمونه با curl
curl -X POST http://localhost:20128/v1/audio/transcriptions \
  -H "Authorization: Bearer your-api-key" \
  -F "file=@audio.mp3" \
  -F "model=openai/whisper-1"
```

`deepgram/nova-3` مسیر بومی Deepgram است و به یک کلید API مربوط به Deepgram نیاز دارد.
اگر فقط OpenRouter پیکربندی شده است، از `openrouter/deepgram/nova-3` استفاده کنید.

ارائهدهندگان **تبدیل گفتار به متن (رونویسی)**:

- `openai/` (سازگار با whisper)
- `groq/` (Groq Whisper Turbo)
- `deepgram/` (خانواده Nova)
- `assemblyai/`
- `nvidia/` (Parakeet، Canary)
- `huggingface/` (گونههای whisper)
- `qwen/`

ارائهدهندگان **تبدیل متن به گفتار (`POST /v1/audio/speech`)**:

- `openai/` (tts-1، tts-1-hd)
- `hyperbolic/`
- `deepgram/` (Aura)
- `nvidia/` (Magpie TTS)
- `elevenlabs/`
- `huggingface/`
- `inworld/`
- `cartesia/`
- `playht/`
- `kie/`
- `aws-polly/`
- `xiaomi-mimo/`
- `coqui/`، `tortoise/`
- `qwen/`

فرمتهای صوتی پشتیبانیشده برای رونویسی: `mp3`، `wav`، `m4a`، `flac`، `ogg`، `webm`. فرمتهای خروجی TTS به ارائهدهنده بستگی دارند (mp3، wav، opus، pcm، mulaw).

### راهبردهای متعادلسازی ترکیبها

متعادلسازی هر ترکیب را در **داشبورد ← ترکیبها ← ایجاد/ویرایش ← راهبرد** پیکربندی کنید.

| راهبرد              | توضیحات                                                                                 |
| ------------------- | --------------------------------------------------------------------------------------- |
| **نوبتی**           | مدلها را بهترتیب و بهصورت چرخشی انتخاب میکند                                            |
| **اولویتدار**       | همیشه ابتدا مدل اول را امتحان میکند؛ فقط هنگام خطا به مدل بعدی میرود                    |
| **تصادفی**          | برای هر درخواست، مدلی تصادفی از ترکیب انتخاب میکند                                      |
| **وزندار**          | مسیریابی را متناسب با وزنهای اختصاصیافته به هر مدل انجام میدهد                          |
| **کماستفادهترین**   | درخواست را به مدلی با کمترین درخواستهای اخیر هدایت میکند (با استفاده از معیارهای ترکیب) |
| **بهینهسازی هزینه** | درخواست را به ارزانترین مدل موجود هدایت میکند (با استفاده از جدول قیمتگذاری)            |

پیشفرضهای کلی ترکیب را میتوان در **داشبورد ← تنظیمات ← مسیریابی ← پیشفرضهای ترکیب** تعیین کرد.
مهلتهای زمانی مقصدهای ترکیب، بهطور پیشفرض مهلت زمانی درخواست فعلی را به ارث میبرند. از **مهلت زمانی مقصد
(ثانیه)** در پیشفرضهای ترکیب یا یک ترکیب مجزا فقط زمانی استفاده کنید که یک محدودیت کوتاهتر برای هر مقصد باید
بازگشت سریعتر به مقصد جایگزین را فعال کند.

بهینهسازیهای ترکیب با تأخیر صفر، اختیاری هستند. **بهینهسازیهای تأخیر صفر** را غیرفعال نگه دارید تا
این قابلیتهای مربوط به تأخیر، مقصدهای جایگزین را وارد رقابت نکنند، مقصدها را بر اساس سابقه TTFT
رد نکنند یا درخواستهای جایگزین را فشرده نکنند؛ فعالسازی آن اجازه میدهد پوشش ریسک پیکربندیشده، رد پیشبینانه بر اساس TTFT
و فشردهسازی پیشگیرانه درخواست جایگزین، با کاهش دقت مسیریابی/درخواست، تأخیر انتهایی را کاهش دهند.

زمانی که ارائهدهندگان بالادستی به محدودیتهای سختگیرانه
`max_tokens` / `maxOutputTokens` نیاز دارند، **بافر توکن استدلال** را غیرفعال کنید. در صورت فعال بودن، مسیریابی ترکیبی فقط برای مدلهایی
که سقف خروجی مشخصی دارند، فضای اضافی مدل استدلال را اضافه میکند و اگر مقدار بافرشده امن از آن سقف فراتر رود،
محدودیت توکن کلاینت را بدون تغییر باقی میگذارد. اگر محدودیت کلاینت از قبل بالاتر از یک سقف مشخص باشد،
OmniRoute پیش از ارسال درخواست به بالادست، آن را تا همان سقف کاهش میدهد.

### داشبورد سلامت

از طریق **داشبورد ← سلامت** به آن دسترسی پیدا کنید. نمای کلی بلادرنگ سلامت سیستم با ۶ کارت:

| کارت                 | آنچه نمایش میدهد                                               |
| -------------------- | -------------------------------------------------------------- |
| **وضعیت سیستم**      | زمان کارکرد، نسخه، میزان استفاده از حافظه، پوشه داده           |
| **سلامت ارائهدهنده** | وضعیت زمان اجرای قطعکننده مدار سراسری ارائهدهنده               |
| **محدودیتهای نرخ**   | دورههای انتظار فعال اتصال برای هر حساب همراه با زمان باقیمانده |
| **قفلهای فعال**      | قفلهای فعال در محدوده مدل و محرومسازیهای موقت                  |
| **کش امضا**          | آمار کش حذف موارد تکراری (کلیدهای فعال، نرخ اصابت)             |
| **تلهمتری تأخیر**    | تجمیع تأخیر p50/p95/p99 برای هر ارائهدهنده                     |

**نکته حرفهای:** صفحه سلامت هر ۱۰ ثانیه بهطور خودکار تازهسازی میشود. برای شناسایی ارائهدهندگانی که با مشکل مواجهاند، از کارت قطعکننده مدار استفاده کنید.

## 🤖 مسیریابی خودکار (بدون نیاز به پیکربندی)

OmniRoute همراه با یک **مسیریاب خودکار مبتنی بر امتیازدهی** عرضه میشود که برای هر درخواست، بهترین مدل را از میان تمام ارائهدهندگان متصل انتخاب میکند — بدون نیاز به نگهداری هیچ ترکیبی. کافی است درخواست را با یکی از پیشوندهای `auto/*` ارسال کنید؛ OmniRoute در لحظه یک ترکیب مجازی میسازد و گزینهها را بر اساس تأخیر، هزینه، نرخ موفقیت، تناسب پنجره زمینه، مناسببودن مدل برای وظیفه، خطاهای اخیر، سهمیه و وضعیت قطعکننده مدار امتیازدهی میکند.

| پیشوند         | معیار بهینهسازی                                                                                                   |
| -------------- | ----------------------------------------------------------------------------------------------------------------- |
| `auto`         | حالت پیشفرض متعادل (تأخیر × هزینه × نرخ موفقیت)                                                                   |
| `auto/coding`  | وظایف برنامهنویسی: Claude، GPT-5، GLM، Kimi، Qwen Coder و مدلهای برنامهنویسی DeepSeek را ترجیح میدهد              |
| `auto/cheap`   | کمترین هزینه بهازای هر توکن؛ تأخیر بیشتر را میپذیرد                                                               |
| `auto/fast`    | کمترین تأخیر؛ هزینه را نادیده میگیرد                                                                              |
| `auto/offline` | فقط ارائهدهندگان محلی (Ollama، vLLM، llama.cpp) — مناسب برای محیطهای ایزوله از شبکه                               |
| `auto/smart`   | اولویت با کیفیت استدلال (Opus، GPT-5 xhigh، R1، استدلال GLM 5.1)                                                  |
| `auto/lkgp`    | «آخرین ارائهدهنده مطلوب شناختهشده» — ابتدا به آخرین ارائهدهنده موفق متصل میماند، سپس به قوانین جایگزین رجوع میکند |

مثال:

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer $OMNIROUTE_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "auto/coding",
    "messages": [{ "role": "user", "content": "این تابع Python را بازآرایی کن" }],
    "stream": true
  }'
```

مسیریاب خودکار بهطور کامل در [AUTO-COMBO.md](../routing/AUTO-COMBO.md) توضیح داده شده است — از جمله نحوه تنظیم وزنهای امتیازدهی، قراردادن ارائهدهندگان در فهرست سیاه و بررسی تصمیمهای مسیریابی در **داشبورد ← ترکیب خودکار**.

## 🔌 یکپارچهسازی MCP و A2A

OmniRoute هم یک **سرور MCP** (پروتکل زمینه مدل) و هم یک **سرور A2A** (JSON-RPC 2.0 عاملبهعامل) است. هر محیط توسعه یا میزبان عامل سازگار با MCP میتواند ابزارهای OmniRoute را مستقیماً فراخوانی کند — بدون نیاز به هیچ پوشش اضافی.

### روشهای انتقال MCP

- **SSE**: `http://localhost:20128/api/mcp/sse`
- **HTTP قابلجریان**: `http://localhost:20128/api/mcp/stream`
- **stdio**: `omniroute --mcp` (برای افزونههای محیط توسعه که stdio را ترجیح میدهند)

### اتصال Claude Desktop

فایل `~/Library/Application Support/Claude/claude_desktop_config.json` را در macOS، یا فایل معادل آن را در Windows/Linux ویرایش کنید:

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### اتصال Cursor / Continue / VS Code MCP

از URL مربوط به SSE یعنی `http://localhost:20128/api/mcp/sse` و یک کلید API از نوع Bearer که در **داشبورد ← کلیدهای API** ایجاد شده است، استفاده کنید.

### دامنهها

MCP در حال حاضر 32 دامنه نامگذاریشده تعریف میکند. هر کلید Bearer را میتوان به دامنههای مشخصی محدود کرد — برای فهرست مرجع دامنهها و ابزارها به [MCP-SERVER.md](../frameworks/MCP-SERVER.md) و برای طرحواره JSON-RPC به [A2A-SERVER.md](../frameworks/A2A-SERVER.md) مراجعه کنید.

## 🧠 سیستم مهارتها

OmniRoute یک **چارچوب مهارت** توسعهپذیر (`src/lib/skills/`) ارائه میدهد تا عاملها و نقطه پایانی A2A بتوانند روالهای مختص دامنه را اجرا کنند (برای مثال `code-review`، `summarize`، `extract-facts` و `web-research`).

- **رابط کاربری بازارچه** — مهارتها را از مسیر **داشبورد ← مهارتها** مرور و نصب کنید
- **دامنههای اختصاصی هر کلید** — مشخص کنید کدام کلیدهای API میتوانند کدام مهارتها را فراخوانی کنند
- **مهارتهای سفارشی** — یک فایل TypeScript را در `src/lib/a2a/skills/` قرار دهید و آن را ثبت کنید تا بلافاصله از طریق A2A قابل فراخوانی شود

مرجع کامل: [SKILLS.md](../frameworks/SKILLS.md).

## 💾 سیستم حافظه

OmniRoute **حافظه مکالمهای بلندمدت** را با بازیابی ترکیبی ذخیره میکند:

- **SQLite FTS5** برای جستوجوی کلیدواژهای در نوبتهای مکالمه گذشته
- **ذخیرهساز برداری Qdrant** (اختیاری) برای یادآوری معنایی
- **استخراج خودکار واقعیتها** — موجودیتها، ترجیحات و تصمیمها پس از هر نشست خلاصه شده و در جدول `memory_facts` ذخیره میشوند
- حافظهها بهازای هر کلید API و هر نشست تفکیک میشوند

حافظهها را در **داشبورد ← حافظه** مدیریت کنید (جستوجو، ویرایش، برونبری و پاکسازی). رابط HTTP (`/api/memory/*`) به عاملها اجازه میدهد واقعیتها را بهصورت برنامهنویسیشده ارسال و جستوجو کنند — به [MEMORY.md](../frameworks/MEMORY.md) مراجعه کنید.

## 🔔 وبهوکها

برای پایش و خودکارسازی بلادرنگ، در رویدادهای OmniRoute مشترک شوید.

- در مسیر **داشبورد ← وبهوکها** یک وبهوک با URL مقصد و کلید محرمانه امضای HMAC ایجاد کنید
- رویدادهای موجود: `request.completed`، `request.failed`، `provider.unavailable`، `budget.exceeded`، `combo.switched`، `circuit_breaker.opened`، `circuit_breaker.closed`
- هر بار ارسالی برای اعتبارسنجی شامل `X-OmniRoute-Signature` (HMAC-SHA256) است
- تلاشهای مجدد: 3 تلاش با تأخیر تصاعدی، سپس انتقال به صف نامههای مرده

طرحواره کامل در [WEBHOOKS.md](../frameworks/WEBHOOKS.md).

## ☁️ عاملهای ابری

OmniRoute با عاملهای کدنویسی ابری (**OpenAI Codex Cloud**، **Devin**، **Jules** و **Antigravity**) یکپارچه میشود تا بتوانید وظایف طولانیمدت را از همان داشبوردی که مسیریابی محلی شما را مدیریت میکند، ارسال کنید.

- وظایف را در **داشبورد ← عاملهای ابری** یا از طریق `POST /api/v1/agents/tasks` ایجاد کنید
- وضعیت، گزارشها و مصنوعات هر وظیفه را پیگیری کنید
- برای هر ارائهدهنده از کلید API خودتان استفاده کنید — اطلاعات ورود هرگز از نمونه OmniRoute خارج نمیشوند

## 🛠️ مدیریت برنامهنویسیشده

میتوانید تمام منابع OmniRoute (ارائهدهندگان، ترکیبها، کلیدها و تنظیمات) را از طریق HTTP و با استفاده از یک **کلید Bearer دارای دامنه `manage`** مدیریت کنید.

کلید را در مسیر **داشبورد ← کلیدهای API ← کلید جدید ← دامنه: manage** ایجاد کنید، سپس:

```bash
# فهرست ارائهدهندگان
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# افزودن اتصال ارائهدهنده
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# ایجاد یک ترکیب
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# فهرستکردن/ایجاد کلیدهای API
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

برای مشاهده فهرست کامل نقاط پایانی و طرحوارههای درخواست/پاسخ، به [API_REFERENCE.md](../reference/API_REFERENCE.md) مراجعه کنید.

## 💻 CLI داخلی

OmniRoute یک CLI داخلی (`omniroute …`) برای راهاندازی، عیبیابی و کنترل زمان اجرا ارائه میکند. این ابزار **از صفحه «ابزارهای CLI» در داشبورد جدا است**؛ آن صفحه CLIهای شخص ثالث (Claude Code، Cursor، Codex، Cline و …) را پیکربندی میکند تا بتوانند با OmniRoute ارتباط برقرار کنند.

```bash
omniroute setup                    # راهنمای تعاملی (رمز عبور، ارائهدهندگان، ترکیبها)
omniroute setup --non-interactive  # مناسب برای CI
omniroute doctor                   # عیبیابی سلامت (دایرکتوری داده، پایگاه داده، ارائهدهندگان، پورتها)
omniroute providers available      # فهرست ارائهدهندگان پشتیبانیشده
omniroute providers list           # فهرست اتصالهای پیکربندیشده
omniroute providers test <id>      # آزمایش زنده اتصال یک ارائهدهنده
omniroute combos list              # فهرست ترکیبها
omniroute combos switch <name>     # تنظیم ترکیب پیشفرض
omniroute models                   # فهرست مدلهای موجود (--json، --search)
omniroute keys add | list | remove # مدیریت کلیدهای API از ترمینال
omniroute backup                   # تهیه اسنپشات از پیکربندی و پایگاه داده
omniroute restore [<timestamp>]    # بازیابی از یک اسنپشات
omniroute health                   # جزئیات سلامت (قطعکنندهها، کش، حافظه)
omniroute quota                    # میزان مصرف سهمیه ارائهدهنده
omniroute mcp status               # وضعیت سرور MCP
omniroute a2a status               # وضعیت سرور A2A
omniroute tunnel list|create|stop  # تونلهای Cloudflare/Tailscale/ngrok
omniroute reset-password           # بازنشانی رمز عبور مدیر
omniroute --mcp                    # راهاندازی سرور MCP از طریق stdio
omniroute --port 3000              # راهاندازی سرور روی یک پورت سفارشی
```

نکته: `omniroute doctor --json` را با ابزار پایش خود همراه کنید تا درباره اتصالهای ناسالم ارائهدهندگان هشدار دریافت کنید.

## 🖥️ برنامه دسکتاپ (Electron)

OmniRoute بهعنوان یک برنامه دسکتاپ بومی برای Windows، macOS و Linux در دسترس است.

### نصب

```bash
# از دایرکتوری electron:
cd electron
npm install

# حالت توسعه (اتصال به سرور توسعه در حال اجرای Next.js):
npm run dev

# حالت تولید (از بیلد مستقل استفاده میکند):
npm start
```

### ساخت نصبکنندهها

```bash
cd electron
npm run build          # پلتفرم فعلی
npm run build:win      # Windows (.exe NSIS)
npm run build:mac      # macOS (.dmg عمومی)
npm run build:linux    # Linux (.AppImage)
```

خروجی ← `electron/dist-electron/`

### قابلیتهای کلیدی

| قابلیت                | توضیحات                                                             |
| --------------------- | ------------------------------------------------------------------- |
| **آمادگی سرور**       | پیش از نمایش پنجره، سرور را بررسی میکند (بدون صفحه خالی)            |
| **سینی سیستم**        | کوچکسازی در سینی، تغییر پورت و خروج از منوی سینی                    |
| **مدیریت پورت**       | تغییر پورت سرور از سینی (سرور بهصورت خودکار مجدداً راهاندازی میشود) |
| **سیاست امنیت محتوا** | CSP محدودکننده از طریق هدرهای نشست                                  |
| **تکنمونهای**         | در هر لحظه فقط یک نمونه از برنامه میتواند اجرا شود                  |
| **حالت آفلاین**       | سرور همراه Next.js بدون اینترنت کار میکند                           |

### متغیرهای محیطی

| متغیر                 | پیشفرض  | توضیحات                               |
| --------------------- | ------- | ------------------------------------- |
| `OMNIROUTE_PORT`      | `20128` | پورت سرور                             |
| `OMNIROUTE_MEMORY_MB` | `512`   | محدودیت heap در Node.js (64–16384 MB) |
