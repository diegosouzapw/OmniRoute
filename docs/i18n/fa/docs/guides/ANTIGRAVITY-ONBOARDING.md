## 1. مقایسهٔ Antigravity و Antigravity CLI (agy)

هر دو ارائهدهنده از **بکاند یکسان Google** استفاده میکنند — کلاینت OAuth، نوسازی توکن، نقاط پایانی و حسابهای Google در هر دو یکساناند. تفاوت در مدلهایی است که مشاهده میکنید.

> برای مقایسهٔ رسمی Google، به [اطلاعیهٔ Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) مراجعه کنید.

| جنبه                | `antigravity` (IDE)                          | `agy` (CLI)                                          |
| ------------------- | -------------------------------------------- | ---------------------------------------------------- |
| **محصول Google**    | Antigravity 2.0 / Antigravity IDE            | Antigravity CLI                                      |
| **بکاند**           | همان Google Cloud Code API                   | همان Google Cloud Code API                           |
| **OAuth / توکن**    | همان کلاینت، همان نوسازی                     | همان کلاینت، همان نوسازی                             |
| **فهرست مدلها**     | فهرست منتخب ایستا (بهصورت ثابت در OmniRoute) | واکشی زنده از Google از طریق `:fetchAvailableModels` |
| **مدلهای Claude**   | Sonnet 4.6، Opus 4.6 (هرکدام 4 گونه)         | Sonnet 4.6، Opus 4.6 (هرکدام 4 گونه)                 |
| **نامگذاری Gemini** | برچسبهای ساده (کم/متوسط/زیاد)                | شناسههای بالادستی (extra-low/low/agent)              |
| **مدلهای اضافی**    | `gpt-oss-120b-medium`                        | ممکن است شامل مدلهای بیشتری از Google باشد           |
| **کاربرد پیشفرض**   | یکپارچهسازی با IDE (VS Code، JetBrains)      | دسترسی از طریق CLI / API                             |
| **سهمیه**           | مشترک با agy (همان حساب Google)              | مشترک با antigravity (همان حساب Google)              |

**مدلهای در دسترس (تأییدشده از طریق آزمایش، 2026-07-29)**:

- Gemini: 3.6 Flash، 3.5 Flash، 3.1 Pro، 3 Flash، 2.5 Flash (با سطوح مختلف استدلال)
- Claude: Sonnet 4.6، Opus 4.6 (هرکدام با گونههای پیشفرض/کم/متوسط/زیاد)
- سایر: GPT-OSS 120B Medium
- **Claude Sonnet 5 در دسترس نیست** — فقط گونههای 4.6 پشتیبانی میشوند

**چرا فهرست مدلها متفاوت است**: CLI گوگل طبق وبلاگ رسمی این شرکت، «برای سرعت و سربار کم بهینهسازی شده» و «بهطور مشترک با مدلهای Gemini بهینهسازی شده است». محصول وب/IDE «برای جامعیت بهینهسازی شده است». CLI برای کشف پویای مدلها از `:fetchAvailableModels` استفاده میکند، درحالیکه IDE از یک فهرست منتخب ایستا استفاده میکند.

**در عمل**: برای مدلهای Gemini از پیشوند `agy/` استفاده کنید (برای مثال `agy/gemini-3.7-flash-high`). برای فهرست منتخب ایستا از `antigravity/` استفاده کنید. هر دو به یک بکاند Google متصل میشوند، اما نامگذاری مدلهای متفاوتی ارائه میدهند. سهمیه مشترک است — استفاده از هر یک از ارائهدهندگان، از محدودیتهای همان حساب Google کسر میشود.

## 2. Google One AI Pro: سیستم سهمیه

> برای جزئیات رسمی سهمیه، به [مستندات Antigravity: طرحها](https://antigravity.google/docs/plans) و برای آخرین بهروزرسانیهای قیمتگذاری، به [تغییرات طرحهای Antigravity](https://antigravity.google/blog/changes-to-antigravity-plans) مراجعه کنید.

Google Antigravity از یک **سهمیه دولایه** بر اساس «کار انجامشده» (وزن محاسباتی) استفاده میکند، نه تعداد پیامها.

### دو لایه

| لایه                | چیست                     | چرخه بازنشانی                                                                                   |
| ------------------- | ------------------------ | ----------------------------------------------------------------------------------------------- |

| **خط مبنای ۷ روزه** | سقف قطعی هفتگی           | در صورت رسیدن به سقف، بازنشانی ۵ ساعته را نادیده میگیرد؛ دسترسی تا دوره ۷ روزه بعدی مسدود میشود |

**نحوه محاسبه «کار انجامشده»**: وظایف سنگین مبتنی بر عامل (برای مثال، «کل این مخزن را بازآرایی کن») سهمیه را بسیار سریعتر از وظایف ساده (برای مثال، «این تابع را اصلاح کن») مصرف میکنند. هیچ داشبورد بلادرنگی برای نمایش میزان مصرف وجود ندارد.

### مدلهای Gemini در مقایسه با مدلهای غیر Gemini

- **مدلهای Gemini** (Flash + Pro): یک محدودیت نرخ مشترک دارند که بر اساس قیمتگذاری API مصرف میشود. اگر Flash هشت برابر ارزانتر از Pro باشد، ۸ برابر توکن Flash بیشتری دریافت میکنید.
- **مدلهای غیر Gemini** (Claude، GPT-OSS): محدودیتهای نرخ **جداگانهای** دارند. ممکن است حتی وقتی دسترسی به Gemini مسدود شده است، همچنان در دسترس باشند.

### اعتبارهای AI (مصرف مازاد)

> برای آگاهی از نحوه کارکرد اعتبارها، به [اعتبارهای Google One AI](https://support.google.com/googleone/answer/14534406) مراجعه کنید.

هنگامی که سهمیه خط مبنا تمام میشود:

- **هرگز**: منتظر بازنشانی سهمیه میماند؛ پیام «سهمیه مدل خط مبنا به پایان رسیده است» را نمایش میدهد
- **همیشه**: بهطور خودکار از اعتبارهای AI استفاده میکند؛ پس از بازنشانی سهمیه خط مبنا دوباره به آن برمیگردد

اعتبارها بهصورت جداگانه خریداری میشوند و بر اساس قیمتگذاری استاندارد API کسر میشوند.

### جزئیات کلیدی

- سهمیه **در سطح حساب مشترک است** — یک حساب Google یکسان در Antigravity IDE، CLI و OmniRoute از یک مخزن سهمیه مشترک استفاده میکند
- هر حساب Google سهمیه مستقل خود را دارد — چند حساب = چند مخزن سهمیه
- کاربران AI Pro گزارش کردهاند که هنگام رسیدن به سقف هفتگی خط مبنا، بهجای بازنشانی ۵ ساعته با **مسدودسازی ۷ روزه** مواجه میشوند (Google تأیید کرده است که این رفتار برای مدیریت تقاضای بالا تعمدی است)

**هنگامی که سهمیه حساب شما تمام میشود**: OmniRoute بهطور خودکار درخواست را با حساب در دسترس بعدی در مسیر ترکیبی دوباره امتحان میکند. نیازی به مداخله دستی نیست.

## 3. نحوه دریافت projectId

هر اتصال antigravity/agy به یک `projectId` از Google Cloud Code نیاز دارد. بدون آن، نقطه پایانی `/v1internal:models` خطای 404 برمیگرداند.

### روش A: خودکار (پیشنهادی)

OmniRoute این فرایند را بهطور خودکار مدیریت میکند. هنگامی که یک حساب Google جدید را از طریق OAuth داشبورد اضافه میکنید:

1. OmniRoute توکن را تازهسازی میکند
2. برای یافتن projectId، تابع `loadCodeAssist` را فراخوانی میکند
3. اگر پروژهای وجود نداشته باشد، برای ایجاد آن `onboardUser` را فراخوانی میکند
4. برای دریافت projectId تازه ایجادشده، `loadCodeAssist` را دوباره امتحان میکند
5. آن را در پایگاه داده ذخیره میکند

**این روش برای بیشتر حسابها کار میکند** — نیازی به انجام مراحل دستی نیست.

### روش B: دستی از طریق agy CLI

اگر شناسایی خودکار ناموفق بود (برای موارد وقوع این مشکل به بخش ۵ مراجعه کنید):

```bash
# نصب agy CLI (اگر از قبل نصب نشده است)
npm install -g @anthropic-ai/agy

# ورود با حساب Google شما
agy login

# حسابی را انتخاب کنید که به راهاندازی اولیه نیاز دارد
# این کار ثبتنام Cloud Code را فعال کرده و یک projectId اختصاص میدهد
```

پس از موفقیت `agy login`، توکن را در داشبورد OmniRoute تازهسازی کنید. projectId بهطور خودکار شناسایی خواهد شد.

### نحوه تأیید

پایگاه داده را بررسی کنید:

```bash
# داخل کانتینر OmniRoute
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

یا گزارشها را بررسی کنید:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. URI تغییر مسیر OAuth

### مشکل

Google OAuth به یک URI تغییر مسیر معتبر نیاز دارد. تنظیم پیشفرض OmniRoute از `http://127.0.0.1:20128/callback` (loopback) استفاده میکند. این مورد برای بیلدهای محلی کار میکند، اما برای **استقرارهای راه دور** (برای مثال، سروری که از طریق IP شبکه LAN به آن دسترسی دارید) **ناموفق است**.

Google آن دسته از URIهای تغییر مسیر را رد میکند که:

- از آدرسهای IP استفاده میکنند (باید دامنهای با پسوند `.com`، `.org` و مانند آن باشند)
- با URIهای تغییر مسیر ثبتشده در پیکربندی کلاینت OAuth مطابقت ندارند

### راهحل

**گزینه A: استفاده از جریان داخلی OAuth (پیشفرض)**

- زمانی کار میکند که از طریق `localhost` یا `127.0.0.1` به OmniRoute دسترسی داشته باشید
- به هیچ پیکربندیای نیاز ندارد

**گزینه B: اطلاعات اعتبارسنجی سفارشی OAuth**

- متغیر `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` را در محیط خود تنظیم کنید
- اطلاعات اعتبارسنجی Google OAuth خود را وارد کنید:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- نشانی `https://your-domain.com/callback` را در Google Cloud Console بهعنوان URI تغییر مسیر مجاز ثبت کنید

**گزینه C: استفاده از agy CLI برای ورود اولیه**

- دستور `agy login` را روی دستگاهی اجرا کنید که به OmniRoute دسترسی خواهد داشت
- جریان OAuth بهصورت محلی تکمیل و توکنها ذخیره میشوند
- اتصال را از طریق داشبورد به OmniRoute وارد کنید

### محدودیتها

- اطلاعات اعتبارسنجی سفارشی OAuth به یک نام دامنه نیاز دارند (Google آدرسهای IP را بهعنوان URI تغییر مسیر نمیپذیرد)
- اگر دامنه ندارید، بهجای آن از گزینه A یا C استفاده کنید

## 5. عیبیابی: زمانی که راهاندازی خودکار ناموفق است

OmniRoute برای اکثر حسابها، شناسایی projectId و فرایند پذیرش اولیه را بهطور خودکار انجام میدهد. زمانی که این فرایند ناموفق باشد، علت اصلی معمولاً یکی از موارد زیر است:

### منطقه حساب مسدود شده است

**نشانه**: دستور `agy login` پیام «بررسی واجد شرایط بودن ناموفق بود: حساب فعلی شما واجد شرایط استفاده از Antigravity نیست، زیرا در حال حاضر در موقعیت مکانی شما در دسترس نیست.» را برمیگرداند.

**علت اصلی**: حسابهای Google دارای فیلد بکاند «Country Association» هستند که هنگام ثبتنام تنظیم میشود. agy CLI و Cloud Code API این فیلد را بهصورت سختگیرانه بررسی میکنند؛ برخلاف نسخه وب Gemini که فقط IP فعلی شما را بررسی میکند.

> برای بررسی یا تغییر منطقه مرتبط با حساب خود، به [فرم ارتباط کشور Google](https://policies.google.com/country-association-form) مراجعه کنید.

**چرا نسخه وب Gemini کار میکند، اما agy کار نمیکند**:

- نسخه وب Gemini / Google One: فقط IP فعلی را بررسی میکند (پروکسی کار میکند)
- agy CLI / Cloud Code API: فیلد بکاند Country Association را میخواند (پروکسی کمکی نمیکند)

**راهحل**:

1. درحالیکه از یک IP ایالات متحده استفاده میکنید، به [فرم ارتباط کشور Google](https://policies.google.com/country-association-form) مراجعه کنید
2. درخواست تغییر منطقه را ارسال کنید (گزینه «من در کشور دیگری زندگی میکنم» را انتخاب کنید)
3. بین 1 تا 24 ساعت منتظر بمانید تا Google درخواست را پردازش و اعلان ایمیلی را ارسال کند
4. پس از آن، دستور `agy login` باید با موفقیت اجرا شود

### حساب فاقد پروژه Cloud Code است

**نشانه**: گزارشها شامل `loadCodeAssist returned no project id` و `onboardUser failed (400)` هستند.

**علت اصلی**: حساب هرگز در Google Cloud Code ثبت نشده و فرایند پذیرش اولیه خودکار نیز ناموفق بوده است.

**راهحل**: دستور `agy login` را بهصورت دستی اجرا کنید تا ثبتنام Cloud Code آغاز شود، سپس توکن را در داشبورد OmniRoute تازهسازی کنید.

### توکن منقضی یا لغو شده است

**نشانه**: خطاهای 401 در گزارشها یا پیامهای «توکن منقضی شده است».

**راهحل**: توکن را در مسیر Dashboard → Providers → agy → Click refresh icon تازهسازی کنید. اگر خود توکن تازهسازی لغو شده باشد، باید دوباره از طریق OAuth احراز هویت کنید.

## فلوچارت تصمیمگیری

```
حساب کار نمیکند؟
│
├─ آیا در پایگاه داده projectId دارد؟
│  ├─ بله ← مشکل از جای دیگری است (توکن منقضی شده، محدودیت نرخ و غیره)
│  └─ خیر ↓
│
├─ آیا «ارتباط کشوری» حساب روی منطقهای محدودشده تنظیم شده است؟
│  ├─ بله ← منطقه را در فرم «ارتباط کشوری Google» تغییر دهید
│  │         (https://policies.google.com/country-association-form)
│  │         ۱ تا ۲۴ ساعت صبر کنید، سپس دوباره تلاش کنید
│  └─ خیر ↓
│
├─ آیا حساب اشتراک Google One AI Pro دارد؟
│  ├─ خیر ← ابتدا در one.google.com اشتراک تهیه کنید
│  └─ بله ↓
│
├─ کشف خودکار را امتحان کنید (توکن را در داشبورد تازهسازی کنید)
│  ├─ کار میکند ← تمام
│  └─ همچنان ناموفق است ↓
│
└─ روش دستی: دستور `agy login` را روی دستگاه اجرا کنید
   ├─ کار میکند ← توکن را در داشبورد تازهسازی کنید؛ projectId شناسایی میشود
   └─ ناموفق است ← پیام خطا را بررسی کنید؛ احتمالاً مشکل از منطقه یا اشتراک است
```
