قواعد فشردهسازی فایلهای JSON هستند که در زمان اجرا بارگذاری میشوند. این قواعد عمداً فقط شامل داده هستند تا بستههای زبانی جدید و فیلترهای فرمان RTK بدون تغییر کد موتور قابل بررسی باشند.

> **طرحوارهٔ مرجع (منبع حقیقت):** [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) (JSON Schema draft 2020-12).
> نمونههای زیر صرفاً جنبهٔ نمایشی دارند — در صورت تردید، بستهٔ خود را با `_schema.json` اعتبارسنجی کنید.

## بستههای قواعد Caveman

بستههای قواعد Caveman در مسیر زیر قرار دارند:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

هر بسته شامل جایگزینیهایی است که پس از جداسازی نواحی محافظتشده، روی متن عادی اعمال میشوند.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### فیلدهای Caveman

| فیلد                     | الزامی | توضیحات                                                                      |
| ------------------------ | ------ | ---------------------------------------------------------------------------- |
| `language`               | بله    | کلید زبان شبیه BCP-47، مانند `en`، `pt-BR` یا `es`                           |
| `category`               | بله    | نام فایل/دستهبندی بسته، برای مثال `filler` یا `dedup`                        |
| `rules`                  | بله    | آرایهای از قواعد جایگزینی regex                                              |
| `rules[].name`           | بله    | نام پایدار قاعده                                                             |
| `rules[].pattern`        | بله    | منبع regex در JavaScript                                                     |
| `rules[].flags`          | خیر    | پرچمهای regex در JavaScript؛ مقدار پیشفرض `gi` است                           |
| `rules[].replacement`    | خیر    | رشتهٔ جایگزین یا مقدار بازگشتی هنگامی که `replacementMap` تطابقی پیدا نمیکند |
| `rules[].replacementMap` | خیر    | جایگزینیهای مختص هر تطابق که کلید آنها متن تطبیقیافتهٔ نرمالسازیشده است      |
| `rules[].context`        | خیر    | `all`، `user`، `assistant` یا `system`؛ مقدار پیشفرض `all` است               |
| `rules[].category`       | خیر    | `filler`، `context`، `structural`، `dedup`، `terse` یا `ultra`               |
| `rules[].minIntensity`   | خیر    | `lite`، `full` یا `ultra`؛ مقدار پیشفرض `lite` است                           |
| `rules[].description`    | خیر    | خلاصهٔ خوانا برای انسان از قاعده                                             |

وقتی تطبیق حساس به بزرگی و کوچکی حروف اهمیت دارد، از `flags` استفاده کنید؛ برای مثال، هنگام حذف حرف تعریف پیش از متن با حروف کوچک، بدون حذف `the OpenAI API`. هنگامی که یک regex چندین گزینه با خروجیهای متفاوت دارد، از `replacementMap` استفاده کنید؛ این کار ضمن حفظ رفتار توابع جایگزینی داخلی و غنیتر TypeScript، بستههای قواعد JSON را صرفاً دادهمحور نگه میدارد.

## بستههای فیلتر RTK

فیلترهای RTK در مسیر زیر قرار دارند:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

هر فیلتر نحوهٔ تشخیص و فشردهسازی یک خانواده از خروجیهای فرمان را توصیف میکند.

```json
{
  "id": "test-vitest",
  "label": "خروجی Vitest",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "آزمونهای ناموفق را نگه میدارد",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### فیلدهای RTK

| فیلد                       | الزامی | توضیحات                                                                         |
| -------------------------- | ------ | ------------------------------------------------------------------------------- |
| `id`                       | بله    | شناسهٔ پایدار فیلتر                                                             |
| `label`                    | بله    | نام خوانا برای داشبورد                                                          |
| `category`                 | بله    | خانوادهٔ فیلتر: git، test، build، shell، docker، package، infra، cloud، generic |
| `priority`                 | خیر    | هنگام تطابق چند فیلتر، اولویت بالاتر برنده میشود                                |
| `match.outputTypes`        | خیر    | شناسههای خروجی آشکارساز که این فیلتر را انتخاب میکنند                           |
| `match.commands`           | خیر    | توکنهای فرمان که این فیلتر را انتخاب میکنند                                     |
| `match.patterns`           | خیر    | الگوهای عبارت منظم که این فیلتر را از روی متن خروجی انتخاب میکنند               |
| `rules.stripAnsi`          | خیر    | حذف دنبالههای گریز ANSI پیش از مراحل عبارت منظم                                 |
| `rules.replace`            | خیر    | جایگزینیهای مرتبشدهٔ عبارت منظم که خطبهخط اعمال میشوند                          |
| `rules.matchOutput`        | خیر    | قواعد خروجی با پایان زودهنگام و محافظ اختیاری `unless`                          |
| `rules.includePatterns`    | خیر    | خطوطی که حفظ آنها ترجیح داده میشود                                              |
| `rules.dropPatterns`       | خیر    | خطوطی که باید بهعنوان نویز حذف شوند                                             |
| `rules.collapsePatterns`   | خیر    | خطوط تکراری منطبق که میتوان آنها را ادغام کرد                                   |
| `rules.deduplicate`        | خیر    | ادغام خطوط نرمالشدهٔ تکراری                                                     |
| `rules.truncateLineAt`     | خیر    | محدودیت تعداد نویسه در هر خط با پشتیبانی ایمن از Unicode                        |
| `rules.maxLines`           | خیر    | حداکثر تعداد خطوط نگهداریشده پیش از حفظ انتهای خروجی                            |
| `rules.headLines`          | خیر    | خطوط ابتدایی که هنگام کوتاهسازی نگه داشته میشوند                                |
| `rules.tailLines`          | خیر    | خطوط انتهایی که برای حفظ زمینهٔ اخیر نگه داشته میشوند                           |
| `rules.onEmpty`            | خیر    | پیام جایگزین هنگامی که فیلترکردن تمام محتوا را حذف میکند                        |
| `rules.filterStderr`       | خیر    | نرمالسازی پیشوندهای رایج stderr پیش از مراحل بعدی فیلترکردن                     |
| `preserve.errorPatterns`   | خیر    | خطوط خطایی که باید پس از کوتاهسازی باقی بمانند                                  |
| `preserve.summaryPatterns` | خیر    | خطوط خلاصهای که باید پس از کوتاهسازی باقی بمانند                                |
| `tests[]`                  | خیر    | نمونههای اعتبارسنجی درونخطی که در دروازهٔ تأیید RTK استفاده میشوند              |

RTK مراحل اعلانی را به این ترتیب اعمال میکند: `stripAnsi`، `filterStderr`، `replace`،
`matchOutput`، `dropPatterns`/`includePatterns`، `truncateLineAt`، `headLines`/`tailLines`،
`maxLines` و `onEmpty`.

فیلترهای سفارشی را میتوان از منابع زیر بارگذاری کرد:

1. فایلهای `.rtk/filters.json` پروژه، فقط پس از آنکه هش منطبقی در `.rtk/trust.json` وجود داشته باشد یا
   `trustProjectFilters` فعال شده باشد.
2. فایل سراسری `DATA_DIR/rtk/filters.json`.
3. فیلترهای داخلی.

فایلهای سفارشی پروژه/سراسری میتوانند شامل یک شیء فیلتر یا آرایهای از اشیای فیلتر باشند. فیلترهای
سفارشی نامعتبر با ارائهٔ اطلاعات تشخیصی نادیده گرفته میشوند؛ فیلترهای داخلی نامعتبر باعث شکست اعتبارسنجی میشوند.

فایل اعتماد پروژه:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

نادیدهگیری محیطی `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` بدون نیاز به هش به فیلترهای پروژه اعتماد
میکند و باید استفاده از آن به توسعهٔ محلی کنترلشده محدود شود.

## قوانین ایمنی

- قوانین را ایدمپوتنت نگه دارید: اجرای دوبارهٔ یک فیلتر نباید خروجی را خراب کند.
- در صورت امکان، متن دقیق خطاها، مسیر فایلها، شمارهٔ خطوط و خلاصهٔ فرمانها را حفظ کنید.
- از قوانینی که بلوکهای کد، payloadهای JSON، URLها یا اطلاعات محرمانه را تغییر میدهند، اجتناب کنید.
- برای خانوادههای جدید فرمانها، پوشش تست واحد را به تستهای detector/filter اضافه کنید.
- نمونههای `tests[]` را به هر فیلتر داخلی و همچنین به فیلترهای سفارشی مشترک اضافه کنید.

## اعتبارسنجی

بستههای قوانین پیش از استفاده اعتبارسنجی میشوند. بستههای داخلی Caveman و فیلترهای داخلی RTK در صورت بروز خطا هنگام اعتبارسنجی، بلافاصله متوقف میشوند تا داراییهای انتشار خراب پیش از عرضه شناسایی شوند. فیلترهای سفارشی RTK، در صورت شکست تجزیه یا اعتبارسنجی اعتماد، همراه با اطلاعات تشخیصی نادیده گرفته میشوند.

اعتبارسنجی متمرکز:

```bash
node --import tsx/esm --test tests/unit/compression/rule-loader.test.ts tests/unit/compression/language-packs.test.ts
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts tests/unit/compression/rtk-dsl-pipeline.test.ts
```
