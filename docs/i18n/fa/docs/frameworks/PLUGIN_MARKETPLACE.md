> **منبع اصلی:** `src/lib/plugins/` (`marketplace.ts`، `manager.ts`، `manifest.ts`،
> `scanner.ts`، `loader.ts`)، `src/app/api/plugins/` و
> `src/app/(dashboard)/dashboard/plugins/`
> **آخرین بهروزرسانی:** 2026-06-28 — v3.8.40

OmniRoute همراه با یک سیستم افزونه به سبک WordPress ارائه میشود. افزونهها
دایرکتوریهای مستقلی هستند — هرکدام دارای یک مانیفست `plugin.json` و یک فایل
ورودی — که به خط لوله درخواست (`onRequest` / `onResponse` / `onError`) و
رویدادهای چرخه حیات (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
متصل میشوند.

**بازار افزونهها** لایه کشف روی این سیستم است. این لایه، کاتالوگی قابل مرور از
افزونههای قابل نصب ارائه میکند. بهطور پیشفرض، کاتالوگ یک رجیستری اولیه داخلی
و کوچک است؛ اپراتور میتواند آن را به یک URL رجیستری راهدور سفارشی متصل کند که
در این حالت، دریافت داده بهوسیله یک محافظ SSRF با قابلیت تفکیک DNS ایمنسازی
میشود (به [امنیت](#security) مراجعه کنید).

تمام مسیرهای افزونه **فقط از طریق loopback** در دسترس هستند (سطح 1 —
`LOCAL_ONLY`): افزونهها کد را در فرایندهای فرزند بارگذاری و اجرا میکنند،
بنابراین این مسیرها، صرفنظر از احراز هویت، از هیچ مبدأ غیر-loopback قابل دسترسی
نیستند. به
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md)
مراجعه کنید.

## نحوه عملکرد اجزا در کنار یکدیگر

```
داشبورد (/dashboard/plugins)
  ├─ زبانه «نصبشده»  → GET /api/plugins            (listPlugins)
  │                     POST /api/plugins/scan      (pluginManager.scan)
  │                     POST /api/plugins/{name}/activate|deactivate
  │                     DELETE /api/plugins/{name}   (حذف نصب)
  └─ زبانه «بازار»     → GET /api/plugins/marketplace
                          → listMarketplacePlugins()
                            ├─ بدون URL سفارشی → SEED_REGISTRY داخلی
                            └─ URL سفارشی → محافظ SSRF تابع isSafeMarketplaceUrl()
                                          → safeOutboundFetch(guard:"public-only")
```

- **لایه رجیستری** — `src/lib/plugins/marketplace.ts`: فهرست کردن / جستوجوی
  کاتالوگ، همراه با بازگشت به رجیستری اولیه در صورت بروز هرگونه خطا.
- **لایه چرخه حیات** — `src/lib/plugins/manager.ts` (سینگلتون `pluginManager`):
  نصب، ارتقا، فعالسازی، غیرفعالسازی، حذف نصب، اسکن و بارگذاری هنگام راهاندازی.
- **لایه مانیفست** — `src/lib/plugins/manifest.ts`: شِمای Zod و مقادیر پیشفرض
  برای `plugin.json`.
- **اسکنر** — `src/lib/plugins/scanner.ts`: افزونههای موجود روی دیسک را در
  دایرکتوری افزونه کشف میکند.
- **بارگذار** — `src/lib/plugins/loader.ts`: هر افزونه را در یک فرایند فرزند
  ایزوله اجرا میکند و فراخوانی هوکها را از طریق IPC واسطهگری میکند.

## کاتالوگ بازار

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) فهرستی از
اشیای `MarketplaceEntry` را برمیگرداند:

| فیلد          | نوع      | توضیحات                                       |
| ------------- | -------- | --------------------------------------------- |
| `name`        | string   | نام افزونه با قالب kebab-case                 |
| `version`     | string   | semver                                        |
| `description` | string   | خلاصه کوتاه                                   |
| `author`      | string   | نویسنده / سازمان                              |
| `license`     | string   | شناسه مجوز به سبک SPDX                        |
| `downloadUrl` | string   | URL دانلود منبع (ممکن است خالی باشد)          |
| `repository`  | string?  | URL اختیاری مخزن                              |
| `tags`        | string[] | برچسبهای جستوجو/فیلتر                         |
| `downloads`   | number   | تعداد دانلودها                                |
| `rating`      | number   | 0–5                                           |
| `verified`    | boolean  | آیا ورودی بهعنوان تأییدشده علامتگذاری شده است |
| `lastUpdated` | string   | رشته تاریخ تقریباً مطابق ISO                  |

وقتی هیچ URL رجیستری سفارشی پیکربندی نشده باشد، کاتالوگ همان
`SEED_REGISTRY` داخلی است (در حال حاضر شامل `request-logger`، `rate-limiter`،
`cost-tracker` و `theme-manager`). رجیستری اولیه همیشه در دسترس است — اگر
رجیستری راهدور پیکربندیشده قابل دسترسی نباشد، وضعیتی غیر از `200` برگرداند یا
بدنهای ناشناخته ارائه کند، `listMarketplacePlugins()` یک هشدار ثبت میکند و به
فهرست اولیه بازمیگردد.

> نکته: **کاتالوگ** بازار (مرور/جستوجو) بهطور کامل از ابتدا تا انتها متصل شده
> است، اما **نصب** تککلیکی از کاتالوگ بازار هنوز پیادهسازی نشده است — دکمه
> «نصب» داشبورد برای یک ورودی بازار در حال حاضر پیام «بهزودی» را نمایش میدهد.
> در حال حاضر، نصب از طریق جریان نصب با مسیر محلی (`POST /api/plugins`) و کشف
> روی دیسک (`POST /api/plugins/scan`) انجام میشود.

## API REST

همهٔ نقاط پایانی به احراز هویت مدیریتی (`requireManagementAuth`) نیاز دارند **و**
فقط از طریق loopback قابل دسترسی هستند — `/api/plugins` و `/api/plugins/` در
`LOCAL_ONLY_API_PREFIXES` (`src/server/authz/routeGuard.ts`) فهرست شدهاند.

| نقطهٔ پایانی                     | متد    | توضیحات                                                  |
| -------------------------------- | ------ | -------------------------------------------------------- |
| `/api/plugins`                   | GET    | فهرست افزونههای نصبشده (با فیلتر اختیاری `?status=`)     |
| `/api/plugins`                   | POST   | نصب افزونه از یک مسیر محلی مطلق                          |
| `/api/plugins/scan`              | POST   | اسکن دایرکتوری افزونهها و ثبت افزونههای جدید             |
| `/api/plugins/marketplace`       | GET    | فهرست ورودیهای کاتالوگ بازارچه                           |
| `/api/plugins/[name]`            | GET    | دریافت جزئیات افزونهٔ نصبشده                             |
| `/api/plugins/[name]`            | DELETE | حذف نصب یک افزونه                                        |
| `/api/plugins/[name]/activate`   | POST   | فعالسازی (بارگذاری + ثبت hookها)                         |
| `/api/plugins/[name]/deactivate` | POST   | غیرفعالسازی (اجرای `onDeactivate` و لغو ثبت hookها)      |
| `/api/plugins/[name]/config`     | GET    | دریافت پیکربندی افزونه + schema پیکربندی                 |
| `/api/plugins/[name]/config`     | PUT    | بهروزرسانی پیکربندی افزونه (اعتبارسنجیشده براساس schema) |

فیلتر `status` برای `GET /api/plugins` یکی از مقادیر
`installed` / `active` / `inactive` / `error` را میپذیرد. مقدار نامعتبر، پاسخ `400` را برمیگرداند.

### فهرست افزونههای نصبشده

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### نصب از یک مسیر محلی

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

مقدار `path` باید **مطلق** باشد و نباید شامل بخشهای پیمایش `..` یا
بایتهای null باشد (این محدودیت توسط Zod اعمال میشود). دایرکتوری منبع باید دارای یک
`plugin.json` معتبر باشد (یا دایرکتوری والدِ یکی از آنها باشد). در صورت موفقیت، پاسخ با کد `201` و
رکورد افزونهٔ نصبشده برگردانده میشود.

### مرور بازارچه

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### بهروزرسانی پیکربندی افزونه

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config` هر مقدار ارائهشده را براساس
`configSchema` افزونه (تعریفشده در manifest) اعتبارسنجی میکند: فیلدهای `number` محدودیتهای `min`/`max` را رعایت میکنند،
و فیلدهای `select` باید با `enum` تعریفشده مطابقت داشته باشند. کلیدهایی که در schema
وجود ندارند، بدون تغییر پذیرفته میشوند.

## پیکربندی

### دایرکتوری افزونهها

افزونهها در دایرکتوری دادهٔ OmniRoute قرار میگیرند:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (یا هر فایلی که manifest.main به آن اشاره میکند)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) آن دایرکتوری را در
سه مرحله تعیین میکند:

1. **`OMNIROUTE_PLUGINS_DIR`**، در صورت تنظیم بودن — بدون هیچ تغییری و مستقل از مقدار `HOME` استفاده میشود. این
   گزینهٔ صریح برای Docker/K8s است؛ جایی که درخت افزونهها بهصورت bind mount در مسیری
   قرار میگیرد که معمولاً ارتباطی با دایرکتوری home کانتینر ندارد (#11827).
2. `<home>/.omniroute/plugins`، که در آن `<home>` از متغیرهای محیطی `HOME` / `USERPROFILE`
   گرفته میشود.
3. `/tmp/.omniroute/plugins`، هنگامی که فرایند هیچ homeای export نکرده باشد.

دایرکتوری تعیینشده هنگام راهاندازی یکبار با عنوان `scanner.dir_resolved` ثبت میشود و
ورودی انتخابشده (`OMNIROUTE_PLUGINS_DIR`، `home` یا `no-home-fallback`) را مشخص میکند — بنابراین imageای
که بدون اعلام روی مرحلهٔ 3 قرار میگیرد، این موضوع را گزارش میکند، نه اینکه فقط فهرست خالی افزونهها را نمایش دهد.
`POST /api/plugins/scan` هر زیردایرکتوری موجود در آن مسیر را که دارای یک
`plugin.json` معتبر باشد، کشف و ثبت میکند؛ همین دایرکتوری همچنین ریشهای است که
`pluginManager.install()` افزونهها را در آن کپی میکند، بنابراین override، فرایند کشف و
نصب را با هم جابهجا میکند.

> **`OMNIROUTE_PLUGINS_DIR` همان `OMNIROUTE_PLUGIN_PATH` نیست.** مورد دوم فقط توسط
> بارگذار افزونههای فرمان CLI (`bin/cli/plugins.mjs`) خوانده میشود تا packageهای npm با نام `omniroute-cmd-*`
> را پیدا کند که زیرفرمانهایی به `omniroute` اضافه میکنند — این متغیر هیچ تأثیری بر اسکنر زمان اجرا
> که در اینجا توضیح داده شد ندارد. برای اطلاعات مربوط به آن بخش، [PLUGINS.md](./PLUGINS.md) را ببینید.

### URL سفارشی registry بازارچه

منبع کاتالوگ بازارچه از تنظیم `pluginMarketplaceUrl`
خوانده میشود (`src/lib/plugins/marketplace.ts` مقدار `settings.pluginMarketplaceUrl` را میخواند). هنگامی که
روی یک URL از نوع `http(s)` تنظیم شده باشد، `listMarketplacePlugins()` آن URL را دریافت میکند و
یا یک آرایهٔ JSON سطحبالا از ورودیها یا یک شیء دارای آرایهٔ `plugins` را میپذیرد؛
ورودیهایی که `name` رشتهای ندارند، فیلتر میشوند. هنگامی که تنظیم نشده باشد (یا زمانی که fetch
در بررسی SSRF رد شود / پاسخ نامعتبری برگرداند)، از seed registry داخلی
استفاده میشود.

زبانهٔ «بازارچه» در داشبورد، فیلدی برای این URL ارائه میکند (که مقدار آن از
`GET /api/settings` بازخوانی میشود).

> نکتهٔ پیادهسازی: عمل «ذخیره» در داشبورد، مقدار
> `pluginMarketplaceUrl` را به `PATCH /api/settings` ارسال میکند. در زمان نگارش این متن، این
> کلید در `updateSettingsSchema`
> (`src/shared/validation/settingsSchemas.ts`) تعریف نشده است؛ بنابراین پیش از اتکا به آن، ماندگاری مقدار را در
> release خود بررسی کنید — مسیر **خواندن** (`getSettings()` →
> `listMarketplacePlugins()`) پس از موجود شدن کلید در محل ذخیرهسازی تنظیمات، آن را در نظر میگیرد.

## امنیت

### سطح مسیر — فقط loopback

افزونهها کد را در فرایندهای فرزندِ ایجادشده اجرا میکنند؛ بنابراین کل سطح `/api/plugins`
بهعنوان `LOCAL_ONLY` (سطح 1) طبقهبندی میشود. اعمال محدودیت loopback بدون قیدوشرط
و **پیش از** هرگونه بررسی احراز هویت انجام میشود؛ بنابراین حتی اگر یک توکن مدیریتی
افشاشده از طریق تونل به سیستم برسد، باز هم نمیتواند افزونهای را نصب، فعال یا حذف کند.
به [`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) و
قواعد سختگیرانه شماره 15 / 17 مراجعه کنید.

### محافظ SSRF رجیستری بازار افزونهها

URL سفارشی رجیستری نوعی پیکربندی است که مهاجم میتواند بر آن تأثیر بگذارد؛ بنابراین
پیش از واکشی آن، `listMarketplacePlugins()` این URL را از دو لایه عبور میدهد:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - هر چیزی را که `http:` / `https:` نباشد رد میکند.
   - میزبانهای صریح خصوصی/loopback/link-local/ULA را (هم IPv4 **و هم** IPv6،
     از جمله IPv4-mapped) از طریق تابع متعارف `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) رد میکند.
   - رکوردهای `A` و `AAAA` را **هر دو** تفکیک نام میکند و اگر **هرکدام** از
     آدرسهای تفکیکشده خصوصی باشند، آن را رد میکند؛ بدینترتیب مسیر دور زدن
     public-hostname → private-IP مسدود میشود.
   - **بهصورت بسته شکست میخورد**: شکست در تفکیک DNS باعث رد شدن URL میشود.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): محافظ URL با حالت public-only را
   هنگام واکشی دوباره اعمال میکند و **تغییرمسیرها را مسدود میکند** (هیچ چرخش
   public → private از نوع `30x` مجاز نیست).

URLی که در هر یک از این لایهها ناموفق باشد، درخواست را متوقف نمیکند؛ بازار افزونهها
بیسروصدا به رجیستری اولیه داخلی بازمیگردد و یک هشدار ثبت میکند.

> این محافظ در PR #3774 بهطور ویژه سختگیرانهتر شد تا A + AAAA را تفکیک نام کند و
> بهجای بررسیِ صرفاً IPv4، از تابع متعارف `isPrivateHost` استفاده کند.

### جداسازی اجرای افزونه

- **جداسازی فرایند** — `loadPlugin()` (`src/lib/plugins/loader.ts`) هر افزونه را
  در یک فرایند فرزند جداگانه Node.js ایجاد میکند و از طریق IPC با آن ارتباط برقرار
  میکند. فراخوانیهای hook دارای مهلت زمانی با تشدید از `SIGTERM` به `SIGKILL`
  هستند.
- **فهرست مجاز Env** — فرایند فرزند فقط مجموعهای از متغیرهای محیطی موجود در
  فهرست مجاز را دریافت میکند؛ مجموعه گستردهتر تنها زمانی اعطا میشود که manifest
  مجوز `env` را درخواست کند.
- **محصورسازی مسیر** — عملیات نصب/ارتقا/حذف بررسی میکنند که دایرکتوری افزونه و
  `manifest.main`، پیش از هرگونه کپی یا حذف بازگشتی، **درون** ریشه مدیریتشده
  افزونه resolve شوند (برای محافظت در برابر مسیرهای دستکاریشده پایگاه داده و
  پیمایش `../` در `manifest.main`). فعالسازی، symlinkها را از طریق `realpath`
  resolve میکند و از بارگذاری نقطه ورودیای که از دایرکتوری افزونه خارج شود
  خودداری میکند.
- **پین اختیاری یکپارچگی** — یک manifest میتواند فیلد `integrity`
  (`sha256-<base64>`، با قالب SRI) را اعلام کند. در صورت وجود، loader هنگام
  بارگذاری، هش فایل ورودی را تأیید میکند و در صورت عدم تطابق از فعالسازی
  خودداری میکند. این سازوکار تشخیص دستکاریِ اختیاری است و **نه** یک مرز امنیتی؛
  مسیریابی محدود به loopback و مدل مجوزها مرزهای واقعی هستند.

## Manifest (`plugin.json`)

توسط `PluginManifestSchema` (`src/lib/plugins/manifest.ts`) اعتبارسنجی میشود:

| فیلد               | نوع       | توضیحات                                                          |
| ------------------ | --------- | ---------------------------------------------------------------- |
| `name`             | string    | الزامی؛ kebab-case (`^[a-z0-9-]+$`)، بین 1 تا 100 نویسه          |
| `version`          | string    | الزامی؛ semver (`MAJOR.MINOR.PATCH`)                             |
| `description`      | string?   | حداکثر 500 نویسه                                                 |
| `author`           | string?   | حداکثر 200 نویسه                                                 |
| `license`          | string?   | مقدار پیشفرض `MIT`                                               |
| `main`             | string?   | فایل ورودی؛ مقدار پیشفرض `index.js`                              |
| `source`           | enum?     | `local` \| `marketplace` (مقدار پیشفرض `local`)                  |
| `tags`             | string[]? | برچسبهای جستوجو                                                  |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                                  |
| `hooks`            | object?   | مقادیر بولی که مشخص میکنند افزونه کدام hookها را پیادهسازی میکند |
| `skills`           | object[]? | تعریفهای اختیاری skill                                           |
| `enabledByDefault` | boolean?  | فعالسازی خودکار هنگام نصب                                        |
| `configSchema`     | object?   | نگاشت فیلدهای پیکربندی (`string`/`number`/`boolean`/`select`)    |
| `integrity`        | string?   | پین اختیاری فایل ورودی با `sha256-<base64>`                      |

مجوزها از enum زیر انتخاب میشوند:
`network` / `file-read` / `file-write` / `env` / `exec`.

## جریان چرخهٔ حیات

```
نصب (POST /api/plugins، مسیر)
  → اسکن/اعتبارسنجی manifest → کپی به staging → اطمینان از قرار داشتن main درون دایرکتوری
  → تغییر نام اتمی به ~/.omniroute/plugins/<name> → درج ردیف در پایگاه داده
  → اجرای onInstall → اگر enabledByDefault بود: فعالسازی

فعالسازی (POST /api/plugins/{name}/activate)
  → بررسی محصور بودن realpath → loadPlugin() (ایجاد فرایند فرزند)
  → ثبت hookهای اعلامشده → status = "active" → اجرای onActivate

غیرفعالسازی (POST /api/plugins/{name}/deactivate)
  → اجرای onDeactivate (پیش از لغو ثبت) → لغو ثبت hookها
  → خاتمه دادن به فرایند فرزند → status = "inactive"

حذف نصب (DELETE /api/plugins/{name})
  → در صورت فعال بودن، غیرفعالسازی → اجرای onUninstall
  → حذف بازگشتی دایرکتوری افزونه با بررسی محصور بودن → حذف ردیف از پایگاه داده
```

اجرای مجدد `install` برای دایرکتوریای که نسخهٔ manifest آن **اکیداً
جدیدتر** از نسخهٔ نصبشده است، بهطور خودکار ارتقا را انجام میدهد (نصب مجدد پاک؛ پیکربندی به
مقادیر پیشفرض بازنشانی میشود). نسخهٔ یکسان یا قدیمیتر رد میشود.

## داشبورد

صفحهٔ داشبورد در `/dashboard/plugins`
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) دو زبانه دارد:

- **نصبشده** — افزونههای نصبشده را همراه با hookهای اعلامشدهٔ آنها، کلید
  فعالسازی/غیرفعالسازی، دکمهٔ حذف نصب و عملیات «اسکن برای افزونهها»
  (`POST /api/plugins/scan`) فهرست میکند.
- **فروشگاه** — کاتالوگ دریافتی از `GET /api/plugins/marketplace` را همراه با
  فیلدی برای تنظیم URL رجیستری سفارشی نمایش میدهد.

صفحهٔ پیکربندی هر افزونه در `/dashboard/plugins/[name]/config`
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`) قرار دارد.
