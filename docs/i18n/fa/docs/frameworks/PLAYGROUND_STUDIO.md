## نمای کلی

Playground Studio، مسیر `/dashboard/playground` را از یک ویرایشگر ساده مبتنی بر Monaco به یک فضای کاری کامل برای آزمایش تبدیل میکند. این قابلیت، فایل قدیمی `page.tsx` را با پوستهای به نام `PlaygroundStudio` جایگزین میکند که چهار زبانه و یک پنل پیکربندی مشترک را نمایش میدهد.

```
┌ Playground ──────────────────────────────────────────────────────────┐
│ [💬 گفتگو] [⚖ مقایسه] [{} API] [🔧 ساخت]      142↑ 38↓ · $0.002 </>│
├──────────────────────────────────────────┬───────────────────────────┤
│  {محتوای زبانه فعال}                    │ ─ پیکربندی                │
│                                          │ نقطه پایانی [chat ∨]      │
│                                          │ مدل       [gpt-5.4 ∨]     │
│                                          │ سیستم     [ناحیه متنی]    │
│                                          │ دما       ▕▕▔▔ 0.7        │
│                                          │ پیشتنظیمها [▾ بارگذاری][ذخیره] │
│                                          │ [✨ بهبود پرامپت]          │
└──────────────────────────────────────────┴───────────────────────────┘
```

## زبانهها

### زبانه گفتگو

`ChatPlayground.tsx` را به یک محیط کاری چندمرحلهای با قابلیت استریم ارتقا میدهد:

- رندر کامل Markdown از طریق `MarkdownMessage.tsx` (بلوکهای کد، جدولها، فهرستها و پیوندها).
- دریافت پرامپت سیستم از پنل پیکربندی مشترک.
- نمایش توکن/هزینه برای هر پیام (توکنهای پرامپت + تکمیل).
- تولید مجدد آخرین پاسخ.
- ارسال به `POST /v1/chat/completions` با استریم SSE.

### زبانه مقایسه

وجه تمایز اصلی برای یک پراکسی: اجرای ۱ پرامپت بهطور موازی روی حداکثر **۴ مدل**.

- حداکثر ۴ ستون که هرکدام بهصورت مستقل از `/v1/chat/completions` استریم میکنند.
- دکمه `+ افزودن مدل` با میانبر Cmd+K برای افزودن ستونها.
- گزینه `اجرای همه ▶` با استفاده از `Promise.all` و یک `AbortController` برای هر ستون، تمام استریمها را بهطور همزمان آغاز میکند.
- گزینه سراسری **لغو همه** تمام استریمهای در حال اجرا را متوقف میکند.
- `ProviderMetrics` در هر ستون، TTFT، TPS، تعداد توکنها و هزینه تخمینی را بهصورت بلادرنگ نمایش میدهد.
- معیارها با برچسب **«برآورد سمت کلاینت»** (D12) مشخص شدهاند — اندازهگیری از نخستین قطعه SSE آغاز میشود.

### زبانه API

برای کاربران حرفهای، ۱۰۰٪ ویرایشگر اصلی Monaco را حفظ میکند (D14):

- ۱۰ نقطه پایانی: تکمیلهای گفتگو، تکمیلها، تعبیهها، تصاویر، صدا، گفتار، رونویسیها، تعدیل محتوا، رتبهبندی مجدد و جستوجو.
- بارگذاری فایل چندوجهی.
- استریم SSE با خروجی بلادرنگ.
- در قالب `ApiTab.tsx` بستهبندی شده است (بارگذاری تنبل، `ssr: false`).

### زبانه ساخت

رابط کاربری ابزارها/فراخوانی تابع و خروجی ساختاریافته:

- `ToolsBuilder.tsx` — افزودن/ویرایش/حذف `tools[]` با ویرایشگر JSON schema برای هر ابزار.
  پارامترها را از طریق `ToolDefinitionSchema` (Zod) اعتبارسنجی میکند.
- `StructuredOutputEditor.tsx` — فعال یا غیرفعالکردن حالت JSON بههمراه ویرایشگر JSON schema.
  پاسخ را با استفاده از `StructuredOutputSchema` (Zod) در برابر schema اعتبارسنجی میکند.
- درخواست را با `tools[]` و/یا `response_format` به `/v1/chat/completions` ارسال میکند.

`StudioConfigPane.tsx` — همیشه قابل مشاهده و جمعشدنی است.

| فیلد         | کامپوننت              | توضیحات                                                                             |

## بهبوددهنده پرامپت

`ImprovePromptButton.tsx` → `useImprovePrompt.ts` → `POST /api/playground/improve-prompt`:

1. مودال هشدار میدهد که «سهمیه مصرف خواهد شد».
2. پس از تأیید، `{ system, prompt, model, tone }` را به route ارسال میکند.
3. route بهصورت داخلی `/v1/chat/completions` را با `promptImprover.META_SYSTEM_PROMPT` فراخوانی میکند.
4. `{ improvedSystem?, improvedPrompt?, tokensIn, tokensOut }` را برمیگرداند.
5. رابط کاربری، پرامپت سیستم در پنل پیکربندی و پرامپت کاربر در زبانه Chat را بهروزرسانی میکند.

## پیشتنظیمها

`PresetPicker.tsx` → `usePresets.ts` → `/api/playground/presets/*`:

- در جدول SQLite با نام `playground_presets` ذخیره میشوند (migration با نام `084_playground_presets.sql`).
- هر پیشتنظیم این موارد را ذخیره میکند: `name`، `endpoint`، `model`، `system`، `params_json`، `created_at`.
- CRUD: فهرست با `GET`، ایجاد با `POST`، دریافت با `GET /:id`، بهروزرسانی با `PUT /:id`، حذف با `DELETE /:id`.

## معیارهای استریم

`useStreamMetrics.ts` + `streamMetrics.ts` (تابع خالص):

- `start()` — زمان شروع درخواست را ثبت میکند.
- `onFirstChunk()` — TTFT را ثبت میکند.
- `onChunk(n)` — تعداد توکنهای completion را تجمیع میکند.
- `finish(usage?)` — معیارهای نهایی را محاسبه میکند: `ttftMs`، `totalMs`، `tps`، `tokensIn`، `tokensOut`، `costUsd`.
- قیمتگذاری از جدول ایستا در `src/lib/playground/types.ts` دریافت میشود (با برچسب «تخمینی» — D13).

## routeهای Backend

| متد      | مسیر                             | Handler                                                                                                       |
| -------- | -------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `POST`   | `/api/playground/improve-prompt` | با Zod و `ImprovePromptRequestSchema` اعتبارسنجی میکند؛ `/v1/chat/completions` را با فراپرامپت فراخوانی میکند |
| `GET`    | `/api/playground/presets`        | `{ presets: PlaygroundPresetListItem[] }` را برمیگرداند                                                       |
| `POST`   | `/api/playground/presets`        | پیشتنظیم را ایجاد میکند؛ `PlaygroundPresetCreateSchema` را اعتبارسنجی میکند                                   |
| `GET`    | `/api/playground/presets/:id`    | یک پیشتنظیم یا 404 را برمیگرداند                                                                              |
| `PUT`    | `/api/playground/presets/:id`    | بهروزرسانی جزئی                                                                                               |
| `DELETE` | `/api/playground/presets/:id`    | 204                                                                                                           |

احراز هویت: اختیاری (`REQUIRE_API_KEY`). خطاها از طریق `buildErrorBody()` (قانون قطعی شماره ۱۲).

## عیبیابی

| نشانه                                          | علت                                  | راهحل                                                                                                               |
| ---------------------------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| ویرایشگر Monaco در زبانه API نمایش داده نمیشود | SSR، Monaco را بارگذاری کرده است     | بررسی کنید که `ApiTab` از `dynamic(..., { ssr: false })` استفاده میکند                                              |
| جریانهای مقایسه بهصورت ترتیبی اجرا میشوند      | استفاده نادرست از `Promise.all`      | شروع همه جریانها باید در یک فراخوانی `Promise.all` انجام شود                                                        |
| معیارها مقدار `null` را برای TTFT نشان میدهند  | کنترلکننده نخستین قطعه متصل نشده است | بررسی کنید که `useStreamMetrics.onFirstChunk()` در حلقه خواندن SSE فراخوانی میشود                                   |
| پیشتنظیم ذخیره نمیشود                          | مهاجرت DB اجرا نشده است              | `npm run db:migrate` را اجرا کنید یا سرور را مجدداً راهاندازی کنید (مهاجرت هنگام راهاندازی بهطور خودکار اجرا میشود) |
| بهبود پرامپت خطای 502 برمیگرداند               | مدل در بخش پیکربندی تنظیم نشده است   | کاربر باید پیش از بهبود، نام یک مدل را در پنل پیکربندی وارد کند                                                     |
| کد خروجی `MISSING_API_KEY` را نشان میدهد       | جاینگهدار درج نشده است               | `codeExport.ts` همیشه از `API_KEY_PLACEHOLDER = "$OMNIROUTE_API_KEY"` استفاده میکند                                 |
