> **منبع:** `src/lib/{a2a,acp,cloudAgent}/`، `src/app/api/{a2a,acp,cloud}/`، `src/app/api/v1/agents/`
> **آخرین بهروزرسانی:** 2026-06-28 — v3.8.40

OmniRoute سه رابط متفاوت مرتبط با عاملها ارائه میدهد. این رابطها در نگاه اول مشابه به نظر میرسند، اما مسائل متفاوتی را حل میکنند. برای انتخاب گزینه مناسب از این صفحه استفاده کنید.

## خلاصه

| رابط                          | بهترین کاربرد                                                                                                           | انتقال                        | استاندارد             |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------- | ----------------------------- | --------------------- |
| **A2A — عاملبهعامل**          | همکاری میان عاملها با عاملهای همتایی که از پروتکل A2A پشتیبانی میکنند                                                   | JSON-RPC 2.0 روی HTTP         | A2A v0.3 (مشخصات باز) |
| **ACP — رجیستری عاملهای CLI** | شناسایی / ثبت / اجرای عاملهای کدنویسی CLI نصبشده روی دستگاه کاربر (Cursor، Cline، Codex CLI، Claude Code، Aider و غیره) | HTTP REST                     | مختص OmniRoute        |
| **عاملهای ابری**              | ارسال وظایف کدنویسی طولانیمدت به سرویسهای ابری خارجی (Codex Cloud، Devin، Jules، Cursor Cloud)                          | HTTP REST + وظایف مبتنی بر DB | مختص OmniRoute        |

این سه مورد مستقل از یکدیگرند — میتوانید هر ترکیبی از آنها را انتخاب کنید.

## درخت تصمیم

```
آیا برای انجام کار خارج از این دستگاه به یک سرویس ابری نیاز دارید (Codex Cloud / Cursor Cloud / Devin / Jules)؟
├─ بله → عاملهای ابری (POST /api/v1/agents/tasks)
└─ خیر → ادامه دهید
    │
    آیا عامل همتایی دارید که از A2A پشتیبانی کند و بخواهد همکاری کند؟
    ├─ بله → A2A (POST /a2a)
    └─ خیر → ادامه دهید
        │
        آیا باید عاملهای کدنویسی CLI نصبشده بهصورت محلی را فهرست / پیکربندی کنید؟
        ├─ بله → ACP (GET /api/acp/agents)
        └─ خیر → از /v1/chat/completions ساده استفاده کنید
```

## 1. A2A — عاملبهعامل

**مشخصات:** [A2A v0.3](https://a2a-protocol.org)
**نقطه پایانی OmniRoute:** `POST /a2a` (JSON-RPC 2.0)
**کارت عامل:** `GET /.well-known/agent.json`

### چه زمانی استفاده شود

- ساخت یک سامانه چندعاملی که OmniRoute یکی از عاملهای همتای آن است
- ارائه هوشمندی مسیریابی OmniRoute (مسیریابی هوشمند، مدیریت سهمیه و غیره) به عاملهای موجود در چارچوبهایی مانند Google ADK یا شبکههای عمومی عاملها
- قراردادن OmniRoute پشت یک رابط استاندارد برای کشف و فراخوانی

### متدها

- `message/send` — ارسال یک پیام و دریافت پاسخ همگام
- `message/stream` — ارسال پیام و دریافت رویدادهای پیشرفت بهصورت جریان SSE
- `tasks/get` — خواندن وظیفه براساس شناسه
- `tasks/cancel` — لغو یک وظیفه در حال اجرا

### مهارتهای داخلی (6)

- `smart-routing` — مسیریابی یک پرامپت از طریق ترکیب بهینه
- `quota-management` — گزارش وضعیت سهمیه هر ارائهدهنده
- `provider-discovery` — فهرستکردن ارائهدهندگان نصبشده همراه با قابلیتهای آنها
- `cost-analysis` — برآورد هزینه یک درخواست/مکالمه
- `health-report` — تجمیع وضعیت قطعکننده مدار/دوره انتظار/قفلشدگی برای هر ارائهدهنده
- `list-capabilities` — فهرستکردن مهارتها و فرادادههای موجود عامل

### بررسی عمیق

برای جزئیات انتقال، ساختار کارت عامل، پیکربندی TTL وظایف و الگوی افزودن مهارتهای جدید، به [A2A-SERVER.md](./A2A-SERVER.md) مراجعه کنید.

## 2. ACP — رجیستری عاملهای CLI

**نقطه پایانی OmniRoute:** `GET /api/acp/agents`
**منبع:** `src/lib/acp/{index,manager,registry}.ts`

### چیست

ACP، **فهرست محلی عاملهای CLI** در OmniRoute است. این بخش تشخیص میدهد کدام CLIهای کدنویسی روی میزبان نصب شدهاند (Cursor، Cline، Claude Code، Codex CLI، Continue و غیره)، نسخههای آنها را شناسایی میکند و آنها را در داشبورد نمایش میدهد تا کاربر بتواند هر CLI را برای اتصال به OmniRoute تنظیم کند.

این یک پروتکل خارجی نیست — بلکه رجیستری داخلیای است که رابط کاربری «ابزارهای CLI» و ردیابی اثر انگشت CLI را پشتیبانی میکند (به [CLI-TOOLS.md](../reference/CLI-TOOLS.md) مراجعه کنید).

### چه کاری انجام میدهد

- میزبان را برای یافتن باینریهای CLI نصبشده بررسی میکند (بسته به سیستمعامل از `which` / `where` استفاده میکند)
- نسخه هر CLI را میخواند (`<bin> --version` را فراخوانی میکند)
- بهصورت اختیاری عاملهای سفارشی تعریفشده توسط کاربر را میپذیرد (مسیر باینری + بررسی نسخه + آرگومانهای اجرا)
- عاملهای سفارشی را در تنظیمات ذخیره میکند
- فهرست یکپارچه را به داشبورد بازمیگرداند

### API REST

| نقطه پایانی       | متد  | توضیحات                                                               | احراز هویت |
| ----------------- | ---- | --------------------------------------------------------------------- | ---------- |
| `/api/acp/agents` | GET  | فهرست عاملهای شناساییشده + سفارشی (تعداد نصبشده/کل)                   | کلید API   |
| `/api/acp/agents` | POST | افزودن/بهروزرسانی/حذف عامل سفارشی (تمایزدهنده عملیات در بدنه درخواست) | کلید API   |

ساختار بدنه برای POST (`customAgentBodySchema` در `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### موارد استفاده

- صفحه «ابزارهای CLI» در داشبورد، موارد نصبشده را فهرست میکند و برای اتصال هرکدام به OmniRoute به شما کمک میکند
- عاملهای سفارشی به کاربران حرفهای اجازه میدهند CLIهای داخلی/اختصاصیای را ثبت کنند که OmniRoute بهصورت پیشفرض آنها را نمیشناسد
- نتیجه شناسایی، ماتریس اثر انگشت `cli-tools` را تغذیه میکند

### چه زمانی نباید از ACP استفاده کرد

- ACP وظایف را _اجرا_ نمیکند. فقط CLIها را شناسایی و پیکربندی میکند. برای فراخوانی واقعی یک CLI، باید خودتان آن را با متغیرهای محیطی ارائهشده توسط OmniRoute اجرا کنید (`OPENAI_BASE_URL`، `OPENAI_API_KEY` و غیره).

## 3. عاملهای ابری

**نقاط پایانی OmniRoute:** `/api/v1/agents/tasks/*` (چرخه حیات) + `/api/cloud/*` (زیرساخت اتصال)
**منبع:** `src/lib/cloudAgent/`

### چیست

یک رابط یکپارچه برای عاملهای کدنویسی ابری شخص ثالث است. شما یک پرامپت + نشانی URL مخزن ارسال میکنید، OmniRoute آن را به عامل ابری مناسب میسپارد، وضعیت را بهصورت دورهای بررسی میکند و نتایج را بازمیگرداند.

### عاملهای پشتیبانیشده (4 مورد، همگی در `src/lib/cloudAgent/agents/` تأیید شدهاند)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### چرخه حیات

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() برای هر کلاس عامل
  → سرویس خارجی کار را آغاز میکند
  → ردیف وظیفه در پایگاه داده ایجاد میشود (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → همگامسازی تنبل وضعیت از ارائهدهنده
  → وضعیت فعلی + برنامه + گزارش فعالیت را بازمیگرداند
  ↓
POST /api/v1/agents/tasks/[id]   (عملیات: "approve" | "message" | "cancel")
  → درخواست را به ارائهدهنده هدایت میکند (یا بهصورت محلی لغوشده علامت میزند)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → لغو محلی
```

### احراز هویت

⚠️ **همه نقاط پایانی `/api/v1/agents/tasks/*` به احراز هویت مدیریتی نیاز دارند** (کامیت `588a0333`). فراخوانهایی که فقط از Bearer استفاده میکنند، از نسخه v3.8.0 به بعد پاسخ 401 دریافت میکنند.

### بررسی عمیق

برای قرارداد `CloudAgentBase`، جزئیات ویژه هر عامل، جزئیات شِما و نقاط پایانی زیرساخت اعتبارنامهها، به [CLOUD_AGENT.md](./CLOUD_AGENT.md) مراجعه کنید.

## مقایسه: A2A در برابر Cloud Agents

هر دو دارای «وظایف طولانیمدت» هستند، اما در لایههای متفاوت:

| جنبه             | A2A                                                                                        | Cloud Agents                           |
| ---------------- | ------------------------------------------------------------------------------------------ | -------------------------------------- |
| استاندارد        | Open A2A v0.3                                                                              | مختص OmniRoute                         |
| محل اجرای پردازش | داخل OmniRoute (با استفاده از ترکیبهای پیکربندیشده)                                        | خارجی (سرورهای Codex / Devin / Jules)  |
| مدتزمان وظیفه    | TTL پیشفرض ۵ دقیقه (قابل پیکربندی در `TaskManager`)                                        | از چند دقیقه تا چند ساعت               |
| آگاه از مخزن     | خیر (فقط پرامپتها را ارسال میکند)                                                          | بله (URL مخزن + شاخه)                  |
| مورد استفاده     | همکاری میان عاملها، مسیریابی هوشمند بهعنوان سرویس                                          | واگذاری «پیادهسازی قابلیت X در مخزن Y» |
| احراز هویت       | `OMNIROUTE_API_KEY` اختیاری برای `/a2a`؛ دسترسی مدیریتی برای ابزارهای REST در `/api/a2a/*` | همیشه نیازمند دسترسی مدیریتی           |

## نمونههای یکپارچهسازی

### کشف قابلیتهای A2A در OmniRoute

```bash
curl http://localhost:20128/.well-known/agent.json
```

کارت عامل را همراه با هر ۶ مهارت، انتقالها و نسخه برمیگرداند.

### فراخوانی OmniRoute بهعنوان یک عامل A2A

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### فهرستکردن عاملهای CLI نصبشده از طریق ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### افزودن یک عامل CLI سفارشی

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### ارسال یک وظیفه Cloud Agent

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### بررسی دورهای وضعیت وظیفه ابری

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## چه زمانی از کدام گزینه استفاده کنیم

- **رابط کاربری چتبات / دستیار** ← `/v1/chat/completions` (سازگار با OpenAI — نه یک پروتکل عامل)
- **همکاری چندعاملی** ← A2A
- **فهرستکردن CLIهای محلی در داشبورد** ← ACP
- **واگذاری وظایف طولانیمدت برنامهنویسی به سرویسهای ابری** ← Cloud Agents
