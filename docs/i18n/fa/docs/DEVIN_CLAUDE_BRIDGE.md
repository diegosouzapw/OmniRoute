`devin-cli-agentic` به محیط اجرای واقعی Claude Code اجازه میدهد از نقطه پایانی محلی Anthropic
Messages در OmniRoute استفاده کند، درحالیکه Devin CLI رسمی پاسخهای مدل را از طریق ACP stdio ارائه میدهد. این
ارائهدهندههای موجود Anthropic، Claude OAuth، Claude Web یا `devin-cli` را تغییر نمیدهد.

> **وضعیت فعلی: Claude Code روی نسخه `2.1.258` تثبیت شده است؛ آخرین اعتبارسنجی آفلاین و زنده
> روی نسخه `2.1.220` ثبت شده است.** نسخه تثبیتشده `2.1.220` سه سناریوی ایزوله را از طریق Devin CLI
> `3000.2.17` و مدل `swe-1-7-lightning` تکمیل کرد؛ آن اجرای زنده نهایی، نوبتهای `Read`،
> `Edit` و `Bash` تحت مالکیت کلاینت، نتایج موفق `npm test`، کشف فرمانها و مهارتهای
> پروژه، مسیریابی صرفاً از طریق Devin و نبود هرگونه خروجی شبکه به Claude را اثبات کرد. سپس نسخه تثبیتشده به `2.1.258`
> ارتقا یافت (نسلی از CLI که هویت Claude در OmniRoute از آن تقلید میکند و نخستین شاخهای است که
> سطح Fable 5.1 را بهصورت بومی عرضه میکند). روی نسخه تثبیتشده جدید، لایه نصب و `claude --version`
> در تصویر پایه تثبیتشده تأیید شدند و مجموعه آزمون واحد پل، `compose config` و
> اثبات ایستای ایزولهسازی با موفقیت اجرا میشوند — اما سناریوی ساختگی آفلاین و مجموعه زنده سهسناریویی
> هنوز دوباره اجرا نشدهاند. پیش از اتکا به پل با این نسخه تثبیتشده، آنها را دوباره اجرا کنید
> (به بخش «بهروزرسانی ابزارهای تثبیتشده» مراجعه کنید).

## معماری

```text
Claude Code 2.1.258 (کانتینر ایزوله لینوکس با کاربر غیر root)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (ارائهدهنده با قالب Claude و بدون احراز هویت)
  -> devin acp --agent-type summarizer (ACP stdio رسمی، بدون ابزارهای Devin)
  -> حساب Devin در والیوم اختصاصی devin-auth
```

عامل پیشفرض ACP در CLI رسمی میتواند ابزارهای خودش را اجرا کند، بنابراین این پل از
آن استفاده نمیکند. پل عامل ثابت `summarizer` در ACP را راهاندازی میکند که حالت CLI رسمی آن هیچ ابزاری ندارد و
درخواست سریالشده Anthropic را بهصورت رد اجرای عملیات قالببندی میکند. هنگامی که اقدام دیگری تحت مالکیت Claude
لازم باشد، پاسخ باید دقیقاً شامل یک پاکت ابزار کلاینت باشد. هرگونه
`tool_call` یا `tool_call_update` مربوط به ACP، پیش از آنکه پاسخی بتواند موفق گزارش شود، رد میشود.

سریالساز در `open-sse/executors/devin-agentic/serializer.ts` موارد `system`،
`text`، `tool_use`، `tool_result`، `thinking`، `redacted_thinking`، `tool_choice` و ابزارهای
ارائهشده توسط Claude Code را حفظ میکند. تصاویر و بلوکهای ناشناخته صراحتاً با شکست مواجه میشوند. نتایج بزرگ ابزار
از یک نشانگر قابلمشاهده کوتاهسازی استفاده میکنند.

تجزیهگر در هر نوبت مدل، یک پاکت مستقل `<tool>{...}</tool>` را میپذیرد. این تجزیهگر
نام را با فهرست ابزارهای درخواست تطبیق میدهد، آرگومانها را بر اساس JSON
Schema آن ابزار اعتبارسنجی میکند، روایت/اقدامهای ترکیبی را رد میکند و اجازه یک ترمیم محدود را میدهد. سپس Claude Code
`tool_use` حاصل از Anthropic را بهصورت محلی اجرا میکند و `tool_result` را از طریق
OmniRoute بازمیفرستد.

## ایزولهسازی و مدل تهدید

نصب، حساب و پیکربندی Claude روی میزبان خارج از محدوده هستند و ممنوع تلقی میشوند.
سرویسهای Compose:

- با UID/GID برابر با `10001:10001`، فایلسیستم ریشه فقطخواندنی، قابلیتهای حذفشده و
  `no-new-privileges` اجرا میشوند؛
- از یک `/home/bridge` خصوصی، یک والیوم اختصاصی پیکربندی Claude، دادههای ایزوله OmniRoute
  و یک والیوم جداگانه `devin-auth` استفاده میکنند؛
- فقط فضاهای کاری/شواهد یکبارمصرف `.sandbox` را mount میکنند؛
- پوشه خانگی میزبان، Keychain، SSH، اعتبارنامههای ابری یا سوکت Docker را mount نمیکنند؛
- محیطها را بهصورت صریح میسازند و متغیرهای API/OAuth/مسیریابی Anthropic را حذف میکنند؛
- استنتاج Claude Code را فقط با یک کلید صرفاً محلی به `http://omniroute:20128` هدایت میکنند.

پروفایل آفلاین از یک شبکه داخلی استفاده میکند. در پروفایل زنده، OmniRoute فقط از طریق
`network-guard` به نقاط پایانی رسمی Devin دسترسی پیدا میکند؛ مقصدهای نامرتبط رد میشوند.
Claude Code یک محافظ خروجی جداگانه با سیاست رد همه دارد و فقط از طریق `NO_PROXY` میتواند به سرویس محلی OmniRoute
دسترسی پیدا کند. فایلهای ممیزی محافظها فقط توسط فرایند محافظ مربوطه mount میشوند.
اسکریپتها پیش از خروجیگرفتن از شواهد عاری از توکن، مالکیت فایل، حالت، تعداد پیوندها و تمام تصمیمها را
بررسی میکنند.

اثبات ایزولهسازی را بهصورت مستقل اجرا کنید:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

این اسکریپت توپولوژی، mountهای نامگذاریشده، تنظیمات کاربر غیر root/فقطخواندنی، مسیریابی محلی صریح،
نبود متغیرهای محیطی حساس، نبود سوکت Docker، مسدود بودن دسترسی به
`api.anthropic.com` و `claude.ai`، انتخاب ارائهدهنده صرفاً از طریق Devin و شکست صریح در صورت
در دسترس نبودن بکاند ACP را اعتبارسنجی میکند.

## راهاندازی اولیه و استفاده معمول

ایمیج پینشده را بسازید:

```bash
./scripts/devin-bridge/build
```

فقط volume ایزولهشده Devin را احراز هویت کنید:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

فرمان ورود از فرایند رسمی توکن دستی که برای محیطهای راهدور/container در نظر گرفته شده است استفاده میکند. مقدار مستقیماً در اعلان CLI وارد میشود؛ این مقدار بهعنوان آرگومان پردازش ارسال نمیشود، در Git نوشته نمیشود و از میزبان کپی نمیشود.

محیط اجرای ایزولهشده Claude Code را راهاندازی کنید:

```bash
./scripts/devin-bridge/launch
```

`launch` پیش از شروع Claude Code کانتینریشده، ایزولهسازی، احراز هویت Devin و کشف مدل را دوباره بررسی میکند. این فرمان هرگز فایل اجرایی Claude میزبان را اجرا نمیکند. نامهای مستعار مدل را میتوان در `.env.devin-bridge` تنظیم کرد؛ هر مقدار پیکربندیشده باید پیشوند `devin-cli-agentic/` را حفظ کند.

## فرمانهای اعتبارسنجی

مسیر آفلاینِ بازتولیدپذیر به حساب Devin نیاز ندارد و هنگام اجرا به اینترنت متصل نمیشود:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

مسیر زنده و احراز هویتشده که باید صریحاً فعال شود، بهشکل زیر است:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

اجراکننده زنده برای جلوگیری از باز کردن ناگهانی چندین نشست ACP، بین سناریوها منتظر میماند و بهجای اعتماد به ادعاهای متنی، رویدادهای ساختاریافته جریان Claude را اعتبارسنجی میکند. سه سناریوی آن موارد زیر را اثبات میکنند:

1. خواندن مستقیم پروژه و تحلیل نقصها؛
2. یک `Edit` واقعی، اجرای `npm test` از طریق `Bash` تحت مالکیت کلاینت و یک نتیجه نهایی؛
3. اجرای `/bridge-check` بههمراه کشف `bridge-proof`، خواندن پروژه، اجرای موفقیتآمیز دیگری از `npm test` تحت مالکیت کلاینت و تکمیل بدون کار معلق.

گیت نهایی همچنین ممیزی شبکه Devin را بررسی میکند و لازم میداند ممیزی خروجی شبکه Claude خالی باقی بماند.

## بهروزرسانی ابزارهای پینشده

نسخههای Node، Claude Code و Devin CLI در `docker/devin-bridge/Dockerfile` پین شدهاند. برای بهروزرسانی:

1. نسخههای صریح را تغییر دهید؛
2. هر دو checksum آرشیو Devin مخصوص معماری را با مقادیر مربوط به artifact رسمی جایگزین کنید؛
3. ایمیج را دوباره بسازید و همه فرمانهای اعتبارسنجی آفلاین را اجرا کنید؛
4. نسخهها را درون ایمیج تأیید کنید؛
5. مجموعه زنده سهسناریوییِ احراز هویتشده را دوباره اجرا کنید.

هیچیک از CLIها را بهصورت سراسری روی میزبان نصب نکنید و اعتبارسنجی checksum را با دانلودی تأییدنشده جایگزین نکنید.

## عیبیابی و پاکسازی

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  مسیریابی محلی و خطاهای پاکسازیشده اجراکننده را نمایش میدهد.
- `.sandbox/evidence/mock-acp.jsonl` اقدامات قطعی mock ACP را ثبت میکند.
- `.sandbox/evidence/claude-stream.jsonl` اجرای آفلاین واقعی Claude Code را ثبت میکند.
- `.sandbox/evidence/live-*.jsonl` سه جریان زنده اعتبارسنجیشده را ثبت میکند.
- `.sandbox/evidence/egress.jsonl` و `.sandbox/evidence/claude-egress.jsonl` کپیهای اعتبارسنجیشده و بدون توکن از ممیزیهای محافظ هستند.

کانتینرها و شبکههای تحت مالکیت را متوقف کنید، درحالیکه volumeهای ورود/پیکربندی حفظ میشوند:

```bash
./scripts/devin-bridge/clean
```

کل محیط تحت مالکیت bridge، از جمله volumeهای نامگذاریشده، را حذف کنید:

```bash
./scripts/devin-bridge/clean --all
```

## محدودیتها

- پل به نقش ثابت و بدون ابزار `summarizer` متکی است، زیرا Devin CLI `3000.2.17`
  یک عامل ACP خنثی و بدون ابزار ارائه نمیکند. آداپتور پاسخهای میانی با ساختار خلاصهگونه را جبران
  میکند، اما یک تلاش اصلاحی محدود همچنان ممکن است صراحتاً شکست بخورد.
- فراخوانیهای زنده ACP ممکن است پاسخهای گذرای `502`/`504` برگردانند. هارنس بین سناریوها فاصله ایجاد میکند؛
  شکست پایدار همچنان بهصورت fail-closed باقی میماند و هرگز ارائهدهندهٔ دیگری را انتخاب نمیکند.
- زمینهٔ ACP از هر درخواست Anthropic بازسازی میشود؛ هیچ وابستگی به فرایند/نشست
  وجود ندارد.
- در هر پاسخ مدل، یک فراخوانی ابزار پشتیبانی میشود؛ فراخوانیهای موازی رد میشوند.
- تصاویر صراحتاً پشتیبانی نمیشوند. قابلیت بینایی، خروجی تفکر، کنترلهای effort و پنجرهٔ زمینهٔ 1M
  اعلام نمیشوند.
- SSE از رویدادهای چرخهٔ عمر معتبر Anthropic استفاده میکند، اما پس از جمعآوری نوبت محدود ACP منتشر
  میشود؛ قطعههای ACP بهصورت افزایشی ارسال نمیشوند.
