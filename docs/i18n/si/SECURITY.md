## ආරක්ෂක ගෘහනිර්මාණය

OmniRoute බහු-ස්තර ආරක්ෂක ආකෘතියක් ක්රියාත්මක කරයි:

```
ඉල්ලීම → CORS → Authz නළ මාර්ගය (වර්ගීකරණය → ප්රතිපත්ති → බලාත්මක කිරීම)
       → ආරක්ෂණ සීමා (PII ආවරණය, ප්රේරක එන්නත් කිරීම, දෘශ්ය පාලම)
       → අනුපාත සීමාකරු → පරිපථ බිඳුම → සිසිලන කාලය → ආකෘති අගුලු දැමීම → සැපයුම්කරු
```

### 🛡️ ගබඩා කළ දත්තවල සංකේතනය

SQLite තුළ ගබඩා කර ඇති සියලු සංවේදී දත්ත, scrypt යතුරු ව්යුත්පන්න කිරීම සමඟ **AES-256-GCM** භාවිතයෙන් සංකේතනය කර ඇත:

- API යතුරු, ප්රවේශ ටෝකන, නැවුම් කිරීමේ ටෝකන සහ ID ටෝකන
- අනුවාදිත ආකෘතිය: `enc:v1:<iv>:<ciphertext>:<authTag>`
- `STORAGE_ENCRYPTION_KEY` සකසා නොමැති විට Passthrough ප්රකාරය (සරල පෙළ)

```bash
# සංකේතන යතුරක් ජනනය කරන්න:
STORAGE_ENCRYPTION_KEY=$(openssl rand -hex 32)
```

`block` ප්රකාරයේදී අවහිර කරනු ලබන්නේ **ඉහළ** බරපතළභාවයකින් යුතු හඳුනාගැනීම් පමණි. මධ්යම බරපතළභාවයේ
කාණ්ඩ ලොග් කරන නමුත් `sanitizeRequest` මඟින් කිසිවිටෙක අවහිර නොකෙරේ.

උපකරණ පුවරුව (Settings → Security) හෝ `.env` හරහා වින්යාස කරන්න:

```env
INPUT_SANITIZER_ENABLED=true
INPUT_SANITIZER_MODE=block    # අනතුරු අඟවන්න | අවහිර කරන්න (ඇතුළු කිරීමේ ප්රතිපත්තිය; පැරණි "redact" මඟින් ඇතුළු කළ පෙළ ඉවත් නොකෙරේ)
INPUT_SANITIZER_BLOCK_THRESHOLD=high  # ඉහළ (පෙරනිමි) | මධ්යම | අඩු — මෙම මට්ටමේ හෝ ඊට ඉහළ බරපතළභාවයන් අවහිර කිරීමේ ප්රකාරයේදී අවහිර කෙරේ
```

## අවශ්ය පරිසර විචල්ය

සේවාදායකය ආරම්භ කිරීමට පෙර සියලුම රහස් අගයන් සකසා තිබිය යුතුය. ඒවා නොමැති නම් හෝ දුර්වල නම් සේවාදායකය **වහාම අසාර්ථක වනු ඇත**.

```bash
# අනිවාර්යයි — මේවා නොමැතිව සේවාදායකය ආරම්භ නොවේ:
JWT_SECRET=$(openssl rand -base64 48)     # අවම වශයෙන් අක්ෂර 32ක්
API_KEY_SECRET=$(openssl rand -hex 32)    # අවම වශයෙන් අක්ෂර 16ක්

# නිර්දේශිතයි — ගබඩා කර ඇති දත්ත සංකේතනය සක්රීය කරයි:
STORAGE_ENCRYPTION_KEY=$(openssl rand -hex 32)
```

සේවාදායකය `changeme`, `secret`, හෝ `password` වැනි දන්නා දුර්වල අගයන් සක්රීයව ප්රතික්ෂේප කරයි.

## Docker ආරක්ෂාව

- නිෂ්පාදන පරිසරයේදී root නොවන පරිශීලකයෙකු භාවිත කරන්න
- රහස් කියවීමට පමණක් හැකි වෙළුම් ලෙස සවිකරන්න
- `.env` ගොනු කිසිවිටෙක Docker images තුළට පිටපත් නොකරන්න
- සංවේදී ගොනු බැහැර කිරීමට `.dockerignore` භාවිත කරන්න
- HTTPS පසුපස ක්රියාත්මක වන විට `AUTH_COOKIE_SECURE=true` ලෙස සකසන්න

```bash
docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --read-only \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  -e JWT_SECRET="$(openssl rand -base64 48)" \
  -e API_KEY_SECRET="$(openssl rand -hex 32)" \
  -e STORAGE_ENCRYPTION_KEY="$(openssl rand -hex 32)" \
  diegosouzapw/omniroute:latest
```

## පරායත්තතා

- `npm audit` නිතිපතා ධාවනය කරන්න (`npm run audit:deps` ප්රධාන + electron ආවරණය කරයි)
- පරායත්තතා යාවත්කාලීනව තබාගන්න
- පෙර-commit පරීක්ෂණ සඳහා ව්යාපෘතිය `husky` + `lint-staged` භාවිත කරයි (lint-staged + check-docs-sync + check:any-budget:t11)
- සෑම push කිරීමකදීම CI pipeline එක ESLint ආරක්ෂක නීති ධාවනය කරයි (`no-eval`, `no-implied-eval`, `no-new-func` = දෝෂයකි)
- මොඩියුලය පූරණය වන විට Zod හරහා සපයන්නාගේ නියතයන් වලංගු කෙරේ (`src/shared/validation/schemas.ts`)
- පෙරනිමියෙන් ආරක්ෂිත පුස්තකාල භාවිත කෙරේ: `dompurify` / `isomorphic-dompurify` (XSS), `jose` (JWT), `better-sqlite3` (පරාමිතික විමසුම් නිසා SQLi අවදානමක් නොමැත), `bcryptjs` (මුරපද hash කිරීම)

## දැඩි ආරක්ෂක නීති

මෙම නීති මෙවලම් සහ සමාලෝචකයන් විසින් බලාත්මක කරනු ලැබේ:

1. **කිසිවිටෙක රහස් commit නොකරන්න** — `.env` gitignore කර ඇත; `.env.example` යනු අච්චුවයි (literal අගයන් නොමැත, අදහස් පමණි — පහත PUBLIC_CREDS.md බලන්න)
2. **කිසිවිටෙක `eval()`, `new Function()`, හෝ implied eval භාවිත නොකරන්න** — ESLint මෙය බලාත්මක කරයි
3. **පැහැදිලි ක්රියාකරු අනුමැතියකින් තොරව කිසිවිටෙක Husky hooks මඟ නොහරින්න** (`--no-verify`, `--no-gpg-sign`)
4. **routes තුළ කිසිවිටෙක raw SQL නොලියන්න** — සැමවිටම `src/lib/db/` හරහා යන්න (පරාමිතික)
5. **සැමවිටම Zod සමඟ ආදාන වලංගු කරන්න** — `src/shared/validation/schemas.ts`
6. **සැමවිටම upstream headers පිරිසිදු කරන්න** — ප්රතික්ෂේප ලැයිස්තුව `src/shared/constants/upstreamHeaders.ts` තුළ ඇත
7. **ගබඩා කර ඇති අක්තපත්ර සංකේතනය කරන්න** — `src/lib/db/encryption.ts` හරහා AES-256-GCM
8. **`resolvePublicCred()` හරහා පොදු upstream OAuth හඳුනාගැනීම් භාවිත කරන්න** — `AIza…` / `GOCSPX-…` / `…apps.googleusercontent.com` literal අගයන් කිසිවිටෙක source තුළ කාවද්දන්න එපා. [`docs/security/PUBLIC_CREDS.md`](docs/security/PUBLIC_CREDS.md) බලන්න.
9. **`buildErrorBody()` / `sanitizeErrorMessage()` හරහා දෝෂ ප්රතිචාර යවන්න** — raw `err.stack` / `err.message` කිසිවිටෙක HTTP / SSE / executor / MCP ප්රතිචාර අන්තර්ගතයන් තුළ නොතබන්න. [`docs/security/ERROR_SANITIZATION.md`](docs/security/ERROR_SANITIZATION.md) බලන්න.
10. **`env` විකල්පය හරහා `exec()` / `spawn()` runtime අගයන් ලබා දෙන්න** — බාහිර paths හෝ විශ්වාස නොකළ අගයන් shell වෙත යැවෙන scripts තුළට කිසිවිටෙක string-interpolate නොකරන්න. යොමුව: `src/mitm/cert/install.ts::updateNssDatabases`.
11. **පෙරනිමියෙන් ආරක්ෂිත පුස්තකාලවලට ප්රමුඛත්වය දෙන්න** — [tldrsec/awesome-secure-defaults](https://github.com/tldrsec/awesome-secure-defaults) බලන්න (Helmet.js, DOMPurify, ssrf-req-filter, safe-regex, Google Tink). ඔබේම විසඳුමක් නිර්මාණය කිරීමට පෙර ඒවා භාවිත කරන්න.
