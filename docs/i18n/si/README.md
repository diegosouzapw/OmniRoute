## 💰 මසකට නොමිලේ ටෝකන ~1.47B

</div>

> නොමිලේ ලබාදෙන ස්තර අතින් එකතු කිරීම වෙහෙසකරයි — SDK දුසිම් ගණනක්, අනුපාත සීමා දුසිම් ගණනක්, සහ ඔබට ඇත්ත වශයෙන්ම කොපමණ ප්රමාණයක් තිබේදැයි කිසිදු අදහසක් නැත. OmniRoute විසින් **නැවත නැවත ලැබෙන pool key 34ක් පුරා නොමිලේ-ස්තර ඇතුළත් කිරීම් 452ක්** නාමාවලියට ඇතුළත් කරන අතර, බෙදාගත් pool අනුව අනුපිටපත් ඉවත් කර, **ප්රකාශිත ධනාත්මක මාසික අයවැයක් සහිත pool 16ක් සහ එක් එක් මාදිලිය සඳහා Groq සීමා පහක්** මත පදනම්ව ප්රධාන ටෝකන සංඛ්යාව ගණනය කරයි. කලාපීය අනන්යතා පරීක්ෂාවකින් පසුව පමණක් විවෘත වන කෝටා (අද වන විට: ModelScope) වෙනම පෙන්වනු ලබයි; කලාපීය අනන්යතා සත්යාපනය පිටුපස +~6Mක් ඇති අතර, ඒවා කිසිවිටෙක ප්රධාන සංඛ්යාවට එකතු නොකෙරේ. ප්රතිඵලය උපකරණ පුවරුවේ (`/dashboard/free-tiers`) දිගටම දෘශ්යමාන වේ.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute නොමිලේ-ස්තර අයවැය කාඩ්පත: ස්ථාවරව මසකට නොමිලේ ටෝකන ~1.47Bක්, ලියාපදිංචි වීමේ ක්රෙඩිට් සමඟ පළමු මාසයේදී ~2.07Bක් දක්වා; එක් endpoint එකක් පිටුපස නාමාවලියට ඇතුළත් කළ නොමිලේ-ස්තර ඇතුළත් කිරීම් 452ක් ආවරණය කරන ලේඛනගත නැවත නැවත ලැබෙන pool key 34කින්. අවංක, pool අනුව අනුපිටපත් ඉවත් කළ ගණනය — ප්රකාශිත ධනාත්මක මාසික ටෝකන අයවැයක් සහිත නැවත නැවත ලැබෙන pool 16ක් සහ එක් එක් මාදිලිය සඳහා Groq සීමා පහක් ඇතුළුව, බෙදාගත් සෑම pool එකක්ම එක් වරක් පමණක් ගණන් කෙරේ; සැපයුම්කරුවන් 13 දෙනෙකු නියමයන්-අවදානම් නාමාවලියේ මඟහැරිය යුතු ලෙස සලකුණු කර ඇති බැවින් තීරණය ඔබ සතුය. අයවැය තීරුවට Mistral 1B, Nara 210M, LLM7 150M, Groq 30M (එක් එක් මාදිලිය සඳහා සීමා පහක්) සහ කුඩා pool ඇතුළත් වන අතර, ප්රධාන සංඛ්යාව කෘත්රිමව වැඩි නොවන පරිදි පළමු මාසයේ ලියාපදිංචි වීමේ ක්රෙඩිට් සහ ස්ථිරව නොමිලේ ලැබෙන ටෝකන-සීමාවක්-නොමැති සැපයුම්කරුවන් වෙනම පෙන්වයි. සජීවී භාවිත කළ/ඉතිරි ප්රමාණය /dashboard/free-tiers හි."/>

## 📡 OmniRoute Radar

ප්රලේඛනගත කර ඇති, ඉහත pool-අනුපිටපත් ඉවත් කළ නාමාවලියෙන් ලැබෙන ප්රධාන නොමිලේ-ස්ථර අගය තවමත් **~1.47B tokens/month** වේ. තාවකාලික සැපයුම්කරු ලියාපදිංචි වීමේ බැර මඟින් පළමු මාසයේ අගය වෙනමම **~2.10B** දක්වා ඉහළ නැංවිය හැක. Radar යනු OmniRoute නිකුතු අතරතුර වඩාත් යාවත්කාලීන නොමිලේ-මාදිලි ලබාගත හැකි බව අවශ්ය පුද්ගලයන් සඳහා වන විකල්ප, අත්සන් කළ නාමාවලි අතිපිහිතයකි; ප්රජා නාමාවලිය සහ දැනට පවතින සෑම නොමිලේ විශේෂාංගයක්ම නොමිලේම පවතී.

සහායකයන්ට සජීවී නාමාවලිය සහ අමතර සැපයුම්කරු අවස්ථා ලබාගත හැක. එහි වෙනම, වෙනස් විය හැකි උපරිම සීමාව සැපයුම්කරුගේ ලබාගත හැකි බව අනුව **උපරිම වශයෙන් ආසන්න වශයෙන් 3B tokens/month** වේ. එම සීමාව සහතිකයක් නොවේ: සැපයුම්කරුවන්ට ඕනෑම වේලාවක කෝටා, සුදුසුකම්, මාදිලි හෝ කලාප වෙනස් කළ හැක.

Radar සඳහා සහභාගී වීම විකල්ප වන අතර එය GET සඳහා පමණි. OmniRoute සේවාලාභියා prompts, traffic, සැපයුම්කරු වින්යාසය, usage telemetry, හෝ දේශීය නිවේදන-ඉවතලීමේ තත්ත්වය උඩුගත නොකරයි. සුදුසුකම් සහ වත්මන් නාමාවලිය පිළිබඳ **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)** වෙතින් දැනගන්න.

omniroute doctor        # සැපයුම්කරුවන්, ports සහ native dependencies රෝග නිර්ණය කරන්න

OmniRoute සේවාදායකයක තිබේද? **එම CLI එකම** භාවිතයෙන් ඔබේ ලැප්ටොප් පරිගණකයෙන් එය මෙහෙයවන්න. විෂයපථගත ප්රවේශ token එකක් සමඟ එක් වරක්
පිවිසෙන්න; ඉන්පසු සෑම විධානයක්ම දුරස්ථ පද්ධතිය ඉලක්ක කරයි.

```bash
omniroute connect 192.168.0.15            # මුරපදය → විෂයපථගත token එක, context එකක් ලෙස සුරැකේ
omniroute models list                     # ← දුරස්ථ සේවාදායකයට එරෙහිව ධාවනය වේ
omniroute configure codex                 # ← දුරස්ථ model එකක් තෝරා, දේශීය Codex profile එකක් ලියයි
omniroute tokens create --name ci --scope read   # වෙනත් යන්ත්ර සඳහා වඩාත් සීමිත tokens නිකුත් කරන්න
omniroute contexts use default            # ← නැවත දේශීය සේවාදායකයට මාරු වන්න
```

### 🎚️ එන්ජින්වලින් ඔබ්බට — ප්රතිදාන ශෛලීන්, අනුවර්තී ඩයලය සහ එක් එක් ඉල්ලීම සඳහා පාලනය

ඉහත එන්ජින් 12 මඟින් **ඇතුළට** යන දේ සංකුචිත කරයි. තවත් ස්තර තුනක් මඟින් **කෙසේද**, **කවදාද**, සහ **පිටතට** එන්නේ කුමක්ද යන්න හැඩගස්වයි:

- **🪄 ප්රතිදාන ශෛලීන්** _(ප්රතිදාන-අක්ෂ මෙහෙයවීම)_ — නිර්ණායක සහ cache-ආරක්ෂිත ප්රතිචාර-හැඩගැස්වීමේ උපදෙස් ඇතුළු කරයි; ඒවා එකිනෙක සමඟ සංයෝජනය කළ හැකි අතර, එක් එක් ශෛලියට `lite` / `full` / `ultra` තීව්රතාවක් ඇත. ශෛලියක් එක් කිරීම එක් පේළියක registry ඇතුළත් කිරීමක් පමණි:
  - **සංක්ෂිප්ත ගද්යය** — අනවශ්ය පිරවුම් / articles / අවිනිශ්චිත ප්රකාශ ඉවත් කරයි; තාක්ෂණික අන්තර්ගතය නිවැරදිව තබාගනී.
  - **අඩු කේත** — "කම්මැලි ජ්යෙෂ්ඨ සංවර්ධක" YAGNI: ඉල්ලා නොමැති අමතර ව්යුහ නොමැතිව, ක්රියාත්මක වන අවම වෙනස.
  - **Ponytail (කම්මැලි ජ්යෙෂ්ඨ සංවර්ධක)** — YAGNI පියගැට පෙළ ඉහළට ගොස්, මූලික හේතුව නිරාකරණය කර, ක්රියාත්මක වන කුඩාම diff එක ලබා දෙයි.
  - **මට ADHD තිබේ (ක්රියාව පළමුව)** — ඊළඟ ක්රියාව මුලින් දක්වයි, පියවර අංක කරයි, එක් නිශ්චිත ඊළඟ පියවරක් ලබා දෙයි, පෙරවදනක් නැත.
  - **සංක්ෂිප්ත CJK (文言)** — සම්භාව්ය-චීන අතිශය සංක්ෂිප්ත ශෛලිය (`zh` locale එකට පමණක් සීමා කර ඇත).
- **🎯 අනුවර්තී සන්දර්භ-අයවැය** _(ඩයලය)_ — එක් සක්රිය/අක්රිය ටෝකන සීමාවක් වෙනුවට, **ආකෘතියේ සන්දර්භ කවුළුවට ගැළපීමට** අවශ්ය ප්රමාණයට පමණක් අඩුම පිරිවැයක් සහ අවමම තොරතුරු අලාභයක් ඇති එන්ජින් ක්රමයෙන් යොදවයි. ප්රතිපත්තිය: `reserve-output` (පෙරනිමිය, ආකෘතිය-සැලකිල්ලට ගන්නා) · `percentage` · `absolute`. ආකාරය: `floor` (ගැළපීම සහතික කරයි) · `replace-autotrigger` (ඔබේ පැහැදිලි තේරීම ප්රමුඛ වේ) · `off` (පැරණි සීමාව).
- **🎛️ සංකුචනය තීරණය කරන ස්ථානය** _(ප්රමුඛතා අනුපිළිවෙළ, ඉහළ → පහළ)_ — එක් එක් ඉල්ලීමේ `x-omniroute-compression` header එක › routing-combo override එක › සක්රිය නම් කළ profile එක › අනුවර්තී / ස්වයංක්රීය ප්රේරණය › panel පෙරනිමිය › අක්රියයි. යෙදූ සැලැස්ම `X-OmniRoute-Compression: <mode>; source=<source>` ප්රතිචාර header එකෙන් නැවත පෙන්වයි.

ටෝකන සීමාව අනුව ස්වයංක්රීය ප්රේරණය කරන්න, අනුවර්තී ඩයලය සක්රිය කරන්න, නම් කළ profile එකක් ස්ථාවර කරන්න, එක් ඉල්ලීමක් සඳහා තාවකාලිකව සකසන්න, හෝ එක් එක් routing combo සඳහා pipeline එකක් පවරන්න — කාර්යභාරයට ගැළපෙන ක්රමය තෝරන්න. වෙනසක් ප්රවර්ධනය කිරීමට පෙර, විකල්පයෙන් සක්රිය කළ හැකි offline **ඇගයීම් පද්ධතියක්** (`npm run eval:compression`) ස්ථාවර corpus එකක් මත නිරවද්යතාව සහ ඉතිරිය සසඳා ලකුණු කරයි.

ඔබ සම්බන්ධ කළ ආකෘති ලැයිස්තුගත වී තිබිය යුතුය. 🎉 එපමණයි — coding ආරම්භ කරන්න; OmniRoute ඔබ වෙනුවෙන් ස්වයංක්රීයව route කර fallback භාවිත කරයි.

ඔබේ client එකට අභිරුචි headers යැවිය නොහැකි නම්, OmniRoute tokenized compatibility aliases ද සපයයි:

```txt
OpenAI නාමාවලිය:    http://localhost:20128/vscode/YOUR_KEY/
OpenAI ආකෘති:       http://localhost:20128/vscode/YOUR_KEY/models
OpenAI සංවාදය:      http://localhost:20128/vscode/YOUR_KEY/chat/completions
OpenAI ප්රතිචාර:    http://localhost:20128/vscode/YOUR_KEY/responses
Ollama සංවාදය:      http://localhost:20128/vscode/YOUR_KEY/api/chat
Ollama ටැග්:         http://localhost:20128/vscode/YOUR_KEY/api/tags
```

මේවා භාවිත කරන්නෙ `Authorization: Bearer ...` අමුණා යැවිය නොහැකි clients සඳහා පමණි. Header සත්යාපනය තවමත් නිර්දේශිත ආකාරයයි.

## 📦 තවත් ස්ථාපන ක්රම — Docker, source, pnpm, Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` ඉහළම **ප්රකාශිත** ස්ථාවර SemVer අනුව යාවත්කාලීන වේ. එය git `main` අනුගමනය නොකරයි. GitOps සඳහා `:X.Y.Z` නිශ්චිතව සඳහන් කරන්න. [Docker නිකුතු නාලිකා](docs/guides/DOCKER_GUIDE.md#release-channels) බලන්න.මෙම image එකෙහි **`OMNIROUTE_MEMORY_MB=1024`** නිශ්චිතව සකසා ඇත. එය dashboard එක සහ සැහැල්ලු chat එකක් සඳහා ප්රමාණවත් වේ. **Coding agents** (Claude Code, Codex, Grok, … වෙතින් `POST /v1/responses`) සඳහා වඩා විශාල V8 heap එකක් අවශ්ය වේ; එසේ නොමැතිව දිගු contexts දෙකක් එකිනෙක අතිච්ඡාදනය වන විට ~12 GiB දී process එක `FATAL ERROR` සමඟ අසාර්ථක වේ. Container එක heap එකට වඩා විශාල ලෙස සකසන්න (native buffers V8 වලින් පිටත පවතී):

| කාර්යභාරය                          | Heap (`-e OMNIROUTE_MEMORY_MB`) | Container (`--memory`) |
| ---------------------------------- | ------------------------------- | ---------------------- |
| Dashboard / සැහැල්ලු chat          | `1024` (image පෙරනිමිය)         | ≥2 g                   |
| එක් coding agent එකක්              | `8192`                          | ≥10 g                  |
| සමකාලීන දිගු `/v1/responses` දෙකක් | `10240`–`12288`                 | ≥12–16 g               |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

සම්පූර්ණ වගුව: [Docker මාර්ගෝපදේශය — runtime RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

> **පූර්ව-නිකුතු Docker නාලිකාව:** `diegosouzapw/omniroute:next` සහ
> `diegosouzapw/omniroute:next-web` වත්මන් පෙරනිමි `release/v*`

**🥟 Bun**

Bun runtime හඳුනාගැනීම හරහා සම්මත `bun install` සහ global ස්ථාපනය (`bun install -g omniroute`) සඳහා සහය දක්වයි:

- **අන්තර්ගත `bun:sqlite`**: Bun යටතේ ක්රියාත්මක වන විට OmniRoute විසින් Bun හි අන්තර්ගත `bun:sqlite` driver එක භාවිත කරන අතර, Node.js මතදී `better-sqlite3` හෝ `sql.js` වෙත යොමු වේ.
- **dev හි ස්වයංක්රීය Webpack bundler තේරීම**: Development (`bun run dev`) විසින් Bun ස්වයංක්රීයව හඳුනාගෙන native V8 binding නොගැළපීම් වැළැක්වීම සඳහා Turbopack අක්රිය කර Webpack භාවිත කරයි. Production builds (`bun run build`) Node මත මෙන්ම `OMNIROUTE_USE_TURBOPACK` නිශ්චිතවම අනුගමනය කරයි: පෙරනිමියෙන් Turbopack ද, Webpack සමඟ build කිරීමට `OMNIROUTE_USE_TURBOPACK=0` ද භාවිත වේ (`Dockerfile.bun` එය `--build-arg` එකක් ලෙස නිරාවරණය කරයි).
- **කැපවූ Bun Dockerfile**: Native Bun production deployments සඳහා බහු-අදියර `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

### දායක වන ආකාරය

1. ගබඩාව fork කරන්න
2. **සක්රිය** `release/vX.Y.Z` අවසන් ලක්ෂ්යයෙන් (`main` වෙතින් නොව) ශාඛාවක් සාදන්න — [ශාඛාකරණ සහ නිකුතු ආකෘතිය](docs/ops/BRANCHING_MODEL.md) බලන්න
3. ඔබේ විශේෂාංග ශාඛාව සාදන්න (`git checkout -b feat/amazing-feature`)
4. ඔබේ වෙනස්කම් commit කරන්න (`git commit -m 'feat: add amazing feature'`)
5. ශාඛාවට push කරන්න (`git push origin feat/amazing-feature`)
6. **base = එම `release/vX.Y.Z` ශාඛාව** ලෙස Pull Request එකක් විවෘත කරන්න
