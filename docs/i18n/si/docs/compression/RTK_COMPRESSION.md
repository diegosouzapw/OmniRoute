RTK සම්පීඩනය යනු ටර්මිනල් සහ මෙවලම් ප්රතිදානය සඳහා OmniRoute සතු විධාන-සංවේදී සම්පීඩන එන්ජිමයි. බොහෝ සන්දර්භ වර්ධනය පරීක්ෂණ ලොග්, බිල්ඩ් ප්රතිදානය,
පැකේජ කළමනාකරු ඝෝෂාව, ෂෙල් පිටපත්, Docker ප්රතිදානය, git ප්රතිදානය සහ ස්ටැක් ට්රේස් වෙතින් ඇති වන කේතකරණ නියෝජිත සැසි සඳහා එය
නිර්මාණය කර ඇත.

RTK සෘජුවම `defaultMode: "rtk"` සමඟ හෝ ස්ථරගත නළ මාර්ගයක පළමු පියවර ලෙස, සාමාන්යයෙන් පහත පරිදි, ධාවනය කළ හැක:

```txt
rtk -> caveman
```

එම අනුපිළිවෙළ පළමුව ඝෝෂාකාරී යන්ත්ර ප්රතිදානය සම්පීඩනය කර, ඉන්පසු ඉතිරි ගද්යය සංක්ෂිප්ත කිරීමට Caveman හට ඉඩ සලසයි.

උඩුගං RTK විසින් විධාන-ප්රතිදානය සඳහා `60-90%` ඉතිරියක් වාර්තා කරයි. එහි README ආදර්ශ සැසිය
සම්මත ටෝකන `~118,000` සිට RTK ටෝකන `~23,900` දක්වා අඩු වන අතර, එය `79.7%` ක ඉතිරියකි (`~80%`). Caveman ආදාන සම්පීඩනය සමඟ ස්ථරගත ඉතිරි කිරීම ගණනය කිරීම සඳහා OmniRoute එම උඩුගං සාමාන්යය භාවිත කරයි:

```txt
RTK සාමාන්යය:   80% ඉතිරිය
Caveman ආදානය:  46% ඉතිරිය
ස්ථරගත:         1 - (1 - 0.80) * (1 - 0.46) = 89.2% ඉතිරිය
පරාසය:          1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

## එය සම්පීඩනය කරන දේ

අන්තර්ගත නාමාවලිය දැනට මෙම ප්රවර්ග හරහා පෙරහන් 49ක් සමඟ සපයනු ලැබේ:

| ප්රවර්ගය  | උදාහරණ                                                        |
| --------- | ------------------------------------------------------------- |
| `git`     | `git status`, `git branch`, `git diff`, `git log`             |
| `test`    | Vitest, Jest, Pytest, Playwright, Go පරීක්ෂණ, Cargo පරීක්ෂණ   |
| `build`   | TypeScript, ESLint, Biome, Prettier, Vite, Webpack, Turbo, Nx |
| `package` | `npm install`, `npm audit`, `pip`, `uv sync`, Poetry, Bundler |
| `shell`   | `ls`, `find`, `grep`, සාමාන්ය ෂෙල් ලොග්                       |
| `docker`  | `docker ps`, Docker ලොග්                                      |
| `infra`   | Terraform, OpenTofu, `systemctl status`                       |
| `generic` | JSON ප්රතිදානය, ස්ටැක් ට්රේස්, සාමාන්ය ප්රතිදාන පසුබැසීම      |

`open-sse/services/compression/engines/rtk/commandDetector.ts` හි ඇති අනාවරකය පෙරහන් තේරීමට පෙර ප්රතිදානය
වර්ගීකරණය කරයි. විධාන පන්තියක් පමණක් ප්රමාණවත් නොවන විට, පෙරහන්වලට විධාන රටාව හෝ ප්රතිදාන regex අනුවද ගැළපිය හැක.

## පෙරහන් නිරාකරණය

RTK මෙම අනුපිළිවෙළට පෙරහන් පූරණය කරයි:

1. විශ්වාසදායක වූ විට පමණක් `.rtk/filters.toml` සහ `.rtk/filters.json` වෙතින් ව්යාපෘති පෙරහන්.
2. `DATA_DIR/rtk/filters.toml` සහ `DATA_DIR/rtk/filters.json` වෙතින් ගෝලීය පෙරහන්.
3. `open-sse/services/compression/engines/rtk/filters/` වෙතින් අන්තර්ගත පෙරහන්.

එකම විෂය පථය තුළ, RTK TOML schema v1 පෙරහන් OmniRoute JSON පෙරහන්වලට වඩා ප්රමුඛත්වය ගනී. ආයාත කළ විධාන-විශේෂිත පෙරහනකට එම විෂය පථයේ වඩා පුළුල් පෙරහනක් අභිබවා යා හැකි වන පරිදි, විධාන-වර්ග ගැළපීමට පෙර TOML
`match_command` ප්රකාශන පරීක්ෂා කෙරේ. ගොනු ආකෘතිය කුමක් වුවද, ව්යාපෘති විෂය පථය තවමත් ගෝලීය
විෂය පථයට වඩා ප්රමුඛත්වය ගනී.

regex පෙරහන් මඟින් මෙවලම් ප්රතිදානය නියෝජිතයන්ට පෙන්වන ආකාරය වෙනස් කළ හැකි බැවින්, ව්යාපෘති පෙරහන් හිතාමතාම විශ්වාස දොරටුවකට යටත් කර ඇත. පහත සඳහන් කොන්දේසිවලින් එකක් සත්ය වූ විට ව්යාපෘති පෙරහන් ගොනුවක් පිළිගනු ලැබේ:

- `rtkConfig.trustProjectFilters` යනු `true` වේ.
- `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1` සකසා ඇත.
- `.rtk/trust.json` හි ව්යාපෘති පෙරහන් ගොනුවට ගැළපෙන SHA-256 හැෂ් අගය අඩංගු වේ.

විශ්වාස ගොනු උදාහරණය:

```json
{
  "filtersSha256": "0123456789abcdef...",
  "filtersTomlSha256": "fedcba9876543210..."
}
```

හැෂ් වෙන වෙනම පවතී: `filtersSha256` විසින් `.rtk/filters.json` විශ්වාස කරන අතර, `filtersTomlSha256`
විසින් `.rtk/filters.toml` විශ්වාස කරයි. එක් ගොනුවක් සංස්කරණය කිරීමෙන් අවලංගු වන්නේ එහිම විශ්වාස ඇතුළත් කිරීම පමණි. ගෝලීය ගොනු
පරිපාලකයා විසින් ස්ථාපනය කරනු ලබන අතර පවතින ගෝලීය-පෙරහන් විශ්වාස හැසිරීම භාවිත කරයි.

අභිරුචි පෙරහන් එක් පෙරහන් වස්තුවක් හෝ පෙරහන් වස්තු අරාවක් විය හැක. වලංගු නොවන අභිරුචි පෙරහන්
මඟහැර ` /api/context/rtk/filters` රෝගනිර්ණවලින් වාර්තා කෙරේ. වලංගු නොවන අන්තර්ගත පෙරහන් වහාම අසමත් වේ.

## RTK TOML schema v1 අනුකූලතාව

OmniRoute හට RTK TOML schema v1 භාවිතයෙන් ප්රකාශනාත්මක පෙරහන් ගොනු විග්රහ කිරීමට, වලංගු කිරීමට, පරීක්ෂා කිරීමට සහ ස්ථාපනය කිරීමට හැකිය.
සහාය දක්වන ක්ෂේත්ර වන්නේ `description`, `match_command`, `strip_ansi`, `filter_stderr`,
`strip_lines_matching`, `keep_lines_matching`, `replace`, `match_output`, `truncate_lines_at`,
`head_lines`, `tail_lines`, `max_lines`, `on_empty`, සහ `[[tests.<filter>]]` පේළිගත පරීක්ෂණ වේ.
නොදන්නා ක්ෂේත්ර, වලංගු නොවන හෝ අනාරක්ෂිත නිත්ය ප්රකාශන, එකවර ඇති ඉවත් කිරීමේ/රඳවාගැනීමේ රීති, 1 MiB ඉක්මවන ගොනු,
සහ නොදන්නා පෙරහන් වෙත යොමු කිරීම් ප්රතික්ෂේප කෙරේ. පේළිගත පරීක්ෂණ අසමත් වන ගොනුවක් පරීක්ෂා කිරීම සඳහා
වලංගු කළ හැකි නමුත් එය ස්ථාපනය කිරීමට හෝ පූරණය කිරීමට නොහැක. අභිරුචි ගොනු පූරණය කිරීමේ අසමත්වීම්
තවදුරටත් fail-open ලෙස පවතී: වලංගු නොවන ගොනුව මඟහැර ඉතිරි පෙරහන් දිගටම ක්රියා කරයි.

සේවාලාභියා මෙවලම් ප්රතිදානය දැනටමත් ග්රහණය කරගත් පසුව OmniRoute වෙත එය ලැබෙන බැවින්, `filter_stderr = true`
මඟින් ක්රියාවලි ග්රහණය වෙනස් කළ නොහැක. මෙම ක්ෂේත්රය කිසිදු ක්රියාවක් නොකරන විකල්පයක් ලෙස පිළිගන්නා අතර වලංගුකරණය අනතුරු ඇඟවීමක් ලබා දෙයි.
මෙය හිතාමතාම **RTK TOML schema v1 අනුකූලතාව** ලෙස විස්තර කරන අතර, RTK ක්රියාත්මක කළ හැකි ගොනුව,
shell hooks, Rust විධාන ක්රියාත්මක කිරීම්, හෝ එහි trust-store සැකැස්ම සමඟ පූර්ණ අනුකූලතාවක් ලෙස විස්තර නොකෙරේ.

උපකරණ පුවරුවේ උසස් RTK දසුන අලවන ලද හෝ උඩුගත කරන ලද TOML පිළිගනී. වලංගුකරණය කියවීමට පමණි.
ස්ථාපනය මඟින් සීමාකාරී අවසර සහිතව `DATA_DIR/rtk/filters.toml` වෙත පරමාණුකව ලියන අතර නැවත ආරම්භ කිරීමකින් තොරව
සජීවී පෙරහන් නාමාවලිය නැවුම් කරයි. පවතින ගොනුවක් ප්රතිස්ථාපනය කිරීමට පැහැදිලි `overwrite`
තහවුරු කිරීමක් අවශ්ය වන අතර පළමුව `DATA_DIR/rtk/filters.toml.bak` නිර්මාණය කරයි.

## පෙරහන් DSL

පෙරහන් [Compression Rules Format](./COMPRESSION_RULES_FORMAT.md) හි විස්තර කර ඇති JSON schema භාවිත කරයි.
ධාවන පරිසරය මෙම අදියර අනුපිළිවෙළින් යොදයි:

```txt
stripAnsi -> filterStderr -> replace -> matchOutput -> පේළි ඉවත් කිරීම/ඇතුළත් කිරීම
  -> truncateLineAt -> head/tail/maxLines -> onEmpty
```

වැදගත් ක්ෂේත්ර:

| ක්ෂේත්රය                     | අරමුණ                                                            |
| ---------------------------- | ---------------------------------------------------------------- |
| `rules.stripAnsi`            | ගැළපීමට පෙර terminal වර්ණ/පාලන අනුක්රම ඉවත් කිරීම                |
| `rules.filterStderr`         | ගැළපීමට/පෙරීමට පෙර පොදු stderr උපසර්ග සාමාන්යකරණය කිරීම          |
| `rules.replace`              | අනුපිළිවෙළට සකස් කළ නිත්ය ප්රකාශන ප්රතිස්ථාපන යෙදීම              |
| `rules.matchOutput`          | ප්රතිදානය දන්නා තත්ත්වයකට ගැළපෙන විට සංක්ෂිප්ත සාරාංශයක් ලබා දීම |
| `rules.matchOutput[].unless` | දෝෂ/අසමත් වීමේ රටාවක් පවතින විට කෙටි මඟ මඟහැරීම                  |
| `rules.dropPatterns`         | අනවශ්ය පේළි ඉවත් කිරීම                                           |
| `rules.includePatterns`      | ක්රියාමාර්ග ගත හැකි පේළිවලට ප්රමුඛතාව දීම                        |
| `rules.collapsePatterns`     | නැවත නැවත ගැළපෙන පේළි හකුළා දැමීම                                |
| `rules.deduplicate`          | පෙරහන්-විශේෂිත opt-in: අඛණ්ඩ අනුපිටපත් පේළි හකුළා දැමීම          |
| `rules.truncateLineAt`       | Unicode-ආරක්ෂිත පේළි-විශේෂිත කප්පාදු කිරීම                       |
| `rules.onEmpty`              | සියලු පේළි පෙරා ඉවත් කළහොත් භාවිත කරන ආදේශක පණිවිඩය              |
| `tests[]`                    | සත්යාපන දොරටුව භාවිත කරන පේළිගත නියැදි                           |

ගොඩනඟා ඇති පෙරහන්වල පේළිගත `tests[]` නියැදි ඇතුළත් විය යුතුය. අභිරුචි පෙරහන්වලද,
විශේෂයෙන් ඒවා ව්යාපෘති අතර බෙදාගන්නා විට, එම නියැදි ඇතුළත් කළ යුතුය.

## පේළි අනුපිටපත් ඉවත් කිරීම (ස්තර දෙකක්)

RTK ස්වාධීන ස්තර දෙකකදී අනුපිටපත් පේළි හකුළයි:

1. **පෙරහනකට අදාළ `deduplicate` (තෝරා සක්රීය කළ යුතුය, පෙරනිමිය `false`).** පෙරහනකට `rules.deduplicate: true`
   සකසා, කප්පාදු කිරීමට පෙර _එම පෙරහනට ගැළපුණු ප්රතිදානය තුළ_ ඇති අනුයාත අනුපිටපත් පේළි හකුළා දැමිය හැක.
   මෙය `lineFilter.ts` තුළ ධාවනය වේ. පැරණි පෙරහන් සඳහා, පෙරහන `collapsePatterns` නිර්වචනය කරන්නේ නම්
   මෙය ස්වයංක්රීයව සක්රීය කෙරේ. යෝජනා ක්රමය:
   `open-sse/services/compression/engines/rtk/filterSchema.ts` තුළ `deduplicate: z.boolean().default(false)`.
2. **එන්ජිම පුරා `deduplicateThreshold` (පෙරනිමිය `3`).** සියලු පෙරහන් ධාවනය වූ පසු, සම්පූර්ණ ප්රතිඵලය පුරා
   එක සමාන අනුයාත පේළි `>= deduplicateThreshold` සංඛ්යාවකින් යුතු ඕනෑම අනුක්රමයක් එන්ජිම විසින් හකුළනු ලැබේ
   (`deduplicateRepeatedLines`, `engines/rtk/index.ts` තුළ යොදනු ලැබේ). සාමාන්යකරණයේදී අගය 2–100 අතරට
   සීමා කෙරේ.

පෙරහනකට අදාළ අදියර පළමුව (පෙරහන තුළ) ධාවනය වන අතර, එන්ජිම පුරා අදියර අවසානයේ (එක් කළ
ප්රතිදානය මත) ධාවනය වේ. එබැවින් ඒවා දෙවරක් ගණනය කිරීමකින් තොරව එකට ක්රියා කරයි.

## පේළි සමූහගත කිරීම (`enableGrouping`)

`rtkConfig.enableGrouping` `true` වූ විට (පෙරනිමිය `false`), RTK විසින් අනුපිටපත් ඉවත් කළ පසු ලැබෙන ප්රතිඵලය මත අතිරේක `groupSimilarLines`
අදියරක් ධාවනය කර, _ආසන්න වශයෙන් සමාන_ (බයිට් මට්ටමින් සර්වසම නොවන)
අනුයාත පේළි අනුක්රම හකුළයි. සමූහගත කිරීම ක්රියාත්මක වීමට අවශ්ය අවම අනුක්රම දිග
`rtkConfig.groupingThreshold` (පෙරනිමිය `3`) වේ. මෙය `deduplicateThreshold` හි ව්යුහාත්මක ප්රතිරූපයයි: අනුපිටපත් ඉවත් කිරීම සර්වසම පුනරාවර්තන හසුරුවන අතර,
සමූහගත කිරීම "සුළු වෙනස්කම් සහිත එකම හැඩය" හසුරුවයි. සලකුණු දෙකම `key_value` වගුවේ තිරසාරව සුරකින `rtkConfig` JSON
හි කොටස් වේ (ඉහත වින්යාසය බලන්න), එබැවින් යළි ආරම්භ කිරීමෙන් පසුවත් සැකසුම පවතී.

## කේත විවරණ ඉවත් කිරීම (`stripCodeComments` / `preserveDocstrings`)

`rtkConfig.applyToCodeBlocks` සක්රීය කර ඇති විට, වැටකින් වට කළ කේත කුට්ටිවලින් විවරණ ඉවත් කිරීමටද RTK හට හැකිය:

- `stripCodeComments` (පෙරනිමිය `false`) — තෝරා සක්රීය කළ යුතුය. `true` වූ විට, RTK විසින් JavaScript
  සහ TypeScript වැටකින් වට කළ කුට්ටිවලින් විවරණ ඉවත් කරයි. ඓතිහාසිකව මෙම සලකුණ කියවන ලද නමුත් කිසිවිටෙක යොදා නොගත් බැවින්,
  නිහඬ නිෂ්පාදන වෙනසක් වළක්වා ගැනීමට පෙරනිමිය "සුරකින්න" ලෙසම පවතී.
- `preserveDocstrings` (පෙරනිමිය `true`) — විවරණ ඉවත් කරන විට, JSDoc/`/** … */` කුට්ටි විවරණ
  තබා ගනී (ඒවා වැය කරන බයිට්වලට වඩා වටිනා API ප්රලේඛන රැගෙන යයි). ඒවාද ඉවත් කිරීමට `false` ලෙස සකසන්න.

විවරණ ඉවත් කිරීම `open-sse/services/compression/engines/rtk/codeStripper.ts` තුළ ක්රියාත්මක කර ඇත. එය
**TypeScript විග්රහකය** (regex එකක් නොවේ) භාවිත කරන බැවින් තන්තු, අච්චු සහ regex ලිටරල් කිසිවිටෙක
විවරණ ලෙස වරදවා නොගනී. තවද JSX අනාවරණය වූ විට එය සම්පූර්ණයෙන්ම ක්රියාව නවත්වයි (එමඟින් JSX ප්රකාශන-බහාලුම් විවරණ
කිසිවිටෙක දූෂිත නොවේ). විවරණ ඉවත් කිරීම දැනට අදාළ වන්නේ **JavaScript සහ TypeScript සඳහා පමණි** — ඉවත්කාරකයේ
`CodeLanguage` කට්ටලයේ ඇති අනෙකුත් භාෂා (Python, Rust, Go, Ruby, Java) සඳහා හිස් පේළි සහ
සුදු ඉඩ හකුළන නමුත් විවරණ ඉවත් නොකරයි. විවරණ ඉවත් කළ කුට්ටි ධාවනය `rulesApplied` තුළ
`rtk:code-strip` ලෙස ටැග් කෙරේ.

> **සටහන — GCF / වගුමය කේතනය වෙනම එන්ජිමකි.** RTK තුළ "GCF"
> (Graph Compact Format) වගුමය/තීරුමය JSON කේතකය අඩංගු **නොවේ**. පැරණි
> `omni-tabular` කේතකයක් ප්රතිස්ථාපනය කළ එම කේතකය **headroom** එන්ජිම තුළ පවතී
> (`open-sse/services/compression/engines/headroom/`, ඒ සමඟ ඇතුළත් කර ඇති codec එක
> `headroom/gcf/` යටතේ ඇත). එය මෙහි ලේඛනගත කර ඇති RTK පෙරහන් නළමඟට සම්බන්ධ නොවේ.

RTK පරීක්ෂණ payload:

```json
{
  "command": "npm test",
  "text": "FAIL tests/example.test.ts\nAssertionError: expected true\nTest Files 1 failed",
  "config": {
    "intensity": "standard"
  }
}
```

සම්පීඩන පෙරදසුන් payload:

```json
{
  "mode": "stacked",
  "messages": [
    {
      "role": "tool",
      "content": "FAIL tests/example.test.ts\nAssertionError: expected true\nTest Files 1 failed"
    }
  ],
  "config": {
    "rtkConfig": {
      "rawOutputRetention": "failures"
    }
  }
}
```

කළමනාකරණ routes සඳහා dashboard කළමනාකරණ සත්යාපනය හෝ ගැළපෙන API-key ප්රතිපත්තිය අවශ්ය වේ.

RTK TOML වලංගුකරණ payload:

```json
{
  "action": "validate",
  "content": "schema_version = 1\n\n[filters.my-tool]\nmatch_command = \"^my-tool\\\\b\"\nmax_lines = 20\n"
}
```

වලංගු කළ ගොනුව ගෝලීයව ස්ථාපනය කිරීමට `"action": "install"` භාවිත කරන්න. පවතින ගෝලීය ගොනුවක්
ප්රතිස්ථාපනය කිරීම සමාලෝචනය කර තහවුරු කිරීමෙන් පසුව පමණක් `"overwrite": true` එක් කරන්න.

## අමු ප්රතිදානය ප්රතිසාධනය

RTK සාමාන්යයෙන් සම්පීඩිත පෙළ පමණක් ආපසු ලබා දෙයි. දෝෂ නිදොස් කිරීම සඳහා, `rawOutputRetention` මඟින් සංවේදී දත්ත ඉවත් කළ
අමු ප්රතිදානය රඳවාගත හැක:

| අගය        | හැසිරීම                                                                   |
| ---------- | ------------------------------------------------------------------------- |
| `never`    | අමු ප්රතිදානය රඳවා නොගන්න                                                 |
| `failures` | අසාර්ථක වී ඇතැයි සැලකිය හැකි ප්රතිදානය පමණක් රඳවාගන්න                     |
| `always`   | සංවේදී දත්ත ඉවත් කිරීමෙන් පසු, සෑම සම්පීඩිත RTK අමු ප්රතිදානයක්ම රඳවාගන්න |

රඳවාගත් ගොනු පහත ස්ථානය යටතේ ලියනු ලැබේ:

```txt
DATA_DIR/rtk/raw-output/
```

පොදු bearer tokens, API keys, Slack tokens,
AWS access keys, සහ පැවරුම් ආකාරයේ `token=...`, `secret=...`, `password=...` අගයන් ඇතුළුව රහස්, ස්ථිරව සුරැකීමට පෙර ඉවත් කරනු ලැබේ. විශ්ලේෂණ
තුළ ගබඩා කරන්නේ දර්ශක හැඳුනුම්කාරකය, ප්රමාණය සහ hash පාරදත්ත පමණි.

## සත්යාපන ද්වාරය

ඉලක්කගත සත්යාපන ද්වාරය බාහිර විධාන ක්රියාත්මක නොකර, අන්තර්ගත built-in filter පරීක්ෂණ ධාවනය කරයි:

```bash
node --import tsx/esm --test tests/unit/compression/rtk-verify.test.ts
```

වඩා පුළුල් RTK ද්වාරය වන්නේ:

```bash
node --import tsx/esm --test \
  tests/unit/compression/rtk-*.test.ts \
  tests/unit/compression/pipeline-integration.test.ts \
  tests/unit/compression/context-compression-api.test.ts
```

නිකුතුවට පෙර පුළුල් සම්පීඩන ද්වාරය ධාවනය කරන්න:

```bash
node --import tsx/esm --test \
  tests/unit/compression/*.test.ts \
  tests/golden-set/*.test.ts \
  tests/integration/compression-pipeline.test.ts \
  tests/unit/api/compression/compression-api.test.ts
```

## RTK පුළුල් කිරීම

1. filter JSON ගොනුවක් එක් කරන්න හෝ යාවත්කාලීන කරන්න.
2. වැදගත් හැසිරීම සනාථ කරන අවම වශයෙන් එක් `tests[]` නියැදියක් ඇතුළත් කරන්න.
3. නව විධාන පවුල් සඳහා `tests/unit/compression/fixtures/rtk/` යටතේ fixture එකක් එක් කරන්න.
4. නව ප්රතිදාන පන්තියක් හඳුන්වා දීමේදී විධාන හඳුනාගැනීමේ ආවරණය එක් කරන්න.
5. සත්යාපන සහ පුළුල් RTK ද්වාර ධාවනය කරන්න.
6. filter එක ව්යාපෘතියට-දේශීය නම්, සමාලෝචනයෙන් පසුව පමණක් `.rtk/filters.json` commit කර `.rtk/trust.json` නැවුම් කරන්න.

### තීව්රතාව වින්යාස කිරීම

**එක් එක් combo එක සඳහා** (combo config තුළ):

```json
{
  "combo": "my-coding-combo",
  "routing": {/* ... */},
  "compression": {
    "engine": "rtk",
    "intensity": "aggressive"
  }
}
```

**ක්රමලේඛමය ලෙස**:

`rtkEngine` (`@omniroute/open-sse/services/compression/engines/rtk`) යනු
`CompressionEngine` එකක් වන අතර එයට `updateConfig` method එකක් නොමැත. ඒ වෙනුවට registry helper හරහා engine එකක config
යාවත්කාලීන කරන්න:

```ts
import { updateEngineConfig } from "@omniroute/open-sse/services/compression/engines/registry";

updateEngineConfig("rtk", { intensity: "aggressive" });
```

### අභිරුචි පෙරහන් පූරණය කිරීම

```
~/.omniroute/rtk/filters/my-filter.json     # පරිශීලක මට්ටම
<project>/.rtk/filters/my-filter.json      # ව්යාපෘති මට්ටම
```

ආරම්භයේදී `open-sse/services/compression/engines/rtk/filterLoader.ts` තුළ ඇති `loadRtkFilters()` හරහා පෙරහන් ස්වයංක්රීයව පූරණය වේ. පූරකය පහත ස්ථානවලින් පෙරහන් සොයාගනී:

- ගොඩනඟා ඇති නාමාවලිය: `open-sse/services/compression/engines/rtk/filters/`
- පරිශීලක නාමාවලිය: `~/.omniroute/rtk/filters/`
- ව්යාපෘති නාමාවලිය: `<project>/.rtk/filters/`

ක්රමලේඛනමය ලෙස පෙරහන් පූරණය කිරීමට:

import { loadRtkFilters } from "@omniroute/open-sse/services/compression/engines/rtk/filterLoader";

// විකල්ප: customFiltersEnabled (පරිශීලක/ව්යාපෘති පෙරහන් පූරණය කිරීම, පෙරනිමියෙන් සක්රියයි),

### වලංගුකරණය

පෙරහන් පූරණය වන විට Zod යෝජනා ක්රමයට එරෙහිව වලංගුකරණය කරනු ලැබේ. වැරදි ව්යුහයක් ඇති පෙරහනක් පූරණය වීමට අසමත් වී දෝෂයක් ලොග් කරයි:

```
RTK_FILTER_LOADER: filter "my-filter" failed validation:
  - rules.replace.0.pattern: Invalid regex
  - match.commands: must not be empty
```

ස්ථාපනය කර ඇති සියලු පෙරහන් වලංගුකරණය කිරීමට, `open-sse/services/compression/engines/rtk/verify.ts` වෙතින් අපනයනය කරන `runRtkFilterTests()` අමතන්න.

### හොඳම භාවිතයන්

1. **සෑම විටම `tests[]` ඇතුළත් කරන්න** — ඒවා ඔබගේ පෙරහන ක්රියා කරන බව සනාථ කරන අතර ප්රතිගමන වළක්වයි
2. **කෙටි පරිපථ සඳහා `matchOutput` භාවිත කරන්න** — එක් පේළියකින් සම්පූර්ණ අදහස පැහැදිලි වේ නම්, මුළු කොටසම ප්රතිස්ථාපනය කරන්න
3. **`strip` වෙනුවට `keep` වඩාත් සුදුසුය** — පැහැදිලි "සෑම විටම සුරකින්න" නීති, "සෑම විටම ඉවත් කරන්න" නීතිවලට වඩා ආරක්ෂිතය
4. **තීව්රතා මට්ටම් 3 හිම පරීක්ෂා කරන්න** — `minimal` කිසිදු වෙනසක් නොකරන එකක් විය යුතු අතර, `aggressive` තවමත් දෝෂ සුරැකිය යුතුය
5. **`unless` ක්ෂේත්රය භාවිත කරන්න** — "X තිබේ නම් ක්රියාත්මක නොකරන්න" යන කොන්දේසියෙන් කෙටි පරිපථ ආරක්ෂා කරන්න

## අමු ප්රතිදානය ප්රතිසාධනය කිරීම සහ සත්යාපන ද්වාරය

RTK විසින් ප්රතිදානය දැඩි ලෙස සම්පීඩනය කරන විට, දෝෂහරණය, විගණනය හෝ නැවත ධාවනය සඳහා ඔබට **මුල් පෙළ ප්රතිසාධනය කළ හැක**.

### අමු ප්රතිදානය ප්රතිසාධනය ක්රියා කරන ආකාරය

```
මුල් ප්රතිදානය (ටෝකන 10K)
        │
        ▼
RTK සම්පීඩනය (rawOutput.enabled=true සමඟ)
        │
        ├─▶ සම්පීඩිත ප්රතිදානය (ටෝකන 2K)  ──▶ LLM වෙත
        │
        └─▶ මුල් ප්රතිදානය (ටෝකන 10K)   ──▶ DB තුළ ගබඩා කෙරේ
                                                  (request_id මඟින් සම්බන්ධ කර ඇත)
```

### අමු ප්රතිදාන ගබඩා කිරීම සක්රීය කිරීම

**එක් එක් ඉල්ලීම සඳහා** (combo වින්යාසය තුළ):

```json
{
  "compression": {
    "engine": "rtk",
    "intensity": "aggressive",
    "rawOutput": {
      "enabled": true,
      "maxBytes": 1048576 // 1MB cap
    }
  }
}
```

**පෙරනිමිය**: `rawOutput.enabled: false` (ගබඩා ඉඩ ඉතිරි කරයි).

### ගබඩා පිරිවැය

| එක් ඉල්ලීමකට               | 1MB සීමාව    | 10MB සීමාව    |
| -------------------------- | ------------ | ------------- |
| සාමාන්ය සම්පීඩිත ප්රතිදානය | ~5KB         | ~5KB          |
| ගබඩා කළ අමු ප්රතිදානය      | ~50-500KB    | ~500KB-5MB    |
| දිනකට ඉල්ලීම් 1000ක් සමඟ   | 50-500MB/දින | 500MB-5GB/දින |

> **නිර්දේශය**: අමු ප්රතිදානය සැමවිටම සක්රීයව තැබීම වෙනුවට, **දෝෂහරණ සැසි** හෝ **නියැදි විගණනය** සඳහා පමණක් සක්රීය කරන්න.

### මුල් ප්රතිදානය ප්රතිසාධනය කිරීම

```ts
import { readRtkRawOutput } from "omniroute/compression/engines/rtk/rawOutput";

const raw = readRtkRawOutput(pointerId); // pointerId from compression stats
if (raw) {
  console.log("Original output:", raw);
}
```

සම්පීඩනයෙන් පසු `CompressionStats.rtkRawOutputPointers[]` තුළ `pointerId` ආපසු ලබා දෙයි.
ශ්රිත අත්සන සඳහා `open-sse/services/compression/engines/rtk/rawOutput.ts:102` බලන්න.

### සත්යාපන ද්වාරය

**RTK පෙරහන් සත්යාපනය** (`open-sse/services/compression/engines/rtk/verify.ts`) සියලු පෙරහන් ඒවායේ `tests[]` සමඟ සත්යාපනය කර, තීව්රතා මට්ටම් 3දීම හැසිරීම නිවැරදි බව තහවුරු කරයි.

සත්යාපනය ධාවනය කිරීමට **`runRtkFilterTests()` අමතන්න**:

```ts
import { runRtkFilterTests } from "open-sse/services/compression/engines/rtk/verify";

const result = runRtkFilterTests();
console.log(`Passed: ${result.outcomes.filter((o) => o.passed).length}`);
console.log(`Failed: ${result.outcomes.filter((o) => !o.passed).length}`);
if (!result.passed) {
  console.error("Filters failed verification");
  result.outcomes
    .filter((o) => !o.passed)
    .forEach((o) => {
      console.error(
        `  - ${o.filterId} / ${o.testName}: expected "${o.expected}", got "${o.actual}"`
      );
    });
}
```

**එය සත්යාපනය කරන දෑ**:

1. සෑම පෙරහනක්ම පූරණය වී schema සත්යාපනය සමත් වේ
2. සෑම `tests[]` ප්රවේශයක්ම අපේක්ෂිත ප්රතිදානය නිපදවයි
3. `minimal` තීව්රතාව කිසිදු මෙහෙයුමක් සිදු නොකරයි (මුල් අගය රැකගෙන ව්යුහාත්මක පෙරහන් පමණක් යොදයි)
4. `aggressive` තීව්රතාව දෝෂ, පරීක්ෂණ අසමත්වීම් සහ stack traces රැකගනී
5. සම්පීඩිත ප්රතිදානය කිසිවිටෙකත් මුල් ආදානයට වඩා විශාල නොවේ

- මූලාශ්රය: `open-sse/services/compression/engines/rtk/` (ගොනු 63ක්, ~70KB)

- **පෙරහනක වෙනසක් ඒකාබද්ධ කිරීමට පෙර** — සෑම විටම පරීක්ෂණ සමත් වන බව තහවුරු කරන්න
- **RTK engine උත්ශ්රේණිගත කිරීමෙන් පසු** — schema වෙනස් වී තිබිය හැක
- **අධීක්ෂණයේදී වරින් වර** — පරීක්ෂණ fixturesවල අපගමනයෙන් ආරක්ෂා කරයි
- **නව tool/command පවුලක් එක් කරන විට** — නව පෙරහන ක්රියා කරන බව සනාථ කරයි
