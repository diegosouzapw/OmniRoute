## Caveman රීති ඇසුරුම්

Caveman රීති ඇසුරුම් පහත ස්ථානයේ පවතී:

```txt
open-sse/services/compression/rules/<language>/<pack>.json
```

සෑම ඇසුරුමකම, ආරක්ෂිත කලාප වෙන් කිරීමෙන් පසු සාමාන්ය ගද්යයට යෙදෙන ප්රතිස්ථාපන අඩංගු වේ.

```json
{
  "language": "en",
  "category": "filler",
  "rules": [
    {
      "name": "question_to_directive",
      "pattern": "\\b(?:Can you explain why|Could you show me how)\\b\\s*",
      "replacement": "Explain why ",
      "replacementMap": {
        "can you explain why": "Explain why ",
        "could you show me how": "Show how "
      },
      "flags": "gi",
      "context": "all",
      "category": "context",
      "minIntensity": "lite",
      "description": "Convert verbose questions into direct requests."
    }
  ]
}
```

### Caveman ක්ෂේත්ර

| ක්ෂේත්රය                 | අවශ්යද | විස්තරය                                                                           |
| ------------------------ | ------ | --------------------------------------------------------------------------------- |
| `language`               | ඔව්    | `en`, `pt-BR`, `es` වැනි BCP-47 ආකාරයේ භාෂා යතුරක්                                |
| `category`               | ඔව්    | ඇසුරුම් ප්රවර්ගයේ ගොනු නාමය/ප්රවර්ගය, උදාහරණයක් ලෙස `filler` හෝ `dedup`           |
| `rules`                  | ඔව්    | regex ප්රතිස්ථාපන රීති අරාවක්                                                     |
| `rules[].name`           | ඔව්    | ස්ථාවර රීති නාමය                                                                  |
| `rules[].pattern`        | ඔව්    | JavaScript regex මූලාශ්රය                                                         |
| `rules[].flags`          | නැත    | JavaScript regex ධජ; පෙරනිමිය `gi`                                                |
| `rules[].replacement`    | නැත    | `replacementMap` හි ගැළපීමක් නොමැති විට භාවිත කරන ප්රතිස්ථාපන පෙළ හෝ අමතර විකල්පය |
| `rules[].replacementMap` | නැත    | සාමාන්යකරණය කළ ගැළපුණු පෙළ අනුව යතුරුගත කළ, ගැළපීමට විශේෂිත ප්රතිස්ථාපන           |
| `rules[].context`        | නැත    | `all`, `user`, `assistant`, හෝ `system`; පෙරනිමිය `all`                           |
| `rules[].category`       | නැත    | `filler`, `context`, `structural`, `dedup`, `terse`, හෝ `ultra`                   |
| `rules[].minIntensity`   | නැත    | `lite`, `full`, හෝ `ultra`; පෙරනිමිය `lite`                                       |
| `rules[].description`    | නැත    | මිනිසුන්ට කියවිය හැකි රීති සාරාංශය                                                |

කුඩා අකුරින් ඇති ගද්යයට පෙර article ඉවත් කිරීමේදී `the OpenAI API` ඉවත් නොකිරීම වැනි, අක්ෂර ප්රමාණයට සංවේදී ගැළපීම වැදගත් වන අවස්ථාවල `flags` භාවිත කරන්න. එක් regex එකක විවිධ ප්රතිදාන අවශ්ය වන විකල්ප කිහිපයක් ඇති විට `replacementMap` භාවිත කරන්න; මෙය වඩාත් සවිස්තරාත්මක built-in TypeScript ප්රතිස්ථාපන ශ්රිතවල හැසිරීම පවත්වා ගනිමින් JSON රීති ඇසුරුම් දත්තවලට පමණක් සීමා කරයි.

## RTK පෙරහන් ඇසුරුම්

RTK පෙරහන් පිහිටන්නේ:

```txt
open-sse/services/compression/engines/rtk/filters/<filter>.json
```

සෑම පෙරහනක්ම විධාන ප්රතිදාන පවුලක් හඳුනාගෙන සම්පීඩනය කරන ආකාරය විස්තර කරයි.

```json
{
  "id": "test-vitest",
  "label": "Vitest output",
  "category": "test",
  "priority": 92,
  "match": {
    "outputTypes": ["test-vitest"],
    "commands": ["vitest", "npm test", "npm run test"],
    "patterns": ["\\bFAIL\\b", "\\bPASS\\b", "\\bTest Files\\b"]
  },
  "rules": {
    "stripAnsi": true,
    "replace": [{ "pattern": "\\s+\\[[0-9]+ms\\]", "replacement": "" }],
    "matchOutput": [
      {
        "pattern": "All tests passed",
        "message": "vitest: ok",
        "unless": "FAIL|Error:"
      }
    ],
    "includePatterns": ["FAIL", "Error:", "Test Files", "Tests"],
    "dropPatterns": ["^\\s*$", "Duration\\s+\\d+"],
    "collapsePatterns": ["^\\s+at "],
    "deduplicate": true,
    "truncateLineAt": 240,
    "maxLines": 160,
    "headLines": 24,
    "tailLines": 40,
    "onEmpty": "vitest: ok",
    "filterStderr": false
  },
  "preserve": {
    "errorPatterns": ["FAIL", "Error:", "AssertionError"],
    "summaryPatterns": ["Test Files", "Tests", "Snapshots"]
  },
  "tests": [
    {
      "name": "keeps failing tests",
      "command": "vitest",
      "input": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed",
      "expected": "FAIL test/a.test.ts\\nError: boom\\nTest Files 1 failed"
    }
  ]
}
```

### RTK ක්ෂේත්ර

| ක්ෂේත්රය                   | අවශ්යද | විස්තරය                                                                      |
| -------------------------- | ------ | ---------------------------------------------------------------------------- |
| `id`                       | ඔව්    | ස්ථාවර පෙරහන් හැඳුනුම්කාරකය                                                  |
| `label`                    | ඔව්    | උපකරණ පුවරුවේ කියවිය හැකි නම                                                 |
| `category`                 | ඔව්    | පෙරහන් පවුල: git, test, build, shell, docker, package, infra, cloud, generic |
| `priority`                 | නැත    | පෙරහන් කිහිපයක් ගැළපෙන විට ඉහළ ප්රමුඛතාව ඇති එක ජය ගනී                       |
| `match.outputTypes`        | නැත    | මෙම පෙරහන තෝරන අනාවරක ප්රතිදාන හැඳුනුම්කාරක                                  |
| `match.commands`           | නැත    | මෙම පෙරහන තෝරන විධාන ටෝකන                                                    |
| `match.patterns`           | නැත    | ප්රතිදාන පෙළෙන් මෙම පෙරහන තෝරන regex රටා                                     |
| `rules.stripAnsi`          | නැත    | regex අදියරවලට පෙර ANSI escape අනුක්රම ඉවත් කරයි                             |
| `rules.replace`            | නැත    | පේළියෙන් පේළියට යොදන අනුපිළිවෙළගත regex ආදේශන                                |
| `rules.matchOutput`        | නැත    | විකල්ප `unless` ආරක්ෂකයක් සහිත කෙටි-පරිපථ ප්රතිදාන රීති                      |
| `rules.includePatterns`    | නැත    | රඳවා ගැනීමට ප්රමුඛත්වය දිය යුතු පේළි                                         |
| `rules.dropPatterns`       | නැත    | අනවශ්ය දත්ත ලෙස ඉවත් කළ යුතු පේළි                                            |

RTK ප්රකාශනාත්මක අදියර මෙම අනුපිළිවෙළට යොදයි: `stripAnsi`, `filterStderr`, `replace`,
`matchOutput`, `dropPatterns`/`includePatterns`, `truncateLineAt`, `headLines`/`tailLines`,
`maxLines`, සහ `onEmpty`.

අභිරුචි පෙරහන් පහත ස්ථානවලින් පූරණය කළ හැක:

1. ගැළපෙන `.rtk/trust.json` hash එකක් තිබීමෙන් පසුව හෝ
   `trustProjectFilters` සක්රීය කර ඇති විට පමණක් ව්යාපෘති `.rtk/filters.json` ගොනු.
2. ගෝලීය `DATA_DIR/rtk/filters.json`.
3. ඇතුළත් කළ පෙරහන්.

ව්යාපෘති/ගෝලීය අභිරුචි ගොනුවල එක් පෙරහන් object එකක් හෝ පෙරහන් object array එකක් අඩංගු විය හැක. වලංගු නොවන
අභිරුචි පෙරහන් රෝගනිශ්චය තොරතුරු සමඟ මඟ හරිනු ලැබේ; වලංගු නොවන ඇතුළත් කළ පෙරහන් නිසා වලංගුකරණය අසාර්ථක වේ.

ව්යාපෘති විශ්වාස ගොනුව:

```json
{
  "filtersSha256": "0123456789abcdef..."
}
```

පරිසර අතික්රමණය වන `OMNIROUTE_RTK_TRUST_PROJECT_FILTERS=1`, hash එකක් නොමැතිව ව්යාපෘති පෙරහන් විශ්වාස කරන අතර,
එය පාලිත දේශීය සංවර්ධනයට පමණක් සීමා කළ යුතුය.

## ආරක්ෂක නීති

- නීති idempotent ලෙස තබා ගන්න: එකම පෙරහන දෙවරක් ධාවනය කිරීමෙන් ප්රතිදානය දූෂිත නොවිය යුතුය.
- හැකි සෑම අවස්ථාවකම නිශ්චිත දෝෂ පෙළ, ගොනු මාර්ග, පේළි අංක සහ විධාන සාරාංශ එලෙසම සුරකින්න.
- කේත කොටස්, JSON payloads, URLs හෝ රහස් වෙනස් කරන නීතිවලින් වළකින්න.
- අනාවරක/පෙරහන් පරීක්ෂණවල නව විධාන පවුල් සඳහා ඒකක පරීක්ෂණ ආවරණය එක් කරන්න.
- සෑම ගොඩනඟා ඇති පෙරහනකටම සහ හවුල් අභිරුචි පෙරහන්වලටම `tests[]` සාම්පල එක් කරන්න.

## වලංගුකරණය

නීති ඇසුරුම් භාවිතයට පෙර වලංගුකරණය කරනු ලැබේ. දෝෂ සහිත නිකුතු සම්පත් බෙදාහැරීමට පෙර හඳුනාගැනීම සඳහා, ගොඩනඟා ඇති Caveman ඇසුරුම් සහ ගොඩනඟා ඇති RTK පෙරහන් වලංගුකරණය අතරතුර වහාම අසාර්ථක වේ. විග්රහ කිරීම හෝ විශ්වාසය වලංගුකරණය අසාර්ථක වන විට, අභිරුචි RTK පෙරහන් රෝග විනිශ්චය තොරතුරු සමඟ මඟහරිනු ලැබේ.
