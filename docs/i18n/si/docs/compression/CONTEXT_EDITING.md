පවරා දෙන ලද **සන්දර්භ සංස්කරණය** යනු Claude සඳහා පමණක් ඇති සන්දර්භ-කළමනාකරණ විශේෂාංගයකි. ඉල්ලීම් අන්තර්ගතය ප්රොක්සියෙන් පිටවීමට _පෙර_ එය නැවත ලියන OmniRoute හි දේශීය
සම්පීඩන එන්ජින් (Caveman, RTK, LLMLingua, stacked pipelines) මෙන් නොව — Context Editing මඟින් **සපයන්නාගෙන්** එහිම ක්රියාත්මක සන්දර්භ කවුළුවෙන් යල් පැන ගිය
මෙවලම්-භාවිත / මෙවලම්-ප්රතිඵල බ්ලොක් ඉවත් කරන ලෙස ඉල්ලා සිටී. OmniRoute කරන්නේ අන්තර්ගත
පරාමිතියක් (`context_management.edits[]`) ඇමිණීම පමණි; සත්ය ඉවත් කිරීම Claude විසින් එහිම tokenizer එකට අනුව සිදු කරයි.

මෙය ස්වභාවයෙන්ම පවරා දෙන ලද හැකියාවකි: වෙනත් සපයන්නන් මෙම පරාමිතිය ප්රතික්ෂේප කරන බැවින්, OmniRoute එය
Claude සහ Claude-Code-අනුකූල relays සඳහා පමණක් දැඩිව සීමා කරයි.

සත්යයේ මූලාශ්රය: `open-sse/config/contextEditing.ts` (උපායමාර්ග ids, අන්තර්ගතයට ඇතුළත් කිරීම, telemetry
උපුටා ගැනීම), `open-sse/executors/base.ts` (ඇතුළත් කිරීමේ gate + 400-fallback), සහ
`open-sse/services/compression/types.ts` (වින්යාස හැඩය + පෙරනිමිය).

## `clear_tool_uses` කරන්නේ කුමක්ද

OmniRoute පිටතට යවන Anthropic Messages අන්තර්ගතයට තනි සංස්කරණයක් ඇතුළත් කරයි:

```json
{
  "context_management": {
    "edits": [
      {
        "type": "clear_tool_uses_20250919",
        "trigger": { "type": "input_tokens", "value": 100000 },
        "keep": { "type": "tool_uses", "value": 3 }
      }
    ]
  }
}
```

- `type: "clear_tool_uses_20250919"` — දිනය යොදා ඇති Anthropic උපායමාර්ග id එක (`CLEAR_TOOL_USES_STRATEGY`).
- `trigger.value: 100000` — ඉල්ලීමේ ආදාන tokens මෙම සීමාව ඉක්මවූ පසු, Claude පැරණි
  මෙවලම්-භාවිත/ප්රතිඵල යුගල ඉවත් කිරීම අරඹයි (`CONTEXT_EDITING_DEFAULT_TRIGGER_TOKENS`, Anthropic හි පෙරනිමිය).
- `keep.value: 3` — වඩාත්ම මෑත මෙවලම්-භාවිත/ප්රතිඵල යුගල N සංඛ්යාව වෙනස් නොකර තබා ගනී
  (`CONTEXT_EDITING_DEFAULT_KEEP_TOOL_USES`).

මෙම beta එක `anthropic-beta: context-management-2025-06-27` ශීර්ෂකය හරහා ප්රචාරණය කෙරෙන අතර,
OmniRoute දැනටමත් Claude ඉල්ලීම් සඳහා එය නිකුත් කරයි.

ඇතුළත් කිරීම `applyContextEditingToBody()` මඟින් සිදු කරන අතර එය **idempotent** වේ: `clear_tool_uses`
සංස්කරණයක් දැනටමත් අන්තර්ගතයේ තිබේ නම් (පෙර ඇමතුමකින් එක් කළ හෝ client විසින් සැපයූ), අන්තර්ගතය
එලෙසම තබයි. `clear_thinking_20251015` සංස්කරණයක් ද තිබේ නම්, Anthropic විසින්
`edits[]` array එකේ `clear_thinking`, `clear_tool_uses` ට පෙර තිබීම අවශ්ය කරන බැවින්, OmniRoute
`clear_thinking` සංස්කරණය ඉදිරියට එන ලෙස ස්ථායීව අනුපිළිවෙළ සකසයි.

## එක් එක් combo සඳහා enable toggle එක

Context Editing පෙරනිමියෙන් **අක්රිය** වන අතර භාවිත කිරීමට තෝරා සක්රිය කළ යුතුය. toggle එක යනු
සම්පීඩන වින්යාසයේ ගෙන යන තනි boolean අගයකි:

- සැකසුම් key එක: `contextEditing.enabled` (camelCase — `context_editing` / `context-editing` **නොවේ**).
- වර්ගය: `open-sse/services/compression/types.ts` තුළ
  `ContextEditingConfig { enabled: boolean }`.
- පෙරනිමිය: `DEFAULT_CONTEXT_EDITING_CONFIG = { enabled: false }`.
- Zod schema එක: `src/shared/validation/compressionConfigSchemas.ts` තුළ `contextEditingConfigSchema`.
- ගබඩා කිරීම: අනෙකුත් සම්පීඩන සැකසුම් සමඟ ස්ථිරව සුරකියි
  (`src/lib/db/compression.ts` තුළ normalized කර ඇත).

dashboard එකේ toggle එක සම්පීඩන hub එකේ
(`src/app/(dashboard)/dashboard/context/combos/CompressionHub.tsx`) පවතින අතර `saveSettings()` හරහා
`{ contextEditing: { enabled: … } }` නැවත ලියයි. එය සම්පීඩන-සැකසුම් object එක මත රඳා පවතින බැවින්, සම්පූර්ණයෙන්ම
ස්වාධීන මතුපිටක් වීම වෙනුවට එක් එක් combo සඳහා වන සම්පීඩන profile එක සමඟ සංයුක්ත වේ — වින්යාසය රැගෙන යන්නේ on/off flag එක පමණි; සියලු සීමාවන් (`trigger`,
`keep`) ඉහත ලේඛනගත කර ඇති නියතයන් වේ.

## Claude සඳහා පමණක් වන ගේටින් කිරීම

ඇතුළත් කිරීම සිදුවන්නේ සත්ය Claude හෝ Claude-Code-අනුකූල රිලේ සඳහා පමණි.
`open-sse/executors/base.ts` හි ගේටය මෙසේය:

```ts
if (
  (this.provider === "claude" || isClaudeCodeCompatible(this.provider)) &&
  contextEditing?.enabled &&
  !contextEditingDisabled
) {
  applyContextEditingToBody(transformedBody, { enabled: true });
}
```

- `this.provider === "claude"` — සැබෑ Anthropic යතුර/OAuth.
- `isClaudeCodeCompatible(this.provider)` — provider id එක `anthropic-compatible-cc-` උපසර්ගයෙන් ආරම්භ වන රිලේ (ඒවා Claude Code අනුකූලතාව ප්රකාශ කරන බැවින්, බීටාව පිළිගැනීමට වඩාත් ඉඩ ඇති රිලේ ඒවාය). `open-sse/services/provider.ts` බලන්න.

හිතාමතාම **බැහැර කර ඇති** ඒවා:

- `claude-web` — කිසිවිටෙක `context_management` නොදකින `create_conversation_params` ඉල්ලීම් ආකෘතියක් සහිත බ්රවුසර රිලේ එකක්.
- සාමාන්ය `anthropic-compatible-*` රිලේ (`-cc-` උපසර්ගය නොමැති) — බීටා සහාය අවිනිශ්චිත තෙවන පාර්ශ්ව අන්ත ලක්ෂ්ය.

ටොගලය සක්රියව තිබුණද, Claude නොවන providers වෙත කිසිවිටෙක `context_management` පරාමිතිය නොලැබේ.

## 400 fallback / රිලේ ආවරණය

Claude-අනුකූල රිලේ එකක් බීටාව ප්රකාශ කළද, `context_management` පරාමිතිය HTTP 400 සමඟ ප්රතික්ෂේප කළ හැකිය. ඉල්ලීම අසාර්ථක කිරීම වෙනුවට සුමට ලෙස පසුබැසීමට, executor එක පරාමිතිය ඉවත් කර එම URL එකම **එක් වරක්** නැවත උත්සාහ කරයි:

```ts
if (
  response.status === HTTP_STATUS.BAD_REQUEST &&
  contextEditing?.enabled &&
  !contextEditingDisabled &&
  transformedBody?.context_management !== undefined
) {
  const errText = await response
    .clone()
    .text()
    .catch(() => "");
  if (/context[_-]management|context editing/i.test(errText)) {
    contextEditingDisabled = true;
    delete transformedBody.context_management;
    let retryBody = JSON.stringify(transformedBody);
    if (isClaudeCodeCompatible(this.provider) || this.provider === "claude") {
      retryBody = await signRequestBody(retryBody);
    }
    response = await fetch(url, { ...fetchOptions, body: retryBody });
  }
}
```

හැසිරීම:

1. මෙය ක්රියාත්මක වන්නේ context editing සක්රියව තිබියදී, body එකෙහි සැබවින්ම `context_management` අඩංගු වන අවස්ථාවක ලැබෙන `400` සඳහා පමණි.
2. නොගැළපෙන මාර්ගය සඳහා මුල් response එක නොවෙනස්ව තබාගැනීමට, 400 body එක `clone()` හරහා කියවනු ලැබේ.
3. දෝෂ පෙළ `/context[_-]management|context editing/i` සමඟ ගැළපිය යුතුය — සම්බන්ධයක් නොමැති 400 දෝෂයක් (උදා. `max_tokens must be >= 1`) fallback එක ක්රියාත්මක **නොකරයි**; මුල් දෝෂය ඉදිරියට ප්රචාරය වේ.
4. ගැළපීමකදී එය `contextEditingDisabled = true` ලෙස සකසයි (පසුව retry/fallback URL එකක් සඳහා නව `transformedBody` එකක් ගොඩනැගුවහොත් නැවත ඇතුළත් කිරීම මෙයින් වළක්වයි), `context_management` මකා දමයි, Claude / Claude-Code-අනුකූල රිලේ සඳහා body එක නැවත අත්සන් කරයි (`signRequestBody`), සහ එම URL එකම එක් වරක් නැවත උත්සාහ කරයි.

සත්ය Claude විසින් බීටාව `ANTHROPIC_BETA_BASE` තුළ රැගෙන යන අතර මෙම fallback මාර්ගයට නොපැමිණේ.

## `applied_edits` ටෙලිමෙට්රි

Claude response එකකින් පසුව, provider විසින් සැබවින්ම ඉවත් කළ context ප්රමාණය OmniRoute වාර්තා කරයි. මෙය **stream නොකෙරේ** — එය streaming නොවන response body එකෙන් හැකි උපරිමයෙන් උපුටාගන්නා අතර, කිසිවිටෙක response එකට බලපාන්නේ නැත (ටෙලිමෙට්රි අසාර්ථක වීම් නොසලකා හැරේ).

- උපුටාගැනීම: `open-sse/config/contextEditing.ts` හි `extractContextEditingTelemetry(responseBody)`.
  එය response ආකෘතියේ වෙනස්කම්වලට ප්රතිරෝධී ලෙස ස්ථාන තුනක `applied_edits` පරීක්ෂා කරයි:
  - `context_management.applied_edits`
  - `usage.context_management.applied_edits`
  - `usage.applied_edits`
- එක් එක් ප්රවේශයෙන් කියවන ක්ෂේත්ර: `cleared_input_tokens` සහ `cleared_tool_uses`
  (snake_case, Anthropic-ස්වදේශීය), `clearedInputTokens` / `clearedToolUses` camelCase විකල්ප සමඟ.
- `applied_edits` array එකක් හමු නොවූ විට හෝ කිසිවක් සැබවින්ම ඉවත් කර නොමැති විට `null` ආපසු ලබා දෙයි.

රිසිට්පතේ ආකෘතිය `ContextEditingTelemetry { editCount, clearedInputTokens, clearedToolUses }` වේ.
වාර්තා කිරීම `open-sse/handlers/chatCore.ts` තුළ (`provider === "claude"` සඳහා සීමා කර) `recordContextEditingTelemetry()` (`src/lib/db/compressionAnalytics.ts`) හරහා සිදු වන අතර, එය පහත ටැග් සහිත compression analytics පේළියක් ලියයි:

- `mode: "context-editing"`
- `engine: "context-editing"`
- `tokens_saved` / `original_tokens` = ඉවත් කළ input-token ගණන
- `request_id` සඳහා `::context-editing` ප්රත්යය එක් කර ඇත

එබැවින් පැවරූ clearing දේශීය engines සමඟ compression analytics තුළ `context-editing` engine ලේබලය යටතේ පෙන්වෙන අතර, එය RTK/Caveman/LLMLingua ඉතිරිකිරීම්වලින් වෙන්කර හඳුනාගත හැකිය.
