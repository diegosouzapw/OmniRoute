## දළ විශ්ලේෂණය

OmniRoute විසින් ඉහළ මට්ටමේ සැපයුම්කරුවන් වෙත ඉල්ලීම් ළඟා වීමට **පෙර ක්රියාශීලීව** ධාවනය වන මොඩියුලර් ප්රොම්ප්ට් සම්පීඩන නළ මාර්ගයක් ක්රියාත්මක කරයි. මෙයින් අදහස් වන්නේ ඔබේ ටෝකන ඉතිරිය විනිවිද පෙනෙන ලෙස සිදුවන බවයි — ඔබේ කාර්ය ප්රවාහයට කිසිදු වෙනසක් අවශ්ය නොවේ.

```
සේවාලාභී ඉල්ලීම
  → සම්පීඩන උපායමාර්ග තේරීම
    → Combo අභිබවා යාමක්ද? → Combo සැකසුම භාවිත කරන්න
    → ස්වයංක්රීය-ප්රේරක සීමාවද? → ස්වයංක්රීය ප්රකාරය භාවිත කරන්න
    → පෙරනිමි ප්රකාරයද? → ගෝලීය සැකසුම භාවිත කරන්න
    → අක්රියද? → සම්පීඩනය මඟහරින්න
  → තෝරාගත් සම්පීඩන ප්රකාරය
    → අක්රිය: සම්පීඩනයක් නැත
    → සැහැල්ලු: ආරක්ෂිත හිස්තැන්/ආකෘතිකරණ පිරිසිදු කිරීම (~15%)
    → සම්මත: Caveman-ශෛලියේ පිරවුම් වචන ඉවත් කිරීම (~30%)
    → ආක්රමණශීලී: ඉතිහාසය වියපත් කිරීම + සාරාංශකරණය (~50%)
    → අතිශය: හියුරිස්ටික් කප්පාදුව + කේත-කොටස් තුනී කිරීම (~75%)
    → RTK: විධාන-දැනුවත් ටර්මිනල්/මෙවලම්-ප්රතිදාන පෙරීම (ඉහළ මට්ටමේ 60-90% පරාසය)
    → ස්තරගත: අනුපිළිවෙළට සැකසූ බහු-එන්ජින් නළ මාර්ගය, සාමාන්යයෙන් RTK පසුව Caveman (සුදුසුකම් ලබන 78-95% පරාසය)
  → සම්පීඩිත ඉල්ලීම → සැපයුම්කරු
```

## සම්පීඩන ප්රකාර

### අක්රිය

කිසිදු සම්පීඩනයක් යොදනු නොලැබේ. සියලුම පණිවිඩ වෙනස් නොවී හුවමාරු වේ.

### සැහැල්ලු ප්රකාරය (~15% ඉතිරිය, <1ms ප්රමාදය)

ආරක්ෂිතම ප්රකාරය — අර්ථයට කිසිදු වෙනසක් නොකර, ආකෘතිකරණය පමණක් පිරිසිදු කරයි:

| ශිල්පීය ක්රමය            | විස්තරය                                          |
| ------------------------ | ------------------------------------------------ |
| `collapseWhitespace`     | අඛණ්ඩ හිස් පේළි සහ පේළි අග හිස්තැන් ඒකාබද්ධ කරයි |
| `dedupSystemPrompt`      | අනුපිටපත් පද්ධති පණිවිඩ ඉවත් කරයි                |
| `compressToolResults`    | විස්තීර්ණ මෙවලම්/ශ්රිත ප්රතිදාන සම්පීඩනය කරයි    |
| `removeRedundantContent` | නැවත නැවත ඇති උපදෙස් ඉවත් කරයි                   |
| `replaceImageUrls`       | base64 රූප දත්ත URI කෙටි කරයි                    |

**වඩාත් සුදුසු:** සැමවිටම සක්රිය භාවිතය, ආරක්ෂාව තීරණාත්මක වන කාර්ය ප්රවාහ.

### සම්මත ප්රකාරය (~30% ඉතිරිය)

[Caveman](https://github.com/JuliusBrussee/caveman) වෙතින් ආභාසය ලබා ඇත — අර්ථය රැකගනිමින් පිරවුම් වචන සහ අනවශ්ය ලෙස දිගු වාක්ය ඛණ්ඩ ඉවත් කරයි:

- පිරවුම් වචන ඉවත් කරයි ("කරුණාකර", "මම හිතන්නේ", "මූලික වශයෙන්", "ඇත්ත වශයෙන්ම")
- අනවශ්ය ලෙස දිගු වාක්ය ඛණ්ඩ සංක්ෂිප්ත කරයි ("කිරීම සඳහා" → "කිරීමට", "ප්රතිඵලයක් ලෙස" → "නිසා")
- විනීත දෙගිඩියාව ඉවත් කරයි ("ඔබට අපහසු නැත්නම්...", "ඔබට හැකි නම්...")
- කේතකරණ ප්රොම්ප්ට් සඳහා සකස් කළ regex රීති 30කට වැඩි ගණනක්

**වඩාත් සුදුසු:** දෛනික කේතකරණ කාර්ය ප්රවාහ, පිරිවැය ගැන සැලකිලිමත් කණ්ඩායම්.

### ආක්රමණශීලී ප්රකාරය (~50% ඉතිරිය)

දිගු සැසි සඳහා බුද්ධිමත් ඉතිහාස කළමනාකරණය:

- **පණිවිඩ වියපත් කිරීම** — පැරණි පණිවිඩ ක්රමයෙන් වැඩි වශයෙන් සම්පීඩනය කරයි
- **මෙවලම් ප්රතිඵල සාරාංශකරණය** — දිගු මෙවලම් ප්රතිදාන සාරාංශවලින් ප්රතිස්ථාපනය කරයි
- **ව්යුහාත්මක අඛණ්ඩතා ආරක්ෂක** — `tool_use` + `tool_result` යුගල සංගතව පවතින බව සහතික කරයි
- **සන්දර්භ කවුළු පිළිබඳ අවබෝධය** — එක් එක් මාදිලියේ ටෝකන සීමාවලට ගරු කරයි

**වඩාත් සුදුසු:** දීර්ඝ දෝෂහරණ සැසි, විශාල කේත පදනම්.

### අතිශය ප්රකාරය (~75% ඉතිරිය)

ටෝකන තීරණාත්මක වන අවස්ථා සඳහා උපරිම සම්පීඩනය:

- **හියුරිස්ටික් කප්පාදුව** — අදාළතා සීමාවට පහළ පණිවිඩ ඉවත් කරයි
- **කේත කොටස් තුනී කිරීම** — පුනරාවර්තන කේත උදාහරණ සම්පීඩනය කරයි
- **ද්විමය සෙවුම් කප්පාදුව** — සන්දර්භ කවුළුව සඳහා ප්රශස්ත කැපුම් ලක්ෂ්යය සොයයි
- ආක්රමණශීලී ප්රකාරයේ සියලුම විශේෂාංග ඇතුළත් වේ

**වඩාත් සුදුසු:** ඔබ නැවත නැවතත් සන්දර්භ සීමාවලට ළඟා වන විට.

### RTK ප්රකාරය (ඉහළ මට්ටමේ 60-90% පරාසය)

RTK ප්රකාරය කේතකරණ නියෝජිත සැසිවල දිස්වන විස්තීර්ණ මෙවලම් ප්රතිදාන සඳහා ප්රශස්ත කර ඇත:

- `git status`, `git diff`, `git log`, පරීක්ෂණ ධාවක,
  TypeScript/Vite/Webpack ගොඩනැගීම්, ESLint/Biome/Prettier, npm විගණන/ස්ථාපන, Docker ලොග්, යටිතල පහසුකම්
  ප්රතිදාන සහ සාමාන්ය shell ප්රතිදාන වැනි විධාන/ප්රතිදාන පන්ති හඳුනාගනී

- පේළිගත-පරීක්ෂණ වලංගුකරණය සහ ව්යාපෘති ගොනු සඳහා විශ්වාස-පාලනය සමඟින්, ව්යාපෘති හෝ ගෝලීය `filters.toml` ගොනුවලින් RTK TOML schema v1 පෙරහන් ආයාත කරයි
- පේළිගත සත්යාපන සාම්පල සමඟ ඇතුළත් පෙරහන් 49ක් සපයයි
- ANSI පාලන අනුක්රම, ප්රගති තීරු, පුනරාවර්තන පේළි සහ ක්රියාමාර්ග ගත නොහැකි අනවශ්ය දත්ත ඉවත් කරයි
- අසමත්වීම්, දෝෂ, අනතුරු ඇඟවීම්, වෙනස් කළ ගොනු, සාරාංශ සහ දිගු ප්රතිදානයේ අවසාන කොටස රැකගනී
- විශ්වාස-පාලිත ව්යාපෘති පෙරහන්, ගෝලීය පෙරහන් සහ විකල්ප සංවේදී තොරතුරු ඉවත් කළ අමු-ප්රතිදාන ප්රතිසාධනය සඳහා සහාය දක්වයි

**වඩාත් සුදුසු:** shell, build, test, git, grep සහ ගොනු-ප්රතිදාන පිටපත් සහිත නියෝජිත සැසි.

### ස්තරගත ප්රකාරය (සුදුසුකම් ලබන 78-95% පරාසය)

ස්තරගත ප්රකාරය සම්පීඩන එන්ජින් කිහිපයක් නියත අනුපිළිවෙළකට ධාවනය කරයි. පෙරනිමි නළ මාර්ගය වන්නේ:

```txt
RTK -> Caveman
```

එම අනුපිළිවෙළ පළමුව ටර්මිනල්/මෙවලම් ප්රතිදානය සංක්ෂිප්තව තබා, ඉන් පසුව ඉතිරි ස්වාභාවික-භාෂා ප්රොම්ප්ට් වෙත Caveman අර්ථාන්විත සංක්ෂිප්තකරණය යොදයි. ස්තරගත නළ මාර්ග ගෝලීයව හෝ මාර්ගගත කිරීමේ combo වෙත පවරන ලද සම්පීඩන combo හරහා වින්යාස කළ හැකිය.

**වඩාත් සුදුසු:** විශාල මෙවලම් ලොග් සමඟ මානව උපදෙස් හෝ සහායක සාරාංශ අඩංගු මිශ්ර සන්දර්භ.

## Upstream ඉතුරුම් ගණනය

OmniRoute සම්පීඩන ඉතුරුම් මූලාශ්ර දෙකක් මත පදනම්ව ලේඛනගත කරයි: upstream ව්යාපෘති මිණුම් සලකුණු සහ
OmniRoute හිම engine සංයෝජනය.

| මූලාශ්රය | මෙහි භාවිත කරන Upstream README අගය                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Caveman  | ප්රතිදාන tokens `~75%`ක් අඩුය, මිණුම් සලකුණු සාමාන්ය ප්රතිදාන ඉතුරුම `65%`කි, පරාසය `22-87%`කි, සහ ආදාන සම්පීඩන මෙවලම `~46%`කි |
| RTK      | විධාන-ප්රතිදාන ඉතුරුම් `60-90%`කි; නියැදි සැසියක tokens `~118,000 -> ~23,900`, හෝ `79.7%`ක ඉතුරුමක් (`~80%`)                   |

එකිනෙක අතිච්ඡාදනය වන මෙවලම්/සන්දර්භ payload සඳහා, පෙරනිමි OmniRoute සංයෝජනය engines එක මත එක යොදයි:

```txt
RTK -> Caveman
```

ඒකාබද්ධ ඉතුරුම් ආකලනීය නොව, ගුණාකාර වේ:

```txt
combined = 1 - (1 - RTK savings) * (1 - Caveman input savings)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

RTK සහ Caveman යන දෙකටම එකම ආදාන/සන්දර්භ payload එක අඩු කළ හැකි විට එම `78-95%` අගය අදාළ වේ.
Caveman ප්රතිචාර ප්රතිදාන මාදිලිය වෙනම එකකි: එය සක්රීය කළ විට, Caveman හිම ප්රතිදාන ඉතුරුම් (සාමාන්යය `65%`,
ප්රධාන අගය `~75%`, පරාසය `22-87%`) භාවිත කරන්න. මුළු බිල්පත් ඉතුරුම් ඔබගේ prompt/ප්රතිදාන මිශ්රණය මත රඳා පවතී.

### "eligible" යන්නෙන් සැබවින්ම අදහස් වන්නේ කුමක්ද

15-95% ප්රධාන පරාසය සැබෑ එකක් වුවත්, එය අදාළ වන්නේ **අතිරික්ත හෝ අනවශ්ය ලෙස දීර්ඝ** අන්තර්ගතයට පමණි — නැවත නැවත
එන දෝෂ පේළි, එකම අනතුරු ඇඟවීම අධික ලෙස නැවත දක්වන build log එකක්, ප්රමාණය ඉක්මවූ `grep`/ගොනු-කියවීම් dump එකක්.
එයින් සෑම ඉල්ලීමක්ම එතරම් ප්රමාණයකින් ඉතිරි කරන බව **අදහස් නොවේ**.

ප්රායෝගිකව සත්යාපනය කර ඇත (`tests/unit/compression/stacked-compression-tool-result-savings.test.ts`): සමාන

## වින්යාසය

### උපකරණ පුවරුව

`Dashboard → Context & Cache` වෙත යන්න:

- **Caveman** — මාදිලි තේරීම, භාෂා පැකේජ, පෙරදසුන, සහ ගෝලීය පෙරනිමි
- **RTK** — විධාන-පෙරහන් පෙරදසුන, RTK ආරක්ෂක සැකසුම්, සහ පෙරහන් නාමාවලිය
- **Compression Combos** — රවුටින් කොම්බෝ වලට පවරා ඇති නම් කරන ලද එන්ජින් පයිප්ලයින්
- **Auto-Trigger Threshold** — ටෝකන් ගණන සීමාව ඉක්මවා ගිය විට ස්වයංක්රීයව සම්පීඩනය ක්රියාත්මක කරන්න

### එක්-කොම්බෝ අධිලේඛනය

`Dashboard → Context & Cache → Compression Combos` හි, රවුටින් කොම්බෝ එකකට සම්පීඩන කොම්බෝ එකක් පවරන්න:

```txt
Combo: "free-tier-fallback"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

මෙය ඔබට නොමිලේ/කේතීකරණ සපයන්නන් මත ස්ටැක් කරන ලද සම්පීඩනය භාවිතා කිරීමට ඉඩ සලසයි, ගෙවන ලද දායකත්වයන් මත ලයිට් මාදිලිය තබා ගනිමින්.

මෙම "Per-Combo Override" පැවරුම **routing-combo compression mode** override (Default/Off/Lite/Standard/Aggressive/Ultra) ට වඩා වෙනස් පාලනයකි — එම override එක නම් කරන ලද සම්පීඩන-කොම්බෝ පයිප්ලයින් එකක් තෝරා නොගනී; එය `resolveCompressionPlan` මගින් විමසන `compressionMode` ක්ෂේත්රය පමණක් සකසයි. එය කොම්බෝ කාඩ්පතේ (`Dashboard → Combos`) හෝ, #6760 සිට, `Dashboard → Context & Cache → Compression Combos` හි "Assign to routing" ලැයිස්තුවේ එක් එක් රවුටින් කොම්බෝ එකකට, ඉහත ලේඛනගත කර ඇති පයිප්ලයින්-පැවරුම් චෙක්බොක්ස් එකට යාබදව සැකසිය හැක. පෘෂ්ඨ දෙකම එකම `PUT /api/combos/{id}` අන්ත ලක්ෂ්යය හරහා පවතී.

### එක්-ඉල්ලීමකට අධිලේඛනය

තනි ඉල්ලීමක් සඳහා සම්පීඩන සැලැස්ම අධිලේඛනය කිරීමට `x-omniroute-compression` ඉල්ලීම් ශීර්ෂය යවන්න. එයට ඉහළම ප්රමුඛතාවය ඇත — එය රවුටින්-කොම්බෝ අධිලේඛනය, සක්රීය පැතිකඩ, ස්වයංක්රීය-ප්රේරකය, සහ පැනලයේ පෙරනිමිය පරාජය කරයි. නොදන්නා අගයන් නොසලකා හරිනු ලැබේ (ඉල්ලීම කිසි විටෙක ප්රතික්ෂේප නොවේ) සහ ගෝලීය ප්රධාන ස්විචය තවමත් සියල්ල පාලනය කරයි: සම්පීඩනය ගෝලීයව අක්රිය වූ විට, ශීර්ෂයට එය ක්රියාත්මක කළ නොහැක. අගයන්:

| අගය           | බලපෑම                                                                                        |
| ------------- | -------------------------------------------------------------------------------------------- |
| `off`         | මෙම ඉල්ලීම සඳහා සම්පීඩනයක් නැත.                                                              |
| `default`     | පැනලයෙන් ලබාගත් පෙරනිමි පැතිකඩ (සක්රීය පැතිකඩ නොසලකා හරියි). හානිකර එන්ජින් අක්රියව පවතී.    |

| `engine:<id>` | සක්රිය කළ විට තනි එන්ජිමක්, උදා: `engine:rtk`. මෙය එම එන්ජිම සඳහා එක්-ඉල්ලීමකට තෝරා ගැනීමයි. |
| `<combo>`     | නම් කරන ලද කොම්බෝ එකක්, මුලින් නම අනුව (අකුරු සංවේදී නොවන), පසුව id අනුව ගැලපේ.              |

`allow-lossy`, `engine:<id>`, හෝ නම් කරන ලද කොම්බෝ එකක් නොමැතිව, හානිකර එන්ජින් යොදනු නොලැබේ. සම්පීඩනය ක්රියාත්මක වන විට ඉල්ලීමට තවමත් සැසි අනුපිටපත් ඉවත් කිරීම සහ හිස්තැන් නැවීම ලැබේ.

යොදන ලද සැලැස්ම `X-OmniRoute-Compression: <mode>; source=<source>` ප්රතිචාර ශීර්ෂයේ නැවත දෝංකාර දෙනු ලැබේ, එහිදී `<source>` යනු `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, හෝ `off` වලින් එකකි.

curl http://localhost:20128/api/settings/compression

## උසස් සම්පීඩන පද්ධති

සම්මත ක්රම 7ට අමතරව, OmniRoute සන්දර්භය මත පදනම්ව ස්වයංක්රීයව ක්රියා කරන උසස් සම්පීඩන පද්ධති කිහිපයක් ඇතුළත් වේ.

### හැඹිලි-දැනුවත් සම්පීඩනය

සමහර සපයන්නන් (prompt caching සහිත Anthropic වැනි) **prompt caching** සඳහා සහය දක්වයි, එමඟින් පිරිවැය සහ ප්රමාදය අඩු කිරීම සඳහා prompt හි කොටස් හැඹිලිගත කිරීමට ඔවුන්ට ඉඩ සලසයි. හැඹිලිගත කිරීම සක්රීය කර ඇති විට, ආක්රමණශීලී සම්පීඩනය ඇත්ත වශයෙන්ම කාර්ය සාධනයට **හානි** කළ හැකිය, මන්ද එය හැඹිලිගත ටෝකන වෙනස් කරන අතර, හැඹිලිය අවලංගු කරයි.

`cachingAware.ts` මොඩියුලය **හැඹිලි සන්දර්භය හඳුනා ගැනීමෙන්** සහ ඒ අනුව **සම්පීඩන උපාය මාර්ගය සකස් කිරීමෙන්** මෙය විසඳයි.

#### එය ක්රියා කරන ආකාරය

1. **හැඹිලි සන්දර්භය හඳුනා ගන්න** — `cache_control` සලකුණු සඳහා ඉල්ලීම් ශරීරය පරිලෝකනය කරයි
2. **හැඹිලි සපයන්නන් හඳුනා ගන්න** — ඉලක්කගත සපයන්නා හැඹිලිගත කිරීමට සහය දක්වන්නේ දැයි පරීක්ෂා කරයි
3. **උපාය මාර්ගය සකස් කරන්න** — හැඹිලි සපයන්නන් සඳහා `aggressive`/`ultra` `standard` වෙත පහත හෙළයි
4. **පද්ධති prompt මඟ හරින්න** — පද්ධති prompts සාමාන්යයෙන් හැඹිලිගත කර ඇත, එබැවින් ඒවා සම්පීඩනය නොකරන්න
5. **නිශ්චිත පරිවර්තන භාවිතා කරන්න** — ස්ථාවර ප්රතිදානයක් නිපදවන පරිවර්තන පමණක් භාවිතා කරන්න

#### කේත උදාහරණය

```ts
import {
  detectCachingContext,
  getCacheAwareStrategy,
} from "@omniroute/open-sse/services/compression/cachingAware";

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← හැඹිලි සලකුණ
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### කවදාද භාවිතා කළ යුත්තේ

හැඹිලි-දැනුවත් සම්පීඩනය **සැමවිටම ක්රියාත්මකයි** — වින්යාස කිරීමක් අවශ්ය නොවේ. එය ක්රියාත්මක වන්නේ:

- ඉල්ලීමට `cache_control` සලකුණු ඇති විට
- ඉලක්කගත සපයන්නා prompt caching සඳහා සහය දක්වන විට (Anthropic, OpenAI, ආදිය)

### ප්රගතිශීලී වයස්ගත වීම

දිගු සංවාදවලදී බොහෝ පණිවිඩ වාර ගණනක් එකතු වේ, නමුත් පැරණි වාර ගණන අඩු අදාළ වේ. `progressiveAging.ts` මොඩියුලය **වාර ගණන දුර අනුව පණිවිඩ පිරිහීමට ලක් කරයි**:

- **නවතම වාර ගණන (0-3)**: වචනානුසාරයෙන් තබා ඇත (සම්පූර්ණ විස්තරය)
- **මධ්යම වාර ගණන (4-8)**: සැහැල්ලු සම්පීඩනය (හිස්තැන්, ආකෘතිකරණ පිරිසිදු කිරීම)
- **පැරණි වාර ගණන (9+)**: ගුහා මානව සම්පීඩනය (පිරවුම් ඉවත් කිරීම, සාරාංශ කිරීම)
- **ඉතා පැරණි වාර ගණන (20+)**: දැඩි ලෙස සාරාංශ කර හෝ ඉවත් කර ඇත

#### කේත උදාහරණය

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... තවත් වාර 50ක් ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // පළමු වාර 3: වචනානුසාරයෙන්
  light: 8, // වාර 4-8: සැහැල්ලු සම්පීඩනය
  moderate: 20, // වාර 9-20: ගුහා මානව සම්පීඩනය
  // වාර 21+: දැඩි සාරාංශකරණය
});

// saved = ඉතිරි කළ ටෝකන ගණන
```

#### කවදාද භාවිතා කළ යුත්තේ

`aggressive` සහ `ultra` ක්රම සඳහා ප්රගතිශීලී වයස්ගත වීම **සැමවිටම ක්රියාත්මකයි**. එය විශේෂයෙන් ඵලදායී වන්නේ:

- දිගු කාලීන කේතීකරණ සැසි
- දින කිහිපයක සංවාද
- බොහෝ මෙවලම් ඇමතුම් සහිත නියෝජිත වැඩ ප්රවාහයන්

### ගුහා මානව ප්රතිදාන ක්රමය

`outputMode.ts` මොඩියුලය **පද්ධති prompt උපදෙස්** ඇතුළත් කරයි, එමඟින් ආකෘතියම සම්පීඩිත, කෙටි ප්රතිදානයක් ("ගුහා මානව" ශෛලියක්) නිපදවීමට සලස්වයි.

#### එය ක්රියා කරන ආකාරය

ආදානය සම්පීඩනය කරනවා වෙනුවට, මෙම ක්රමය පද්ධති prompt එකක් එක් කරයි:

> "අවම වචන වලින් පිළිතුරු දෙන්න. සුහදශීලී බව මඟ හරින්න. කෙටි වාක්ය භාවිතා කරන්න."

මෙය විශේෂයෙන් හොඳින් ක්රියා කරන්නේ:

- කේත උත්පාදනය (කෙටි ප්රතිදානය = අඩු ටෝකන)
- ඉක්මන් ප්රශ්නෝත්තර (විස්තීර්ණ පැහැදිලි කිරීම් අවශ්ය නොවේ)
- කණ්ඩායම් සැකසීම (උපරිම ඵලදායිතාව)

#### කවදාද භාවිතා කළ යුත්තේ

ගුහා මානව ප්රතිදාන ක්රමය **තෝරාගත හැකි** — එය combo config හරහා සකසන්න:

  "config": {
    "auto": {
      "outputMode": "caveman"
    }
  }
}

ඉදිරියට පටවයි — නැවත යෙදීම no-op එකකි. හඳුනාගත් ඉල්ලීම් භාෂාවට පරිවර්තනයක්
ඇති විට, ඉංග්රීසි වෙනුවට දේශීයකරණය කළ උපදෙස් එන්නත් කරනු ලැබේ.

#### සක්රීය කරන්නේ කෙසේද

ඩෑෂ්බෝඩ් එකේ: **Context → Settings → Compression** — එක් එක් විලාසය සඳහා
on/off ටොගලයක් සහ මට්ටම් තේරීමක් සහිත එක් පේළියක්. ක්රමලේඛනාත්මකව, සම්පීඩන
වින්යාසය තේරීම මෙලෙස පවත්වා ගනී:

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

අතර `terse-prose` වෙත සිතියම්ගත වේ, සෑම පැරණි භාෂාවකම පැරණි එන්නත් කිරීමට
බයිට්-සමාන වේ.

භාෂා තේරීම: `languageConfig.enabled` සක්රියව ඇති විට, `autoDetect`

`autoDetect` අක්රිය කිරීම `defaultLanguage` අගුළු දමයි. අක්රිය → ඉංග්රීසි.

### මෙවලම් ප්රතිඵල සම්පීඩනය

`toolResultCompressor.ts` මොඩියුලය මෙවලම් ප්රතිඵල සඳහා **විශේෂිත සම්පීඩන
උපාය මාර්ග 5ක්** සපයයි (ශ්රිත ඇමතුම්, නියෝජිත ප්රතිදාන, සෙවුම් ප්රතිඵල, ආදිය):

1. **සෙවුම් ප්රතිඵල සම්පීඩනය** — අතිරික්ත ප්රතිඵල ඉවත් කරයි, ඉහළ-N තබා ගනී
2. **ගොනු කියවීමේ සම්පීඩනය** — විශාල ගොනු කපා දමයි, ශීර්ෂ/ආනයන ආරක්ෂා කරයි
3. **කේත ක්රියාත්මක කිරීමේ සම්පීඩනය** — අත්යවශ්ය stdout/stderr පමණක් තබා ගනී
4. **දත්ත සමුදා විමසුම් සම්පීඩනය** — පේළි සීමා කරයි, විස්තරාත්මක මෙටා දත්ත ඉවත් කරයි

#### කවදාද භාවිතා කළ යුත්තේ

මෙවලම් ඇමතුම් ඇති විට මෙවලම් ප්රතිඵල සම්පීඩනය **සැමවිටම සක්රියව** පවතී.
වින්යාස කිරීමක් අවශ්ය නොවේ.

### ස්ථරගත නල මාර්ගය

ස්ථරගත මාදිලිය **අනුපිළිවෙලින් බහු එන්ජින්** ක්රියාත්මක කරයි — සාමාන්යයෙන්
මුලින් RTK (මෙවලම් ප්රතිදානය මත 60-90% ඉතිරිකිරීම්), පසුව Caveman (ඉතිරි
පෙළ මත 30% අමතර ඉතිරිකිරීම්). මෙය **78-95% මුළු ඉතිරිකිරීම්** ලබා ගනී.

#### එය ක්රියා කරන ආකාරය

```
ආදානය (1000 ටෝකන)
  → RTK (විධාන-දැනුවත් පෙරහන) → 200 ටෝකන
    → Caveman (පිරවුම් ඉවත් කිරීම) → 140 ටෝකන
  → ප්රතිදානය (140 ටෝකන, 86% ඉතිරිකිරීම්)
```

#### කවදාද භාවිතා කළ යුත්තේ

ස්ථරගත මාදිලිය භාවිතා කරන්න:

- මෙවලම්-බර වැඩ ප්රවාහයන් (නියෝජිත කේතීකරණය, පර්යේෂණ)
- පිරිවැය-සංවේදී කණ්ඩායම් සැකසීම
- ඔබට උපරිම ටෝකන ඉතිරිකිරීම් අවශ්ය විට

සංයෝජනය හරහා වින්යාස කරන්න:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "modePack": "stacked"
    }
  }
}
```

## සම්පීඩන Combo අභිබවා යාම්

විවිධ භාවිත අවස්ථා සඳහා හැසිරීම සියුම්ව සකස් කිරීමට, ගෝලීය සම්පීඩන ප්රකාරය **එක් එක් combo සඳහා** අභිබවා යා හැක:

```json
{
  "id": "coding-combo",
  "strategy": "priority",
  "config": {
    "auto": {
      "weights": { "taskFit": 0.5 },
      "modePack": "quality-first"
    }
  },
  "compressionOverride": {
    "mode": "aggressive",
    "stackedPipelines": ["rtk", "caveman"],
    "preserveToolDefinitions": true
  }
}
```

මෙය පහත අවස්ථා සඳහා ප්රයෝජනවත් වේ:

- **කේතකරණ combos**: දිගු සැසි සඳහා `aggressive` ප්රකාරය භාවිත කරන්න
- **ඉක්මන් ප්රශ්නෝත්තර combos**: වේගවත් ප්රතිචාර සඳහා `lite` ප්රකාරය භාවිත කරන්න
- **මෙවලම් බහුල combos**: උපරිම ඉතිරිකිරීම් සඳහා `stacked` ප්රකාරය භාවිත කරන්න
- **නිෂ්පාදන combos**: හැඹිලිගත කිරීමේ සේවා සපයන්නන් සඳහා `cache-aware` ප්රකාරය භාවිත කරන්න
