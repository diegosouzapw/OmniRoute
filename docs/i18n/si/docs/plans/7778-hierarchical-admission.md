1. පවතින තනි-යතුරු semaphore ගිවිසුම සහ නව atomic බහු-යතුරු ගිවිසුම ඉලක්කගත පරීක්ෂණ මඟින් ස්ථිර කරන්න: අර්ධ වෙන්කිරීම් නොතිබීම, FIFO පෝලිම්ගත කිරීම, අවලංගු කිරීම, කාලසීමාව ඉක්මවීම, පෝලිම පිරීම, idempotent මුදාහැරීම, සංඛ්යාලේඛන සහ පිරිසිදු කිරීම.
2. පවතින account semaphore එක එය තිබෙන ස්ථානයේම සාමාන්යකරණය කරන්න. `acquire()` යනු `acquireMany()` වටා ඇති අනුකූලතා wrapper එකක් ලෙස තබාගන්න; දෙවන scheduler එකක් හෝ dependency එකක් එක් නොකරන්න.
3. `chatCore` තුළ ඇති account-පමණක් acquisition එක, `withRateLimit` ට වහාම පෙර සිදු කරන එක් සමුච්චිත global/provider/account acquisition එකකින් ප්රතිස්ථාපනය කරන්න. account rotation එක connection එක වෙනස් කරන සෑම අවස්ථාවකම සම්පූර්ණ කට්ටලය නැවත ලබාගන්න, සහ streaming සම්පූර්ණ වන තෙක් release එක රඳවාගන්න.
4. පවතින resilience settings pipeline එක (types, defaults, normalization, schema, API response, UI සහ translations) global සහ provider caps සමඟ පුළුල් කරන්න. පැරණි Bottleneck concurrency control එකේ සැබෑ විෂයපථය පැහැදිලි වන පරිදි එය connection/quota-scope concurrency ලෙස නැවත ලේබල් කරන්න.
5. ඉලක්කගත පරීක්ෂණ, lint, typecheck, static checks සහ සම්පූර්ණ test suite එක ධාවනය කරන්න; හැසිරීම් වෙනස changelog එකේ ලේඛනගත කරන්න.

හිතාමතාම පවත්වාගෙන යන හැසිරීම්: zero/null concurrency එකක් gate එක මඟහරියි, account-පමණක් callers දිගටම `acquire()` භාවිත කරයි, blocked-account controls ඒවායේ key format සහ API එක එලෙසම පවත්වාගනී, සහ provider rate-limit queue හැසිරීම වෙනස් නොවේ.
