## විශේෂාංග ෆ්ලෑග් යනු මොනවාද

විශේෂාංග ෆ්ලෑගයක් යනු ධාවනකාලයේදී අගය වෙනස් කර දත්ත සමුදායේ සුරැකිය හැකි,
ක්රියාවලිය නැවත යෙදවීමක් අවශ්ය නොවන, නමක් සහිත ටොගලයකි (boolean හෝ enum).
සෑම ෆ්ලෑගයක්ම `key`, `label`, `description`, `category`, `defaultValue`,
`type`, සහ `requiresRestart` ඉඟියක් සහිත `FeatureFlagDefinition` එකකින් විස්තර කෙරේ.

### නිරාකරණ අනුපිළිවෙළ

ෆ්ලෑගයක **බලපැවැත්වෙන අගය**
[`resolveFeatureFlag()`](../../src/shared/utils/featureFlags.ts) මඟින් පහත
ප්රමුඛතා අනුපිළිවෙළට අනුව නිරාකරණය කෙරේ (ඉහළම ප්රමුඛතාව ජය ගනී):

1. **DB අතික්රමණය** — `feature_flags` නාම අවකාශය යටතේ `key_value` වගුවේ
   ගබඩා කර ඇති අගයක් (උපකරණ පුවරුව හෝ REST API එක හරහා සකසා ඇත).
2. **පරිසර විචල්යය** — සකසා ඇති සහ හිස් නොවන විට `process.env[<KEY>]`.
3. **අර්ථ දැක්වීමේ පෙරනිමිය** — `featureFlagDefinitions.ts` හි `defaultValue`.

boolean ෆ්ලෑගයක බලපැවැත්වෙන අගය `"true"`, `"1"`, හෝ `"yes"` වන විට එය
**සක්රීය** ලෙස සැලකේ (`isFeatureFlagEnabled()` බලන්න).

> [!NOTE]
> බොහෝ ෆ්ලෑග් සඳහා [`ENVIRONMENT.md`](./ENVIRONMENT.md) හි ලේඛනගත කර ඇති
> **එම නමින්ම** යුත් ගැළපෙන පරිසර විචල්යයක් ද ඇත. ෆ්ලෑගයේ DB අතික්රමණයට
> එම පරිසර විචල්යයට වඩා ප්රමුඛතාව ලැබේ. `requiresRestart: true` සහිත
> ෆ්ලෑගයක් වහාම සුරැකෙන නමුත් එය නැවත කියවනු ලබන්නේ ක්රියාවලිය ආරම්භ වන
> අවස්ථාවේදී පමණි — එය ටොගල් කිරීමෙන් උපකරණ පුවරුවේ **"සේවාදායකය නැවත අරඹන්න"**
> බැනරයක් දිස් වේ.

## කොඩි ක්රියාත්මක/අක්රිය කිරීම

### පාලක පුවරුව

**පාලක පුවරුව → සැකසුම් → විශේෂාංග කොඩි**
(`/dashboard/settings/feature-flags`) වෙත යන්න.
ජාලකය (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagsGrid.tsx`) පහත දේට සහය දක්වයි:

- යතුරෙන් හෝ විස්තරයෙන් **සොයන්න**, සහ ප්රවර්ගය අනුව **පෙරහන් කරන්න** (අතිරේකව කෘතිම **නැවත ආරම්භ කිරීම අවශ්යයි** දසුනක්ද ඇත).
- බූලියන් කොඩි සඳහා **ටොගලයක්** සහ එනම් කොඩි සඳහා **පතන මෙනුවක්**
  (`src/app/(dashboard)/dashboard/settings/components/FeatureFlagCard.tsx`).
- සෑම කොඩියක් සඳහාම **මූලාශ්ර ලාංඡනයක්** — `DB`, `ENV`, හෝ `DEF` — ඵලදායී අගය පැමිණියේ කොහෙන්දැයි පෙන්වයි.
- අධිලේඛනය ඉවත් කිරීමට **නැවත පිහිටුවන්න** බොත්තමක් (`DB`-මූලාශ්ර කොඩි සඳහා පමණක් පෙන්වයි), සහ පහළින් **සියලු අධිලේඛන නැවත පිහිටුවන්න** බොත්තමක්.
- `requiresRestart` කොඩියක් වෙනස් කළ විට **සේවාදායකය නැවත ආරම්භ කරන්න** බැනරයක්.

### REST API

සියලු මෙහෙයුම් තනි මාර්ගයක් හරහා සිදු වේ:
[`src/app/api/settings/feature-flags/route.ts`](../../src/app/api/settings/feature-flags/route.ts).
සෑම ක්රමවේදයකටම සත්යාපිත පාලක පුවරු සැසියක් අවශ්ය වේ (එසේ නොමැති නම් `401`).

#### `GET /api/settings/feature-flags`

සෑම කොඩියක්ම එහි ඵලදායී අගය, මූලාශ්රය සහ සාරාංශයක් සමඟ ආපසු ලබා දෙයි.

```jsonc
{
  "flags": [
    {
      "key": "REQUIRE_API_KEY",
      "label": "Require API Key",
      "description": "Require an API key for all incoming requests",
      "category": "security",
      "type": "boolean",
      "enumValues": null,
      "defaultValue": "false",
      "effectiveValue": "false",
      "source": "default", // "db" | "env" | "default"
      "requiresRestart": false,
      "warningLevel": "caution",
    },
    // ... all 77 flags
  ],
  "summary": {
    "total": 56,
    "active": 0,
    "inactive": 0,
    "overriddenByDb": 0,
    "overriddenByEnv": 0,
  },
}
```

#### `PUT /api/settings/feature-flags`

තනි අධිලේඛනයක් සකසන්න හෝ ඉවත් කරන්න. Body: `{ key: string; value?: string }`.
`value` අතහැර දැමීමෙන් අධිලේඛනය ඉවත් වේ (env / default ප්රතිස්ථාපනය කරයි).

```bash
# Set a DB override
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY","value":"true"}'

# Remove the override (no "value")
curl -X PUT http://localhost:20128/api/settings/feature-flags \
  -H "Content-Type: application/json" \
  -d '{"key":"REQUIRE_API_KEY"}'
```

ප්රතිචාරය නව `effectiveValue`/`source`, `previousValue`/
`previousSource`, සහ `requiresRestart` ප්රතිරාවය කරයි. නොදන්නා යතුරු සහ පරාසයෙන් පිටත එනම් අගයන් `400` සමඟ ප්රතික්ෂේප වේ.

#### `DELETE /api/settings/feature-flags`

සියලුම DB අධිලේඛන එකවර ඉවත් කරයි, සෑම කොඩියක්ම එහි env / default අගයට ප්රතිස්ථාපනය කරයි. `{ cleared: <count>, message: "..." }` ආපසු ලබා දෙයි.

> [!NOTE]
> `requiresRestart: true` සහිත කොඩි ක්රියාවලියක් නැවත පූරණය කිරීමෙන් පසුව පමණක් ක්රියාත්මක වේ.
> පාලක පුවරුවේ නැවත ආරම්භ කිරීමේ ප්රවාහය `POST /api/restart` අමතා පසුව සේවාදායකය නැවත ක්රියාත්මක වන තෙක් `GET /api/health/ping` විමසයි.
