## සාරාංශය

OmniRoute දැන් `/api/v1/relay/chat/completions` සඳහා රිලේ ආකාර තුනකට සහාය දක්වයි:

- `ts`: TypeScript රිලේ එක ක්රියාවලිය තුළ භාවිත කරන්න.
- `bifrost`: Bifrost ද්වාරය අනිවාර්යයෙන් භාවිත කරන්න.
- `auto`: ලබා ගත හැකි විට Bifrost වෙත ප්රමුඛත්වය දී, අසාර්ථක වුවහොත් TypeScript වෙත පසුබසින්න.

ඔබ ඉහළ ඉල්ලීම් අනුපාතයකින් (දිනකට ටෝකන විශාල සංඛ්යාවක්, ආසන්න වශයෙන් අඛණ්ඩ ප්රවාහයක්) ක්රියාත්මක වන විට, හොඳම උපාය වන්නේ ප්රධාන ක්රියාකාරී මාර්ගය කිසිවිටෙකත් අක්රිය sidecar එකක් නිසා අවහිර නොවන පරිදි පසුබැසීමේ මාර්ගය පැහැදිලිව සහ වේගවත්ව තබා ගැනීමයි.

## ආකාරවල හැසිරීම

- `ts`
  - අවම මෙහෙයුම් සංකීර්ණත්වය.
  - සියලුම මාර්ගගත කිරීම් සහ වලංගු කිරීම් Node තුළ ක්රියාත්මක වේ.
  - ලබා ගත හැකි බව සඳහා sidecar පරායත්තතාවක් නොමැත.
- `bifrost`
  - සියලුම ඉල්ලීම් sidecar ද්වාරය හරහා යාමට බල කරයි.
  - ස්වයංක්රීය පසුබැසීමක් නොමැත.
  - sidecar සෞඛ්යය සහ ප්රමාදය සහතික කර ඇති විට පමණක් ප්රයෝජනවත් වේ.
- `auto`
  - sidecar වෙත ළඟා විය හැකි සහ එය සබල කර ඇති විට එය භාවිත වේ.
  - අසාර්ථක උත්සාහ මඟින් පසුබැසීමේ ශීර්ෂක සක්රිය කර, ඉල්ලීම් සාර්ථකත්වය සීමාගතව පවත්වා ගැනීම සඳහා ගමනාගමනය TS වෙත ආපසු යවයි.
  - දැඩි ලෙස sidecar හරහා පමණක් මාර්ගගත කිරීමට වඩා අඛණ්ඩ ක්රියාකාරීත්වය වැදගත් වන නිෂ්පාදන පරිසර සඳහා ආරක්ෂිතම තේරීම මෙම ආකාරයයි.

## අද පවතින 9router සහ CLIPROXYAPI සංසන්දනය

9router සහ CLIPROXYAPI යන දෙකම ඓතිහාසිකව upstream සැපයුම්කරුවන් සඳහා ගැළපුම් මාර්ග නිරාවරණය කළ අනුකලනයන් වේ.

- 9router යනු upstream සම්බන්ධීකරණය සහ ගැළපුම් හැසිරීම සඳහා වන අන්තර්ගත මාර්ගයකි.
- CLIPROXYAPI යනු CLI / SDK ආකාරයේ ගමනාගමනය සඳහා වන proxy API පාලමකි.
- කැපවූ sidecar ආකාරයේ අතරමැදි පියවරක් සහ අඩු ප්රමාදයක් සහිත දේශීය බෙදාහැරීමක් අවශ්ය වන විට භාවිත කරන බාහිරකරණය කළ මාර්ගය ලෙස Bifrost ස්ථාවර කරමින් පවතී.

ඔබ දැනට 9router/CLIPROXYAPI සංසන්දනය කරන්නේ නම්:

- භාරදීමට පෙර API මාර්ගය තුළ ඉල්ලීම් අත්සන් කිරීම, අවසර ලැයිස්තු පරීක්ෂා සහ DB ප්රතිපත්ති ද්වාර තබා ගන්න.
- කාර්ය ප්රවාහයකට දැඩි sidecar හැසිරීමක් සහ එක් එක් ඉල්ලීම සඳහා අඩු විචල්යතාවක් අවශ්ය නම්, `OMNIROUTE_RELAY_BACKEND=bifrost` භාවිත කරන්න.
- සිදුවීම් තත්ත්ව යටතේ ක්රමවත් පිරිහීමක් සමඟ sidecar ප්රත්යස්ථතාව අවශ්ය නම්, `OMNIROUTE_RELAY_BACKEND=auto` භාවිත කරන්න.

## පසුඅන්ත සීමා ගිවිසුම

ස්ථාවර නිෂ්පාදන සීමාව වන්නේ OmniRoute රිලේ API එක මිස උපකරණ පුවරුවේ ක්රියාත්මක කිරීම නොවේ. Next.js උපකරණ පුවරුවට දේශීය සේවා ස්ථාපනය කිරීමට, වින්යාස කිරීමට සහ අධීක්ෂණය කිරීමට හැකි නමුත්, ඉල්ලීම් මාර්ගගත කිරීම රිලේ API හරහා ඇතුළු වී එම සීමාව පිටුපසින් භාර දිය යුතුය.

දිගුකාලීන පසුඅන්ත තේරීම්:

- ක්රියාවලිය තුළ ප්රතිපත්ති සහ පසුබැසීමේ මාර්ගය ලෙස TypeScript රිලේ එක තබා ගන්න. ඕනෑම පසුඅන්ත භාරදීමකට පෙර සත්යාපනය, අවසර ලැයිස්තු, ඉල්ලීම් සාමාන්යකරණය, ගිණුම්කරණය සහ ආරක්ෂක පරීක්ෂා මෙහි පවත්වා ගන්න.

- කළමනාකරණය කළ ක්රියාවලි දැනටමත් HTTP-අනුකූල API නිරාවරණය කරන නිසාත්, මාර්ග ආරක්ෂකයට සීමාව විගණනය කළ හැකි නිසාත්, අසාර්ථකත්ව/පසුබැසීමේ හැසිරීම ඉල්ලීම් ලොගවල දෘශ්යමාන වන නිසාත්, අද දින අධීක්ෂණය කළ සේවා සඳහා loopback HTTP වඩාත් සුදුසුය. අනාගත SDK හෝ socket ප්රවාහනයක් එක් කිරීම වටින්නේ එය හුදකලාකරණය හෝ පසුබැසීමේ අර්ථකථනය දුර්වල නොකර p99 මාර්ගගත කිරීමේ ප්රමාදය මැනිය හැකි ලෙස අඩු කරන්නේ නම් පමණි.

එබැවින්, ඉතා ඉහළ ප්රවාහ ධාරිතාවක් සහිත යෙදවීමක් සඳහා පෙරනිමි පිළිතුර වන්නේ Bifrost සබල කර ඇති `auto` ය: සාර්ථකත්ව අනුපාතය සඳහා TypeScript පසුබැසීම ආරක්ෂා කර ගනිමින් ප්රධාන ක්රියාකාරී මාර්ගයේ Go sidecar එක භාවිත කරන්න. ක්රමවත් පිරිහීමට වඩා දැඩි ලෙස sidecar හරහා පමණක් ක්රියා කිරීම වැදගත් වන විට පමණක් `bifrost` භාවිත කරන්න.
