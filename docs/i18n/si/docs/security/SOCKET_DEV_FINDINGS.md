## §1 — MITM මූල-CA ස්ථාපනය (`77484.js`)

**මූලාශ්ර ගොනු**:

- `src/mitm/cert/install.ts` — පොදු `installCert()` / `uninstallCert()`,
  වේදිකා-විශේෂිත `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — ස්ථාපන මාර්ග භාවිත කරන හවුල් `execFile` / `spawn` / PowerShell
  උපකාරක.

**ප්රේරකය**: පරිශීලකයා `/dashboard/cli-tools/mitm` හි දේශීය උපකරණ පුවරුවේ
"MITM ප්රොක්සිය සක්රිය කරන්න" මත ක්ලික් කරයි. මෙම මාර්ගය loopback සඳහා පමණි — `CLAUDE.md` හි
දැඩි නීතිය #17 සහ `src/server/authz/routeGuard.ts::isLocalOnlyPath()` බලන්න. tunnel එකක් හරහා නිරාවරණය වූ
JWT එකකට මෙම කේත මාර්ගය ප්රේරණය කිරීමට **නොහැකිය**.

**සිදු කරන වරප්රසාදිත මෙහෙයුම් (එක් එක් වේදිකාව අනුව)**:

| මෙහෙයුම් පද්ධතිය       | විධාන                                                                                                             |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC හරහා `certutil -addstore Root <cert>`                                                                         |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | `certutil -d sql:<profile>` හරහා එක් එක් පැතිකඩ සඳහා NSS DB යාවත්කාලීන කිරීම                                      |

මේවා `mitmproxy`, Charles Proxy, Fiddler, සහ Caddy භාවිත කරන විධානම වේ.
ඒවා OmniRoute තුළ පවතින බව
`docs/security/STEALTH_GUIDE.md` හි ලේඛනගත කර ඇත.

**v3.8.6 අවම කිරීම**:

- `runElevatedPowerShell()` තවදුරටත් `-EncodedCommand <base64utf16le>` භාවිත නොකරයි.
  උසස් වරප්රසාද සහිත payload එක එක් එක් ඇමතුම සඳහා වන තාවකාලික `.ps1` ගොනුවකට (ප්රකාරය 0o600,

  වර්ගීකාරකය විසින් සලකුණු කරන ලද සාම්ප්රදායික PowerShell හරහා base64-වරප්රසාද-උසස්කිරීමේ ඇඟිලි සලකුණ ඉවත් කරයි.
- `installCertWindows` තුළ මෙතැනට යොමු කරන inline `SECURITY-AUDITOR-NOTE:` කොටසක්

`CLOUD_URL` වින්යාස කර ඇත. දෙකම අක්රිය නම්, Cloud අන්ත ලක්ෂ්යය වෙත
පිටතට යන ජාල ඇමතුමක් සිදු නොකෙරේ.

**v3.8.5 හැසිරීම (Socket.dev විසින් නිවැරදිව හඳුනාගත් දෝෂය)**:

`cloudUpdatedAt > localUpdatedAt` වූ විට, Cloud ප්රතිචාරයෙන් ලැබුණු
`accessToken`, `refreshToken`, සහ `providerSpecificData` භාවිතයෙන්
`updateLocalTokens()` ඒවා උඩින් ලිවීය. HMAC නැත, අත්සනක් නැත, checksum එකක් නැත.
වැරදි ලෙස වින්යාස කළ හෝ ද්වේෂසහගත `CLOUD_URL` එකකට (හෝ සන්නිවේදන නාලිකාවේ
MITM එකකට) සපයන්නාගේ OAuth ටෝකන නිහඬව මාරු කළ හැකි විය.

**v3.8.6 අවම කිරීම**:

1. **HMAC සත්යාපනය**: JSON විග්රහ කිරීමට පෙර `verifyCloudSignature(rawBody, sigHeader)`
   විසින් `X-Cloud-Sig` ශීර්ෂකය (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) පරීක්ෂා කරයි. රහස සකසා තිබේ නම්, අත්සන අනිවාර්ය වේ.
   එසේ නොමැති නම් (පැරණි මාදිලිය), අනතුරු ඇඟවීමක් ලොග් කර ප්රතිචාරය
   පිළිගනු ලැබේ — v3.9 සිට රහස අනිවාර්ය වනු ඇත.
2. **රහස් ක්ෂේත්ර සඳහා පැහැදිලි අනුමැතිය**: `accessToken` / `refreshToken` /
   `providerSpecificData` උඩින් ලියනු ලබන්නේ
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true` වූ විට **පමණි**. පෙරනිමි මාදිලිය
   සමමුහුර්ත කරන්නේ අක්තපත්ර නොවන පාරදත්ත (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) පමණි. දුරස්ථ ටෝකන සමමුහුර්තකරණය මත
   රඳා සිටි පරිශීලකයන් සඳහා මෙය **අනුකූලතාව බිඳ දමන වෙනසකි** — ඔවුන් එයට
   පැහැදිලිව අනුමැතිය දිය යුතුය.

**අප එය තබාගන්නේ ඇයි**: OmniRoute Cloud කුලී නිවැසියෙකුට කණ්ඩායම් අක්තපත්ර
මධ්යගත කිරීමට ඇති එකම ක්රමය Cloud Sync වේ. මෙම නිවැරදි කිරීම තර්ජන ආකෘතිය

සෑම ස්ටබ් එකක්ම එකම අතුරුමුහුණත අපනයනය කරන නමුත්, සෑම ශ්රිතයක්ම ධාවන වේලාවේදී
