OmniRoute තුළ HTTP, HTTPS, හෝ SOCKS5 ප්රොක්සි හරහා ඉහළ ප්රවාහ AI සැපයුම්කරුවන්ගේ ගමනාගමනය මාර්ගගත කිරීමට ඔබට ඉඩ සලසන සියලු විශේෂාංග සහිත ප්රොක්සි කළමනාකරණ පද්ධතියක් ඇතුළත් වේ. ඔබ අවහිර කළ කලාපයක සිටියත්, IP මාරු කිරීම අවශ්ය වුවත්, හෝ රහසිගත ඇඟිලි සලකුණුකරණය අවශ්ය වුවත් — මෙම මාර්ගෝපදේශය සියල්ල ආවරණය කරයි.

## මට්ටම් 4ක ප්රොක්සි පද්ධතිය

OmniRoute විසින් **ස්වාධීන විෂය පථ හතරකදී** ප්රොක්සි වින්යාස කිරීමට සහය දක්වන අතර, ඒවා ප්රමුඛතා අනුපිළිවෙළට නිරාකරණය කෙරේ:

```
ප්රමුඛතා නිරාකරණ අනුපිළිවෙළ (ඉහළම → පහළම):

  1. 🔵 ගිණුම්/සම්බන්ධතා ප්රොක්සිය  →  එක් API යතුරකට / OAuth සම්බන්ධතාවකට
  2. 🟡 සැපයුම්කරු ප්රොක්සිය       →  එක් සැපයුම්කරුවකුට (උදා., සියලු OpenAI ගමනාගමනය)
  3. 🟠 සංයෝජන ප්රොක්සිය          →  එක් සංයෝජන/මාර්ගගත කිරීමේ වින්යාසයකට
  4. 🟢 ගෝලීය ප්රොක්සිය           →  සියලු ගමනාගමනය, සියලු සැපයුම්කරුවන්
```

### නිරාකරණය ක්රියා කරන ආකාරය

OmniRoute විසින් ඉහළ මට්ටමේ සැපයුම්කරුවකු වෙත ඉල්ලීමක් යවන විට, එය එක් එක් මට්ටම අනුපිළිවෙළින් පරීක්ෂා කරන `resolveProxyForConnectionFromRegistry()` අමතයි:

1. **ගිණුම් මට්ටම** — මෙම නිශ්චිත සම්බන්ධතා ID එකට ප්රොක්සියක් පවරා තිබේද?
2. **සැපයුම්කරු මට්ටම** — මෙම සැපයුම්කරුට (උදා., `openai`) ප්රොක්සියක් පවරා තිබේද?
3. **ගෝලීය මට්ටම** — ගෝලීය ප්රොක්සියක් වින්යාස කර තිබේද?
4. **ප්රොක්සියක් නැත** — සැපයුම්කරු වෙත සෘජු සම්බන්ධතාවක්.

පළමු ගැළපීම තෝරා ගැනේ. මෙයින් අදහස් වන්නේ ඔබට ගෝලීය ප්රොක්සියක් පෙරනිමි විකල්පයක් ලෙස සකසා, නිශ්චිත සැපයුම්කරුවන් හෝ සම්බන්ධතා සඳහා එය අභිබවා යා හැකි බවයි.

## ප්රොක්සි රෙජිස්ට්රිය (CRUD)

ප්රොක්සි රෙජිස්ට්රිය යනු ඔබගේ සියලු ප්රොක්සි ගබඩා කරන SQLite වගුවකි (`proxy_registry`). සෑම ප්රොක්සියකටම පහත දෑ ඇත:

| ක්ෂේත්රය   | වර්ගය   | විස්තරය                                              |
| ---------- | ------- | ---------------------------------------------------- |
| `id`       | UUID    | අනන්ය හඳුනාගැනීමේ අගය                                |
| `name`     | String  | මිනිසුන්ට කියවිය හැකි ලේබලය                          |
| `type`     | String  | ප්රොටෝකෝලය: `http`, `https`, `socks5`                |
| `host`     | String  | ප්රොක්සි සත්කාරක නාමය හෝ IP ලිපිනය                   |
| `port`     | Integer | පෝට් අංකය                                            |
| `username` | String  | සත්යාපන පරිශීලක නාමය (ගබඩා කර ඇති විට සංකේතනය කර ඇත) |
| `password` | String  | සත්යාපන මුරපදය (ගබඩා කර ඇති විට සංකේතනය කර ඇත)       |
| `region`   | String  | භූගෝලීය කලාප ලේබලය                                   |
| `notes`    | String  | නිදහස් පෙළ සටහන්                                     |
| `status`   | String  | `active` හෝ `inactive`                               |
| `source`   | String  | `manual` හෝ `oneproxy`                               |

### ප්රොක්සියක් සෑදීම

**උපකරණ පුවරුව හරහා:**

1. **සැකසීම් → ප්රොක්සි** වෙත යන්න
2. **ප්රොක්සියක් එක් කරන්න** ක්ලික් කරන්න
3. වර්ගය, සත්කාරකය, පෝට් එක සහ විකල්ප සත්යාපන අක්තපත්ර පුරවන්න
4. සුරකින්න

**API හරහා:**

```bash
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "US Proxy",
    "type": "http",
    "host": "proxy.example.com",
    "port": 8080,
    "username": "user",
    "password": "pass",
    "region": "US"
  }'
```

### ප්රොක්සියක් යාවත්කාලීන කිරීම

```bash
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "id": "proxy-uuid-here",
    "host": "new-proxy.example.com",
    "port": 9090
  }'
```

> **සටහන:** ඔබ පැහැදිලිවම හිස් නොවන ප්රතිස්ථාපන අගයන් එවන්නේ නැතිනම් අක්තපත්ර සුරැකී පවතී. `username`/`password` සඳහා හිස් තන්තු යැවීමෙන් ගබඩා කර ඇති අගයන් එලෙසම තබා ගනී.

### ප්රොක්සියක් මකා දැමීම

### ආයාතය/නිර්යාතය

ප්රොක්සි **උපස්ථ/ප්රතිසාධන** පද්ධතියට ඇතුළත් වේ. ඔබගේ OmniRoute වින්යාසය නිර්යාත කරන විට:

1. **උපකරණ පුවරුව → සැකසීම් → උපස්ථය** වෙත යන්න

**CLI ඇඟිලි සලකුණු ටොගලය** (`සැකසුම් → ආරක්ෂාව`) ස්වදේශීය CLI ද්විමය ගොනුවල (Claude Code, Codex, ආදිය) නිශ්චිත අත්සනට ගැළපෙන ලෙස HTTP ශීර්ෂ සහ JSON body ක්ෂේත්ර නැවත අනුපිළිවෙළට සකසයි. මෙය proxy එකට **අමතරව** ක්රියා කරයි:

```
ඔබේ IP එක (අවහිර කළ) → Proxy IP එක (US) → සැපයුම්කරුගේ API එක
                         + TLS ව්යාජකරණය
                         + CLI ඇඟිලි සලකුණ
```

ඔබට එකවර **IP සැඟවීම** සහ **ඉල්ලීම්වල සත්යතාව** යන දෙකම ලැබේ.

### Proxy IP එක රැකගැනීම

dashboard එකේ ඇති වර්ණ-කේතනය කළ ලාංඡන මඟින් සක්රිය proxy මට්ටම පෙන්වයි:

| ලාංඡනය | මට්ටම      | අර්ථය                                           |

| 🟢     | ගෝලීය      | සියලුම ගමනාගමනය මෙම proxy එක හරහා යයි           |

| 🔵     | සම්බන්ධතාව | මෙම නිශ්චිත යතුර/ගිණුම මෙම proxy එක භාවිත කරයි  |

සත්යාපනය සඳහා ලාංඡනය මඟින් විසඳාගත් proxy IP එකද පෙන්වයි.

## Upstream Proxy මාදිලි

CLIProxyAPI රටාව භාවිත කරන සැපයුම්කරුවන් සඳහා, OmniRoute විසින් upstream proxy මාදිලි තුනකට සහාය දක්වයි:

| මාදිලිය       | විස්තරය                                                        |
| ------------- | -------------------------------------------------------------- |
| `native`      | OmniRoute විසින් proxy මාර්ගගත කිරීම සෘජුව හසුරුවයි (පෙරනිමි)  |
| `cliproxyapi` | බාහිර CLIProxyAPI instance එකකට පැවරේ                          |
| `fallback`    | පළමුව native උත්සාහ කර, අසාර්ථක වුවහොත් CLIProxyAPI භාවිත කරයි |

එක් එක් සැපයුම්කරු සඳහා වින්යාස කරන්න:

```bash
curl -X PUT "http://localhost:20128/api/upstream-proxy/openai" \
  -H "Content-Type: application/json" \
  -d '{"mode": "native", "enabled": true}'
```

- **එක් එක් සැපයුම්කරු සඳහා proxy** අතික්රමණ
- **එක් එක් සම්බන්ධතාව සඳහා proxy** පැවරුම්
- වින්යාස කළ proxy එක හරහා **සම්බන්ධතා පරීක්ෂාව**
- සක්රිය proxy මට්ටම පෙන්වන **වර්ණ-කේතනය කළ ලාංඡන**

### සැකසුම් → 1proxy ටැබය

- නොමිලේ proxy ලබාගැනීම සඳහා **දැන් සමමුහුර්ත කරන්න** බොත්තම
- **සංඛ්යාලේඛන කාඩ්පත්**: මුළු ගණන, සක්රිය, සාමාන්ය ගුණාත්මකභාවය, අවසන් සමමුහුර්ත කිරීම
- **පෙරහන්**: ප්රොටෝකෝලය, රටේ කේතය, අවම ගුණාත්මකභාවය
- host, ප්රොටෝකෝලය, රට, ගුණාත්මක ලකුණු, ප්රමාදය, නිර්නාමිකභාවය සහ Google ප්රවේශය සහිත **proxy වගුව**
- සාර්ථක/අසාර්ථක වීමේ ලුහුබැඳීම සහ අඛණ්ඩ අසාර්ථක වීම් ගණන සහිත **සමමුහුර්ත තත්ත්ව** පැනලය
- සියලුම 1proxy ඇතුළත් කිරීම් ඉවත් කිරීමට **සියල්ල මකන්න**

## දෝෂ නිරාකරණය

### "SOCKS5 ප්රොක්සිය අක්රීය කර ඇත"

ඔබගේ `.env` ගොනුව තුළ `ENABLE_SOCKS5_PROXY=true` සකසා නැවත ආරම්භ කරන්න.

### ප්රොක්සිය හරහා ඇතිවන "socket hang up" දෝෂ

අක්රීය සම්බන්ධතා විසන්ධි කරන අඩු මිල ප්රොක්සි සමඟ මෙය සාමාන්ය තත්ත්වයකි. OmniRoute දැනටමත් පහත ආකාරයෙන් මෙය හසුරුවයි:

- ප්රොක්සි සම්බන්ධතාවල keep-alive අක්රීය කිරීම (`keepAliveTimeout: 1`)
- pipelining අක්රීය කිරීම (`pipelining: 0`)
- නැවත නැවතත් handshakes සිදු වීම වැළැක්වීමට dispatchers හැඹිලිගත කිරීම

එය දිගටම පවතී නම්, වෙනත් ප්රොක්සියක් උත්සාහ කරන්න හෝ 1proxy rotation විශේෂාංගය භාවිත කරන්න.

### OAuth අතරතුර "unsupported_country_region_territory"

OAuth ප්රවාහය ආරම්භ කිරීමට **පෙර** ප්රොක්සිය වින්යාස කර ඇති බවට වග බලා ගන්න. OmniRoute විසින් OAuth token හුවමාරුව වින්යාස කළ ප්රොක්සිය හරහා යොමු කරයි. පළමුව global හෝ provider මට්ටමේ ප්රොක්සියක් සකසා, ඉන්පසු සම්බන්ධ වන්න.

### ප්රොක්සිය භාවිත නොවීම

විසඳුම් අනුපිළිවෙළ පරීක්ෂා කරන්න:

1. `GET /api/settings/proxy?resolve=your-connection-id` මඟින් සත්යාපනය කරන්න
2. ප්රොක්සියේ `status` අගය `active` (`inactive` නොවන) දැයි පරීක්ෂා කරන්න
3. ප්රොක්සි පැවරුම් විෂයපථය ඔබගේ සම්බන්ධතාවට ගැළපෙන බවට වග බලා ගන්න

### 1proxy සමමුහුර්ත කිරීම අසාර්ථක වීම

සමමුහුර්ත තත්ත්වය පරීක්ෂා කරන්න:

```bash
curl "http://localhost:20128/api/settings/oneproxy?action=status"
```

`consecutiveFailures >= 5` නම්, circuit breaker ක්රියාත්මක වී ඇත. එය යළි සැකසීමට server එක නැවත ආරම්භ කරන්න, නැතහොත් අතින් යළි සැකසීම සඳහා රැඳී සිටින්න.

## දත්ත සමුදා ව්යුහය

### `proxy_registry` වගුව

```sql
CREATE TABLE proxy_registry (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  type TEXT NOT NULL DEFAULT 'http',
  host TEXT NOT NULL,
  port INTEGER NOT NULL,
  username TEXT DEFAULT '',
  password TEXT DEFAULT '',
  region TEXT,
  notes TEXT,
  status TEXT DEFAULT 'active',
  source TEXT NOT NULL DEFAULT 'manual',    -- 'manual' හෝ 'oneproxy'
  quality_score INTEGER,                     -- 0-100 (1proxy පමණි)
  latency_ms INTEGER,                        -- මිලි තත්පර (1proxy පමණි)
  anonymity TEXT,                            -- transparent/anonymous/elite
  google_access INTEGER DEFAULT 0,           -- Google වෙත ප්රවේශ විය හැකිද? (1proxy)
  last_validated TEXT,                       -- ISO කාල මුද්රාව (1proxy)
  country_code TEXT,                         -- ISO අකුරු 2ක කේතය (1proxy)
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### `proxy_assignments` වගුව

```sql
CREATE TABLE proxy_assignments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  proxy_id TEXT NOT NULL REFERENCES proxy_registry(id),
  scope TEXT NOT NULL,        -- 'global', 'provider', 'account', 'combo'
  scope_id TEXT,              -- provider ID, connection ID, හෝ combo ID
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(scope, scope_id)
);
```

## ප්රොක්සි සෞඛ්ය පරීක්ෂාව (v3.8.16+)

OmniRoute හි **proxy fast-fail** යාන්ත්රණය (`src/lib/proxyHealth.ts`) ඉක්මන් TCP සම්බන්ධතා පරීක්ෂාවක් මඟින් තත්පර 2කට අඩු කාලයකදී ක්රියා විරහිත ප්රොක්සි හඳුනාගෙන, එක් එක් ඉල්ලීම සඳහා අමතර පිරිවැයක් ඇති වීම වැළැක්වීමට **ප්රතිඵලය හැඹිලිගත කරයි**.

### එය ක්රියා කරන ආකාරය

```
ඉල්ලීම ──▶ ProxyHealthCache.get(url)
             │
             ├─ හැඹිලි ගැළපීමක් + නැවුම්ද?  ──▶ හැඹිලිගත තත්ත්වය ආපසු ලබා දෙන්න
             │
             └─ හැඹිලි ගැළපීමක් නැතිද / කල් ඉකුත්ද?  ──▶ host:port වෙත TCP සම්බන්ධතාවක් ඇති කරන්න
                                          (කාල සීමාව: FAST_FAIL_TIMEOUT_MS)
                                          ──▶ HEALTH_CACHE_TTL_MS සඳහා හැඹිලිගත කරන්න
                                          ──▶ ප්රතිඵලය ආපසු ලබා දෙන්න
```

මෙය නොමැතිව, ක්රියා විරහිත ප්රොක්සියක් අසාර්ථක වීමට පෙර සෑම ඉල්ලීමක්ම සම්පූර්ණ `PROXY_TIMEOUT_MS` කාලය සඳහා (පෙරනිමිය තත්පර 30) අවහිර කරනු ඇත.

### සීරුමාරු කළ හැකි පරිසර විචල්ය

| විචල්යය                      | පෙරනිමිය | අරමුණ                                        |
| ---------------------------- | -------- | -------------------------------------------- |
| `PROXY_FAST_FAIL_TIMEOUT_MS` | `2000`   | එක් සෞඛ්ය පරීක්ෂාවකට TCP සම්බන්ධතා කාල සීමාව |
| `PROXY_HEALTH_CACHE_TTL_MS`  | `30000`  | සෞඛ්ය ප්රතිඵලයක් හැඹිලිගත කර තබන කාලය        |

**නිර්දේශිත අගයන්:**

| අවස්ථාව                             | Fast-fail කාල සීමාව | හැඹිලි TTL | හේතුව                                                                       |
| ----------------------------------- | ------------------- | ---------- | --------------------------------------------------------------------------- |
| ඉහළ දත්ත ප්රවාහයක් සහිත API gateway | 1500ms              | 60000ms    | වේගවත් හා දැඩි අසාර්ථක වීම; පරීක්ෂා අඩු කිරීමට දිගු හැඹිලි කාලයක්           |
| භූගෝලීයව ව්යාප්ත node               | 3000ms              | 15000ms    | මන්දගාමී ජාලවලට වැඩි කාලයක් අවශ්යය; වේගවත් failover සඳහා කෙටි හැඹිලි කාලයක් |
| සංවර්ධනය / පරීක්ෂා කිරීම            | 1000ms              | 10000ms    | දේශීය ප්රොක්සි මත වේගවත් පුනරාවර්තනය                                        |
| රහසිගත / හඳුනාගැනීම්-විරෝධී         | 2500ms              | 45000ms    | rate limits ක්රියාත්මක කළ හැකි වේගවත් probing වැළැක්වීම                     |

### ප්රොක්සි සෞඛ්යය පරීක්ෂා කිරීම

```ts
import { getAllProxyHealthStatuses, invalidateProxyHealth } from "omniroute/proxyHealth";

const statuses = getAllProxyHealthStatuses();
for (const s of statuses) {
  console.log(`${s.proxyUrl} → healthy=${s.healthy}, stale=${s.stale}`);
}

// නිශ්චිත ප්රොක්සියක් බලෙන් නැවත පරීක්ෂා කරන්න
invalidateProxyHealth("http://user:pass@203.0.113.7:8080");
```

හැඹිලි ප්රවේශය `HEALTH_CACHE_TTL_MS` ඉක්මවා ඇති විට `stale` සලකුණ `true` වන අතර, ඊළඟ ඉල්ලීම නැවුම් පරීක්ෂාවක් ක්රියාත්මක කරනු ඇත.

### ප්රොක්සි වර්ගය අනුව පෙරනිමි

සෞඛ්ය පරීක්ෂාව URL scheme එක මත පදනම් වූ යෝග්ය පෙරනිමි භාවිත කරයි:

| Scheme                     | පෙරනිමි port එක |
| -------------------------- | --------------- |
| `http://`                  | 8080            |
| `https://`                 | 443             |
| `socks5://` / `socks5h://` | 1080            |

URL එකේ ඇති අභිරුචි port (`http://host:9999`) සෑම විටම scheme පෙරනිමියට වඩා ප්රමුඛත්වය ගනී.

## ප්රොක්සි විශ්ලේෂණ සහ නිරීක්ෂණ හැකියාව

මාර්ගගත කිරීමේ රටා, ප්රමාද ඉහළ යෑම් සහ නැවත නැවත සිදුවන අසාර්ථකවීම් හඳුනාගැනීමට ක්රියාකරුවන්ට උපකාර කිරීම සඳහා OmniRoute එක් එක් ප්රොක්සිය අනුව භාවිතය නිරීක්ෂණය කරයි.

### නිරීක්ෂණය කරන්නේ මොනවාද

වින්යාස කළ ප්රොක්සියක් හරහා යන සෑම ඉල්ලීමක් සඳහාම, OmniRoute පහත දෑ වාර්තා කරයි:

| මෙට්රිකය     | විස්තරය                                             |
| ------------ | --------------------------------------------------- |
| `proxy_url`  | සම්පූර්ණ ප්රොක්සි URL එක (සත්යාපන අක්තපත්ර සඟවා ඇත) |
| `provider`   | උඩුගං සැපයුම්කරුගේ ID එක (openai, anthropic, ආදිය)  |
| `latency_ms` | ප්රොක්සි සම්බන්ධතා ආරම්භය ඇතුළු මුළු වට-ගමන් කාලය   |
| `connect_ms` | TCP සම්බන්ධතා කාලය පමණි                             |
| `status`     | උඩුගං සේවාවෙන් ලැබුණු HTTP තත්ත්ව කේතය              |
| `error`      | ඉල්ලීම අසාර්ථක වූයේ නම් දෝෂ පන්තිය                  |

### දත්ත වෙත ප්රවේශ වීම

```bash
# මෑතකාලීන ප්රොක්සි සිදුවීම්
curl -H "Authorization: Bearer $OMNIROUTE_KEY" \
  "http://localhost:20128/api/usage/proxy-logs?limit=100"
```

සැබෑ අන්ත ලක්ෂ්යය `/api/usage/proxy-logs` වේ (`src/app/api/usage/proxy-logs/route.ts` බලන්න). මෙම අන්ත ලක්ෂ්යය පහත දෑ සඳහා සහාය දක්වයි:

- `GET /api/usage/proxy-logs` — ප්රොක්සි ලොග් ලබාගන්න
- `DELETE /api/usage/proxy-logs` — සියලු ප්රොක්සි ලොග් මකා දමන්න

අවශ්ය නම්, සමස්ත සංඛ්යාලේඛන SQL හරහා `proxy_logs` වගුවෙන් සෘජුවම විමසිය හැක. උපකරණ පුවරු UI එකෙහි සමස්ත දසුන් තිබිය හැක.

### පොදු රටා

**අස්ථාවර ප්රොක්සියක් හඳුනාගන්න** (සාර්ථකත්වය සහ අසාර්ථකත්වය අතර මාරු වේ):

```sql
SELECT proxy_url,
       COUNT(*) AS total,
       SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) AS errors,
       ROUND(100.0 * SUM(CASE WHEN status >= 500 THEN 1 ELSE 0 END) / COUNT(*), 1) AS error_pct
FROM proxy_logs
WHERE timestamp > datetime('now', '-1 hour')
GROUP BY proxy_url
HAVING error_pct > 5
ORDER BY error_pct DESC;
```

**මන්දගාමී ප්රොක්සි සොයන්න** (p95 ප්රමාදය > 2s):

```sql
WITH ranked AS (
  SELECT proxy_url, latency_ms,
         PERCENT_RANK() OVER (PARTITION BY proxy_url ORDER BY latency_ms) AS pct
  FROM proxy_logs
  WHERE timestamp > datetime('now', '-24 hour')
)
SELECT proxy_url, latency_ms
FROM ranked
WHERE pct >= 0.95
ORDER BY latency_ms DESC;
```

මෙය හිතාමතාම **තෝරා සක්රීය කළ යුතු සහ විනාශකාරී නොවන** ලෙස නිර්මාණය කර ඇත: පෙරනිමියෙන් උපලේඛකය
අසාර්ථකවීම් ගණන් කර ලොග් කිරීම පමණක් සිදු කරයි (`decision.ts` තුළ ප්රතිපත්තිය C බලන්න), සහ `PROXY_AUTO_DISABLE`
කිසිවිටෙක පේළියක් මකා නොදමයි — ඒ සඳහා වෙන් වූ, වඩාත් ආක්රමණශීලී
`PROXY_AUTO_REMOVE` ධජය ඇත. දෙකම `true` ලෙස සකසා තිබේ නම්, `PROXY_AUTO_REMOVE`
ප්රමුඛ වේ (මකා දැමීමට නියමිත ප්රොක්සියක් ඒ අතරතුර මෘදු ලෙස අක්රීය කිරීමෙන් ප්රයෝජනයක් නැත). සම්පූර්ණ
විචල්ය ලැයිස්තුව සඳහා [පරිසර වින්යාස](../reference/ENVIRONMENT.md) යොමුව බලන්න.
