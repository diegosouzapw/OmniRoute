Web Cookie සපයන්නන් මඟින් API key එකක් වෙනුවට ඔබගේ පවතින බ්රවුසර සැසිය හරහා AI සේවාවක් භාවිත කිරීමට OmniRoute හට හැකියාව ලබා දෙයි. ඔබට දැනටමත් සේවාවක වෙබ් අඩවිය හරහා එයට ප්රවේශය ඇති විට සහ එම සත්යාපිත සැසියම OmniRoute විසින් භාවිත කිරීමට අවශ්ය විට ඒවා ප්රයෝජනවත් වේ.

API-key සපයන්නන් මෙන් නොව, Web Cookie සපයන්නන් සත්යාපනය සඳහා ඔබගේ බ්රවුසරය වෙබ් අඩවියට යවන අක්තපත්ර භාවිත කරයි.

# ආරම්භ කිරීමට පෙර

> **වැදගත්:** සෑම විටම අක්තපත්ර පිටපත් කළ යුත්තේ **සජීවී ජාල ඉල්ලීමකින්** මිස ඔබගේ බ්රවුසරයේ cookie ගබඩාවෙන් **නොවේ**.

බොහෝ සත්යාපන ගැටලු ඇති වන්නේ වැරදි ස්ථානයෙන් cookies පිටපත් කිරීම හේතුවෙනි.

## Cookie ගබඩාවෙන් පිටපත් නොකරන්න

බොහෝ බ්රවුසර පහත මාර්ගය හරහා ගබඩා කළ cookies පෙන්වයි:

```
DevTools
→ Application (හෝ Storage)
→ Cookies
```

මෙම cookies නිවැරදි ලෙස පෙනුණත්, ඒවා:

- කල් ඉකුත් වූ ඒවා විය හැක
- අසම්පූර්ණ විය හැක
- සත්යාපිත ඉල්ලීම් මත පමණක් යවන cookies නොමැති විය හැක

මෙම අගයන් වලංගු ලෙස පෙනුණත්, ඒවා භාවිත කිරීමෙන් සත්යාපනය අසාර්ථක විය හැක.

## සජීවී ඉල්ලීමකින් පිටපත් කරන්න

ඒ වෙනුවට, සාර්ථක ඉල්ලීමක cookies භාවිත කරන්න:

```
DevTools
→ Network
→ පිටුව නැවුම් කරන්න
→ chat හෝ conversation ඉල්ලීමක් විවෘත කරන්න
→ Request Headers
→ Cookie
```

`Cookie` ඉල්ලීම් ශීර්ෂයේ අඩංගු වන්නේ ඔබගේ බ්රවුසරය සාර්ථකව භාවිත කළ නිශ්චිත සත්යාපන තොරතුරුය.

බොහෝ Web Cookie සපයන්නන් සඳහා, OmniRoute තුළ ඇලවිය යුත්තේ මෙම අගයයි.

# සාමාන්ය සැකසුම

බොහෝ Web Cookie සපයන්නන් සඳහා සැකසුම් ක්රියාවලිය එකම වේ.

1. සපයන්නාගේ වෙබ් අඩවියට පුරන්න.
2. බ්රවුසරයේ Developer Tools විවෘත කරන්න.
3. **Network** ටැබය විවෘත කරන්න.
4. පිටුව නැවුම් කරන්න.
5. සත්යාපිත chat හෝ conversation ඉල්ලීමක් විවෘත කරන්න.
6. අවශ්ය සත්යාපන අක්තපත්ර පිටපත් කරන්න.
7. OmniRoute විවෘත කරන්න.
8. **Providers → Add Provider** වෙත යන්න.
9. ඔබගේ Web Cookie සපයන්නා තෝරන්න.
10. අක්තපත්ර අලවන්න.
11. **Test Connection** ක්ලික් කරන්න.
12. සපයන්නා සුරකින්න.

අවශ්ය නිශ්චිත අක්තපත්ර සපයන්නා අනුව වෙනස් වේ.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) යනු ලියාපදිංචි වීමක් අවශ්ය නොවන නොමිලේ පාරිභෝගික කතාබස් වේදිකාවකි — පළමු පිවිසුමේදී සැසිය නිර්නාමිකව නිර්මාණය වන අතර `uid`, `si_usr_id`, සහ `si_ses_id` යන කුකී තුන හරහා එය පවත්වාගෙන යයි. OmniRoute විසින් එකම model id එකක් (`notrack-c`, alias `ntw`) හරහා එම `/api/dispatch` endpoint එක proxy කරයි.

### සම්බන්ධ වීමේ පියවර

1. ඔබේ බ්රවුසරයෙන් [notrack.ai](https://notrack.ai) විවෘත කර නිර්නාමික සැසි කුකිය පිහිටුවීමට ඉඩ දෙන්න.
2. **DevTools → Network** විවෘත කර, පිටුව නැවුම් කර, ඕනෑම `/api` ඉල්ලීමක් මත ක්ලික් කරන්න.
3. **Request Headers** තුළ ඇති සම්පූර්ණ `Cookie` header අගය පිටපත් කරන්න.
4. OmniRoute තුළ **Providers → Add Provider → NoTrack Web (Free)** වෙත යන්න.
5. කුකී පෙළ `apiKey` ක්ෂේත්රයට අලවා **Save** කරන්න.

OmniRoute විසින් අලවන ලද පෙළෙන් `uid`, `si_usr_id`, සහ `si_ses_id` උපුටාගෙන, එම යුගල පමණක් සහිත පිරිසිදු `Cookie` header එකක් නැවත ගොඩනඟයි — එසේම, පවතී නම් `nt_session` (ලොග් වී ඇති ගිණුම් සඳහා පිහිටුවන `ntk_…` token එක) ද එක් කරයි. මෙම තුනෙන් එකක් හෝ නොමැති නම්, විකල්ප ආකෘති අත්හදා බැලීමට ක්රියාකරුවන්ට හැකි වන පරිදි අලවන ලද මුල් පෙළ වෙනස් නොකර ඉදිරියට යවනු ලැබේ.

### Model ids

| Model id    | ප්රදර්ශන නාමය | සටහන්                                                         |
| ----------- | ------------- | ------------------------------------------------------------- |
| `notrack-c` | NoTrack C     | පෙරනිමිය — upstream dispatch model එක `C`.                    |
| `C`         | NoTrack C     | `notrack-c` සඳහා alias එකකි (මුල් upstream dispatch code එක). |
| `notrack`   | NoTrack C     | `notrack-c` සඳහා alias එකකි.                                  |
| `ntw`       | NoTrack C     | `notrack-c` සඳහා කෙටි alias එකකි.                             |

Model ids හතරම එකම upstream dispatch model එකට (`C`) සිතියම්ගත වේ.

### ඉල්ලීම් විකල්ප

Executor එක ඉල්ලීම් body එකේ ඇති මෙම විකල්ප ක්ෂේත්ර පිළිගනී:

| Body field            | පෙරනිමිය | අරමුණ                                                                 |
| --------------------- | -------- | --------------------------------------------------------------------- |
| `notrack_mode`        | `usual`  | Dispatch mode එක (නිදහස්-ආකෘති පෙළකි; upstream එක `usual`, … පිළිගනී) |
| `notrack_max_turns`   | `6`      | පිළිතුරු දීමට පෙර upstream එකට ගත හැකි අභ්යන්තර වාර ගණන.              |
| `notrack_chat_id`     | `null`   | පවතින upstream කතාබහක් නැවත අරඹන්න (නව කතාබහක් සඳහා ඇතුළත් නොකරන්න).  |
| `notrack_attachments` | `[]`     | upstream ඇමුණුම් විස්තරකවල pass-through array එකකි.                   |
| `notrack_regenerate`  | `false`  | පෙර වාරය සඳහා නැවත ජනනය කළ පිළිතුරක් ඉල්ලීමට `true` ලෙස සකසන්න.       |

### හැකියාවන්

- **Streaming සහ non-streaming** කතාබස් සම්පූර්ණ කිරීම්.
- **Tool calling** — ඉල්ලීම මත `tools: [...]` සකසන්න; executor එක ඒවා tool-call envelope contract එකක් තුළට serialise කර, model එකේ ප්රතිචාර නැවත OpenAI `tool_calls` ලෙස parse කරයි.
- **`response_format`** — `json_object` සහ `json_schema` සඳහා සහය දක්වයි. Executor එක model එකේ පිළිතුරෙන් පළමු JSON object එක උපුටාගෙන, ආපසු ලබා දීමට පෙර එය string එකක් බවට පත් කරයි.
- **Reasoning ඉඟිය** — upstream එක `thinking` event එකක් යවන විට executor එක `reasoning` delta එකක් නිකුත් කරයි.

### සීමාවන්

- Upstream එක නිර්නාමික භාවිත සීමා බලාත්මක කරයි — ඒවා ඉක්මවූ විට executor එක හිතකාමී පණිවිඩයක් සමඟ 429 දෝෂයක් පෙන්වයි.
- සියලුම model ids එකම upstream dispatch model එකට විසඳේ; එක් එක් model සඳහා වෙනම මාරුවක් නොමැත.
- Executor එක upstream හි `/api/chats` endpoint එක අමතන්නේ නැති බැවින්, කතාබස් ඉතිහාසය / සැසි ස්වයංක්රීයව කළමනාකරණය නොවේ. පවතින upstream කතාබහක් නැවත අරඹීමට `notrack_chat_id` භාවිත කරන්න.

# Web Cookie Providers හට කළ හැකි සහ කළ නොහැකි දේ

Web Cookie providers විසින් වෙබ් අඩවියක කතාබස් අතුරුමුහුණත නැවත භාවිත කරයි. ඒවා නිල API වලට සමාන හැකියාවන් **ලබා නොදේ**.

## සහාය දක්වන දෑ

- ඔබගේ පවතින බ්රවුසර සැසිය භාවිතයෙන් සත්යාපනය කිරීම
- ඔබගේ ගිණුම හරහා ලබා ගත හැකි ආකෘති වෙත ප්රවේශ වීම
- චැට් ප්රතිචාර ප්රවාහනය කිරීම
- API යතුරක් අවශ්ය නොවීම

## සහාය නොදක්වන දෑ

- ශ්රිත කැඳවීම
- මෙවලම් කැඳවීම
- ස්වයංක්රීය ගොනු සංස්කරණය
- නියෝජිත-පාදක IDE කාර්ය ප්රවාහ
- API සඳහා පමණක් වන විශේෂාංග

මෙය අපේක්ෂිත හැසිරීමක් වන අතර එය දෝෂයක් **නොවේ**.

ඔබට මෙවලම් ක්රියාත්මක කිරීම, ස්වයංක්රීය ගොනු සංස්කරණය හෝ වෙනත් නියෝජිත කාර්ය ප්රවාහ අවශ්ය නම්, Web Cookie සැපයුම්කරුවෙකු වෙනුවට **API-key සැපයුම්කරුවෙකු** භාවිත කරන්න.
