## දළ විශ්ලේෂණය

Quota Sharing Engine එකම සම්බන්ධතාව බෙදාගන්නා API යතුරු කිහිපයක් අතර සැපයුම්කරුවෙකුගේ කාලය මත පදනම් වූ කෝටාව (උදා: Codex
පැය 5 ක කවුළුව, Kimi පැයකට ඉල්ලීම් 1500) සාධාරණව බෙදාහරියි.

**එය විසඳන ගැටලුව:** OmniRoute එකම upstream සැපයුම්කරුගේ ගිණුමට එරෙහිව API යතුරු රැසක් ප්රොක්සි කරයි. බෙදාගැනීමේ තර්කනයක් නොමැතිව, A යතුරෙන් පැමිණෙන ඉල්ලීම් ප්රවාහයක් පැය සඳහා වූ සැපයුම්කරුගේ කෝටාව අවසන් කළ හැකි අතර, කවුළුව යළි සැකසෙන තෙක් B සහ C යතුරු අවහිර වී පවතී.
එන්ජිම මෙය වළක්වන්නේ:

1. එක් එක් මානය අනුව සෑම යතුරකම චලිත පරිභෝජනය (%, ඉල්ලීම්, ටෝකන, $) නිරීක්ෂණය කිරීමෙනි.
2. කාර්ය-සංරක්ෂණ සාධාරණ-කොටස් ඇල්ගොරිතමයක් යෙදීමෙනි: ගෝලීය සංචිතය සන්තෘප්ත වී නොමැති අතරතුර යතුරකට අක්රිය කොටස්වලින් ණයට ගත හැක.
3. ඉල්ලීම upstream ක්රියාත්මක කරන්නා වෙත ළඟාවීමට පෙර hot path එකෙහි (`chatCore.ts`) ප්රතිඵලය බලාත්මක කිරීමෙනි.

## ඇල්ගොරිතමය: කාර්ය-සංරක්ෂණ සාධාරණ-කොටස

`src/lib/quota/fairShare.ts` තුළ ක්රියාත්මක කර ඇත.

### ප්රකාර

| කොන්දේසිය                                  | ප්රකාරය       | හැසිරීම                                                             |
| ------------------------------------------ | ------------- | ------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **ත්යාගශීලී** | පරිභෝජනය කළ මුළු ප්රමාණය අඩු කළ ගෝලීය සීමාව දක්වා යතුරකට ණයට ගත හැක |
| `globalUsedPercent >= saturationThreshold` | **දැඩි**      | තනි සාධාරණ කොටස දැඩිව බලාත්මක කරයි                                  |

පෙරනිමි `saturationThreshold = 0.5` (පරිසර විචල්යය `QUOTA_SATURATION_THRESHOLD`).

### එක් එක් මානය සඳහා තීරණය

සංචිතයේ සෑම සක්රිය මානයක් සඳහාම, එන්ජිම පහත දෑ ගණනය කරයි:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = මෙම යතුර සඳහා වත්මන් චලිත අගය (QuotaStore.peek වෙතින්)
remaining       = fairShareAllowed - consumed
```

ඉන්පසු:

- **`policy = hard`**: `consumed > fairShareAllowed` සහ ප්රකාරය දැඩි නම් → **අවහිර කරන්න**.
- **`policy = soft`**: `consumed > fairShareAllowed` සහ ප්රකාරය දැඩි නම් → **දඬුවමක් යොදන්න** (combo තුළ ප්රමුඛතාව අඩු කරන්න; කිසිවිටෙකත් දැඩිව අවහිර නොකරන්න).
- **`policy = burst`**: සාධාරණ කොටස නොසලකා ගෝලීය ඉඩකඩ පවතින අතරතුර ඉඩ දෙන්න.

### නිරපේක්ෂ උපරිම සීමාව

වෙන් කිරීමක් මත ඇති `capValue` + `capUnit`, ප්රකාරයෙන් හෝ ප්රතිපත්තියෙන් ස්වාධීන වූ දැඩි උපරිම සීමාවකි.
`consumed >= capValue` වන ඕනෑම මානයක් සෑමවිටම ඉල්ලීම **අවහිර කරයි**.

### බහු-මාන පරීක්ෂාව

සංචිතයේ **ඕනෑම** මානයක් එය අවහිර කරන්නේ නම් ඉල්ලීමක් අවහිර වේ. මාන එකිනෙකින් ස්වාධීන වේ — 5h% අවසන් වීම weekly% මානයට බලපාන්නේ නැත.

### ණයට ගැනීම

ත්යාගශීලී ප්රකාරයේදී, තම වෙන් කිරීම අඩුවෙන් පරිභෝජනය කර ඇති යතුරකට අනෙකුත් යතුරුවල වෙන් නොකළ කොටස්වලින් ඇති අතිරික්තය භාවිත කළ හැක.
සූත්රය මෙසේය:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

මෙහි `consumedByOtherKeys = consumedTotal - consumedByThisKey` වේ. ගෝලීය උපරිම සීමාව (එම මානය සඳහා සංචිතයේ `limit`) සෑමවිටම දැඩි උපරිම සීමාව වේ.

## ස්ලයිඩින් කවුළු ගණකය

`src/lib/quota/sqliteQuotaStore.ts` සහ `redisQuotaStore.ts` තුළ ක්රියාත්මක කර ඇත.

එක් එක් `(apiKeyId, dimensionKey)` සඳහා බකට් දෙකක් ඇත:

- `curr`: වත්මන් බකට් එක (`floor(nowMs / windowMs)`)
- `prev`: පෙර බකට් එක (`curr - 1`)

ඵලදායී චලිත අගය:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**නිරවද්යතාව**: ~99% ක් නිරවද්යයි. බකට් අතර සීමාවේදී දෝෂය උපරිම වශයෙන් කවුළු ප්රමාණයෙන් 1% කි (බකට් 2 ආසන්නකරණයට ආවේණිකය).

### සමකාලීනත්වය

SQLite ධාවකය: එක් එක් `(apiKeyId | dimensionKey)` යතුර සඳහා ඇති මතකය තුළ mutex එක, read-modify-write තරඟ තත්ත්වය වළක්වයි. රටාව `src/sse/services/auth.ts` හි anti-thundering-herd රටාව පිළිබිඹු කරයි.

Redis ධාවකය: පරමාණුක වර්ධනය සඳහා Lua EVAL ස්ක්රිප්ට් එකක් භාවිත කරයි — එය තනි Redis විධානයක් ලෙස ක්රියාත්මක වේ.

## පයිප්ලයින් ඒකාබද්ධ කිරීම

### PRE හුක් (`open-sse/handlers/chatCore.ts`)

සත්යාපනය සහ ප්රතිපත්ති පරීක්ෂා කිරීමෙන් පසුව, upstream executor එකට පෙර ධාවනය වේ:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → එක් එක් මානය සඳහා getQuotaStore().peek()
      → fairShare.decideFairShare()
      → අවහිර කරන්නේ නම් → 429 ආපසු ලබා දෙන්න (buildErrorBody, දෘඪ රීතිය #12)
      → අවසර දෙන්නේ නම් + ප්රමුඛතාව අඩු කරන්නේ නම් → candidate මත quotaSoftPenalty=true සකසන්න
  → executor.execute()
```

**විවෘත-අසමත් වීම**: `enforceQuotaShare` දෝෂයක් නිකුත් කළහොත්, `pino.warn` ලොගයක් සමඟ
ඉල්ලීමට ඉදිරියට යාමට අවසර ලැබේ. මෙය කෝටා-එන්ජින් දෝෂයක් මඟින් සියලු
ගමනාගමනය අවහිර වීම වළක්වයි.

### POST හුක් (පරිභෝජනය වාර්තා කිරීම)

සාර්ථක ප්රතිචාරයකින් පසුව:

```
executor සාර්ථක ප්රතිඵලයක් ආපසු ලබා දෙයි
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → එක් එක් මානය සඳහා getQuotaStore().consume()
      → විවෘත-අසමත් වීම: දෝෂ pino.warn ලෙස ලොග් කෙරේ, කිසිවිටෙක client වෙත ප්රචාරණය නොකෙරේ
```

**විචලන සටහන**: ප්රතිචාරයෙන් පසුව `consume` අසමත් වුවහොත්, rolling counter එක අඩුවෙන් ගණන් කරයි.
සපයන්නාගෙන් ලැබෙන සන්තෘප්ති සංඥාව (උදා. `anthropic-ratelimit-unified-5h-utilization`)
ඊළඟ ඉල්ලීමේදී ගෝලීය ඇස්තමේන්තුව නිවැරදි කරයි.

### Combo මෘදු දඬුවම (`open-sse/services/combo.ts`)

`decision.deprioritize === true` වන විට:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // පෙරනිමිය 0.7
}
```

අනෙකුත් සියලුම ලකුණුකරණ සාධකවලින් පසුව දඬුවම යොදනු ලැබේ. එය දෘඪ ලෙස අවහිර නොකර,
සන්තෘප්ත key එකක් තෝරාගැනීමේ auto-combo සම්භාවිතාව අඩු කරයි.

## දෝෂ නිරාකරණය

### Redis වින්යාස කර ඇති නමුත් සම්බන්ධ නොවේ

`ioredis` ස්ථාපනය කර ඇති බව (`npm ls ioredis`) සහ `QUOTA_STORE_REDIS_URL`
වෙත ළඟා විය හැකි බව පරීක්ෂා කරන්න. සම්බන්ධතාව අසාර්ථක වූ විට factory එක SQLite වෙත ආපසු හැරේ (`warn`
මට්ටමින් ලොග් කරනු ලැබේ).

### `peek` පැරණි දත්ත ලබා දෙයි / fail-open වේ

`peek` දෝෂයක් නිකුත් කළහොත්, `enforceQuotaShare` ප්රතිඵලය "අවසර දෙන්න" ලෙස සලකයි (fail-open).
මූලික හේතුව හඳුනාගැනීමට `quota:enforce` සහ `quota:factory` ඇතුළත් කිරීම් සඳහා
`pino` ලොග් පරීක්ෂා කරන්න.

### පරිභෝජන කවුන්ටරයේ අපගමනය

සැබෑ සැපයුම්කරු භාවිතය කවුන්ටරවලට වඩා වෙනස් නම්, එය අපේක්ෂිතය — buckets 2ක
ස්ලයිඩින් කවුළුවට කවුළු සීමාවලදී ~1% දෝෂයක් ඇති අතර, `consume` ප්රතිචාරයෙන් පසු
fire-and-forget ආකාරයෙන් ක්රියා කරයි. සන්තෘප්ති සංඥාව (`saturationSignals.ts`)
තත්පර 30ක TTL එකක් සමඟ සැබෑ සැපයුම්කරු භාවිතය කියවා ඒ අනුව `globalUsedPercent`
සකසයි.

### සංචිතය පරිභෝජන අනුපාතය සඳහා "දත්ත නැත" ලෙස පෙන්වයි

## localStorage වෙතින් සංක්රමණය

`/dashboard/costs/quota-share` පළමුව පූරණය වන විට, `useLocalStoragePoolMigration` hook එක පහත කරුණු පරීක්ෂා කරයි:

1. `localStorage.getItem("omniroute:quota-share:pools")` හිස් නොවීම.
2. `GET /api/quota/pools` මඟින් `[]` ආපසු ලබා දීම (DB එක හිස්ය).

දෙකම සත්ය නම්, එය සෑම පැරණි pool එකක්ම සමූහයක් ලෙස `POST /api/quota/pools` වෙත යවා, පසුව localStorage key එක ඉවත් කරයි. මෙම සංක්රමණය idempotent වේ: කොන්දේසිය 2 නැවත සංක්රමණය වීම වළක්වයි.

## අභ්යන්තර Strategy වර්ගීකරණය

`quota-share` යනු **අභ්යන්තර භාවිතයට පමණක්** වූ routing strategy එකකි (`src/shared/constants/routingStrategies.ts` තුළ `INTERNAL_ROUTING_STRATEGY_VALUES`). එය පද්ධතිය මඟින් mint කරන ලද `qtSd/` pool combos සඳහා පමණක් භාවිත වන අතර, UI හෝ API තුළ පරිශීලකයාට තෝරාගත හැකි විකල්පයක් ලෙස කිසිවිටෙකත් නොපෙන්වන පරිදි එය හිතාමතාම `ROUTING_STRATEGY_VALUES` වෙතින් බැහැර කර ඇත.
