## මෙය පවතින්නේ ඇයි

`hidePaidModels` මඟින් "මෙම ආකෘතිය නොමිලේද?" යන්නටත් `hideAutoCombos` මඟින් "`auto/*`
අතථ්ය ids කිසිසේත් ප්රචාරය කළ යුතුද?" යන්නටත් පිළිතුරු සපයයි — එහෙත් ඒ දෙකෙන් එකක්වත් ක්රියාකරුවකුට
අභිමත ආකෘති උපකූලකයක් තෝරා සකස් කිරීමට ඉඩ නොදෙයි (උදා: මිලකරණයෙන් ස්වාධීනව, යම් Claude Code / OpenCode සේවාලාභියකුට
පෙනිය යුතු ආකෘති පමණක් හරියටම ඉදිරිපත් කිරීම). #11481 එය ස්වාධීන, තේරීමෙන් සක්රිය කළ හැකි string-array සැකසුම් දෙකක් ලෙස එක් කරයි.

## එක් අවහිර ලක්ෂ්යයක් නොව, දෙකක්

#6512 වෙතින් ලද පාඩම මෙහිදීත් ඒ ආකාරයෙන්ම අදාළ වේ (`hidePaidModels` මත පමණක් පදනම් වූ නාමාවලි පෙරහනක් යෙදුවත්, combo අපේක්ෂක
සංචිතය ස්වාධීනව ගොඩනැගුණු බැවින් `auto/*` හට තවමත් ගෙවීම් සහිත ආකෘතියකට මාර්ගගත වීමට හැකි විය).
ගැළපුම් ප්රකාශකය වන `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) පහත ස්ථාන දෙකෙන්ම කැඳවනු ලැබේ:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` ලැයිස්තුගත කිරීම තුළම, `shouldHidePaid()` දැනටමත් පාලනය කරන
  මූලාශ්රයකට අදාළ අවහිර ලක්ෂ්ය 5 තුළ (ස්ථිතික `PROVIDER_MODELS`, සමමුහුර්ත කළ සපයන්නාගේ පේළි,
  අභිරුචි පේළි, alias-පාදක පේළි, කළමනාකරණය කළ fallback පේළි).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — සමාන
  `filterPaidOnlyCandidates()` කැඳවීමට වහාම පසුව `virtualFactory.ts::buildPreparedPool` වෙතින් කැඳවනු ලබන බැවින්,
  ප්රතික්ෂේපිත ආකෘතියක් කිසි විටෙකත් `auto/*` අපේක්ෂක සංචිතයකට තෝරාගත නොහැක.

## පෙරහන් නොකරන දෑ

`hideAutoCombos` හි දැනට පවතින හැසිරීම පිළිබිඹු කරයි: **පැහැදිලිව** යවන ලද ආකෘති id එකක් (`auto/*` හරහා නොව,
