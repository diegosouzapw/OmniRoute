Reasoning routing නීති දැනට පවතින model සහ combo routing ක්රමය පුළුල් කරයි. සක්රිය නීතියක් නොගැළපෙන විට,
දැනට පවතින thinking, suffix, connection-default සහ provider-translation හැසිරීම
වෙනස් නොවේ.

## කළමනාකරණය

නීති කළමනාකරණය **Settings → Global Routing** යටතේ ලබා ගත හැක. API-key සංස්කාරකය තෝරාගත් key එකට
පෙරහන් කළ එම කළමනාකරණ UI එකම සපයයි.

කළමනාකරණ API එක මෙම routes මඟින් නිරාවරණය කෙරේ:

- `/api/settings/reasoning-routing-rules` හි `GET` සහ `POST`
- `/api/settings/reasoning-routing-rules/[id]` හි `GET`, `PATCH`, සහ `DELETE`
- `/api/settings/reasoning-routing-rules/simulate` හි `POST`

සියලු routes `requireManagementAuth` භාවිත කරයි. Inputs,
`src/shared/validation/schemas/reasoningRouting.ts` හි ඇති schemas භාවිතයෙන් වලංගු කරනු ලැබේ. Simulator එක කිසි විටෙක upstream call එකක් සිදු නොකරයි.

## නීති නිරාකරණය

මුල් ඇගයීම හරියටම එක් නීතියක් තෝරා ගනී. Scopes මෙම අනුපිළිවෙළට පරීක්ෂා කෙරේ:

1. `apiKey`
2. `combo`
3. `model`
4. `global`

Scope එකක් තුළ, පළමුව ඉහළ `priority` අගය ජය ගනී; ඉන්පසු glob pattern එකකට වඩා නිශ්චිත model ගැළපීමක්ද,
ඉන්පසු ස්ථාවර `createdAt` සහ `id` අනුපිළිවෙළද සලකා බලනු ලැබේ. `requestTags`, `metadata.tags` වෙතින් පමණක් කියවනු ලබන අතර
`any` හෝ `all` ගැළපීමට සහාය දක්වයි.

`connection` නීතියක් ඇගයීමට ලක් කරන්නේ මුල් නීතියක් ජය නොගත් විට සහ නිශ්චිත provider connection එකක්
දැනටමත් තෝරාගෙන ඇති විට පමණි. එයට effort සහ budget පමණක් වෙනස් කළ හැක.

## Effort සහ Budget

`sourceEffort` සඳහා `any`, `missing`, `none`, `low`, `medium`, `high`, `xhigh`, `max`, සහ
`ultra` පිළිගනු ලැබේ. `missing` යනු request එකේ discrete effort එකක්වත්, thinking toggle එකක්වත්,
thinking budget එකක්වත් නොමැති බවයි. එබැවින් budget-only signal එකක් ගැළපෙන්නේ `any` සමඟ පමණි.

`effortMode` හි ප්රභේද තුනක් ඇත:

- `inherit` මඟින් client effort එක රඳවා ගන්නා අතර model එකට හෝ combo එකට වෙනස් වීමට තවදුරටත් ඉඩ දෙයි.
- `default` මඟින් පැහැදිලි reasoning signal එකක් නොමැති විට පමණක් `targetEffort` සකසයි.
- `force` මඟින් discrete effort එක `targetEffort` සමඟ ප්රතිස්ථාපනය කරයි.

ස්වාධීනව, `budgetAction` සඳහා `preserve`, `remove`, හෝ `set` විය හැක. `none` සමඟ ඇති `force` මඟින්
හඳුනාගත් සියලු effort සහ budget fields ඉවත් කරයි. `set` සමඟ `none` භාවිතය වලංගු නොවේ.

දන්නා නොගැළපෙන models ඉලක්ක කරන requests, upstream call එකට පෙර ප්රතික්ෂේප කරනු ලැබේ. Combo
targets සඳහා, නොගැළපෙන entries ඉවත් කෙරේ; කිසිවක් ඉතිරි නොවන්නේ නම් request එක `400` status එක ලබා දෙයි.
නොදන්නා capability data මඟින් අනතුරු ඇඟවීමක් ජනනය වන අතර නීතිය සක්රියව තබයි.
