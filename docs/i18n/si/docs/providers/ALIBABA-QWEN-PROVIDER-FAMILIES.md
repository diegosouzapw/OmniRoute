නිරූපණය කෙරේ. කලාපය යනු සම්බන්ධතා දත්තයකි, වෙනම නිෂ්පාදනයක් නොවේ.

මාර්ග, සංයෝජන සහ ඓතිහාසික භාවිතය සඳහා ධාවනකාල අනුකූලතා අන්වර්ථ නාමයක් ලෙස පවතී. එහි උපකරණ පුවරු කාඩ්පත `alibaba` තුළට ඒකාබද්ධ කර ඇත; දත්ත සමුදාය
නැවත ලිවීම අවශ්ය නොවේ.

Qwen Cloud භාවිතය අනුව ගෙවීමේ නිෂ්පාදනය සහ Alibaba Cloud Model Studio දැනට DashScope-අනුකූල
ධාවනකාල සත්කාරක බෙදාගත්තද, පරිශීලකයන් යතුරු ලබාගන්නේ සහ ගිණුම් කළමනාකරණය කරන්නේ
විවිධ නිෂ්පාදන අතුරුමුහුණත් හරහා බැවින් ඒවා වෙනම සපයන්නන්ගේ අනන්යතා ලෙස පවතී. Alibaba සහ Qwen Cloud Token Plan නිෂ්පාදන
විවිධ අන්තලක්ෂ්ය පවුල් භාවිත කරන බැවින්, නිෂ්පාදන හතරම වෙනම සපයන්නන්ගේ ID ලෙස පවතී.

## සම්බන්ධතා ගිවිසුම

නව සම්බන්ධතා ස්ථාවර කලාප යතුර `providerSpecificData` තුළ ගබඩා කරයි:

```json
{
  "region": "global-sg"
}
```

අවසර ලත් අගයන් වන්නේ `global-sg` සහ `china-beijing` ය. අන්තලක්ෂ්යය
සපයන්නාගේ ID සහ කලාපය මත පදනම්ව මධ්යගතව ව්යුත්පන්න කෙරේ. පෙරසැකසුමක් නොවන `providerSpecificData.baseUrl` එකක් පැහැදිලි ක්රියාකරු
අභිබවා යාමක් ලෙස පවතින අතර එයට ප්රමුඛත්වය හිමි වේ; පැරණි සුරැකි පෙරසැකසුම් URL නැවත කලාපීය
අනුකෘතියට සාමාන්යකරණය කෙරේ.

මෙය සම්බන්ධතා යෝජනා ක්රමය විස්තාරණය කළ හැකි ලෙස තබා ගනී: වෙනත් සපයන්නාගේ කාඩ්පතක්
නිර්මාණය නොකර හෝ සුරැකි සපයන්නන්ගේ ID වෙනස් නොකර විසඳුම්කාරකයට තවත් කලාපයක් එක් කළ හැක.

## ගැළපුම සහ ක්රියාත්මක කිරීම

1. කලාපීය endpoint resolver එක එක් කර දැනට පවතින ගෝලීය පෙරනිමි අගයන් රඳවා ගන්න.
2. `alibaba`, එහි `alibaba-cn` ගැළපුම් ID එක, සහ `qwen-cloud` සඳහා සජීවී කලාපීය DashScope `/models` සොයාගැනීම භාවිත කරන්න. සාමාන්ය endpoint එක රූප, වීඩියෝ, ශ්රව්ය, embedding, සහ වෙනත් chat නොවන models ද ආපසු ලබා දෙන බැවින්, ඒවායේ ප්රතිචාර පළමුව text-generation filter එකක් හරහා යයි. ඉන්පසු `qwen-cloud` එහි provider registry එකේ ප්රකාශිත, නඩත්තු කරනු ලබන allowlist එක යොදයි.
