IDE සැසියක් නොමැතිව Cursor, OmniRoute පසුපස තැබීමට ක්රම දෙකක් ඇත:

1. **`cursor-api` සැපයුම්කරු** ("Cursor API" කාඩ්පත, `cua` යන අන්වර්ථ නාමය): Cursor පරිශීලක API යතුරක් (`crsr_…`, `https://cursor.com/dashboard/api` හිදී ජනනය කරන ලද) රඳවා ගන්නා API-යතුරු සැපයුම්කරුවෙකි. ඉන්පසු ඕනෑම OmniRoute සේවාලාභියෙකුට සාමාන්ය කෝටා, පසුබැසීමේ සහ ලොග් කිරීමේ ස්තර සමඟ `/v1/chat/completions` හරහා `cursor-api/<model>` හෝ `cua/<model>` ලෙස Cursor ආකෘති වෙත ළඟා විය හැක. IDE සැපයුම්කරු (`cursor`, OAuth/IDE සැසිය) නොවෙනස්ව පවතී.
2. **Cursor CLI සෘජු යොමුකිරීම**: Cursor CLI (`agent`) එක OmniRoute වෙත යොමු කරන්න. එවිට CLI එක සිදු කරන සෑම RPC එකක්ම OmniRoute API යතුරකින් සත්යාපනය කර, `cursor-api` සම්බන්ධතාවක අක්තපත්රය සමඟ Cursor වෙත යොමු කර, Logs පිටුවේ වාර්තා කෙරේ.

## යතුර හුවමාරු කරන්නේ ඇයි

`api2.cursor.sh`, අමු `crsr_…` යතුරක් Bearer ටෝකනයක් ලෙස පිළිගන්නේ නැත (401). Cursor CLI එක පළමුව යතුර `/auth/exchange_user_api_key` වෙත POST කර, පැයකට පසු කල් ඉකුත් වන සැසි JWT එකක් ලබා ගනී; ආපසු ලැබෙන `refreshToken` එකෙහිද එකම `exp` අගය ඇති බැවින්, නැවුම් කිරීම යනු යතුර නැවත හුවමාරු කිරීමයි.
`open-sse/services/cursorApiKeyAuth.ts` එම හුවමාරුව සිදු කර, එක් යතුරකට එක් සැසි ටෝකනයක් හැඹිලිගත කර, කල් ඉකුත්වීමට මිනිත්තු පහකට පෙර නැවත හුවමාරු කර, Cursor වෙතින් 401 ප්රතිචාරයක් ලැබුණු විට හැඹිලිගත ටෝකනය ඉවත් කරයි. `CursorExecutor`, `cursor-api` සම්බන්ධතා සඳහා upstream ප්රවාහය විවෘත කිරීමට මොහොතකට පෙර එය කැඳවයි.

## `cursor-api` සැපයුම්කරු

රෙජිස්ට්රිය: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` හා සමාන `format`, `baseUrl` සහ
`models`). නාමාවලි කාඩ්පත:
`src/shared/constants/providers/apikey/specialty-media.ts`. ක්රියාත්මකකාරක සිතියම:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

උපකරණ පුවරුව: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

ඉන්පසු:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

සටහන්:

- `cursor-api` සඳහා ආකෘති ලැයිස්තුව ස්ථිතික Cursor රෙජිස්ට්රියෙන් පැමිණේ (IDE සැපයුම්කරු පසුබසින විට භාවිත කරන එකම ලැයිස්තුව); OmniRoute සත්කාරකය මත `cursor-agent` ස්ථාපනය කිරීම අවශ්ය නොවේ.
- `POST /api/providers/{id}/refresh-cursor` යනු `cursor` IDE සැපයුම්කරු සඳහා පමණි; `cursor-api` සම්බන්ධතා සඳහා අලුත් කිරීමට IDE සැසියක් නොමැත.

## Cursor CLI සෘජු යොමුකිරීම

මාර්ගය: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. හසුරුවනය තමන්ගේම සත්යාපනය බලාත්මක කරන බැවින් `/api/cursor-cli/` උපසර්ගය `src/shared/constants/publicApiRoutes.ts` තුළ ලියාපදිංචි කර ඇත:

| මාර්ගය                                                                                                                            | CLI වෙතින් අපේක්ෂිත සත්යාපනය | OmniRoute සිදු කරන දේ                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                                | `Bearer <OmniRoute API key>` | යතුර වලංගු කර, පැය 1ක HS256 JWT එකක් (`JWT_SECRET` සමඟ අත්සන් කළ) නිර්මාණය කර එය ආපසු ලබා දෙයි                                                                                       |
| අනෙකුත් සෑම මාර්ගයක්ම (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`          | නිකුත් කරන්නා/ප්රේක්ෂකයා/කල් ඉකුත්වීම තහවුරු කර, සක්රිය `cursor-api` සම්බන්ධතාවක් තෝරා, Authorization ශීර්ෂකය හුවමාරු කළ Cursor ටෝකනයෙන් ප්රතිස්ථාපනය කර, පිළිතුර ආපසු ප්රවාහනය කරයි |

CLI එක තමන්ට ලැබෙන ඕනෑම ටෝකනයකින් `exp` විකේතනය කරන බැවින්, එයට පාරදෘශ්ය නොවන ටෝකනයක් ලබා දීමෙන් සෑම ඉල්ලීමකටම පාහේ පෙර එය නැවත හුවමාරු කරයි; නිර්මාණය කළ JWT එක එය වළක්වයි. OmniRoute වෙතින් 401 ලැබුණහොත් CLI එක නැවත හුවමාරු කරයි.

### සැකසුම

1. OmniRoute API යතුරක් (Dashboard → API keys) සහ `cursor-api` සම්බන්ධතාවක් සාදන්න.
2. agent ප්රවාහය සඳහා HTTP/1.1 භාවිත කරන ලෙස CLI එකට දන්වන්න. `~/.cursor/cli-config.json` තුළ:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   මෙය නොමැතිව CLI එක agent වාරය වෙනම වින්යාස කළ agent සත්කාරකයකට HTTP/2 හරහා විවෘත කරන අතර, endpoint එක හරහා ගමන් කරන්නේ පාලන-තල RPC පමණි.

3. OmniRoute වෙත යොමු කර CLI එක ධාවනය කරන්න:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

සෑම පියවරක්ම සැපයුම්කරු `cursor-api`, ඉල්ලීම් වර්ගය `cursor-cli`, මාර්ගය `/api/cursor-cli/<rpc>` ලෙස Logs තුළ සටහන් වන අතර, එය OmniRoute API යතුරට සහ එය සැපයූ සම්බන්ධතාවට ආරෝපණය කෙරේ.
