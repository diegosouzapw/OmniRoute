### 3.1 `src/app/` — App Router

App Router මඟින් උපකරණ පුවරු UI එක සහ පොදු/කළමනාකරණ HTTP API එක යන දෙකම නිරාවරණය කරයි.
**ගෝලීය මිඩ්ල්වෙයා නොමැත** — බාධා කිරීම එක් එක් මාර්ගය අනුව සිදු කෙරේ.

`src/app/` යටතේ ඇති ඉහළ-මට්ටමේ කොටස්:

| මාර්ගය                                                                        | අරමුණ                                           |
| ----------------------------------------------------------------------------- | ----------------------------------------------- |
| `api/`                                                                        | සියලුම HTTP API මාර්ග (පහත විස්තරය බලන්න)       |
| `a2a/`                                                                        | A2A JSON-RPC 2.0 අන්ත ලක්ෂ්යය (`POST /a2a`)     |
| `.well-known/agent.json/`                                                     | A2A Agent Card සොයාගැනීමේ ලේඛනය                 |
| `(dashboard)/`                                                                | උපකරණ පුවරු UI (මාර්ග සමූහය, URL උපසර්ගයක් නැත) |
| `auth/`, `login/`, `forgot-password/`, `callback/`                            | සත්යාපන ප්රවාහ                                  |
| `landing/`                                                                    | අලෙවිකරණ/පිවිසුම් පිටුව                         |
| `docs/`                                                                       | කාවැද්දූ API ලේඛන දසුන                          |
| `status/`, `maintenance/`, `offline/`                                         | මෙහෙයුම් පිටු                                   |
| `privacy/`, `terms/`                                                          | නීතිමය පිටු                                     |
| `400/`, `401/`, `403/`, `408/`, `429/`, `500/`, `502/`, `503/`                | ස්ථිතික දෝෂ පිටු                                |
| `error.tsx`, `global-error.tsx`, `not-found.tsx`, `forbidden/`, `loading.tsx` | රාමුක දෝෂ/පූරණ සීමා                             |
| `layout.tsx`, `page.tsx`, `globals.css`, `manifest.ts`                        | මූලික කවචය                                      |

   registry එක තුළ) models ලියාපදිංචි කරන්න.
6. `tests/unit/` යටතේ පරීක්ෂණ ලියන්න.

### නව API route එකක් එක් කිරීම

1. `src/app/api/your-route/route.ts` සාදන්න.
2. මෙම රටාව අනුගමනය කරන්න: CORS → Zod body වලංගුකරණය → සත්යාපනය → handler වෙත පැවරීම.
3. නව request ආකෘතියක් නම්: `src/shared/validation/schemas.ts` තුළ Zod schema එක එක් කරන්න.
4. එය කළමනාකරණයට පමණක් නම්: `src/shared/constants/publicApiRoutes.ts`
   වෙත path එක එක් කරන්න (පොදු API පෘෂ්ඨය සඳහා denylist එක).
5. `tests/unit/` යටතේ පරීක්ෂණ එක් කරන්න.
6. `docs/reference/API_REFERENCE.md` සහ `docs/openapi.yaml` යාවත්කාලීන කරන්න.

### නව DB module එකක් එක් කිරීම

1. `src/lib/db/yourModule.ts` සාදා `./core.ts` වෙතින් `getDbInstance()` ආයාත කරන්න.
2. ඔබේ domain එක සඳහා CRUD functions නිර්යාත කරන්න.
3. නව tables තිබේ නම්: `src/lib/db/migrations/` යටතේ අනුක්රමිකව අංකනය කළ,
   idempotent සහ transactional migration එකක් එක් කරන්න.
4. Importers විසින් `@/lib/db/yourModule` වෙතින් සෘජු imports භාවිත කරයි (barrel එකක් නොවේ — පැරණි `localDb.ts` නැවත-නිර්යාත ස්තරය ඉවත් කර ඇත).
5. `tests/unit/` යටතේ පරීක්ෂණ එක් කරන්න.

5. [MCP-SERVER.md](../frameworks/MCP-SERVER.md) යාවත්කාලීන කරන්න.

## 11. සම්මුතීන්

- **කේත ශෛලිය**: හිස්තැන් 2ක indent කිරීම, ද්විත්ව උද්ධෘත ලකුණු, අක්ෂර 100ක පළල, semicolons,
  `es5` trailing commas — `lint-staged` හරහා Prettier මඟින් බලාත්මක කෙරේ.
- **Imports**: බාහිර → අභ්යන්තර (`@/`, `@omniroute/open-sse`) → සාපේක්ෂ.
- **නාමකරණය**: files සඳහා `camelCase` හෝ `kebab-case`, components සඳහා `PascalCase`,
  constants සඳහා `UPPER_SNAKE`.
- **ESLint**: සෑම තැනකම `no-eval`, `no-implied-eval`, `no-new-func` = `error`;
  `open-sse/` සහ `tests/` තුළ `no-explicit-any` = `warn`, අනෙක් ස්ථානවල error.
- **TypeScript**: `strict: false` (පැරණි ස්ථාවරය). modules අතර සීමා සඳහා
  inference වෙනුවට පැහැදිලි types භාවිත කිරීමට ප්රමුඛත්වය දෙන්න.
- **දත්ත සමුදාය**: routes හෝ handlers තුළ කිසිවිටෙක raw SQL නොලියන්න — සැමවිටම
  `src/lib/db/` modules හරහා යන්න. කිසිවිටෙක barrel-import නොකරන්න — නිශ්චිත `src/lib/db/*` modules සෘජුව භාවිත කරන්න.
- **DB-entity typing (#3512)**: DB table එකක row ආකෘතිය ලියන හෝ කියවන function එකක්,
  call site එකේ `any` හෝ inline anonymous type එකක් වෙනුවට, එම table එකේ
  columns 1:1 ලෙස පිළිබිඹු කරන නම් කළ TS interface එකක් ලබාගෙන/ආපසු ලබා දිය යුතුය.
  interface එක function එක අසල තබන්න (උදා. `saveRequestUsage` ට ඉහළින්
  `src/lib/usage/usageHistory.ts` තුළ `export interface UsageEntry`), විවිධ writers විසින් row එක
  ක්රමයෙන් පුරවන විට එක් එක් fields optional/nullable ලෙස තබන්න,
  සහ callers අතර ආකෘතිය වෙනස් වන field එකක් සඳහා `any` වෙනුවට `unknown` භාවිත කිරීමට ප්රමුඛත්වය දෙන්න
  (field එක මත එය ලේඛනගත කරන්න, උදා. `UsageEntry.tokens`
  raw provider-shaped usage සහ normalized shape යන දෙකම පිළිගනී). මේ ආකාරයෙන්
  file එකක `any` ගණන ශුන්යයට ළඟා වූ පසු, එය නැවත පිරිහිය නොහැකි වන සේ
  `check:any-budget:t11` allowlist එකට (`scripts/check/check-t11-any-budget.mjs`,
  `maxAny: 0`) එක් කරන්න. මෙය first-slice සම්මුතියකි — පුළුල් "anonymous `any` නැත"
  පිරිසිදු කිරීම අනෙකුත් codebase එක පුරා පුනරාවර්තනීයව සිදු කෙරේ.
- **දෝෂ**: නිශ්චිත error types සමඟ try/catch භාවිත කර, pino context සමඟ log කරන්න. SSE streams තුළ
  කිසිවිටෙක දෝෂ නිහඬව නොසලකා හරින්න; cleanup සඳහා abort signals භාවිත කරන්න.
- **ආරක්ෂාව**: කිසිවිටෙක `eval()` / `new Function()` / implied eval භාවිත නොකරන්න. සියලු
  inputs Zod සමඟ වලංගු කරන්න. නිෂ්ක්රීයව ඇති credentials සංකේතනය කරන්න (AES-256-GCM).
  `src/shared/constants/upstreamHeaders.ts` denylist එක
  sanitize/validation ස්තරය සමඟ සමපාතව තබා ගන්න.
- **Commits**: Conventional Commits — `feat(scope): subject`. අවසර ලත් scopes:
  `db`, `sse`, `oauth`, `dashboard`, `api`, `cli`, `docker`, `ci`, `mcp`,
  `a2a`, `memory`, `skills`.
- **Branches**: prefixes `feat/`, `fix/`, `refactor/`, `docs/`, `test/`,
  `chore/`. කිසිවිටෙක `main` වෙත සෘජුව commit නොකරන්න.
- **Husky**: pre-commit විසින් `lint-staged` + `check:docs-sync` +
  `check:any-budget:t11` ධාවනය කරයි; pre-push විසින් `check:any-budget:t11` + `check:tracked-artifacts` ධාවනය කරයි (වේගවත් gates; `test:unit` බැහැර කරයි).

## 12. දැඩි නීති (CLAUDE.md වෙතින්)

1. කිසිවිටෙකත් රහස් හෝ අක්තපත්ර commit නොකරන්න.
2. කිසිවිටෙකත් barrel-import නොකරන්න — නිශ්චිත `src/lib/db/*` මොඩියුල සෘජුවම භාවිත කරන්න.
3. කිසිවිටෙකත් `eval()` / `new Function()` / ව්යංග eval භාවිත නොකරන්න.
4. කිසිවිටෙකත් `main` වෙත සෘජුවම commit නොකරන්න.
5. කිසිවිටෙකත් routes තුළ raw SQL නොලියන්න — සැමවිටම `src/lib/db/` මොඩියුල හරහා යන්න.
6. SSE streams තුළ දෝෂ නිහඬව නොසලකා නොහරින්න.
7. සැමවිටම Zod schemas මඟින් ආදාන වලංගු කරන්න.
8. production code වෙනස් කරන විට සැමවිටම පරීක්ෂණ ඇතුළත් කරන්න.
9. ආවරණය (statements, lines, functions, branches) ≥ 60% මට්ටමේ පවත්වාගත යුතුය.
