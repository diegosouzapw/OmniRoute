`@omniroute/opencode-plugin-v2` මඟින් ඔබගේ සම්පූර්ණ OmniRoute නාමාවලිය — models, combos සහ
auto-combos — ප්රදර්ශන නාම, මිල ගණන් සහ නොමිලේ-ස්ථර භාවිත සීමා සමඟ OpenCode v2 හි model picker එකට එක් කරයි.

OpenCode v1 සහ v2 plugins පූරණය කරන්නේ වෙනස් contracts හරහා බැවින්, මෙය `@omniroute/opencode-plugin`
වෙතින් වෙන් වූ package එකකි. ඔබගේ OpenCode ප්රධාන අනුවාදයට ගැළපෙන එක තෝරන්න; ඒවා අතර කිසිවක්
හවුලේ භාවිත නොවන බැවින්, එකක් උත්ශ්රේණි කිරීමෙන් අනෙක උත්ශ්රේණි කිරීමට කිසිවිටෙක බල නොකෙරේ.

## අවශ්යතා

- OpenCode v2.
- ළඟා විය හැකි OmniRoute gateway එකක් (පෙරනිමියෙන් `http://localhost:20128`).
- Node.js 22 හෝ 24.

## ස්ථාපනය

Plugin එක `opencode.json` වෙත එක් කරන්න:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

ඉන්පසු models, `omniroute/<provider>/<model>` ලෙස දිස් වේ; එම උපසර්ගය සහ
OpenCode විසින් අක්තපත්රය ගබඩා කරන integration එකේ id එක `providerId` මඟින් තීරණය කරයි.

## අක්තපත්ර

Plugin එක පහත ස්ථාන තුනෙහි, මෙම අනුපිළිවෙළට, gateway key එකක් සොයයි:

1. **ඔබ OpenCode තුළ සම්බන්ධ කළ අක්තපත්රය.** Plugin එක integration එකක් ලියාපදිංචි කරන බැවින්,
   OpenCode හිම auth flow එකට key එක ගබඩා කළ හැක. කිසිවක් `opencode.json` තුළට නොයයි — මෙය වඩාත් යෝග්යය.
2. එක් එක් project එක සඳහා වෙනම override එකක් ලෙස plugin options තුළ `apiKey`. එමඟින් key එක ඔබ
   commit කිරීමට ඉඩ ඇති file එකක තැබේ.
3. Environment එකේ `OMNIROUTE_API_KEY`.

මේ තුනෙන් කිසිවක් නොමැති විට, නාමාවලිය හිස් වන අතර, නිහඬව හිස් picker එකක් ඉතිරි කිරීම වෙනුවට
plugin එක startup අවස්ථාවේදී එක් වරක් ඒ බව දැනුම් දෙයි.

### Management token එක වෙනස් key එකකි

Combos, provider තත්ත්වය සහ වැඩිදියුණු කිරීම් (ප්රදර්ශන නාම, මිල ගණන්, නොමිලේ-ස්ථර භාවිත සීමා) ලැබෙන්නේ
gateway හි `/api/*` endpoints වෙතිනි; බොහෝ deployments ඒවා inference key එක වෙනුවට **management** token
එකක් මඟින් ආරක්ෂා කරයි:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

`managementReadToken` සකසා නොමැති විට, එය `apiKey` වෙත පසුබැසෙයි. Gateway එකක් එම fallback එක
ප්රතික්ෂේප කළත් නාමාවලිය තවමත් ප්රකාශයට පත් වේ, නමුත් ප්රදර්ශන නාම වෙනුවට අමු model ids සමඟ,
canonical alias dedupe නොමැතිව, මිල ගණන් නොමැතිව සහ combos නොමැතිවය. එසේ සිදු වූ විට plugin එක
එක් එක් endpoint එක සඳහා එක් වරක් අනතුරු අඟවමින් endpoint එක සහ අහිමි වූ දේ නම් කරයි — එබැවින්
ගුණාත්මකභාවය අඩු වූ picker එකක් කිසිවිටෙක අභිරහසක් නොවේ.

## නාමාවලිය යාවත්කාලීනව පවතින ආකාරය

නාමාවලිය අවශ්ය වූ විට පමණක් ලබාගෙන `modelCacheTtlMs` කාලයක් සඳහා හැඹිලිගත කරන අතර, gateway වෙත ළඟා විය නොහැකි විට අවසන් වරට දැන සිටි නාමාවලිය ලබාගත හැකි ලෙස තැටි snapshot එකක් තබා ගනී — එබැවින් ඇනහිටීමකදී ඔබට අහිමි වන්නේ යාවත්කාලීන බව පමණි. Models සහ combos ලැබුණු වහාම ප්රකාශයට පත් කෙරේ; auto-combos, provider ලැයිස්තුව සහ enrichment overlay එක ලැබුණු විට ඒවා එක් කෙරෙන බැවින්, මන්දගාමී endpoint එකකට සම්පූර්ණ තේරීම්කාරකය රඳවා තබාගත නොහැක.

නම්වල gateway දන්නා තොරතුරු අඩංගු වේ: model එක යොමු කෙරෙන upstream provider, `[Free]` සලකුණක් සහ ඒ සමඟ ලැබෙන budget එක — එබැවින් එකම model එක අලෙවි කරන connections දෙකක් වෙන්කර හඳුනාගත හැක. `"providerTag": false` භාවිතයෙන් prefix එක අක්රිය කරන්න.

අතින් refresh කිරීමේ command එකක් නොමැත: OpenCode v2 commands යනු callbacks නොව prompt templates වන බැවින් plugin එකකට එවැන්නක් නිරාවරණය කළ නොහැක. Refresh කිරීම් TTL අනුව සිදු වේ; host එකෙන් reload කරන ලෙස ඉල්ලා සිටින්නේ නාමාවලිය හෝ overlay එක සැබවින්ම වෙනස් වූ විට පමණක් වන අතර, සෑම refresh කිරීමකටම වරක් නොවේ.

## Gemini මත tool ඇමතීම

Tool declarations තුළ `$schema` හෝ `additionalProperties` ඇති සම්පූර්ණ request එකක් Gemini විසින් ප්රතික්ෂේප කරමින් `400 INVALID_ARGUMENT` ලෙස පිළිතුරු දෙයි. මෙම plugin එක, මෙම providerගේ Gemini model එකක් වෙත යැවෙන tool schemas වලින් එම keywords ඉවත් කරන අතර අනෙක් සෑම request එකක්ම වෙනස් නොකර තබයි. Reference එක ඉවත් කිරීමෙන් schema එක "ඕනෑම දෙයක් පිළිගන්නා" ලෙස පුළුල් වන බැවින්, `$ref` අඩංගු tool එකක් ඉවත් කිරීම් නොකර එලෙසම ඉදිරියට යවනු ලැබේ.
එය අක්රිය කිරීමට `"geminiSanitization": false` සකසන්න.
