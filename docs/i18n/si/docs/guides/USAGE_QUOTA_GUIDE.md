## දළ විශ්ලේෂණය

OmniRoute හරහා ගලා යන සෑම ඉල්ලීමක්ම පහත තොරතුරු ග්රහණය කරන **භාවිත වාර්තාවක්** ජනනය කරයි:

- **අනන්යතාව**: කුමන API යතුර, සැපයුම්කරු, මොඩලය සහ සංයෝජනයද යන්න
- **ටෝකන**: ප්රේරක ටෝකන, සම්පූර්ණ කිරීමේ ටෝකන, හැඹිලිගත ටෝකන සහ එකතුව
- **පිරිවැය**: USD මුදල (මිලකරණ දත්තවලින් ගණනය කෙරේ)
- **කාල දත්ත**: ප්රමාදය, ආරම්භක/අවසන් වේලා මුද්රා
- **තත්ත්වය**: සාර්ථක, දෝෂ, අනුපාත-සීමා කළ, ආදිය.

මෙම වාර්තා **විශ්ලේෂණ** ලෙස සමූහනය කර, **කෝටා සැණරූ** ලෙස ස්ථිරව ගබඩා කර, **එක් එක් යතුර සඳහා වන අයවැය සීමා** බලාත්මක කිරීමට භාවිත කරයි.

```
ඉල්ලීම ──▶ chatCore ──▶ usage.record() ──▶ SQLite
                                  │
                          ┌───────┼───────┐
                          ▼       ▼       ▼
                    විශ්ලේෂණ  කෝටාව  බිල්කරණය
                 (උපකරණ පුවරුව) (බලාත්මක) (අපනයනය)
```

## වාර්තා කරනු ලබන දේ

`usage.ts` සේවාව සෑම ඉල්ලීමක් සඳහාම **භාවිත සිදුවීමක්** ග්රහණය කරයි:

| ක්ෂේත්රය           | වර්ගය   | මූලාශ්රය                                                   |
| ------------------ | ------- | ---------------------------------------------------------- |
| `id`               | string  | වාර්තා කරන විට ජනනය කළ UUID                                |
| `apiKeyId`         | string  | ඉල්ලීම ආරම්භ කළ API යතුර                                   |
| `provider`         | string  | සැපයුම්කරුගේ ID (openai, anthropic, ආදිය)                  |
| `model`            | string  | මොඩලයේ ID (gpt-5, claude-opus-4-6, ආදිය)                   |
| `comboId`          | string? | සංයෝජනයක් හරහා යොමු කළේ නම් සංයෝජන ID                      |
| `promptTokens`     | number  | උඩුගං ප්රතිචාරයෙන්                                         |
| `completionTokens` | number  | උඩුගං ප්රතිචාරයෙන්                                         |
| `cachedTokens`     | number  | හැඹිලි ගැළපුම් ටෝකන (Anthropic ප්රේරක හැඹිලිකරණය, ආදිය)    |
| `totalTokens`      | number  | ප්රේරක + සම්පූර්ණ කිරීම                                    |
| `costUsd`          | number  | මිලකරණ දත්තවලින් ගණනය කරන ලදී                              |
| `latencyMs`        | number  | ආරම්භයේ සිට අවසානය දක්වා ඉල්ලීමේ කාලසීමාව                  |
| `status`           | enum    | `success`, `error`, `rate_limited`, `timeout`, `cancelled` |
| `errorClass`       | string? | status != success නම් දෝෂ පන්තිය                           |
| `timestamp`        | string  | ISO 8601 UTC                                               |
| `metadata`         | object  | අභිරුචි ප්ලගිනයක් මඟින් ඇතුළත් කළ දත්ත                     |

### ටෝකන පැමිණෙන්නේ කොතැනින්ද

**ප්රතිචාර හසුරුවනය** තුළදී උඩුගං සැපයුම්කරුගේ ප්රතිචාරයෙන් ටෝකන උපුටා ගනු ලැබේ:

```ts
// open-sse/handlers/chatCore.ts වෙතින්
const response = await providerExecutor.execute(provider, request);
const usage = response.usage || {
  prompt_tokens: 0,
  completion_tokens: 0,
  cached_tokens: 0,
};
```

භාවිත දත්ත ආපසු ලබා නොදෙන සැපයුම්කරුවන් සඳහා (සමහර web-cookie සැපයුම්කරුවන්), OmniRoute විසින් `~4 chars per token` අනුමාන ක්රමයක් භාවිත කර ටෝකන **ඇස්තමේන්තු** කරයි (`open-sse/services/autoCombo/pipelineRouter.ts` බලන්න).

### හැඹිලිගත ටෝකන

OmniRoute විසින් `cached_tokens`, `prompt_tokens` වෙතින් වෙන්ව නිරීක්ෂණය කරන්නේ:

- Anthropic ප්රේරක හැඹිලිකරණය හැඹිලිගත ටෝකන සඳහා අඩු කළ අනුපාතයක් අය කරන බැවිනි (සාමාන්ය අනුපාතයෙන් 10%)
- සමහර සැපයුම්කරුවන් වෙනස් ලෙස මිල කළ යුතු `cache_read_input_tokens` ආපසු ලබා දෙන බැවිනි
- විශ්ලේෂණ මඟින් **හැඹිලි ගැළපුම් අනුපාතය** = `cached_tokens / prompt_tokens` පෙන්විය හැකි බැවිනි

## පිරිවැය ගණනය කිරීම

පිරිවැය ගණනය කරනු ලබන්නේ LiteLLM වෙතින් සමමුහුර්ත කරන ලද **මිල දත්ත** (`src/lib/pricingSync.ts`) භාවිතයෙනි:

| මාදිලිය           | ආදානය $/1M | ප්රතිදානය $/1M | හැඹිලිගත $/1M |
| ----------------- | ---------- | -------------- | ------------- |
| gpt-5             | $2.50      | $10.00         | —             |
| claude-opus-4-6   | $15.00     | $75.00         | $1.50         |
| claude-sonnet-4-5 | $3.00      | $15.00         | $0.30         |
| gemini-2.5-pro    | $1.25      | $10.00         | —             |

පිරිවැය සූත්රය (`src/lib/usage/costCalculator.ts`):

```ts
cost =
  (prompt_tokens - cached_tokens) * input_price +
  cached_tokens * cached_price +
  completion_tokens * output_price;
```

> **හැඹිලිගත කොටස ප්රේරකයෙන් අඩු කරන්නේ ඇයි?** හැඹිලිගත කොටස සඳහා වෙනම මිල නියම කර ඇත; සම්පූර්ණ ප්රේරකයට ආදාන මිල අය කිරීමෙන් පිරිවැය අධික ලෙස ගණනය වේ.

### මිල සමමුහුර්තකරණය

## කෝටා බලාත්මක කිරීම

එක් එක් API යතුර සඳහා කෝටාව ස්ථාන දෙකකදී බලාත්මක කෙරේ:

1. **මෘදු සීමාව** (`quotaWarnAt`): භාවිතය සීමාව ඉක්මවන විට උපකරණ පුවරුවේ අනතුරු ඇඟවීමක් පෙන්වයි
2. **දෘඪ සීමාව** (`quotaLimit`): සීමාව ඉක්මවන විට ඉල්ලීම HTTP 429 සමඟ ප්රතික්ෂේප කෙරේ

### වින්යාසය

```ts
// එක් API යතුරක් සඳහා
await updateApiKey(keyId, {
  quotaWarnAt: 5_00,    // $5.00 — අනතුරු ඇඟවීම පෙන්වන්න
  quotaLimit: 10_00,    // $10.00 — දෘඪ නැවැත්වීම
  quotaWindow: "month", // "day" | "week" | "month" | "all"
});
````

### බලාත්මක කිරීමේ ප්රවාහය

```
ඉල්ලීම ──▶ quotaCheck()
              │
              ├── සීමාව තුළද?  ──▶ ඉඩ දෙන්න
              │
              └── සීමාව ඉක්මවාද?  ──▶ 429 ඉල්ලීම් අධිකයි
                                   Retry-After ශීර්ෂකය සමඟ
```

### කෝටා සැණරූ

ප්රවණතා විශ්ලේෂණය සඳහා `quotaSnapshots` වගුවේ **ඓතිහාසික කෝටා තත්ත්වය** ගබඩා කෙරේ:

| ක්ෂේත්රය | විස්තරය |
| ----------- | -------------------------------- | ------ | ------- |
| `apiKeyId` | නිරීක්ෂණය කෙරෙන යතුර |
| `window` | "day" | "week" | "month" |
| `used` | මෙම කාල කවුළුව තුළ භාවිත කළ පිරිවැය (ශත) |
| `limit` | සීමාව (ශත) |
| `resetAt` | කාල කවුළුව යළි සකසන වේලාව |
| `createdAt` | සැණරුව ලබාගත් වේලාව |

පිරිවැය > 0 වන **සෑම ඉල්ලීමකදීම** සැණරූ ලබාගන්නා අතර, ඒවා පහත කාර්යයන් සඳහා භාවිත කෙරේ:

- උපකරණ පුවරුවේ කෝටා ප්රගති තීරුව පෙන්වීම
- දින 30ක කෝටා ප්රවණතා ප්රස්තාර පෙන්වීම
- භාවිතය සීමාවට ළඟා වන විට ඇඟවීම් ක්රියාත්මක කිරීම

- **`/api/usage/analytics`** — සමුච්චිත භාවිත ප්රමිතික (ආකෘතිය, සැපයුම්කරු, යතුර අනුව සමූහගත කරන්න)
- **`/api/usage/quota`** — එක් එක් API යතුරේ වත්මන් කෝටා තත්ත්වය
- **`/api/usage/history`** — ඉල්ලීම් ඉතිහාස ලොග

## රඳවා තබා ගැනීම සහ පිරිසිදු කිරීම

එක් ඉල්ලීමකට භාවිත දත්ත ~1-10KB කින් වර්ධනය වේ. මහා පරිමාණයේදී, මෙය සැලකිය යුතු විය හැක.

### රඳවා තබා ගැනීමේ සැකසුම්

භාවිත ඉතිහාසය රඳවා තබා ගැනීම UI හි Database Settings හරහා හෝ `/api/settings/database` හරහා වින්යාස කරයි.

පෙරනිමියෙන්, භාවිත ඉතිහාසය **දින 90ක්** රඳවා තබා ගැනේ.

### පිරිසිදු කිරීම

පැරණි වාර්තා `src/lib/db/cleanup.ts` මඟින් පිරිසිදු කරනු ලැබේ:

- පසුබිම් cron ක්රියාවලිය මඟින් ක්රියාත්මක කෙරේ
- වින්යාස කර ඇති `usageHistory` රඳවා තබා ගැනීමේ සැකසුමට වඩා පැරණි `usage_history` වාර්තා මකා දමයි

### ගබඩා ඇස්තමේන්තුව

| ඉල්ලීම් අනුපාතය       | දින 30ක ගබඩාව | දින 90ක ගබඩාව |
| --------------------- | ------------- | ------------- |
| දිනකට ඉල්ලීම් 100     | ~3MB          | ~9MB          |
| දිනකට ඉල්ලීම් 1,000   | ~30MB         | ~90MB         |
| දිනකට ඉල්ලීම් 10,000  | ~300MB        | ~900MB        |
| දිනකට ඉල්ලීම් 100,000 | ~3GB          | ~9GB          |

ඉතා ඉහළ තදබදයක් සඳහා, පහත දෑ සලකා බලන්න:

- Database Settings හරහා රඳවා තබා ගැනීමේ කාලසීමාව අඩු කිරීම
- අමු වාර්තා වෙනුවට `aggregated_metrics` භාවිත කිරීම (විශ්ලේෂණ සඳහා පමණි)

## පිරිවැය ප්රශස්තකරණ ඉඟි

### 1. නිවැරදි ආකෘතිය භාවිත කරන්න

```bash
# ඉක්මන් පිළිතුර — ලාභදායී + වේගවත් විකල්පය භාවිත කරන්න
curl -d '{"model":"auto/fast","messages":[...]}'

# සංකීර්ණ කාර්යය — ගුණාත්මක විකල්පය භාවිත කරන්න
curl -d '{"model":"auto/smart","messages":[...]}'
```

### 2. හැඹිලිගත කිරීම සක්රීය කරන්න

Anthropic prompt හැඹිලිගත කිරීම මඟින් **නැවත නැවත භාවිත වන සන්දර්භ සඳහා 90%ක් ඉතිරි කරයි**:

```ts
// හැඹිලිගත කිරීම ස්වයංක්රීයයි — එකම විශාල system prompt එක ඇතුළත් කරන්න
const response = await openai.chat({
  model: "claude-sonnet-4-5",
  system: longSystemPrompt, // ස්වයංක්රීයව හැඹිලිගත කෙරේ
  messages: [{ role: "user", content: "..." }],
});
```

### 3. සම්පීඩනය භාවිත කරන්න

RTK + Caveman සම්පීඩනය මඟින් **මෙවලම් බහුල සැසිවලදී 15-95%ක් ඉතිරි කරයි**:

```ts
const config = {
  compression: {
    engine: "rtk",
    intensity: "aggressive",
  },
};
```

### 4. එක් එක් යතුර සඳහා කෝටා සකසන්න

පාලනයකින් තොර පිරිවැය වැළැක්වීමට සැමවිටම `quotaLimit` සකසන්න:

```ts
await updateApiKey(keyId, { quotaLimit: 10_00 }); // මසකට $10 සීමාව
```

### 5. වැඩිම පරිභෝජකයන් විගණනය කරන්න

API යතුර අනුව කාණ්ඩගත කර පිරිවැය අනුව අනුපිළිවෙළට සැකසීමට dashboard එක හෝ **`/api/usage/analytics`** භාවිත කරන්න:

```bash
GET /api/usage/analytics?groupBy=apiKey
```

## ගැටලු නිරාකරණය

### "පිරිවැය අපේක්ෂිත ප්රමාණයට වඩා වැඩියි"

1. **`/api/usage/analytics?groupBy=model`** පරීක්ෂා කරන්න — මිල අධික ආකෘතිය සොයා ගන්න
2. **`/api/usage/analytics?groupBy=apiKey`** පරීක්ෂා කරන්න — වැඩිම පරිභෝජකයා සොයා ගන්න
3. මිල දත්ත යාවත්කාලීන බව තහවුරු කරන්න: `POST /api/pricing/sync`

### "වාර්තා අස්ථානගතයි"

- Dashboard → Database → Cleanup යටතේ ඇති DB රඳවා තබා ගැනීමේ සැකසුම් පරීක්ෂා කරන්න — ආවර්තිත පිරිසිදු කිරීමේ කාර්යය මඟින් පැරණි වාර්තා මකා දමනු ලැබේ (`src/lib/db/cleanup.ts`)
- `src/lib/db/usage*.ts` හි දෝෂ පරීක්ෂා කරන්න — DB ලිවීමේ අසාර්ථක වීම් ලොග් කරන නමුත් මතුපිටට පෙන්වන්නේ නැත
- ඉල්ලීම සැබවින්ම `chatCore` වෙත ළඟා වූ බව තහවුරු කරන්න — combo මාර්ගගත කිරීම පරීක්ෂා කරන්න

### "කෝටාව බලාත්මක නොවේ"

- යතුරේ `quotaLimit` සැකසුම පරීක්ෂා කරන්න

- `quotaSnapshots` වාර්තා සොයන්න — ඒවා සෑම ඉල්ලීමකදීම නිර්මාණය විය යුතුය
