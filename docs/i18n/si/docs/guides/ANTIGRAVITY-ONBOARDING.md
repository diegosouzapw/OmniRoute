## 1. Antigravity සහ Antigravity CLI (agy) අතර වෙනස

සපයන්නන් දෙදෙනාම **එකම Google පසුබිම් පද්ධතිය** භාවිත කරයි — සමාන OAuth සේවාලාභියා, ටෝකන නැවුම් කිරීම, අන්ත ලක්ෂ්ය සහ Google ගිණුම්. වෙනස වන්නේ ඔබට පෙනෙන මාදිලි මොනවාද යන්නයි.

> Google හි නිල සංසන්දනය සඳහා [Antigravity CLI නිවේදනය](https://antigravity.google/blog/introducing-google-antigravity-cli) බලන්න.

**මාදිලි නාමාවලිය වෙනස් වන්නේ ඇයි**: Google හි CLI එක “වේගය සහ අඩු අමතර පිරිවැය සඳහා ප්රශස්ත කර” ඇති අතර, “Gemini මාදිලි සමඟ සම-ප්රශස්ත කර” ඇත (Google හි නිල බ්ලොග් සටහන අනුව). Web/IDE නිෂ්පාදනය “විස්තීර්ණත්වය සඳහා ප්රශස්ත කර” ඇත. CLI එක මාදිලි ගතිකව සොයාගැනීමට `:fetchAvailableModels` භාවිත කරන අතර, IDE එක ස්ථිතිකව තෝරා සැකසූ ලැයිස්තුවක් භාවිත කරයි.

**ප්රායෝගික භාවිතයේදී**: Gemini මාදිලි සඳහා `agy/` උපසර්ගය භාවිත කරන්න (උදා. `agy/gemini-3.7-flash-high`). ස්ථිතිකව තෝරා සැකසූ ලැයිස්තුව සඳහා `antigravity/` භාවිත කරන්න. දෙකම එකම Google පසුබිම් පද්ධතිය වෙත පිවිසෙන නමුත්, වෙනස් මාදිලි නම් පෙන්වයි. කෝටාව බෙදාගනු ලැබේ — ඕනෑම සපයන්නෙකු භාවිත කිරීම එකම Google ගිණුමේ සීමාවන්ට එරෙහිව ගණනය වේ.

## 3. projectId එකක් ලබාගන්නා ආකාරය

සෑම antigravity/agy සම්බන්ධතාවකටම Google Cloud Code `projectId` එකක් අවශ්ය වේ. එය නොමැතිව, `/v1internal:models` endpoint එක 404 ලබා දෙයි.

### ක්රමය A: ස්වයංක්රීය (නිර්දේශිතයි)

OmniRoute මෙය ස්වයංක්රීයව හසුරුවයි. Dashboard OAuth හරහා ඔබ නව Google ගිණුමක් එක් කරන විට:

1. OmniRoute token එක නැවුම් කරයි
2. projectId එක සොයාගැනීමට `loadCodeAssist` අමතයි
3. project එකක් නොපවතී නම්, එකක් සෑදීමට `onboardUser` අමතයි
4. අලුතින් සාදන ලද projectId එක ලබාගැනීමට `loadCodeAssist` නැවත උත්සාහ කරයි
5. එය database එකට සුරකියි

**මෙය බොහෝ ගිණුම් සඳහා ක්රියා කරයි** — අතින් සිදු කළ යුතු පියවර නොමැත.

## 4. OAuth යළි-යොමු URI

### ගැටලුව

Google OAuth සඳහා වලංගු යළි-යොමු URI එකක් අවශ්ය වේ. OmniRoute හි පෙරනිමි සැකසුම `http://127.0.0.1:20128/callback` (loopback) භාවිත කරයි. මෙය දේශීය builds සඳහා ක්රියා කරන නමුත් **දුරස්ථ deployments සඳහා අසාර්ථක වේ** (උදා., LAN IP එකක් හරහා ප්රවේශ වන server එකක්).

Google විසින් පහත ආකාරයේ යළි-යොමු URI ප්රතික්ෂේප කරයි:

- IP ලිපින භාවිත කරන ඒවා (`.com`, `.org` ආදියෙන් අවසන් වන domain එකක් විය යුතුය)
- OAuth client config තුළ ලියාපදිංචි කර ඇති යළි-යොමු URI සමඟ නොගැළපෙන ඒවා

### විසඳුම

**විකල්පය A: අන්තර්ගත OAuth ප්රවාහය භාවිත කරන්න (පෙරනිමි)**

- ඔබ `localhost` හෝ `127.0.0.1` වෙතින් OmniRoute වෙත ප්රවේශ වන විට ක්රියා කරයි
- වින්යාස කිරීමක් අවශ්ය නොවේ

**විකල්පය B: අභිරුචි OAuth අක්තපත්ර**

- ඔබගේ environment එක තුළ `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` සකසන්න
- ඔබගේම Google OAuth අක්තපත්ර සපයන්න:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console තුළ `https://your-domain.com/callback` බලයලත් යළි-යොමු URI එකක් ලෙස ලියාපදිංචි කරන්න

**විකල්පය C: ආරම්භක පිවිසුම සඳහා agy CLI භාවිත කරන්න**

- OmniRoute වෙත ප්රවේශ වන යන්ත්රය මත `agy login` ධාවනය කරන්න
- OAuth ප්රවාහය දේශීයව සම්පූර්ණ වන අතර tokens ගබඩා වේ
- Dashboard හරහා connection එක OmniRoute වෙත import කරන්න

### සීමාවන්

- අභිරුචි OAuth අක්තපත්ර සඳහා domain නාමයක් අවශ්ය වේ (Google විසින් යළි-යොමු URI ලෙස IP ලිපින පිළිගන්නේ නැත)
- ඔබට domain එකක් නොමැති නම්, ඒ වෙනුවට විකල්පය A හෝ C භාවිත කරන්න

## 5. දෝෂ නිරාකරණය: ස්වයංක්රීය සැකසුම අසාර්ථක වූ විට

බොහෝ accounts සඳහා OmniRoute විසින් projectId සොයාගැනීම සහ onboarding ස්වයංක්රීයව හසුරුවයි. එය අසාර්ථක වූ විට, මූලික හේතුව සාමාන්යයෙන් පහත සඳහන් එකකි:

### Account එකෙහි කලාපය අවහිර කර ඇත

**රෝග ලක්ෂණය**: `agy login` මඟින් "සුදුසුකම් පරීක්ෂාව අසාර්ථක විය: Antigravity දැනට ඔබගේ ස්ථානයේ ලබාගත නොහැකි බැවින්, ඔබගේ වත්මන් account එක ඒ සඳහා සුදුසු නොවේ." යන්න ලබා දෙයි.

**මූලික හේතුව**: Google accounts සතුව ලියාපදිංචි වන අවස්ථාවේ සකසන ලද backend "Country Association" field එකක් ඇත. ඔබගේ වත්මන් IP එක පමණක් පරීක්ෂා කරන web Gemini මෙන් නොව, agy CLI සහ Cloud Code API මෙම field එක දැඩි ලෙස පරීක්ෂා කරයි.

> ඔබගේ account එක හා සම්බන්ධ කලාපය පරීක්ෂා කිරීමට හෝ වෙනස් කිරීමට, [Google Country Association Form](https://policies.google.com/country-association-form) වෙත පිවිසෙන්න.

**web Gemini ක්රියා කළත් agy ක්රියා නොකරන්නේ ඇයි**:

- Web Gemini / Google One: වත්මන් IP එක පමණක් පරීක්ෂා කරයි (proxy හරහා සමත් වේ)
- agy CLI / Cloud Code API: backend Country Association field එක කියවයි (proxy එකෙන් ප්රයෝජනයක් නොවේ)

**විසඳුම**:

1. US IP එකක් භාවිත කරමින් [Google Country Association Form](https://policies.google.com/country-association-form) වෙත පිවිසෙන්න
2. කලාපය වෙනස් කිරීමේ ඉල්ලීමක් ඉදිරිපත් කරන්න ("I live in a different country" තෝරන්න)
3. Google විසින් ඉල්ලීම සකසා email දැනුම්දීම එවන තෙක් පැය 1-24ක් රැඳී සිටින්න
4. ඉන්පසු `agy login` සාර්ථක විය යුතුය

### Account එකට Cloud Code project එකක් නොමැත

**රෝග ලක්ෂණය**: Logs තුළ `loadCodeAssist returned no project id` සහ `onboardUser failed (400)` පෙන්වයි.

**මූලික හේතුව**: Account එක කිසිදා Google Cloud Code සමඟ ලියාපදිංචි කර නොමැති අතර, ස්වයංක්රීය onboarding ක්රියාවලිය අසාර්ථක වී ඇත.

**විසඳුම**: Cloud Code ලියාපදිංචිය ආරම්භ කිරීමට `agy login` අතින් ධාවනය කර, ඉන්පසු OmniRoute Dashboard තුළ token එක refresh කරන්න.

### Token එක කල් ඉකුත් වී හෝ අවලංගු කර ඇත

**රෝග ලක්ෂණය**: Logs තුළ 401 දෝෂ, හෝ "Token has expired" පණිවිඩ පෙන්වයි.

**විසඳුම**: Dashboard → Providers → agy → refresh icon එක click කිරීම මඟින් token එක refresh කරන්න. Refresh token එකම අවලංගු කර ඇත්නම්, OAuth හරහා නැවත සත්යාපනය කිරීමට අවශ්ය වේ.
