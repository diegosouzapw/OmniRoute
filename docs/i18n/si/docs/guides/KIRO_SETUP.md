## පසුබිම: Kiro ගිණුම් අතර ගැටුම් ඇති විය හැක්කේ ඇයි

Kiro හි පසුබිම් පද්ධතිය සක්රිය සැසි නිරීක්ෂණය කිරීමට AWS SSO OIDC සේවාලාභී ලියාපදිංචි කිරීම් භාවිත කරයි.
තීරණාත්මක සීමාව වන්නේ: **සෑම OIDC සේවාලාභී ලියාපදිංචියක්ම වරකට සහාය දක්වන්නේ එක් සක්රිය
සැසියකට පමණි**. දෙවන උපාංගයක් හෝ පරිශීලකයෙකු එම ලියාපදිංචි කළ සේවාලාභියාම භාවිතයෙන්
සත්යාපනය කරන විට, පසුබිම් පද්ධතිය පළමු ගිණුමේ refresh token එක අවලංගු කරයි.

වෙනත් Kiro ගිණුමක් දැනටමත් පුරනය වී ඇති පරිගණකයක `kiro-cli login` ධාවනය කරන විට
ගැටලු ඇති කරන යාන්ත්රණයද මෙයම වේ — නව පුරනය වීම පළමු
ගිණුමේ token එක අවලංගු කරයි.

## OmniRoute මෙය විසඳන ආකාරය (v3.8.0+)

## v3.8.0 ට පෙර නිර්මාණය කළ සම්බන්ධතා සඳහා සංක්රමණ සටහන

වෙන් වූ OIDC සේවාලාභී ලියාපදිංචියක් නොමැත. මෙම සම්බන්ධතා දිගටම ක්රියා කරන නමුත් හවුල්

## Kiro ගිණුම් දෙකක් එකිනෙකට සමගාමීව එක් කිරීම

### පූර්ව අවශ්යතා

- OmniRoute v3.8.0 හෝ ඊට පසු අනුවාදයක්.
- ක්රියාකාරී Kiro ගිණුමක් (විද්යුත් තැපෑල + මුරපදය, Google, හෝ GitHub පුරනය වීම).
- අවශ්ය නම් දෙවන Kiro ගිණුමක්.

### පියවර 1: පළමු ගිණුම ආයාත කරන්න

1. **උපකරණ පුවරුව → සපයන්නන් → සපයන්නෙකු එක් කරන්න → Kiro** විවෘත කරන්න.
2. පහත සඳහන් එකක් තෝරන්න:
   - **Token ආයාත කිරීම** — `aorAAAAAG` සමඟ ආරම්භ වන refresh token එකක් අලවන්න.
   - **API Key** — දිගුකාලීන Kiro / CodeWhisperer API key එකක් අලවන්න.
   - **Google / GitHub පුරනය වීම** — බ්රවුසරය තුළ OAuth ප්රවාහය සම්පූර්ණ කරන්න.
   - **ස්වයංක්රීය ආයාතය** — බොත්තම ක්ලික් කරන්න; OmniRoute විසින්
     දේශීය kiro-cli දත්ත සමුදායෙන් හෝ `~/.aws/sso/cache` වෙතින් අක්තපත්ර කියවයි.
3. සම්බන්ධතාව සුරැකේ. Refresh-token ප්රවාහ ස්වයංක්රීයව වෙන් වූ
   OIDC සේවාලාභියෙකු ලියාපදිංචි කරයි. API-key ප්රවාහ AWS සමඟ යතුර වලංගු කරන අතර refresh token එකක් ගබඩා නොකරයි.

### පියවර 2: දෙවන ගිණුම ආයාත කරන්න

දෙවන ගිණුම සඳහා පියවර 1 නැවත සිදු කරන්න. සෑම ආයාතයක්ම වෙනම OIDC
සේවාලාභී ලියාපදිංචියක් නිර්මාණය කරන බැවින්, සම්බන්ධතා දෙක සම්පූර්ණයෙන්ම හුදකලා වේ.

### පියවර 3: සම්බන්ධතා දෙකම සක්රිය බව තහවුරු කරන්න

1. **උපකරණ පුවරුව → සපයන්නන්** — Kiro සම්බන්ධතා දෙකම **සක්රිය** තත්ත්වය පෙන්විය යුතුය.
2. **උපකරණ පුවරුව → සෞඛ්යය** — සම්බන්ධතා දෙකම ඒවායේ token සෞඛ්ය පරීක්ෂාව සමත් විය යුතුය.

### පියවර 4: ගිණුම් අතර මාර්ගගත කිරීමට combo එකක් භාවිත කරන්න

ඒවා අතර භාරය සමතුලිත කිරීමට හෝ එකක් අසාර්ථක වුවහොත් අනෙකට මාරු වීමට සම්බන්ධතා දෙකම ඉලක්ක ලෙස යොදා combo එකක් සාදන්න:

```
kiro/kiro-dev → kiro/kiro-pro
```

combo වින්යාසය සඳහා [FEATURES.md](./FEATURES.md) සහ මාර්ගගත කිරීමේ ලේඛන බලන්න.

## ව්යවසාය / IDC පරිශීලකයින්

AWS IAM Identity Center (IDC) ගිණුම් සඳහා, **Dashboard → Providers → Kiro → Device Code** වෙතින් **AWS Builder ID / IDC උපාංග-කේත**
ප්රවාහය භාවිත කරන්න. උපාංග-කේත ප්රවාහය සැමවිටම සම්පූර්ණයෙන් හුදකලා කර ඇත.
මෙම සම්බන්ධතා සඳහා නැවත ආයාත කිරීමක් අවශ්ය නොවේ.

පෙරනිමි නොවන AWS කලාපයක ක්රියාත්මක වන ව්යවසාය පරිශීලකයින්ට Import Token API හරහා
ආයාත කිරීමේදී කලාපය සඳහන් කළ හැක:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

`region` ක්ෂේත්රය සඳහන් නොකළ විට එය පෙරනිමියෙන් `us-east-1` වේ.

## API යතුරු ආයාත ප්රවාහය

API යතුරු සත්යාපනය දිගුකාලීන Kiro / AWS CodeWhisperer bearer අක්තපත්ර සඳහා වේ. එය
OAuth නැවුම් කිරීම භාවිත නොකරන බැවින්, හවුල් OIDC සැසි අවලංගු වීම වළක්වයි.

### උපකරණ පුවරුව

1. **Dashboard -> Providers -> Kiro** විවෘත කරන්න.
2. **API Key** තෝරන්න.
3. API යතුර සහ විකල්ප AWS කලාපය අලවන්න (පෙරනිමියෙන් `us-east-1`).
4. OmniRoute යතුර වලංගු කර සම්බන්ධතාව සුරකියි.

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### අභ්යන්තර ගිවිසුම

API මාර්ගය, `KiroService.validateApiKey()` ඇමතීමෙන් යතුර වලංගු කරයි. එය
කලාපයට ගැළපෙන CodeWhisperer/Amazon Q අන්ත ලක්ෂ්යයට එරෙහිව `ListAvailableProfiles` භාවිත කර
`profileArn` එකක් නිරාකරණය කරයි.

සුරකින ලද සම්බන්ධතාව භාවිත කරන්නේ:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

ධාවන වේලාවේදී, `KiroExecutor.buildHeaders()` යතුර
`Authorization: Bearer <key>` ලෙස යවා `tokentype: API_KEY` එක් කරයි. කෝටා/පැතිකඩ ඇමතුම්
ද එම සලකුණම භාවිත කරන බැවින්, AWS විසින් bearer අගය OIDC හෝ සමාජ ප්රවේශ ටෝකනයක් ලෙස නොව
දිගුකාලීන API යතුරක් ලෙස සලකයි.

## OIDC සේවාදායක කල් ඉකුත් වීම

AWS SSO OIDC පොදු සේවාදායක සාමාන්යයෙන් දින 90කට පසු කල් ඉකුත් වේ
(`clientSecretExpiresAt`). නිරීක්ෂණ හැකියාව සඳහා OmniRoute මෙම කාල මුද්රාව `providerSpecificData`
තුළ ගබඩා කරයි. සම්බන්ධතාවක් දින ~90කට පසු නැවුම් වීම නවත්වන්නේ නම්, නව OIDC සේවාදායක
ලියාපදිංචියක් ලබා ගැනීමට සම්බන්ධතාව නැවත ආයාත කරන්න. කල් ඉකුත් වූ විට ස්වයංක්රීයව නැවත ලියාපදිංචි කිරීම
අනාගත වැඩිදියුණු කිරීමක් ලෙස නිරීක්ෂණය කෙරේ.

API යතුරු සම්බන්ධතා AWS SSO OIDC හරහා නැවුම් නොකරන බැවින් ඒවාට OIDC සේවාදායක
කල් ඉකුත් වීමක් නොමැත.

  null නොවන `clientId` එකක් පෙන්වන බව තහවුරු කරන්න. කිසියම් සම්බන්ධතාවක `clientId` නොමැති නම්,
  එය v3.8.0ට පෙර ආයාත කර ඇත — එය නැවත ආයාත කරන්න.

### "Token validation failed" සමඟ ආයාත කිරීම අසාර්ථක වේ

- නැවුම් කිරීමේ ටෝකනය `aorAAAAAG` සමඟ ආරම්භ වන බව තහවුරු කරන්න.
- OmniRoute හට `https://oidc.us-east-1.amazonaws.com` (හෝ වින්යාස කළ
  කලාපය) වෙත ප්රවේශ විය හැකි බව තහවුරු කරන්න. ඔබ ආයතනික ප්රොක්සියක් පිටුපස සිටී නම්,
  **Dashboard → Settings → Proxies** තුළ සපයන්නා-මට්ටමේ ප්රොක්සියක් සකසන්න.

### API යතුරු ආයාත කිරීම අසාර්ථක වේ

- AWS කලාපය යතුරට/ගිණුමට ගැළපෙන බව තහවුරු කරන්න. `us-east-1` පෙරනිමිය වේ.
