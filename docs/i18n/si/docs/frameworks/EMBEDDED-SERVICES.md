
තත්ත්වයන් `version_manager` DB වගුවේ (`status` තීරුව) ගබඩා කර ඇති අතර,
`ServiceSupervisor` හි මතකය-තුළ තත්ත්වයෙහි ද පිළිබිඹු කෙරේ. ක්රියාත්මක වන
ක්රියාවලියක් සඳහා මතකය-තුළ තත්ත්වය බලධාරී මූලාශ්රය වේ; ආරම්භයේදී DB තත්ත්වය
ස්ථිර විකල්ප මූලාශ්රය වේ.

### මෙහෙයුම් අගුල

`ServiceSupervisor`, async මෙහෙයුම් අගුලක් (`withLock()`) හරහා ජීවන චක්ර
මෙහෙයුම් අනුක්රමික කරයි. එකම supervisor එක මත සමගාමී `start()` ඇමතුම් සිදු කළ
විට හරියටම එක් ක්රියාවලි නිර්මාණයක් පමණක් සිදු වේ; දෙවන කැඳවුම්කරු රැඳී සිට
පවතින තත්ත්වය ආපසු ලබා දෙයි. උදාහරණයක් ලෙස, ස්වයංක්රීය ආරම්භය සහ UI බොත්තමක්
එකවර ක්රියාත්මක වන විට ඇති විය හැකි ධාවන තත්ත්ව ගැටුම් මෙය වළක්වයි.

## 4. API යොමුව

`/api/services/` යටතේ ඇති සියලු මාර්ග **LOCAL_ONLY** වේ (loopback සඳහා පමණි, දැඩි රීතිය #17).
සත්යාපන ටෝකනය නොසලකා, loopback නොවන ඉල්ලීම්වලට `403 LOCAL_ONLY` ලැබේ.

### 4.1 9Router අන්ත ලක්ෂ්ය (මාර්ග 11)

#### `POST /api/services/9router/install`

npm වෙතින් 9Router ස්ථාපනය කරයි. එයටම අයත් `package.json` සහ
`node_modules/` සමඟ `DATA_DIR/services/9router/` නිර්මාණය කරයි. OmniRoute හිම පරායත්තතා සමඟ ගැටීමක් ඇති නොකරයි.

**ඉල්ලීම් බඳ** (සියල්ල විකල්පීයයි):

```json
{ "version": "latest" }
```

| ක්ෂේත්රය  | වර්ගය    | පෙරනිමිය   | විස්තරය                                   |
| --------- | -------- | ---------- | ----------------------------------------- |
| `version` | `string` | `"latest"` | ස්ථාපනය කළ යුතු npm අනුවාද ටැගය හෝ semver |

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය                                                          |
| ------- | ---------------------------------------------------------------- |
| `200`   | `{ ok: true, installedVersion: "x.y.z", path: "..." }`           |
| `400`   | වලංගු නොවන ඉල්ලීම් බඳ (Zod වලංගුකරණ අසමත් වීම)                   |
| `409`   | දැනටමත් ස්ථාපනය වෙමින් පවතී (අගුල රඳවා ඇත)                       |
| `500`   | npm ස්ථාපනය අසාර්ථකයි — හිතකාමී දෝෂ පණිවිඩය සඳහා `message` බලන්න |

**සටහන්:** `execFile('npm', [...])` භාවිත කරයි — shell එකක් හෝ අන්තර්නිවේෂණයක් නැත (දැඩි රීතිය #13).
EACCES දෝෂ හිතකාමී පණිවිඩ ලෙස ඉදිරිපත් කෙරේ.

---

#### `POST /api/services/9router/start`

9Router ආරම්භ කරයි. දැනටමත් ලියාපදිංචි කර නොමැති නම් supervisor එකක් ලියාපදිංචි කර,
ඉන්පසු `supervisor.start()` අමතයි. දැනටමත් ක්රියාත්මක වන විට මෙය idempotent වේ.

**ඉල්ලීම් බඳ:** නැත

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය                                                    |
| ------- | ---------------------------------------------------------- |
| `200`   | `ServiceStatus` වස්තුව (පහත schema එක බලන්න)               |
| `409`   | 9Router ස්ථාපනය කර නැත (`status: "not_installed"`)         |
| `503`   | ආරම්භ කිරීම අසාර්ථකයි (ක්රියාවලි දෝෂය — `lastError` බලන්න) |

**ServiceStatus schema එක:**

```json
{
  "tool": "9router",
  "state": "running",
  "pid": 12345,
  "port": 20130,
  "health": "healthy",
  "startedAt": "2026-05-25T10:00:00.000Z",
  "lastError": null
}
```

#### `POST /api/services/9router/stop`

9Router ක්රමානුකූලව නවත්වයි. SIGTERM යවා තත්පර 15ක් රැඳී සිට, තවමත් සජීවී නම් SIGKILL යවයි.
දැනටමත් නවතා ඇති විට මෙය idempotent වේ.

**ඉල්ලීම් බඳ:** නැත

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය                             |
| ------- | ----------------------------------- |
| `200`   | `ServiceStatus` (state: "stopped")  |
| `503`   | අනපේක්ෂිත ලෙස නැවැත්වීම අසාර්ථක විය |

---

#### `POST /api/services/9router/restart`

මෙහෙයුම් අගුල යටතේ `stop()` කිරීමෙන් පසු `start()` කිරීමට සමාන වේ.

**ඉල්ලීම් බඳ:** නැත

**ප්රතිචාර:** `start` හා සමානයි (අවසාන `ServiceStatus` ආපසු ලබා දෙයි).

#### `POST /api/services/9router/update`

9Router නව npm අනුවාදයකට යාවත්කාලීන කරයි. සේවාව ක්රියාත්මක වෙමින් පවතී නම්, එය පළමුව
නවත්වනු ලැබේ, npm ස්ථාපනය ක්රියාත්මක කරයි (නව අනුවාදය එම ස්ථානයේම ස්ථාපනය කරමින්), ඉන්පසු
සේවාව නැවත ආරම්භ කරයි.

**ඉල්ලීම් බඳ** (සියල්ල විකල්පීයයි):

```json
{ "version": "latest" }
```

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය                                                         |
| ------- | --------------------------------------------------------------- |
| `200`   | `{ ok: true, previousVersion: "...", installedVersion: "..." }` |
| `400`   | වලංගු නොවන බඳ                                                   |
| `500`   | npm යාවත්කාලීන කිරීම අසාර්ථකයි                                  |

#### `POST /api/services/9router/rotate-key`

9Router සඳහා නව API යතුරක් ජනනය කර, එය නිශ්චල තත්ත්වයේදී සංකේතනය කර, සේවාව
ක්රියාත්මක නම් නැවත ආරම්භ කරයි; එවිට එය තම පරිසරයෙන් නව යතුර ලබා ගනී. පැරණි යතුර
වහාම අවලංගු කෙරේ.

**ඉල්ලීම් බඳ:** නැත

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය                                    |
| ------- | ------------------------------------------ |
| `200`   | `{ keyRotated: true, restarted: boolean }` |
| `500`   | යතුර මාරු කිරීම අසාර්ථකයි                  |

**ආරක්ෂාව:** නව යතුර කිසිවිටෙක ප්රතිචාරයේ ආපසු ලබා නොදේ (අක්තපත්ර කාන්දුවක් නැත).
එය `version_manager` වගුවේ සංකේතනය කර (AES-256-GCM) ගබඩා කරයි.

#### `POST /api/services/9router/auto-start`

ස්වයංක්රීය ආරම්භක සලකුණ මාරු කරයි. `enabled: true` වූ විට, ඊළඟ වතාවේ OmniRoute ආරම්භ වන විට
(සේවාව ස්ථාපනය කර ඇත්නම්) සේවාව ස්වයංක්රීයව ආරම්භ වේ.

**ඉල්ලීම් බඳ:**

```json
{ "enabled": true }
```

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය               |
| ------- | --------------------- |
| `200`   | `{ autoStart: true }` |
| `400`   | වලංගු නොවන බඳ         |

#### `GET /api/services/9router/logs`

9Router හි stdout/stderr වළලු බෆරයෙන් සජීවී ලොග්වල SSE ප්රවාහය.

**විමසුම් පරාමිති:**

| පරාමිතිය | වර්ගය     | පෙරනිමිය | විස්තරය                                                                |
| -------- | --------- | -------- | ---------------------------------------------------------------------- |
| `tail`   | `integer` | 200      | පළමුව යැවිය යුතු ඓතිහාසික පේළි ගණන (උපරිම 1000)                        |
| `filter` | `string`  | නැත      | අක්ෂර ප්රමාණයට සංවේදී නොවන උපතන්තු පෙරහන (regex නැත — ReDoS-ආරක්ෂිතයි) |

**SSE සිදුවීම්:**

| සිදුවීම     | දත්ත        | විස්තරය                                |
| ----------- | ----------- | -------------------------------------- |
| `snapshot`  | `LogLine[]` | ආරම්භක ඓතිහාසික tail එක                |
| `log`       | `LogLine`   | සජීවී ලොග් පේළිය                       |
| `heartbeat` | `{}`        | සෑම තත්පර 15කටම සම්බන්ධතාව සජීවීව තබයි |

**LogLine schema එක:**

```json
{
  "ts": 1716633600000,
  "stream": "stdout",
  "line": "[9router] Listening on :20130"
}
```

**ප්රතිචාර:**

| තත්ත්වය | විස්තරය                                       |
| ------- | --------------------------------------------- |

සත්යාපන header එකක් අවශ්ය නොවේ.

**යුගල කිරීම:** open-wa නිල නොවන අතර WhatsApp සමඟ අනුබද්ධ නොවේ — සම්බන්ධිත
අංකයට WhatsApp හිම ස්වයංක්රීයකරණ හඳුනාගැනීම හේතුවෙන් තහනම් වීමේ අවදානමක් ඇත.
පළමු ආරම්භයේදී, යුගල කිරීමේ QR කේතය stdout වෙත මුද්රණය කර පවතින
ලොග් පැනලය/SSE ප්රවාහය හරහා පෙන්වයි — මෙම ඒකාබද්ධ කිරීම තුළ තවම කැපවූ
QR-රූප endpoint එකක් නොමැත.

### 4.7 ප්රතිවිරුද්ධ ප්රොක්සිය (9Router dashboard කාවැද්දීම)

dashboard එක අභ්යන්තර ප්රතිවිරුද්ධ ප්රොක්සියක් හරහා iframe එකක් තුළ 9Router වෙබ් UI එක
කාවද්දයි:

```
GET|POST|... /dashboard/providers/services/9router/embed/[...path]
```

මෙම ප්රොක්සිය:

- ඉල්ලීම `http://127.0.0.1:{port}/{path}` වෙත යොමු කරයි (loopback පමණි)
- පැමිණෙන `cookie` සහ `authorization` headers ඉවත් කරයි (OmniRoute සැසිය කාන්දු නොවේ)
- 9Router සත්යාපනය සඳහා `Authorization: Bearer {apiKey}` ඇතුළත් කරයි
- ප්රතිචාරයෙන් `set-cookie`, `content-security-policy`, `x-frame-options`, `cross-origin-*` ඉවත් කරයි
- `<base href>` ඇතුළත් කිරීමට සහ නිරපේක්ෂ මාර්ග සාමාන්යකරණය කිරීමට (`/foo` → `/dashboard/.../embed/foo`) HTML ප්රතිචාර නැවත ලියයි

කාවැද්දූ dashboard එක සඳහා WebSocket upgrades, කැපවූ port එකක ඇති සහායක server එකක් මඟින්
හසුරුවනු ලැබේ (`src/lib/services/embedWsProxy.ts` බලන්න).

**ආරක්ෂාව:** කාවැද්දුම් ප්රොක්සි මාර්ග `LOCAL_ONLY_API_PREFIXES` යටතේ
වර්ගීකරණය කර ඇති අතර loopback වෙතින් පමණක් ප්රවේශ විය හැක. Cloudflare/Ngrok
tunnel එකක් හරහා JWT එකක් ලබාගන්නා ප්රහාරකයෙකුට කාවැද්දූ සේවාවලට ප්රොක්සි කළ නොහැක.

## 5. ආරක්ෂාව

### LOCAL_ONLY බලාත්මක කිරීම (දැඩි රීතිය #17)

`/api/services/` සහ `/dashboard/providers/services/*/embed/` යටතේ ඇති සියලුම routes,
`src/server/authz/routeGuard.ts` තුළ LOCAL_ONLY ලෙස වර්ගීකරණය කර ඇත. ඕනෑම auth
ශාඛාවකට පෙර loopback පරීක්ෂාව කොන්දේසි විරහිතව ක්රියාත්මක වේ:

```
ඉල්ලීම පැමිණේ
  → isLocalOnlyPath(path)?
      → loopback නොවේ → 403 LOCAL_ONLY (සෑම විටම, auth පරීක්ෂාවට පෙර)
      → loopback වේ   → සාමාන්ය auth වෙත ඉදිරියට යයි
```

මෙමගින් කාන්දු වූ JWT එකකට (උදා., tunnel එකක් හරහා) `npm install` හෝ
process spawning ක්රියාත්මක කිරීම වළක්වයි. සම්පූර්ණ tier matrix එක සඳහා
`docs/security/ROUTE_GUARD_TIERS.md` බලන්න.

### API key ඇතුළත් කිරීම

9Router සහ Mux හිම HTTP endpoints සඳහා API key/bearer token එකක් අවශ්ය වේ.
OmniRoute:

1. සේවාවට විශේෂිත prefix එකක් (`nr_` 9Router සඳහා, `mx_` Mux සඳහා) සමඟ
   `crypto.randomBytes(32).toString("base64url")` හරහා key එකක් ජනනය කරයි.
2. AES-256-GCM භාවිතයෙන් එය at-rest ආකාරයෙන් සංකේතනය කරයි (provider credentials
   සඳහා භාවිත කරන cipher එකම වේ).
3. spawn කරන අවස්ථාවේ එය විකේතනය කර environment variable එකක් ලෙස ඇතුළත් කරයි —
   9Router සඳහා `NINEROUTER_API_KEY`, Mux සඳහා `MUX_SERVER_AUTH_TOKEN` (කිසිවිටෙක CLI
   flag එකක් ලෙස නොවේ; එම නිසා token එක `ps`/process ලැයිස්තුගත කිරීම්වල කිසිවිටෙක
   නොපෙනේ).
4. කිසිදු HTTP response එකක plaintext key එක කිසිවිටෙක ආපසු ලබා නොදෙයි.

CLIProxyAPI වෙත spawn කරන විට ඇතුළත් කරන වෙන් කළ data-plane key එකක් ලැබේ
(`needsApiKey: true` — adapter එකට එරෙහි model sync කිරීම සඳහා භාවිත වේ).

### SSRF ආරක්ෂණය

Reverse HTTP proxy එක (`/dashboard/.../embed/[...path]`) ඉල්ලීම් ඉදිරියට යැවීමට
`http://127.0.0.1:{port}` පමණක් භාවිත වන ලෙස hardcode කර ඇත. එය loopback නොවන
ගමනාන්ත වෙත යන redirects කිසිවිටෙක අනුගමනය නොකරයි. Loopback පරාසයෙන් පිටතට resolve
වන ඕනෑම upstream URL එකක් ප්රතික්ෂේප කිරීමට `ssrf-req-filter` library එක භාවිත කරයි.

### Shell ආරක්ෂාව (දැඩි රීතිය #13)

`npm install` කැඳවනු ලබන්නේ `execFile('npm', ['install', pkg, '--prefix', dir])` හරහාය —
template literals, shell එකක්, හෝ command string එක තුළට බාහිර paths interpolate කිරීමක්
නොමැත. Runtime අගයන් (ports, API keys) child process එකේ `env` object එක හරහා යවනු ලැබේ.

### Error පිරිසිදු කිරීම (දැඩි රීතිය #12)

`/api/services/*` වෙතින් ලැබෙන සියලුම error responses, `buildErrorBody()` හෝ
`sanitizeErrorMessage()` හරහා යයි. අමු `err.stack` සහ `err.message` කිසිවිටෙක
caller වෙත ඒ ආකාරයෙන්ම ආපසු ලබා නොදෙයි.

## 6. නව embedded service එකක් එක් කිරීම

මෙම පියවර 8 අනුගමනය කරන්න. ප්රමිතිය ලෙස අනුගමනය කළ යුතු canonical reference එක
වශයෙන් `src/lib/services/installers/` සහ `src/app/api/services/` තුළ ඇති දැනට පවතින
implementations කියවන්න.

### පියවර 1 — Installer එක සාදන්න

`ninerouter.ts` ආදර්ශයට ගනිමින් `src/lib/services/installers/{name}.ts` සාදන්න:

```typescript
export const NAME_PACKAGE = "your-npm-package";
export const NAME_DEFAULT_PORT = 20132; // භාවිතයේ නොමැති port එකක් තෝරන්න

export async function install(version = "latest"): Promise<InstallResult> { ... }
export async function update(version = "latest"): Promise<InstallResult> { ... }
export async function uninstall(): Promise<void> { ... }
export function resolveSpawnArgs(apiKey: string, port: number): SpawnArgs { ... }
export async function getInstalledVersion(): Promise<string | null> { ... }
export async function getLatestVersion(): Promise<string | null> { ... }
```

`installers/utils.ts` වෙතින් `runNpm(['install', NAME_PACKAGE, '--prefix', dir])`
භාවිත කරන්න — `execSync` හෝ shell interpolation කිසිවිටෙක භාවිත නොකරන්න.

### පියවර 2 — Bootstrap තුළ ලියාපදිංචි කරන්න

`src/lib/services/bootstrap.ts` හි `SERVICES` array එකට `ServiceEntry` එකක් එක් කරන්න:

```typescript
{
  tool: "myservice",
  port: NAME_DEFAULT_PORT,
  healthPath: "/health",
  healthIntervalMs: 5_000,
  stopTimeoutMs: 15_000,
  logsBufferBytes: 5_242_880,
  needsApiKey: true, // API key එකක් අවශ්ය නොවේ නම් false
}
```

`cfg.tool === "myservice"` හසුරුවන ලෙස `buildSpawnArgsFactory()` පුළුල් කරන්න.

#### සම්බන්ධ කළ හැකි provider-plugin contract එක (Phase 1, #7333)

`src/lib/services/providerPlugins/` මඟින් backend එකක `bootstrap.ts` හි `ServiceEntry`
fields සහ `serviceBackends.ts` හි manifest-template fields, එකිනෙකට සම්බන්ධ නොවන files
දෙකක එකම backend එකේ ව්යුහය වෙන වෙනම ප්රකාශ කිරීම වෙනුවට, තනි object එකකට අසුරන
`ServiceProviderPlugin` contract එකක් හඳුන්වා දෙයි. මෙය ලියන අවස්ථාව වන විට
**`9router` පමණක් migrate කර ඇත** — `bootstrap.ts`, එහි `SERVICES[]` entry එක
`getServiceProviderPlugin("9router")` (`src/lib/services/providerPlugins/registry.ts`)
වෙතින් ලබා ගන්නා අතර plugin එක නොමැති වුවහොත් startup error එකක් throw කරයි.
`cliproxy`, `mux`, සහ `bifrost` වෙනස් කිරීමකින් තොරව පෙර පැවති inline `SERVICES[]`
literals මතම පවතී.

`open-sse/config/providerPluginManifest.ts` වෙත
`SERVICE_BACKEND_MANIFEST_TEMPLATE` entry එකකින් නිසි ලෙස සැකසූ
`ProviderPluginManifestEntry` එකක් ගොඩනඟන additive
`createServiceBackendManifestEntry(pluginId, template)` helper එකක්ද එක් කර ඇත —

**විසඳුම:**

## 8. නිතර අසන ප්රශ්න

**ප්ර: කාවැද්දූ සේවාවල අන්ත ලක්ෂ්ය loopback නොවන සේවාලාභීන්ට නිරාවරණය කළ හැකිද?**

නැත. LOCAL_ONLY මට්ටම හිතාමතාම පනවා ඇත (දැඩි රීතිය #17). `npm install` ක්රියාත්මක කළ හැකි හෝ `node` ක්රියාවලි ආරම්භ කළ හැකි මාර්ග loopback නොවන ගමනාගමනයෙන් ප්රවේශ විය නොහැකි විය යුතුය. එසේ නොවුවහොත්, උමඟක් (Cloudflare, Ngrok, Tailscale) හරහා JWT එකක් කාන්දු වීමෙන් අත්තනෝමතික ක්රියාවලි ආරම්භ කිරීමට ඉඩ ලැබේ. `/api/services/` සඳහා මෙයින් බැහැර වීමේ විකල්පයක් නොමැත — `/api/mcp/` මෙන් නොව, එය manage-scope මඟහැරීමේ ලැයිස්තුවෙන් බැහැර කර ඇත. `docs/security/ROUTE_GUARD_TIERS.md` බලන්න.

`"degraded"` යන්නෙන් අදහස් කරන්නේ සෞඛ්ය පරීක්ෂණයෙන් 200 නොවන ප්රතිචාරයක් ලැබුණු බවයි. `"unknown"` යන්නෙන් අදහස් කරන්නේ තවමත් කිසිදු පරීක්ෂණයක් සම්පූර්ණ වී නොමැති බවයි (පළමු poll කිරීම සමඟ ඇති race තත්ත්වයක්). ආරම්භයේදී මේ දෙකම තාවකාලික වේ. `"running"` වූ පසු `healthIntervalMs * 3` ms කට වඩා සෞඛ්ය තත්ත්වය `"degraded"` ලෙස පවතී නම්, කාවැද්දූ සේවාව ක්රියාත්මක වන නමුත් එහි HTTP API එක ප්රතිචාර නොදක්වයි. තත්ත්ව ප්රතිචාරයේ port එක නිවැරදිද සහ සේවාව සැබවින්ම එම port එකේ සවන්දෙමින් සිටීද යන්න පරීක්ෂා කරන්න.
