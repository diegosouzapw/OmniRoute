### එක් ඡේදයකින් ගෘහනිර්මාණය

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) යනු හවුල් මතකස්ථ මුදු බෆරයකි (පෙරනිමියෙන් ඇතුළත් කිරීම් 1000ක්, `INSPECTOR_BUFFER_SIZE` හරහා වින්යාස කළ හැකිය). සියලුම ග්රහණ මූලාශ්ර `push()` හරහා එයට ලියයි. බෆරය `kindDetector.ts` භාවිතයෙන් සෑම ඇතුළත් කිරීමක්ම වර්ගීකරණය කරයි (එය LLM ඉල්ලීමක්ද යන්න තීරණය කරයි), `contextKey` එකක් (පද්ධති prompt එකේ SHA-256 ඇඟිලි සලකුණක්) ගණනය කරයි, සහ `globalTrafficBuffer.subscribe()` හරහා සියලු WebSocket ග්රාහකයන් වෙත විකාශනය කරයි. Dashboard එක `GET /api/tools/traffic-inspector/ws` හරහා සම්බන්ධ වන අතර, සම්බන්ධ වීමේදී snapshot එකක්ද, ඉන්පසු `new`/`update`/`clear` සිදුවීම්ද ලබා ගනී.

## §2 ග්රහණ ක්රම

Traffic Inspector මඟින් **එකවර ග්රහණ මූලාශ්ර 5කට** සහාය දක්වයි. එක් එක් මූලාශ්රය ස්වාධීනව සක්රිය හෝ අක්රිය කළ හැක. සෑම `InterceptedRequest` එකකම (`src/mitm/inspector/types.ts`) ඇති `source` ක්ෂේත්රය `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, හෝ `"tproxy"` යන අගයන්ගෙන් එකකි.

### ක්රමය 1 — AgentBridge (පෙරනිමි, සැමවිටම සක්රියයි)

**මූලාශ්රය:** AgentBridge හසුරුවන්නන් (`src/mitm/handlers/base.ts`)
**යාන්ත්රණය:** `MitmHandlerBase` තුළ ඇති සෑම `intercept()` ඇමතුමක්ම ඉදිරියට යැවීමට පෙර `hookBufferStart()` ද, සම්පූර්ණ වූ විට `hookBufferUpdate()` ද අමතයි. අමතර වින්යාස කිරීමක් අවශ්ය නොවේ — AgentBridge ක්රියාත්මක වූ වහාම මෙය ක්රියා කරයි.
**ආවරණය:** AgentBridge තුළ වින්යාස කර ඇති IDE නියෝජිතයන් 9
**සටහන:** `InterceptedRequest` තුළ `source` ක්ෂේත්රය = `"agent-bridge"`

### ක්රමය 2 — අභිරුචි ධාරක (DNS යළි-යොමු කිරීම)

**මූලාශ්රය:** පරිශීලකයා අර්ථ දක්වන ධාරක ලැයිස්තුව (`inspector_custom_hosts` වගුව)
**යාන්ත්රණය:** UI හරහා ධාරකයක් එක් කිරීමෙන් `/etc/hosts` වෙත `127.0.0.1 <host>` එක් කෙරේ (sudo අවශ්යයි). පවතින AgentBridge MITM සේවාදායකය (port 443) නව ධාරකය සඳහා SNI සහතිකයක් ගතිකව ජනනය කරයි.
**ආවරණය:** එක් කළ ධාරකය භාවිත කරන ඕනෑම යෙදුමක් — යෙදුම් වින්යාසය වෙනස් කිරීම අවශ්ය නොවේ
**සටහන:** `source` = `"custom-host"`

භාවිත අවස්ථා සඳහා උදාහරණ:

- Python ස්ක්රිප්ට් වෙතින් `api.openai.com` අධීක්ෂණය කිරීම
- `my-internal-llm.company.com` දෝෂහරණය කිරීම
- එකම ජාලයේ ඇති ජංගම උපාංගවල ගමනාගමනය ග්රහණය කිරීම (ARP spoofing හරහා — උසස්)

### ක්රමය 3 — HTTP_PROXY සවන්දෙන්නා (port 8080)

**මූලාශ්රය:** `HTTP_PROXY`/`HTTPS_PROXY` පරිසර විචල්ය භාවිත කරන යෙදුම්
**යාන්ත්රණය:** සම්මත පැහැදිලි HTTP/HTTPS ප්රොක්සියක් ලෙස ක්රියා කරන port 8080 හි ද්විතීයික සවන්දෙන්නෙක් (`src/mitm/inspector/httpProxyServer.ts`). `CONNECT` උමං (HTTPS) සහ සෘජු HTTP ඉල්ලීම් පිළිගනී.
**ආවරණය:** `HTTP_PROXY` පරිසර විචල්යයට ගරු කරන ඕනෑම යෙදුමක් — DNS වෙනසක් හෝ sudo අවශ්ය නොවේ
**සටහන:** `source` = `"http-proxy"`

```bash
# තනි විධානයක් සඳහා ඉක්මන් ග්රහණයක්:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# shell සැසියක අඛණ්ඩ ග්රහණයක්:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS සීමාව:** HTTPS `CONNECT` උමං පෙරනිමියෙන් ග්රහණය කරන්නේ පාරදත්ත ලෙස පමණි (ධාරකය, port, කාල තොරතුරු) — TLS අන්තර්ගතය විකේතනය නොකෙරේ. සම්පූර්ණ අන්තර්ගත පරීක්ෂාව සඳහා "ප්රොක්සි ක්රමයේදී HTTPS විකේතනය කරන්න" ටොගලය සක්රිය කරන්න (ස්ව කැමැත්තෙන් සක්රිය කළ යුතු අතර AgentBridge සහතිකය විශ්වාස කළ යුතුය).

**Port ගැටුම:** port 8080 භාවිතයේ පවතී නම්, AgentBridge ව්යුහගත දෝෂයක් සමඟ 409 ප්රතිචාරයක් ලබා දෙයි. `INSPECTOR_HTTP_PROXY_PORT` පරිසර විචල්යය හරහා port එක වෙනස් කරන්න.

### ක්රමය 4 — පද්ධතිය පුරා ප්රොක්සිය (උසස්, ස්ව කැමැත්තෙන් සක්රිය කළ යුතුයි)

**මූලාශ්රය:** OS මට්ටමේ ප්රොක්සි සැකසුම් (යන්ත්රයේ ඇති සියලුම යෙදුම්වලට අදාළ වේ)
**යාන්ත්රණය:** සියලුම HTTP/HTTPS ගමනාගමනය HTTP_PROXY සවන්දෙන්නා හරහා යළි-යොමු කිරීමට OS API භාවිත කරයි:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **ආවරණය:** පද්ධති ප්රොක්සි සැකසුම්වලට ගරු කරන යන්ත්රයේ ඇති සෑම යෙදුමක්ම
  **සටහන:** `source` = `"system-proxy"`

**ආරක්ෂණ යාන්ත්රණ:**

- ස්වයංක්රීය අක්රිය කිරීමේ කාලගණකය (පෙරනිමියෙන් මිනිත්තු 30කි, `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` හරහා වින්යාස කළ හැක)
- පෙර පැවති පද්ධති ප්රොක්සි තත්ත්වය DB තුළ සුරැකෙන අතර ප්රතිවර්තනය කිරීමේදී යළි පිහිටුවේ
- එය සක්රියව තිබියදී පරිශීලකයා ඉවතට සංචාලනය කළහොත් උපකරණ පුවරුව "පද්ධති ප්රොක්සිය ප්රතිවර්තනය කරමින්" විමසුම පෙන්වයි
- UI මඟින් `⚠ උසස්` ලාංඡනයක් සහ පැහැදිලි තහවුරු කිරීමේ පිරික්සුම් කොටුවක් පෙන්වයි

### ක්රමය 5 — TPROXY පාරදෘශ්ය විකේතනය (Linux, root, ස්ව කැමැත්තෙන් සක්රිය කළ යුතුයි)

**මූලාශ්රය:** Kernel TPROXY + ප්රතිපත්ති මාර්ගගත කිරීම (`src/mitm/tproxy/`)
**යාන්ත්රණය:** `mangle OUTPUT` තුළ ඉලක්ක port එකකට (පෙරනිමියෙන් `443`) යන නව දේශීය පිටතට යොමු වූ TCP සම්බන්ධතාවලට ලකුණු යොදයි, `ip rule` එකක් ලකුණු කළ පැකට් දේශීය බෙදාහැරීම වෙත යළි මාර්ගගත කරයි, සහ `mangle PREROUTING` හි `TPROXY` ඉලක්කය ඒවා පාරදෘශ්ය (**IP_TRANSPARENT**) සවන්දෙන්නෙකුට (පෙරනිමි port එක `8443`) භාර දෙයි. සවන්දෙන්නා ගතික CA එකක් මඟින් **ඉල්ලුම මත එක් එක් SNI ධාරක නාමය සඳහා** නිකුත් කරන ලද අග්ර සහතිකයක් භාවිතයෙන් TLS අවසන් කර, විකේතනය කළ හුවමාරුව ග්රහණය කර, ඉල්ලීම යළි සංකේතනය කර මුල් ගමනාන්තය වෙත ඉදිරියට යවයි.
**ආවරණය:** ඉලක්ක port එකේ ඇති **අත්තනෝමතික** ගමනාන්ත ධාරක — `/etc/hosts` ව්යාජකරණයක්, `HTTP_PROXY` පරිසර විචල්යයක් හෝ පද්ධතිය පුරා ප්රොක්සි වෙනස් කිරීමක් අවශ්ය නොවේ. අන්තර්ඛණ්ඩනය කරන ලද ක්රියාවලියට වින්යාස වෙනසක් අවශ්ය නොවන නමුත් එය ගතික CA එක විශ්වාස කළ යුතුය.
**සටහන:** `source` = `"tproxy"`

**අවශ්යතා:** Linux පමණි (**IP_TRANSPARENT** ලබා ගත හැක්කේ Linux හි පමණි), **CAP_NET_ADMIN** හැකියාව (root), සහ C මෙවලම් දාමයක් භාවිතයෙන් ගොඩනැගිය යුතු ස්වදේශීය N-API ඇඩෝනයක් (`npm run build:native:tproxy`). එය ලබා ගත නොහැකි විට, "TPROXY විකේතනයට Linux + root + ස්වදේශීය ඇඩෝනය අවශ්ය වේ" යන මෙවලම් ඉඟිය සමඟ උපකරණ පුවරුවේ ටොගලය අක්රිය වේ. ෆයර්වෝල් නීති ගනුදෙනුමය ආකාරයෙන් යෙදීම/ප්රතිවර්තනය කිරීම සිදු වේ (බිඳවැටීමකින් කිසිවිටෙකත් `mangle` නීතියක් ඉතිරි නොවේ) සහ නැවත ආරම්භ කිරීමේදී ඒවා ඉවත් වේ. SO_MARK මත පදනම් වූ ප්රති-ලූපයක්, ප්රොක්සිය විසින්ම යළි සංකේතනය කර ඉදිරියට යවන ගමනාගමනය නැවත අන්තර්ඛණ්ඩනය වීම වළක්වයි.

මෙය තමන්ගේම වෙන්වූ ක්රියාකරු මාර්ගෝපදේශයක් සහිත සැලකිය යුතු උපපද්ධතියකි — සම්පූර්ණ ෆයර්වෝල් ක්රියාපටිපාටිය, එක් එක් SNI සඳහා ගතික CA + විශ්වාස-ගබඩා ස්ථාපකය, දේශීය-පමණක් මාර්ගය, ප්රති-ලූප විස්තර සහ වින්යාස යෝජනාක්රමය සඳහා `docs/security/MITM-TPROXY-DECRYPT.md` බලන්න (git තුළ ඇත; `/docs` වෙත සම්පාදනය කර නැත). ටොගලය `GET / POST / DELETE /api/tools/agent-bridge/tproxy` මඟින් පාලනය වේ (සටහන: මාර්ගය පිහිටා ඇත්තේ Traffic Inspector උපසර්ගය යටතේ නොව AgentBridge උපසර්ගය යටතේය).

### 4.1 වර්ග හඳුනාගැනීම (`src/mitm/inspector/kindDetector.ts`)

සංඥා 4ක් භාවිතයෙන් සෑම ඉල්ලීමක්ම `"llm"`, `"app"`, හෝ `"unknown"` ලෙස වර්ගීකරණය කරයි:

1. **සත්කාරක රෙජිස්ට්රිය** — දන්නා LLM API සත්කාරක නාම ~18ක් (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot, ආදිය)
2. **මාර්ග රටා** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses`, ආදිය
3. **අන්තර්ගතයේ හැඩය** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` ක්ෂේත්ර හඳුනාගනී
4. **පරිශීලක-නියෝජිත ඉඟි** — UA පෙළෙහි `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 හරහා එක් කළ අභිරුචි සත්කාරක, පෝරම ආදානයෙන් ඔවුන්ගේ `kind` උරුම කරගනී (පෙරනිමිය `"custom"` වේ).

### 4.2 SSE ඒකාබද්ධකය (`src/mitm/inspector/sseMerger.ts`)

**ස්වාධීන clean-room ක්රියාත්මක කිරීමකි.** සිදුවීම් විග්රහ කිරීම
[WHATWG සේවාදායකය-යවන සිදුවීම් ඇල්ගොරිතමය](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
අනුගමනය කරන අතර, ප්රතිනිර්මාණය පොදු [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), සහ
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
ප්රවාහ යෝජනාක්රම අනුගමනය කරයි.

අමු SSE delta සිදුවීම්වලින් අවසාන සහායක පණිවිඩය ප්රතිනිර්මාණය කරයි:

- **Anthropic**: දර්ශකය අනුව `content_block_delta` සමුච්චය කරයි; `text_delta`, `input_json_delta` (මෙවලම් ඇමතුම්), `thinking_delta` හසුරුවයි
- **OpenAI**: Chat Completions තේරීම්/මෙවලම් ඇමතුම් සහ Responses API ප්රතිදාන අයිතම දර්ශකය අනුව සමුච්චය කරයි
- **Gemini**: `candidates[i].content.parts` සමුච්චය කරයි
- **නොදන්නා**: අමු සිදුවීම් ඒ අයුරින්ම ආපසු ලබා දෙයි

Response පටිත්ත ටොගලයක් පෙන්වයි: **"අමු සිදුවීම් ↔ ඒකාබද්ධ කළ"**.

### 4.3 සංවාද සාමාන්යකාරකය (`src/mitm/inspector/conversationNormalizer.ts`)

**ස්වාධීන clean-room ක්රියාත්මක කිරීමකි.** සාමාන්යකරණය දේශීය black-box
ගිවිසුම් සහ පොදු OpenAI, Anthropic, හා Gemini පණිවිඩ යෝජනාක්රම මගින් නිර්වචනය වේ; කිසිදු upstream
ක්රියාත්මක කිරීමක මූලාශ්රයක් භාවිත නොකෙරේ.

දර්ශනය කිරීමට පෙර OpenAI, Anthropic, සහ Gemini පණිවිඩ ආකෘති තනි `NormalizedConversation` එකකට පරිවර්තනය කරයි:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // ඉල්ලීමේ අන්තර්ගතයෙන් ලැබෙන messages / contents / prompt
  response: NormalizedTurn[]; // සහායක ප්රතිචාරය (sseMerger හරහා ඒකාබද්ධ කර ඇත)
  contextKey: string | null; // SHA-256 පද්ධති-prompt ඇඟිලි සලකුණ
}
```

බ්ලොක් වර්ග: `text`, `tool_use`, `tool_result`. සැපයුම්කරු කවරෙකු වුවත් Conversation පටිත්ත මෙම හැඩය භාවිත කරයි.

### 4.4 සන්දර්භ යතුර වර්ණ ගැන්වීම (`src/mitm/inspector/contextKey.ts`)

- පද්ධති prompt එකේ `SHA-256` ගණනය කරයි (පළමු `role:system` පණිවිඩය, හෝ `system` ක්ෂේත්රය, හෝ Gemini `systemInstruction`)
- අක්ෂර 12ක hex උපසර්ගයක් ආපසු ලබා දෙයි (`"a3f9c2..."`)
- වම් මායිම් තීරුව සඳහා frontend එක යතුර නියත HSL වර්ණයකට සිතියම්ගත කරයි
- **"එකම සන්දර්භය" පෙරහන**: `ctx #a3f` චිපය ක්ලික් කිරීමෙන් එකම ඇඟිලි සලකුණ සහිත ඉල්ලීම් පමණක් පෙන්වන පෙරහනක් එක් කරයි

මෙය එකම නියෝජිත සැසිය තුළ ක්රියාත්මක වන විවිධ "පුද්ගල භූමිකා" හෝ කාර්යයන් දෘශ්යමය ලෙස පහසුවෙන් වෙන්කර හඳුනාගැනීමට සලස්වයි.

### 4.5 LLM පාරදත්ත උකහා ගැනීම

LLM ඉල්ලීම් සඳහා, LLM Details පටිත්ත පහත දෑ උකහා ගනී:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // ඉල්ලීම් අන්තර්ගතයෙන් හෝ ප්රතිචාරයෙන්
  messages: number; // වාර ගණන
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE ප්රතිචාරයක් නම් true
  mappedTo: string | null; // x-omniroute-mapped ශීර්ෂකය
  costEstimateUsd: number | null; // OmniRoute මිලකරණය මත පදනම් වූ ඇස්තමේන්තුගත පිරිවැය
}
```

### 4.6 සජීවී ක්රියාත්මක වෙමින් පවතින ඉල්ලීම් පෙරහන

ඉල්ලීමේ `status` ක්ෂේත්රය `number | "in-flight" | "error"` වේ — ඉල්ලීම ආරම්භ වන මොහොතේම ඇතුළත් කිරීමක්
`"in-flight"` ලෙස යොමු කරනු ලබන අතර, ප්රතිචාරය (හෝ දෝෂය) පැමිණි විට එය **එම ස්ථානයේම යාවත්කාලීන**
කෙරේ. මෙවලම් තීරුවේ **"සජීවී"** ටොගලය
(`liveOnly`, i18n යතුර `trafficInspector.liveOnly`) ලැයිස්තුව
`status === "in-flight"` වන ඇතුළත් කිරීම්වලට සීමා කරමින්, විවෘත සම්බන්ධතා තත්කාලීනව නිරීක්ෂණය කිරීමට ඔබට ඉඩ සලසයි.

පෙරහන යනු
`src/lib/inspector/matchesTrafficFilter.ts` හි ඇති පිරිසිදු, client-side predicate එකකි:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

ටොගලයේ තත්ත්වය `useTrafficFilters` (පරීක්ෂක dashboard hooks) තුළ පවතින අතර
අනෙකුත් පෙරහන් (පැතිකඩ, සත්කාරකය, නියෝජිතයා, මූලාශ්රය, තත්ත්වය, සන්දර්භය) සමඟ ඒකාබද්ධ වේ.

### 4.7 ක්රියාවලි ආරෝපණය (Linux)

Linux මත, බාධා කොට ගත් සෑම ඉල්ලීමක්ම එය **ආරම්භ කළ දේශීය
ක්රියාවලියට** ආරෝපණය කළ හැක. `InterceptedRequest` වෙත විකල්ප ක්ෂේත්ර දෙකක් එක් කෙරේ:

```ts
pid?: number;          // ආරම්භක ක්රියාවලි id එක (Linux පමණි)
processName?: string;  // ආරම්භක ක්රියාවලියේ නම (Linux පමණි)
```

`src/mitm/inspector/processAttribution.ts` පහත පරිදි සම්බන්ධතාවේ _client_
තාවකාලික port එක PID + නමකට සිතියම්ගත කරයි:

1. port එක සඳහා socket inode සොයාගැනීමට `/proc/net/tcp` සහ `/proc/net/tcp6` කියවීම
   (`parseProcNetTcpForInode`, පිරිසිදු fixture-testable parser එකකි).
2. `socket:[<inode>]` වෙත symlink එකක් සඳහා `/proc/<pid>/fd/` පරිලෝකනය කිරීම.
3. `/proc/<pid>/comm` වෙතින් ක්රියාවලියේ නම කියවීම.

තත්පර 1ක TTL cache එකක් භාරය යටතේ procfs පරිලෝකන පිරිවැය සීමා කරයි. ආරෝපණය
**හැකි උපරිම උත්සාහයෙන්** සිදු කෙරේ — ඕනෑම අසාර්ථකත්වයක් `null` ලෙස විසඳෙන අතර ග්රහණය කිසිවිටෙක අවහිර නොකරයි.
macOS/Windows මත ශ්රිතය `null` ආපසු ලබා දෙයි (stub; `lsof`/`GetExtendedTcpTable`
සහාය පසුකාලීන කාර්යයකි).

### 5.1 සැසියක් පටිගත කිරීම

- **CONNECT tunnel HTTPS**: TLS interception සබල කර නොමැති නම්, Mode 3 (HTTP_PROXY) විසින් HTTPS ගමනාන්ත සඳහා ග්රහණය කරන්නේ tunnel metadata පමණි. මෙය සැලසුම්ගත හැසිරීමකි — AgentBridge cert එක විශ්වාස නොකරන විට පාරදෘශ්ය ග්රහණය එම යෙදුම් සඳහා TLS සත්යාපනය බිඳ දමනු ඇත.
- **සමහර components තුළ hardcoded strings**: සමහර UI components (F7/F8) තුළ තවමත් i18n keys මගින් ආවරණය නොවන hardcoded strings සුළු සංඛ්යාවක් ඇත. මේවා i18n gap report එකේ දන්නා සීමාවක් ලෙස ලේඛනගත කර ඇත; පසුකාලීන pass එකකදී ඒවා සංක්රමණය කරනු ඇත. බලපෑමට ලක්වන strings යනු ක්රියාකාරී භාවිතය සඳහා පරිවර්තනය අවශ්ය නොවන UI අලංකරණ labels වේ.

1. සේවාදායකය තවමත් ක්රියාත්මකදැයි පරීක්ෂා කරන්න: `GET /api/tools/traffic-inspector/capture-modes`
2. පිටුව නැවත පූරණය කරන්න — WebSocket නැවත සම්බන්ධ වී නව snapshot එකක් ලබා ගනී
3. සේවාදායකය නැවත ආරම්භ කර තිබේ නම්, මතකයේ ඇති buffer එක හිස් කර ඇත — session එකක් පටිගත කර නොතිබුණේ නම් පැරණි ඇතුළත් කිරීම් නැති වී ඇත

### Port 8080 ගැටුම

HTTP_PROXY මාදිලිය ආරම්භ කිරීමට අසමත් වන්නේ නම්:

```bash
lsof -i :8080    # ක්රියාවලිය සොයන්න
```

port එක වෙනස් කරන්න:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### System proxy එක පෙර තත්ත්වයට පත් නොවීම

පද්ධතිය පුරා proxy මාදිලිය සක්රියව තිබියදී OmniRoute බිඳ වැටෙන්නේ නම්:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

proxy එක සක්රියව තිබූ බව DB තත්ත්වයෙන් අනාවරණය වුවහොත්, ඊළඟ වර පූරණය කිරීමේදී dashboard එක "System proxy එක පෙර තත්ත්වයට පත් කරන්න" යන විකල්පයද ලබා දෙනු ඇත.

### Buffer එක පිරී ඇත

buffer එක `INSPECTOR_BUFFER_SIZE` වෙත (පෙරනිමිය 1000) ළඟා වූ විට, නව ඇතුළත් කිරීම් පැරණිතම ඒවා ඉවත් කරමින් එක් වේ. වැදගත් ඉල්ලීම් නැති වෙමින් පවතී නම්:

- `INSPECTOR_BUFFER_SIZE` වැඩි කරන්න (උදා., 5000) — රඳවා තබා ගැනීම වෙනුවෙන් වැඩි මතකයක් භාවිත කරයි
- අදාළ කාල පරාසය DB වෙත ස්ථිරව සුරැකීමට session එකක් පටිගත කරන්න
