## §1 දළ විශ්ලේෂණය

### AgentBridge යනු කුමක්ද?

IDE නියෝජිතයෙකු (උදා., GitHub Copilot, Cursor, Claude Code) API ඇමතුමක් සිදු කරන විට, එය ඉහළ ප්රවාහයේ AI සැපයුම්කරුට (OpenAI, Anthropic, ආදිය) සෘජුවම සම්බන්ධ වේ. AgentBridge විසින් කිසිදු නියෝජිත වින්යාස වෙනසක් අවශ්ය නොකර, TLS මට්ටමේදී එම සම්බන්ධතාව පාරදෘශ්යව හසුකරගෙන ඉල්ලීම OmniRoute හරහා යළි ලියයි.

මෙයින් ඔබට කළ හැක්කේ:

## §2 ගෘහනිර්මාණය

### 2.1 සංරචක පිළිබඳ දළ විශ්ලේෂණය

```
IDE නියෝජිතයා (VS Code / Cursor / ආදිය)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS යළි-යොමු කිරීම
    │
    ▼
src/mitm/server.cjs  (port 443, CJS අනු ක්රියාවලිය)
    │  Host header SNI අනුව ඉලක්කය නිරාකරණය කරයි
    │  AgentBridge CA මඟින් අත්සන් කළ එක් එක් SNI සඳහා TLS සහතික ජනනය කරයි
    ├── මඟහැරීමේ ලැයිස්තුවට ගැළපේද? → TCP සෘජු හුවමාරුව (විකේතනය නොකරයි)
    ├── ඉලක්කයට ගැළපේද? → fetch → OmniRoute රවුටරය (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── ඉල්ලීම් body/headers මත maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector වෙත ප්රකාශයට පත් කරයි
    │               └── fetchRouter() → /v1/chat/completions
    └── ගැළපීමක් නැද්ද? → TCP සෘජු හුවමාරුව (විකේතනය නොකරයි)
```

### 2.2 MITM සේවාදායකය (`src/mitm/server.cjs`)

මූලික MITM සේවාදායකය Node.js CJS අනු ක්රියාවලියක් ලෙස ක්රියාත්මක වේ (පවතින CJS කේත පදනම නැවත ලිවීමෙන් වැළකීම සඳහා). එය:

- port 443 මත සවන් දෙයි (විශේෂ වරප්රසාද හෝ `authbind`/`setcap` අවශ්ය වේ)
- මෙහෙයුම් පද්ධතියෙන් CONNECT උමං ලබා ගනී (`/etc/hosts` DNS යළි-යොමු කිරීම හරහා)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) මඟින් අත්සන් කළ එක් එක් SNI සඳහා TLS සහතික ජනනය කරයි
- `targets/index.ts` රෙජිස්ට්රිය හරහා Host header අනුව ඉලක්ක නියෝජිතයා නිරාකරණය කරයි
- HTTP හරහා `http://127.0.0.1:20128` වෙත TypeScript හසුරුවන ස්තරයට යොමු කරයි

`TARGET_HOSTS`, ආරම්භයේදී `targets/index.ts` මඟින් ලියනු ලබන `DATA_DIR/mitm/targets.json` වෙතින් පූරණය කෙරෙන අතර, එමඟින් CJS සේවාදායකය නැවත ආරම්භ නොකර ගතික යාවත්කාලීන කිරීම් සිදු කළ හැක.

> #6684 හි එක් කළ ස්ථිර මූල-CA ආකෘතියයි (`src/mitm/cert/rootCa.ts` +

> නිහඬව සිදු නොවේ). CA සහතිකය, පැරණි leaf සහතිකය භාවිත කළ එම
> `omniroute-mitm.crt` විශ්වාස-ගබඩා ස්ථානයටම ස්ථාපනය වේ
> (`cert/install.ts::installCaCert`) — ද්විත්ව විශ්වාස පිරිසිදු කිරීමක් අවශ්ය නොවේ.

### 2.3 හසුරුවන මූල පන්තිය (`src/mitm/handlers/base.ts`)

සියලුම නියෝජිත හසුරුවන්නන් `MitmHandlerBase` විස්තාරණය කරයි:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // ආරක්ෂිත උපකාරක: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

එක් එක් හසුරුවන්නා ප්රොක්සි කිරීම පෙර `hookBufferStart()` ද, අවසන් වූ විට `hookBufferUpdate()` ද කැඳවයි. මේවා `InterceptedRequest` ඇතුළත් කිරීම් `globalTrafficBuffer` තුළට යොමු කරයි ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 බලන්න).

### 2.4 ඉලක්ක රෙජිස්ට්රිය (`src/mitm/targets/`)

එක් එක් නියෝජිතයාට ප්රකාශනාත්මක ඉලක්ක ගොනුවක් ඇත:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

රෙජිස්ට්රිය (`targets/index.ts`) `ALL_TARGETS` නිර්යාත කරන අතර ආරම්භයේදී `DATA_DIR/mitm/targets.json` නිකුත් කරයි.

### 2.5 සෘජු හුවමාරුව සහ මඟහැරීමේ ලැයිස්තුව (`src/mitm/passthrough.ts`)

**මඟහැරීමේ ලැයිස්තුව** (ඉලක්ක ගැළපීමට වඩා ප්රමුඛත්වය දී පළමුව පරීක්ෂා කරයි):

- පෙරනිමි රටා: බැංකු hosts, `.gov.`, OAuth/SSO සැපයුම්කරුවන් (Okta, Auth0), ආදිය.
- පරිශීලක රටා: `agent_bridge_bypass` DB වගුවේ ගබඩා කර ඇත
- මඟහැරූ hosts වෙත විනිවිද පෙනෙන TCP උමඟක් ලැබේ — TLS **කිසිවිටෙකත් විකේතනය නොකෙරේ**

**පෙරනිමි සෘජු හුවමාරුව** (ඉලක්ක ගැළපීමක් නොමැති සහ මඟහැරීමේ ලැයිස්තුවේ නොමැති විට):

- මෙයටද TCP උමඟක් ලැබේ — සම්බන්ධතා කිසිවිටෙකත් බිඳ නොදමයි
- AgentBridge මඟින් සාමාන්ය පද්ධති HTTPS ගමනාගමනයට බාධා කිරීම වළක්වයි

මාර්ගගත කිරීමේ ප්රමුඛතාව:

```
මඟහැරීමේ ලැයිස්තුව → ඉලක්ක ගැළපීම → සෘජු හුවමාරුව
```

### 2.6 ඉහළ ප්රවාහ CA සහතිකය (`src/mitm/upstreamTrust.ts`)

අභිරුචි CA එකක් සහිත ආයතනික ජාල පරිසර සඳහා:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

මෙය සකසා ඇති විට, අමතර CA සහතිකය සමඟ `undici` හි ගෝලීය dispatcher වින්යාස කරයි. එමඟින් AgentBridge හට ආයතනික TLS අවසන් කිරීමේ proxies හරහා ඉහළ ප්රවාහ සැපයුම්කරුවන් වෙත ළඟා විය හැක.

### 2.7 රහස් ආවරණය කිරීම (`src/mitm/maskSecrets.ts`)

ස්වාධීන clean-room ස්කෑනරය, ඉල්ලීම් bodies සහ අක්තපත්ර headers
Traffic Inspector buffer එකට හෝ ඕනෑම log එකකට ඇතුළු වීමට **පෙර** ඒවාට යොදනු ලැබේ. එය එක් රේඛීය පරිලෝකනයක් සිදු කරයි:

- `sk-` / `ak-` / `pk-` උපසර්ග සහිත tokens (OpenAI/Anthropic මාදිලිය)
- RFC 6750 `Authorization: Bearer <token>` අක්තපත්ර, සම්පූර්ණ token එකට ප්රමුඛත්වය සමඟ
- තිත් සහ padding කළ ආකාර ඇතුළුව සාමාන්ය දිගු අපැහැදිලි tokens (අක්ෂර ≥40)

`sanitizeHeaders()` රඳවාගත් නම් කුඩා අකුරුවලට පරිවර්තනය කරයි, array අගයන් නියත ආකාරයකින් එක් කරයි, proxy සත්යාපනය ඇතුළු හවුල් hop-by-hop/framing ප්රතික්ෂේප ලැයිස්තුව ඉවත් කරයි, `cookie` සහ `set-cookie` සම්පූර්ණයෙන්ම සඟවයි, සහ අක්තපත්ර අගයන් ස්කෑනරයට පවරයි.

#### Electron-පදනම් වූ IDE මෙහෙයුම් පද්ධතියේ විශ්වාස ගබඩාව නොසලකා හරියි (`NODE_EXTRA_CA_CERTS`)

සමහර IDE — විශේෂයෙන් **Antigravity IDE**, සහ අනෙකුත් Electron / VS Code-ව්යුත්පන්න යෙදුම් — පිටතට යන
`fetch`/HTTPS සඳහා **මෙහෙයුම් පද්ධතියේ විශ්වාස ගබඩාව පරිශීලනය නොකරන** තමන්ගේම Node.js ධාවන පරිසරයක්
ඇතුළත් කරයි. මෙහෙයුම් පද්ධති/NSS මට්ටමින් CA විශ්වාස කිරීම IDE හි ස්වදේශීය **පසුඅන්තය**
(උදා. මෙහෙයුම් පද්ධතියේ CA කට්ටලය භාවිත කරන Go භාෂා සේවාදායකයක්) සඳහා ප්රමාණවත් වුවද, **Electron ඉදිරිඅන්තය**
තුළ TLS තවමත් අසාර්ථක වනු ඇත — MITM ලොගය තුළ පසුඅන්තයේ bootstrap ඇමතුම් `200` ලබා දෙන බව පෙන්වුවත්,
එය යෙදුමෙන් _පිටවී ඇති_ ලෙස හෝ _"සම්බන්ධතා දෝෂයක්"_ ලෙස දිස් වේ. පියවර දෙකක්
අවශ්ය වන අතර, දෙකම වැදගත්ය:

1. ධාවන පරිසරය පැහැදිලිවම CA වෙත යොමු කරන්න:
   ```bash

   ```
2. **එම shell එකෙන් IDE දියත් කරන්න.** ඩෙස්ක්ටොප් අයිකනය / Dock / Start මෙනුවෙන් එය ආරම්භ කිරීමේදී
   shell exports උරුම නොවන අතර, `~/.config/environment.d/*.conf` අදාළ වන්නේ
   නව චිත්රක පිවිසීමකින් පසුව පමණි. පළමුව IDE සම්පූර්ණයෙන්ම වසා දමන්න — Electron හි singleton අගුල නිසා දෙවන
   දියත් කිරීමක් සිදු කළ විට පවතින ක්රියාවලියට අවධානය යොමු කිරීම පමණක් සිදු වන අතර නව පරිසරය නොසලකා හැරේ.

ඉහත මෙහෙයුම් පද්ධති විශ්වාසය + NSS පියවර තවමත් අවශ්ය වේ (සමහර සත්යාපන
ප්රවාහ භාවිත කරන Chromium ජාල තොගය එක්-පරිශීලක NSS ගබඩාව කියවන අතර, දේශීයව විශ්වාස කළ CA එකක් මඟින්
අභිබවා යන `*.googleapis.com` සඳහා වූ එහිම ස්ථිතික pins ද ඇත). ඊට අමතරව Node `fetch` මාර්ගය `NODE_EXTRA_CA_CERTS` මඟින් ආවරණය කරයි.

### 3.5 අවදානම් නිවේදනය

AgentBridge විසින් IDE එක ඉහළ ප්රවාහ සැපයුම්කරුවන් සමඟ සත්යාපනය වීමට භාවිත කරන අක්තපත්ර (OAuth ටෝකන, API යතුරු) ග්රහණය කරයි. මේවා **ලොග් කිරීමට පෙර ආවරණය කරනු ලැබේ** (§2.7 බලන්න), නමුත් OmniRoute හි MITM ස්තරයට දෘශ්යමාන වේ. එක් එක් නියෝජිතයා පළමු වරට සක්රිය කිරීමේදී ඉවත් කළ හැකි අවදානම් නිවේදන සංවාදයක් පෙන්වයි.

### 3.7 ගෙන යා හැකි වින්යාස ආයාතය/නිර්යාතය

යන්ත්ර හරහා සැකසුමක් ප්රතිනිර්මාණය කළ හැකි වන පරිදි AgentBridge හට **ක්රියාකරු විසින් සීරුමාරු කළ හැකි** තත්ත්වය අනුවාදගත JSON blob එකක් බවට අනුක්රමණය කළ හැක. අනුක්රමකය `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) වන අතර, එය `AgentBridgeConfigSchema` මගින් වලංගු කෙරේ.

නිර්යාතයට හරියටම කොටස් තුනක් ඇතුළත් වේ (අන්තර්ගත පෙරනිමි හිතාමතාම **නිර්යාත නොකෙරේ**, එබැවින් ආයාත කිරීමේදී ඒවා කිසිවිටෙකත් අනුපිටපත් කිරීමක් හෝ ඒවා සමඟ ගැටීමක් සිදු නොවේ):

| ක්ෂේත්රය         | මූලාශ්රය                                                            | සටහන්                                                                             |
| ---------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| `bypassPatterns` | පරිශීලක-නිර්වචිත මඟහැරීමේ රටා (`agent_bridge_bypass`)               | පෙරනිමි bank/gov/okta රටා බැහැර කෙරේ                                              |
| `customHosts`    | Traffic Inspector අභිරුචි සත්කාරක (`inspector_custom_hosts`)        | එක් එක් අයිතමය: `{ host, kind: "llm"\|"app"\|"custom", label? }`                  |
| `agentMappings`  | එක් එක් agent සඳහා ආකෘති සිතියම්ගත කිරීම් (`agent_bridge_mappings`) | සිතියම්ගත කිරීම් ඇති සෑම agent කෙනෙකු සඳහාම `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ආයාත හැසිරීම** (`POST /api/tools/agent-bridge/config`): මඟහැරීමේ රටා සහ එක් එක් agent සඳහා වන සිතියම්ගත කිරීම් **සම්පූර්ණයෙන් ප්රතිස්ථාපනය කෙරේ**; අභිරුචි සත්කාරක **idempotent ලෙස** එකතු කෙරේ (`INSERT OR IGNORE`). එක් එක් වර්ගයෙන් කොපමණ සංඛ්යාවක් යෙදූයේද යන්න ප්රතිචාරය වාර්තා කරයි:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

වින්යාසයෙහි **ඇතුළත් නොවන** දෑ: සේවාදායකය ක්රියාත්මක වන තත්ත්වය, සහතික මාර්ග, එක් එක් නියෝජිතයාට අදාළ DNS තත්ත්වය, උඩුගං CA මාර්ගය සහ TPROXY සැකසුම් — ඒවා අතේ ගෙන යා හැකි අභිරුචි නොව, සත්කාරක/ධාවනකාල තත්ත්වයන් වේ.

සෑම agent කාඩ්පතකම පියවර 3ක සැකසුම් විශාරදයක් ඇත:

1. **පූර්ව අවශ්යතා තහවුරු කරන්න** — Server එක ක්රියාත්මකද? Cert එක විශ්වාසදායකද? IDE එක ස්ථාපනය කර තිබේද (ස්වයංක්රීයව හඳුනාගනීද)?
2. **DNS සක්රිය කරන්න** — `/etc/hosts` ඇතුළත් කිරීම් එක් කරයි (sudo අවශ්ය වේ). එක් කෙරෙන පේළි නිශ්චිතව පෙන්වයි.
3. **Models සිතියම්ගත කරන්න** — විකල්ප model සිතියම්කරණ වගුවකි. Wildcards පිළිගනී.

### සංවේදී hosts සඳහා මඟහැරීම් ලැයිස්තුව

මඟහැරීම් ලැයිස්තුව මඟින් මූල්ය ආයතන, OAuth/SSO සපයන්නන් සහ අනෙකුත් සංවේදී hosts **කිසිවිටෙකත් විකේතනය නොකරන බව** සහතික කරයි. ඒවායේ TLS traffic එක පාරදෘශ්ය TCP tunnel එකක් ලෙස හරහා ගමන් කරයි — OmniRoute කිසිවිටෙකත් plaintext නොදකී.

පෙරනිමි මඟහැරීම් patternsවලට ඇතුළත් වන්නේ:

- `*.bank.*`, `*.gov.*` (මූල්ය/රාජ්ය)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/අනන්යතාව)
- `*.apple.com`, `*.icloud.com` (Apple පද්ධති සේවා)

පරිශීලකයා එක් කළ මඟහැරීම් patterns `agent_bridge_bypass` වගුවේ ගබඩා වන අතර අනෙක් සියල්ලට වඩා ප්රමුඛත්වය ගනී.

### රහස් ආවරණය කිරීම

`src/mitm/maskSecrets.ts` වෙතින් `maskSecrets()` යොදනු ලබන්නේ:

- `TrafficBuffer.push()` කිරීමට පෙර සෑම request body එකකටම
- logging හෝ broadcasting කිරීමට පෙර සෑම header එකකටම

Patterns: `sk-`/`ak-`/`pk-` උපසර්ග සහිත tokens, `Bearer` tokens සහ අක්ෂර ≥40ක generic tokens.

### Upstream CA cert

`AGENTBRIDGE_UPSTREAM_CA_CERT` සකසා ඇති විට, ආරම්භයේදී file එක කියවනු ලැබේ. Path එක පවතින නමුත් file එක කියවිය නොහැකි නම්, AgentBridge පැහැදිලි දෝෂයක් log කර ආරම්භ වීම ප්රතික්ෂේප කරයි (ආයතනික පරිසරවල නිහඬ TLS අසාර්ථකවීම් වළක්වයි).

### දන්නා සීමාවන්

- **Port 443 සඳහා වරප්රසාද අවශ්ය වේ**: Linux මත, AgentBridge සඳහා Node binary එකට `setcap 'cap_net_bind_service=+ep'` අවශ්ය වේ, නැතහොත් `authbind` හරහා ක්රියාත්මක කළ යුතුය. සැකසුම් විශාරදය OS-විශේෂිත උපදෙස් පෙන්වයි.
- **IDE නැවත ආරම්භ කිරීම අවශ්ය වේ**: DNS යළි යොමු කිරීමෙන් පසු, නව host resolution එක ක්රියාත්මක වීමට IDE එක නැවත ආරම්භ කළ යුතුය.

- **Electron frontends සඳහා `NODE_EXTRA_CA_CERTS` අවශ්ය වේ**: bundle කළ Node/Electron runtime එකක් මත frontend ක්රියාත්මක වන IDEs, OS/NSS trust store එක නොසලකා හරින අතර `NODE_EXTRA_CA_CERTS` සකසා ඇති shell එකකින් දියත් කළ යුතුය (§3.2 බලන්න). එය නොමැති විට ඇතිවන ලක්ෂණය: IDE backend එක සත්යාපනය වෙයි (MITM හි `200`s පෙන්වයි), නමුත් UI එක logged out තත්ත්වයේම පවතී.
- **එකම IDE එකේ බහු ස්ථාපන ස්වාධීන වේ**: system ස්ථාපනයක් (උදා. `/usr/share/antigravity/antigravity`) සහ user-local "Full" ස්ථාපනයක් (උදා. `~/AntigravityIDE_Full/antigravity-ide`) යනු ඒවාටම අයත් runtimes සහිත වෙනම processes වේ — එක් එක් එක CA ඇතුළත් කර නැවත දියත් කළ යුතුය. නැවත දියත් කිරීමට පෙර එහි binary path එකෙන් ක්රියාත්මක වන ස්ථාපනය හඳුනාගන්න.
- **අනන්යතාව සකසන්නේ agentගේ system prompt එකෙන් මිස routed model එකෙන් නොවේ**: ඔබ agentගේ model එක වෙනත් provider කෙනෙකුට යළි සිතියම්ගත කළ විට, IDE එක එය system prompt එකට ඇතුළත් කරන බැවින් ප්රතිචාරය තවමත් agentගේ ස්වදේශීය අනන්යතාව කියා සිටී (උදා. ## §6 දෝෂ නිරාකරණය

### 443 පෝට් ගැටුම

වෙනත් ක්රියාවලියක් දැනටමත් 443 පෝට් එකට සවන් දෙමින් සිටී නම් (වෙබ් සේවාදායකයක්, VPN එකක් ආදිය):

```bash
lsof -i :443          # ක්රියාවලිය සොයන්න
sudo fuser -k 443/tcp  # බලයෙන් නවත්වන්න (ප්රවේශමෙන් භාවිත කරන්න)
```

විකල්පයක් ලෙස, AgentBridge සැකසුම් තුළ වරප්රසාද රහිත පෝට් එකක් වින්යාස කර `iptables` / `pf` යළි-යොමු කිරීමේ රීති සකසන්න.

### සහතිකය විශ්වාස නොකෙරේ

AgentBridge ආරම්භ කිරීමෙන් පසු IDE එක TLS දෝෂ පෙන්වයි නම්:

1. සහතිකය ස්ථාපනය කර ඇති බව තහවුරු කරන්න: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) හෝ `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. සමහර යෙදුම් තමන්ගේම විශ්වාස ගබඩාවක් පවත්වාගෙන යයි (Firefox, Linux මත Chrome). "Trust Cert" නැවත ක්රියාත්මක කර NSS/Firefox සඳහා විශේෂිත සහතික ගබඩාව පරීක්ෂා කරන්න.
3. විශ්වාසය ලබා දීමෙන් පසු IDE එක නැවත ආරම්භ කරන්න — දැනට ක්රියාත්මක TLS සැසි පැරණි විශ්වාස තත්ත්වය භාවිත කරයි.

### විශ්වාසදායක CA එකක් තිබියදීත් IDE එකෙන් ඉවත් වී තිබීම / "connection error"

රෝග ලක්ෂණය: DNS යළි-යොමු කර CA එකට විශ්වාසය ලබා දීමෙන් පසු, Electron මත පදනම් වූ IDE එකක් (උදා. Antigravity)

හේතුව: IDE එක සමඟ ඇතුළත් කර ඇති **Node/Electron ධාවන පරිසරය OS විශ්වාස ගබඩාව නොසලකා හරියි**. ස්වදේශීය
පසුබිම් කොටස (Go භාෂා සේවාදායකයක්) OS CA එක විශ්වාස කර සත්යාපනය කරයි, නමුත් Electron ඉදිරිපස
එසේ නොකරයි — එබැවින් UI එක එය නොබැඳි බව විශ්වාස කරයි.

### DNS ප්රචාරණය වී නැත

`/etc/hosts` යාවත්කාලීන කර ඇති බව පරීක්ෂා කරන්න:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS හැඹිලිය හිස් කරන්න:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### Trae විමර්ශනය

Trae යනු සාපේක්ෂව නව AI කේතකරණ සහායකයකි. handler එකක් ක්රියාත්මක කිරීමට පෙර:

1. VS Code / JetBrains marketplaces තුළ හෝ ස්වාධීන යෙදුමක් ලෙස binary/extension එක හඳුනා ගන්න
2. API hosts සහ endpoint ආකෘති සොයා ගැනීම සඳහා mitmproxy භාවිතයෙන් traffic ග්රහණය කර ගන්න
3. authentication යාන්ත්රණය තීරණය කරන්න
4. TOS සහ API සොයාගත හැකි බව මත පදනම්ව ඉදිරියට යා යුතුද නැද්ද යන්න තක්සේරු කරන්න

විමර්ශනය සම්පූර්ණ වන තෙක්, dashboard එකෙහි Trae card එක "විමර්ශනය කරමින් පවතී" badge එකක් සහ "ශක්යතාව වාර්තා කරන්න" link එකක් පෙන්වයි. `src/mitm/handlers/trae.ts` හි ඇති handler stub එක ව්යූහගත `තවම ක්රියාත්මක කර නොමැත` error එකක් නිකුත් කරයි.
