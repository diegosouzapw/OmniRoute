AgentBridge යනු IDE AI නියෝජිතයන්ගෙන් පැමිණෙන HTTPS ගමනාගමනය හසුකරගෙන, එය OmniRoute හි ඒකාබද්ධ මාර්ගගත කිරීමේ එන්ජිම හරහා නැවත මාර්ගගත කරන OmniRoute හි MITM (Man-in-the-Middle) ප්රොක්සියයි. එය **IDE නියෝජිතයන් 10කට** සහාය දක්වයි — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code, සහ Trae (විමර්ශනය කරමින් පවතී) — එමඟින් OmniRoute වෙළඳපොළේ AI කේතකරණ සහායකයන් සඳහා පුළුල්ම ආවරණයක් සහිත MITM ප්රොක්සිය බවට පත් කරයි.

## §1 දළ විශ්ලේෂණය

### AgentBridge යනු කුමක්ද?

IDE නියෝජිතයෙකු (උදා., GitHub Copilot, Cursor, Claude Code) API ඇමතුමක් සිදු කරන විට, එය ඉහළ ප්රවාහයේ AI සැපයුම්කරුට (OpenAI, Anthropic, ආදිය) සෘජුවම සම්බන්ධ වේ. AgentBridge විසින් කිසිදු නියෝජිත වින්යාස වෙනසක් අවශ්ය නොකර, TLS මට්ටමේදී එම සම්බන්ධතාව පාරදෘශ්යව හසුකරගෙන ඉල්ලීම OmniRoute හරහා යළි ලියයි.

මෙයින් ඔබට කළ හැක්කේ:

- **සියලු නියෝජිත ගමනාගමනය නිරීක්ෂණය කිරීම**: හසුකරගත් සෑම ඉල්ලීමක්ම [Traffic Inspector](./TRAFFIC_INSPECTOR.md) වෙත ප්රකාශයට පත් කෙරේ.

## §2 ගෘහනිර්මාණය

### 2.1 සංරචක පිළිබඳ දළ විශ්ලේෂණය

```
IDE නියෝජිතයා (VS Code / Cursor / ආදිය)
    │  HTTPS (port 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← DNS යළි-යොමු කිරීම
    │
    ▼
src/mitm/server.cjs  (port 443, CJS අනු ක්රියාවලිය)
    │  Host header SNI අනුව ඉලක්කය නිරාකරණය කරයි
    │  AgentBridge CA මඟින් අත්සන් කළ එක් එක් SNI සඳහා TLS සහතික ජනනය කරයි
    ├── මඟහැරීමේ ලැයිස්තුවට ගැළපේද? → TCP සෘජු හුවමාරුව (විකේතනය නොකරයි)
    ├── ඉලක්කයට ගැළපේද? → fetch → OmniRoute රවුටරය (port 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── ඉල්ලීම් body/headers මත maskSecrets()
    │               ├── TrafficBuffer.push() — Traffic Inspector වෙත ප්රකාශයට පත් කරයි
    │               └── fetchRouter() → /v1/chat/completions
    └── ගැළපීමක් නැද්ද? → TCP සෘජු හුවමාරුව (විකේතනය නොකරයි)
```

### 2.2 MITM සේවාදායකය (`src/mitm/server.cjs`)

මූලික MITM සේවාදායකය Node.js CJS අනු ක්රියාවලියක් ලෙස ක්රියාත්මක වේ (පවතින CJS කේත පදනම නැවත ලිවීමෙන් වැළකීම සඳහා). එය:

- port 443 මත සවන් දෙයි (විශේෂ වරප්රසාද හෝ `authbind`/`setcap` අවශ්ය වේ)
- මෙහෙයුම් පද්ධතියෙන් CONNECT උමං ලබා ගනී (`/etc/hosts` DNS යළි-යොමු කිරීම හරහා)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) මඟින් අත්සන් කළ එක් එක් SNI සඳහා TLS සහතික ජනනය කරයි
- `targets/index.ts` රෙජිස්ට්රිය හරහා Host header අනුව ඉලක්ක නියෝජිතයා නිරාකරණය කරයි
- HTTP හරහා `http://127.0.0.1:20128` වෙත TypeScript හසුරුවන ස්තරයට යොමු කරයි

`TARGET_HOSTS`, ආරම්භයේදී `targets/index.ts` මඟින් ලියනු ලබන `DATA_DIR/mitm/targets.json` වෙතින් පූරණය කෙරෙන අතර, එමඟින් CJS සේවාදායකය නැවත ආරම්භ නොකර ගතික යාවත්කාලීන කිරීම් සිදු කළ හැක.

> #6684 හි එක් කළ ස්ථිර මූල-CA ආකෘතියයි (`src/mitm/cert/rootCa.ts` +

> නිහඬව සිදු නොවේ). CA සහතිකය, පැරණි leaf සහතිකය භාවිත කළ එම

> (`cert/install.ts::installCaCert`) — ද්විත්ව විශ්වාස පිරිසිදු කිරීමක් අවශ්ය නොවේ.

### 2.3 හසුරුවන මූල පන්තිය (`src/mitm/handlers/base.ts`)

සියලුම නියෝජිත හසුරුවන්නන් `MitmHandlerBase` විස්තාරණය කරයි:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // ආරක්ෂිත උපකාරක: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

එක් එක් හසුරුවන්නා ප්රොක්සි කිරීම පෙර `hookBufferStart()` ද, අවසන් වූ විට `hookBufferUpdate()` ද කැඳවයි. මේවා `InterceptedRequest` ඇතුළත් කිරීම් `globalTrafficBuffer` තුළට යොමු කරයි ([Traffic Inspector](./TRAFFIC_INSPECTOR.md) §4 බලන්න).

### 2.4 ඉලක්ක රෙජිස්ට්රිය (`src/mitm/targets/`)

එක් එක් නියෝජිතයාට ප්රකාශනාත්මක ඉලක්ක ගොනුවක් ඇත:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

රෙජිස්ට්රිය (`targets/index.ts`) `ALL_TARGETS` නිර්යාත කරන අතර ආරම්භයේදී `DATA_DIR/mitm/targets.json` නිකුත් කරයි.

### 2.5 සෘජු හුවමාරුව සහ මඟහැරීමේ ලැයිස්තුව (`src/mitm/passthrough.ts`)

**මඟහැරීමේ ලැයිස්තුව** (ඉලක්ක ගැළපීමට වඩා ප්රමුඛත්වය දී පළමුව පරීක්ෂා කරයි):

- පෙරනිමි රටා: බැංකු hosts, `.gov.`, OAuth/SSO සැපයුම්කරුවන් (Okta, Auth0), ආදිය.
- පරිශීලක රටා: `agent_bridge_bypass` DB වගුවේ ගබඩා කර ඇත
- මඟහැරූ hosts වෙත විනිවිද පෙනෙන TCP උමඟක් ලැබේ — TLS **කිසිවිටෙකත් විකේතනය නොකෙරේ**

**පෙරනිමි සෘජු හුවමාරුව** (ඉලක්ක ගැළපීමක් නොමැති සහ මඟහැරීමේ ලැයිස්තුවේ නොමැති විට):

- මෙයටද TCP උමඟක් ලැබේ — සම්බන්ධතා කිසිවිටෙකත් බිඳ නොදමයි
- AgentBridge මඟින් සාමාන්ය පද්ධති HTTPS ගමනාගමනයට බාධා කිරීම වළක්වයි

මාර්ගගත කිරීමේ ප්රමුඛතාව:

```
මඟහැරීමේ ලැයිස්තුව → ඉලක්ක ගැළපීම → සෘජු හුවමාරුව
```

### 2.6 ඉහළ ප්රවාහ CA සහතිකය (`src/mitm/upstreamTrust.ts`)

අභිරුචි CA එකක් සහිත ආයතනික ජාල පරිසර සඳහා:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

මෙය සකසා ඇති විට, අමතර CA සහතිකය සමඟ `undici` හි ගෝලීය dispatcher වින්යාස කරයි. එමඟින් AgentBridge හට ආයතනික TLS අවසන් කිරීමේ proxies හරහා ඉහළ ප්රවාහ සැපයුම්කරුවන් වෙත ළඟා විය හැක.

### 2.7 රහස් ආවරණය කිරීම (`src/mitm/maskSecrets.ts`)

ස්වාධීන clean-room ස්කෑනරය, ඉල්ලීම් bodies සහ අක්තපත්ර headers
Traffic Inspector buffer එකට හෝ ඕනෑම log එකකට ඇතුළු වීමට **පෙර** ඒවාට යොදනු ලැබේ. එය එක් රේඛීය පරිලෝකනයක් සිදු කරයි:

- `sk-` / `ak-` / `pk-` උපසර්ග සහිත tokens (OpenAI/Anthropic මාදිලිය)
- RFC 6750 `Authorization: Bearer <token>` අක්තපත්ර, සම්පූර්ණ token එකට ප්රමුඛත්වය සමඟ
- තිත් සහ padding කළ ආකාර ඇතුළුව සාමාන්ය දිගු අපැහැදිලි tokens (අක්ෂර ≥40)

`sanitizeHeaders()` රඳවාගත් නම් කුඩා අකුරුවලට පරිවර්තනය කරයි, array අගයන් නියත ආකාරයකින් එක් කරයි, proxy සත්යාපනය ඇතුළු හවුල් hop-by-hop/framing ප්රතික්ෂේප ලැයිස්තුව ඉවත් කරයි, `cookie` සහ `set-cookie` සම්පූර්ණයෙන්ම සඟවයි, සහ අක්තපත්ර අගයන් ස්කෑනරයට පවරයි.

### 3.2 සහතිකය විශ්වාස කිරීම

IDEs විසින් MITM සම්බන්ධතාව පිළිගැනීමට පෙර AgentBridge CA සහතිකය මෙහෙයුම් පද්ධතිය විසින් විශ්වාස කළ යුතුය.

**Linux (NSS — Chrome/Firefox):**

certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt

#### Electron-පාදක IDEs මෙහෙයුම් පද්ධතියේ විශ්වාස ගබඩාව නොසලකා හරියි (`NODE_EXTRA_CA_CERTS`)

සමහර IDEs — විශේෂයෙන් **Antigravity IDE**, සහ වෙනත් Electron / VS Code වෙතින් ව්යුත්පන්න වූ යෙදුම් — පිටතට යන
`fetch`/HTTPS සඳහා **මෙහෙයුම් පද්ධතියේ විශ්වාස ගබඩාව පරීක්ෂා නොකරන** තමන්ගේම Node.js ධාවන පරිසරයක් ඇතුළත් කරයි.
මෙහෙයුම් පද්ධති/NSS මට්ටමේදී CA විශ්වාස කිරීම IDE හි ස්වදේශීය **පසුඅන්තය** සඳහා ප්රමාණවත් වේ
(උදා. මෙහෙයුම් පද්ධතියේ CA කට්ටලය භාවිත කරන Go භාෂා සේවාදායකයක්), නමුත් **Electron ඉදිරිඅන්තය**
තවමත් TLS අසාර්ථක කරයි — MITM ලොගය පසුඅන්තයේ bootstrap ඇමතුම් `200` ආපසු ලබා දෙන බව පෙන්වුවද,
එය යෙදුමෙන් _පිටවී ඇති_ ලෙස හෝ _"සම්බන්ධතා දෝෂයක්"_ පෙන්වන ලෙස දිස් වේ. පියවර දෙකක්
අවශ්ය වන අතර, දෙකම වැදගත් වේ:

1. CA වෙත ධාවන පරිසරය පැහැදිලිව යොමු කරන්න:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **එම shell එකෙන් IDE දියත් කරන්න.** ඩෙස්ක්ටොප් අයිකනයෙන් / Dock වෙතින් / Start මෙනුවෙන්
   එය ආරම්භ කිරීමේදී shell exports උරුම නොවන අතර, `~/.config/environment.d/*.conf` අදාළ වන්නේ
   නව චිත්රක පිවිසුමකින් පසුව පමණි. පළමුව IDE සම්පූර්ණයෙන්ම වසා දමන්න — Electron හි singleton lock නිසා දෙවන
   දියත් කිරීමක් සිදු වූ විට පවතින ක්රියාවලිය වෙත පමණක් අවධානය යොමු වන අතර නව පරිසරය නොසලකා හැරේ.

ඉහත මෙහෙයුම් පද්ධති විශ්වාසය + NSS පියවර තවමත් අවශ්ය වේ (සමහර සත්යාපන
ප්රවාහ භාවිත කරන Chromium ජාල තොගය එක් එක් පරිශීලකයාගේ NSS ගබඩාව කියවන අතර, `*.googleapis.com` සඳහා
දේශීයව විශ්වාස කළ CA එකක් මඟින් අභිබවා යන එයටම අයත් ස්ථිතික pins ද ඇත). ඊට අමතරව Node `fetch` මාර්ගය `NODE_EXTRA_CA_CERTS` මඟින් ආවරණය කරයි.

### 3.5 අවදානම් දැන්වීම

ඉහළ-ධාරා සැපයුම්කරුවන් සමඟ සත්යාපනය වීමට IDE භාවිත කරන අක්තපත්ර (OAuth ටෝකන, API යතුරු) AgentBridge විසින් අන්තර්ග්රහණය කරයි. මේවා **ලොග් කිරීමට පෙර සඟවනු ලැබේ** (§2.7 බලන්න), නමුත් OmniRoute හි MITM ස්තරයට දෘශ්යමාන වේ. එක් එක් නියෝජිතයා පළමු වරට සක්රිය කිරීමේදී ඉවත් කළ හැකි අවදානම් දැන්වීම් modal එකක් පෙන්වයි.

**අනාථ-තත්ත්ව බැනරය:** බිඳවැටීමක් නිසා ඉතිරි වූ තත්ත්වයක් (DNS ව්යාජකරණය / CA / පද්ධති proxy) පිටුව හඳුනාගත් විට, කාඩ්පත ඇම්බර් පැහැති බැනරයක් පෙන්වයි — _"පෙර සැසියක් පද්ධති තත්ත්වයක් ඉතිරි කර ඇත (DNS ව්යාජකරණය, CA, හෝ පද්ධති proxy). එය පිරිසිදු කිරීමට අලුත්වැඩියා කිරීම ක්රියාත්මක කරන්න."_ — සහ **අලුත්වැඩියා කිරීම** බොත්තම ඉස්මතු කරයි. `Repair` යනු ProxyBridge හි `--cleanup` flag එකේ යෙදුම්-ස්තර ප්රතිසමයයි (එය `src/mitm/manager.ts` හි `repairMitm()` වෙත කාර්යය පවරයි).

> නැවත නැවත sudo විමසුම් ඇතිවීම වැළැක්වීම සඳහා MITM root CA එක නවතා/ආරම්භ කිරීම අතරතුර ස්ථාපිතව තබා ගනී
> (mitmproxy/Charles හි හැසිරීමද මෙයයි), එබැවින් එය නතර කරන විට ස්වයංක්රීයව සිදුවන දෙයක් වෙනුවට
> එය ඉවත් කිරීම පැහැදිලි **CA ඉවත් කරන්න** ක්රියාවකි.

### 3.7 අතේ ගෙන යා හැකි වින්යාස ආයාතය/නිර්යාතය

AgentBridge හට **ක්රියාකරුට සකස් කළ හැකි** තත්ත්වය අනුවාදගත JSON blob එකක් බවට serialize කළ හැකි අතර, එමඟින් එක් යන්ත්රයක සැකසුමක් තවත් යන්ත්රවල ප්රතිනිර්මාණය කළ හැක. serializer එක `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) වන අතර, එය `AgentBridgeConfigSchema` මඟින් වලංගු කෙරේ.

නිර්යාතයට හරියටම කොටස් තුනක් ඇතුළත් වේ (ගොඩනඟා ඇති පෙරනිමි හිතාමතාම නිර්යාත කරන්නේ **නැත**, එබැවින් ආයාත කිරීමේදී ඒවා කිසිවිටෙක අනුපිටපත් නොවී හෝ ඒවා සමඟ ගැටුම් ඇති නොවේ):

| ක්ෂේත්රය         | මූලාශ්රය                                                          | සටහන්                                                                      |
| ---------------- | ----------------------------------------------------------------- | -------------------------------------------------------------------------- |
| `bypassPatterns` | පරිශීලකයා විසින් නිර්වචනය කළ මඟහැරීම් රටා (`agent_bridge_bypass`) | පෙරනිමි bank/gov/okta රටා බැහැර කර ඇත                                      |
| `customHosts`    | Traffic Inspector අභිරුචි සත්කාරක (`inspector_custom_hosts`)      | එක් එක් අගය: `{ host, kind: "llm"\|"app"\|"custom", label? }`              |
| `agentMappings`  | එක් එක් නියෝජිතයා සඳහා ආකෘති සිතියම්කරණ (`agent_bridge_mappings`) | සිතියම්කරණ ඇති සෑම නියෝජිතයෙකු සඳහාම `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**ආයාත කිරීමේ හැසිරීම** (`POST /api/tools/agent-bridge/config`): මඟහැරීම් රටා සහ එක් එක් නියෝජිතයා සඳහා වන සිතියම්කරණ **සම්පූර්ණයෙන්ම ප්රතිස්ථාපනය කෙරේ**; අභිරුචි සත්කාරක **අනන්යතානුකූලව** එක් කෙරේ (`INSERT OR IGNORE`). එක් එක් වර්ගයෙන් කොපමණ සංඛ්යාවක් යෙදූවාදැයි ප්රතිචාරය වාර්තා කරයි:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

වින්යාසයට **ඇතුළත් නොවන** දෑ: සේවාදායකයේ ධාවන තත්ත්වය, සහතික මාර්ග, එක් එක් නියෝජිතයා සඳහා DNS තත්ත්වය, upstream CA මාර්ගය සහ TPROXY සැකසුම් — ඒවා අතේ ගෙන යා හැකි අභිරුචි නොව, සත්කාරක/ධාවනකාල තත්ත්වය වේ.

සෑම agent කාඩ්පතකම පියවර 3ක සැකසුම් විශාරදයක් ඇත:

1. **පූර්ව අවශ්යතා තහවුරු කරන්න** — Server එක ක්රියාත්මකද? Cert එක විශ්වාසදායකද? IDE එක ස්ථාපනය කර තිබේද (ස්වයංක්රීයව හඳුනාගනීද)?
2. **DNS සක්රිය කරන්න** — `/etc/hosts` ඇතුළත් කිරීම් එක් කරයි (sudo අවශ්ය වේ). එක් කෙරෙන පේළි නිශ්චිතව පෙන්වයි.
3. **Models සිතියම්ගත කරන්න** — විකල්ප model සිතියම්කරණ වගුවකි. Wildcards පිළිගනී.

Agents 1–8 සඳහා, AgentBridge විසින් IDE ස්ථාපනය ස්වයංක්රීයව හඳුනාගැනීමට උත්සාහ කරයි:

### සංවේදී hosts සඳහා මඟහැරීම් ලැයිස්තුව

මඟහැරීම් ලැයිස්තුව මඟින් මූල්ය ආයතන, OAuth/SSO සපයන්නන් සහ අනෙකුත් සංවේදී hosts **කිසිවිටෙකත් විකේතනය නොකරන බව** සහතික කරයි. ඒවායේ TLS traffic එක පාරදෘශ්ය TCP tunnel එකක් ලෙස හරහා ගමන් කරයි — OmniRoute කිසිවිටෙකත් plaintext නොදකී.

පෙරනිමි මඟහැරීම් patternsවලට ඇතුළත් වන්නේ:

- `*.bank.*`, `*.gov.*` (මූල්ය/රාජ්ය)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/අනන්යතාව)
- `*.apple.com`, `*.icloud.com` (Apple පද්ධති සේවා)

පරිශීලකයා එක් කළ මඟහැරීම් patterns `agent_bridge_bypass` වගුවේ ගබඩා වන අතර අනෙක් සියල්ලට වඩා ප්රමුඛත්වය ගනී.

### DNS ප්රචාරණය වී නැත

`/etc/hosts` යාවත්කාලීන කර ඇති බව පරීක්ෂා කරන්න:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS හැඹිලිය හිස් කරන්න:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```
