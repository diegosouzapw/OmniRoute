### සැලසුම් මූලධර්ම

1. **ප්රථමයෙන් දේශීයව** — සියලුම තත්ත්වයන් SQLite තුළ පවතින අතර බාහිර සේවා අවශ්ය නොවේ.
2. **අවහිර නොවන** — සිදුවීම් ප්රතිචාරයක් නොබලා යවනු ලැබේ; LLM ප්රතිචාර මාර්ගය
   ගේමිෆිකේෂන් තර්කනය හේතුවෙන් කිසිවිටෙක ප්රමාද නොවේ.
3. **සේවාදායකයෙන් බලය ලත්** — XP ගණනය කරනු ලබන්නේ සේවාදායක පැත්තේ පමණි; සේවාලාභීන්ට
   ලකුණු කෘත්රිමව වැඩි කළ නොහැක.
4. **පෞද්ගලිකත්වයට ගරු කරන** — ප්රමුඛතා පුවරුවට සහභාගී වීම විකල්පයකි; පරිශීලකයන්ට
   තම පැතිකඩ සැඟවිය හැක.
5. **සම්මේලනයට සූදානම්** — ප්රජා සේවාදායකවලට අත්සන් කළ API හරහා ලකුණු තල්ලු කළ හැක;
   සමමුහුර්ත කිරීම ආකලන නොව නැවත ලිවීමකි.

## ගෘහනිර්මාණය

### ඉහළ-මට්ටමේ ප්රවාහය

```
සේවාලාභී ඉල්ලීම
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (පවතින නල මාර්ගය) ...
      → ඉහළ-ධාරා ප්රතිචාරය සේවාලාභියා වෙත යවන ලදී
      → setImmediate (ප්රතිචාරයක් නොබලා):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

සිදුවීම් විමෝචකය එකම ඒකාබද්ධ කිරීමේ ස්ථානය වේ. ප්රතිචාරය යැවීමෙන් පසු `chatCore.ts` විසින්
`emitGamificationEvent()` කැඳවනු ලැබේ; සිදුවීම් මොඩියුලය
XP, අඛණ්ඩතා, ලාංඡන, ප්රමුඛතා පුවරු සහ වංචා-විරෝධී උපපද්ධති වෙත බෙදාහරියි.

### ප්රදාන ක්රියාවලිය

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP ප්රමාණය ලබා ගැනීමට `XP_REWARDS[action]` සොයන්න.
2. `checkRateLimit()` හරහා යවන්න (වංචා-විරෝධී: යතුරකට විනාඩියකට උපරිම XP 1000).
3. ගනුදෙනුවක් විවෘත කරන්න:
   - වත්මන් `user_levels` පේළිය කියවන්න.
   - XP එකතු කර `levelFromXp(totalXp)` හරහා මට්ටම නැවත ගණනය කරන්න.
   - මට්ටම වෙනස් වී ඇත්නම්, `levelUp = true` ලෙස සකසන්න.
   - `user_levels` පේළිය යාවත්කාලීන කරන්න.
   - `xp_audit_log` වෙත ඇතුළත් කරන්න.
4. ප්රතිඵලය ආපසු ලබා දෙන්න. කැඳවුම්කරු දැනුම්දීම් හසුරුවයි.

### උපකාරකය: `levelFromXp(totalXp)`

සමුච්චිත XP ප්රමාණය `totalXp` ඉක්මවන තෙක් `xp_for_level(n)` එකතු කරමින් 1..100 මට්ටම් හරහා පුනරාවර්තනය කරයි. සපුරා ඇති සීමාව සහිත ඉහළම මට්ටම ආපසු ලබා දෙයි.
මෙය O(100) වේ — මට්ටම් 100කට සීමා වන බැවින් පිළිගත හැකිය.

### ඇගයීම් ක්රියාවලිය

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # සියලු නිර්වචන
    → getUserBadges(apiKeyId)         # දැනටමත් උපයා ඇති ඒවා (මඟහරින්න)
    → උපයා නොගත් සෑම ලාංඡනයක් සඳහාම:
       → matchesCriteria(badge, event, userState)
       → ගැළපේ නම්: awardBadge(apiKeyId, badgeId)
         → දැනුම්දීම් දත්ත ආපසු ලබා දෙන්න
```

ඇගයීම **සිදුවීම්-ධාවිත** වේ — එය සෑම ක්රීඩාකරණ සිදුවීමකටම පසුව ක්රියාත්මක වන නමුත්, සිදුවීම් ක්රියාවට ගැළපෙන `criteria.type` සහිත ලාංඡන පමණක් පරීක්ෂා කරයි. මෙය ඇගයීම වේගවත් කරයි (බොහෝ සිදුවීම් සඳහා < 5ms).

## අඛණ්ඩතා ට්රැකරය

**ගොනුව:** `src/lib/gamification/streaks.ts`

### දත්ත ආකෘතිය

අඛණ්ඩතා, නාමාවකාශගත යතුරු යටතේ `key_value` වගුවේ (හවුල් උපයෝගිතා වගුව) ගබඩා කර ඇත:

| යතුර                          | අගය                              | විස්තරය             |
| ----------------------------- | -------------------------------- | ------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | සක්රිය අඛණ්ඩතා දත්ත |

### තර්කනය

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` වෙතින් අඛණ්ඩතා වාර්තාව කියවන්න.
2. `{current}`, `{longest}`, `{lastDate}` (ISO දින තන්තුව) විග්රහ කරන්න.
3. `lastDate === today` නම් — වෙනසක් නැත (අද සඳහා දැනටමත් ගණන් කර ඇත).
4. `lastDate === yesterday` නම් — `current` වැඩි කරන්න; අවශ්ය නම් `longest` යාවත්කාලීන කරන්න.
5. `lastDate < yesterday` නම් — `current = 1` ලෙස යළි සකසන්න (අඛණ්ඩතාව බිඳී ඇත).
6. යාවත්කාලීන කළ වාර්තාව ලියන්න.
7. සන්ධිස්ථාන පරීක්ෂා කරන්න: දින 7, 14, 30, 60, 90, 180, 365. සන්ධිස්ථානයක් පසු කළේ නම්,
   `milestone = true` ලෙස සකසන්න (කැඳවුම්කරු XP ප්රදානය කර ලාංඡන පරීක්ෂා කරයි).

### ආන්තික අවස්ථා

- **කාල කලාපය**: අඛණ්ඩතා UTC දින භාවිත කරයි (`new Date().toISOString().slice(0, 10)`).
  මෙය චේතනාන්විතය — තනි සම්මත කාල කලාපයක්, කාල කලාප අතර මාරු වීමෙන් පද්ධතිය අයුතු ලෙස භාවිත කිරීම වළක්වයි.
- **නව පරිශීලකයන්**: අඛණ්ඩතා වාර්තාවක් නොපවතී; පළමු ඉල්ලීම
  `current=1, longest=1, lastDate=today` සමඟ එය සාදයි.
- **දිනකට ඉල්ලීම් කිහිපයක්**: UTC දිනයේ පළමු ඉල්ලීම පමණක්
  අඛණ්ඩතාව වැඩි කරයි.

## ටෝකන් බෙදාගැනීම

**ගොනුව:** `src/lib/gamification/sharing.ts`

### ද්විත්ව-සටහන් ලෙජරය

සෑම මාරු කිරීමක්ම `token_ledger` තුළ පේළි දෙකක් නිර්මාණය කරයි:

| පේළිය | `from_key_id` | `to_key_id` | `amount` |
| ----- | ------------- | ----------- | -------- |
| හර    | යවන්නා        | ලබන්නා      | +amount  |
| බැර   | ලබන්නා        | යවන්නා      | -amount  |

රැඳී සිටින්න — සම්මුතිය මෙසේය:

| පේළිය | `from_key_id` | `to_key_id` | `amount` | අර්ථය                   |
| ----- | ------------- | ----------- | -------- | ----------------------- |
| යැවීම | යවන්නා        | ලබන්නා      | +amount  | යවන්නාගෙන් පිටතට ගලායාම |
| ලැබීම | ලබන්නා        | යවන්නා      | +amount  | ලබන්නා වෙතට ගලාඒම       |

ශේෂය ගණනය කරන්නේ මෙසේය:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### මාරු කිරීමේ ප්රවාහය

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **වලංගු කරන්න**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **අයිඩම්පොටෙන්සි**: `idempotency_key` දැනටමත් ලෙජරයේ තිබේදැයි පරීක්ෂා කරන්න.
   එසේ නම්, හැඹිලිගත ප්රතිඵලය ආපසු ලබා දෙන්න.
3. **ගනුදෙනුව** (තනි SQLite ගනුදෙනුවක්):
   a. යවන්නාගේ ශේෂය ගණනය කරන්න.
   b. `balance < amount` නම්, අවලංගු කරන්න (ප්රමාණවත් අරමුදල් නොමැත).
   c. යැවීමේ පේළිය ඇතුළත් කරන්න (`from=sender,` ආපසු ලබා දෙන්න.

### අනුපාත සීමා කිරීම

- එක් API යතුරකට මිනිත්තුවකට උපරිම මාරු කිරීම් 10ක්.
- එක් මාරු කිරීමකට උපරිම ටෝකන් 10,000ක්.
- එක් API යතුරකට දිනකට මාරු කළ හැකි උපරිම ටෝකන් ගණන 100,000කි.

- **කේතය**: අක්ෂර 8ක අක්ෂරාංක කේතයක් (උදා., `A3K9-X7M2`), මිනිසුන්ට කියවිය හැකි අතර,

  ක්රමලේඛනමය මුදාගැනීම සඳහා භාවිත කෙරේ (උදා., URL සබැඳි).

### ගබඩා කිරීම

| තීරුව        | අගය                        |

අමු ටෝකනය නිර්මාණය කරන අවස්ථාවේදී පරිශීලකයාට හරියටම එක් වරක් ආපසු ලබා දේ. OmniRoute
එය නැවත කිසිවිටෙක ගබඩා කිරීම හෝ පෙන්වීම සිදු නොකරයි — පවතින්නේ හැෂ් එක පමණි.

2. මුදාගන්නා පරිශීලකයා එම යොමු කරන්නාගෙන් මීට පෙර කිසිදු කේතයක් මුදාගෙන නොමැත
   (`invite_tokens` + මුදාගැනීමේ ලොගය මත සම්බන්ධ කරයි).

පරීක්ෂාවන්ගෙන් එකක් හෝ අසමත් වුවහොත්, පැහැදිලි දෝෂ පණිවිඩයක් සමඟ මුදාගැනීම ප්රතික්ෂේප කෙරේ.

### කල් ඉකුත්වීම සහ සීමා

- පෙරනිමි `max_uses`: 10 (නිර්මාණය කරන අවස්ථාවේ වින්යාස කළ හැක).
- පෙරනිමි `expires_at`: නිර්මාණය කළ දින සිට දින 30ක්.
- කල් ඉකුත් වූ හෝ භාවිත සීමාව අවසන් වූ කේත HTTP 410 Gone ආපසු ලබා දෙයි.

සෑම API යතුරක් සඳහාම, පද්ධතිය පැයකට උපයාගත් XP හි ගලායන දින 7ක කවුළුවක් පවත්වාගෙන යයි. සෑම XP ප්රදානයකදීම:

1. පරිශීලකයාගේ වත්මන් පැයක XP අනුපාතය ගණනය කරන්න.
2. සමස්තයේ මධ්යන්යය සහ සම්මත අපගමනය ගණනය කරන්න.
3. `z = (user_rate - mean) / stddev` ගණනය කරන්න.
4. `z > 3.0` නම් (සම්මත අපගමන 3ක්), එය විෂමතාවක් ලෙස සලකුණු කරන්න.

විෂමතා `action = 'anomaly_detected'` සමඟ `xp_audit_log` වෙත සටහන් කර පරිපාලක උපකරණ පුවරුවේ පෙන්වනු ලැබේ.
