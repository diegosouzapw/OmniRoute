OmniRoute විසින් තෙවන පාර්ශ්වීය cloud-hosted coding agents (Codex Cloud, Cursor,
Devin, Jules) දිගු කාලයක් ක්රියාත්මක වන tasks ලෙස සම්බන්ධීකරණය කරයි. එක් එක් agent එක ඒකාකාර interface එකක් පසුපස ආවරණය කර ඇති බැවින්,
සේවාලාභීන්ට provider-විශේෂිත APIs සමඟ සෘජුව කටයුතු නොකර prompt එකක් + repo URL එකක් ඉදිරිපත් කර ප්රතිඵල ලබාගත හැක.

Cloud Agent task එකක් සාමාන්ය chat completion එකක් **නොවේ**. එය මිනිත්තු සිට පැය ගණනක් ගත විය හැකි,
එහි artifact එක ලෙස Pull Request එකක් නිපදවිය හැකි, සහ පසු විපරම් පණිවිඩ මෙන්ම (සමහර providers තුළ) සැලසුම් අනුමත කිරීමේ ද්වාර සඳහා සහාය දක්වන, කල්පවත්නා බහු-පියවර
වැඩ ඒකකයකි.

Registry එක: `src/lib/cloudAgent/registry.ts` — `getAgent(providerId)`,
`getAvailableAgents()`, සහ `isCloudAgentProvider(providerId)` export කරයි. Registry එක යනු
module එක load වන විට පුරවන සරල in-memory `Record<string, CloudAgentBase>` එකකි.

## ගෘහ නිර්මාණය

```
සේවාලාභියා (Dashboard / CLI / API)
  → POST /api/v1/agents/tasks (කළමනාකරණ සත්යාපනය අවශ්යයි)
    → CreateCloudAgentTaskSchema වලංගුකරණය (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) වෙතින් ලබාගනී
         (පළමුව apiKey, නොමැති නම් accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ upstream provider API වෙත HTTP POST
      └─ අභ්යන්තර id + externalId සහිත CloudAgentTask එකක් ආපසු ලබාදෙයි
    → cloud_agent_tasks (SQLite) වෙත insertCloudAgentTask(...)

Polling (කියවීමේදී සිදුවන lazy sync):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // status + activities නැවුම් කරයි
    → නව status, result, completed_at සමඟ updateCloudAgentTask(...)
    → serialized task එක ආපසු ලබාදෙයි

අන්තර්ක්රියා:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → "approve" සඳහා agent.approvePlan(externalId, credentials)
    → "message" සඳහා agent.sendMessage(externalId, message, credentials)
    → "cancel" සඳහා status එක "cancelled" ලෙස වෙනස් වේ (දේශීයව පමණි)
```

Sync කිරීම **lazy** වේ: සෑම `GET /tasks/[id]` එකකදීම status එක upstream වෙතින් නැවුම් කෙරේ.
පසුබිම් poller එකක් නොමැත. නැවුම් තත්ත්වයක් අවශ්ය Dashboards, GET
endpoint එක සාධාරණ කාලාන්තරයකින් poll කළ යුතුය.

## `CloudAgentBase` අතුරුමුහුණත

මූලාශ්රය: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // අනුමානාත්මක upstream-string → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` හිතාමතාම දෝෂයක් නිකුත් කරයි — Codex Cloud ස්වයංක්රීයව සැලසුම් කරන අතර එයට
අනුමැති ද්වාරයක් නොමැත. `CodexCloudAgent.listSources` මඟින් `[]` ආපසු ලබා දෙයි.

`CursorCloudAgent`, Cursor හි නිල REST API (`api.cursor.com/v0`) හරහා එහි Background / Cloud Agents
**පරිශීලක හෝ සේවා-ගිණුම් API යතුරක්** සමඟ මෙහෙයවයි — මෙය තහනම් වීමේ අවදානම පිළිබඳ අනතුරු ඇඟවීමක්
සහිත provider `cursor` භාවිතයෙන් Cursor IDE හි OAuth සැසිය නැවත භාවිත කිරීමට වඩා ආරක්ෂිත,
ප්රථම-පාර්ශ්වීය විකල්පයයි. එය සරල REST ඇඩැප්ටරයකි (`@cursor/sdk` ස්වදේශීය
පරායත්තතාවක් නොමැත). `approvePlan` දෝෂයක් නිකුත් කරයි (Cursor නියෝජිතයන් ස්වයංක්රීයව ක්රියා කරයි); `listSources` මඟින්
යතුරට ප්රවේශ විය හැකි නිධි ලැයිස්තුගත කරයි. Cursor, හවුල්
`CloudAgentStatus` වෙත පැහැදිලිව සිතියම්ගත කරන ලද UPPERCASE තත්ත්ව enum
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) ආපසු ලබා දෙයි. කේත වෙනසකින් තොරව API අනුවාදය/මාර්ගය
නිවැරදි කිරීමට හැකි වන පරිදි, එක් එක් අක්තපත්රය සඳහා `baseUrl` අභිබවා සැකසිය හැක.

## වසම් වර්ග

මූලාශ්රය: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // වලංගු URL එකක් විය යුතුය
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // තත්පර, ධන පූර්ණ සංඛ්යාවකි
  cost?: number; // ධන දශම සංඛ්යාවකි
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // අභ්යන්තර `task_...` හැඳුනුම්කාරකය
```

## දත්ත සමුදාය

මූලාශ්රය: `src/lib/cloudAgent/db.ts` — වගුව
`createCloudAgentTaskTable()` හරහා අවශ්ය අවස්ථාවේදී නිර්මාණය කෙරේ (`src/lib/cloudAgent/index.ts` වෙතින් මොඩියුලය ආයාත කරන අවස්ථාවේදීද මෙය කැඳවනු ලැබේ).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL injection වැළැක්වීම සඳහා `updateCloudAgentTask` විසින් **තීරු සුදු ලැයිස්තුවක්** බලාත්මක කරයි:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. අර්ධ යාවත්කාලීනයේ ඇති වෙනත් ඕනෑම යතුරක් නිහඬව ඉවත් කෙරේ.

## REST API — Cloud සපයන්නා සම්බන්ධ කිරීම

`src/app/api/cloud/` යටතේ ඇති මෙම සහායක endpoints, දුරස්ථ clients
(CLI, Electron app එක, හෝ sync workers) විසින් සපයන්නාගේ සම්බන්ධතා metadata කියවීමට
සහ model aliases විසඳීමට භාවිත කරයි. මේවා task endpoints භාවිත කරන management auth මඟින් නොව,
**සාමාන්ය API key එකක්** මඟින් (`validateApiKey` හරහා) සත්යාපනය කෙරේ.

| ක්රමය | Path                            | අරමුණ                                                                         |
| ----- | ------------------------------- | ----------------------------------------------------------------------------- |
| POST  | `/api/cloud/auth`               | API key එක වලංගු කර, masked සම්බන්ධතා metadata + model aliases ආපසු ලබා දීම   |
| PUT   | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` නැවුම් කිරීම                     |
| POST  | `/api/cloud/model/resolve`      | model alias එකක් `{ provider, model }` වෙත විසඳීම                             |
| GET   | `/api/cloud/models/alias`       | සියලු model aliases ලැයිස්තුගත කිරීම                                          |
| PUT   | `/api/cloud/models/alias`       | model alias එකක් සැකසීම (සක්රීය නම් Cloud වෙත ස්වයංක්රීයව sync කිරීමද ඇතුළුව) |

`/api/cloud/auth` කිසිවිටෙකත් අමු `apiKey` / `accessToken` / `refreshToken` ආපසු ලබා නොදේ. එය
`hasApiKey`, `hasAccessToken`, `hasRefreshToken`, සහ masked පෙරදසුනක්
(`maskedApiKey`: මුල් අක්ෂර 4 + `****` + අවසාන අක්ෂර 4) ආපසු ලබා දෙයි.

## Credentials විසඳීම

`src/lib/cloudAgent/api.ts` තුළ ඇති `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` හරහා සක්රීය සපයන්නාගේ සම්බන්ධතා load කරයි.
2. සෑම සම්බන්ධතාවක් සඳහාම, `apiKey` (trim කළ) ප්රමුඛව භාවිත කරයි. එය නොමැති නම් `accessToken` භාවිත කරයි.
3. හිස් නොවන පළමු token එක `{ apiKey: token }` ලෙස wrap කර ආපසු ලබා දෙයි.
4. භාවිත කළ හැකි token එකක් හමු නොවුණහොත් `null` ආපසු ලබා දෙයි — API එක
   `400` සමඟ `"No active credentials configured for cloud agent provider: <id>"` යන පණිවිඩය ප්රතිචාර ලෙස ලබා දෙයි.

මෙයින් අදහස් වන්නේ Cloud Agents සාමාන්ය LLM සපයන්නන් භාවිත කරන Provider Connection table එකම
නැවත භාවිත කරන බවයි. Jules සක්රීය කිරීමට, `provider: "jules"` සහ පුරවන ලද `apiKey` එකක් සහිත
සක්රීය සම්බන්ධතාවක් සාදන්න.

5. සම්බන්ධතා record එකක් අවශ්ය නම් සපයන්නා `src/shared/constants/providers.ts` වෙත එක් කරන්න.
   OAuth මත පදනම් වූ සපයන්නන්ට `src/lib/oauth/providers/` ද අවශ්ය වේ.
6. `tests/unit/cloud-agent-*.test.ts` යටතේ tests එක් කරන්න.
7. මෙම ලේඛනය සහ dashboard එකේ `CLOUD_AGENTS` constant එක යාවත්කාලීන කරන්න.
