OmniRoute මඟින් භාෂා ආකෘතිවලට (සහ මෙහෙයවන්නන්ට) නැවත භාවිත කළ හැකි හැකියාවන් සංයෝජනය කිරීමට ඉඩ දෙන, විස්තාරණය කළ හැකි Skills රාමුවක් සපයයි — ගොනු පද්ධතියෙන් කියවීම සහ HTTP ඉල්ලීම්වල සිට වැලිපෙට්ටියක ක්රියාත්මක කරන කේත සහ තෝරාගත් වෙළඳපොළ කුසලතා දක්වා.

කුසලතාවක් යනු අනුවාදගත, යෝජනා ක්රමයකින් අර්ථ දක්වන ලද වැඩ ඒකකයකි. OmniRoute හට පිටතට යවන ඉල්ලීම් තුළ මෙවලම් අර්ථ දැක්වීම් ලෙස කුසලතා ඇතුළු කිරීමට, ආකෘතියෙන් ආපසු පැමිණෙන මෙවලම් කැඳවීම් අතරමඟ ග්රහණය කිරීමට, ගැළපෙන හසුරුවනය ක්රියාත්මක කිරීමට සහ සංවාදය දිගටම කරගෙන යාම සඳහා ප්රතිඵලය නැවත ආකෘතියට සැපයීමට හැකිය. ආකෘතියට කිසිවිටෙක ක්රියාත්මක කිරීමේ අභ්යන්තරය නොපෙනේ — පෙනෙන්නේ මෙවලම් අතුරුමුහුණත පමණි.

## සංකල්ප

### කුසලතා මූලාශ්ර

කුසලතා මූලාශ්ර තුනක් එකම ලේඛනාගාරය තුළ එකට පවතී:

1. **අන්තර්ගත කුසලතා** (`src/lib/skills/builtins.ts`) — OmniRoute සමඟ සපයනු ලැබේ. පොදු භාවිත අවස්ථා ආවරණය කරයි:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/` යටතේ එක් එක් API යතුරට වෙන් වූ වැලිපෙට්ටි වැඩබිම
   - `http_request` — `guard: "public-only"` සමඟ `safeOutboundFetch` හරහා පිටතට යවන HTTP ඉල්ලීම
   - `web_search` — හැඹිලිගත කිරීම සහිත මාරු කළ හැකි සෙවුම් සපයන්නෙක් (`executeWebSearch`)
   - `eval_code` — Docker වැලිපෙට්ටියක ක්රියාත්මක කරන `node` හෝ `python`
   - `execute_command` — Docker වැලිපෙට්ටියක ක්රියාත්මක කරන shell විධානය
   - `browser` — Playwright මත පදනම් වූ මූලික රාමුව, පෙරනිමියෙන් අක්රියයි (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute වෙළඳපොළ) — `https://skillsmp.com/api/v1/skills/search` වෙතින් ලබා ගනී. Settings තුළ `skillsmpApiKey` අවශ්ය වේ.
3. **SkillsSH** (`skills.sh` ප්රජා නාමාවලිය) — `https://skills.sh/api/search` වෙතින් ලබා ගනී. සත්යාපනය අවශ්ය නොවේ; SKILL.md අන්තර්ගතය GitHub raw වෙතින් ලබා ගනී.

උපකරණ පුවරුව ස්ථාපනය කරන්නේ කුමන නාමාවලියෙන්ද යන්න තනි "සක්රිය සපයන්නෙක්" විසින් පාලනය කරයි (`src/lib/skills/providerSettings.ts`). එය **Settings → Memory & Skills** යටතේ මාරු කරන්න. පෙරනිමිය: `skillsmp`.

### කුසලතා අනන්යතාව

මතකය තුළ ඇති ලේඛනාගාරයේ (`src/lib/skills/registry.ts`) කුසලතා සඳහා යතුරු ලෙස `name@version` භාවිත කෙරේ. අනුවාදය semver (`^\d+\.\d+\.\d+$`) විය යුතුය. `resolveVersion()` හට `^`, `~`, `>`, `>=`, `<`, `<=`, `==`, සහ නිශ්චිත ගැළපුම් සීමා තේරුම් ගත හැකිය.

### කුසලතා මාදිලිය

සෑම කුසලතාවකටම එය ඇතුළත් කරන්නේ කවදාද යන්න පාලනය කරන ධාවන කාල මාදිලියක් ඇත:

| මාදිලිය | හැසිරීම                                                                                         |
| ------- | ----------------------------------------------------------------------------------------------- |
| `on`    | සෑම විටම මෙවලම් අර්ථ දැක්වීමක් ලෙස ඇතුළත් කෙරේ                                                  |
| `off`   | කිසිවිටෙක ඇතුළත් නොකෙරේ, කිසිවිටෙක ක්රියාත්මක කළ නොහැක                                          |
| `auto`  | පැමිණෙන ඉල්ලීමට සාපේක්ෂව ලකුණු කරයි; ලකුණ ≥ `AUTO_MIN_SCORE` නම් පමණක් ඇතුළත් කෙරේ (පෙරනිමිය 3) |

වෙළඳපොළෙන් ස්ථාපනය කරන කුසලතා සඳහා පෙරනිමිය `auto` වේ. `enabled=true` සහ `mode="off"` එක්ව භාවිත කිරීමෙන් අදහස් වන්නේ "ලියාපදිංචි කර ඇති නමුත් අක්රිය" යන්නයි — පැරණි කේත මාර්ග අනුකූලව පවත්වා ගැනීම සඳහා පැරණි තීරුව හරහා `enabled` මාරු කිරීමේදී `mode` ද යාවත්කාලීන කරයි (`src/app/api/skills/[id]/route.ts`).

### තත්ත්වය (ක්රියාත්මක කිරීම්)

කුසලතා ක්රියාත්මක කිරීම් පහත තත්ත්ව සමඟ `skill_executions` වගුවේ හඹා යනු ලැබේ (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### ලේඛනාගාර හැඹිලිය

`SkillRegistry` යනු තත්පර 60ක TTL හැඹිලියක් සහිත singleton එකකි (`registry.ts:14`). `loadFromDatabase()` idempotent වන අතර `pendingLoad` හරහා සමකාලීන කැඳවීම් අනුපිටපත් ඉවත් කරයි. ඕනෑම ලිවීමක් (`register`/`unregister`/`unregisterById`) හැඹිලිය අවලංගු කරයි. `getSkillVersions(name)` සහ `resolveVersion(name, constraint)` හරහා අනුවාද සොයන්න.

### සපයන්නා පිළිබඳ දැනුවත් ඇතුළත් කිරීම

`src/lib/skills/injection.ts` තුළ ඇති `injectSkills()` යනු ලියාපදිංචි කුසලතා සපයන්නාට විශේෂිත මෙවලම් අර්ථ දැක්වීම් බවට පත් කරන ප්රවේශ ලක්ෂ්යයයි:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

ආකෘතිය එය නැවත කැඳවන විට නිවැරදි අනුවාදය තෝරාගැනීමට හසුරුවනයට හැකි වන පරිදි මෙවලම් නාමය `name@version` ලෙස කේතනය කර ඇත.

### AUTO ලකුණුකරණය

`mode="auto"` වන විට, සෑම අපේක්ෂක කුසලතාවක්ම ඉල්ලීම් සන්දර්භයට සාපේක්ෂව ලකුණු කරනු ලැබේ (`injection.ts` හි `scoreAutoSkill()`):

| සංඥාව                                            | ලකුණු      |
| ------------------------------------------------ | ---------- |
| කුසලතා නාමය සන්දර්භය තුළ එලෙසම දිස් වේ           | +6         |
| සෑම නාම ටෝකනයක්ම සන්දර්භ ටෝකනයකට ගැළපේ           | +2         |
| සෑම ටැග් උපතන්තුවක්ම සන්දර්භයට ගැළපේ             | +3         |
| සෑම විස්තර ටෝකනයක්ම සන්දර්භයට ගැළපේ              | +1         |
| පසුබිම් හේතුව නාම ටෝකනයකට ගැළපේ                  | ටෝකනයකට +2 |

### මෙවලම් කැඳවීම් අතරමැදිව ග්රහණය කිරීම

උඩුගං සේවාව මෙවලමක් කැඳවන ප්රතිචාරයක් ලබාදුන් පසු, කතාබස් හසුරුවනය විසින් `src/lib/skills/interception.ts` හි `handleToolCallExecution()` කැඳවනු ලැබේ:

1. `extractToolCalls()` සැපයුම්කරුට විශේෂිත ව්යුහ කියවයි (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`).
2. බිල්ට්-ඉන් මෙවලම් අන්වර්ථ නාම (උදා. `omniroute_web_search` → `web_search`) පළමුව නිරාකරණය කෙරේ. බිල්ට්-ඉන් හසුරුවන පේළිය තුළම ක්රියාත්මක වේ.
3. අනෙකුත් සියල්ල `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` හරහා යොමු කෙරේ.
4. ප්රතිඵල නැවත ප්රතිචාරය තුළට ඇතුළත් කෙරේ — සුදුසු පරිදි `tool_results`, `function_call_output` අයිතම, හෝ Anthropic `tool_result` බ්ලොක් ලෙස.

පැහැදිලිවම පරිශීලකයා විසින් නිර්වචනය කළ හසුරුවන අක්රිය කරන ඉල්ලීම් මාර්ග සඳහා, බිල්ට්-ඉන් අතරමැදි ග්රහණයට පමණක් ඉඩ දීමට ක්රියාත්මක කිරීමේ සන්දර්භයේ `customSkillExecutionEnabled` අගය `false` ලෙස සැකසිය හැක.

## Docker සෑන්ඩ්බොක්ස්

අන්තර්නිර්මිත නොවන කේත මාර්ග (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) හරහා Docker තුළ ක්රියාත්මක වේ. සෑම කන්ටේනරයක්ම පහත සැකසුම් සමඟ දියත් කෙරේ:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (readOnly=true විට)
```

පෙරනිමි (`SandboxRunner.DEFAULT_CONFIG`):

| ක්ෂේත්රය         | පෙරනිමිය        | සටහන්                                                |
| ---------------- | --------------- | ---------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus` වෙත යැවීමට පෙර 1000න් බෙදනු ලැබේ            |
| `memoryLimit`    | 256 MB          | දැඩි සීමාව                                           |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` හරහා මෘදු අවසන් කිරීම      |
| `networkEnabled` | `false`         | `--network none` බවට පත්වේ                           |
| `readOnly`       | `true`          | මූල FS කියවීමට පමණි; `/tmp` සහ `/workspace` tmpfs වේ |

වසා දැමීම සඳහා `SandboxRunner.kill(id)` සහ `killAll()` නිරාවරණය කර ඇත; ක්රියාත්මක වන කන්ටේනර් `runningContainers: Map<string, ChildProcess>` තුළ නිරීක්ෂණය කෙරේ.

### සෑන්ඩ්බොක්ස් පරිසර විචල්ය

`src/lib/skills/builtins.ts` තුළ `process.env` හරහා වින්යාස කර ඇත:

### වැඩබිම් හුදකලාව

`file_read` සහ `file_write` සෑම මාර්ගයක්ම `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/` හි එක් එක් API යතුරට අදාළ වැඩබිමකට සාපේක්ෂව නිරාකරණය කරයි. කිසිදු තැටි I/O ක්රියාවකට පෙර මාර්ග තරණය (`..`) සහ තහනම් කළ කොටස් (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) ප්රතික්ෂේප කෙරේ.

### HTTP ශක්තිමත් කිරීම

`http_request` (`builtins.ts:257`):

- ක්රම අවසර ලැයිස්තුව: `GET, HEAD, POST, PUT, PATCH, DELETE`
- අවහිර කළ පිටතට යන ශීර්ෂක: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- යළි-යොමු කිරීම් අක්රියයි (`allowRedirect: false`)
- `guard: "public-only"` සමඟ `safeOutboundFetch` හරහා මාර්ගගත කෙරේ (පුද්ගලික/ලූප්බැක් පරාස අවහිර කෙරේ)
- ප්රතිචාරය `SKILLS_MAX_HTTP_RESPONSE_BYTES` හිදී කප්පාදු කෙරේ; සේවාලාභියාට `truncated: true` පෙනේ

`src/lib/skills/hybrid.ts` මඟින් එක් එක් ඇමතුම සඳහා `direct` (ක්රියාවලිය තුළ) සහ `sandbox` ක්රියාත්මක කිරීම අතර තීරණය කරන `HybridExecutor` එකක් නිර්වචනය කරයි; කාල සීමාව ඉක්මවීමේ/මතක දෝෂවලදී `autoUpgrade` නැවත උත්සාහ කිරීමේ මාර්ගයක් ද ඇත. සම්බන්ධ කර ඇති `directExecutor` / `sandboxRunner` ක්රියාත්මක කිරීම් අඩංගු නොවන ආදර්ශ පමණි (`executeDirect`, `executeInSandbox` ස්ථානධාරක වස්තු ආපසු ලබා දෙයි) — මෙම මොඩියුලය තවමත් ගොඩනැගෙමින් පවතින ගිවිසුමක් ලෙස සලකන්න. සැබෑ ක්රියාත්මක කිරීම තවමත් `skillExecutor` + `SandboxRunner` හරහා සිදු වේ.

## නව අන්තර්ගත කුසලතාවක් එක් කිරීම

1. **හසුරුවනය නිර්වචනය කරන්න** `src/lib/skills/builtins.ts` තුළ (හෝ `src/lib/skills/builtin/` යටතේ ඇති සහෝදර ගොනුවක). අත්සන: `(input, { apiKeyId, sessionId }) => Promise<output>`.
2. **සෑන්ඩ්බොක්ස් කළ කේත මාර්ගයක්ද?** `sandboxRunner.run(image, command, env, sandboxConfig({...}))` අමතන්න. අවසර ලැයිස්තුවට එරෙහිව `normalizeImage()` භාවිත කරන්න.
3. **ගොනු පද්ධති මාර්ගයක්ද?** තැටියට ප්රවේශ වීමට පෙර සැමවිටම `resolveWorkspacePath(input, context)` හරහා යවන්න.
4. **ජාල ඇමතුමක්ද?** `guard: "public-only"` සමඟ `safeOutboundFetch` භාවිත කරන්න; `sanitizeHeaders()` හරහා ශීර්ෂ පිරිසිදු කරන්න.
5. **ලියාපදිංචි කරන්න** `builtinSkills` වෙත ප්රවේශය එක් කිරීමෙන් (හෝ ආරම්භයේදී `registerBrowserSkill(executor)` ආකාරයෙන් ඇමතීමෙන්).
6. උඩුගං ආකෘතිය වෙනත් නමක් නිකුත් කරන්නේ නම්, `BUILTIN_TOOL_ALIASES` (`interception.ts:23`) තුළ **අන්තර්ගත මෙවලම් අන්වර්ථ සම්බන්ධ කරන්න** (විකල්ප).
7. `src/lib/skills/__tests__/` තුළ **පරීක්ෂණ** (Vitest).

## අභිරුචි (අන්තර්ගත නොවන) කුසලතාවක් එක් කිරීම

1. ක්රියාවලි ආරම්භයේදී හසුරුවනය ලියාපදිංචි කරන්න:
   ```ts
   skillExecutor.registerHandler("my-handler", async (input, ctx) => { ... });
   ```
2. `POST /api/skills/install` හරහා කුසලතාව ඇතුළත් කරන්න (`handlerCode` ක්ෂේත්රය ලියාපදිංචි කළ හසුරුවන නමට ගැළපිය යුතුය).
3. `PUT /api/skills/[id]` හරහා `mode`, `on` හෝ `auto` වෙත මාරු කරන්න.

## මෙහෙයුම් උපදෙස්

- **ප්රධාන ස්විචය:** `settings.skillsEnabled = false` සියලු ක්රියාත්මක කිරීම් අවහිර කරන අතර `/api/skills/executions` මත HTTP `503` ආපසු ලබා දෙයි. ලේඛනාගාරය දිගටම පූරණය වේ.
- **පිටතට යන ගමනාගමනය සීමා කරන්න:** සම්පූර්ණයෙන්ම ජාලයෙන් වෙන් කළ සෑන්ඩ්බොක්ස්කරණය සඳහා `SKILLS_SANDBOX_NETWORK_ENABLED` සකසා නොතබන්න (පෙරනිමිය). එක් එක් ඇමතුම සඳහා `networkEnabled: true` යෙදුවද ප්රධාන ද්වාරයේ අවසරය තවමත් අවශ්ය වේ.
- **නිශ්චිත අනුරූවලට ඉඩ දෙන්න:** අවසර ලැයිස්තුව පුළුල් කිරීමට `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"` සකසන්න.
- **ක්රියාත්මක කිරීම් විගණනය කරන්න:** `/dashboard/skills/executions` සහ `omniroute_skills_executions` යන දෙකම `skill_executions` විමසයි. සාර්ථක ධාවනයන්හි `durationMs` ඇතුළත් වේ; අසාර්ථකත්වයන්හි `errorMessage` ඇතුළත් වේ.
- **හැඹිලි අවලංගු කිරීම:** අතින් DB සංස්කරණය කිරීමෙන් පසු `skillRegistry.invalidateCache()` අමතන්න; එසේ නොමැති නම් තත්පර 60ක් රැඳී සිටින්න.
- **නිර්නාමික වැඩබිම:** `apiKeyId` හිස් වූ විට, සියලු ඇමතුම් එකම `"anonymous"` වැඩබිම වෙත හැෂ් වේ — බෙදාගැනීම පිළිබඳ දැනුවත් කේතය සැමවිටම සැබෑ යතුරක් ලබා දිය යුතුය.

## ක්රියාත්මක කිරීමේ ජීවන චක්රය (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) යනු සෑම skill කැඳවීමක්ම කළමනාකරණය කරන **singleton** එකකි. කාල සීමා ඉක්මවීම්, නැවත උත්සාහ කිරීම් සහ ක්රියාත්මක කිරීමේ තත්ත්වය නිදොස් කිරීම සඳහා එහි ජීවන චක්රය අවබෝධ කර ගැනීම අතිශයින් වැදගත් වේ.

### අදියර 5ක ජීවන චක්රය

```
   execute() කැඳවන ලදී
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← පෝලිම්ගත කර ඇත, තවම ආරම්භ කර නැත (DB පේළිය සාදන ලදී)
  └──────┬──────┘
         │ handler එක ආරම්භ කරන්න
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← කාල සීමාවක් සමඟ handler එක කැඳවන ලදී
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (වෙනත් මාර්ගයක් නැත — මව් ක්රියාවලිය විසින් නවතා දමන ලදී)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   තත්ත්වය, ප්රතිදානය සහ durationMs සමඟ DB පේළිය යාවත්කාලීන කරන ලදී
```

### පෙරනිමි වින්යාසය

| සැකසුම       | පෙරනිමිය      | පහත ක්රමයෙන් වින්යාස කළ හැක          |
| ------------ | ------------- | ------------------------------------ |
| `timeout`    | `30000` (30s) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`           | `skillExecutor.setMaxRetries(count)` |

> **වැදගත්**: executor එක singleton එකකි — `setTimeout()` කැඳවීම ඉන්පසු සිදු කරන සියලුම කැඳවීම් වෙත ගෝලීයව බලපායි. එක් එක් skill සඳහා වෙන වෙනම කාල සීමා දැනට සහාය නොදක්වයි; එක් එක් skill සඳහා වෙනස් කාල සීමා අවශ්ය නම්, වෙන වෙනම ක්රියාවලි ඉදිරිපත් කරන්න හෝ executor එක fork කරන්න.

### තත්ත්ව අගයන්

`src/lib/skills/types.ts` වෙතින්:

```ts
enum SkillStatus {
  PENDING = "pending", // පෝලිම්ගත කර ඇත, තවම ආරම්භ කර නැත
  RUNNING = "running", // Handler එක කැඳවන ලදී
  SUCCESS = "success", // Handler එක වලංගු ප්රතිදානයක් ආපසු ලබා දුන්නේය
  ERROR = "error", // Handler එක ව්යතිරේකයක් නිකුත් කළේය
  TIMEOUT = "timeout", // Executor එකේ කාල සීමාව ඉක්මවා ගියේය
}
```

> **සටහන**: `TIMEOUT` තත්ත්වය enum එක තුළ අර්ථ දක්වා ඇති නමුත් වත්මන් executor ක්රියාත්මක කිරීම මඟින් එය **සත්ය වශයෙන්ම DB වෙත ලියනු නොලැබේ** — කාල සීමා ඉක්මවීම් `"Skill execution timed out"` පණිවිඩය සමඟ `ERROR` ලෙස පෙන්වයි. මෙම තත්ත්ව enum එක අනාගත භාවිතය සඳහා වෙන් කර ඇත.

### ක්රියාත්මක කිරීම් පරීක්ෂා කිරීම

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID එක අනුව නිශ්චිත ක්රියාත්මක කිරීමක් ලබා ගන්න
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// API යතුරක් සඳහා මෑත ක්රියාත්මක කිරීම් ලැයිස්තුගත කරන්න
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// මුළු ක්රියාත්මක කිරීම් ගණන ගණන් කරන්න
const total = skillExecutor.countExecutions("api-key-id");
```

### නැවත උත්සාහ කිරීමේ හැසිරීම

`maxRetries` සැකසුම ගබඩා කර ඇති නමුත් executor එකේ `execute()` ක්රමය මඟින් එය **දැනට භාවිත නොකෙරේ** — එය සිදු කරන්නේ එක් උත්සාහයක් පමණි. අනාගත ක්රියාත්මක කිරීම සඳහා සහ එය කියවීමට අවශ්ය hooks සඳහා `maxRetries` අගය නිරාවරණය කර ඇත.

දැනට, නැවත උත්සාහ කිරීම් skill handler එක තුළම ක්රියාත්මක කළ යුතුය. ගොඩනඟා ඇති
skills, executor එක සමඟ ලියාපදිංචි කර ඇත (උදා. `registerBuiltinSkills(executor)`
/ `registerBrowserSkill(executor)` `src/lib/skills/builtin/` තුළ); ඔබ ලියාපදිංචි කරන ඕනෑම handler එකකට
තමන්ගේම නැවත උත්සාහ කිරීමේ loop එකක් ආවරණය කළ හැකිය:

```ts
// skill handler එකක් තුළ
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

## SkillMode පිළිබඳ සවිස්තරාත්මක විස්තරය

`SkillMode` enum එක (`src/lib/skills/types.ts`) මඟින් කුසලතා ක්රියාත්මක කරන්නේ **කවදාද සහ කෙසේද** යන්න පාලනය කරයි:

```ts
enum SkillMode {
  AUTO = "auto", // කුසලතාව කැඳවිය යුත්තේ කවදාදැයි LLM තීරණය කරයි
  MANUAL = "manual", // පැහැදිලි පරිශීලක ඉල්ලීමක් මඟින් පමණක් ක්රියාත්මක කෙරේ
  HYBRID = "hybrid", // AUTO ලකුණුකරණය + අතින් අතික්රමණය කිරීම
}
```

> **සටහන**: කේත පදනම `SkillMode` (AUTO/MANUAL/HYBRID) නිර්වචනය කරන අතර, `Skill.mode` ක්ෂේත්රය වෙනස් ආකෘතියක් (`"on" | "off" | "auto"`) භාවිත කරයි. ඒවා එකිනෙකට සම්බන්ධ නමුත් සර්වසම නොවේ — `SkillMode` යනු ක්රියාත්මක කිරීමේ ප්රතිපත්තිය සඳහා වන අතර, `Skill.mode` යනු එක් එක් කුසලතාව සක්රීය කිරීම සඳහා වේ.

### එක් එක් මාදිලිය භාවිත කළ යුත්තේ කවදාද

| මාදිලිය  | LLM හැසිරීම                                                                                | භාවිත අවස්ථාව                                  |
| -------- | ------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| `AUTO`   | අවශ්ය යැයි සලකන විට LLM හට කුසලතාව කැඳවිය හැක                                              | පොදු කාර්ය කුසලතා (ගොනු කියවීම, HTTP ඉල්ලීම්)  |
| `MANUAL` | LLM හට කුසලතාව කැඳවිය නොහැක; එය ක්රියාත්මක කරන්නේ පැහැදිලි `executeSkill` API ඇමතුමක් පමණි | සංවේදී මෙහෙයුම් (දත්ත සමුදායට ලිවීම, ගෙවීම්)   |
| `HYBRID` | LLM හට කුසලතාව යෝජනා කළ හැක; පරිශීලකයා එය තහවුරු කළ යුතුය                                  | අතුරු ප්රතිඵල ඇති නමුත් අනතුරුදායක නොවන කුසලතා |

### AUTO ලකුණුකරණය

`AUTO` මාදිලිය සක්රීයව ඇති විට, එක් එක් අපේක්ෂක කුසලතාව ඉල්ලීම්
සන්දර්භයට සාපේක්ෂව `src/lib/skills/injection.ts` තුළ ඇති `scoreAutoSkill()` මඟින් ලකුණු කෙරේ — මෙය එකතු කිරීමේ,
පූර්ණ සංඛ්යා ලකුණු පද්ධතියකි (කුසලතා නාම ගැළපීම, නම/ටැගය/විස්තරයේ ටෝකන අතිච්ඡාදනය,
පසුබිම්-හේතු ඉඟි, සැපයුම්කරු-ඉඟි ප්රසාද/දඬුවම්). `score >= AUTO_MIN_SCORE = 3` සහිත ඉහළම
`AUTO_MAX_SKILLS = 5` කුසලතා, කැඳවිය හැකි මෙවලම් ලෙස
ඇතුළත් කෙරෙන අතර, සමාන ලකුණු ඇති විට පළමුව `installCount` මඟින්ද පසුව නම මඟින්ද අනුපිළිවෙළ තීරණය කෙරේ. සම්පූර්ණ ලකුණු වගුව මෙම ලේඛනයේ කලින් ඇති
[**මෙවලම් ස්කීමා උත්පාදනය → AUTO ලකුණුකරණය**](#auto-scoring) තුළ බලන්න;
float `0.6` ආකාරයේ සීමාවක් හෝ `registry.ts` ලකුණුකරණයක් නොමැත.

## අන්තර්ගත කුසලතා නාමාවලිය

OmniRoute සමඟ `src/lib/skills/builtin/` තුළ තෝරා සකස් කළ අන්තර්ගත කුසලතා කට්ටලයක් සැපයේ. වඩාත් පොදු ඒවා:

### බ්රව්සර් ස්වයංක්රීයකරණ කුසලතාව

බ්රව්සර් කුසලතාව (`src/lib/skills/builtin/browser.ts`) Playwright/Puppeteer හරහා headless බ්රව්සර් ස්වයංක්රීයකරණය සපයයි. **එය ක්රියාත්මක කර ඇති නමුත් පෙරනිමි කුසලතා නාමාවලියෙහි ඇතුළත් නොවේ** — එය භාවිත කිරීමට, බ්රව්සර් දිගු ප්ලගිනය වෙනම ස්ථාපනය කරන්න.

```ts
// ඔබගේ වින්යාසය තුළ සක්රීය කරන්න
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // සැමවිටම පැහැදිලි කැඳවීමක් අවශ්ය කරන්න
  allowedSkills: ["browser"],
  timeout: 60000, // පිටු පූරණය සඳහා තත්පර 60ක්
  maxRetries: 1,
};
```

### අනෙකුත් අන්තර්ගත ප්රවර්ග

| ප්රවර්ගය             | කුසලතා                                              | මාදිලිය |
| -------------------- | --------------------------------------------------- | ------- |
| ගොනු I/O             | `file_read`, `file_write`                           | AUTO    |
| HTTP                 | `http_request`                                      | AUTO    |
| සෙවීම                | `web_search`                                        | AUTO    |
| කේත ක්රියාත්මක කිරීම | `eval_code` (sandbox කළ JavaScript/Python)          | HYBRID  |
