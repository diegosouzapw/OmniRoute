## វិធាន

- គោលដៅគ្របដណ្តប់អនុវត្តចំពោះឯកសារកូដប្រភព មិនមែន `tests/**` ទេ។
- `open-sse/**` គឺជាផ្នែកមួយនៃផលិតផល ហើយត្រូវតែស្ថិតក្នុងវិសាលភាព។
- កូដថ្មីមិនគួរកាត់បន្ថយការគ្របដណ្តប់នៅក្នុងតំបន់ដែលបានកែប្រែឡើយ។
- ផ្តល់អាទិភាពដល់ការធ្វើតេស្តឥរិយាបថ និងលទ្ធផលសាខា ជាជាងព័ត៌មានលម្អិតនៃការអនុវត្ត។
- សម្រាប់ `src/lib/db/**` គួរប្រើមូលដ្ឋានទិន្នន័យ SQLite បណ្តោះអាសន្ន និងទិន្នន័យសាកល្បងតូចៗ ជាជាងការក្លែងធ្វើទូលំទូលាយ។

- `npm run coverage:report`

- `npm run test:coverage:legacy`

## គោលការណ៍ Ratchet

ធ្វើបច្ចុប្បន្នភាពកម្រិតអប្បបរមារបស់ `npm run test:coverage` តែបន្ទាប់ពីគម្រោងពិតជាលើសគោលដៅបន្ទាប់ ដោយមានគម្លាតសុវត្ថិភាពគ្រប់គ្រាន់ប៉ុណ្ណោះ។

**កម្រិតបច្ចុប្បន្ន៖** `npm run test:coverage` អនុវត្តកម្រិតអប្បបរមា **60 សេចក្តីបញ្ជា / 60 បន្ទាត់ / 60 មុខងារ / 60 សាខា** (ម៉ែត្រនេះត្រូវបានកំណត់មូលដ្ឋានឡើងវិញក្នុង Quality-Gates Fase 6A.1 — មូលដ្ឋាន 82.58% ពីមុនត្រូវបានបំប៉ោង ពីព្រោះវាបានរាប់បញ្ចូលឯកសារសាកល្បង និងមិនបានរាប់បញ្ចូល `open-sse`)។ ពាក្យបញ្ជា `test:coverage:legacy` រក្សាទុកម៉ែត្រចាស់ 50/50/50 សម្រាប់ការប្រៀបធៀបជាប្រវត្តិសាស្ត្រ។

សម្រាប់ការត្រួតពិនិត្យកម្រិតអប្បបរមាបែបម្តងម្កាល ដោយផ្អែកលើរបាយការណ៍ចុងក្រោយ សូមប្រើ៖
