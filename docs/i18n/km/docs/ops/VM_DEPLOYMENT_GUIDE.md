## 1. កំណត់រចនាសម្ព័ន្ធ VM

### 1.1 បង្កើត instance

នៅលើអ្នកផ្តល់សេវា VPS ដែលអ្នកពេញចិត្ត៖

- ជ្រើសរើស Ubuntu 24.04 LTS
- ជ្រើសរើសគម្រោងអប្បបរមា (1 vCPU / 1 GB RAM)
- កំណត់ពាក្យសម្ងាត់ root ដែលរឹងមាំ ឬកំណត់រចនាសម្ព័ន្ធ SSH key
- កត់ត្រា **IP សាធារណៈ** (ឧ. `203.0.113.10`)

### 1.2 តភ្ជាប់តាមរយៈ SSH

```bash
ssh root@203.0.113.10
```

### 1.3 ធ្វើបច្ចុប្បន្នភាពប្រព័ន្ធ

```bash
apt update && apt upgrade -y
```

### 1.4 ដំឡើង Docker

```bash
# ដំឡើង dependencies
apt install -y ca-certificates curl gnupg

# បន្ថែម repository ផ្លូវការរបស់ Docker
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 ដំឡើង nginx

```bash
apt install -y nginx
```

### 1.6 កំណត់រចនាសម្ព័ន្ធ Firewall (UFW)

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (បញ្ជូនបន្ត)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **គន្លឹះ**: ដើម្បីទទួលបានសុវត្ថិភាពអតិបរមា សូមដាក់កំហិតច្រក 80 និង 443 ឱ្យប្រើបានតែជាមួយ IP របស់ Cloudflare ប៉ុណ្ណោះ។ សូមមើលផ្នែក [សុវត្ថិភាពកម្រិតខ្ពស់](#advanced-security)។

## 2. ដំឡើង OmniRoute

### 2.1 បង្កើតថតកំណត់រចនាសម្ព័ន្ធ

```bash
mkdir -p /opt/omniroute
```

### 2.2 បង្កើតឯកសារ environment variables

```bash
cat > /opt/omniroute/.env << 'EOF'
# === សុវត្ថិភាព ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # តម្រូវឱ្យមានក្នុង production៖ ប្រើដោយ Codex Responses WS bridge

# === កម្មវិធី ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URLs (ប្តូរទៅជាដូមែនរបស់អ្នក) ===
# URL មូលដ្ឋានខាងក្នុងពី server ទៅ server សម្រាប់ការងារដែលបានកំណត់ពេល / self-fetches។
BASE_URL=http://127.0.0.1:20128
# URL ដែលបង្ហាញដល់ browser និងប្រើសម្រាប់ OAuth callbacks, តំណ dashboard និង URL សាធារណៈដែលបានបង្កើត។
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# ជម្រើសកំណត់ជាក់លាក់នូវ public origin ជំនួស សម្រាប់ URL ទ្រព្យសកម្មសាធារណៈដែលបានបង្កើត។
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Cloud Sync (ជាជម្រើស) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **សំខាន់**: សូមបង្កើត secret key ដែលមានលក្ខណៈពិសេសមិនស្ទួនគ្នា! ប្រើ `openssl rand -hex 32` សម្រាប់ key នីមួយៗ។

### 2.3 ចាប់ផ្តើម container

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 ផ្ទៀងផ្ទាត់ថាវាកំពុងដំណើរការ

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

វាគួរតែបង្ហាញ៖ `[DB] SQLite database ready` និង `listening on port 20128`។

## 3. កំណត់រចនាសម្ព័ន្ធ nginx (Reverse Proxy)

### 3.1 បង្កើតវិញ្ញាបនបត្រ SSL (Cloudflare Origin)

នៅក្នុងផ្ទាំងគ្រប់គ្រង Cloudflare៖

1. ចូលទៅកាន់ **SSL/TLS → Origin Server**
2. ចុច **Create Certificate**
3. រក្សាការកំណត់លំនាំដើម (15 ឆ្នាំ, \*.yourdomain.com)
4. ចម្លង **Origin Certificate** និង **Private Key**

```bash
mkdir -p /etc/nginx/ssl

# បិទភ្ជាប់វិញ្ញាបនបត្រ
nano /etc/nginx/ssl/origin.crt

# បិទភ្ជាប់សោឯកជន
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 ការកំណត់រចនាសម្ព័ន្ធ Nginx

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# ម៉ាស៊ីនមេលំនាំដើម — ទប់ស្កាត់ការចូលប្រើដោយផ្ទាល់តាមរយៈ IP
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # ប្តូរទៅដែនរបស់អ្នក

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # ការគាំទ្រ WebSocket
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (ព្រឹត្តិការណ៍ដែលផ្ញើពីម៉ាស៊ីនមេ) — ការស្ទ្រីមការឆ្លើយតបរបស់ AI
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# បញ្ជូនបន្តពី HTTP → HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

រក្សារយៈពេលអស់ពេលនៃស្ទ្រីម reverse-proxy ឱ្យស្របគ្នានឹងអថេរបរិស្ថានកំណត់ពេលអស់របស់ OmniRoute។ ប្រសិនបើអ្នកដំឡើងតម្លៃ
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` ត្រូវដំឡើង `proxy_read_timeout` / `proxy_send_timeout`
ឱ្យខ្ពស់ជាងកម្រិតដូចគ្នា។

OmniRoute ប្រើ `NEXT_PUBLIC_BASE_URL` ជា origin ផ្លូវការដែលបង្ហាញចំពោះកម្មវិធីរុករក សម្រាប់ OAuth
callbacks និងតំណសាធារណៈដែលបានបង្កើត។ ប្រតិបត្តិការសរសេរនៅលើផ្ទាំងគ្រប់គ្រងដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ ប្រើសំណើ same-origin
រួមជាមួយការការពារ CSRF ដែលភ្ជាប់នឹង session ដូច្នេះវាមិនត្រូវការ URL មូលដ្ឋានសាធារណៈថេរទេ។ Headers
`X-Forwarded-*` ខាងលើនៅតែជាទិន្នន័យមេតាសម្រាប់ការកំណត់ផ្លូវដែលមានប្រយោជន៍ ប៉ុន្តែវាមិនមែនជាការជំនួស
សម្រាប់ការកំណត់ URL សាធារណៈជាក់លាក់នោះទេ នៅពេលដែល OAuth ឬតំណកម្មវិធីរុករកដែលបានបង្កើតត្រូវការវា។ បើកតែ
`OMNIROUTE_TRUST_PROXY` ប៉ុណ្ណោះ ប្រសិនបើអតិថិជនមិនអាចចូលប្រើ OmniRoute ដោយផ្ទាល់បាន ហើយ proxy របស់អ្នក
ដកចេញ/បង្កើតឡើងវិញនូវ headers ដែលបានបញ្ជូនបន្តចូលមក។
