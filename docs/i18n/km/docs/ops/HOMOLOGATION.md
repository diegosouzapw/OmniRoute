## តម្រូវការជាមុន

1. ចម្លង `.env.homolog.example` ទៅជា `.env.homolog` (ត្រូវបាន git មិនអើពើ — កុំ commit វាដាច់ខាត) ហើយបំពេញ៖
   - `HOMOLOG_BASE_URL` — deploy គោលដៅ ឧ. `http://192.168.0.15:20128`។
   - `HOMOLOG_ADMIN_PASSWORD` — ពាក្យសម្ងាត់គ្រប់គ្រង dashboard សម្រាប់ deploy នោះ។
   - `HOMOLOG_CRITICAL_PROVIDERS` — បុព្វបទ provider ដែលបំបែកដោយសញ្ញាក្បៀស និងទទួលបានសំណើ smoke chat ពិតប្រាកដ (ឧ. `openai,anthropic,gemini,codex,grok,glm,deepseek,openrouter`)។
   - `HOMOLOG_API_KEY` — ទុកឱ្យទទេក្នុងការដំណើរការធម្មតា; suite នឹងបង្កើត និងដកហូត ephemeral key របស់វាដោយខ្លួនឯង។ កំណត់តម្លៃនេះតែក្នុងករណី debug ស្រទាប់តែមួយដោយឯកោប៉ុណ្ណោះ។
2. ដំណើរការ `npm install` ក្នុង repo (dependencies របស់ suite — `httpyac`, `promptfoo`, `playwright-ctrf-json-reporter`, `junit-to-ctrf`, `ctrf` — គឺជា devDependencies ធម្មតា)។
3. ដំណើរការ `npx playwright install` ប្រសិនបើ browser binaries មិនទាន់មាន។

## របៀបដំណើរការ

```bash
npm run homolog
```

ដើម្បីផ្ទៀងផ្ទាត់ជាមួយ deploy ដែលកំណែរបស់វាមិនត្រូវគ្នានឹង `package.json` មូលដ្ឋាន (ឧ. ម៉ាស៊ីន homologation ដែលនៅតែប្រើ patch release មុន) សូម override កំណែដែលរំពឹងទុកយ៉ាងច្បាស់៖

```bash
HOMOLOG_EXPECT_VERSION=3.8.47 npm run homolog
```

ការដំណើរការនឹងបញ្ចប់ដោយ non-zero ប្រសិនបើស្រទាប់ណាមួយបរាជ័យ ហើយតែងតែព្យាយាមដកហូត ephemeral API key ដែលវាបានបង្កើត ទោះបីជាបរាជ័យក៏ដោយ (`finally` block ក្នុង `scripts/homolog/run.mjs`)។

## ការអានរបាយការណ៍

លទ្ធផលទាំងអស់ត្រូវបានរក្សាទុកក្នុង `homolog-report/` (ត្រូវបាន git មិនអើពើ)៖

- `summary.md` — តារាងដូចគ្នាដែលបានបង្ហាញទៅ stdout ដោយមានមួយជួរសម្រាប់ស្រទាប់នីមួយៗ (✅/❌ + ព័ត៌មានលម្អិត)។
- `homolog-ctrf.json` — របាយការណ៍ CTRF រួមបញ្ចូលគ្នា (ការបញ្ចូលគ្នានៃលទ្ធផល API/SSE, provider-smoke និង UI) — នេះជាវត្ថុភ្ជាប់ដែលត្រូវភ្ជាប់ទៅនឹងបញ្ជីត្រួតពិនិត្យ STOP #2 របស់ release។
- `httpyac-junit.xml`, `api-ctrf.json`, `providers-ctrf.json`, `ui-ctrf.json` — របាយការណ៍ដើម/អន្តរការីតាមស្រទាប់នីមួយៗ។
- `promptfooconfig.yaml`, `provider-misses.json` — config របស់ promptfoo ដែលបានបង្កើតសម្រាប់ការដំណើរការបច្ចុប្បន្ន និង critical providers ណាមួយដែលបាត់ពី catalog កំពុងដំណើរការ។

ការបរាជ័យរបស់ L0 នឹងបញ្ឈប់ភ្លាមៗ (មិនមាន ephemeral key ត្រូវបានបង្កើតទេ) ពីព្រោះភាពមិនត្រូវគ្នានៃកំណែ/សុខភាព មានន័យថាស្រទាប់បន្ទាប់ទាំងអស់នឹងកំពុងផ្ទៀងផ្ទាត់ deploy ខុស។

## ការកំណត់ baseline ឡើងវិញ នៅពេល UI ផ្លាស់ប្តូរដោយស្របច្បាប់

L4b (route smoke) និង L4c (លំហូរ UI របស់ API-key) ដំណើរការដោយ DOM locators ពិតប្រាកដ មិនមែន snapshots ទេ ដូច្នេះការផ្លាស់ប្តូរ UI ដែលស្របច្បាប់ភាគច្រើនមិនតម្រូវឱ្យធ្វើបច្ចុប្បន្នភាព suite ឡើយ។ នៅពេលការផ្លាស់ប្តូរមួយធ្វើឱ្យ locator ខូច (ឧ. ស្លាកប៊ូតុងដែលបានប្តូរឈ្មោះ ឬទំព័រការកំណត់ដែលបានផ្លាស់ទី)៖

1. ផ្ទៀងផ្ទាត់ locator ឡើងវិញជាមួយ source បច្ចុប្បន្ន (specs បានកត់ត្រារួចហើយថា locator នីមួយៗត្រូវបានផ្ទៀងផ្ទាត់ជាមួយ file/line មួយណា — អនុវត្តតាមលំនាំដដែល កុំស្មាន)។
2. ធ្វើបច្ចុប្បន្នភាព spec ក្នុង `tests/homolog/ui/`។
3. ដំណើរការ `npm run homolog` ឡើងវិញ (ឬគ្រាន់តែ Playwright spec ដែលរងផលប៉ះពាល់) ជាមួយ VPS ដើម្បីបញ្ជាក់ការកែតម្រូវ រួច commit។

មិនមាន visual/pixel baseline នៅក្នុង suite នេះទេ (F1) — សូមមើល Roadmap សម្រាប់ផ្នែកនោះ។

## ផែនទីបង្ហាញផ្លូវ (F2 / F3)

ការរចនា និងការដាក់ឱ្យប្រើប្រាស់ជាដំណាក់កាលមាននៅក្នុង planning spec ផ្ទៃក្នុង `_tasks/superpowers/specs/2026-07-13-homolog-e2e-suite-design.md` (មិនមាន link ទេ — ជាវត្ថុ `_tasks/` ផ្ទៃក្នុង មិនមែនជាផ្នែកនៃឯកសារដែលត្រូវបានតាមដានរបស់ repo នេះទេ)។ សេចក្តីសង្ខេប៖

- **F2** — ការថត walkthrough ពេញលេញ → Playwright Test Agents (`planner`/`generator`) បំប្លែងវាទៅជា flow specs (បង្កើត combo, សាកល្បង provider, កែសម្រួលការកំណត់, MCP tools) + visual regression baseline (Lost Pixel) ដែលមាន masks លើទិន្នន័យ dynamic (metrics, timestamps, logs) + routine ថែទាំ `healer` សម្រាប់ release នីមួយៗ។
- **F3** — វិសាលភាព resilience/contract/wiring៖ toxiproxy + provider ដែលត្រូវគ្នាជាមួយ OpenAI ក្លែងក្លាយនៅលើ devbox, combo `homolog-resilience` នៅលើ VPS ដែលចង្អុលទៅវា (បញ្ចូល timeout → អះអាង fallback + circuit breaker បើក/បិទតាម `/api/monitoring/health`); ការធ្វើតេស្ត contract ដោយ Schemathesis ដែលមាន gate ជាមួយ `docs/openapi.yaml` (`--max-examples` ទាប, seeds ថេរ, តែ endpoints ដែលមិនមែនជា LLM); និងការភ្ជាប់ `npm run homolog` + `summary.md` របស់វាទៅក្នុងដំណាក់កាល STOP #2 របស់ `/generate-release`។
