## ការរៀបចំ

1. **ដំណើរការ OmniRoute** — `npm install -g omniroute && omniroute` (ផ្ទាំងគ្រប់គ្រងនៅ `http://localhost:20128`)។
2. **ដំឡើងផ្នែកបន្ថែម** — ស្វែងរក "OmniRoute" ក្នុងទិដ្ឋភាព Extensions។
3. **ជ្រើសរើសម៉ូដែល** — Copilot Chat → កម្មវិធីជ្រើសរើសម៉ូដែល → **គ្រប់គ្រងម៉ូដែល…** → **OmniRoute** បន្ទាប់មកធីក
   អ្វីដែលអ្នកចង់ប្រើ។

មិនចាំបាច់កំណត់រចនាសម្ព័ន្ធអ្វីទេ នៅពេល OmniRoute ដំណើរការលើ port លំនាំដើម។ សម្រាប់ instance ពីចម្ងាយ សូមបើក
**រូបតំណាង OmniRoute ក្នុង Activity Bar** (ឬដំណើរការ `OmniRoute: Manage Connection`) ហើយកំណត់៖

- **URL របស់ម៉ាស៊ីនមេ** — root របស់ម៉ាស៊ីនមេ ឧ. `http://192.168.0.15:20128`។ បច្ច័យ `/v1` នឹងត្រូវបាន
  បន្ថែមដោយផ្នែកបន្ថែម ដូច្នេះកុំបញ្ចូលវា។
- **API key** — តែនៅពេលម៉ាស៊ីនមេកំណត់ `REQUIRE_API_KEY` ប៉ុណ្ណោះ។ វាត្រូវបានរក្សាទុកក្នុង keychain របស់ OS តាមរយៈ VS
  Code SecretStorage ហើយមិនដែលរក្សាទុកក្នុង `settings.json` ទេ។

## អ្វីដែលកម្មវិធីជ្រើសរើសនឹងបង្ហាញ

ផ្នែកបន្ថែមមិនបង្ហាញ payload ដើមរបស់ `GET /v1/models` ទេ — វារៀបចំទ្រង់ទ្រាយ payload នោះ ហើយចំនួនដែលអ្នក
ឃើញនឹងតិចជាងទំហំ catalog ដោយសារហេតុផលចេតនាពីរ។

### វាស្នើសុំ id មួយសម្រាប់ម៉ូដែលនីមួយៗ

`MODELS_CATALOG_PREFIX_MODE` មានលំនាំដើមជា **`dual`** ដែលផ្សព្វផ្សាយម៉ូដែលនីមួយៗពីរដង — ម្តង
ក្រោម alias prefix ខ្លី និងម្តងក្រោម canonical provider prefix — ដូច្នេះការកំណត់របស់ client ចាស់ៗ
នៅតែអាចដោះស្រាយទម្រង់ទាំងពីរបាន៖

```
cc/claude-sonnet-4-6        ← alias prefix
claude/claude-sonnet-4-6    ← canonical prefix, ម៉ូដែលដូចគ្នា
```

ផ្នែកបន្ថែមស្នើសុំ **`GET /v1/models?prefix=alias`** ដើម្បីឱ្យទទួលបាន id មួយសម្រាប់ម៉ូដែលនីមួយៗ ដោយមិន
ផ្លាស់ប្តូរការកំណត់ទូទាំងម៉ាស៊ីនមេសម្រាប់ client ផ្សេងទៀតរបស់អ្នក។ លើ instance យោងមួយ វាបានកាត់បន្ថយ
**ពី 2345 ធាតុមកត្រឹម 1396 — 949 ជាធាតុស្ទួន ដោយមិនបាត់ម៉ូដែលណាមួយឡើយ។**

ប្រសិនបើអ្នកចង់កែវានៅកម្រិតទូទាំងម៉ាស៊ីនមេសម្រាប់ client _ទាំងអស់_ សូមកំណត់ feature flag
`MODELS_CATALOG_PREFIX_MODE` ទៅជា `alias` ក្នុងផ្ទាំងគ្រប់គ្រង។ សូមមើល
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) សម្រាប់
query parameter និងតារាងតាម mode នីមួយៗ។

### វាលាក់ម៉ូដែលដែលមិនអាចជជែកបាន

Catalog ក៏រាយបញ្ជីម៉ូដែលរូបភាព វីដេអូ អូឌីយ៉ូ rerank, embedding និង moderation ផងដែរ។ ម៉ូដែលទាំងនោះ
នឹងត្រូវបដិសេធនៅពេលមានសំណើជជែកទោះយ៉ាងណាក៏ដោយ៖

```
HTTP 400 — ម៉ូដែល '<id>' គឺជាម៉ូដែលបង្កើតរូបភាព ហើយមិនអាចប្រើលើ
/v1/chat/completions បានទេ។ សូមប្រើ POST /v1/images/generations ជំនួសវិញ។
```

ដូច្នេះ វាត្រូវបានច្រោះចេញតាម field `type` របស់វា មុនពេលទៅដល់កម្មវិធីជ្រើសរើស។ **ម៉ូដែល Responses-API
ត្រូវបានរក្សាទុក** — រាល់ធាតុ Codex / GPT-5.x ផ្សព្វផ្សាយ `supported_endpoints: ["responses"]`
ហើយ OmniRoute បម្លែងវាសម្រាប់ `/v1/chat/completions` ដូច្នេះវាអាចប្រើបានយ៉ាងពេញលេញ។

### អ្នកផ្តល់សេវាដែលអ្នកមិនធ្លាប់កំណត់រចនាសម្ព័ន្ធ

Catalog រាយបញ្ជីម៉ូដែលពីអ្នកផ្តល់សេវាដែលមាន **ការតភ្ជាប់សកម្ម** _រួមទាំង_ អ្នកផ្តល់សេវា **noAuth**
ទាំងអស់ — ពោលគឺអ្នកផ្តល់សេវាដែលមិនត្រូវការ key និងបង្កើតបានជាផ្នែកធំនៃកម្រិតឥតគិតថ្លៃ។ នេះគឺជាចេតនា។ ដើម្បីលាក់
ពួកវា សូមបន្ថែមពួកវាទៅ `blockedProviders` ក្នុងការកំណត់ផ្ទាំងគ្រប់គ្រង; មិនមានអ្វីផ្លាស់ប្តូរក្នុង
ផ្នែកបន្ថែមទេ។

## ផ្ទាំងគ្រប់គ្រងនៅក្នុងផ្ទាំង VS Code

`omnicopilot.dashboardOpen: "editor"` បង្ហាញផ្ទាំងគ្រប់គ្រង OmniRoute នៅក្នុងផ្ទាំងកម្មវិធីកែសម្រួលតាមរយៈ
Simple Browser ជំនួសឱ្យកម្មវិធីរុករកខាងក្រៅ។ ការបង្កប់ត្រូវតែ **ជ្រើសរើសបើកនៅលើម៉ាស៊ីនមេ** តាមរយៈ
`DASHBOARD_ALLOW_EMBED=vscode` ដែលបម្រើទំព័រ HTML ជាមួយ
`frame-ancestors 'self' vscode-webview:` ជំនួសឱ្យលំនាំដើម `frame-ancestors 'none'` +
`X-Frame-Options: DENY`។ ផ្ទៃ API (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) នៅតែរក្សា
បឋមកថាដ៏តឹងរ៉ឹងដដែល ទោះជាក្នុងករណីណាក៏ដោយ។

> ⚠️ **វាជាទង់ពេលស្ថាបនា មិនមែនទង់ពេលដំណើរការទេ។** Next.js ចងក្រង `headers()` ទៅក្នុងបញ្ជីផ្លូវ
> ដូច្នេះ `next.config.mjs` អានអថេរនេះ ខណៈពេលកញ្ចប់កំពុងត្រូវបានស្ថាបនា
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`)។
> ការនាំចេញវាមុនពេលដំណើរការម៉ាស៊ីនមេដែលបានស្ថាបនារួច មិនផ្លាស់ប្តូរអ្វីឡើយ — បឋមកថាត្រូវបានបញ្ចូលថេររួចហើយ។

```bash
# អថេរត្រូវតែមាននៅក្នុងពាក្យបញ្ជា BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ឬ npm run build:release
npm start
```
