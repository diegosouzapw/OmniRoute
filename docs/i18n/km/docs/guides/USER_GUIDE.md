## 🎯 ករណីប្រើប្រាស់

### ករណីទី 1៖ "ខ្ញុំមានការជាវ Claude Pro"

**បញ្ហា៖** កូតាផុតកំណត់ដោយមិនបានប្រើ និងជួបដែនកំណត់អត្រាក្នុងអំឡុងពេលសរសេរកូដខ្លាំង

```
បន្សំ៖ "maximize-claude"
  1. cc/claude-opus-4-7        (ប្រើការជាវឱ្យអស់លទ្ធភាព)
  2. glm/glm-4.7               (ជម្រើសបម្រុងតម្លៃទាប នៅពេលកូតាអស់)
  3. if/qwen3.8-max-preview       (ជម្រើសបម្រុងបន្ទាន់ឥតគិតថ្លៃ)

តម្លៃប្រចាំខែ៖ $20 (ការជាវ) + ~$5 (ជម្រើសបម្រុង) = សរុប $25
ធៀបនឹង $20 + ការប៉ះដែនកំណត់ = ភាពធុញថប់
```

### ករណីទី 2៖ "ខ្ញុំចង់បានតម្លៃសូន្យ"

**បញ្ហា៖** មិនមានលទ្ធភាពបង់ថ្លៃការជាវ និងត្រូវការ AI សរសេរកូដដែលអាចទុកចិត្តបាន

```
បន្សំ៖ "zero-cost"
  1. if/kimi-k2.7-code          (បានរាយថាមានការចូលប្រើឥតគិតថ្លៃ; អាចមានដែនកំណត់អត្រា)
  2. kr/qwen3-coder-next        (ជម្រើសបម្រុង Kiro ឥតគិតថ្លៃ)

តម្លៃប្រចាំខែ៖ $0
គុណភាព៖ ផ្ទៀងផ្ទាត់ម៉ូដែល ដែនកំណត់ ឯកជនភាព និង SLA សម្រាប់បន្ទុកការងាររបស់អ្នក
```

### ករណីទី 3៖ "ខ្ញុំត្រូវការការសរសេរកូដ 24/7 ដោយគ្មានការរំខាន"

**បញ្ហា៖** មានកាលកំណត់ និងមិនអាចទទួលយកពេលវេលាផ្អាកដំណើរការបាន

```
បន្សំ៖ "always-on"
```

### ការដំឡើង npm ជាសកល (បានណែនាំ)

```bash
npm install -g omniroute

# បង្កើតថតកំណត់រចនាសម្ព័ន្ធ
mkdir -p ~/.omniroute

# បង្កើតឯកសារ .env (សូមមើល .env.example)
cp .env.example ~/.omniroute/.env

# ចាប់ផ្តើមម៉ាស៊ីនមេ
omniroute

omniroute --port 3000
```

CLI ផ្ទុក `.env` ដោយស្វ័យប្រវត្តិពី `~/.omniroute/.env` ឬ `./.env`។

### របៀប Tray

ចាប់ផ្តើម OmniRoute ក្នុងថាសប្រព័ន្ធ៖

```bash
omniroute serve --tray
```

ពាក្យបញ្ជានឹងបញ្ចប់បន្ទាប់ពីម៉ាស៊ីនមេ និង tray រួចរាល់។

ម៉ាស៊ីនមេបន្តដំណើរការដោយមិនចាំបាច់មាន terminal។

របៀប Tray គាំទ្រ macOS, Windows និងសម័យ Linux ដែលមានចំណុចប្រទាក់ក្រាហ្វិក។ របៀប Tray មិនបើកផ្ទាំងគ្រប់គ្រងដោយស្វ័យប្រវត្តិទេ។

ប្រើម៉ឺនុយ tray សម្រាប់សកម្មភាពទាំងនេះ៖

- បើកផ្ទាំងគ្រប់គ្រង។
- បើក `/dashboard/logs`។
- ផ្លាស់ប្តូរការចាប់ផ្តើមដោយស្វ័យប្រវត្តិ។
- បញ្ឈប់ OmniRoute។

កុំប្រើ `--tray` រួមជាមួយជម្រើសទាំងនេះ៖

- `--daemon`
- `--log`
- `--no-recovery`

របៀបទាំងនេះតម្រូវឱ្យមានការគ្រប់គ្រងកម្មសិទ្ធិដំណើរការខុសៗគ្នា។

បើកការចាប់ផ្តើមនៅពេលចូលប្រើម៉ាស៊ីនលើកក្រោយ៖

```bash
omniroute autostart enable
```

ការចាប់ផ្តើមដោយស្វ័យប្រវត្តិប្រើរបៀប tray នៅលើ macOS, Windows និងសម័យ Linux ដែលមានចំណុចប្រទាក់ក្រាហ្វិក។ Linux ដែលគ្មានចំណុចប្រទាក់ក្រាហ្វិកប្រើសេវាអ្នកប្រើ systemd ដែលមានស្រាប់។

បិទការចាប់ផ្តើមនៅពេលចូលប្រើ៖

```bash
omniroute autostart disable
```

### ការលុបការដំឡើង

នៅពេលអ្នកលែងត្រូវការ OmniRoute យើងផ្តល់ស្គ្រីបរហ័សពីរសម្រាប់ការលុបចេញឱ្យស្អាត៖

| ពាក្យបញ្ជា               | សកម្មភាព                                                                                          |
| ------------------------ | ------------------------------------------------------------------------------------------------- |
| `npm run uninstall`      | លុបកម្មវិធីប្រព័ន្ធ ប៉ុន្តែ **រក្សាទុក DB និងការកំណត់រចនាសម្ព័ន្ធរបស់អ្នក** ក្នុង `~/.omniroute`។ |
| `npm run uninstall:full` | លុបកម្មវិធី ហើយ **លុបជាអចិន្ត្រៃយ៍នូវការកំណត់រចនាសម្ព័ន្ធ សោ និងមូលដ្ឋានទិន្នន័យទាំងអស់**។        |

> ចំណាំ៖ ដើម្បីដំណើរការពាក្យបញ្ជាទាំងនេះ សូមចូលទៅកាន់ថតគម្រោង OmniRoute (ប្រសិនបើអ្នកបាន clone វា) រួចដំណើរការពួកវា។ ជាជម្រើស ប្រសិនបើបានដំឡើងជាសកល អ្នកអាចដំណើរការ `npm uninstall -g omniroute` បានដោយផ្ទាល់។

### Void Linux (xbps-src)

អ្នកប្រើប្រាស់ Void Linux អាចវេចខ្ចប់ និងដំឡើង OmniRoute ដោយផ្ទាល់តាមប្រព័ន្ធ ដោយប្រើក្របខណ្ឌចងក្រងឆ្លងវេទិកា `xbps-src`។ វាធ្វើស្វ័យប្រវត្តិកម្មលើការបង្កើត Node.js standalone រួមជាមួយ native bindings របស់ `better-sqlite3` ដែលត្រូវការ។

<details>
<summary><b>មើលគំរូ xbps-src</b></summary>

```bash
# ឯកសារគំរូសម្រាប់ 'omniroute'
pkgname=omniroute
version=3.8.0
revision=1
hostmakedepends="nodejs python3 make"
depends="openssl"
short_desc="Universal AI gateway with smart routing for multiple LLM providers"
maintainer="zenobit <zenobit@disroot.org>"
license="MIT"
homepage="https://github.com/diegosouzapw/OmniRoute"
distfiles="https://github.com/diegosouzapw/OmniRoute/archive/refs/tags/v${version}.tar.gz"
checksum=009400afee90a9f32599d8fe734145cfd84098140b7287990183dde45ae2245b
system_accounts="_omniroute"
omniroute_homedir="/var/lib/omniroute"
export NODE_ENV=production
export npm_config_engine_strict=false
export npm_config_loglevel=error
export npm_config_fund=false
export npm_config_audit=false

do_build() {
	# កំណត់ស្ថាបត្យកម្ម CPU គោលដៅសម្រាប់ node-gyp
	local _gyp_arch
	case "$XBPS_TARGET_MACHINE" in
		aarch64*) _gyp_arch=arm64 ;;
		armv7*|armv6*) _gyp_arch=arm ;;
		i686*) _gyp_arch=ia32 ;;
		*) _gyp_arch=x64 ;;
	esac

	# 1) ដំឡើង dependencies ទាំងអស់ – រំលង scripts
	NODE_ENV=development npm ci --ignore-scripts

	# 2) បង្កើត Next.js standalone bundle
	npm run build

	# 3) ចម្លង static assets ទៅក្នុង standalone
	cp -r .next/static .next/standalone/.next/static
	[ -d public ] && cp -r public .next/standalone/public || true

	# 4) ចងក្រង native binding របស់ better-sqlite3
	local _node_gyp=/usr/lib/node_modules/npm/node_modules/node-gyp/bin/node-gyp.js
	(cd node_modules/better-sqlite3 && node "$_node_gyp" rebuild --arch="$_gyp_arch")

	# 5) ដាក់ binding ដែលបានចងក្រងទៅក្នុង standalone bundle
	local _bs3_release=.next/standalone/node_modules/better-sqlite3/build/Release
	mkdir -p "$_bs3_release"
	cp node_modules/better-sqlite3/build/Release/better_sqlite3.node "$_bs3_release/"

	# 6) លុប sharp bundles ដែលជាក់លាក់ចំពោះស្ថាបត្យកម្ម
	rm -rf .next/standalone/node_modules/@img

	# 7) ចម្លង runtime dependencies របស់ pino ដែលការវិភាគ static របស់ Next.js បានរំលង៖
	for _mod in pino-abstract-transport split2 process-warning; do
		cp -r "node_modules/$_mod" .next/standalone/node_modules/
	done
}

do_check() {
	npm run test:unit
}

do_install() {
	vmkdir usr/lib/omniroute/.next
	vcopy .next/standalone/. usr/lib/omniroute/.next/standalone

	# ទប់ស្កាត់ការលុបថត app router ទទេរបស់ Next.js ដោយ post-install hook
	for _d in \
		.next/standalone/.next/server/app/dashboard \
		.next/standalone/.next/server/app/dashboard/settings \
		.next/standalone/.next/server/app/dashboard/providers; do
		touch "${DESTDIR}/usr/lib/omniroute/${_d}/.keep"
	done

	cat > "${WRKDIR}/omniroute" <<'EOF'
#!/bin/sh
export PORT="${PORT:-20128}"
export DATA_DIR="${DATA_DIR:-${XDG_DATA_HOME:-${HOME}/.local/share}/omniroute}"
export APP_LOG_TO_FILE="${APP_LOG_TO_FILE:-false}"
mkdir -p "${DATA_DIR}"
exec node /usr/lib/omniroute/.next/standalone/server.js "$@"
EOF
	vbin "${WRKDIR}/omniroute"
}

post_install() {
	vlicense LICENSE
}
```

```bash
# តាមរយៈ API
curl -X POST http://localhost:20128/api/provider-models \
  -H "Content-Type: application/json" \
  -d '{"provider": "openai", "modelId": "gpt-5.2", "modelName": "GPT-5.2"}'

# បញ្ជី៖ curl http://localhost:20128/api/provider-models?provider=openai

```

ឬប្រើផ្ទាំងគ្រប់គ្រង៖ **អ្នកផ្តល់សេវា → [អ្នកផ្តល់សេវា] → ម៉ូដែលផ្ទាល់ខ្លួន**។

មានតែសំណើដែលផ្ញើទៅកាន់ URL របស់ដៃគូដែលបានដាក់ក្នុងបញ្ជីអនុញ្ញាតយ៉ាងច្បាស់ប៉ុណ្ណោះ ដែលនឹងទទួលបាន header `X-OmniRoute-Peer-Trace`។ ច្រកមួយនឹងបដិសេធ instance ID ដែលត្រូវបានប្រើម្តងទៀត ឬចំនួនតំណដែលអនុញ្ញាតត្រូវបានប្រើអស់ ដោយប្រើ HTTP `508 Loop Detected`; អ្នកផ្តល់សេវាខាងលើធម្មតានឹងមិនទទួលបាន metadata របស់ដៃគូឡើយ។

ការតភ្ជាប់ដៃគូជាច្រវាក់ មិនមែនជាការចម្លងមូលដ្ឋានទិន្នន័យ ឬការផ្ទេរបន្ទុកពេល host បរាជ័យនោះទេ។ ច្រកនីមួយៗរក្សាទុកស្ថានភាព SQLite, cache, កម្មវិធីរាប់អត្រា និង session ដោយឯករាជ្យ។ ប្រើ reverse proxy ដែលមានការត្រួតពិនិត្យសុខភាព ឬការផ្ទេរទៅជម្រើសបម្រុងនៅផ្នែក client សម្រាប់ភាពអាចប្រើបានបែប active/passive ឬ active/active ហើយកុំភ្ជាប់មូលដ្ឋានទិន្នន័យ SQLite តែមួយទៅក្នុង instance OmniRoute ជាច្រើនដែលកំពុងដំណើរការ។

### Route ផ្ទាល់សម្រាប់អ្នកផ្តល់សេវា

បញ្ជូនសំណើដោយផ្ទាល់ទៅកាន់អ្នកផ្តល់សេវាជាក់លាក់មួយ ដោយមានការផ្ទៀងផ្ទាត់ម៉ូដែល៖

```bash
POST http://localhost:20128/v1/providers/openai/chat/completions
POST http://localhost:20128/v1/providers/openai/embeddings
POST http://localhost:20128/v1/providers/fireworks/images/generations
```

បុព្វបទរបស់អ្នកផ្តល់សេវាត្រូវបានបន្ថែមដោយស្វ័យប្រវត្តិ ប្រសិនបើបាត់។ ម៉ូដែលដែលមិនត្រូវគ្នានឹងត្រឡប់ `400`។

### ការកំណត់រចនាសម្ព័ន្ធ Proxy បណ្ដាញ

```bash
# កំណត់ proxy សកល
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"global": {"type":"http","host":"proxy.example.com","port":"8080"}}'

# proxy តាមអ្នកផ្តល់សេវានីមួយៗ
curl -X PUT http://localhost:20128/api/settings/proxy \
  -d '{"providers": {"openai": {"type":"socks5","host":"proxy.example.com","port":"1080"}}}'

# សាកល្បង proxy
curl -X POST http://localhost:20128/api/settings/proxy/test \
  -d '{"proxy":{"type":"socks5","host":"proxy.example.com","port":"1080"}}'
```

**លំដាប់អាទិភាព៖** ជាក់លាក់តាម key → ជាក់លាក់តាម combo → ជាក់លាក់តាមអ្នកផ្តល់សេវា → សកល → Environment។

- ការធ្វើសមកាលកម្មផ្ទៃខាងក្រោយដោយស្វ័យប្រវត្តិ ជាមួយ timeout + fail-fast
- នៅក្នុង production គួរប្រើ `NEXT_PUBLIC_BASE_URL`/`NEXT_PUBLIC_CLOUD_URL` នៅផ្នែក server

### Cloudflare Quick Tunnel

- មាននៅក្នុង **ផ្ទាំងគ្រប់គ្រង → Endpoint** សម្រាប់ Docker និងការដាក់ឱ្យដំណើរការដែលបង្ហោះដោយខ្លួនឯងផ្សេងទៀត
- បង្កើត URL `https://*.trycloudflare.com` បណ្តោះអាសន្ន ដែលបញ្ជូនបន្តទៅកាន់ endpoint `/v1` បច្ចុប្បន្នរបស់អ្នកដែលឆបគ្នាជាមួយ OpenAI
- ការបើកជាលើកដំបូងនឹងដំឡើង `cloudflared` តែនៅពេលចាំបាច់ប៉ុណ្ណោះ; ការចាប់ផ្ដើមឡើងវិញនៅពេលក្រោយនឹងប្រើ binary ដែលបានគ្រប់គ្រងដដែល
- Quick Tunnel មិនត្រូវបានស្ដារឡើងវិញដោយស្វ័យប្រវត្តិបន្ទាប់ពី OmniRoute ឬ container ចាប់ផ្ដើមឡើងវិញទេ; បើកវាឡើងវិញពីផ្ទាំងគ្រប់គ្រងនៅពេលចាំបាច់
- URL របស់ tunnel គឺបណ្តោះអាសន្ន ហើយផ្លាស់ប្តូររាល់ពេលដែលអ្នកបញ្ឈប់/ចាប់ផ្តើម tunnel
- ជាលំនាំដើម Quick Tunnel ដែលបានគ្រប់គ្រងប្រើការបញ្ជូនតាម HTTP/2 ដើម្បីជៀសវាងការព្រមានអំពី QUIC UDP buffer ដែលរំខាន នៅក្នុង container ដែលមានធនធានកំណត់
- កំណត់ `CLOUDFLARED_PROTOCOL=quic` ឬ `auto` ប្រសិនបើអ្នកចង់កំណត់ជំនួសជម្រើសការបញ្ជូនដែលបានគ្រប់គ្រង
- កំណត់ `CLOUDFLARED_BIN` ប្រសិនបើអ្នកចង់ប្រើ binary `cloudflared` ដែលបានដំឡើងជាមុន ជំនួសឱ្យការទាញយកដែលបានគ្រប់គ្រង
- ផ្ទាំង Cloudflare Quick Tunnel, Tailscale Funnel និង ngrok Tunnel អាចត្រូវបានបង្ហាញ ឬលាក់នៅក្នុង **ការកំណត់ → រូបរាង**។ ការលាក់ផ្ទាំងមួយមិនបញ្ឈប់ tunnel ដែលកំពុងដំណើរការទេ។

### ភាពឆ្លាតវៃរបស់ LLM Gateway (ដំណាក់កាលទី 9)

- **Semantic Cache** — រក្សាទុកក្នុង cache ដោយស្វ័យប្រវត្តិនូវ response ដែលមិនមែនជា streaming និងមាន temperature=0 (រំលងដោយប្រើ `X-OmniRoute-No-Cache: true`)
- **Request Idempotency** — លុបសំណើស្ទួនក្នុងរយៈពេល 5s តាមរយៈ header `Idempotency-Key` ឬ `X-Request-Id`
- **ការតាមដានវឌ្ឍនភាព** — ព្រឹត្តិការណ៍ SSE `event: progress` ដែលតម្រូវឱ្យជ្រើសប្រើ តាមរយៈ header `X-OmniRoute-Progress: true`

| **ប្រើប្រាស់តិចបំផុត**           | កំណត់ផ្លូវទៅគណនីដែលមានត្រាពេលវេលា `lastUsedAt` ចាស់បំផុត ដើម្បីចែកចាយចរាចរណ៍ឱ្យស្មើគ្នា                     |
| **បង្កើនប្រសិទ្ធភាពថ្លៃដើម**     | កំណត់ផ្លូវទៅគណនីដែលមានតម្លៃអាទិភាពទាបបំផុត ដើម្បីបង្កើនប្រសិទ្ធភាពសម្រាប់អ្នកផ្ដល់សេវាដែលមានថ្លៃដើមទាបបំផុត |

**យុទ្ធសាស្ត្របន្សំកម្រិតខ្ពស់ និងយុទ្ធសាស្ត្រស្វ័យប្រវត្តិ** (អាចកំណត់រចនាសម្ព័ន្ធតាមបន្សំនីមួយៗ ឬតាមរយៈបុព្វបទ `auto/*` — សូមមើល [AUTO-COMBO.md](../routing/AUTO-COMBO.md))៖

- `priority` — លំដាប់តឹងរ៉ឹង មិនដែលប្ដូរវេនជុំគ្នាទេ
- `weighted` — បែងចែកចរាចរណ៍តាមសមាមាត្រ ដោយផ្អែកលើទម្ងន់របស់ម៉ូដែលនីមួយៗ
- `fill-first` — ប្រើម៉ូដែលទីមួយរហូតដល់ដែនកំណត់របស់វា
- `round-robin` / `strict-random` / `random`
- `p2c` (ជម្រើសពីរក្នុងចំណោមពីរ)
- `least-used` និង `cost-optimized`
- `auto` — កំណត់ផ្លូវដោយផ្អែកលើពិន្ទុ ក្នុងចំណោមបេក្ខភាពទាំងអស់
- `lkgp` (អ្នកផ្ដល់សេវាល្អចុងក្រោយដែលបានស្គាល់) — ភ្ជាប់ទៅអ្នកផ្ដល់សេវាដែលជោគជ័យចុងក្រោយ បន្ទាប់មកត្រឡប់ទៅប្រើច្បាប់ជំនួស
- `context-optimized` — ជ្រើសម៉ូដែលដែលមានបង្អួចបរិបទទំនេរធំបំផុត
- `context-relay` — តភ្ជាប់ម៉ូដែលបរិបទវែងជាបន្តបន្ទាប់ សម្រាប់វេនតាមដានបន្ទាប់

#### បឋមកថាសម័យជាប់លាប់ខាងក្រៅ

សម្រាប់ភាពជាប់លាប់នៃសម័យខាងក្រៅ (ឧទាហរណ៍ ភ្នាក់ងារ Claude Code/Codex នៅពីក្រោយប្រូកស៊ីបញ្ច្រាស) សូមផ្ញើ៖

```http
X-Session-Id: your-session-key
```

OmniRoute ក៏ទទួលយក `x_session_id` និងត្រឡប់សោសម័យដែលមានប្រសិទ្ធភាពក្នុង `X-OmniRoute-Session-Id` ផងដែរ។

ប្រសិនបើអ្នកប្រើ Nginx និងផ្ញើបឋមកថាទម្រង់សញ្ញាគូសក្រោម សូមបើក៖

```nginx
underscores_in_headers on;
```

#### ឈ្មោះក្លែងក្លាយម៉ូដែលដែលមានតួអក្សរជំនួស

បង្កើតលំនាំតួអក្សរជំនួស ដើម្បីផ្គូផ្គងឈ្មោះម៉ូដែលឡើងវិញ៖

```
លំនាំ៖ claude-sonnet-*     →  គោលដៅ៖ cc/claude-sonnet-4-6
លំនាំ៖ gpt-*               →  គោលដៅ៖ gh/gpt-5.3-codex
```

តួអក្សរជំនួសគាំទ្រ `*` (តួអក្សរណាមួយ) និង `?` (តួអក្សរតែមួយ)។

#### ខ្សែសង្វាក់ជំនួស

កំណត់ខ្សែសង្វាក់ជំនួសសកល ដែលអនុវត្តចំពោះសំណើទាំងអស់៖

```
ខ្សែសង្វាក់៖ production-fallback
  1. cc/claude-opus-4-7
  2. gh/gpt-5.3-codex
  3. glm/glm-4.7
```

### ភាពធន់ និងឧបករណ៍ផ្ដាច់សៀគ្វី

កំណត់រចនាសម្ព័ន្ធតាមរយៈ **ផ្ទាំងគ្រប់គ្រង → ការកំណត់ → ភាពធន់**។

OmniRoute អនុវត្តភាពធន់កម្រិតអ្នកផ្ដល់សេវា ដោយមានសមាសភាគចំនួនប្រាំ៖

1. **ជួរសំណើ និងការកំណត់ចង្វាក់** — ការរៀបចំលំហូរសំណើកម្រិតប្រព័ន្ធ៖
   - **សំណើក្នុងមួយនាទី (RPM)** — ចំនួនសំណើអតិបរមាក្នុងមួយនាទី សម្រាប់គណនីនីមួយៗ
   - **ពេលវេលាអប្បបរមារវាងសំណើ** — ចន្លោះអប្បបរមាគិតជាមិល្លីវិនាទីរវាងសំណើ
   - **សំណើដំណាលគ្នាអតិបរមា** — ចំនួនសំណើដំណាលគ្នាអតិបរមាសម្រាប់គណនីនីមួយៗ

2. **រយៈពេលរង់ចាំការតភ្ជាប់** — ការកំណត់រចនាសម្ព័ន្ធតាមប្រភេទការផ្ទៀងផ្ទាត់ សម្រាប់ការតភ្ជាប់តែមួយ បន្ទាប់ពីការបរាជ័យដែលអាចសាកល្បងម្ដងទៀត៖
   - **រយៈពេលរង់ចាំមូលដ្ឋាន** — ចន្លោះពេលរង់ចាំលំនាំដើម សម្រាប់ការបរាជ័យពីប្រភពខាងលើដែលអាចសាកល្បងម្ដងទៀត
   - **ប្រើព័ត៌មានណែនាំអំពីការសាកល្បងម្ដងទៀតពីប្រភពខាងលើ** — គោរពតាម `Retry-After` ដែលមានសុពលភាព ឬព័ត៌មានណែនាំអំពីការកំណត់ឡើងវិញ នៅពេលមានផ្ដល់ជូន
   - **ជំហានពន្យារពេលអតិបរមា** — កម្រិតពន្យារពេលកើនទ្វេគុណអតិបរមា សម្រាប់ការបរាជ័យកើតឡើងដដែលៗ

3. **ឧបករណ៍ផ្ដាច់សៀគ្វីអ្នកផ្ដល់សេវា** — តាមដានការបរាជ័យពីដើមដល់ចប់របស់អ្នកផ្ដល់សេវា សម្គាល់អ្នកផ្ដល់សេវាថាមានស្ថានភាពធ្លាក់ចុះនៅកម្រិតព្រមានដែលបានកំណត់ និងបើកឧបករណ៍ផ្ដាច់ នៅពេលដល់កម្រិតបរាជ័យដែលបានកំណត់៖
   - **កម្រិតភាពធ្លាក់ចុះ** — ចំនួនការបរាជ័យជាប់ៗគ្នារបស់អ្នកផ្ដល់សេវា មុនពេលចូលទៅស្ថានភាព `DEGRADED`
   - **កម្រិតបរាជ័យ** — ចំនួនការបរាជ័យជាប់ៗគ្នារបស់អ្នកផ្ដល់សេវា មុនពេលចូលទៅស្ថានភាព `OPEN`
   - **ពេលវេលាផុតកំណត់សម្រាប់ការកំណត់ឡើងវិញ** — ចន្លោះពេលមុនពេលសាកល្បងអ្នកផ្ដល់សេវាម្ដងទៀត
   - **CLOSED** (មានស្ថានភាពល្អ) — សំណើដំណើរការជាធម្មតា
   - **DEGRADED** — សំណើនៅតែដំណើរការ ខណៈដែលការបរាជ័យកើនឡើងត្រូវបានតាមដាន
   - **OPEN** — អ្នកផ្ដល់សេវាត្រូវបានទប់ស្កាត់ជាបណ្ដោះអាសន្ន បន្ទាប់ពីការបរាជ័យកើតឡើងដដែលៗ
   - **HALF_OPEN** — កំពុងសាកល្បងថាតើអ្នកផ្ដល់សេវាបានស្ដារឡើងវិញឬអត់

   ដែនកំណត់អត្រា `429` ដែលមានវិសាលភាពត្រឹមការតភ្ជាប់ នៅតែស្ថិតក្នុង **រយៈពេលរង់ចាំការតភ្ជាប់** ហើយមិនត្រូវបានរាប់បញ្ចូលក្នុងឧបករណ៍ផ្ដាច់សៀគ្វីអ្នកផ្ដល់សេវាទេ។

   ស្ថានភាពពេលដំណើរការរបស់ឧបករណ៍ផ្ដាច់សៀគ្វីអ្នកផ្ដល់សេវា ត្រូវបានបង្ហាញតែនៅលើ **ផ្ទាំងគ្រប់គ្រង → ស្ថានភាព** ប៉ុណ្ណោះ។

4. **រង់ចាំរយៈពេលត្រជាក់** — ប្រសិនបើការតភ្ជាប់បេក្ខភាពទាំងអស់កំពុងស្ថិតក្នុងរយៈពេលរង់ចាំរួចហើយ OmniRoute អាចរង់ចាំរហូតដល់រយៈពេលរង់ចាំឆាប់បំផុតបានបញ្ចប់ ហើយសាកល្បងសំណើអតិថិជនដដែលម្ដងទៀតដោយស្វ័យប្រវត្តិ។

5. **ការរកឃើញដែនកំណត់អត្រាដោយស្វ័យប្រវត្តិ** — នៅពេលអ្នកផ្ដល់សេវាប្រភពខាងលើត្រឡប់ចន្លោះពេលរង់ចាំជាក់លាក់ ព័ត៌មានណែនាំទាំងនោះនឹងជំនួសរយៈពេលរង់ចាំការតភ្ជាប់មូលដ្ឋាន ប្រសិនបើបានបើកការកំណត់នេះ។

**គន្លឹះសម្រាប់អ្នកជំនាញ៖** ប្រើទំព័រ **ស្ថានភាព** ដើម្បីត្រួតពិនិត្យ និងកំណត់ឧបករណ៍ផ្ដាច់សៀគ្វីអ្នកផ្ដល់សេវាដែលកំពុងដំណើរការឡើងវិញ បន្ទាប់ពីមានការដាច់សេវា។ ទំព័រភាពធន់គ្រាន់តែផ្លាស់ប្ដូរការកំណត់រចនាសម្ព័ន្ធប៉ុណ្ណោះ។

| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **នាំចេញមូលដ្ឋានទិន្នន័យ**  | ទាញយកមូលដ្ឋានទិន្នន័យ SQLite បច្ចុប្បន្នជាឯកសារ `.sqlite`                                                                                                       |
| **នាំចេញទាំងអស់ (.tar.gz)** | ទាញយកប័ណ្ណសារបម្រុងទុកពេញលេញ ដែលរួមមាន៖ មូលដ្ឋានទិន្នន័យ ការកំណត់ combos ការតភ្ជាប់អ្នកផ្តល់សេវា (មិនរួមបញ្ចូលព័ត៌មានសម្ងាត់) និងទិន្នន័យមេតារបស់ API key       |
| **នាំចូលមូលដ្ឋានទិន្នន័យ**  | ផ្ទុកឡើងឯកសារ `.sqlite` ដើម្បីជំនួសមូលដ្ឋានទិន្នន័យបច្ចុប្បន្ន។ ការបម្រុងទុកមុននាំចូលត្រូវបានបង្កើតដោយស្វ័យប្រវត្តិ លុះត្រាតែ `DISABLE_SQLITE_AUTO_BACKUP=true` |

```bash
# API៖ នាំចេញមូលដ្ឋានទិន្នន័យ
curl -o backup.sqlite http://localhost:20128/api/db-backups/export

# API៖ នាំចេញទាំងអស់ (ប័ណ្ណសារពេញលេញ)
curl -o backup.tar.gz http://localhost:20128/api/db-backups/exportAll

# API៖ នាំចូលមូលដ្ឋានទិន្នន័យ
curl -X POST http://localhost:20128/api/db-backups/import \
  -F "file=@backup.sqlite"
```

**ការផ្ទៀងផ្ទាត់ការនាំចូល៖** ឯកសារដែលបាននាំចូលត្រូវបានផ្ទៀងផ្ទាត់ភាពត្រឹមត្រូវ (ការត្រួតពិនិត្យ SQLite pragma) តារាងចាំបាច់ (`provider_connections`, `provider_nodes`, `combos`, `api_keys`) និងទំហំ (អតិបរមា 100MB)។

**ករណីប្រើប្រាស់៖**

- ផ្ទេរ OmniRoute រវាងម៉ាស៊ីន
- បង្កើតការបម្រុងទុកខាងក្រៅសម្រាប់ការស្ដារឡើងវិញក្រោយគ្រោះមហន្តរាយ
- ចែករំលែកការកំណត់រចនាសម្ព័ន្ធរវាងសមាជិកក្រុម (នាំចេញទាំងអស់ → ចែករំលែកប័ណ្ណសារ)

### ផ្ទាំងគ្រប់គ្រងការកំណត់

ទំព័រការកំណត់ត្រូវបានរៀបចំជា **7 ផ្ទាំង** ដើម្បីងាយស្រួលរុករក៖

| ផ្ទាំង            | មាតិកា                                                                                                                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ទូទៅ**          | ឧបករណ៍ផ្ទុកទិន្នន័យប្រព័ន្ធ ឥរិយាបថលំនាំដើម និងភាពមើលឃើញនៃ Endpoint tunnel                                                                                                               |
| **រូបរាង**        | ការគ្រប់គ្រងស្បែក (ភ្លឺ/ងងឹត/ប្រព័ន្ធ) ភាពមើលឃើញរបស់របារចំហៀង និងប៊ូតុងបិទបើកផ្ទាំងសម្រាប់កាត Cloudflare/Tailscale/ngrok tunnel                                                          |
| **AI**            | ថវិកាសម្រាប់ការគិត (បញ្ជូនបន្ត / ដកចេញដោយស្វ័យប្រវត្តិ / ផ្ទាល់ខ្លួន / សម្របខ្លួន — សូមមើល [THINKING_BUDGET.md](./THINKING_BUDGET.md)) system prompt សកល និងស្ថិតិ prompt cache          |
| **សុវត្ថិភាព**    | ការកំណត់ការចូលប្រើ/ពាក្យសម្ងាត់ ការគ្រប់គ្រងការចូលប្រើតាម IP ការផ្ទៀងផ្ទាត់ API សម្រាប់ `/models` ការទប់ស្កាត់អ្នកផ្តល់សេវា និងរបាំងការពារ prompt-injection                              |
| **ការកំណត់ផ្លូវ** | យុទ្ធសាស្ត្រកំណត់ផ្លូវសកល (បំពេញមុន / Round Robin / P2C / ចៃដន្យ / ប្រើតិចបំផុត / បង្កើនប្រសិទ្ធភាពចំណាយ) ឈ្មោះក្លែងក្លាយ wildcard របស់ម៉ូដែល ខ្សែសង្វាក់ fallback និងលំនាំដើមរបស់ combo |
| **ភាពធន់**        | ជួរសំណើ រយៈពេលសម្រាកការតភ្ជាប់ ការកំណត់រចនាសម្ព័ន្ធ provider breaker និងឥរិយាបថរង់ចាំឱ្យរយៈពេលសម្រាកបញ្ចប់                                                                               |
| **កម្រិតខ្ពស់**   | ការកំណត់រចនាសម្ព័ន្ធ proxy សកល (HTTP/SOCKS5) និងការកំណត់ជំនួស proxy សម្រាប់អ្នកផ្តល់សេវានីមួយៗ                                                                                           |

ផ្នែកទូទៅលែងបង្ហាញស្ទួននូវកំណត់ត្រា និងកំណត់សម្គាល់ cache ដែលអាចបានតែអានទៀតហើយ។ ការកំណត់រយៈពេលរក្សាទុក និង
ការបង្កើនប្រសិទ្ធភាពមូលដ្ឋានទិន្នន័យត្រូវបានរក្សាទុកតាមរយៈ `/api/settings/database`; ការសម្អាត cache ដោយដៃប្រើ
`DELETE /api/cache`។ ចំនួនអតិបរមានៃជួរដេកក្នុងកំណត់ត្រាសំណើ និង proxy ត្រូវបានគ្រប់គ្រងដោយ
`CALL_LOGS_TABLE_MAX_ROWS` និង `PROXY_LOGS_TABLE_MAX_ROWS`។

### ការគ្រប់គ្រងថ្លៃចំណាយ និងថវិកា

ចូលប្រើតាមរយៈ **ផ្ទាំងគ្រប់គ្រង → ថ្លៃចំណាយ**។

| ផ្ទាំង    | គោលបំណង                                                                                                             |
| --------- | ------------------------------------------------------------------------------------------------------------------- |
| **ថវិកា** | កំណត់ដែនកំណត់ចំណាយសម្រាប់ API key នីមួយៗ ដោយមានថវិកាប្រចាំថ្ងៃ/ប្រចាំសប្ដាហ៍/ប្រចាំខែ និងការតាមដានក្នុងពេលជាក់ស្ដែង |
| **តម្លៃ** | មើល និងកែសម្រួលធាតុតម្លៃរបស់ម៉ូដែល — ថ្លៃចំណាយក្នុងមួយ 1K input/output tokens សម្រាប់អ្នកផ្តល់សេវានីមួយៗ            |

```bash
# API៖ កំណត់ថវិកា
curl -X POST http://localhost:20128/api/usage/budget \
  -H "Content-Type: application/json" \
  -d '{"keyId": "key-123", "limit": 50.00, "period": "monthly"}'

# API៖ ទទួលយកស្ថានភាពថវិកាបច្ចុប្បន្ន
curl http://localhost:20128/api/usage/budget
```

**ការតាមដានថ្លៃចំណាយ៖** រាល់សំណើកត់ត្រាការប្រើប្រាស់ token និងគណនាថ្លៃចំណាយដោយប្រើតារាងតម្លៃ។ មើលការបែងចែកលម្អិតនៅក្នុង **ផ្ទាំងគ្រប់គ្រង → ការប្រើប្រាស់** តាមអ្នកផ្តល់សេវា ម៉ូដែល និង API key។

### យុទ្ធសាស្ត្រតុល្យភាព Combo

កំណត់រចនាសម្ព័ន្ធតុល្យភាពសម្រាប់ combo នីមួយៗនៅក្នុង **ផ្ទាំងគ្រប់គ្រង → Combos → បង្កើត/កែសម្រួល → យុទ្ធសាស្ត្រ**។

| យុទ្ធសាស្ត្រ       | ការពិពណ៌នា                                                                     |
| ------------------ | ------------------------------------------------------------------------------ |
| **Round-Robin**    | ប្តូរវេនឆ្លងកាត់ម៉ូដែលតាមលំដាប់                                                |
| **Priority**       | តែងតែសាកល្បងម៉ូដែលទីមួយជាមុន ហើយប្តូរទៅម៉ូដែលបម្រុងតែក្នុងករណីមានកំហុសប៉ុណ្ណោះ |
| **Random**         | ជ្រើសរើសម៉ូដែលដោយចៃដន្យពី combo សម្រាប់សំណើនីមួយៗ                              |
| **Weighted**       | បញ្ជូនតាមសមាមាត្រដោយផ្អែកលើទម្ងន់ដែលបានកំណត់សម្រាប់ម៉ូដែលនីមួយៗ                |
| **Least-Used**     | បញ្ជូនទៅម៉ូដែលដែលមានសំណើថ្មីៗតិចបំផុត (ប្រើម៉ែត្រវាស់វែងរបស់ combo)            |
| **Cost-Optimized** | បញ្ជូនទៅម៉ូដែលដែលមានតម្លៃថោកបំផុត និងអាចប្រើបាន (ប្រើតារាងតម្លៃ)               |

តម្លៃលំនាំដើមសកលរបស់ combo អាចកំណត់បាននៅក្នុង **Dashboard → Settings → Routing → Combo Defaults**។
តាមលំនាំដើម ពេលអស់កំណត់របស់គោលដៅ combo ទទួលបន្តពីពេលអស់កំណត់របស់សំណើបច្ចុប្បន្ន។ ប្រើ **Target timeout
(seconds)** លើតម្លៃលំនាំដើមរបស់ combo ឬលើ combo នីមួយៗ តែនៅពេលដែលចង់ឱ្យដែនកំណត់ខ្លីជាងសម្រាប់គោលដៅនីមួយៗ
បង្កឱ្យមានការប្តូរទៅគោលដៅបម្រុងបានលឿនជាងមុន។

ការបង្កើនប្រសិទ្ធភាព combo ដែលគ្មានភាពយឺតយ៉ាវ តម្រូវឱ្យអ្នកជ្រើសរើសបើក។ ទុកឱ្យ **Zero-latency optimizations** បិទ ដើម្បី
ទប់ស្កាត់មុខងារពាក់ព័ន្ធនឹងភាពយឺតយ៉ាវទាំងនេះពីការប្រជែងជាមួយគោលដៅបម្រុង ការរំលងគោលដៅដោយផ្អែកលើប្រវត្តិ TTFT
ឬការបង្រួមសំណើបម្រុង។ ការបើកវាអនុញ្ញាតឱ្យការបញ្ជូនសំណើបន្ថែមដែលបានកំណត់ ការរំលងដោយព្យាករណ៍ TTFT
និងការបង្រួមការប្តូរទៅគោលដៅបម្រុងជាមុន ផ្លាស់ប្តូរភាពស្មោះត្រង់នៃការបញ្ជូន/សំណើ ដើម្បីកាត់បន្ថយ
ភាពយឺតយ៉ាវនៅផ្នែកចុង។

បិទ **Reasoning token buffer** នៅពេលដែលអ្នកផ្តល់សេវាខាងដើមទាមទារដែនកំណត់
`max_tokens` / `maxOutputTokens` យ៉ាងតឹងរ៉ឹង។ នៅពេលបើក ការបញ្ជូន combo បន្ថែមតែទំហំបន្ថែមសម្រាប់ម៉ូដែល reasoning
ចំពោះម៉ូដែលដែលមានកម្រិតអតិបរមាលទ្ធផលដែលបានដឹងប៉ុណ្ណោះ ហើយរក្សាដែនកំណត់ token របស់ client ឱ្យនៅដដែល នៅពេលដែល
តម្លៃ buffer ដែលមានសុវត្ថិភាពនឹងលើសកម្រិតអតិបរមានោះ។ ប្រសិនបើដែនកំណត់របស់ client លើសកម្រិតអតិបរមាដែលបានដឹងរួចហើយ
OmniRoute នឹងកាត់បន្ថយវាមកត្រឹមកម្រិតអតិបរមានោះ មុនពេលផ្ញើសំណើទៅខាងដើម។

## 🔌 ការរួមបញ្ចូល MCP និង A2A

OmniRoute គឺជា **ម៉ាស៊ីនមេ MCP** (Model Context Protocol) និងជា **ម៉ាស៊ីនមេ A2A** (Agent-to-Agent JSON-RPC 2.0)។ IDE ឬម៉ាស៊ីនទទួលភ្នាក់ងារណាមួយដែលត្រូវគ្នាជាមួយ MCP អាចហៅឧបករណ៍ OmniRoute ដោយផ្ទាល់ — មិនចាំបាច់មាន wrapper បន្ថែមឡើយ។

### មធ្យោបាយដឹកជញ្ជូន MCP

- **SSE**៖ `http://localhost:20128/api/mcp/sse`
- **HTTP ដែលអាចស្ទ្រីមបាន**៖ `http://localhost:20128/api/mcp/stream`
- **stdio**៖ `omniroute --mcp` (សម្រាប់កម្មវិធីជំនួយ IDE ដែលផ្តល់អាទិភាពដល់ stdio)

### ភ្ជាប់ Claude Desktop

កែសម្រួល `~/Library/Application Support/Claude/claude_desktop_config.json` (macOS) ឬឯកសារដែលមានតួនាទីសមមូលនៅលើ Windows/Linux៖

```json
{
  "mcpServers": {
    "omniroute": {
      "command": "omniroute",
      "args": ["--mcp"]
    }
  }
}
```

### ភ្ជាប់ Cursor / Continue / VS Code MCP

ប្រើ URL របស់ SSE `http://localhost:20128/api/mcp/sse` និងសោ Bearer API ដែលបានបង្កើតនៅក្នុង **ផ្ទាំងគ្រប់គ្រង → សោ API**។

### វិសាលភាព

បច្ចុប្បន្ន MCP កំណត់វិសាលភាពដែលមានឈ្មោះចំនួន 32។ សោ Bearer នីមួយៗអាចត្រូវបានកំណត់ឱ្យប្រើតែវិសាលភាពជាក់លាក់ — សូមមើល [MCP-SERVER.md](../frameworks/MCP-SERVER.md) សម្រាប់បញ្ជីវិសាលភាព និងឧបករណ៍ផ្លូវការ និង [A2A-SERVER.md](../frameworks/A2A-SERVER.md) សម្រាប់គ្រោងការណ៍ JSON-RPC។

គ្រប់គ្រងអង្គចងចាំក្នុង **Dashboard → Memory** (ស្វែងរក កែសម្រួល នាំចេញ សម្អាត)។ ចំណុចប្រទាក់ HTTP (`/api/memory/*`) អនុញ្ញាតឱ្យភ្នាក់ងារបញ្ជូន និងសួររកការពិតតាមកម្មវិធី — សូមមើល [MEMORY.md](../frameworks/MEMORY.md)។

## 🔔 Webhooks

ជាវព្រឹត្តិការណ៍ OmniRoute សម្រាប់ការត្រួតពិនិត្យ និងស្វ័យប្រវត្តិកម្មតាមពេលវេលាជាក់ស្តែង។

- បង្កើត webhook ក្នុង **Dashboard → Webhooks** ដោយមាន URL គោលដៅ និង secret សម្រាប់ការចុះហត្ថលេខា HMAC
- ព្រឹត្តិការណ៍ដែលមាន៖ `request.completed`, `request.failed`, `provider.unavailable`, `budget.exceeded`, `combo.switched`, `circuit_breaker.opened`, `circuit_breaker.closed`
- payload នីមួយៗរួមបញ្ចូល `X-OmniRoute-Signature` (HMAC-SHA256) សម្រាប់ការផ្ទៀងផ្ទាត់
- ការព្យាយាមឡើងវិញ៖ ព្យាយាម 3 ដងជាមួយការពន្យារពេលកើនឡើងជាអិចស្ប៉ូណង់ស្យែល បន្ទាប់មកបញ្ជូនទៅជួរ dead-letter

គ្រោងការណ៍ពេញលេញមាននៅក្នុង [WEBHOOKS.md](../frameworks/WEBHOOKS.md)។

## 🛠️ ការគ្រប់គ្រងតាមកម្មវិធី

អ្នកអាចគ្រប់គ្រងធនធាន OmniRoute ទាំងអស់ (providers, combos, keys, settings) តាមរយៈ HTTP ដោយប្រើ **Bearer key ដែលមានវិសាលភាព `manage`**។

បង្កើត key ក្នុង **Dashboard → API Keys → New Key → Scope: manage** បន្ទាប់មក៖

```bash
# រាយបញ្ជី providers
curl http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"

# បន្ថែមការតភ្ជាប់ provider
curl -X POST http://localhost:20128/api/providers \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "provider": "openai", "apiKey": "sk-...", "name": "main" }'

# បង្កើត combo
curl -X POST http://localhost:20128/api/combos \
  -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "premium", "strategy": "priority", "models": [{ "model": "cc/claude-opus-4-7" }, { "model": "glm/glm-5.1" }] }'

# រាយបញ្ជី/បង្កើត API keys
curl http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY"
curl -X POST http://localhost:20128/api/keys -H "Authorization: Bearer $OMNIROUTE_MANAGE_KEY" \
  -d '{ "name": "ci-bot", "scopes": ["chat"] }'
```

សូមមើល [API_REFERENCE.md](../reference/API_REFERENCE.md) សម្រាប់កាតាឡុក endpoint ពេញលេញ និងគ្រោងការណ៍ request/response។

## 💻 CLI ផ្ទៃក្នុង

OmniRoute ភ្ជាប់មកជាមួយ CLI ផ្ទៃក្នុង (`omniroute …`) សម្រាប់ការដំឡើង ការធ្វើរោគវិនិច្ឆ័យ និងការគ្រប់គ្រងពេលដំណើរការ។ វា**ដាច់ដោយឡែកពីទំព័រ "CLI Tools" នៅក្នុងផ្ទាំងគ្រប់គ្រង** ដែលកំណត់រចនាសម្ព័ន្ធ CLI របស់ភាគីទីបី (Claude Code, Cursor, Codex, Cline, …) ដើម្បីឱ្យពួកវាអាចទាក់ទងជាមួយ OmniRoute បាន។

```bash
omniroute setup                    # អ្នកជំនួយការអន្តរកម្ម (ពាក្យសម្ងាត់ អ្នកផ្តល់សេវា បន្សំ)
omniroute setup --non-interactive  # សមស្របសម្រាប់ CI
omniroute doctor                   # ការធ្វើរោគវិនិច្ឆ័យសុខភាព (ថតទិន្នន័យ DB អ្នកផ្តល់សេវា ច្រក)
omniroute providers available      # រាយបញ្ជីអ្នកផ្តល់សេវាដែលគាំទ្រ
omniroute providers list           # រាយបញ្ជីការតភ្ជាប់ដែលបានកំណត់រចនាសម្ព័ន្ធ
omniroute providers test <id>      # សាកល្បងការតភ្ជាប់អ្នកផ្តល់សេវាដោយផ្ទាល់
omniroute combos list              # រាយបញ្ជីបន្សំ
omniroute combos switch <name>     # កំណត់បន្សំលំនាំដើម
omniroute models                   # រាយបញ្ជីម៉ូដែលដែលមាន (--json, --search)
omniroute keys add | list | remove # គ្រប់គ្រង API key ពីស្ថានីយ
omniroute backup                   # ថតចម្លងស្ថានភាពរចនាសម្ព័ន្ធ + DB
omniroute restore [<timestamp>]    # ស្ដារពីរូបថតចម្លងស្ថានភាព
omniroute health                   # ព័ត៌មានសុខភាពលម្អិត (ឧបករណ៍ផ្ដាច់ cache អង្គចងចាំ)
omniroute quota                    # ការប្រើប្រាស់កូតារបស់អ្នកផ្តល់សេវា
omniroute mcp status               # ស្ថានភាពម៉ាស៊ីនមេ MCP
omniroute a2a status               # ស្ថានភាពម៉ាស៊ីនមេ A2A
omniroute tunnel list|create|stop  # ផ្លូវរូង Cloudflare/Tailscale/ngrok
omniroute reset-password           # កំណត់ពាក្យសម្ងាត់អ្នកគ្រប់គ្រងឡើងវិញ
omniroute --mcp                    # ចាប់ផ្ដើមម៉ាស៊ីនមេ MCP តាម stdio
omniroute --port 3000              # ចាប់ផ្ដើមម៉ាស៊ីនមេលើច្រកផ្ទាល់ខ្លួន
```

គន្លឹះ៖ ប្រើ `omniroute doctor --json` ជាមួយឧបករណ៍ត្រួតពិនិត្យរបស់អ្នក ដើម្បីជូនដំណឹងអំពីការតភ្ជាប់អ្នកផ្តល់សេវាដែលមានបញ្ហា។
