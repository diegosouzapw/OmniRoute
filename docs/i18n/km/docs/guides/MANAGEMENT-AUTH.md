## ម៉ាទ្រីសវិសាលភាព

វិសាលភាពគ្រប់គ្រងសោ API និងវិសាលភាពសញ្ញាសម្គាល់ចូលប្រើគឺជាវាក្យសព្ទផ្សេងគ្នា។ វិសាលភាពឧបករណ៍ MCP គឺជាវាក្យសព្ទទីបី ដែលត្រូវបានពិនិត្យជាមួយ `scopeMatches` ជំនួសឲ្យអនុគមន៍ណាមួយក្នុងតារាងខាងក្រោម។ មួយទល់មួយ៖ [ឈ្មោះលំហវិសាលភាពបី](../frameworks/MCP-SERVER.md#three-scope-namespaces)។

### វិសាលភាពសញ្ញាសម្គាល់ចូលប្រើ (`oma_live_…`)

| វិសាលភាព | ប្រតិបត្តិការទូទៅ                                                                 |
| -------- | --------------------------------------------------------------------------------- |
| `read`   | ការរាយបញ្ជី/ស្ថានភាព GETs ដែលសញ្ញាសម្គាល់ត្រូវបានអនុញ្ញាតឲ្យមើលឃើញ                |
| `write`  | ការផ្លាស់ប្ដូរ (បង្កើត/ធ្វើបច្ចុប្បន្នភាព/លុប) ក្រោមអ្នកគ្រប់គ្រង                 |
| `admin`  | CLI ពីចម្ងាយពេញលេញ / សញ្ញាសម្គាល់ភ្ជាប់ (លំនាំដើមការចាប់ផ្ដើមពាក្យសម្ងាត់នៅទីនេះ) |

សញ្ញាសម្គាល់ដែលមាន `read` មិនអាចហៅផ្លូវ `write` បានទេ។ ទម្រង់សារពេលដំណើរការ៖
`Access token scope '<have>' is insufficient; '<need>' required.`

### វិសាលភាពគ្រប់គ្រងសោ API

| វិសាលភាព | អត្ថន័យ                                                           |
| -------- | ----------------------------------------------------------------- |
| (គ្មាន)  | ការទាយទុកតែប៉ុណ្ណោះ។ ផ្លូវគ្រប់គ្រងប្រគល់លេខ 403 មកវិញ។           |
| `manage` | API គ្រប់គ្រង (ច្រកដូចគ្នានឹងសាខាសោ API `requireManagementAuth`)  |
| `admin`  | ក៏បំពេញតាម `hasManageScope` ផងដែរ (ចាត់ទុកថាមានសមត្ថភាពគ្រប់គ្រង) |

បើក `manage` នៅលើសោក្នុងចំណុចប្រទាក់អ្នកប្រើប្រាស់ API Keys / API Manager។ កុំប្រើសោម៉ាស៊ីនភ្ញៀវជជែកឡើងវិញសម្រាប់ស្វ័យប្រវត្តិកម្ម លុះត្រាតែអ្នកបានផ្ដល់វិសាលភាពនោះដោយចេតនា។

## របៀបបង្កើត និងដកហូត

### វគ្គ JWT របស់ផ្ទាំងគ្រប់គ្រង

1.  បើក `/login` រួចចូលដោយប្រើពាក្យសម្ងាត់គ្រប់គ្រង (`INITIAL_PASSWORD` នៅពេលចាប់ផ្ដើមដំបូង)។
2.  Cookie `auth_token` គឺ HttpOnly។ ផ្ទាំងគ្រប់គ្រងរបស់ Browser ប្រើវាដោយស្វ័យប្រវត្តិ។
3.  ចេញពីប្រព័ន្ធតាមរយៈ `/api/auth/logout`។ មិនមានលេខសម្ងាត់ដែលមានអាយុកាលវែងសម្រាប់ចម្លងនោះទេ។

### ថូខឹន machine-id របស់ CLI

1.  ដំណើរការ `omniroute` នៅលើ **ម៉ាស៊ីនតែមួយ** ជាមួយ server (loopback)។
2.  CLI បង្កើតថូខឹន machine-id មួយនៅក្រោម `~/.omniroute/` (chmod 600)។
3.  នេះ **មិន** ដំណើរការពីម៉ាស៊ីនផ្សេងទៀតទេ។ ប្រើ Access Token សម្រាប់ CLI ពីចម្ងាយ។

### Access Token ដែលមានវិសាលភាព (`oma_live_…`)

1.  ផ្ទាំងគ្រប់គ្រង: **Settings → Access Tokens** → បង្កើត (ឈ្មោះ + វិសាលភាព)។ **លេខសម្ងាត់នឹងបង្ហាញតែម្ដងប៉ុណ្ណោះ។**
2.  ឬ CLI: `omniroute connect <host>` (ពាក្យសម្ងាត់ → ថូខឹន)។ សូមមើល [Remote Mode](./REMOTE-MODE.md)។
3.  Header: `Authorization: Bearer oma_live_…`
4.  ដកហូតពីទំព័រ Access Tokens ដូចគ្នា (ឬលុបបរិបទ CLI)។
5.  Server គ្រាន់តែរក្សាទុក hash មួយប៉ុណ្ណោះ។ ចាត់ទុក plaintext ដូចជាពាក្យសម្ងាត់។

### API key ដែលមានវិសាលភាពគ្រប់គ្រង

1.  ផ្ទាំងគ្រប់គ្រង: **API Manager / API Keys** → បង្កើត ឬកែសម្រួល key → បើក `manage` (ឬ `admin`)។
2.  Header: `Authorization: Bearer sk-…` (បុព្វបទពិតប្រាកដរបស់ key)។
3.  ដកហូត ឬដក `manage` ចេញនៅក្នុង UI ដូចគ្នា។
4.  សិទ្ធិអប្បបរមាសម្រាប់ការស្វ័យប្រវត្តិកម្មដែលមិនមែនជា CLI: គួរប្រើ Access Token ប្រភេទ `read` សម្រាប់កិច្ចការ GET-only; ប្រើ `manage` នៅលើ API key លុះត្រាតែអ្នកហៅត្រូវតែអាចនិយាយ `/v1` និងការគ្រប់គ្រងផងដែរ។

## ទម្រង់ Header

```http
Authorization: Bearer oma_live_<secret>
Authorization: Bearer sk-<secret>
Cookie: auth_token=<dashboard-jwt>
```

កុំដាក់ព័ត៌មានសម្ងាត់គ្រប់គ្រងនៅក្នុង URL path ឬ query string។ ការផ្ទៀងផ្ទាត់ភាពត្រឹមត្រូវនៃការគ្រប់គ្រងគឺមានតែនៅក្នុង header/cookie ប៉ុណ្ណោះ។

## ឧទាហរណ៍សម្រាប់ចម្លង-បិទភ្ជាប់

អានតែប៉ុណ្ណោះ (រាយបញ្ជី provider)។ ប្រើ Access Token ប្រភេទ `read`៖

```bash
curl -sS "$OMNIROUTE_URL/api/providers" \
  -H "Authorization: Bearer oma_live_<read-token>"
```

កែប្រែ (បង្កើតការតភ្ជាប់ provider)។ ប្រើ Access Token ប្រភេទ `write`/`admin` ឬ API key ដែលមានវិសាលភាពគ្រប់គ្រង៖

```bash
curl -sS -X POST "$OMNIROUTE_URL/api/providers" \
  -H "Authorization: Bearer oma_live_<write-or-admin-token>" \
  -H "Content-Type: application/json" \
  -d '{"provider":"openai","apiKey":"<upstream-key>"}'
```

ការទាញយក (មិនមែនការគ្រប់គ្រង)។ API key ធម្មតា មិនតម្រូវឱ្យមាន `manage` ទេ៖

```bash
curl -sS "$OMNIROUTE_URL/v1/models" \
  -H "Authorization: Bearer sk-<inference-key>"
```

## កំហុសពេលដំណើរការបច្ចុប្បន្ន (កុំបង្ហាញលេខសម្ងាត់)

| ស្ថានភាព                                         | ស្ថានភាពធម្មតា | សារ (បានសម្អាត)                                                      |
| :----------------------------------------------- | :------------- | :------------------------------------------------------------------- |
| គ្មានព័ត៌មានសម្ងាត់                              | 401            | `Authentication required`                                            |
| Invalid/expired `oma_live_…`                     | 401            | `Invalid or expired access token`                                    |
| API key ត្រឹមត្រូវដែលគ្មាន `manage`/`admin`      | 403            | `API key lacks 'manage' scope. Enable it in the API Keys dashboard.` |
| API key ធម្មតាមិនត្រឹមត្រូវនៅលើ management route | 403            | `Invalid management token`                                           |
| វិសាលភាព Access Token ទាបពេក                     | 403            | `Access token scope '<have>' is insufficient; '<need>' required.`    |

"Invalid management token" មានន័យថា bearer **មិន** ត្រូវបានទទួលយកជាព័ត៌មានសម្ងាត់គ្រប់គ្រងទេ។ វាមិនប្រាប់អ្នកថាត្រូវបង្កើត family មួយណាទេ។ ប្រើតារាងខាងលើ: inference keys ត្រូវការវិសាលភាព `manage`; remote CLI ត្រូវការ `oma_live_…`; ផ្ទាំងគ្រប់គ្រងប្រើ session cookie។
