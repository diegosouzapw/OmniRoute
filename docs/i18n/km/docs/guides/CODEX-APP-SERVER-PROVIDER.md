## 1. ស្ថាបត្យកម្ម

```
┌─ កម្មវិធី OmniRoute ─────────────┐        ┌─ sidecar របស់ codex-app-server ─────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ ថូខឹនសមត្ថភាព)                │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  គ្រប់គ្រង OpenAI OAuth ដោយខ្លួនឯង  │
└──────────────────────────────────┘        │  (~/.codex/auth.json, ធ្វើឱ្យស្រស់ស្វ័យប្រវត្តិ) │
        │ ចែករំលែក (volume របស់ compose)     └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → ថូខឹនសមត្ថភាព WS (ទាំងពីរភ្ជាប់វា)
  codex-appserver-home    → ~/.codex (auth.json ត្រូវបានសរសេរដោយ dashboard
                             និងអានដោយ codex app-server របស់ sidecar)
```

- sidecar ស្តាប់ **តែ** នៅលើបណ្តាញ compose ខាងក្នុង
  (`ws://codex-app-server:1456`) ដែលការពារដោយថូខឹនសមត្ថភាព។ វា **មិនដែល**
  ត្រូវបានបើកផ្សាយទៅ host ឬអ៊ីនធឺណិតទេ។
- Codex CLI ត្រូវបានដាក់បញ្ចូលជាស្រេចក្នុង `omniroute:base` ដូច្នេះមិនចាំបាច់ដំឡើង codex លើ
  host ឬម៉ាស៊ីនរបស់អ្នកប្រើទេ នៅពេលអ្នកដំណើរការ sidecar។

## 2. ដំណើរការវា

```bash
# ចាប់ផ្តើម stack ដោយរួមបញ្ចូល profile របស់ codex app-server sidecar៖
docker compose --profile base --profile codex-app-server up -d
# (podman៖ podman compose --profile base --profile codex-app-server up -d)
```

sidecar បង្កើតថូខឹនសមត្ថភាព WS របស់វានៅពេល boot លើកដំបូង (ចូលទៅក្នុង volume
`codex-appserver-token` ដែលបានចែករំលែក) ហើយកម្មវិធីអានថូខឹនដូចគ្នាតាមរយៈ
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`។ មិនចាំបាច់ភ្ជាប់ថូខឹនដោយដៃទេ។

## 3. ភ្ជាប់ + ចូលគណនី

1. នៅក្នុង dashboard សូមបន្ថែមការតភ្ជាប់សម្រាប់ **OpenAI Codex (App-Server)**។ មិនតម្រូវឱ្យមាន API
   key ឬថូខឹនទេ (វាជាក្រុមហ៊ុនផ្តល់សេវាដែលមិនត្រូវការការផ្ទៀងផ្ទាត់ — sidecar ជាអ្នកគ្រប់គ្រងការផ្ទៀងផ្ទាត់)។
2. ប្រសិនបើ Codex CLI របស់ sidecar **មិនទាន់បានចូលគណនី** ការត្រួតពិនិត្យស្ថានភាព
   ការតភ្ជាប់នឹងរាយការណ៍ថា _"កំពុងដំណើរការ ប៉ុន្តែមិនទាន់បានចូលគណនី"_ (មិនមែនជាកំហុសការផ្ទៀងផ្ទាត់ពណ៌ក្រហមទេ)។ ប្រើ
   **ចូលគណនីជាមួយ ChatGPT**៖ វានឹងដំណើរការ device-OAuth ស្តង់ដាររបស់ Codex នៅក្នុង
   browser របស់អ្នក ហើយបន្ទាប់មកសរសេរ `~/.codex/auth.json` ចូលទៅក្នុង volume ដែលបានចែករំលែកតាមរយៈ
   **អនុវត្តការផ្ទៀងផ្ទាត់** (ការចូលគណនីតែមួយនេះបម្រើទាំងក្រុមហ៊ុនផ្តល់សេវា `codex` និង
   `codex-app-server`)។
3. បន្ទាប់ពីបានចូលគណនី ការត្រួតពិនិត្យស្ថានភាពនឹងប្រែជាពណ៌បៃតង (វាផ្ទៀងផ្ទាត់ទាំង `/readyz` **និង**
   `account/read` — នោះគឺ កំពុងដំណើរការ _និង_ បានផ្ទៀងផ្ទាត់) ហើយចាប់ផ្តើមទទួលការងារ។

dashboard មិនដែលសរសេរជាន់លើ `~/.codex/auth.json` ដែលមានស្រាប់ និងដំណើរការល្អទេ — វាសរសេរ
តែនៅពេលឯកសារមិនមាន ឬថូខឹនរបស់វាហួសសុពលភាពប៉ុណ្ណោះ (ការបម្រុងទុកតែងតែត្រូវបានបង្កើត)។

## 4. សេណារីយ៉ូនៃការដាក់ឱ្យប្រើប្រាស់

- **ប្រតិបត្តិករដែលមាន Codex CLI បានផ្ទៀងផ្ទាត់រួចហើយ** — ភ្ជាប់
  `~/.codex` របស់ host អ្នកទៅក្នុង sidecar (`codex-appserver-home`) ហើយរំលងជំហានចូលគណនី។
- **អ្នកប្រើសាធារណៈ ដែលមិនបានដំឡើង codex នៅមូលដ្ឋាន** — មិនជាបញ្ហាទេ៖ sidecar មាន
  CLI រួចហើយ។ អ្នកប្រើគ្រាន់តែផ្ទៀងផ្ទាត់តាមរយៈ dashboard ប៉ុណ្ណោះ។
- **OmniRoute លើ bare-metal (គ្មាន sidecar ប្រើ codex របស់ host)** — កំណត់
  `OMNIROUTE_CODEX_APPSERVER_WS` ឱ្យចង្អុលទៅ `codex app-server` របស់អ្នក ហើយធានាថា
  codex របស់ host បានចូលគណនីរួច; ព័ត៌មានជំនួយ "មិនបានដំឡើង codex" នឹងបង្ហាញ ប្រសិនបើគ្មាន binary។

## 5. Residential / UDP egress (ជម្រើសបន្ថែមសម្រាប់ប្រតិបត្តិករ មិនបានរួមបញ្ចូល)

sidecar ទូទៅខាងលើបញ្ជូន traffic ចេញតាមបណ្តាញធម្មតារបស់ container។ ប្រតិបត្តិករ
ដែលត្រូវការឱ្យ traffic របស់ Codex ចេញតាម **residential exit** (ឧ. TUN
tailscale sidecar ដែលដឹកជញ្ជូន TCP + UDP/QUIC) អាចដំណើរការវាជា compose
override ដាច់ដោយឡែក; វា **មិនមែន** ជាផ្នែកនៃ profile `codex-app-server`
ដែលបានផ្តល់ជូនដោយចេតនា។ សូមមើលសៀវភៅណែនាំប្រតិបត្តិការផ្ទៃក្នុងសម្រាប់ការរៀបចំនោះ។
