## របៀបប៉ាន់ស្មានថ្លៃចំណាយ

### ប្រភពតម្លៃ

ថ្លៃចំណាយបានមកពីតារាងតម្លៃដែលត្រូវបានដោះស្រាយតាមលំដាប់អាទិភាពនេះ
([`src/lib/pricingSync.ts`](../../src/lib/pricingSync.ts))៖

1. **ការកំណត់ជំនួសដោយអ្នកប្រើប្រាស់** — តម្លៃដែលអ្នកកំណត់នៅក្នុងផ្ទាំងគ្រប់គ្រង / តាមរយៈ `PATCH /api/pricing`។
2. **តម្លៃខាងក្រៅដែលបានធ្វើសមកាលកម្ម** — ទាញយកពី
   `model_prices_and_context_window.json` សាធារណៈរបស់ LiteLLM នៅពេលបើកការធ្វើសមកាលកម្ម (រក្សាទុកក្នុង
   namespace `pricing_synced` ដាច់ដោយឡែក ដូច្នេះវាមិនអាចសរសេរជាន់លើការកំណត់ជំនួសរបស់អ្នកបានទេ)។
3. **តម្លៃលំនាំដើមដែលបានសរសេរជាប់ក្នុងកូដ** — ផ្តល់មកជាមួយ OmniRoute។

ការធ្វើសមកាលកម្មតម្លៃខាងក្រៅគឺ **ត្រូវតែជ្រើសរើសបើក** ហើយត្រូវបានបិទតាមលំនាំដើម។ env vars ពាក់ព័ន្ធ
(សូមមើល [`.env.example`](../../.env.example))៖

| Env var                 | លំនាំដើម  | គោលបំណង                                                                   |
| ----------------------- | --------- | ------------------------------------------------------------------------- |
| `PRICING_SYNC_ENABLED`  | `false`   | បើកការធ្វើសមកាលកម្មតម្លៃ LiteLLM នៅផ្ទៃខាងក្រោយពេលចាប់ផ្តើម។              |
| `PRICING_SYNC_INTERVAL` | `86400`   | ចន្លោះពេលធ្វើសមកាលកម្មគិតជា **វិនាទី** (លំនាំដើមម្តងក្នុងមួយថ្ងៃ)។        |
| `PRICING_SYNC_SOURCES`  | `litellm` | បញ្ជីប្រភពដែលបំបែកដោយសញ្ញាក្បៀស (បច្ចុប្បន្នគាំទ្រតែ `litellm` ប៉ុណ្ណោះ)។ |

### រូបមន្តគណនាថ្លៃចំណាយ

ថ្លៃចំណាយត្រូវបានគណនាសម្រាប់សំណើនីមួយៗពីចំនួន token និងអត្រាក្នុងមួយលាន token នៅក្នុង
[`src/lib/usage/costCalculator.ts`](../../src/lib/usage/costCalculator.ts)
(`computeCostFromPricing` / `calculateCost`)៖

- **Input tokens** (ដក cache reads និង cache-creation tokens) × អត្រា `input`។
- **Cache-read tokens** × អត្រា `cached` (បើគ្មាន ប្រើអត្រា input ជំនួស)។
- **Cache-creation tokens** × អត្រា `cache_creation` (បើគ្មាន ប្រើអត្រា input ជំនួស)។
- **Output tokens** × អត្រា `output`។
- **Reasoning tokens** × អត្រា `reasoning` (បើគ្មាន ប្រើអត្រា output ជំនួស)។

អត្រាទាំងអស់ត្រូវបានបកស្រាយជា USD ក្នុងមួយ 1,000,000 tokens។ កម្រិតសេវា "fast"/"priority" ឬ
"flex" របស់ Codex អនុវត្តមេគុណថ្លៃចំណាយ (`getCodexFastCostMultiplier`) — ឧ. flex
ត្រូវបានគិតថ្លៃជាមួយការបញ្ចុះតម្លៃ token 50% ដែលបង្ហាញជា **ការសន្សំ flex** នៅលើផ្ទាំងគ្រប់គ្រង។

ឈ្មោះ model ត្រូវបានធ្វើឱ្យមានទម្រង់ស្តង់ដារជាមុន (prefix ផ្លូវរបស់ provider ដូចជា `openai/` ឬ
`accounts/fireworks/models/` ត្រូវបានដកចេញ) ដូច្នេះជួរដេកប្រវត្តិសាស្ត្រនៅតែអាចផ្គូផ្គងនឹងតម្លៃបាន។

### របៀបកត់ត្រាការចំណាយ

- ថ្លៃចំណាយក្នុងមួយសំណើត្រូវបានគណនាបន្ទាប់ពីទទួល response និងកត់ត្រាតាមបែប fire-and-forget ដើម្បីកុំឱ្យវា
  បន្ថែម latency ដល់ client។ ការប្រើប្រាស់ quota រួមត្រូវបានកំណត់ពេលនៅ event-loop tick បន្ទាប់
  តាមរយៈ [`src/lib/quota/spendRecorder.ts`](../../src/lib/quota/spendRecorder.ts)។
- ការចំណាយតាម API key ត្រូវបានដាក់ក្នុង buffer និង flush ជាបាច់ដោយ
  [`SpendBatchWriter`](../../src/lib/spend/batchWriter.ts) (ចន្លោះពេល flush លំនាំដើម 60s,
  buffer 1,000 ធាតុ)។ អាចកែសម្រួលតាមរយៈ៖

  | Env var                             | លំនាំដើម | គោលបំណង                                    |
  | ----------------------------------- | -------- | ------------------------------------------ |
  | `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` | `60000`  | ចន្លោះពេល flush គិតជាមីលីវិនាទី។           |
  | `OMNIROUTE_SPEND_MAX_BUFFER_SIZE`   | `1000`   | ចំនួនធាតុអតិបរមាក្នុង buffer មុនពេល flush។ |

តួលេខថ្លៃចំណាយនៅលើផ្ទាំងគ្រប់គ្រង **មិនមែន** អានពីចំនួនប្រាក់ដុល្លារក្នុងមួយជួរដេកដែលបានរក្សាទុកទេ — តួលេខទាំងនោះ
ត្រូវបានគណនាឡើងវិញភ្លាមៗពីចំនួន token និងតារាងតម្លៃបច្ចុប្បន្ន រាល់ពេល analytics endpoint
ដំណើរការ។ នេះមានន័យថា ការកែតម្លៃខុស (និងការធ្វើសមកាលកម្មឡើងវិញ) នឹងធ្វើបច្ចុប្បន្នភាព
ការប៉ាន់ស្មានថ្លៃចំណាយជាប្រវត្តិសាស្ត្រដោយមានប្រសិទ្ធភាពត្រឡប់ក្រោយ។

## ផ្ទាំងគ្រប់គ្រង៖ ទំព័រ Costs

ទំព័រ **Costs** ស្ថិតនៅ `/dashboard/costs`
(`src/app/(dashboard)/dashboard/costs/`)។
ទិដ្ឋភាពសំខាន់របស់វាគឺផ្ទាំង **Cost Overview**
(`src/app/(dashboard)/dashboard/costs/CostOverviewTab.tsx`)
ដែលផ្ទុកទិន្នន័យទាំងអស់ពី `GET /api/usage/analytics`។

អ្វីដែលវាបង្ហាញ៖

- **ផ្ទាំងសង្ខេបការចំណាយ** — ការចំណាយប៉ាន់ស្មានសម្រាប់ _ថ្ងៃនេះ (1d)_, _7d_, _30d_ និងចន្លោះពេលដែលបានជ្រើសរើស។ ឧបករណ៍ជ្រើសរើសចន្លោះពេល៖ `7d`, `30d`, `90d`, `all`។
- **រង្វាស់សំខាន់ៗ** — ចំនួនសំណើក្នុងចន្លោះពេល ក្រុមហ៊ុនផ្តល់សេវាដែលសកម្ម ម៉ូដែលដែលសកម្ម និងតម្លៃជាមធ្យមក្នុងមួយសំណើ។
- **កម្មវិធីរុករកការចំណាយ** — តារាងដែលអាចតម្រៀប/ត្រងបាន ដោយដាក់ជាក្រុមតាម **ក្រុមហ៊ុនផ្តល់សេវា**, **ម៉ូដែល**, **API key**, **គណនី** ឬ **កម្រិតសេវាកម្ម** ព្រមទាំងបង្ហាញតម្លៃ ចំនួនសំណើ ចំនួន token តម្លៃជាមធ្យម/សំណើ និងភាគរយនៃការចំណាយសរុប។
- **ការប្រើប្រាស់ token** — ចំនួន token សរុប / input / output និងសមាមាត្រ input:output។
- **ប្រសិទ្ធភាពនៃការបញ្ជូន** — ចំនួន fallback អត្រា fallback និងវិសាលភាពគ្របដណ្តប់ម៉ូដែលដែលបានស្នើសុំ។
- **ការព្យាករណ៍ប្រចាំខែ** — ព្យាករណ៍ការចំណាយនៅចុងខែពីមធ្យមភាគប្រចាំថ្ងៃថ្មីៗ។
- **ការប្រៀបធៀបរយៈពេល** — ភាគរយនៃការប្រែប្រួលរវាងពាក់កណ្តាលទីមួយ និងពាក់កណ្តាលទីពីរនៃចន្លោះពេល។
- **គំនូសតាង** — និន្នាការតម្លៃប្រចាំថ្ងៃ ចំណែករបស់ក្រុមហ៊ុនផ្តល់សេវា (គំនូសតាងរង្វង់) ក្រុមហ៊ុនផ្តល់សេវាឈានមុខ ម៉ូដែលឈានមុខ តម្លៃតាម API key តម្លៃតាមគណនី លំនាំប្រើប្រាស់ប្រចាំសប្តាហ៍ និងផែនទីកម្ដៅសកម្មភាព។
- **ការនាំចេញ** — ទាញយកចន្លោះពេលបច្ចុប្បន្នជា **CSV** ឬ **JSON** (ប៊ូតុងនឹងបង្ហាញនៅពេលមានទិន្នន័យតម្លៃធំជាងសូន្យ)។

នៅពេលគ្មានចរាចរណ៍ដែលមានតម្លៃ ជួរដេកនឹងបង្ហាញស្លាក "Legacy / Free" ជំនួសឱ្យ `$0` ដោយឆ្លុះបញ្ចាំងពីម៉ូដែលតាមដានការសន្សំ។

## CLI

CLI របស់ OmniRoute ផ្ដល់នូវពាក្យបញ្ជាសម្រាប់ថ្លៃចំណាយ ការប្រើប្រាស់ និងតម្លៃ (ដែលបានចុះឈ្មោះនៅក្នុង
[`bin/cli/commands/registry.mjs`](../../bin/cli/commands/registry.mjs))។

### `omniroute cost`

របាយការណ៍ថ្លៃចំណាយដែលបានប្រមូលផ្ដុំពី `/api/usage/analytics`។

```bash
omniroute cost                          # 30d ចុងក្រោយ ដាក់ជាក្រុមតាមអ្នកផ្ដល់សេវា
omniroute cost --period 7d              # 7 ថ្ងៃចុងក្រោយ
omniroute cost --group-by model         # ដាក់ជាក្រុមតាម provider | model | combo | api-key | day
omniroute cost --since 2026-06-01 --until 2026-06-13
omniroute cost --api-key <key> --limit 50
```

ជួរឈរ៖ ក្រុម ចំនួនសំណើ token ចូល/ចេញ ថ្លៃចំណាយ (USD) និងភាគរយនៃចំនួនសរុប។ បន្ទាត់សរុបរួម
ត្រូវបានបង្ហាញនៅចុងបញ្ចប់ (មិនបង្ហាញនៅពេលប្រើ `--quiet` ឬ `--output json`)។

### `omniroute pricing`

```bash
omniroute pricing list [--provider <p>] [--model <m>] [--limit 200]
```

> `pricing defaults show` អានពី `GET /api/pricing/defaults`។ ដើម្បីកែសម្រួលតម្លៃរបស់ម៉ូដែលនីមួយៗ
> សូមប្រើទំព័រ **តម្លៃ** នៅលើផ្ទាំងគ្រប់គ្រង ឬ `PATCH /api/pricing`។

## ការដោះស្រាយបញ្ហា

- **ថ្លៃចំណាយទាំងអស់បង្ហាញ $0 / "ចាស់ / ឥតគិតថ្លៃ"។** ម៉ូដែលដែលកំពុងប្រើមិនមានធាតុតម្លៃទេ។
  បើកដំណើរការការធ្វើសមកាលកម្មពីខាងក្រៅ (`PRICING_SYNC_ENABLED=true`) ហើយដំណើរការ `omniroute pricing sync` ឬ
  កំណត់តម្លៃដោយដៃតាមរយៈទំព័រតម្លៃ / `PATCH /api/pricing`។
- **ម៉ូដែលពីមុនមួយមានតម្លៃមិនត្រឹមត្រូវ។** កែតម្លៃ (កំណត់ជំនួស ឬធ្វើសមកាលកម្មឡើងវិញ) — ថ្លៃចំណាយត្រូវបាន
  គណនាឡើងវិញពីចំនួន token រាល់ពេលអានទិន្នន័យវិភាគ ដូច្នេះការប៉ាន់ស្មាននឹងធ្វើបច្ចុប្បន្នភាពដល់ទិន្នន័យពីមុន។
- **ការចំណាយមានភាពយឺតយ៉ាវជាងពេលវេលាជាក់ស្ដែង។** ការចំណាយតាម key នីមួយៗត្រូវបានដំណើរការជាបាច់; បន្ថយ
  `OMNIROUTE_SPEND_FLUSH_INTERVAL_MS` ប្រសិនបើអ្នកត្រូវការទិន្នន័យថ្មីជាងមុន។
