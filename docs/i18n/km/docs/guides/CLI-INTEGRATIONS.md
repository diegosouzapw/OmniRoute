OmniRoute ផ្តល់ជូនក្រុមពាក្យបញ្ជា `setup-*` ដែលកំណត់រចនាសម្ព័ន្ធ CLI សម្រាប់សរសេរកូដ
(Codex, Claude Code, OpenCode, Cline, …) ឱ្យប្រើ OmniRoute ជា backend របស់វា — ដូច្នេះ
ឧបករណ៍នោះទាក់ទងទៅកាន់ endpoint **តែមួយ** ហើយ OmniRoute បញ្ជូនសំណើទៅកាន់ provider ដែលត្រឹមត្រូវ
ជាមួយនឹងការប្ដូរទៅជម្រើសបម្រុងដោយស្វ័យប្រវត្តិ។ ពាក្យបញ្ជានីមួយៗអានកាតាឡុកម៉ូដែល **ផ្ទាល់**
ពី OmniRoute ដែលកំពុងដំណើរការ (ក្នុងម៉ាស៊ីន ឬពីចម្ងាយ) ហើយសរសេរទៅឯកសារកំណត់រចនាសម្ព័ន្ធផ្ទាល់របស់ឧបករណ៍នៅលើម៉ាស៊ីន
**របស់អ្នក**។ API key ត្រូវបានយោងតាម environment variable នៅគ្រប់កន្លែងដែលឧបករណ៍
គាំទ្រវា។ ពាក្យបញ្ជាដែលរក្សាទុកឯកសារ environment មូលដ្ឋានរបស់ឧបករណ៍ត្រូវបានកត់សម្គាល់ខាងក្រោម។

ក៏មានកម្មវិធីបើកដំណើរការទូទៅមួយផងដែរ — `omniroute run <target>` — ដែលបើកដំណើរការ
`claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` ឬ `gemini` ដោយបញ្ចូល
environment ត្រឹមត្រូវ ដោយមិនសរសេរការកំណត់រចនាសម្ព័ន្ធណាមួយឡើយ។ គោលដៅ និង
ឈ្មោះក្លែងកាត់របស់ពួកវាមកពី manifest ស្តង់ដារ `bin/cli/cli-manifest.mjs`
(`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`,
`open-code`, `qwen-code`, `gemini-cli`) ហើយ `omniroute completion` ផ្ដល់
ពាក្យគោលដៅដែលទាញយកពី manifest ដូចគ្នា។ កម្មវិធីបើកដំណើរការដាច់ដោយឡែកសម្រាប់ឧបករណ៍នីមួយៗពីជំនាន់ចាស់ —
`omniroute launch` (Claude Code) និង `omniroute launch-codex` (Codex) — នៅតែ
អាចប្រើបាន។

ការចាប់ផ្ដើមប្រើប្រាស់ provider អាចធ្វើបានពី context ក្នុងម៉ាស៊ីន ឬពីចម្ងាយដូចគ្នា។ ពាក្យបញ្ជា
ដែលផ្ដោតលើ API ខាងក្រោមរក្សាការផ្ទៀងផ្ទាត់សម្រាប់ការគ្រប់គ្រងឱ្យដាច់ដោយឡែកពីព័ត៌មានសម្ងាត់របស់ provider
ហើយមិនបង្ហាញព័ត៌មានសម្ងាត់នៅក្នុងលទ្ធផលដែលមានរចនាសម្ព័ន្ធឡើយ៖

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

សម្រាប់ស្គ្រីប គួរប្រើ `--credential-stdin` ឬ `--credential-env`; `--credential`
នៅតែរក្សាទុកសម្រាប់ការប្រើប្រាស់ក្នុងម៉ាស៊ីនដែលមានការគ្រប់គ្រង។ `providers remove` តម្រូវឱ្យមាន `--yes` នៅលើ
terminal ដែលមិនអន្តរកម្ម ហើយពាក្យបញ្ជាទាំងប្រាំគោរពតាម context ដែលកំពុងសកម្ម ឬ
ជម្រើសសកល `--base-url`/`--api-key`។

សម្រាប់ការរៀបចំមូលដ្ឋានដោយសរសេរផ្ទាល់តែម្ដងនៃសមាហរណកម្មពីរដែលមានមុខងារពេញលេញបំផុត សូមមើល
សេចក្ដីណែនាំលម្អិតសម្រាប់ឧបករណ៍នីមួយៗ៖

## តារាងមេ

ពាក្យបញ្ជាទាំងអស់គោរពតាម **active context** (កំណត់ដោយ `omniroute connect` សូមមើល
[Remote Mode](./REMOTE-MODE.md)) ឬ flag `--remote <url> --api-key <key>` ដែលបានបញ្ជាក់ជាក់លាក់។
"Local ទល់នឹង remote" ខាងក្រោមមានន័យថា៖ នៅពេលគ្មាន flag វាតម្រង់ទៅកាន់ `http://localhost:20128`;
នៅពេលមាន `--remote` (ឬ active remote context) វាទាញយកកាតាឡុកពី
server នោះ ហើយសរសេរការកំណត់រចនាសម្ព័ន្ធនៅលើម៉ាស៊ីន local។

កំណត់សម្គាល់អំពី flags (បានផ្ទៀងផ្ទាត់នៅក្នុងកូដប្រភពរបស់ command)៖

- `--remote <url>` — ទាញយក catalog ពី OmniRoute ពីចម្ងាយ (ជំនួស `--port`
  និង context ដែលកំពុងសកម្ម)។ `--api-key <key>` ផ្ដល់ credential សម្រាប់
  server នោះ (តាមលំនាំដើម ប្រើ env var `OMNIROUTE_API_KEY` ឬ token របស់ context ដែលកំពុងសកម្ម)។
- `--only <patterns>` — substring ដែលបំបែកដោយសញ្ញាក្បៀស; រក្សាទុកតែ model ID ដែលត្រូវគ្នា
  (ឧ. `--only glm,kimi`)។ មាននៅលើ `setup-codex`, `setup-claude`,
  `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush`។
- `--dry-run` — បង្ហាញឱ្យឃើញច្បាស់នូវអ្វីដែលនឹងត្រូវបានសរសេរ ដោយមិនប៉ះពាល់ដល់
  filesystem។ មាននៅលើ command `setup-*` ទាំងអស់ **លើកលែងតែ** `setup-cursor`
  (ដែលមិនសរសេរ file ឡើយ)។
- `--model <id>` — តម្រូវឱ្យមាន (ឬជ្រើសរើសតាមអន្តរកម្ម) សម្រាប់ tool ដែលមិនមាន
  ការរកឃើញ model ដោយស្វ័យប្រវត្តិ៖ Cline, Kilo, Roo, Goose, Qwen, Aider, 5dive។ Tool ទាំងនោះ
  ក៏ទទួលយក `--yes` សម្រាប់ការដំណើរការដែលមិនមានអន្តរកម្មផងដែរ (ដែលក្នុងករណីនោះតម្រូវឱ្យមាន `--model`)។
  `setup-opencode` ទទួលយក `--model` ដើម្បីកំណត់ model កម្រិតកំពូលតាមលំនាំដើម។
- `--model <id>` នៅលើ `omniroute run` អនុវត្តតាមការតភ្ជាប់តាម target នីមួយៗរបស់ manifest
  (`bin/cli/cli-manifest.mjs`)៖ **aider** ទទួលបាន `--model openai/<id>` និង
  **opencode** ទទួលបាន `--model omniroute/<id>` (prefix ត្រូវបានបន្ថែមតែនៅពេល id
  មិនទាន់មានវាប៉ុណ្ណោះ); **qwen** និង **gemini** ទទួលបាន id ដដែលៗ;
  **claude** ទទួលបានវាតាមរយៈ `ANTHROPIC_MODEL`, **goose** តាមរយៈ `GOOSE_MODEL` និង
  **codex** តាមរយៈ args `-c model_providers.omniroute.*`។ **Qwen គឺជា run
  target តែមួយគត់ដែលតម្រូវឱ្យមាន `--model` ជាដាច់ខាត** — `omniroute run qwen` ដែលគ្មានវា នឹងបញ្ចប់
  ដោយ exit code `2` ជាមួយ error ជាក់លាក់មួយ។
- `--port <port>` — port របស់ OmniRoute មូលដ្ឋាន (លំនាំដើម `20128`, ត្រូវបានមិនអើពើនៅពេលកំណត់
  `--remote`)។ មាននៅលើ `setup-*` ទាំងអស់ និង launcher ទាំងពីរ។
- exit code របស់ `omniroute run`៖ exit code ផ្ទាល់របស់ CLI កូនត្រូវបានបញ្ជូនបន្ត
  ដដែលៗ; `2` = argument មិនត្រឹមត្រូវ (target ដែលមិនគាំទ្រ, ខ្វះ
  `--model` ដែលតម្រូវឱ្យមាន, container guard); `127` = target binary មិនមាននៅក្នុង `PATH`;
  `130`/`143`/`129` នៅពេលការបើកដំណើរការត្រូវបានបញ្ចប់ដោយ `SIGINT`/`SIGTERM`/`SIGHUP`;
  `1` = ការបរាជ័យក្នុងការបើកដំណើរការ runtime ផ្សេងទៀត។
- launcher ទាំងពីរ (`launch`, `launch-codex`) ទទួលយក `--profile <name>` ដើម្បីជ្រើសរើស
  profile ដែលបានសរសេរដោយ `setup-claude` / `setup-codex` ព្រមទាំង args ដែលបញ្ជូនបន្តទៅ
  binary `claude` / `codex` មូលដ្ឋាន។

## ការប្រើប្រាស់ក្នុងមូលដ្ឋាន

នៅពេល OmniRoute កំពុងដំណើរការនៅលើ `localhost:20128` គ្រាន់តែដំណើរការពាក្យបញ្ជាដំឡើងសម្រាប់ឧបករណ៍របស់អ្នក។ កាតាឡុកត្រូវបានទាញយកពីម៉ាស៊ីនមេក្នុងមូលដ្ឋាន។

```bash
# Codex៖ សរសេរប្រូហ្វាល់មួយសម្រាប់ម៉ូដែលដែលត្រូវគ្នានីមួយៗទៅក្នុង ~/.codex/
omniroute setup-codex
codex --profile glm52            # ប្រើប្រូហ្វាល់ដែលបានបង្កើត

# Claude Code៖ សរសេរប្រូហ្វាល់តាមម៉ូដែល រួចបើកដំណើរការមួយ
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode៖ សរសេរ provider ដែលឆបគ្នាជាមួយ openai ដោយរួមបញ្ចូលម៉ូដែលទាំងអស់ក្នុងកាតាឡុក
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # យោងតាមរយៈ {env:OMNIROUTE_API_KEY} និងមិនរក្សាទុកលើថាសឡើយ

omniroute setup-aider --model glm/glm-5.2

omniroute setup-continue --dry-run
```

## ការប្រើប្រាស់ពីចម្ងាយ

```bash

  --only glm,kimi

# ប្រូហ្វាល់ Codex ពីកាតាឡុកពីចម្ងាយ

# បើកដំណើរការ CLI ដោយផ្ទាល់ជាមួយម៉ាស៊ីនពីចម្ងាយ
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

ជំនួសឱ្យការបញ្ជូន `--remote`/`--api-key` រាល់ពេល សូមចូលប្រើម្តង ហើយអនុញ្ញាតឱ្យ **បរិបទសកម្ម** ផ្តល់តម្លៃទាំងនោះដោយស្វ័យប្រវត្តិ៖

```bash
omniroute connect 192.168.0.15        # បង្កើត token ដែលមាន scope និងរក្សាទុកបរិបទ
omniroute setup-codex                 # ← ឥឡូវនេះប្រើកាតាឡុកពីចម្ងាយ
omniroute setup-opencode              # ← ដូចគ្នា
omniroute launch                      # ← Claude Code ជាមួយម៉ាស៊ីនពីចម្ងាយ
```

សូមមើល [របៀបពីចម្ងាយ](./REMOTE-MODE.md) សម្រាប់បរិបទ scope និងការគ្រប់គ្រង token។

## កង agent របស់ 5dive

[5dive](https://5dive.ai) ដំណើរការកង agent សរសេរកូដដែលដំណើរការរយៈពេលយូរ ដោយ agent នីមួយៗជា unit របស់ systemd ក្រោមអ្នកប្រើ Unix ផ្ទាល់ខ្លួន។ វាមិនមែនជា CLI សរសេរកូដដោយខ្លួនវាទេ ដូច្នេះគ្មានអ្វីសម្រាប់ `omniroute run` បើកដំណើរការឡើយ — `5dive` គឺជា target សម្រាប់ **កំណត់រចនាសម្ព័ន្ធតែប៉ុណ្ណោះ**។

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

ទម្រង់ទាំងពីរសរសេរ **ប្រូហ្វាល់ផ្ទៀងផ្ទាត់ភាពត្រឹមត្រូវ** មួយរបស់ 5dive ហើយ seat `claude` ទាំងអស់ដែលបានភ្ជាប់ជាមួយប្រូហ្វាល់នោះ នឹងទាក់ទងទៅ OmniRoute។ មានបីចំណុចដែលជាក់លាក់ចំពោះ target នេះ៖

- **វាដំណើរការនៅលើម៉ាស៊ីន fleet ក្នុងនាមជា root។** verb របស់ 5dive ធ្វើប្រតិបត្តិការលើ unit របស់ systemd ក្នុងមូលដ្ឋាន និងថត state ដែលគ្រប់គ្រងដោយ root ហើយមិនមានរបៀបពីចម្ងាយទេ។ recipe នឹងប្រតិបត្តិខ្លួនវាឡើងវិញតាមរយៈ `sudo` នៅពេលវាមិនទាន់ជា root (`--no-sudo` បិទសកម្មភាពនោះ ហើយបោះពុម្ពពាក្យបញ្ជាជំនួសវិញ)។
- **endpoint ត្រូវតែជា `https://` លុះត្រាតែវាជា loopback។** API key របស់ agent ត្រូវបានផ្ញើតាម URL នោះជាមួយគ្រប់សំណើ ហើយ 5dive បដិសេធ endpoint នៅក្រៅម៉ាស៊ីនដែលប្រើ plaintext។ អាសយដ្ឋាន LAN ឯកជនក៏មិនមែនជាករណីលើកលែងដែរ។
- **ការកំណត់ម៉ូដែលថេររបស់ seat នីមួយៗមានអាទិភាពជាងប្រូហ្វាល់។** ប្រូហ្វាល់មាន `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL` ប៉ុន្តែ seat ដែលនៅតែកំណត់ថេរទៅ model id ស្តង់ដារ នឹងបរាជ័យនៅ turn ដំបូងដោយបង្ហាញ _"មានបញ្ហាជាមួយម៉ូដែលដែលបានជ្រើសរើស"_។ បញ្ជូន `--agent <name>` (អាចធ្វើម្តងទៀតបាន) ដើម្បីកំណត់ seat ទាំងនោះផងដែរ។ recipe នឹងបោះពុម្ពពាក្យបញ្ជា នៅពេលអ្នកមិនធ្វើដូច្នោះ។

API key ត្រូវបានបញ្ជូនទៅ 5dive តាម **stdin** (`--api-key=-`) ដូច្នេះវាមិនដែលបង្ហាញក្នុងលទ្ធផលរបស់ `ps` ឡើយ។

ការតម្រង់ប្រូហ្វាល់ទៅកាន់ **combo** របស់ OmniRoute ជំនួសឱ្យម៉ូដែលតែមួយ គឺជាអ្វីដែលផ្តល់ failover របស់ provider ដល់ fleet៖ នៅពេល endpoint ចម្បងដាច់ទាំងស្រុងនៅពាក់កណ្តាល turn ក្នុងការដំណើរការដែលបានកត់ត្រានៅ
[#11578](https://github.com/diegosouzapw/OmniRoute/issues/11578) agent បានបញ្ចប់ជំហានដែលនៅសល់របស់វាលើ fallback ហើយមិនបានបង្ហាញការដាច់សេវានោះឡើយ។

## ការរក្សា native deps នៅពេលអាប់ដេត៖ `--include=optional`

នៅពេលអ្នកអាប់ដេតដោយប្រើ `omniroute update` (បន្ទាប់ពីបញ្ជាក់ ឬដោយប្រើ `--apply`) OmniRoute ដំណើរការការដំឡើងដោយបញ្ចូល `--include=optional` ជាស្រេច៖

```bash
npm install -g omniroute@latest --include=optional
```

នេះ **មិនមែន** ជា flag ដែលអ្នកត្រូវបញ្ជូនទៅ `omniroute update` ទេ — វាតែងតែត្រូវបានអនុវត្តដោយកម្មវិធីអាប់ដេត។ វាធានាថា `optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM stack) នៅតែមានបន្ទាប់ពីការអាប់ដេត ទោះបីជាការកំណត់រចនាសម្ព័ន្ធ npm របស់អ្នកបានកំណត់ `omit=optional` ក៏ដោយ ដែលបើមិនដូច្នោះទេ វានឹងលុប native SQLite driver និង OS-keyring binding ដោយស្ងាត់ៗ។ ដើម្បីមើល command ពិតប្រាកដជាមុនដោយមិនអនុវត្ត៖

```bash
omniroute update --dry-run
# [DRY RUN] នឹងដំណើរការ៖ npm install -g omniroute@latest --include=optional
```

flag ផ្សេងទៀតរបស់ `omniroute update` (បានផ្ទៀងផ្ទាត់ក្នុងកូដប្រភព)៖ `--check` (បញ្ចប់ដោយលេខកូដ 1 ប្រសិនបើហួសសម័យ), `--apply` (ដំឡើងដោយមិនសួរបញ្ជាក់), `--changelog`, `--no-backup`, `--yes`។

## Google Gemini CLI តាមរយៈ `omniroute run gemini`

កិច្ចសន្យាត្រូវបានផ្ទៀងផ្ទាត់ជាមួយ `@google/gemini-cli` 0.50.0៖ CLI គោរពតាម `GOOGLE_GEMINI_BASE_URL` ហើយផ្ញើ `POST /v1beta/models/<model>:generateContent` (និង `:streamGenerateContent?alt=sse`) ទៅកាន់វា — ត្រូវគ្នាយ៉ាងពិតប្រាកដនឹងផ្ទៃ Gemini ដើមរបស់ OmniRoute (`/v1beta`)។ `omniroute run gemini` កំណត់តភ្ជាប់វាដោយស្វ័យប្រវត្តិ៖

- `GOOGLE_GEMINI_BASE_URL` → OmniRoute base URL ដែលកំពុងសកម្ម (root ដោយគ្មាន `/v1`);
- `GEMINI_API_KEY` → ព័ត៌មានសម្ងាត់ OmniRoute ដែលបានដោះស្រាយ (ជម្រើស/env/context);
- **`GEMINI_CLI_HOME` ដាច់ដោយឡែកជាបណ្ដោះអាសន្ន** ដែល `.gemini/settings.json` របស់វាជ្រើសរើសការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ `gemini-api-key` ដូច្នេះ session Google OAuth ដែលបានរក្សាទុក (Code Assist) នឹងមិនអាចជំនួសការបើកដំណើរការដែលតម្រង់ទៅ OmniRoute បានទេ — វាត្រូវបានលុបបន្ទាប់ពីចាកចេញ;
- **អនាម័យ env**៖ env របស់ child ត្រូវបានសម្អាតដោយដក `GOOGLE_API_KEY`, `GOOGLE_GENAI_USE_VERTEXAI` និង `GOOGLE_GENAI_USE_GCA` ចេញ (ដែលអាចបង្វែរការផ្ទៀងផ្ទាត់អត្តសញ្ញាណទៅ Vertex/Code Assist) ហើយ `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` ត្រូវបានកំណត់ជាជម្រើសការពារបន្ថែម — គោលដៅ `run` ផ្សេងទៀតទទួលបានការដោះស្រាយដូចគ្នាសម្រាប់អថេរដែលមានភាពផ្ទុយគ្នារបស់ពួកវា;
- ការបញ្ចូល `--model <id>` ពី `--provider`/`--model`។

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

កម្មវិធីការពារភាពជឿទុកចិត្តលើ workspace របស់ Gemini នៅតែអនុវត្តក្នុង headless mode — សូមបញ្ជូន `--skip-trust` (ឬជឿទុកចិត្តលើ directory តាមរយៈអន្តរកម្ម) ដោយខ្លួនអ្នក; launcher មិនរំលងវាដោយចេតនា។ launcher នេះខុសពី **ការចុះឈ្មោះ ACP** (`src/lib/acp/registry.ts`, `gemini --acp`) ដែលនៅតែជាការរួមបញ្ចូល agent-protocol សម្រាប់ `/dashboard/acp-agents`។

## ការត្រួតពិនិត្យ smoke ពិតប្រាកដ (ត្រូវជ្រើសចូលប្រើ)

ការធ្វើតេស្តតំរែតំរង់នៃផែនការចាប់ផ្ដើមដែលអាចកំណត់លទ្ធផលឡើងវិញបាន ដំណើរការនៅក្នុង CI (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`)។ ដើម្បីផ្ទៀងផ្ទាត់ binary ពិតប្រាកដជាមួយម៉ាស៊ីនមេ OmniRoute ពិតប្រាកដ មាន harness ដែលត្រូវជ្រើសចូលប្រើនៅ
`tests/integration/upstream-cli-smoke.int.test.ts`។ វាមិនដែលដំណើរការដោយស្វ័យប្រវត្តិទេ
(រាល់តេស្តរងទាំងអស់ត្រូវបានរំលង លុះត្រាតែ `RUN_CLI_SMOKE=1`) ហើយបញ្ជូនព័ត៌មានសម្ងាត់តាមរយៈឈ្មោះ env-var
(មិនដែលបញ្ជូនតាមតម្លៃទេ) លាក់បាំងខ្សែអក្សរដែលមានទម្រង់ដូច key ពី output ណាមួយដែលបានកត់ត្រា រំលង
គោលដៅដែល binary របស់វាមិនត្រូវបានដំឡើង និងចាត់ថ្នាក់ការបរាជ័យជា
ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ / upstream / ការកំណត់រចនាសម្ព័ន្ធ ជំនួសឱ្យតម្លៃ boolean ធម្មតា៖

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

ជាជម្រើស៖ `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` កំណត់ការត្រួតពិនិត្យឱ្យនៅត្រឹមគោលដៅទាំងនេះ;
`OMNIROUTE_SMOKE_TIMEOUT_MS` កំណត់ជំនួសរយៈពេលអស់ពេល 120 វិនាទីសម្រាប់គោលដៅនីមួយៗ។
