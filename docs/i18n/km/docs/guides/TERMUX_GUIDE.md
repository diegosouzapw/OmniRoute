OmniRoute អាចដំណើរការជាម៉ាស៊ីនមេគ្មានចំណុចប្រទាក់ក្រាហ្វិកនៅលើ Android តាមរយៈ Termux។ កម្មវិធីផ្ទៃតុ Electron មិនត្រូវបានគាំទ្រនៅក្នុង Termux ទេ ប៉ុន្តែផ្ទាំងគ្រប់គ្រងលើបណ្ដាញ និង API ដែលឆបគ្នាជាមួយ OpenAI អាចប្រើបានពីកម្មវិធីរុករកក្នុងឧបករណ៍ ឬពីឧបករណ៍ផ្សេងទៀតនៅលើបណ្ដាញតែមួយ។

## តម្រូវការជាមុន

ដំឡើង Termux ពី F-Droid ឬកំណែចេញផ្សាយនៅលើ GitHub បន្ទាប់មកធ្វើបច្ចុប្បន្នភាពកញ្ចប់ និងដំឡើងឧបករណ៍សម្រាប់ build ដែលត្រូវការដោយ dependency ដើម ដូចជា `better-sqlite3`។

```bash
pkg update
pkg upgrade
pkg install nodejs python build-essential git
```

> **កំណែ Node.js:** OmniRoute ត្រូវការ Node `>=22.22.2 <23 || >=24.0.0 <27` (ត្រូវគ្នានឹង `engines` ក្នុង `package.json` / `SUPPORTED_NODE_RANGE`)។ `nodejs-lts` របស់ Termux ជាទូទៅផ្ដល់មកជាមួយ Node 20 LTS ដែល **លែងត្រូវបានគាំទ្រហើយ** — សូមដំឡើង `pkg install nodejs` (កំណែបច្ចុប្បន្ន) ជំនួសវិញ ហើយផ្ទៀងផ្ទាត់ថា `node --version` រាយការណ៍កំណែ 22.x/24.x ឬខ្ពស់ជាងនេះ។

ប្រសិនបើការចងក្រងកញ្ចប់ដើមបរាជ័យ សូមដំណើរការពាក្យបញ្ជា `pkg install` ខាងលើម្ដងទៀត រួចសាកល្បងដំឡើង OmniRoute ឡើងវិញ។

## ការដំឡើង

ដំណើរការកញ្ចប់ចេញផ្សាយចុងក្រោយដោយផ្ទាល់៖

```bash
npx -y omniroute@latest
```

អ្នកក៏អាចដំឡើងវាជាសកលបានផងដែរ៖

```bash
npm install -g omniroute
omniroute
```

## ការដំណើរការ

ចាប់ផ្ដើម OmniRoute ក្នុងរបៀបម៉ាស៊ីនមេគ្មានចំណុចប្រទាក់ក្រាហ្វិក៖

```bash
omniroute
```

ឬ៖

```bash
npx omniroute
```

ផ្ទាំងគ្រប់គ្រងស្ដាប់នៅ៖

```text
http://localhost:20128
```

បើក URL នោះក្នុងកម្មវិធីរុករក Android។ ប្រសិនបើអ្នកដំណើរការកម្មវិធី client នៅក្នុង Termux សូមប្រើ host និង port ដូចគ្នាជា URL មូលដ្ឋានដែលឆបគ្នាជាមួយ OpenAI។

## ការដំណើរការនៅផ្ទៃខាងក្រោយ

សម្រាប់ដំណើរការផ្ទៃខាងក្រោយសាមញ្ញ៖

```bash
nohup omniroute > omniroute.log 2>&1 &
```

ដើម្បីបញ្ឈប់វា៖

```bash
pkill -f omniroute
```

សម្រាប់ការចាប់ផ្ដើមដោយស្វ័យប្រវត្តិបន្ទាប់ពីឧបករណ៍ boot សូមដំឡើងកម្មវិធីបន្ថែម Termux:Boot និងបង្កើតស្គ្រីប boot៖

```bash
mkdir -p ~/.termux/boot
cat > ~/.termux/boot/omniroute.sh <<'EOF'
#!/data/data/com.termux/files/usr/bin/sh
cd "$HOME"
nohup omniroute > "$HOME/omniroute.log" 2>&1 &
EOF
chmod +x ~/.termux/boot/omniroute.sh
```

ការបង្កើនប្រសិទ្ធភាពថ្មរបស់ Android អាចបញ្ឈប់ដំណើរការផ្ទៃខាងក្រោយដែលដំណើរការយូរ។ សូមបិទការបង្កើនប្រសិទ្ធភាពថ្មសម្រាប់ Termux ប្រសិនបើត្រូវការឱ្យម៉ាស៊ីនមេបន្តនៅអនឡាញ។

## ការចូលប្រើពីឧបករណ៍ផ្សេងទៀត

ស្វែងរកអាសយដ្ឋាន IP របស់ទូរសព្ទនៅលើបណ្ដាញ WiFi៖

```bash
ip addr show wlan0
```

បន្ទាប់មកបើកផ្ទាំងគ្រប់គ្រងពីឧបករណ៍មួយផ្សេងទៀត៖

```text
http://PHONE_IP:20128
```

ឧទាហរណ៍៖

```text
http://192.168.1.50:20128
```

រក្សាទូរសព្ទ និង client ឱ្យនៅលើបណ្ដាញដែលអាចទុកចិត្តបានដូចគ្នា។ ប្រសិនបើអ្នកបើកឱ្យចូលប្រើ OmniRoute ពីខាងក្រៅទូរសព្ទ សូមបើកប្រើ API key និងការផ្ទៀងផ្ទាត់អត្តសញ្ញាណសម្រាប់ផ្ទាំងគ្រប់គ្រង។

## ថតទិន្នន័យ

តាមលំនាំដើម OmniRoute រក្សាទុកទិន្នន័យនៅក្រោមថត home របស់ Termux ដោយអនុវត្តតាមឥរិយាបថ path ទិន្នន័យខាងម៉ាស៊ីនមេដូចគ្នាដែលប្រើនៅលើ Linux។ ដើម្បីដាក់មូលដ្ឋានទិន្នន័យនៅទីតាំងជាក់លាក់មួយ៖

```bash
export DATA_DIR="$HOME/.omniroute"
omniroute
```

## ដែនកំណត់

- Electron មិនដំណើរការនៅក្នុង Termux ទេ។
- មិនមាន system tray ឬការរួមបញ្ចូលជាមួយផ្ទៃតុទេ។
- ការរៀបចំនេះគឺសម្រាប់តែម៉ាស៊ីនមេប៉ុណ្ណោះ៖ ប្រើផ្ទាំងគ្រប់គ្រងក្នុងកម្មវិធីរុករក។
- dependency ដើមអាចត្រូវការការចងក្រងនៅលើឧបករណ៍។
- ឧបករណ៍ Android ដែលមានអង្គចងចាំតិច អាចត្រូវកាត់បន្ថយចំនួនសំណើដំណាលគ្នា។
- មុខងារវិញ្ញាបនបត្រ MITM/ប្រព័ន្ធ អាចត្រូវការការកំណត់ trust store នៅកម្រិត Android ខាងក្រៅ Termux។

## ការដោះស្រាយបញ្ហា

### Platform ដែលមិនគាំទ្រ៖ android (រាល់សំណើទាំងអស់ត្រឡប់ HTTP 500)

**រោគសញ្ញា៖** `omniroute` / `omniroute serve` បង្ហាញ `✔ OmniRoute is running!` ប៉ុន្តែរាល់សំណើពីផ្ទាំងគ្រប់គ្រង ឬ API ទាំងអស់ ត្រឡប់ `500 Internal Server Error` ធម្មតា។ `~/.omniroute/logs/application/app.log` នៅតែទទេ `APP_LOG_LEVEL=debug` មិនបង្ហាញអ្វីដែលមានប្រយោជន៍ទេ ហើយ body នៃ response គឺជាអត្ថបទធម្មតា (`Internal Server Error`) ដោយគ្មានព័ត៌មានលម្អិតជា JSON។

**មូលហេតុ៖** Termux/Node build មួយចំនួនរាយការណ៍ `process.platform === "android"`។ `getCacheDirectory()` របស់ Next.js មិនគ្រប់គ្រង platform នោះទេ៖ វាតម្រូវឱ្យ `~/.cache` (ឬថត tmp ទូទៅ) មានរួចជាមុន បើមិនដូច្នោះទេ វានឹងបរាជ័យនៅពេលផ្ទុក instrumentation hook ជាមួយ៖

```text
Error: An error occurred while loading instrumentation hook: Unsupported platform: android
```

ដោយសារ hook មិនដែលត្រូវបានផ្ទុក ការកត់ត្រា log ក៏មិនចាប់ផ្ដើមដែរ — ដូច្នេះកំហុស 500 ហាក់ដូចជាមិនអាចវិនិច្ឆ័យបានទាំងស្រុង។ OmniRoute បង្កើត `~/.cache` (និងកំណត់ `XDG_CACHE_HOME` នៅពេលមិនទាន់បានកំណត់) នៅក្នុងចំណុចចូល CLI មុនពេល Next.js ចាប់ផ្ដើម ដើម្បីឱ្យការត្រួតពិនិត្យនេះជោគជ័យនៅលើ Android/Termux។

**ដំណោះស្រាយដែលគាំទ្រ (មិនចាំបាច់កែ patch កញ្ចប់)៖**

```bash
mkdir -p ~/.cache
omniroute serve
```

នៅលើ OmniRoute build បច្ចុប្បន្ន CLI ធ្វើដូចនេះដោយស្វ័យប្រវត្តិនៅលើ Android/Termux — ការដំឡើងថ្មីដោយ `npx -y omniroute@latest` / ការដំឡើងជាសកល មិនគួរត្រូវការជំហានដោយដៃនេះទេ។ ប្រសិនបើអ្នកនៅតែឃើញកំហុសបន្ទាប់ពីធ្វើបច្ចុប្បន្នភាព សូមបង្កើត `~/.cache` ម្ដងដូចខាងលើ ហើយចាប់ផ្ដើមឡើងវិញ។

**កុំ** កែ patch `dist/server.js` ដើម្បីបង្ខំ `process.platform = "linux"`។ ការកែ patch កញ្ចប់បែបនេះនឹងត្រូវសរសេរជាន់លើរាល់ពេលដំឡើង ឬធ្វើបច្ចុប្បន្នភាពឡើងវិញ ហើយវាមិនចាំបាច់ទេ នៅពេលថត cache មានរួចហើយ។

### Port កំពុងត្រូវបានប្រើរួចហើយ

ពិនិត្យមើលអ្វីដែលកំពុងស្ដាប់នៅលើ port លំនាំដើម៖

```bash
ss -ltnp | grep 20128
```

បញ្ឈប់ដំណើរការចាស់៖


### មិនអាចចូលប្រើផ្ទាំងគ្រប់គ្រងពីឧបករណ៍ផ្សេងទៀត

ផ្ទៀងផ្ទាត់ថាឧបករណ៍ទាំងពីរស្ថិតនៅលើបណ្ដាញ WiFi ដូចគ្នា បន្ទាប់មកសាកល្បងពី Termux៖

```bash
curl http://localhost:20128
```

ប្រសិនបើការចូលប្រើក្នុងឧបករណ៍ដំណើរការ ប៉ុន្តែការចូលប្រើតាម LAN មិនដំណើរការ សូមពិនិត្យមើលការបំបែក hotspot/WiFi របស់ Android និង firewall ឬ profile VPN ណាមួយនៅលើទូរសព្ទ។
