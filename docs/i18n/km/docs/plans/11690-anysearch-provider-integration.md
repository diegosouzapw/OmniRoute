## 1. ទិន្នន័យពិតរបស់សេវា (ឯកសារផ្លូវការ ដែលបានផ្ទៀងផ្ទាត់ឆ្លងគ្នា)

- URL មូលដ្ឋាន: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0)។
- `POST /v1/search` - ប៉ារ៉ាម៉ែត្រ: `query` (តម្រូវឱ្យមាន), `max_results` (1-10, លំនាំដើម 10), `tag` (`{domain}.{sub_domain}` ការបញ្ជូនតាមប្រភេទឈរ), `zone` (cn/intl), `language`, `params` (វាលប្រភេទឈរដែលមានរចនាសម្ព័ន្ធ), `format` (json/markdown)។
- `GET /v1/sub-domains?domain=...` - កាតាឡុកសមត្ថភាព មិនត្រូវបានរាប់បញ្ចូលក្នុងកូតាឡើយ។
- `POST /v1/extract` - ទាញយក/ស្រង់ `{url, title, content}`; តួសំណើ JSON តឹងរ៉ឹង មានដែនកំណត់ 16 KiB។
- `POST /v1/auth/email/register` - ការចុះឈ្មោះដោយការហៅតែមួយ ត្រឡប់កូនសោអត្ថបទធម្មតាប្រើបានម្តង `as_sk_...`។
- ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ: `Authorization: Bearer <as_sk_...>` ជាជម្រើស; ការប្រើប្រាស់អនាមិកនឹងត្រូវបន្ថយទៅកម្រិតកំណត់តាម IP ដោយប្រើប្រាស់កូតាឥតគិតថ្លៃប្រចាំថ្ងៃ; កូនសោមិនត្រឹមត្រូវត្រឡប់ 401/403 ដោយគ្មានការប្ដូរទៅអនាមិកដោយស្ងាត់ៗ។
- កម្រិតឥតគិតថ្លៃ: 1000 សំណើ/ថ្ងៃ, 20 QPS ក្នុងមួយកូនសោ។ កម្រិតបង់ប្រាក់: មិនទាន់មានតម្លៃកំណត់ (នឹងមកដល់ឆាប់ៗនេះ)។
- ស្រោមឆ្លើយតប: ជោគជ័យ `{code: 0, message: "success", request_id, data}`; បរាជ័យ `{code: -1, message}`។ កំហុសការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ/កូតាមិនមាន `error_code` ដែលមានរចនាសម្ព័ន្ធទេ (អត្ថបទសារគឺជាសញ្ញា); កំហុសជាក់លាក់សម្រាប់ការស្រង់មាន `error_code` (`invalid_extract_url`, `extract_failed`)។ មិនមានបឋមកថា `Retry-After` លើ 429 ទេ។

## 3. សេចក្តីសម្រេចចិត្ត (សម្រេចទាំងអស់នៅ 2026-08-26)

1. **គោលជំហរកំណត់ផ្លូវ៖ `fallbackOnly`។** ហេតុផល៖ អ្នកផ្តល់សេវាឥតគិតថ្លៃដែលមានតម្លៃ 0 មិនត្រូវគ្របដណ្ដប់លើការកំណត់ផ្លូវដោយស្វ័យប្រវត្តិផ្អែកលើតម្លៃឡើយ។ ការជ្រើសរើសដោយបញ្ជាក់ច្បាស់ និងការត្រឡប់ក្រោយពេលមានបរាជ័យ មិនទទួលរងផលប៉ះពាល់ទេ។ គំរូមុន៖ ធាតុ xquik ដែលបានបញ្ចូលចូលគ្នា។
2. **វិសាលភាព៖ webSearch + webFetch តាមរយៈ `POST /v1/extract` ក្នុង v1។** ស្របតាមគំរូគំនិតសមត្ថភាពពីររបស់ tavily/exa។ ផ្ទៃមុខងារបញ្ឈរ (`tag`, `sub-domains`, `batch_search`) មិនស្ថិតក្នុងវិសាលភាពទេ — បច្ចុប្បន្នមិនមាន IR សម្រាប់ប៉ារ៉ាម៉ែត្របញ្ឈរឡើយ។
3. **ការបង្ហាញកូតា៖ `freeMonthlyQuota: 0`** (ការបង្ហាញបែបប្រុងប្រយ័ត្នដូច xquik)។ ចំនួនអនុញ្ញាតជាក់ស្តែង (1000 សំណើ/ថ្ងៃ កំណត់ឡើងវិញរៀងរាល់ថ្ងៃ) ត្រូវបានបង្ហាញជំនួសវិញនៅក្នុងអត្ថបទ `authHint` នៃកាតាឡុក UI។ ហេតុផល៖ ការបង្ហាញកូតាត្រូវតែត្រូវគ្នានឹងលក្ខខណ្ឌកំណត់ឡើងវិញ។ ការបម្លែងដែនកំណត់ប្រចាំថ្ងៃទៅជាចំនួនសមមូលប្រចាំខែ (30000) គឺជាការសន្យាមិនពិតដែល UI មិនអាចបំពេញបាន។
4. **searchTypes៖ `["web"]` ប៉ុណ្ណោះ។** មិនមានភស្តុតាងសាធារណៈអំពីមុខងារបញ្ឈរសម្រាប់ព័ត៌មាន/រូបភាពនៅក្នុង AnySearch API ទេ។ ច្រកទ្វារដែលរួមបញ្ចូល API ដោយគ្មានមុខងារបញ្ឈរដែលបានចងក្រងជាឯកសារ (ឧ. Google Custom Search) បង្ហាញតែការស្វែងរកតាមវេបប៉ុណ្ណោះ ជាជាងផ្គូផ្គងព័ត៌មាន -> វេបដោយស្ងៀមស្ងាត់។
5. **គោលជំហរចំពោះសោ៖** អាចដំណើរការដោយគ្មានសោ។ សោមិនត្រឹមត្រូវបញ្ជូនត្រឡប់ 401/403 ហើយមិនត្រូវបានបន្ទាបកម្រិតទៅជាអនាមិកដោយស្ងៀមស្ងាត់ឡើយ (ឆ្លុះបញ្ចាំងកិច្ចសន្យារបស់ប្រព័ន្ធដើម)។
6. **ការដកចេញដោយចេតនា៖** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (ការស្ទាក់ចាប់ការជជែកនៅតែប្រើ firecrawl/jina/tavily); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (endpoint ពីចម្ងាយដែលអនុញ្ញាតអនាមិកប្រើក្រុមដែលកំណត់តាម IP រួមមួយសម្រាប់ IP ចេញនីមួយៗ ដូច្នេះ extract ដោយគ្មានសោត្រូវតែជ្រើសប្រើដោយចេតនា មិនមែនជាបេក្ខជនសម្រាប់ការកំណត់ផ្លូវស្វ័យប្រវត្តិទេ); `QUOTA_STATUS_PROVIDERS` (AnySearch ផ្តល់សញ្ញាអំពីកូតាតាមរយៈ 429/envelope មិនមែនស្ថានភាព 402/403 ទេ)។
