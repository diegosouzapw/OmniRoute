1. ចាក់សោកិច្ចសន្យា semaphore ដែលមានស្រាប់សម្រាប់ key តែមួយ និងកិច្ចសន្យាថ្មីបែប atomic សម្រាប់ key ច្រើន
   ដោយប្រើតេស្តដែលផ្តោតជាក់លាក់៖ គ្មានការកក់ទុកដោយផ្នែក, ការតម្រង់ជួរតាម FIFO, ការបោះបង់,
   timeout, ជួរពេញ, ការដោះលែងបែប idempotent, ស្ថិតិ និងការសម្អាត។
2. ធ្វើឱ្យ account semaphore ដែលមានស្រាប់មានលក្ខណៈទូទៅនៅនឹងកន្លែង។ រក្សា `acquire()` ជា
   compatibility wrapper ជុំវិញ `acquireMany()`; កុំបន្ថែម scheduler ទីពីរ
   ឬ dependency។
3. ជំនួសការទទួលយកសម្រាប់តែ account នៅក្នុង `chatCore` ដោយការទទួលយករួមតែមួយសម្រាប់
   global/provider/account ភ្លាមៗមុន `withRateLimit`។
   ទទួលយកសំណុំទាំងមូលឡើងវិញ រាល់ពេលដែលការប្ដូរ account ផ្លាស់ប្ដូរ connection
   ហើយរក្សាការដោះលែងរហូតដល់ streaming បញ្ចប់។
4. ពង្រីក pipeline នៃ resilience settings ដែលមានស្រាប់ (types, defaults,
   normalization, schema, API response, UI និងការបកប្រែ) ដោយបន្ថែមកម្រិតអតិបរមា global
   និង provider។ ដាក់ស្លាកឡើងវិញលើ Bottleneck concurrency control ចាស់ជា
   connection/quota-scope concurrency ដើម្បីបញ្ជាក់ឱ្យច្បាស់អំពីវិសាលភាពពិតប្រាកដរបស់វា។
5. ដំណើរការតេស្តដែលផ្តោតជាក់លាក់, lint, typecheck, static checks និងសំណុំតេស្តពេញលេញ;
   ចងក្រងឯកសារអំពីការផ្លាស់ប្ដូរឥរិយាបថនៅក្នុង changelog។

ឥរិយាបថដែលរក្សាទុកដោយចេតនា៖ concurrency ដែលមានតម្លៃសូន្យ/null រំលង gate,
អ្នកហៅដែលប្រើតែ account បន្តប្រើ `acquire()`, controls សម្រាប់ blocked-account រក្សា
key format និង API របស់ពួកវាដដែល ហើយឥរិយាបថជួរ provider rate-limit នៅតែមិនផ្លាស់ប្ដូរ។
