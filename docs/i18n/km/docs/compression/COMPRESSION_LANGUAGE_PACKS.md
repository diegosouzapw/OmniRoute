## ការរកឃើញភាសា

`languageDetector.ts` ប្រើវិធីសាស្ត្រសន្និដ្ឋានស្រាលៗ ដើម្បីកំណត់ភាសាពីអត្ថបទប្រអប់បញ្ចូល។ ភាសាលំនាំដើមដែលបានកំណត់នៅតែត្រូវបានគោរព ហើយការរកឃើញអាចត្រូវបានបិទតាមរយៈការកំណត់រចនាសម្ព័ន្ធ នៅពេលត្រូវការការគ្រប់គ្រងយ៉ាងជាក់លាក់។

លទ្ធផលនៃការរកឃើញត្រូវបានប្រើសម្រាប់តែជ្រើសរើសកញ្ចប់ច្បាប់ប៉ុណ្ណោះ។ វាមិនផ្លាស់ប្តូរការបញ្ជូនទៅអ្នកផ្តល់សេវា ការជ្រើសរើសតំបន់ភាសា ឬភាសាចំណុចប្រទាក់អ្នកប្រើទេ។

## ទម្រង់ការកំណត់រចនាសម្ព័ន្ធ

ការកំណត់ការបង្ហាប់អាចរួមបញ្ចូល៖

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` គ្រប់គ្រងតម្លៃលំនាំដើមនៃផ្ទាំងគ្រប់គ្រង/ការមើលជាមុន។ `cavemanConfig` គឺជាការកំណត់រចនាសម្ព័ន្ធម៉ាស៊ីនពេលដំណើរការ
ដែលត្រូវបានប្រើនៅពេល Caveman បង្ហាប់អត្ថបទសារ។

## ការបន្ថែមកញ្ចប់ភាសា

1. បង្កើត `open-sse/services/compression/rules/<language>/<pack>.json`។
2. ប្រើទម្រង់ច្បាប់ Caveman ពី `docs/compression/COMPRESSION_RULES_FORMAT.md`។
3. រក្សាការជំនួសឱ្យមានលក្ខណៈប្រុងប្រយ័ត្ន និងជៀសវាងការផ្លាស់ប្តូរកូដ អត្តសញ្ញាណកម្ម URLs ឬ JSON។
4. បន្ថែម ឬធ្វើបច្ចុប្បន្នភាពការធ្វើតេស្តសម្រាប់ការជ្រើសរើសភាសា និងឥរិយាបថនៃការជំនួស។
5. បង្ហាញស្លាក dashboard/i18n ថ្មី ប្រសិនបើភាសានោះបង្ហាញនៅក្នុងឧបករណ៍ជ្រើសរើស UI។

## API

កញ្ចប់ដែលមានអាចត្រូវបានសួររកដោយប្រើ៖

```bash
curl http://localhost:20128/api/compression/language-packs
```

endpoint សម្រាប់មើលជាមុនទទួលយកការកំណត់រចនាសម្ព័ន្ធភាសាដែលកំណត់ជំនួស៖

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

កញ្ចប់ភាសាទាំង 6 បានទទួលឃ្លា `SHARED_BOUNDARIES` នៅក្នុង v3.8.0 ដែលត្រូវបានអនុវត្តនៅគ្រប់
កម្រិតអាំងតង់ស៊ីតេ Caveman (LITE, FULL, ULTRA)។ វាណែនាំឱ្យ engine រក្សាទុក pattern ទាំងនេះដដែលៗ
ដោយមិនគិតពីការដកពាក្យបំពេញនៅជុំវិញ៖

| ប្រភេទ pattern                | ឧទាហរណ៍                                |
| ----------------------------- | -------------------------------------- |
| ប្លុកកូដដែលមានរបង             | ` ```python\n...\n``` `                |
| កូដក្នុងបន្ទាត់               | `` `my_var` ``                         |
| URLs                          | `https://example.com/path`             |
| ផ្លូវឯកសារ (ដាច់ខាត + ទាក់ទង) | `/etc/hosts`, `./src/index.ts`         |
| បឋមកថាកំហុស                   | `Error:`, `TypeError:`, `SyntaxError:` |
| បន្ទាត់ stack trace           | `  at functionName (file.ts:12:3)`     |

pattern ទាំងនេះត្រូវបានបញ្ចូលក្នុង `DEFAULT_CAVEMAN_CONFIG.preservePatterns` (ពីមុនជា `[]`)។
constant នេះស្ថិតនៅក្នុង `open-sse/services/compression/types.ts`។

### ហេតុអ្វីវាសំខាន់

បើគ្មាន SHARED_BOUNDARIES ទេ របៀប Caveman កម្រិតខ្លាំងអាចលុបមាតិកាដែលមើលទៅដូចជាអត្ថបទ
ដដែលៗ ប៉ុន្តែតាមពិតជា snippet កូដ ផ្លូវឯកសារ ឬ error stack។ SHARED_BOUNDARIES ដើរតួជា
សំណាញ់សុវត្ថិភាពដែលមិនអាស្រ័យលើភាសា ហើយត្រូវបានអនុវត្តមុនពេលច្បាប់ពាក្យបំពេញដំណើរការ។

### ការកំណត់ `preservePatterns` តាមបំណង

អាចបន្ថែម pattern ផ្សេងទៀតនៅពេលដំណើរការ តាមរយៈការកំណត់ការបង្ហាប់៖

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````
