## ស្ថាបត្យកម្ម

```
Client (Dashboard / CLI / API)
  → POST /api/v1/agents/tasks (តម្រូវឱ្យមានការផ្ទៀងផ្ទាត់សម្រាប់ការគ្រប់គ្រង)
    → ការធ្វើ validation ដោយ CreateCloudAgentTaskSchema (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ ទាញយកពី getProviderConnections({ provider, isActive: true })
         (apiKey ជាមុន បើមិនមានទើបប្រើ accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ HTTP POST ទៅ API របស់ provider upstream
      └─ ត្រឡប់ CloudAgentTask ដែលមាន id ខាងក្នុង + externalId
    → insertCloudAgentTask(...) ទៅក្នុង cloud_agent_tasks (SQLite)

ការធ្វើ Polling (lazy sync នៅពេលអាន):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // ធ្វើឱ្យ status + activities ថ្មីឡើងវិញ
    → updateCloudAgentTask(...) ជាមួយ status, result, completed_at ថ្មី
    → ត្រឡប់ task ដែលបាន serialize

អន្តរកម្ម:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        សម្រាប់ "approve"
    → agent.sendMessage(externalId, message, credentials) សម្រាប់ "message"
    → status ប្តូរទៅជា "cancelled"                      សម្រាប់ "cancel" (តែក្នុង local ប៉ុណ្ណោះ)
```

ការធ្វើ sync គឺជា **lazy**៖ status ត្រូវបានធ្វើឱ្យថ្មីពី upstream រាល់ពេល `GET /tasks/[id]`។
មិនមាន background poller ទេ។ Dashboard ដែលត្រូវការ state ថ្មី គួរតែ poll endpoint GET
នៅចន្លោះពេលសមស្រប។

## អ៊ីនធឺហ្វេស `CloudAgentBase`

ប្រភព៖ `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // heuristic upstream-string → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` បោះកំហុសដោយចេតនា — Codex Cloud រៀបចំផែនការដោយស្វ័យប្រវត្តិ ហើយ
មិនមានច្រកអនុម័តទេ។ `CodexCloudAgent.listSources` ត្រឡប់ `[]`។

`CursorCloudAgent` គ្រប់គ្រង Background / Cloud Agents របស់ Cursor តាមរយៈ REST
API ផ្លូវការរបស់វា (`api.cursor.com/v0`) ដោយប្រើ **API key របស់អ្នកប្រើ ឬ service-account** — ជាជម្រើសផ្លូវការពីភាគីទីមួយ
ដែលមានសុវត្ថិភាពជាងការប្រើសម័យ OAuth របស់ Cursor IDE ឡើងវិញ (អ្នកផ្តល់សេវា `cursor`
ដែលមានការព្រមានអំពីហានិភ័យនៃការហាមឃាត់)។ វាជាអាដាប់ទ័រ REST ធម្មតា (មិនមានភាពអាស្រ័យ native
លើ `@cursor/sdk`)។ `approvePlan` បោះកំហុស (ភ្នាក់ងារ Cursor ដំណើរការដោយស្វ័យប្រវត្តិ); `listSources` រាយបញ្ជី
ឃ្លាំងកូដដែល key អាចចូលប្រើបាន។ Cursor ត្រឡប់ enum ស្ថានភាពជាអក្សរធំ
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) ដែលត្រូវបានផ្គូផ្គងយ៉ាងជាក់លាក់ទៅនឹង
`CloudAgentStatus` រួម។ `baseUrl` អាចបដិសេធតម្លៃបានតាម credential នីមួយៗ ដូច្នេះកំណែ/ផ្លូវ API អាច
ត្រូវបានកែតម្រូវដោយមិនចាំបាច់ផ្លាស់ប្តូរកូដ។

## ប្រភេទដូមែន

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // ត្រូវតែជា URL ដែលត្រឹមត្រូវ
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // វិនាទី ជាចំនួនគត់វិជ្ជមាន
  cost?: number; // ជាចំនួនទសភាគវិជ្ជមាន
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // id `task_...` ខាងក្នុង
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // id របស់អ្នកផ្តល់សេវាខាងលើ
  status: CloudAgentStatus;
  prompt: string; // 1..10000 តួអក្សរ
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

ស្គីមាផ្ទៀងផ្ទាត់ (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`) ត្រូវបាន
នាំចេញរួមជាមួយប្រភេទទាំងនេះ ហើយត្រូវបានប្រើដោយកម្មវិធីដោះស្រាយ route។

## មូលដ្ឋានទិន្នន័យ

ប្រភព៖ `src/lib/cloudAgent/db.ts` — តារាងត្រូវបានបង្កើតបែប lazy តាមរយៈ
`createCloudAgentTaskTable()` (ក៏ត្រូវបានហៅពី `src/lib/cloudAgent/index.ts` នៅពេល
នាំចូលម៉ូឌុលផងដែរ)។

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask` អនុវត្ត **បញ្ជីអនុញ្ញាតជួរឈរ** ដើម្បីទប់ស្កាត់ SQL injection៖
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`។ key ផ្សេងទៀតណាមួយនៅក្នុងការធ្វើបច្ចុប្បន្នភាពដោយផ្នែក នឹងត្រូវបានបោះចោលដោយស្ងៀមស្ងាត់។

## REST API — វដ្តជីវិតរបស់កិច្ចការ

**ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ៖** endpoint `/api/v1/agents/tasks*` ទាំងអស់តម្រូវឱ្យមាន **ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណសម្រាប់ការគ្រប់គ្រង**
(`requireCloudAgentManagementAuth` រុំ `requireManagementAuth` ពី
`src/lib/api/requireManagementAuth`)។ វាត្រូវបានអនុវត្តបន្ទាប់ពី commit `588a0333`
(_"ជួសជុល(auth)៖ តម្រូវឱ្យមានការផ្ទៀងផ្ទាត់អត្តសញ្ញាណសម្រាប់ការគ្រប់គ្រងចំពោះ API របស់ agent និង cooldown"_).

| វិធីសាស្ត្រ | ផ្លូវ                         | គោលបំណង                                                     |
| ----------- | ----------------------------- | ----------------------------------------------------------- |
| OPTIONS     | `/api/v1/agents/tasks`        | សំណើ CORS preflight                                         |
| GET         | `/api/v1/agents/tasks`        | រាយបញ្ជីកិច្ចការ (តម្រង៖ `provider`, `status`, `limit≤500`) |
| POST        | `/api/v1/agents/tasks`        | បង្កើតកិច្ចការ (បញ្ជូនទៅ upstream + រក្សាទុក)               |
| DELETE      | `/api/v1/agents/tasks?id=...` | លុបកិច្ចការតាម query id (**មិន**បោះបង់នៅ upstream)          |
| OPTIONS     | `/api/v1/agents/tasks/[id]`   | សំណើ CORS preflight                                         |
| GET         | `/api/v1/agents/tasks/[id]`   | អានកិច្ចការ + ធ្វើសមកាលកម្មស្ថានភាពពី upstream បែប lazy     |
| POST        | `/api/v1/agents/tasks/[id]`   | សកម្មភាព៖ `approve` / `message` / `cancel`                  |
| DELETE      | `/api/v1/agents/tasks/[id]`   | លុបកិច្ចការតាម path id                                      |

## REST API — ហេដ្ឋារចនាសម្ព័ន្ធតភ្ជាប់ Cloud Provider

Endpoint ជំនួយទាំងនេះនៅក្រោម `src/app/api/cloud/` ត្រូវបានប្រើដោយ client ពីចម្ងាយ
(ដូចជា CLI, កម្មវិធី Electron ឬ sync worker) ដើម្បីអាន metadata នៃការតភ្ជាប់ provider
និងដោះស្រាយ model alias។ ពួកវាត្រូវបានផ្ទៀងផ្ទាត់ដោយប្រើ **API key ធម្មតា**
(តាមរយៈ `validateApiKey`) មិនមែនការផ្ទៀងផ្ទាត់សម្រាប់ការគ្រប់គ្រងដែលប្រើដោយ task endpoint នោះទេ។

| វិធីសាស្ត្រ | Path                            | គោលបំណង                                                                        |
| ----------- | ------------------------------- | ------------------------------------------------------------------------------ |
| POST        | `/api/cloud/auth`               | ផ្ទៀងផ្ទាត់ API key ហើយត្រឡប់ metadata នៃការតភ្ជាប់ដែលបានបិទបាំង + model alias |
| PUT         | `/api/cloud/credentials/update` | ធ្វើឱ្យ `accessToken` / `refreshToken` / `expiresAt` ទាន់សម័យ                  |
| POST        | `/api/cloud/model/resolve`      | ដោះស្រាយ model alias ទៅជា `{ provider, model }`                                |
| GET         | `/api/cloud/models/alias`       | រាយបញ្ជី model alias ទាំងអស់                                                   |
| PUT         | `/api/cloud/models/alias`       | កំណត់ model alias (និង sync ដោយស្វ័យប្រវត្តិទៅ Cloud ប្រសិនបើបានបើកប្រើ)       |

`/api/cloud/auth` មិនដែលត្រឡប់ `apiKey` / `accessToken` / `refreshToken` ដើមឡើយ។ វា
ត្រឡប់ `hasApiKey`, `hasAccessToken`, `hasRefreshToken` និងការមើលជាមុនដែលបានបិទបាំង
(`maskedApiKey`: 4 តួដំបូង + `****` + 4 តួចុងក្រោយ)។

## ការដោះស្រាយ Credentials

`getCloudAgentCredentials(providerId)` នៅក្នុង `src/lib/cloudAgent/api.ts`៖

1. ផ្ទុកការតភ្ជាប់ provider ដែលសកម្មតាមរយៈ `getProviderConnections({ provider: providerId, isActive: true })`។
2. សម្រាប់ការតភ្ជាប់នីមួយៗ វាផ្តល់អាទិភាពដល់ `apiKey` (ដែលបានកាត់ដកចន្លោះទទេ)។ ប្រសិនបើគ្មាន វាប្រើ `accessToken` ជំនួស។
3. ត្រឡប់ token មិនទទេដំបូងដែលរុំជា `{ apiKey: token }`។
4. ត្រឡប់ `null` ប្រសិនបើរកមិនឃើញ token ដែលអាចប្រើបាន — API នឹងឆ្លើយតបដោយ `400` ជាមួយ
   `"No active credentials configured for cloud agent provider: <id>"`។

នេះមានន័យថា Cloud Agents ប្រើតារាង Provider Connection ដូចគ្នានឹង provider
LLM ធម្មតា។ ដើម្បីបើកប្រើ Jules សូមបង្កើតការតភ្ជាប់សកម្មមួយជាមួយ `provider: "jules"`
និង `apiKey` ដែលមានតម្លៃ។

## ការបន្ថែម Cloud Agent ថ្មី

1. បង្កើត `src/lib/cloudAgent/agents/<name>.ts` ដែលពង្រីកពី `CloudAgentBase`។
2. អនុវត្ត `createTask`, `getStatus`, `approvePlan` (ឬ throw ប្រសិនបើមិនអនុវត្ត),
   `sendMessage`, `listSources`។ ប្រើ `this.mapStatus(...)` សម្រាប់ការធ្វើឱ្យស្ថានភាពមានទម្រង់ស្តង់ដារ។
3. ចុះឈ្មោះនៅក្នុង `src/lib/cloudAgent/registry.ts` ក្រោម `providerId` ដែលមានស្ថិរភាព។
4. ពង្រីក literal union របស់ `providerId` នៅក្នុង `src/lib/cloudAgent/types.ts`
   (`CloudAgentTask.providerId` និង `CreateCloudAgentTaskSchema`)។
5. បន្ថែម provider ទៅ `src/shared/constants/providers.ts` ប្រសិនបើវាត្រូវការកំណត់ត្រា
   ការតភ្ជាប់។ provider ដែលផ្អែកលើ OAuth ក៏ត្រូវការ `src/lib/oauth/providers/` ផងដែរ។
6. បន្ថែម test នៅក្រោម `tests/unit/cloud-agent-*.test.ts`។
7. ធ្វើបច្ចុប្បន្នភាពឯកសារនេះ និង constant `CLOUD_AGENTS` របស់ dashboard។
