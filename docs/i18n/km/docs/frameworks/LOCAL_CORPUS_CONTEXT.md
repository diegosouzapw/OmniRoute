## វាជាអ្វី

Local Corpus អនុញ្ញាតឱ្យប្រតិបត្តិករបង្ហាញថតឯកសារអត្ថបទមួយដែលបានអនុម័តយ៉ាងច្បាស់ទៅកាន់
ម៉ាស៊ីនមេ MCP របស់ OmniRoute។ ឯកសារនៅតែស្ថិតក្នុងថតដើមរបស់វា៖ OmniRoute រក្សាទុកតែ
root path កាណូនិកនៅក្នុង SQLite និងថែរក្សាលិបិក្រមស្វែងរកក្នុងអង្គចងចាំ។ វាមិន
ចម្លងមាតិកា corpus ចូលទៅក្នុង repository ឬ database ឡើយ។

ការធ្វើឱ្យលិបិក្រមស្រស់ឡើងវិញមានលក្ខណៈជាបន្តបន្ទាប់។ ឯកសារដែលមិនបានផ្លាស់ប្តូរត្រូវបានប្រើឡើងវិញដោយផ្អែកលើទំហំ និងពេលវេលា
កែប្រែ ឯកសារដែលបានផ្លាស់ប្តូរត្រូវបានអានឡើងវិញ និងធ្វើ hash ដោយ SHA-256 ហើយឯកសារដែលបានលុបត្រូវបានដកចេញ។
ការស្វែងរកធ្វើឱ្យលិបិក្រមដែលមានអាយុលើសពី 30 វិនាទីស្រស់ឡើងវិញ។ អ្នកហៅក៏អាចស្នើសុំការធ្វើឱ្យស្រស់
ភ្លាមៗផងដែរ។

## កំណត់រចនាសម្ព័ន្ធប្រភព

route ការកំណត់តម្រូវឱ្យមានការផ្ទៀងផ្ទាត់ management ដូចគ្នានឹង API ការកំណត់ផ្សេងទៀត។
path ដែលបានដាក់ស្នើត្រូវតែមានរួចជាស្រេច និងត្រូវតែជា directory path ដាច់ខាត។

```bash
# ភ្ជាប់ថតដែលបានអនុម័ត
curl -X POST http://localhost:20128/api/settings/local-corpus \
  -H "Content-Type: application/json" \
  -d '{"rootPath":"/absolute/path/to/approved-text"}'

# ពិនិត្យការកំណត់រចនាសម្ព័ន្ធ និងស្ថានភាពលិបិក្រម
curl http://localhost:20128/api/settings/local-corpus

# ផ្តាច់ដោយមិនផ្លាស់ប្តូរឯកសារប្រភព
curl -X DELETE http://localhost:20128/api/settings/local-corpus
```

## ឧបករណ៍ MCP

ឧបករណ៍ទាំងបីតម្រូវឱ្យមាន `read:local-corpus`។ ការឆ្លើយតបរបស់ឧបករណ៍បង្ហាញ relative paths និង
basename របស់ root directory ប៉ុណ្ណោះ មិនបង្ហាញ absolute path របស់វាឡើយ។

| ឧបករណ៍                | សេចក្តីពិពណ៌នា                                                                                   |
| :-------------------- | :----------------------------------------------------------------------------------------------- |
| `local_corpus_status` | រាយការណ៍ស្ថានភាពការកំណត់រចនាសម្ព័ន្ធ ទំហំលិបិក្រម ដែនកំណត់ និងពេលធ្វើឱ្យស្រស់ចុងក្រោយ            |
| `local_corpus_search` | ស្វែងរកអត្ថបទដែលបានធ្វើលិបិក្រម និងត្រឡប់បំណែកអត្ថបទតាមបន្ទាត់ដែលមានដែនកំណត់ (រហូតដល់ 20 លទ្ធផល) |
| `local_corpus_read`   | អានជួរបន្ទាត់ដែលមានដែនកំណត់ពីឯកសារមួយដែលបានអនុញ្ញាត និងប្រើ path ទាក់ទងនឹង corpus                |

ឧទាហរណ៍ input MCP៖

```json
{ "query": "Red River monitoring", "limit": 10, "refresh": false }
```

```json
{ "relativePath": "hydrology/stations.md", "startLine": 20, "endLine": 80 }
```

## ព្រំដែនសុវត្ថិភាព

- បញ្ជីអនុញ្ញាតផ្តោតលើអត្ថបទ៖ `.cfg`, `.csv`, `.geojson`, `.htm`, `.html`, `.ini`,
  `.js`, `.json`, `.jsonl`, `.jsx`, `.log`, `.md`, `.mjs`, `.ps1`, `.py`, `.sh`,
  `.sql`, `.toml`, `.ts`, `.tsx`, `.txt`, `.xml`, `.yaml`, និង `.yml`។
- Symlink ត្រូវបានរំលង។ path សម្រាប់អានត្រូវបានបម្លែងជាទម្រង់កាណូនិក និងត្រូវតែស្ថិតនៅក្នុង
  root ដែលបានកំណត់រចនាសម្ព័ន្ធ។ absolute path និងការប៉ុនប៉ង traversal ត្រូវបានបដិសេធ។
- ឈ្មោះថតដែលរសើប និងត្រូវបានបង្កើតដោយស្វ័យប្រវត្តិត្រូវបានដកចេញ៖ `.build`, `.codex`, `.env`,
  `.git`, `.next`, `.omniroute`, `.ssh`, `coverage`, `dist`, `node_modules`, និង
  `secrets`។
- ដែនកំណត់លំនាំដើមគឺឯកសារ 5,000, 1 MiB ក្នុងមួយឯកសារ, មាតិកាដែលបានធ្វើលិបិក្រមសរុប 64 MiB,
  ប្រហែល 4,000 តួអក្សរក្នុងមួយបំណែកស្វែងរក និង 400 បន្ទាត់ក្នុងមួយការអាន។
- ឯកសារដែលមាន NUL ត្រូវបានចាត់ទុកថាមិនមែនជាអត្ថបទ ហើយត្រូវបានរំលង ឬបដិសេធ។

ឯកសារ binary ដូចជា PDF, DOCX, រូបភាព និង archive មិនត្រូវបានគាំទ្រដោយចេតនា។
សូមបម្លែងពួកវាទៅជាទម្រង់អត្ថបទដែលបានអនុម័តនៅក្នុងថតដែលបានកំណត់រចនាសម្ព័ន្ធ មុនពេលធ្វើលិបិក្រម។

## កំណត់សម្គាល់ប្រតិបត្តិការ

- ការផ្លាស់ប្តូរ ឬលុប root ដែលបានកំណត់រចនាសម្ព័ន្ធ នឹងសម្អាតលិបិក្រមក្នុងអង្គចងចាំដែលបានចែករំលែក។
- ការចាប់ផ្តើម process ឡើងវិញនឹងបោះបង់លិបិក្រម។ ការស្វែងរកបន្ទាប់នឹងបង្កើតវាឡើងវិញពីប្រភពដែលបានកំណត់រចនាសម្ព័ន្ធ។
- `local_corpus_status` មិនបង្ខំឱ្យធ្វើ scan ទេ។ ប្រើ `local_corpus_search` ជាមួយ
  `refresh: true` នៅពេលត្រូវការធ្វើ scan ឡើងវិញភ្លាមៗ។
- កំហុសក្នុងការ scan និងអានត្រូវបានរាប់ ឬត្រឡប់ជាកំហុសដែលបានសម្អាតទិន្នន័យរសើប។ ឯកសារប្រភព
  មិនត្រូវបានកែប្រែឡើយ។
