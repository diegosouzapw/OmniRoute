## តើវាជាអ្វី

OmniRoute អាចភ្ជាប់ទៅកាន់ workspace របស់ **Notion** ជា **ប្រភពបរិបទ** — មូលដ្ឋានចំណេះដឹង
ដែលអាចអាន/សរសេរបាន និងដែល agent អាចចូលប្រើតាមរយៈ MCP server ដែលភ្ជាប់មកជាមួយ។ នៅពេល
Notion integration token ត្រូវបានកំណត់រចនាសម្ព័ន្ធ ឧបករណ៍ MCP អនុញ្ញាតឱ្យ LLM ស្វែងរកទំព័រ និង database,
អានមាតិកាទំព័រ និងមែកធាង block, query database ដោយប្រើ filter/sort និងបន្ថែម
block ថ្មី — ទាំងអស់នេះត្រូវបានបញ្ជូនបន្តតាម OmniRoute (ជាមួយការព្យាយាមឡើងវិញ, timeout និងការចាត់ថ្នាក់កំហុស)
ដូច្នេះ model មិនដែលចូលប្រើ Notion API ដោយផ្ទាល់ឡើយ។

Integration នេះគឺជា wrapper ស្តើង និងរឹងមាំលើ Notion REST API ផ្លូវការ
(`https://api.notion.com/v1`, `Notion-Version: 2026-03-11`)។ Client
(`src/lib/notion/api.ts`) បន្ថែម៖

- **ការព្យាយាមឡើងវិញជាមួយ exponential backoff** (រហូតដល់ 3 ដង) សម្រាប់ `429` និង `5xx`។
- **request timeout រយៈពេល 55 វិនាទី** តាមរយៈ `AbortController`។
- **ការចាត់ថ្នាក់កំហុសដែលមាន type** — `NotionAuthError` (401/403),
  `NotionNotFoundError` (404), `NotionRateLimitError` (429, គោរពតាមការណែនាំ `retry after`),
  `NotionValidationError` (400/409), `NotionServerError` (5xx),
  `NotionTimeoutError`។
- **ការសម្អាតសារ** ដែលដកបំណែកមានលក្ខណៈដូច stack trace ចេញ មុនពេលបង្ហាញ។

## ការដំឡើង

មិនមាន **environment variable** សម្រាប់ Notion token ទេ — វាត្រូវបានរក្សាទុកក្នុង
តារាង SQLite `key_value` (namespace `notion`, key `integration_token`) តាមរយៈ
`src/lib/db/notion.ts`។ កំណត់រចនាសម្ព័ន្ធវាពីផ្ទាំង **Context Sources** នៃ Endpoint
dashboard (`NotionSourceCard` ដែលនៅជាប់ `ObsidianSourceCard`) ឬតាមរយៈ settings REST API។

> [!NOTE]
> Token នេះគឺជា **Notion internal integration token**។ បង្កើត integration មួយនៅ
> <https://www.notion.com/my-integrations> បន្ទាប់មក share ទំព័រ/database ដែលអ្នកចង់ឱ្យ
> OmniRoute ចូលប្រើជាមួយ integration នោះ (គំរូសិទ្ធិរបស់ Notion ផ្អែកលើការចែករំលែក
> មិនមែនទូទាំង workspace ទេ)។

### កំណត់រចនាសម្ព័ន្ធតាមរយៈ REST

```bash
# រក្សាទុក + ផ្ទៀងផ្ទាត់ integration token (POST ផ្ទៀងផ្ទាត់ដោយដំណើរការការស្វែងរកសាកល្បង)
curl -X POST http://localhost:20128/api/settings/notion \
  -H "Content-Type: application/json" \
  -d '{"token":"ntn_xxx"}'

# ពិនិត្យស្ថានភាពការតភ្ជាប់
curl http://localhost:20128/api/settings/notion

# ផ្ដាច់ការតភ្ជាប់ (សម្អាត token ដែលបានរក្សាទុក)
curl -X DELETE http://localhost:20128/api/settings/notion
```

Method ទាំងបីតម្រូវឱ្យមានការផ្ទៀងផ្ទាត់ dashboard (`isAuthenticated`)។ នៅពេល `POST`,
OmniRoute រក្សាទុក token ហើយដំណើរការការស្វែងរកសាកល្បងចំនួន 1 លទ្ធផលភ្លាមៗ; ប្រសិនបើ Notion
ត្រឡប់ error object វិញ token នឹងត្រូវបានសម្អាត ហើយ call នឹងបរាជ័យជាមួយ `400`។

## ឧបករណ៍ MCP (6)

ត្រូវបានកំណត់ក្នុង `open-sse/mcp-server/tools/notionTools.ts`។ Token ត្រូវបានស្វែងរកនៅពេល call
តាមរយៈ `getNotionToken()`; ប្រសិនបើមិនមានការកំណត់រចនាសម្ព័ន្ធទេ ឧបករណ៍នឹងបោះកំហុស
`"Notion integration token not configured. Set it in Settings > Context Sources."`

| ឧបករណ៍                       | Scope          | សេចក្ដីពិពណ៌នា                                                                               |
| ---------------------------- | -------------- | -------------------------------------------------------------------------------------------- |
| `notion_search`              | `read:notion`  | ស្វែងរកទំព័រ និង database តាម text query (ត្រឡប់ title, ID និង URL)។ មាន pagination។         |
| `notion_get_page`            | `read:notion`  | ទាញយកមាតិកា និង metadata របស់ទំព័រតាម ID របស់វា។                                             |
| `notion_list_block_children` | `read:notion`  | រាយ block children ទាំងអស់របស់ block ឬទំព័រ (មែកធាង block)។ មាន pagination។                  |
| `notion_query_database`      | `read:notion`  | Query database ជាមួយ `filter` + `sorts` ជាជម្រើស (ទម្រង់ Notion API)។ មាន pagination។        |
| `notion_get_database`        | `read:notion`  | ទាញយក schema/metadata របស់ database តាម ID។                                                  |
| `notion_append_blocks`       | `write:notion` | បន្ថែម block children ទៅកាន់ block ឬទំព័រដែលមានស្រាប់ (អតិបរមា 100 block ក្នុង request មួយ)។ |

### Parameter បញ្ចូល

- `notion_search` — `query` (1–500 តួអក្សរ), `pageSize` (1–100, លំនាំដើម 20),
  `startCursor` (ជាជម្រើស)។
- `notion_get_page` — `pageId` (hex 32 តួអក្សរ ឬ UUID)។
- `notion_list_block_children` — `blockId`, `pageSize` (1–100, លំនាំដើម 50),
  `startCursor` (ជាជម្រើស)។
- `notion_query_database` — `databaseId`, `filter` (ជាជម្រើស, ទម្រង់ filter របស់ Notion),
  `sorts` (array ជាជម្រើស), `pageSize` (1–100, លំនាំដើម 50), `startCursor` (ជាជម្រើស)។
- `notion_get_database` — `databaseId`។
- `notion_append_blocks` — `blockId`, `children` (array នៃ block object),
  `after` (ទីតាំងជាជម្រើស)។

### Scope

ឧបករណ៍អានតម្រូវឱ្យមាន `read:notion` ហើយឧបករណ៍សរសេរតម្រូវឱ្យមាន `write:notion`។
Scope ត្រូវបានអនុវត្តដោយ `withScopeEnforcement()` ក្នុង
`open-sse/mcp-server/server.ts` តែនៅពេល `OMNIROUTE_MCP_ENFORCE_SCOPES=true` ប៉ុណ្ណោះ;
scope ដែល caller ត្រូវបានអនុញ្ញាត មកពី `OMNIROUTE_MCP_SCOPES` (បំបែកដោយសញ្ញាក្បៀស) ឬ
scope context របស់ API key ដែលបានផ្ទៀងផ្ទាត់។ សូមមើល [MCP-SERVER.md](./MCP-SERVER.md) សម្រាប់
គំរូ scope ពេញលេញ។

## ករណីប្រើប្រាស់

- **ចម្លើយដែលផ្អែកលើចំណេះដឹង** — អនុញ្ញាតឱ្យភ្នាក់ងារប្រើ `notion_search` ស្វែងរកក្នុងកន្លែងធ្វើការ និង
  ប្រើ `notion_get_page` លើលទ្ធផលកំពូលមុនពេលឆ្លើយ ដើម្បីឱ្យការឆ្លើយតបដកស្រង់ឯកសារផ្ទៃក្នុងពិតប្រាកដ។
- **លំហូរការងារដែលគាំទ្រដោយមូលដ្ឋានទិន្នន័យ** — ប្រើ `notion_query_database` លើមូលដ្ឋានទិន្នន័យកិច្ចការ/CRM ជាមួយ
  តម្រង + ការតម្រៀប បន្ទាប់មកសង្ខេប ឬចាត់ថ្នាក់ជួរដេកតាមអាទិភាព។
- **ការសរសេរត្រឡប់ / ការកត់ត្រា** — ប្រើ `notion_append_blocks` ដើម្បីបន្ថែមកំណត់ត្រាកិច្ចប្រជុំ សេចក្ដីសង្ខេបការដំណើរការ
  ឬលទ្ធផលរបស់ភ្នាក់ងារទៅក្នុងទំព័រដែលមានស្រាប់ (បានតែបន្ថែមបន្ត; គ្មានការកែសម្រួលដែលបំផ្លាញទិន្នន័យ)។
- **ការរុករករចនាសម្ព័ន្ធ** — ប្រើ `notion_list_block_children` ដើម្បីឆ្លងកាត់មែកធាងប្លុករបស់ទំព័រ
