## 1. A2A — ភ្នាក់ងារទៅភ្នាក់ងារ

**លក្ខណៈបញ្ជាក់៖** [A2A v0.3](https://a2a-protocol.org)
**ចំណុចបញ្ចប់ OmniRoute៖** `POST /a2a` (JSON-RPC 2.0)
**កាតភ្នាក់ងារ៖** `GET /.well-known/agent.json`

### ពេលណាគួរប្រើ

- បង្កើតប្រព័ន្ធពហុភ្នាក់ងារ ដែល OmniRoute ជាភ្នាក់ងារដៃគូមួយ
- ផ្តល់សមត្ថភាពកំណត់ផ្លូវឆ្លាតវៃរបស់ OmniRoute (`smart-routing`, `quota-management` ជាដើម) ទៅឱ្យភ្នាក់ងារនៅក្នុង framework ដូចជា Google ADK ឬបណ្តាញភ្នាក់ងារទូទៅ
- រុំ OmniRoute នៅពីក្រោយចំណុចប្រទាក់ស្តង់ដារសម្រាប់ការរកឃើញ + ការហៅប្រើ

### មេតូដ

- `message/send` — ដាក់ស្នើសារ និងទទួលការឆ្លើយតបសមកាលកម្ម
- `message/stream` — ដាក់ស្នើ + ទទួលព្រឹត្តិការណ៍វឌ្ឍនភាពដែលស្ទ្រីមតាម SSE
- `tasks/get` — អានកិច្ចការតាម ID
- `tasks/cancel` — បោះបង់កិច្ចការដែលកំពុងដំណើរការ

### ជំនាញដែលមានស្រាប់ (6)

- `smart-routing` — កំណត់ផ្លូវ prompt តាមរយៈ combo ដែលសមស្របបំផុត
- `quota-management` — រាយការណ៍ស្ថានភាព quota តាម provider នីមួយៗ
- `provider-discovery` — រាយបញ្ជី provider ដែលបានដំឡើង ព្រមទាំងសមត្ថភាពរបស់ពួកវា
- `cost-analysis` — ប៉ាន់ស្មានការចំណាយនៃសំណើ/ការសន្ទនា
- `health-report` — ប្រមូលផ្តុំស្ថានភាព breaker/cooldown/lockout តាម provider នីមួយៗ
- `list-capabilities` — រាយសមត្ថភាព និង metadata ដែលមានរបស់ភ្នាក់ងារ

### ព័ត៌មានលម្អិតស៊ីជម្រៅ

សូមមើល [A2A-SERVER.md](./A2A-SERVER.md) សម្រាប់ព័ត៌មានលម្អិតអំពីមធ្យោបាយបញ្ជូន រចនាសម្ព័ន្ធកាតភ្នាក់ងារ ការកំណត់រចនាសម្ព័ន្ធ TTL របស់កិច្ចការ និងគំរូសម្រាប់បន្ថែមជំនាញថ្មី។

## 2. ACP — បញ្ជីចុះឈ្មោះភ្នាក់ងារ CLI

**OmniRoute endpoint:** `GET /api/acp/agents`
**ប្រភព:** `src/lib/acp/{index,manager,registry}.ts`

### វាជាអ្វី

ACP គឺជា **បញ្ជីសារពើភណ្ឌភ្នាក់ងារ CLI មូលដ្ឋាន** របស់ OmniRoute។ វារកឃើញថាតើ CLI សម្រាប់សរសេរកូដណាខ្លះត្រូវបានដំឡើងនៅលើម៉ាស៊ីន (Cursor, Cline, Claude Code, Codex CLI, Continue ជាដើម) កំណត់កំណែរបស់ពួកវា និងបង្ហាញពួកវានៅលើផ្ទាំងគ្រប់គ្រង ដើម្បីឱ្យអ្នកប្រើអាចកំណត់ CLI នីមួយៗឱ្យចង្អុលទៅ OmniRoute។

នេះមិនមែនជាពិធីការខាងក្រៅទេ — វាជាបញ្ជីចុះឈ្មោះខាងក្នុងដែលផ្តល់ថាមពលដល់ UI "CLI Tools" និងការតាមដានស្នាមសម្គាល់ CLI (សូមមើល [CLI-TOOLS.md](../reference/CLI-TOOLS.md))។

### វាធ្វើអ្វីខ្លះ

- ពិនិត្យរក binary របស់ CLI ដែលបានដំឡើងនៅលើម៉ាស៊ីន (ប្រើ `which` / `where` អាស្រ័យលើ OS)
- អានកំណែរបស់ CLI នីមួយៗ (ហៅ `<bin> --version`)
- អាចទទួលយកភ្នាក់ងារផ្ទាល់ខ្លួនដែលកំណត់ដោយអ្នកប្រើ (ផ្លូវទៅកាន់ binary + ការពិនិត្យកំណែ + អាគុយម៉ង់សម្រាប់ដំណើរការ)
- រក្សាទុកភ្នាក់ងារផ្ទាល់ខ្លួននៅក្នុងការកំណត់
- បញ្ជូនបញ្ជីរួមទៅផ្ទាំងគ្រប់គ្រង

### REST API

| Endpoint          | វិធីសាស្ត្រ | សេចក្តីពិពណ៌នា                                                                       | ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ |
| ----------------- | ----------- | ------------------------------------------------------------------------------------ | ------------------------ |
| `/api/acp/agents` | GET         | រាយបញ្ជីភ្នាក់ងារដែលបានរកឃើញ + ផ្ទាល់ខ្លួន (ចំនួនបានដំឡើង/សរុប)                      | API key                  |
| `/api/acp/agents` | POST        | បន្ថែម/ធ្វើបច្ចុប្បន្នភាព/លុបភ្នាក់ងារផ្ទាល់ខ្លួន (សញ្ញាសម្គាល់សកម្មភាពនៅក្នុង body) | API key                  |

ទម្រង់ body សម្រាប់ POST (`customAgentBodySchema` នៅក្នុង `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### ករណីប្រើប្រាស់

- ទំព័រ "CLI Tools" ក្នុងផ្ទាំងគ្រប់គ្រងរាយបញ្ជីអ្វីដែលបានដំឡើង និងជួយអ្នកកំណត់ឱ្យពួកវានីមួយៗចង្អុលទៅ OmniRoute
- ភ្នាក់ងារផ្ទាល់ខ្លួនអនុញ្ញាតឱ្យអ្នកប្រើកម្រិតខ្ពស់ចុះឈ្មោះ CLI ខាងក្នុង/កម្មសិទ្ធិ ដែល OmniRoute មិនស្គាល់តាមលំនាំដើម
- លទ្ធផលនៃការរកឃើញផ្តល់ទិន្នន័យដល់ម៉ាទ្រីសស្នាមសម្គាល់ `cli-tools`

### ពេលណាមិនគួរប្រើ ACP

- ACP មិន _ដំណើរការ_ កិច្ចការទេ។ វាគ្រាន់តែរកឃើញ + កំណត់រចនាសម្ព័ន្ធ CLI ប៉ុណ្ណោះ។ ដើម្បីហៅប្រើ CLI ជាក់ស្តែង អ្នកត្រូវបើកដំណើរការវាដោយខ្លួនឯង ជាមួយអថេរបរិស្ថានដែល OmniRoute ផ្តល់ឱ្យ (`OPENAI_BASE_URL`, `OPENAI_API_KEY` ជាដើម)។

## 3. ភ្នាក់ងារ Cloud

**OmniRoute endpoints:** `/api/v1/agents/tasks/*` (វដ្តជីវិត) + `/api/cloud/*` (ហេដ្ឋារចនាសម្ព័ន្ធតភ្ជាប់)
**ប្រភព:** `src/lib/cloudAgent/`

### វាជាអ្វី

ចំណុចប្រទាក់ឯកសណ្ឋានមួយសម្រាប់ភ្នាក់ងារសរសេរកូដលើ Cloud របស់ភាគីទីបី។ អ្នកដាក់ស្នើ prompt + URL របស់ repo ហើយ OmniRoute បញ្ជូនវាទៅភ្នាក់ងារ Cloud ដែលត្រឹមត្រូវ ពិនិត្យស្ថានភាពជាបន្តបន្ទាប់ និងបញ្ជូនលទ្ធផលត្រឡប់មកវិញ។

### ភ្នាក់ងារដែលគាំទ្រ (4 ដែលទាំងអស់ត្រូវបានបញ្ជាក់នៅក្នុង `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### វដ្តជីវិត

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() សម្រាប់ class របស់ភ្នាក់ងារនីមួយៗ
  → សេវាខាងក្រៅចាប់ផ្តើមការងារ
  → row របស់កិច្ចការត្រូវបានបង្កើតនៅក្នុង DB (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → ធ្វើសមកាលកម្មស្ថានភាពបែប lazy ពី provider
  → បញ្ជូនត្រឡប់ស្ថានភាពបច្ចុប្បន្ន + ផែនការ + កំណត់ហេតុសកម្មភាព
  ↓
POST /api/v1/agents/tasks/[id]   (សកម្មភាព: "approve" | "message" | "cancel")
  → បញ្ជូនបន្តទៅ provider (ឬសម្គាល់ថាបានបោះបង់នៅមូលដ្ឋាន)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → បោះបង់នៅមូលដ្ឋាន
```

### ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ

⚠️ **endpoint `/api/v1/agents/tasks/*` ទាំងអស់តម្រូវឱ្យមានការផ្ទៀងផ្ទាត់អត្តសញ្ញាណសម្រាប់ការគ្រប់គ្រង** (commit `588a0333`)។ អ្នកហៅដែលប្រើតែ Bearer នឹងទទួលបាន 401 ចាប់តាំងពី v3.8.0។
