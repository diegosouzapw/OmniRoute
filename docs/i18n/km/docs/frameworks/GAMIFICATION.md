### គោលការណ៍រចនា

1. **ផ្តោតលើមូលដ្ឋានជាចម្បង** — ស្ថានភាពទាំងអស់ស្ថិតក្នុង SQLite ដោយមិនតម្រូវឱ្យមានសេវាកម្មខាងក្រៅ។
2. **មិនរារាំង** — ព្រឹត្តិការណ៍ត្រូវបានផ្ញើហើយមិនរង់ចាំ; ផ្លូវឆ្លើយតបរបស់ LLM
   មិនត្រូវបានពន្យារពេលដោយតក្កវិជ្ជាហ្គេមមីហ្វីខេសិនឡើយ។
3. **ម៉ាស៊ីនបម្រើជាអ្នកកំណត់ផ្លូវការ** — XP ត្រូវបានគណនាតែពីខាងម៉ាស៊ីនបម្រើប៉ុណ្ណោះ; កម្មវិធីអតិថិជនមិនអាច
   បំប៉ោងពិន្ទុបានទេ។
4. **គោរពឯកជនភាព** — ការចូលរួមក្នុងតារាងចំណាត់ថ្នាក់គឺជាជម្រើសដែលត្រូវយល់ព្រម; អ្នកប្រើប្រាស់អាច
   លាក់ប្រវត្តិរូបរបស់ពួកគេ។
5. **ត្រៀមរួចជាស្រេចសម្រាប់សហព័ន្ធកម្ម** — ម៉ាស៊ីនបម្រើសហគមន៍អាចរុញបញ្ជូនពិន្ទុតាមរយៈ API ដែលមានហត្ថលេខា;
   ការធ្វើសមកាលកម្មគឺជាការសរសេរជាន់ មិនមែនការបូកបន្ថែមទេ។

## ស្ថាបត្យកម្ម

### លំហូរកម្រិតខ្ពស់

```
សំណើពីកម្មវិធីអតិថិជន
  → /v1/chat/completions
    → handleChatCore()                      [open-sse/handlers/chatCore.ts]
      → ... (ខ្សែដំណើរការដែលមានស្រាប់) ...
      → ការឆ្លើយតបពីប្រភពខាងលើត្រូវបានផ្ញើទៅកម្មវិធីអតិថិជន
      → setImmediate (ផ្ញើហើយមិនរង់ចាំ):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
          → updateLeaderboard()             [src/lib/gamification/leaderboard.ts]
          → checkAnomalies()                [src/lib/gamification/antiCheat.ts]
```

កម្មវិធីបញ្ចេញព្រឹត្តិការណ៍គឺជាចំណុចរួមបញ្ចូលតែមួយគត់។ `chatCore.ts` ហៅ
`emitGamificationEvent()` បន្ទាប់ពីការឆ្លើយតបត្រូវបានផ្ញើ; ម៉ូឌុលព្រឹត្តិការណ៍បែងចែកបន្ត
ទៅកាន់ប្រព័ន្ធរង XP ស៊េរីបន្តបន្ទាប់ ផ្លាកសញ្ញា តារាងចំណាត់ថ្នាក់ និងការទប់ស្កាត់ការក្លែងបន្លំ។

```
  rotate/            ← POST បង្វិលសោសម្ងាត់ថូខិនអញ្ជើញ
```

### លំហូរផ្តល់រង្វាន់

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. ស្វែងរក `XP_REWARDS[action]` ដើម្បីទទួលបានចំនួន XP។
2. ឆ្លងកាត់ `checkRateLimit()` (ការពារការបន្លំ៖ អតិបរមា 1000 XP/នាទី សម្រាប់ key នីមួយៗ)។
3. បើក transaction មួយ៖
   - អាន row `user_levels` បច្ចុប្បន្ន។
   - បន្ថែម XP; គណនាកម្រិតឡើងវិញតាមរយៈ `levelFromXp(totalXp)`។
   - ប្រសិនបើកម្រិតបានផ្លាស់ប្តូរ កំណត់ `levelUp = true`។
   - ធ្វើបច្ចុប្បន្នភាព row `user_levels`។
   - បញ្ចូលទៅក្នុង `xp_audit_log`។
4. ត្រឡប់លទ្ធផល។ អ្នកហៅជាអ្នកដោះស្រាយការជូនដំណឹង។

### មុខងារជំនួយ៖ `levelFromXp(totalXp)`

ធ្វើរង្វិលជុំតាមកម្រិត 1..100 ដោយបូក `xp_for_level(n)` រហូតដល់ XP សរុបបង្គរ
លើស `totalXp`។ វាត្រឡប់កម្រិតខ្ពស់បំផុតដែលបានបំពេញកម្រិតកំណត់។
វាមានភាពស្មុគស្មាញ O(100) — អាចទទួលយកបាន ដោយសារកម្រិតត្រូវបានកំណត់អតិបរមាត្រឹម 100។

## កម្មវិធីតាមដាន Streak

**ឯកសារ:** `src/lib/gamification/streaks.ts`

### ម៉ូដែលទិន្នន័យ

Streak ត្រូវបានរក្សាទុកក្នុងតារាង `key_value` (តារាងឧបករណ៍ប្រើប្រាស់រួម) ក្រោម key ដែលមាន namespace៖

| Key                           | តម្លៃ                            | ការពិពណ៌នា            |
| ----------------------------- | -------------------------------- | --------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | ទិន្នន័យ streak សកម្ម |

### តក្កវិជ្ជា

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. អានកំណត់ត្រា streak ពី `key_value`។
2. បំបែកតម្លៃ `{current}`, `{longest}`, `{lastDate}` (ខ្សែអក្សរកាលបរិច្ឆេទ ISO)។
3. ប្រសិនបើ `lastDate === today` — មិនមានការផ្លាស់ប្តូរ (បានរាប់រួចហើយនៅថ្ងៃនេះ)។
4. ប្រសិនបើ `lastDate === yesterday` — បង្កើន `current`; ធ្វើបច្ចុប្បន្នភាព `longest` ប្រសិនបើចាំបាច់។
5. ប្រសិនបើ `lastDate < yesterday` — កំណត់ `current = 1` ឡើងវិញ (streak ត្រូវបានផ្តាច់)។
6. សរសេរកំណត់ត្រាដែលបានធ្វើបច្ចុប្បន្នភាព។
7. ពិនិត្យ milestone៖ 7, 14, 30, 60, 90, 180, 365 ថ្ងៃ។ ប្រសិនបើបានឆ្លងកាត់ កំណត់
   `milestone = true` (អ្នកហៅផ្តល់ XP និងពិនិត្យ badge)។

### ករណីពិសេស

- **តំបន់ពេលវេលា**៖ streak ប្រើកាលបរិច្ឆេទ UTC (`new Date().toISOString().slice(0, 10)`)។
  នេះគឺជាចេតនា — តំបន់ពេលវេលាស្តង់ដារតែមួយការពារការកេងប្រវ័ញ្ចតាមរយៈ
  ការប្តូរតំបន់ពេលវេលា។
- **អ្នកប្រើប្រាស់ថ្មី**៖ មិនទាន់មានកំណត់ត្រា streak ទេ; សំណើដំបូងនឹងបង្កើតវាជាមួយ
  `current=1, longest=1, lastDate=today`។
- **សំណើច្រើនក្នុងមួយថ្ងៃ**៖ មានតែសំណើដំបូងនៃថ្ងៃ UTC ប៉ុណ្ណោះ
  ដែលបង្កើន streak។

### ការគណនាចំណាត់ថ្នាក់

ចំណាត់ថ្នាក់ត្រូវបាន **គណនានៅពេលអាន** មិនមែនរក្សាទុកទេ។ វាជួយជៀសវាងទិន្នន័យចំណាត់ថ្នាក់
ដែលហួសសម័យ និងលុបបំបាត់តម្រូវការសម្រាប់ job គណនាចំណាត់ថ្នាក់ឡើងវិញតាមកាលកំណត់។

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

លំនាំ query៖

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### ការប្តូរវេនតាមរយៈពេល

តារាងចំណាត់ថ្នាក់ប្រចាំសប្តាហ៍ និងប្រចាំខែប្តូរវេនដោយស្វ័យប្រវត្តិ៖

1. **រក្សាទុកក្នុងបណ្ណសារ**៖ នៅព្រំដែននៃរយៈពេល ចម្លងធាតុបច្ចុប្បន្នទៅ
   `leaderboard_archive` ជាមួយស្លាករយៈពេល។
2. **កំណត់ឡើងវិញ**៖ លុបធាតុសម្រាប់រយៈពេលដែលបានផុតកំណត់។
3. **ការកេះដំណើរការ**៖ ពិនិត្យរាល់ពេលហៅ `updateLeaderboard()`; សំណើដំបូង
   នៃរយៈពេលថ្មីនឹងកេះដំណើរការប្តូរវេន។

វាធានាថាតារាងប្រចាំសប្តាហ៍ត្រូវបានកំណត់ឡើងវិញរៀងរាល់ថ្ងៃចន្ទ ម៉ោង 00:00 UTC ហើយតារាងប្រចាំខែ
ត្រូវបានកំណត់ឡើងវិញនៅថ្ងៃទី 1 នៃខែនីមួយៗ។

### បច្ចុប្បន្នភាពតាមពេលវេលាជាក់ស្តែងរបស់ SSE

```
Client → GET /api/gamification/stream
  → បានបង្កើតការតភ្ជាប់ SSE
  → Server ផ្ញើ snapshot តារាងចំណាត់ថ្នាក់ top-10 ភ្លាមៗ
  → រៀងរាល់ 5 វិនាទី៖ push top-10 ដែលបានធ្វើបច្ចុប្បន្នភាព ប្រសិនបើមានការផ្លាស់ប្តូរ
  → រៀងរាល់ 15 វិនាទី៖ comment heartbeat (": heartbeat\n\n")
  → Client ផ្តាច់ការតភ្ជាប់ → សម្អាត (ដក listener ចេញ)
```

តែនៅពេលទិន្នន័យតារាងចំណាត់ថ្នាក់ពិតជាបានផ្លាស់ប្តូរចាប់តាំងពីការ push ចុងក្រោយប៉ុណ្ណោះ។

រាល់ការផ្ទេរនីមួយៗបង្កើតពីរជួរនៅក្នុង `token_ledger`៖

| ជួរ    | `from_key_id` | `to_key_id` | `amount` |
| ------ | ------------- | ----------- | -------- |
| ឥណពន្ធ | អ្នកផ្ញើ      | អ្នកទទួល    | +amount  |
| ឥណទាន  | អ្នកទទួល      | អ្នកផ្ញើ    | -amount  |

សូមរង់ចាំ — ទម្រង់កំណត់គឺ៖

| ជួរ  | `from_key_id` | `to_key_id` | `amount` | អត្ថន័យ                |
| ---- | ------------- | ----------- | -------- | ---------------------- |
| ផ្ញើ | អ្នកផ្ញើ      | អ្នកទទួល    | +amount  | លំហូរចេញពីអ្នកផ្ញើ     |
| ទទួល | អ្នកទទួល      | អ្នកផ្ញើ    | +amount  | លំហូរចូលទៅកាន់អ្នកទទួល |

សមតុល្យត្រូវបានគណនាដូចខាងក្រោម៖

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### លំហូរនៃការផ្ទេរ

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **ផ្ទៀងផ្ទាត់**៖ `amount > 0`, `fromKeyId !== toKeyId`។
2. **ភាពមិនប្រែប្រួលពេលប្រតិបត្តិម្តងហើយម្តងទៀត**៖ ពិនិត្យមើលថាតើ `idempotency_key` មានរួចហើយនៅក្នុងបញ្ជីគណនេយ្យឬអត់។
   ប្រសិនបើមាន សូមត្រឡប់លទ្ធផលដែលបានរក្សាទុកក្នុងឃ្លាំងសម្ងាត់។
3. **ប្រតិបត្តិការ** (ប្រតិបត្តិការ SQLite តែមួយ)៖
   a. គណនាសមតុល្យរបស់អ្នកផ្ញើ។
   b. ប្រសិនបើ `balance < amount` សូមបោះបង់ (មូលនិធិមិនគ្រប់គ្រាន់)។
   c. បញ្ចូលជួរផ្ញើ (`from=sender,`។

### ការកំណត់អត្រា

- អតិបរមា 10 ការផ្ទេរក្នុងមួយនាទី សម្រាប់ API key នីមួយៗ។
- អតិបរមា 10,000 token សម្រាប់ការផ្ទេរតែមួយ។
- អតិបរមា 100,000 token ដែលបានផ្ទេរក្នុងមួយថ្ងៃ សម្រាប់ API key នីមួយៗ។

## ការអញ្ជើញ និងការប្តូរយក Token

**ឯកសារ:** `src/lib/gamification/invites.ts`

### ទម្រង់កូដ

- **កូដ**៖ អក្សរ និងលេខ 8 តួ (ឧទាហរណ៍ `A3K9-X7M2`) ដែលមនុស្សអាចអានបាន
  និងបង្ហាញដល់អ្នកប្រើប្រាស់។
- **Token**៖ token ចៃដន្យទំហំ 32-byte ដែលត្រូវបានរក្សាទុកជា hash SHA-256។ ប្រើសម្រាប់
  ការប្តូរយកតាមកម្មវិធី (ឧទាហរណ៍ តំណ URL)។

### ការផ្ទុក

| ជួរឈរ        | តម្លៃ                           |
| ------------ | ------------------------------- |
| `code`       | `A3K9X7M2` (តែមួយគត់ មាន index) |
| `token_hash` | SHA-256(raw_token)              |

token ដើមត្រូវបានត្រឡប់ទៅអ្នកប្រើប្រាស់តែម្តងគត់ នៅពេលបង្កើត។ OmniRoute
មិនរក្សាទុក ឬបង្ហាញវាម្តងទៀតឡើយ — មានតែ hash ប៉ុណ្ណោះដែលនៅតែរក្សាទុក។

### ការទប់ស្កាត់ការណែនាំខ្លួនឯង

នៅពេលអ្នកប្រើប្រាស់ប្តូរយកកូដ ប្រព័ន្ធពិនិត្យថា៖

1. កូដនេះជាកម្មសិទ្ធិរបស់ `api_key_id` ផ្សេង។
2. អ្នកប្រើប្រាស់ដែលកំពុងប្តូរយក មិនធ្លាប់បានប្តូរយកកូដណាមួយពីអ្នកណែនាំដូចគ្នាពីមុនទេ
   (ភ្ជាប់លើ `invite_tokens` + កំណត់ហេតុការប្តូរយក)។

ប្រសិនបើការពិនិត្យណាមួយបរាជ័យ ការប្តូរយកនឹងត្រូវបានបដិសេធដោយមានសារកំហុសច្បាស់លាស់។

### ការផុតកំណត់ និងដែនកំណត់

- `max_uses` លំនាំដើម៖ 10 (អាចកំណត់រចនាសម្ព័ន្ធបាននៅពេលបង្កើត)។
- `expires_at` លំនាំដើម៖ 30 ថ្ងៃចាប់ពីពេលបង្កើត។
- កូដដែលផុតកំណត់ ឬត្រូវបានប្រើអស់ នឹងត្រឡប់ HTTP 410 Gone។

## ការភ្ជាប់សហព័ន្ធម៉ាស៊ីនមេសហគមន៍

ម៉ាស៊ីនមេសហគមន៍ត្រូវបានចុះឈ្មោះតាមរយៈថូខឹនអញ្ជើញដែលចេញដោយម៉ាស៊ីនមេពីចម្ងាយ។ អ៊ីនស្តង់មូលដ្ឋាន៖

### ការរកឃើញភាពមិនប្រក្រតីដោយពិន្ទុ Z

សម្រាប់ API key នីមួយៗ ប្រព័ន្ធរក្សាចន្លោះពេលរំកិលរយៈពេល 7 ថ្ងៃនៃ XP ដែលទទួលបានក្នុងមួយម៉ោង។ នៅពេលផ្ដល់ XP នីមួយៗ៖

1. គណនាអត្រា XP ប្រចាំម៉ោងបច្ចុប្បន្នរបស់អ្នកប្រើ។
2. គណនាមធ្យមភាគ និងគម្លាតស្តង់ដាររបស់ក្រុមទិន្នន័យ។
3. គណនា `z = (user_rate - mean) / stddev`។
4. ប្រសិនបើ `z > 3.0` (គម្លាតស្តង់ដារ 3) សម្គាល់ថាជាភាពមិនប្រក្រតី។

ភាពមិនប្រក្រតីត្រូវបានកត់ត្រាទៅ `xp_audit_log` ជាមួយ `action = 'anomaly_detected'` ហើយត្រូវបានបង្ហាញនៅលើផ្ទាំងគ្រប់គ្រងរបស់អ្នកគ្រប់គ្រង។

### កំណត់ត្រាសវនកម្ម

រាល់ការផ្ដល់ XP ការផ្ទេរ ការទទួលបានផ្លាកសញ្ញា និងការរកឃើញភាពមិនប្រក្រតី ត្រូវបានកត់ត្រាទៅ `xp_audit_log` ជាមួយ៖

| វាល          | សេចក្ដីពិពណ៌នា                                    |
| ------------ | ------------------------------------------------- |
| `api_key_id` | នរណា                                              |

```typescript
setImmediate(() => {
```

## ការពិចារណាសម្រាប់ពេលអនាគត

- **ព្រឹត្តិការណ៍តាមរដូវកាល**៖ សំណុំផ្លាកសញ្ញាដែលមានរយៈពេលកំណត់ និងរដូវកាលតារាងចំណាត់ថ្នាក់។
- **តារាងចំណាត់ថ្នាក់ក្រុម**៖ ដាក់អ្នកប្រើប្រាស់ជាក្រុមតាមស្ថាប័ន ឬបន្សំ។
- **មេគុណ XP**៖ បង្កើន XP ក្នុងអំឡុងពេលផ្សព្វផ្សាយ។
- **ការចែករំលែកសមិទ្ធផល**៖ បង្កើតកាតផ្លាកសញ្ញាដែលអាចចែករំលែកបាន (រូបភាព OpenGraph)។
- **ការជូនដំណឹង Push លើទូរសព្ទ**៖ ការជូនដំណឹងផ្អែកលើ webhook សម្រាប់ព្រឹត្តិការណ៍ផ្លាកសញ្ញា/កម្រិត។
- **Leaderboard API**៖ API សាធារណៈសម្រាប់ការរួមបញ្ចូលជាមួយភាគីទីបី។
