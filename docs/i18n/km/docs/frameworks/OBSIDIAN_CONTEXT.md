## តើវាជាអ្វី

OmniRoute ភ្ជាប់ទៅ vault របស់ **Obsidian** ក្នុងនាមជា **ប្រភពបរិបទ** — មូលដ្ឋានចំណេះដឹង
Markdown មូលដ្ឋាន ដែល agent អាន និងសរសេរតាមរយៈម៉ាស៊ីនមេ MCP ដែលភ្ជាប់មកជាមួយ។ ការរួមបញ្ចូលនេះ
ទាក់ទងជាមួយ plugin សហគមន៍ **Obsidian Local REST API** ដែលកំពុងដំណើរការនៅក្នុងកម្មវិធី desktop
ដូច្នេះ agent អាចស្វែងរកកំណត់ត្រា អាន/សរសេរ/កែបំណះឯកសារ រាយបញ្ជី vault ធ្វើការជាមួយ
កំណត់ត្រាតាមកាលកំណត់ប្រចាំថ្ងៃ/ប្រចាំសប្តាហ៍ គ្រប់គ្រង tag ដំណើរការ command របស់ Obsidian និង
(ជាជម្រើស) សម្របសម្រួលការធ្វើសមកាលកម្ម vault ទ្វេទិសរវាង desktop↔mobile។

កម្មវិធីភ្ញៀវ (`src/lib/obsidian/api.ts`) គ្របដណ្ដប់ Local REST API ដោយមាន៖

- **ការព្យាយាមឡើងវិញដោយមានការពន្យារពេល** សម្រាប់កំហុស `5xx` បណ្តោះអាសន្ន និង **អស់ពេលក្រោយ 30 វិនាទី** តាមរយៈ `AbortController`។
- **ការចាត់ថ្នាក់កំហុសដែលមានប្រភេទច្បាស់លាស់** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`។
- **សារណែនាំងាយយល់ "មិនអាចភ្ជាប់ទៅ Obsidian បាន"** ដែលបញ្ជាក់អំពីកំហុសច្រឡំ port ដែលជួបញឹកញាប់
  (HTTP នៅលើ `27123` **មិនមែន** endpoint MCP នៅលើ `27124` ទេ) និងទម្រង់ Tailscale។
- **ការអ៊ិនកូដ path** ដែលទាក់ទងនឹង vault ដើម្បីឱ្យ path កំណត់ត្រាដែលមានដកឃ្លា/សញ្ញា slash មានសុវត្ថិភាព។

## ការដំឡើង

មិនមាន **environment variable** សម្រាប់ token ឬ base URL របស់ Obsidian ទេ — ទាំងពីរត្រូវបាន
រក្សាទុកក្នុងតារាង SQLite `key_value` (namespace `obsidian`) តាមរយៈ
`src/lib/db/obsidian.ts`។ token ត្រូវបាន **អ៊ិនគ្រីបនៅពេលរក្សាទុក** (AES-256-GCM ជាមួយ
ជម្រើសបម្រុងដែលត្រូវគ្នានឹង plaintext ជំនាន់ចាស់)។ កំណត់រចនាសម្ព័ន្ធពីផ្ទាំង **ប្រភពបរិបទ** នៃ
dashboard របស់ Endpoint (`ObsidianSourceCard`) ឬតាមរយៈ REST API សម្រាប់ការកំណត់។

> [!IMPORTANT]
> plugin **Obsidian Local REST API** ត្រូវតែបានដំឡើង និងកំពុងដំណើរការ។ ចំណុចប្រទាក់ REST
> របស់វាស្តាប់នៅលើ **HTTP `127.0.0.1:27123`** (base URL លំនាំដើម)។ Port `27124`
> គឺជា endpoint MCP/HTTPS _ដាច់ដោយឡែក_ ហើយត្រូវបានបដិសេធយ៉ាងជាក់លាក់ដោយ route នៃការកំណត់។
> ប្រសិនបើភ្ជាប់ពីឧបករណ៍ផ្សេង សូមប្រើ `http://<tailscale-ip>:27123`។

### key កំណត់រចនាសម្ព័ន្ធ (SQLite `key_value`, namespace `obsidian`)

| Key               | គោលបំណង                                               | បានអ៊ិនគ្រីប |
| ----------------- | ----------------------------------------------------- | ------------ |
| `api_key`         | bearer token របស់ Local REST API                      | បាទ/ចាស      |
| `base_url`        | REST base URL (លំនាំដើម `http://127.0.0.1:27123`)     | ទេ           |
| `vault_path`      | path ដាច់ខាតទៅកាន់ថត vault (សម្រាប់សមកាលកម្ម)         | ទេ           |
| `webdav_username` | ឈ្មោះអ្នកប្រើ WebDAV ដែលបានបង្កើត (សមកាលកម្ម vault)   | ទេ           |
| `webdav_password` | ពាក្យសម្ងាត់ WebDAV ដែលបានបង្កើត (សមកាលកម្ម vault)    | បាទ/ចាស      |
| `webdav_enabled`  | ថាតើការធ្វើសមកាលកម្ម vault តាម WebDAV ត្រូវបានបើកឬអត់ | ទេ           |

### កំណត់រចនាសម្ព័ន្ធតាមរយៈ REST

```bash
# រក្សាទុក + ផ្ទៀងផ្ទាត់ token របស់ Local REST API (POST ផ្ទៀងផ្ទាត់តាមរយៈការពិនិត្យស្ថានភាព)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# ពិនិត្យស្ថានភាពការតភ្ជាប់ (ត្រឡប់ connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# ផ្តាច់ការតភ្ជាប់ (សម្អាត token ដែលបានរក្សាទុក)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

method ទាំងអស់តម្រូវឱ្យមានការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ dashboard។ `POST` បដិសេធ URL ណាមួយនៅលើ port `27124`
ហើយផ្ទៀងផ្ទាត់ token ដោយហៅ endpoint ស្ថានភាពរបស់ Local REST API មុនពេលរក្សាទុក។

### ការធ្វើសមកាលកម្ម vault តាម WebDAV

`src/app/api/settings/obsidian/webdav/route.ts` គ្រប់គ្រងការធ្វើសមកាលកម្ម vault ដែលគាំទ្រដោយ WebDAV
ជាជម្រើស (ដំណើរការដោយ `src/lib/obsidianSync.ts`)។ ការបើកវានឹងកំណត់ឱ្យ OmniRoute ប្រើ
ថត vault មូលដ្ឋាន និងបង្កើតគូឈ្មោះអ្នកប្រើ/ពាក្យសម្ងាត់ WebDAV ចៃដន្យ៖

```bash
# បើកការធ្វើសមកាលកម្ម WebDAV សម្រាប់ថត vault (បង្កើតឈ្មោះអ្នកប្រើ/ពាក្យសម្ងាត់)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# ទទួលស្ថានភាពសមកាលកម្ម WebDAV (ព័ត៌មានសម្ងាត់ត្រូវបានត្រឡប់តែនៅពេលបានបើកប៉ុណ្ណោះ)
curl http://localhost:20128/api/settings/obsidian/webdav

# បិទការធ្វើសមកាលកម្ម WebDAV (សម្អាតព័ត៌មានសម្ងាត់ + .stignore ដែលបានគ្រប់គ្រង)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### ប្រភពបរិបទតាម API key នីមួយៗ (ជាជម្រើស)

ការកំណត់រចនាសម្ព័ន្ធ Obsidian អាចកំណត់វិសាលភាព **តាម API key នីមួយៗ** តាមរយៈតារាង `api_key_context_sources`
(`src/lib/db/apiKeyContextSources.ts`)។ នៅពេលការហៅ MCP ផ្ទុក id របស់ API key ដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ
`getObsidianConfigForApiKey()` នឹងផ្តល់អាទិភាពដល់ token/base-URL/vault-path ផ្ទាល់ខ្លួនរបស់ key នោះ
(`source: "api_key"`) ហើយបើមិនមានទេ វានឹងប្រើការកំណត់រចនាសម្ព័ន្ធសកលជំនួស (`source: "global"`)។

## ឧបករណ៍ MCP (22)

កំណត់នៅក្នុង `open-sse/mcp-server/tools/obsidianTools.ts`។ Token/base-URL ត្រូវបានកំណត់
សម្រាប់ការហៅនីមួយៗ (តាម API key ជាមុនសិន បន្ទាប់មកតាមការកំណត់សកល)។ ឧបករណ៍ដែលភ្ជាប់ទៅកាន់ **ម៉ាស៊ីនមេសមកាលកម្ម** OmniRoute
(ឧបករណ៍ `obsidian_sync_*` ទាំងបួន) តម្រូវបន្ថែមឱ្យមាន token ផ្ទៀងផ្ទាត់សមកាលកម្មដែលបានកំណត់រចនាសម្ព័ន្ធ
នៅក្នុងការកំណត់ OmniRoute។

### ឧបករណ៍សរសេរ (`write:obsidian`)

| ឧបករណ៍                           | សេចក្ដីពិពណ៌នា                                                                              |
| -------------------------------- | ------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | បង្កើត ឬសរសេរជាន់លើកំណត់ត្រាមួយដោយប្រើខ្លឹមសារ Markdown ដែលបានផ្ដល់។                        |
| `obsidian_append_note`           | បន្ថែមខ្លឹមសារទៅកំណត់ត្រា; អាចបន្ថែមទៅចំណងជើង/ប្លុកជាក់លាក់មួយ។                             |
| `obsidian_patch_note`            | បន្ថែមនៅខាងចុង/ខាងដើម ឬជំនួសដោយចំគោលដៅនៅចំណងជើង ប្លុក ឬវាល frontmatter។                     |
| `obsidian_delete_note`           | លុបកំណត់ត្រាចេញពី vault ជាអចិន្ត្រៃយ៍។                                                      |
| `obsidian_move_note`             | ផ្លាស់ទី ឬប្ដូរឈ្មោះកំណត់ត្រានៅក្នុង vault។                                                 |
| `obsidian_execute_command`       | ប្រតិបត្តិពាក្យបញ្ជា Obsidian តាម ID ពាក្យបញ្ជារបស់វា។                                      |
| `obsidian_open_file`             | បើកឯកសារមួយក្នុង Obsidian (បង្កើតឯកសារនោះ ប្រសិនបើវាមិនមាន)។                                |
| `obsidian_sync_trigger`          | ចាប់ផ្ដើមការធ្វើសមកាលកម្ម vault ទ្វេទិសរវាង desktop↔mobile ភ្លាមៗ។                          |
| `obsidian_sync_resolve_conflict` | ដោះស្រាយការប៉ះទង្គិចសមកាលកម្ម៖ រក្សាទុក `local` (mobile), `remote` (desktop) ឬ `keep-both`។ |

> [!NOTE]
> គោលដៅរបស់ `obsidian_patch_note` ទទួលយក `targetType` ជា `heading | block | frontmatter`
> និង `operation` ជា `append | prepend | replace` ដោយមាន `createTargetIfMissing`
> ជាជម្រើស។ ឧបករណ៍ `obsidian_sync_*` ទាំងបួនទាក់ទងទៅកាន់ម៉ាស៊ីនមេសមកាលកម្មមូលដ្ឋាន
> (`http://127.0.0.1:27781` តាមលំនាំដើម) និងតម្រូវឱ្យមាន sync token។

### វិសាលភាព

ឧបករណ៍អានតម្រូវឱ្យមាន `read:obsidian`; ឧបករណ៍សរសេរតម្រូវឱ្យមាន `write:obsidian`។ ការអនុវត្ត
គឺដូចគ្នានឹង Notion — គ្រប់គ្រងដោយ `withScopeEnforcement()` នៅក្នុង
`open-sse/mcp-server/server.ts`, ដោយដំណើរការនៅពេល `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, ជាមួយ
វិសាលភាពដែលអនុញ្ញាតបានមកពី `OMNIROUTE_MCP_SCOPES` ឬបរិបទវិសាលភាពរបស់ API key។ សូមមើល
[MCP-SERVER.md](./MCP-SERVER.md)។

## ចំណុចបញ្ចប់

| វិធីសាស្ត្រ | ផ្លូវ                           | គោលបំណង                                                   |
| ----------- | ------------------------------- | --------------------------------------------------------- |
| `GET`       | `/api/settings/obsidian`        | ត្រឡប់ `{ connected, hasToken, baseUrl, vaultPath }`។     |
| `POST`      | `/api/settings/obsidian`        | រក្សាទុក + ផ្ទៀងផ្ទាត់ token (បដិសេធ port `27124`)។       |
| `DELETE`    | `/api/settings/obsidian`        | ផ្ដាច់ការតភ្ជាប់ (សម្អាត token ដែលបានរក្សាទុក)។           |
| `GET`       | `/api/settings/obsidian/webdav` | ស្ថានភាព sync WebDAV + ព័ត៌មានសម្ងាត់ (នៅពេលបើកដំណើរការ)។ |
| `POST`      | `/api/settings/obsidian/webdav` | បើកដំណើរការ sync WebDAV សម្រាប់ថត vault មួយ។              |
| `DELETE`    | `/api/settings/obsidian/webdav` | បិទដំណើរការ sync WebDAV។                                  |

> ទាំងនេះគឺជា route ការកំណត់ dashboard។ vault ខ្លួនវាត្រូវបានចូលប្រើតាមរយៈ Obsidian
> Local REST API (`base_url` ដែលបានកំណត់រចនាសម្ព័ន្ធ) និងតាមរយៈឧបករណ៍ MCP ខាងលើ — មិនមាន
> endpoint ប្រូកស៊ី Obsidian `/v1` សាធារណៈទេ។

## ករណីប្រើប្រាស់

- **ចម្លើយដែលផ្អែកលើ vault** — `obsidian_search_simple` / `obsidian_search_structured`
  បន្ទាប់មក `obsidian_read_note` ដើម្បីឱ្យ agent ឆ្លើយដោយផ្អែកលើកំណត់ត្រាពិតប្រាកដរបស់អ្នក។
- **ការសរសេរកំណត់ត្រា / កំណត់ហេតុប្រចាំថ្ងៃ** — `obsidian_write_note`, `obsidian_append_note` ឬ
  `obsidian_patch_note` ដែលកែប្រែចំទីតាំង ដើម្បីកត់ត្រាលទ្ធផលរបស់ agent សេចក្ដីសង្ខេប ឬកំណត់ត្រាប្រចាំថ្ងៃ
  (`obsidian_get_periodic_note`) ទៅក្នុង vault។
- **ការរុករក vault** — `obsidian_list_vault`, `obsidian_get_document_map` និង
  `obsidian_get_tags` ដើម្បីស្វែងយល់ពីរចនាសម្ព័ន្ធមុនពេលអាន/សរសេរ។
- **ស្វ័យប្រវត្តិកម្ម Obsidian** — `obsidian_list_commands` + `obsidian_execute_command` ដើម្បី
  បញ្ជា plugin/command ពី agent; `obsidian_open_file` ដើម្បីបង្ហាញកំណត់ត្រាមួយក្នុង UI។
- **ការធ្វើសមកាលកម្មលើឧបករណ៍ចល័ត** — បើកដំណើរការ sync WebDAV បន្ទាប់មកប្រើ `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  ដើម្បីសម្របសម្រួល desktop↔mobile និងដោះស្រាយការប៉ះទង្គិច។
