Relay (Vercel, Deno, Cloudflare) បញ្ចប់ការតភ្ជាប់ upstream នៅលើ backend
បែប serverless ដើម្បីឱ្យ OmniRoute អាចបញ្ជូនចរាចរចេញពីតំបន់ដែលមានស្ថិរភាព ខណៈពេលរក្សា
API key របស់ provider នៅផ្នែក server។ ឯកសារនេះពន្យល់អំពី failure mode ចំនួនពីរ
ដែលប្រតិបត្តិករជួបប្រទះក្នុង production និងវិធីស្ដារឡើងវិញដែល OmniRoute ផ្តល់ជូន
សម្រាប់ករណីនីមួយៗ។

## របៀបរក្សាទុកការផ្ទៀងផ្ទាត់ relay

នៅពេលអ្នក deploy relay ពី **Settings → Proxy Pool → Deploy Relay** លំហូរ
deploy នឹងរក្សាទុក auth token របស់ relay ក្នុង field JSON `notes` របស់ proxy៖

- ប្រសិនបើបានកំណត់ `STORAGE_ENCRYPTION_KEY` token នឹងត្រូវបានសរសេរជា `relayAuthEnc`
  (ត្រូវបានអ៊ិនគ្រីបដោយ AES នៅពេលរក្សាទុក)។
- បើមិនដូច្នោះទេ វានឹងត្រូវបានសរសេរជា plaintext `relayAuth`។

នៅពេលមាន request `extractRelayAuth(notes)` នឹងត្រឡប់ទម្រង់ណាមួយដែលមាន
ដូច្នេះ relay នៅតែបន្តដំណើរការបន្ទាប់ពី restart។

## Failure mode 1 — មិនអាចឌិគ្រីប token បន្ទាប់ពីប្ដូរ key

**រោគសញ្ញា៖** relay ដែលធ្លាប់ដំណើរការពីមុន ឥឡូវត្រឡប់កំហុស upstream `401`/auth
បន្ទាប់ពីការប្ដូរ `STORAGE_ENCRYPTION_KEY` នៅក្នុង environment ឬ secret manager។
blob `relayAuthEnc` ដែលបានរក្សាទុកមិនអាចត្រូវបានឌិគ្រីបទៀតទេ ដូច្នេះ
`extractRelayAuth` ត្រឡប់ string ទទេ ហើយ relay មិនផ្ញើ auth ឡើយ។

**ការស្ដារឡើងវិញ — ជួសជុលនៅនឹងកន្លែង (មិនចាំបាច់ redeploy)៖**

1. បើក **Settings → Proxy Pool**។
2. ជួរដេក relay ដែលបាត់ auth បង្ហាញ badge ពណ៌លឿង `auth missing` និងប៊ូតុង
   **Repair**។
3. ចុច **Repair**។ OmniRoute ហៅ
   `POST /api/settings/proxies/[id]/repair-relay` ដែល៖
   - ឌិគ្រីប `relayAuthEnc` ដោយប្រើ key **បច្ចុប្បន្ន**,
   - សរសេរ plaintext `relayAuth` ត្រឡប់ចូលក្នុង `notes`,
   - ត្រឡប់ `{ repaired: true, mode: "recovered" }`។

Relay នឹងបន្តផ្តល់សេវាឡើងវិញដោយមិនចាំបាច់បញ្ចូលព័ត៌មានសម្ងាត់សម្រាប់ deploy ម្ដងទៀត។

វិធីនេះដំណើរការតែក្នុងករណីដែល `STORAGE_ENCRYPTION_KEY` បច្ចុប្បន្ននៅតែអាចឌិគ្រីប
blob បាន។ ប្រសិនបើអ្នកបានប្ដូរ key **ដោយគ្មាន** migration នោះ blob
មិនអាចស្ដារឡើងវិញបានទេ។

## Failure mode 2 — token មិនអាចស្ដារឡើងវិញបាន (key ចាស់ត្រូវបានប្ដូរចេញ)

**រោគសញ្ញា៖** អ្នកបានចុច **Repair** ហើយទទួលបាន
`{ repaired: false, mode: "redeploy", status: 409 }`។

**ការស្ដារឡើងវិញ — redeploy៖**

Token ដែលបានរក្សាទុកមិនអាចស្ដារឡើងវិញដោយប្រើ key បច្ចុប្បន្នបានទេ។ Deploy relay
ឡើងវិញពី modal ដដែលដែលអ្នកបានប្រើពីដំបូង (**Deploy Relay** menu → Vercel / Deno
/ Cloudflare)។ លំហូរ deploy នឹងសរសេរ token ថ្មីមួយ (ដែលត្រូវបានអ៊ិនគ្រីបដោយប្រើ key
បច្ចុប្បន្ន) ហើយ badge `auth missing` របស់ជួរដេកនោះនឹងបាត់។

នៅក្នុង UI ប៊ូតុង **Repair** នឹងបើក modal សម្រាប់ redeploy ដោយខ្លួនឯង នៅពេល
token មិនអាចស្ដារឡើងវិញបាន ដូច្នេះអ្នកមិនចាំបាច់ស្វែងរកវាដោយដៃទេ។

## Failure mode 3 — អាចចូលប្រើ relay បាន ប៉ុន្តែវាមិនមានស្ថានភាពល្អ

**រោគសញ្ញា៖** ការធ្វើតេស្ត proxy (ប៊ូតុង `speed`) បង្ហាញថា relay ដំណើរការ ប៉ុន្តែ request
នៅតែបរាជ័យម្ដងម្កាល។

ពិនិត្យ relay awareness headers ដែលត្រូវបានត្រឡប់ដោយ auto-test probe របស់ OmniRoute
(មើល **Settings → Proxy Pool** និង counters `relayTested` / `relayAlive`)៖

- `x-relay-url` — relay backend ណាមួយដែលបានឆ្លើយតប។
- `x-relay-mode` — `ts` | `bifrost` | `auto` សម្រាប់ request នោះ។
- `x-relay-attempts` — ចំនួន relay hops ដែលត្រូវបានសាកល្បងមុនពេលជោគជ័យ។
- `x-relay-fallback` — `true` នៅពេល request ប្ដូរពី backend ដែលពេញចិត្ត
  ទៅកាន់ TypeScript relay។

អត្រា `x-relay-fallback` ខ្ពស់ជាមួយ `relayAlive` ទាប មានន័យថា sidecar
backend មិនមានស្ថានភាពល្អ ហើយអ្នកគួរជួសជុលវា ឬប្ដូរយុទ្ធសាស្ត្រ relay backend
ទៅជា `ts` (មើល `RELAY_BACKEND_STRATEGY.md`)។

## ឯកសារយោង API

| វិធីសាស្ត្រ | Path                                      | Body                    | ជោគជ័យ                                                                                                                                          | បរាជ័យ                                                                                      |
| ----------- | ----------------------------------------- | ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `POST`      | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | `200 { repaired: true, mode: "recovered" }` នៅពេល derivation ឡើងវិញបានជោគជ័យ; `200 { repaired: false, mode: "noop" }` នៅពេលមាន plaintext រួចហើយ | `409 { mode: "redeploy" }` មិនអាចស្ដារឡើងវិញបាន; `400` មិនមែនជាប្រភេទ relay; `404` រកមិនឃើញ |

List route `GET /api/settings/proxies` ភ្ជាប់
`relayInfo: { isRelay, authMissing, repairMode }` ដែលមិនមាន secret ទៅនឹង item នីមួយៗ ដើម្បីឱ្យ dashboard
អាចបង្ហាញជម្រើសជួសជុលដោយមិនបង្ហាញ token ជាដាច់ខាត។
