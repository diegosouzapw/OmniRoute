# មុនពេលអ្នកចាប់ផ្តើម

> **សំខាន់៖** តែងតែចម្លងព័ត៌មានសម្គាល់ពី **សំណើបណ្ដាញផ្ទាល់** ហើយ **កុំ** ចម្លងពីកន្លែងផ្ទុក cookie របស់កម្មវិធីរុករកអ្នក។

បញ្ហាផ្ទៀងផ្ទាត់អត្តសញ្ញាណជាច្រើនកើតឡើងដោយសារការចម្លង cookie ពីកន្លែងខុស។

## កុំចម្លងពីកន្លែងផ្ទុក Cookie

កម្មវិធីរុករកភាគច្រើនបង្ហាញ cookie ដែលបានរក្សាទុកតាមរយៈ៖

```
ឧបករណ៍អ្នកអភិវឌ្ឍន៍
→ កម្មវិធី (ឬកន្លែងផ្ទុក)
→ Cookies
```

ទោះបីជា cookie ទាំងនេះមើលទៅត្រឹមត្រូវក៏ដោយ វាអាច៖

- ហួសសម័យ
- មិនពេញលេញ
- ខ្វះ cookie ដែលត្រូវបានផ្ញើតែក្នុងសំណើដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណប៉ុណ្ណោះ

ការប្រើតម្លៃទាំងនេះអាចបណ្ដាលឱ្យការផ្ទៀងផ្ទាត់អត្តសញ្ញាណបរាជ័យ ទោះបីជាវាមើលទៅមានសុពលភាពក៏ដោយ។

## ចម្លងពីសំណើផ្ទាល់

ជំនួសមកវិញ សូមប្រើ cookie ពីសំណើដែលជោគជ័យ៖

```
ឧបករណ៍អ្នកអភិវឌ្ឍន៍
→ បណ្ដាញ
→ ផ្ទុកទំព័រឡើងវិញ
→ បើកសំណើជជែក ឬការសន្ទនា
→ បឋមកថាសំណើ
→ Cookie
```

បឋមកថាសំណើ `Cookie` មានព័ត៌មានផ្ទៀងផ្ទាត់អត្តសញ្ញាណពិតប្រាកដដែលកម្មវិធីរុករករបស់អ្នកបានប្រើដោយជោគជ័យ។

សម្រាប់អ្នកផ្តល់សេវា Web Cookie ភាគច្រើន នេះគឺជាតម្លៃដែលគួរបិទភ្ជាប់ទៅក្នុង OmniRoute។

# ការរៀបចំទូទៅ

ដំណើរការរៀបចំគឺដូចគ្នាសម្រាប់អ្នកផ្តល់សេវា Web Cookie ភាគច្រើន។

1. ចូលគណនីនៅលើគេហទំព័ររបស់អ្នកផ្តល់សេវា។
2. បើកឧបករណ៍អ្នកអភិវឌ្ឍន៍របស់កម្មវិធីរុករក។
3. បើកផ្ទាំង **បណ្ដាញ**។
4. ផ្ទុកទំព័រឡើងវិញ។
5. បើកសំណើជជែក ឬការសន្ទនាដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ។
6. ចម្លងព័ត៌មានសម្គាល់សម្រាប់ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណដែលត្រូវការ។
7. បើក OmniRoute។
8. ចូលទៅកាន់ **អ្នកផ្តល់សេវា → បន្ថែមអ្នកផ្តល់សេវា**។
9. ជ្រើសរើសអ្នកផ្តល់សេវា Web Cookie របស់អ្នក។
10. បិទភ្ជាប់ព័ត៌មានសម្គាល់។
11. ចុច **សាកល្បងការតភ្ជាប់**។
12. រក្សាទុកអ្នកផ្តល់សេវា។

ព័ត៌មានសម្គាល់ជាក់លាក់ដែលត្រូវការ អាស្រ័យលើអ្នកផ្តល់សេវា។

# អ្វីដែលអ្នកផ្តល់សេវា Web Cookie អាច និងមិនអាចធ្វើបាន

អ្នកផ្តល់សេវា Web Cookie ប្រើចំណុចប្រទាក់ជជែករបស់គេហទំព័រឡើងវិញ។ វា **មិន** ផ្ដល់សមត្ថភាពដូចគ្នានឹង API ផ្លូវការទេ។

## បានគាំទ្រ

- ផ្ទៀងផ្ទាត់អត្តសញ្ញាណដោយប្រើសម័យកម្មវិធីរុករកដែលមានស្រាប់របស់អ្នក
- ចូលប្រើម៉ូដែលដែលមានតាមរយៈគណនីរបស់អ្នក
- ចាក់ផ្សាយការឆ្លើយតបក្នុងការជជែក
- មិនត្រូវការ API key

## មិនបានគាំទ្រ

- ការហៅ function
- ការហៅ tool
- ការកែសម្រួលឯកសារដោយស្វ័យប្រវត្តិ
- លំហូរការងារ IDE បែប agent
- មុខងារដែលមានតែក្នុង API

នេះជាឥរិយាបថដែលបានរំពឹងទុក ហើយ **មិនមែន** ជា bug ទេ។

ប្រសិនបើអ្នកត្រូវការការប្រតិបត្តិ tool ការកែសម្រួលឯកសារដោយស្វ័យប្រវត្តិ ឬលំហូរការងារ agent ផ្សេងទៀត សូមប្រើ **អ្នកផ្តល់សេវាដែលប្រើ API key** ជំនួសឱ្យអ្នកផ្តល់សេវា Web Cookie។

# ចំណុចគួរប្រុងប្រយ័ត្នអំពីការផ្ទៀងផ្ទាត់សុពលភាព

ការជោគជ័យនៃ **សាកល្បងការតភ្ជាប់** ឬការផ្ទៀងផ្ទាត់សុពលភាព cookie គ្រាន់តែបញ្ជាក់ថា ព័ត៌មានសម្គាល់ដែលបានផ្ដល់មើលទៅស្ថិតក្នុងទម្រង់ដែលរំពឹងទុកប៉ុណ្ណោះ។

រហូតដល់ Issue #7857 ត្រូវបានដោះស្រាយ ការផ្ទៀងផ្ទាត់សុពលភាពដោយជោគជ័យ **មិនធានា** ថាអ្នកផ្តល់សេវានឹងអាចផ្ទៀងផ្ទាត់អត្តសញ្ញាណដោយជោគជ័យនោះទេ។

ប្រសិនបើការផ្ទៀងផ្ទាត់អត្តសញ្ញាណនៅតែបរាជ័យ សូមផ្ទៀងផ្ទាត់ថាអ្នកបានចម្លងព័ត៌មានសម្គាល់ពីសំណើបណ្ដាញផ្ទាល់ ជំនួសឱ្យកន្លែងផ្ទុក cookie របស់កម្មវិធីរុករក។

---

# ការដោះស្រាយបញ្ហា

## ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណបរាជ័យ

ផ្ទៀងផ្ទាត់ថាព័ត៌មានសម្គាល់ត្រូវបានចម្លងពី៖

```
បណ្ដាញ
→ បឋមកថាសំណើ
→ Cookie
```

ហើយ **មិនមែន** មកពី៖

```
កម្មវិធី
→ Cookies
```

---

## Cookie ដំណើរការក្នុងកម្មវិធីរុករក ប៉ុន្តែមិនដំណើរការក្នុង OmniRoute

អ្នកផ្តល់សេវាខ្លះរួមបញ្ចូល cookie ដែលត្រូវបានផ្ញើតែក្នុងអំឡុងពេលមានសំណើដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណប៉ុណ្ណោះ។

ចម្លងព័ត៌មានសម្គាល់ម្ដងទៀតពីសំណើបណ្ដាញថ្មី បន្ទាប់ពីបានបើកការសន្ទនាដោយជោគជ័យ។

---

## សម័យបានផុតកំណត់

អ្នកផ្តល់សេវា Web Cookie ប្រើសម័យកម្មវិធីរុករកដែលមានស្រាប់របស់អ្នក។

ប្រសិនបើសម័យកម្មវិធីរុករករបស់អ្នកផុតកំណត់ ឬអ្នកចាកចេញពីគណនី អ្នកត្រូវចម្លងសំណុំព័ត៌មានសម្គាល់ថ្មី។

---

## ការសាកល្បងការតភ្ជាប់ជោគជ័យ ប៉ុន្តែសំណើបរាជ័យ

រហូតដល់ Issue #7857 ត្រូវបានដោះស្រាយ ការឆ្លងកាត់ការផ្ទៀងផ្ទាត់សុពលភាព មិនធានាថាសំណើផ្ទៀងផ្ទាត់អត្តសញ្ញាណនឹងជោគជ័យនោះទេ។

ចម្លងព័ត៌មានសម្គាល់របស់អ្នកម្ដងទៀតពីសំណើថ្មីដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ មុននឹងបន្តដោះស្រាយបញ្ហាបន្ថែមទៀត។

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

មគ្គុទ្ទេសក៍ Claude Web បង្ហាញពីដំណើរការរៀបចំពេញលេញសម្រាប់អ្នកផ្តល់សេវា Web Cookie និងប្រើជាការអនុវត្តយោង។

# ការអនុវត្តល្អបំផុត

- ចម្លងព័ត៌មានសម្គាល់ពីសំណើថ្មីដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ។
- ជៀសវាងការប្រើ cookie ចាស់ឡើងវិញ។
- រក្សាសម័យកម្មវិធីរុករករបស់អ្នកឱ្យនៅសកម្ម ខណៈពេលកំពុងប្រើអ្នកផ្តល់សេវា Web Cookie។
- ចាត់ទុក cookie ដែលបានចម្លងជាព័ត៌មានសម្គាល់រសើប។
- ប្រើអ្នកផ្តល់សេវាដែលប្រើ API key នៅពេលអ្នកត្រូវការការហៅ function ឬលំហូរការងារ agent។
