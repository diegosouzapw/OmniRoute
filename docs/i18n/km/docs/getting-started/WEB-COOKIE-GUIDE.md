# មុនពេលអ្នកចាប់ផ្តើម

> **សំខាន់៖** តែងតែចម្លងព័ត៌មានសម្គាល់ពី **សំណើបណ្តាញដែលកំពុងដំណើរការ** ហើយ **កុំ** ចម្លងពីឃ្លាំង cookie របស់កម្មវិធីរុករក។

បញ្ហាផ្ទៀងផ្ទាត់អត្តសញ្ញាណជាច្រើនបណ្តាលមកពីការចម្លង cookie ពីកន្លែងមិនត្រឹមត្រូវ។

## កុំចម្លងពីឃ្លាំង Cookie

កម្មវិធីរុករកភាគច្រើនបង្ហាញ cookie ដែលបានរក្សាទុកតាមរយៈ៖

```
DevTools
→ Application (ឬ Storage)
→ Cookies
```

ទោះបីជា cookie ទាំងនេះមើលទៅត្រឹមត្រូវក៏ដោយ វាអាច៖

- ហួសសុពលភាព
- មិនពេញលេញ
- ខ្វះ cookie ដែលផ្ញើតែនៅពេលមានសំណើដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណប៉ុណ្ណោះ

ការប្រើតម្លៃទាំងនេះអាចបណ្តាលឱ្យការផ្ទៀងផ្ទាត់អត្តសញ្ញាណបរាជ័យ ទោះបីជាវាមើលទៅមានសុពលភាពក៏ដោយ។

## ចម្លងពីសំណើដែលកំពុងដំណើរការ

ជំនួសមកវិញ សូមប្រើ cookie ពីសំណើដែលបានជោគជ័យ៖

```
DevTools
→ Network
→ ផ្ទុកទំព័រឡើងវិញ
→ បើកសំណើជជែក ឬសំណើសន្ទនា
→ Request Headers
→ Cookie
```

ក្បាលសំណើ `Cookie` មានព័ត៌មានផ្ទៀងផ្ទាត់អត្តសញ្ញាណពិតប្រាកដដែលកម្មវិធីរុករករបស់អ្នកបានប្រើដោយជោគជ័យ។

សម្រាប់អ្នកផ្តល់សេវា Web Cookie ភាគច្រើន នេះគឺជាតម្លៃដែលគួរបិទភ្ជាប់ទៅក្នុង OmniRoute។

# ការដំឡើងទូទៅ

ដំណើរការដំឡើងគឺដូចគ្នាសម្រាប់អ្នកផ្តល់សេវា Web Cookie ភាគច្រើន។

1. ចូលគណនីនៅលើគេហទំព័ររបស់អ្នកផ្តល់សេវា។
2. បើក Developer Tools របស់កម្មវិធីរុករក។
3. បើកផ្ទាំង **Network**។
4. ផ្ទុកទំព័រឡើងវិញ។
5. បើកសំណើជជែក ឬសំណើសន្ទនាដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ។
6. ចម្លងព័ត៌មានសម្គាល់សម្រាប់ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណដែលត្រូវការ។
7. បើក OmniRoute។
8. ទៅកាន់ **Providers → Add Provider**។
9. ជ្រើសរើសអ្នកផ្តល់សេវា Web Cookie របស់អ្នក។
10. បិទភ្ជាប់ព័ត៌មានសម្គាល់។
11. ចុច **Test Connection**។
12. រក្សាទុកអ្នកផ្តល់សេវា។

ព័ត៌មានសម្គាល់ជាក់លាក់ដែលត្រូវការអាស្រ័យលើអ្នកផ្តល់សេវា។

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) គឺជាវេទិកាជជែកសម្រាប់អ្នកប្រើប្រាស់ដោយឥតគិតថ្លៃ ដែលមិនតម្រូវឱ្យចុះឈ្មោះទេ — សម័យត្រូវបានបង្កើតដោយអនាមិកនៅពេលចូលប្រើលើកដំបូង ហើយត្រូវបានរក្សាទុកតាមរយៈខូគីចំនួនបី៖ `uid`, `si_usr_id` និង `si_ses_id`។ OmniRoute បញ្ជូនបន្ត endpoint `/api/dispatch` ដូចគ្នាតាមរយៈលេខសម្គាល់ម៉ូដែលតែមួយ (`notrack-c`, ឈ្មោះក្លែងកាត់ `ntw`)។

### ជំហានតភ្ជាប់

1. បើក [notrack.ai](https://notrack.ai) នៅក្នុងកម្មវិធីរុករករបស់អ្នក ហើយទុកឱ្យខូគីសម័យអនាមិកត្រូវបានកំណត់។
2. បើក **DevTools → Network** ផ្ទុកទំព័រឡើងវិញ ហើយចុចលើសំណើ `/api` ណាមួយ។
3. នៅក្នុង **Request Headers** ចម្លងតម្លៃពេញលេញនៃ header `Cookie`។
4. នៅក្នុង OmniRoute សូមចូលទៅកាន់ **Providers → Add Provider → NoTrack Web (Free)**។
5. បិទភ្ជាប់ខ្សែអក្សរខូគីទៅក្នុងវាល `apiKey` ហើយចុច **Save**។

OmniRoute ស្រង់យក `uid`, `si_usr_id` និង `si_ses_id` ពីខ្សែអក្សរដែលបានបិទភ្ជាប់ ហើយបង្កើត header `Cookie` ស្អាតឡើងវិញដោយមានតែគូទាំងនោះប៉ុណ្ណោះ — ព្រមទាំង `nt_session` (ថូខឹន `ntk_…` ដែលត្រូវបានកំណត់សម្រាប់គណនីដែលបានចូលប្រើ) នៅពេលមានវត្តមាន។ ប្រសិនបើតម្លៃណាមួយក្នុងចំណោមតម្លៃទាំងបីបាត់ ខ្សែអក្សរដើមដែលបានបិទភ្ជាប់នឹងត្រូវបានបញ្ជូនបន្តដោយមិនកែប្រែ ដើម្បីឱ្យអ្នកប្រតិបត្តិការអាចសាកល្បងទម្រង់ជំនួសផ្សេងៗ។

### លេខសម្គាល់ម៉ូដែល

### សមត្ថភាព

- ការបំពេញការជជែកបែប **ស្ទ្រីម និងមិនស្ទ្រីម**។
- **ការហៅឧបករណ៍** — កំណត់ `tools: [...]` នៅក្នុងសំណើ; កម្មវិធីប្រតិបត្តិនឹងបម្លែងវាទៅជាទម្រង់ស្រោមកិច្ចសន្យាសម្រាប់ការហៅឧបករណ៍ ហើយញែកការឆ្លើយតបរបស់ម៉ូដែលត្រឡប់ទៅជា `tool_calls` របស់ OpenAI។
- **`response_format`** — គាំទ្រ `json_object` និង `json_schema`។ កម្មវិធីប្រតិបត្តិស្រង់យកវត្ថុ JSON ដំបូងពីការឆ្លើយតបរបស់ម៉ូដែល ហើយបម្លែងវាទៅជាខ្សែអក្សរមុនពេលបញ្ជូនត្រឡប់។
- **តម្រុយហេតុផល** — កម្មវិធីប្រតិបត្តិបញ្ចេញ delta `reasoning` នៅពេលប្រព័ន្ធខាងប្រភពផ្ញើព្រឹត្តិការណ៍ `thinking`។

### ដែនកំណត់

- ប្រព័ន្ធខាងប្រភពកំណត់កូតាប្រើប្រាស់អនាមិក — នៅពេលកូតាត្រូវបានប៉ះ កម្មវិធីប្រតិបត្តិនឹងបង្ហាញ 429 ជាមួយសារដែលងាយយល់។

- ជៀសវាងការប្រើ cookie ចាស់ឡើងវិញ។
- រក្សាសម័យកម្មកម្មវិធីរុករករបស់អ្នកឱ្យសកម្ម ខណៈពេលប្រើអ្នកផ្តល់សេវា Web Cookie។
- ចាត់ទុក cookie ដែលបានចម្លងជាព័ត៌មានសម្ងាត់រសើប។
- ប្រើអ្នកផ្តល់សេវាដែលប្រើ API key នៅពេលអ្នកត្រូវការការហៅមុខងារ ឬលំហូរការងារភ្នាក់ងារ។
