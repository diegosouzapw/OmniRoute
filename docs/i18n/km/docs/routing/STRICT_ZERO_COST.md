> ទាំងអស់ឱ្យដូចគ្នាទាំងស្រុងនៅកម្រិតបៃ)។ វាជាជម្រើសដ៏តឹងរ៉ឹងជាង `hidePaidModels`
> (`open-sse/services/autoCombo/paidModelFilter.ts`, #6512) សម្រាប់ប្រតិបត្តិករដែលត្រូវការការធានាដាច់ខាត
> ប្រឆាំងនឹងការចំណាយប្រាក់បន្ថែមណាមួយ មិនមែនត្រឹមតែ «បានកត់ត្រាថាឥតគិតថ្លៃ» ប៉ុណ្ណោះទេ។

## ហេតុអ្វីវាមាន និងហេតុអ្វី `hidePaidModels` តែមួយមុខមិនគ្រប់គ្រាន់

`hidePaidModels` ឆ្លើយសំណួរថា «តើម៉ូដែលនេះត្រូវបានចាត់ថ្នាក់ជាឥតគិតថ្លៃក្នុង `FREE_MODEL_BUDGETS` ឥឡូវនេះឬទេ?» —
វាជាទិន្នន័យកាតាឡុកត្រឹមពេលវេលាជាក់លាក់មួយ ដែលត្រូវបានពិនិត្យតាមរយៈ `isFreeModel()`/`providerHasFreeModels()`
(`src/shared/utils/freeModels.ts`)។ វាមិនបង្ហាញអ្វីអំពីហានិភ័យពិតប្រាកដពីរខាងក្រោមនេះទេ៖

1. ចំនួនអនុញ្ញាតរបស់កម្រិតឥតគិតថ្លៃ `recurring-*`/`one-time-initial` អាចត្រូវបាន **ប្រើអស់** — កាតាឡុក
   នៅតែរាយម៉ូដែលនោះថាឥតគិតថ្លៃ ប៉ុន្តែគណនីដែលនៅពីក្រោយវាលែងមានកូតានៅសល់ទៀតហើយ។
2. ការប្រើលើសកម្រិតឥតគិតថ្លៃ មិនមែនតែងតែត្រូវបានបញ្ឈប់ដោយដាច់ខាតនោះទេ។ Provider ខ្លះបញ្ជាក់យ៉ាងច្បាស់ថា
   មិនអាចភ្ជាប់មធ្យោបាយទូទាត់ណាមួយបានឡើយ («មិនតម្រូវឱ្យមានប័ណ្ណឥណទាន»); Provider ខ្លះទៀតមិនបានបញ្ជាក់ ហើយ
   មួយចំនួនតូចគិតថ្លៃដោយស្វ័យប្រវត្តិ នៅពេលប្រើលើសចំនួនអនុញ្ញាតឥតគិតថ្លៃ។

`hidePaidModels` មិនអាចបែងចែកករណីទាំងនេះបានទេ — វាមិនដែលត្រូវបានបង្កើតឡើងសម្រាប់គោលបំណងនោះឡើយ។ STRICT_ZERO_COST បន្ថែម
ការត្រួតពិនិត្យទាំងពីរនេះយ៉ាងជាក់លាក់ ដោយវាយតម្លៃតាម candidate នីមួយៗ **មុន** ការចាត់ចំណាត់ថ្នាក់តាមប្រភេទ/កម្រិត និង **មុន**
ការបញ្ជូន — មិនដែលធ្វើបន្ទាប់ពី request ត្រូវបានផ្ញើចេញរួចហើយឡើយ។

## ការចាត់ថ្នាក់ candidate

សម្រាប់ candidate នីមួយៗក្នុង pool (`open-sse/services/autoCombo/virtualFactory.ts::buildPreparedPool`,
ភ្លាមៗបន្ទាប់ពី `filterPaidOnlyCandidates`)៖

1. **មិនមាននៅក្នុង `FREE_MODEL_BUDGETS` ទាល់តែសោះ** → ត្រូវដកចេញ។ នេះគ្របដណ្តប់លើម៉ូដែលដែលគិតថ្លៃពិតប្រាកដ និង
   Provider/ម៉ូដែលណាមួយដែល OmniRoute មិនទាន់បានចាត់ថ្នាក់ — candidate ថ្មីត្រូវបានដកចេញជាមុន មិនមែនដាក់បញ្ចូលទេ។
2. **`freeType: "keyless"`** → ឆ្លងកាត់ភ្លាមៗ **ប៉ុន្តែសម្រាប់តែ candidate ដែលពិតជាបានមកតាម
   no-auth path ប៉ុណ្ណោះ** (`connectionId === SYNTHETIC_NOAUTH_CONNECTION_ID`,
   `open-sse/services/autoCombo/resilienceCandidateFilter.ts`)។ មិនមាន credential សម្រាប់
   candidate នោះទេ ដូច្នេះ request ទៅកាន់វាមិនអាចត្រូវបានគិតថ្លៃឡើយ — មិនចាំបាច់ និងមិនអាចធ្វើ
   ការត្រួតពិនិត្យពេលដំណើរការបានទេ។ Provider/ម៉ូដែល `keyless` ដូចគ្នាដែលមានក្នុងកាតាឡុក ប៉ុន្តែត្រូវបានចូលប្រើតាម
   connection DB **ពិតប្រាកដ** (`connectionId` ជា connection id ពិតប្រាកដ ឬ candidate មាន
   `allowedConnectionIds`) មិនទទួលបានផ្លូវកាត់នេះទេ — metadata `keyless` ពិពណ៌នាជាក់លាក់អំពី
   no-auth path មិនមែនអំពី Provider ជាទូទៅទេ ហើយវាមិនដែលផ្តល់សិទ្ធិដល់គណនីពិតប្រាកដដែលមាន
   credential ឡើយ។ candidate បែបនេះនឹងបន្តទៅការត្រួតពិនិត្យទី 3 ដូច candidate ផ្សេងទៀត ដែលនៅទីនោះវា
   ត្រូវបានដកចេញ លុះត្រាតែធាតុកាតាឡុកមាន `hardStopGuaranteed: true` ដោយឡែក (`keyless` ពិតប្រាកដ
   មិនដែលមានវាទេ — ផ្លូវកាត់គឺជាមធ្យោបាយតែមួយគត់របស់វាដើម្បីធានាសុវត្ថិភាព)។
3. **`freeType` ផ្សេងទៀតណាមួយ** (`recurring-daily`, `recurring-monthly`, `recurring-credit`,
   `recurring-uncapped`, `one-time-initial` និងប្រភេទនាពេលអនាគតណាមួយដែល module នេះមិន
   ដោះស្រាយជាករណីពិសេស) → ឆ្លងកាត់លុះត្រាតែ **លក្ខខណ្ឌទាំងអស់** ខាងក្រោមត្រូវបានបំពេញ៖
   - `hardStopGuaranteed: true` ត្រូវបានកំណត់លើធាតុកាតាឡុក (`FreeModelBudget.hardStopGuaranteed`,
     `open-sse/config/freeModelCatalog.ts`) — ជា **ការពិតដែលបានជ្រើសរើស និងកំណត់ដោយដៃ** អំពីលក្ខខណ្ឌដែល
     Provider បានផ្សព្វផ្សាយផ្ទាល់ (ឧ. ការអះអាងច្បាស់លាស់ថា «មិនតម្រូវឱ្យមានប័ណ្ណឥណទាន») ហើយមិនដែលត្រូវបានសន្និដ្ឋានពី
     `freeType` ឬពីការឆ្លើយតបរបស់ API ផ្ទាល់ឡើយ។ ការមិនកំណត់ (`undefined`) និង `false` ទាំងពីរត្រូវបានចាត់ទុកថា
     «មិនមានការធានា»។
   - មាន usage adapter សម្រាប់ Provider ក្នុង `USAGE_FETCHER_PROVIDERS`
     (`open-sse/services/usage.ts`) — ជា registry ដូចគ្នាដែលគាំទ្រ quota dashboard និង
     `getUsageForProvider()` ស្រាប់។ គ្មាន adapter → ត្រូវដកចេញជាអចិន្ត្រៃយ៍ រហូតដល់មានការបន្ថែម adapter មួយ។
   - `FreeAccessState` ផ្ទាល់ដែលបាន cache សម្រាប់ **connection ជាក់លាក់ដែលកំពុងត្រូវបាន
     វាយតម្លៃ** មាន `status: "SAFE"` ត្រូវបានពិនិត្យក្នុងចន្លោះពេល
     `settings.autoRefreshProviderQuotaInterval` (តាមលំនាំដើម 180s — ជា setting ដែលមានស្រាប់ មិនមែនជា
     តម្លៃថ្មីទេ) ហើយរាយការណ៍ថា `remainingFreeAllowance` ខ្ពស់ជាងកម្រិតបម្រុងសុវត្ថិភាពតូចមួយ។
4. **`freeType: "discontinued"`** → ត្រូវដកចេញជានិច្ច។

## សុវត្ថិភាពនៃការតភ្ជាប់ (ការផ្ទៀងផ្ទាត់តាមការតភ្ជាប់នីមួយៗ មិនមែនតាម candidate នីមួយៗទេ)

candidate មួយនៅក្នុង auto-combo pool មិនតែងតែត្រូវបានភ្ជាប់ទៅនឹង connection តែមួយទេ។ candidate

**នៅសល់ចន្លោះខ្វះខាតមួយ ហើយវាត្រូវបានទុកដោយចេតនា។** `excludeTosAvoid` នៅតែដកបេក្ខភាពចេញ មុនពេល
បញ្ជីត្រូវបានបង្កើត ដូច្នេះម៉ូដែលដែលបានរៀបចំកំណត់ជា `tos: "avoid"` នឹងអវត្តមានដោយគ្មានផ្តល់មូលហេតុ — ជាភាព
មើលមិនឃើញដូចគ្នាដែលផ្នែកនេះទើបតែបានដោះស្រាយសម្រាប់របាំងការពារដោយឥតគិតថ្លៃ។ ការបិទចន្លោះនេះផងដែរ មានន័យថាត្រូវសម្រេចថា
ការដកចេញដោយសារ ToS គួររាយការណ៍អ្វី ដែលជាសំណួរដាច់ដោយឡែកពីសុវត្ថិភាពផ្នែកសេដ្ឋកិច្ច; ទំព័រនេះបញ្ជាក់ពី
ចន្លោះខ្វះខាតនោះ ជាជាងធ្វើពុតថាវាមិនមាន។

សម្រាប់ការប្រៀបធៀបមុន/ក្រោយក្រៅបណ្តាញ `npx tsx scripts/ad-hoc/dry-run-strict-zero-cost.ts` នៅតែដំណើរការ
ជាមួយលទ្ធផលបេក្ខភាពរបស់ instance ដែលកំពុងដំណើរការ; វាអាន `connectionId` ពិតរបស់បេក្ខភាពនីមួយៗ ដូច្នេះវា
ក៏សាកល្បងផ្លូវសុវត្ថិភាពនៃការតភ្ជាប់ផងដែរ។ បេក្ខភាព `keyless` ត្រូវតែមកជាមួយ
`connectionId` សំយោគសម្រាប់ការមិនផ្ទៀងផ្ទាត់អត្តសញ្ញាណ មិនមែនជាការតភ្ជាប់ពិតទេ។ ផ្លូវស្វ័យប្រវត្តិ `keyless` ដែលមានស្រាប់បច្ចុប្បន្នគឺ OpenCode Free; ចំនួនបេក្ខភាពពិតប្រាកដ
នៅតែអាស្រ័យលើការរកឃើញម៉ូដែលជាក់ស្តែង ហើយគួរត្រូវបានវាស់លើការដាក់ឱ្យប្រើប្រាស់គោលដៅ ជាជាង
ចម្លងពីការដំណើរការចាស់។ បេក្ខភាព `recurring-*` នឹងឆ្លងកាត់បានតែនៅពេលវាមានទាំង
អាដាប់ទ័រការប្រើប្រាស់ដែលបានចុះបញ្ជី និង `hardStopGuaranteed: true`; ទិន្នន័យមេតាមិនពេញលេញនៅតែត្រូវបានបិទដោយសុវត្ថិភាព។

ជាមួយ `excludeTosAvoid: true` បេក្ខភាពទាំងអស់ដែលបានរៀបចំកំណត់ជា `tos: "avoid"` ត្រូវបានដកចេញ។ បច្ចុប្បន្ន OpenCode Free
មានសេចក្តីសម្រេចនោះ ដូច្នេះការបើករបាំងការពារនេះអាចធ្វើឱ្យបណ្តុំ `keyless` ដែលនៅសល់ក្នុងការដាក់ឱ្យប្រើប្រាស់ក្លាយជាទទេ។
នេះគឺជាការដោះដូរដែលរំពឹងទុកពីការបើករបាំងការពារ ToS មិនមែនជាកំហុសទេ៖ របាំងការពារនេះមានលំនាំដើមជា `false`
ដោយសារហេតុផលនេះតែម្តង (សូមមើល "របាំងការពារ ToS" ខាងលើ)។

## ការបើកដំណើរការ

```json
PUT /api/settings
{ "freeAccessPolicy": "strict", "excludeTosAvoid": false }
```

ការកំណត់ថ្មីទាំងពីរមានតម្លៃលំនាំដើមជាតម្លៃមុនពេលបន្ថែមមុខងារនេះ (`"off"` / `false`) — ប្រសិនបើមិនបើកដំណើរការការកំណត់ណាមួយទេ វានឹងមិនផ្លាស់ប្តូរឥរិយាបថកំណត់ផ្លូវ `auto/*` ដែលមានស្រាប់ណាមួយឡើយ។
