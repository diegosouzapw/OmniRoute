លេខសម្គាល់និម្មិត `auto/*` ឬទេ?" — មុខងារទាំងពីរមិនអនុញ្ញាតឱ្យប្រតិបត្តិករជ្រើសរើសសំណុំរងតាមបំណងណាមួយនៃ
ម៉ូដែលបានទេ (ឧ. បង្ហាញតែម៉ូដែលដែលកម្មវិធីភ្ញៀវ Claude Code / OpenCode ជាក់លាក់មួយគួរមើលឃើញ

## ចំណុចត្រួតពិនិត្យពីរ មិនមែនមួយទេ

មេរៀនពី #6512 (តម្រងកាតាឡុកដែលប្រើតែ `hidePaidModels` នៅតែអនុញ្ញាតឱ្យ `auto/*` បញ្ជូនទៅ
ម៉ូដែលបង់ប្រាក់ ព្រោះបណ្តុំបេក្ខជននៃបន្សំត្រូវបានបង្កើតដោយឯករាជ្យ) អនុវត្តដូចគ្នាបេះបិទនៅទីនេះ។
លក្ខខណ្ឌផ្គូផ្គង `isModelExposureAllowed()` (`src/shared/utils/modelExposureList.ts`) ត្រូវបាន
ហៅពីទីតាំងទាំងពីរនេះ៖

- `src/app/api/v1/models/catalog.ts` — បញ្ជី `/v1/models` ផ្ទាល់ នៅចំណុចត្រួតពិនិត្យតាមប្រភពទាំង 5 ដូចគ្នា
  ដែល `shouldHidePaid()` គ្រប់គ្រងរួចហើយ (ម៉ូដែលឋិតិវន្ត `PROVIDER_MODELS`, ជួរទិន្នន័យអ្នកផ្តល់សេវាដែលបានធ្វើសមកាលកម្ម,
  ជួរទិន្នន័យផ្ទាល់ខ្លួន, ជួរទិន្នន័យដែលគាំទ្រដោយឈ្មោះក្លែងក្លាយ, ជួរទិន្នន័យបម្រុងដែលបានគ្រប់គ្រង)។
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — ត្រូវបានហៅ
  ពី `virtualFactory.ts::buildPreparedPool` ភ្លាមៗបន្ទាប់ពីការហៅ
  `filterPaidOnlyCandidates()` ដែលមានតួនាទីសមមូល ដូច្នេះម៉ូដែលដែលត្រូវបានហាមឃាត់ មិនអាចត្រូវបានជ្រើសចូលទៅក្នុងបណ្តុំបេក្ខជន
  `auto/*` ឡើយ។

## អ្វីដែលមិនត្រូវបានត្រង

ឆ្លុះបញ្ចាំងឥរិយាបថដែលមានស្រាប់របស់ `hideAutoCombos`៖ លេខសម្គាល់ម៉ូដែលដែលត្រូវបានផ្ញើ **ដោយជាក់លាក់** (មិនមែនតាមរយៈ `auto/*`
និងមិនមែនរកឃើញតាមរយៈបញ្ជីកាតាឡុក) មិនត្រូវបានរារាំងនៅពេលបញ្ជូនឡើយ — មានតែ
ការផ្សព្វផ្សាយ/សមាជិកភាពក្នុងបណ្តុំបេក្ខជនប៉ុណ្ណោះដែលត្រូវបានត្រង។ វាឯករាជ្យពី `hidePaidModels`;
ប្រតិបត្តិករអាចចង់បានសំណុំដែលបានជ្រើសរើសយ៉ាងជាក់លាក់ ដោយហេតុផលដែលមិនពាក់ព័ន្ធនឹងតម្លៃ ដូច្នេះ
ការកំណត់ទាំងពីរត្រូវបានផ្សំជាតម្រង AND ឯករាជ្យពីគ្នា ដូចគ្នានឹងការផ្សំពហុទង់ដែលមានស្រាប់នៅក្នុង
`catalog.ts`។

ការនាំចេញការកំណត់ (`GET /api/settings/export-json`) រួមបញ្ចូលអារេទាំងពីរដដែលៗ ដូចវាល
ការកំណត់ផ្សេងទៀតទាំងអស់ — មិនដូចតម្រងនាំចេញជំហានបន្សំរបស់ `hidePaidModels` ទេ នៅទីនេះមិនមានហានិភ័យនៃការបញ្ចូលឡើងវិញទេ៖
