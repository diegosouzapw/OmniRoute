ច្បាប់កំណត់ផ្លូវ reasoning ពង្រីកមុខងារកំណត់ផ្លូវ model និង combo ដែលមានស្រាប់។ នៅពេលគ្មានច្បាប់សកម្មណាមួយត្រូវគ្នា ឥរិយាបថដែលមានស្រាប់សម្រាប់ thinking, suffix, connection-default និង provider-translation នៅតែមិនផ្លាស់ប្តូរ។

## ការគ្រប់គ្រង

ការគ្រប់គ្រងច្បាប់អាចប្រើបាននៅក្រោម **Settings → Global Routing**។ កម្មវិធីកែសម្រួល API-key ផ្តល់ UI គ្រប់គ្រងដូចគ្នា ដែលបានចម្រាញ់សម្រាប់ key ដែលបានជ្រើសរើស។

Management API ត្រូវបានបង្ហាញតាមរយៈ route ទាំងនេះ៖

- `GET` និង `POST` នៅ `/api/settings/reasoning-routing-rules`
- `GET`, `PATCH` និង `DELETE` នៅ `/api/settings/reasoning-routing-rules/[id]`
- `POST` នៅ `/api/settings/reasoning-routing-rules/simulate`

route ទាំងអស់ប្រើ `requireManagementAuth`។ input ត្រូវបានផ្ទៀងផ្ទាត់ដោយ schema នៅក្នុង `src/shared/validation/schemas/reasoningRouting.ts`។ simulator មិនធ្វើ upstream call ឡើយ។

## ការដោះស្រាយច្បាប់

ការវាយតម្លៃដំបូងជ្រើសរើសច្បាប់តែមួយគត់។ scope ត្រូវបានពិនិត្យតាមលំដាប់នេះ៖

1. `apiKey`
2. `combo`
3. `model`
4. `global`

នៅក្នុង scope មួយ `priority` ខ្ពស់ជាងនឹងឈ្នះមុន បន្ទាប់មកការផ្គូផ្គង model ជាក់លាក់នឹងឈ្នះ glob pattern ហើយបន្ទាប់មកតម្រៀបតាម `createdAt` និង `id` ដែលមានស្ថិរភាព។ `requestTags` ត្រូវបានអានតែពី `metadata.tags` ប៉ុណ្ណោះ ហើយគាំទ្រការផ្គូផ្គង `any` ឬ `all`។

ច្បាប់ `connection` ត្រូវបានវាយតម្លៃតែនៅពេលគ្មានច្បាប់ដំបូងណាមួយឈ្នះ ហើយ provider connection ជាក់លាក់មួយត្រូវបានជ្រើសរើសរួចហើយ។ វាអាចផ្លាស់ប្តូរបានតែ effort និង budget ប៉ុណ្ណោះ។

## Effort និង Budget

`sourceEffort` ទទួលយក `any`, `missing`, `none`, `low`, `medium`, `high`, `xhigh`, `max` និង `ultra`។ `missing` មានន័យថា request មិនមានទាំង discrete effort, thinking toggle ឬ thinking budget។ ដូច្នេះ សញ្ញា budget-only ត្រូវបានផ្គូផ្គងតែដោយ `any` ប៉ុណ្ណោះ។

`effortMode` មានបីប្រភេទ៖

- `inherit` រក្សា effort របស់ client ខណៈដែលនៅតែអនុញ្ញាតឱ្យ model ឬ combo ផ្លាស់ប្តូរ។
- `default` កំណត់ `targetEffort` តែនៅពេលគ្មានសញ្ញា reasoning ជាក់លាក់។
- `force` ជំនួស discrete effort ដោយ `targetEffort`។

ដោយឯករាជ្យ `budgetAction` អាចជា `preserve`, `remove` ឬ `set`។ `force` ជាមួយ `none` លុប field effort និង budget ដែលស្គាល់ទាំងអស់។ `none` រួមជាមួយ `set` គឺមិនត្រឹមត្រូវ។

request ដែលកំណត់គោលដៅទៅ model ដែលដឹងថាមិនឆបគ្នា ត្រូវបានបដិសេធមុន upstream call។ សម្រាប់គោលដៅ combo ធាតុដែលមិនឆបគ្នាត្រូវបានដកចេញ។ ប្រសិនបើគ្មានធាតុណាមួយនៅសល់ request នឹងត្រឡប់ status `400`។ ទិន្នន័យ capability ដែលមិនស្គាល់បង្កើតការព្រមាន ហើយទុកឱ្យច្បាប់នៅតែសកម្ម។

## សុវត្ថិភាព និងការដឹកជញ្ជូន

model ប្រភព និងគោលដៅ ឬ combo ប្រភព និងគោលដៅ នៅតែស្ថិតក្រោមគោលការណ៍ API-key ដែលមានស្រាប់។ ច្បាប់ reasoning មិនដែលពង្រីកសិទ្ធិ model, combo ឬ quota ទេ។

engine ត្រូវបានរួមបញ្ចូលទៅក្នុង Chat Completions, Responses, Anthropic Messages និង path ខាងក្នុងរបស់ Codex WebSocket។ path របស់ WebSocket ទទួលយកតែ Codex target models ប៉ុណ្ណោះ។ combo targets មិនអាចត្រូវបានប្រតិបត្តិនៅទីនោះទេ។ ការសម្រេចចិត្តរបស់ច្បាប់ត្រូវបានរក្សាទុកនៅក្នុង route trace ដែលមានស្រាប់ ដោយគ្មាន secret។
