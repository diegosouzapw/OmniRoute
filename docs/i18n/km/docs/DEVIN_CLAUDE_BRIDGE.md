## Isolation និង threat model

ការដំឡើង គណនី និងការកំណត់រចនាសម្ព័ន្ធ Claude របស់ host គឺនៅក្រៅវិសាលភាព ហើយត្រូវបានចាត់ទុកថា
ត្រូវបានហាមឃាត់។ Service របស់ Compose៖

- ដំណើរការជា UID/GID `10001:10001` ជាមួយ root filesystem ដែលបានកំណត់ឱ្យ read-only, capability ដែលត្រូវបានដកចេញ និង
  `no-new-privileges`;
- ប្រើ `/home/bridge` ឯកជន, volume configuration របស់ Claude ដែលបានឧទ្ទិស, ទិន្នន័យ OmniRoute ដាច់ដោយឡែក
  និង volume `devin-auth` ដាច់ដោយឡែក;
- mount តែ workspace/evidence `.sandbox` ដែលអាចបោះបង់ចោលបាន;
- មិន mount home របស់ host, Keychain, SSH, credential របស់ cloud ឬ Docker socket ទេ;
- បង្កើត environment ជាក់លាក់ និងលុប variable API/OAuth/routing របស់ Anthropic;
- ដឹកនាំ inference របស់ Claude Code ទៅតែ `http://omniroute:20128` ដោយប្រើ key សម្រាប់តែមូលដ្ឋាន។

profile offline ប្រើ network ខាងក្នុង។ នៅក្នុង profile live, OmniRoute ចូលទៅដល់
endpoint Devin ផ្លូវការតាមរយៈ `network-guard` តែប៉ុណ្ណោះ; destination ដែលមិនពាក់ព័ន្ធត្រូវបានបដិសេធ។
Claude Code មាន egress guard បដិសេធទាំងអស់ដោយឡែក ហើយអាចចូលទៅដល់តែ service OmniRoute មូលដ្ឋាន
តាមរយៈ `NO_PROXY`។ File audit របស់ guard ត្រូវបាន mount ដោយ process guard របស់ពួកវាតែប៉ុណ្ណោះ។
script ផ្ទៀងផ្ទាត់ ownership, mode, ចំនួន link និងការសម្រេចចិត្តនីមួយៗរបស់ file មុនពេល export
evidence ដែលគ្មាន token។

ដំណើរការភស្តុតាង isolation ដោយឯករាជ្យ៖

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

វាផ្ទៀងផ្ទាត់ topology, named mount, ការកំណត់ non-root/read-only, routing មូលដ្ឋានយ៉ាងជាក់លាក់,
អវត្តមាននៃ environment variable ដែលមានលក្ខណៈរសើប, អវត្តមាននៃ Docker socket, ការចូលទៅ
`api.anthropic.com` និង `claude.ai` ដែលត្រូវបានទប់ស្កាត់, ការជ្រើសរើស provider សម្រាប់តែ Devin និងការបរាជ័យយ៉ាងច្បាស់លាស់នៅពេល
ACP backend មិនអាចប្រើបាន។

## ការដំឡើងលើកដំបូង និងការប្រើប្រាស់ធម្មតា

```bash
./scripts/devin-bridge/build
```

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

ពាក្យបញ្ជាចូលប្រើប្រាស់នេះ ប្រើលំហូរ token ដោយដៃផ្លូវការ ដែលមានបំណងសម្រាប់បរិស្ថានពីចម្ងាយ/container។ តម្លៃត្រូវបានបញ្ចូលដោយផ្ទាល់ទៅក្នុង CLI prompt; វាមិនត្រូវបានផ្ដល់ជា argument របស់ process សរសេរទៅក្នុង Git ឬចម្លងពី host ឡើយ។

ដំណើរការ runtime Claude Code ដែលដាច់ដោយឡែក៖

```bash
./scripts/devin-bridge/launch
```

`launch` ពិនិត្យឡើងវិញនូវភាពដាច់ដោយឡែក ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ Devin និងការរកឃើញ model មុនពេលចាប់ផ្ដើម Claude Code ដែលដំណើរការក្នុង container។ វាមិនដែលដំណើរការ executable Claude របស់ host ឡើយ។ អាចកំណត់ឈ្មោះក្លែងក្លាយរបស់ model នៅក្នុង `.env.devin-bridge`; រាល់តម្លៃដែលបានកំណត់ ត្រូវតែរក្សាបុព្វបទ `devin-cli-agentic/`។

## ពាក្យបញ្ជាសម្រាប់ការផ្ទៀងផ្ទាត់

ដំណើរការ offline ដែលអាចធ្វើឡើងវិញបាន មិនត្រូវការគណនី Devin និងមិនមានការចូលប្រើអ៊ីនធឺណិតនៅពេល runtime៖

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
./scripts/devin-bridge/verify-anthropic-isolation
```

ដំណើរការ live ដែលតម្រូវឱ្យមានការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ និងការជ្រើសរើសចូលរួម គឺ៖

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/test-live-devin
```

កម្មវិធីដំណើរការ live រង់ចាំនៅចន្លោះ scenario នីមួយៗ ដើម្បីជៀសវាងការបើក ACP session ជាបន្តបន្ទាប់យ៉ាងលឿន ហើយផ្ទៀងផ្ទាត់ event ដែលមានរចនាសម្ព័ន្ធពី stream របស់ Claude ជំនួសឱ្យការជឿលើការអះអាងជាអត្ថបទ។ scenario ទាំងបីរបស់វាបញ្ជាក់ថា៖

1. ការអាន project ដោយផ្ទាល់ និងការវិភាគ defect;
2. `Edit` ពិតប្រាកដមួយ `Bash` `npm test` ដែលគ្រប់គ្រងដោយ client និងលទ្ធផលចុងក្រោយមួយ;
3. `/bridge-check` រួមជាមួយការរកឃើញ `bridge-proof` ការអាន project ការ `npm test` ដែលគ្រប់គ្រងដោយ client និងជោគជ័យមួយទៀត ព្រមទាំងការបញ្ចប់ដោយគ្មានការងារដែលកំពុងរង់ចាំ។

ច្រកត្រួតពិនិត្យចុងក្រោយក៏ពិនិត្យ network audit របស់ Devin ផងដែរ ហើយតម្រូវឱ្យ egress audit របស់ Claude នៅតែទទេ។

## ការធ្វើបច្ចុប្បន្នភាពឧបករណ៍ដែលបានកំណត់កំណែជាក់លាក់

Image កំណត់កំណែជាក់លាក់របស់ Node, Claude Code និង Devin CLI នៅក្នុង `docker/devin-bridge/Dockerfile`។ ដើម្បីធ្វើបច្ចុប្បន្នភាព៖

1. ផ្លាស់ប្ដូរកំណែដែលបានបញ្ជាក់ជាក់លាក់;
2. ជំនួស checksum ទាំងពីររបស់ archive Devin សម្រាប់ architecture នីមួយៗ ដោយតម្លៃសម្រាប់ artifact ផ្លូវការ;
3. បង្កើតឡើងវិញ និងដំណើរការរាល់ពាក្យបញ្ជាផ្ទៀងផ្ទាត់ offline;
4. បញ្ជាក់កំណែនៅខាងក្នុង image;
5. ដំណើរការ live suite ដែលមានបី scenario និងបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណឡើងវិញ។

កុំដំឡើង CLI ណាមួយក្នុងចំណោម CLI ទាំងពីរជា global នៅលើ host ឬជំនួសការផ្ទៀងផ្ទាត់ checksum ដោយការទាញយកដែលមិនបានផ្ទៀងផ្ទាត់។

## ការវិនិច្ឆ័យបញ្ហា និងការសម្អាត

- `docker compose -f docker/devin-bridge/compose.yml --profile offline logs omniroute`
  បង្ហាញ routing មូលដ្ឋាន និងកំហុស executor ដែលបានសម្អាតទិន្នន័យរសើប។
- `.sandbox/evidence/mock-acp.jsonl` កត់ត្រាសកម្មភាព mock ACP ដែលអាចកំណត់លទ្ធផលដដែលៗបាន។
