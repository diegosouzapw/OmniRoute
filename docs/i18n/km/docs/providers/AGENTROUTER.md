[AgentRouter](https://agentrouter.org) គឺជា relay ដែលត្រូវគ្នាជាមួយ Anthropic និងលក់បន្ត
Claude ព្រមទាំងម៉ូដែលផ្សេងៗទៀត ដែលជាញឹកញាប់មានតម្លៃទាបជាង Anthropic API ផ្ទាល់។ វាត្រូវបាន
រចនាឡើងឱ្យអាចប្រើជំនួស `ANTHROPIC_BASE_URL` សម្រាប់កម្មវិធី Claude Code
ផ្លូវការបានភ្លាមៗ ដូច្នេះវាទទួលយកតែចរាចរណ៍ដែលត្រូវគ្នានឹងទម្រង់ទិន្នន័យលើបណ្តាញរបស់ Claude Code ប៉ុណ្ណោះ (User-Agent ជាក់លាក់ ទង់ `anthropic-beta` បឋមកថា Stainless SDK ជាដើម)។

## ចាប់ផ្តើមរហ័ស — ប្រើអ្នកផ្តល់សេវា `agentrouter` ដើម (បានណែនាំ)

សម្រាប់អ្នកប្រើភាគច្រើន **មិនត្រូវការការដំឡើងពិសេសទេ**។ OmniRoute ភ្ជាប់មកជាមួយ
អ្នកផ្តល់សេវា `agentrouter` ដែលមានស្រាប់ និងបានរួមបញ្ចូលទម្រង់ទិន្នន័យលើបណ្តាញពេញលេញរបស់ Claude Code រួចហើយ (សូមមើល
`open-sse/config/providerRegistry.ts` → `agentrouter`)។ ដើម្បីប្រើវា៖

1. បើក **ផ្ទាំងគ្រប់គ្រង → អ្នកផ្តល់សេវា → បន្ថែមអ្នកផ្តល់សេវា**។
2. ជ្រើសរើស **AgentRouter** ពីបញ្ជី។
3. បិទភ្ជាប់ API key `sk-...` របស់អ្នក ហើយរក្សាទុក។

ប៉ុណ្ណឹងជាការស្រេច — មិនត្រូវការអថេរបរិស្ថាន និងមិនត្រូវការប្រភេទអ្នកផ្តល់សេវាផ្ទាល់ខ្លួនទេ។ ម៉ូដែលដែលមានស្រាប់
រួមមាន `claude-opus-4-6`, `claude-haiku-4-5-20251001`, `glm-5.1` និង
`deepseek-v3.2`។

ផ្នែកដែលនៅសល់នៃមគ្គុទ្ទេសក៍នេះគ្របដណ្តប់លើ **វិធីកម្រិតខ្ពស់**៖ ការប្រើប្រភេទអ្នកផ្តល់សេវា
`anthropic-compatible-cc-*`។ ប្រើវានៅពេលអ្នកត្រូវការការគ្រប់គ្រងបន្ថែម
លើទម្រង់ទិន្នន័យលើបណ្តាញ — ឧទាហរណ៍ នៅពេលភ្ជាប់ទៅ relay ដែលមានលក្ខណៈដូច AgentRouter ផ្សេងទៀត
ដែលមិនទាន់មាននៅក្នុងបញ្ជីអ្នកផ្តល់សេវាដើម ឬនៅពេលកំណត់ជំនួស
URL មូលដ្ឋាន ផ្លូវជជែក ឬសំណុំបឋមកថា។

## តម្រូវការជាមុន

- គណនី AgentRouter និង API key។ អ្នកចុះឈ្មោះថ្មីទទួលបានឥណទានឥតគិតថ្លៃតាមរយៈតំណសម្ព័ន្ធ
  នៅក្នុង [README](../README.md) របស់គម្រោង។
- OmniRoute កំពុងដំណើរការដោយបានបើកទង់មុខងារ `ENABLE_CC_COMPATIBLE_PROVIDER`
  (សូមមើលខាងក្រោម)។

## 1. បើកប្រភេទអ្នកផ្តល់សេវាដែលត្រូវគ្នាជាមួយ CC

ប្រភេទអ្នកផ្តល់សេវាដែលត្រូវគ្នាជាមួយ Claude Code ត្រូវបានគ្រប់គ្រងដោយទង់មុខងារ ពីព្រោះវា
ផ្ញើចរាចរណ៍ដែលត្រាប់តាមកម្មវិធី Claude Code ផ្លូវការយ៉ាងជិតស្និទ្ធ។ បើកវាដោយ
កំណត់អថេរបរិស្ថានមុនពេលចាប់ផ្តើម OmniRoute៖

```bash
ENABLE_CC_COMPATIBLE_PROVIDER=true
```

ឧទាហរណ៍ Docker៖

```bash
docker run -d --name omniroute \
  --restart unless-stopped \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  -e ENABLE_CC_COMPATIBLE_PROVIDER=true \
  diegosouzapw/omniroute:latest
```

បន្ទាប់ពីចាប់ផ្តើមឡើងវិញ ផ្ទាំងគ្រប់គ្រងនឹងបង្ហាញជម្រើស **បន្ថែមអ្នកផ្តល់សេវាដែលត្រូវគ្នាជាមួយ Claude Code**
បន្ថែមពីលើដំណើរការដែលត្រូវគ្នាជាមួយ OpenAI និង Anthropic ដែលមានស្រាប់។

## 2. បង្កើតអ្នកផ្តល់សេវានៅក្នុងផ្ទាំងគ្រប់គ្រង

1. បើក **ផ្ទាំងគ្រប់គ្រង → អ្នកផ្តល់សេវា → បន្ថែមអ្នកផ្តល់សេវា**។
2. ជ្រើសរើស **បន្ថែមអ្នកផ្តល់សេវាដែលត្រូវគ្នាជាមួយ Claude Code** (អាចមើលឃើញតែនៅពេលទង់ខាងលើត្រូវបានកំណត់)។
3. បំពេញវាលទាំងនេះ៖

| វាល          | តម្លៃ                                                                         |
| ------------ | ----------------------------------------------------------------------------- |
| ឈ្មោះ        | `AgentRouter` (ឬស្លាកណាមួយ)                                                   |
| បុព្វបទ      | `agentrouter` (ឈ្មោះហៅក្រៅងាយស្រួលដែលបង្ហាញក្នុងកំណត់ហេតុ និងផ្ទាំងគ្រប់គ្រង) |
| URL មូលដ្ឋាន | `https://agentrouter.org`                                                     |
| ផ្លូវជជែក    | `/v1/messages?beta=true` (លំនាំដើម — ទុកឱ្យនៅដដែល)                            |

> អត្តសញ្ញាណម៉ូដែលស្តង់ដារនៅតែប្រើលេខសម្គាល់ node ពេញលេញរបស់អ្នកផ្តល់សេវា
> (`anthropic-compatible-cc-{uuid}/{model}`)។ **បុព្វបទ** គ្រាន់តែជាឈ្មោះហៅក្រៅសម្រាប់ការបង្ហាញ
> ដែលត្រូវបានដោះស្រាយដោយ `src/lib/usage/callLogs.ts` ដើម្បីឱ្យលទ្ធផលកំណត់ហេតុងាយអានជាងមុន។

4. (ជាជម្រើស) បិទភ្ជាប់ API key របស់អ្នកនៅក្នុងវាល **ផ្ទៀងផ្ទាត់** ហើយចុច **ពិនិត្យ** ដើម្បី
   បញ្ជាក់ការតភ្ជាប់មុនពេលរក្សាទុក។
5. ចុច **បន្ថែម**។

បន្ទាប់ពីបង្កើតរួច សូមបើកអ្នកផ្តល់សេវា ហើយបន្ថែម **ការតភ្ជាប់** ដោយប្រើ API
key (`sk-...`) របស់ AgentRouter។ `test_status` របស់ការតភ្ជាប់គួរតែប្តូរទៅជា `active`។

## 3. ប្រើវាតាមរយៈ combo ឬដោយផ្ទាល់

យោងទៅកាន់ម៉ូដែលដោយប្រើបុព្វបទរបស់អ្នកផ្តល់សេវារបស់អ្នកជា namespace៖

```bash
curl -X POST http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "agentrouter/claude-opus-4-6",
    "messages": [{"role": "user", "content": "hello"}],
    "max_tokens": 100
  }'
```

លេខសម្គាល់ម៉ូដែលស្តង់ដារ `anthropic-compatible-cc-{uuid}/claude-opus-4-6` ក៏ដំណើរការផងដែរ
ហើយវាជាលេខសម្គាល់ដែលបង្ហាញនៅក្នុងមូលដ្ឋានទិន្នន័យ និងការកំណត់រចនាសម្ព័ន្ធ combo។

ឬបន្ថែមវាទៅក្នុង combo ដើម្បីគ្រប់គ្រងការបញ្ជូនសំណើ ផ្លូវបម្រុង និងកូតា ដូចអ្នកផ្តល់សេវា
ផ្សេងទៀតដែរ។

## ការដោះស្រាយបញ្ហា

**`{"error":{"message":"unauthorized client detected, ..."}}`** — សំណើរបស់អ្នកមិនត្រូវគ្នា
នឹង wire image របស់ Claude Code ទេ។ បញ្ហានេះកើតឡើងនៅពេលអ្នកផ្តល់សេវាត្រូវបានកំណត់រចនាសម្ព័ន្ធ
ជា `openai-compatible-chat` ជំនួសឱ្យ `anthropic-compatible-cc` ឬនៅពេល flag
`ENABLE_CC_COMPATIBLE_PROVIDER=true` មិនត្រូវបានកំណត់នៅពេលចាប់ផ្ដើម។

**`{"error":{"message":"无效的令牌","type":"new_api_error"}}` (HTTP 401)** —
"Token មិនត្រឹមត្រូវ"។ wire image ត្រឹមត្រូវ ប៉ុន្តែ API key ត្រូវបានបដិសេធ។ បង្កើត
key ថ្មីនៅក្នុង dashboard របស់ AgentRouter ហើយធ្វើបច្ចុប្បន្នភាពការតភ្ជាប់។

**`{"error":{"code":"content-blocked","type":"agent_router_api_error"}}`
(HTTP 400)** — moderation hook របស់ AgentRouter បានបដិសេធខ្លឹមសារសំណើ ឬគម្រោងរបស់
key មិនអនុញ្ញាតឱ្យប្រើម៉ូដែលដែលបានស្នើ។ សាកល្បង prompt ឬម៉ូដែលផ្សេងទៀត;
ទាក់ទងផ្នែកជំនួយ AgentRouter ប្រសិនបើ prompt ដែលគ្មានគ្រោះថ្នាក់ត្រូវបានរារាំងជាបន្តបន្ទាប់។

**`[400]: content-blocked` តែលើម៉ូដែលជាក់លាក់** — គម្រោង AgentRouter ភាគច្រើនអនុញ្ញាត
តែម៉ូដែលមួយចំនួនប៉ុណ្ណោះ (ឧ. `claude-opus-4-6`)។ លេខសម្គាល់ម៉ូដែលផ្សេងទៀតបញ្ជូនត្រឡប់
`unauthorized_client_error` ទោះបីជា key មានសុពលភាពក៏ដោយ។ ពិនិត្យមើលថាតើគម្រោងរបស់អ្នក
គ្របដណ្ដប់ម៉ូដែលណាខ្លះនៅក្នុង dashboard របស់ AgentRouter។

**`Invalid JSON response from provider (reset after Ns)` ពីកំណត់ហេតុ omniroute** —
upstream បានបញ្ជូនត្រឡប់ body ដែលមិនមែនជា JSON (ជាទូទៅគឺទំព័រកំហុស HTML ពី WAF)។
ជាធម្មតា នេះមានន័យថាសំណើមិនដែលបានទៅដល់ backend របស់ AgentRouter ទេ — សូមពិនិត្យឡើងវិញថា
លេខសម្គាល់អ្នកផ្តល់សេវាចាប់ផ្ដើមដោយ `anthropic-compatible-cc-` (ចំណាំសញ្ញាដកនៅខាងចុង —
សូមមើល `CLAUDE_CODE_COMPATIBLE_PREFIX` នៅក្នុង `open-sse/services/claudeCodeCompatible.ts`)
ហើយ feature flag ត្រូវបានបើក។

**`unauthorized client detected` / ទំព័រកំហុស HTML ទោះបីជាមានអ្នកផ្តល់សេវា AgentRouter
រួចហើយក៏ដោយ** — អ្នកទំនងជាមានអ្នកផ្តល់សេវា AgentRouter **ច្រើនជាងមួយ**
ហើយសំណើរបស់អ្នកកំពុងទៅដល់អ្នកផ្តល់សេវាខុស។ ប្រសិនបើអ្នកផ្តល់សេវា
`anthropic-compatible-*` (មិនមែន `cc`) ឬ `openai-compatible-chat-*` ដែលបានបង្កើតដោយដៃ
និងនៅសល់ ត្រូវបានបង្កើតដោយប្រើបុព្វបទ `agentrouter` វាអាចកាន់កាប់លេខសម្គាល់ម៉ូដែល
`agentrouter/<model>` (ហើយ combo អាចយោងទៅវាតាម node ID) ដូច្នេះ traffic នឹងត្រូវបានបញ្ជូនទៅអ្នកផ្តល់សេវានោះ —
ដែលផ្ញើ User-Agent ទូទៅ ហើយត្រូវបានបដិសេធ — ជំនួសឱ្យអ្នកផ្តល់សេវា
`agentrouter` ដែលមានស្រាប់ និងភ្ជាប់មកជាមួយ wire image ត្រឹមត្រូវ។ ពិនិត្យមើលថាម៉ូដែល
ត្រូវបាន resolve ទៅកាន់ទីណាពិតប្រាកដនៅក្នុងកំណត់ហេតុ omniroute (tag `ROUTING` បង្ហាញ
`agentrouter/<model> → <providerId>/<model>`); ប្រសិនបើ `<providerId>` មិនមែនជា
`agentrouter` សូមបង្រួបបង្រួមទៅប្រើអ្នកផ្តល់សេវាដើម៖ កំណត់ combo ឱ្យចង្អុលទៅ
`agentrouter/<model>` (providerId `agentrouter`) ហើយលុបអ្នកផ្តល់សេវា compatible ដែលស្ទួន។
អ្នកផ្តល់សេវាដើមមិនត្រូវការការកំណត់រចនាសម្ព័ន្ធ wire image និងមិនត្រូវការ
