## តម្រូវការជាមុន

- Cookie header ពេញលេញពីសម័យ ChatGPT ដែលបានចូលគណនី;
- Chrome ឬ Chromium រួមជាមួយសម័យក្រាហ្វិក ឬអេក្រង់ Xvfb សម្រាប់ការដំឡើង npm, systemd និង PM2;
- ជាមួយប្រូហ្វាល់ Docker `web` ប្រើសេវា Chromium ខាងក្នុងពី
  `docker-compose.yml`;
- OpenAI `tunnel-client` v0.0.13 និងឧបករណ៍ភ្ជាប់ផ្ទាល់ខ្លួនរបស់ ChatGPT សម្រាប់ឧបករណ៍ Codex មូលដ្ឋាន។

tunnel ត្រូវការសម្រាប់តែវេនឧបករណ៍ប៉ុណ្ណោះ។ ផ្លូវទាំងអស់ដែលបានរាយ រួមទាំង `pro` អាចប្រើ
សមត្ថភាពឧបករណ៍មូលដ្ឋានដែលចងភ្ជាប់នឹងវេនដូចគ្នា នៅពេល tunnel និងឧបករណ៍ភ្ជាប់ត្រូវបានកំណត់រចនាសម្ព័ន្ធ។

- Workspace, sandbox, គោលការណ៍អនុម័ត និងកាតាឡុកឧបករណ៍ គឺមកពីសែល Codex ដើមកំណើត។ អត្ថបទ prompt ដែលសរសេរដោយសេរីមិនមានសិទ្ធិអំណាចលើធាតុទាំងនេះទេ។
- ChatGPT ទទួលបានតែសមត្ថភាពដែលមានអាយុកាលខ្លីសម្រាប់ turn នីមួយៗប៉ុណ្ណោះ។ MCP broker ទទួលយកតែឧបករណ៍ដែល Codex បានផ្តល់ជូនក្នុង turn ជាក់លាក់នោះ។
- ការបញ្ជាក់ **Allow once** ដោយស្វ័យប្រវត្តិ គ្រាន់តែបញ្ជូនសំណើឧបករណ៍ត្រឡប់ទៅ Codex ប៉ុណ្ណោះ។ មានតែ Codex ទេដែលសម្រេចអំពីការអនុម័ត និងការប្រតិបត្តិ។
- មុនលទ្ធផលដំបូង combo មួយអាចប្តូរទៅគោលដៅដែលត្រូវគ្នាមួយផ្សេងទៀត។ បន្ទាប់ពីការបញ្ចេញលទ្ធផលចាប់ផ្តើម provider, model, connection និង browser turn នឹងត្រូវបានភ្ជាប់ថេររហូតដល់ turn បញ្ចប់។
- Cookies, runtime keys, storage state និង capability tokens មិនបង្ហាញក្នុងការឆ្លើយតបរបស់ provider ឬកំណត់ហេតុសំណើទេ។

## VPS ដែលគ្មានអេក្រង់ និង Docker

សម្រាប់ការដំឡើងតាម npm, systemd និង PM2, OmniRoute រកឃើញផ្លូវ Chrome និង Chromium ដែលប្រើជាទូទៅ។ ជាជម្រើស អ្នកអាចកំណត់ `CHATGPT_WEB_CODEX_CHROME_PATH`។ Runtime turns ប្រើ Chrome ដែលមានចំណុចប្រទាក់ដោយចេតនា ពីព្រោះ ChatGPT បដិសេធទម្រង់ browser បែប headless ពិតប្រាកដ។ ដូច្នេះ host ដែលគ្មានអេក្រង់ត្រូវតែដំណើរការ OmniRoute ជាមួយអេក្រង់ Xvfb ឯកជន។ ការកំណត់ផ្លូវ Chrome តែមួយមុខមិនបង្កើតអេក្រង់ឱ្យទេ។

Profile `web` របស់ Docker ចាប់ផ្តើម `chatgpt-web-codex-browser` នៅលើបណ្តាញ Compose ខាងក្នុង។ Sidecar ដំណើរការ Chrome ដែលមានចំណុចប្រទាក់នៅក្នុង Xvfb ដូច្នេះមិនត្រូវការអេក្រង់ជាក់ស្តែងទេ។ Port CDP របស់វាមិនត្រូវបានផ្សព្វផ្សាយនៅលើ host ទេ។ Volume របស់ browser profile ដែលបានការពារត្រូវបានបំបែកពី volume ទិន្នន័យរបស់ OmniRoute ហើយ browser ទទួលបាន shared memory គ្រប់គ្រាន់។ CDP proxy ខាងក្នុងស្តាប់តែនៅលើ port `9223` ក្នុងបណ្តាញ Compose ប៉ុណ្ណោះ។ Chrome នៅតែត្រូវបាន bind ទៅ loopback ក្នុង sidecar។

Supervisor lease មួយនៅក្រោម `DATA_DIR` រារាំងដំណើរការ OmniRoute ច្រើនពីការកាន់កាប់ tunnel និង broker state ដូចគ្នា។ ភាពប៉ះទង្គិចត្រូវបានរាយការណ៍ដោយ doctor។

## ការស្ដារឡើងវិញបែបអន្តរកម្ម

ដំណើរការ Docker ស្វ័យប្រវត្តិមិនមានផ្ទាំងដែលអាចមើលឃើញពី host ទេ ប៉ុន្តែ Chrome ខ្លួនវាមានចំណុចប្រទាក់នៅក្នុងអេក្រង់ Xvfb ឯកជន។ នៅពេល ChatGPT តម្រូវឱ្យចូលគណនី ឬដោះស្រាយ challenge បែបអន្តរកម្ម ហេដ្ឋារចនាសម្ព័ន្ធ browser VNC ដែលមានស្រាប់អាចត្រូវបានប្រើសម្រាប់ការស្ដារឡើងវិញ។ Browser UI និង CDP ត្រូវតែអាចចូលប្រើបានតែតាម loopback, ការតភ្ជាប់គ្រប់គ្រងដែលបានផ្ទៀងផ្ទាត់ ឬ SSH tunnel ប៉ុណ្ណោះ។ noVNC ត្រូវបន្តបិទក្នុងអំឡុងប្រតិបត្តិការធម្មតា។
