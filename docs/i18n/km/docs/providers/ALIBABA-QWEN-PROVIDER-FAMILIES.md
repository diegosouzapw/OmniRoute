ឯកសារនេះកត់ត្រាសេចក្តីសម្រេចនៃការអនុវត្តសម្រាប់
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854)។ ផលិតផលសាធារណៈត្រូវបាន
តំណាងជាក្រុមគ្រួសារអ្នកផ្តល់សេវាចំនួនបួន។ តំបន់គឺជាទិន្នន័យនៃការតភ្ជាប់ មិនមែនជាផលិតផលដាច់ដោយឡែកទេ។

## សេចក្តីសម្រេច

| ក្រុមគ្រួសារអ្នកផ្តល់សេវា                        | OmniRoute ID            | តំបន់សកល  | តំបន់ចិន |
| ------------------------------------------------ | ----------------------- | --------- | -------- |
| Alibaba Cloud Model Studio (បង់តាមការប្រើប្រាស់) | `alibaba`               | សិង្ហបុរី | ប៉េកាំង  |
| Alibaba Cloud Token Plan                         | `bailian-coding-plan`   | សិង្ហបុរី | ប៉េកាំង  |
| Qwen Cloud (បង់តាមការប្រើប្រាស់)                 | `qwen-cloud`            | សកល       | ប៉េកាំង  |
| Qwen Cloud Token Plan                            | `qwen-cloud-token-plan` | សិង្ហបុរី | ប៉េកាំង  |

ID `alibaba-cn` ដែលមានស្រាប់ នៅតែជាឈ្មោះជំនួសសម្រាប់ភាពឆបគ្នាពេលដំណើរការ សម្រាប់ការតភ្ជាប់ដែលបានរក្សាទុក ផ្លូវបញ្ជូន
ម៉ូដែល ការរួមបញ្ចូល និងទិន្នន័យប្រើប្រាស់ពីមុន។ កាតផ្ទាំងគ្រប់គ្រងរបស់វាត្រូវបានបញ្ចូលទៅក្នុង `alibaba`; មិនតម្រូវឱ្យ
សរសេរមូលដ្ឋានទិន្នន័យឡើងវិញទេ។

បច្ចុប្បន្ន Qwen Cloud ដែលបង់តាមការប្រើប្រាស់ និង Alibaba Cloud Model Studio ប្រើម៉ាស៊ីនមេពេលដំណើរការដែលឆបគ្នាជាមួយ DashScope
រួមគ្នា ប៉ុន្តែពួកវានៅតែមានអត្តសញ្ញាណអ្នកផ្តល់សេវាដាច់ដោយឡែកពីគ្នា ព្រោះអ្នកប្រើប្រាស់ទទួលបានសោ និងគ្រប់គ្រង
គណនីតាមរយៈផ្ទៃផលិតផលផ្សេងៗគ្នា។ ផលិតផល Alibaba និង Qwen Cloud Token Plan ប្រើ
ក្រុមគ្រួសារ endpoint ផ្សេងគ្នា ដូច្នេះផលិតផលទាំងបួននៅតែមាន ID អ្នកផ្តល់សេវាដាច់ដោយឡែកពីគ្នា។

## កិច្ចសន្យានៃការតភ្ជាប់

ការតភ្ជាប់ថ្មីរក្សាទុកសោតំបន់ដែលមានស្ថិរភាពក្នុង `providerSpecificData`៖

```json
{
  "region": "global-sg"
}
```

តម្លៃដែលអនុញ្ញាតគឺ `global-sg` និង `china-beijing`។ endpoint ត្រូវបានទាញយកជាកណ្តាលដោយផ្អែកលើ
ID អ្នកផ្តល់សេវា និងតំបន់។ `providerSpecificData.baseUrl` ដែលមិនមែនជាតម្លៃកំណត់ជាមុន នៅតែជាការកំណត់ជំនួសយ៉ាងច្បាស់ដោយប្រតិបត្តិករ
និងមានអាទិភាព ខណៈ URL កំណត់ជាមុនចាស់ៗដែលបានរក្សាទុក ត្រូវបានធ្វើឱ្យស្របតាមម៉ាទ្រីស
តំបន់វិញ។

វិធីនេះរក្សាឱ្យស្គីមាការតភ្ជាប់អាចពង្រីកបាន៖ តំបន់មួយទៀតអាចត្រូវបានបន្ថែមទៅកម្មវិធីដោះស្រាយ ដោយមិនចាំបាច់
បង្កើតកាតអ្នកផ្តល់សេវាមួយទៀត ឬផ្លាស់ប្តូរ ID អ្នកផ្តល់សេវាដែលបានរក្សាទុក។

## ភាពត្រូវគ្នា និងការដាក់ឱ្យប្រើប្រាស់

1. បន្ថែមកម្មវិធីកំណត់ endpoint តាមតំបន់ និងរក្សាតម្លៃលំនាំដើម global បច្ចុប្បន្ន។
2. ប្រើការស្វែងរក DashScope `/models` តាមតំបន់ដោយផ្ទាល់សម្រាប់ `alibaba`, ID ភាពត្រូវគ្នា `alibaba-cn` របស់វា និង `qwen-cloud`។ ការឆ្លើយតបរបស់ពួកវាត្រូវឆ្លងកាត់តម្រង text-generation មួយជាមុនសិន ពីព្រោះ endpoint ទូទៅក៏ត្រឡប់ម៉ូដែលរូបភាព វីដេអូ អូឌីយ៉ូ embedding និងម៉ូដែលផ្សេងទៀតដែលមិនមែនជា chat ផងដែរ។ បន្ទាប់មក `qwen-cloud`
   អនុវត្ត allowlist ដែលត្រូវបានថែទាំ និងប្រកាសក្នុង provider registry របស់វា។ Alibaba Model Studio
   និង Qwen Cloud រក្សាកាតាឡុកដែលបានជ្រើសរើសដោយឡែកពីគ្នា ទោះបីជាបច្ចុប្បន្នពួកវាប្រើ runtime hosts រួមគ្នាក៏ដោយ។
3. ចុះឈ្មោះ `qwen-cloud-token-plan` ជាមួយ allowlist ម៉ូដែលអត្ថបទរបស់ Token Plan បច្ចុប្បន្ន។
4. បន្ថែមកម្មវិធីជ្រើសរើសតំបន់ដែលមាន type ទៅក្នុងប្រអប់បន្ថែម/កែសម្រួល connection។
5. លាក់កាត `alibaba-cn` ដែលស្ទួន និងរួមបញ្ចូល connection ដែលមានស្រាប់របស់វានៅលើទំព័រ provider `alibaba`។
6. បន្តអនុញ្ញាតឱ្យប្រើការកំណត់ endpoint ផ្ទាល់ខ្លួនជំនួស សម្រាប់ការដាក់ឱ្យប្រើប្រាស់កម្រិតខ្ពស់ និងជាក់លាក់សម្រាប់ workspace។

ម៉ូដែលមេឌៀរបស់ Token Plan នៅតែស្ថិតនៅក្រៅកាតាឡុក chat ពីព្រោះពួកវាប្រើ endpoint ដាច់ដោយឡែក។
`wan2.7-image` និង `wan2.7-image-pro` ត្រូវបានចុះឈ្មោះក្នុង `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` និង `happyhorse-1.1-r2v` ត្រូវបានចុះឈ្មោះក្នុង
