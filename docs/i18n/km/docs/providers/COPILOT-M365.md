`copilot-m365-web` (ឈ្មោះក្លែងកាត់ `m365copilot`) ផ្ញើសំណើជជែកតាមទម្រង់ OpenAI តាមរយៈ
សម័យកម្មកម្មវិធីរុករក Microsoft 365 Copilot BizChat ដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណនៅ
`m365.cloud.microsoft/chat`។ នេះជាការរួមបញ្ចូលក្រៅផ្លូវការ។

> **ទើបតែចាប់ផ្តើមប្រើអ្នកផ្តល់សេវា Web Cookie មែនទេ?**
>
> សូមអាន **`docs/getting-started/WEB-COOKIE-GUIDE.md`** សម្រាប់ដំណើរការរៀបចំទូទៅ ការណែនាំអំពីការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ ដែនកំណត់ និងការដោះស្រាយបញ្ហា មុនពេលអនុវត្តតាមមគ្គុទ្ទេសក៍ជាក់លាក់សម្រាប់អ្នកផ្តល់សេវានេះ។
>
> **សំខាន់៖** ព័ត៌មានសម្ងាត់សម្រាប់អ្នកផ្តល់សេវានេះ **មិនមែនជា cookie ទេ**។ កុំចម្លង
> cookie ពី `m365.cloud.microsoft`។ ព័ត៌មានសម្ងាត់គឺជាប៉ារ៉ាម៉ែត្រសំណួររបស់ URL WebSocket
> និងផ្នែកផ្លូវ ដែលទាំងពីរត្រូវបានអានពីផ្ទាំង Network របស់ DevTools។

## តម្រូវការជាមុន

- គណនី Microsoft 365 ដែលមានសិទ្ធិចូលប្រើ BizChat នៅ `m365.cloud.microsoft/chat`
- កម្មវិធីរុករកផ្អែកលើ Chromium (Chrome, Edge) សម្រាប់ពិនិត្យ WebSocket ក្នុង DevTools
- អាជ្ញាបណ្ណ M365 Copilot (រួមបញ្ចូលជាមួយគម្រោង Microsoft 365 Business/Enterprise ជាច្រើន)

## ការចាប់យកព័ត៌មានសម្ងាត់ (វិធីសាស្ត្រ WebSocket)

1. ចូលនៅ `https://m365.cloud.microsoft/chat` ហើយចាប់ផ្តើមការសន្ទនា។
2. បើក **DevTools → Network**។
3. ច្រោះតាម **WS** (WebSocket)។
4. ចុចការតភ្ជាប់ Chathub WebSocket។ ស្វែងរក URL ដែលចាប់ផ្តើមដោយ
   `wss://substrate.office.com/m365Copilot/Chathub/`។
5. ពី **Request URL** របស់វា សូមចម្លង៖
   - តម្លៃប៉ារ៉ាម៉ែត្រសំណួរ `access_token` (JWT ដែលមានអាយុកាលខ្លី)។
   - ផ្នែកផ្លូវ Chathub បន្ទាប់ពី `/Chathub/` (ឧ. `<oid>@<tenant>`)។

URL ពេញលេញមានទម្រង់៖

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. នៅក្នុង OmniRoute សូមចូលទៅ **អ្នកផ្តល់សេវា → បន្ថែមអ្នកផ្តល់សេវា** ជ្រើស **Microsoft 365 Copilot
   (BizChat)** ហើយបិទភ្ជាប់ព័ត៌មានសម្ងាត់ក្នុងទម្រង់៖

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. ចុច **សាកល្បងការតភ្ជាប់** និង **រក្សាទុក**។

## ការចាប់យកព័ត៌មានសម្ងាត់ (ការនាំចូល HAR)

ជំនួសឱ្យការចម្លងតម្លៃពី URL WebSocket ដោយដៃ អ្នកអាចនាំចេញឯកសារ DevTools HAR
បាន៖

1. បើក **DevTools → Network**។
2. ចាប់ផ្តើម ឬបន្តការសន្ទនា BizChat (សកម្មភាពនេះបង្កឱ្យមានការតភ្ជាប់ WebSocket)។
3. ចុចកណ្ដុរស្ដាំនៅក្នុងផ្ទាំង Network ហើយជ្រើស **Save all as HAR with content**។
4. នៅក្នុង OmniRoute សូមប្រើប៊ូតុង **Import .har file** នៅលើប្រអប់ការតភ្ជាប់អ្នកផ្តល់សេវា។

OmniRoute ស្កេន HAR ដើម្បីរក URL Chathub WebSocket ស្រង់យក
`access_token` និង `chathubPath` ហើយបំពេញវាលព័ត៌មានសម្ងាត់ដោយស្វ័យប្រវត្តិ។ ការ
នាំចូល HAR ឌិកូដពេលផុតកំណត់របស់ JWT និងបង្ហាញអាយុកាលថូខឹនដែលនៅសល់។

> **កុំ commit ឯកសារនាំចេញ HAR ពិតប្រាកដ ថូខឹនចូលប្រើ ឬថូខឹនធ្វើឱ្យស្រស់ឡើងវិញឡើយ។** តម្លៃសម្រាប់ការធ្វើតេស្ត និង
> ឯកសារត្រូវតែជាតម្លៃជំនួសជានិច្ច។

## អាយុកាលថូខឹន និងការធ្វើឱ្យស្រស់ឡើងវិញ

`access_token` មានអាយុកាលខ្លី (ជាធម្មតា **~75 នាទី**)។ បន្ទាប់ពីផុតកំណត់ អ្នកផ្តល់សេវា
រាយការណ៍កំហុសការតភ្ជាប់ ហើយអ្នកត្រូវចាប់យកព័ត៌មានសម្ងាត់ឡើងវិញ។

### ការធ្វើឱ្យស្រស់ឡើងវិញដោយស្វ័យប្រវត្តិជាមួយ `refreshToken`

ដើម្បីជៀសវាងការចាប់យកឡើងវិញដោយដៃ អ្នកអាចរក្សាទុកថូខឹនធ្វើឱ្យស្រស់ឡើងវិញរបស់ Microsoft នៅក្នុង
**ការកំណត់កម្រិតខ្ពស់ → providerSpecificData** របស់ការតភ្ជាប់៖

| វាល            | សេចក្ដីពិពណ៌នា                                                                        |
| -------------- | ------------------------------------------------------------------------------------- |
| `refreshToken` | ថូខឹនធ្វើឱ្យស្រស់ឡើងវិញ Microsoft OAuth សម្រាប់វិសាលភាព `substrate.office.com/sydney` |
| `tier`         | `individual` (លំនាំដើម), `edu` ឬ `enterprise`                                         |

ទទួលយកថូខឹនធ្វើឱ្យស្រស់ឡើងវិញពីលំហូរកូដឧបករណ៍ ឬកូដអនុញ្ញាតរបស់ Microsoft
ដែលកំណត់វិសាលភាពទៅ `substrate.office.com/sydney`។ នៅពេលបានកំណត់ `refreshToken` OmniRoute
នឹងធ្វើឱ្យ `access_token` ស្រស់ឡើងវិញជាមុន មុនសំណើនីមួយៗ ដូច្នេះអ្នកមិនចាំបាច់
ចាប់យកឡើងវិញបន្ទាប់ពីការផុតកំណត់រៀងរាល់ ~75 នាទីឡើយ។

ប្រសិនបើមិនបានកំណត់ `refreshToken` ទេ អ្នកត្រូវចាប់យកព័ត៌មានសម្ងាត់ WebSocket ឡើងវិញដោយដៃ
បន្ទាប់ពីការផុតកំណត់នីមួយៗ។

### ការជ្រើសរើសកម្រិត

| កម្រិត       | ឈ្មោះក្លែងកាត់ | ផ្ទៃប្រើប្រាស់                         |
| ------------ | -------------- | -------------------------------------- |
| `individual` | _(លំនាំដើម)_   | M365 Copilot សម្រាប់អ្នកប្រើប្រាស់ទូទៅ |
| `edu`        | `included`     | M365 Copilot សម្រាប់វិស័យអប់រំ         |
| `enterprise` | `work`         | M365 Copilot សម្រាប់ការងារ             |

កំណត់កម្រិតនៅក្នុង **ការកំណត់កម្រិតខ្ពស់ → providerSpecificData → tier**។ កម្រិតនេះប៉ះពាល់ដល់
ការកំណត់ផ្លូវ BizChat និងសិទ្ធិចូលប្រើម៉ូដែល។

## គំរូសុវត្ថិភាព

- **ការរួមបញ្ចូលក្រៅផ្លូវការ។** អ្នកផ្តល់សេវានេះប្រើវិស្វកម្មបញ្ច្រាសលើពិធីការ WebSocket របស់ BizChat។
  វាអាចឈប់ដំណើរការដោយគ្មានការជូនដំណឹង នៅពេល Microsoft ផ្លាស់ប្តូរ endpoint។
- ទង់ `subscriptionRisk: true` បង្ហាញថា ការរួមបញ្ចូលនេះពឹងផ្អែកលើ
  endpoint ដែលមិនមានឯកសារពន្យល់។ ការរឹតបន្តឹងគណនីអាចកើតមាន ប៉ុន្តែមិនទាន់ត្រូវបានបញ្ជាក់ទេ។
- access token គឺជា JWT ដែលមានអាយុកាលខ្លី។ សូមចាត់ទុកវាដូចជាពាក្យសម្ងាត់៖ កុំ commit,
  កត់ត្រាក្នុង log ឬចែករំលែកវា។
- refresh token ផ្តល់សិទ្ធិចូលប្រើ BizChat រយៈពេលវែង។ សូមរក្សាទុកវាដោយ
  ការប្រុងប្រយ័ត្នដូចគ្នានឹង API key។

## ការដោះស្រាយបញ្ហា

### ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណបរាជ័យភ្លាមៗ

- ផ្ទៀងផ្ទាត់ថា អ្នកបានចម្លងពី **WebSocket URL** មិនមែនពីសំណើ XHR/Fetch ទេ។ ព័ត៌មាន
  សម្គាល់អត្តសញ្ញាណស្ថិតនៅក្នុង query parameter `access_token` នៃការតភ្ជាប់ Chathub WebSocket
  មិនមែននៅក្នុង header `Authorization: Bearer` ទេ។
- ត្រូវប្រាកដថា `chathubPath` រួមបញ្ចូល segment `<oid>@<tenant>` ពេញលេញពី URL
  path។

### Token ផុតកំណត់បន្ទាប់ពីប្រហែល 75 នាទី

- ចាប់យកព័ត៌មានសម្គាល់អត្តសញ្ញាណឡើងវិញពី DevTools ឬ
- កំណត់រចនាសម្ព័ន្ធ `refreshToken` នៅក្នុងការកំណត់កម្រិតខ្ពស់ ដើម្បីធ្វើឱ្យស្រស់ដោយស្វ័យប្រវត្តិ។

### ការសាកល្បងការតភ្ជាប់ជោគជ័យ ប៉ុន្តែ chat ត្រឡប់ 401
