## `claude-web`

`claude-web` ផ្ញើសំណើជជែកក្នុងទម្រង់ OpenAI តាមរយៈសម័យកម្មវិធីរុករកតាមអ៊ីនធឺណិត `claude.ai`
ដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ។ កម្មវិធីប្រតិបត្តិធ្វើឱ្យ cookie ដែលបានផ្ដល់មានទម្រង់ស្តង់ដារ កំណត់អង្គភាពមួយដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ
រៀបចំស្ថានភាពការសន្ទនា ជ្រើសរើសការដឹកជញ្ជូនដោយផ្ទាល់ ឬតាមកម្មវិធីរុករកតាមអ៊ីនធឺណិត និង
បម្លែងការឆ្លើយតប SSE ពី upstream យ៉ាងតឹងរ៉ឹង។ ការសម្របសម្រួលស្ថិតនៅក្នុង
`open-sse/executors/claude-web.ts:320`។

> **ទើបតែចាប់ផ្ដើមប្រើអ្នកផ្ដល់សេវា Web Cookie មែនទេ?**
>
> សូមអាន **`docs/getting-started/WEB-COOKIE-GUIDE.md`** សម្រាប់ដំណើរការរៀបចំទូទៅ ការណែនាំអំពីការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ ដែនកំណត់ និងការដោះស្រាយបញ្ហា មុននឹងអនុវត្តតាមការណែនាំជាក់លាក់សម្រាប់អ្នកផ្ដល់សេវានេះ។

### ព័ត៌មានសម្គាល់អត្តសញ្ញាណ និងការកំណត់អង្គភាព

ផ្ដល់ទាំង Cookie header ពេញលេញរបស់ `claude.ai` ឬតម្លៃ session ធម្មតា។ តម្លៃធម្មតាត្រូវបាន
ធ្វើឱ្យមានទម្រង់ស្តង់ដារទៅជា `sessionKey`; cookie ផ្សេងទៀតត្រូវបានរក្សាទុក ប្រសិនបើបានផ្ដល់។ កម្មវិធីប្រតិបត្តិទទួលយក
cookie តាមរយៈ `cookie` ឬ `apiKey` ហើយ
អានតម្លៃ `deviceId` និង `orgId` ជាជម្រើសពីទិន្នន័យការតភ្ជាប់
(`open-sse/executors/claude-web.ts:72`)។

ប្រសិនបើគ្មាន `orgId` កម្មវិធីប្រតិបត្តិនឹងហៅ `GET https://claude.ai/api/organizations` ហើយប្រើ
អង្គភាពដំបូងដែលត្រូវបានត្រឡប់ពីសម័យ Claude Web ដែលបានផ្ទៀងផ្ទាត់អត្តសញ្ញាណ
(`open-sse/executors/claude-web.ts:141`)។ វាបិទដោយសុវត្ថិភាពនៅពេលគ្មានអង្គភាពត្រឹមត្រូវត្រូវបាន
ត្រឡប់ រាយការណ៍ការអនុញ្ញាត session ដែលត្រូវបានបដិសេធជា 401 និងបែងចែកការប្រឈមពី Cloudflare
ចេញពីការបរាជ័យក្នុងការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ។
