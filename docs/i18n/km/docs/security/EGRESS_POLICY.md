> **កំណត់ចរាចរចេញឱ្យប្រើតែគ្រួសារ IP មួយ — `auto`, `ipv4` ឬ `ipv6` — សម្រាប់ប្រូកស៊ីនីមួយៗ ដើម្បីកុំឱ្យការចេញតាម IPv6 តែប៉ុណ្ណោះ លេចធ្លាយត្រឡប់ទៅ IPv4 ដោយស្ងាត់ស្ងៀម។**

> **ប្រភពយោងផ្លូវការ:** `open-sse/utils/proxyFamily.ts`, `open-sse/utils/proxyDispatcher.ts`, `open-sse/utils/proxyFetch.ts`, `open-sse/utils/socksConnectorWithFamily.ts`, `open-sse/utils/proxyFamilyResolve.ts`, `src/shared/validation/schemas.ts`, `src/lib/db/proxies.ts`, `src/lib/db/upstreamProxy.ts`, `src/lib/db/migrations/099_proxy_family.sql`

OmniRoute អនុញ្ញាតឱ្យប្រូកស៊ីនីមួយៗមាន **សេចក្តីបង្គាប់សម្រាប់គ្រួសារអាសយដ្ឋានចរាចរចេញ**។ តាមលំនាំដើម ប្រព័ន្ធប្រតិបត្តិការជាអ្នកជ្រើសរើស IPv4 ឬ IPv6 (dual-stack, "Happy Eyeballs")។ នៅពេលអ្នកកំណត់សេចក្តីបង្គាប់ទៅជា `ipv4` ឬ `ipv6` OmniRoute នឹងកំណត់រាល់ការតភ្ជាប់តាមប្រូកស៊ីនោះឱ្យប្រើគ្រួសារដែលបានជ្រើសរើស និង **បិទបរាជ័យដោយសុវត្ថិភាព** ជំនួសឱ្យការត្រឡប់ទៅប្រើគ្រួសារមួយទៀត។

ទំព័រនេះពន្យល់អំពីសេចក្តីបង្គាប់នេះថាជាអ្វី ហេតុអ្វីបានជាវាមាន វាត្រូវបានកំណត់រចនាសម្ព័ន្ធនៅទីណា និងរបៀបដែល runtime ដោះស្រាយវា។

## វាជាអ្វី

ប្រូកស៊ីនីមួយៗក្នុងបញ្ជីចុះឈ្មោះមានវាល `family` ដែលអាចមានតម្លៃបី ហើយត្រូវបានផ្ទៀងផ្ទាត់ដោយ Zod enum៖

```ts
// src/shared/validation/schemas.ts
family: z.enum(["auto", "ipv4", "ipv6"]).optional().default("auto"),
```

តាមលំនាំដើម វាលនេះមានតម្លៃ `"auto"` ដែលរក្សាឥរិយាបថ dual-stack ពីមុន។ ការកំណត់វាទៅជា `ipv4` ឬ `ipv6` នឹងកំណត់គ្រួសារសម្រាប់ការតភ្ជាប់របស់ប្រូកស៊ីនោះ។

សេចក្តីបង្គាប់នេះត្រូវបានធ្វើឱ្យមានទម្រង់ស្តង់ដារនៅគ្រប់ទីកន្លែងតាមរយៈ helper តែមួយ ដូច្នេះតម្លៃដែលមិនស្គាល់ណាមួយនឹងត្រូវប្តូរទៅជា `auto`៖

```ts
// open-sse/utils/proxyFamily.ts
export type ProxyFamily = "auto" | "ipv4" | "ipv6";

export function parseProxyFamily(value: unknown): ProxyFamily {
  return value === "ipv4" || value === "ipv6" ? value : "auto";
}
```

## របៀបកំណត់រចនាសម្ព័ន្ធ

### ផ្ទាំងគ្រប់គ្រង

ឧបករណ៍ជ្រើសរើសស្ថិតនៅក្នុងសំណុំបែបបទប្រូកស៊ីនៃផ្ទាំង **ក្រុមប្រូកស៊ី**៖

1. បើក **ផ្ទាំងគ្រប់គ្រង → ការកំណត់ → ប្រូកស៊ី → ក្រុមប្រូកស៊ី**
2. បន្ថែម ឬកែសម្រួលប្រូកស៊ី
3. កំណត់បញ្ជីទម្លាក់ចុះ **IP family** ទៅជា `ស្វ័យប្រវត្តិ (dual-stack)`, `តែ IPv4` ឬ `តែ IPv6`
4. រក្សាទុក

វត្ថុបញ្ជានេះត្រូវបាន render ដោយ `ProxyRegistryManager.tsx` (ត្រូវបាន mount ក្នុង `proxy/ProxyPoolTab.tsx`)។

### API

វាល `family` គឺជាផ្នែកមួយនៃ payload សម្រាប់បង្កើត/ធ្វើបច្ចុប្បន្នភាពបញ្ជីប្រូកស៊ី ដែលត្រូវបានផ្ទៀងផ្ទាត់ដោយ `createProxyRegistrySchema` / `updateProxyRegistrySchema` (`src/shared/validation/schemas.ts`) និងដំណើរការដោយ `POST` / `PATCH /api/v1/management/proxies`៖

```bash
# បង្កើតប្រូកស៊ីដែលប្រើតែ IPv6
curl -X POST http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{
    "name": "IPv6 egress",
    "type": "socks5",
    "host": "proxy.example.com",
    "port": 1080,
    "family": "ipv6"
  }'

# ប្តូរប្រូកស៊ីដែលមានស្រាប់ឱ្យប្រើតែ IPv4
curl -X PATCH http://localhost:20128/api/v1/management/proxies \
  -H "Content-Type: application/json" \
  -d '{ "id": "proxy-uuid-here", "family": "ipv4" }'
```

វាលដូចគ្នានេះក៏ត្រូវបានទទួលយកដោយ object កំណត់រចនាសម្ព័ន្ធប្រូកស៊ី inline ដែលប្រើសម្រាប់ធាតុ upstream-proxy ផងដែរ (`upstream_proxy_config.family`, សូមមើល [គំរូទិន្នន័យ](#data-model))។

សម្រាប់ API CRUD/ការកំណត់ប្រូកស៊ីផ្សេងទៀត សូមមើល [PROXY_GUIDE.md](../ops/PROXY_GUIDE.md)។

## របៀបដែល `auto` ដោះស្រាយ

នៅពេល `family` ជា `auto` OmniRoute **មិន** បន្ថែម directive ណាមួយទេ — URL ប្រូកស៊ីត្រូវបានប្រើដូចដែលមាន ហើយ family សម្រាប់ការតភ្ជាប់ត្រូវបានកំណត់ដោយលក្ខណៈផ្ទាល់របស់វា។

នៅពេលបង្កើត URL (`proxyConfigToUrl` / `normalizeProxyUrl` ក្នុង `open-sse/utils/proxyDispatcher.ts`) ប្រូកស៊ី `auto` បង្កើត URL ធម្មតាដោយគ្មានសញ្ញាសម្គាល់៖

```ts
// open-sse/utils/proxyDispatcher.ts
const fam = parseProxyFamily(config.family);
const normalized = normalizeProxyUrl(proxyUrlStr, "context proxy", {
  allowSocks5,
});
return fam === "auto" ? normalized : `${normalized}?family=${fam}`;
```

នៅពេល dispatch (`resolveDispatcherFamily`) `auto` ត្រូវបានដោះស្រាយទៅជា family ផ្ទាល់របស់ម៉ាស៊ីនមេ IP-literal ឬ `null` (អនុញ្ញាតឱ្យ OS សម្រេច) សម្រាប់ hostname៖

```ts
// open-sse/utils/proxyDispatcher.ts
function resolveDispatcherFamily(parsed: URL): 4 | 6 | null {
  const directive = parseProxyFamily(parsed.searchParams.get("family") ?? undefined);
  const literal = detectIpLiteralFamily(parsed.hostname);
  if (directive === "auto") return literal; // null សម្រាប់ hostname → OS ជាអ្នកជ្រើសរើស
  // ...
}
```

ដូច្នេះ៖

- `auto` + ម៉ាស៊ីនមេ IP-literal (`192.0.2.1` / `[2001:db8::1]`) → family របស់ literal នោះ។
- `auto` + hostname → `null` → ការដោះស្រាយ dual-stack ស្តង់ដាររបស់ OS។

## របៀបដែល `ipv4` / `ipv6` ត្រូវបានអនុវត្តយ៉ាងតឹងរ៉ឹង

Directive ដែលមិនមែនជា `auto` ត្រូវបានបញ្ជូនជាសញ្ញាសម្គាល់ query សិប្បនិម្មិតតែមួយ — `?family=ipv4` ឬ `?family=ipv6` — ដែលត្រូវបានបន្ថែមម្តងទៅ URL របស់ proxy ដែលបានធ្វើ normalization។ `normalizeProxyUrl` ប្រយ័ត្នក្នុងការដក និងបន្ថែមសញ្ញាសម្គាល់នេះឡើងវិញតែម្តងគត់ ដូច្នេះវាមិនធ្វើឱ្យការញែក port ខូចឡើយ។

នៅពេល dispatcher ត្រូវបានបង្កើត សញ្ញាសម្គាល់នេះត្រូវបានអាន និងបម្លែងទៅជា connect family ជាក់លាក់មួយ។ ប្រសិនបើ host ជា IP literal នៃ family **ផ្ទុយគ្នា** នោះ OmniRoute នឹងបោះ error (ភាពផ្ទុយគ្នាត្រូវបានដោះស្រាយបែប fail-closed)៖

```ts
// open-sse/utils/proxyDispatcher.ts
const want = directive === "ipv6" ? 6 : 4;
if (literal !== null && literal !== want) {
  throw new Error(
    `[ProxyDispatcher] Proxy family directive ${directive} contradicts ${literal === 6 ? "IPv6" : "IPv4"} literal host`
  );
}
```

បន្ទាប់មក family ជាក់លាក់ត្រូវបានកំណត់ថេរនៅលើ connector៖

- **HTTP/HTTPS proxies** (`ProxyAgent`): `proxyTls: { family, autoSelectFamily: false }` — បិទ Happy Eyeballs ដើម្បីឱ្យមានតែ family ដែលបានជ្រើសរើសប៉ុណ្ណោះត្រូវបានតភ្ជាប់។
- **SOCKS5 proxies**: connector ផ្ទាល់ខ្លួនមួយបញ្ជូន `socket_options: { family, autoSelectFamily: false }` ចូលទៅក្នុង SOCKS client (សូមមើល [ភាពឆបគ្នាជាមួយ SOCKS5](#socks5-compatibility))។

## ភាពឆបគ្នាជាមួយ SOCKS5

ការកំណត់ family ថេរដំណើរការជាមួយ SOCKS5 proxies ប៉ុន្តែ `fetch-socks` ស្តង់ដារមិនបង្ហាញ socket options ដែលចាំបាច់សម្រាប់កំណត់ family របស់ proxy hop ឱ្យនៅថេរទេ។ OmniRoute ផ្តល់ connector ផ្ទាល់ខ្លួនសម្រាប់គោលបំណងនេះ៖

```ts
// open-sse/utils/socksConnectorWithFamily.ts
export function buildSocksFamilySocketOptions(family: 4 | 6 | null): Record<string, unknown> {
  if (family === 6) return { family: 6, autoSelectFamily: false };
  if (family === 4) return { family: 4, autoSelectFamily: false };
  return {};
}
```

រាល់ SOCKS5 dispatch ទាំងអស់ឆ្លងកាត់ `createSocksDispatcherWithFamily` ដោយមិនគិតពី `family` (រួមទាំង `null` / `auto` លើ hostname ផងដែរ)៖ `buildSocksFamilySocketOptions(null)` ផ្តល់លទ្ធផល `{}` ហើយ path ដូចគ្នានៃ `SocksClient.createConnection` + TLS `buildConnector` ត្រូវបានប្រើជាមួយការកំណត់ `socket_options` ឱ្យថេរ ដូច្នេះ Happy Eyeballs មិនអាចជ្រើសរើស IPv4 សម្រាប់គោលការណ៍ egress ដែលអនុញ្ញាតតែ IPv6 បានទេ។

ការគាំទ្រ SOCKS5 ត្រូវបានបើកតាមលំនាំដើម (អាចបដិសេធដោយប្រើ `ENABLE_SOCKS5_PROXY=false`)។ សូមមើល [PROXY_GUIDE.md → អថេរបរិស្ថាន](../ops/PROXY_GUIDE.md#environment-variables)។

## ឥរិយាបថ Fail-Closed

គោលបំណងសំខាន់ទាំងមូលរបស់ directive គឺដើម្បី **បដិសេធ** ជាជាងប្តូរទៅប្រើ family ខុសដោយស្ងៀមស្ងាត់។ Guard ចំនួនពីរអនុវត្តរឿងនេះ៖

1. **ភាពផ្ទុយគ្នានៃ literal** — directive ដែលផ្ទុយនឹង host ជា IP literal នឹងបោះ error នៅពេលបង្កើត dispatcher (`resolveDispatcherFamily` ដែលបានបង្ហាញខាងលើ)។

2. **ការត្រួតពិនិត្យ DNS ជាមុនសម្រាប់ hostname** — សម្រាប់ hostname របស់ proxy ដែលបានកំណត់ family ឱ្យថេរ `proxyFetch.ts` ផ្ទៀងផ្ទាត់ថា hostname ពិតជាមាន record នៅក្នុង family ដែលត្រូវការ **មុនពេល** ធ្វើ egress តាមរយៈ `assertHostnameSupportsFamily`៖

   ```ts
   // open-sse/utils/proxyFamilyResolve.ts
   const hasFamily = records.some((r) => r.family === family);
   if (!hasFamily) {
     throw new Error(
       `[ProxyFamily] Proxy host ${host} has no ${family === 6 ? "IPv6 (AAAA)" : "IPv4 (A)"} record; ` +
         `refusing ${family === 6 ? "IPv6" : "IPv4"}-only egress (fail-closed)`
     );
   }
   ```

   នៅពេលបរាជ័យ `proxyFetch.ts` ដាក់ស្លាក error ដោយប្រើ `code = "PROXY_FAMILY_UNAVAILABLE"` និង `statusCode = 503`។ ការបរាជ័យក្នុងការធ្វើ DNS resolution ក៏ត្រូវបានចាត់ទុកជា fail-closed ដូចគ្នា (បដិសេធមិនធ្វើ egress)។

host ដែលជា IP literal មិនធ្វើអ្វីឡើយសម្រាប់ការត្រួតពិនិត្យ DNS ជាមុន — family របស់វាជាលក្ខណៈភ្ជាប់មកជាមួយស្រាប់ ហើយមិនត្រូវការ lookup ទេ។

## ម៉ូដែលទិន្នន័យ

ជួរឈរ `family` ត្រូវបានបន្ថែមដោយ migration `099_proxy_family.sql` ទៅក្នុងតារាងចំនួន **ពីរ**៖

```sql
-- src/lib/db/migrations/099_proxy_family.sql
ALTER TABLE proxy_registry ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
ALTER TABLE upstream_proxy_config ADD COLUMN family TEXT NOT NULL DEFAULT 'auto';
```

- `proxy_registry.family` — ការកំណត់សម្រាប់ proxy នីមួយៗនៅក្នុងធាតុ registry (`src/lib/db/proxies.ts`)។ សំណួរសម្រាប់ដោះស្រាយជ្រើសរើស `family` រួមជាមួយជួរឈរ proxy ផ្សេងទៀត ហើយតម្លៃដែលបាត់ ឬមិនមែនជាខ្សែអក្សរ នឹងត្រូវបានបម្លែងទៅជា `"auto"`។
- `upstream_proxy_config.family` — ការកំណត់សម្រាប់ធាតុ upstream proxy (`src/lib/db/upstreamProxy.ts`) ដោយមានតម្លៃលំនាំដើម `"auto"` ដូចគ្នា។

នៅពេលវត្ថុ proxy ដែលបានដោះស្រាយមាន `family` ដែលមិនមែនជា `auto` នោះ `proxyConfigToUrl` នឹងបន្ថែមសញ្ញាសម្គាល់ `?family=` ដើម្បីឱ្យការកំណត់ថេរនោះបន្តមានប្រសិទ្ធភាពរហូតដល់ dispatcher។
