## ស្រទាប់កំណត់ស្នាមសម្គាល់ TLS

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

សម័យ `wreq-js` អចិន្ត្រៃយ៍ត្រូវបានបង្កើតតាមតម្រូវការសម្រាប់វិសាលភាពគណនី និងប្រូកស៊ីដែលបានដោះស្រាយនីមួយៗ។
`TlsClient` ដែលប្រើរួមទូទាំងដំណើរការ រក្សាទុកសម័យយ៉ាងច្រើនបំផុត 128 ដែលក្លែងត្រាប់តាម **Chrome 124 នៅលើ macOS** សម្រាប់
ប្រភពដើមនៅពីក្រោយ Cloudflare។ `TlsClient.fetch()` បដិសេធសំណើជាសុវត្ថិភាពនៅពេល native runtime
មិនមាន; អ្នកហៅអាចជ្រើសរើសជម្រើសបម្រុងនៅខាងក្រៅ wrapper នេះដោយជាក់លាក់។

- ទម្រង់សម័យ៖ `browser: "chrome_124", os: "macos"`
- ការដោះស្រាយប្រូកស៊ី (តាមលំដាប់អាទិភាព)៖ `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (រួមទាំងអក្សរតូច)
- ពេលវេលាអស់កំណត់៖ `TLS_CLIENT_TIMEOUT_MS` (ទទួលតម្លៃបន្តពី `FETCH_TIMEOUT_MS`, លំនាំដើម 600000)
- Response របស់ `wreq-js` ឆបគ្នាជាមួយ fetch (`headers`, `text()`, `json()`, `clone()`, `body`)។
- កម្មវិធីឃ្លាំមើលបៃដំបូង (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656)៖ `TlsClient.fetch()`
  បញ្ចប់ការរង់ចាំភ្លាមៗនៅពេលបឋមកថាពីប្រភពដើមមកដល់ ដូច្នេះ `TLS_CLIENT_TIMEOUT_MS` តែមួយមិនអាចកំណត់ព្រំដែនរយៈពេលសម្រាប់
  body ដែលមិនដែលផ្ដល់បៃដំបូងបានទេ។ `guardTlsFirstByte()` ឱ្យប្រតិបត្តិការ `read()` ដំបូងរបស់ body
  ប្រណាំងជាមួយ `TLS_FIRST_BYTE_WATCHDOG_MS` (លំនាំដើម `10000`, `0` បិទវា); body ដែលដំណើរការធម្មតា
  មិនរងផលប៉ះពាល់ទេ ខណៈដែល body ជាប់គាំងធ្វើឱ្យ wreq reader ត្រូវបានបោះបង់ និងអនុញ្ញាតឱ្យតក្កវិជ្ជា
  TLS-fallback ដែលមានស្រាប់របស់ `proxyFetch` បន្តទៅកាន់ dispatcher ផ្ទាល់/ប្រូកស៊ី (សំណើដែលមិនអាចចាក់ឡើងវិញដោយសុវត្ថិភាព ឧទាហរណ៍
  POST ដែលមាន body នៅតែបញ្ចេញកំហុស ជំនួសឱ្យការព្យាយាមឡើងវិញដោយស្ងាត់ៗ)។

### ការដឹកជញ្ជូនរបស់អ្នកផ្ដល់សេវាដោយប្រើ Web-cookie — wreq-js 3.2.0

web-cookie ឯកទេសទាំងប្រាំខាងក្រោម។ wrapper ស្ដើងរបស់អ្នកផ្ដល់សេវានីមួយៗជ្រើសរើសទម្រង់ browser/OS។ adapter

## កញ្ចប់បំបាំងខ្លួន Claude Code

នៅពេលបើក `cliCompatMode` OmniRoute កែទម្រង់សំណើ Claude ដែលផ្ញើចេញ ដើម្បីឱ្យពួកវាមិនអាចបែងចែកបានពីចរាចរណ៍ `claude-cli`។ ម៉ូឌុលចំនួនបីសហការគ្នា៖

### `claudeCodeFingerprint.ts`

គណនា fingerprint `cc_version` ប្រវែង 3 តួអក្សរ ដែលបានបង្កប់ក្នុង billing header៖

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (កំណត់ថេរក្នុងកូដ; ត្រូវគ្នានឹង client ផ្លូវការ)
- ទិន្នន័យបញ្ចូល៖ តួអក្សរនៅ index 4, 7, 20 នៃអត្ថបទសារដំបូងរបស់អ្នកប្រើ + version string
- លទ្ធផល៖ hex prefix ប្រវែង 3 តួអក្សរ

### `claudeCodeCCH.ts` (Client Content Hash)

ការត្រួតពិនិត្យភាពត្រឹមត្រូវនៅផ្នែក server ដែល Claude Code CLI ផ្លូវការគណនាតាមរយៈ Bun/Zig។ OmniRoute អនុវត្តវាឡើងវិញដោយប្រើ `xxhash-wasm`៖

1. បម្លែង body ទៅជាទម្រង់សៀរៀល ដោយប្រើ placeholder `cch=00000;`
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. hex ជាអក្សរតូចប្រវែង 5 តួអក្សរ ដែលបំពេញសូន្យពីខាងមុខ
4. ជំនួស `cch=00000;` ដោយ token ដែលបានគណនា

ថេរ៖

- Seed៖ `0x6e52736ac806831e`
- Pattern៖ `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

បញ្ចូល Unicode **zero-width joiner** (`U+200D`) បន្ទាប់ពីតួអក្សរដំបូងនៃឈ្មោះ client ដែល "រសើប" ដើម្បីឱ្យ filter ខាង upstream មិនអាចស្វែងរកពួកវាដោយ grep បាន។ បញ្ជីពាក្យលំនាំដើម៖

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

អនុវត្តចំពោះ៖ block `system`, `messages[].content` ទាំងអស់ និង `tools[].description` / `tools[].function.description`។ Operator អាចកំណត់ជំនួសបានតាមរយៈ `setSensitiveWords()`។

### `claudeCodeCompatible.ts` — provider `anthropic-compatible-cc-*`

សម្រាប់ relay Anthropic របស់ភាគីទីបី ដែលទទួលយកតែចរាចរណ៍ "Claude Code ពិតប្រាកដ"៖

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- តាមលំនាំដើម `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- ជម្រើសបិទបើក "Enable redact-thinking beta" សម្រាប់ connection នីមួយៗ នឹងបន្ថែម `redact-thinking-2026-02-12` នៅពេល upstream ដែល CC Compatible ត្រូវការជាក់លាក់នូវ thinking stream ដែលបានលាក់ព័ត៌មាន
- ជម្រើសបិទបើក "Enable summarized thinking display" សម្រាប់ connection នីមួយៗ រក្សាទុក `providerSpecificData.requestDefaults.summarizeThinking` និងបន្ថែម `display: "summarized"` ទៅក្នុងសំណើ thinking របស់ CC Compatible ដែលមិនទាន់បានកំណត់ display mode
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (គ្រួសារ Opus/Sonnet 4.x)
- path លំនាំដើម៖ `/v1/messages?beta=true`

ម៉ូឌុលពាក់ព័ន្ធក្នុងកញ្ចប់ដូចគ្នា៖

- `claudeCodeConstraints.ts` — ច្បាប់ temperature + cache-control

## ការបំបាំងខ្លួន Antigravity

សំណើ Antigravity រក្សាអត្ថបទរបស់អ្នកហៅឱ្យដូចដើមគ្រប់ byte។ OmniRoute មិនបញ្ចូលតួអក្សរ zero-width ទៅក្នុង prompt ឬប្តូរឈ្មោះ/បញ្ចូល tool ដើម្បីក្លែងធ្វើជា IDE client ឡើយ។

### `antigravityHeaderScrub.ts`

ដកសញ្ញាសម្គាល់ Stainless SDK (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) ចេញមុនពេលបញ្ជូនបន្ត។

### ⚠️ ហានិភ័យ៖ `ANTIGRAVITY_CREDITS=always` (ចំណុចងាយបណ្តាលឱ្យគណនីត្រូវបានហាមឃាត់)

`ANTIGRAVITY_CREDITS=always` (ប្រើប្រាស់ដោយ `open-sse/executors/antigravity.ts`) បញ្ជូន **រាល់** សំណើតាមរយៈ Antigravity AI Credit Overages (Google credits បង់ប្រាក់) ជំនួសឱ្យការអនុញ្ញាតឱ្យ quota កម្រិតឥតគិតថ្លៃរបស់ Google គ្រប់គ្រងការប្រើប្រាស់។ វាត្រូវបានចងក្រងឯកសារថាជាមុខងារមួយ ប៉ុន្តែវាគឺជា **របាយការណ៍អំពីការរំលោភ ToS ដែលកើតឡើងញឹកញាប់បំផុតតែមួយគត់ដែលយើងបានឃើញ** — គណនី Google Ultra ជាច្រើនត្រូវបានហាមឃាត់ដោយមាន `403 / "service disabled for ToS violation" / insufficient_quota` បន្ទាប់ពីដំណើរការរយៈពេលពីរបីម៉ោងជាមួយ `=always`។

ការអនុវត្តវិធានការរបស់ upstream ស្ថិតនៅ **ខាង Google** មិនមែនជាអ្វីដែល OmniRoute អាចទប់ស្កាត់បានទេ។ ឈ្មោះ env var និងឯកសារដែលមានស្រាប់ ធ្វើឱ្យវាមើលទៅដូចជាជម្រើសដែលមានសុវត្ថិភាពសម្រាប់បើក ប៉ុន្តែវាមិនមានសុវត្ថិភាពទេ។

**មូលហេតុដែលវាបង្កឱ្យប្រព័ន្ធស្វែងរកការបំពានចាប់អារម្មណ៍ខ្លាំងជាងការប្រើប្រាស់តែកម្រិតឥតគិតថ្លៃ៖**

- ការចំណាយដោយស្វ័យប្រវត្តិជាបន្តបន្ទាប់លើគណនី Google តែមួយ ត្រូវបានសម្គាល់ខុសពីការប្រើប្រាស់កម្រិតឥតគិតថ្លៃដែលឈានដល់ quota រួចឈប់។
- Credit overage មិនមានពិដានអត្រាទេ ដូច្នេះ client ដែលបានកំណត់រចនាសម្ព័ន្ធខុស អាចចំណាយអស់រាប់រយ USD ក្នុងរយៈពេលប៉ុន្មាននាទី ហើយមើលទៅដូចជាការលក់ API key បន្ត ឬចរាចរណ៍ bot។
- អ្នកប្រើ OmniRoute ជាច្រើនដែលប្រើ overage credits ស្របពេលគ្នាពី external IP តែមួយ ធ្វើឱ្យសញ្ញាសង្ស័យកាន់តែខ្លាំង។

**វិធីសាស្ត្រដែលបានណែនាំ៖**

1. រក្សាលំនាំដើម `ANTIGRAVITY_CREDITS=off` លុះត្រាតែ operator ទទួលយកជាក់លាក់នូវហានិភ័យនៃ paid-credit និងការអនុវត្តវិធានការលើគណនី។ `retry` ផ្ញើសំណើធម្មតាជាមុន ហើយបញ្ចូល credits មិនលើសពីមួយដង បន្ទាប់ពី quota 429 ដែលមានលក្ខណៈសម្បត្តិគ្រប់គ្រាន់។ `always` បញ្ចូល credits នៅលើសំណើដំបូង។
2. **ចែកចាយបន្ទុកទៅ provider ផ្សេងៗតាមរយៈ Auto-Combo** (`model: "auto"` ឬ `kr/glm/etc`-combo) ជំនួសឱ្យការប្រើប្រាស់គណនី Antigravity តែមួយរហូតដល់កម្រិតអតិបរមា។
3. **កំណត់ដែនកំណត់ RPM សម្រាប់ connection នីមួយៗ** នៅក្នុងទំព័រកែសម្រួលរបស់ Antigravity provider (Dashboard → Providers → Antigravity → connection → rate limit)។ 30–60 RPM គឺជាដែនកំណត់ខាងលើដែលអាចការពារបានសម្រាប់ការប្រើប្រាស់ជាបន្តបន្ទាប់។
4. **ប្រើបណ្តាញ upstream ដែលមានស្ថិរភាព និងគ្រប់គ្រងដោយ operator** ហើយជៀសវាងការចែករំលែកគណនីតែមួយរវាងអ្នកប្រើ ឬ workload ដែលមិនពាក់ព័ន្ធគ្នា។
5. **ប្រសិនបើត្រូវបានហាមឃាត់**៖ ដាក់ពាក្យបណ្តឹងតវ៉ាតាម `support.google.com` → "Restore Workspace/Account access" ដោយភ្ជាប់ response body `quota_exceeded` / `service disabled` ពិតប្រាកដដែល Google បានផ្ញើ។ ការស្ដារឡើងវិញមិនត្រូវបានធានាទេ។

ឯកសារយោងអំពី environment រៀបរាប់ពីផលប៉ះពាល់លើគណនី និងការចំណាយនៃ credits mode នីមួយៗ។

តារាងតាមអ្នកផ្តល់សេវាដែលកំណត់លំដាប់ header និងលំដាប់ field ក្នុង JSON body ឱ្យបាន **ជាក់លាក់** ដូចដែលបានចាប់យកពី mitmproxy traces របស់ CLI ផ្លូវការ។ បច្ចុប្បន្នបានចុះឈ្មោះ៖ `codex`, `claude` ព្រមទាំង profile ដែលកំណត់នៅពេលដំណើរការនៅក្នុង `providerHeaderProfiles.ts` សម្រាប់ `antigravity` និង `github`។

```ts
interface CliFingerprint {
  headerOrder: string[]; // ប្រកាន់អក្សរធំតូច
  bodyFieldOrder: string[]; // JSON keys កម្រិតកំពូល
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

បិទ/បើកតាមអ្នកផ្តល់សេវានីមួយៗតាមរយៈ env (សូមមើលខាងក្រោម)។ នៅពេលបិទ headers/body keys នឹងបង្ហាញតាមលំដាប់ណាក៏ដោយដែល Node/JSON ផ្តល់ឱ្យ — ងាយស្រួលកំណត់ស្នាមម្រាមដៃ។

## MITM Proxy (Antigravity, Linux/macOS/Windows)

សម្រាប់ CLI ដែល binary របស់វាមិនអាចប្តូរទិសតាមរយៈ `OPENAI_BASE_URL` បាន OmniRoute ដំណើរការ proxy មូលដ្ឋានដែលបញ្ចប់ TLS។ Endpoint ស្ថិតនៅក្រោម `src/app/api/cli-tools/antigravity-mitm/`។

| វិធីសាស្ត្រ | Endpoint                                | គោលបំណង                                                  |
| ----------- | --------------------------------------- | -------------------------------------------------------- |
| GET         | `/api/cli-tools/antigravity-mitm`       | ស្ថានភាព — កំពុងដំណើរការ, pid, dnsConfigured, certExists |
| POST        | `/api/cli-tools/antigravity-mitm`       | ចាប់ផ្តើម MITM (តម្រូវឱ្យមាន `apiKey` + `sudoPassword`)  |
| DELETE      | `/api/cli-tools/antigravity-mitm`       | បញ្ឈប់ MITM                                              |
| GET         | `/api/cli-tools/antigravity-mitm/alias` | រាយបញ្ជីឈ្មោះក្លែងក្លាយរបស់ម៉ូដែល                        |
| PUT         | `/api/cli-tools/antigravity-mitm/alias` | រក្សាទុកឈ្មោះក្លែងក្លាយរបស់ម៉ូដែលសម្រាប់ឧបករណ៍មួយ        |

Host គោលដៅដែលត្រូវបានស្ទាក់ចាប់៖ **`daily-cloudcode-pa.googleapis.com`** (upstream របស់ Antigravity)។

### លំដាប់ចាប់ផ្តើម (`src/mitm/manager.ts::startMitm`)

1. បង្កើតវិញ្ញាបនបត្រដែលចុះហត្ថលេខាដោយខ្លួនឯងតាមរយៈ `selfsigned` (RSA-2048, SHA-256, 1 ឆ្នាំ) — `cert/generate.ts`
2. ដំឡើងវិញ្ញាបនបត្រទៅក្នុង system trust store — `cert/install.ts`
3. បន្ថែម hosts entry `127.0.0.1 daily-cloudcode-pa.googleapis.com` — `dns/dnsConfig.ts`
4. បង្កើត process `src/mitm/server.cjs` ជាមួយ `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (លំនាំដើម `443`)
5. រក្សាទុក PID ទៅ `<DATA_DIR>/mitm/.mitm.pid`

### ការរកឃើញ trust store បែប dynamic របស់ Linux — `cert/install.ts`

`getLinuxCertConfig()` ពិនិត្យតាមបញ្ជីអាទិភាព ហើយជ្រើសរើស directory ដំបូងដែលមានស្រាប់៖

| គ្រួសារ Distro           | Directory                                   | ពាក្យបញ្ជាធ្វើបច្ចុប្បន្នភាព |
| ------------------------ | ------------------------------------------- | ---------------------------- |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates`     |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`            |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`            |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates`     |

ឈ្មោះឯកសារវិញ្ញាបនបត្រ៖ `omniroute-mitm.crt`។ ផ្គូផ្គងស្នាមម្រាមដៃតាមរយៈ `getCertFingerprint()` (SHA-1 នៃ DER)។

លើសពីនេះ `updateNssDatabases()` ដំឡើងទៅក្នុង NSS DB របស់អ្នកប្រើម្នាក់ៗ នៅពេលមាន `certutil`៖ `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, profile ទាំងអស់របស់ Firefox (រួមទាំង snap) ក្រោម nickname **`OmniRoute MITM Root CA`**។

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** PowerShell ដែលមានសិទ្ធិខ្ពស់ → `certutil -addstore Root`

### ការផ្ទៀងផ្ទាត់អត្តសញ្ញាណ

MITM endpoint ទាំងអស់តម្រូវឱ្យមានការផ្ទៀងផ្ទាត់អត្តសញ្ញាណសម្រាប់ការគ្រប់គ្រង (`requireCliToolsAuth`)។ ពាក្យសម្ងាត់ sudo ត្រូវបាន cache ក្នុង module scope (មិនដែលនៅក្នុង `globalThis`) ហើយត្រូវបានសម្អាតនៅពេល `stopMitm()`។

## ការសម្អាត Header ចូល

OmniRoute សម្អាត header របស់កម្មវិធីអតិថិជនដែលចូលមក មុនពេលបញ្ជូនបន្ត ដូច្នេះសំណើដែលមកពី Cursor នឹងមិនធ្វើឱ្យ `User-Agent: Cursor/X.Y.Z` លេចធ្លាយទៅកាន់ Claude upstream ទេ។ សូមមើល `src/shared/constants/upstreamHeaders.ts` សម្រាប់បញ្ជីហាមឃាត់ ដែលត្រូវបានរក្សាឱ្យស៊ីសង្វាក់គ្នាជាមួយ Zod schemas និងការធ្វើតេស្តឯកតា។

## ការធ្វើបច្ចុប្បន្នភាពស្នាមសម្គាល់ នៅពេលអ្នកផ្តល់សេវាប្ដូរ

1. ចាប់យកចរាចរណ៍ CLI ផ្លូវការដោយប្រើ `mitmproxy` (ការស្ទាក់ចាប់ TLS + ការបញ្ចេញ dump)
2. ស្រង់ JA3/JA4 និងលំដាប់ header ជាក់ស្តែង
3. ធ្វើបច្ចុប្បន្នភាពធាតុ `CLI_FINGERPRINTS[...]` ដែលពាក់ព័ន្ធ
4. ដំឡើងកំណែតម្លៃលំនាំដើម `*_USER_AGENT` ដែលត្រូវគ្នានៅក្នុង `.env.example`
5. ប្រសិនបើ TLS handshake ខ្លួនវាបានផ្លាស់ប្ដូរ សូមធ្វើបច្ចុប្បន្នភាព wrapper របស់អ្នកផ្តល់សេវាដែលពាក់ព័ន្ធ ឬជម្រើស `browser:` របស់ wreq-js
6. ដំណើរការការធ្វើតេស្ត TLS ជាក់លាក់សម្រាប់អ្នកផ្តល់សេវា និង canary ដោយដៃប្រឆាំងនឹងអ្នកផ្តល់សេវាផ្ទាល់
7. ចេញផ្សាយជាកំណែ patch ហើយចងក្រងឯកសារនៅក្នុង `CHANGELOG.md`
