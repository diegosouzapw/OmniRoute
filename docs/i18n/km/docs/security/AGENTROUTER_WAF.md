ច្រកផ្លូវបញ្ជូនបន្ត upstream `agentrouter` ដំណើរការតម្រងមាតិកាផ្អែកលើពាក្យគន្លឹះលើ
`messages[].content`។ តម្រងនេះមួយផ្នែកមានលក្ខណៈកំណត់ជាក់លាក់ (តែងតែរារាំង
ឃ្លាជាក់លាក់មួយចំនួន) និងមួយផ្នែកមានលក្ខណៈប្រូបាប៊ីលីតេ (ប្រែប្រួលតាមសំណើជាបន្តបន្ទាប់ក្នុងរយៈពេលខ្លី — កាន់តែ
តឹងរ៉ឹងបន្ទាប់ពីមានសំណើរហ័សជាច្រើន ហើយត្រឡប់មកធម្មតាវិញបន្ទាប់ពីរយៈពេលសម្រាក)។

នៅពេល WAF រារាំងសំណើ វាត្រឡប់៖

```
HTTP/1.1 400 Bad Request
{"error":{"code":"content-blocked","message":"content-blocked (request id: ...)","param":"","type":"agent_router_api_error"}}
```

## វិសាលភាពនៃតម្រង

WAF ត្រួតពិនិត្យតែ `messages[].content` ប៉ុណ្ណោះ។ វា**មិន**ត្រួតពិនិត្យ៖

- ប្រអប់បញ្ចូល `system`
- ប្លុកមាតិកាដែលមានរចនាសម្ព័ន្ធ (`tool_result`, `tool_use`, `thinking`, `image`)
- វាល `description` និង `input_schema` របស់ឧបករណ៍
- មេតាទិន្នន័យសំណើ បឋមកថា ឬលេខសម្គាល់ម៉ូដែល

## ឥរិយាបថនៅពេលមានបន្ទុក

បន្ទាប់ពីមានសំណើរហ័សប្រហែល 5 ក្នុងចន្លោះពេលខ្លី WAF ចាប់ផ្តើមរារាំងមាតិកា
ដែលតាមធម្មតាអាចឆ្លងកាត់បាន។ bucket បន្ធូរវិញបន្ទាប់ពីគ្មានសកម្មភាពប្រហែល 5–10 វិនាទី។
នេះគឺជា rate limiter ដូចគ្នាដែលកំណត់តាម IP និង key ហើយបង្កឱ្យមាន
កំហុស `400 content-blocked` ម្តងម្កាល នៅពេល Claude Code ឬ Codex CLI
ធ្វើការហៅប្រើឧបករណ៍ / ផ្ញើសារជាច្រើនដងជាប់ៗគ្នាក្នុងរយៈពេលខ្លី។

## វិធានការកាត់បន្ថយដែលបានអនុវត្តរួចហើយនៅក្នុង OmniRoute

1. **`open-sse/services/wafRateLimit.ts`** — យន្តការការពារ burst ដែលបង្ខំឱ្យមាន
   ចន្លោះពេលអប្បបរមា 500 ms រវាងសំណើចេញទៅកាន់ URL `agentrouter:*`
   ណាមួយ។ ចន្លោះពេលនេះទាបជាងកម្រិតដែលមនុស្សអាចដឹងពីភាពយឺតបាន ហើយការពារ
   WAF មិនឱ្យធ្វើសកម្មភាពលើចរាចរណ៍ធម្មតា។

2. **`BaseExecutor.WAF_RETRY_CONFIG`** — នៅពេល upstream ត្រឡប់
   `400 content-blocked` executor នឹងព្យាយាម URL ដដែលម្តងទៀតដោយប្រើ
   exponential backoff (1.5 s, 3.0 s, អតិបរមា 2 ដង)។ បន្ទាប់ពី backoff
   WAF ជាធម្មតាបន្ធូរវិញ ហើយការព្យាយាមម្តងទៀតទទួលជោគជ័យ។

3. **`tests/unit/compression/harness.test.ts`** — test fixture
   `longInput` ត្រូវបានប្តូរពី `"lorem ipsum dolor sit amet ".repeat(40)`
   ទៅជា `"example content for testing purposes ".repeat(40)` ដូច្នេះនៅពេល
   Claude Code អានឯកសារនេះតាមឧបករណ៍ `Read` មាតិកាឯកសារ
   មិនហូរត្រឡប់តាមប្លុក `tool_result` ហើយបង្កឱ្យ WAF រារាំងទេ។

## គោលការណ៍ណែនាំសម្រាប់ប្រអប់បញ្ចូល និងលទ្ធផលឧបករណ៍

ទូទៅ៖

- ជំនួស `Lorem ipsum …` ដោយ `example text …` ឬមាតិកាពិតប្រាកដ

- ជំនួស `I'm here to help` / `here to help` ដោយពាក្យបើកដែលជាក់លាក់ជាងនេះ

## ការរាយការណ៍ false positive ទៅ upstream

តម្រងបច្ចុប្បន្នតឹងរ៉ឹងហួសហេតុ — វារារាំង "Lorem ipsum" នៅក្នុងប្លុក
`tool_result` ទោះបីជាអ្នកប្រតិបត្តិមិនមានបំណងបញ្ចូល prompt យ៉ាងច្បាស់ក៏ដោយ។
អ្នកប្រតិបត្តិដែលចង់ឱ្យបញ្ហានេះត្រូវបានជួសជុលនៅប្រភព គួរទាក់ទង
`agentrouter.org` ដើម្បីរាយការណ៍ false positive។ blocklist
ខាងលើគឺជាលទ្ធផលជាក់ស្តែងពីការសាកល្បង upstream គិតត្រឹមថ្ងៃទី 2026-08-03។
