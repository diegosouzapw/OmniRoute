Web Cookie فراہم کنندگان OmniRoute کو API key کے بجائے آپ کے موجودہ براؤزر سیشن کے ذریعے AI سروس استعمال کرنے دیتے ہیں۔ یہ اس وقت مفید ہوتے ہیں جب آپ کو پہلے ہی کسی سروس کی ویب سائٹ کے ذریعے اس تک رسائی حاصل ہو اور آپ چاہتے ہوں کہ OmniRoute اسی تصدیق شدہ سیشن کو استعمال کرے۔

API-key فراہم کنندگان کے برعکس، Web Cookie فراہم کنندگان ان اسنادی معلومات کے ذریعے تصدیق کرتے ہیں جو آپ کا براؤزر ویب سائٹ کو بھیجتا ہے۔

---

# شروع کرنے سے پہلے

> **اہم:** اسنادی معلومات ہمیشہ کسی **فعال نیٹ ورک درخواست** سے نقل کریں، اپنے براؤزر کے cookie storage سے **نہیں**۔

تصدیق کے بہت سے مسائل غلط جگہ سے cookies نقل کرنے کی وجہ سے پیدا ہوتے ہیں۔

## Cookie Storage سے نقل نہ کریں

زیادہ تر براؤزرز محفوظ شدہ cookies کو یہاں دکھاتے ہیں:

```
DevTools
→ Application (یا Storage)
→ Cookies
```

اگرچہ یہ cookies درست نظر آ سکتی ہیں، لیکن یہ ممکن ہے کہ:

- پرانی ہوں
- نامکمل ہوں
- ان cookies سے محروم ہوں جو صرف تصدیق شدہ درخواستوں کے ساتھ بھیجی جاتی ہیں

ان اقدار کو استعمال کرنے سے تصدیق ناکام ہو سکتی ہے، چاہے وہ بظاہر درست ہی کیوں نہ لگیں۔

## فعال درخواست سے نقل کریں

اس کے بجائے، کسی کامیاب درخواست کی cookies استعمال کریں:

```
DevTools
→ Network
→ صفحہ ریفریش کریں
→ کسی چیٹ یا گفتگو کی درخواست کھولیں
→ Request Headers
→ Cookie
```

`Cookie` درخواست header میں وہی درست تصدیقی معلومات ہوتی ہیں جنہیں آپ کے براؤزر نے کامیابی سے استعمال کیا تھا۔

زیادہ تر Web Cookie فراہم کنندگان کے لیے یہی وہ قدر ہے جسے OmniRoute میں چسپاں کرنا چاہیے۔

---

# عمومی سیٹ اپ

زیادہ تر Web Cookie فراہم کنندگان کے لیے سیٹ اپ کا عمل یکساں ہے۔

1. فراہم کنندہ کی ویب سائٹ پر سائن اِن کریں۔
2. براؤزر کے Developer Tools کھولیں۔
3. **Network** ٹیب کھولیں۔
4. صفحہ ریفریش کریں۔
5. کوئی تصدیق شدہ چیٹ یا گفتگو کی درخواست کھولیں۔
6. مطلوبہ تصدیقی اسنادی معلومات نقل کریں۔
7. OmniRoute کھولیں۔
8. **Providers → Add Provider** پر جائیں۔
9. اپنا Web Cookie فراہم کنندہ منتخب کریں۔
10. اسنادی معلومات چسپاں کریں۔
11. **Test Connection** پر کلک کریں۔
12. فراہم کنندہ محفوظ کریں۔

مطلوبہ اسنادی معلومات فراہم کنندہ کے لحاظ سے مختلف ہوتی ہیں۔

---

# فراہم کنندہ کی اسنادی معلومات کے فارمیٹس

مختلف ویب سائٹس تصدیقی معلومات کو مختلف طریقوں سے محفوظ کرتی ہیں۔ کچھ کو صرف cookies درکار ہوتی ہیں، جبکہ دیگر کو اضافی headers یا tokens بھی درکار ہو سکتے ہیں۔

| فراہم کنندہ                     | اسنادی معلومات کا فارمیٹ      | فراہم کنندہ کی رہنما             |
| ------------------------------- | ----------------------------- | -------------------------------- |
| Claude Web                      | مکمل Cookie درخواست header    | `docs/providers/CLAUDE_WEB.md`   |
| ChatGPT Web (Codex)             | مکمل Cookie header            | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(تصدیق کریں)_                |                                  |
| Copilot Web                     | _(تصدیق کریں)_                | `docs/providers/COPILOT-M365.md` |
| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(تصدیق کریں)_                |                                  |
| ...                             | ...                           | ...                              |

> جیسے ہی نئے Web Cookie فراہم کنندگان شامل کیے جائیں یا موجودہ فراہم کنندگان اپنی تصدیقی ضروریات تبدیل کریں، اس جدول کو اپ ڈیٹ کریں۔

# Web Cookie فراہم کنندگان کیا کر سکتے ہیں اور کیا نہیں

Web Cookie فراہم کنندگان کسی ویب سائٹ کے چیٹ انٹرفیس کو دوبارہ استعمال کرتے ہیں۔ یہ سرکاری APIs جیسی صلاحیتیں فراہم **نہیں** کرتے۔

## معاونت یافتہ

- اپنے موجودہ براؤزر سیشن کے ذریعے تصدیق
- اپنے اکاؤنٹ کے ذریعے دستیاب models تک رسائی
- چیٹ جوابات کی streaming
- API key درکار نہیں

## غیر معاون

- Function calling
- Tool calling
- خودکار فائل ترمیم
- Agentic IDE workflows
- صرف API میں دستیاب خصوصیات

یہ متوقع طرزِ عمل ہے اور کوئی bug **نہیں** ہے۔

اگر آپ کو tool execution، خودکار فائل ترمیم، یا دیگر agent workflows درکار ہوں، تو Web Cookie فراہم کنندہ کے بجائے **API-key فراہم کنندہ** استعمال کریں۔

---

# توثیق سے متعلق احتیاط

کامیاب **Test Connection** یا cookie validation صرف یہ تصدیق کرتی ہے کہ فراہم کردہ اسنادی معلومات بظاہر متوقع فارمیٹ میں ہیں۔

جب تک Issue #7857 حل نہیں ہو جاتا، کامیاب validation اس بات کی **ضمانت نہیں دیتی** کہ فراہم کنندہ کامیابی سے تصدیق کر سکے گا۔

اگر تصدیق پھر بھی ناکام ہو، تو یقینی بنائیں کہ آپ نے اسنادی معلومات براؤزر کے cookie storage کے بجائے کسی فعال نیٹ ورک درخواست سے نقل کی تھیں۔

---

# مسائل کا ازالہ

## تصدیق ناکام ہوتی ہے

یقینی بنائیں کہ اسنادی معلومات یہاں سے نقل کی گئی تھیں:

```
Network
→ Request Headers
→ Cookie
```

اور یہاں سے **نہیں**:

```
Application
→ Cookies
```

---

## Cookie براؤزر میں کام کرتی ہے لیکن OmniRoute میں نہیں

کچھ فراہم کنندگان ایسی cookies شامل کرتے ہیں جو صرف تصدیق شدہ درخواستوں کے دوران بھیجی جاتی ہیں۔

کسی گفتگو کو کامیابی سے کھولنے کے بعد، نئی نیٹ ورک درخواست سے اسنادی معلومات دوبارہ نقل کریں۔

---

## سیشن کی میعاد ختم ہو گئی

Web Cookie فراہم کنندگان آپ کا موجودہ براؤزر سیشن استعمال کرتے ہیں۔

اگر آپ کے براؤزر سیشن کی میعاد ختم ہو جائے یا آپ سائن آؤٹ کر دیں، تو آپ کو اسنادی معلومات کا نیا مجموعہ نقل کرنا ہوگا۔

---

## Test Connection کامیاب ہے لیکن درخواستیں ناکام ہوتی ہیں

جب تک Issue #7857 حل نہیں ہو جاتا، validation میں کامیابی اس بات کی ضمانت نہیں دیتی کہ تصدیقی درخواست کامیاب ہوگی۔

مزید مسائل کا ازالہ کرنے سے پہلے، کسی نئی تصدیق شدہ درخواست سے اپنی اسنادی معلومات دوبارہ نقل کریں۔

---

# فراہم کنندہ کی مثال

فراہم کنندہ سے متعلق مکمل مرحلہ وار رہنمائی کے لیے دیکھیں:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web کی رہنما Web Cookie فراہم کنندہ کے لیے سیٹ اپ کا مکمل عمل دکھاتی ہے اور حوالہ جاتی implementation کے طور پر کام کرتی ہے۔

---

# بہترین طریقے

- کسی نئی تصدیق شدہ درخواست سے اسنادی معلومات نقل کریں۔
- پرانی cookies دوبارہ استعمال کرنے سے گریز کریں۔
- Web Cookie فراہم کنندگان استعمال کرتے وقت اپنا براؤزر سیشن فعال رکھیں۔
- نقل کی گئی cookies کو حساس اسنادی معلومات سمجھیں۔
- جب آپ کو function calling یا agent workflows درکار ہوں تو API-key فراہم کنندگان استعمال کریں۔
