Web Cookie فراہم کنندگان OmniRoute کو API key کے بجائے آپ کے موجودہ براؤزر سیشن کے ذریعے AI سروس استعمال کرنے دیتے ہیں۔ یہ اس وقت مفید ہوتے ہیں جب آپ کو پہلے ہی کسی سروس کی ویب سائٹ کے ذریعے رسائی حاصل ہو اور آپ چاہتے ہوں کہ OmniRoute اسی تصدیق شدہ سیشن کو استعمال کرے۔

API-key فراہم کنندگان کے برعکس، Web Cookie فراہم کنندگان ان اسنادی معلومات کے ذریعے تصدیق کرتے ہیں جو آپ کا براؤزر ویب سائٹ کو بھیجتا ہے۔

---

# شروع کرنے سے پہلے

> **اہم:** اسنادی معلومات ہمیشہ کسی **لائیو نیٹ ورک درخواست** سے نقل کریں، اپنے براؤزر کی cookie storage سے **نہیں**۔

تصدیق کے بہت سے مسائل cookies کو غلط جگہ سے نقل کرنے کی وجہ سے پیدا ہوتے ہیں۔

## Cookie Storage سے نقل نہ کریں

زیادہ تر براؤزرز محفوظ شدہ cookies کو درج ذیل کے ذریعے دکھاتے ہیں:

```
DevTools
→ Application (یا Storage)
→ Cookies
```

اگرچہ یہ cookies درست نظر آ سکتی ہیں، لیکن یہ درج ذیل ہو سکتی ہیں:

- پرانی
- نامکمل
- ان cookies سے محروم جو صرف تصدیق شدہ درخواستوں پر بھیجی جاتی ہیں

ان اقدار کے استعمال سے تصدیق ناکام ہو سکتی ہے، چاہے وہ بظاہر درست ہی کیوں نہ ہوں۔

## لائیو درخواست سے نقل کریں

اس کے بجائے، کسی کامیاب درخواست کی cookies استعمال کریں:

```
DevTools
→ Network
→ صفحہ ریفریش کریں
→ کوئی chat یا conversation درخواست کھولیں
→ Request Headers
→ Cookie
```

`Cookie` درخواست header میں وہی مکمل تصدیقی معلومات ہوتی ہیں جو آپ کے براؤزر نے کامیابی سے استعمال کی تھیں۔

زیادہ تر Web Cookie فراہم کنندگان کے لیے یہی وہ قدر ہے جسے OmniRoute میں چسپاں کیا جانا چاہیے۔

# عمومی سیٹ اپ

زیادہ تر Web Cookie فراہم کنندگان کے لیے سیٹ اپ کا طریقہ یکساں ہے۔

1. فراہم کنندہ کی ویب سائٹ پر سائن اِن کریں۔
2. براؤزر کے Developer Tools کھولیں۔
3. **Network** ٹیب کھولیں۔
4. صفحہ ریفریش کریں۔
5. کوئی تصدیق شدہ chat یا conversation درخواست کھولیں۔
6. مطلوبہ تصدیقی اسنادی معلومات نقل کریں۔
7. OmniRoute کھولیں۔
8. **Providers → Add Provider** پر جائیں۔
9. اپنا Web Cookie فراہم کنندہ منتخب کریں۔
10. اسنادی معلومات چسپاں کریں۔
11. **Test Connection** پر کلک کریں۔
12. فراہم کنندہ محفوظ کریں۔

درکار اسنادی معلومات فراہم کنندہ کے لحاظ سے مختلف ہوتی ہیں۔

| فراہم کنندہ                     | اسنادی معلومات کا فارمیٹ      | فراہم کنندہ کی گائیڈ             |

| ChatGPT Web (Codex)             | مکمل Cookie header            | `docs/providers/CHATGPT_WEB.md`  |
| Gemini Web                      | _(تصدیق کریں)_                |                                  |

| Grok Web                        | _(تصدیق کریں)_                |                                  |
| ...                             | ...                           | ...                              |

> نئے Web Cookie فراہم کنندگان شامل ہونے یا موجودہ فراہم کنندگان کی تصدیقی ضروریات تبدیل ہونے پر اس جدول کو اپ ڈیٹ کریں۔

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) صارفین کے لیے ایک مفت چیٹ پلیٹ فارم ہے جس کے لیے سائن اپ درکار نہیں — پہلے وزٹ پر سیشن گمنام طور پر بنایا جاتا ہے اور تین کوکیز کے ذریعے برقرار رہتا ہے: `uid`، `si_usr_id`، اور `si_ses_id`۔ OmniRoute اسی `/api/dispatch` اینڈ پوائنٹ کو ایک واحد ماڈل آئی ڈی (`notrack-c`، عرف `ntw`) کے ذریعے پراکسی کرتا ہے۔

### منسلک کرنے کے مراحل

1. اپنے براؤزر میں [notrack.ai](https://notrack.ai) کھولیں اور گمنام سیشن کوکی سیٹ ہونے دیں۔
2. **DevTools → Network** کھولیں، صفحہ ریفریش کریں، اور کسی بھی `/api` درخواست پر کلک کریں۔
3. **Request Headers** میں مکمل `Cookie` ہیڈر ویلیو کاپی کریں۔
4. OmniRoute میں **Providers → Add Provider → NoTrack Web (Free)** پر جائیں۔
5. کوکی اسٹرنگ کو `apiKey` فیلڈ میں پیسٹ کریں اور **Save** پر کلک کریں۔

OmniRoute پیسٹ کی گئی اسٹرنگ سے `uid`، `si_usr_id`، اور `si_ses_id` اخذ کرتا ہے اور صرف انہی جوڑوں کے ساتھ ایک صاف `Cookie` ہیڈر دوبارہ بناتا ہے — نیز موجود ہونے کی صورت میں `nt_session` (لاگ اِن اکاؤنٹس کے لیے سیٹ کیا گیا `ntk_…` ٹوکن) بھی شامل کرتا ہے۔ اگر ان تینوں میں سے کوئی ایک موجود نہ ہو تو پیسٹ کی گئی خام اسٹرنگ بغیر تبدیلی کے آگے بھیج دی جاتی ہے، تاکہ آپریٹرز متبادل ساختوں کے ساتھ تجربہ کر سکیں۔

### ماڈل آئی ڈیز

| ماڈل آئی ڈی | نمائشی نام | نوٹس                                          |
| ----------- | ---------- | --------------------------------------------- |
| `notrack-c` | NoTrack C  | ڈیفالٹ — اپ اسٹریم ڈسپیچ ماڈل `C`۔            |
| `C`         | NoTrack C  | `notrack-c` کا عرف (خام اپ اسٹریم ڈسپیچ کوڈ)۔ |
| `notrack`   | NoTrack C  | `notrack-c` کا عرف۔                           |
| `ntw`       | NoTrack C  | `notrack-c` کا مختصر عرف۔                     |

چاروں ماڈل آئی ڈیز ایک ہی اپ اسٹریم ڈسپیچ ماڈل (`C`) سے میپ ہوتی ہیں۔

### درخواست کے اختیارات

ایگزیکیوٹر درخواست کی باڈی میں درج ذیل اختیاری فیلڈز قبول کرتا ہے:

| باڈی فیلڈ             | ڈیفالٹ  | مقصد                                                                           |
| --------------------- | ------- | ------------------------------------------------------------------------------ |
| `notrack_mode`        | `usual` | ڈسپیچ موڈ (آزاد طرز کی اسٹرنگ؛ اپ اسٹریم `usual`، … قبول کرتا ہے)              |
| `notrack_max_turns`   | `6`     | جواب دینے سے پہلے اپ اسٹریم کے ممکنہ داخلی ٹرنز کی تعداد۔                      |
| `notrack_chat_id`     | `null`  | موجودہ اپ اسٹریم چیٹ دوبارہ شروع کریں (نئی چیٹ کے لیے اسے شامل نہ کریں)۔       |
| `notrack_attachments` | `[]`    | اپ اسٹریم اٹیچمنٹ ڈسکرپٹرز کی پاس تھرو ارے۔                                    |
| `notrack_regenerate`  | `false` | گزشتہ ٹرن کے لیے دوبارہ تیار کردہ جواب کی درخواست کرنے کے لیے `true` سیٹ کریں۔ |

### صلاحیتیں

- **اسٹریمنگ اور نان اسٹریمنگ** چیٹ کمپلیشنز۔
- **ٹول کالنگ** — درخواست میں `tools: [...]` سیٹ کریں؛ ایگزیکیوٹر انہیں ٹول کال اینویلپ کنٹریکٹ میں سیریلائز کرتا ہے اور ماڈل کے جوابات کو واپس OpenAI `tool_calls` میں پارس کرتا ہے۔
- **`response_format`** — `json_object` اور `json_schema` معاونت یافتہ ہیں۔ ایگزیکیوٹر ماڈل کے جواب سے پہلا JSON آبجیکٹ اخذ کرتا ہے اور واپس کرنے سے پہلے اسے اسٹرنگ میں تبدیل کرتا ہے۔
- **ریزننگ کا اشارہ** — جب اپ اسٹریم کوئی `thinking` ایونٹ بھیجتا ہے تو ایگزیکیوٹر ایک `reasoning` ڈیلٹا خارج کرتا ہے۔

### حدود

- اپ اسٹریم گمنام استعمال کے کوٹاز نافذ کرتا ہے — حد عبور ہونے پر ایگزیکیوٹر دوستانہ پیغام کے ساتھ 429 ظاہر کرتا ہے۔
- تمام ماڈل آئی ڈیز ایک ہی اپ اسٹریم ڈسپیچ ماڈل پر ریزولو ہوتی ہیں؛ ہر ماڈل کے لیے علیحدہ سوئچ موجود نہیں۔
- ایگزیکیوٹر اپ اسٹریم کے `/api/chats` اینڈ پوائنٹ کو کال نہیں کرتا، اس لیے چیٹ ہسٹری / سیشنز خودکار طور پر منظم نہیں ہوتے۔ موجودہ اپ اسٹریم چیٹ دوبارہ شروع کرنے کے لیے `notrack_chat_id` استعمال کریں۔

# ویب کوکی پرووائیڈرز کیا کر سکتے ہیں اور کیا نہیں

ویب کوکی پرووائیڈرز کسی ویب سائٹ کے چیٹ انٹرفیس کو دوبارہ استعمال کرتے ہیں۔ وہ آفیشل APIs جیسی صلاحیتیں **فراہم نہیں** کرتے۔

## معاونت یافتہ

- اپنے موجودہ براؤزر سیشن کے ذریعے توثیق کریں
- اپنے اکاؤنٹ کے ذریعے دستیاب ماڈلز تک رسائی حاصل کریں
- چیٹ کے جوابات کو اسٹریم کریں
- کسی API کلید کی ضرورت نہیں

## غیر معاونت یافتہ

- فنکشن کالنگ
- ٹول کالنگ
- خودکار فائل ایڈیٹنگ
- ایجنٹ پر مبنی IDE ورک فلو
- صرف API کے ذریعے دستیاب خصوصیات

یہ متوقع طرزِ عمل ہے اور **بگ نہیں** ہے۔

اگر آپ کو ٹول چلانے، خودکار فائل ایڈیٹنگ، یا دیگر ایجنٹ ورک فلو کی ضرورت ہو تو Web Cookie فراہم کنندہ کے بجائے **API-key provider** استعمال کریں۔

# توثیق سے متعلق اہم وضاحت

کامیاب **Test Connection** یا کوکی کی توثیق صرف یہ تصدیق کرتی ہے کہ فراہم کردہ اسناد بظاہر متوقع فارمیٹ میں ہیں۔

Issue #7857 حل ہونے تک، کامیاب توثیق اس بات کی **ضمانت نہیں دیتی** کہ فراہم کنندہ کامیابی سے تصدیقِ شناخت کر سکے گا۔

اگر تصدیقِ شناخت پھر بھی ناکام ہو تو یقینی بنائیں کہ آپ نے اسناد براؤزر کی کوکی اسٹوریج کے بجائے کسی فعال نیٹ ورک درخواست سے کاپی کی ہیں۔

## کوکی براؤزر میں کام کرتی ہے لیکن OmniRoute میں نہیں

کچھ فراہم کنندگان ایسی کوکیز شامل کرتے ہیں جو صرف تصدیق شدہ درخواستوں کے دوران بھیجی جاتی ہیں۔

کسی گفتگو کو کامیابی سے کھولنے کے بعد، ایک نئی نیٹ ورک درخواست سے اسناد دوبارہ کاپی کریں۔

---

## سیشن کی میعاد ختم ہونا

Web Cookie فراہم کنندگان آپ کا موجودہ براؤزر سیشن استعمال کرتے ہیں۔

اگر آپ کے براؤزر سیشن کی میعاد ختم ہو جائے یا آپ سائن آؤٹ کر دیں تو آپ کو اسناد کا نیا مجموعہ کاپی کرنا ہوگا۔ معاونت یافتہ ویب فراہم کنندگان کے لیے کوکی کی تجدید کو خودکار بنانے کے لیے، معاون ٹول [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md) دیکھیں۔

---

## Test Connection کامیاب ہے لیکن درخواستیں ناکام ہوتی ہیں

Issue #7857 حل ہونے تک، توثیق میں کامیابی اس بات کی ضمانت نہیں دیتی کہ تصدیقِ شناخت کی درخواست کامیاب ہوگی۔

مزید خرابیوں کا ازالہ کرنے سے پہلے، کسی نئی تصدیق شدہ درخواست سے اپنی اسناد دوبارہ کاپی کریں۔

---

# فراہم کنندہ کی مثال

فراہم کنندہ کے لیے مخصوص مکمل مرحلہ وار رہنمائی کے لیے دیکھیں:

- **Claude Web** — `docs/providers/CLAUDE_WEB.md`

Claude Web کی گائیڈ Web Cookie فراہم کنندہ کے لیے سیٹ اپ کا مکمل طریقہ دکھاتی ہے اور حوالہ جاتی نفاذ کے طور پر کام کرتی ہے۔

---

# بہترین طریقے

- کسی نئی تصدیق شدہ درخواست سے اسناد کاپی کریں۔
- پرانی کوکیز کو دوبارہ استعمال کرنے سے گریز کریں۔
- Web Cookie فراہم کنندگان استعمال کرتے وقت اپنا براؤزر سیشن فعال رکھیں۔
- کاپی کی گئی کوکیز کو حساس اسناد سمجھیں۔
- جب آپ کو فنکشن کالنگ یا ایجنٹ ورک فلو درکار ہوں تو API-key providers استعمال کریں۔
