## یہ کیا کرتا ہے

کوئی مخصوص AI ماڈل (جیسے GPT-4o یا Claude) منتخب کرنے کے بجائے، آپ OmniRoute کو ہر درخواست کے لیے **خودکار طور پر بہترین ماڈل منتخب کرنے** دے سکتے ہیں۔ یہ درج ذیل عوامل کو مدِنظر رکھتا ہے:

- **صحت** — کیا فراہم کنندہ اس وقت کام کر رہا ہے؟
- **رفتار** — یہ کتنا تیز ہے؟
- **لاگت** — اس کی قیمت کتنی ہے؟
- **معیار** — کیا یہ اس نوعیت کے کام میں اچھا ہے؟
- **گنجائش** — کیا اس کا کوٹا باقی ہے؟

OmniRoute آپ کے تمام منسلک فراہم کنندگان کو اسکور دیتا ہے اور بہترین فراہم کنندہ منتخب کرتا ہے۔ اگر وہ ناکام ہو جائے تو یہ خودکار طور پر اگلے فراہم کنندہ کو آزماتا ہے۔

## فوری آغاز

**مرحلہ 1**: اپنے IDE یا CLI میں ماڈل کو `auto` پر سیٹ کریں:

```
model: "auto"
```

**مرحلہ 2**: بس اتنا ہی! باقی سب OmniRoute سنبھال لیتا ہے۔

**مرحلہ 3** (اختیاری): مخصوص کاموں کے لیے کوئی ویریئنٹ استعمال کریں:

```
model: "auto/coding"    # کوڈ کے لیے بہترین
model: "auto/fast"      # تیز ترین جواب
model: "auto/cheap"     # سب سے سستا انتخاب
```

## مجھے کون سا "auto" استعمال کرنا چاہیے؟

| اگر آپ چاہتے ہیں...      | یہ استعمال کریں | اس کے لیے بہترین           | یہ کیسے کام کرتا ہے                                 |
| ------------------------ | --------------- | -------------------------- | --------------------------------------------------- |
| **مجموعی طور پر بہترین** | `auto`          | عمومی سوالات، چیٹ          | رفتار، لاگت اور معیار میں توازن رکھتا ہے            |
| **بہترین کوڈ**           | `auto/coding`   | کوڈ لکھنا، ڈیبگنگ          | کوڈنگ کے کاموں میں اچھے ماڈلز منتخب کرتا ہے         |
| **تیز ترین جواب**        | `auto/fast`     | فوری جوابات، کم تاخیر      | رفتار کو ہر چیز پر ترجیح دیتا ہے                    |
| **سب سے سستا انتخاب**    | `auto/cheap`    | رقم کی بچت                 | سب سے سستا فراہم کنندہ منتخب کرتا ہے                |
| **ذہین ترین ماڈل**       | `auto/smart`    | پیچیدہ کام                 | معیار کو ترجیح دیتا ہے + نئے ماڈلز آزماتا ہے        |
| **سب سے زیادہ دستیاب**   | `auto/offline`  | جب فراہم کنندگان مصروف ہوں | سب سے زیادہ گنجائش والے فراہم کنندگان منتخب کرتا ہے |

### مثالیں

```bash
# عمومی چیٹ — متوازن
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# کوڈ بنانا — معیار کو ترجیح
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# فوری جواب — رفتار کو ترجیح
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## یہ کیسے کام کرتا ہے (سادہ وضاحت)

جب آپ `model: "auto"` کے ساتھ درخواست بھیجتے ہیں، تو OmniRoute:

1. **آپ کے تمام منسلک فراہم کنندگان کو دیکھتا ہے** — آپ کی جانب سے شامل کیا گیا ہر فراہم کنندہ (OpenAI، Anthropic، Google وغیرہ)
2. **ہر ایک کو اسکور دیتا ہے**، اور دیگر عوامل کے ساتھ درج ذیل کو اہمیت دیتا ہے:
   - کیا یہ کام کر رہا ہے؟ (صحت)
   - کیا اس کے پاس گنجائش ہے؟ (کوٹا)
   - اس کی قیمت کتنی ہے؟ (قیمت)
   - یہ کتنا تیز ہے؟ (رفتار)
   - کیا یہ اس کام میں اچھا ہے؟ (معیار)
3. **بہترین فراہم کنندہ منتخب کرتا ہے** — سب سے زیادہ اسکور والا فراہم کنندہ آپ کی درخواست وصول کرتا ہے
4. **خودکار بحالی کرتا ہے** — اگر وہ ناکام ہو جائے تو OmniRoute خودکار طور پر اگلے فراہم کنندہ کو آزماتا ہے

### اسکورنگ کا نظام

ہر فراہم کنندہ کو 0 سے 1 تک اسکور ملتا ہے۔ اسکور جتنا زیادہ ہوگا، موزونیت اتنی ہی بہتر ہوگی۔

| عامل          | وزن | اس کا مطلب                                          |
| ------------- | --- | --------------------------------------------------- |
| صحت           | 20% | کیا فراہم کنندہ کام کر رہا ہے؟ (سرکٹ بریکر کی حالت) |
| کوٹا          | 15% | کیا اس کی گنجائش باقی ہے؟                           |
| لاگت          | 15% | یہ کتنا مہنگا ہے؟ (سستا = زیادہ اسکور)              |
| رفتار         | 12% | یہ کتنا تیز ہے؟ (کم تاخیر = زیادہ اسکور)            |
| کام سے مطابقت | 8%  | کیا یہ اس نوعیت کے کام میں اچھا ہے؟                 |
| استحکام       | 5%  | کیا اس کی کارکردگی مستقل ہے؟ (کم شرحِ خرابی)        |
| درجہ          | 5%  | اکاؤنٹ کا درجہ (Ultra > Pro > Free)                 |
| دیگر          | 20% | سیاق سے وابستگی، کنکشن کی کثافت وغیرہ               |

### ویریئنٹس اسکورنگ کو کیسے تبدیل کرتے ہیں

ہر ویریئنٹ مختلف وزن استعمال کرتا ہے:

| ویریئنٹ        | ترجیح        | اہم وزن                        |
| -------------- | ------------ | ------------------------------ |
| `auto`         | متوازن       | صحت=20%، کوٹا=15%، لاگت=15%    |
| `auto/coding`  | معیار        | کام سے مطابقت=37%، استحکام=15% |
| `auto/fast`    | رفتار        | تاخیر=32%، صحت=28%             |
| `auto/cheap`   | لاگت         | لاگت=37%                       |
| `auto/smart`   | معیار + تلاش | کام سے مطابقت=37%، تلاش=10%    |
| `auto/offline` | گنجائش       | کوٹا=37%، صحت=28%              |

## یہ ناکامیوں کو کیسے سنبھالتا ہے

OmniRoute میں تحفظ کی **تین سطحیں** ہیں:

### 1. خودکار متبادل

اگر بہترین فراہم کنندہ ناکام ہو جائے تو OmniRoute خودکار طور پر اگلے فراہم کنندہ کو آزماتا ہے۔ آپ کو کچھ کرنے کی ضرورت نہیں۔

### 2. خودکار بحالی

اگر کوئی فراہم کنندہ مسلسل ناکام ہوتا رہے:

- **اسکور < 0.2** → 5 منٹ کے لیے خارج
- **سرکٹ بریکر کھلا ہو** → خودکار طور پر خارج
- **50% سے زیادہ فراہم کنندگان بند ہوں** → ہنگامی صورتِ حال کا موڈ (کوئی تجرباتی انتخاب نہیں)

### 3. ہنگامی متبادل

اگر تمام فراہم کنندگان ناکام ہو جائیں تو OmniRoute آخری حل کے طور پر درخواستوں کو مستحکم مفت فراہم کنندگان (جیسے Kiro یا Qoder) کی طرف بھیجتا ہے۔

---

## متعدد اکاؤنٹس کی معاونت

اگر ایک ہی فراہم کنندہ کے لیے آپ کے متعدد اکاؤنٹس ہوں (مثلاً دو OpenAI کلیدیں)، تو OmniRoute ہر اکاؤنٹ کو ایک **علیحدہ امیدوار** سمجھتا ہے۔ اس کا مطلب ہے:

- اکاؤنٹ A کا کوٹہ باقی ہے → اسے استعمال کریں
- اکاؤنٹ B پر شرح کی حد نافذ ہے → اسے چھوڑ دیں
- اکاؤنٹ C سستا ہے → اسے ترجیح دیں

ہر اکاؤنٹ کو اس کی اپنی صحت، کوٹے اور رفتار کی بنیاد پر آزادانہ طور پر اسکور دیا جاتا ہے۔

---

## بینڈٹ ایکسپلوریشن

OmniRoute بہتر اختیارات دریافت کرنے کے لیے کبھی کبھار نئے فراہم کنندگان کو **آزماتا** ہے:

- **ڈیفالٹ**: 5% درخواستیں بے ترتیب فراہم کنندگان کو بھیجی جاتی ہیں
- **Auto/smart**: آزمائش کی شرح 10%
- جب 50% سے زیادہ فراہم کنندگان غیر صحت مند ہوں تو **غیر فعال**

اس سے OmniRoute کو یہ سیکھنے میں مدد ملتی ہے کہ آپ کے استعمال کے طریقوں کے لیے کون سے فراہم کنندگان بہترین کام کرتے ہیں۔

## عام سوالات

### "کیا یہ ہمیشہ سب سے مہنگا ماڈل منتخب کرے گا؟"

**نہیں۔** ڈیفالٹ طور پر لاگت اسکور کا صرف 15% ہے۔ ایک سستا، تیز اور صحت مند فراہم کنندہ کسی مہنگے فراہم کنندہ سے بہتر ثابت ہو سکتا ہے۔ اگر آپ لاگت کو مزید ترجیح دینا چاہتے ہیں تو `auto/cheap` استعمال کریں۔

### "اگر کوئی فراہم کنندہ بند ہو جائے تو کیا ہوگا؟"

OmniRoute خودکار طور پر اسے چھوڑ کر اگلے فراہم کنندہ کو آزماتا ہے۔ اگر کوئی فراہم کنندہ مسلسل ناکام ہوتا رہے تو اسے عارضی طور پر (5-30 منٹ کے لیے) خارج کر دیا جاتا ہے۔ آپ کو کچھ کرنے کی ضرورت نہیں۔

### "کیا میں دیکھ سکتا ہوں کہ کون سا فراہم کنندہ استعمال ہوا؟"

رسپانس ہیڈرز دیکھیں — OmniRoute ہر رسپانس میں استعمال ہونے والے فراہم کنندہ اور ماڈل کی معلومات شامل کرتا ہے۔

### "کیا یہ میرے استعمال سے سیکھتا ہے؟"

جی ہاں! اسکورنگ سسٹم وقت کے ساتھ بہتر فیصلے کرنے کے لیے تاریخی ڈیٹا (تاخیر، خرابی کی شرحیں اور کامیابی کی شرحیں) استعمال کرتا ہے۔

### "`auto` اور `auto/smart` میں کیا فرق ہے؟"

- `auto` — متوازن، 5% آزمائش
- `auto/smart` — معیار کو اولین ترجیح (`auto/coding` جیسے ہی وزن)، 10% آزمائش

جب آپ بہترین معیار چاہتے ہوں اور کبھی کبھار ہونے والی آزمائش سے مطمئن ہوں تو `auto/smart` استعمال کریں۔

### "کیا میں کسی مخصوص فراہم کنندہ کو لازمی طور پر استعمال کروا سکتا ہوں؟"

جی ہاں! `auto` کے بجائے `priority` حکمتِ عملی والا کومبو استعمال کریں، پھر `model` فیلڈ میں کومبو کا **بالکل درست نام** بھیجیں (مثلاً `model: "my-combo"` — نہ کہ `auto`)۔ تفصیلات کے لیے [تکنیکی حوالہ](../routing/AUTO-COMBO.md) دیکھیں۔

### "یہ راؤنڈ رابن سے کیسے مختلف ہے؟"

راؤنڈ رابن فراہم کنندگان کو ترتیب وار استعمال کرتا ہے۔ آٹو کومبو **ہر فراہم کنندہ کو اسکور** دیتا ہے اور بہترین کو منتخب کرتا ہے۔ یہ زیادہ ذہین ہے — یہ صحت، رفتار، لاگت اور معیار کو مدِنظر رکھتا ہے۔
