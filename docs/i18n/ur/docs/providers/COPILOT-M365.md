`copilot-m365-web` (عرف `m365copilot`) ایک تصدیق شدہ Microsoft 365 Copilot BizChat براؤزر سیشن کے ذریعے `m365.cloud.microsoft/chat` پر OpenAI فارمیٹ کی چیٹ درخواستیں بھیجتا ہے۔ یہ ایک غیر سرکاری انضمام ہے۔

> **Web Cookie فراہم کنندگان کے لیے نئے ہیں؟**
>
> اس فراہم کنندہ سے متعلق مخصوص رہنما ہدایات پر عمل کرنے سے پہلے عمومی سیٹ اپ کے عمل، تصدیقی رہنمائی، حدود اور مسائل کے حل کے لیے **`docs/getting-started/WEB-COOKIE-GUIDE.md`** پڑھیں۔
>
> **اہم:** اس فراہم کنندہ کی اسناد **کوکی نہیں ہیں**۔ `m365.cloud.microsoft` سے
> کوکیز نقل نہ کریں۔ اسناد ایک WebSocket URL کوئری پیرامیٹر اور پاتھ سیگمنٹ ہیں،
> جنہیں DevTools کے Network ٹیب سے حاصل کیا جاتا ہے۔

## پیشگی تقاضے

- `m365.cloud.microsoft/chat` پر BizChat تک رسائی رکھنے والا Microsoft 365 اکاؤنٹ
- DevTools میں WebSocket کا معائنہ کرنے کے لیے Chromium پر مبنی براؤزر (Chrome، Edge)
- M365 Copilot لائسنس (Microsoft 365 کے کئی Business/Enterprise منصوبوں میں شامل)

## اسناد حاصل کرنا (WebSocket طریقہ)

1. `https://m365.cloud.microsoft/chat` پر سائن اِن کریں اور گفتگو شروع کریں۔
2. **DevTools → Network** کھولیں۔
3. **WS** (WebSocket) کے ذریعے فلٹر کریں۔
4. Chathub WebSocket کنکشن پر کلک کریں۔ ایسا URL تلاش کریں جو
   `wss://substrate.office.com/m365Copilot/Chathub/` سے شروع ہوتا ہو۔
5. اس کے **Request URL** سے یہ چیزیں نقل کریں:
   - `access_token` کوئری پیرامیٹر کی قدر (مختصر مدت کے لیے مؤثر JWT)۔
   - `/Chathub/` کے بعد آنے والا Chathub پاتھ سیگمنٹ (مثلاً `<oid>@<tenant>`)۔

مکمل URL کی ساخت یہ ہے:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute میں **Providers → Add Provider** پر جائیں، **Microsoft 365 Copilot
   (BizChat)** منتخب کریں، اور اسناد کو درج ذیل فارمیٹ میں چسپاں کریں:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** اور پھر **Save** پر کلک کریں۔

## اسناد حاصل کرنا (HAR درآمد)

WebSocket URL سے قدریں دستی طور پر نقل کرنے کے بجائے، آپ DevTools کی HAR
فائل برآمد کر سکتے ہیں:

1. **DevTools → Network** کھولیں۔
2. BizChat گفتگو شروع کریں یا جاری رکھیں (اس سے WebSocket کنکشن فعال ہوتا ہے)۔
3. Network پینل میں دائیں کلک کریں اور **Save all as HAR with content** منتخب کریں۔
4. OmniRoute میں فراہم کنندہ کے کنکشن ڈائیلاگ پر **Import .har file** بٹن استعمال کریں۔

OmniRoute، Chathub WebSocket URL کے لیے HAR کو اسکین کرتا ہے، `access_token` اور
`chathubPath` اخذ کرتا ہے، اور اسناد کے فیلڈز کو خودکار طور پر پُر کر دیتا ہے۔ HAR
درآمد JWT کی میعاد ختم ہونے کا وقت ڈی کوڈ کرتی ہے اور ٹوکن کی باقی ماندہ مدت دکھاتی ہے۔

> **کسی حقیقی HAR برآمد، رسائی ٹوکن یا ریفریش ٹوکن کو کبھی commit نہ کریں۔** ٹیسٹ اور
> دستاویزی قدروں میں ہمیشہ پلیس ہولڈرز استعمال کیے جانے چاہییں۔

## ٹوکن کی مدت اور ریفریش

`access_token` مختصر مدت کے لیے مؤثر ہوتا ہے (عام طور پر **~75 منٹ**)۔ میعاد ختم ہونے کے بعد، فراہم کنندہ
کنکشن کی خرابی رپورٹ کرتا ہے اور آپ کو اسناد دوبارہ حاصل کرنا ہوں گی۔

### `refreshToken` کے ساتھ خودکار ریفریش

دستی طور پر دوبارہ اسناد حاصل کرنے سے بچنے کے لیے، آپ کنکشن کی
**Advanced Settings → providerSpecificData** میں Microsoft ریفریش ٹوکن محفوظ کر سکتے ہیں:

| فیلڈ           | وضاحت                                                                  |
| -------------- | ---------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` اسکوپ کے لیے Microsoft OAuth ریفریش ٹوکن |
| `tier`         | `individual` (ڈیفالٹ)، `edu`، یا `enterprise`                          |

Microsoft کے device-code یا authorization-code فلو سے ریفریش ٹوکن حاصل کریں،
جس کا اسکوپ `substrate.office.com/sydney` ہو۔ `refreshToken` سیٹ ہونے پر، OmniRoute
ہر درخواست سے پہلے `access_token` کو پیشگی ریفریش کرتا ہے، اس لیے آپ کو
ہر ~75 منٹ کی میعاد ختم ہونے کے بعد دوبارہ اسناد حاصل کرنے کی ضرورت نہیں ہوتی۔

اگر `refreshToken` سیٹ نہ ہو تو ہر بار میعاد ختم ہونے کے بعد آپ کو WebSocket اسناد
دستی طور پر دوبارہ حاصل کرنا ہوں گی۔

### ٹیئر کا انتخاب

| ٹیئر         | عرف        | سطح                        |
| ------------ | ---------- | -------------------------- |
| `individual` | _(ڈیفالٹ)_ | صارفین کے لیے M365 Copilot |
| `edu`        | `included` | تعلیمی M365 Copilot        |
| `enterprise` | `work`     | کام کے لیے M365 Copilot    |

ٹیئر کو **Advanced Settings → providerSpecificData → tier** میں سیٹ کریں۔ ٹیئر
BizChat کی روٹنگ اور ماڈل تک رسائی کو متاثر کرتا ہے۔

## سیکیورٹی ماڈل

- **غیر سرکاری انضمام۔** یہ فراہم کنندہ BizChat WebSocket پروٹوکول کی ریورس انجینئرنگ
  کرتا ہے۔ Microsoft کی جانب سے endpoint تبدیل کیے جانے پر یہ بغیر اطلاع کے کام کرنا بند کر سکتا ہے۔
- `subscriptionRisk: true` فلیگ ظاہر کرتا ہے کہ یہ انضمام ایک غیر دستاویزی
  endpoint پر انحصار کرتا ہے۔ اکاؤنٹ پر پابندیاں ممکن ہیں، لیکن ان کی تصدیق نہیں ہوئی۔
- access token ایک مختصر مدتی JWT ہے۔ اسے پاس ورڈ کی طرح سمجھیں: اسے commit،
  log یا share نہ کریں۔
- refresh token، BizChat سطح تک طویل مدتی رسائی فراہم کرتا ہے۔ اسے
  API key جتنی ہی احتیاط سے محفوظ کریں۔

## خرابیوں کا ازالہ

### توثیق فوراً ناکام ہو جاتی ہے

- تصدیق کریں کہ آپ نے **WebSocket URL** سے کاپی کیا ہے، نہ کہ کسی XHR/Fetch درخواست سے۔ یہ
  credential، Chathub WebSocket کنکشن کے `access_token` query parameter میں ہوتا ہے —
  `Authorization: Bearer` header میں نہیں۔
- یقینی بنائیں کہ `chathubPath` میں URL
  path سے مکمل `<oid>@<tenant>` حصہ شامل ہے۔

### Token تقریباً 75 منٹ بعد زائد المیعاد ہو جاتا ہے

یہ متوقع رویہ ہے۔ `refreshToken` کے بغیر access token مختصر مدتی ہوتا ہے۔ ان میں سے کوئی ایک طریقہ اختیار کریں:

- DevTools سے credential دوبارہ حاصل کریں، یا
- خودکار refresh کے لیے Advanced Settings میں `refreshToken` ترتیب دیں۔

### Test Connection کامیاب ہوتا ہے لیکن chat میں 401 واپس آتا ہے

ممکن ہے validation اور پہلی request کے درمیان token زائد المیعاد ہو گیا ہو۔ ایک
تازہ credential دوبارہ حاصل کریں۔

### Copilot فراہم کنندگان کی فہرست میں ظاہر نہیں ہوتا

یقینی بنائیں کہ **Dashboard → Providers** میں `copilot-m365-web` فعال ہے۔ بعض tiers میں فراہم کنندہ
بطور ڈیفالٹ پوشیدہ ہو سکتا ہے۔
