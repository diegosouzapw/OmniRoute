## `claude-web`

`claude-web` ایک تصدیق شدہ `claude.ai` براؤزر سیشن کے ذریعے OpenAI فارمیٹ کی چیٹ درخواستیں بھیجتا ہے۔ ایگزیکیوٹر فراہم کردہ کوکی کو نارملائز کرتا ہے، ایک تصدیق شدہ تنظیم کا تعین کرتا ہے، گفتگو کی حالت تیار کرتا ہے، براہِ راست یا براؤزر ٹرانسپورٹ منتخب کرتا ہے، اور اپ اسٹریم SSE جواب کا سختی سے ترجمہ کرتا ہے۔ آرکیسٹریشن `open-sse/executors/claude-web.ts:320` میں ہے۔

> **Web Cookie فراہم کنندگان پہلی بار استعمال کر رہے ہیں؟**
>
> اس فراہم کنندہ سے مخصوص رہنما کی پیروی کرنے سے پہلے عمومی سیٹ اپ کے عمل، تصدیقی رہنمائی، حدود، اور خرابیوں کے ازالے کے لیے **`docs/getting-started/WEB-COOKIE-GUIDE.md`** پڑھیں۔

### ماڈل کیٹلاگ

فراہم کنندہ رجسٹری فی الحال صرف یہ سات جامد ماڈل IDs ظاہر کرتی ہے
(`open-sse/config/providers/registry/claude/web/index.ts:11`):

| ماڈل ID                     | نمائشی نام              |
| --------------------------- | ----------------------- |
| `claude-fable-5`            | Claude Fable 5 (ویب)    |
| `claude-opus-4-8`           | Claude Opus 4.8 (ویب)   |
| `claude-sonnet-5`           | Claude Sonnet 5 (ویب)   |
| `claude-haiku-4-5-20251001` | Claude Haiku 4.5 (ویب)  |
| `claude-opus-4-7`           | Claude Opus 4.7 (ویب)   |
| `claude-opus-4-6`           | Claude Opus 4.6 (ویب)   |
| `claude-sonnet-4-6`         | Claude Sonnet 4.6 (ویب) |

اس فراہم کنندہ کے لیے متحرک ماڈل دریافت نافذ نہیں کی گئی۔ مذکورہ بالا فہرست رن ٹائم کیٹلاگ ہے۔

### اسناد اور تنظیم کا تعین

یا تو مکمل `claude.ai` Cookie ہیڈر یا صرف سیشن ویلیو فراہم کریں۔ صرف ویلیو فراہم کرنے پر اسے `sessionKey` میں نارملائز کیا جاتا ہے؛ اگر دیگر کوکیز فراہم کی گئی ہوں تو وہ برقرار رہتی ہیں۔ ایگزیکیوٹر کوکی کو `cookie` یا `apiKey` کے ذریعے قبول کرتا ہے اور کنکشن ڈیٹا سے اختیاری `deviceId` اور `orgId` ویلیوز پڑھتا ہے
(`open-sse/executors/claude-web.ts:72`)۔

اگر `orgId` موجود نہ ہو تو ایگزیکیوٹر `GET https://claude.ai/api/organizations` کو کال کرتا ہے اور تصدیق شدہ Claude Web سیشن کے ذریعے واپس آنے والی پہلی تنظیم استعمال کرتا ہے
(`open-sse/executors/claude-web.ts:141`)۔ کوئی درست تنظیم واپس نہ آنے پر یہ محفوظ طور پر ناکام ہو جاتا ہے، مسترد شدہ سیشن اجازت کو 401 کے طور پر رپورٹ کرتا ہے، اور Cloudflare چیلنج کو تصدیقی ناکامی سے الگ شناخت کرتا ہے۔

### گفتگو کی کارروائیاں

اختیاری ٹاپ لیول `claude_web` آبجیکٹ سخت ہے۔ نامعلوم فیلڈز مسترد کر دی جاتی ہیں۔ اس کی قبول شدہ فیلڈز `open-sse/executors/claude-web/session.ts:50` میں متعین ہیں:

| فیلڈ                  | مطلب                                                                        |
| --------------------- | --------------------------------------------------------------------------- |
| `operation`           | ڈیفالٹ طور پر `completion`؛ دوبارہ کوشش کی باری کے لیے `retry` استعمال کریں |
| `conversation_id`     | موجودہ گفتگو کے لیے واضح UUID                                               |
| `parent_message_uuid` | پیرنٹ اسسٹنٹ پیغام کے لیے واضح UUID                                         |
| `timezone`            | درست IANA ٹائم زون نام                                                      |
| `locale`              | ساختی طور پر درست لوکیل                                                     |
| `tool_states`         | اختیاری اکاؤنٹ ٹول اسٹیٹ ارے، زیادہ سے زیادہ 128 اندراجات                   |

تیار شدہ درخواستیں دو اپ اسٹریم اینڈ پوائنٹس میں سے ایک استعمال کرتی ہیں
(`open-sse/executors/claude-web.ts:203`):

- نئی یا فالو اپ باری
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/completion` پر پوسٹ کی جاتی ہے۔
- دوبارہ کوشش
  `POST https://claude.ai/api/organizations/{orgId}/chat_conversations/{conversationId}/retry_completion` پر پوسٹ کی جاتی ہے۔

نئی باری میں `create_conversation_params` شامل ہوتا ہے۔ کیش شدہ یا واضح طور پر لنک شدہ فالو اپ میں `parent_message_uuid` شامل ہوتا ہے اور `create_conversation_params` شامل نہیں ہوتا۔ دوبارہ کوشش کے لیے گفتگو اور پیرنٹ پیغام، دونوں کی حالت درکار ہوتی ہے اور کوئی پرامپٹ نہیں بھیجا جاتا
(`open-sse/executors/claude-web/session.ts:254`)۔ نئی گفتگوئیں تصدیق شدہ UI کو `/new` پر کھولتی ہیں؛ کیش شدہ یا واضح طور پر لنک شدہ فالو اپ عین گفتگو کا صفحہ کھولتے ہیں
(`open-sse/executors/claude-web/session.ts:324`)۔

گفتگو کی حالت ایک اِن میموری کیش ہے جس کی کلید SHA-256 اکاؤنٹ اسکوپ اور کالر کا کینونیکل ٹرانسکرپٹ ہے۔ اندراجات 30 منٹ بعد زائد المیعاد ہو جاتے ہیں اور کیش زیادہ سے زیادہ 5,000 اندراجات تک محدود ہے
(`open-sse/executors/claude-web/session.ts:12`)۔ حالت صرف اس وقت کمٹ کی جاتی ہے جب سخت اسٹریم پارسر `message_stop` کا مشاہدہ کرے؛ پراسیس دوبارہ شروع ہونے پر یہ ضائع ہو جاتی ہے۔ کیش مِس ہونے کی صورت میں، متعدد پیغامات والی درخواست کو سابقہ پیغامات خاموشی سے حذف کرنے کے بجائے ایک ریکوری پرامپٹ میں سیریلائز کیا جاتا ہے۔

لوکیل اور ٹائم زون کے لیے ترجیح کی یہ ترتیب استعمال ہوتی ہے: درخواست کی `claude_web` ویلیو، کنکشن ویلیو، رن ٹائم ویلیو، پھر لوکیل کے لیے `en-US` یا ٹائم زون کے لیے `UTC`
(`open-sse/executors/claude-web/session.ts:218`)۔

### ٹولز اور درخواست کے پے لوڈز

براہِ راست درخواستیں صرف کالر کے فراہم کردہ، ساختی طور پر درست OpenAI فنکشن ٹولز کو تبدیل کرتی ہیں۔ کوئی من گھڑت جامد ڈیفالٹ ٹول فہرست موجود نہیں ہے
(`open-sse/executors/claude-web/payload.ts:102`)۔

اس کے برعکس، براؤزر درخواستیں تصدیق شدہ UI درخواست کو کیپچر کرتی ہیں اور اس کے اکاؤنٹ ٹولز، ٹول اسٹیٹس، اور ذاتی نوعیت کے اسٹائلز برقرار رکھتی ہیں۔ تیار شدہ گفتگو، ماڈل، استدلال، پرامپٹ، اور پیغام UUID فیلڈز پھر بھی کیپچر شدہ درخواست کو اوور رائیڈ کرتی ہیں
(`open-sse/executors/claude-web/browserTransport.ts:175`)۔ براؤزر ٹیمپلیٹس کا اسکوپ اکاؤنٹ، تنظیم، کوکی، لوکیل، اور ٹائم زون کے ہیش کے ذریعے متعین ہوتا ہے اور وہ 30 منٹ بعد زائد المیعاد ہو جاتے ہیں
(`open-sse/executors/claude-web/browserTransport.ts:11`,
`open-sse/executors/claude-web/browserTransport.ts:158`)۔ جب کسی براہِ راست درخواست میں کالر ٹولز نہ ہوں تو وہ اس اسکوپ شدہ ٹیمپلیٹ کو دوبارہ استعمال کر سکتی ہے؛ واضح کالر ٹولز کو ترجیح حاصل ہوتی ہے
(`open-sse/executors/claude-web/browserTransport.ts:214`)۔

### ٹرانسپورٹ کا انتخاب

ڈیفالٹ راستہ `sendClaudeWebDirect()` ہے، جو تشکیل کردہ Chrome 146 پروفائل اور فراہم کردہ کوکی کے ساتھ `tlsFetchClaude()` کو کال کرتا ہے (`open-sse/services/claudeTlsClient.ts:23`)۔ یہ کوئی سالور لانچ نہیں کرتا اور نہ ہی متبادل کوکی تیار کرتا ہے۔

اکاؤنٹ کے دائرۂ کار والے براؤزر اڈاپٹر کو بنیادی ٹرانسپورٹ بنانے کے لیے `WEB_COOKIE_USE_BROWSER` کو `1`، `true`، یا `on` پر سیٹ کریں۔ کسی شناخت شدہ Cloudflare 403 چیلنج کی صورت میں براہِ راست ٹرانسپورٹ سے براؤزر اڈاپٹر پر فال بیک کی اجازت دینے کے لیے `OMNIROUTE_BROWSER_POOL` کو انہی اقدار میں سے کسی ایک پر سیٹ کریں (`open-sse/executors/claude-web.ts:195`)۔ دیگر HTTP ناکامیاں اس فال بیک کو متحرک نہیں کرتیں۔

براؤزر اڈاپٹر کوکیز کو اسی مشترکہ Playwright کانٹیکسٹ میں رکھتا ہے، اوپر بیان کردہ دائرۂ کار والی ہیش شدہ کلید استعمال کرتا ہے، اور اسی کانٹیکسٹ سے تکمیل بھیجتا ہے (`open-sse/executors/claude-web/browserTransport.ts:444`)۔ یہ براؤزر کے ذریعے حل کی گئی کوکی کو کبھی بھی براہِ راست TLS کلائنٹ میں برآمد نہیں کرتا۔ براؤزر کی دوبارہ کوششوں کے لیے ایک غیر زائدالمیعاد UI ٹیمپلیٹ درکار ہوتا ہے جو اسی حقیقی Playwright کانٹیکسٹ سے منسلک ہو (`open-sse/executors/claude-web/browserTransport.ts:467`)۔ براؤزر کے جوابی مطالعے تصدیق شدہ صفحے میں تدریجی طور پر چلتے ہیں، درخواست کی منسوخی کا احترام کرتے ہیں، اور جیسے ہی اپ اسٹریم باڈی 16 MiB سے تجاوز کرے، اسے منسوخ کر دیتے ہیں (`open-sse/executors/claude-web/browserTransport.ts:259`)۔

ایگزیکیوٹر مشترکہ درخواست لاگر کو ایک مخفی کردہ آڈٹ پروجیکشن واپس کرتا ہے: تنظیم، گفتگو اور پیغام کے UUIDs، پرامپٹ متن، ٹول کی تعریفیں، کوکیز، اور ڈیوائس شناخت کار خارج کر دیے جاتے ہیں (`open-sse/executors/claude-web.ts:237`،
`open-sse/executors/claude-web.ts:252`)۔ ٹرانسپورٹ استثنا بھی پھینکے گئے پیغام کے بجائے ایک عمومی کنکشن خرابی واپس کرتے ہیں۔

### SSE کا طرزِ عمل

`createClaudeWebResponse()`، LF یا CRLF فریمنگ اور متعدد سطروں والے `data:` فیلڈز کو سنبھالتا ہے۔ یہ متنی ڈیلٹاز کو `content`، تفکری ڈیلٹاز کو `reasoning_content`، اور معلوم میٹا ڈیٹا ایونٹس کو `claude_web` جوابی ایکسٹینشن سے میپ کرتا ہے۔ ہر میٹا ڈیٹا ایونٹ کو اس کے اپنے فیلڈ الاؤ لسٹ کے ذریعے پروجیکٹ کیا جاتا ہے (`open-sse/executors/claude-web/stream.ts:37`)۔ گفتگو، پیرنٹ پیغام، اسسٹنٹ پیغام، اور آپریشن کا میٹا ڈیٹا بھی `X-OmniRoute-Claude-Web-*` ہیڈرز میں واپس کیا جاتا ہے (`open-sse/executors/claude-web/stream.ts:364`)۔

خراب JSON، اپ اسٹریم `error` ایونٹس، نامعلوم ایونٹ اقسام، غلط ترتیب، مواد کے بلاکس میں عدم مطابقت، یا `message_stop` سے پہلے EOF کی صورت میں پارسر محفوظ انداز میں ناکام ہو جاتا ہے۔ اسٹریمنگ آؤٹ پٹ ایک اختتامی چنک اور ایک `[DONE]` خارج کرتا ہے؛ بفر شدہ آؤٹ پٹ بھی یہی پارسر استعمال کرتا ہے۔ پارسر `message_stop` کو فوراً اختتامی تصور کرتا ہے، بعد میں آنے والا اپ اسٹریم ڈیٹا منسوخ کرتا ہے، اور ڈاؤن اسٹریم منسوخی کو اپ اسٹریم ریڈر تک منتقل کرتا ہے (`open-sse/executors/claude-web/stream.ts:461`،
`open-sse/executors/claude-web/stream.ts:563`)۔ نامکمل SSE سطروں اور جمع شدہ ایونٹس کی حد 1 MiB مقرر ہے (`open-sse/executors/claude-web/stream.ts:17`،
`open-sse/executors/claude-web/stream.ts:62`)۔
