`chatgpt-web-codex` (عرف `cgpt-codex`) ایک تصدیق شدہ ChatGPT براؤزر سیشن کے ذریعے Codex Responses کے ٹرنز کو مربوط کرتا ہے۔ یہ ریٹائر شدہ مشترکہ
`chatgpt-web` فراہم کنندہ سے آزاد ہے اور
`open-sse/vendor/codex-chatgpt-web/` کے تحت MIT نوٹس کے حامل نفاذ کو استعمال کرتا ہے، جسے upstream v4.0.7 commit
`b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` کے ذریعے تازہ کیا گیا ہے۔

## مشترکہ فراہم کنندہ کی ریٹائرمنٹ

سابقہ مشترکہ فراہم کنندہ IDs `chatgpt-web` اور `cgpt-web` اب شامل نہیں کیے جاتے کیونکہ ان کے pre-key/proof-of-work نفاذ کی اصل نسبت کی توثیق نہیں کی جا سکی۔ دونوں میں سے کسی بھی ID کے لیے واضح درخواستیں، بشمول slash-prefixed model IDs اور محفوظ شدہ aliases، کسی بھی upstream درخواست سے پہلے HTTP `410` اور کوڈ **PROVIDER_RETIRED** کے ساتھ بند حالت میں ناکام ہو جاتی ہیں۔

Migration `168_retire_chatgpt_web.sql` مماثل فراہم کنندہ کنکشنز کو tombstone کرتی ہے اور ان کے فعال session leases کو غیر مؤثر بناتی ہے۔ یہ کنکشن کی تاریخ اور API-key allowlists کو محفوظ رکھتی ہے؛ یہ کسی allowlist میں متبادل رسائی شامل نہیں کرتی۔ Codex فراہم کنندہ اور اس کے کنکشنز اس ریٹائرمنٹ سے مماثل نہیں ہوتے۔

## پیشگی تقاضے

- سائن اِن شدہ ChatGPT سیشن سے ایک مکمل Cookie header؛
- npm، systemd، اور PM2 تنصیبات کے لیے Chrome یا Chromium کے ساتھ ایک گرافیکل سیشن یا Xvfb display؛
- Docker `web` پروفائل کے ساتھ، `docker-compose.yml` سے داخلی Chromium سروس؛
- مقامی Codex ٹولز کے لیے OpenAI `tunnel-client` v0.0.13 اور ایک ChatGPT custom connector۔

tunnel صرف ٹول ٹرنز کے لیے درکار ہے۔ درج کردہ ہر route، بشمول `pro`، tunnel اور connector کی ترتیب مکمل ہونے پر اسی ٹرن سے منسلک مقامی ٹول کی صلاحیت استعمال کر سکتا ہے۔

## ڈیش بورڈ سیٹ اپ

1. **ChatGPT Web (Codex)** فراہم کنندہ کھولیں اور ایک کنکشن شامل کریں۔
2. مکمل ChatGPT Cookie header، tunnel ID، runtime key، اور custom connector کا نام پیسٹ کریں۔ نئے ٹول کی صلاحیت رکھنے والے سیٹ اپس کو لازماً ایک نیا بنایا ہوا connector استعمال کرنا چاہیے جس کا نام بالکل `OmniRoute Codex v2` ہو، جس میں Authentication کو None اور Permissions کو Allow all actions پر سیٹ کیا گیا ہو۔
3. کنکشن چیک چلائیں۔ OmniRoute براؤزر کی مدد سے چلنے والی Temporary Chat کھولتا ہے اور معلوم کرتا ہے کہ اکاؤنٹ کے لیے Sol اور Pro دستیاب ہیں یا نہیں۔
4. کنکشن محفوظ کریں۔ OmniRoute پیسٹ کردہ cookie کو تصدیق شدہ Playwright storage state سے بدل دیتا ہے اور اسے encrypted credential abstraction کے ذریعے runtime key کے ساتھ محفوظ کرتا ہے۔

کامیابی سے محفوظ کیے جانے کے بعد خام cookie برقرار نہیں رکھی جاتی۔ سیشن کی میعاد ختم ہونے پر، کنکشن کھولیں، ایک تازہ مکمل Cookie header پیسٹ کریں، اور چیک دوبارہ چلائیں۔ ترمیمی ڈائیلاگ میں doctor status براؤزر، storage state، sign-in، Temporary Chat، tunnel، connector، اور ٹول کے round-trip کی الگ الگ رپورٹ دیتا ہے۔

> کسی حقیقی cookie، runtime key، storage state، یا capability token کو کبھی commit نہ کریں۔ ٹیسٹ اور
> دستاویزی اقدار ہمیشہ placeholders ہونی چاہییں۔

## ماڈلز اور combos

مقررہ model routes یہ ہیں:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna، کم کوشش
- `chatgpt-web-codex/think` — GPT-5.6 Luna، درمیانی کوشش
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

ان میں سے کسی ایک کو کسی بھی دوسرے model کی طرح ایک combo میں شامل کریں۔ Codex ایپ combo کا نام باقاعدہ Responses endpoint، `/v1/responses`، کو `model` کے طور پر بھیجتی ہے؛ کوئی الگ Codex endpoint یا mode switch موجود نہیں ہے۔

Free/Go اکاؤنٹس Luna routes فراہم کرتے ہیں۔ Sol کی صلاحیت رکھنے والے اکاؤنٹس Instant سے High تک فراہم کرتے ہیں، اور Pro کی صلاحیت رکھنے والے اکاؤنٹس اضافی طور پر Extra High اور Pro فراہم کرتے ہیں۔ ہر route کا backend model اور reasoning effort مقرر ہوتا ہے؛ متصادم واضح Responses effort، منتخب کردہ براؤزر موڈ کو خاموشی سے تبدیل کرنے کے بجائے بند حالت میں ناکام ہو جاتا ہے۔

کسی پرانے `Codex Native` یا `OmniRoute Codex` connector کا نام تبدیل یا اسے دوبارہ استعمال نہ کریں۔ ChatGPT عوامی MCP contract کو connector identity کے لحاظ سے cache کرتا ہے، جبکہ تازہ کردہ bridge ایک نیا براہِ راست turn-token contract استعمال کرتا ہے۔ runtime ان legacy identities کو مسترد کرتا ہے اور ایک نیا `OmniRoute Codex v2` connector درکار قرار دیتا ہے۔

## سیکیورٹی ماڈل

- مقامی راستے کے لیے ایک Responses درخواست، ایک تسلیم شدہ Codex کلائنٹ، اور مماثل
  تھریڈ اور ٹرن شناختیں درکار ہیں۔
- ورک اسپیس، سینڈ باکس، منظوری کی پالیسی، اور ٹول کیٹلاگ مقامی Codex شیل سے آتے ہیں؛
  آزاد متن پر مشتمل پرامپٹ ان کے لیے بااختیار نہیں ہے۔
- ChatGPT کو ہر ٹرن کے لیے صرف ایک قلیل مدتی صلاحیتی ٹوکن ملتا ہے۔ MCP بروکر صرف وہی
  ٹولز قبول کرتا ہے جو Codex نے عین اسی ٹرن میں پیش کیے ہوں۔
- **Allow once** کی خودکار تصدیق صرف ٹول کی درخواست Codex کو واپس کرتی ہے۔ منظوری اور
  عمل درآمد کا فیصلہ صرف Codex کرتا ہے۔
- پہلی آؤٹ پٹ سے پہلے، کوئی کومبو کسی دوسرے موافق ہدف پر واپس جا سکتا ہے۔ آؤٹ پٹ
  شروع ہونے کے بعد، فراہم کنندہ، ماڈل، کنکشن، اور براؤزر ٹرن، ٹرن مکمل ہونے تک مقرر رہتے ہیں۔
- کوکیز، رن ٹائم کیز، اسٹوریج اسٹیٹ، اور صلاحیتی ٹوکن فراہم کنندہ کے
  جوابات یا درخواست لاگز میں ظاہر نہیں ہوتے۔

## ڈسپلے کے بغیر VPS اور Docker

npm، systemd، اور PM2 تنصیبات کے لیے، OmniRoute عام Chrome اور Chromium راستوں کا پتا لگاتا ہے۔
متبادل طور پر، `CHATGPT_WEB_CODEX_CHROME_PATH` سیٹ کریں۔ رن ٹائم ٹرن دانستہ طور پر ونڈو والا
Chrome استعمال کرتے ہیں کیونکہ ChatGPT حقیقی ہیڈ لیس براؤزر کی ساخت مسترد کر دیتا ہے۔ لہٰذا ڈسپلے کے بغیر میزبان کو
OmniRoute ایک نجی Xvfb ڈسپلے کے ساتھ چلانا چاہیے؛ صرف Chrome کا راستہ سیٹ کرنے سے ڈسپلے فراہم نہیں ہوتا۔

Docker کا `web` پروفائل اندرونی Compose
نیٹ ورک پر `chatgpt-web-codex-browser` شروع کرتا ہے۔ سائیڈ کار Xvfb کے اندر ونڈو والا Chrome چلاتا ہے، اس لیے کسی طبعی ڈسپلے کی ضرورت نہیں۔ اس کی CDP
پورٹ میزبان پر شائع نہیں کی جاتی۔ محفوظ براؤزر پروفائل والیوم
OmniRoute ڈیٹا والیوم سے الگ ہے، اور براؤزر کو کافی مشترکہ میموری ملتی ہے۔ اندرونی CDP پراکسی
Compose نیٹ ورک کے اندر صرف پورٹ `9223` پر سنتی ہے؛ Chrome سائیڈ کار میں لوپ بیک ہی سے منسلک رہتا ہے۔

`DATA_DIR` کے تحت ایک سپروائزر لیز متعدد OmniRoute پراسیسز کو
ایک ہی ٹنل اور بروکر اسٹیٹ کی ملکیت رکھنے سے روکتی ہے۔ کسی تضاد کی اطلاع ڈاکٹر کے ذریعے دی جاتی ہے۔

## انٹرایکٹو بحالی

خودکار Docker راستے میں میزبان کو دکھائی دینے والی کوئی ونڈو نہیں ہوتی، لیکن Chrome خود نجی
Xvfb ڈسپلے کے اندر ونڈو والا ہوتا ہے۔ جب ChatGPT کو انٹرایکٹو سائن اِن یا چیلنج درکار ہو، تو موجودہ VNC
براؤزر انفراسٹرکچر کو بحالی کے لیے استعمال کیا جا سکتا ہے۔ براؤزر UI اور CDP صرف
لوپ بیک، کسی توثیق شدہ انتظامی کنکشن، یا SSH ٹنل کے ذریعے قابل رسائی رہنے چاہییں؛ معمول کے آپریشن
کے دوران noVNC غیر فعال رہتا ہے۔

## WebSocket فال بیک

جب کسی کومبو میں ChatGPT Web (Codex) شامل ہو، تو Responses WebSocket برج
اپ اسٹریم سے منسلک ہونے سے پہلے HTTP/SSE فال بیک کی درخواست کرتا ہے۔ پھر منتقلی
`/v1/responses` کے ذریعے ہوتی ہے۔
