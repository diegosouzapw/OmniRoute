IDE سیشن کے بغیر Cursor کو OmniRoute کے پیچھے رکھنے کے دو طریقے:

1. **`cursor-api` پرووائیڈر** (کارڈ "Cursor API"، عرف `cua`): ایک API-key
   پرووائیڈر جو Cursor صارف کی API کلید (`crsr_…`، جو
   `https://cursor.com/dashboard/api` پر بنائی جاتی ہے) رکھتا ہے۔ اس کے بعد کوئی بھی OmniRoute کلائنٹ
   معمول کی کوٹا، فال بیک اور لاگنگ تہوں کے ساتھ، `/v1/chat/completions` کے ذریعے
   `cursor-api/<model>` یا `cua/<model>` کے طور پر Cursor ماڈلز تک رسائی حاصل کرتا ہے۔ IDE
   پرووائیڈر (`cursor`، OAuth/IDE سیشن) میں کوئی تبدیلی نہیں کی گئی۔
2. **Cursor CLI پاس تھرو**: Cursor CLI (`agent`) کو OmniRoute کی طرف اشارہ کریں تاکہ
   CLI کی ہر RPC کو OmniRoute API کلید کے ذریعے توثیق کیا جائے، اسے
   `cursor-api` کنکشن کی سند کے ساتھ Cursor کو فارورڈ کیا جائے، اور
   Logs صفحے میں ریکارڈ کیا جائے۔

## کلید کا تبادلہ کیوں کیا جاتا ہے

`api2.cursor.sh` خام `crsr_…` کلید کو Bearer ٹوکن کے طور پر مسترد کرتا ہے (401)۔ Cursor
CLI پہلے کلید کو `/auth/exchange_user_api_key` پر POST کرتا ہے اور ایک سیشن
JWT وصول کرتا ہے جو ایک گھنٹے بعد ختم ہو جاتا ہے؛ واپس آنے والے `refreshToken` میں بھی وہی
`exp` ہوتا ہے، لہٰذا ریفریش کرنے کا مطلب کلید کا دوبارہ تبادلہ کرنا ہے۔
`open-sse/services/cursorApiKeyAuth.ts` یہ تبادلہ انجام دیتا ہے، ہر کلید کے لیے ایک سیشن
ٹوکن کیش کرتا ہے، مدت ختم ہونے سے پانچ منٹ پہلے دوبارہ تبادلہ کرتا ہے، اور Cursor کی جانب سے 401
جواب آنے پر کیش شدہ ٹوکن ہٹا دیتا ہے۔ `CursorExecutor`، `cursor-api` کنکشنز کے لیے
اپ اسٹریم اسٹریم کھولنے سے عین پہلے اسے کال کرتا ہے۔

## `cursor-api` پرووائیڈر

رجسٹری: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`، `authType: "apikey"`، وہی `format`، `baseUrl` اور
`models` جو `cursor` کے ہیں)۔ کیٹلاگ کارڈ:
`src/shared/constants/providers/apikey/specialty-media.ts`۔ ایگزیکیوٹر میپ:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`)۔

ڈیش بورڈ: Providers → Cursor API → Add API key۔

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

پھر:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

نوٹس:

- `cursor-api` کے لیے ماڈل فہرست جامد Cursor رجسٹری سے آتی ہے (یہی وہ
  فہرست ہے جسے IDE پرووائیڈر فال بیک کے طور پر استعمال کرتا ہے)؛ OmniRoute ہوسٹ پر
  `cursor-agent` انسٹال کرنے کی ضرورت نہیں۔
- `POST /api/providers/{id}/refresh-cursor` صرف `cursor` IDE پرووائیڈر
  کے لیے ہے؛ `cursor-api` کنکشنز میں تجدید کے لیے کوئی IDE سیشن نہیں ہوتا۔

## Cursor CLI پاس تھرو

روٹ: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`۔ سابقہ `/api/cursor-cli/` کو
`src/shared/constants/publicApiRoutes.ts` میں رجسٹر کیا گیا ہے کیونکہ ہینڈلر
اپنی توثیق خود نافذ کرتا ہے:

| راستہ                                                                                                                      | CLI سے متوقع توثیق           | OmniRoute کیا کرتا ہے                                                                                                                                                    |
| -------------------------------------------------------------------------------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                         | `Bearer <OmniRoute API key>` | کلید کی توثیق کرتا ہے، 1 گھنٹے کا HS256 JWT بناتا ہے (`JWT_SECRET` سے دستخط شدہ) اور اسے واپس کرتا ہے                                                                    |
| ہر دوسرا راستہ (`/aiserver.v1.*`، `/agent.v1.AgentService/RunSSE`، `/aiserver.v1.BidiService/BidiAppend`، `/v1/traces`، …) | `Bearer <that JWT>`          | اجرا کنندہ/سامع/میعاد کی توثیق کرتا ہے، ایک فعال `cursor-api` کنکشن منتخب کرتا ہے، Authorization ہیڈر کو تبادلہ شدہ Cursor ٹوکن سے بدلتا ہے اور جواب واپس اسٹریم کرتا ہے |

CLI موصول ہونے والے ہر ٹوکن سے `exp` ڈی کوڈ کرتا ہے، اس لیے اسے ایک مبہم
ٹوکن دینے سے وہ تقریباً ہر درخواست سے پہلے دوبارہ تبادلہ کرتا ہے؛ بنایا گیا JWT اس سے
بچاتا ہے۔ OmniRoute کی جانب سے 401 آنے پر CLI دوبارہ تبادلہ کرتا ہے۔

### سیٹ اپ

1. ایک OmniRoute API کلید (Dashboard → API keys) اور ایک `cursor-api`
   کنکشن بنائیں۔
2. CLI کو agent اسٹریم کے لیے HTTP/1.1 استعمال کرنے کی ہدایت دیں۔
   `~/.cursor/cli-config.json` میں:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   اس کے بغیر CLI، agent ٹرن کو HTTP/2 کے ذریعے ایک علیحدہ
   ترتیب شدہ agent ہوسٹ پر کھولتا ہے اور صرف کنٹرول پلین RPCs ہی
   اینڈ پوائنٹ سے گزرتی ہیں۔

3. OmniRoute کے مقابل CLI چلائیں:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ہر ہاپ Logs میں پرووائیڈر `cursor-api`، درخواست کی قسم `cursor-cli`،
راستہ `/api/cursor-cli/<rpc>` کے طور پر آتا ہے، اور اسے OmniRoute API کلید اور اسے
فراہم کرنے والے کنکشن سے منسوب کیا جاتا ہے۔

### ناکامی کی صورتیں

| صورتِ حال                                         | CLI کو جواب                                        |
| ------------------------------------------------- | -------------------------------------------------- |
| نامعلوم OmniRoute کلید اور `REQUIRE_API_KEY=true` | تبادلے پر 401 `unauthenticated`                    |
| `REQUIRE_API_KEY=false`                           | گمنام سیشن (`/v1/*` کے طرزِ عمل کے مطابق)          |
| میعاد ختم شدہ / خارجی / تبدیل شدہ سیشن JWT        | 401، CLI دوبارہ تبادلہ کرتا ہے                     |
| تبادلے کے بعد OmniRoute API کلید منسوخ کر دی گئی  | اگلی RPC پر 401                                    |
| کوئی فعال `cursor-api` کنکشن نہیں                 | 503 `unavailable`                                  |
| Cursor کنکشن کی کلید مسترد کرتا ہے                | 401 `unauthenticated`، کیش شدہ سیشن حذف کر دیا گیا |
| اپ اسٹریم ناقابلِ رسائی                           | 502 `unavailable` (صاف کیا گیا پیغام)              |
| `JWT_SECRET` سیٹ نہیں ہے                          | تبادلے پر 503                                      |
