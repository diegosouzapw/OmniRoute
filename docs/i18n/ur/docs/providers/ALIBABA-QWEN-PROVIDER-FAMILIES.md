یہ دستاویز
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854) کے لیے نفاذ کے فیصلے کو ریکارڈ کرتی ہے۔ عوامی مصنوعات کو
چار فراہم کنندہ خاندانوں کی صورت میں پیش کیا گیا ہے۔ خطہ کنکشن کا ڈیٹا ہے، کوئی علیحدہ مصنوعہ نہیں۔

## فیصلہ

| فراہم کنندہ خاندان                                | OmniRoute ID            | عالمی خطہ | چین کا خطہ |
| ------------------------------------------------- | ----------------------- | --------- | ---------- |
| Alibaba Cloud Model Studio (حسبِ استعمال ادائیگی) | `alibaba`               | سنگاپور   | بیجنگ      |
| Alibaba Cloud Token Plan                          | `bailian-coding-plan`   | سنگاپور   | بیجنگ      |
| Qwen Cloud (حسبِ استعمال ادائیگی)                 | `qwen-cloud`            | عالمی     | بیجنگ      |
| Qwen Cloud Token Plan                             | `qwen-cloud-token-plan` | سنگاپور   | بیجنگ      |

موجودہ `alibaba-cn` ID محفوظ شدہ کنکشنز، ماڈل
روٹس، کومبوز اور سابقہ استعمال کے لیے رن ٹائم مطابقتی عرف کے طور پر برقرار ہے۔ اس کا ڈیش بورڈ کارڈ `alibaba` میں ضم کر دیا گیا ہے؛ ڈیٹابیس کو
دوبارہ لکھنے کی ضرورت نہیں ہے۔

Qwen Cloud کا حسبِ استعمال ادائیگی ماڈل اور Alibaba Cloud Model Studio فی الحال DashScope سے مطابقت رکھنے والے
رن ٹائم ہوسٹس کا اشتراک کرتے ہیں، لیکن یہ علیحدہ فراہم کنندہ شناختیں برقرار رکھتے ہیں کیونکہ صارفین مختلف پروڈکٹ انٹرفیسز کے ذریعے کلیدیں حاصل کرتے اور
اکاؤنٹس کا نظم کرتے ہیں۔ Alibaba اور Qwen Cloud Token Plan مصنوعات مختلف
اینڈ پوائنٹ خاندان استعمال کرتی ہیں، اس لیے چاروں مصنوعات علیحدہ فراہم کنندہ IDs کے طور پر برقرار رہتی ہیں۔

## اینڈ پوائنٹ میٹرکس

| فراہم کنندہ خاندان      | `global-sg`                                                              | `china-beijing`                                                      | وائر فارمیٹ |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ----------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic   |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI      |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI      |

API کلید اور اینڈ پوائنٹ کا تعلق ایک ہی مصنوعہ اور خطے سے ہونا چاہیے۔ کسی خطے کا انتخاب
توثیق اور معمول کی درخواستوں کے لیے استعمال ہونے والے پیش سیٹ اینڈ پوائنٹ کو تبدیل کر دیتا ہے۔

## کنکشن معاہدہ

نئے کنکشنز مستحکم خطے کی کلید کو `providerSpecificData` میں محفوظ کرتے ہیں:

```json
{
  "region": "global-sg"
}
```

مجاز اقدار `global-sg` اور `china-beijing` ہیں۔ اینڈ پوائنٹ مرکزی طور پر
فراہم کنندہ ID اور خطے سے اخذ کیا جاتا ہے۔ غیر پیش سیٹ `providerSpecificData.baseUrl` ایک واضح آپریٹر
اوور رائیڈ کے طور پر برقرار رہتا ہے اور اسے ترجیح حاصل ہوتی ہے، جبکہ پرانے محفوظ شدہ پیش سیٹ URLs کو دوبارہ علاقائی
میٹرکس کے مطابق معمول پر لایا جاتا ہے۔

اس سے کنکشن اسکیما قابلِ توسیع رہتا ہے: ریزالور میں کوئی دوسرا خطہ
نیا فراہم کنندہ کارڈ بنائے یا محفوظ شدہ فراہم کنندہ IDs تبدیل کیے بغیر شامل کیا جا سکتا ہے۔

## مطابقت اور اجرا

1. علاقائی endpoint resolver شامل کریں اور موجودہ عالمی defaults برقرار رکھیں۔
2. `alibaba`، اس کی `alibaba-cn` مطابقتی ID، اور `qwen-cloud` کے لیے براہِ راست علاقائی DashScope `/models` دریافت استعمال کریں۔ ان کے responses پہلے ایک text-generation filter سے گزرتے ہیں کیونکہ عمومی endpoint image، video، audio، embedding، اور دیگر non-chat models بھی واپس کرتا ہے۔ اس کے بعد `qwen-cloud` اپنی provider registry میں اعلان کردہ برقرار رکھی گئی allowlist لاگو کرتا ہے۔ Alibaba Model Studio اور Qwen Cloud الگ الگ مرتب کردہ catalogs برقرار رکھتے ہیں، اگرچہ فی الحال وہ یکساں runtime hosts استعمال کرتے ہیں۔
3. موجودہ Token Plan text-model allowlist کے ساتھ `qwen-cloud-token-plan` رجسٹر کریں۔
4. connections شامل/ترمیم کرنے کے dialogs میں typed region selector شامل کریں۔
5. نقل شدہ `alibaba-cn` card چھپائیں اور اس کے موجودہ connections کو `alibaba` provider page پر شامل کریں۔
6. advanced اور workspace-specific deployments کے لیے custom endpoint overrides دستیاب رکھیں۔

Token Plan media models، chat catalog سے باہر رہتے ہیں کیونکہ وہ مخصوص endpoints استعمال کرتے ہیں۔
`wan2.7-image` اور `wan2.7-image-pro`، `open-sse/config/imageRegistry.ts` میں رجسٹرڈ ہیں؛
`happyhorse-1.1-i2v`، `happyhorse-1.1-t2v`، اور `happyhorse-1.1-r2v`،
`open-sse/config/videoRegistry.ts` میں رجسٹرڈ ہیں۔ دونوں registries، `qwen-cloud-token-plan` کی connection
شناخت اور اس کے region-specific credentials دوبارہ استعمال کرتی ہیں۔

معمول کے Qwen Cloud میں `qwen-cloud` شناخت کے تحت الگ pay-as-you-go image اور video catalogs موجود ہیں۔
اس کے image models یہ ہیں: `wan2.7-image-pro`، `wan2.7-image`، `qwen-image-3.0-pro`،
`qwen-image-2.0-pro-2026-06-22`، `qwen-image-2.0-2026-03-03`، اور `z-image-turbo`۔ اس کے video
models یہ ہیں: `happyhorse-1.1-i2v`، `happyhorse-1.1-t2v`، `happyhorse-1.1-r2v`،
`happyhorse-1.0-video-edit`، `wan2.7-t2v`، `wan2.7-i2v`، `wan2.7-r2v-2026-06-12`، اور
`wan2.7-videoedit`۔ یہ models صرف معمول کے `qwen-cloud` connection اور علاقائی
DashScope media endpoint کو دوبارہ استعمال کرتے ہیں۔ Token Plan اور pay-as-you-go registries ایک دوسرے کی
model lists نہ inherit کرتی ہیں اور نہ merge کرتی ہیں۔

`bailian-coding-plan` شناخت کی اپنی media allowlists بھی ہیں:
image generation کے لیے `wan2.7-image`، `wan2.7-image-pro`، `qwen-image-2.0`، اور
`qwen-image-2.0-pro`، نیز video generation کے لیے
`happyhorse-1.1-i2v`، `happyhorse-1.1-t2v`، اور `happyhorse-1.1-r2v`۔
یہ صرف Bailian Coding Plan connection اور علاقائی Coding Plan endpoint استعمال کرتی ہے۔
اس کی image اور video registries، Qwen Cloud کے کسی بھی provider سے نہ inherit کرتی ہیں اور نہ merge ہوتی ہیں۔

معمول کی `alibaba` شناخت کی الگ image اور video allowlists ہیں۔ اس کے image models یہ ہیں:
`qwen-image-3.0-pro`، `qwen-image-2.0-pro-2026-06-22`، `qwen-image-2.0`،
`z-image-turbo`، اور `wan2.6-t2i`۔ اس کے شامل کردہ video models یہ ہیں: `happyhorse-1.1-i2v`،
`happyhorse-1.1-t2v`، `happyhorse-1.1-r2v`، `happyhorse-1.0-video-edit`،
`wan2.7-i2v-2026-04-25`، `wan2.6-i2v-flash`، `wan2.7-t2v-2026-06-12`،
`wan2.7-r2v-2026-06-12`، اور `wan2.7-videoedit`۔ یہ models صرف Alibaba Model Studio
connection اور اس کے منتخب کردہ علاقائی media endpoint کو استعمال کرتے ہیں؛ انہیں کسی Coding Plan یا Qwen
Cloud registry میں شامل نہیں کیا جاتا۔

Qwen Cloud Token Plan کا chat catalog، Individual plan کی exact-string text allowlist کی پیروی کرتا ہے:
`qwen3.8-max-preview`، `qwen3.7-max`، `qwen3.7-plus`، `qwen3.6-flash`، `glm-5.2`، اور
`deepseek-v4-pro`۔ Wan اور HappyHorse entries الگ image/video generation APIs سے تعلق رکھتی ہیں۔

Alibaba Token Plan اپنے Anthropic-compatible endpoint کے ذریعے یہی چھ موجودہ text-generation model IDs
فراہم کرتا ہے۔ اس کا Singapore option موجودہ `global-sg` region key محفوظ کرتا ہے؛ صرف user-facing label
ان provider families سے مختلف ہے جو اس region کو Global کہتے ہیں۔

معمول کے Qwen Cloud کا chat catalog دانستہ طور پر مکمل live text response سے محدود تر ہے۔ اس کی
برقرار رکھی گئی allowlist، `open-sse/config/providers/registry/qwen-cloud/index.ts` میں موجود ہے؛ live
discovery صرف وہ IDs واپس کرتی ہے جو upstream response اور اس registry list دونوں میں موجود ہوں۔

Alibaba Model Studio بھی اسی live-intersection اصول کی پیروی کرتا ہے، جس کے لیے اس کی آزادانہ طور پر برقرار رکھی گئی
allowlist، `open-sse/config/providers/registry/alibaba/index.ts` میں موجود ہے۔ `alibaba-cn` مطابقتی
provider اسی catalog کو دوبارہ استعمال کرتا ہے، جبکہ discovery کو Beijing endpoint کے خلاف resolve کرتا ہے۔
