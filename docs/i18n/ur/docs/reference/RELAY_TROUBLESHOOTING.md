ریلے (Vercel، Deno، Cloudflare) کسی serverless backend پر upstream کنکشن ختم کرتے ہیں تاکہ OmniRoute فراہم کنندہ کی API key کو سرور کی جانب محفوظ رکھتے ہوئے ایک مستحکم خطے سے egress کر سکے۔ یہ دستاویز ان دو ناکامی کی صورتوں اور ہر ایک کے لیے OmniRoute میں شامل بحالی کے طریقوں کا احاطہ کرتی ہے جن کا آپریٹرز کو پروڈکشن میں سامنا ہوتا ہے۔

## ریلے کی توثیق کیسے محفوظ کی جاتی ہے

جب آپ **ترتیبات → پراکسی پول → ریلے تعینات کریں** سے کوئی ریلے تعینات کرتے ہیں، تو تعیناتی کا عمل ریلے کا توثیقی ٹوکن پراکسی کے `notes` JSON فیلڈ میں محفوظ کرتا ہے:

- اگر `STORAGE_ENCRYPTION_KEY` سیٹ ہو تو ٹوکن `relayAuthEnc` کے طور پر لکھا جاتا ہے
  (محفوظ حالت میں AES کے ذریعے مرموز)۔
- بصورت دیگر، اسے سادہ متن میں `relayAuth` کے طور پر لکھا جاتا ہے۔

درخواست کے وقت `extractRelayAuth(notes)` موجود شکل میں سے کسی ایک کو واپس کرتا ہے، اس لیے ریلے دوبارہ شروع ہونے کے بعد بھی کام کرتا رہتا ہے۔

## ناکامی کی صورت 1 — کلید کی تبدیلی کے بعد ناقابلِ کشائی ٹوکن

**علامت:** وہ ریلے جو پہلے کام کرتے تھے، اب ماحول یا secret-manager میں `STORAGE_ENCRYPTION_KEY` کی تبدیلی کے بعد upstream `401`/توثیقی خرابیاں واپس کرتے ہیں۔ محفوظ شدہ `relayAuthEnc` blob کی اب کشائی نہیں ہو سکتی، اس لیے `extractRelayAuth` خالی اسٹرنگ واپس کرتا ہے اور ریلے کوئی توثیق نہیں بھیجتا۔

**بحالی — اسی جگہ مرمت کریں (دوبارہ تعیناتی کے بغیر):**

1. **ترتیبات → پراکسی پول** کھولیں۔
2. جن ریلے قطاروں میں توثیق موجود نہیں ہوتی، ان پر پیلا `auth missing` بیج اور
   **مرمت کریں** بٹن دکھائی دیتا ہے۔
3. **مرمت کریں** پر کلک کریں۔ OmniRoute
   `POST /api/settings/proxies/[id]/repair-relay` کو کال کرتا ہے، جو:
   - **موجودہ** کلید کے ذریعے `relayAuthEnc` کی کشائی کرتا ہے،
   - سادہ متن `relayAuth` کو دوبارہ `notes` میں لکھتا ہے،
   - `{ repaired: true, mode: "recovered" }` واپس کرتا ہے۔

تعیناتی کی کوئی اسناد دوبارہ درج کیے بغیر ریلے سروس فراہم کرنا دوبارہ شروع کر دیتا ہے۔

یہ صرف اسی صورت میں کام کرتا ہے جب موجودہ `STORAGE_ENCRYPTION_KEY` اب بھی blob کی کشائی کر سکتی ہو۔ اگر آپ نے منتقلی کے **بغیر** کلید تبدیل کی ہے، تو blob ناقابلِ بازیافت ہے۔

## ناکامی کی صورت 2 — ناقابلِ بازیافت ٹوکن (کلید تبدیل ہو چکی ہے)

**علامت:** آپ نے **مرمت کریں** پر کلک کیا اور
`{ repaired: false, mode: "redeploy", status: 409 }` موصول ہوا۔

**بحالی — دوبارہ تعیناتی:**

محفوظ شدہ ٹوکن کو موجودہ کلید کے ذریعے بازیافت نہیں کیا جا سکتا۔ ریلے کو اسی موڈل سے دوبارہ تعینات کریں جسے آپ نے اصل میں استعمال کیا تھا (**ریلے تعینات کریں** مینو → Vercel / Deno / Cloudflare)۔ تعیناتی کا عمل ایک نیا ٹوکن لکھتا ہے (جو موجودہ کلید کے ذریعے مرموز ہوتا ہے) اور قطار کا `auth missing` بیج غائب ہو جاتا ہے۔

UI میں، جب ٹوکن ناقابلِ بازیافت ہو تو **مرمت کریں** بٹن خود ہی دوبارہ تعیناتی کا موڈل کھول دیتا ہے، اس لیے آپ کو اسے دستی طور پر تلاش کرنے کی ضرورت نہیں پڑتی۔

## ناکامی کی صورت 3 — ریلے قابلِ رسائی مگر غیر صحت مند

**علامت:** پراکسی ٹیسٹ (`speed` بٹن) ریلے کو فعال دکھاتا ہے، مگر درخواستیں اب بھی وقفے وقفے سے ناکام ہوتی ہیں۔

OmniRoute کی خودکار جانچ probe کی جانب سے واپس کیے گئے ریلے آگاہی headers چیک کریں
(**ترتیبات → پراکسی پول** اور `relayTested` / `relayAlive` کاؤنٹرز دیکھیں):

- `x-relay-url` — کس ریلے backend نے جواب دیا۔
- `x-relay-mode` — اس درخواست کے لیے `ts` | `bifrost` | `auto`۔
- `x-relay-attempts` — کامیابی سے پہلے کتنے ریلے hops آزمائے گئے۔
- `x-relay-fallback` — جب درخواست ترجیحی backend سے TypeScript ریلے پر واپس منتقل ہوئی تو `true`۔

کم `relayAlive` کے ساتھ `x-relay-fallback` کی بلند شرح کا مطلب ہے کہ sidecar backend غیر صحت مند ہے اور آپ کو یا تو اسے درست کرنا چاہیے یا ریلے backend حکمتِ عملی کو `ts` پر تبدیل کرنا چاہیے (`RELAY_BACKEND_STRATEGY.md` دیکھیں)۔

## API حوالہ

| طریقہ  | راستہ                                     | باڈی                    | کامیابی                                                                                                                                | ناکامی                                                                                             |
| ------ | ----------------------------------------- | ----------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `POST` | `/api/settings/proxies/[id]/repair-relay` | `{ "id": "<proxyId>" }` | دوبارہ اخذ ہونے پر `200 { repaired: true, mode: "recovered" }`؛ سادہ متن پہلے سے موجود ہونے پر `200 { repaired: false, mode: "noop" }` | ناقابلِ بازیافت ہونے پر `409 { mode: "redeploy" }`؛ ریلے کی قسم نہ ہونے پر `400`؛ نہ ملنے پر `404` |

فہرست کا route `GET /api/settings/proxies` ہر آئٹم کے ساتھ راز سے پاک
`relayInfo: { isRelay, authMissing, repairMode }` منسلک کرتا ہے تاکہ dashboard ٹوکن کو کبھی ظاہر کیے بغیر مرمت کی سہولت دکھا سکے۔
