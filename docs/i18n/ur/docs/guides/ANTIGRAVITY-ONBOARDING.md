## 1. Antigravity بمقابلہ Antigravity CLI (agy)

دونوں پرووائیڈرز ایک ہی **Google بیک اینڈ** استعمال کرتے ہیں — یکساں OAuth کلائنٹ، ٹوکن ریفریش، اینڈ پوائنٹس، اور Google اکاؤنٹس۔ فرق صرف یہ ہے کہ آپ کو کون سے ماڈلز نظر آتے ہیں۔

> Google کا آفیشل موازنہ دیکھنے کے لیے [Antigravity CLI کا اعلان](https://antigravity.google/blog/introducing-google-antigravity-cli) ملاحظہ کریں۔

| پہلو                | `antigravity` (IDE)                        | `agy` (CLI)                                               |
| ------------------- | ------------------------------------------ | --------------------------------------------------------- |
| **Google پروڈکٹ**   | Antigravity 2.0 / Antigravity IDE          | Antigravity CLI                                           |
| **بیک اینڈ**        | وہی Google Cloud Code API                  | وہی Google Cloud Code API                                 |
| **OAuth / ٹوکن**    | وہی کلائنٹ، وہی ریفریش                     | وہی کلائنٹ، وہی ریفریش                                    |
| **ماڈل کیٹلاگ**     | جامد منتخب فہرست (OmniRoute میں ہارڈ کوڈڈ) | Google سے `:fetchAvailableModels` کے ذریعے لائیو جانچ شدہ |
| **Claude ماڈلز**    | Sonnet 4.6، Opus 4.6 (ہر ایک کی 4 اقسام)   | Sonnet 4.6، Opus 4.6 (ہر ایک کی 4 اقسام)                  |
| **Gemini نام کاری** | واضح لیبلز (Low/Medium/High)               | اپ اسٹریم IDs (extra-low/low/agent)                       |
| **اضافی ماڈلز**     | `gpt-oss-120b-medium`                      | Google کے اضافی ماڈلز شامل ہو سکتے ہیں                    |
| **ڈیفالٹ استعمال**  | IDE انضمام (VS Code، JetBrains)            | CLI / API رسائی                                           |
| **کوٹا**            | agy کے ساتھ مشترک (وہی Google اکاؤنٹ)      | antigravity کے ساتھ مشترک (وہی Google اکاؤنٹ)             |

**دستیاب ماڈلز (تجربے کے ذریعے تصدیق شدہ، 2026-07-29)**:

- Gemini: 3.6 Flash، 3.5 Flash، 3.1 Pro، 3 Flash، 2.5 Flash (سوچنے کی مختلف سطحوں کے ساتھ)
- Claude: Sonnet 4.6، Opus 4.6 (ہر ایک کی default/low/medium/high اقسام)
- دیگر: GPT-OSS 120B Medium
- **Claude Sonnet 5 دستیاب نہیں ہے** — صرف 4.6 کی اقسام معاونت یافتہ ہیں

**ماڈل کیٹلاگ مختلف کیوں ہے**: Google کے آفیشل بلاگ کے مطابق، Google کا CLI "رفتار اور کم اوورہیڈ کے لیے بہتر بنایا گیا ہے" اور "Gemini ماڈلز کے ساتھ مشترکہ طور پر بہتر بنایا گیا ہے"۔ Web/IDE پروڈکٹ کو "جامعیت کے لیے بہتر بنایا گیا ہے"۔ CLI ماڈلز کو متحرک طور پر دریافت کرنے کے لیے `:fetchAvailableModels` استعمال کرتا ہے، جبکہ IDE ایک جامد منتخب فہرست استعمال کرتا ہے۔

**عملی طور پر**: Gemini ماڈلز کے لیے `agy/` سابقہ استعمال کریں (مثلاً `agy/gemini-3.7-flash-high`)۔ جامد منتخب فہرست کے لیے `antigravity/` استعمال کریں۔ دونوں ایک ہی Google بیک اینڈ تک رسائی حاصل کرتے ہیں، لیکن ماڈلز کے مختلف نام ظاہر کرتے ہیں۔ کوٹا مشترک ہے — کسی بھی پرووائیڈر کا استعمال اسی Google اکاؤنٹ کی حدود میں شمار ہوتا ہے۔

Credits علیحدہ خریدے جاتے ہیں اور معیاری API قیمتوں کے مطابق منہا ہوتے ہیں۔

## 3. projectId کیسے حاصل کریں

ہر antigravity/agy connection کو Google Cloud Code کا `projectId` درکار ہوتا ہے۔ اس کے بغیر `/v1internal:models` endpoint، 404 واپس کرتا ہے۔

### طریقہ A: خودکار (تجویز کردہ)

OmniRoute یہ کام خودکار طور پر انجام دیتا ہے۔ جب آپ Dashboard OAuth کے ذریعے نیا Google account شامل کرتے ہیں:

1. OmniRoute token کو refresh کرتا ہے
2. projectId دریافت کرنے کے لیے `loadCodeAssist` کو call کرتا ہے
3. اگر کوئی project موجود نہ ہو تو اسے بنانے کے لیے `onboardUser` کو call کرتا ہے
4. نیا بنایا گیا projectId حاصل کرنے کے لیے `loadCodeAssist` کو دوبارہ آزماتا ہے
5. اسے database میں محفوظ کرتا ہے

**یہ زیادہ تر accounts کے لیے کام کرتا ہے** — کسی دستی مرحلے کی ضرورت نہیں۔

### طریقہ B: agy CLI کے ذریعے دستی طور پر

اگر خودکار دریافت ناکام ہو جائے (ایسا کب ہوتا ہے، اس کے لیے سیکشن 5 دیکھیں):

```bash
# agy CLI انسٹال کریں (اگر پہلے سے انسٹال نہیں ہے)
npm install -g @anthropic-ai/agy

# اپنے Google account سے لاگ ان کریں
agy login

# وہ account منتخب کریں جسے onboarding درکار ہے
# اس سے Cloud Code registration شروع ہوتی ہے اور ایک projectId تفویض ہوتا ہے
```

`agy login` کامیاب ہونے کے بعد OmniRoute Dashboard میں token کو refresh کریں۔ projectId خودکار طور پر دریافت ہو جائے گا۔

### تصدیق کیسے کریں

database چیک کریں:

```bash
# OmniRoute container کے اندر
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

یا logs چیک کریں:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth ری ڈائریکٹ URI

### مسئلہ

Google OAuth کے لیے ایک درست ری ڈائریکٹ URI درکار ہوتا ہے۔ OmniRoute کا ڈیفالٹ `http://127.0.0.1:20128/callback` (لوپ بیک) استعمال کرتا ہے۔ یہ مقامی بلڈز کے لیے کام کرتا ہے، لیکن **ریموٹ ڈیپلائمنٹس کے لیے ناکام ہو جاتا ہے** (مثلاً، LAN IP کے ذریعے رسائی حاصل کیا جانے والا سرور)۔

Google ان ری ڈائریکٹ URIs کو مسترد کر دیتا ہے جو:

- IP ایڈریس استعمال کرتے ہیں (لازماً `.com`، `.org` وغیرہ پر ختم ہونے والا ڈومین ہونا چاہیے)
- OAuth کلائنٹ کنفیگ میں رجسٹرڈ ری ڈائریکٹ URIs سے مطابقت نہیں رکھتے

### حل

**آپشن A: بلٹ اِن OAuth فلو استعمال کریں (ڈیفالٹ)**

- اس وقت کام کرتا ہے جب آپ `localhost` یا `127.0.0.1` سے OmniRoute تک رسائی حاصل کرتے ہیں
- کسی کنفیگریشن کی ضرورت نہیں

**آپشن B: حسبِ ضرورت OAuth اسناد**

- اپنے انوائرمنٹ میں `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` سیٹ کریں
- اپنی Google OAuth اسناد فراہم کریں:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Google Cloud Console میں `https://your-domain.com/callback` کو ایک مجاز ری ڈائریکٹ URI کے طور پر رجسٹر کریں

**آپشن C: ابتدائی لاگ اِن کے لیے agy CLI استعمال کریں**

- اس مشین پر `agy login` چلائیں جو OmniRoute تک رسائی حاصل کرے گی
- OAuth فلو مقامی طور پر مکمل ہو جاتا ہے اور ٹوکنز محفوظ ہو جاتے ہیں
- Dashboard کے ذریعے کنکشن کو OmniRoute میں درآمد کریں

### حدود

- حسبِ ضرورت OAuth اسناد کے لیے ڈومین نام درکار ہوتا ہے (Google ری ڈائریکٹ URIs کے طور پر IP ایڈریس قبول نہیں کرتا)
- اگر آپ کے پاس ڈومین نہیں ہے، تو اس کے بجائے آپشن A یا C استعمال کریں

## 5. خرابیوں کا ازالہ: جب خودکار سیٹ اپ ناکام ہو جائے

OmniRoute زیادہ تر اکاؤنٹس کے لیے projectId کی دریافت اور آن بورڈنگ خودکار طور پر سنبھالتا ہے۔ جب یہ ناکام ہوتا ہے، تو بنیادی وجہ عموماً ان میں سے ایک ہوتی ہے:

### اکاؤنٹ کا خطہ بلاک ہے

**علامت**: `agy login` یہ پیغام لوٹاتا ہے: "اہلیت کی جانچ ناکام ہو گئی: آپ کا موجودہ اکاؤنٹ Antigravity کے لیے اہل نہیں ہے، کیونکہ یہ فی الحال آپ کے مقام پر دستیاب نہیں ہے۔"

**بنیادی وجہ**: Google اکاؤنٹس میں بیک اینڈ کا ایک "Country Association" فیلڈ ہوتا ہے جو رجسٹریشن کے وقت سیٹ کیا جاتا ہے۔ agy CLI اور Cloud Code API اس فیلڈ کو سختی سے چیک کرتے ہیں — ویب Gemini کے برعکس، جو صرف آپ کا موجودہ IP چیک کرتا ہے۔

> اپنے اکاؤنٹ سے منسلک خطے کو چیک یا تبدیل کرنے کے لیے [Google Country Association Form](https://policies.google.com/country-association-form) ملاحظہ کریں۔

**ویب Gemini کام کیوں کرتا ہے لیکن agy کیوں نہیں**:

- ویب Gemini / Google One: صرف موجودہ IP چیک کرتا ہے (پراکسی کامیاب ہو جاتی ہے)
- agy CLI / Cloud Code API: بیک اینڈ کا Country Association فیلڈ پڑھتا ہے (پراکسی مدد نہیں کرتی)

**حل**:

1. امریکی IP استعمال کرتے ہوئے [Google Country Association Form](https://policies.google.com/country-association-form) ملاحظہ کریں
2. خطہ تبدیل کرنے کی درخواست جمع کروائیں ("I live in a different country" منتخب کریں)
3. Google کی کارروائی اور ای میل اطلاع کے لیے 1-24 گھنٹے انتظار کریں
4. اس کے بعد `agy login` کامیاب ہو جانا چاہیے

### اکاؤنٹ میں Cloud Code پروجیکٹ موجود نہیں

**علامت**: لاگز میں `loadCodeAssist returned no project id` اور `onboardUser failed (400)` دکھائی دیتا ہے۔

**بنیادی وجہ**: اکاؤنٹ کبھی Google Cloud Code کے ساتھ رجسٹر نہیں ہوا، اور خودکار آن بورڈنگ ناکام ہو گئی۔

**حل**: Cloud Code رجسٹریشن شروع کرنے کے لیے `agy login` دستی طور پر چلائیں، پھر OmniRoute Dashboard میں ٹوکن ریفریش کریں۔

### ٹوکن کی میعاد ختم ہو گئی یا اسے منسوخ کر دیا گیا

**علامت**: لاگز میں 401 کی خرابیاں، یا "Token has expired" کے پیغامات۔

**حل**: Dashboard → Providers → agy → ریفریش آئیکن پر کلک کر کے ٹوکن ریفریش کریں۔ اگر ریفریش ٹوکن خود منسوخ ہو چکا ہے، تو آپ کو OAuth کے ذریعے دوبارہ توثیق کرنی ہوگی۔

## فیصلہ سازی کا فلوچارٹ

```
اکاؤنٹ کام نہیں کر رہا؟
│
├─ کیا database میں اس کا projectId موجود ہے؟
│  ├─ ہاں → مسئلہ کہیں اور ہے (token کی میعاد ختم، rate limit، وغیرہ)
│  └─ نہیں ↓
│
├─ کیا اکاؤنٹ کی Country Association کسی محدود region پر سیٹ ہے؟
│  ├─ ہاں → Google Country Association Form پر region تبدیل کریں
│  │         (https://policies.google.com/country-association-form)
│  │         1-24 گھنٹے انتظار کریں، پھر دوبارہ کوشش کریں
│  └─ نہیں ↓
│
├─ کیا اکاؤنٹ کے پاس Google One AI Pro subscription ہے؟
│  ├─ نہیں → پہلے one.google.com پر subscription حاصل کریں
│  └─ ہاں ↓
│
├─ خودکار دریافت آزمائیں (Dashboard میں token کو refresh کریں)
│  ├─ کام کرتا ہے → مکمل
│  └─ پھر بھی ناکام ↓
│
└─ دستی طریقہ: مشین پر `agy login` چلائیں
   ├─ کام کرتا ہے → Dashboard میں token کو refresh کریں، projectId دریافت ہو جائے گا
   └─ ناکام → error message چیک کریں، غالباً region یا subscription کا مسئلہ ہے
```
