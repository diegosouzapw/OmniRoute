یہ گائیڈ OmniRoute میں Kiro (AWS کی میزبانی میں چلنے والا AI کوڈنگ اسسٹنٹ) اکاؤنٹس شامل کرنے کا طریقہ بیان کرتی ہے،
جس میں سیشن کے ٹکراؤ کے بغیر بیک وقت متعدد اکاؤنٹس چلانے پر توجہ دی گئی ہے۔

---

## پس منظر: Kiro اکاؤنٹس میں ٹکراؤ کیوں ہو سکتا ہے

Kiro کا بیک اینڈ فعال سیشنز کو ٹریک کرنے کے لیے AWS SSO OIDC کلائنٹ رجسٹریشنز استعمال کرتا ہے۔
اہم پابندی یہ ہے: **ہر OIDC کلائنٹ رجسٹریشن ایک وقت میں صرف ایک فعال
سیشن کو سپورٹ کرتی ہے**۔ جب کوئی دوسرا ڈیوائس یا صارف اسی رجسٹرڈ
کلائنٹ کے ذریعے توثیق کرتا ہے، تو بیک اینڈ پہلے اکاؤنٹ کے ریفریش ٹوکن کو منسوخ کر دیتا ہے۔

یہ وہی طریقۂ کار ہے جو ایسی مشین پر `kiro-cli login` چلانے کے دوران مسائل پیدا کرتا ہے
جہاں کوئی دوسرا Kiro اکاؤنٹ پہلے ہی سائن اِن ہو — نیا لاگ اِن پہلے
اکاؤنٹ کا ٹوکن منسوخ کر دیتا ہے۔

---

## OmniRoute اس مسئلے کو کیسے حل کرتا ہے (v3.8.0+)

v3.8.0 سے، OmniRoute ہر Kiro کنکشن امپورٹ کے دوران `registerClient()` (AWS SSO OIDC) کو کال کرتا ہے۔
اس سے ہر OmniRoute کنکشن کو اپنی مخصوص OIDC کلائنٹ رجسٹریشن ملتی ہے۔
چونکہ ہر کلائنٹ رجسٹریشن آزاد ہوتی ہے، اس لیے ایک اکاؤنٹ کو ریفریش یا
دوبارہ توثیق کرنے سے کسی دوسرے اکاؤنٹ کا ریفریش ٹوکن متاثر نہیں ہوتا۔

یہ علیحدگی ریفریش ٹوکن امپورٹ کے طریقوں پر لاگو ہوتی ہے، جبکہ API کلید کے ذریعے توثیق
OIDC ریفریش سیشنز سے مکمل طور پر گریز کرتی ہے:

| امپورٹ کا طریقہ                                             | علیحدگی کی حیثیت                                                                                |
| ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC ڈیوائس کوڈ فلو                         | ڈیوائس کوڈ فلو متعارف ہونے کے بعد سے علیحدہ                                                     |
| **ٹوکن امپورٹ کریں** (ریفریش ٹوکن کو دستی طور پر پیسٹ کرنا) | v3.8.0 سے علیحدہ                                                                                |
| **Google / GitHub سوشل لاگ اِن**                            | v3.8.0 سے علیحدہ                                                                                |
| **خودکار امپورٹ** (kiro-cli SQLite)                         | v3.8.0 سے علیحدہ (SQLite کا راستہ پہلے ہی علیحدہ تھا؛ SSO کیش فال بیک بھی اب علیحدہ ہے)         |
| **API کلید** (طویل مدتی CodeWhisperer کلید)                 | کوئی ریفریش سیشن نہیں؛ کلید کی توثیق کی جاتی ہے اور اسے بیئرر اسناد کے طور پر محفوظ کیا جاتا ہے |

---

## v3.8.0 سے پہلے بنائے گئے کنکشنز کے لیے منتقلی کا نوٹ

v3.8.0 سے پہلے امپورٹ کیے گئے کنکشنز میں مخصوص OIDC کلائنٹ رجسٹریشن
`providerSpecificData` میں محفوظ نہیں ہوتی۔ یہ کنکشنز کام کرتے رہتے ہیں لیکن مشترکہ
سوشل توثیقی ریفریش اینڈ پوائنٹ استعمال کرتے ہیں، جس کا مطلب ہے کہ ایسے دو کنکشنز اب بھی ایک
دوسرے کو منسوخ کر سکتے ہیں۔

**علیحدگی حاصل کرنے کے لیے:** پرانا کنکشن **ڈیش بورڈ → فراہم کنندگان** سے حذف کریں اور
اسے معاونت یافتہ امپورٹ فلوز میں سے کسی ایک کے ذریعے دوبارہ امپورٹ کریں۔ نئے بنائے گئے تمام کنکشنز کو
اپنی کلائنٹ رجسٹریشن خودکار طور پر مل جائے گی۔

## دو Kiro اکاؤنٹس کو ساتھ ساتھ شامل کرنا

### پیشگی شرائط

- OmniRoute v3.8.0 یا اس کے بعد کا ورژن۔
- ایک فعال Kiro اکاؤنٹ (ای میل + پاس ورڈ، Google، یا GitHub لاگ اِن)۔
- اختیاری طور پر، دوسرا Kiro اکاؤنٹ۔

### مرحلہ 1: پہلا اکاؤنٹ امپورٹ کریں

1. **ڈیش بورڈ → فراہم کنندگان → فراہم کنندہ شامل کریں → Kiro** کھولیں۔
2. ان میں سے ایک منتخب کریں:
   - **ٹوکن امپورٹ کریں** — `aorAAAAAG` سے شروع ہونے والا ریفریش ٹوکن پیسٹ کریں۔
   - **API کلید** — طویل مدتی Kiro / CodeWhisperer API کلید پیسٹ کریں۔
   - **Google / GitHub لاگ اِن** — براؤزر میں OAuth فلو مکمل کریں۔
   - **خودکار امپورٹ** — بٹن پر کلک کریں؛ OmniRoute مقامی kiro-cli ڈیٹابیس یا `~/.aws/sso/cache` سے اسناد پڑھتا ہے۔
3. کنکشن محفوظ ہو جاتا ہے۔ ریفریش ٹوکن فلوز خودکار طور پر ایک مخصوص
   OIDC کلائنٹ رجسٹر کرتے ہیں۔ API کلید کے فلوز AWS کے ذریعے کلید کی توثیق کرتے ہیں اور ریفریش ٹوکن محفوظ نہیں کرتے۔

### مرحلہ 2: دوسرا اکاؤنٹ امپورٹ کریں

دوسرے اکاؤنٹ کے لیے مرحلہ 1 دہرائیں۔ چونکہ ہر امپورٹ ایک الگ OIDC
کلائنٹ رجسٹریشن بناتا ہے، اس لیے دونوں کنکشنز مکمل طور پر علیحدہ رہتے ہیں۔

### مرحلہ 3: تصدیق کریں کہ دونوں کنکشنز فعال ہیں

1. **ڈیش بورڈ → فراہم کنندگان** — دونوں Kiro کنکشنز کی حیثیت **فعال** ہونی چاہیے۔
2. **ڈیش بورڈ → صحت** — دونوں کنکشنز کو اپنے ٹوکن کی صحت کی جانچ میں کامیاب ہونا چاہیے۔

### مرحلہ 4: اکاؤنٹس کے درمیان روٹنگ کے لیے کومبو استعمال کریں

لوڈ بیلنسنگ یا ان کے درمیان فال بیک کے لیے دونوں کنکشنز کو ہدف بنا کر ایک کومبو بنائیں:

```
kiro/kiro-dev → kiro/kiro-pro
```

کومبو کی تشکیل کے لیے [FEATURES.md](./FEATURES.md) اور روٹنگ کی دستاویزات دیکھیں۔

## انٹرپرائز / IDC صارفین

AWS IAM Identity Center (IDC) اکاؤنٹس کے لیے، **Dashboard → Providers → Kiro → Device Code** سے **AWS Builder ID / IDC ڈیوائس کوڈ** فلو استعمال کریں۔ ڈیوائس کوڈ فلو ہمیشہ سے مکمل طور پر الگ تھلگ رہا ہے۔ ان کنکشنز کے لیے دوبارہ درآمد کی ضرورت نہیں ہے۔

ایسے انٹرپرائز صارفین جو غیر ڈیفالٹ AWS ریجن میں کام کرتے ہیں، Import Token API کے ذریعے درآمد کرتے وقت ریجن متعین کر سکتے ہیں:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

اگر `region` فیلڈ شامل نہ کی جائے تو اس کی ڈیفالٹ قدر `us-east-1` ہوتی ہے۔

## API کلید درآمد کرنے کا فلو

API کلید پر مبنی تصدیق طویل مدتی Kiro / AWS CodeWhisperer bearer اسناد کے لیے ہے۔ یہ OAuth ریفریش استعمال نہیں کرتی، اس لیے مشترکہ OIDC سیشن کے غیر مؤثر ہونے سے بچاتی ہے۔

### ڈیش بورڈ

1. **Dashboard -> Providers -> Kiro** کھولیں۔
2. **API Key** منتخب کریں۔
3. API کلید اور اختیاری AWS ریجن چسپاں کریں (ڈیفالٹ `us-east-1` ہے)۔
4. OmniRoute کلید کی توثیق کرتا ہے اور کنکشن محفوظ کر دیتا ہے۔

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### داخلی معاہدہ

API روٹ `KiroService.validateApiKey()` کو کال کر کے کلید کی توثیق کرتا ہے، جو ریجن سے مطابقت رکھنے والے CodeWhisperer/Amazon Q اینڈ پوائنٹ کے خلاف `ListAvailableProfiles` استعمال کرتا ہے اور ایک `profileArn` کا تعین کرتا ہے۔

محفوظ کردہ کنکشن یہ استعمال کرتا ہے:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

رن ٹائم پر، `KiroExecutor.buildHeaders()` کلید کو `Authorization: Bearer <key>` کے طور پر بھیجتا ہے اور `tokentype: API_KEY` شامل کرتا ہے۔ کوٹا/پروفائل کالز بھی یہی نشان استعمال کرتی ہیں، تاکہ AWS اس bearer کو OIDC یا سوشل رسائی ٹوکن کے بجائے ایک طویل مدتی API کلید سمجھے۔

## OIDC کلائنٹ کی میعاد ختم ہونا

AWS SSO OIDC پبلک کلائنٹس عموماً 90 دن کے بعد زائد المیعاد ہو جاتے ہیں (`clientSecretExpiresAt`)۔ OmniRoute مشاہدہ پذیری کے لیے یہ ٹائم اسٹیمپ `providerSpecificData` میں محفوظ کرتا ہے۔ اگر کوئی کنکشن تقریباً 90 دن بعد ریفریش ہونا بند کر دے، تو تازہ OIDC کلائنٹ رجسٹریشن حاصل کرنے کے لیے کنکشن کو دوبارہ درآمد کریں۔ میعاد ختم ہونے پر خودکار دوبارہ رجسٹریشن کو مستقبل کی بہتری کے طور پر ٹریک کیا جا رہا ہے۔

API کلید والے کنکشنز میں OIDC کلائنٹ کی میعاد ختم نہیں ہوتی، کیونکہ وہ AWS SSO OIDC کے ذریعے ریفریش نہیں ہوتے۔

## مسائل کا ازالہ

### دوسرا اکاؤنٹ بار بار لاگ آؤٹ ہو رہا ہے

- **Dashboard → Providers** میں دونوں کنکشنز چیک کریں اور تصدیق کریں کہ ہر ایک کے خام JSON میں `clientId` کی قدر null نہیں ہے (معلوماتی آئیکن کے ذریعے دیکھی جا سکتی ہے)۔ اگر کسی بھی کنکشن میں `clientId` موجود نہیں ہے، تو اسے v3.8.0 سے پہلے درآمد کیا گیا تھا — اسے دوبارہ درآمد کریں۔

### "Token validation failed" کے ساتھ درآمد ناکام ہو جاتی ہے

- یقینی بنائیں کہ ریفریش ٹوکن `aorAAAAAG` سے شروع ہوتا ہے۔
- یقینی بنائیں کہ OmniRoute، `https://oidc.us-east-1.amazonaws.com` (یا ترتیب دیے گئے ریجن) تک رسائی حاصل کر سکتا ہے۔ اگر آپ کسی کارپوریٹ پراکسی کے پیچھے ہیں، تو **Dashboard → Settings → Proxies** میں پرووائیڈر کی سطح کی پراکسی مقرر کریں۔

### API کلید کی درآمد ناکام ہو جاتی ہے

- تصدیق کریں کہ کلید Kiro / CodeWhisperer API کلید ہے، ریفریش ٹوکن نہیں۔
- تصدیق کریں کہ AWS ریجن کلید/اکاؤنٹ سے مطابقت رکھتا ہے۔ ڈیفالٹ `us-east-1` ہے۔
- کلید کو `ListAvailableProfiles` کال کرنے کے قابل ہونا چاہیے؛ بصورت دیگر OmniRoute مطلوبہ `profileArn` کا تعین نہیں کر سکتا۔

دیگر مسائل کے لیے، مرکزی [TROUBLESHOOTING.md](./TROUBLESHOOTING.md) دیکھیں۔
