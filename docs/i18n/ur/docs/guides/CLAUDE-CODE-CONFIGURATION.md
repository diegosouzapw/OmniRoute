**Claude Code** CLI (`claude`) کو OmniRoute کی طرف پوائنٹ کریں — مقامی یا ریموٹ VPS —
فی ماڈل پروفائلز کے ساتھ، Codex سیٹ اپ کی طرز پر۔

---

## فوری آغاز

```bash
# Claude Code کو مقامی OmniRoute کے ساتھ چلائیں (فعال کانٹیکسٹ خودکار طور پر دریافت کرتا ہے)
omniroute launch

# ریموٹ OmniRoute کے ساتھ ( `omniroute connect <host>` کے بعد یہ خودکار ہے)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# فی ماڈل پروفائلز بنائیں، پھر ان میں سے ایک چلائیں
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json میں لکھتا ہے
omniroute launch --profile glm52  # OmniRoute کے ذریعے glm/glm-5.2 استعمال کرنے والا Claude Code
```

## Claude Code گیٹ وے سے کیسے جڑتا ہے

Claude Code، **Anthropic Messages API** سے رابطہ کرتا ہے اور اسے ماحولیاتی متغیرات کے ذریعے ایک حسبِ ضرورت
اینڈ پوائنٹ کی طرف پوائنٹ کیا جاتا ہے (اس میں `--base-url` فلیگ موجود نہیں):

| متغیر                                        | مقصد                                                                                                      |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `ANTHROPIC_BASE_URL`                         | گیٹ وے کا روٹ URL (Claude Code آخر میں `/v1/messages` شامل کرتا ہے)۔ **آخر میں `/v1` نہ لگائیں۔**         |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` کے طور پر بھیجا جاتا ہے — اپنا OmniRoute رسائی ٹوکن / API کلید استعمال کریں     |
| `ANTHROPIC_API_KEY`                          | متبادل: `x-api-key` کے طور پر بھیجا جاتا ہے۔ اگر دونوں سیٹ ہوں تو `ANTHROPIC_AUTH_TOKEN` کو ترجیح ملتی ہے |
| `ANTHROPIC_MODEL`                            | کسی مخصوص ماڈل کو لازمی بنائیں (`/model` پِکر کے ڈیفالٹ کو اوور رائیڈ کرتا ہے)                            |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → مقامی `/model` پِکر، `/v1/models` سے `claude*`/`anthropic*` ماڈلز دکھاتا ہے                         |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | فی جواب آؤٹ پٹ ٹوکنز کی حد مقرر کریں (مثلاً `65536`)                                                      |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | خودکار کمپیکشن کے لیے ٹوکن کی حد                                                                          |

> ماحولیاتی متغیرات **اسٹارٹ اپ پر صرف ایک بار** پڑھے جاتے ہیں — انہیں تبدیل کرنے کے بعد Claude Code دوبارہ شروع کریں۔

`omniroute launch` یہ سب آپ کے لیے سیٹ کرتا ہے: یہ فعال کانٹیکسٹ سے بنیادی URL + ٹوکن
حاصل کرتا ہے (لہٰذا `omniroute connect <vps>` کے بعد `omniroute launch`
براہِ راست کام کرتا ہے)، سرور کی صحت جانچتا ہے، اور `claude` کو چلاتا ہے۔

## ڈسکوری عرفیات — غیر Claude ماڈلز کو `/model` پِکر میں دکھائیں

Claude Code کی گیٹ وے ماڈل ڈسکوری صرف وہ ids دکھاتی ہے جو `claude`
یا `anthropic` سے شروع ہوتی ہیں، لہٰذا `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` کے ساتھ مقامی
`/model` پِکر عموماً OmniRoute کے **صرف** Claude/Anthropic ماڈلز دکھاتا ہے — کوئی
`kimi/kimi-k2.6` یا `glm/glm-5.2` کبھی ظاہر نہیں ہوتا، حالاں کہ اس کی روٹنگ درست طور پر ہوتی ہے۔

OmniRoute کسی بھی فعال ماڈل (اور کومبو) کو `claude/…` id کے تحت منعکس کر سکتا ہے تاکہ وہ
اس فلٹر سے گزر کر پِکر میں ظاہر ہو:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

جب آپ Claude Code میں ان میں سے کسی ایک کو منتخب کرتے ہیں تو OmniRoute روٹنگ سے پہلے `claude/` ریپر
ہٹا کر اصل id بحال کر دیتا ہے — ایک حقیقی `claude/<real-claude-model>` id
(اصل Claude OAuth فراہم کنندہ) کو ہمیشہ جوں کا توں چھوڑا جاتا ہے۔

**یہ بطور ڈیفالٹ بند ہے** اور تین سطحی گیٹ کے ذریعے کنٹرول ہوتا ہے (زیادہ مخصوص
ترتیب کو ترجیح ملتی ہے)، تاکہ سادہ OmniRoute ان کلائنٹس کے لیے اپنے کیٹلاگ کو دوگنا نہ کرے جو
Claude Code استعمال نہیں کرتے:

| سطح         | مقام                                                                                            |
| ----------- | ----------------------------------------------------------------------------------------------- |
| ماڈل        | فراہم کنندہ کی تفصیلات کا صفحہ → فی ماڈل "Claude Code میں ظاہر کریں" ٹوگل                       |
| فراہم کنندہ | فراہم کنندہ کی تفصیلات کا صفحہ → فراہم کنندہ کی سطح کا ٹوگل (اس کے تمام ماڈلز کا احاطہ کرتا ہے) |
| عالمی       | ترتیبات → فیچر فلیگز → `EXPOSE_CC_DISCOVERY_ALIASES` (بطور ڈیفالٹ بند)                          |

`EXPOSE_CC_DISCOVERY_ALIASES` ماحولیاتی متغیر عالمی سطح کو لازماً آن کر دیتا ہے
اور ڈیش بورڈ اوور رائیڈ پر ترجیح رکھتا ہے (ایسا ہونے پر فیچر فلیگز اسکرین
"ماحولیاتی متغیر کے ذریعے فعال" کا نوٹ دکھاتی ہے)۔ وہاں سے فی فراہم کنندہ اور
فی ماڈل ٹوگلز مزید تخصیص کرتے ہیں — مثلاً عالمی سطح بند + Kimi فراہم کنندہ آن ہونے سے
صرف Kimi کے ماڈلز ظاہر ہوتے ہیں۔

> ⚠️ **غیر Claude ماڈلز پر ونڈو کا عدم تطابق۔** Claude Code ہر ایسی id کے لیے 200K کانٹیکسٹ
> ونڈو فرض کرتا ہے جسے وہ نہیں پہچانتا (وہ `/v1/models` سے حقیقی ونڈو نہیں پڑھ سکتا)۔
> زیادہ بڑی ونڈو والے ماڈل (مثلاً Kimi K2 کی 256K) کے لیے
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW` کو ماڈل کی حقیقی ونڈو سے کم قدر پر سیٹ کریں تاکہ
> خودکار کمپیکشن وقت سے پہلے فعال نہ ہو۔ اوپر بنائے گئے پروفائلز پہلے ہی
> ہر ماڈل کے لیے ایسا کرتے ہیں۔

## ڈیش بورڈ پر آن بورڈنگ بلاک

Claude ٹول کارڈ (**ڈیش بورڈ → CLI Code**) اس انسٹینس کے لیے بالکل درست `settings.json` جزو
دریافت کے عرف سے متعلق معلوماتی بٹن کے ساتھ، ایک کاپی بٹن سمیت دکھاتا ہے:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<your OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<your OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

بنیادی URL وہی ہے جسے کارڈ نے حل کیا ہے (بشمول آپ کے درج کردہ حسبِ ضرورت اوور رائیڈ کے)، اور یہ پہلے ہی
معیاری شکل میں ہے — نہ `/v1` لاحقہ، نہ آخر میں سلیش۔ **کلید کبھی دکھائی نہیں جاتی**: بلاک میں ایک
پلیس ہولڈر فراہم کیا جاتا ہے، لہٰذا اسکرین شاٹ یا پیسٹ کیا ہوا ٹکڑا اسے افشا نہیں کر سکتا۔ اس کی جگہ اپنی کلید پیسٹ کریں۔

ایسے کسی بھی ماڈل کے لیے، جس کی حقیقی کانٹیکسٹ ونڈو 200K نہ ہو، اسی `env` بلاک کے تحت `CLAUDE_CODE_AUTO_COMPACT_WINDOW`
شامل کریں — Claude Code ہر اس id کے لیے 200K فرض کرتا ہے جسے وہ شناخت نہیں کرتا، اس لیے
بصورتِ دیگر خودکار کمپیکشن غلط مقام پر فعال ہو جاتی ہے (پچھلے حصے میں انتباہ دیکھیں)۔
اسنیپٹ بلڈر یہ قدر بھی قبول کرتا ہے، لہٰذا ہدف ماڈل کی ونڈو جاننے والا کالر
اسے براہِ راست خارج کر سکتا ہے۔

ماخذ: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (خالص
بلڈر، یونٹ ٹیسٹ شدہ)، جسے `ClaudeGatewayOnboardingBlock` رینڈر کرتا ہے۔

## پروفائلز (`CLAUDE_CONFIG_DIR`)

Claude Code میں **مقامی پروفائل فائلیں موجود نہیں ہیں** (Codex کی `~/.codex/<name>.config.toml` کے برعکس)۔
روایتی طریقۂ کار `CLAUDE_CONFIG_DIR` ہے — ہر
پروفائل کے لیے ایک الگ کنفگ ڈائریکٹری، جس میں اس کی اپنی `settings.json`، اسناد، تاریخچہ اور کیش ہوتے ہیں۔

`omniroute setup-claude` فعال `/v1/models` کیٹلاگ حاصل کرتا ہے اور ہر ماڈل کے لیے ایک
پروفائل `~/.claude/profiles/<name>/settings.json` میں لکھتا ہے، اور
**وہی نام استعمال کرتا ہے جو `setup-codex` میں ہیں** (`glm52`، `kimi-k27`، `deepseek-pro`، …):

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **تصدیقی ٹوکن کبھی پروفائل میں نہیں لکھا جاتا۔** اسے
> `omniroute launch --profile <name>` کے ساتھ چلائیں (یہ فعال کانٹیکسٹ سے `ANTHROPIC_AUTH_TOKEN`
> داخل کرتا ہے)، یا خود `ANTHROPIC_AUTH_TOKEN` ایکسپورٹ کریں اور
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude` چلائیں۔

**ماڈل کی دریافت کے بعد خودکار ہم وقت سازی (اختیاری)۔** جب بھی کسی فراہم کنندہ کے ماڈل کی
ہم وقت سازی فعال کیٹلاگ کو تبدیل کرے، OmniRoute انہی `~/.claude/profiles/<name>/settings.json`
فائلوں کو خودکار طور پر دوبارہ بنا سکتا ہے — یوں نئے یا تبدیل شدہ ناموں والے ماڈلز کے لیے کمانڈ دوبارہ چلائے بغیر
پروفائل بن جاتے ہیں۔ یہ **بطور ڈیفالٹ بند** ہے: اسے **CLI Code ڈیش بورڈ** سے فعال کریں ("CLI profile
auto-sync" → Claude Code)، یا `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` مقرر کریں (یہ
`CLI_ALLOW_CONFIG_WRITES` کا بھی احترام کرتا ہے، جو بطور ڈیفالٹ فعال ہے)۔ فعال ہونے پر یہ صرف پروفائل فائلیں لکھتا ہے؛ یہ کبھی
آپ کی فعال/ڈیفالٹ Claude کنفگ، تصدیق، یا `~/.claude/settings.json` تبدیل نہیں کرتا۔

### پروفائلز بنانا + استعمال کرنا

```bash
# مقامی OmniRoute
omniroute setup-claude

# ریموٹ VPS (ہر پروفائل میں VPS URL شامل کرتا ہے)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# صرف کچھ فراہم کنندگان
omniroute setup-claude --only glm,kimi

# لکھے بغیر پیش منظر
omniroute setup-claude --dry-run

# ایک پروفائل چلائیں
omniroute launch --profile kimi-k27
```

## ماڈل کے درجات (اختیاری)

Claude Code صلاحیت کے درجات کی بنیاد پر روٹنگ کرتا ہے۔ اگر آپ ہر درجے کے لیے مختلف فراہم کنندگان استعمال کرنا چاہتے ہیں، تو env /
settings کے ذریعے ہر درجے کو ایک OmniRoute ماڈل سے میپ کریں:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

بصورتِ دیگر، ہر چیز کے لیے ایک ہی `ANTHROPIC_MODEL` (جسے پروفائلز سیٹ کرتے ہیں) استعمال کیا جاتا ہے۔

---

## ریموٹ موڈ

ایک بار `omniroute connect <host>` چلانے کے بعد (دیکھیں
[ریموٹ موڈ](./REMOTE-MODE.md))، `omniroute launch` اور `omniroute setup-claude`
خودکار طور پر اس ریموٹ سرور کو ہدف بناتے ہیں اور اس کا محدود دائرۂ کار رکھنے والا رسائی ٹوکن استعمال کرتے ہیں — کسی
اضافی فلیگ کی ضرورت نہیں۔ ہر بار چلانے کے لیے `--remote` / `--api-key` کے ذریعے اسے اوور رائیڈ کریں۔

## مسائل کا ازالہ

**Claude Code گیٹ وے کو نظر انداز کرتا ہے** — تصدیق کریں کہ `ANTHROPIC_BASE_URL` میں **کوئی
`/v1` نہیں** ہے اور `claude` کو دوبارہ شروع کریں (env کو آغاز کے وقت صرف ایک بار پڑھا جاتا ہے)۔ `omniroute launch`
یہ کام آپ کے لیے سنبھالتا ہے۔

**`/model` چننے والا خالی ہے / گیٹ وے ماڈلز غائب ہیں** — اس کے لیے Claude Code
v2.1.219+ اور `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` درکار ہیں۔ چننے والے میں صرف `claude*` /
`anthropic*` ماڈل IDs ظاہر ہوتی ہیں؛ کسی بھی دوسرے ماڈل کو
`ANTHROPIC_MODEL=<id>` کے ساتھ زبردستی استعمال کریں (پروفائلز یہی کرتے ہیں)۔

**`400 Ambiguous model 'claude-…'`** — Claude Code ہمیشہ **بغیر سابقے کے**
ماڈل IDs بھیجتا ہے (مثلاً `claude-opus-4-8`)، لہٰذا جب Claude Code (`cc/…`) اور
Claude (`claude/…`) دونوں فراہم کنندگان منسلک ہوں، تو سابقے کے بغیر id دو روٹس سے مطابقت رکھتی ہے اور
OmniRoute اندازہ لگانے سے انکار کر دیتا ہے۔ اسے کسی بھی طریقے سے درست کریں: سابقے والی id کو
`ANTHROPIC_MODEL=cc/claude-opus-4-8` کے ذریعے مقرر کریں، یا **بغیر سابقے والے Claude ماڈلز کے لیے Claude Code کو
ترجیح دیں** فعال کریں — Claude فراہم کنندہ کے صفحے پر موجود ٹوگل، یا
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (بطور ڈیفالٹ بند؛
دیکھیں [ماحول](../reference/ENVIRONMENT.md)) — جو بغیر سابقے والی `claude-*`
IDs کو اس کے بجائے Claude Code کی طرف روٹ کرتا ہے۔ فراہم کنندہ کے واضح سابقے ہمیشہ فوقیت رکھتے ہیں۔

**تصدیقِ شناخت کی خرابیاں** — پروفائل میں کوئی ٹوکن موجود نہیں ہوتا۔ `omniroute launch --profile`
استعمال کریں (یہ اسے داخل کر دیتا ہے) یا `ANTHROPIC_AUTH_TOKEN` ایکسپورٹ کریں۔

**پروفائلز الگ تھلگ نہیں رہتے** — ہر پروفائل ایک الگ `CLAUDE_CONFIG_DIR` ہے؛
تصدیق کریں کہ سیشن کے اندر `echo $CLAUDE_CONFIG_DIR` اس مقام کی طرف اشارہ کرتا ہے:
`~/.claude/profiles/<name>`۔
