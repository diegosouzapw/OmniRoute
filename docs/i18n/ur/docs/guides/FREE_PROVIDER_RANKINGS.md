> **خلاصہ**: OmniRoute اپنے **مفت** فراہم کنندگان کو ماڈل کے معیار کے لحاظ سے **Arena AI
> (LMArena طرز کے) ELO اسکورز** استعمال کرتے ہوئے درجہ دیتا ہے۔ ڈیش بورڈ میں **مفت فراہم کنندگان کی درجہ بندی** کا صفحہ کھولیں تاکہ معلوم ہو سکے کہ کون سے مفت فراہم کنندگان آپ کے کام کے لیے مضبوط ترین ماڈلز فراہم کرتے ہیں —
> مجموعی طور پر، یا زمرے کے لحاظ سے فلٹر کر کے (کوڈنگ، جائزہ، دستاویزات، ڈی بگنگ)۔

---

## یہ کیا ہے

OmniRoute میں 329 فراہم کنندگان رجسٹرڈ ہیں، جن میں 155 کیٹلاگ اندراجات **مفت/بلا توثیق**
کے طور پر نشان زد ہیں
(بلا توثیق،
مفت درجے کا OAuth، یا مفت درجے کی API کلید — ملاحظہ کریں
[مفت درجات کی رہنما](../getting-started/FREE-TIERS-GUIDE.md) اور مکمل
[مفت درجات کی ڈائریکٹری](../reference/FREE_TIERS.md))۔ مسئلہ یہ ہے کہ مفت فراہم کنندگان کے
ماڈلز کے معیار میں بہت زیادہ فرق ہوتا ہے۔ کسی جدید ترین ماڈل کو پیش کرنے والا بلا توثیق
فراہم کنندہ، کسی چھوٹے پرانے ماڈل کو پیش کرنے والے فراہم کنندہ سے کہیں زیادہ مفید ہے۔

**مفت فراہم کنندگان کی درجہ بندی** اس سوال کا جواب دیتی ہے: "**کون سا مفت فراہم کنندہ مجھے بہترین ماڈل دیتا ہے؟**"۔ اس کے لیے
ہر مفت فراہم کنندہ کے کیٹلاگ کو
**Arena AI لیڈر بورڈ** سے حاصل کردہ **اجتماعی طور پر ماخذ کردہ معیاری اسکورز** کے ساتھ جوڑا جاتا ہے
(انسانی ترجیحات پر مبنی ELO، یعنی وہی تصور جو LMArena
چیٹ بوٹ ایرینا کے پسِ پشت ہے)۔ اس کے بعد فراہم کنندگان کو ان کے **بہترین مفت ماڈل** کی مضبوطی کے لحاظ سے درجہ دیا جاتا ہے۔

درجہ بندی تین حقیقی ذرائع سے شمار کی جاتی ہے:

1. مفت فراہم کنندگان کی فہرستیں — `NOAUTH_PROVIDERS`، نیز `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS` کے وہ اندراجات جن پر `hasFree` نشان زد ہے
   (`src/shared/constants/providers.ts`)۔
2. فراہم کنندہ رجسٹری سے ہر فراہم کنندہ کا ماڈل کیٹلاگ
   (`open-sse/config/providerRegistry.ts`)۔
3. ELO سے اخذ کردہ کام سے مطابقت کے اسکورز، جو Arena ELO ہم وقت سازی انجن
   (`src/lib/arenaEloSync.ts`) کے ذریعے `model_intelligence` DB ٹیبل میں محفوظ کیے جاتے ہیں۔

جوڑنے کی منطق `src/lib/freeProviderRankings.ts` میں موجود ہے۔

## رسائی کا طریقہ

### ڈیش بورڈ صفحہ

ڈیش بورڈ کھولیں اور **لاگتیں → مفت فراہم کنندگان کی درجہ بندی** پر جائیں، یا براہِ راست یہاں جائیں:

```
/dashboard/free-provider-rankings
```

یہ صفحہ (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) درج ذیل دکھاتا ہے:

- بہترین درجہ رکھنے والے مفت فراہم کنندگان کے لیے **سرفہرست 3 کا پوڈیم** (🥇 🥈 🥉)۔
- ایک مکمل **درجہ بندی کی جدول**، جس کے کالم ہیں: **درجہ**، **فراہم کنندہ**، **بہترین ماڈل**،
  **اسکور**، **اوسط اسکور**، **ماڈلز**، **قسم**۔
- **زمرہ فلٹر بٹنز**: _تمام زمرے_، _ڈیفالٹ_، _کوڈنگ_، _جائزہ_،
  _دستاویزات_، _ڈی بگنگ_۔

ہر فراہم کنندہ کا **قسم** بیج بتاتا ہے کہ وہ کس طرح مفت ہے:

| بیج      | مطلب                                              |
| -------- | ------------------------------------------------- |
| `NOAUTH` | ہمیشہ مفت، کسی اسناد کی ضرورت نہیں                |
| `OAUTH`  | مفت درجے (`hasFree`) کے ساتھ OAuth فراہم کنندہ    |
| `APIKEY` | مفت درجے (`hasFree`) کے ساتھ API کلید فراہم کنندہ |

اسکورز خام اعداد کے بجائے انسانی طور پر قابلِ فہم لیبلز کی صورت میں دکھائے جاتے ہیں (مثلاً _اعلیٰ ترین_، _شاندار_، _بہت اچھا_،
_اچھا_، _اوسط_)، کیونکہ بنیادی قدر فیصد نہیں بلکہ معیار کی نسبتی
درجہ بندی ہے۔

### API اینڈ پوائنٹ

یہ صفحہ ایک عوامی، صرف پڑھنے کے اینڈ پوائنٹ
(`src/app/api/free-provider-rankings/route.ts`) سے تقویت پاتا ہے:

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

استفساری پیرامیٹرز (Zod کے ذریعے توثیق شدہ):

| پیرامیٹر   | قسم    | ڈیفالٹ      | نوٹس                                                                                                              |
| ---------- | ------ | ----------- | ----------------------------------------------------------------------------------------------------------------- |
| `category` | اسٹرنگ | (کوئی نہیں) | `default`، `coding`، `review`، `documentation`، `debugging` میں سے ایک۔ مشترکہ درجہ بندی کے لیے اسے شامل نہ کریں۔ |
| `limit`    | عدد    | `50`        | `1–100` کی حد تک محدود کیا جاتا ہے۔                                                                               |

جواب کی ساخت:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` اصل Arena ELO قدر ہے؛ `score` معمول پر لائی گئی کام سے مطابقت کی قدر ہے
(ذیل میں ملاحظہ کریں)۔ جن فراہم کنندگان کے کسی ماڈل کا اسکور موجود نہ ہو، انہیں جواب سے خارج کر دیا جاتا ہے۔

## اسکور کیسے کام کرتے ہیں

### ماخذ: Arena AI لیڈر بورڈ

Arena ELO سنک انجن (`src/lib/arenaEloSync.ts`)، Arena AI لیڈر بورڈ API
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`) سے دو لیڈر بورڈز — `text`
اور `code` — حاصل کرتا ہے۔ ہر لیڈر بورڈ اندراج میں ماڈل کا نام، وینڈر، ELO `score`، اعتماد کا وقفہ، اور ووٹوں کی تعداد شامل ہوتی ہے۔

لیڈر بورڈ کی کیٹیگریز کو OmniRoute ٹاسک کیٹیگریز سے یوں میپ کیا جاتا ہے:

| Arena لیڈر بورڈ | OmniRoute ٹاسک کیٹیگریز                           |
| --------------- | ------------------------------------------------- |
| `text`          | `default`، `review`، `documentation`، `debugging` |
| `code`          | `coding`                                          |

### نارملائزیشن (ٹاسک موزونیت اسکور)

خام ELO اسکورز کو ہر لیڈر بورڈ کے لیے نارملائز کرکے **`[0.4, 0.98]` میں ٹاسک موزونیت کی قدر** بنایا جاتا ہے:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

اسکور کبھی `0` یا `1` تک نہیں پہنچتا، جس سے صارف کی اوور رائیڈز کے لیے گنجائش باقی رہتی ہے۔ یہی وہ `score` فیلڈ ہے جو آپ API رسپانس میں دیکھتے ہیں اور یہی لیبل ڈیش بورڈ پر دکھایا جاتا ہے۔

### اعتماد

Arena کے ووٹوں کی تعداد کی بنیاد پر ہر اندراج کو اعتماد کی ایک سطح دی جاتی ہے:

| اعتماد   | ووٹس    |
| -------- | ------- |
| `high`   | ≥ 5,000 |
| `medium` | ≥ 1,000 |
| `low`    | < 1,000 |

### اسٹوریج اور تازگی

نارملائز شدہ اندراجات کو `source = "arena_elo"` کے ساتھ `model_intelligence` DB ٹیبل میں لکھا جاتا ہے (`src/lib/db/modelIntelligence.ts`)۔ اندراجات کی میعاد **7 دن بعد ختم ہو جاتی ہے**، لہٰذا جو پرووائیڈر سنک ہونا بند کر دے وہ بالآخر پرانا ڈیٹا فراہم کرنے کے بجائے فہرست سے خارج ہو جاتا ہے۔

سنک **بطور ڈیفالٹ فعال** ہوتا ہے:

- یہ سرور کے آغاز پر ایک بار، اور پھر مقررہ وقفے سے ٹائمر پر چلتا ہے
  (`src/lib/arenaEloSync.ts`، جسے `src/instrumentation-node.ts` سے منسلک کیا گیا ہے)۔
- یہ **نان بلاکنگ ہے اور کبھی مہلک خرابی کا سبب نہیں بنتا** — اگر اپ اسٹریم سے ڈیٹا حاصل کرنا ناکام ہو جائے تو OmniRoute چلتا رہتا ہے، اور رینکنگز صرف آخری درست ڈیٹا دکھاتی ہیں (یا خالی حالت)۔

اسے دو انوائرنمنٹ ویری ایبلز کنٹرول کرتے ہیں (جن کی دستاویز
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md) میں موجود ہے):

| ویری ایبل                 | ڈیفالٹ        | مقصد                                                            |
| ------------------------- | ------------- | --------------------------------------------------------------- |
| `ARENA_ELO_SYNC_ENABLED`  | `true`        | آؤٹ باؤنڈ سنک سے دست بردار ہونے کے لیے اسے `false` پر سیٹ کریں۔ |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24h) | سنک کا وقفہ، سیکنڈز میں۔                                        |

### مینوئل سنک / اسٹیٹس / کلیئر

آپریٹرز کے لیے، ایک تصدیق شدہ مینجمنٹ اینڈ پوائنٹ مینوئل کنٹرول فراہم کرتا ہے
(`src/app/api/intelligence/sync/route.ts` — مینجمنٹ توثیق درکار ہے):

```
GET    /api/intelligence/sync          # موجودہ سنک اسٹیٹس (enabled، lastSync، nextSync، intervalMs)
POST   /api/intelligence/sync          # مینوئل سنک شروع کریں؛ لکھے بغیر پیش منظر دیکھنے کے لیے باڈی: { "dryRun": true }
DELETE /api/intelligence/sync          # سنک شدہ arena_elo انٹیلیجنس کے تمام اندراجات صاف کریں
```

اگر رینکنگز کا صفحہ خالی ہو تو مینوئل `POST /api/intelligence/sync` (یا صرف سرور کو دوبارہ شروع کرنا) اسے دوبارہ پُر کر دیتا ہے۔

### ماڈلز کو لیڈر بورڈ سے میچ کرنا

رجسٹری ماڈل IDs اور Arena ماڈل کے نام ہمیشہ بالکل یکساں نہیں ہوتے۔ رینکنگ میں لچک دار میچنگ استعمال ہوتی ہے (`src/lib/freeProviderRankings.ts` میں `findMatchingIntelligence`):

1. نارملائز شدہ ماڈل ID پر عین مطابق میچ۔
2. آخر میں موجود ورژن لاحقہ ہٹانے کے بعد میچ (مثلاً `kimi-k2.6` → `kimi-k2`)۔
3. پری فکس میچ (لیڈر بورڈ ماڈل کا نام رجسٹری ID کا پری فکس ہو)۔

سنک کی جانب، معلوم وینڈر پری فکسز (`anthropic/`، `openai/`، `google/`، …) ہٹا دیے جاتے ہیں اور ایک مختصر عرفی نقشہ معیاری ناموں کو ان متبادل صورتوں تک وسیع کرتا ہے جو OmniRoute اندرونی طور پر استعمال کرتا ہے، تاکہ ماڈلز کسی بھی نام کے تحت قابلِ تلاش رہیں۔

### پرووائیڈر کی درجہ بندی کیسے ہوتی ہے

ہر مفت پرووائیڈر کے لیے، انجن اس کی کیٹلاگ میں موجود ہر ماڈل کو اسکور کرتا ہے، پھر:

- **بہترین ماڈل** = پرووائیڈر کا سب سے زیادہ اسکور کرنے والا ماڈل۔
- **اوسط اسکور** = اس پرووائیڈر کے تمام اسکور شدہ ماڈلز کا اوسط اسکور۔
- **ماڈلز** = پرووائیڈر کے کتنے ماڈلز کا Arena اسکور موجود تھا۔

پرووائیڈرز کو پہلے **بہترین ماڈل کے اسکور**، اور پھر اوسط اسکور کے لحاظ سے ترتیب دیا جاتا ہے۔ اس طرح ایسے پرووائیڈر کو فائدہ ملتا ہے جو کم از کم ایک مضبوط مفت ماڈل فراہم کرتا ہو۔

---

## مفت فراہم کنندگان منتخب کرنے کے لیے اس کا استعمال

1. **درست زمرہ منتخب کریں۔** ایجنٹ پر مبنی/کوڈ ورک لوڈز کے لیے **کوڈنگ** فلٹر استعمال کریں، یا
   عمومی چیٹ کے لیے اسے **تمام زمرے** / **ڈیفالٹ** پر رہنے دیں۔ ایک ہی فراہم کنندہ
   مختلف زمروں میں مختلف درجہ حاصل کر سکتا ہے، کیونکہ ہر لیڈر بورڈ پر اس کا سرفہرست ماڈل مختلف ہوتا ہے۔
2. **ایک مرتبہ کی سیٹ اپ کے لیے پوڈیم کو ترجیح دیں۔** اگر آپ صرف ایک یا دو مفت
   فراہم کنندگان سے جڑنا چاہتے ہیں، تو اپنے زمرے میں سرفہرست درجہ رکھنے والوں سے آغاز کریں۔
3. **قسم کا بیج چیک کریں۔** `NOAUTH` فراہم کنندگان سے جڑنا سب سے تیز ہے (کسی
   اسناد کی ضرورت نہیں)۔ `OAUTH` / `APIKEY` کے مفت درجات کے لیے فوری سائن اپ درکار ہوتا ہے، لیکن اکثر یہ
   زیادہ طاقتور ماڈلز تک رسائی فراہم کرتے ہیں۔ کنکشن کے مراحل کے لیے [مفت درجات کی گائیڈ](../getting-started/FREE-TIERS-GUIDE.md)
   دیکھیں۔
4. **متعدد فراہم کنندگان سے جڑیں اور Auto-Combo کو فیصلہ کرنے دیں۔** Arena ELO کا وہی ڈیٹا جو
   اس صفحے کو تقویت دیتا ہے، Auto-Combo اسکورنگ انجن کے **کام کے لیے موزونیت کے عامل** کو بھی فراہم کیا جاتا ہے
   (`open-sse/services/autoCombo/taskFitness.ts`، ترجیحی ترتیب
   `user_override → arena_elo → models_dev_tier → static table`)۔ لہٰذا سرفہرست مفت فراہم کنندگان سے جڑنے کے بعد،
   `model: "auto"` (مثلاً `auto/coding`) کے ساتھ روٹنگ ہر درخواست کے لیے
   خودکار طور پر اعلیٰ معیار کے مفت ماڈلز کو ترجیح دے گی۔ مکمل 16 عاملی اسکورنگ کے لیے
   [Auto-Combo](../routing/AUTO-COMBO.md) دیکھیں۔
