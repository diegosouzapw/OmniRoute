OmniRoute، OpenAI Codex استعمال کرنے کے **دو** طریقے فراہم کرتا ہے:

| فراہم کنندہ            | یہ OpenAI سے کیسے رابطہ کرتا ہے                                                                                                                                                                                    | استعمال سے متعلق تنبیہ                                           |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------- |
| **`codex`**            | آپ کا ChatGPT/OpenAI OAuth ٹوکن براہِ راست Responses API کو دوبارہ بھیجتا ہے                                                                                                                                       | **ہاں** — آفیشل سیشن کو proxy/router کے استعمال کی اجازت نہیں ہے |
| **`codex-app-server`** | JSON-RPC/WebSocket کے ذریعے **Codex CLI کے اپنے `codex app-server`** کو چلاتا ہے؛ CLI اپنے OAuth (`~/.codex/auth.json`) کی ملکیت رکھتا اور اسے خودکار طور پر تازہ کرتا ہے، بالکل ایک انٹرایکٹو `codex` سیشن کی طرح | **نہیں** — OmniRoute کبھی کسی ٹوکن کو API کو دوبارہ نہیں بھیجتا  |

چونکہ `codex-app-server` کبھی کسی ٹوکن کو دوبارہ نہیں بھیجتا، اس لیے اس پر
سیشن دوبارہ بھیجنے سے متعلق استعمال کی تنبیہ لاگو نہیں ہوتی۔ البتہ اس کے لیے
**ترتیب کردہ app-server URL پر قابلِ رسائی Codex CLI** درکار ہے، اور اس CLI کا
**سائن اِن ہونا** ضروری ہے۔

## 1. فنِ تعمیر

```
┌─ OmniRoute ایپ ─────────────────┐        ┌─ codex-app-server سائیڈکار ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ صلاحیتی ٹوکن)                │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth کا خود انتظام         │
└──────────────────────────────────┘        │  (~/.codex/auth.json، خودکار تازگی) │
        │ اشتراک کرتا ہے (compose volumes)   └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS صلاحیتی ٹوکن (دونوں اسے mount کرتے ہیں)
  codex-appserver-home    → ~/.codex (auth.json ڈیش بورڈ کے ذریعے لکھی جاتی ہے،
                             اور سائیڈکار کا codex app-server اسے پڑھتا ہے)
```

- سائیڈکار صلاحیتی ٹوکن کے پیچھے **صرف** اندرونی compose نیٹ ورک
  (`ws://codex-app-server:1456`) پر سنتا ہے۔ اسے میزبان یا انٹرنیٹ پر **کبھی**
  شائع نہیں کیا جاتا۔
- Codex CLI کو `omniroute:base` میں پہلے سے شامل کیا گیا ہے، اس لیے سائیڈکار
  چلاتے وقت میزبان یا صارف کی مشین پر codex انسٹال کرنے کی ضرورت نہیں ہوتی۔

## 2. اسے شروع کریں

```bash
# codex app-server سائیڈکار پروفائل کے ساتھ اسٹیک شروع کریں:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

سائیڈکار پہلی بار بوٹ ہونے پر اپنا WS صلاحیتی ٹوکن بناتا ہے (مشترکہ
`codex-appserver-token` volume میں) اور ایپ وہی ٹوکن
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` کے ذریعے پڑھتی ہے۔ ٹوکن کو دستی طور
پر منسلک کرنے کی ضرورت نہیں۔

## 3. منسلک کریں + سائن اِن کریں

1. ڈیش بورڈ میں **OpenAI Codex (App-Server)** کے لیے ایک کنکشن شامل کریں۔ کسی
   API کلید یا ٹوکن کی ضرورت نہیں ہے (یہ no-auth فراہم کنندہ ہے — توثیق کی
   ملکیت سائیڈکار کے پاس ہے)۔
2. اگر سائیڈکار کی Codex CLI نے **ابھی تک سائن اِن نہیں کیا**، تو کنکشن کی صحت
   کی جانچ _"چل رہا ہے لیکن سائن اِن نہیں ہے"_ کی اطلاع دیتی ہے (سرخ توثیقی
   خرابی نہیں)۔ **ChatGPT کے ساتھ سائن اِن کریں** استعمال کریں: یہ آپ کے براؤزر
   میں معیاری Codex device-OAuth چلاتا ہے اور پھر **توثیق لاگو کریں** کے ذریعے
   مشترکہ volume میں `~/.codex/auth.json` لکھتا ہے (یہی ایک لاگ اِن `codex` اور
   `codex-app-server` دونوں فراہم کنندگان کے لیے استعمال ہوتا ہے)۔
3. سائن اِن ہونے کے بعد صحت کی جانچ سبز ہو جاتی ہے (یہ `/readyz` **اور**
   `account/read` دونوں کی تصدیق کرتی ہے — یعنی سروس فعال _اور_ توثیق شدہ ہے)
   اور کام کرنا شروع کر دیتی ہے۔

ڈیش بورڈ کسی صحت مند موجودہ `~/.codex/auth.json` کو کبھی اوور رائٹ نہیں کرتا —
یہ صرف اس وقت لکھتا ہے جب فائل موجود نہ ہو یا اس کا ٹوکن فرسودہ ہو (ہمیشہ ایک
بیک اپ لیا جاتا ہے)۔

## 4. تعیناتی کے منظرنامے

- **پہلے سے توثیق شدہ Codex CLI رکھنے والا آپریٹر** — اپنے میزبان کا
  `~/.codex` سائیڈکار (`codex-appserver-home`) میں mount کریں اور سائن اِن کا
  مرحلہ چھوڑ دیں۔
- **عوامی صارف، مقامی طور پر codex انسٹال نہیں** — اس سے فرق نہیں پڑتا:
  سائیڈکار میں CLI موجود ہے۔ صارف صرف ڈیش بورڈ کے ذریعے توثیق کرتا ہے۔
- **Bare-metal OmniRoute (کوئی سائیڈکار نہیں، میزبان پر codex)** — اپنے
  `codex app-server` کی طرف `OMNIROUTE_CODEX_APPSERVER_WS` کی نشان دہی کریں اور
  یقینی بنائیں کہ میزبان کا codex سائن اِن ہے؛ اگر binary موجود نہ ہو تو
  "codex انسٹال نہیں ہے" کا اشارہ ظاہر ہوتا ہے۔

## 5. رہائشی / UDP اخراجی ٹریفک (آپریٹر کے لیے اضافی، شامل نہیں)

مندرجہ بالا عمومی سائیڈکار کنٹینر کے معمول کے نیٹ ورک کے ذریعے اخراجی ٹریفک
بھیجتا ہے۔ جس آپریٹر کو Codex ٹریفک **رہائشی خروج** کے ذریعے بھیجنے کی ضرورت ہو
(مثلاً TCP + UDP/QUIC لے جانے والا TUN tailscale سائیڈکار)، وہ اسے ایک الگ
compose override کے طور پر چلاتا ہے؛ اسے دانستہ طور پر فراہم کردہ
`codex-app-server` پروفائل کا حصہ **نہیں** بنایا گیا۔ اس سیٹ اپ کے لیے اندرونی
عملیاتی runbook دیکھیں۔
