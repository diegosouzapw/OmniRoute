OmniRoute کو OpenAI سے ہم آہنگ بیک اینڈ کے طور پر استعمال کرنے کے لیے Codex CLI کی مکمل رہنمائی۔

---

> **TOML واحد مؤثر فارمیٹ ہے۔** جدید Codex صرف `~/.codex/config.toml`
> پڑھتا ہے (codex-cli 0.147.0 کے ساتھ تصدیق شدہ: `codex --help` کے مطابق
> `-c/--config` کے اوور رائیڈز "`~/.codex/config.toml` سے لوڈ کیے جاتے ہیں")۔ پرانی
> `~/.codex/config.yaml` میراثی npm CLI سے متعلق تھی اور اسے خاموشی سے نظر انداز کر دیا جاتا ہے۔
> ڈیش بورڈ جنریٹر (`/api/cli-tools/apply`، ٹول `codex`) محتاط
> مرج کے ساتھ TOML لکھتا ہے — موجودہ کلیدیں اور دوسرے پرووائیڈر بلاکس محفوظ رہتے ہیں،
> API کلید `OMNIROUTE_API_KEY` میں رہتی ہے (فائل میں کبھی نہیں)، اور باقی رہ جانے والی میراثی
> `config.yaml` کو چھوئے بغیر مائیگریشن نوٹ کے طور پر رپورٹ کیا جاتا ہے۔

## استعمال کے لیے تیار config.toml

`<YOUR_HOST>` اور `<YOUR_KEY>` کو اپنی اقدار سے تبدیل کریں:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ہر ٹول کال کے لیے ہسٹری اسٹوریج کی حد

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc یا ~/.zshrc — اصل کلیدی قدر، config.toml میں کبھی نہیں
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT ایپ کے اندر شامل Codex

اگر آپ نے ChatGPT ڈیسک ٹاپ ایپ کے ذریعے Codex انسٹال کیا ہے تو ممکن ہے کہ `codex` بائنری
صرف ایپ بنڈل کے اندر موجود ہو اور ابھی آپ کے شیل `PATH` میں شامل نہ ہو۔ وسائل کی
ڈائریکٹری کو اپنی شیل اسٹارٹ اپ فائل میں شامل کریں:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

نیا شیل کھولیں، پھر تصدیق کریں:

```bash
command -v codex
codex --version
```

### مقامی غیر توثیق شدہ OmniRoute: پلیس ہولڈر کلید کافی ہے

Codex پہلی درخواست کے CLI سے باہر جانے **سے پہلے** تصدیق کرتا ہے کہ `env_key`
میں نامزد کردہ ماحولیاتی متغیر موجود ہے۔ اگر آپ کی **مقامی** OmniRoute
انسٹینس کو توثیق درکار نہیں تو کوئی بھی غیر خالی پلیس ہولڈر کام کرے گا:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

اگر آپ کا OmniRoute سرور محفوظ یا ریموٹ ہو تو اس کی بجائے حقیقی کلید استعمال کریں۔

> **عام ہوسٹ کے اختیارات**
>
> | رسائی         | URL                           |
> | ------------- | ----------------------------- |
> | مقامی نیٹ ورک | `http://192.168.0.1:20128/v1` |
> | Tailscale     | `http://100.x.x.x:20128/v1`   |
> | لوپ بیک       | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — یہ تمام ماڈلز کے لیے کیوں کام کرتا ہے

Codex CLI نے فروری 2026 میں `wire_api = "chat"` (Chat Completions) کو متروک قرار دیا تھا اور اب `wire_api = "responses"` (OpenAI Responses API) **لازمی** ہے۔ v0.138 سے `wire_api = "chat"` سیٹ کرنے پر آغاز کے فوراً بعد کریش ہو جاتا ہے۔

GLM اور Kimi سمیت بہت سے پرووائیڈرز اب بھی صرف Chat Completions اینڈ پوائنٹ فراہم کرتے ہیں۔ DeepSeek V4 اب مقامی Responses API کے ساتھ ساتھ Anthropic سے ہم آہنگ اینڈ پوائنٹ بھی فراہم کرتا ہے؛ OmniRoute بطور ڈیفالٹ Responses استعمال کرتا ہے اور ہر DeepSeek کنکشن کو Anthropic مطابقت منتخب کرنے دیتا ہے۔

**OmniRoute اسے شفاف طریقے سے حل کرتا ہے:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute پرووائیڈر کا مقامی پروٹوکول منتخب کرتا ہے اور ضرورت کے وقت ترجمہ کرتا ہے
    → POST /responses (DeepSeek V4) یا /chat/completions (Mistral / GLM / Kimi / دیگر)
```

OmniRoute استعمال کرتے وقت آپ کو کبھی علیحدہ ترجمہ پراکسی کی ضرورت نہیں ہوتی۔ **تمام ماڈلز `wire_api = "responses"` استعمال کرتے ہیں** — باقی کام OmniRoute سنبھالتا ہے۔

> **`wire_api` ڈیفالٹ ہے** — فیلڈ کی ڈیفالٹ قدر `"responses"` ہے اور اسے `config.toml` سے مکمل طور پر حذف کیا جا سکتا ہے۔ اسے واضح طور پر صرف اسی وقت سیٹ کریں جب آپ مقصد کو دستاویزی شکل دے رہے ہوں۔

## سیاقی ونڈو اور اختصار

### ٹوکن کنفیگریشن فیلڈز

| فیلڈ                             | وضاحت                                                                                                                                                                                                     |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | فعال ماڈل کے لیے ٹوکن کا کل بجٹ۔ اسے ماڈل کی مشتہر کردہ حد پر سیٹ کریں۔                                                                                                                                   |
| `model_auto_compact_token_limit` | وہ حد جو ہسٹری کے خودکار اختصار کو متحرک کرتی ہے۔ **زیادہ سے زیادہ: `model_context_window` کا 90%** — 90% سے زیادہ قدریں خاموشی سے نظر انداز کر دی جاتی ہیں۔                                              |
| `tool_output_token_limit`        | ہسٹری میں ہر ٹول کال کے آؤٹ پٹ کے لیے محفوظ کیے جانے والے ٹوکنز کی حد۔ یہ کسی ایک بڑے ٹول رسپانس کو پوری ونڈو بھرنے سے روکتی ہے۔ **یہ زیادہ سے زیادہ آؤٹ پٹ نہیں ہے** — یہ ہسٹری میں ذخیرہ کرنے کی حد ہے۔ |
| `compact_prompt`                 | اختصار کے دوران استعمال ہونے والے سسٹم پرامپٹ کے لیے اِن لائن اوور رائیڈ (v0.138+)۔                                                                                                                       |

> **`model_max_output_tokens` کے بارے میں نوٹ**: یہ فیلڈ **Codex CLI کنفیگ اسکیما کا حصہ نہیں ہے** (Codex Rust کوڈ بیس میں موجود نہیں)۔ سیٹ کیے جانے پر اسے خاموشی سے نظر انداز کر دیا جاتا ہے۔ اس پر انحصار نہ کریں — ہسٹری میں محفوظ ہونے والے ٹول آؤٹ پٹ کی مقدار کو کنٹرول کرنے کے لیے `tool_output_token_limit` استعمال کریں۔

## استدلال کی کوشش

یہ کنٹرول کرتا ہے کہ جواب دینے سے پہلے ماڈل کتنا "سوچتا" ہے۔

| قدر      | اس کے لیے استعمال کریں                   |
| -------- | ---------------------------------------- |
| `none`   | کوئی استدلال نہیں — براہِ راست جواب      |
| `low`    | معمولی کام (نام بدلنا، فارمیٹ کرنا)      |
| `medium` | متعین نہ ہونے پر **سرور کا ڈیفالٹ**      |
| `high`   | درمیانی درجے کے کام (ری فیکٹرنگ، ڈیبگنگ) |
| `xhigh`  | آرکیٹیکچر، گہرا تجزیہ، پیچیدہ مسائل      |

```bash
# ہر اجرا کے لیے اوور رائیڈ
codex -c model_reasoning_effort=low "متغیر x کا نام بدل کر count کریں"
codex -c model_reasoning_effort=xhigh "auth ماڈیول ڈیزائن کریں"
```

استدلال کی ایک **خلاصہ کاری** بھی متعین کریں تاکہ Desktop سوچ کا متن رینڈر کر سکے (صرف انکرپٹڈ بلابز نہیں):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # یا معاونت ہونے پر ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute سوچ کا بجٹ (سرور کی ترتیب)

OmniRoute ہوسٹ پر، **Settings → AI → Thinking Budget** کو **`passthrough`** ہونا چاہیے تاکہ Codex کی کوشش/خلاصہ upstream تک پہنچ سکے۔ **`auto` موڈ** کلائنٹ کے تمام `reasoning` / `reasoning_effort` فیلڈز ہٹا دیتا ہے اور Codex درست طور پر کنفیگر ہونے کے باوجود سوچ کے پینلز خالی کر دے گا۔

مکمل رہنما: [THINKING_BUDGET.md](./THINKING_BUDGET.md)۔

کمپریشن اور پرامپٹ کیش ایک دوسرے سے آزاد ہیں اور `passthrough` کے تحت کام کرتے رہتے ہیں۔

## پروفائلز — ہر ماڈل/ورک فلو کے لیے نام یافتہ کنفیگریشنز

پروفائلز آپ کو ایک ہی فلیگ کے ساتھ ماڈل + کانٹیکسٹ ونڈو تبدیل کرنے دیتے ہیں۔ ہر پروفائل ایک فلیٹ
`~/.codex/<name>.config.toml` فائل ہے جو بنیادی `config.toml` کے اوپر اوورلے ہوتی ہے۔

> **نام رکھنے کا اصول (Codex CLI v0.137+):** فائل لازماً `~/.codex/<name>.config.toml` ہونی چاہیے — **`profile-` پریفکس نہیں ہونا چاہیے**۔
> CLI، `-p kimi-k27` کو → `~/.codex/kimi-k27.config.toml` میں ریزولو کرتا ہے۔ اگر فائل نہ ملے تو ڈیفالٹ خاموشی سے لاگو ہو جاتا ہے۔

```bash
codex --profile kimi-k27 "اس کوڈ بیس کی 10k لائنوں کا تجزیہ کریں"
codex -p glm52 "آرکیٹیکچر کا جائزہ"
codex --profile deepseek-flash "متغیر کا نام بدلیں"   # تیز، سستا
```

### کوشش کے پروفائلز (ایک ہی ماڈل، مختلف کوشش)

```bash
codex -p low      # cx/gpt-5.5، کوشش=low
codex -p medium   # cx/gpt-5.5، کوشش=medium
codex -p high     # cx/gpt-5.5، کوشش=high
codex -p xhigh    # cx/gpt-5.5، کوشش=xhigh (ڈیفالٹ)
codex -p chat     # cx/gpt-5.5، کوئی کوشش متعین نہیں (سرور ڈیفالٹ)
```

## `omniroute setup-codex` کے ذریعے خودکار طور پر پروفائلز بنانا

اگر آپ OmniRoute کو VPS پر چلاتے ہیں، تو فعال ماڈل کیٹلاگ سے پروفائل فائلیں خودکار طور پر بنا سکتے ہیں:

```bash
# VPS سے (پورٹ 20128 پر مقامی OmniRoute استعمال کرتا ہے)
omniroute setup-codex

# کسی بھی مشین سے — اپنے VPS کی نشاندہی کریں
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# فائلیں لکھے بغیر پیش منظر دیکھیں
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# صرف GLM اور Kimi پروفائلز بنائیں
omniroute setup-codex --only glm,kimi

# حسبِ ضرورت ڈائریکٹری میں لکھیں
omniroute setup-codex --codex-home /path/to/.codex
```

یہ کمانڈ `/v1/models` حاصل کرتی ہے، معلوم ماڈلز کے لیے بہتر بنائے گئے پروفائلز استعمال کرتی ہے، دیگر موافق ٹیکسٹ ماڈلز کے لیے کیٹلاگ میٹا ڈیٹا کو متبادل کے طور پر استعمال کرتی ہے، اور ہر ایک کے لیے `~/.codex/<name>.config.toml` لکھتی ہے۔ یہ عمل idempotent ہے — اسے دوبارہ چلانا محفوظ ہے۔

جب کسی provider کے ماڈل کی کامیاب دریافت/درآمد سے فعال کیٹلاگ تبدیل ہو، تو OmniRoute انہی پروفائل فائلوں کو **خودکار طور پر sync** بھی کر سکتا ہے۔ یہ **اختیاری ہے اور بطور ڈیفالٹ بند ہوتا ہے**: اسے **CLI Code dashboard** سے فعال کریں ("CLI profile auto-sync" → Codex)، یا `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` مقرر کریں (یہ `CLI_ALLOW_CONFIG_WRITES` کا بھی احترام کرتا ہے، جو بطور ڈیفالٹ فعال ہوتا ہے)۔ فعال ہونے پر یہ صرف علیحدہ `~/.codex/*.config.toml` پروفائل فائلیں لکھتا ہے؛ یہ فعال/ڈیفالٹ `~/.codex/config.toml`، Codex-lb ترتیبات، توثیق، یا provider کے انتخاب کو کبھی تبدیل نہیں کرتا۔

## `omniroute launch-codex` کے ذریعے Codex چلانا

Codex چلانے سے پہلے آپ کے OmniRoute instance کی صحت کی جانچ کرتا ہے:

```bash
# مقامی OmniRoute کے ساتھ چلائیں (ڈیفالٹ پورٹ 20128)
omniroute launch-codex

# کسی مخصوص پروفائل کے ساتھ چلائیں
omniroute launch-codex --profile kimi-k27

# دور دراز VPS کے ساتھ چلائیں
omniroute launch-codex --remote http://100.x.x.x:20128/v1 --api-key sk-xxx

# اضافی دلائل codex کو دیں
omniroute launch-codex --profile glm52 -- --yolo "fix this bug"
```

Codex ان دو عمومی manifest پر مبنی entry points کا بھی ہدف ہے
(`bin/cli/cli-manifest.mjs`):

```bash
# انٹرایکٹو ماڈل چننے والا → ~/.codex/<name>.config.toml لکھتا ہے (TOML، env_key)
omniroute configure codex

# -c flags کے ذریعے omniroute provider شامل کر کے codex چلائیں (کوئی config نہیں لکھی جاتی)
omniroute run codex
```

## طویل دورانیے کے کام

OmniRoute کی دو ڈیفالٹ ترتیبات کئی گھنٹوں پر محیط Codex CLI سیشنز کو خاموشی سے ناکام بنا سکتی ہیں۔ ان میں سے کوئی بھی Codex CLI کی ترتیب نہیں ہے — دونوں OmniRoute کی جانب موجود ہیں۔ ایسے اپ اسٹریم پراکسیز سے کنفیگریشن منتقل کرنے والے صارفین، جو اکاؤنٹس کو پِن کرتے اور بیکار رہنے کی حد بندیاں غیر فعال کرتے ہیں، اکثر دونوں مسائل کا سامنا کرتے ہیں اور یہ نتیجہ اخذ کرتے ہیں کہ OmniRoute ”طویل سیشن برقرار نہیں رکھ سکتا۔“

| علامت                                                                                | ممکنہ وجہ                                                           | کنٹرول                   |
| ------------------------------------------------------------------------------------ | ------------------------------------------------------------------- | ------------------------ |
| سیشن مسلسل اکاؤنٹس تبدیل کرتا ہے / ٹرنز کے درمیان پرامپٹ کیش کا تسلسل ختم ہو جاتا ہے | سیشن افینیٹی TTL، `0` ہے (غیر فعال)                                 | `sessionAffinityTtlMs`   |
| کلائنٹ کو کوئی پرامپٹ دکھائے بغیر دورانِ استدلال کنکشن منقطع ہو جاتا ہے              | اپ اسٹریم چنک نہ آنے پر 10 منٹ بعد اسٹریم آئیڈل واچ ڈاگ فعال ہو گیا | `STREAM_IDLE_TIMEOUT_MS` |

متعلقہ مباحث: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (طویل کام کا منقطع ہونا)، [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (افینیٹی ڈیفالٹ طور پر غیر فعال کیوں ہے)۔ ٹریکنگ: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287)۔

### 1. سیشن افینیٹی — ایک گفتگو کو ایک اکاؤنٹ کے ساتھ پِن کریں

**ڈیفالٹ:** `sessionAffinityTtlMs = 0` (غیر فعال)۔

**اسے کہاں مقرر کریں**

- ڈیش بورڈ → **ترتیبات → روٹنگ** → **سیشن افینیٹی** → **افینیٹی TTL (سیکنڈز)** (`ComboDefaultsTab`)
- یا **ملی سیکنڈز** میں `sessionAffinityTtlMs` کے ساتھ ترتیبات کو PATCH کریں (Zod رینج `0`–`86_400_000`، یعنی زیادہ سے زیادہ 24 گھنٹے)

> #7274 میں اس کا نام صرف Codex کے لیے مخصوص `codexSessionAffinityTtlMs` سے تبدیل کیا گیا۔ پرانی کلید اب بھی صرف پڑھنے کے عرف کے طور پر قبول کی جاتی ہے؛ نئی کنفیگریشنز کو `sessionAffinityTtlMs` استعمال کرنا چاہیے۔ TTL کے `0` سے زیادہ ہوتے ہی افینیٹی اب صرف Codex نہیں بلکہ **کسی بھی** پرووائیڈر پر لاگو ہوتی ہے — [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → سیشن افینیٹی دیکھیں۔

**اسے 0 پر رکھنے سے کیا خراب ہوتا ہے**

کثیر ٹرن والی Codex گفتگو کے ہر ٹرن کو فعال کومبو حکمتِ عملی کے ذریعے الگ سے روٹ کیا جاتا ہے اور ہر ٹرن **مختلف اکاؤنٹ** پر پہنچ سکتا ہے۔ اس سے اپ اسٹریم سیشن / پرامپٹ کیش کا تسلسل ٹوٹ جاتا ہے۔ OmniRoute صرف اسی وقت Codex سیشن ہیڈرز (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) اور `prompt_cache_key` / `session_id` جیسی باڈی فیلڈز کو دیکھتا ہے جب TTL، `0` سے زیادہ ہو (`src/sse/services/auth.ts` میں `extractSessionAffinityKey`)۔

**کئی گھنٹوں کے ایک واحد کام کے لیے تجویز**

TTL کو **کام کے متوقع حقیقی دورانیے سے زیادہ** مقرر کریں (UI کی زیادہ سے زیادہ حد **86400 سیکنڈز** = 24 گھنٹے ہے):

| کام کا متوقع دورانیہ       | افینیٹی TTL (UI، سیکنڈز)           | `sessionAffinityTtlMs` |
| -------------------------- | ---------------------------------- | ---------------------- |
| چند گھنٹے                  | `14400` (4 گھنٹے)                  | `14400000`             |
| رات بھر / تقریباً 12 گھنٹے | `43200` (12 گھنٹے)                 | `43200000`             |
| پورا دن                    | `86400` (24 گھنٹے، زیادہ سے زیادہ) | `86400000`             |

اختیاری فعال کاری دانستہ ہے: افینیٹی کو غیر فعال کرنا اکاؤنٹس کے درمیان لوڈ بیلنسنگ کو ترجیح دیتا ہے؛ اسے فعال کرنا ایک طویل ایجنٹ سیشن کے تسلسل کو ترجیح دیتا ہے۔ یہ رہنما ڈیفالٹ کو تبدیل **نہیں** کرتا — طویل Codex کام چلانے والے آپریٹرز کو خود اسے فعال کرنا ہوگا۔

### 2. اسٹریم آئیڈل ٹائم آؤٹ — خاموش استدلالی ٹرنز کو ختم نہ کریں

**ڈیفالٹ:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 منٹ)۔ مقرر نہ ہونے کی صورت میں یہ `REQUEST_TIMEOUT_MS` سے قدر اخذ کرتا ہے؛ مشترکہ بنیادی قدر بھی 600000 ہے۔ [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → ٹائم آؤٹس دیکھیں۔

**ڈیفالٹ قدر پر کیا خراب ہوتا ہے**

Codex کا کوئی reasoning / tool turn جو **بغیر کسی حقیقی upstream chunk** کے 10 منٹ سے زیادہ خاموش رہے، اسے SSE idle watchdog (`open-sse/utils/stream.ts`) زبردستی بند کر دیتا ہے۔ کلائنٹ کو اکثر صرف کنکشن منقطع ہوتا دکھائی دیتا ہے — جو “بغیر کسی اطلاع کے خودکار طور پر رک گیا” سے مطابقت رکھتا ہے۔

اہم تفصیل: OmniRoute کا مصنوعی SSE **heartbeat idle clock کو reset نہیں کرتا**۔ صرف حقیقی upstream body chunk ہی `lastChunkTime` کو اپ ڈیٹ کرتا ہے۔ ایسا خاموش model جو اب بھی “سوچ” رہا ہو، watchdog کے نقطۂ نظر سے رکے ہوئے upstream جیسا ہی دکھائی دیتا ہے۔

متعلقہ Undici body inactivity: `FETCH_BODY_TIMEOUT_MS` (یہ بھی بطور ڈیفالٹ اسی 10 منٹ کی baseline پر ہوتا ہے؛ `0` اسے غیر فعال کر دیتا ہے)۔ streaming کے لیے، `FETCH_TIMEOUT_MS` صرف connection setup / ابتدائی headers کا احاطہ کرتا ہے — stream فعال ہونے کے بعد، تعطل کو `STREAM_IDLE_TIMEOUT_MS` اور `FETCH_BODY_TIMEOUT_MS` کنٹرول کرتے ہیں۔

**کئی گھنٹوں کے ایک واحد task کے لیے تجویز**

OmniRoute process environment (`.env` / compose / systemd) میں:

```bash
# طویل reasoning turns کے لیے stream idle اور body inactivity cutoffs غیر فعال کریں
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

یا انہیں اپنے متوقع طویل ترین خاموش وقفے سے زیادہ کر دیں (قدریں milliseconds میں ہیں):

```bash
# مثال: upstream chunks کے درمیان 2 گھنٹے تک خاموشی کی اجازت دیں
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

ان env vars کو تبدیل کرنے کے بعد OmniRoute کو restart کریں۔

### عملی طریقہ — کئی گھنٹوں کا Codex task

1. **اکاؤنٹ pin کریں:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) یا `86400` (زیادہ سے زیادہ 24h)۔
2. OmniRoute کے environment میں **idle cutoffs بڑھائیں / غیر فعال کریں**:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. معمول کا Codex `config.toml` (`wire_api = "responses"`، درست `base_url`، `OMNIROUTE_API_KEY`) برقرار رکھیں — ان دونوں رویّوں کے لیے Codex کی جانب کوئی affinity/idle knobs موجود نہیں ہیں۔
4. OmniRoute کو restart کریں، پھر طویل Codex task شروع کریں۔

### ڈیفالٹس کا فیصلہ (#7287)

| Knob                     | جاری کردہ ڈیفالٹ  | کیا اس گائیڈ میں تبدیل کریں؟                                                                         |
| ------------------------ | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (بند)         | **نہیں** — opt-in ہی رہے گا (load-balancing بمقابلہ continuity؛ Discussion #5718 دیکھیں)             |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 منٹ) | **نہیں** — عمومی traffic کے لیے 10 منٹ ہی رہے گا؛ طویل Codex چلانے والے اسے بڑھائیں یا غیر فعال کریں |

کسی بھی ڈیفالٹ کو عالمی طور پر تبدیل کرنے سے instance کے ہر کلائنٹ کا رویہ بدل جائے گا، صرف Codex کا نہیں۔ knobs کو دستاویزی شکل دیں؛ جب تک کوئی واضح operator decision اس کے برعکس نہ ہو، ڈیفالٹس کو برقرار رہنے دیں۔

### Idle cuts کی تشخیص

جب idle watchdog متحرک ہوتا ہے، OmniRoute اس ساخت کی ایک سطر log کرتا ہے:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` (یا code `stream_idle_timeout` / error name `StreamIdleTimeoutError`) کو grep کریں۔ provider segment وہی ہوتا ہے جسے OmniRoute نے اس request کے لیے استعمال کیا (`codex`، کوئی دوسرا provider id، یا نامعلوم ہونے کی صورت میں `provider`) — یہ ہمیشہ حرف بہ حرف `codex` نہیں ہوتا۔

## خرابیوں کا ازالہ

**`Error: wire_api = "chat" is no longer supported`**
اپنی کنفیگریشن سے `wire_api = "chat"` ہٹا دیں۔ `wire_api = "responses"` سیٹ کریں یا فیلڈ کو حذف کر دیں (v0.138 سے ڈیفالٹ `"responses"` ہے)۔

**`Error: model not found`**
تصدیق کریں کہ ماڈل درست سابقے کے ساتھ OmniRoute میں موجود ہے۔ `omniroute models list` استعمال کریں یا `/dashboard/providers/<provider>` کھولیں۔

**`Authentication error`**
تصدیق کریں کہ `OMNIROUTE_API_KEY` ایکسپورٹ کیا گیا ہے: `echo $OMNIROUTE_API_KEY`۔

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex پہلی درخواست کرنے سے پہلے تصدیق کرتا ہے کہ env var موجود ہے۔ محفوظ سرورز کے لیے
حقیقی key ایکسپورٹ کریں، یا جب آپ کے **مقامی** OmniRoute instance کو
auth درکار نہ ہو تو `OMNIROUTE_API_KEY=local` جیسی کوئی غیر خالی placeholder قدر استعمال کریں۔
اگر آپ نے اسے `~/.bashrc` یا `~/.zshrc` میں شامل کیا ہے تو shell دوبارہ شروع کریں۔

**`Connection refused`**
تصدیق کریں کہ OmniRoute چل رہا ہے اور `base_url` کا host/port آپ کے نیٹ ورک (local بمقابلہ Tailscale بمقابلہ VPS) کے لیے درست ہے۔

**سیاق کی حد کے قریب سیشن کریش ہو جاتا ہے**
`model_context_window` اور `model_auto_compact_token_limit` کو واضح طور پر سیٹ کریں۔ اوپر دی گئی سیاقی ونڈو کی جدول دیکھیں۔

**Compaction بہت دیر سے متحرک ہوتی ہے**
`model_auto_compact_token_limit` کو ونڈو کے 80–85% تک کم کریں۔ اسے کبھی بھی 90% سے زیادہ سیٹ نہ کریں۔

**پروفائل لوڈ نہیں ہو رہا (`-p <name>` خاموشی سے نظر انداز ہو جاتا ہے)**
تصدیق کریں کہ فائل `~/.codex/<name>.config.toml` پر موجود ہے (`profile-` سابقے کے بغیر)۔ `ls ~/.codex/*.config.toml` چلائیں۔

**طویل Codex ٹاسک دورانِ اجرا منقطع ہو جاتا ہے / ٹرنز کے درمیان اکاؤنٹس تبدیل ہو جاتے ہیں**
[طویل عرصے تک چلنے والے ٹاسکس](#long-running-tasks) دیکھیں۔ session affinity فعال کریں (TTL ٹاسک کی مدت سے زیادہ ہو) اور `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` کو بڑھائیں یا غیر فعال کریں۔ OmniRoute لاگز میں `Idle timeout: no data from` تلاش کرنے کے لیے grep استعمال کریں۔
