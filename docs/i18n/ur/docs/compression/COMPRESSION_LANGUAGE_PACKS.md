Caveman کمپریشن، پہلے سے موجود انگریزی قواعد کے علاوہ زبان کے لیے مخصوص رول پیکس بھی لوڈ کر سکتی ہے۔
اس سے بنیادی انجن مستحکم رہتا ہے، جبکہ پرتگالی، ہسپانوی، جرمن، فرانسیسی، اطالوی، جاپانی، اور
مستقبل کے زبان پیکس آزادانہ طور پر ارتقا کر سکتے ہیں۔

## مقام

زبان پیکس یہاں موجود ہیں:

```txt
open-sse/services/compression/rules/<language>/
```

فی الحال فراہم کردہ پیکس (`rules/` ڈائریکٹری کے مندرجات کے مقابلے میں تصدیق شدہ):

| زبان             | ڈائریکٹری      | موجود رول کیٹیگریز                                  |
| ---------------- | -------------- | --------------------------------------------------- |
| انگریزی          | `rules/en/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| ہسپانوی          | `rules/es/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| پرتگالی (برازیل) | `rules/pt-BR/` | `context`, `dedup`, `filler`, `structural`, `ultra` |
| انڈونیشیائی      | `rules/id/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| اطالوی           | `rules/it/`    | `context`, `dedup`, `filler`, `structural`, `ultra` |
| جرمن             | `rules/de/`    | `context`, `filler`, `structural`                   |
| فرانسیسی         | `rules/fr/`    | `context`, `filler`, `structural`                   |
| جاپانی           | `rules/ja/`    | `context`, `filler`, `structural`                   |

> **برابری سے متعلق نوٹ:** `en`, `es`, `pt-BR`, `id`، اور `it` پیکس میں تمام 5 کیٹیگریز موجود ہیں؛ `de`, `fr`, `ja` میں 3 کیٹیگریز فراہم کی جاتی ہیں۔ غیر موجود `dedup` اور `ultra` کیٹیگریز خاموشی سے پہلے سے موجود انگریزی قواعد استعمال کرتی ہیں۔ چھوٹے پیکس میں `dedup.json` اور `ultra.json` شامل کرنے کے لیے تعاون کا خیرمقدم ہے۔
>
> `pt-BR` پیک Lenine Júnior کے **[Troglodita](https://github.com/leninejunior/troglodita)** پر مبنی ہے — یہ برازیلی پرتگالی گرامر کے لیے ابتدا سے ڈیزائن کردہ ایک کمپریشن سسٹم ہے (حشو میں کمی، PT-BR کے غیر ضروری الفاظ کا اخراج، اور برازیلی ڈویلپر کمیونٹی کے لیے تکنیکی اختصارات)۔
>
> مستند کیٹیگری فہرست اور ہر کیٹیگری کا اسکیما [`open-sse/services/compression/rules/_schema.json`](../../open-sse/services/compression/rules/_schema.json) میں موجود ہے (JSON Schema draft 2020-12)۔

## زبان کی شناخت

`languageDetector.ts` پرامپٹ متن سے زبان کا اندازہ لگانے کے لیے ہلکی پھلکی ہیورسٹکس استعمال کرتا ہے۔
کنفیگر کردہ ڈیفالٹ زبان کا اب بھی لحاظ رکھا جاتا ہے، اور جب عین کنٹرول درکار ہو تو کنفیگ کے ذریعے
شناخت کو غیر فعال کیا جا سکتا ہے۔

شناخت کا آؤٹ پٹ صرف رول پیکس منتخب کرنے کے لیے استعمال ہوتا ہے۔ یہ پرووائیڈر روٹنگ، لوکیل
کے انتخاب، یا UI کی زبان کو تبدیل نہیں کرتا۔

## کنفیگ کی ساخت

کمپریشن کی ترتیبات میں یہ شامل ہو سکتا ہے:

```json
{
  "languageConfig": {
    "enabled": true,
    "defaultLanguage": "en",
    "autoDetect": true,
    "enabledPacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  },
  "cavemanConfig": {
    "language": "en",
    "autoDetectLanguage": true,
    "enabledLanguagePacks": ["en", "pt-BR", "es", "id", "de", "fr", "ja"]
  }
}
```

`languageConfig` ڈیش بورڈ/پری ویو کے ڈیفالٹس کو کنٹرول کرتا ہے۔ `cavemanConfig` رن ٹائم انجن کی کنفیگ ہے
جو Caveman کے پیغام کے متن کو کمپریس کرتے وقت استعمال ہوتی ہے۔

## زبان پیک شامل کرنا

1. `open-sse/services/compression/rules/<language>/<pack>.json` بنائیں۔
2. `docs/compression/COMPRESSION_RULES_FORMAT.md` میں موجود Caveman اصولوں کا فارمیٹ استعمال کریں۔
3. تبدیلیوں کو محتاط رکھیں اور کوڈ، identifiers، URLs، یا JSON کو تبدیل کرنے سے گریز کریں۔
4. زبان کے انتخاب اور تبدیلی کے رویّے کے لیے ٹیسٹس شامل یا اپ ڈیٹ کریں۔
5. اگر زبان UI selectors میں ظاہر ہوتی ہے تو نئے dashboard/i18n labels دستیاب کریں۔

## API

دستیاب پیکس کے بارے میں اس طرح استفسار کیا جا سکتا ہے:

```bash
curl http://localhost:20128/api/compression/language-packs
```

پیش نظارہ endpoint زبان کی config overrides قبول کرتا ہے:

```bash
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{
    "mode": "standard",
    "text": "Por favor, eu gostaria que voce basicamente resumisse isso.",
    "config": {
      "languageConfig": {
        "defaultLanguage": "pt-BR",
        "autoDetect": true
      }
    }
  }'
```

## SHARED_BOUNDARIES (v3.8.0)

v3.8.0 میں تمام 6 زبان پیکس کو ایک `SHARED_BOUNDARIES` شق دی گئی، جو Caveman کی ہر
شدت (LITE, FULL, ULTRA) پر لاگو ہوتی ہے۔ یہ engine کو ہدایت دیتی ہے کہ اردگرد کے غیر ضروری متن کو ہٹانے سے قطع نظر،
ان نمونوں کو من و عن محفوظ رکھا جائے:

| نمونے کی قسم              | مثال                                   |
| ------------------------- | -------------------------------------- |
| Fenced کوڈ بلاکس          | ` ```python\n...\n``` `                |
| Inline کوڈ                | `` `my_var` ``                         |
| URLs                      | `https://example.com/path`             |
| فائل پاتھس (مطلق + نسبتی) | `/etc/hosts`, `./src/index.ts`         |
| خرابی کے headers          | `Error:`, `TypeError:`, `SyntaxError:` |
| Stack trace سطریں         | `  at functionName (file.ts:12:3)`     |

یہ نمونے `DEFAULT_CAVEMAN_CONFIG.preservePatterns` میں شامل کیے جاتے ہیں (پہلے `[]` تھا)۔
یہ constant `open-sse/services/compression/types.ts` میں موجود ہے۔

### یہ کیوں اہم ہے

SHARED_BOUNDARIES کے بغیر، جارحانہ Caveman modes ایسے مواد کو حذف کر سکتے تھے جو بظاہر دہرایا ہوا
نثری متن لگتا تھا، مگر دراصل کوڈ snippet، فائل پاتھ، یا error stack ہوتا تھا۔ SHARED_BOUNDARIES ایک
زبان سے آزاد حفاظتی جال کے طور پر کام کرتا ہے، جو filler اصول چلنے سے پہلے لاگو ہوتا ہے۔

### preservePatterns کو حسبِ ضرورت بنانا

compression settings کے ذریعے runtime پر اضافی نمونے شامل کیے جا سکتے ہیں:

````json
{
  "cavemanConfig": {
    "preservePatterns": [
      "```[\\s\\S]*?```",
      "`[^`]+`",
      "https?://\\S+",
      "(?:/|\\./)[^\\s]+",
      "\\b(?:Error|TypeError|SyntaxError|RangeError):",
      "\\s+at\\s+\\S+\\s+\\(\\S+:\\d+:\\d+\\)"
    ]
  }
}
````

حسبِ ضرورت نمونے 6 defaults میں توسیع کرتے ہیں (ان کی جگہ نہیں لیتے)۔

## عملی نوٹس

- جب کوئی زبان پیک موجود نہ ہو تو English کے built-in اصول fallback کے طور پر برقرار رہتے ہیں۔
- غیر معتبر built-in JSON پیکس validation میں ناکام ہو جاتے ہیں تاکہ release assets کا معیار خاموشی سے کم نہ ہو۔
- اصولوں کے پیکس صرف data پر مشتمل ہوتے ہیں اور انہیں کوڈ import نہیں کرنا چاہیے یا صوابدیدی logic نہیں چلانی چاہیے۔
- compression analytics layer منتخب کردہ mode اور engine کو ریکارڈ کرتی ہے، مکمل prompt text کو نہیں۔
