یہ دستاویز Fly.io پر OmniRoute کی اصل تعیناتی کے عمل کی وضاحت کرتی ہے، جس میں دو صورتوں کا احاطہ کیا گیا ہے:

- موجودہ پروجیکٹ کو پہلی بار Fly.io پر تعینات کرنا
- بعد میں کوڈ کی اپ ڈیٹس شائع کرنا
- اسی تعیناتی کے ورک فلو پر عمل کرنے والے نئے پروجیکٹس

یہ رہنما موجودہ پروجیکٹ کے لیے تصدیق شدہ اور عملی کنفیگریشن پر مبنی ہے۔ ایپلیکیشن کا نام `omniroute` ہے۔

---

## 1. تعیناتی کے اہداف

- پلیٹ فارم: Fly.io
- تعیناتی کا طریقہ: مقامی `flyctl` کے ذریعے براہِ راست اشاعت
- رن ٹائم: ریپوزٹری میں موجود `Dockerfile` اور `fly.toml` کا استعمال
- ڈیٹا کا مستقل ذخیرہ: `/data` پر ماؤنٹ کیا گیا Fly Volume
- رسائی کا URL: `https://omniroute.fly.dev/`

---

## 2. موجودہ پروجیکٹ کی کلیدی کنفیگریشن

اس بات کی تصدیق ہو چکی ہے کہ موجودہ ریپوزٹری میں موجود `fly.toml` درج ذیل کلیدی آئٹمز پر مشتمل ہے:

```toml
app = 'omniroute'
primary_region = 'sin'

[[mounts]]
  source = 'data'
  destination = '/data'

[processes]
  app = 'node run-standalone.mjs'

[http_service]
  internal_port = 20128

[env]
  TZ = "Asia/Shanghai"
  HOST = "0.0.0.0"
  HOSTNAME = "0.0.0.0"
  BIND = "0.0.0.0"
```

نوٹس:

- `app = 'omniroute'` یہ طے کرتا ہے کہ تعیناتی کس Fly ایپلیکیشن کو ہدف بنائے گی
- `destination = '/data'` مستقل والیوم کی ماؤنٹ ڈائریکٹری طے کرتا ہے
- اس پروجیکٹ میں `DATA_DIR=/data` سیٹ کرنا ضروری ہے، بصورتِ دیگر ڈیٹابیس اور کلیدیں کنٹینر کی عارضی ڈائریکٹری میں لکھی جائیں گی

## 3. پیشگی تقاضے

### 3.1 Fly CLI انسٹال کرنا

Windows PowerShell:

```powershell
pwsh -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

اگر آپ کے ماحول میں انسٹالیشن اسکرپٹ ناکام ہو جائے، تو آپ `flyctl` بائنری کو دستی طور پر ڈاؤن لوڈ کر کے اپنے `PATH` میں شامل بھی کر سکتے ہیں۔

### 3.2 اپنے Fly اکاؤنٹ میں لاگ اِن کرنا

```powershell
flyctl auth login
```

### 3.3 لاگ اِن کی حالت کی تصدیق کرنا

```powershell
flyctl auth whoami
flyctl version
```

## 4. موجودہ پروجیکٹ کی پہلی بار تعیناتی

### 4.1 کوڈ کلون کریں اور ڈائریکٹری میں داخل ہوں

```powershell
git clone https://github.com/diegosouzapw/OmniRoute.git
cd OmniRoute
```

### 4.2 ایپلیکیشن کے نام کی تصدیق کریں

`fly.toml` کھولیں اور درج ذیل لائن کی تصدیق کریں:

```toml
app = 'omniroute'
```

اگر آپ اپنی نئی ایپلیکیشن پر تعینات کر رہے ہیں، تو آپ اسے عالمی طور پر منفرد نام میں تبدیل کر سکتے ہیں، مثلاً:

```toml
app = 'omniroute-yourname'
```

نوٹ:

- یقینی بنائیں کہ کنسول میں دکھائی دینے والی ایپلیکیشن `fly.toml` میں موجود `app` کی قدر سے مطابقت رکھتی ہو
- اگر آپ نے پہلے کوئی مختلف نام استعمال کیا تھا، جیسے `oroute`، تو اسے `omniroute` کے ساتھ خلط ملط نہ کریں

### 4.3 ایپلیکیشن بنائیں

اگر ایپلیکیشن ابھی موجود نہیں ہے:

```powershell
flyctl apps create omniroute
```

اگر آپ نے ایپلیکیشن کا نام تبدیل کیا ہے، تو `omniroute` کو اپنے منتخب کردہ نام سے بدل دیں۔

### 4.4 پہلی تعیناتی

```powershell
flyctl deploy
```

## 5. مطلوبہ پیرامیٹرز

یہ پروجیکٹ Fly.io پر کم از کم درج ذیل پیرامیٹرز کنفیگر کرنے کی تجویز دیتا ہے۔

### 5.1 تصدیق شدہ پیرامیٹرز

یہ پیرامیٹرز موجودہ `omniroute` ایپلیکیشن کی حقیقی تعیناتیوں میں استعمال کیے گئے ہیں:

- `API_KEY_SECRET`
- `DATA_DIR`
- `JWT_SECRET`
- `MACHINE_ID_SALT`
- `NEXT_PUBLIC_BASE_URL`
- `OMNIROUTE_WS_BRIDGE_SECRET` (پروڈکشن میں درکار — WebSocket برج کی توثیق کے لیے استعمال ہوتا ہے)
- `STORAGE_ENCRYPTION_KEY`

### 5.2 `INITIAL_PASSWORD` کے بارے میں

موجودہ پروجیکٹ میں `INITIAL_PASSWORD` سیٹ نہیں کیا گیا کیونکہ اس تعیناتی کے لیے اس کی ضرورت نہیں ہے۔

اگر اسے سیٹ نہ کیا جائے:

- اسٹارٹ اپ لاگ ظاہر کرے گا کہ ڈیفالٹ پاس ورڈ `CHANGEME` ہے
- تعیناتی کے بعد آپ کو جلد از جلد سسٹم سیٹنگز میں لاگ اِن پاس ورڈ تبدیل کرنا چاہیے

اگر آپ بغیر دستی مداخلت کے بیک اینڈ پاس ورڈ کی ابتدائی ترتیب کرنا چاہتے ہیں، تو آپ اسے بعد میں شامل کر سکتے ہیں:

- `INITIAL_PASSWORD`

## 6. تجویز کردہ پیرامیٹرز

### 6.1 Secrets کی ترتیب

Fly Secrets کے لیے درج ذیل متغیرات تجویز کیے جاتے ہیں:

| متغیر                        | سفارش             | وضاحت                                                      |
| ---------------------------- | ----------------- | ---------------------------------------------------------- |
| `API_KEY_SECRET`             | لازمی             | API Key بنانے اور اس کی توثیق کے لیے استعمال ہوتا ہے       |
| `JWT_SECRET`                 | لازمی             | لاگ اِن سیشنز اور JWT پر دستخط کرنے کے لیے استعمال ہوتا ہے |
| `OMNIROUTE_WS_BRIDGE_SECRET` | پروڈکشن میں لازمی | WebSocket برج کی توثیق کا راز                              |
| `STORAGE_ENCRYPTION_KEY`     | پُرزور تجویز کردہ | محفوظ شدہ حساس کنکشن کی معلومات کو انکرپٹ کرتا ہے          |
| `MACHINE_ID_SALT`            | تجویز کردہ        | ایک مستقل مشین شناخت کنندہ بناتا ہے                        |
| `INITIAL_PASSWORD`           | اختیاری           | پہلی تعیناتی پر ابتدائی بیک اینڈ پاس ورڈ مقرر کرتا ہے      |
| OAuth/API نجی اسناد          | حسبِ ضرورت        | بیرونی پلیٹ فارم کی توثیق کی ترتیب                         |

### 6.2 موجودہ پروجیکٹ کے لیے تجویز کردہ اقدار

| متغیر                  | تجویز کردہ قدر              |
| ---------------------- | --------------------------- |
| `DATA_DIR`             | `/data`                     |
| `NEXT_PUBLIC_BASE_URL` | `https://omniroute.fly.dev` |

نوٹس:

- `DATA_DIR=/data` نہایت اہم ہے اور اسے Fly Volume کے ماؤنٹ پوائنٹ سے مطابقت رکھنا ضروری ہے
- `NEXT_PUBLIC_BASE_URL` شیڈیولر، فرنٹ اینڈ کال بیکس، اور اسی نوعیت کے دیگر حالات میں استعمال ہوتا ہے

### 6.3 OAuth کال بیک URL کی ترتیب

اگر آپ Fly.io کی تعیناتی پر OAuth پر مبنی فراہم کنندگان (مثلاً Antigravity، Gemini، Cursor) فعال کرنا چاہتے ہیں، تو درج ذیل دو نکات یقینی بنائیں:

1. **`NEXT_PUBLIC_BASE_URL` کو اپنے عوامی HTTPS ڈومین پر مقرر کریں**

   ```powershell
   flyctl secrets set NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev -a omniroute
   ```

   اگر آپ حسبِ ضرورت ڈومین استعمال کر رہے ہیں، تو اسے متعلقہ ڈومین سے بدل دیں (مثلاً `https://omniroute.yourdomain.com`)۔

2. **فراہم کنندہ کے کنسول میں کال بیک URL ترتیب دیں**

   تمام OAuth فراہم کنندگان ایک ہی کال بیک پاتھ `/callback` استعمال کرتے ہیں — ہر فراہم کنندہ کے لیے کوئی الگ کال بیک روٹ موجود نہیں ہے:

   ```text
   <NEXT_PUBLIC_BASE_URL>/callback
   ```

   مثال کے طور پر، Gemini، Antigravity، Cursor، یا GitLab Duo میں سے کوئی بھی ہو:
   - `https://omniroute.fly.dev/callback`

   اگر `NEXT_PUBLIC_BASE_URL` فراہم کنندہ کے ساتھ رجسٹرڈ کال بیک URL سے مطابقت نہیں رکھتا، تو OAuth کا عمل براؤزر ری ڈائریکٹ کے مرحلے پر ناکام ہو جائے گا۔

## 7. ایک کمانڈ سے Secrets کی ترتیب

درج ذیل کمانڈز محفوظ بے ترتیب اقدار بناتی ہیں اور موجودہ پروجیکٹ کے تمام مطلوبہ پیرامیٹرز ایک ہی مرحلے میں Fly Secrets میں لکھ دیتی ہیں۔

نوٹس:

- اس میں `INITIAL_PASSWORD` شامل نہیں ہے
- یہ موجودہ پروجیکٹ `omniroute` کے لیے ہے

```powershell
$apiKeySecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$jwtSecret = [Convert]::ToHexString((1..64 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$machineIdSalt = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$storageKey = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()
$wsBridgeSecret = [Convert]::ToHexString((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 })).ToLower()

flyctl secrets set `
  API_KEY_SECRET=$apiKeySecret `
  JWT_SECRET=$jwtSecret `
  MACHINE_ID_SALT=$machineIdSalt `
  STORAGE_ENCRYPTION_KEY=$storageKey `
  OMNIROUTE_WS_BRIDGE_SECRET=$wsBridgeSecret `
  DATA_DIR=/data `
  NEXT_PUBLIC_BASE_URL=https://omniroute.fly.dev `
  -a omniroute
```

Linux / macOS پر، آپ `openssl rand -hex 32` بھی استعمال کر سکتے ہیں:

```bash
flyctl secrets set OMNIROUTE_WS_BRIDGE_SECRET=$(openssl rand -hex 32) -a omniroute
```

نوٹس:

- `OMNIROUTE_WS_BRIDGE_SECRET` پروڈکشن میں لازمی ہے؛ اس کی عدم موجودگی WebSocket برج ہینڈ شیک کو ناکام کر دے گی

اگر آپ ابتدائی پاس ورڈ بھی مقرر کرنا چاہتے ہیں:

```powershell
flyctl secrets set INITIAL_PASSWORD=your-strong-password -a omniroute
```


- یہ کہ `fly.toml` میں `app` کی قدر کنسول میں موجود ایپلیکیشن سے مطابقت رکھتی ہے

## 9. بعد کی اپ ڈیٹس اور ریلیزز

کوڈ اپ ڈیٹس کے بعد، ریلیز کا عمل سیدھا سادہ ہے:

```powershell
git pull
flyctl deploy
```

اگر آپ کو کوڈ تبدیل کیے بغیر صرف پیرامیٹرز اپ ڈیٹ کرنے ہوں:

```powershell
flyctl secrets set KEY=value -a omniroute
```

Fly خودکار طور پر مشینوں کی رولنگ اپ ڈیٹ انجام دے گا۔

### 9.1 اپنے فورک کی `fly.toml` محفوظ رکھتے ہوئے اپ اسٹریم ریپوزٹری کی اپ ڈیٹس ٹریک کرنا

اگر موجودہ ریپوزٹری ایک فورک ہے اور آپ اپ اسٹریم `https://github.com/diegosouzapw/OmniRoute` سے اپ ڈیٹس ہم وقت کرنا چاہتے ہیں، تو ذیل کے ورک فلو پر عمل کریں۔

سب سے پہلے، اپنے ریموٹس کی تصدیق کریں:

```powershell
git remote -v
```

آپ کو کم از کم یہ نظر آنا چاہیے:

- `origin` آپ کے اپنے فورک کی طرف اشارہ کرتا ہو
- `upstream` اصل ریپوزٹری کی طرف اشارہ کرتا ہو

اگر `upstream` کنفیگر نہیں ہے، تو اسے شامل کریں:

```powershell
git remote add upstream https://github.com/diegosouzapw/OmniRoute.git
```

اپ اسٹریم کے ساتھ ہم وقت کرنے سے پہلے، تازہ ترین کمیٹس اور ٹیگز حاصل کریں:

```powershell
git fetch upstream --tags
```

موجودہ ورژن اور اپ اسٹریم ٹیگز چیک کریں:

```powershell
git describe --tags --always
git show --no-patch --oneline v3.4.7
```

> نوٹ: موجودہ پروجیکٹ ورژن `v3.8.0` ہے۔ ذیل میں `v3.4.7` کے حوالہ جات صرف تاریخی مثالوں کے طور پر برقرار رکھے گئے ہیں۔ حقیقی ریلیزز کے لیے `:latest` یا موجودہ ورژن ٹیگ (مثلاً `:v3.8.0`) استعمال کریں۔

اگر آپ اپنے فورک کی `fly.toml` کو لازماً برقرار رکھتے ہوئے تازہ ترین اپ اسٹریم `main` کو مرج کرنا چاہتے ہیں، تو اس ورک فلو پر عمل کریں:

```powershell
git merge upstream/main
git checkout HEAD~1 -- fly.toml
git add -- fly.toml
git commit -m "chore(deploy): keep fork fly.toml"
git push origin main
```

نوٹس:

- `git merge upstream/main` اصل ریپوزٹری سے تازہ ترین کوڈ ہم وقت کرتا ہے
- `git checkout HEAD~1 -- fly.toml` مرج سے پہلے والی آپ کے فورک کی اپنی `fly.toml` بحال کرتا ہے
- اگر اپ اسٹریم نے `fly.toml` میں ترمیم نہیں کی، تو یہ مرحلہ کوئی فرق متعارف نہیں کرائے گا
- اگر اپ اسٹریم نے `fly.toml` میں ترمیم کی ہے، تو یہ مرحلہ یقینی بناتا ہے کہ آپ کی Fly ایپلیکیشن کا نام، والیوم ماؤنٹ، ریجن، اور فورک سے مخصوص دیگر ڈپلائمنٹ کنفیگریشن اوور رائٹ نہ ہوں

اگر آپ کسی مخصوص ریلیز ٹیگ (مثلاً `v3.4.7`) کے مطابق ہم آہنگ ہونا چاہتے ہیں، تو پہلے تصدیق کریں کہ ٹیگ پہلے ہی `upstream/main` میں شامل ہے:

```powershell
git merge-base --is-ancestor v3.4.7 upstream/main
```

کامیاب واپسی کا مطلب ہے کہ `upstream/main` میں وہ ورژن پہلے ہی موجود ہے؛ آپ صرف `upstream/main` کو مرج کر سکتے ہیں۔

### 9.2 اپ اسٹریم کے ساتھ ہم وقت کرنے کے بعد معیاری ریلیز ترتیب

اصل ریپوزٹری کے ساتھ ہم وقت کرنے کے بعد، ریلیز کی اس تجویز کردہ ترتیب پر عمل کریں:

1. `git fetch upstream --tags`
2. `git merge upstream/main`
3. فورک کی `fly.toml` بحال کریں
4. `git push origin main`
5. `flyctl deploy`
6. `flyctl status -a omniroute`
7. `flyctl logs --no-tail -a omniroute`

یہ وہی حقیقی ورک فلو ہے جو موجودہ پروجیکٹ کو `v3.4.7` پر اپ گریڈ کرتے وقت استعمال کیا گیا تھا (مثال ایک تاریخی ورژن کا حوالہ دیتی ہے؛ موجودہ حقیقی ورژن `v3.8.0` ہے)۔

```powershell
flyctl status -a omniroute
```

### 10.2 آغاز کے لاگز دیکھیں

```powershell
flyctl logs --no-tail -a omniroute
```

### 10.3 سائٹ کی رسائی کی تصدیق کریں

```powershell
try {
  (Invoke-WebRequest -Uri "https://omniroute.fly.dev" -MaximumRedirection 5 -UseBasicParsing).StatusCode
} catch {
  if ($_.Exception.Response) {
    $_.Exception.Response.StatusCode.value__
  } else {
    throw
  }
}
```

`200` کی واپسی کی قدر اس بات کی نشاندہی کرتی ہے کہ سائٹ معمول کے مطابق جواب دے رہی ہے۔

## 11. کامیابی کی نشانیاں

کامیاب تعیناتی کے بعد، لاگز میں درج ذیل سے ملتا جلتا مواد نظر آنا چاہیے:

```text
[bootstrap] Secrets persisted to: /data/server.env
[DB] SQLite database ready: /data/storage.sqlite
```

یہ دو نکات انتہائی اہم ہیں:

- `/data/server.env` تصدیق کرتا ہے کہ رن ٹائم سیکرٹس مستقل والیوم میں لکھے گئے ہیں
- `/data/storage.sqlite` تصدیق کرتا ہے کہ ڈیٹابیس مستقل والیوم میں لکھا گیا ہے

اگر اس کے بجائے `/app/data/...` نظر آئے، تو `DATA_DIR` غلط ترتیب دیا گیا ہے اور اسے فوری طور پر درست کرنا ضروری ہے۔

## 12. عام مسائل

### 12.1 `Secrets` صفحہ خالی ہے

عموماً اس کی دو وجوہات ہوتی ہیں:

- آپ نے ابھی تک `flyctl secrets set` نہیں چلایا
- آپ کوئی دوسری ایپلیکیشن دیکھ رہے ہیں (مثلاً `omniroute` کے بجائے `oroute`)

### 12.2 `flyctl deploy` کی جانب سے `app not found` کی اطلاع

پہلے ایپلیکیشن بنائیں:

```powershell
flyctl apps create omniroute
```

### 12.3 `fly.toml` کی پارسنگ ناکام ہو جاتی ہے

درج ذیل کی جانچ کریں:

- آیا تبصروں میں بگڑے ہوئے حروف موجود ہیں
- آیا TOML کی اقتباس بندی اور انڈینٹیشن درست ہیں

### 12.4 ڈیٹا مستقل طور پر محفوظ نہیں ہو رہا

درج ذیل دونوں چیزوں کی تصدیق کریں:

- `fly.toml` میں `destination = '/data'` موجود ہے
- `DATA_DIR` کو `/data` پر سیٹ کیا گیا ہے

### 12.5 کیا یہ `INITIAL_PASSWORD` کے بغیر چل سکتا ہے؟

جی ہاں، یہ چل سکتا ہے۔ یہ متبادل کے طور پر ڈیفالٹ `CHANGEME` پاس ورڈ استعمال کرے گا۔ پروڈکشن میں بیک اینڈ پاس ورڈ کو جلد از جلد تبدیل کرنے کی سفارش کی جاتی ہے۔

---

## 13. نئے پروجیکٹس کے لیے دوبارہ استعمال

اگر آپ اس دستاویز کے مطابق کوئی نیا پروجیکٹ تعینات کر رہے ہیں، تو آپ کو صرف ان چیزوں کو تبدیل کرنے کی ضرورت ہے:

1. `fly.toml` میں `app` کی قدر تبدیل کریں
2. `NEXT_PUBLIC_BASE_URL` تبدیل کریں
3. `DATA_DIR=/data` برقرار رکھیں
4. `API_KEY_SECRET`، `JWT_SECRET`، `MACHINE_ID_SALT`، اور `STORAGE_ENCRYPTION_KEY` دوبارہ بنائیں
5. پہلی تعیناتی کے بعد تصدیق کریں کہ لاگز `/data` میں لکھے جا رہے ہیں

کسی سابقہ پروجیکٹ کی کلیدیں دوبارہ استعمال نہ کریں۔

## 14. موجودہ پروجیکٹ کے لیے کم سے کم ریلیز چیک لسٹ

بعد کی ریلیزز کے لیے سب سے زیادہ استعمال ہونے والی کمانڈز یہ ہیں:

```powershell
flyctl auth whoami
flyctl status -a omniroute
flyctl secrets list -a omniroute
flyctl deploy
flyctl logs --no-tail -a omniroute
```

عام ریلیز کے لیے بنیادی کمانڈ صرف یہ ہے:

```powershell
flyctl deploy
```

نئے ماحول میں پہلی بار تعیناتی کے لیے بنیادی مراحل یہ ہیں:

1. `flyctl auth login`
2. `flyctl apps create omniroute`
3. `flyctl secrets set ... -a omniroute`
4. `flyctl deploy`
5. `flyctl logs --no-tail -a omniroute`
