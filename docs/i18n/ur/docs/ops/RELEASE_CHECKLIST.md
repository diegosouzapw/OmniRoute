## npm Trusted Publishing (v3.8.51 سے ڈیفالٹ) — درخواست پر مرحلہ وار، براہِ راست بطور متبادل

`npm-publish.yml` ڈیفالٹ طور پر **npm Trusted Publishing (OIDC)** کے ذریعے شائع کرتا ہے:
`stage-npm` جاب (github-hosted) اس رن کے لیے GitHub کے id-token کو مختصر مدت کے npm
کریڈینشل سے تبدیل کرتا ہے — ریپوزٹری سیکرٹس میں کوئی طویل مدتی npm ٹوکن نہیں، کوئی 2FA پرامپٹ نہیں، اور provenance منسلک ہوتا ہے۔
اب جبکہ 2FA کو نظر انداز کرنے والے ٹوکنز کو ختم کیا جا رہا ہے، npm کی منظور کردہ بائی پاس یہی ہے؛
یہ WS1.3 ضمانت برقرار رکھتے ہوئے اس مکمل خودکار فلو کو بحال کرتا ہے جو پروجیکٹ میں v3.8.48 تک موجود تھا
(لیک ہونے والا ٹوکن اکیلے شائع نہیں کر سکتا — کیونکہ کوئی ٹوکن ہے ہی نہیں)۔

**ایک بار کی سیٹ اپ (مالک):** npmjs.com → پیکیج `omniroute` → Settings → _Trusted
Publisher_ → GitHub: مالک `diegosouzapw`، ریپو `OmniRoute`، ورک فلو `npm-publish.yml`
(environment: none)۔ جب تک یہ موجود نہ ہو، خودکار مرحلہ `ENEEDAUTH` کے ساتھ ناکام ہوگا:
`publish_mode=staged` (ذیل میں) یا `direct` کے ساتھ دوبارہ ڈسپیچ کریں۔

### مرحلہ وار اشاعت (درخواست پر — `publish_mode=staged`)

npm-publish ورک فلو اب براہِ راست شائع نہیں کرتا: یہ پیک شدہ tarball
(`check:pack-boot`) کو بوٹ کرتا ہے اور پھر `npm stage publish` چلاتا ہے — یہی عین بائٹس
رجسٹری میں محفوظ کر دی جاتی ہیں، مگر مالک کی منظوری تک **انسٹال نہیں کی جا سکتیں**۔
انسانی 2FA گیٹ اب ثبوت سے پہلے نہیں بلکہ اس کے بعد آتا ہے۔

**ورک فلو گرین ہونے کے بعد مالک کا فلو:**

1. `npm stage list omniroute` — اسٹیج id تلاش کریں (یہ ورک فلو کے خلاصے میں بھی دکھائی جاتی ہے)۔
2. مرحلہ وار محفوظ کی گئی بائٹس کی تصدیق کریں (تجویز کردہ): `npm stage download <id>`، پھر ڈاؤن لوڈ کردہ
   tarball کو عارضی prefix میں انسٹال کرکے بوٹ کریں (`npm run check:pack-boot`، CI میں
   اسی pack→install→boot فیصلے کو خودکار بناتا ہے)۔
3. `npm stage approve <id>` — 2FA پرامپٹ ہی اشاعت ہے۔ `npm stage reject <id>` اسے مسترد کر دیتا ہے۔
4. اشاعت کے بعد حفاظتی جال: اشاعت کے بعد کا verifier (v3.8.49 پلان کا WS1.4) صاف
   کنٹینر میں عوامی رجسٹری سے شائع شدہ ورژن انسٹال کرکے اسے بوٹ کرتا ہے۔

**ہنگامی متبادل:** `publish_mode=direct` کے ساتھ `workflow_dispatch` پرانے فوری
`npm publish` کو بحال کرتا ہے (صرف اس صورت میں استعمال کریں جب staging خود درست کام نہ کرے؛ وجہ درج کریں)۔

**ایک بار کی مضبوطی (مالک، npmjs.com):** `omniroute` کے لیے Trusted Publisher کو
صرف-stage موڈ میں ترتیب دیں تاکہ لیک ہونے والا طویل مدتی ٹوکن کہیں سے بھی براہِ راست `npm publish`
نہ کر سکے — CI صرف stage کر سکتا ہے؛ صرف مالک کا 2FA ریلیز کرتا ہے۔

**خراب artifact کی حکمتِ عملی (بلا تبدیلی):** ڈیفالٹ فوری ردِعمل کے طور پر
`npm deprecate omniroute@<bad> "<reason> — use <fixed>"` استعمال کریں (چند منٹ، قابلِ واپسی)؛
`npm unpublish` صرف 72h/no-dependents ونڈو کے اندر، اور کبھی بھی پہلے اقدام کے طور پر نہیں۔
Docker: کسی ورژن ٹیگ کو کبھی دوبارہ نہ لکھیں — rollback کا مطلب `latest` کو آخری درست digest کی طرف دوبارہ پوائنٹ کرنا ہے۔

**Docker Hub `latest` (ہر مستحکم SemVer اشاعت پر لازم):**
`docker-publish` ورک فلو کو **دونوں** `X.Y.Z` اور، جب
`should-promote-latest.sh` اس بات سے متفق ہو کہ یہ سب سے بلند مستحکم SemVer ہے، `:latest`
کو **ایک ہی digest** کے ساتھ ٹیگ کرنا چاہیے۔ جاب کے بعد: Hub کے `latest` کا digest نئے
SemVer digest کے برابر ہو اور `last_updated` تبدیل ہوا ہو۔ `:latest` کو کسی پرانے
بلڈ پر نہ چھوڑیں جبکہ ریلیز نوٹس ان اصلاحات کا ذکر کر رہے ہوں جو صرف git پر موجود ہیں۔
Compose کوئیک اسٹارٹس `:latest` استعمال کرتے ہیں؛ GitOps کو `X.Y.Z` پن کرنا جاری رکھنا چاہیے۔
[Docker ریلیز چینلز](../guides/DOCKER_GUIDE.md#release-channels) اور #10317 دیکھیں۔

## ہاٹ فکس فاسٹ لین (لیبل `hotfix`)

`hotfix` لیبل والا PR بھاری CI میٹرکس (9-shard E2E، coverage ratchet،
quality-gate، quality-extended) کو چھوڑ دیتا ہے اور تیز، زیادہ مؤثر گیٹس برقرار رکھتا ہے: build،
unit shards، integration، vitest، lint/typecheck، docs-sync، `check:pack-artifact`
اور tarball boot-smoke (`check:pack-boot`)۔ ہدف: تقریباً 33 منٹ کے بجائے ≤15min میں سبز حالت۔

**داخلے کی پالیسی — چاروں شرائط لازم ہیں (Chromium/VS Code/Node کی ہنگامی لینز کی طرز پر):**

1. **شدت**: پروڈکشن خراب ہے — شائع شدہ artifact بوٹ ہوتے وقت کریش کرتا ہے / کوئی
   سیکیورٹی اصلاح درکار ہے / ریلیز کا ہر صارف متاثر ہے۔ "اہم" کا مطلب "خراب" نہیں ہے۔
2. **اختیار**: صرف repository کا مالک `hotfix` لیبل لگاتا ہے۔ لیبل ہی
   منظوری ہے — کسی campaign PR پر اسے کبھی خود سے استعمال نہ کریں۔
3. **ثبوت**: PR کی تفصیل میں پچھلی مکمل طور پر سبز heavy run کا لنک شامل ہو (وہ suite جس کی
   توثیق چھوڑے گئے jobs دوبارہ کرتے)، نیز اصلاح کا اپنا پہلے ناکام اور پھر کامیاب ہونے والا test۔
4. **دائرۂ کار**: صرف cherry-pick — کم سے کم اصلاح، کوئی refactor نہیں، کوئی اضافی تبدیلی ساتھ شامل نہیں۔

چھوڑی گئی coverage/ratchet سطح کی اگلی مکمل run میں
release branch پر دوبارہ توثیق کی جاتی ہے (مسلسل release-green) — یہ لین صرف انتظار چھوڑتی ہے، توثیق کبھی نہیں۔
صرف tests پر مشتمل diffs (`tests/` کے تحت تمام files، `tests/e2e/` کے تحت کوئی نہیں) کسی بھی لیبل کے بغیر
خودکار طور پر E2E میٹرکس چھوڑ دیتے ہیں۔

### Hooks (Husky سے توثیق شدہ)

Husky hooks، `.husky/` میں موجود ہیں اور git operations پر خودکار طور پر چلتے ہیں۔

- **pre-commit:** `npx lint-staged + node scripts/check/check-docs-sync.mjs + npm run check:any-budget:t11`
- **pre-push:** تیز، قطعی gates — `npm run check:any-budget:t11 && npm run check:tracked-artifacts` (2026-06-13 کو فعال کیا گیا)۔ جان بوجھ کر `test:unit` شامل نہیں ہے (سست؛ CI کے `test-unit` job میں شامل ہے)۔
  - release branches کو push کرنے سے پہلے `npm run test:unit` دستی طور پر چلائیں۔

اگر کوئی hook ناکام ہو جائے: بنیادی مسئلہ حل کریں، `--no-verify` کے ذریعے اسے نظر انداز نہ کریں۔

### Conventional Commits

ریلیز میں شامل ہونے والے تمام commits کو `type(scope): subject` فارمیٹ کی پیروی کرنا ضروری ہے۔

**درست types:** `feat`، `fix`، `refactor`، `docs`، `test`، `chore`، `perf`، `style`، `ci`

**درست scopes:** `db`، `sse`، `oauth`، `dashboard`، `api`، `cli`، `docker`، `ci`، `mcp`، `a2a`، `memory`، `skills`، `cloud-agent`، `guardrails`، `compression`، `auto-combo`، `resilience`، `providers`، `executors`، `translator`، `domain`، `authz`

Breaking changes: `BREAKING CHANGE:` footer یا scope کے بعد `!` شامل کریں (مثلاً `feat(api)!: drop /v0`)۔

### بِلڈ لے آؤٹ

ریپوزٹری تین الگ output directories استعمال کرتی ہے — انہیں کبھی آپس میں نہ ملائیں:

| ڈائریکٹری | مقصد                                                               | ٹریک شدہ؟         |
| --------- | ------------------------------------------------------------------ | ----------------- |
| `src/`    | ایپلیکیشن کا ماخذ (TypeScript / TSX)                               | ہاں               |
| `.build/` | بِلڈ کے درمیانی نتائج — `next build` کا output (`distDir`)         | نہیں (gitignored) |
| `dist/`   | تقسیم کے قابل npm bundle — `assembleStandalone` کے ذریعے تیار کردہ | نہیں (gitignored) |

> **آپریٹر نوٹ:** ریموٹ VPS image directory بدستور `/usr/lib/node_modules/omniroute/app/` ہے۔
> صرف **ریپوزٹری کے اندر** بِلڈ output منتقل ہوا ہے (`app/` → `dist/`)۔ deploy skills، `dist/`
> کے مندرجات کو ریموٹ `app/` directory میں rsync کرتی ہیں — VPS path میں کسی تبدیلی کی ضرورت نہیں۔

**واحد بِلڈ کا عمل:**

```
npm run build:release
  └─ rm -rf .build dist          (صفائی)
  └─ next build → .build/next/   (درمیانی نتائج)
  └─ assembleStandalone          (standalone + static + public + natives کو dist/ میں کاپی کرتا ہے)
  └─ writes dist/BUILD_SHA       (HEAD sentinel)
```

deploy کے لیے `npm run build` چلانے کے بعد الگ سے `npm run build:cli` ہرگز نہ چلائیں — اس کے بجائے
`npm run build:release` استعمال کریں، جو ایک ہی کمانڈ میں صاف rebuild + sentinel انجام دیتی ہے۔

## رول بیک

اگر ریلیز میں کوئی سنگین مسئلہ ہو:

1. `gh release edit vX.Y.Z --prerelease` (اسے تازہ ترین ریلیز نہ ہونے کے طور پر نشان زد کرتا ہے)
2. `git tag -d vX.Y.Z && git push --delete origin vX.Y.Z` (صرف اس صورت میں جب صارفین نے اسے ابھی تک اختیار نہ کیا ہو)
3. یا: `release/vX.Y.0` پر ہاٹ فکس → پیچ ریلیز `vX.Y.(Z+1)`
4. GitHub Discussions اور Discord میں فوراً اطلاع دیں

## سخت اصول

- کبھی بھی براہِ راست `main` میں کمٹ نہ کریں
- کبھی بھی `main` یا `release/*` برانچز پر `git push --force` استعمال نہ کریں
- Husky ہُکس (`--no-verify`) کو کبھی نظرانداز نہ کریں
- راز، اسناد، یا `.env` فائلیں کبھی کمٹ نہ کریں
- کوریج لازماً ≥60/60/60/60 (اسٹیٹمنٹس/لائنز/فنکشنز/برانچز) برقرار رہنی چاہیے
- `src/`، `open-sse/`، `electron/`، یا `bin/` میں پروڈکشن کوڈ تبدیل کرتے وقت ہمیشہ ٹیسٹس شامل یا اپ ڈیٹ کریں
