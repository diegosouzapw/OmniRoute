## اصول

- کوریج کے اہداف سورس فائلوں پر لاگو ہوتے ہیں، `tests/**` پر نہیں۔
- `open-sse/**` پروڈکٹ کا حصہ ہے اور اسے دائرۂ کار میں برقرار رہنا چاہیے۔
- نئے کوڈ سے تبدیل شدہ حصوں میں کوریج کم نہیں ہونی چاہیے۔
- نفاذ کی تفصیلات کے بجائے رویے اور برانچ کے نتائج کی جانچ کو ترجیح دیں۔
- `src/lib/db/**` کے لیے وسیع پیمانے کے ماکس کے بجائے عارضی SQLite ڈیٹابیسز اور چھوٹے فکسچرز کو ترجیح دیں۔

## موجودہ کمانڈ سیٹ

- `npm run test:coverage`
  - یونٹ ٹیسٹ سوٹ کے لیے بنیادی سورس کوریج گیٹ
  - `text-summary`، `html`، `json-summary`، اور `lcov` تیار کرتا ہے
- `npm run coverage:report`
  - تازہ ترین رن سے فائل بہ فائل تفصیلی رپورٹ
- `npm run test:coverage:legacy`
  - صرف تاریخی موازنے کے لیے

## معلوم خلا
