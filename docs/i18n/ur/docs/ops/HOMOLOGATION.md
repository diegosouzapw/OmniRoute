ہومولوگیشن VPS پر چلنے والی OmniRoute تعیناتی کی حقیقی ماحول میں E2E توثیق
(`HOMOLOG_BASE_URL`، مثلاً `http://192.168.0.15:20128`)۔ ایک کمانڈ دستی
ریلیز STOP #2 چیک لسٹ کو ایک خودکار، شواہد پیدا کرنے والے رن سے بدل دیتی ہے۔

## اس میں کیا شامل ہے

| سطح                      | یہ کیا جانچتا ہے                                                                                                                                                                                          | نفاذ                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |

کوئی eval نہیں۔ AI صرف مستقبل کے دیکھ بھال کے کام میں شامل ہوگا (ذیل میں Roadmap دیکھیں)۔

## پیشگی تقاضے

1. `.env.homolog.example` کو `.env.homolog` میں کاپی کریں (یہ gitignored ہے — اسے کبھی commit نہ کریں) اور درج ذیل معلومات پُر کریں:
   - `HOMOLOG_BASE_URL` — ہدف deploy، مثلاً `http://192.168.0.15:20128`۔
   - `HOMOLOG_ADMIN_PASSWORD` — اس deploy کے لیے dashboard کا انتظامی پاس ورڈ۔
   - `HOMOLOG_CRITICAL_PROVIDERS` — کوما سے الگ کردہ provider prefixes جن کے لیے حقیقی
     smoke chat request بھیجی جاتی ہے (مثلاً `openai,anthropic,gemini,codex,grok,glm,deepseek,openrouter`)۔
   - `HOMOLOG_API_KEY` — معمول کی runs میں اسے خالی چھوڑیں؛ suite اپنی عارضی key خود بناتی
     اور منسوخ کرتی ہے۔ اسے صرف کسی ایک layer کو الگ سے debug کرنے کے لیے سیٹ کریں۔
2. repo میں `npm install` چلائیں (suite کی dependencies — `httpyac`، `promptfoo`،
   `playwright-ctrf-json-reporter`، `junit-to-ctrf`، `ctrf` — عام devDependencies ہیں)۔
3. اگر browser binaries پہلے سے موجود نہیں ہیں تو `npx playwright install` چلائیں۔

## چلانے کا طریقہ

```bash
npm run homolog
```

ایسے deploy کے مقابل توثیق کرنے کے لیے جس کا version مقامی `package.json` سے مطابقت نہیں رکھتا
(مثلاً homologation box اب بھی گزشتہ patch release پر ہو)، متوقع version کو واضح طور پر
override کریں:

```bash
HOMOLOG_EXPECT_VERSION=3.8.47 npm run homolog
```

اگر کوئی layer ناکام ہو تو run غیر صفر قدر کے ساتھ بند ہوتی ہے، اور ناکامی کی صورت میں بھی اپنی
بنائی ہوئی عارضی API key کو ہمیشہ منسوخ کرنے کی کوشش کرتی ہے (`scripts/homolog/run.mjs` میں
`finally` block)۔

## رپورٹ پڑھنا

تمام output `homolog-report/` میں محفوظ ہوتی ہے (gitignored):

- `summary.md` — وہی table جو stdout پر پرنٹ ہوتی ہے، ہر layer کے لیے ایک row (✅/❌ + تفصیل)۔
- `homolog-ctrf.json` — متحدہ CTRF report (API/SSE، provider-smoke، اور UI نتائج کا merge)
  — release کی STOP #2 checklist کے ساتھ منسلک کرنے کے لیے یہی artifact ہے۔
- `httpyac-junit.xml`، `api-ctrf.json`، `providers-ctrf.json`، `ui-ctrf.json` — ہر
  layer کی raw/intermediate reports۔
- `promptfooconfig.yaml`، `provider-misses.json` — موجودہ run کے لیے تیار کردہ promptfoo config
  اور وہ تمام اہم providers جو live catalog میں موجود نہیں تھے۔

L0 کی ناکامی پر عمل فوراً رک جاتا ہے (کوئی عارضی key نہیں بنائی جاتی)، کیونکہ version/health
کی عدم مطابقت کا مطلب ہے کہ ہر بعد والی layer غلط deploy کی توثیق کر رہی ہوگی۔

## جائز UI تبدیلیوں کے بعد baseline دوبارہ مرتب کرنا

L4b (route smoke) اور L4c (API-key UI flow) snapshots کے بجائے حقیقی DOM locators کے ذریعے
چلتے ہیں، اس لیے زیادہ تر جائز UI تبدیلیوں پر suite update کرنے کی ضرورت نہیں ہوتی۔ جب کوئی تبدیلی
locator کو توڑ دے (مثلاً button label کا نام بدل جائے یا settings page منتقل ہو جائے):

1. موجودہ source کے مقابل locator کی دوبارہ تصدیق کریں (specs میں پہلے ہی درج ہے کہ ہر locator کی
   تصدیق کس file/line کے مقابل کی گئی تھی — اسی طریقے پر عمل کریں، اندازہ نہ لگائیں)۔
2. `tests/homolog/ui/` میں spec کو update کریں۔
3. اصلاح کی تصدیق کے لیے VPS کے مقابل `npm run homolog` (یا صرف متاثرہ Playwright spec)
   دوبارہ چلائیں، پھر commit کریں۔

اس suite میں کوئی visual/pixel baseline نہیں ہے (F1) — اس کے لیے Roadmap دیکھیں۔

## Roadmap (F2 / F3)

design اور مرحلہ وار rollout داخلی planning spec
`_tasks/superpowers/specs/2026-07-13-homolog-e2e-suite-design.md` میں موجود ہیں (linked نہیں
ہے — یہ داخلی `_tasks/` artifact ہے، اس repo کی tracked docs کا حصہ نہیں)۔ خلاصہ:

- **F2** — مکمل walkthrough recording → Playwright Test Agents (`planner`/`generator`)
  اسے flow specs میں تبدیل کرتے ہیں (combo بنانا، provider کی جانچ، settings میں ترمیم، MCP tools) +
  متحرک data (metrics، timestamps، logs) پر masks کے ساتھ visual regression baseline (Lost Pixel) +
  ہر release کے لیے `healer` maintenance routine۔
- **F3** — resilience/contract/wiring coverage: devbox پر toxiproxy + ایک جعلی OpenAI-compatible
  provider، اور VPS پر اس کی طرف اشارہ کرتا ہوا `homolog-resilience` combo
  (injected timeout → `/api/monitoring/health` کے ذریعے fallback + circuit breaker کے
  open/close ہونے کی تصدیق)؛ `docs/openapi.yaml` کے مقابل gated Schemathesis contract testing
  (کم `--max-examples`، مقررہ seeds، صرف non-LLM endpoints)؛ اور `npm run homolog` +
  اس کی `summary.md` کو `/generate-release` کے STOP #2 مرحلے میں شامل کرنا۔
