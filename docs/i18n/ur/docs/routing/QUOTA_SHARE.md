## جائزہ

کوٹہ شیئرنگ انجن کسی فراہم کنندہ کے وقت پر مبنی کوٹے (مثلاً Codex کی
5 گھنٹے کی ونڈو، Kimi کی 1500 درخواستیں فی گھنٹہ) کو ایک ہی کنکشن استعمال کرنے والی
متعدد API کلیدوں میں منصفانہ طور پر تقسیم کرتا ہے۔

**حل کیا جانے والا مسئلہ:** OmniRoute بہت سی API کلیدوں کو اسی upstream
فراہم کنندہ اکاؤنٹ کے ذریعے پراکسی کرتا ہے۔ شیئرنگ منطق کے بغیر، کلید A سے آنے والا اچانک بوجھ
فراہم کنندہ کا فی گھنٹہ کوٹہ ختم کر سکتا ہے، جس کے نتیجے میں کلیدیں B اور C ونڈو ری سیٹ ہونے تک مسدود رہتی ہیں۔
انجن درج ذیل طریقوں سے اسے روکتا ہے:

1. ہر کلید کے لیے ہر جہت (٪، درخواستیں، ٹوکنز، $) میں رولنگ کھپت کا سراغ لگانا۔
2. کام کو برقرار رکھنے والا منصفانہ تقسیم کا الگورتھم لاگو کرنا: جب تک عالمی پول
   مکمل طور پر استعمال نہ ہو، ایک کلید غیر استعمال شدہ حصوں سے مستعار لے سکتی ہے۔
3. درخواست کے upstream executor تک پہنچنے سے پہلے hot path (`chatCore.ts`) میں
   نتیجے کا نفاذ کرنا۔

## الگورتھم: کام کو برقرار رکھنے والی منصفانہ تقسیم

`src/lib/quota/fairShare.ts` میں نافذ کیا گیا ہے۔

### طریقے

| شرط                                        | طریقہ    | طرزِ عمل                                            |
| ------------------------------------------ | -------- | --------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **فیاض** | کلید، عالمی حد منفی کل استعمال تک مستعار لے سکتی ہے |
| `globalUsedPercent >= saturationThreshold` | **سخت**  | انفرادی منصفانہ حصے کا سختی سے نفاذ کرتا ہے         |

ڈیفالٹ `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`) ہے۔

### فی جہت فیصلہ

پول کی ہر فعال جہت کے لیے، انجن درج ذیل حساب لگاتا ہے:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = اس کلید کی موجودہ رولنگ قدر (QuotaStore.peek سے)
remaining       = fairShareAllowed - consumed
```

پھر:

- **`policy = hard`**: اگر `consumed > fairShareAllowed` ہو اور طریقہ سخت ہو → **مسدود کریں**۔
- **`policy = soft`**: اگر `consumed > fairShareAllowed` ہو اور طریقہ سخت ہو → **جرمانہ لگائیں** (combo میں ترجیح کم کریں؛ کبھی مکمل طور پر مسدود نہ کریں)۔
- **`policy = burst`**: منصفانہ حصے سے قطع نظر، عالمی گنجائش موجود ہونے تک اجازت دیں۔

### مطلق حد

کسی allocation پر `capValue` + `capUnit` طریقے یا
policy سے آزاد ایک قطعی حد ہے۔ جس بھی جہت میں `consumed >= capValue` ہو، وہ ہمیشہ درخواست کو **مسدود** کرتی ہے۔

### متعدد جہتوں کی جانچ

اگر پول کی **کوئی بھی** جہت درخواست کو مسدود کرے تو درخواست مسدود ہو جاتی ہے۔ جہتیں
آزاد ہیں — 5h% کا ختم ہونا weekly% جہت کو متاثر نہیں کرتا۔

### مستعار لینا

فیاض طریقے میں، کوئی کلید جس کا allocation مکمل طور پر استعمال نہ ہوا ہو، دوسری
کلیدوں کے غیر مختص حصوں سے اضافی مقدار استعمال کر سکتی ہے۔ فارمولا یہ ہے:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

جہاں `consumedByOtherKeys = consumedTotal - consumedByThisKey` ہے۔ عالمی حد
(اس جہت کے لیے پول کا `limit`) ہمیشہ قطعی حد رہتی ہے۔

## سلائیڈنگ ونڈو کاؤنٹر

`src/lib/quota/sqliteQuotaStore.ts` اور `redisQuotaStore.ts` میں نافذ کیا گیا ہے۔

ہر `(apiKeyId, dimensionKey)` کے لیے دو بکٹ:

- `curr`: موجودہ بکٹ (`floor(nowMs / windowMs)`)
- `prev`: پچھلی بکٹ (`curr - 1`)

مؤثر رولنگ قدر:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**درستگی**: تقریباً 99٪ درست۔ بکٹوں کی سرحد پر غلطی زیادہ سے زیادہ ونڈو کے حجم کا 1٪
ہوتی ہے (یہ 2-بکٹ تخمینے میں فطری ہے)۔

### ہم وقتی عمل

SQLite ڈرائیور: ہر `(apiKeyId | dimensionKey)` کلید کے لیے in-memory mutex،
read-modify-write تصادم کو روکتا ہے۔ پیٹرن `src/sse/services/auth.ts` کے anti-thundering-herd کی عکاسی کرتا ہے۔

Redis ڈرائیور: atomic increment کے لیے Lua EVAL اسکرپٹ — ایک واحد Redis کمانڈ کے طور پر چلتا ہے۔

## ڈرائیورز

### SQLite (ڈیفالٹ، 0-install)

- ٹیبل: `quota_consumption` (مائیگریشن `073_quota_pools.sql` / `074_quota_consumption.sql` دیکھیں)۔
- سنگل-انسٹینس ڈیپلائمنٹس کے لیے بہترین۔
- تمام مستقل ڈیٹا موجودہ OmniRoute SQLite DB (`DATA_DIR/storage.sqlite`) میں محفوظ ہوتا ہے۔

### Redis (اختیاری، ملٹی-انسٹینس)

- `ioredis` npm پیکیج درکار ہے۔
- کاؤنٹرز Redis میں محفوظ ہوتے ہیں؛ میٹا ڈیٹا (پولز/مختصات) بدستور SQLite میں رہتا ہے۔
- ملٹی-ریپلیکا ڈیپلائمنٹس کے لیے بہترین، جہاں کاؤنٹرز کا مشترک ہونا ضروری ہو۔

### ڈرائیورز تبدیل کرنا

سیٹنگز UI (`/dashboard/settings` → Quota Store) کے ذریعے، یا env vars کے ذریعے:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

DB سیٹنگ کو env پر ترجیح حاصل ہے۔ اگر `driver=redis` ہو لیکن URL موجود نہ ہو یا
`ioredis` انسٹال نہ ہو، تو فیکٹری SQLite پر واپس آ جاتی ہے اور ایک انتباہ لاگ کرتی ہے۔

ڈرائیور کے انتخاب کی ترتیب:

1. DB سیٹنگ `quotaStore.driver`
2. Env `QUOTA_STORE_DRIVER`
3. ڈیفالٹ: `sqlite`

## پائپ لائن انٹیگریشن

### PRE ہُک (`open-sse/handlers/chatCore.ts`)

تصدیق اور پالیسی کی جانچ کے بعد، اپ اسٹریم ایگزیکیوٹر سے پہلے چلتا ہے:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → ہر جہت کے لیے getQuotaStore().peek()
      → fairShare.decideFairShare()
      → اگر بلاک ہو → 429 واپس کریں (buildErrorBody، سخت اصول #12)
      → اگر اجازت ہو + ترجیح کم ہو → امیدوار پر quotaSoftPenalty=true سیٹ کریں
  → executor.execute()
```

**Fail-open**: اگر `enforceQuotaShare` کوئی خرابی پھینکے، تو درخواست کو
`pino.warn` لاگ کے ساتھ گزرنے دیا جاتا ہے۔ یہ کوٹہ انجن کی خرابی کو تمام
ٹریفک بلاک کرنے سے روکتا ہے۔

### POST ہُک (استعمال ریکارڈ کرنا)

کامیاب رسپانس کے بعد:

```
ایگزیکیوٹر کامیابی واپس کرتا ہے
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → ہر جہت کے لیے getQuotaStore().consume()
      → fail-open: خرابیاں pino.warn کے طور پر لاگ ہوتی ہیں، کلائنٹ تک کبھی نہیں پہنچائی جاتیں
```

**ڈرفٹ نوٹ**: اگر رسپانس کے بعد `consume` ناکام ہو جائے، تو رولنگ کاؤنٹر استعمال کو کم شمار کرتا ہے۔
فراہم کنندہ کی سیچوریشن علامت (مثلاً `anthropic-ratelimit-unified-5h-utilization`)
اگلی درخواست پر مجموعی تخمینے کو درست کر دیتی ہے۔

### کومبو سافٹ پینلٹی (`open-sse/services/combo.ts`)

جب `decision.deprioritize === true` ہو:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // ڈیفالٹ 0.7
}
```

یہ پینلٹی اسکورنگ کے دیگر تمام عوامل کے بعد لاگو ہوتی ہے۔ یہ سیچوریٹڈ کلید کو
سختی سے بلاک کیے بغیر، آٹو کومبو کے ذریعے اسے منتخب کیے جانے کے امکان کو کم کرتی ہے۔

| `QUOTA_STORE_REDIS_URL`            | _(خالی)_ | Redis URL، مثلاً `redis://localhost:6379`                                  |
| `QUOTA_SATURATION_THRESHOLD`       | `0.5`    | 0..1؛ `>= threshold` سخت موڈ فعال کرتا ہے                                  |
| `QUOTA_SOFT_DEPRIORITIZE_FACTOR`   | `0.7`    | 0..1؛ نرم پالیسی کے مجموعی اسکور کے لیے ضربی عامل                          |
| `QUOTA_CONSUMPTION_RETENTION_DAYS` | `14`     | پرانے `quota_consumption` بکیٹس کو GC کے ذریعے ہٹانے سے پہلے دنوں کی تعداد |

DB ترتیبات (`quotaStore.*`) ماحولیاتی متغیرات پر فوقیت رکھتی ہیں۔

## مسائل کا حل

### Redis تشکیل شدہ ہے لیکن کنیکٹ نہیں ہو رہا

یقینی بنائیں کہ `ioredis` انسٹال ہے (`npm ls ioredis`) اور `QUOTA_STORE_REDIS_URL`
قابلِ رسائی ہے۔ کنکشن ناکام ہونے پر فیکٹری SQLite پر واپس چلی جاتی ہے (جس کا اندراج
`warn` پر ہوتا ہے)۔

### `peek` پرانا نتیجہ دیتا ہے / fail-open

اگر `peek` استثنا پھینکتا ہے تو `enforceQuotaShare` نتیجے کو "اجازت" (fail-open)
سمجھتا ہے۔ بنیادی وجہ معلوم کرنے کے لیے `quota:enforce` اور `quota:factory`
اندراجات کے لیے `pino` لاگز چیک کریں۔

### استعمال کے کاؤنٹر میں انحراف

اگر فراہم کنندہ کا حقیقی استعمال کاؤنٹرز سے مختلف ہو تو یہ متوقع ہے — 2-بکٹ
sliding window میں ونڈو کی حدود پر تقریباً 1% خرابی ہوتی ہے، اور `consume`
جواب کے بعد fire-and-forget انداز میں چلتا ہے۔ سیچوریشن سگنل (`saturationSignals.ts`)
30 سیکنڈ TTL کے ساتھ فراہم کنندہ کا حقیقی استعمال پڑھتا ہے اور اسی کے مطابق
`globalUsedPercent` کو ایڈجسٹ کرتا ہے۔

### پول برن ریٹ کے لیے "کوئی ڈیٹا نہیں" دکھاتا ہے

`computeBurnRate` کو کم از کم 2 تاریخی نمونے درکار ہیں۔ سابقہ `consume` کالز کے
بغیر نئے پولز `tokensPerSecond: 0` اور `timeToExhaustionMs: null` دکھائیں گے۔

## localStorage سے منتقلی

جب `/dashboard/costs/quota-share` پہلی بار لوڈ ہوتا ہے، تو ہُک `useLocalStoragePoolMigration`
درج ذیل کی جانچ کرتا ہے:

1. `localStorage.getItem("omniroute:quota-share:pools")` خالی نہ ہو۔
2. `GET /api/quota/pools` سے `[]` واپس آئے (DB خالی ہو)۔

اگر دونوں شرائط درست ہوں، تو یہ ہر پرانے پول کو بیچ کی صورت میں `POST /api/quota/pools` پر پوسٹ کرتا ہے،
پھر localStorage کلید حذف کر دیتا ہے۔ یہ منتقلی idempotent ہے: شرط 2
دوبارہ منتقلی کو روکتی ہے۔

## داخلی حکمتِ عملی کی درجہ بندی

`quota-share` ایک **صرف داخلی** روٹنگ حکمتِ عملی ہے (`src/shared/constants/routingStrategies.ts` میں
`INTERNAL_ROUTING_STRATEGY_VALUES`)۔ اسے خصوصی طور پر سسٹم کے بنائے ہوئے
`qtSd/` پول کومبوز استعمال کرتے ہیں، اور اسے جان بوجھ کر `ROUTING_STRATEGY_VALUES` سے خارج رکھا گیا ہے تاکہ یہ کبھی بھی
UI یا API میں صارف کے لیے قابلِ انتخاب اختیار کے طور پر ظاہر نہ ہو۔

## DB اسکیما کا خلاصہ

مائیگریشنز `078`، `079` اور `085` کے ذریعے تین ٹیبلز شامل کیے گئے ہیں:

- `quota_pools` + `quota_allocations` — پول کی تعریفیں اور ہر کلید کے لیے مختص مقداریں۔
- `quota_consumption` — ہر `(apiKeyId, dimensionKey)` کے لیے رولنگ 2-بکٹ کاؤنٹرز۔
- `provider_plans` — فراہم کنندہ کے پلانز کی دستی اوور رائیڈز (ہر connectionId کے لیے dimensions JSON)۔

تمام ٹیبلز idempotent `CREATE TABLE IF NOT EXISTS` مائیگریشنز کے ذریعے شامل کیے گئے ہیں۔
