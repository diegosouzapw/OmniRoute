Traffic Inspector، OmniRoute کا بلٹ اِن HTTPS ٹریفک ڈیبگر ہے — Charles Proxy / mitmweb / HTTP Toolkit جیسا ایک ٹول، جو **LLM-aware** اور **agent-aware** ہے۔ یہ `/dashboard/tools/traffic-inspector` پر موجود ہے اور بیک وقت زیادہ سے زیادہ 5 کیپچر ذرائع سے لائیو ٹریفک وصول کرتا ہے۔

**ڈیش بورڈ کا مقام:** `/dashboard/tools/traffic-inspector`
**سائیڈبار گروپ:** Tools (AgentBridge کے بعد)
**یہ بھی دیکھیں:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge کیپچر موڈ 1 ہے۔

### ایک پیراگراف میں فنِ تعمیر

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) ایک مشترکہ اِن میموری رِنگ بفر ہے (ڈیفالٹ طور پر 1000 اندراجات، `INSPECTOR_BUFFER_SIZE` کے ذریعے قابلِ ترتیب)۔ تمام کیپچر ذرائع `push()` کے ذریعے اس میں لکھتے ہیں۔ بفر `kindDetector.ts` استعمال کرتے ہوئے ہر اندراج کی درجہ بندی کرتا ہے (یہ تعین کرتا ہے کہ آیا یہ LLM درخواست ہے)، ایک `contextKey` کا حساب لگاتا ہے (سسٹم پرامپٹ کا SHA-256 فنگر پرنٹ)، اور `globalTrafficBuffer.subscribe()` کے ذریعے تمام WebSocket سبسکرائبرز کو براڈکاسٹ کرتا ہے۔ ڈیش بورڈ `GET /api/tools/traffic-inspector/ws` کے ذریعے منسلک ہوتا ہے اور کنکشن قائم ہونے پر ایک اسنیپ شاٹ وصول کرتا ہے، جس کے بعد `new`/`update`/`clear` ایونٹس آتے ہیں۔

## §2 کیپچر موڈز

Traffic Inspector بیک وقت **5 کیپچر ذرائع** کو سپورٹ کرتا ہے۔ ہر ایک کو آزادانہ طور پر آن یا آف کیا جا سکتا ہے۔ ہر `InterceptedRequest` (`src/mitm/inspector/types.ts`) پر موجود `source` فیلڈ کی قدر `"agent-bridge"`، `"custom-host"`، `"http-proxy"`، `"system-proxy"`، یا `"tproxy"` میں سے ایک ہوتی ہے۔

### موڈ 1 — AgentBridge (ڈیفالٹ، ہمیشہ فعال)

**ماخذ:** AgentBridge ہینڈلرز (`src/mitm/handlers/base.ts`)
**طریقۂ کار:** `MitmHandlerBase` میں ہر `intercept()` کال فارورڈ کرنے سے پہلے `hookBufferStart()` اور تکمیل پر `hookBufferUpdate()` کو کال کرتی ہے۔ کسی اضافی کنفیگریشن کی ضرورت نہیں — AgentBridge کے چلتے ہی کام کرتا ہے۔
**رسائی:** AgentBridge میں کنفیگر کیے گئے 9 IDE ایجنٹس
**نوٹ:** `InterceptedRequest` میں `source` فیلڈ = `"agent-bridge"`

### موڈ 2 — حسبِ ضرورت ہوسٹس (DNS ری ڈائریکٹ)

**ماخذ:** صارف کی متعین کردہ ہوسٹ فہرست (`inspector_custom_hosts` ٹیبل)
**طریقۂ کار:** UI کے ذریعے ہوسٹ شامل کرنے پر `/etc/hosts` میں `127.0.0.1 <host>` شامل ہو جاتا ہے (sudo درکار ہے)۔ موجودہ AgentBridge MITM سرور (پورٹ 443) نئے ہوسٹ کے لیے متحرک طور پر SNI سرٹیفکیٹ بناتا ہے۔
**رسائی:** شامل کردہ ہوسٹ استعمال کرنے والی کوئی بھی ایپلیکیشن — ایپ کی کنفیگریشن میں تبدیلی درکار نہیں
**نوٹ:** `source` = `"custom-host"`

استعمال کی مثالیں:

- Python اسکرپٹس سے `api.openai.com` کی نگرانی
- `my-internal-llm.company.com` کو ڈیبگ کرنا
- اسی نیٹ ورک پر موجود موبائل ڈیوائسز سے ٹریفک کیپچر کرنا (ARP اسپوفنگ کے ذریعے — ایڈوانسڈ)

### موڈ 3 — HTTP_PROXY لسنر (پورٹ 8080)

**ماخذ:** `HTTP_PROXY`/`HTTPS_PROXY` ماحولیاتی متغیرات استعمال کرنے والی ایپلیکیشنز
**طریقۂ کار:** پورٹ 8080 پر ایک ثانوی لسنر (`src/mitm/inspector/httpProxyServer.ts`) جو ایک معیاری واضح HTTP/HTTPS پراکسی کے طور پر کام کرتا ہے۔ یہ `CONNECT` ٹنلز (HTTPS) اور براہِ راست HTTP درخواستیں قبول کرتا ہے۔
**رسائی:** `HTTP_PROXY` ماحول کو استعمال کرنے والی کوئی بھی ایپلیکیشن — نہ DNS میں تبدیلی، نہ sudo
**نوٹ:** `source` = `"http-proxy"`

```bash
# کسی ایک کمانڈ کے لیے فوری کیپچر:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# شیل سیشن میں مستقل کیپچر:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS کی حد:** HTTPS `CONNECT` ٹنلز کو صرف میٹا ڈیٹا (ہوسٹ، پورٹ، وقت) کی صورت میں کیپچر کیا جاتا ہے — ڈیفالٹ طور پر TLS باڈی کو ڈکرپٹ نہیں کیا جاتا۔ باڈی کے مکمل معائنے کے لیے "پراکسی موڈ میں HTTPS ڈکرپٹ کریں" ٹوگل فعال کریں (اختیاری، AgentBridge سرٹیفکیٹ کا قابلِ اعتماد ہونا ضروری ہے)۔

**پورٹ کا ٹکراؤ:** اگر پورٹ 8080 استعمال میں ہو تو AgentBridge ایک منظم ایرر کے ساتھ 409 واپس کرتا ہے۔ `INSPECTOR_HTTP_PROXY_PORT` ماحولیاتی متغیر کے ذریعے پورٹ تبدیل کریں۔

### موڈ 4 — پورے سسٹم کی پراکسی (ایڈوانسڈ، اختیاری)

**ماخذ:** OS سطح کی پراکسی سیٹنگز (مشین پر موجود تمام ایپس پر لاگو)
**طریقۂ کار:** تمام HTTP/HTTPS ٹریفک کو HTTP_PROXY لسنر سے گزارنے کے لیے OS APIs استعمال کرتا ہے:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **رسائی:** مشین پر موجود ہر وہ ایپلیکیشن جو سسٹم پراکسی سیٹنگز استعمال کرتی ہے
  **نوٹ:** `source` = `"system-proxy"`

**حفاظتی طریقۂ کار:**

- خودکار طور پر غیر فعال کرنے والا ٹائمر (ڈیفالٹ 30 منٹ، `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` کے ذریعے قابلِ کنفیگریشن)
- سسٹم پراکسی کی سابقہ حالت DB میں محفوظ ہوتی ہے اور واپسی پر بحال کر دی جاتی ہے
- فعال حالت میں صارف کے کہیں اور جانے پر ڈیش بورڈ "سسٹم پراکسی واپس بحال کی جا رہی ہے" کا پرامپٹ دکھاتا ہے
- UI میں `⚠ ایڈوانسڈ` بیج + واضح تصدیقی چیک باکس دکھایا جاتا ہے

### موڈ 5 — TPROXY شفاف ڈکرپشن (Linux، root، اختیاری)

**ماخذ:** کرنل TPROXY + پالیسی روٹنگ (`src/mitm/tproxy/`)
**طریقۂ کار:** `mangle OUTPUT` میں ہدف پورٹ (ڈیفالٹ `443`) کی جانب نئی مقامی آؤٹ باؤنڈ TCP کنکشنز کو نشان زد کرتا ہے، ایک `ip rule` نشان زدہ پیکٹس کو مقامی ترسیل کی جانب دوبارہ روٹ کرتا ہے، اور `mangle PREROUTING` کا `TPROXY` ہدف انہیں ایک شفاف (**IP_TRANSPARENT**) لسنر (ڈیفالٹ پورٹ `8443`) کے حوالے کرتا ہے۔ لسنر، متحرک CA کے ذریعے **ہر SNI ہوسٹ نیم کے لیے حسبِ ضرورت** جاری کردہ لیف سرٹیفکیٹ سے TLS ختم کرتا ہے، ڈکرپٹ شدہ تبادلہ کیپچر کرتا ہے، اور درخواست کو دوبارہ انکرپٹ کر کے اصل منزل کی طرف فارورڈ کرتا ہے۔
**رسائی:** ہدف پورٹ پر **کوئی بھی** منزل ہوسٹ — نہ `/etc/hosts` اسپوف، نہ `HTTP_PROXY` ماحول، نہ پورے سسٹم کی پراکسی میں تبدیلی۔ انٹرسیپٹ کیے جانے والے پراسیس کی کنفیگریشن میں کسی تبدیلی کی ضرورت نہیں، لیکن اسے متحرک CA پر اعتماد کرنا ضروری ہے۔
**نوٹ:** `source` = `"tproxy"`

**تقاضے:** صرف Linux (**IP_TRANSPARENT** صرف Linux پر دستیاب ہے)، **CAP_NET_ADMIN** قابلیت (root)، اور ایک مقامی N-API ایڈ آن جسے C ٹول چین کے ساتھ بنانا ضروری ہے (`npm run build:native:tproxy`)۔ دستیاب نہ ہونے پر ڈیش بورڈ ٹوگل اس ٹول ٹِپ کے ساتھ غیر فعال ہوتا ہے: "TPROXY ڈکرپشن کے لیے Linux + root + مقامی ایڈ آن درکار ہیں"۔ فائر وال قواعد ٹرانزیکشن کے طور پر لاگو/واپس کیے جاتے ہیں (کریش ہونے پر کبھی کوئی `mangle` قاعدہ باقی نہیں رہتا) اور ری بوٹ پر صاف ہو جاتے ہیں۔ SO_MARK پر مبنی اینٹی لوپ، پراکسی کے اپنے دوبارہ انکرپٹ شدہ فارورڈ کو دوبارہ انٹرسیپٹ ہونے سے روکتا ہے۔

یہ ایک بڑا ذیلی نظام ہے جس کی اپنی مخصوص آپریٹر گائیڈ موجود ہے — مکمل فائر وال ترکیب، فی SNI متحرک CA + ٹرسٹ اسٹور انسٹالر، صرف مقامی روٹ، اینٹی لوپ کی تفصیلات، اور کنفیگریشن اسکیما کے لیے `docs/security/MITM-TPROXY-DECRYPT.md` (git؛ `/docs` میں کمپائل نہیں کیا گیا) دیکھیں۔ ٹوگل کو `GET / POST / DELETE /api/tools/agent-bridge/tproxy` کے ذریعے کنٹرول کیا جاتا ہے (نوٹ: روٹ Traffic Inspector پریفکس کے بجائے AgentBridge پریفکس کے تحت موجود ہے)۔

| 4. پورے سسٹم پر     | ٹوگل + تصدیق               |           ہاں           | مشین پر موجود تمام ایپس                   | 30 منٹ میں خودکار طور پر غیر فعال                                                                                                             |
| 5. TPROXY decrypt   | ٹوگل (Linux + مقامی addon) | ہاں (root + CA install) | ہدف پورٹ پر کوئی بھی host                 | کسی بھی host کو decrypt کرتا ہے؛ بطور ڈیفالٹ غیر فعال — `docs/security/MITM-TPROXY-DECRYPT.md` دیکھیں (git؛ `/docs` میں compile نہیں کیا گیا) |

## §4 LLM سے آگاہ خصوصیات

### 4.1 قسم کا تعین کرنے والا (`src/mitm/inspector/kindDetector.ts`)

4 اشاریوں کا استعمال کرتے ہوئے ہر درخواست کو `"llm"`، `"app"`، یا `"unknown"` کے طور پر درجہ بند کرتا ہے:

1. **ہوسٹ رجسٹری** — تقریباً 18 معروف LLM API ہوسٹ نام (OpenAI، Anthropic، Gemini، Groq، Mistral، Together، Fireworks، Cohere، Perplexity، Hugging Face، OpenRouter، xAI، Moonshot، وغیرہ)
2. **پاتھ پیٹرنز** — `/v1/chat/completions`، `/v1/messages`، `/generateContent`، `/v1/responses`، وغیرہ
3. **باڈی کی ساخت** — `messages[]` (OpenAI/Claude)، `contents[]` (Gemini)، `prompt`، `input` فیلڈز کا پتہ لگاتا ہے
4. **یوزر ایجنٹ کے اشارے** — UA اسٹرنگ میں `codex`، `claude`، `gemini`، `antigravity`، `kiro`، `copilot`، `cursor`

Mode 2 کے ذریعے شامل کیے گئے کسٹم ہوسٹس فارم ان پٹ سے اپنا `kind` اخذ کرتے ہیں (ڈیفالٹ `"custom"` ہے)۔

### 4.2 SSE مرجر (`src/mitm/inspector/sseMerger.ts`)

**خود مختار کلین روم نفاذ۔** ایونٹ پارسنگ
[WHATWG server-sent events algorithm](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)
کی پیروی کرتی ہے، جبکہ تشکیلِ نو عوامی [OpenAI](https://platform.openai.com/docs/api-reference/chat/create)،
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming)، اور
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
اسٹریمنگ اسکیماؤں کی پیروی کرتی ہے۔

خام SSE ڈیلٹا ایونٹس سے اسسٹنٹ کے حتمی پیغام کی تشکیلِ نو کرتا ہے:

- **Anthropic**: انڈیکس کے لحاظ سے `content_block_delta` جمع کرتا ہے؛ `text_delta`، `input_json_delta` (ٹول کالز)، `thinking_delta` کو سنبھالتا ہے
- **OpenAI**: Chat Completions کے انتخاب/ٹول کالز اور Responses API آؤٹ پٹ آئٹمز کو انڈیکس کے لحاظ سے جمع کرتا ہے
- **Gemini**: `candidates[i].content.parts` جمع کرتا ہے
- **نامعلوم**: خام ایونٹس کو بغیر تبدیلی کے واپس کرتا ہے

Response ٹیب ایک ٹوگل دکھاتا ہے: **"خام ایونٹس ↔ ضم شدہ"**۔

### 4.3 گفتگو نارملائز کرنے والا (`src/mitm/inspector/conversationNormalizer.ts`)

**خود مختار کلین روم نفاذ۔** نارملائزیشن کی تعریف مقامی بلیک باکس
کنٹریکٹس اور عوامی OpenAI، Anthropic، اور Gemini پیغام اسکیماؤں کے ذریعے کی گئی ہے؛ کسی اپ اسٹریم
نفاذ کا ماخذ استعمال نہیں کیا گیا۔

رینڈرنگ سے پہلے OpenAI، Anthropic، اور Gemini پیغام فارمیٹس کو ایک واحد `NormalizedConversation` میں تبدیل کرتا ہے:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // درخواست کی باڈی سے messages / contents / prompt
  response: NormalizedTurn[]; // اسسٹنٹ کا جواب (sseMerger کے ذریعے ضم شدہ)
  contextKey: string | null; // سسٹم پرامپٹ کا SHA-256 فنگر پرنٹ
}
```

بلاک کی اقسام: `text`، `tool_use`، `tool_result`۔ فراہم کنندہ کوئی بھی ہو، Conversation ٹیب یہی ساخت استعمال کرتا ہے۔

### 4.4 کانٹیکسٹ کلید کی رنگ آمیزی (`src/mitm/inspector/contextKey.ts`)

- سسٹم پرامپٹ کا `SHA-256` شمار کرتا ہے (پہلا `role:system` پیغام، یا `system` فیلڈ، یا Gemini کا `systemInstruction`)
- 12 حروف پر مشتمل ہیکس سابقہ (`"a3f9c2..."`) واپس کرتا ہے
- فرنٹ اینڈ بائیں بارڈر کی پٹی کے لیے کلید کو ایک قطعی HSL رنگ سے میپ کرتا ہے
- **"ایک ہی کانٹیکسٹ" فلٹر**: `ctx #a3f` چپ پر کلک کرنے سے صرف ایک ہی فنگر پرنٹ والی درخواستیں دکھانے کے لیے فلٹر شامل ہو جاتا ہے

اس سے ایک ہی ایجنٹ سیشن میں چلنے والی مختلف "شخصیات" یا کاموں کو بصری طور پر ممتاز کرنا آسان ہو جاتا ہے۔

### 4.5 LLM میٹا ڈیٹا اخذ کرنا

LLM درخواستوں کے لیے، LLM Details ٹیب درج ذیل معلومات اخذ کرتا ہے:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // درخواست کی باڈی یا جواب سے
  messages: number; // ٹرنز کی تعداد
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // اگر SSE جواب ہو تو true
  mappedTo: string | null; // x-omniroute-mapped ہیڈر
  costEstimateUsd: number | null; // OmniRoute کی قیمتوں کی بنیاد پر تخمینی لاگت
}
```

### 4.6 زیرِ عمل براہِ راست درخواست کا فلٹر

درخواست کا `status` فیلڈ `number | "in-flight" | "error"` ہے — درخواست شروع ہوتے ہی ایک اندراج
`"in-flight"` کے طور پر شامل کر دیا جاتا ہے اور جواب (یا خرابی) آنے پر اسے **اسی جگہ اپ ڈیٹ**
کیا جاتا ہے۔ ٹول بار کا **"براہِ راست"** ٹوگل
(`liveOnly`، i18n کلید `trafficInspector.liveOnly`) فہرست کو ان اندراجات تک محدود کرتا ہے
جن کا `status === "in-flight"` ہو، جس سے آپ کھلے کنکشنز کو حقیقی وقت میں دیکھ سکتے ہیں۔

یہ فلٹر
`src/lib/inspector/matchesTrafficFilter.ts` میں ایک خالص، کلائنٹ سائیڈ پریڈیکیٹ ہے:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

ٹوگل کی حالت `useTrafficFilters` (انسپکٹر ڈیش بورڈ ہکس) میں موجود رہتی ہے اور
دوسرے فلٹرز (پروفائل، ہوسٹ، ایجنٹ، ماخذ، اسٹیٹس، کانٹیکسٹ) کے ساتھ مل کر کام کرتی ہے۔

### 4.7 پراسیس سے نسبت (Linux)

Linux پر، ہر انٹرسیپٹ کی گئی درخواست کو **اسے شروع کرنے والے مقامی
پراسیس** سے منسوب کیا جا سکتا ہے۔ `InterceptedRequest` میں دو اختیاری فیلڈز شامل کیے گئے ہیں:

```ts
pid?: number;          // شروع کرنے والے پراسیس کی id (صرف Linux)
processName?: string;  // شروع کرنے والے پراسیس کا نام (صرف Linux)
```

`src/mitm/inspector/processAttribution.ts` کنکشن کی _کلائنٹ_
عارضی پورٹ کو درج ذیل طریقے سے PID + نام سے میپ کرتا ہے:

1. پورٹ کے لیے ساکٹ inode تلاش کرنے کی خاطر `/proc/net/tcp` اور `/proc/net/tcp6` کو پڑھنا
   (`parseProcNetTcpForInode`، ایک خالص، فکسچر سے قابلِ آزمائش پارسر)۔
2. `socket:[<inode>]` کے سم لنک کے لیے `/proc/<pid>/fd/` کو اسکین کرنا۔
3. `/proc/<pid>/comm` سے پراسیس کا نام پڑھنا۔

1 سیکنڈ کی TTL کیش لوڈ کے دوران procfs اسکین کی لاگت کو محدود رکھتی ہے۔ نسبت
**بہترین ممکنہ کوشش** پر مبنی ہے — کسی بھی ناکامی کا نتیجہ `null` ہوتا ہے اور یہ کیپچر کو کبھی بلاک نہیں کرتی۔
macOS/Windows پر فنکشن `null` واپس کرتا ہے (اسٹب؛ `lsof`/`GetExtendedTcpTable`
کی معاونت آئندہ شامل کی جائے گی)۔

## §5 سیشنز

### 5.1 سیشن ریکارڈ کرنا

1. ٹول بار میں **"● سیشن ریکارڈ کریں"** پر کلک کریں → ایک نام درج کریں (اختیاری)
2. لائیو ٹیل معمول کے مطابق جاری رہتی ہے؛ ایک سرخ متحرک اشارہ `◉ REC · <نام> · 00:42 · 23 درخواستیں` دکھاتا ہے
3. **"⏹ روکیں"** پر کلک کریں → سیشن اسنیپ شاٹ `inspector_sessions` + `inspector_session_requests` میں محفوظ ہو جاتا ہے

### 5.2 ریکارڈ شدہ سیشن دیکھنا

ٹول بار میں **سیشنز** ڈراپ ڈاؤن محفوظ شدہ سیشنز کی فہرست دکھاتا ہے۔ کسی ایک کو منتخب کرنے پر:

- سیشن کا اسنیپ شاٹ لوڈ ہوتا ہے (منجمد حالت)
- ایک بینر دکھاتا ہے: `ریکارڈ شدہ سیشن "<نام>" دیکھا جا رہا ہے — [لائیو پر واپس جائیں]`
- Recharts کے مجموعی اعداد و شمار کے ساتھ Stats ٹیب دستیاب ہو جاتا ہے

### 5.3 برآمدی فارمیٹس

ہر سیشن کو درج ذیل صورتوں میں برآمد کیا جا سکتا ہے:

| فارمیٹ                     | استعمال                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools، Charles، Fiddler کے ساتھ ہم آہنگ — آف لائن تجزیے کے لیے درآمد کریں |
| **JSONL**                  | ہر سطر میں ایک `InterceptedRequest` — `llm-interceptor` فارمیٹ کے ساتھ ہم آہنگ      |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` یا سیشنز ڈراپ ڈاؤن میں موجود ⬇ بٹن کے ذریعے برآمد کریں۔

Traffic Inspector اجازت دہی کے ہیڈرز اور درخواست کے متن سمیت **تمام انٹرسیپٹ شدہ HTTPS ٹریفک** دکھاتا ہے۔ درج ذیل کنٹرولز نافذ ہیں:

| کنٹرول                                  | تفصیلات                                                                                                                                                                                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **LOCAL_ONLY**                          | تمام روٹس اور WebSocket اینڈ پوائنٹ صرف لوپ بیک تک محدود ہیں (تصدیق سے پہلے `routeGuard.ts` میں نافذ کیا جاتا ہے)                                                                          |
| **خفیہ معلومات کی ماسکنگ**              | خطی `maskSecret()` اسکینر `TrafficBuffer.push()` سے پہلے RFC 6750 Bearer اسناد، فراہم کنندہ کے سابقے والی کلیدیں اور طویل مبہم ٹوکنز کو مخفی کرتا ہے                                       |
| **باڈی کے حجم کی حد**                   | `INSPECTOR_MAX_BODY_KB` (طے شدہ 1024 KB) سے بڑی باڈیز کو `"(کارکردگی کی خاطر مختصر کیا گیا)"` نوٹس کے ساتھ مختصر کر دیا جاتا ہے                                                            |
| **ہیڈر کی تطہیر**                       | نام چھوٹے حروف میں تبدیل کیے جاتے ہیں؛ فریمنگ/ہاپ-بائی-ہاپ اور پراکسی تصدیقی ہیڈرز ہٹا دیے جاتے ہیں؛ کوکیز مکمل طور پر مخفی کی جاتی ہیں؛ اسناد کی اقدار `maskSecret()` کے سپرد کی جاتی ہیں |
| **CSP**                                 | داخل کردہ رسپانس باڈیز کے ذریعے XSS روکنے کے لیے Traffic Inspector صفحات پر سخت Content Security Policy                                                                                    |
| **طے شدہ طور پر کوئی مستقل ذخیرہ نہیں** | `TrafficBuffer` ان میموری ہے اور سرور کے دوبارہ شروع ہونے پر ضائع ہو جاتا ہے۔ سیشنز صرف واضح طور پر ریکارڈ کیے جانے پر مستقل طور پر محفوظ ہوتے ہیں                                         |

### نافذ کردہ سخت قواعد

| اصول                              | اطلاق                                                                               |
| --------------------------------- | ----------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Traffic Inspector روٹس کے تمام HTTP خرابی کے جوابات کی تطہیر کی جاتی ہے             |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/`، LOCAL_ONLY + SPAWN_CAPABLE ہے (سسٹم پراکسی کمانڈز) |

### معلوم حدود

- **پورے سسٹم کا پراکسی موڈ** مشین پر موجود تمام ایپلیکیشنز کو متاثر کرتا ہے، بشمول VPN کلائنٹس اور SSO۔ ہمیشہ خودکار طور پر غیر فعال کرنے والے ٹائمر کے ساتھ استعمال کریں۔ مشترکہ مشینوں پر استعمال نہ کریں۔
- **CONNECT ٹنل HTTPS**: موڈ 3 (HTTP_PROXY)، TLS انٹرسیپشن فعال نہ ہونے کی صورت میں HTTPS منزلوں کے لیے صرف ٹنل میٹا ڈیٹا حاصل کرتا ہے۔ یہ دانستہ ڈیزائن ہے — ان ایپس کے لیے AgentBridge سرٹیفکیٹ قابلِ اعتماد بنائے بغیر شفاف کیپچر TLS توثیق کو ناکام کر دے گا۔
- **کچھ اجزا میں ہارڈ کوڈ شدہ اسٹرنگز**: کچھ UI اجزا (F7/F8) میں چند ہارڈ کوڈ شدہ اسٹرنگز موجود ہیں جو ابھی تک i18n کلیدوں کے تحت نہیں آتیں۔ انہیں i18n گیپ رپورٹ میں معلوم حد کے طور پر درج کیا گیا ہے؛ انہیں آئندہ مرحلے میں منتقل کیا جائے گا۔ متاثرہ اسٹرنگز UI کے آرائشی لیبلز ہیں جنہیں عملی استعمال کے لیے ترجمے کی ضرورت نہیں۔

## §7 مسائل کا ازالہ

### WebSocket کا منقطع ہونا

اگر لائیو ٹیل "Disconnected" دکھائے:

1. چیک کریں کہ سرور اب بھی چل رہا ہے: `GET /api/tools/traffic-inspector/capture-modes`
2. صفحہ دوبارہ لوڈ کریں — WebSocket دوبارہ منسلک ہو کر ایک تازہ اسنیپ شاٹ وصول کرتا ہے
3. اگر سرور دوبارہ شروع کیا گیا تھا، تو اِن میموری بفر صاف ہو چکا ہوگا — پرانی اندراجات ختم ہو چکی ہیں، الا یہ کہ کوئی سیشن ریکارڈ کیا گیا ہو

### پورٹ 8080 کا تصادم

اگر HTTP_PROXY موڈ شروع نہ ہو سکے:

```bash
lsof -i :8080    # پراسیس تلاش کریں
```

پورٹ تبدیل کریں:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### سسٹم پراکسی واپس بحال نہیں ہوئی

اگر سسٹم گیر پراکسی موڈ فعال ہونے کے دوران OmniRoute کریش ہو جائے:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

اگر اگلی بار لوڈ ہونے پر ڈیش بورڈ کو DB کی حالت سے معلوم ہو کہ پراکسی فعال تھی، تو وہ "سسٹم پراکسی واپس بحال کریں" کا اختیار بھی پیش کرے گا۔

### بفر بھر گیا

جب بفر `INSPECTOR_BUFFER_SIZE` (پہلے سے طے شدہ 1000) تک پہنچتا ہے، تو نئی اندراجات قدیم ترین اندراجات کو خارج کر دیتی ہیں۔ اگر اہم درخواستیں ضائع ہو رہی ہوں:

- `INSPECTOR_BUFFER_SIZE` بڑھائیں (مثلاً، 5000) — اس سے زیادہ میموری کے بدلے زیادہ اندراجات محفوظ رہیں گی
- متعلقہ دورانیے کو DB میں برقرار رکھنے کے لیے ایک سیشن ریکارڈ کریں

## §8 API حوالہ

تمام روٹس `LOCAL_ONLY` (صرف لوپ بیک) اور `SPAWN_CAPABLE` (سسٹم پراکسی کمانڈز) ہیں۔ `src/server/authz/routeGuard.ts` دیکھیں۔

بنیادی پاتھ: `/api/tools/traffic-inspector/`

### درخواستوں کا انتظام

| طریقہ  | پاتھ                        | وضاحت                                                                                     |
| ------ | --------------------------- | ----------------------------------------------------------------------------------------- |
| GET    | `/requests`                 | درخواستوں کی فہرست (فلٹر کے قابل: `?profile=llm&host=&agent=&status=&source=&sessionId=`) |
| GET    | `/requests/{id}`            | کسی ایک درخواست کی تفصیلات                                                                |
| DELETE | `/requests`                 | اِن میموری بفر صاف کریں                                                                   |
| POST   | `/requests/{id}/replay`     | اسی درخواست کو OmniRoute روٹر کے ذریعے دوبارہ چلائیں                                      |
| PUT    | `/requests/{id}/annotation` | کسی درخواست پر نوٹ محفوظ یا اپ ڈیٹ کریں                                                   |

### WebSocket

| طریقہ | پاتھ  | وضاحت                                                                                         |
| ----- | ----- | --------------------------------------------------------------------------------------------- |
| GET   | `/ws` | لائیو WebSocket اسٹریم۔ منسلک ہونے پر `snapshot`، پھر `new`/`update`/`clear` ایونٹس بھیجتی ہے |

### برآمد

| طریقہ | پاتھ          | وضاحت                                                 |
| ----- | ------------- | ----------------------------------------------------- |
| GET   | `/export.har` | موجودہ فلٹر شدہ فہرست کو HAR 1.2 کے طور پر برآمد کریں |

### حسبِ ضرورت ہوسٹس

| طریقہ  | پاتھ            | وضاحت                                                     |
| ------ | --------------- | --------------------------------------------------------- |
| GET    | `/hosts`        | حسبِ ضرورت ہوسٹس کی فہرست دکھائیں                         |
| POST   | `/hosts`        | ہوسٹ شامل کریں (`/etc/hosts` خودکار طور پر ترمیم ہوتا ہے) |
| DELETE | `/hosts/{host}` | ہوسٹ ہٹائیں                                               |
| PATCH  | `/hosts/{host}` | `enabled` کو ٹوگل کریں                                    |

### کیپچر موڈز

| طریقہ | پاتھ                           | وضاحت                                                                                         |
| ----- | ------------------------------ | --------------------------------------------------------------------------------------------- |
| GET   | `/capture-modes`               | AgentBridge / حسبِ ضرورت ہوسٹس / HTTP_PROXY / سسٹم پراکسی موڈز کی حالت + `tls-intercept` ٹوگل |
| POST  | `/capture-modes/http-proxy`    | HTTP_PROXY لسنر شروع/بند کریں (`{action: "start"\|"stop"}`)                                   |
| POST  | `/capture-modes/system-proxy`  | سسٹم گیر پراکسی لاگو/واپس بحال کریں (`{action: "apply"\|"revert"}`)                           |
| POST  | `/capture-modes/tls-intercept` | پراکسی موڈ میں HTTPS باڈی ڈکرپشن ٹوگل کریں (`{enabled: boolean}`)                             |

> **TPROXY ڈکرپٹ** (کیپچر موڈ 5) کو AgentBridge سابقے کے تحت ایک **علیحدہ** روٹ چلاتا ہے —
> `GET / POST / DELETE /api/tools/agent-bridge/tproxy` — یہ
> `/api/tools/traffic-inspector/` کے تحت نہیں ہے۔ دیکھیں:
> `docs/security/MITM-TPROXY-DECRYPT.md` (git؛ `/docs` میں کمپائل نہیں کیا گیا)۔
