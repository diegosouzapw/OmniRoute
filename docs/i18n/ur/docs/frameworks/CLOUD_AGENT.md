> **حقیقت کا مستند ماخذ:** `src/lib/cloudAgent/` اور `src/app/api/v1/agents/tasks/`
> **آخری بار اپ ڈیٹ کیا گیا:** 2026-06-28 — v3.8.40 (فرنٹ میٹر کی تازہ کاری؛ cursor-cloud سمیت 4 ایجنٹس)

OmniRoute فریقِ ثالث کے کلاؤڈ پر ہوسٹ کردہ کوڈنگ ایجنٹس (Codex Cloud، Cursor،
Devin، Jules) کو طویل دورانیے کے ٹاسکس کے طور پر منظم کرتا ہے۔ ہر ایجنٹ کو ایک یکساں انٹرفیس کے پیچھے لپیٹا گیا ہے تاکہ
کلائنٹس فراہم کنندہ سے مخصوص APIs سے نمٹے بغیر ایک پرامپٹ + ریپو URL جمع کرا سکیں اور نتائج حاصل کر سکیں۔

Cloud Agent ٹاسک کوئی معمول کا چیٹ کمپلیشن **نہیں** ہے۔ یہ کام کی ایک پائیدار، کثیر مرحلہ
اکائی ہے جس میں چند منٹ سے کئی گھنٹے لگ سکتے ہیں، جو اپنے
آرٹیفیکٹ کے طور پر Pull Request تیار کر سکتی ہے، اور فالو اَپ پیغامات نیز (بعض فراہم کنندگان میں) پلان کی منظوری کے مراحل کی معاونت کرتی ہے۔

## فنِ تعمیر

```
کلائنٹ (ڈیش بورڈ / CLI / API)
  → POST /api/v1/agents/tasks (انتظامی تصدیق درکار ہے)
    → CreateCloudAgentTaskSchema کی توثیق (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) سے حاصل کرتا ہے
         (پہلے apiKey، دستیاب نہ ہونے پر accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ اپ اسٹریم فراہم کنندہ API کو HTTP POST
      └─ اندرونی id + externalId کے ساتھ CloudAgentTask واپس کرتا ہے
    → cloud_agent_tasks (SQLite) میں insertCloudAgentTask(...)

پولنگ (پڑھنے پر سست مطابقت پذیری):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // اسٹیٹس + سرگرمیوں کو تازہ کرتا ہے
    → نئے اسٹیٹس، نتیجے، completed_at کے ساتھ updateCloudAgentTask(...)
    → سیریلائز کردہ ٹاسک واپس کرتا ہے

تعاملات:
  POST /api/v1/agents/tasks/[id]  باڈی: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve" کے لیے
    → agent.sendMessage(externalId, message, credentials) "message" کے لیے
    → اسٹیٹس "cancelled" میں تبدیل ہوتا ہے             "cancel" کے لیے (صرف مقامی)
```

مطابقت پذیری **سست** ہے: ہر `GET /tasks/[id]` پر اسٹیٹس کو اپ اسٹریم سے تازہ کیا جاتا ہے۔
پس منظر میں کوئی پولر موجود نہیں ہے۔ جن ڈیش بورڈز کو تازہ حالت درکار ہو، انہیں مناسب وقفے سے GET
اینڈپوائنٹ کو پول کرنا چاہیے۔

## `CloudAgentBase` انٹرفیس

ماخذ: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // بالائی نظام کی اسٹرنگ سے enum تک تخمینی میپنگ
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` دانستہ طور پر استثنا پھینکتا ہے — Codex Cloud خودکار طور پر منصوبہ بناتا ہے اور اس میں منظوری کا کوئی مرحلہ نہیں ہے۔ `CodexCloudAgent.listSources`، `[]` واپس کرتا ہے۔

`CursorCloudAgent`، Cursor کے Background / Cloud Agents کو اس کی سرکاری REST API (`api.cursor.com/v0`) کے ذریعے **صارف یا سروس اکاؤنٹ کی API کلید** کے ساتھ چلاتا ہے — یہ Cursor IDE کے OAuth سیشن کو دوبارہ استعمال کرنے کے مقابلے میں زیادہ محفوظ، فریقِ اول متبادل ہے (فراہم کنندہ `cursor`، جس کے ساتھ پابندی لگنے کے خطرے کی تنبیہ شامل ہے)۔ یہ ایک سادہ REST اڈاپٹر ہے (کوئی مقامی `@cursor/sdk` انحصار نہیں)۔ `approvePlan` استثنا پھینکتا ہے (Cursor ایجنٹس خود مختار طور پر چلتے ہیں)؛ `listSources` کلید کے ذریعے قابلِ رسائی ریپوزٹریز کی فہرست دیتا ہے۔ Cursor بڑے حروف والے اسٹیٹس enums (`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) واپس کرتا ہے، جنہیں واضح طور پر مشترکہ `CloudAgentStatus` سے میپ کیا جاتا ہے۔ `baseUrl` کو ہر اسناد کے لیے اوور رائیڈ کیا جا سکتا ہے، تاکہ API ورژن/پاتھ کو کوڈ میں تبدیلی کے بغیر درست کیا جا سکے۔

## ڈومین کی اقسام

ماخذ: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // ایک درست URL ہونا ضروری ہے
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // سیکنڈز، مثبت صحیح عدد
  cost?: number; // مثبت اعشاری عدد
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // داخلی `task_...` آئی ڈی
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // بالائی فراہم کنندہ کی آئی ڈی
  status: CloudAgentStatus;
  prompt: string; // 1..10000 حروف
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

توثیقی اسکیمے (`CreateCloudAgentTaskSchema`، `UpdateCloudAgentTaskSchema`) اقسام کے ساتھ ہی ایکسپورٹ کیے جاتے ہیں اور روٹ ہینڈلرز کے ذریعے استعمال ہوتے ہیں۔

## ڈیٹابیس

ماخذ: `src/lib/cloudAgent/db.ts` — ٹیبل کو ضرورت کے وقت
`createCloudAgentTaskTable()` کے ذریعے بنایا جاتا ہے (اسے ماڈیول امپورٹ کے وقت
`src/lib/cloudAgent/index.ts` سے بھی کال کیا جاتا ہے)۔

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

`updateCloudAgentTask`، SQL انجیکشن سے بچاؤ کے لیے **کالم وائٹ لسٹ** نافذ کرتا ہے:
`status`، `prompt`، `source`، `options`، `result`، `activities`، `error`،
`completed_at`۔ جزوی اپ ڈیٹ میں موجود کوئی بھی دوسری کلید خاموشی سے حذف کر دی جاتی ہے۔

## REST API — ٹاسک کا لائف سائیکل

**توثیق:** تمام `/api/v1/agents/tasks*` اینڈ پوائنٹس کے لیے **مینجمنٹ توثیق**
درکار ہے (`requireCloudAgentManagementAuth`،
`src/lib/api/requireManagementAuth` کے `requireManagementAuth` کو ریپ کرتا ہے)۔
یہ پابندی commit `588a0333`
(_"درستگی(auth): ایجنٹ اور کول ڈاؤن APIs کے لیے مینجمنٹ توثیق درکار بنائیں"_) کے بعد نافذ ہے۔

| طریقہ   | راستہ                         | مقصد                                                               |
| ------- | ----------------------------- | ------------------------------------------------------------------ |
| OPTIONS | `/api/v1/agents/tasks`        | CORS پری فلائٹ                                                     |
| GET     | `/api/v1/agents/tasks`        | ٹاسکس کی فہرست (`provider`، `status`، `limit≤500` کے ذریعے فلٹر)   |
| POST    | `/api/v1/agents/tasks`        | ٹاسک بنائیں (اپ اسٹریم کو بھیجتا اور محفوظ کرتا ہے)                |
| DELETE  | `/api/v1/agents/tasks?id=...` | کوئری id کے ذریعے ٹاسک حذف کریں (اپ اسٹریم کو منسوخ **نہیں** کرتا) |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS پری فلائٹ                                                     |
| GET     | `/api/v1/agents/tasks/[id]`   | ٹاسک پڑھیں + اپ اسٹریم سے اسٹیٹس کو ضرورت کے وقت سنک کریں          |
| POST    | `/api/v1/agents/tasks/[id]`   | عمل: `approve` / `message` / `cancel`                              |
| DELETE  | `/api/v1/agents/tasks/[id]`   | پاتھ id کے ذریعے ٹاسک حذف کریں                                     |

### ٹاسک بنائیں

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Fix the bug in src/foo.ts where the parser returns null",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    },
    "options": {
      "autoCreatePr": true,
      "planApprovalRequired": false
    }
  }'
```

جواب `201`:

```json
{
  "data": {
    "id": "task_1731512345678_abc123def",
    "providerId": "devin",
    "externalId": "session_xyz",
    "status": "queued",
    "prompt": "...",
    "source": { "repoName": "user/repo", "repoUrl": "...", "branch": "main" },
    "options": { "autoCreatePr": true },
    "createdAt": "2026-05-13T12:34:56.789Z"
  }
}
```

### پلان منظور کریں

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"action":"approve"}'
```

### فالو اپ پیغام بھیجیں

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"message","message":"Also add a unit test for the parser"}'
```

### منسوخ کریں (صرف مقامی اسٹیٹس)

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks/<id> \
  -d '{"action":"cancel"}'
```

`cancel` مقامی DB میں `status` کو `"cancelled"` میں تبدیل کرتا ہے، لیکن اپ اسٹریم
فراہم کنندہ کو کال **نہیں** کرتا — `CloudAgentBase` میں کوئی abort RPC موجود نہیں ہے۔
اپ اسٹریم بلنگ روکنے کے لیے، ٹاسک کو فراہم کنندہ کے اپنے کنسول میں ختم کریں۔

## REST API — کلاؤڈ پرووائیڈر کا بنیادی ڈھانچہ

`src/app/api/cloud/` کے تحت موجود یہ معاون اینڈ پوائنٹس ریموٹ کلائنٹس
(CLI، Electron ایپ، یا سنک ورکرز) کے ذریعے پرووائیڈر کنکشن کا میٹا ڈیٹا پڑھنے
اور ماڈل عرفیات کو حل کرنے کے لیے استعمال ہوتے ہیں۔ ان کی توثیق ایک **باقاعدہ API کلید**
(`validateApiKey` کے ذریعے) سے ہوتی ہے، نہ کہ ٹاسک اینڈ پوائنٹس کے زیرِ استعمال مینجمنٹ توثیق سے۔

| طریقہ | پاتھ                            | مقصد                                                                                |
| ----- | ------------------------------- | ----------------------------------------------------------------------------------- |
| POST  | `/api/cloud/auth`               | API کلید کی توثیق کرنا، مخفی کنکشن میٹا ڈیٹا + ماڈل عرفیات واپس کرنا                |
| PUT   | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` کو تازہ کرنا                           |
| POST  | `/api/cloud/model/resolve`      | ماڈل عرف کو `{ provider, model }` میں حل کرنا                                       |
| GET   | `/api/cloud/models/alias`       | تمام ماڈل عرفیات کی فہرست دینا                                                      |
| PUT   | `/api/cloud/models/alias`       | ماڈل عرف مقرر کرنا (اور فعال ہونے کی صورت میں خودکار طور پر Cloud کے ساتھ سنک کرنا) |

`/api/cloud/auth` کبھی بھی اصل `apiKey` / `accessToken` / `refreshToken` واپس نہیں کرتا۔ یہ
`hasApiKey`، `hasAccessToken`، `hasRefreshToken`، اور ایک مخفی پیش منظر
(`maskedApiKey`: پہلے 4 + `****` + آخری 4) واپس کرتا ہے۔

## اسناد کا تعین

`src/lib/cloudAgent/api.ts` میں `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` کے ذریعے فعال پرووائیڈر کنکشنز لوڈ کرتا ہے۔
2. ہر کنکشن کے لیے `apiKey` (اضافی خالی جگہیں ہٹا کر) کو ترجیح دیتا ہے۔ موجود نہ ہونے پر `accessToken` استعمال کرتا ہے۔
3. پہلے غیر خالی ٹوکن کو `{ apiKey: token }` کی شکل میں لپیٹ کر واپس کرتا ہے۔
4. اگر کوئی قابلِ استعمال ٹوکن نہ ملے تو `null` واپس کرتا ہے — API درج ذیل پیغام کے ساتھ
   `400` جواب دیتا ہے:
   `"کلاؤڈ ایجنٹ پرووائیڈر کے لیے کوئی فعال اسناد ترتیب نہیں دی گئیں: <id>"`۔

اس کا مطلب ہے کہ Cloud Agents بھی وہی Provider Connection ٹیبل دوبارہ استعمال کرتے ہیں جو باقاعدہ LLM
پرووائیڈرز استعمال کرتے ہیں۔ Jules کو فعال کرنے کے لیے `provider: "jules"`
اور پُر شدہ `apiKey` کے ساتھ ایک فعال کنکشن بنائیں۔

## ڈیش بورڈ

ماخذ: `src/app/(dashboard)/dashboard/cloud-agents/page.tsx`

ایک `"use client"` React صفحہ جو:

- ٹاسکس کی فہرست دکھاتا ہے (`GET /api/v1/agents/tasks` کے ذریعے وقفے وقفے سے حاصل کیے جاتے ہیں)۔
- ایک ایسے فارم کے ذریعے نئے ٹاسکس جمع کراتا ہے جو `CreateCloudAgentTaskSchema` سے میپ ہوتا ہے۔
- اسٹیٹس بیجز (`queued`، `running`، `awaiting_approval`، `completed`،
  `failed`، `cancelled`) دکھاتا اور `activities[]` ٹائم لائن رینڈر کرتا ہے۔
- جب `status === "completed"` ہو تو `result.prUrl` / `commitMessage` / `summary` نمایاں کرتا ہے۔

## A2A کے ساتھ انضمام

Cloud Agents کو ایک ایسی A2A مہارت رجسٹر کر کے A2A مہارتوں کے طور پر ظاہر کیا جا سکتا ہے جو
اپنے `tasks/send` ہینڈلر کو `getAgent(...).createTask(...)` کے سپرد کرتی ہے اور A2A ٹاسک
اسٹیٹس ایونٹس کو JSON-RPC 2.0 پروٹوکول میں تبدیل کرتی ہے۔ [A2A-SERVER.md](./A2A-SERVER.md) دیکھیں۔

## نیا Cloud Agent شامل کرنا

1. `CloudAgentBase` کو توسیع دیتے ہوئے `src/lib/cloudAgent/agents/<name>.ts` بنائیں۔
2. `createTask`، `getStatus`، `approvePlan` (یا اگر قابلِ اطلاق نہ ہو تو استثنا خارج کریں)،
   `sendMessage`، `listSources` نافذ کریں۔ اسٹیٹس کو معمول پر لانے کے لیے `this.mapStatus(...)` استعمال کریں۔
3. `src/lib/cloudAgent/registry.ts` میں ایک مستحکم `providerId` کے تحت رجسٹر کریں۔
4. `src/lib/cloudAgent/types.ts` میں `providerId` لٹرل یونین کو توسیع دیں
   (`CloudAgentTask.providerId` اور `CreateCloudAgentTaskSchema`)۔
5. اگر پرووائیڈر کو کنکشن ریکارڈ درکار ہو تو اسے `src/shared/constants/providers.ts` میں شامل کریں۔
   OAuth پر مبنی پرووائیڈرز کو `src/lib/oauth/providers/` بھی درکار ہے۔
6. `tests/unit/cloud-agent-*.test.ts` کے تحت ٹیسٹس شامل کریں۔
7. اس دستاویز اور ڈیش بورڈ کے `CLOUD_AGENTS` مستقل کو اپ ڈیٹ کریں۔

## کنفیگریشن

| ماحولیاتی متغیر  | مقصد                                                                          |
| ---------------- | ----------------------------------------------------------------------------- |
| `DATA_DIR`       | `cloud_agent_tasks` رکھنے والے SQLite ڈیٹابیس کا مقام                         |
| `JWT_SECRET`     | ٹاسک اینڈ پوائنٹس پر انتظامی توثیق کے لیے درکار ہے                            |
| `API_KEY_SECRET` | محفوظ شدہ حالت میں فراہم کنندہ کے کنکشن کی اسناد کو خفیہ کرنے کے لیے درکار ہے |

فی الحال Cloud-Agent کے لیے مخصوص کوئی ماحولیاتی متغیر موجود نہیں ہے — ہر راز
`provider_connections` ٹیبل میں محفوظ ہوتا ہے۔
