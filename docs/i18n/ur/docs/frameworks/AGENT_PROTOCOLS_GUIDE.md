OmniRoute ایجنٹس سے متعلق تین مختلف سطحیں فراہم کرتا ہے۔ پہلی نظر میں یہ ایک جیسی دکھائی دیتی ہیں، لیکن مختلف مسائل حل کرتی ہیں۔ درست سطح منتخب کرنے کے لیے یہ صفحہ استعمال کریں۔

## خلاصہ

| سطح                         | کس کے لیے بہترین                                                                                                            | ترسیل                      | معیار                  |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------- | -------------------------- | ---------------------- |
| **A2A — ایجنٹ سے ایجنٹ**    | A2A پروٹوکول استعمال کرنے والے ہم مرتبہ ایجنٹس کے ساتھ بین الایجنٹ تعاون                                                    | HTTP پر JSON-RPC 2.0       | A2A v0.3 (کھلی تخصیص)  |
| **ACP — CLI ایجنٹس رجسٹری** | صارف کی مشین پر نصب CLI کوڈنگ ایجنٹس (Cursor، Cline، Codex CLI، Claude Code، Aider وغیرہ) کا پتہ لگانا / رجسٹر کرنا / چلانا | HTTP REST                  | OmniRoute کے لیے مخصوص |
| **کلاؤڈ ایجنٹس**            | بیرونی کلاؤڈ سروسز (Codex Cloud، Devin، Jules، Cursor Cloud) کو طویل دورانیے کے کوڈنگ کام جمع کرانا                         | HTTP REST + DB پر مبنی کام | OmniRoute کے لیے مخصوص |

یہ تینوں ایک دوسرے سے آزاد ہیں — ان میں سے کوئی بھی مجموعہ منتخب کریں۔

## فیصلہ جاتی شجرہ

```
کیا آپ کو اس مشین سے باہر کام انجام دینے کے لیے کسی کلاؤڈ سروس (Codex Cloud / Cursor Cloud / Devin / Jules) کی ضرورت ہے؟
├─ ہاں → کلاؤڈ ایجنٹس (POST /api/v1/agents/tasks)
└─ نہیں → جاری رکھیں
    │
    کیا آپ کے پاس کوئی ایسا ہم مرتبہ ایجنٹ ہے جو A2A استعمال کرتا ہو اور تعاون کرنا چاہتا ہو؟
    ├─ ہاں → A2A (POST /a2a)
    └─ نہیں → جاری رکھیں
        │
        کیا آپ کو مقامی طور پر نصب CLI کوڈنگ ایجنٹس کی فہرست بنانے / انہیں ترتیب دینے کی ضرورت ہے؟
        ├─ ہاں → ACP (GET /api/acp/agents)
        └─ نہیں → سادہ /v1/chat/completions استعمال کریں
```

## 1. A2A — ایجنٹ سے ایجنٹ

**تخصیص:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute اینڈ پوائنٹ:** `POST /a2a` (JSON-RPC 2.0)
**ایجنٹ کارڈ:** `GET /.well-known/agent.json`

### کب استعمال کریں

- ایسا کثیر ایجنٹ نظام بناتے وقت جس میں OmniRoute ہم مرتبہ ایجنٹس میں سے ایک ہو
- Google ADK جیسے فریم ورکس یا عمومی ایجنٹ میشز میں موجود ایجنٹس کو OmniRoute کی روٹنگ ذہانت (smart-routing، quota-management وغیرہ) فراہم کرتے وقت
- OmniRoute کو معیاری دریافت + استدعا سطح کے پیچھے لپیٹتے وقت

### طریقے

- `message/send` — پیغام جمع کرائیں اور ہم وقت جواب وصول کریں
- `message/stream` — پیغام جمع کرائیں + SSE کے ذریعے اسٹریم کردہ پیش رفت کے واقعات وصول کریں
- `tasks/get` — ID کے ذریعے کام پڑھیں
- `tasks/cancel` — جاری کام منسوخ کریں

### بلٹ اِن مہارتیں (6)

- `smart-routing` — پرامپٹ کو بہترین مجموعے کے ذریعے روٹ کریں
- `quota-management` — ہر فراہم کنندہ کے کوٹے کی حالت رپورٹ کریں
- `provider-discovery` — نصب شدہ فراہم کنندگان کو ان کی صلاحیتوں سمیت فہرست کریں
- `cost-analysis` — کسی درخواست/گفتگو کی لاگت کا تخمینہ لگائیں
- `health-report` — ہر فراہم کنندہ کے لیے بریکر/کول ڈاؤن/لاک آؤٹ کی حالت یکجا کریں
- `list-capabilities` — ایجنٹ کی دستیاب مہارتوں اور میٹا ڈیٹا کی فہرست بنائیں

### تفصیلی جائزہ

ترسیل کی تفصیلات، ایجنٹ کارڈ کی ساخت، کام کی TTL ترتیب، اور نئی مہارتیں شامل کرنے کے سانچے کے لیے [A2A-SERVER.md](./A2A-SERVER.md) دیکھیں۔

## 2. ACP — CLI ایجنٹس رجسٹری

**OmniRoute اینڈ پوائنٹ:** `GET /api/acp/agents`
**ماخذ:** `src/lib/acp/{index,manager,registry}.ts`

### یہ کیا ہے

ACP، OmniRoute کی **مقامی CLI ایجنٹ انوینٹری** ہے۔ یہ پتہ لگاتی ہے کہ ہوسٹ پر کون سے کوڈنگ CLIs انسٹال ہیں (Cursor، Cline، Claude Code، Codex CLI، Continue وغیرہ)، ان کے ورژنز معلوم کرتی ہے، اور انہیں ڈیش بورڈ پر دکھاتی ہے تاکہ صارف ہر CLI کو OmniRoute کی جانب پوائنٹ کرنے کے لیے ترتیب دے سکے۔

یہ کوئی بیرونی پروٹوکول نہیں ہے — یہ ایک اندرونی رجسٹری ہے جو "CLI Tools" UI اور CLI فنگر پرنٹ ٹریکنگ کو تقویت دیتی ہے (دیکھیے [CLI-TOOLS.md](../reference/CLI-TOOLS.md))۔

### یہ کیا کرتی ہے

- انسٹال شدہ CLI بائنریز کے لیے ہوسٹ کی جانچ کرتی ہے (OS کے مطابق `which` / `where` استعمال کرتی ہے)
- ہر CLI کا ورژن پڑھتی ہے (`<bin> --version` کال کرتی ہے)
- اختیاری طور پر صارف کے متعین کردہ کسٹم ایجنٹس قبول کرتی ہے (بائنری پاتھ + ورژن پروب + اسپان آرگومنٹس)
- کسٹم ایجنٹس کو سیٹنگز میں مستقل طور پر محفوظ رکھتی ہے
- متحدہ فہرست ڈیش بورڈ کو واپس کرتی ہے

### REST API

| اینڈ پوائنٹ       | طریقہ | تفصیل                                                         | توثیق    |
| ----------------- | ----- | ------------------------------------------------------------- | -------- |
| `/api/acp/agents` | GET   | شناخت شدہ + کسٹم ایجنٹس کی فہرست (انسٹال شدہ/کل تعداد)        | API کلید |
| `/api/acp/agents` | POST  | کسٹم ایجنٹ شامل/اپ ڈیٹ/حذف کریں (باڈی میں ایکشن امتیاز کنندہ) | API کلید |

POST کے لیے باڈی کی ساخت (`src/app/api/acp/agents/route.ts` میں `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### استعمال کے مواقع

- ڈیش بورڈ کا "CLI Tools" صفحہ انسٹال شدہ ٹولز کی فہرست دکھاتا ہے اور ہر ٹول کو OmniRoute کی جانب پوائنٹ کرنے میں مدد دیتا ہے
- کسٹم ایجنٹس ماہر صارفین کو ایسی داخلی/ملکیتی CLIs رجسٹر کرنے دیتے ہیں جن کے بارے میں OmniRoute کو بطور ڈیفالٹ علم نہیں ہوتا
- شناخت کا نتیجہ `cli-tools` فنگر پرنٹ میٹرکس کو ڈیٹا فراہم کرتا ہے

### ACP کب استعمال نہ کریں

- ACP ٹاسکس _چلاتا_ نہیں ہے۔ یہ صرف CLIs کا پتہ لگاتا اور انہیں کنفیگر کرتا ہے۔ کسی CLI کو حقیقتاً استعمال کرنے کے لیے، اسے OmniRoute کی فراہم کردہ ماحول متغیرات (`OPENAI_BASE_URL`، `OPENAI_API_KEY` وغیرہ) کے ساتھ خود لانچ کریں۔

## 3. کلاؤڈ ایجنٹس

**OmniRoute اینڈ پوائنٹس:** `/api/v1/agents/tasks/*` (لائف سائیکل) + `/api/cloud/*` (بنیادی انتظام)
**ماخذ:** `src/lib/cloudAgent/`

### یہ کیا ہے

فریقِ ثالث کے کلاؤڈ کوڈنگ ایجنٹس کے لیے ایک یکساں انٹرفیس۔ آپ ایک پرامپٹ + ریپو URL جمع کراتے ہیں، OmniRoute اسے درست کلاؤڈ ایجنٹ کو بھیجتا ہے، اسٹیٹس پول کرتا ہے، اور نتائج واپس کرتا ہے۔

### معاونت یافتہ ایجنٹس (4، سبھی کی `src/lib/cloudAgent/agents/` میں تصدیق شدہ ہے)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### لائف سائیکل

```
POST /api/v1/agents/tasks
  → ہر ایجنٹ کلاس کے لیے BaseAgent.createTask()
  → بیرونی سروس کام شروع کرتی ہے
  → DB میں ٹاسک کی قطار بنائی جاتی ہے (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → فراہم کنندہ سے ضرورت کے وقت اسٹیٹس کی ہم وقت سازی
  → موجودہ اسٹیٹس + منصوبہ + سرگرمی لاگ واپس کرتا ہے
  ↓
POST /api/v1/agents/tasks/[id]   (ایکشن: "approve" | "message" | "cancel")
  → فراہم کنندہ کو فارورڈ کرتا ہے (یا مقامی طور پر منسوخ شدہ نشان زد کرتا ہے)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → مقامی منسوخی
```

### توثیق

⚠️ **تمام `/api/v1/agents/tasks/*` اینڈ پوائنٹس کے لیے انتظامی توثیق درکار ہے** (کمٹ `588a0333`)۔ v3.8.0 سے صرف بیئرر استعمال کرنے والے کالرز کو 401 موصول ہوتا ہے۔

### تفصیلی جائزہ

`CloudAgentBase` کنٹریکٹ، ہر ایجنٹ کی تفصیلات، اسکیما کی تفصیلات، اور اسناد کے بنیادی انتظام کے اینڈ پوائنٹس کے لیے [CLOUD_AGENT.md](./CLOUD_AGENT.md) دیکھیں۔

## موازنہ: A2A بمقابلہ Cloud Agents

دونوں میں "طویل عرصے تک چلنے والے کام" ہوتے ہیں، لیکن مختلف سطحوں پر:

| پہلو                | A2A                                                                                 | Cloud Agents                             |
| ------------------- | ----------------------------------------------------------------------------------- | ---------------------------------------- |
| معیار               | Open A2A v0.3                                                                       | OmniRoute کے لیے مخصوص                   |
| کمپیوٹ کہاں چلتا ہے | OmniRoute کے اندر (تشکیل شدہ کمبی نیشنز استعمال کرتا ہے)                            | بیرونی (Codex / Devin / Jules سرورز)     |
| کام کا دورانیہ      | ڈیفالٹ TTL 5 منٹ (`TaskManager` میں قابلِ تشکیل)                                    | منٹوں سے گھنٹوں تک                       |
| ریپو سے آگاہ        | نہیں (صرف پرامپٹس بھیجتا ہے)                                                        | ہاں (ریپو URL + برانچ)                   |
| استعمال کا معاملہ   | ایجنٹس کے درمیان تعاون، بطور سروس اسمارٹ روٹنگ                                      | "ریپو Y میں فیچر X نافذ کریں" تفویض کرنا |
| توثیق               | `/a2a` کے لیے اختیاری `OMNIROUTE_API_KEY`؛ `/api/a2a/*` REST معاونین کے لیے مینجمنٹ | ہمیشہ مینجمنٹ                            |

## انضمام کی مثالیں

### OmniRoute کی A2A صلاحیتیں دریافت کریں

```bash
curl http://localhost:20128/.well-known/agent.json
```

تمام 6 مہارتوں، ٹرانسپورٹس اور ورژن کے ساتھ Agent Card واپس کرتا ہے۔

### OmniRoute کو بطور A2A ایجنٹ کال کریں

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP کے ذریعے انسٹال شدہ CLI ایجنٹس کی فہرست حاصل کریں

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### ایک حسبِ ضرورت CLI ایجنٹ شامل کریں

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
```

### Cloud Agent کا کام جمع کروائیں

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### کلاؤڈ کام کی حالت پول کریں

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## کس موقع پر کیا استعمال کریں

- **چیٹ بوٹ / copilot فرنٹ اینڈ** → `/v1/chat/completions` (OpenAI سے ہم آہنگ — ایجنٹ پروٹوکول نہیں)
- **متعدد ایجنٹس کے درمیان تعاون** → A2A
- **ڈیش بورڈ میں مقامی CLIs کی فہرست دکھانا** → ACP
- **طویل عرصے تک چلنے والے کوڈنگ کے کام کلاؤڈ سروسز کو تفویض کرنا** → Cloud Agents
