# 🚀 OmniRoute — مفت AI گیٹ وے

<img src="./docs/diagrams/readme-hero.svg" width="100%" alt="OmniRoute — کوڈنگ کبھی نہ روکیں۔ ہر AI ٹول → 359 فراہم کنندگان — 150+ مفت — ایک ہی اینڈ پوائنٹ کے ذریعے۔ Claude Code، Codex، Cursor، Cline، Copilot اور Antigravity کو خودکار متبادل کے ساتھ مفت Claude / GPT / Gemini سے مربوط کریں۔ RTK + Caveman کی تہہ دار کمپریشن 15–95% ٹوکنز (~89% اوسط) بچاتی ہے — کبھی حدود سے نہ ٹکرائیں۔ 359 AI فراہم کنندگان · 150+ مفت درجے · ~1.62B مفت ٹوکنز/ماہ · 19 روٹنگ حکمتِ عملیاں · آغاز کے لیے $0۔"/>

## 💰 ~1.62B مفت ٹوکنز / ماہ

</div>

> مفت درجات کو دستی طور پر یکجا کرنا تکلیف دہ ہے — درجنوں SDKs، درجنوں شرح کی حدود، اور یہ جاننے کا کوئی طریقہ نہیں کہ حقیقتاً آپ کے پاس کتنا ہے۔ OmniRoute، **35 بار بار دستیاب پول کلیدوں میں مفت درجے کی 491 اندراجات** فہرست بند کرتا ہے اور ٹوکن کی نمایاں تعداد کا حساب **شائع شدہ مثبت ماہانہ بجٹ والے 17 پولز کے ساتھ Groq کی فی ماڈل پانچ حدود** سے لگاتا ہے، جبکہ مشترکہ پول کی بنیاد پر نقل ختم کی جاتی ہے۔ وہ کوٹے جو صرف علاقائی شناخت کی تصدیق کے بعد دستیاب ہوتے ہیں (فی الحال: ModelScope)، الگ دکھائے جاتے ہیں، علاقائی شناخت کی تصدیق کے پیچھے +~6M، اور انہیں کبھی بھی نمایاں مجموعے میں شامل نہیں کیا جاتا۔ نتیجہ ڈیش بورڈ (`/dashboard/free-tiers`) پر نظر آتا رہتا ہے۔

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute مفت درجے کا بجٹ کارڈ: مستقل طور پر ہر ماہ ~1.62B مفت ٹوکنز، سائن اپ کریڈٹس کے ساتھ پہلے مہینے میں زیادہ سے زیادہ ~2.22B، ایک اینڈ پوائنٹ کے پیچھے مفت درجے کی 491 فہرست بند اندراجات کا احاطہ کرنے والی 35 دستاویزی بار بار دستیاب پول کلیدوں سے۔ دیانت دارانہ، پول کی نقل ختم کرکے کیا گیا حساب — ہر مشترکہ پول صرف ایک بار شمار کیا گیا، جس میں شائع شدہ مثبت ماہانہ ٹوکن بجٹ والے 17 بار بار دستیاب پولز اور Groq کی فی ماڈل پانچ حدود شامل ہیں؛ شرائط کے خطرے کی فہرست میں 13 فراہم کنندگان کو اجتناب کے طور پر نشان زد کیا گیا ہے تاکہ فیصلہ آپ کر سکیں۔ بجٹ بار میں Mistral 1B، Nara 210M، LLM7 150M، xKiro 150M، Groq 30M (فی ماڈل پانچ حدود) اور چھوٹے پولز شامل ہیں، جبکہ پہلے مہینے کے سائن اپ کریڈٹس اور مستقل طور پر مفت، ٹوکن کی حد سے آزاد فراہم کنندگان الگ دکھائے جاتے ہیں تاکہ وہ کبھی بھی نمایاں مجموعے کو مصنوعی طور پر نہ بڑھائیں۔ /dashboard/free-tiers پر براہ راست استعمال شدہ/باقی مقدار۔"/>

> براہ راست `/dashboard/free-tiers` صفحے کا متحرک خلاصہ۔ مکمل طریقۂ کار (پول کی نقل کا خاتمہ، کریڈٹ کے درجات، فراہم کنندہ کی شرائط): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**۔
>
> <sub>ان اعداد و شمار کا براہ راست کیٹلاگ کے مقابل ہر دو ہفتے بعد دوبارہ آڈٹ کیا جاتا ہے اور یہ **دونوں سمتوں میں تبدیل ہوتے ہیں** — کوئی فراہم کنندہ مفت درجہ ختم کرے تو تعداد کم ہو جاتی ہے؛ کوئی نیا شامل ہو تو بڑھ جاتی ہے۔ ہم وہی شائع کرتے ہیں جس کا کیٹلاگ حقیقتاً حساب لگاتا ہے، کبھی بھی بہترین ممکنہ صورت کو اوپر کی طرف گول کرکے نہیں۔</sub>

## 📡 OmniRoute Radar

اوپر درج دستاویزی اور پول کی سطح پر نقل سے پاک کیٹلاگ سے مفت درجے کی بنیادی پیشکش بدستور **~1.62B ٹوکنز/ماہ** ہے۔ فراہم کنندگان کے عارضی سائن اَپ کریڈٹس پہلے مہینے کی حد کو علیحدہ طور پر بڑھا کر **~2.22B** تک لے جا سکتے ہیں۔ Radar ایک اختیاری، دستخط شدہ کیٹلاگ اوورلے ہے، جو ان لوگوں کے لیے ہے جو OmniRoute کی ریلیزز کے درمیانی عرصے میں مفت ماڈلز کی تازہ ترین دستیابی چاہتے ہیں؛ کمیونٹی کیٹلاگ اور تمام موجودہ مفت خصوصیات بدستور مفت رہیں گی۔

معاونین لائیو کیٹلاگ اور فراہم کنندگان کے اضافی مواقع حاصل کر سکتے ہیں۔ اس کی علیحدہ،
تبدیل ہونے والی بالائی حد فراہم کنندگان کی دستیابی کے لحاظ سے **زیادہ سے زیادہ تقریباً 3B ٹوکنز/ماہ** ہے۔
یہ بالائی حد ضمانت نہیں ہے: فراہم کنندگان کسی بھی وقت کوٹے، اہلیت، ماڈلز یا خطے تبدیل کر سکتے ہیں۔

Radar اختیاری ہے اور صرف GET استعمال کرتا ہے۔ OmniRoute کلائنٹ پرامپٹس، ٹریفک، فراہم کنندہ

```bash
omniroute run claude   --model openai/gpt-5.4          # Claude Code
omniroute run codex    --model glm/glm-5.2             # OpenAI Codex CLI
omniroute run aider    --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose    --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen     --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini   --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# یا فراہم کنندہ+ماڈل تعاملی طور پر منتخب کریں اور ٹول کی اپنی کنفیگ لکھیں:
omniroute configure codex          # یہ بھی: claude opencode qwen aider goose gemini cline continue kilo
```

ہر کمانڈ فعال ریموٹ سیاق (`omniroute connect <host>`) کی پابندی کرتی ہے، `--dry-run`
بغیر چلائے عین env/args کا پیش منظر دکھاتا ہے، اور `--api-key-env NAME` رازوں کو
آپ کی شیل ہسٹری سے باہر رکھتا ہے۔ → [CLI انضمامات](docs/guides/CLI-INTEGRATIONS.md)

## 🔌 مکمل CLI + A2A اور MCP

</div>

> سرور سے آگے بڑھ کر، OmniRoute ایک **مکمل کمانڈ لائن کاک پٹ** ہے جس میں **80+ کمانڈز** ہیں، نیز کھلے ایجنٹ پروٹوکولز بھی ہیں تاکہ کوئی AI ایجنٹ اسے **خود سے** چلا سکے۔

### ⌨️ ایک حقیقی CLI (صرف `start` نہیں)

```bash
omniroute               # گیٹ وے + ڈیش بورڈ پیش کریں (پورٹ 20128)
omniroute chat          # انٹرایکٹو TUI چیٹ کلائنٹ (سلیش: /model /combo /skill /memory)
omniroute setup         # پہلی بار چلانے کے لیے رہنمائی یافتہ وزرڈ
omniroute doctor        # فراہم کنندگان، پورٹس اور مقامی انحصارات کی تشخیص کریں
```

### 🛰️ ریموٹ موڈ — CLI یہاں چلائیں، OmniRoute کو VPS پر

OmniRoute کسی سرور پر ہے؟ اسے اپنے لیپ ٹاپ سے **اسی CLI** کے ذریعے چلائیں۔ محدود دائرۂ کار والے رسائی ٹوکن کے ساتھ ایک بار لاگ اِن کریں؛ اس کے بعد ہر کمانڈ ریموٹ کو ہدف بنائے گی۔

```bash
omniroute connect 192.168.0.15            # پاس ورڈ → محدود دائرۂ کار والا ٹوکن، بطور سیاق محفوظ
omniroute models list                     # ← ریموٹ سرور کے خلاف چلتا ہے
omniroute configure codex                 # ← ریموٹ ماڈل منتخب کرتا ہے، مقامی Codex پروفائل لکھتا ہے
omniroute tokens create --name ci --scope read   # دیگر مشینوں کے لیے مزید محدود ٹوکن بنائیں
omniroute contexts use default            # ← واپس مقامی سرور پر جائیں
```

ٹوکنز کے دائرۂ کار `read` / `write` / `admin` ہیں؛ پراسیس شروع کرنے والے روٹس صرف لوپ بیک تک محدود رہتے ہیں۔

### 🎚️ انجنز سے آگے — آؤٹ پٹ اسٹائلز، اڈاپٹیو ڈائل اور فی درخواست کنٹرول

اوپر موجود 12 انجنز اِن پٹ کو مختصر کرتے ہیں۔ مزید تین پرتیں یہ طے کرتی ہیں کہ آؤٹ پٹ **کیسے**، **کب** اور **کیا** نکلے گا:

- **🪄 آؤٹ پٹ اسٹائلز** _(آؤٹ پٹ محور کی رہنمائی)_ — جواب کی ساخت متعین کرنے والی قطعی اور کیش-محفوظ ہدایات شامل کریں؛ انہیں یکجا کیا جا سکتا ہے اور ہر ایک کی شدت `lite` / `full` / `ultra` ہو سکتی ہے۔ کوئی اسٹائل شامل کرنے کے لیے رجسٹری میں صرف ایک سطر درکار ہے:
  - **مختصر نثر** — غیر ضروری عبارت / آرٹیکلز / تذبذب نکال دیں؛ تکنیکی مواد بالکل درست رکھیں۔
  - **کم کوڈ** — "سست سینئر ڈویلپر" والا YAGNI: کم سے کم قابلِ عمل تبدیلی، بغیر مانگے کوئی اضافی ڈھانچہ نہیں۔
  - **پونی ٹیل (سست سینئر ڈویلپر)** — YAGNI کی سیڑھی چڑھیں، بنیادی وجہ درست کریں، کم سے کم قابلِ عمل diff۔
  - **مجھے ADHD ہے (عمل پہلے)** — اگلا عمل پہلے، مراحل نمبر وار، ایک واضح اگلا قدم، کوئی تمہید نہیں۔
  - **مختصر CJK (文言)** — کلاسیکی چینی کا انتہائی مختصر انداز (صرف `zh` لوکیل کے لیے)۔
- **🎯 اڈاپٹیو سیاقی بجٹ** _(ڈائل)_ — ٹوکنز کی صرف ایک آن/آف حد کے بجائے، کم ترین لاگت اور کم ترین معلوماتی نقصان والے انجنز کو صرف اتنا بڑھائیں جتنا **ماڈل کی کانٹیکسٹ ونڈو میں فٹ ہونے** کے لیے ضروری ہو۔ پالیسی: `reserve-output` (ڈیفالٹ، ماڈل سے آگاہ) · `percentage` · `absolute`۔ موڈ: `floor` (فٹ ہونے کی ضمانت) · `replace-autotrigger` (آپ کا واضح انتخاب مقدم) · `off` (روایتی حد)۔
- **🎛️ کمپریشن کا فیصلہ کہاں ہوتا ہے** _(ترجیح، زیادہ → کم)_ — فی درخواست `x-omniroute-compression` ہیڈر › راؤٹنگ-کومبو اووررائیڈ › فعال نام زد پروفائل › اڈاپٹیو / آٹو ٹریگر › پینل ڈیفالٹ › آف۔ لاگو شدہ منصوبہ `X-OmniRoute-Compression: <mode>; source=<source>` رسپانس ہیڈر میں واپس دکھائی دیتا ہے۔

ٹوکن حد کے ذریعے آٹو ٹریگر کریں، اڈاپٹیو ڈائل آن کریں، کوئی نام زد پروفائل مقرر کریں، فی درخواست ایک وقتی ترتیب لگائیں، یا ہر راؤٹنگ کومبو کے لیے پائپ لائن مختص کریں — جو بھی کام کے بوجھ کے مطابق ہو۔ اختیاری آف لائن **جائزہ فریم ورک** (`npm run eval:compression`) کسی تبدیلی کو نافذ کرنے سے پہلے ایک مقررہ کارپس پر معلوماتی وفاداری بمقابلہ بچت کی درجہ بندی کرتا ہے۔


```bash
curl http://localhost:20128/v1/models -H "Authorization: Bearer YOUR_KEY"
```

```txt
Ollama tags:      http://localhost:20128/vscode/YOUR_KEY/api/tags
```

انہیں صرف ان کلائنٹس کے لیے استعمال کریں جو `Authorization: Bearer ...` منسلک نہیں کر سکتے۔ ہیڈر کے ذریعے تصدیق بدستور ترجیحی طریقہ ہے۔

## 📦 تنصیب کے مزید طریقے — Docker، سورس، pnpm، Arch

**🐳 Docker**

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

`:latest` سب سے اعلیٰ **شائع شدہ** مستحکم SemVer کی پیروی کرتا ہے۔ یہ git `main` کو ٹریک نہیں کرتا۔ GitOps کے لیے `:X.Y.Z` مقرر کریں۔ [Docker ریلیز چینلز](docs/guides/DOCKER_GUIDE.md#release-channels) دیکھیں۔ امیج میں **`OMNIROUTE_MEMORY_MB=1024`** مقرر ہے۔ یہ ڈیش بورڈ اور ہلکی چیٹ کے لیے کافی ہے۔ **کوڈنگ ایجنٹس** (Claude Code، Codex، Grok، … سے `POST /v1/responses`) کو کہیں زیادہ بڑا V8 heap درکار ہوتا ہے، ورنہ دو باہم متجاوز طویل contexts کے دوران تقریباً 12 GiB پر پراسیس `FATAL ERROR` دیتا ہے۔ کنٹینر کا سائز heap سے زیادہ رکھیں (native buffers، V8 سے باہر موجود ہوتے ہیں):

| کام کا بوجھ                     | Heap (`-e OMNIROUTE_MEMORY_MB`) | کنٹینر (`--memory`) |
| ------------------------------- | ------------------------------- | ------------------- |
| ڈیش بورڈ / ہلکی چیٹ             | `1024` (امیج کا ڈیفالٹ)         | ≥2 g                |
| ایک کوڈنگ ایجنٹ                 | `8192`                          | ≥10 g               |
| بیک وقت دو طویل `/v1/responses` | `10240`–`12288`                 | ≥12–16 g            |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

مکمل جدول: [Docker گائیڈ — رن ٹائم RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents)۔

> `diegosouzapw/omniroute:next-web` موجودہ ڈیفالٹ `release/v*`
> برانچ کی پیروی کرتے ہیں۔ یہ قابلِ تغیر tags صرف غیر جاری شدہ اصلاحات کی جانچ کے لیے ہیں اور
> **پروڈکشن کے لیے معاونت یافتہ نہیں ہیں**۔ دیکھیں

**🥟 Bun**

Bun رن ٹائم کی شناخت کے ذریعے معیاری `bun install` اور عالمی تنصیب (`bun install -g omniroute`) معاونت یافتہ ہیں:

- **بلٹ اِن `bun:sqlite`**: Bun کے تحت چلتے وقت OmniRoute، Bun کا بلٹ اِن `bun:sqlite` ڈرائیور استعمال کرتا ہے، جبکہ Node.js پر `better-sqlite3` یا `sql.js` استعمال کرتا ہے۔
- **ڈویلپمنٹ میں خودکار Webpack bundler انتخاب**: ڈویلپمنٹ (`bun run dev`) خودکار طور پر Bun کی شناخت کرتی ہے اور native V8 binding کی عدم مطابقت روکنے کے لیے Turbopack کو غیر فعال کرکے Webpack استعمال کرتی ہے۔ پروڈکشن builds (`bun run build`) عین Node کی طرح `OMNIROUTE_USE_TURBOPACK` کی پیروی کرتی ہیں: ڈیفالٹ طور پر Turbopack، اور Webpack کے ساتھ build کرنے کے لیے `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` اسے `--build-arg` کے طور پر فراہم کرتا ہے)۔
- **Bun کے لیے مخصوص Dockerfile**: مقامی Bun پروڈکشن deployments کے لیے multi-stage `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`)۔

```bash

bun install
bun run dev
```

**⚡ تیز تر / ہلکی تنصیب (native build کو چھوڑ دیں)**

native SQLite انجن (`better-sqlite3`) ایک **اختیاری** dependency ہے، اس لیے عالمی
تنصیب کبھی بھی سورس سے compilation پر نہیں رکتی: جب کوئی prebuilt binary آپ کے
پلیٹ فارم/Node سے مطابقت رکھتی ہو تو اسے استعمال کیا جاتا ہے، بصورتِ دیگر شفاف انداز میں pure-JS انجن
(Node 22+ پر `node:sqlite`، ورنہ شامل کردہ `sql.js` WASM) استعمال کیا جاتا ہے — کسی build tool کی ضرورت نہیں۔

تنصیب کے بعد کی native warm-up کارروائی کو مکمل طور پر چھوڑنے کے لیے (CI، headless، یا سست مشینیں):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 بھی اسے چھوڑ دیتا ہے
```

تیز ترین تنصیبات کے لیے **pnpm** کو ترجیح دیں (content-addressed store + hard links — اوپر دیکھیں)۔
ڈیش بورڈ کے بغیر headless رن ٹائم کے لیے Docker کا `base` profile (اوپر) یا
[Termux گائیڈ](docs/guides/TERMUX_GUIDE.md) استعمال کریں۔ CLI اور ویب ڈیش بورڈ ایک ہی پراسیس کے ذریعے ایک
پورٹ پر پیش کیے جاتے ہیں، اس لیے فی الحال کوئی الگ صرف-CLI package موجود نہیں ہے۔

### تعاون کیسے کریں

1. ریپوزٹری کو فورک کریں
2. **فعال** `release/vX.Y.Z` کے آخری سرے سے برانچ بنائیں (`main` سے نہیں) — [برانچنگ اور ریلیز ماڈل](docs/ops/BRANCHING_MODEL.md) دیکھیں
3. اپنی فیچر برانچ بنائیں (`git checkout -b feat/amazing-feature`)
4. اپنی تبدیلیاں کمٹ کریں (`git commit -m 'feat: add amazing feature'`)
5. برانچ پر پش کریں (`git push origin feat/amazing-feature`)
6. **base = وہی `release/vX.Y.Z` برانچ** رکھتے ہوئے ایک پل ریکویسٹ کھولیں

تفصیلی رہنما اصولوں کے لیے [CONTRIBUTING.md](CONTRIBUTING.md) دیکھیں۔

### نیا ورژن جاری کرنا

```bash
# ایک ریلیز بنائیں — npm publish خودکار طور پر انجام پاتا ہے
VERSION=x.y.z
gh release create "v${VERSION}" --title "v${VERSION}" --generate-notes
```
