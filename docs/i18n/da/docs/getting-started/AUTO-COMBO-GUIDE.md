## Hvad det gør

I stedet for at vælge en bestemt AI-model (som GPT-4o eller Claude) kan du lade OmniRoute **vælge den bedste automatisk** til hver anmodning. Det tager højde for:

- **Driftstilstand** — Fungerer udbyderen lige nu?
- **Hastighed** — Hvor hurtig er den?
- **Pris** — Hvor meget koster den?
- **Kvalitet** — Er den god til denne type opgave?
- **Kapacitet** — Har den resterende kvote?

OmniRoute bedømmer alle dine tilsluttede udbydere og vælger den bedste. Hvis den fejler, prøver det automatisk den næste.

---

## Hurtig start

**Trin 1**: Indstil din model til `auto` i din IDE eller CLI:

```
model: "auto"
```

**Trin 2**: Det var det! OmniRoute håndterer resten.

**Trin 3** (valgfrit): Brug en variant til specifikke opgaver:

```
model: "auto/coding"    # Bedst til kode
model: "auto/fast"      # Hurtigste svar
model: "auto/cheap"     # Billigste mulighed
```

## Hvilken "auto" skal jeg bruge?

| Hvis du ønsker...    | Brug denne     | Bedst til                      | Sådan fungerer det                           |
| -------------------- | -------------- | ------------------------------ | -------------------------------------------- |
| **Bedst samlet set** | `auto`         | Generelle spørgsmål, chat      | Afbalancerer hastighed, pris og kvalitet     |
| **Bedst til kode**   | `auto/coding`  | Skrivning af kode, fejlfinding | Vælger modeller, der er gode til kodeopgaver |
| **Hurtigste svar**   | `auto/fast`    | Hurtige svar, lav latenstid    | Prioriterer hastighed over alt andet         |
| **Billigste valg**   | `auto/cheap`   | At spare penge                 | Vælger den billigste udbyder                 |
| **Smarteste model**  | `auto/smart`   | Komplekse opgaver              | Kvalitet først + afprøver nye modeller       |
| **Mest tilgængelig** | `auto/offline` | Når udbyderne har travlt       | Vælger udbydere med mest kapacitet           |

### Eksempler

```bash
# Generel chat — afbalanceret
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Kodegenerering — kvalitet først
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Hurtigt svar — hastighed først
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Sådan fungerer det (forenklet version)

Når du sender en anmodning med `model: "auto"`, gør OmniRoute følgende:

1. **Gennemgår alle dine tilsluttede udbydere** — Alle de udbydere, du har tilføjet (OpenAI, Anthropic, Google osv.)
2. **Bedømmer hver enkelt** ud fra blandt andet:
   - Fungerer den? (driftstilstand)
   - Har den kapacitet? (kvote)
   - Hvor meget koster den? (pris)
   - Hvor hurtig er den? (hastighed)
   - Er den god til denne opgave? (kvalitet)
3. **Vælger den bedste** — Udbyderen med den højeste score får din anmodning
4. **Genopretter automatisk** — Hvis den fejler, prøver OmniRoute automatisk den næste

### Bedømmelsessystemet

Hver udbyder får en score fra 0 til 1. Jo højere scoren er, desto bedre passer udbyderen.

| Faktor         | Vægt | Hvad det betyder                                      |
| -------------- | ---- | ----------------------------------------------------- |
| Driftstilstand | 20%  | Fungerer udbyderen? (circuit breaker-tilstand)        |
| Kvote          | 15%  | Har den resterende kapacitet?                         |
| Pris           | 15%  | Hvor dyr er den? (billigere = højere score)           |
| Hastighed      | 12%  | Hvor hurtig er den? (lavere latenstid = højere score) |
| Opgavematch    | 8%   | Er den god til denne type opgave?                     |
| Stabilitet     | 5%   | Er den stabil? (lav fejlrate)                         |
| Niveau         | 5%   | Kontoniveau (Ultra > Pro > Free)                      |
| Andet          | 20%  | Konteksttilknytning, forbindelsestæthed osv.          |

### Sådan ændrer varianterne bedømmelsen

Hver variant bruger forskellige vægte:

| Variant        | Prioriterer            | Vigtigste vægte                 |
| -------------- | ---------------------- | ------------------------------- |
| `auto`         | Balance                | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kvalitet               | taskFit=37%, stability=15%      |
| `auto/fast`    | Hastighed              | latency=32%, health=28%         |
| `auto/cheap`   | Pris                   | cost=37%                        |
| `auto/smart`   | Kvalitet + udforskning | taskFit=37%, exploration=10%    |
| `auto/offline` | Kapacitet              | quota=37%, health=28%           |

## Sådan håndterer den fejl

OmniRoute har **tre beskyttelseslag**:

### 1. Automatisk fallback

Hvis den bedste udbyder svigter, prøver OmniRoute automatisk den næste. Du behøver ikke gøre noget.

### 2. Selvhelbredelse

Hvis en udbyder bliver ved med at svigte:

- **Score < 0.2** → Udelukkes i 5 minutter
- **Circuit breaker åben** → Udelukkes automatisk
- **Mere end 50 % af udbyderne er nede** → Hændelsestilstand (ingen udforskning)

### 3. Nødfallback

Hvis alle udbydere svigter, sender OmniRoute som en sidste udvej anmodninger til stabile gratis udbydere (som Kiro eller Qoder).

---

## Understøttelse af flere konti

Hvis du har flere konti hos den samme udbyder (f.eks. to OpenAI-nøgler), behandler OmniRoute hver konto som en **separat kandidat**. Det betyder:

- Konto A har resterende kvote → brug den
- Konto B er hastighedsbegrænset → spring den over
- Konto C er billigere → foretræk den

Hver konto bedømmes uafhængigt ud fra sin egen driftstilstand, kvote og hastighed.

---

## Bandit-udforskning

OmniRoute **udforsker** lejlighedsvis nye udbydere for at finde bedre muligheder:

- **Standard**: 5 % af anmodningerne sendes til tilfældige udbydere
- **Auto/smart**: Udforskningsgrad på 10 %
- **Deaktiveret**, når mere end 50 % af udbyderne ikke fungerer korrekt

Dette hjælper OmniRoute med at lære, hvilke udbydere der fungerer bedst til dine brugsmønstre.

## Ofte stillede spørgsmål

### "Vælger den altid den dyreste model?"

**Nej.** Omkostninger udgør som standard kun 15 % af scoren. En billig, hurtig og velfungerende udbyder kan slå en dyr udbyder. Brug `auto/cheap`, hvis du vil prioritere omkostninger endnu højere.

### "Hvad sker der, hvis en udbyder går ned?"

OmniRoute springer automatisk udbyderen over og prøver den næste. Hvis en udbyder bliver ved med at svigte, udelukkes den midlertidigt (5-30 minutter). Du behøver ikke gøre noget.

### "Kan jeg se, hvilken udbyder der blev brugt?"

Kontrollér svarheaderne — OmniRoute inkluderer den anvendte udbyder og model i hvert svar.

### "Lærer den af min brug?"

Ja! Scoresystemet bruger historiske data (latens, fejlrater og succesrater) til at træffe bedre beslutninger over tid.

### "Hvad er forskellen på `auto` og `auto/smart`?"

- `auto` — Afbalanceret, 5 % udforskning
- `auto/smart` — Kvalitet først (samme vægtning som `auto/coding`), 10 % udforskning

Brug `auto/smart`, når du ønsker den bedste kvalitet og accepterer lejlighedsvis udforskning.

### "Kan jeg gennemtvinge en bestemt udbyder?"

Ja! Brug en kombination med `priority`-strategien i stedet for `auto`, og send derefter kombinationens **præcise navn** som feltet `model` (f.eks. `model: "my-combo"` — ikke `auto`). Se [Teknisk reference](../routing/AUTO-COMBO.md) for flere oplysninger.

### "Hvordan adskiller dette sig fra round-robin?"

Round-robin gennemgår udbyderne i rækkefølge. Auto-combo **giver hver udbyder en score** og vælger den bedste. Det er smartere — det tager højde for driftstilstand, hastighed, omkostninger og kvalitet.
