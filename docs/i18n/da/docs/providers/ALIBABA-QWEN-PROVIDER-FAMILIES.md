Dette dokument beskriver implementeringsbeslutningen for
[Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). De offentlige produkter er
repræsenteret som fire udbyderfamilier. Regionen er forbindelsesdata, ikke et separat produkt.

## Beslutning

| Udbyderfamilie                               | OmniRoute-ID            | Global region | Kina-region |
| -------------------------------------------- | ----------------------- | ------------- | ----------- |
| Alibaba Cloud Model Studio (forbrugsbaseret) | `alibaba`               | Singapore     | Beijing     |
| Alibaba Cloud Token Plan                     | `bailian-coding-plan`   | Singapore     | Beijing     |
| Qwen Cloud (forbrugsbaseret)                 | `qwen-cloud`            | Global        | Beijing     |
| Qwen Cloud Token Plan                        | `qwen-cloud-token-plan` | Singapore     | Beijing     |

Det eksisterende `alibaba-cn`-ID forbliver et kompatibilitetsalias under kørsel for gemte forbindelser, modelruter,
kombinationer og historisk forbrug. Dets dashboardkort indgår i `alibaba`; der kræves ingen
omskrivning af databasen.

Qwen Clouds forbrugsbaserede produkt og Alibaba Cloud Model Studio deler i øjeblikket de DashScope-kompatible
runtime-værter, men de forbliver separate udbyderidentiteter, fordi brugerne henter nøgler og administrerer
konti via forskellige produktgrænseflader. Produkterne Alibaba og Qwen Cloud Token Plan bruger
forskellige endpointfamilier, så alle fire produkter forbliver separate udbyder-ID'er.

## Endpointmatrix

| Udbyderfamilie          | `global-sg`                                                              | `china-beijing`                                                      | Dataformat |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ---------- |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI     |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic  |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI     |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI     |

API-nøglen og endpointet skal tilhøre det samme produkt og den samme region. Når en region vælges,
ændres det forudindstillede endpoint, som bruges til validering og normale anmodninger.

## Forbindelseskontrakt

Nye forbindelser gemmer den stabile regionsnøgle i `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

De tilladte værdier er `global-sg` og `china-beijing`. Endpointet udledes centralt fra
udbyder-ID'et og regionen. En ikke-forudindstillet `providerSpecificData.baseUrl` forbliver en eksplicit
operatørtilsidesættelse og har forrang, mens gamle gemte forudindstillede URL'er normaliseres tilbage til den regionale
matrix.

Dette gør forbindelsesskemaet udvideligt: Endnu en region kan føjes til resolveren uden
at oprette endnu et udbyderkort eller ændre gemte udbyder-ID'er.

## Kompatibilitet og udrulning

1. Tilføj den regionale endpoint-resolver, og bevar de nuværende globale standardindstillinger.
2. Brug live regional DashScope `/models`-registrering for `alibaba`, dets kompatibilitets-id
   `alibaba-cn` og `qwen-cloud`. Deres svar gennemgår først et filter for tekstgenerering, fordi det
   generiske endpoint også returnerer modeller til billeder, video, lyd, embeddings og andre
   modeller, der ikke er chatmodeller. `qwen-cloud` anvender derefter den vedligeholdte allowliste,
   der er deklareret i dets udbyderregister. Alibaba Model Studio og Qwen Cloud beholder separate
   kuraterede kataloger, selvom de i øjeblikket deler runtime-værter.
3. Registrer `qwen-cloud-token-plan` med den aktuelle allowliste for tekstmodeller i Token Plan.
4. Tilføj en typesikret regionsvælger til dialogerne til tilføjelse og redigering af forbindelser.
5. Skjul det duplikerede `alibaba-cn`-kort, og medtag dets eksisterende forbindelser på
   `alibaba`-udbydersiden.
6. Bevar muligheden for tilpassede endpoint-tilsidesættelser til avancerede og
   arbejdsområdespecifikke implementeringer.

Token Plan-mediemodeller forbliver uden for chatkataloget, fordi de bruger dedikerede endpoints.
`wan2.7-image` og `wan2.7-image-pro` er registreret i `open-sse/config/imageRegistry.ts`;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` og `happyhorse-1.1-r2v` er registreret i
`open-sse/config/videoRegistry.ts`. Begge registre genbruger forbindelsesidentiteten
`qwen-cloud-token-plan` og dens regionsspecifikke legitimationsoplysninger.

Den almindelige Qwen Cloud har separate billed- og videokataloger med forbrugsafregning under
identiteten `qwen-cloud`. Dens billedmodeller er `wan2.7-image-pro`, `wan2.7-image`,
`qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` og
`z-image-turbo`. Dens videomodeller er `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`,
`happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`,
`wan2.7-r2v-2026-06-12` og `wan2.7-videoedit`. Disse modeller genbruger kun den almindelige
`qwen-cloud`-forbindelse og det regionale DashScope-medieendpoint. Registrene for Token Plan og
forbrugsafregning arver eller sammenfletter ikke hinandens modellister.

Identiteten `bailian-coding-plan` har også sine egne medie-allowlister:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` og `qwen-image-2.0-pro` til
billedgenerering samt
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` og `happyhorse-1.1-r2v` til
videogenerering. Den bruger kun Bailian Coding Plan-forbindelsen og det regionale Coding Plan-endpoint.
Dens billed- og videoregistre arver ikke fra eller sammenflettes med nogen af Qwen Cloud-udbyderne.

Den almindelige `alibaba`-identitet har separate allowlister for billeder og video. Dens
billedmodeller er `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` og `wan2.6-t2i`. Dens tilføjede videomodeller er `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` og `wan2.7-videoedit`. Disse modeller bruger kun Alibaba Model Studio-
forbindelsen og dens valgte regionale medieendpoint. De føjes ikke til noget Coding Plan- eller
Qwen Cloud-register.

Chatkataloget for Qwen Cloud Token Plan følger Individual-planens allowliste med eksakt
strengmatchning for tekstmodeller:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` og
`deepseek-v4-pro`. Wan- og HappyHorse-poster hører til de separate API'er til billed- og
videogenerering.

Alibaba Token Plan eksponerer de samme seks aktuelle model-id'er til tekstgenerering gennem sit
Anthropic-kompatible endpoint. Singapore-indstillingen gemmer den eksisterende regionsnøgle
`global-sg`; kun den brugervendte etiket adskiller sig fra udbyderfamilier, der kalder regionen
Global.

Det almindelige Qwen Cloud-chatkatalog er bevidst smallere end det fulde live-tekstsvar. Dets
vedligeholdte allowliste findes i `open-sse/config/providers/registry/qwen-cloud/index.ts`;
live-registrering returnerer kun id'er, der findes både i upstream-svaret og på denne registerliste.

Alibaba Model Studio følger den samme regel om live-krydsning med sin uafhængigt vedligeholdte
allowliste i `open-sse/config/providers/registry/alibaba/index.ts`. Kompatibilitetsudbyderen
`alibaba-cn` genbruger dette katalog, mens registreringen udføres mod Beijing-endpointet.
