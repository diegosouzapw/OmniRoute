**OmniCopilot** placerer alle modeller, som din OmniRoute leverer, i den _indbyggede_ modelvælger i GitHub Copilot Chat. Ingen ekstra sidebjælke, ingen separat chatgrænseflade — Copilots agenttilstand, værktøjskald, MCP-servere og brugerdefinerede instruktioner fungerer fortsat, blot med den model, du vælger.

|                         |                                                                                                                                                 |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Installer (VS Code)** | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Installer (forks)**   | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Kildekode/problemer** | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Kræver**              | VS Code 1.104+                                                                                                                                  |

> **Der kræves intet Copilot-abonnement.** Siden VS Code 1.122 har en sprogmodeludbyder kunnet fungere
> uden GitHub-login og uden nogen Copilot-plan. Integrerede fuldførelser og
> embeddings-baserede funktioner ligger uden for udbyder-API'en og kræver stadig Copilot.

## Opsætning

1. **Kør OmniRoute** — `npm install -g omniroute && omniroute` (dashboard på `http://localhost:20128`).
2. **Installer udvidelsen** — søg efter "OmniRoute" i visningen Udvidelser.
3. **Vælg en model** — Copilot Chat → modelvælger → **Administrer modeller…** → **OmniRoute**, og markér derefter
   dem, du ønsker.

Der er intet at konfigurere, når OmniRoute kører på standardporten. For en fjerninstans skal du åbne
**OmniRoute-ikonet på aktivitetslinjen** (eller køre `OmniRoute: Manage Connection`) og angive:

- **Server-URL** — serverens rodadresse, f.eks. `http://192.168.0.15:20128`. Suffikset `/v1`
  tilføjes af udvidelsen; medtag det ikke.
- **API-nøgle** — kun når serveren angiver `REQUIRE_API_KEY`. Gemmes i operativsystemets nøglering via VS
  Code SecretStorage, aldrig i `settings.json`.

## Hvad modelvælgeren viser

Udvidelsen viser ikke den rå `GET /v1/models`-nyttelast — den bearbejder den, og antallet, du
ser, er lavere end katalogets størrelse af to tilsigtede årsager.

### Den anmoder om ét id pr. model

`MODELS_CATALOG_PREFIX_MODE` har som standard værdien **`dual`**, hvilket annoncerer hver model to gange — én gang
med det korte aliaspræfiks og én gang med det kanoniske udbyderpræfiks — så ældre klientkonfigurationer
fortsat kan slå begge former op:

```
cc/claude-sonnet-4-6        ← aliaspræfiks
claude/claude-sonnet-4-6    ← kanonisk præfiks, samme model
```

Udvidelsen anmoder om **`GET /v1/models?prefix=alias`**, så der modtages ét id pr. model uden
at ændre indstillingen for hele serveren for dine andre klienter. På en referenceinstans reducerede dette
**2345 poster til 1396 — 949 dubletter, nul mistede modeller.**

Hvis du hellere vil rette det på hele serveren for _alle_ klienter, skal du indstille funktionsflaget
`MODELS_CATALOG_PREFIX_MODE` til `alias` i dashboardet. Se
[API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix) for
forespørgselsparameteren og tabellen for hver tilstand.

### Den skjuler modeller, som ikke kan chatte

Kataloget indeholder også modeller til billeder, video, lyd, rerangering, embeddings og moderering. De bliver
alligevel afvist ved en chatanmodning:

```
HTTP 400 — Modellen '<id>' er en billedgenereringsmodel og kan ikke bruges på
/v1/chat/completions. Brug POST /v1/images/generations i stedet.
```

Derfor filtreres de fra via deres `type`-felt, før de når modelvælgeren. **Responses-API-
modeller bevares** — hver Codex-/GPT-5.x-post annoncerer `supported_endpoints: ["responses"]`,
og OmniRoute oversætter dem til `/v1/chat/completions`, så de kan bruges uden problemer.

### Udbydere, du aldrig har konfigureret

Kataloget viser modeller fra udbydere med en **aktiv forbindelse** _samt_ alle **noAuth**-
udbydere — de nøglefri udbydere, der udgør en stor del af det gratis niveau. Det er tilsigtet. Hvis du vil skjule
dem, skal du føje dem til `blockedProviders` i dashboardets indstillinger; intet ændres i
udvidelsen.

## Dashboard i en VS Code-fane

`omnicopilot.dashboardOpen: "editor"` viser OmniRoute-dashboardet i en editorfane via
Simple Browser i stedet for en ekstern browser. Indlejring er **frivillig på serveren** via
`DASHBOARD_ALLOW_EMBED=vscode`, som leverer HTML-siderne med
`frame-ancestors 'self' vscode-webview:` i stedet for standardindstillingen `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. API-overfladen (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) beholder de
strenge headere uanset hvad.

> ⚠️ **Det er et flag ved byggetid, ikke ved kørselstid.** Next.js kompilerer `headers()` ind i route-
> manifestet, så `next.config.mjs` læser variablen, mens pakken bygges
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Det ændrer intet at eksportere den foran en allerede bygget server — headerne er indbygget.

```bash
# variablen skal være til stede i BUILD-kommandoen
DASHBOARD_ALLOW_EMBED=vscode npm run build        # eller npm run build:release
npm start
```

| Sådan installerede du      | Kan du aktivere indlejring?                                                                                                                          |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fra kildekoden             | ✅ angiv variablen i buildkommandoen som ovenfor                                                                                                     |
| `npm install -g omniroute` | ❌ den udgivne pakke leveres med en færdigbygget pakke — byg i stedet fra kildekoden                                                                 |
| Docker-image               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — det færdigbyggede image på Docker Hub understøtter ikke indlejring |

Uden et build, hvor indlejring er aktiveret, afviser siden at blive vist i en frame. Udvidelsen registrerer dette ud fra
svarheaderne og falder tilbage til den eksterne browser — intet går i stykker, og den oplyser om det én gang.
Se [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) og issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfiguration af dine andre værktøjer fra VS Code

**`OmniRoute: Configure Coding CLI`** bruger `omniroute`-CLI'en til at skrive brugsklare profiler
til Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo og Roo — de samme konfigurationer, som er beskrevet i
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). API-nøglen overføres til CLI'en via
miljøvariablen `OMNIROUTE_API_KEY`, aldrig på kommandolinjen.

## Fejlfinding

| Symptom                                               | Årsag/løsning                                                                                                                                                                                                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ingen OmniRoute-modeller i vælgeren                   | Serveren kan ikke nås. Prikken på statuslinjen bliver grå; kør `OmniRoute: Check Connection`. Registrering foregår lydløst efter hensigten og tilføjer ingen modeller i stedet for at vise en prompt.                                                                     |
| Hver model vises to gange                             | Du bruger en version af OmniCopilot, der er ældre end 1.0.1 — opdater. Udvidelsen anmoder nu med `?prefix=alias`.                                                                                                                                                         |
| En billed-/lydmodel blev tidligere vist, men er væk   | Dette er tilsigtet siden 1.0.1 — den kunne aldrig besvare en chatanmodning.                                                                                                                                                                                               |
| Panelet mangler på aktivitetslinjen                   | VS Code flytter ekstra visningscontainere til overløbsmenuen **"…"** nederst på aktivitetslinjen, og en container, der er skjult via højreklik, forbliver skjult. Højreklik på aktivitetslinjen → markér **OmniRoute**, eller åbn den med `OmniRoute: Manage Connection`. |
| Dashboardet åbnes i browseren trods `editor`-tilstand | Serveren blev ikke **bygget** med `DASHBOARD_ALLOW_EMBED=vscode` (se ovenfor) — det ændrer intet at angive den ved opstart af en færdigbygget installation. Tilbagefaldet er tilsigtet.                                                                                   |
| Modellisten er forældet efter ændring af udbydere     | `OmniRoute: Refresh Models` eller linket ↻ i panelet.                                                                                                                                                                                                                     |
