## 1. Antigravity kontra Antigravity CLI (agy)

Begge udbydere bruger den **samme Google-backend** — identisk OAuth-klient, tokenfornyelse, endpoints og Google-konti. Forskellen er, hvilke modeller du kan se.

> Se [annonceringen af Antigravity CLI](https://antigravity.google/blog/introducing-google-antigravity-cli) for Googles officielle sammenligning.

| Aspekt                 | `antigravity` (IDE)                              | `agy` (CLI)                                            |
| ---------------------- | ------------------------------------------------ | ------------------------------------------------------ |
| **Google-produkt**     | Antigravity 2.0 / Antigravity IDE                | Antigravity CLI                                        |
| **Backend**            | Samme Google Cloud Code API                      | Samme Google Cloud Code API                            |
| **OAuth / Token**      | Samme klient, samme fornyelse                    | Samme klient, samme fornyelse                          |
| **Modelkatalog**       | Statisk, kurateret liste (hardkodet i OmniRoute) | Hentes dynamisk fra Google via `:fetchAvailableModels` |
| **Claude-modeller**    | Sonnet 4.6, Opus 4.6 (4 varianter af hver)       | Sonnet 4.6, Opus 4.6 (4 varianter af hver)             |
| **Gemini-navngivning** | Tydelige etiketter (Low/Medium/High)             | Upstream-id'er (extra-low/low/agent)                   |
| **Ekstra modeller**    | `gpt-oss-120b-medium`                            | Kan omfatte yderligere modeller fra Google             |
| **Standardanvendelse** | IDE-integration (VS Code, JetBrains)             | CLI-/API-adgang                                        |
| **Kvote**              | Delt med agy (samme Google-konto)                | Delt med antigravity (samme Google-konto)              |

**Tilgængelige modeller (bekræftet via eksperiment, 2026-07-29)**:

- Gemini: 3.6 Flash, 3.5 Flash, 3.1 Pro, 3 Flash, 2.5 Flash (forskellige ræsonneringsniveauer)
- Claude: Sonnet 4.6, Opus 4.6 (hver med varianterne default/low/medium/high)
- Andre: GPT-OSS 120B Medium
- **Claude Sonnet 5 er IKKE tilgængelig** — kun 4.6-varianter understøttes

**Hvorfor modelkataloget er forskelligt**: Googles CLI er "optimeret til hastighed og lavt overhead" og "samoptimeret med Gemini-modeller" (ifølge Googles officielle blog). Web-/IDE-produktet er "optimeret med henblik på alsidighed." CLI'en bruger `:fetchAvailableModels` til dynamisk at finde modeller, mens IDE'en bruger en statisk, kurateret liste.

**I praksis**: Brug præfikset `agy/` til Gemini-modeller (f.eks. `agy/gemini-3.7-flash-high`). Brug `antigravity/` til den statiske, kuraterede liste. Begge bruger den samme Google-backend, men tilbyder forskellig modelnavngivning. Kvoten er delt — brug af en af udbyderne tæller med i den samme Google-kontos grænser.

## 2. Google One AI Pro: Kvotesystem

> Se [Antigravity-dokumentation: Abonnementer](https://antigravity.google/docs/plans) for officielle oplysninger om kvoter og [Ændringer af Antigravity-abonnementer](https://antigravity.google/blog/changes-to-antigravity-plans) for de seneste prisopdateringer.

Google Antigravity bruger en **kvote i to lag**, der er baseret på "Udført arbejde" (beregningsmæssig vægt), ikke antallet af beskeder.

### De to lag

| Lag                 | Hvad det er                          | Opdateringscyklus                                                                     |
| ------------------- | ------------------------------------ | ------------------------------------------------------------------------------------- |
| **5-timers sprint** | Umiddelbar pulje af "udført arbejde" | Nulstilles 5 timer efter den første anmodning i en session                            |
| **7-dages basis**   | Fast ugentlig grænse                 | Tilsidesætter 5-timers opdateringen, hvis den nås; låser indtil næste 7-dages periode |

**Sådan beregnes "Udført arbejde"**: Agenttunge opgaver (f.eks. "Refaktorer hele dette repository") bruger kvoten meget hurtigere end simple opgaver (f.eks. "Ret denne funktion"). Der findes ikke noget dashboard, der viser forbruget i realtid.

### Abonnementsniveauer

| Abonnement   | Pris        | Kvote                                  | Ugentlig grænse                                        |
| ------------ | ----------- | -------------------------------------- | ------------------------------------------------------ |
| Gratis       | $0          | Betydelig kvote, opdateres ugentligt   | Ja                                                     |
| AI Pro       | $19.99/md.  | Høj kvote, løbende 5-timers opdatering | Ja (tilsidesætter 5-timers opdateringen, hvis den nås) |
| AI Ultra 5x  | $99.99/md.  | 5x Pro-kvote                           | Ingen ugentlig grænse                                  |
| AI Ultra 20x | $199.99/md. | 20x Pro-kvote                          | Ingen ugentlig grænse                                  |

### Gemini- kontra ikke-Gemini-modeller

- **Gemini-modeller** (Flash + Pro): Deler en enkelt hastighedsgrænse, som forbruges i henhold til API-priserne. Hvis Flash er 8x billigere end Pro, får du 8x flere Flash-tokens.
- **Ikke-Gemini-modeller** (Claude, GPT-OSS): Har **separate** hastighedsgrænser. De kan fortsat være tilgængelige, selv når Gemini er låst.

### AI-kreditter (overforbrug)

> Se [Google One AI-kreditter](https://support.google.com/googleone/answer/14534406) for at få oplysninger om, hvordan kreditter fungerer.

Når basiskvoten er opbrugt:

- **Aldrig**: Vent på, at kvoten opdateres; viser "Basiskvoten for modellen er nået"
- **Altid**: Brug automatisk AI-kreditter; skifter tilbage til basiskvoten, når den opdateres

Kreditter købes separat og fratrækkes efter API-standardpriser.

### Vigtige oplysninger

- Kvoten **deles på kontoniveau** — den samme Google-konto i Antigravity IDE, CLI og OmniRoute deler én kvotepulje
- Hver Google-konto har sin egen uafhængige kvote — flere konti = flere kvotepuljer
- AI Pro-brugere har rapporteret **7-dages spærringer** i stedet for 5-timers nulstillinger, når den ugentlige basiskvote nås (Google har bekræftet, at dette er tilsigtet ved høj efterspørgsel)

**Når din kontos kvote er opbrugt**: OmniRoute prøver automatisk igen med den næste tilgængelige konto i kombinationsruten. Der kræves ingen manuel handling.

## 3. Sådan får du et projectId

Hver antigravity/agy-forbindelse kræver et Google Cloud Code-`projectId`. Uden det returnerer `/v1internal:models`-slutpunktet 404.

### Metode A: Automatisk (anbefalet)

OmniRoute håndterer dette automatisk. Når du tilføjer en ny Google-konto via OAuth i dashboardet:

1. OmniRoute opdaterer tokenet
2. Kalder `loadCodeAssist` for at finde projectId
3. Hvis der ikke findes et projekt, kaldes `onboardUser` for at oprette et
4. Prøver `loadCodeAssist` igen for at hente det nyoprettede projectId
5. Gemmer det i databasen

**Dette fungerer for de fleste konti** — der kræves ingen manuelle trin.

### Metode B: Manuelt via agy CLI

Hvis den automatiske registrering mislykkes (se afsnit 5 for, hvornår dette sker):

```bash
# Installer agy CLI (hvis det ikke allerede er installeret)
npm install -g @anthropic-ai/agy

# Log ind med din Google-konto
agy login

# Vælg den konto, der skal onboardes
# Dette udløser Cloud Code-registreringen og tildeler et projectId
```

Når `agy login` er gennemført, skal du opdatere tokenet i OmniRoute-dashboardet. projectId registreres automatisk.

### Sådan bekræfter du det

Kontrollér databasen:

```bash
# Inde i OmniRoute-containeren
node -e "const db=require('better-sqlite3')('/app/data/storage.sqlite'); \
  console.log(JSON.stringify(db.prepare(\
    'SELECT email,project_id FROM provider_connections WHERE provider=\"agy\"'\
  ).all(), null, 2))"
```

Eller kontrollér logfilerne:

```
podman logs omniroute 2>&1 | grep "projectId discovered"
```

## 4. OAuth-omdirigerings-URI

### Problemet

Google OAuth kræver en gyldig omdirigerings-URI. OmniRoutes standardindstilling bruger `http://127.0.0.1:20128/callback` (loopback). Dette fungerer for lokale builds, men **mislykkes ved fjerninstallationer** (f.eks. en server, der tilgås via en LAN-IP).

Google afviser omdirigerings-URI'er, der:

- Bruger IP-adresser (skal være et domæne, der ender på `.com`, `.org` osv.)
- Ikke matcher de registrerede omdirigerings-URI'er i OAuth-klientkonfigurationen

### Løsningen

**Mulighed A: Brug det indbyggede OAuth-flow (standard)**

- Fungerer, når du tilgår OmniRoute fra `localhost` eller `127.0.0.1`
- Ingen konfiguration nødvendig

**Mulighed B: Tilpassede OAuth-legitimationsoplysninger**

- Indstil `ANTIGRAVITY_OAUTH_CLIENT_TYPE=web` i dit miljø
- Angiv dine egne Google OAuth-legitimationsoplysninger:
  ```
  GOOGLE_OAUTH_CLIENT_ID=your-client-id
  GOOGLE_OAUTH_CLIENT_SECRET=your-client-secret
  ```
- Registrer `https://your-domain.com/callback` som en godkendt omdirigerings-URI i Google Cloud Console

**Mulighed C: Brug agy CLI til det første login**

- Kør `agy login` på den maskine, der skal tilgå OmniRoute
- OAuth-flowet gennemføres lokalt, og tokens gemmes
- Importér forbindelsen i OmniRoute via Dashboard

### Begrænsninger

- Tilpassede OAuth-legitimationsoplysninger kræver et domænenavn (Google accepterer ikke IP-adresser som omdirigerings-URI'er)
- Hvis du ikke har et domæne, skal du bruge mulighed A eller C i stedet

## 5. Fejlfinding: Når automatisk opsætning mislykkes

OmniRoute håndterer automatisk registrering af projectId og onboarding for de fleste konti. Når det mislykkes, er den grundlæggende årsag normalt én af følgende:

### Kontoregionen er blokeret

**Symptom**: `agy login` returnerer "Berettigelseskontrollen mislykkedes: Din nuværende konto er ikke berettiget til Antigravity, fordi tjenesten ikke er tilgængelig på din placering i øjeblikket."

**Grundlæggende årsag**: Google-konti har et backendfelt kaldet "Country Association", som indstilles ved registreringen. agy CLI og Cloud Code API kontrollerer dette felt strengt — i modsætning til webversionen af Gemini, som kun kontrollerer din aktuelle IP.

> Besøg [Googles formular til landetilknytning](https://policies.google.com/country-association-form) for at kontrollere eller ændre den region, der er knyttet til din konto.

**Hvorfor webversionen af Gemini fungerer, mens agy ikke gør**:

- Webversionen af Gemini / Google One: kontrollerer kun den aktuelle IP (proxy fungerer)
- agy CLI / Cloud Code API: læser backendfeltet Country Association (proxy hjælper ikke)

**Løsning**:

1. Besøg [Googles formular til landetilknytning](https://policies.google.com/country-association-form), mens du bruger en amerikansk IP
2. Indsend en anmodning om regionsændring (vælg "Jeg bor i et andet land")
3. Vent 1-24 timer på, at Google behandler anmodningen og sender en e-mailnotifikation
4. Derefter bør `agy login` lykkes

### Kontoen har intet Cloud Code-projekt

**Symptom**: Logfilerne viser `loadCodeAssist returned no project id` og `onboardUser failed (400)`.

**Grundlæggende årsag**: Kontoen er aldrig blevet registreret hos Google Cloud Code, og den automatiske onboarding mislykkedes.

**Løsning**: Kør `agy login` manuelt for at udløse Cloud Code-registreringen, og opdater derefter tokenet i OmniRoute Dashboard.

### Tokenet er udløbet eller tilbagekaldt

**Symptom**: 401-fejl i logfilerne eller meddelelser om, at tokenet er udløbet.

**Løsning**: Opdater tokenet i Dashboard → Providers → agy → Klik på opdateringsikonet. Hvis selve opdateringstokenet er tilbagekaldt, skal du godkende igen via OAuth.
