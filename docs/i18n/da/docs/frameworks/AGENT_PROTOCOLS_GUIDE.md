> **Kilde:** `src/lib/{a2a,acp,cloudAgent}/`, `src/app/api/{a2a,acp,cloud}/`, `src/app/api/v1/agents/`
> **Senest opdateret:** 2026-06-28 — v3.8.40

OmniRoute tilbyder tre forskellige agentrelaterede grænseflader. De ligner hinanden ved første øjekast, men løser forskellige problemer. Brug denne side til at vælge den rigtige.

## Kort fortalt

| Grænseflade                         | Bedst egnet til                                                                                                                                        | Transport                       | Standard              |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------- | --------------------- |
| **A2A — agent-til-agent**           | Samarbejde på tværs af agenter med peer-agenter, der understøtter A2A-protokollen                                                                      | JSON-RPC 2.0 over HTTP          | A2A v0.3 (åben spec.) |
| **ACP — register over CLI-agenter** | Registrering, detektering og start af CLI-kodningsagenter, der er installeret på brugerens maskine (Cursor, Cline, Codex CLI, Claude Code, Aider osv.) | HTTP REST                       | OmniRoute-specifik    |
| **Cloud-agenter**                   | Indsendelse af langvarige kodningsopgaver til eksterne cloudtjenester (Codex Cloud, Devin, Jules, Cursor Cloud)                                        | HTTP REST + DB-baserede opgaver | OmniRoute-specifik    |

De tre er uafhængige — vælg en hvilken som helst kombination.

## Beslutningstræ

```
Har du brug for, at en cloudtjeneste udfører arbejde uden for denne maskine (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ JA → Cloud-agenter (POST /api/v1/agents/tasks)
└─ NEJ → Fortsæt
    │
    Har du en peer-agent, der understøtter A2A og ønsker at samarbejde?
    ├─ JA → A2A (POST /a2a)
    └─ NEJ → Fortsæt
        │
        Har du brug for at vise/konfigurere CLI-kodningsagenter, der er installeret lokalt?
        ├─ JA → ACP (GET /api/acp/agents)
        └─ NEJ → Brug almindelig /v1/chat/completions
```

## 1. A2A — agent-til-agent

**Specifikation:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute-endpoint:** `POST /a2a` (JSON-RPC 2.0)
**Agentkort:** `GET /.well-known/agent.json`

### Hvornår det skal bruges

- Opbygning af et multiagentsystem, hvor OmniRoute er en af peer-agenterne
- Eksponering af OmniRoutes routingintelligens (smart routing, kvotestyring osv.) for agenter i frameworks som Google ADK eller generiske agentnetværk
- Indkapsling af OmniRoute bag en standardiseret grænseflade til registrering og kald

### Metoder

- `message/send` — indsend en meddelelse, og modtag et synkront svar
- `message/stream` — indsend, og modtag SSE-streamede statushændelser
- `tasks/get` — læs en opgave efter ID
- `tasks/cancel` — annuller en igangværende opgave

### Indbyggede færdigheder (6)

- `smart-routing` — send en prompt gennem den optimale kombination
- `quota-management` — rapportér kvotestatussen for hver udbyder
- `provider-discovery` — vis installerede udbydere med deres funktioner
- `cost-analysis` — estimér omkostningerne ved en anmodning/samtale
- `health-report` — sammenlæg breaker-, cooldown- og lockout-status for hver udbyder
- `list-capabilities` — oplist agentens tilgængelige færdigheder og metadata

### Fordybelse

Se [A2A-SERVER.md](./A2A-SERVER.md) for transportdetaljer, agentkortets struktur, konfiguration af opgavers TTL og skabelonen til tilføjelse af nye færdigheder.

## 2. ACP — register over CLI-agenter

**OmniRoute-endpoint:** `GET /api/acp/agents`
**Kilde:** `src/lib/acp/{index,manager,registry}.ts`

### Hvad det er

ACP er OmniRoutes **lokale oversigt over CLI-agenter**. Det registrerer, hvilke kodnings-CLI'er der er installeret på værten (Cursor, Cline, Claude Code, Codex CLI, Continue osv.), fastslår deres versioner og viser dem i kontrolpanelet, så brugeren kan konfigurere hver CLI til at pege på OmniRoute.

Dette er IKKE en ekstern protokol — det er et internt register, som driver brugergrænsefladen "CLI Tools" og sporingen af CLI-fingeraftryk (se [CLI-TOOLS.md](../reference/CLI-TOOLS.md)).

### Hvad det gør

- Undersøger værten for installerede CLI-binærfiler (bruger `which` / `where` afhængigt af operativsystemet)
- Aflæser hver CLI's version (kalder `<bin> --version`)
- Accepterer valgfrit brugerdefinerede agenter (sti til binærfil + versionskontrol + startargumenter)
- Gemmer brugerdefinerede agenter i indstillingerne
- Returnerer den samlede liste til kontrolpanelet

### REST-API

| Endpoint          | Metode | Beskrivelse                                                              | Godkendelse |
| ----------------- | ------ | ------------------------------------------------------------------------ | ----------- |
| `/api/acp/agents` | GET    | Vis registrerede + brugerdefinerede agenter (installeret/antal i alt)    | API-nøgle   |
| `/api/acp/agents` | POST   | Tilføj/opdater/fjern brugerdefineret agent (handlingsfelt i brødteksten) | API-nøgle   |

Brødtekstformat for POST (`customAgentBodySchema` i `src/app/api/acp/agents/route.ts`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### Anvendelsestilfælde

- Siden "CLI Tools" i kontrolpanelet viser, hvad der er installeret, og hjælper dig med at konfigurere hvert værktøj til at pege på OmniRoute
- Brugerdefinerede agenter giver superbrugere mulighed for at registrere interne/proprietære CLI'er, som OmniRoute ikke kender som standard
- Registreringsresultatet bruges til fingeraftryksmatricen `cli-tools`

### Hvornår ACP IKKE skal bruges

- ACP _kører_ ikke opgaver. Det registrerer og konfigurerer kun CLI'er. For faktisk at aktivere en CLI skal du selv starte den med de miljøvariabler, som OmniRoute leverer (`OPENAI_BASE_URL`, `OPENAI_API_KEY` osv.).

## 3. Cloud-agenter

**OmniRoute-endpoints:** `/api/v1/agents/tasks/*` (livscyklus) + `/api/cloud/*` (infrastruktur)
**Kilde:** `src/lib/cloudAgent/`

### Hvad det er

En ensartet grænseflade til cloudbaserede kodningsagenter fra tredjeparter. Du indsender en prompt + en URL til et repository, hvorefter OmniRoute sender opgaven til den rette cloud-agent, løbende kontrollerer dens status og returnerer resultaterne.

### Understøttede agenter (4, alle bekræftet i `src/lib/cloudAgent/agents/`)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### Livscyklus

```
POST /api/v1/agents/tasks
  → BaseAgent.createTask() for hver agentklasse
  → ekstern tjeneste påbegynder arbejdet
  → opgaverække oprettet i databasen (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → doven statussynkronisering fra udbyderen
  → returnerer aktuel status + plan + aktivitetslog
  ↓
POST /api/v1/agents/tasks/[id]   (action: "approve" | "message" | "cancel")
  → videresender til udbyderen (eller markerer som annulleret lokalt)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → lokal annullering
```

### Godkendelse

⚠️ **Alle `/api/v1/agents/tasks/*`-endpoints kræver administrationsgodkendelse** (commit `588a0333`). Kald, der kun bruger Bearer, modtager 401 siden v3.8.0.

### Fordybelse

Se [CLOUD_AGENT.md](./CLOUD_AGENT.md) for `CloudAgentBase`-kontrakten, agentspecifikke detaljer, skemadetaljer og endpoints til håndtering af legitimationsoplysninger.

## Sammenligning: A2A vs. Cloud Agents

Begge har "langvarige opgaver", men på forskellige lag:

| Aspekt               | A2A                                                                                           | Cloud Agents                                      |
| -------------------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Standard             | Åben A2A v0.3                                                                                 | Specifik for OmniRoute                            |
| Hvor beregning kører | Inde i OmniRoute (bruger konfigurerede kombinationer)                                         | Eksternt (Codex-/Devin-/Jules-servere)            |
| Opgavevarighed       | Standard-TTL på 5 min. (kan konfigureres i `TaskManager`)                                     | Minutter til timer                                |
| Repository-kendskab  | Nej (videresender kun prompts)                                                                | Ja (repository-URL + branch)                      |
| Anvendelse           | Samarbejde på tværs af agenter, intelligent routing som en tjeneste                           | Uddelegér "implementér funktion X i repository Y" |
| Godkendelse          | Valgfri `OMNIROUTE_API_KEY` til `/a2a`; administrationsadgang til REST-hjælperne `/api/a2a/*` | Altid administrationsadgang                       |

## Integrationseksempler

### Find OmniRoutes A2A-funktioner

```bash
curl http://localhost:20128/.well-known/agent.json
```

Returnerer agentkortet med alle 6 færdigheder, transportmekanismer og version.

### Kald OmniRoute som en A2A-agent

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### Vis installerede CLI-agenter via ACP

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### Tilføj en brugerdefineret CLI-agent

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Indsend en Cloud Agent-opgave

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Forespørg løbende om cloud-opgavens status

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```

## Hvornår du skal bruge hvad

- **Chatbot-/copilot-frontend** → `/v1/chat/completions` (OpenAI-kompatibel — ikke en agentprotokol)
- **Samarbejde mellem flere agenter** → A2A
- **Visning af lokale CLI'er i dashboardet** → ACP
- **Uddelegering af langvarige kodningsopgaver til cloudtjenester** → Cloud Agents
