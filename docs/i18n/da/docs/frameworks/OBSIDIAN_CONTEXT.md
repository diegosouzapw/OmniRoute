> (22 MCP-værktøjer), `src/app/api/settings/obsidian/route.ts` +
> `src/app/api/settings/obsidian/webdav/route.ts` (indstillings-API'er). Værktøjsregistrering
> og konfiguration af scopes findes i `open-sse/mcp-server/server.ts`.

## Hvad det er

OmniRoute forbinder til en **Obsidian**-vault som en **kontekstkilde** — en lokal
Markdown-vidensbase, som agenter læser og skriver til via den indbyggede MCP-server.
Integrationen kommunikerer med community-pluginet **Obsidian Local REST API**, der
kører i desktopappen, så agenter kan søge i noter, læse/skrive/opdatere filer, vise
indholdet af vaulten, arbejde med daglige/ugentlige periodiske noter, administrere
tags, køre Obsidian-kommandoer og (valgfrit) koordinere en tovejssynkronisering af
vaulten mellem desktop og mobil.

Klienten (`src/lib/obsidian/api.ts`) omfatter Local REST API'et med:

- **Nye forsøg med backoff** ved midlertidige `5xx`-fejl, **timeout på 30 sekunder** via `AbortController`.
- **Typet fejlklassificering** — `ObsidianAuthError` (401/403),
  `ObsidianNotFoundError` (404), `ObsidianServerError` (5xx), `ObsidianTimeoutError`.
- En **brugervenlig henvisning ved "kan ikke oprette forbindelse til Obsidian"**, som
  fremhæver den almindelige portfejl (HTTP på `27123`, **ikke** MCP-slutpunktet på
  `27124`) og Tailscale-formatet.
- Vault-relative **stikodning**, så notestier med mellemrum/skråstreger håndteres sikkert.

## Opsætning

Der findes **ingen miljøvariabel** til Obsidian-tokenet eller basis-URL'en — begge
gemmes i SQLite-tabellen `key_value` (namespace `obsidian`) via
`src/lib/db/obsidian.ts`. Tokenet er **krypteret ved lagring** (AES-256-GCM med
bagudkompatibelt fallback til klartekst). Konfigurer det fra fanen **Kontekstkilder**
i Endpoint-dashboardet (`ObsidianSourceCard`) eller via REST-API'et til indstillinger.

> [!IMPORTANT]
> Pluginet **Obsidian Local REST API** skal være installeret og køre. Dets REST-
> grænseflade lytter på **HTTP `127.0.0.1:27123`** (standardbasis-URL'en). Port `27124`
> er et _separat_ MCP/HTTPS-slutpunkt og afvises eksplicit af indstillingsruten.
> Ved forbindelse fra en anden enhed skal du bruge `http://<tailscale-ip>:27123`.

### Konfigurationsnøgler (SQLite `key_value`, namespace `obsidian`)

| Nøgle             | Formål                                              | Krypteret |
| ----------------- | --------------------------------------------------- | --------- |
| `api_key`         | Bearer-token til Local REST API                     | ja        |
| `base_url`        | REST-basis-URL (standard `http://127.0.0.1:27123`)  | nej       |
| `vault_path`      | Absolut sti til vault-mappen (til synkronisering)   | nej       |
| `webdav_username` | Genereret WebDAV-brugernavn (vault-synkronisering)  | nej       |
| `webdav_password` | Genereret WebDAV-adgangskode (vault-synkronisering) | ja        |
| `webdav_enabled`  | Om WebDAV-synkronisering af vaulten er aktiveret    | nej       |

### Konfigurer via REST

```bash
# Gem og valider Local REST API-tokenet (POST validerer via et statustjek)
curl -X POST http://localhost:20128/api/settings/obsidian \
  -H "Content-Type: application/json" \
  -d '{"token":"<obsidian-rest-api-key>","baseUrl":"http://127.0.0.1:27123"}'

# Kontrollér forbindelsesstatus (returnerer connected, hasToken, baseUrl, vaultPath)
curl http://localhost:20128/api/settings/obsidian

# Afbryd forbindelsen (rydder det gemte token)
curl -X DELETE http://localhost:20128/api/settings/obsidian
```

Alle metoder kræver dashboardgodkendelse. `POST` afviser enhver URL på port `27124`
og validerer tokenet ved at kalde statusslutpunktet i Local REST API, før det gemmes.

### WebDAV-synkronisering af vault

`src/app/api/settings/obsidian/webdav/route.ts` administrerer en valgfri WebDAV-baseret
synkronisering af vaulten (drevet af `src/lib/obsidianSync.ts`). Når den aktiveres,
dirigeres OmniRoute til en lokal vault-mappe, og der genereres et tilfældigt
WebDAV-brugernavn/adgangskode-par:

```bash
# Aktivér WebDAV-synkronisering for en vault-mappe (genererer brugernavn/adgangskode)
curl -X POST http://localhost:20128/api/settings/obsidian/webdav \
  -H "Content-Type: application/json" \
  -d '{"vaultPath":"/home/me/MyVault"}'

# Hent status for WebDAV-synkronisering (legitimationsoplysninger returneres kun, mens den er aktiveret)
curl http://localhost:20128/api/settings/obsidian/webdav

# Deaktivér WebDAV-synkronisering (rydder legitimationsoplysninger og administreret .stignore)
curl -X DELETE http://localhost:20128/api/settings/obsidian/webdav
```

### Kontekstkilde pr. API-nøgle (valgfrit)

Obsidian-konfigurationen kan afgrænses **pr. API-nøgle** via tabellen
`api_key_context_sources` (`src/lib/db/apiKeyContextSources.ts`). Når et MCP-kald
indeholder et godkendt API-nøgle-id, foretrækker `getObsidianConfigForApiKey()` den
pågældende nøgles eget token/basis-URL/vault-sti (`source: "api_key"`) og falder ellers
tilbage til den globale konfiguration (`source: "global"`).

## MCP-værktøjer (22)

Defineret i `open-sse/mcp-server/tools/obsidianTools.ts`. Tokenet/basis-URL'en bestemmes
for hvert kald (først pr. API-nøgle, derefter globalt). Værktøjer, der tilgår OmniRoutes **synkroniseringsserver**
(de fire `obsidian_sync_*`-værktøjer), kræver desuden det synkroniseringsautentificeringstoken, der er konfigureret
i OmniRoute-indstillingerne.

### Læseværktøjer (`read:obsidian`)

| Værktøj                      | Beskrivelse                                                                                           |
| ---------------------------- | ----------------------------------------------------------------------------------------------------- |
| `obsidian_check_status`      | Kontrollér, om den lokale REST API er tilgængelig og godkendt.                                        |
| `obsidian_search_simple`     | Fuldtekstsøgning i noteindhold; returnerer uddrag med filstier.                                       |
| `obsidian_search_structured` | Søg ved hjælp af et JSON Logic-udtryk (and/or/regex/path-filtre).                                     |
| `obsidian_read_note`         | Læs en note via en boksrelativ sti; eventuelt en bestemt overskrift/blok/frontmatter.                 |
| `obsidian_list_vault`        | Vis filer og mapper i boksen (træstruktur af poster).                                                 |
| `obsidian_get_document_map`  | Hent notens overskriftsstruktur som en afbildning af overskrifter → linjenumre.                       |
| `obsidian_get_note_metadata` | Hent frontmatter, tags, links samt tegn-/ordantal uden det fulde indhold.                             |
| `obsidian_get_active_file`   | Hent stien og indholdet for den aktuelt aktive fil i Obsidian.                                        |
| `obsidian_get_periodic_note` | Hent den daglige/ugentlige/månedlige periodiske note for en dato (i dag, hvis udeladt).               |
| `obsidian_get_tags`          | Vis alle tags i boksen med deres hyppigheder.                                                         |
| `obsidian_list_commands`     | Vis tilgængelige Obsidian-kommando-id'er (bruges med `obsidian_execute_command`).                     |
| `obsidian_sync_status`       | Status for OmniRoute-synkroniseringsserveren: kører, boksnavn, port, oppetid, seneste synkronisering. |
| `obsidian_sync_conflicts`    | Vis uløste synkroniseringskonflikter (sti, konfliktsti, registreringstidspunkt).                      |

### Skriveværktøjer (`write:obsidian`)

| Værktøj                          | Beskrivelse                                                                                    |
| -------------------------------- | ---------------------------------------------------------------------------------------------- |
| `obsidian_write_note`            | Opret eller overskriv en note med det angivne Markdown-indhold.                                |
| `obsidian_append_note`           | Føj indhold til en note; eventuelt til en bestemt overskrift/blok.                             |
| `obsidian_patch_note`            | Tilføj før/efter eller erstat målrettet ved en overskrift, blok eller et frontmatter-felt.     |
| `obsidian_delete_note`           | Slet en note permanent fra boksen.                                                             |
| `obsidian_move_note`             | Flyt eller omdøb en note i boksen.                                                             |
| `obsidian_execute_command`       | Udfør en Obsidian-kommando via dens kommando-id.                                               |
| `obsidian_open_file`             | Åbn en fil i Obsidian (opretter den, hvis den ikke findes).                                    |
| `obsidian_sync_trigger`          | Udløs en øjeblikkelig tovejssynkronisering af boksen mellem computer og mobil.                 |
| `obsidian_sync_resolve_conflict` | Løs en synkroniseringskonflikt: behold `local` (mobil), `remote` (computer) eller `keep-both`. |

> [!NOTE]
> Mål for `obsidian_patch_note` accepterer `targetType` med værdien `heading | block | frontmatter`
> og `operation` med værdien `append | prepend | replace` samt en valgfri
> `createTargetIfMissing`. De fire `obsidian_sync_*`-værktøjer kommunikerer med den lokale synkroniseringsserver
> (`http://127.0.0.1:27781` som standard) og kræver synkroniseringstokenet.

### Adgangsområder

Læseværktøjer kræver `read:obsidian`; skriveværktøjer kræver `write:obsidian`. Håndhævelsen
er identisk med Notion — håndteret af `withScopeEnforcement()` i
`open-sse/mcp-server/server.ts`, betinget af `OMNIROUTE_MCP_ENFORCE_SCOPES=true`, med
tilladte adgangsområder hentet fra `OMNIROUTE_MCP_SCOPES` eller API-nøglens adgangsområdekontekst. Se
[MCP-SERVER.md](./MCP-SERVER.md).

## Endpoints

| Metode   | Sti                             | Formål                                                                     |
| -------- | ------------------------------- | -------------------------------------------------------------------------- |
| `GET`    | `/api/settings/obsidian`        | Returnerer `{ connected, hasToken, baseUrl, vaultPath }`.                  |
| `POST`   | `/api/settings/obsidian`        | Gemmer og validerer tokenet (afviser port `27124`).                        |
| `DELETE` | `/api/settings/obsidian`        | Afbryder forbindelsen (rydder det gemte token).                            |
| `GET`    | `/api/settings/obsidian/webdav` | WebDAV-synkroniseringsstatus og legitimationsoplysninger (mens aktiveret). |
| `POST`   | `/api/settings/obsidian/webdav` | Aktiverer WebDAV-synkronisering for en vault-mappe.                        |
| `DELETE` | `/api/settings/obsidian/webdav` | Deaktiverer WebDAV-synkronisering.                                         |

> Disse er indstillingsruter til dashboardet. Selve vaulten tilgås via Obsidians
> lokale REST API (den konfigurerede `base_url`) og via MCP-værktøjerne ovenfor — der er
> ikke noget offentligt `/v1`-Obsidian-proxyendpoint.

## Brugsscenarier

- **Svar baseret på vaulten** — `obsidian_search_simple` / `obsidian_search_structured`
  efterfulgt af `obsidian_read_note`, så en agent svarer ud fra dine faktiske noter.
- **Oprettelse af noter / journalføring** — `obsidian_write_note`, `obsidian_append_note` eller
  den målrettede `obsidian_patch_note` til at logge agentoutput, resuméer eller daglige noter
  (`obsidian_get_periodic_note`) i vaulten.
- **Navigation i vaulten** — `obsidian_list_vault`, `obsidian_get_document_map` og
  `obsidian_get_tags` til at udforske strukturen før læsning/skrivning.
- **Obsidian-automatisering** — `obsidian_list_commands` + `obsidian_execute_command` til at
  styre plugins/kommandoer fra en agent; `obsidian_open_file` til at vise en note i brugergrænsefladen.
- **Mobilsynkronisering** — aktivér WebDAV-synkronisering og brug derefter `obsidian_sync_trigger` /
  `obsidian_sync_status` / `obsidian_sync_conflicts` / `obsidian_sync_resolve_conflict`
  til at koordinere desktop↔mobil og løse konflikter.
