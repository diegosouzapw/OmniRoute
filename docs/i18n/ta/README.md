## 💰 மாதத்திற்கு ~1.62B இலவச டோக்கன்கள்

</div>

> இலவச அடுக்குகளை கைமுறையாக ஒன்றிணைப்பது கடினமானது — டஜன் கணக்கான SDK-கள், டஜன் கணக்கான விகித வரம்புகள், மேலும் உண்மையில் உங்களிடம் எவ்வளவு உள்ளது என்பதே தெரியாது. OmniRoute, **மீண்டும் மீண்டும் கிடைக்கும் 35 pool key-களில் 489 இலவச-அடுக்கு பதிவுகளைப்** பட்டியலிட்டு, பகிரப்பட்ட pool அடிப்படையில் நகல்களை நீக்கிய பிறகு, **வெளியிடப்பட்ட நேர்மறையான மாதாந்திர பட்ஜெட்டைக் கொண்ட 17 pool-கள் மற்றும் ஒவ்வொரு மாடலுக்குமான ஐந்து Groq வரம்புகளிலிருந்து** டோக்கன் தலைப்பு எண்ணிக்கையைக் கணக்கிடுகிறது. பிராந்திய அடையாளச் சரிபார்ப்புக்குப் பிறகு மட்டுமே திறக்கப்படும் ஒதுக்கீடுகள் (தற்போது: ModelScope) தனியாகக் காட்டப்படுகின்றன; பிராந்திய அடையாளச் சரிபார்ப்புக்குப் பின்னால் +~6M உள்ளது, மேலும் அது தலைப்பு எண்ணிக்கையில் ஒருபோதும் சேர்க்கப்படுவதில்லை. முடிவு டாஷ்போர்டில் (`/dashboard/free-tiers`) தொடர்ந்து காணக்கூடியதாக இருக்கும்.

<img src="./docs/diagrams/free-tier-budget.svg" width="100%" alt="OmniRoute இலவச-அடுக்கு பட்ஜெட் அட்டை: நிலையாக மாதத்திற்கு ~1.62B இலவச டோக்கன்கள்; பதிவுசெய்தல் கிரெடிட்களுடன் முதல் மாதத்தில் ~2.22B வரை; ஒரே endpoint-க்குப் பின்னால் பட்டியலிடப்பட்ட 489 இலவச-அடுக்கு பதிவுகளை உள்ளடக்கும் ஆவணப்படுத்தப்பட்ட 35 தொடர்ச்சியான pool key-களிலிருந்து. நேர்மையான, pool நகல்நீக்கம் செய்யப்பட்ட கணக்கீடு — பகிரப்பட்ட ஒவ்வொரு pool-மும் ஒருமுறை மட்டுமே கணக்கிடப்படுகிறது; வெளியிடப்பட்ட நேர்மறையான மாதாந்திர டோக்கன் பட்ஜெட்டைக் கொண்ட 17 தொடர்ச்சியான pool-கள் மற்றும் ஒவ்வொரு மாடலுக்குமான ஐந்து Groq வரம்புகள் உட்பட; நீங்கள் முடிவு செய்வதற்காக விதிமுறை-அபாயப் பட்டியலில் 13 வழங்குநர்கள் தவிர்க்கப்பட வேண்டியவர்கள் எனக் குறிக்கப்பட்டுள்ளனர். பட்ஜெட் பட்டையில் Mistral 1B, Nara 210M, LLM7 150M, xKiro 150M, Groq 30M (ஒவ்வொரு மாடலுக்குமான ஐந்து வரம்புகள்) மற்றும் சிறிய pool-கள் இடம்பெறுகின்றன; மேலும் முதல் மாதப் பதிவுசெய்தல் கிரெடிட்களும், நிரந்தரமாக இலவசமாகக் கிடைக்கும் டோக்கன் வரம்பற்ற வழங்குநர்களும் தனியாகக் காட்டப்படுகின்றனர், எனவே அவை தலைப்பு எண்ணிக்கையை ஒருபோதும் செயற்கையாக உயர்த்துவதில்லை. /dashboard/free-tiers-இல் நேரடி பயன்படுத்தியது/மீதமுள்ளது."/>

> நேரடி `/dashboard/free-tiers` பக்கத்தின் அசைவூட்டப்பட்ட சுருக்கம். முழுமையான வழிமுறை (pool நகல்நீக்கம், கிரெடிட் அடுக்குகள், வழங்குநர் விதிமுறைகள்): **[docs/reference/FREE_TIERS.md](docs/reference/FREE_TIERS.md)**.
>
> <sub>இந்த எண்ணிக்கைகள் ஒவ்வொரு இரண்டு வாரங்களுக்கும் நேரடி பட்டியலுடன் ஒப்பிட்டு மீண்டும் தணிக்கை செய்யப்படுகின்றன, மேலும் அவை **இரு திசைகளிலும் மாறுகின்றன** — ஒரு வழங்குநர் இலவச அடுக்கை நிறுத்தினால் எண்ணிக்கை குறையும்; புதிய ஒன்று சேர்ந்தால் அது உயரும். பட்டியல் உண்மையில் கணக்கிடுவதையே நாங்கள் வெளியிடுகிறோம்; மேல்நோக்கி முழுமைப்படுத்தப்பட்ட சிறந்த சூழ்நிலையை ஒருபோதும் வெளியிடுவதில்லை.</sub>

## 🆓 நிறுவிய உடனேயே இயங்கும் — விசைகள் தேவையில்லை, கட்டமைப்பும் தேவையில்லை

</div>

<img src="./docs/diagrams/works-zero-config.svg" width="100%" alt="நிறுவிய உடனேயே இயங்கும் — கட்டமைப்பு தேவையில்லை. மூன்று படிகள்: 1. நிறுவுங்கள் — npm i -g omniroute, localhost:20128 இல் சேவையகம் தொடங்கும். 2. உங்கள் கருவியை http://localhost:20128/v1 நோக்கிச் சுட்டுங்கள் — OpenAI-உடன் இணக்கமான எந்தக் கருவியும் (Claude Code, Cursor, Cline). 3. அது பதிலளிக்கும் — API விசை, பதிவுசெய்தல் அல்லது கட்டமைப்பு எதுவுமின்றி உடனடி பதிலைப் பெற model auto-ஐ அழையுங்கள். விசை தேவையற்ற வழங்குநரான OpenCode Free, auto சேர்க்கையில் முன்கூட்டியே இணைக்கப்பட்டுள்ளதால், புதிதாக நிறுவியவுடனேயே அது பதிலளிக்கும்."/>

```bash
# புதிதாக நிறுவப்பட்டது, நற்சான்றுகள் ஏதுமில்லை — `auto` ஏற்கனவே இயங்குகிறது:
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'
```

<sub>குறிப்பிட்ட இலவசப் பின்தளத்தை விரும்புகிறீர்களா? `oc/…` (OpenCode Free)-ஐ நேரடியாக அழையுங்கள். பின்னர் `auto`-க்கு மாறி, OmniRoute தேர்வுசெய்ய அனுமதியுங்கள்.</sub>

<sub>📦 **Python, Node.js, PHP மற்றும் cURL**-க்கான நகலெடுத்து ஒட்டக்கூடிய விரைவுத் தொடக்க ஸ்கிரிப்ட்கள் → [`examples/quickstart/`](examples/quickstart/)</sub>

<img src="./docs/diagrams/resilience-layers.svg" width="100%" alt="OmniRoute மீள்திறன் — 3 சுயாதீன சுய-மீட்பு அடுக்குகள், சரியான தோல்விக்குச் சரியான அடுக்கு. அடுக்கு 1 வழங்குநர் சர்க்யூட் பிரேக்கர் (முழு வழங்குநர்): 408/5xx ஏற்பட்டால் மட்டுமே செயல்படும்; வரம்புகள் OAuth 8× / API-key 12× / local 2×; 60s/30s/15s கழித்து HALF-OPEN சோதனை நிலைக்கு மீட்டமைக்கப்படும்; தேவையின்போது மீட்பு; OPEN நிலையில் இருக்கும்போது combo அடுத்த வழங்குநருக்கு வழிமாற்றும். அடுக்கு 2 இணைப்பு இடைநிறுத்தம் (ஒரு key/account): அடிப்படை OAuth-க்கு 5s / API-key-க்கு 3s; ஒரே நேரத்தில் அதிக கோரிக்கைகள் குவிவதைத் தடுக்கும் பாதுகாப்புடன் அதிவேக ×2 பின்னடைவு; 429 ஆனது Retry-After-ஐ மதிக்கும்; வெற்றி அனைத்து பிழை நிலைகளையும் அழிக்கும்; இடைநிறுத்தத்தில் உள்ள ஒரு key தவிர்க்கப்படும், அதே வேளையில் இணை key-கள் தொடர்ந்து சேவையளிக்கும். அடுக்கு 3 மாடல் பூட்டல் (ஒரு மாடல்): ஒவ்வொரு மாடலுக்குமான 429, local 404 அல்லது பயன்முறை மறுப்புகள் அந்த மாடலை மட்டும் பூட்டும் — முழு இணைப்பை ஒருபோதும் பூட்டாது. இறுதி நிலைகள் (தடைசெய்யப்பட்டது, காலாவதியானது, credits தீர்ந்தது) இயக்குநருக்கானவை, இடைநிறுத்தங்களுக்கானவை அல்ல."/>

## 📡 OmniRoute Radar

மேலே ஆவணப்படுத்தப்பட்ட, பகிரப்பட்ட தொகுப்புகளில் உள்ள நகல்களை நீக்கிய பட்டியலிலிருந்து கிடைக்கும் முக்கிய இலவச அடுக்கு அளவு **~1.62B டோக்கன்கள்/மாதம்** ஆகவே உள்ளது. வழங்குநர்களின் தற்காலிகப் பதிவுச் சலுகைகள் முதல்
மாதத்திற்கான அளவைத் தனியாக **~2.22B** வரை உயர்த்தக்கூடும். OmniRoute வெளியீடுகளுக்கு இடைப்பட்ட காலத்தில்
இலவச மாடல்களின் கிடைப்புநிலை குறித்த புதிய தகவல்களை விரும்புபவர்களுக்காக Radar ஒரு விருப்பத் தேர்வாகக் கிடைக்கும், கையொப்பமிடப்பட்ட பட்டியல் மேலடுக்காகும்; சமூகப் பட்டியலும் ஏற்கெனவே உள்ள ஒவ்வொரு இலவச
அம்சமும் தொடர்ந்து இலவசமாகவே இருக்கும்.

ஆதரவாளர்கள் நேரடிப் பட்டியலையும் கூடுதல் வழங்குநர் வாய்ப்புகளையும் பெறலாம். வழங்குநர்களின் கிடைப்புநிலையைப் பொறுத்து, இதன் தனியான,
மாற்றத்தக்க உச்சவரம்பு **அதிகபட்சமாகச் சுமார் 3B டோக்கன்கள்/மாதம்** ஆகும்.
இந்த உச்சவரம்பிற்கு உத்தரவாதம் இல்லை: வழங்குநர்கள் ஒதுக்கீடுகள், தகுதித் தேவைகள், மாடல்கள் அல்லது பிராந்தியங்களை
எந்த நேரத்திலும் மாற்றலாம்.

Radar-ஐப் பயன்படுத்தத் தனியாகச் சம்மதிக்க வேண்டும்; இது GET கோரிக்கைகளை மட்டுமே பயன்படுத்துகிறது. OmniRoute கிளையன்ட் ப்ராம்ப்ட்கள், போக்குவரத்து, வழங்குநர்
உள்ளமைவு, பயன்பாட்டுத் தொலைஅளவீடு அல்லது அறிவிப்புகளை நிராகரித்த உள்ளூர் நிலை ஆகியவற்றைப் பதிவேற்றாது. தகுதித் தேவைகளையும்
தற்போதைய பட்டியலையும் **[radar.omniroute.online/planos](https://radar.omniroute.online/planos)**-இல் அறிந்துகொள்ளுங்கள்.

omniroute run claude   --model openai/gpt-5.4          # Claude Code

## 🔌 முழுமையான CLI + A2A & MCP

</div>

> சேவையகத்தைத் தாண்டி, OmniRoute என்பது **80+ கட்டளைகளைக்** கொண்ட ஒரு **முழுமையான கட்டளை-வரி கட்டுப்பாட்டு மையம்**; மேலும், ஒரு AI முகவர் இதை **தானாகவே** இயக்குவதற்கான திறந்த முகவர் நெறிமுறைகளையும் கொண்டுள்ளது.

### ⌨️ ஓர் உண்மையான CLI (`start` மட்டும் அல்ல)

```bash
omniroute               # நுழைவாயில் + கட்டுப்பாட்டுப் பலகையை வழங்கும் (port 20128)
omniroute chat          # ஊடாடும் TUI அரட்டை கிளையன்ட் (slash: /model /combo /skill /memory)
omniroute setup         # வழிகாட்டப்பட்ட முதல்-இயக்க வழிகாட்டி
omniroute doctor        # வழங்குநர்கள், போர்ட்கள், இயல்நிலை சார்புகளைக் கண்டறியும்
```

### 🛰️ தொலைநிலை முறை — CLI-ஐ இங்கே இயக்கி, OmniRoute-ஐ VPS-இல் இயக்குங்கள்

சேவையகத்தில் OmniRoute உள்ளதா? **அதே CLI** மூலம் உங்கள் மடிக்கணினியிலிருந்து அதை இயக்குங்கள். வரம்பிடப்பட்ட அணுகல் டோக்கனுடன் ஒருமுறை உள்நுழையுங்கள்;
அதன்பின் ஒவ்வொரு கட்டளையும் தொலைநிலையை இலக்காகக் கொள்ளும்.

```bash
omniroute connect 192.168.0.15            # கடவுச்சொல் → வரம்பிடப்பட்ட டோக்கன், ஒரு சூழலாகச் சேமிக்கப்படும்
omniroute models list                     # ← தொலைநிலைச் சேவையகத்திற்கு எதிராக இயங்கும்
omniroute configure codex                 # ← தொலைநிலை மாதிரியைத் தேர்ந்தெடுத்து, உள்ளமை Codex சுயவிவரத்தை எழுதும்
omniroute tokens create --name ci --scope read   # பிற கணினிகளுக்காகக் குறுகிய வரம்புள்ள டோக்கன்களை உருவாக்கும்
omniroute contexts use default            # ← உள்ளமைச் சேவையகத்திற்குத் திரும்பும்
```

டோக்கன்கள் `read` / `write` / `admin` என வரம்பிடப்பட்டுள்ளன; செயல்முறைகளைத் தொடங்கும் வழித்தடங்கள் loopback-க்கு மட்டும் வரையறுக்கப்பட்டுள்ளன.

<img src="./docs/diagrams/compression-pipeline.svg" width="100%" alt="OmniRoute சுருக்கப் பைப்லைன்: எடுத்துக்காட்டாகக் காட்டப்படும் 10,000-டோக்கன் கிளையன்ட் கோரிக்கை, ஒன்றிணைக்கக்கூடிய 12 என்ஜின்களான Session-Dedup, CCR, Lite, RTK, Responses Tool Output, Headroom, Relevance, Caveman, Aggressive, LLMLingua-2, Ultra மற்றும் OmniGlyph வழியாகச் செல்கிறது — மேலும் ஆவணப்படுத்தப்பட்ட அடுக்கப்பட்ட எடுத்துக்காட்டில் சுமார் 1,080 டோக்கன்களுடன் வழங்குநரை அடையக்கூடும். கட்டமைக்கப்பட்ட உள்ளடக்கம், பாதுகாப்புக் காவல்கள் மற்றும் ஒவ்வொரு படிநிலைக்குமான துல்லிய நுழைவாயில்களால் பாதுகாக்கப்படுகிறது; வெளிப்படையான இழப்புள்ள அல்லது சோதனை முறைகள் தகுதியான உள்ளடக்கத்தை மாற்றக்கூடும்."/>

இயல்புநிலை அடுக்கப்பட்ட சேர்க்கை `RTK → Caveman`-ஐ இயக்குகிறது. இரண்டும் ஒரே கருவி/சூழல் பேலோடில் செயல்படும்போது, சேமிப்புகள் பெருக்கமடைகின்றன:

```txt
combined = 1 − (1 − RTK) × (1 − Caveman_input)
average  = 1 − (1 − 0.80) × (1 − 0.46) = 89.2%
range    = 78.4 – 94.6%
```

குறியீட்டுத் தொகுதிகள், URL-கள், JSON மற்றும் கட்டமைக்கப்பட்ட தரவு ஆகியவை பாதுகாப்பு என்ஜினால் **எப்போதும் பாதுகாக்கப்படுகின்றன**.

> **சில டோக்கன்களே வேலையைச் செய்யும்போது ஏன் பல டோக்கன்களைப் பயன்படுத்த வேண்டும்?** ஒவ்வொரு கோரிக்கையும் OmniRoute-இன் சுருக்கப் பைப்லைன் வழியாக **வெளிப்படையாக** செல்கிறது — கிளையன்ட் மாற்றங்கள் தேவையில்லை. இப்போது இது வரிசையாக இயங்கி, ஒவ்வொரு ரூட்டிங் சேர்க்கைக்கும் ஏற்ப கலந்து பொருத்தக்கூடிய **ஒன்றிணைக்கத்தக்க 12 என்ஜின்களின் அடுக்கு** — [RTK](https://github.com/rtk-ai/rtk), [Caveman](https://github.com/JuliusBrussee/caveman) (⭐ 90K+), [LLMLingua-2](https://github.com/microsoft/LLMLingua), மற்றும் [Troglodita](https://github.com/leninejunior/troglodita) (PT-BR) ஆகியவற்றின் கருத்துகளை அடிப்படையாகக் கொண்டது.

### 🎚️ எஞ்சின்களுக்கும் அப்பால் — வெளியீட்டு பாணிகள், தகவமைப்பு டயல் மற்றும் ஒவ்வொரு கோரிக்கைக்குமான கட்டுப்பாடு

மேலே உள்ள 12 எஞ்சின்கள் **உள்ளே** செல்வதைச் சுருக்குகின்றன. மேலும் மூன்று அடுக்குகள் **எப்படி**, **எப்போது**, மற்றும் **எது வெளியே வருகிறது** என்பதை வடிவமைக்கின்றன:

- **🪄 வெளியீட்டு பாணிகள்** _(வெளியீட்டு-அச்சு வழிநடத்தல்)_ — தீர்மானகரமான, கேச்-பாதுகாப்பான பதில்-வடிவமைப்பு அறிவுறுத்தல்களைச் செலுத்தும்; இவற்றை ஒன்றிணைக்கலாம், ஒவ்வொன்றும் `lite` / `full` / `ultra` தீவிரத்தில் கிடைக்கும். ஒரு பாணியைச் சேர்க்க, ரெஜிஸ்ட்ரியில் ஒரு வரி பதிவு போதும்:
  - **சுருக்கமான உரைநடை** — நிரப்பு வார்த்தைகள் / ஆர்டிக்கிள்கள் / தயக்கமூட்டும் சொற்களை நீக்கவும்; தொழில்நுட்ப உள்ளடக்கத்தைத் துல்லியமாக வைத்திருக்கவும்.
  - **குறைவான குறியீடு** — "சோம்பேறி மூத்த டெவலப்பர்" YAGNI: செயல்படும் மிகச்சிறிய மாற்றம், கோரப்படாத கட்டமைப்பு வேண்டாம்.
  - **போனிடெயில் (சோம்பேறி மூத்த டெவலப்பர்)** — YAGNI படிகளில் ஏறி, மூலக் காரணத்தைச் சரிசெய்து, செயல்படும் மிகச்சிறிய diff-ஐ உருவாக்கவும்.
  - **எனக்கு ADHD உள்ளது (செயல்-முதலில்)** — அடுத்த செயலை முதலில் காட்டவும், படிகளுக்கு எண்கள் இடவும், ஒரே ஒரு உறுதியான அடுத்த படியை வழங்கவும், முன்னுரை வேண்டாம்.
  - **சுருக்கமான CJK (文言)** — செம்மொழிச் சீனத்தின் அதி-சுருக்கமான பாணி (`zh` மொழியமைவுக்கு மட்டும்).
- **🎯 தகவமைப்பு சூழல்-பட்ஜெட்** _(டயல்)_ — ஒரே ஆன்/ஆஃப் டோக்கன் வரம்புக்குப் பதிலாக, **மாடலின் சூழல் சாளரத்திற்குள் பொருந்துவதற்குத்** தேவையான அளவு வரை மட்டுமே, மிக மலிவான மற்றும் குறைந்த இழப்புடைய எஞ்சின்களைப் படிப்படியாக இயக்கும். கொள்கை: `reserve-output` (இயல்புநிலை, மாடலைக் கருத்தில் கொள்வது) · `percentage` · `absolute`. பயன்முறை: `floor` (பொருந்துவதை உறுதிசெய்யும்) · `replace-autotrigger` (உங்கள் வெளிப்படையான தேர்வே முன்னுரிமை பெறும்) · `off` (மரபு வரம்பு).
- **🎛️ சுருக்கம் எங்கு தீர்மானிக்கப்படுகிறது** _(முன்னுரிமை, அதிகம் → குறைவு)_ — ஒவ்வொரு கோரிக்கைக்குமான `x-omniroute-compression` ஹெடர் › ரூட்டிங்-காம்போ ஓவர்ரைடு › செயலில் உள்ள பெயரிடப்பட்ட சுயவிவரம் › தகவமைப்பு / தானியங்கு-தூண்டல் › பேனல் இயல்புநிலை › ஆஃப். பயன்படுத்தப்பட்ட திட்டம் `X-OmniRoute-Compression: <mode>; source=<source>` பதில் ஹெடரில் திருப்பி அனுப்பப்படும்.

டோக்கன் வரம்பின் அடிப்படையில் தானியங்கு-தூண்டலை அமைக்கவும், தகவமைப்பு டயலை இயக்கவும், பெயரிடப்பட்ட சுயவிவரத்தைப் பின் செய்யவும், ஒவ்வொரு கோரிக்கைக்கும் ஒருமுறை மட்டும் பொருந்தும் அமைப்பை வழங்கவும் அல்லது ஒவ்வொரு ரூட்டிங் காம்போவுக்கும் ஒரு பைப்லைனை ஒதுக்கவும் — பணிச்சுமைக்கு எது பொருந்துகிறதோ அதைப் பயன்படுத்துங்கள். விருப்பத்தேர்வாக இயக்கக்கூடிய ஆஃப்லைன் **மதிப்பீட்டு ஹார்னஸ்** (`npm run eval:compression`), ஒரு மாற்றத்தைப் பயன்பாட்டிற்கு உயர்த்துவதற்கு முன், பின் செய்யப்பட்ட கார்பஸில் நம்பகத்தன்மையையும் சேமிப்பையும் மதிப்பிடுகிறது.

`:latest` என்பது **வெளியிடப்பட்ட** நிலையான SemVer பதிப்புகளில் மிக உயர்ந்ததைப் பின்பற்றும். இது git `main`-ஐப் பின்தொடராது. GitOps-க்கு `:X.Y.Z` எனப் பதிப்பை நிலைநிறுத்தவும். [Docker வெளியீட்டுச் சேனல்கள்](docs/guides/DOCKER_GUIDE.md#release-channels) என்பதைப் பார்க்கவும். இந்த image-ல் **`OMNIROUTE_MEMORY_MB=1024`** நிலைநிறுத்தப்பட்டுள்ளது. Dashboard மற்றும் இலகுவான chat-க்கு அது போதுமானது. **Coding agents** (Claude Code, Codex, Grok, … இலிருந்து `POST /v1/responses`) இயக்க மிகவும் பெரிய V8 heap தேவை; இல்லையெனில் ஒன்றுடன் ஒன்று நேரத்தில் இயங்கும் இரண்டு நீண்ட context-களின்போது, செயல்முறை சுமார் 12 GiB-ல் `FATAL ERROR` ஏற்படுத்தும். Heap-ஐ விட container-ன் அளவை அதிகமாக அமைக்கவும் (native buffer-கள் V8-க்கு வெளியே இருக்கும்):

| பணிச்சுமை                                  | Heap (`-e OMNIROUTE_MEMORY_MB`) | Container (`--memory`) |
| ------------------------------------------ | ------------------------------- | ---------------------- |
| Dashboard / இலகுவான chat                   | `1024` (image இயல்புநிலை)       | ≥2 g                   |
| ஒரு coding agent                           | `8192`                          | ≥10 g                  |
| ஒரே நேரத்தில் இரண்டு நீண்ட `/v1/responses` | `10240`–`12288`                 | ≥12–16 g               |

```bash
docker run -d --name omniroute --restart unless-stopped --stop-timeout 40 \
  -e OMNIROUTE_MEMORY_MB=8192 --memory=10g \
  -p 127.0.0.1:20128:20128 -v omniroute-data:/app/data diegosouzapw/omniroute:latest
```

முழு அட்டவணை: [Docker வழிகாட்டி — இயக்கநேர RAM](docs/guides/DOCKER_GUIDE.md#runtime-ram-for-coding-agents).

**🥟 Bun**

Bun runtime கண்டறிதல் மூலம் வழக்கமான `bun install` மற்றும் global நிறுவல் (`bun install -g omniroute`) ஆதரிக்கப்படுகின்றன:

- **உள்ளமைந்த `bun:sqlite`**: Bun-ன் கீழ் இயங்கும்போது, OmniRoute அதன் உள்ளமைந்த `bun:sqlite` driver-ஐப் பயன்படுத்துகிறது; Node.js-ல் `better-sqlite3` அல்லது `sql.js`-க்கு fallback செய்கிறது.
- **dev-ல் தானியங்கி Webpack bundler தேர்வு**: Development (`bun run dev`) தானாகவே Bun-ஐக் கண்டறிந்து, native V8 binding இணக்கமின்மைகளைத் தடுக்க Turbopack-ஐ முடக்கி Webpack-ஐப் பயன்படுத்துகிறது. Production build-கள் (`bun run build`), Node-ஐப் போலவே `OMNIROUTE_USE_TURBOPACK`-ஐத் துல்லியமாகப் பின்பற்றுகின்றன: இயல்புநிலையாக Turbopack; Webpack மூலம் build செய்ய `OMNIROUTE_USE_TURBOPACK=0` (`Dockerfile.bun` இதை `--build-arg` ஆக வழங்குகிறது).
- **Bun-க்கெனத் தனிப்பட்ட Dockerfile**: Native Bun production deployment-களுக்கான multi-stage `Dockerfile.bun` (`docker build -f Dockerfile.bun -t omniroute:bun .`).

நிறுவலுக்குப் பிந்தைய native warm-up-ஐ முழுமையாகத் தவிர்க்க (CI, headless அல்லது மெதுவான கணினிகள்):

```bash
OMNIROUTE_SKIP_POSTINSTALL=1 npm install -g omniroute   # CI=1 என்பதும் இதைத் தவிர்க்கும்
```

மிக வேகமான நிறுவல்களுக்கு **pnpm**-ஐப் பயன்படுத்தவும் (content-addressed store + hard link-கள் — மேலே பார்க்கவும்).
Dashboard இல்லாத headless runtime-க்கு Docker `base` profile-ஐ (மேலே) அல்லது
[Termux வழிகாட்டியை](docs/guides/TERMUX_GUIDE.md) பயன்படுத்தவும். CLI மற்றும் web dashboard ஆகியவை ஒரே process மூலம்
ஒரே port-ல் வழங்கப்படுகின்றன; எனவே தற்போது தனியான CLI-only package இல்லை.

### எவ்வாறு பங்களிப்பது

1. களஞ்சியத்தை fork செய்யவும்
2. **செயலில் உள்ள** `release/vX.Y.Z` முனையிலிருந்து branch உருவாக்கவும் (`main`-இலிருந்து அல்ல) — [Branching & Release Model](docs/ops/BRANCHING_MODEL.md)-ஐப் பார்க்கவும்
3. உங்கள் அம்சத்திற்கான branch-ஐ உருவாக்கவும் (`git checkout -b feat/amazing-feature`)
4. உங்கள் மாற்றங்களை commit செய்யவும் (`git commit -m 'feat: add amazing feature'`)
5. branch-க்குத் தள்ளவும் (`git push origin feat/amazing-feature`)
6. **base = அந்த `release/vX.Y.Z` branch** என அமைத்து ஒரு Pull Request-ஐத் திறக்கவும்

விரிவான வழிகாட்டுதல்களுக்கு [CONTRIBUTING.md](CONTRIBUTING.md)-ஐப் பார்க்கவும்.
