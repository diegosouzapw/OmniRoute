> தகுதியான சூழலில் தானாகவே 15-95% வரை சேமியுங்கள். விரைவான கண்ணோட்டத்திற்கு, [README சுருக்கப் பகுதியைப்](../README.md#%EF%B8%8F-prompt-compression--save-15-95-eligible-tokens-automatically) பார்க்கவும்.

## கண்ணோட்டம்

OmniRoute, கோரிக்கைகள் மேல்நிலை வழங்குநர்களைச் சென்றடைவதற்கு **முன்கூட்டியே** இயங்கும் ஒரு தொகுதிநிலை prompt சுருக்கச் செயலாக்கத் தொடரை நடைமுறைப்படுத்துகிறது. இதனால் உங்கள் token சேமிப்பு வெளிப்படையாக நடைபெறுகிறது — உங்கள் பணிப்பாய்வில் எந்த மாற்றமும் தேவையில்லை.

```
கிளையன்ட் கோரிக்கை
  → சுருக்க உத்தித் தேர்வி
    → Combo override உள்ளதா? → Combo அமைப்பைப் பயன்படுத்து
    → தானியங்கு தூண்டல் வரம்பா? → Auto பயன்முறையைப் பயன்படுத்து
    → இயல்புநிலை பயன்முறையா? → உலகளாவிய அமைப்பைப் பயன்படுத்து
    → Off-ஆ? → சுருக்கத்தைத் தவிர்
  → தேர்ந்தெடுக்கப்பட்ட சுருக்கப் பயன்முறை
    → Off: சுருக்கம் இல்லை
    → Lite: பாதுகாப்பான இடைவெளி/வடிவமைப்புச் சீரமைப்பு (~15%)
    → Standard: Caveman பாணி நிரப்புச் சொற்களை அகற்றுதல் (~30%)
    → Aggressive: வரலாற்றைப் பழமையாக்குதல் + சுருக்கமாக்குதல் (~50%)
    → Ultra: நுண்ணறிவுசார் களைதல் + code-block மெலிதாக்குதல் (~75%)
    → RTK: கட்டளை-அறிவுள்ள முனையம்/கருவி-வெளியீட்டு வடிகட்டல் (மேல்நிலையில் 60-90% வரம்பு)
    → Stacked: வரிசைப்படுத்தப்பட்ட பல-இயந்திரச் செயலாக்கத் தொடர், வழக்கமாக RTK, பின்னர் Caveman (தகுதியானவற்றில் 78-95% வரம்பு)
  → சுருக்கப்பட்ட கோரிக்கை → வழங்குநர்
```

## சுருக்கப் பயன்முறைகள்

### Off

எந்தச் சுருக்கமும் பயன்படுத்தப்படாது. அனைத்து செய்திகளும் மாற்றமின்றிக் கடந்து செல்கின்றன.

### Lite பயன்முறை (~15% சேமிப்பு, <1ms தாமதம்)

மிகவும் பாதுகாப்பான பயன்முறை — சொற்பொருளில் எந்த மாற்றமும் இல்லை; வடிவமைப்புச் சீரமைப்பு மட்டுமே:

| நுட்பம்                  | விளக்கம்                                                           |
| ------------------------ | ------------------------------------------------------------------ |
| `collapseWhitespace`     | தொடர்ச்சியான வெற்று வரிகளையும் இறுதி இடைவெளிகளையும் ஒன்றிணைக்கிறது |
| `dedupSystemPrompt`      | நகல் system செய்திகளை அகற்றுகிறது                                  |
| `compressToolResults`    | அளவுக்கு அதிகமான tool/function வெளியீடுகளைச் சுருக்குகிறது         |
| `removeRedundantContent` | மீண்டும் இடம்பெறும் அறிவுறுத்தல்களை நீக்குகிறது                    |
| `replaceImageUrls`       | base64 படத் தரவு URI-களைச் சுருக்குகிறது                           |

**மிகவும் பொருத்தமானது:** எப்போதும் இயக்கத்தில் இருக்கும் பயன்பாடு, பாதுகாப்பு-முக்கிய பணிப்பாய்வுகள்.

### Standard பயன்முறை (~30% சேமிப்பு)

[Caveman](https://github.com/JuliusBrussee/caveman)-இன் உந்துதலால் உருவாக்கப்பட்டது — பொருளைத் தக்கவைத்துக்கொண்டு நிரப்புச் சொற்களையும் அளவுக்கு அதிகமான சொற்றொடர்களையும் அகற்றுகிறது:

- நிரப்புச் சொற்களை அகற்றுகிறது ("தயவுசெய்து", "நான் நினைக்கிறேன்", "அடிப்படையில்", "உண்மையில்")
- அளவுக்கு அதிகமான சொற்றொடர்களைச் சுருக்குகிறது ("செய்யும் பொருட்டு" → "செய்ய", "இதன் விளைவாக" → "ஏனெனில்")
- பணிவான தயக்க வெளிப்பாடுகளை நீக்குகிறது ("நீங்கள் செய்வீர்களா...", "உங்களால் ஒருவேளை முடிந்தால்...")
- coding prompt-களுக்காகச் சீரமைக்கப்பட்ட 30+ regex விதிகள்

**மிகவும் பொருத்தமானது:** தினசரி coding பணிப்பாய்வுகள், செலவு குறித்து விழிப்புணர்வுள்ள குழுக்கள்.

### Aggressive பயன்முறை (~50% சேமிப்பு)

நீண்ட அமர்வுகளுக்கான நுண்ணறிவுள்ள வரலாற்று மேலாண்மை:

- **செய்திகளைப் பழமையாக்குதல்** — பழைய செய்திகள் படிப்படியாக அதிகம் சுருக்கப்படுகின்றன
- **Tool முடிவுகளைச் சுருக்கமாக்குதல்** — நீளமான tool வெளியீடுகள் சுருக்கங்களால் மாற்றப்படுகின்றன
- **கட்டமைப்பு ஒருமைப்பாட்டுப் பாதுகாப்புகள்** — `tool_use` + `tool_result` இணைகள் சீராக இருப்பதை உறுதிப்படுத்துகிறது
- **Context Window விழிப்புணர்வு** — ஒவ்வொரு model-க்குமான token வரம்புகளைக் கடைப்பிடிக்கிறது

**மிகவும் பொருத்தமானது:** நீட்டிக்கப்பட்ட debugging அமர்வுகள், பெரிய codebase-கள்.

### Ultra பயன்முறை (~75% சேமிப்பு)

Token மிக முக்கியமான சூழல்களுக்கான அதிகபட்சச் சுருக்கம்:

- **நுண்ணறிவுசார் களைதல்** — தொடர்பு வரம்புக்குக் கீழுள்ள செய்திகளை அகற்றுகிறது
- **Code Block மெலிதாக்குதல்** — மீண்டும் மீண்டும் வரும் code எடுத்துக்காட்டுகளைச் சுருக்குகிறது
- **Binary Search துண்டித்தல்** — context window-க்கான உகந்த வெட்டுப் புள்ளியைக் கண்டறிகிறது
- Aggressive பயன்முறையின் அனைத்து அம்சங்களும் உள்ளடக்கப்பட்டுள்ளன

**மிகவும் பொருத்தமானது:** நீங்கள் மீண்டும் மீண்டும் context வரம்புகளை எட்டும்போது.

### RTK பயன்முறை (மேல்நிலையில் 60-90% வரம்பு)

Coding-agent அமர்வுகளில் தோன்றும் அளவுக்கு அதிகமான tool வெளியீடுகளுக்காக RTK பயன்முறை உகப்பாக்கப்பட்டுள்ளது:

- `git status`, `git diff`, `git log`, test runner-கள்,
  TypeScript/Vite/Webpack build-கள், ESLint/Biome/Prettier, npm audit/install-கள், Docker log-கள், infra
  வெளியீடு மற்றும் பொதுவான shell வெளியீடு போன்ற கட்டளை/வெளியீட்டு வகைகளைக் கண்டறிகிறது
- `open-sse/services/compression/engines/rtk/filters/`-இலிருந்து JSON filter pack-களைப் பயன்படுத்துகிறது
- Project அல்லது global `filters.toml` கோப்புகளிலிருந்து RTK TOML schema v1 filter-களை, inline-test
  சரிபார்ப்பு மற்றும் project கோப்புகளுக்கான நம்பிக்கை-கட்டுப்பாட்டுடன் import செய்கிறது
- Inline verify மாதிரிகளுடன் 49 உள்ளமைந்த filter-களை வழங்குகிறது
- ANSI கட்டுப்பாட்டுத் தொடர்கள், முன்னேற்றப் பட்டைகள், மீண்டும் வரும் வரிகள் மற்றும் செயல்படுத்த முடியாத தேவையற்ற தகவல்களை அகற்றுகிறது
- தோல்விகள், பிழைகள், எச்சரிக்கைகள், மாற்றப்பட்ட கோப்புகள், சுருக்கங்கள் மற்றும் நீண்ட வெளியீட்டின் இறுதிப் பகுதியைப் பாதுகாக்கிறது
- நம்பிக்கை-கட்டுப்பாடுள்ள project filter-கள், global filter-கள் மற்றும் விருப்பத்திற்குரிய மறைக்கப்பட்ட மூல-வெளியீட்டு மீட்பை ஆதரிக்கிறது

**மிகவும் பொருத்தமானது:** Shell, build, test, git, grep மற்றும் file-output பதிவுகளைக் கொண்ட agent அமர்வுகள்.

### Stacked பயன்முறை (தகுதியானவற்றில் 78-95% வரம்பு)

Stacked பயன்முறை பல சுருக்க இயந்திரங்களைத் தீர்மானிக்கப்பட்ட வரிசையில் இயக்குகிறது. இயல்புநிலைச் செயலாக்கத் தொடர்:

```txt
RTK -> Caveman
```

இந்த வரிசை முதலில் terminal/tool வெளியீட்டைச் சுருக்கமாக வைத்திருந்து, பின்னர் மீதமுள்ள இயல்மொழி prompt-க்கு Caveman சொற்பொருள் சுருக்கத்தைப் பயன்படுத்துகிறது. Stacked செயலாக்கத் தொடர்களை உலகளாவிய முறையிலோ அல்லது routing combo-க்களுக்கு ஒதுக்கப்பட்ட compression combo-க்கள் மூலமாகவோ உள்ளமைக்கலாம்.

**மிகவும் பொருத்தமானது:** பெரிய tool log-களுடன் மனித அறிவுறுத்தல்கள் அல்லது assistant சுருக்கங்களும் கலந்த சூழல்.

## அப்ஸ்ட்ரீம் சேமிப்புக் கணக்கீடு

OmniRoute இரண்டு மூலங்களிலிருந்து கிடைக்கும் சுருக்கச் சேமிப்புகளை ஆவணப்படுத்துகிறது: அப்ஸ்ட்ரீம் திட்ட அளவுகோல்கள் மற்றும்
OmniRoute-இன் சொந்த எஞ்சின் ஒருங்கிணைப்பு.

| மூலம்   | இங்கே பயன்படுத்தப்பட்ட அப்ஸ்ட்ரீம் README எண்                                                                                                  |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Caveman | `~75%` குறைவான வெளியீட்டு டோக்கன்கள், அளவுகோல் சராசரி வெளியீட்டுச் சேமிப்பு `65%`, வரம்பு `22-87%`, மற்றும் உள்ளீட்டுச் சுருக்கக் கருவி `~46%` |
| RTK     | கட்டளை வெளியீட்டில் `60-90%` சேமிப்பு; மாதிரி அமர்வில் `~118,000 -> ~23,900` டோக்கன்கள், அதாவது `79.7%` சேமிப்பு (`~80%`)                      |

ஒன்றோடொன்று மேலெழும் கருவி/சூழல் பேலோடுகளுக்கு, இயல்புநிலை OmniRoute சேர்க்கை எஞ்சின்களை இவ்வாறு அடுக்குகிறது:

```txt
RTK -> Caveman
```

ஒருங்கிணைந்த சேமிப்புகள் கூட்டல் முறையிலானவை அல்ல, பெருக்கல் முறையிலானவை:

```txt
combined = 1 - (1 - RTK சேமிப்பு) * (1 - Caveman உள்ளீட்டுச் சேமிப்பு)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

RTK மற்றும் Caveman இரண்டும் ஒரே உள்ளீடு/சூழல் பேலோடைக் குறைக்கக்கூடியபோது அந்த `78-95%` எண் பொருந்தும்.
Caveman மறுமொழி வெளியீட்டு முறை தனியானது: அது இயக்கப்பட்டிருக்கும்போது, Caveman-இன் சொந்த வெளியீட்டுச் சேமிப்புகளைப் பயன்படுத்தவும் (`65%`
சராசரி, `~75%` முதன்மைக் குறிப்பு, `22-87%` வரம்பு). மொத்த பில்லிங் சேமிப்பு உங்கள் ப்ராம்ப்ட்/வெளியீட்டு விகிதத்தைப் பொறுத்தது.

### "தகுதியானது" என்பது உண்மையில் எதைக் குறிக்கிறது

15-95% என்ற முதன்மைக் குறிப்பு உண்மையானது, ஆனால் அது **தேவையற்ற மறுபடியும் இடம்பெறும் அல்லது அளவுக்கு அதிகமான** உள்ளடக்கத்திற்கு மட்டுமே பொருந்தும் — மீண்டும் மீண்டும் வரும்
பிழை வரிகள், அதே எச்சரிக்கையைத் தொடர்ந்து வெளியிடும் பில்ட் பதிவு, அளவுக்கு அதிகமான `grep`/கோப்பு-வாசிப்பு டம்ப் போன்றவை. ஒவ்வொரு கோரிக்கையிலும் அவ்வளவு சேமிப்பு கிடைக்கும்
என்று அது பொருள்படாது.

செயல்முறையில் சரிபார்க்கப்பட்டது (`tests/unit/compression/stacked-compression-tool-result-savings.test.ts`): ஒரே மாதிரியான 300
பிழை வரிகளைக் கொண்ட Anthropic-வடிவ `tool_result` தொகுதியின் மீது இயக்கப்பட்ட ஒரு `stacked` (RTK + Caveman) செயல்பாடு
**95.93% டோக்கன் சேமிப்பு / 96.26% எழுத்துச் சேமிப்பு** வழங்கியது — விளம்பரப்படுத்தப்பட்ட வரம்பிற்குள் துல்லியமாக உள்ளது.
ஆனால் இயல்பான, மறுபடியும் வராத கருவி வெளியீட்டின் மீது (தெளிவான `grep` பொருத்தப் பட்டியல்,
குறுகிய கோப்பு வாசிப்பு, வழக்கமான உரையாடல் உரை) அதே பைப்லைனை இயக்கும்போது, அது சரியாகவே **கிட்டத்தட்ட பூஜ்ஜிய சேமிப்பையே** வழங்குகிறது, ஏனெனில்
நீக்குவதற்கு மீளுரைகள் எதுவும் இல்லை; மேலும் கோட் பிளாக்குகள், URL-கள், தலைப்புகள், பதிப்புகள் அல்லது முழுவதும் பெரிய எழுத்திலான மாறிலி அடையாளங்காட்டிகளை நீக்கவோ மாற்றவோ செய்யும்
மறுஎழுத்தாக்கத்தை அனுப்ப `validateCompression()` (`validation.ts`) மறுக்கிறது.

இது எதிர்பார்க்கப்பட்ட, பாதுகாப்பான நடத்தை; பிழை அல்ல: சுருக்கம் முழுமையாக இயக்கப்பட்டிருந்தாலும், பெரும்பாலும் சுத்தமான கோப்புகளை வாசிக்கும்/grep செய்யும் ஒரு கோடிங் அமர்வு
மிதமான மொத்தச் சேமிப்பையே காணும்; அதே சமயம் தோல்வியுறும் லூப் அல்லது அதிகமாகப் பதிவிடும் லிண்டரை எதிர்கொள்ளும் அமர்வு, அந்தப் போக்குவரத்தில்
முழு 78-95% வரம்பையும் காணும். ஒரே அமர்வின் குறைந்த மொத்தச் சேமிப்பு சதவீதத்தை வைத்து சுருக்கம் தவறாக உள்ளமைக்கப்பட்டுள்ளதாகக் கருத வேண்டாம் — முதலில்
அடிப்படைக் கருவி வெளியீடு உண்மையில் தேவையற்ற மறுபடியும் இடம்பெற்றதா என்பதைச் சரிபார்க்கவும்.

## கட்டமைப்பு

### டாஷ்போர்டு

`Dashboard → Context & Cache` என்பதற்குச் செல்லவும்:

- **கேவ்மேன்** — பயன்முறைத் தேர்வு, மொழிப் பொதிகள், முன்னோட்டம் மற்றும் உலகளாவிய இயல்புநிலைகள்
- **RTK** — கட்டளை-வடிகட்டி முன்னோட்டம், RTK பாதுகாப்பு அமைப்புகள் மற்றும் வடிகட்டி பட்டியல்
- **சுருக்கக் காம்போக்கள்** — ரூட்டிங் காம்போக்களுக்கு ஒதுக்கப்பட்ட பெயரிடப்பட்ட எஞ்சின் பைப்லைன்கள்
- **தானியங்கு-தூண்டுதல் வரம்பு** — டோக்கன் எண்ணிக்கை வரம்பை மீறும்போது தானாகவே சுருக்கத்தை செயல்படுத்தும்

### காம்போவுக்கு ஒரு மேலெழுதல்

`Dashboard → Context & Cache → Compression Combos` இல், ஒரு ரூட்டிங் காம்போவுக்கு ஒரு சுருக்கக் காம்போவை ஒதுக்கவும்:

```txt
Combo: "free-tier-fallback"
  Compression Combo: "coding-agent-stack"
  Pipeline: RTK -> Caveman
  Targets:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

இது இலவச/குறியீட்டு வழங்குநர்களில் அடுக்கப்பட்ட சுருக்கத்தைப் பயன்படுத்தவும், அதே நேரத்தில் கட்டணச் சந்தாக்களில் லைட் பயன்முறையை வைத்திருக்கவும் உங்களை அனுமதிக்கிறது.

இந்த "காம்போவுக்கு ஒரு மேலெழுதல்" ஒதுக்கீடு, ரூட்டிங்-காம்போ சுருக்கப் பயன்முறை மேலெழுதலில் (Default/Off/Lite/Standard/Aggressive/Ultra) இருந்து வேறுபட்ட கட்டுப்பாடு ஆகும் — அந்த மேலெழுதல் ஒரு பெயரிடப்பட்ட சுருக்க-காம்போ பைப்லைனைத் தேர்ந்தெடுக்காது; அது `resolveCompressionPlan` ஆல் கலந்தாலோசிக்கப்படும் `compressionMode` புலத்தை மட்டுமே அமைக்கிறது. இதை காம்போ கார்டில் (`Dashboard → Combos`) அல்லது, #6760 முதல், மேலே ஆவணப்படுத்தப்பட்ட பைப்லைன்-ஒதுக்கீட்டு தேர்வுப்பெட்டிக்கு அடுத்ததாக, `Dashboard → Context & Cache → Compression Combos` இல் உள்ள "Assign to routing" பட்டியலில் ஒவ்வொரு ரூட்டிங் காம்போவிற்கும் அமைக்கலாம். இரண்டு மேற்பரப்புகளும் ஒரே `PUT /api/combos/{id}` எண்ட்பாயிண்ட் மூலம் நிலைத்திருக்கும்.

### ஒரு-கோரிக்கை மேலெழுதல்

ஒரு கோரிக்கைக்கான சுருக்கத் திட்டத்தை மேலெழுத `x-omniroute-compression` கோரிக்கை ஹெடரை அனுப்பவும். இதற்கு மிக உயர்ந்த முன்னுரிமை உள்ளது — இது ரூட்டிங்-காம்போ மேலெழுதல், செயலில் உள்ள சுயவிவரம், தானியங்கு-தூண்டுதல் மற்றும் பேனல் இயல்புநிலை ஆகியவற்றை மிஞ்சும். அறியப்படாத மதிப்புகள் புறக்கணிக்கப்படும் (கோரிக்கை ஒருபோதும் நிராகரிக்கப்படாது) மற்றும் உலகளாவிய மாஸ்டர் சுவிட்ச் இன்னும் அனைத்தையும் கட்டுப்படுத்துகிறது: உலகளவில் சுருக்கம் முடக்கப்பட்டிருக்கும் போது, ஹெடர் அதை இயக்க முடியாது. மதிப்புகள்:

| Value         | Effect                                                                                                                                   |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `off`         | இந்தக் கோரிக்கைக்கு சுருக்கம் இல்லை.                                                                                                     |
| `default`     | பேனலில் இருந்து பெறப்பட்ட இயல்புநிலை சுயவிவரம் (செயலில் உள்ள சுயவிவரத்தைப் புறக்கணிக்கிறது). இழப்புள்ள எஞ்சின்கள் முடக்கப்பட்டிருக்கும். |
| `safe`        | ஹெடரைத் தவிர்ப்பது போன்றது: நகல் நீக்கம் மற்றும் வெற்று இடங்களைச் சுருக்குதல் மட்டுமே.                                                   |
| `allow-lossy` | சுருக்கங்கள், பொருத்தமான வடிப்பான்கள் மற்றும் ஸ்டைல் மறுஎழுத்துகள் உட்பட இந்தக் கோரிக்கையின் ஆப்பரேட்டர் திட்டத்தை வைத்திருங்கள்.        |
| `engine:<id>` | செயல்படுத்தப்படும்போது ஒரு ஒற்றை எஞ்சின், எ.கா. `engine:rtk`. இது அந்த எஞ்சினுக்கான ஒரு-கோரிக்கை விருப்பத் தேர்வு.                       |
| `<combo>`     | ஒரு பெயரிடப்பட்ட காம்போ, முதலில் பெயர் (கேஸ்-சென்சிட்டிவ் அல்லாதது) மூலம், பின்னர் ஐடி மூலம் பொருத்தப்படும்.                             |

`allow-lossy`, `engine:<id>`, அல்லது ஒரு பெயரிடப்பட்ட காம்போ இல்லாமல், இழப்புள்ள எஞ்சின்கள் பயன்படுத்தப்படாது. சுருக்கம் இயக்கப்பட்டிருக்கும் போது கோரிக்கை இன்னும் செஷன் நகல் நீக்கம் மற்றும் வெற்று இடங்களைச் சுருக்குதலைப் பெறும்.

பயன்படுத்தப்பட்ட திட்டம் `X-OmniRoute-Compression: <mode>; source=<source>` மறுமொழி ஹெடரில் எதிரொலிக்கப்படும், இங்கு `<source>` என்பது `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default`, அல்லது `off` இவற்றில் ஒன்றாகும்.

### API

```bash
# Get compression settings
curl http://localhost:20128/api/settings/compression

# Update compression settings
curl -X PUT http://localhost:20128/api/settings/compression \
  -H "Content-Type: application/json" \
  -d '{"defaultMode":"stacked","autoTriggerMode":"stacked","autoTriggerTokens":32000}'

# Preview a specific RTK/stacked payload
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{"mode":"rtk","messages":[{"role":"tool","content":"npm test output here"}]}'

# List RTK filter packs
curl http://localhost:20128/api/context/rtk/filters

# Test RTK directly with optional command metadata
curl -X POST http://localhost:20128/api/context/rtk/test \
  -H "Content-Type: application/json" \
  -d '{"command":"npm test","text":"FAIL tests/example.test.ts\nError: boom"}'
```

## மேம்பட்ட சுருக்க அமைப்புகள்

7 நிலையான முறைகளுக்கு அப்பால், OmniRoute ஆனது சூழலின் அடிப்படையில் தானாகவே செயல்படும் பல மேம்பட்ட சுருக்க அமைப்புகளை உள்ளடக்கியுள்ளது.

### தற்காலிக சேமிப்பு-அறி சுருக்கம்

சில வழங்குநர்கள் (Anthropic போன்றவர்கள், தூண்டுதல் தற்காலிக சேமிப்புடன்) **தூண்டுதல் தற்காலிக சேமிப்பை** ஆதரிக்கிறார்கள், இது செலவுகளையும் தாமதத்தையும் குறைக்க தூண்டுதலின் பகுதிகளை தற்காலிகமாக சேமிக்க அனுமதிக்கிறது. தற்காலிக சேமிப்பு இயக்கப்பட்டிருக்கும்போது, தீவிர சுருக்கம் உண்மையில் செயல்திறனை **பாதிக்கலாம்**, ஏனெனில் இது தற்காலிகமாக சேமிக்கப்பட்ட டோக்கன்களை மாற்றுகிறது, தற்காலிக சேமிப்பை செல்லாததாக்குகிறது.

`cachingAware.ts` தொகுதி இதை **தற்காலிக சேமிப்பு சூழலைக் கண்டறிந்து** அதற்கேற்ப **சுருக்க உத்தியைச் சரிசெய்வதன்** மூலம் தீர்க்கிறது.

#### இது எவ்வாறு செயல்படுகிறது

1. **தற்காலிக சேமிப்பு சூழலைக் கண்டறிதல்** — `cache_control` குறிப்பான்களுக்காக கோரிக்கை உடலை ஸ்கேன் செய்கிறது
2. **தற்காலிக சேமிப்பு வழங்குநர்களை அடையாளம் காணுதல்** — இலக்கு வழங்குநர் தற்காலிக சேமிப்பை ஆதரிக்கிறாரா என்று சரிபார்க்கிறது
3. **உத்தியைச் சரிசெய்தல்** — தற்காலிக சேமிப்பு வழங்குநர்களுக்கான `aggressive`/`ultra` முறைகளை `standard` ஆகத் தரமிறக்குகிறது
4. **கணினி தூண்டுதலைத் தவிர்த்தல்** — கணினி தூண்டுதல்கள் பொதுவாக தற்காலிகமாக சேமிக்கப்படும், எனவே அவற்றைச் சுருக்க வேண்டாம்
5. **நிர்ணயிக்கப்பட்ட மாற்றங்களைப் பயன்படுத்துதல்** — நிலையான வெளியீட்டை உருவாக்கும் மாற்றங்களை மட்டுமே பயன்படுத்துங்கள்

#### குறியீடு எடுத்துக்காட்டு

```ts
import {
  detectCachingContext,
  getCacheAwareStrategy,
} from "@omniroute/open-sse/services/compression/cachingAware";

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← தற்காலிக சேமிப்பு குறிப்பான்
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### எப்போது பயன்படுத்த வேண்டும்

தற்காலிக சேமிப்பு-அறி சுருக்கம் **எப்போதும் இயங்கும்** — எந்த உள்ளமைவும் தேவையில்லை. இது பின்வரும் சமயங்களில் மட்டுமே செயல்படும்:

- கோரிக்கையில் `cache_control` குறிப்பான்கள் உள்ளன
- இலக்கு வழங்குநர் தூண்டுதல் தற்காலிக சேமிப்பை ஆதரிக்கிறார் (Anthropic, OpenAI, போன்றவை)

### முற்போக்கான வயதாதல்

நீண்ட உரையாடல்கள் பல செய்தி திருப்பங்களை குவிக்கும், ஆனால் பழைய திருப்பங்கள் குறைவான பொருத்தமானதாக மாறும். `progressiveAging.ts` தொகுதி **திருப்பங்களின் தூரத்தின் அடிப்படையில் செய்திகளைத் தரமிறக்குகிறது**:

- **சமீபத்திய திருப்பங்கள் (0-3)**: வார்த்தைக்கு வார்த்தை வைக்கப்படும் (முழு விவரம்)
- **நடுத்தர திருப்பங்கள் (4-8)**: லைட் சுருக்கம் (வெற்று இடங்கள், வடிவமைப்பு சுத்தம்)
- **பழைய திருப்பங்கள் (9+)**: குகை மனிதன் சுருக்கம் (நிரப்பிகளை நீக்குதல், சுருக்கம்)
- **மிகப் பழைய திருப்பங்கள் (20+)**: அதிகமாக சுருக்கப்படும் அல்லது கைவிடப்படும்

#### குறியீடு எடுத்துக்காட்டு

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... 50 more turns ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // முதல் 3 திருப்பங்கள்: வார்த்தைக்கு வார்த்தை
  light: 8, // திருப்பங்கள் 4-8: லைட் சுருக்கம்
  moderate: 20, // திருப்பங்கள் 9-20: குகை மனிதன் சுருக்கம்
  // திருப்பங்கள் 21+: அதிக சுருக்கம்
});

// saved = சேமிக்கப்பட்ட டோக்கன்களின் எண்ணிக்கை
```

#### எப்போது பயன்படுத்த வேண்டும்

முற்போக்கான வயதாதல் ஆனது `aggressive` மற்றும் `ultra` முறைகளுக்கு **எப்போதும் இயங்கும்**. இது குறிப்பாக இதற்கு பயனுள்ளதாக இருக்கும்:

- நீண்ட நேரம் இயங்கும் குறியீட்டு அமர்வுகள்
- பல நாள் உரையாடல்கள்
- பல கருவி அழைப்புகளுடன் கூடிய முகவர் பணிப்பாய்வுகள்

### குகை மனிதன் வெளியீட்டு முறை

`outputMode.ts` தொகுதி **கணினி தூண்டுதல் வழிமுறைகளை** செலுத்துகிறது, இது மாதிரியே சுருக்கப்பட்ட, சுருக்கமான வெளியீட்டை (ஒரு "குகை மனிதன்" பாணி) உருவாக்கச் செய்கிறது.

#### இது எவ்வாறு செயல்படுகிறது

உள்ளீட்டைச் சுருக்குவதற்குப் பதிலாக, இந்த முறை இது போன்ற ஒரு கணினி தூண்டுதலைச் சேர்க்கிறது:

> "குறைந்த வார்த்தைகளில் பதிலளிக்கவும். மரியாதையான வார்த்தைகளைத் தவிர்க்கவும். குறுகிய வாக்கியங்களைப் பயன்படுத்தவும்."

இது குறிப்பாக இதற்கு நன்றாக வேலை செய்கிறது:

- குறியீடு உருவாக்கம் (சுருக்கமான வெளியீடு = குறைவான டோக்கன்கள்)
- விரைவான கேள்வி பதில் (விரிவான விளக்கங்கள் தேவையில்லை)
- தொகுப்பு செயலாக்கம் (செயல்திறனை அதிகரிக்க)

#### எப்போது பயன்படுத்த வேண்டும்

குகை மனிதன் வெளியீட்டு முறை **தேர்வு செய்யக்கூடியது** — காம்ப்ளக்ஸ் உள்ளமைவு மூலம் இதை அமைக்கவும்:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "outputMode": "caveman"
    }
  }
}
```

### வெளியீட்டு பாணிகள் (பட்டியல்)

மேலே உள்ள குகை மனிதன் வெளியீட்டு முறை என்பது **பாரம்பரிய ஒற்றை-பாணி பாதை** ஆகும். கட்டம் 4 ஆனது இதை தொகுக்கக்கூடிய வெளியீட்டு பாணிகளின் பட்டியலாக பொதுமைப்படுத்தியது: `open-sse/services/compression/outputStyles/catalog.ts` இல் `OUTPUT_STYLE_CATALOG`. ஒவ்வொரு பாணியும் ஒரு கணினி-தூண்டுதல் அறிவுறுத்தலாகும், இது மாதிரியே குறைந்த செலவில் வெளியீட்டை உருவாக்கச் செய்கிறது; பாணிகளை ஒன்றாக இயக்கலாம் மற்றும் பட்டியல் வரிசையில் செலுத்தப்படும்.

பிழை சரங்கள், URLகள் மற்றும் அடையாளங்காட்டிகளை அப்படியே வைத்திருக்கிறது.

#### ஊசி எவ்வாறு செயல்படுகிறது

`applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`) ஆனது
தேர்வை அட்டவணைக்கு எதிராகத் தீர்க்கிறது (அறியப்படாத ஐடிகள் மற்றும் உள்ளூர்-பொருந்தாத பாணிகள்
கைவிடப்படுகின்றன, ஒருபோதும் பிழை இல்லை), தேர்ந்தெடுக்கப்பட்ட வழிமுறைகளை அட்டவணை வரிசையில் இணைக்கிறது,
எல்லைகள் உட்பிரிவை **ஒருமுறை** சேர்க்கிறது, மேலும் ஒரு ஒற்றை ஐடெம்போடென்சி மார்க்கருக்குப் பின்னால்
கணினி ப்ராம்ப்டில் முடிவை முன்-ஏற்றுகிறது (`[OmniRoute Output Styles]`) — மீண்டும் பயன்படுத்துவது
ஒரு நோ-ஆப் ஆகும். கண்டறியப்பட்ட கோரிக்கை மொழிக்கு ஒரு மொழிபெயர்ப்பு இருக்கும்போது,
உள்ளூர்மயமாக்கப்பட்ட அறிவுறுத்தல் ஆங்கிலத்திற்குப் பதிலாக செலுத்தப்படுகிறது.

#### எவ்வாறு இயக்குவது

டாஷ்போர்டில்: **Context → Settings → Compression** — ஒவ்வொரு பாணிக்கும் ஒரு வரிசை,
ஆன்/ஆஃப் டோகிள் மற்றும் ஒரு நிலை தேர்வாளர். நிரல்ரீதியாக, சுருக்க உள்ளமைவு
தேர்வை இவ்வாறு நிலைநிறுத்துகிறது:

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

பின்னோக்கிய இணக்கம்: மரபுவழி `outputMode: "caveman"` காம்போ அமைப்பு இன்னும் வேலை செய்கிறது மற்றும்
`terse-prose` க்கு மேப் செய்கிறது, ஒவ்வொரு மரபுவழி மொழியிலும் பழைய ஊசிக்கு பைட்டு-ஒரே மாதிரியாக இருக்கும்.

மொழித் தேர்வு: `languageConfig.enabled` இயக்கப்பட்டிருக்கும்போது, `autoDetect`
சமீபத்திய பயனர் செய்தியின் மொழியைத் தேர்ந்தெடுக்கிறது (உள்ளீட்டு இயந்திரங்களைப் போலவே அதே கண்டறிதல்);
`autoDetect` ஐ அணைப்பது `defaultLanguage` ஐப் பின்கள் செய்கிறது. ஆஃப் → ஆங்கிலம்.

பாணி × மொழி அணி
`tests/unit/compression/output-styles-i18n-matrix.test.ts` ஆல் பின் செய்யப்பட்டுள்ளது:
குறைந்தபட்சம் ஒரு pt-BR மொழிபெயர்ப்பு (அல்லது ஒரு வெளிப்படையான கண்காணிக்கப்பட்ட விதிவிலக்கு) இல்லாமல்
ஒரு புதிய பாணியை அனுப்ப முடியாது, மேலும் ஒரு இருக்கும் பாணி ஒரு உள்ளூர்மயமாக்கலை அமைதியாக இழக்க முடியாது.
ஒரு பாணியைச் சேர்க்க, [EXTENDING_COMPRESSION.md](./EXTENDING_COMPRESSION.md#adding-an-output-style) ஐப் பார்க்கவும்.

### கருவி முடிவு சுருக்கம்

`toolResultCompressor.ts` தொகுதி கருவி முடிவுகளுக்கான (செயல்பாட்டு அழைப்புகள், முகவர் வெளியீடுகள், தேடல் முடிவுகள் போன்றவை)
**5 சிறப்பு சுருக்க உத்திகளை** வழங்குகிறது:

1. **தேடல் முடிவு சுருக்கம்** — தேவையற்ற முடிவுகளை நீக்குகிறது, முதல்-N ஐ வைத்திருக்கிறது
2. **கோப்பு படிப்பு சுருக்கம்** — பெரிய கோப்புகளை சுருக்குகிறது, தலைப்புகள்/இறக்குமதிகளைப் பாதுகாக்கிறது
3. **குறியீடு செயலாக்க சுருக்கம்** — அத்தியாவசிய stdout/stderr ஐ மட்டுமே வைத்திருக்கிறது
4. **தரவுத்தள வினவல் சுருக்கம்** — வரிசைகளைக் கட்டுப்படுத்துகிறது, விரிவான மெட்டாடேட்டாவை நீக்குகிறது
5. **API பதில் சுருக்கம்** — பூஜ்ய புலங்களை நீக்குகிறது, வரிசைகளை சுருக்குகிறது

#### எப்போது பயன்படுத்த வேண்டும்

கருவி அழைப்புகள் இருக்கும்போது கருவி முடிவு சுருக்கம் **எப்போதும் இயக்கத்தில் இருக்கும்**.
எந்த உள்ளமைவும் தேவையில்லை.

### அடுக்கப்பட்ட பைப்லைன்

அடுக்கப்பட்ட முறை **பல இயந்திரங்களை வரிசையாக** இயக்குகிறது — பொதுவாக RTK முதலில்
(கருவி வெளியீட்டில் 60-90% சேமிப்பு), பின்னர் கேவ்மேன் (மீதமுள்ள உரையில் 30% கூடுதல் சேமிப்பு).
இது **மொத்தமாக 78-95% சேமிப்பை** அடைகிறது.

#### இது எவ்வாறு செயல்படுகிறது

```
உள்ளீடு (1000 டோக்கன்கள்)
  → RTK (கட்டளை-அறிவார்ந்த வடிகட்டி) → 200 டோக்கன்கள்
    → கேவ்மேன் (நிரப்பு நீக்கம்) → 140 டோக்கன்கள்
  → வெளியீடு (140 டோக்கன்கள், 86% சேமிப்பு)
```

#### எப்போது பயன்படுத்த வேண்டும்

அடுக்கப்பட்ட பயன்முறையை இதற்குப் பயன்படுத்தவும்:

- கருவி-அதிகமான பணிப்பாய்வுகள் (முகவர் குறியீட்டு முறை, ஆராய்ச்சி)
- செலவு-உணர்திறன் கொண்ட தொகுதி செயலாக்கம்
- அதிகபட்ச டோக்கன் சேமிப்பு தேவைப்படும்போது

காம்போ வழியாக உள்ளமைக்கவும்:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "modePack": "stacked"
    }
  }
}
```

## கம்ப்ரெஷன் காம்போ மேலெழுதல்கள்

வெவ்வேறு பயன்பாட்டு நிலைகளுக்கான செயல்பாட்டை நுணுக்கமாகச் சரிசெய்ய, உலகளாவிய கம்ப்ரெஷன் பயன்முறையை **ஒவ்வொரு காம்போவிற்கும் தனித்தனியாக** மேலெழுதலாம்:

