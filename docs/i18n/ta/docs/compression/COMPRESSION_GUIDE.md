> தகுதியான சூழலில் தானாகவே 15-95% வரை சேமியுங்கள். விரைவான கண்ணோட்டத்திற்கு, [README சுருக்கப் பகுதியைப்](../README.md#%EF%B8%8F-prompt-compression--save-15-95-eligible-tokens-automatically) பார்க்கவும்.

## கண்ணோட்டம்

OmniRoute, கோரிக்கைகள் மேல்நிலை வழங்குநர்களைச் சென்றடைவதற்கு **முன்கூட்டியே** இயங்கும் ஒரு தொகுதிநிலை prompt சுருக்கச் செயலாக்கத் தொடரை நடைமுறைப்படுத்துகிறது. இதனால் உங்கள் token சேமிப்பு வெளிப்படையாக நடைபெறுகிறது — உங்கள் பணிப்பாய்வில் எந்த மாற்றமும் தேவையில்லை.

```
கிளையன்ட் கோரிக்கை
  → சுருக்க உத்தித் தேர்வி
    → Combo override உள்ளதா? → Combo அமைப்பைப் பயன்படுத்து
    → தானியங்கு தூண்டல் வரம்பா? → Auto பயன்முறையைப் பயன்படுத்து
    → இயல்புநிலை பயன்முறையா? → உலகளாவிய அமைப்பைப் பயன்படுத்து
    → Off-ஆ? → சுருக்கத்தைத் தவிர்
  → தேர்ந்தெடுக்கப்பட்ட சுருக்கப் பயன்முறை
    → Off: சுருக்கம் இல்லை
    → Lite: பாதுகாப்பான இடைவெளி/வடிவமைப்புச் சீரமைப்பு (~15%)
    → Standard: Caveman பாணி நிரப்புச் சொற்களை அகற்றுதல் (~30%)
    → Aggressive: வரலாற்றைப் பழமையாக்குதல் + சுருக்கமாக்குதல் (~50%)
    → Ultra: நுண்ணறிவுசார் களைதல் + code-block மெலிதாக்குதல் (~75%)
    → RTK: கட்டளை-அறிவுள்ள முனையம்/கருவி-வெளியீட்டு வடிகட்டல் (மேல்நிலையில் 60-90% வரம்பு)
    → Stacked: வரிசைப்படுத்தப்பட்ட பல-இயந்திரச் செயலாக்கத் தொடர், வழக்கமாக RTK, பின்னர் Caveman (தகுதியானவற்றில் 78-95% வரம்பு)
  → சுருக்கப்பட்ட கோரிக்கை → வழங்குநர்
```

## சுருக்கப் பயன்முறைகள்

### Off

எந்தச் சுருக்கமும் பயன்படுத்தப்படாது. அனைத்து செய்திகளும் மாற்றமின்றிக் கடந்து செல்கின்றன.

### Lite பயன்முறை (~15% சேமிப்பு, <1ms தாமதம்)

மிகவும் பாதுகாப்பான பயன்முறை — சொற்பொருளில் எந்த மாற்றமும் இல்லை; வடிவமைப்புச் சீரமைப்பு மட்டுமே:

| நுட்பம்                  | விளக்கம்                                                           |
| ------------------------ | ------------------------------------------------------------------ |
| `collapseWhitespace`     | தொடர்ச்சியான வெற்று வரிகளையும் இறுதி இடைவெளிகளையும் ஒன்றிணைக்கிறது |
| `dedupSystemPrompt`      | நகல் system செய்திகளை அகற்றுகிறது                                  |
| `compressToolResults`    | அளவுக்கு அதிகமான tool/function வெளியீடுகளைச் சுருக்குகிறது         |
| `removeRedundantContent` | மீண்டும் இடம்பெறும் அறிவுறுத்தல்களை நீக்குகிறது                    |
| `replaceImageUrls`       | base64 படத் தரவு URI-களைச் சுருக்குகிறது                           |

**மிகவும் பொருத்தமானது:** எப்போதும் இயக்கத்தில் இருக்கும் பயன்பாடு, பாதுகாப்பு-முக்கிய பணிப்பாய்வுகள்.

### Standard பயன்முறை (~30% சேமிப்பு)

[Caveman](https://github.com/JuliusBrussee/caveman)-இன் உந்துதலால் உருவாக்கப்பட்டது — பொருளைத் தக்கவைத்துக்கொண்டு நிரப்புச் சொற்களையும் அளவுக்கு அதிகமான சொற்றொடர்களையும் அகற்றுகிறது:

- நிரப்புச் சொற்களை அகற்றுகிறது ("தயவுசெய்து", "நான் நினைக்கிறேன்", "அடிப்படையில்", "உண்மையில்")
- அளவுக்கு அதிகமான சொற்றொடர்களைச் சுருக்குகிறது ("செய்யும் பொருட்டு" → "செய்ய", "இதன் விளைவாக" → "ஏனெனில்")
- பணிவான தயக்க வெளிப்பாடுகளை நீக்குகிறது ("நீங்கள் செய்வீர்களா...", "உங்களால் ஒருவேளை முடிந்தால்...")
- coding prompt-களுக்காகச் சீரமைக்கப்பட்ட 30+ regex விதிகள்

**மிகவும் பொருத்தமானது:** தினசரி coding பணிப்பாய்வுகள், செலவு குறித்து விழிப்புணர்வுள்ள குழுக்கள்.

### Aggressive பயன்முறை (~50% சேமிப்பு)

நீண்ட அமர்வுகளுக்கான நுண்ணறிவுள்ள வரலாற்று மேலாண்மை:

- **செய்திகளைப் பழமையாக்குதல்** — பழைய செய்திகள் படிப்படியாக அதிகம் சுருக்கப்படுகின்றன
- **Tool முடிவுகளைச் சுருக்கமாக்குதல்** — நீளமான tool வெளியீடுகள் சுருக்கங்களால் மாற்றப்படுகின்றன
- **கட்டமைப்பு ஒருமைப்பாட்டுப் பாதுகாப்புகள்** — `tool_use` + `tool_result` இணைகள் சீராக இருப்பதை உறுதிப்படுத்துகிறது
- **Context Window விழிப்புணர்வு** — ஒவ்வொரு model-க்குமான token வரம்புகளைக் கடைப்பிடிக்கிறது

**மிகவும் பொருத்தமானது:** நீட்டிக்கப்பட்ட debugging அமர்வுகள், பெரிய codebase-கள்.

### Ultra பயன்முறை (~75% சேமிப்பு)

Token மிக முக்கியமான சூழல்களுக்கான அதிகபட்சச் சுருக்கம்:

- **நுண்ணறிவுசார் களைதல்** — தொடர்பு வரம்புக்குக் கீழுள்ள செய்திகளை அகற்றுகிறது
- **Code Block மெலிதாக்குதல்** — மீண்டும் மீண்டும் வரும் code எடுத்துக்காட்டுகளைச் சுருக்குகிறது
- **Binary Search துண்டித்தல்** — context window-க்கான உகந்த வெட்டுப் புள்ளியைக் கண்டறிகிறது
- Aggressive பயன்முறையின் அனைத்து அம்சங்களும் உள்ளடக்கப்பட்டுள்ளன

**மிகவும் பொருத்தமானது:** நீங்கள் மீண்டும் மீண்டும் context வரம்புகளை எட்டும்போது.

### RTK பயன்முறை (மேல்நிலையில் 60-90% வரம்பு)

Coding-agent அமர்வுகளில் தோன்றும் அளவுக்கு அதிகமான tool வெளியீடுகளுக்காக RTK பயன்முறை உகப்பாக்கப்பட்டுள்ளது:

- `git status`, `git diff`, `git log`, test runner-கள்,
  TypeScript/Vite/Webpack build-கள், ESLint/Biome/Prettier, npm audit/install-கள், Docker log-கள், infra
  வெளியீடு மற்றும் பொதுவான shell வெளியீடு போன்ற கட்டளை/வெளியீட்டு வகைகளைக் கண்டறிகிறது
- `open-sse/services/compression/engines/rtk/filters/`-இலிருந்து JSON filter pack-களைப் பயன்படுத்துகிறது
- Project அல்லது global `filters.toml` கோப்புகளிலிருந்து RTK TOML schema v1 filter-களை, inline-test
  சரிபார்ப்பு மற்றும் project கோப்புகளுக்கான நம்பிக்கை-கட்டுப்பாட்டுடன் import செய்கிறது
- Inline verify மாதிரிகளுடன் 49 உள்ளமைந்த filter-களை வழங்குகிறது
- ANSI கட்டுப்பாட்டுத் தொடர்கள், முன்னேற்றப் பட்டைகள், மீண்டும் வரும் வரிகள் மற்றும் செயல்படுத்த முடியாத தேவையற்ற தகவல்களை அகற்றுகிறது
- தோல்விகள், பிழைகள், எச்சரிக்கைகள், மாற்றப்பட்ட கோப்புகள், சுருக்கங்கள் மற்றும் நீண்ட வெளியீட்டின் இறுதிப் பகுதியைப் பாதுகாக்கிறது
- நம்பிக்கை-கட்டுப்பாடுள்ள project filter-கள், global filter-கள் மற்றும் விருப்பத்திற்குரிய மறைக்கப்பட்ட மூல-வெளியீட்டு மீட்பை ஆதரிக்கிறது

**மிகவும் பொருத்தமானது:** Shell, build, test, git, grep மற்றும் file-output பதிவுகளைக் கொண்ட agent அமர்வுகள்.

### Stacked பயன்முறை (தகுதியானவற்றில் 78-95% வரம்பு)

Stacked பயன்முறை பல சுருக்க இயந்திரங்களைத் தீர்மானிக்கப்பட்ட வரிசையில் இயக்குகிறது. இயல்புநிலைச் செயலாக்கத் தொடர்:

```txt
RTK -> Caveman
```

இந்த வரிசை முதலில் terminal/tool வெளியீட்டைச் சுருக்கமாக வைத்திருந்து, பின்னர் மீதமுள்ள இயல்மொழி prompt-க்கு Caveman சொற்பொருள் சுருக்கத்தைப் பயன்படுத்துகிறது. Stacked செயலாக்கத் தொடர்களை உலகளாவிய முறையிலோ அல்லது routing combo-க்களுக்கு ஒதுக்கப்பட்ட compression combo-க்கள் மூலமாகவோ உள்ளமைக்கலாம்.

**மிகவும் பொருத்தமானது:** பெரிய tool log-களுடன் மனித அறிவுறுத்தல்கள் அல்லது assistant சுருக்கங்களும் கலந்த சூழல்.

## அப்ஸ்ட்ரீம் சேமிப்புக் கணக்கீடு

OmniRoute இரண்டு மூலங்களிலிருந்து கிடைக்கும் சுருக்கச் சேமிப்புகளை ஆவணப்படுத்துகிறது: அப்ஸ்ட்ரீம் திட்ட அளவுகோல்கள் மற்றும்
OmniRoute-இன் சொந்த எஞ்சின் ஒருங்கிணைப்பு.

| மூலம்   | இங்கே பயன்படுத்தப்பட்ட அப்ஸ்ட்ரீம் README எண்                                                                                                  |
| ------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Caveman | `~75%` குறைவான வெளியீட்டு டோக்கன்கள், அளவுகோல் சராசரி வெளியீட்டுச் சேமிப்பு `65%`, வரம்பு `22-87%`, மற்றும் உள்ளீட்டுச் சுருக்கக் கருவி `~46%` |
| RTK     | கட்டளை வெளியீட்டில் `60-90%` சேமிப்பு; மாதிரி அமர்வில் `~118,000 -> ~23,900` டோக்கன்கள், அதாவது `79.7%` சேமிப்பு (`~80%`)                      |

ஒன்றோடொன்று மேலெழும் கருவி/சூழல் பேலோடுகளுக்கு, இயல்புநிலை OmniRoute சேர்க்கை எஞ்சின்களை இவ்வாறு அடுக்குகிறது:

```txt
RTK -> Caveman
```

ஒருங்கிணைந்த சேமிப்புகள் கூட்டல் முறையிலானவை அல்ல, பெருக்கல் முறையிலானவை:

```txt
combined = 1 - (1 - RTK சேமிப்பு) * (1 - Caveman உள்ளீட்டுச் சேமிப்பு)
average  = 1 - (1 - 0.80) * (1 - 0.46) = 89.2%
range    = 1 - (1 - 0.60..0.90) * (1 - 0.46) = 78.4-94.6%
```

RTK மற்றும் Caveman இரண்டும் ஒரே உள்ளீடு/சூழல் பேலோடைக் குறைக்கக்கூடியபோது அந்த `78-95%` எண் பொருந்தும்.
Caveman மறுமொழி வெளியீட்டு முறை தனியானது: அது இயக்கப்பட்டிருக்கும்போது, Caveman-இன் சொந்த வெளியீட்டுச் சேமிப்புகளைப் பயன்படுத்தவும் (`65%`
சராசரி, `~75%` முதன்மைக் குறிப்பு, `22-87%` வரம்பு). மொத்த பில்லிங் சேமிப்பு உங்கள் ப்ராம்ப்ட்/வெளியீட்டு விகிதத்தைப் பொறுத்தது.

### "தகுதியானது" என்பது உண்மையில் எதைக் குறிக்கிறது

15-95% என்ற முதன்மைக் குறிப்பு உண்மையானது, ஆனால் அது **தேவையற்ற மறுபடியும் இடம்பெறும் அல்லது அளவுக்கு அதிகமான** உள்ளடக்கத்திற்கு மட்டுமே பொருந்தும் — மீண்டும் மீண்டும் வரும்
பிழை வரிகள், அதே எச்சரிக்கையைத் தொடர்ந்து வெளியிடும் பில்ட் பதிவு, அளவுக்கு அதிகமான `grep`/கோப்பு-வாசிப்பு டம்ப் போன்றவை. ஒவ்வொரு கோரிக்கையிலும் அவ்வளவு சேமிப்பு கிடைக்கும்
என்று அது பொருள்படாது.

செயல்முறையில் சரிபார்க்கப்பட்டது (`tests/unit/compression/stacked-compression-tool-result-savings.test.ts`): ஒரே மாதிரியான 300
பிழை வரிகளைக் கொண்ட Anthropic-வடிவ `tool_result` தொகுதியின் மீது இயக்கப்பட்ட ஒரு `stacked` (RTK + Caveman) செயல்பாடு
**95.93% டோக்கன் சேமிப்பு / 96.26% எழுத்துச் சேமிப்பு** வழங்கியது — விளம்பரப்படுத்தப்பட்ட வரம்பிற்குள் துல்லியமாக உள்ளது.
ஆனால் இயல்பான, மறுபடியும் வராத கருவி வெளியீட்டின் மீது (தெளிவான `grep` பொருத்தப் பட்டியல்,
குறுகிய கோப்பு வாசிப்பு, வழக்கமான உரையாடல் உரை) அதே பைப்லைனை இயக்கும்போது, அது சரியாகவே **கிட்டத்தட்ட பூஜ்ஜிய சேமிப்பையே** வழங்குகிறது, ஏனெனில்
நீக்குவதற்கு மீளுரைகள் எதுவும் இல்லை; மேலும் கோட் பிளாக்குகள், URL-கள், தலைப்புகள், பதிப்புகள் அல்லது முழுவதும் பெரிய எழுத்திலான மாறிலி அடையாளங்காட்டிகளை நீக்கவோ மாற்றவோ செய்யும்
மறுஎழுத்தாக்கத்தை அனுப்ப `validateCompression()` (`validation.ts`) மறுக்கிறது.

இது எதிர்பார்க்கப்பட்ட, பாதுகாப்பான நடத்தை; பிழை அல்ல: சுருக்கம் முழுமையாக இயக்கப்பட்டிருந்தாலும், பெரும்பாலும் சுத்தமான கோப்புகளை வாசிக்கும்/grep செய்யும் ஒரு கோடிங் அமர்வு
மிதமான மொத்தச் சேமிப்பையே காணும்; அதே சமயம் தோல்வியுறும் லூப் அல்லது அதிகமாகப் பதிவிடும் லிண்டரை எதிர்கொள்ளும் அமர்வு, அந்தப் போக்குவரத்தில்
முழு 78-95% வரம்பையும் காணும். ஒரே அமர்வின் குறைந்த மொத்தச் சேமிப்பு சதவீதத்தை வைத்து சுருக்கம் தவறாக உள்ளமைக்கப்பட்டுள்ளதாகக் கருத வேண்டாம் — முதலில்
அடிப்படைக் கருவி வெளியீடு உண்மையில் தேவையற்ற மறுபடியும் இடம்பெற்றதா என்பதைச் சரிபார்க்கவும்.

## உள்ளமைவு

### டாஷ்போர்டு

`Dashboard → Context & Cache` என்பதற்குச் செல்லவும்:

- **Caveman** — பயன்முறைத் தேர்வு, மொழித் தொகுப்புகள், முன்னோட்டம் மற்றும் உலகளாவிய இயல்புநிலைகள்
- **RTK** — கட்டளை-வடிகட்டி முன்னோட்டம், RTK பாதுகாப்பு அமைப்புகள் மற்றும் வடிகட்டி பட்டியல்
- **Compression Combos** — வழிப்படுத்தல் சேர்க்கைகளுக்கு ஒதுக்கப்பட்ட பெயரிடப்பட்ட எஞ்சின் பைப்லைன்கள்
- **Auto-Trigger Threshold** — டோக்கன் எண்ணிக்கை வரம்பை மீறும்போது தானாகவே சுருக்கத்தைச் செயல்படுத்தும்

### ஒவ்வொரு சேர்க்கைக்குமான மேலெழுதுதல்

`Dashboard → Context & Cache → Compression Combos` என்பதில், ஒரு வழிப்படுத்தல் சேர்க்கைக்கு ஒரு சுருக்கச் சேர்க்கையை ஒதுக்கவும்:

```txt
சேர்க்கை: "free-tier-fallback"
  சுருக்கச் சேர்க்கை: "coding-agent-stack"
  பைப்லைன்: RTK -> Caveman
  இலக்குகள்:
    1. if/kimi-k2.7-code
    2. if/qwen3.8-max-preview
```

கட்டணச் சந்தாக்களில் லைட் பயன்முறையைத் தொடர்ந்து பயன்படுத்திக்கொண்டே, இலவச/குறியீட்டாக்க வழங்குநர்களில் அடுக்கப்பட்ட சுருக்கத்தைப் பயன்படுத்த இது உதவுகிறது.

இந்த "Per-Combo Override" ஒதுக்கீடு, **வழிப்படுத்தல்-சேர்க்கை சுருக்கப் பயன்முறை** மேலெழுதுதலிலிருந்து (Default/Off/Lite/Standard/Aggressive/Ultra) வேறுபட்ட கட்டுப்பாடாகும் — அந்த மேலெழுதுதல் பெயரிடப்பட்ட சுருக்க-சேர்க்கைப் பைப்லைனைத் தேர்ந்தெடுக்காது; `resolveCompressionPlan` பயன்படுத்தும் `compressionMode` புலத்தை மட்டுமே அமைக்கும். இதைச் சேர்க்கை அட்டையிலோ (`Dashboard → Combos`) அல்லது #6760 முதல், மேலே ஆவணப்படுத்தப்பட்டுள்ள பைப்லைன்-ஒதுக்கீட்டுத் தேர்வுப்பெட்டிக்கு அருகிலுள்ள `Dashboard → Context & Cache → Compression Combos` என்பதன் "Assign to routing" பட்டியலில் ஒவ்வொரு வழிப்படுத்தல் சேர்க்கைக்கும் அமைக்கலாம். இரண்டு இடைமுகங்களிலும் செய்யப்படும் மாற்றங்கள் ஒரே `PUT /api/combos/{id}` முனைப்புள்ளி மூலம் நிலைநிறுத்தப்படுகின்றன.

### ஒவ்வொரு கோரிக்கைக்குமான மேலெழுதுதல்

ஒரே கோரிக்கைக்கான சுருக்கத் திட்டத்தை மேலெழுத, `x-omniroute-compression` கோரிக்கைத் தலைப்பை அனுப்பவும். இதுவே மிக உயர்ந்த முன்னுரிமையைக் கொண்டுள்ளது — இது வழிப்படுத்தல்-சேர்க்கை மேலெழுதுதல், செயலில் உள்ள சுயவிவரம், தானியக்கத் தூண்டல் மற்றும் பலகையின் இயல்புநிலை ஆகிய அனைத்தையும் மீறும். அறியப்படாத மதிப்புகள் புறக்கணிக்கப்படும் (கோரிக்கை ஒருபோதும் நிராகரிக்கப்படாது); மேலும், உலகளாவிய முதன்மைச் சுவிட்ச் அனைத்தையும் தொடர்ந்து கட்டுப்படுத்தும்: உலகளவில் சுருக்கம் முடக்கப்பட்டிருக்கும்போது, தலைப்பால் அதை இயக்க முடியாது. மதிப்புகள்:

| மதிப்பு       | விளைவு                                                                                                           |
| ------------- | ---------------------------------------------------------------------------------------------------------------- |
| `off`         | இந்தக் கோரிக்கைக்குச் சுருக்கம் இல்லை.                                                                           |
| `default`     | பலகையிலிருந்து பெறப்பட்ட இயல்புநிலைச் சுயவிவரம் (செயலில் உள்ள சுயவிவரத்தைப் புறக்கணிக்கும்).                     |
| `engine:<id>` | இயக்கப்பட்டிருக்கும்போது ஒரு தனி எஞ்சின், எ.கா. `engine:rtk`.                                                    |
| `<combo>`     | பெயரிடப்பட்ட சேர்க்கை; முதலில் பெயரால் (எழுத்துப் பெட்டியைப் பொருட்படுத்தாமல்), பின்னர் id மூலம் பொருத்தப்படும். |

பயன்படுத்தப்பட்ட திட்டம் `X-OmniRoute-Compression: <mode>; source=<source>` பதில் தலைப்பில் திருப்பி அனுப்பப்படும்; இதில் `<source>` என்பது `request-header`, `routing-override`, `active-profile`, `auto-trigger`, `default` அல்லது `off` ஆகியவற்றில் ஒன்றாகும்.

### API

```bash
# சுருக்க அமைப்புகளைப் பெறவும்
curl http://localhost:20128/api/settings/compression

# சுருக்க அமைப்புகளைப் புதுப்பிக்கவும்
curl -X PUT http://localhost:20128/api/settings/compression \
  -H "Content-Type: application/json" \
  -d '{"defaultMode":"stacked","autoTriggerMode":"stacked","autoTriggerTokens":32000}'

# குறிப்பிட்ட RTK/stacked பேலோடை முன்னோட்டமிடவும்
curl -X POST http://localhost:20128/api/compression/preview \
  -H "Content-Type: application/json" \
  -d '{"mode":"rtk","messages":[{"role":"tool","content":"npm test output here"}]}'
```

- ✅ குறியீட்டுத் தொகுதிகள் (வேலியிடப்பட்டவை மற்றும் வரிக்குள் உள்ளவை)

- ✅ JSON கட்டமைப்புகள் மற்றும் கட்டமைக்கப்பட்ட தரவு
- ✅ அடையாளங்காட்டிகள் மற்றும் பாதுகாக்கப்பட்ட தொழில்நுட்ப டோக்கன்கள்
- ✅ கணித வெளிப்பாடுகள்
- ✅ கருவி/செயல்பாட்டு அழைப்பு வரையறைகள்
- ✅ கணினி அறிவுறுத்தல்கள் (lite பயன்முறையில்)

எதுவும் நிலையாகச் சேமிக்கப்படுவதற்கு முன், RTK மூல வெளியீட்டு மீட்பு பொதுவான API விசைகள், bearer டோக்கன்கள், Slack டோக்கன்கள், AWS அணுகல் விசைகள்,

## மேம்பட்ட சுருக்க அமைப்புகள்

7 நிலையான பயன்முறைகளுக்கு அப்பால், சூழலின் அடிப்படையில் தானாகச் செயல்படும் பல மேம்பட்ட சுருக்க
அமைப்புகளை OmniRoute கொண்டுள்ளது.

### தற்காலிக சேமிப்பக விழிப்புணர்வுள்ள சுருக்கம்

சில வழங்குநர்கள் (அறிவுறுத்தல் தற்காலிகச் சேமிப்பைக் கொண்ட Anthropic போன்றவை) **அறிவுறுத்தல் தற்காலிகச் சேமிப்பை**
ஆதரிக்கின்றனர்; இது செலவையும் தாமதத்தையும் குறைப்பதற்காக அறிவுறுத்தலின் பகுதிகளைத் தற்காலிகமாகச் சேமிக்க அனுமதிக்கிறது.
தற்காலிகச் சேமிப்பு இயக்கப்பட்டிருக்கும்போது, தீவிரமான சுருக்கம் செயல்திறனுக்கு உண்மையில் **பாதிப்பை ஏற்படுத்தலாம்**,
ஏனெனில் அது தற்காலிகமாகச் சேமிக்கப்பட்ட டோக்கன்களை மாற்றி, தற்காலிகச் சேமிப்பைச் செல்லாததாக்குகிறது.

`cachingAware.ts` தொகுதி, **தற்காலிகச் சேமிப்புச் சூழலைக் கண்டறிந்து**, அதற்கேற்ப
**சுருக்க உத்தியைச் சரிசெய்வதன்** மூலம் இதைத் தீர்க்கிறது.

#### இது எவ்வாறு செயல்படுகிறது

1. **தற்காலிகச் சேமிப்புச் சூழலைக் கண்டறிதல்** — `cache_control` குறியீடுகளுக்காகக் கோரிக்கை உடலை வருடுகிறது
2. **தற்காலிகச் சேமிப்பு வழங்குநர்களைக் கண்டறிதல்** — இலக்கு வழங்குநர் தற்காலிகச் சேமிப்பை ஆதரிக்கிறாரா என்பதைச் சரிபார்க்கிறது
3. **உத்தியைச் சரிசெய்தல்** — தற்காலிகச் சேமிப்பு வழங்குநர்களுக்கு `aggressive`/`ultra`-ஐ `standard` ஆகத் தரமிறக்குகிறது
4. **கணினி அறிவுறுத்தலைத் தவிர்த்தல்** — கணினி அறிவுறுத்தல்கள் வழக்கமாகத் தற்காலிகமாகச் சேமிக்கப்படுவதால், அவற்றைச் சுருக்க வேண்டாம்
5. **நிர்ணயிக்கப்பட்ட உருமாற்றங்களைப் பயன்படுத்துதல்** — சீரான வெளியீட்டை உருவாக்கும் உருமாற்றங்களை மட்டுமே பயன்படுத்துகிறது

#### குறியீட்டு எடுத்துக்காட்டு

```ts
import {
  detectCachingContext,
  getCacheAwareStrategy,
} from "@omniroute/open-sse/services/compression/cachingAware";

const body = {
  model: "anthropic/claude-sonnet-4.5",
  messages: [{ role: "user", content: "Hello" }],
  cache_control: { type: "ephemeral" }, // ← தற்காலிகச் சேமிப்புக் குறியீடு
};

const ctx = detectCachingContext(body, { provider: "anthropic" });
// → { hasCacheControl: true, provider: "anthropic", isCachingProvider: true }

const strategy = getCacheAwareStrategy("aggressive", ctx);
// → { strategy: "standard", skipSystemPrompt: true, deterministicOnly: true }
```

#### எப்போது பயன்படுத்த வேண்டும்

தற்காலிகச் சேமிப்பக விழிப்புணர்வுள்ள சுருக்கம் **எப்போதும் இயக்கத்தில் இருக்கும்** — உள்ளமைவு எதுவும் தேவையில்லை. இது பின்வரும் சூழல்களில்
மட்டுமே செயல்படத் தொடங்கும்:

- கோரிக்கையில் `cache_control` குறியீடுகள் இருக்கும்போது
- இலக்கு வழங்குநர் அறிவுறுத்தல் தற்காலிகச் சேமிப்பை ஆதரிக்கும்போது (Anthropic, OpenAI போன்றவை)

### படிப்படியான பழமையாதல்

நீண்ட உரையாடல்கள் பல செய்தித் திருப்பங்களைக் குவிக்கின்றன, ஆனால் பழைய திருப்பங்கள்
குறைந்த தொடர்புடையவையாகின்றன. `progressiveAging.ts` தொகுதி **திருப்ப இடைவெளியின் அடிப்படையில் செய்திகளின் விவரத்தைக் குறைக்கிறது**:

- **சமீபத்திய திருப்பங்கள் (0-3)**: மாற்றமின்றி வைக்கப்படும் (முழு விவரம்)
- **இடைப்பட்ட திருப்பங்கள் (4-8)**: Lite சுருக்கம் (வெற்றிடங்கள், வடிவமைப்புத் தூய்மைப்படுத்தல்)
- **பழைய திருப்பங்கள் (9+)**: Caveman சுருக்கம் (தேவையற்ற சொற்களை அகற்றுதல், சுருக்கமாக்குதல்)
- **மிகப் பழைய திருப்பங்கள் (20+)**: பெருமளவில் சுருக்கமாக்கப்படும் அல்லது நீக்கப்படும்

#### குறியீட்டு எடுத்துக்காட்டு

```ts
import { applyAging } from "@omniroute/open-sse/services/compression/progressiveAging";

const messages = [
  { role: "system", content: "You are a helpful assistant" },
  { role: "user", content: "What is 2+2?" },
  { role: "assistant", content: "4" },
  // ... மேலும் 50 திருப்பங்கள் ...
];

const { messages: aged, saved } = applyAging(messages, {
  verbatim: 3, // முதல் 3 திருப்பங்கள்: மாற்றமின்றி
  light: 8, // 4-8 திருப்பங்கள்: lite சுருக்கம்
  moderate: 20, // 9-20 திருப்பங்கள்: caveman சுருக்கம்
  // 21+ திருப்பங்கள்: தீவிரமான சுருக்கமாக்கல்
});

// saved = சேமிக்கப்பட்ட டோக்கன்களின் எண்ணிக்கை
```

#### எப்போது பயன்படுத்த வேண்டும்

`aggressive` மற்றும் `ultra` முறைகளில் முற்போக்கான முதிர்வாக்கம் **எப்போதும் இயக்கத்தில் இருக்கும்**. இது குறிப்பாகப் பின்வருவனவற்றில் பயனுள்ளதாக இருக்கும்:

- நீண்ட நேரம் தொடரும் நிரலாக்க அமர்வுகள்
- பல நாட்கள் நீடிக்கும் உரையாடல்கள்
- பல கருவி அழைப்புகளைக் கொண்ட ஏஜென்ட் பணிப்பாய்வுகள்

### Caveman வெளியீட்டு முறை

மாடலே சுருக்கப்பட்ட, மிகச் செறிவான வெளியீட்டை ("caveman" பாணியில்) உருவாக்கும்படி செய்வதற்காக `outputMode.ts` தொகுதி **கணினி அறிவுறுத்தல் வழிமுறைகளை** உட்செலுத்துகிறது.

#### இது எவ்வாறு செயல்படுகிறது

உள்ளீட்டைச் சுருக்குவதற்குப் பதிலாக, இந்த முறை பின்வருவது போன்ற ஒரு கணினி அறிவுறுத்தலைச் சேர்க்கிறது:

> "மிகக் குறைந்த சொற்களில் பதிலளி. மரியாதை நிமித்தமான பேச்சுகளைத் தவிர். குறுகிய வாக்கியங்களைப் பயன்படுத்து."

இது குறிப்பாகப் பின்வருவனவற்றில் சிறப்பாகச் செயல்படுகிறது:

- நிரல் உருவாக்கம் (மிகச் செறிவான வெளியீடு = குறைவான டோக்கன்கள்)
- விரைவான கேள்வி-பதில் (விரிவான விளக்கங்கள் தேவையில்லை)
- தொகுதிச் செயலாக்கம் (செயல்திறனை அதிகப்படுத்துதல்)

#### எப்போது பயன்படுத்த வேண்டும்

Caveman வெளியீட்டு முறை **விருப்பத் தேர்வாகும்** — combo கட்டமைப்பு மூலம் அதை அமைக்கவும்:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "outputMode": "caveman"
    }
  }
}
```

#### உட்செலுத்தல் எவ்வாறு செயல்படுகிறது

`applyOutputStyles()` (`open-sse/services/compression/outputStyles/apply.ts`) தேர்வைப் பட்டியலுடன் பொருத்தித் தீர்மானிக்கிறது (அறியப்படாத ids மற்றும் மொழிச்சூழலுடன் பொருந்தாத பாணிகள் புறக்கணிக்கப்படும்; அவை ஒருபோதும் பிழையாகாது), தேர்ந்தெடுக்கப்பட்ட அறிவுறுத்தல்களைப் பட்டியல் வரிசையில் இணைக்கிறது, எல்லைகள் பிரிவை **ஒருமுறை** சேர்க்கிறது, பின்னர் ஒற்றை idempotency குறியீட்டிற்குப் (`[OmniRoute Output Styles]`) பின்னால் அதன் முடிவை கணினி அறிவுறுத்தலின் தொடக்கத்தில் வைக்கிறது — மீண்டும் பயன்படுத்துவது எந்த மாற்றத்தையும் ஏற்படுத்தாது. கண்டறியப்பட்ட கோரிக்கை மொழிக்கு மொழிபெயர்ப்பு இருக்கும்போது, ஆங்கிலத்திற்குப் பதிலாக அந்த மொழியாக்கப்பட்ட அறிவுறுத்தல் உட்செலுத்தப்படும்.

#### எவ்வாறு இயக்குவது

முகப்புப் பலகையில்: **சூழல் → அமைப்புகள் → சுருக்கம்** — ஒவ்வொரு பாணிக்கும் on/off மாற்றியும் நிலைத் தேர்வியும் கொண்ட ஒரு வரிசை. நிரல் வழியாக, சுருக்கக் கட்டமைப்பு தேர்வைப் பின்வருமாறு சேமிக்கிறது:

```json
{
  "outputStyles": [
    { "id": "i-have-adhd", "level": "full" },
    { "id": "less-code", "level": "lite" }
  ]
}
```

பின்னோக்கிய இணக்கத்தன்மை: மரபுவழி `outputMode: "caveman"` combo அமைப்பு இன்னும் செயல்படுகிறது; அது `terse-prose`-க்கு வரைபடமாக்கப்படுகிறது, மேலும் ஒவ்வொரு மரபுவழி மொழியிலும் பழைய உட்செலுத்தலுடன் byte அளவில் ஒரே மாதிரியாக இருக்கும்.

மொழித் தேர்வு: `languageConfig.enabled` இயக்கப்பட்டிருக்கும்போது, `autoDetect` சமீபத்திய பயனர் செய்தியின் மொழியைத் தேர்ந்தெடுக்கிறது (உள்ளீட்டு இயந்திரங்கள் பயன்படுத்தும் அதே கண்டறிவான்); `autoDetect`-ஐ முடக்குவது `defaultLanguage`-ஐ நிலைநிறுத்துகிறது. முடக்கப்பட்டிருந்தால் → ஆங்கிலம்.

பாணி × மொழி அணி `tests/unit/compression/output-styles-i18n-matrix.test.ts` மூலம் நிலைநிறுத்தப்பட்டுள்ளது: குறைந்தது ஒரு pt-BR மொழிபெயர்ப்பு (அல்லது வெளிப்படையாகக் கண்காணிக்கப்படும் விதிவிலக்கு) இல்லாமல் ஒரு புதிய பாணியை வெளியிட முடியாது; மேலும் ஏற்கனவே உள்ள ஒரு பாணி எந்த மொழிச்சூழலையும் அமைதியாக இழக்க முடியாது. பாணியைச் சேர்க்க, [EXTENDING_COMPRESSION.md](./EXTENDING_COMPRESSION.md#adding-an-output-style)-ஐப் பார்க்கவும்.

### கருவி முடிவுச் சுருக்கம்

கருவி முடிவுகளுக்காக (function calls, agent outputs, search results போன்றவை) `toolResultCompressor.ts` தொகுதி **5 சிறப்புச் சுருக்க உத்திகளை** வழங்குகிறது:

1. **தேடல் முடிவுச் சுருக்கம்** — தேவையற்ற மீள்முடிவுகளை நீக்கி, முதன்மையான N முடிவுகளை வைத்திருக்கிறது
2. **கோப்பு வாசிப்புச் சுருக்கம்** — பெரிய கோப்புகளைக் குறைத்து, headers/imports-ஐப் பாதுகாக்கிறது
3. **நிரல் இயக்கச் சுருக்கம்** — அத்தியாவசியமான stdout/stderr-ஐ மட்டும் வைத்திருக்கிறது
4. **தரவுத்தள வினவல் சுருக்கம்** — வரிசைகளைக் கட்டுப்படுத்தி, மிக விரிவான metadata-வை நீக்குகிறது
5. **API பதில் சுருக்கம்** — null புலங்களை நீக்கி, arrays-ஐச் சுருக்குகிறது

#### எப்போது பயன்படுத்த வேண்டும்

கருவி அழைப்புகள் இருக்கும்போது, கருவி முடிவுச் சுருக்கம் **எப்போதும் இயக்கத்தில் இருக்கும்**. எந்தக் கட்டமைப்பும் தேவையில்லை.

### அடுக்கப்பட்ட குழாய்த்தொடர்

அடுக்கப்பட்ட முறை **பல இயந்திரங்களை வரிசையாக** இயக்குகிறது — பொதுவாக முதலில் RTK (கருவி வெளியீட்டில் 60-90% சேமிப்பு), பின்னர் Caveman (மீதமுள்ள உரையில் கூடுதலாக 30% சேமிப்பு). இதன் மூலம் **மொத்தம் 78-95% சேமிப்பு** கிடைக்கிறது.

#### இது எவ்வாறு செயல்படுகிறது

```
உள்ளீடு (1000 டோக்கன்கள்)
  → RTK (கட்டளையை உணரும் வடிகட்டி) → 200 டோக்கன்கள்
    → Caveman (நிரப்புச் சொற்களை நீக்குதல்) → 140 டோக்கன்கள்
  → வெளியீடு (140 டோக்கன்கள், 86% சேமிப்பு)
```

#### எப்போது பயன்படுத்த வேண்டும்

பின்வருவனவற்றுக்கு அடுக்கப்பட்ட முறையைப் பயன்படுத்தவும்:

- கருவிகள் அதிகமுள்ள பணிப்பாய்வுகள் (ஏஜென்ட் நிரலாக்கம், ஆராய்ச்சி)
- செலவு முக்கியமான தொகுதிச் செயலாக்கம்
- அதிகபட்ச டோக்கன் சேமிப்பு தேவைப்படும்போது

combo மூலம் கட்டமைக்கவும்:

```json
{
  "strategy": "auto",
  "config": {
    "auto": {
      "modePack": "stacked"
    }
  }
}
```

## கம்ப்ரெஷன் காம்போ மேலெழுதல்கள்

வெவ்வேறு பயன்பாட்டு நிலைகளுக்கான செயல்பாட்டை நுணுக்கமாகச் சரிசெய்ய, உலகளாவிய கம்ப்ரெஷன் பயன்முறையை **ஒவ்வொரு காம்போவிற்கும் தனித்தனியாக** மேலெழுதலாம்:

```json
{
  "id": "coding-combo",
  "strategy": "priority",
  "config": {
    "auto": {
      "weights": { "taskFit": 0.5 },
      "modePack": "quality-first"
    }
  },
  "compressionOverride": {
    "mode": "aggressive",
    "stackedPipelines": ["rtk", "caveman"],
    "preserveToolDefinitions": true
  }
}
```

இது பின்வருவனவற்றுக்குப் பயனுள்ளதாக இருக்கும்:

- **கோடிங் காம்போக்கள்**: நீண்ட அமர்வுகளுக்கு `aggressive` பயன்முறையைப் பயன்படுத்தவும்
- **விரைவான கேள்வி-பதில் காம்போக்கள்**: விரைவான பதில்களுக்கு `lite` பயன்முறையைப் பயன்படுத்தவும்
- **கருவிகள் அதிகம் பயன்படுத்தும் காம்போக்கள்**: அதிகபட்ச சேமிப்புக்கு `stacked` பயன்முறையைப் பயன்படுத்தவும்
- **புரொடக்ஷன் காம்போக்கள்**: கேஷிங் வழங்குநர்களுக்கு `cache-aware` பயன்முறையைப் பயன்படுத்தவும்
