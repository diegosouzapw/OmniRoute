OmniRoute ஆனது `setup-*` கட்டளைகளின் ஒரு குடும்பத்தை வழங்குகிறது, இது ஒரு கோடிங் CLI (Codex, Claude Code, OpenCode, Cline, …) ஐ OmniRoute ஐ அதன் பின்தளமாகப் பயன்படுத்த உள்ளமைக்கிறது — இதனால் கருவி **ஒரே** ஒரு இறுதிப்புள்ளியுடன் பேசுகிறது மற்றும் OmniRoute ஆனது தானியங்கு-பின்பற்றுதலுடன் சரியான வழங்குநருக்கு வழிநடத்துகிறது. ஒவ்வொரு கட்டளையும் இயங்கும் OmniRoute (உள்ளூர் அல்லது தொலைநிலை) இலிருந்து **நேரடி** மாதிரி பட்டியலைப் படித்து, **உங்கள்** கணினியில் கருவியின் சொந்த உள்ளமைவு கோப்பை எழுதுகிறது. API விசை ஆனது கருவி ஆதரிக்கும் இடங்களில் ஒரு சூழல் மாறியால் குறிப்பிடப்படுகிறது. ஒரு கருவி-உள்ளூர் சூழல் கோப்பை நிலைநிறுத்தும் கட்டளைகள் கீழே குறிப்பிடப்பட்டுள்ளன.

ஒரு பொதுவான துவக்கியும் உள்ளது — `omniroute run <target>` — இது எந்த உள்ளமைவையும் எழுதாமல், சரியான சூழல் செலுத்தப்பட்டு `claude`, `codex`, `aider`, `goose`, `opencode`, `qwen` அல்லது `gemini` ஐத் தொடங்குகிறது. இலக்குகள் மற்றும் அவற்றின் மாற்றுப்பெயர்கள் அதிகாரப்பூர்வ வெளிப்பாடான `bin/cli/cli-manifest.mjs` இலிருந்து வருகின்றன (`claude-code|cc|anthropic`, `codex-cli|openai-codex|openai`, `goose-cli`, `open-code`, `qwen-code`, `gemini-cli`), மேலும் `omniroute completion` அதே வெளிப்பாட்டிலிருந்து பெறப்பட்ட இலக்கு சொற்களை வழங்குகிறது. பழைய கருவி சார்ந்த துவக்கிகள் — `omniroute launch` (Claude Code) மற்றும் `omniroute launch-codex` (Codex) — இன்னும் கிடைக்கின்றன.

வழங்குநர் உள்நுழைவு அதே உள்ளூர்/தொலைநிலை சூழலில் இருந்து கிடைக்கிறது. கீழே உள்ள API-முதல் கட்டளைகள் மேலாண்மை அங்கீகாரத்தை வழங்குநர் நற்சான்றிதழ்களிலிருந்து தனித்தனியாக வைத்திருக்கின்றன மற்றும் கட்டமைக்கப்பட்ட வெளியீட்டில் ஒருபோதும் நற்சான்றிதழை அச்சிடுவதில்லை:

```bash
omniroute providers add glm --credential-env GLM_API_KEY --name work
omniroute providers import ./providers.json --dry-run --json
omniroute providers auth openai
omniroute providers edit <connection-id> --default-model glm/glm-5.2
omniroute providers remove <connection-id> --yes
```

ஸ்கிரிப்டுகளுக்கு, `--credential-stdin` அல்லது `--credential-env` ஐ விரும்பவும்; `--credential` கட்டுப்படுத்தப்பட்ட உள்ளூர் பயன்பாட்டிற்காக தக்கவைக்கப்பட்டுள்ளது. `providers remove` ஆனது ஊடாடாத டெர்மினலில் `--yes` ஐக் கோருகிறது, மேலும் இந்த ஐந்து கட்டளைகளும் செயலில் உள்ள சூழல் அல்லது உலகளாவிய `--base-url`/`--api-key` விருப்பங்களை மதிக்கின்றன.

வழங்குநர் தேர்வாளர்கள் தெளிவற்ற ID முன்னொட்டுகள், பெயர்கள் அல்லது வழங்குநர் பெயர்களை நிராகரிக்கின்றன; பல இணைப்புகள் பொருந்தினால் முழு இணைப்பு ID ஐப் பயன்படுத்தவும். உருவாக்கும் மற்றும் திருத்தும் கட்டளைகள் சேமிக்கப்பட்ட இணைப்பை மீண்டும் படிக்கின்றன, மேலும் நீக்குதல் அது இனி படிக்க முடியாததா என்பதை சரிபார்க்கிறது. ஒரு இறக்குமதி ஏற்கனவே உள்ள வழங்குநர்/பெயர் ஜோடியைத் தவிர்க்கிறது. இறக்குமதி செய்யப்பட்ட உள்ளீடுகள் CLI க்கு வழங்கப்பட்ட மேலாண்மை இறுதிப்புள்ளி, சூழல் அல்லது மேலாண்மை நற்சான்றிதழ்களை மேலெழுத முடியாது.

மிகவும் செழுமையான இரண்டு ஒருங்கிணைப்புகளின் ஒருமுறை, கையால் எழுதப்பட்ட அடிப்படை அமைப்பிற்கு, கருவி சார்ந்த ஆழமான ஆய்வுகளைப் பார்க்கவும்:

- [Claude Code உள்ளமைவு](./CLAUDE-CODE-CONFIGURATION.md)
- [Codex CLI உள்ளமைவு](./CODEX-CLI-CONFIGURATION.md)
- [தொலைநிலை முறை](./REMOTE-MODE.md) — உங்கள் மடிக்கணினியிலிருந்து ஒரு தொலைநிலை OmniRoute (VPS / Tailnet) ஐ இயக்கவும்
- [VS Code Copilot Chat](./VSCODE-COPILOT.md) — OmniCopilot நீட்டிப்பு; இது எடிட்டருக்குள்ளிருந்தே இந்த `setup-*` கட்டளைகளை உங்களுக்காக இயக்க முடியும்

## முதன்மை அட்டவணை

ஒவ்வொரு கட்டளையும் **செயலில் உள்ள context**-ஐ (`omniroute connect` மூலம் அமைக்கப்படும்; [தொலைநிலைப் பயன்முறை](./REMOTE-MODE.md)-ஐப் பார்க்கவும்) அல்லது வெளிப்படையான `--remote <url> --api-key <key>` flags-ஐப் பின்பற்றுகிறது. கீழே உள்ள "உள்ளூர் மற்றும் தொலைநிலை" என்பதன் பொருள்: flags எதுவும் இல்லையெனில், இது `http://localhost:20128`-ஐ இலக்காகக் கொள்கிறது; `--remote` பயன்படுத்தப்பட்டால் (அல்லது செயலில் உள்ள தொலைநிலை context இருந்தால்), அந்த server-இலிருந்து catalog-ஐப் பெற்று, config-ஐ உள்ளூரில் எழுதுகிறது.

| `omniroute setup-5dive`    | 5dive (முகவர் குழு)             | `$HOME`-இன் கீழ் எதுவுமில்லை — `5dive agent auth set` வழியாக ஒரு 5dive **அங்கீகாரச் சுயவிவரத்தை** (`/var/lib/5dive/auth-profiles/<name>/`) எழுதுகிறது; root-க்கு மட்டும், முகவர் குழுத் தளத்தில் இயங்குகிறது         | `--remote` `--api-key` `--model` `--auth-profile` `--agent` `--byo-provider` `--fivedive-bin` `--no-sudo` `--yes` `--dry-run` `--port`     | இரண்டும்                 |
| `omniroute run <target>`   | இயக்கநேரத் தொடக்கம் (பொதுவானது) | எதுவுமில்லை — சரியான சூழல் மற்றும் தருமதிப்புகளுடன் `claude`/`codex`/`aider`/`goose`/`opencode`/`qwen`/`gemini`-ஐத் தொடங்குகிறது; Qwen மற்றும் Gemini தற்காலிகத் தனிமைப்படுத்தப்பட்ட முகப்பகத்தைப் பயன்படுத்துகின்றன | `--remote` `--base-url` `--context` `--provider` `--model` `--api-key` `--api-key-env` `--dry-run` `--json` `--port` `--profile` `--token` | இரண்டும்                 |
| `omniroute launch`         | Claude Code                     | எதுவுமில்லை — `ANTHROPIC_BASE_URL`/`ANTHROPIC_AUTH_TOKEN` உட்செலுத்தப்பட்ட நிலையில் `claude`-ஐத் தொடங்குகிறது                                                                                                        | `--remote` `--api-key` `--token` `--profile` `--port`                                                                                      | இரண்டும்                 |
| `omniroute launch-codex`   | OpenAI Codex CLI                | எதுவுமில்லை — `-c` கொடிகள் வழியாக `omniroute` வழங்குநர் உட்செலுத்தப்பட்ட நிலையில் `codex`-ஐத் தொடங்குகிறது                                                                                                           | `--remote` `--api-key` `--profile` (`-p`) `--port`                                                                                         | இரண்டும்                 |

கொடிகள் குறித்த குறிப்புகள் (கட்டளை மூலத்தில் சரிபார்க்கப்பட்டவை):

- `--remote <url>` — தொலைநிலை OmniRoute-இலிருந்து பட்டியலைப் பெறுகிறது (`--port`
  மற்றும் செயலில் உள்ள சூழலை மீறுகிறது). அந்தச் சேவையகத்திற்கான சான்றை
  `--api-key <key>` வழங்குகிறது (`OMNIROUTE_API_KEY` சூழல் மாறி அல்லது செயலில் உள்ள சூழலின் token இயல்புநிலையாகப் பயன்படுத்தப்படும்).
- `--only <patterns>` — காற்புள்ளியால் பிரிக்கப்பட்ட துணைச்சரங்கள்; பொருந்தும் model ID-களை மட்டும்
  வைத்திருக்கும் (எ.கா. `--only glm,kimi`). `setup-codex`, `setup-claude`,
  `setup-opencode`, `setup-continue`, `setup-cursor`, `setup-crush` ஆகியவற்றில் கிடைக்கிறது.
- `--dry-run` — கோப்பு முறைமையைத் தொடாமல், சரியாக என்ன எழுதப்படும் என்பதை
  அச்சிடுகிறது. `setup-cursor`-ஐத் **தவிர** ஒவ்வொரு `setup-*` கட்டளையிலும் கிடைக்கிறது
  (அது ஒருபோதும் கோப்பை எழுதாது).
- `--model <id>` — model-ஐத் தானாகக் கண்டறியும் வசதி இல்லாத கருவிகளுக்கு இது கட்டாயம்
  (அல்லது ஊடாடும் முறையில் தேர்ந்தெடுக்கப்படும்): Cline, Kilo, Roo, Goose, Qwen, Aider, 5dive. ஊடாடாத இயக்கங்களுக்கு
  அந்தக் கருவிகள் `--yes`-ஐயும் ஏற்கின்றன (அப்போது `--model` கட்டாயமாகும்).
  இயல்புநிலை உயர்மட்ட model-ஐ அமைக்க `setup-opencode`, `--model`-ஐ ஏற்கிறது.
- `omniroute run`-இல் உள்ள `--model <id>`, manifest-இன் இலக்கு-வாரியான இணைப்பை
  (`bin/cli/cli-manifest.mjs`) பின்பற்றுகிறது: **aider**, `--model openai/<id>`-ஐப் பெறுகிறது மற்றும்
  **opencode**, `--model omniroute/<id>`-ஐப் பெறுகிறது (id-இல் ஏற்கெனவே அந்த முன்னொட்டு
  இல்லாதபோது மட்டுமே அது சேர்க்கப்படும்); **qwen** மற்றும் **gemini** ஆகியவை id-ஐ மாற்றமின்றிப் பெறுகின்றன;
  **claude**, அதை `ANTHROPIC_MODEL` வழியாகவும், **goose**, `GOOSE_MODEL` வழியாகவும்,
  **codex**, `-c model_providers.omniroute.*` arguments வழியாகவும் பெறுகின்றன. **இயக்க இலக்குகளில்
  `--model`-ஐக் கட்டாயமாகக் கோருவது Qwen மட்டுமே** — அது இல்லாமல் `omniroute run qwen`
  இயக்கப்பட்டால், தெளிவான பிழையுடன் `2` என்ற exit code-ஐ வழங்குகிறது.
- `--port <port>` — உள்ளூர் OmniRoute port (இயல்புநிலை `20128`; `--remote`
  அமைக்கப்பட்டிருந்தால் புறக்கணிக்கப்படும்). அனைத்து `setup-*` கட்டளைகளிலும் இரு launcher-களிலும் உள்ளது.
- `omniroute run` exit code-கள்: child CLI-இன் சொந்த exit code மாற்றமின்றி
  முன்னனுப்பப்படும்; `2` = தவறான arguments (ஆதரிக்கப்படாத இலக்கு, தேவையான
  `--model` இல்லை, container guard); `127` = இலக்கு binary, `PATH`-இல் இல்லை;
  `SIGINT`/`SIGTERM`/`SIGHUP` மூலம் launch முடிவடையும்போது `130`/`143`/`129`;
  `1` = பிற runtime launch தோல்வி.
- இரண்டு launcher-களும் (`launch`, `launch-codex`), `setup-claude` / `setup-codex`
  எழுதிய profile-ஐத் தேர்ந்தெடுக்க `--profile <name>`-ஐ ஏற்கின்றன; மேலும் அடிப்படையான
  `claude` / `codex` binary-க்கான pass-through arguments-ஐயும் ஏற்கின்றன.

ஊடாடும் தேர்வியும் setup செய்முறைகளால் பகிரப்படுகிறது:

```bash
# செயலில் உள்ள உள்ளூர் அல்லது தொலைநிலை model பட்டியலிலிருந்து தேர்ந்தெடுத்து இலக்கை உள்ளமைக்கவும்.
omniroute configure claude
omniroute configure opencode --provider glm
omniroute configure qwen --model qwen/qwen3.8-max-preview --yes
```

தற்போது `configure`, `codex`, `claude`, `opencode`, `qwen`, `aider`, `goose`,
`cline`, `continue`, `kilo`, மற்றும் `5dive` ஆகியவற்றிற்கான சோதிக்கப்பட்ட செய்முறைகளுக்குப் பணியை ஒப்படைக்கிறது.
IDE-மட்டும்,
MITM, மற்றும் வழிகாட்டி-மட்டும் பட்டியல் உள்ளீடுகள் தெளிவான `setup-*`/கைமுறை செயல்முறைகளாகவே நீடிக்கின்றன;
launch செய்யக்கூடிய இலக்குகளாக அவை வழங்கப்படுவதில்லை.

> `setup-opencode` என்பது **இலகுரக OpenAI-இணக்கமான** OpenCode ஒருங்கிணைப்பு.
> மேலும் வளமான plugin ஒருங்கிணைப்பும் உள்ளது — `omniroute setup opencode` — இது
> `@omniroute/opencode-plugin`-ஐ நிறுவுகிறது. அவை வெவ்வேறு கட்டளைகள்; மேலுள்ள அட்டவணை
> `setup-opencode`-ஐ ஆவணப்படுத்துகிறது.
>
> இரண்டு loader-களும் வெவ்வேறு entrypoint-களை எதிர்பார்ப்பதால், ஒவ்வொரு OpenCode major-க்கும்
> ஒன்று என plugin இரண்டு package-களில் வருகிறது:
> OpenCode v1-க்கு `@omniroute/opencode-plugin` மற்றும்

> இன்னும் v1 package-ஐயே நிறுவுகிறது. Options மற்றும் credential lookup வரிசை

## உள்ளூர் பயன்பாடு

OmniRoute `localhost:20128` இல் இயங்கிக்கொண்டிருக்கும்போது, உங்கள் கருவிக்கான அமைப்புக் கட்டளையை மட்டும் இயக்கவும். பட்டியல் உள்ளூர் சேவையகத்திலிருந்து பெறப்படும்.

```bash
# Codex: பொருந்திய ஒவ்வொரு மாதிரிக்கும் ஒரு சுயவிவரத்தை ~/.codex/ இல் எழுதவும்
omniroute setup-codex
codex --profile glm52            # உருவாக்கப்பட்ட சுயவிவரத்தைப் பயன்படுத்தவும்

# Claude Code: ஒவ்வொரு மாதிரிக்கும் தனித்தனி சுயவிவரங்களை எழுதி, பின்னர் ஒன்றைத் தொடங்கவும்
omniroute setup-claude
omniroute launch --profile glm52

# OpenCode: பட்டியலிலுள்ள அனைத்து மாதிரிகளுடனும் openai-இணக்கமான வழங்குநரை எழுதவும்
omniroute setup-opencode
export OMNIROUTE_API_KEY=sk-...  # {env:OMNIROUTE_API_KEY} வழியாகக் குறிப்பிடப்படும்; வட்டில் ஒருபோதும் சேமிக்கப்படாது
opencode -m omniroute/glm/glm-5.2 "..."

# தானியங்கிக் கண்டறிதல் இல்லாத கருவிகளுக்கு மாதிரியை வெளிப்படையாகக் குறிப்பிட வேண்டும்:
omniroute setup-aider --model glm/glm-5.2
omniroute setup-qwen --model qwen/qwen3.8-max-preview

# எதையும் எழுதாமல் முன்னோட்டமிடவும்:
omniroute setup-continue --dry-run
```

எந்தக் கட்டமைப்பையும் எழுதாமல் தொடங்கவும் (சூழல் உட்செலுத்தல் மட்டும்):

```bash
omniroute launch                 # Claude Code → உள்ளூர் OmniRoute
omniroute launch-codex           # Codex CLI → உள்ளூர் OmniRoute
omniroute launch-codex --profile glm52
omniroute run claude --model openai/gpt-5.4
omniroute run codex --model openai/gpt-5.4 --dry-run --json
omniroute run aider --model glm/glm-5.2 -- --message "reply OK"
omniroute run goose --model glm/glm-5.2
omniroute run opencode --model glm/glm-5.2 -- run "reply OK"
omniroute run qwen --model glm/glm-5.2 -- -p "reply OK"
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "reply OK"

# வெளிப்படையான கட்டளைப் பாதை: -- என்பதற்குப் பிறகு வருவதை அப்படியே அனுப்பவும்
omniroute run claude -- --print-system-prompt "review this diff"
```

## தொலைநிலைப் பயன்பாடு

எந்த அமைப்புக் கட்டளையையும் `--remote` + `--api-key` மூலம் தொலைநிலை OmniRoute-ஐ நோக்குமாறு அமைக்கவும். பட்டியல் தொலைநிலையிலிருந்து பெறப்படும்; கட்டமைப்பு உங்கள் உள்ளூர் கணினியில் எழுதப்படும்.

```bash
# தொலைநிலை VPS-க்கு எதிராக OpenCode; glm/kimi மாதிரிகளை மட்டும் வைத்திருக்கவும்
omniroute setup-opencode --remote http://192.168.0.15:20128 --api-key oma_live_xxx \
  --only glm,kimi
opencode -m omniroute/glm/glm-5.2 "..."   # முதலில் OMNIROUTE_API_KEY-ஐ export செய்யவும்

# தொலைநிலைப் பட்டியலிலிருந்து Codex சுயவிவரங்கள்
omniroute setup-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# தொலைநிலைக்கு நேரடியாக ஒரு CLI-ஐத் தொடங்கவும்
omniroute launch       --remote http://192.168.0.15:20128 --api-key oma_live_xxx
omniroute launch-codex --remote http://192.168.0.15:20128 --api-key oma_live_xxx
```

ஒவ்வொரு முறையும் `--remote`/`--api-key` வழங்குவதற்குப் பதிலாக, ஒருமுறை உள்நுழைந்து அவற்றை **செயலில் உள்ள சூழல்** தானாக வழங்க அனுமதிக்கவும்:

```bash
omniroute connect 192.168.0.15        # வரம்பிடப்பட்ட டோக்கனை உருவாக்கி, சூழலைச் சேமிக்கிறது
omniroute setup-codex                 # ← இப்போது தொலைநிலைப் பட்டியலைப் பயன்படுத்துகிறது
omniroute setup-opencode              # ← இதுவும் அதேபோல்
omniroute launch                      # ← தொலைநிலைக்கு எதிராக Claude Code
```

சூழல்கள், வரம்புகள் மற்றும் டோக்கன் மேலாண்மை குறித்து அறிய [தொலைநிலைப் பயன்முறை](./REMOTE-MODE.md) என்பதைப் பார்க்கவும்.

## 5dive முகவர் அணிகள்

[5dive](https://5dive.ai) நீண்ட நேரம் இயங்கும் நிரலாக்க முகவர்களின் ஓர் அணியை இயக்குகிறது; ஒவ்வொன்றும் அதற்கென தனி Unix பயனரின் கீழ் ஒரு systemd அலகாக இருக்கும். இது தானாகவே ஒரு நிரலாக்க CLI அல்ல, எனவே `omniroute run` தொடங்குவதற்கு இதில் எதுவுமில்லை — `5dive` என்பது **கட்டமைப்புக்கு மட்டும்** உரிய இலக்காகும்.

```bash
omniroute configure 5dive --model failover-demo --yes
omniroute setup-5dive --model failover-demo --auth-profile omniroute --agent worker1
```

இரண்டு வடிவங்களும் ஒரு 5dive **அங்கீகாரச் சுயவிவரத்தை** எழுதுகின்றன; அந்தச் சுயவிவரத்துடன் பிணைக்கப்பட்ட ஒவ்வொரு `claude` இருக்கையும் பின்னர் OmniRoute உடன் தொடர்புகொள்ளும். இந்த இலக்கிற்கு மட்டும் உரிய மூன்று விஷயங்கள் உள்ளன:

- **இது அணி ஹோஸ்டில் root ஆக இயங்கும்.** 5dive-இன் வினைகள் உள்ளூர் systemd அலகுகள் மற்றும் root-க்குச் சொந்தமான நிலைக் கோப்பகத்தின் மீது செயல்படுகின்றன; தொலைநிலைப் பயன்முறை கிடையாது. ஏற்கெனவே root ஆக இல்லாதபோது செய்முறை `sudo` மூலம் தன்னை மீண்டும் இயக்குகிறது (`--no-sudo` அதை முடக்கி, அதற்குப் பதிலாகக் கட்டளையை அச்சிடுகிறது).
- **லூப்பேக் அல்லாதபோது முனையம் `https://` ஆக இருக்க வேண்டும்.** முகவரின் API விசை ஒவ்வொரு கோரிக்கையிலும் அந்த URL வழியாகப் பயணிக்கிறது; சாதனத்திற்கு வெளியேயுள்ள மறையாக்கப்படாத முனையத்தை 5dive மறுக்கிறது. தனிப்பட்ட LAN முகவரியும் இதற்கு விதிவிலக்கு அல்ல.
- **ஒவ்வொரு இருக்கைக்கும் சொந்தமான மாதிரிப் பிணைப்பு சுயவிவரத்தைவிட முன்னுரிமை பெறும்.** சுயவிவரம் `ANTHROPIC_DEFAULT_{OPUS,SONNET,HAIKU}_MODEL`-ஐக் கொண்டிருந்தாலும், வழக்கமான மாதிரி id-க்கு இன்னும் பிணைக்கப்பட்டுள்ள இருக்கை அதன் முதல் சுற்றிலேயே _"தேர்ந்தெடுக்கப்பட்ட மாதிரியில் சிக்கல் உள்ளது"_ என்ற செய்தியுடன் தோல்வியடையும். இருக்கைகளையும் பிணைக்க `--agent <name>` என்பதை வழங்கவும் (மீண்டும் வழங்கலாம்); நீங்கள் அவ்வாறு செய்யாதபோது செய்முறை அந்தக் கட்டளையை அச்சிடும்.

API விசை **stdin** (`--api-key=-`) வழியாக 5dive-க்கு வழங்கப்படுவதால், அது `ps` வெளியீட்டில் ஒருபோதும் தோன்றாது.

சுயவிவரத்தை ஒற்றை மாதிரிக்குப் பதிலாக OmniRoute **combo**-வை நோக்கி அமைப்பதே அணிக்கு வழங்குநர் தோல்விமாற்றுத் திறனை வழங்குகிறது: [#11578](https://github.com/diegosouzapw/OmniRoute/issues/11578) இல் பதிவுசெய்யப்பட்ட இயக்கத்தின் நடுவில் முதன்மை முனையம் முற்றிலுமாகச் செயலிழந்தபோது, முகவர் தனது மீதமுள்ள படிகளை மாற்று முனையத்தில் முடித்து, செயலிழப்பைப் பயனருக்குக் காட்டவே இல்லை.

## புதுப்பிப்பின்போது சொந்த சார்புகளைத் தக்கவைத்தல்: `--include=optional`

`omniroute update` மூலம் நீங்கள் புதுப்பிக்கும்போது (உறுதிப்படுத்திய பிறகு அல்லது `--apply` உடன்),
OmniRoute நிறுவலை உள்ளமைக்கப்பட்ட `--include=optional` உடன் இயக்குகிறது:

```bash
npm install -g omniroute@latest --include=optional
```

இது `omniroute update`-க்கு நீங்கள் வழங்கும் கொடி **அல்ல** — புதுப்பிப்பான் இதை எப்போதும்
பயன்படுத்துகிறது. உங்கள் npm உள்ளமைவில் `omit=optional` அமைக்கப்பட்டிருந்தாலும்,
`optionalDependencies` (`better-sqlite3`, `keytar`, `tls-client`, LLMLingua SLM அடுக்கு)
புதுப்பிப்பிற்குப் பிறகும் தக்கவைக்கப்படுவதை இது உறுதிசெய்கிறது; இல்லையெனில் சொந்த SQLite
இயக்கியும் OS-keyring பிணைப்பும் எந்த அறிவிப்புமின்றி நீக்கப்படும். மாற்றங்களைப் பயன்படுத்தாமல்
சரியான கட்டளையை முன்னோட்டமிட:

```bash
omniroute update --dry-run
# [உலர் இயக்கம்] இயக்கப்படவிருந்த கட்டளை: npm install -g omniroute@latest --include=optional
```

பிற `omniroute update` கொடிகள் (மூலத்தில் சரிபார்க்கப்பட்டவை): `--check` (பழைய பதிப்பாக
இருந்தால் வெளியேறும் குறியீடு 1), `--apply` (கேட்காமல் நிறுவுதல்), `--changelog`, `--no-backup`,
`--yes`.

## `omniroute run gemini` வழியாக Google Gemini CLI

`@google/gemini-cli` 0.50.0-க்கு எதிராக ஒப்பந்தம் சரிபார்க்கப்பட்டது: CLI ஆனது
`GOOGLE_GEMINI_BASE_URL`-ஐ மதித்து, அதற்கு எதிராக
`POST /v1beta/models/<model>:generateContent` (மற்றும்
`:streamGenerateContent?alt=sse`) கோரிக்கைகளை அனுப்புகிறது — இது OmniRoute-இன் சொந்த
Gemini இடைமுகத்துடன் (`/v1beta`) துல்லியமாகப் பொருந்துகிறது. `omniroute run gemini` இதைத்
தானாகவே இணைக்கிறது:

- `GOOGLE_GEMINI_BASE_URL` → செயலில் உள்ள OmniRoute அடிப்படை URL (மூலம், `/v1` இல்லாமல்);
- `GEMINI_API_KEY` → தீர்மானிக்கப்பட்ட OmniRoute நற்சான்று (விருப்பம்/env/சூழல்);
- `gemini-api-key` அங்கீகாரத்தைத் தேர்ந்தெடுக்கும் `.gemini/settings.json`-ஐக் கொண்ட
  **தற்காலிகமாகத் தனிமைப்படுத்தப்பட்ட `GEMINI_CLI_HOME`**, இதனால் சேமிக்கப்பட்ட Google OAuth
  அமர்வு (Code Assist) OmniRoute-க்கு வழிநடத்தப்பட்ட தொடக்கத்தை ஒருபோதும் மேலெழுதாது —
  வெளியேறிய பிறகு அகற்றப்படும்;
- **env தூய்மை**: துணைச் செயல்முறையின் env-இலிருந்து `GOOGLE_API_KEY`,
  `GOOGLE_GENAI_USE_VERTEXAI` மற்றும் `GOOGLE_GENAI_USE_GCA` ஆகியவை நீக்கப்படுகின்றன
  (இவை அங்கீகாரத்தை Vertex/Code Assist-க்கு மடைமாற்றும்), மேலும் கூடுதல் பாதுகாப்பு
  மாற்றாக `GEMINI_DEFAULT_AUTH_TYPE=gemini-api-key` அமைக்கப்படுகிறது — பிற `run`
  இலக்குகளும் அவற்றுக்கே உரிய முரண்படும் மாறிகளுக்கு இதே கையாளுதலைப் பெறுகின்றன;
- `--provider`/`--model` இலிருந்து `--model <id>` செலுத்துதல்.

```bash
omniroute run gemini --model glm/glm-5.2 -- --skip-trust -p "hello"
```

Gemini-இன் பணியிட நம்பிக்கைப் பாதுகாப்பு, திரையற்ற பயன்முறையிலும் தொடர்ந்து பொருந்தும் —
`--skip-trust`-ஐ நீங்களே வழங்கவும் (அல்லது கோப்பகத்தை ஊடாடும் முறையில் நம்பவும்);
தொடக்கி திட்டமிட்டே அதைத் தவிர்ப்பதில்லை. இந்தத் தொடக்கி **ACP பதிவிலிருந்து**
(`src/lib/acp/registry.ts`, `gemini --acp`) வேறுபட்டது; அது
`/dashboard/acp-agents`-க்கான முகவர்-நெறிமுறை ஒருங்கிணைப்பாகத் தொடர்கிறது.

## உண்மையான ஸ்மோக் ஸ்வீப் (விருப்பத் தேர்வு)

நிர்ணயிக்கப்பட்ட launch-plan பின்னடைவு சோதனைகள் CI-இல் இயங்குகின்றன (`tests/unit/cli/run-command.test.ts`,
`tests/unit/cli/run-execution.test.ts`). உண்மையான OmniRoute சேவையகத்திற்கு எதிராக உண்மையான
பைனரிகளைச் சரிபார்க்க, விருப்பத் தேர்வாக இயக்கக்கூடிய சோதனை அமைப்பு
`tests/integration/upstream-cli-smoke.int.test.ts`-இல் உள்ளது. இது ஒருபோதும் தானாக இயங்காது
(`RUN_CLI_SMOKE=1` இல்லாவிட்டால் ஒவ்வொரு துணைச் சோதனையும் தவிர்க்கப்படும்), நற்சான்றை அதன் மதிப்பாக
அல்லாமல் env-var பெயராக அனுப்புகிறது, பதிவுசெய்யப்பட்ட எந்த வெளியீட்டிலிருந்தும் விசை வடிவிலான
சரங்களை மறைக்கிறது, பைனரி நிறுவப்படாத இலக்குகளைத் தவிர்க்கிறது, மேலும் தோல்விகளை வெறும் பூலியனாகக்
குறிப்பிடுவதற்குப் பதிலாக auth / upstream / config என வகைப்படுத்துகிறது:

```bash
RUN_CLI_SMOKE=1 \
OMNIROUTE_SMOKE_BASE_URL="http://localhost:20128" \
OMNIROUTE_SMOKE_MODEL="<provider/model>" \
OMNIROUTE_SMOKE_API_KEY_ENV="OMNIROUTE_API_KEY" \
node --import tsx/esm --test tests/integration/upstream-cli-smoke.int.test.ts
```

விருப்பத்தேர்வு: `OMNIROUTE_SMOKE_TARGETS="codex,opencode,qwen"` ஸ்வீப்பைக் கட்டுப்படுத்துகிறது;
`OMNIROUTE_SMOKE_TIMEOUT_MS` ஒவ்வொரு இலக்கிற்குமான 120s நேர வரம்பை மாற்றியமைக்கிறது.
