> **டாஷ்போர்டு:** அமைப்புகள் → **AI** → சிந்தனை பட்ஜெட்  
> **API:** `GET` / `PUT` `/api/settings/thinking-budget`  
> **மூலம்:** `open-sse/services/thinkingBudget.ts`

வழங்குநர்களுக்குச் செல்லும் வழியில் OmniRoute **கிளையன்டின் சிந்தனை/பகுத்தறிவு அளவுருக்களை மீண்டும் எழுத வேண்டுமா** என்பதைச் சிந்தனை பட்ஜெட் கட்டுப்படுத்துகிறது. இது சுருக்கம், ரூட்டிங் அல்லது ப்ராம்ப்ட் கேஷை இயக்கவோ முடக்கவோ **செய்யாது**.

## பயன்முறைகள்

| பயன்முறை                       | OmniRoute என்ன செய்கிறது                                                                                                               | எப்போது பயன்படுத்த வேண்டும்                                                                                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`passthrough`** (இயல்புநிலை) | கிளையன்ட் புலங்களை மாற்றாமல் விடுகிறது (`reasoning`, `reasoning_effort`, Claude `thinking`, Gemini `thinking_config` போன்றவை).         | **Codex / Desktop / முயற்சி + பகுத்தறிவுச் சுருக்கங்களைக் கட்டுப்படுத்த வேண்டிய எந்தவொரு கிளையன்டும்.** கிளையன்ட் `reasoning.summary`-ஐக் கோரும்போது, சிந்தனைப் பலகைகள் தெரிய இது அவசியம்.              |
| **`auto`**                     | அப்ஸ்ட்ரீமுக்கு அனுப்பும் முன் கோரிக்கை உடலிலிருந்து அனைத்து சிந்தனை/பகுத்தறிவுப் புலங்களையும் **நீக்குகிறது**.                        | **வழங்குநரே** இயல்புநிலைகளை உருவாக்க வேண்டும் என்றும், கிளையன்ட் கட்டுப்படுத்தும் சிந்தனை தேவையில்லை என்றும் நீங்கள் திட்டமிட்டு விரும்பும்போது மட்டும். இது **“சிந்தனையைத் தானாகக் காட்டு” என்பதல்ல**. |
| **`custom`**                   | ஒவ்வொரு கோரிக்கையையும் ஒரு நிலையான சிந்தனை டோக்கன் பட்ஜெட்டைக் கொண்டு மேலெழுதுகிறது.                                                   | அனைத்து டிராஃபிக்கிற்குமான சிந்தனை டோக்கன்களின் கடின உச்சவரம்பு.                                                                                                                                        |
| **`adaptive`**                 | செய்திகளின் எண்ணிக்கை, கருவிகள் மற்றும் ப்ராம்ப்ட் நீளம் ஆகியவற்றைப் பயன்படுத்தி, அடிப்படை முயற்சி அளவிலிருந்து பட்ஜெட்டை அளவிடுகிறது. | கிளையன்டின் நோக்கத்தை முழுமையாக நீக்காமல் மென்மையான டோக்கன் கட்டுப்பாட்டைப் பெற.                                                                                                                        |

### `auto` எவற்றை நீக்குகிறது

பயன்முறை `auto` ஆக இருக்கும்போது, `stripThinkingConfig()` பின்வருவனவற்றை (மற்றவற்றுடன் சேர்த்து) நீக்குகிறது:

- OpenAI / Responses: `reasoning`, `reasoning_effort`
- Claude: `thinking`, மேலும் இருந்தால் `output_config.effort`
- Gemini: `generationConfig.thinking_config` / `thinkingConfig`

ஒரு கிளையன்ட் (எ.கா. Codex Desktop) `reasoning: { effort: "ultra", summary: "detailed" }` என்பதை அனுப்பியிருந்தால், **auto அந்தப் பொருளை நீக்கிவிடும்**. அப்ஸ்ட்ரீம் இன்னும் சில பகுத்தறிவு டோக்கன்களுக்குக் கட்டணம் விதிக்கக்கூடும்; ஆனால் பெரும்பாலும் **வெற்று அல்லது குறியாக்கப்பட்டவை மட்டுமே கொண்ட** பகுத்தறிவு உருப்படிகளைத் திருப்பித் தரும் — எனவே UI-இல் பயனுள்ள சிந்தனை ஸ்ட்ரீம் எதுவும் காட்டப்படாது.

| **பகுத்தறிவு மறுஇயக்க கேஷ்**                       | கடுமையான வழங்குநர்களுக்கான (DeepSeek, Kimi, Qwen-thinking, …) பல-திருப்ப மறு-உட்செலுத்தல். Desktop “சிந்தனையைக் காட்டு” என்பதற்கு இணையானதல்ல.              |

## காணக்கூடிய சிந்தனை (Codex / Responses கிளையன்ட்கள்)

ஒரு கிளையன்ட் சிந்தனை உரையைக் காட்ட, பின்வரும் **அனைத்தும்** தேவை:

1. Thinking Budget பயன்முறை = **`passthrough`** (அல்லது நீங்கள் பயன்படுத்தும் பாதைக்கான சுருக்கக் கோரிக்கைகளை போதுமான அளவு மாற்றாமல் வைத்திருக்கும் custom/adaptive).
2. கிளையன்ட் ஒரு சுருக்கத்தைக் கோர வேண்டும், எ.கா. Codex `model_reasoning_summary = "detailed"` / `auto` (`none` அல்ல).
3. அப்ஸ்ட்ரீம் உண்மையிலேயே `response.reasoning_summary_text.*`-ஐ ஸ்ட்ரீம் செய்ய வேண்டும் (அல்லது உருப்படியில் காலியாக இல்லாத `reasoning.summary` இருக்க வேண்டும்).

“மறைகுறியாக்கப்பட்ட தனிப்பட்ட சிந்தனை” மட்டுமே கிடைத்தால், அதற்கான காரணம்:

- பயன்முறை **`auto`** ஆக இருந்தது (கிளையன்ட் கோரிக்கை நீக்கப்பட்டது), அல்லது
- அப்ஸ்ட்ரீம் சுருக்க உரையின்றி `encrypted_content`-ஐ வழங்கியது (வழங்குநர் வரம்பு; OmniRoute ஒரு இடநிரப்பியை மட்டுமே காட்ட முடியும், மறைகுறியாக்கப்படாத உரையைக் காட்ட முடியாது).

## API எடுத்துக்காட்டுகள்

```bash
# படித்தல்
curl -sS https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN"

# Codex / Desktop சிந்தனைக் காட்சிப்படுத்தலுக்குப் பரிந்துரைக்கப்படுகிறது
curl -sS -X PUT https://localhost:20128/api/settings/thinking-budget \
  -H "Authorization: Bearer $OMNIROUTE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"mode":"passthrough","customBudget":10240,"effortLevel":"medium"}'
```

ஸ்கீமா (`updateThinkingBudgetSchema`): `mode` ∈ `passthrough|auto|custom|adaptive`; விருப்பமானவை: `customBudget`, `effortLevel`, `baseBudget`, `complexityMultiplier`.

### நிலைத்தன்மை / மறுதொடக்கம்

மதிப்பு `thinkingBudget` அமைப்புகள் விசையின் கீழ் சேமிக்கப்பட்டு, செயல்முறை தொடக்கத்தில் (`hydrateThinkingBudgetConfig`) ஏற்றப்படுகிறது. DB வழியாக அல்லது API அல்லாத சில பாதைகள் வழியாக மாற்றிய பிறகு, நினைவகத்திலுள்ள singleton வட்டில் உள்ள மதிப்புடன் பொருந்துமாறு **OmniRoute செயல்முறையை மறுதொடக்கம் செய்யவும்**.
