`@omniroute/opencode-plugin-v2` உங்கள் முழு OmniRoute பட்டியலையும் — models, combos மற்றும்
auto-combos — காட்சிப் பெயர்கள், விலை விவரங்கள் மற்றும் இலவச அடுக்கு
வரம்புகளுடன் OpenCode v2-இன் model picker-இல் சேர்க்கிறது.

இது `@omniroute/opencode-plugin`-இலிருந்து தனியான package ஆகும்; ஏனெனில் OpenCode v1 மற்றும் v2 ஆகியவை
வெவ்வேறு ஒப்பந்தங்கள் மூலம் plugins-ஐ ஏற்றுகின்றன. உங்கள் OpenCode major பதிப்புக்குப் பொருந்துவதைத்
தேர்ந்தெடுக்கவும்; அவற்றுக்கிடையே எதுவும் பகிரப்படுவதில்லை, எனவே ஒன்றை மேம்படுத்துவது மற்றொன்றை ஒருபோதும் கட்டாயப்படுத்தாது.

## தேவைகள்

- OpenCode v2.
- அணுகக்கூடிய OmniRoute gateway (இயல்பாக `http://localhost:20128`).
- Node.js 22 அல்லது 24.

## நிறுவல்

`opencode.json`-இல் plugin-ஐச் சேர்க்கவும்:

```json
{
  "plugins": [
    {
      "package": "@omniroute/opencode-plugin-v2",
      "options": {
        "providerId": "omniroute",
        "baseURL": "http://localhost:20128"
      }
    }
  ]
}
```

பின்னர் models `omniroute/<provider>/<model>` என்ற வடிவில் தோன்றும்; `providerId` அந்த முன்னொட்டையும்
OpenCode நற்சான்றைச் சேமிக்கும் integration-இன் id-யையும் தீர்மானிக்கிறது.

## நற்சான்றுகள்

Plugin பின்வரும் மூன்று இடங்களில், இந்த வரிசையில், gateway key-ஐத் தேடுகிறது:

1. **OpenCode-இல் நீங்கள் இணைத்த நற்சான்று.** Plugin ஓர் integration-ஐப் பதிவுசெய்கிறது, எனவே
   OpenCode-இன் சொந்த auth flow key-ஐச் சேமிக்க முடியும். `opencode.json`-இல் எதுவும் சேமிக்கப்படாது — இதையே விரும்பித் தேர்ந்தெடுக்கவும்.
2. ஒவ்வொரு project-க்குமான override-க்கு, plugin options-இல் உள்ள `apiKey`. இது key-ஐ நீங்கள்
   commit செய்யக்கூடிய ஒரு file-இல் வைக்கிறது.
3. environment-இல் உள்ள `OMNIROUTE_API_KEY`.

இந்த மூன்றில் எதுவும் இல்லாவிட்டால், பட்டியல் காலியாக இருக்கும்; அமைதியாக ஒரு காலியான picker-ஐ
விட்டுவிடுவதற்குப் பதிலாக plugin தொடங்கும்போது ஒருமுறை அதைத் தெரிவிக்கும்.

### Management token என்பது வேறொரு key

Combos, provider ஆரோக்கியம் மற்றும் செறிவூட்டல் (காட்சிப் பெயர்கள், விலை விவரங்கள், இலவச அடுக்கு வரம்புகள்) ஆகியவை
gateway-இன் `/api/*` endpoints-இலிருந்து வருகின்றன; பெரும்பாலான deployments இவற்றை inference key-க்கு
பதிலாக ஒரு **management** token-க்குப் பின்னால் கட்டுப்படுத்துகின்றன:

```json
"options": {
  "baseURL": "http://localhost:20128",
  "managementReadToken": "<management read token>"
}
```

அமைக்கப்படாமல் விடப்பட்டால், `managementReadToken` ஆனது `apiKey`-ஐ fallback ஆகப் பயன்படுத்தும். Gateway அந்த fallback-ஐ
நிராகரித்தாலும் பட்டியல் வெளியிடப்படும்; ஆனால் காட்சிப் பெயர்களுக்குப் பதிலாக மூல model ids மட்டுமே இருக்கும்,
canonical alias dedupe, விலை விவரங்கள் மற்றும் combos இருக்காது. இது நிகழும்போது ஒவ்வொரு endpoint-க்கும்
plugin ஒருமுறை எச்சரித்து, endpoint-ஐயும் இழக்கப்பட்டவற்றையும் குறிப்பிடும் — எனவே தரம் குறைந்த picker ஒருபோதும் புரியாத புதிராக இருக்காது.

| -------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `providerId`                     | `"omniroute"`                                       | Provider id, integration id மற்றும் models தோன்றும் முன்னொட்டு                                                        |
| `baseURL`                        | தேவை                                                | Gateway root, `http(s)` மட்டும்; தேவையான இடங்களில் `/v1` பின்னொட்டு சேர்க்கப்படும்                                    |
| `apiKey`                         | இணைக்கப்பட்ட நற்சான்று, பின்னர் `OMNIROUTE_API_KEY` | `/v1/*`-க்கான chat key                                                                                                |
| `managementReadToken`            | `apiKey`-ஐ fallback ஆகப் பயன்படுத்தும்              | `/api/*`-க்கான key — பொதுவாக இது **அதே key அல்ல**                                                                     |
| `displayName`                    | `"OmniRoute"`                                       | picker-இல் உள்ள provider பெயர்                                                                                        |
| `timeoutMs`                      | `10000`                                             | ஒவ்வொரு endpoint-க்குமான fetch timeout (auto-combos 5s பயன்படுத்தும்)                                                 |
| `modelCacheTtlMs`                | `300000`                                            | பட்டியல் cache TTL; disk snapshot ஆனது cold starts-ஐ விரைவுபடுத்தும்                                                  |
| `timeouts`                       | `timeoutMs`-ஐ fallback ஆகப் பயன்படுத்தும்           | ms-இல் ஒவ்வொரு endpoint-க்குமான வரம்புகள்: `models`, `combos`, `autoCombos`, `enrichment`                             |
| `enrichment`                     | `true`                                              | பெயர்கள், விலை விவரங்கள் மற்றும் இலவச அடுக்கு வரம்புகளைப் பெறுதல்                                                     |
| `providerTag`                    | `true`                                              | காட்சிப் பெயருக்கு முன் அது வழிமாற்றும் upstream provider-ஐச் சேர்த்தல்                                               |
| `usableOnly`                     | `false`                                             | gateway provisioned எனத் தெரிவிக்கும் providers-ஐ மட்டும் வைத்திருத்தல்                                               |
| `visibleModels` / `hiddenModels` | `[]`                                                | சரியான பொருத்தம் அல்லது பின்னொட்டுப் பொருத்தம் கொண்ட அனுமதிப் பட்டியல்கள்; மறுப்பு முன்னுரிமை பெறும்                  |
| `geminiSanitization`             | `true`                                              | tool schemas-இலிருந்து Gemini நிராகரிக்கும் JSON-Schema keywords-ஐ நீக்குதல் (`$ref` tools மாற்றமின்றி அனுப்பப்படும்) |
| `apiFormat.allowAnthropic`       | `false`                                             | அனுமதிப் பட்டியலிலுள்ள ids-ஐ Anthropic API block வழியாக வழிமாற்றுதல்                                                  |
| `apiFormat.anthropicModels`      | `[]`                                                | Anthropic-க்கு வழிமாற்றப்படும் முழுமையான model ids                                                                    |
| `logLevel` / `startupDebug`      | `warn` / `false`                                    | Logger விவர அளவு                                                                                                      |

## பட்டியல் எவ்வாறு புதுப்பித்த நிலையில் வைக்கப்படுகிறது

பட்டியல் தேவையானபோது மட்டும் பெறப்பட்டு `modelCacheTtlMs` காலத்திற்கு தற்காலிகச் சேமிப்பில் வைக்கப்படுகிறது; மேலும், கேட்வேயை அணுக முடியாதபோது கடைசியாக அறியப்பட்ட பட்டியல் கிடைக்குமாறு ஒரு வட்டு ஸ்னாப்ஷாட் பாதுகாக்கிறது — செயலிழப்பால் நீங்கள் இழப்பது புதுப்பித்த நிலையை மட்டுமே. மாதிரிகளும் சேர்க்கைகளும் வந்தவுடன் வெளியிடப்படுகின்றன; தானியங்கி சேர்க்கைகள், வழங்குநர் பட்டியல் மற்றும் செறிவூட்டல் மேலடுக்கு ஆகியவை கிடைத்தவுடன் இணைக்கப்படுகின்றன, எனவே மெதுவான ஓர் எண்ட்பாயிண்ட் முழுத் தேர்வியையும் முடக்கி வைத்திருக்க முடியாது.

பெயர்கள் கேட்வே அறிந்துள்ள தகவல்களைக் கொண்டிருக்கும்: ஒரு மாதிரி வழிமாற்றப்படும் அப்ஸ்ட்ரீம் வழங்குநர், ஒரு `[Free]` குறியீடு மற்றும் அதனுடன் கிடைக்கும் பட்ஜெட் — இதனால் ஒரே மாதிரியை வழங்கும் இரண்டு இணைப்புகளை வேறுபடுத்திக் காண முடியும். `"providerTag": false` மூலம் முன்னொட்டை அணைக்கலாம்.

கைமுறைப் புதுப்பிப்பு கட்டளை எதுவுமில்லை: OpenCode v2 கட்டளைகள் ப்ராம்ப்ட் வார்ப்புருக்கள், கால்பேக்குகள் அல்ல; எனவே ஒரு செருகுநிரலால் அத்தகைய கட்டளையை வெளிப்படுத்த முடியாது. புதுப்பிப்புகள் TTL-ஐப் பின்பற்றுகின்றன; பட்டியல் அல்லது மேலடுக்கு உண்மையில் மாறியிருக்கும்போது மட்டுமே ஹோஸ்டிடம் மீளேற்றுமாறு கோரப்படும், ஒவ்வொரு புதுப்பிப்பின்போதும் அல்ல.

## Gemini-இல் கருவி அழைப்பு

கருவி அறிவிப்புகளில் `$schema` அல்லது `additionalProperties` இருந்தால் Gemini முழுக் கோரிக்கையையும் நிராகரித்து, `400 INVALID_ARGUMENT` எனப் பதிலளிக்கிறது. இந்தச் செருகுநிரல், இந்த வழங்குநரின் Gemini மாதிரிக்கு அனுப்பப்படும் கருவி ஸ்கீமாக்களிலிருந்து அந்த முக்கியச்சொற்களை நீக்கி, மற்ற எல்லாக் கோரிக்கைகளையும் மாற்றாமல் விடுகிறது. `$ref` கொண்ட ஒரு கருவி நீக்குதல் செய்யப்படாமல் அப்படியே அனுப்பப்படுகிறது; ஏனெனில் அந்த மேற்கோளை நீக்குவது ஸ்கீமாவை "எதையும் ஏற்கும்" வகையில் விரிவுபடுத்திவிடும்.
இதை அணைக்க `"geminiSanitization": false` என அமைக்கவும்.
