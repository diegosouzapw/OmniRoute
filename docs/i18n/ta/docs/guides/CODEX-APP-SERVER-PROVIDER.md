OmniRoute, OpenAI Codex-ஐப் பயன்படுத்த **இரண்டு** வழிகளை வழங்குகிறது:

| வழங்குநர்              | OpenAI உடன் இது எவ்வாறு தொடர்புகொள்கிறது                                                                                                                                                         | பயன்பாட்டுக் கட்டுப்பாடு                                                          |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| **`codex`**            | உங்கள் ChatGPT/OpenAI OAuth டோக்கனை Responses API-க்கு நேரடியாக மீண்டும் அனுப்புகிறது                                                                                                            | **ஆம்** — அதிகாரப்பூர்வ அமர்வு proxy/router பயன்பாட்டிற்காக அங்கீகரிக்கப்படவில்லை |
| **`codex-app-server`** | JSON-RPC/WebSocket வழியாக **Codex CLI-யின் சொந்த `codex app-server`**-ஐ இயக்குகிறது; ஊடாடும் `codex` அமர்வைப் போலவே CLI தனது OAuth-ஐ (`~/.codex/auth.json`) நிர்வகித்து, தானாகப் புதுப்பிக்கிறது | **இல்லை** — OmniRoute ஒருபோதும் டோக்கனை API-க்கு மீண்டும் அனுப்புவதில்லை          |

`codex-app-server` ஒருபோதும் டோக்கனை மீண்டும் அனுப்பாததால், அதற்கு
அமர்வு-மீளனுப்பல் பயன்பாட்டுக் கட்டுப்பாடு பொருந்தாது. ஆனால், **கட்டமைக்கப்பட்ட
app-server URL-இல் அணுகக்கூடிய Codex CLI** அதற்குத் தேவை; மேலும் அந்த CLI-யில்
**உள்நுழைந்திருக்க** வேண்டும்.

## 1. கட்டமைப்பு

```
┌─ OmniRoute செயலி ───────────────┐        ┌─ codex-app-server sidecar ─────────┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                   │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456         │
│  (+ திறன் டோக்கன்)               │  JSON  │  --ws-auth capability-token         │
│                                  │  RPC   │  OpenAI OAuth-ஐத் தானே நிர்வகிக்கிறது │
└──────────────────────────────────┘        │  (~/.codex/auth.json, தானியக்கப் புதுப்பிப்பு) │
        │ பகிர்கிறது (compose volumes)       └─────────────────────────────────────┘
        ▼
  codex-appserver-token   → WS திறன் டோக்கன் (இரண்டும் இதை mount செய்கின்றன)
  codex-appserver-home    → ~/.codex (dashboard எழுதும் auth.json,
                             sidecar-இன் codex app-server படிக்கும்)
```

- திறன் டோக்கனுக்குப் பின்னால் உள்ளக compose பிணையத்தில்
  (`ws://codex-app-server:1456`) **மட்டுமே** sidecar செவிமடுக்கிறது. இது host
  அல்லது இணையத்தில் **ஒருபோதும்** வெளியிடப்படுவதில்லை.
- Codex CLI, `omniroute:base`-இல் முன்பே சேர்க்கப்பட்டுள்ளது; எனவே sidecar-ஐ
  இயக்கும்போது host அல்லது பயனரின் கணினியில் codex-ஐ நிறுவ வேண்டியதில்லை.

## 2. அதை இயக்குதல்

```bash
# codex app-server sidecar profile உடன் stack-ஐத் தொடங்கவும்:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

முதல் boot-இல் sidecar தனது WS திறன் டோக்கனை உருவாக்கி (பகிரப்பட்ட
`codex-appserver-token` volume-இல்), செயலி அதே டோக்கனை
`OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE` வழியாகப் படிக்கிறது. கைமுறையாக
டோக்கனை இணைக்க வேண்டியதில்லை.

## 3. இணைத்தல் + உள்நுழைதல்

1. dashboard-இல், **OpenAI Codex (App-Server)**-க்கான இணைப்பைச் சேர்க்கவும். API
   key அல்லது டோக்கன் தேவையில்லை (இது அங்கீகாரம் தேவையற்ற வழங்குநர் —
   அங்கீகாரத்தை sidecar நிர்வகிக்கிறது).
2. sidecar-இன் Codex CLI-யில் **இன்னும் உள்நுழையவில்லை** என்றால், இணைப்பின்
   நிலைச் சரிபார்ப்பு _"இயங்குகிறது, ஆனால் உள்நுழையவில்லை"_ என்று தெரிவிக்கும்
   (சிவப்பு அங்கீகாரப் பிழையாக அல்ல). **ChatGPT மூலம் உள்நுழைக** என்பதைப்
   பயன்படுத்தவும்: இது உங்கள் browser-இல் வழக்கமான Codex device-OAuth-ஐ
   இயக்கி, பின்னர் **அங்கீகாரத்தைப் பயன்படுத்து** என்பதன் மூலம் பகிரப்பட்ட
   volume-இல் `~/.codex/auth.json`-ஐ எழுதுகிறது (அதே ஒரு உள்நுழைவு `codex`
   மற்றும் `codex-app-server` ஆகிய இரண்டு வழங்குநர்களுக்கும் பயன்படும்).
3. உள்நுழைந்ததும், நிலைச் சரிபார்ப்பு பச்சை நிறமாக மாறி (`/readyz` **மற்றும்**
   `account/read` இரண்டையும் சரிபார்க்கிறது — அதாவது, இயங்குவதையும்
   அங்கீகரிக்கப்பட்டிருப்பதையும்) செயல்படத் தொடங்குகிறது.

ஆரோக்கியமான ஏற்கனவே உள்ள `~/.codex/auth.json`-ஐ dashboard ஒருபோதும்
மேலெழுதாது — கோப்பு இல்லாதபோது அல்லது அதன் டோக்கன் காலாவதியாகியிருக்கும்போது
மட்டுமே அது எழுதும் (எப்போதும் ஒரு காப்புப்பிரதி எடுக்கப்படும்).

## 4. நிறுவல் சூழல்கள்

- **ஏற்கனவே அங்கீகரிக்கப்பட்ட Codex CLI கொண்ட operator** — உங்கள் host-இன்
  `~/.codex`-ஐ sidecar-இல் (`codex-appserver-home`) mount செய்து, உள்நுழைவுப்
  படியைத் தவிர்க்கவும்.
- **பொது பயனர், உள்ளூரில் codex நிறுவப்படவில்லை** — இது பொருத்தமற்றது:
  sidecar-இல் CLI உள்ளது. பயனர் dashboard வழியாக மட்டும் அங்கீகரிக்கிறார்.
- **Bare-metal OmniRoute (sidecar இல்லை, host codex)** — உங்கள் சொந்த
  `codex app-server`-ஐ நோக்கி `OMNIROUTE_CODEX_APPSERVER_WS`-ஐ அமைத்து, host
  codex-இல் உள்நுழைந்திருப்பதை உறுதிசெய்யவும்; binary இல்லாவிட்டால்
  "codex நிறுவப்படவில்லை" என்ற குறிப்பு தோன்றும்.

## 5. குடியிருப்பு / UDP வெளியேற்றம் (operator-க்கான கூடுதல் வசதி, வழங்கப்படவில்லை)

மேலே உள்ள பொதுவான sidecar, container-இன் வழக்கமான பிணையம் வழியாக
வெளியேறுகிறது. **குடியிருப்பு வெளியேற்றம்** வழியாக Codex traffic வெளியேற
வேண்டிய operator (எ.கா., TCP + UDP/QUIC-ஐக் கொண்டு செல்லும் TUN tailscale
sidecar), அதைத் தனியான compose override ஆக இயக்க வேண்டும்; வழங்கப்படும்
`codex-app-server` profile-இன் பகுதியாக இது வேண்டுமென்றே சேர்க்கப்படவில்லை.
அந்த அமைப்புக்கு உள்ளகச் செயல்பாட்டு runbook-ஐப் பார்க்கவும்.
