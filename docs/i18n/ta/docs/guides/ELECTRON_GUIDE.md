> **உண்மையின் ஆதாரம்:** `electron/` பணியிடம்
> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-06-28 — v3.8.40

OmniRoute ஆனது **Electron 41** + **electron-builder 26.10** கொண்டு உருவாக்கப்பட்ட, பல தளங்களில் இயங்கும் டெஸ்க்டாப் செயலியை (Windows / macOS / Linux) வழங்குகிறது. டெஸ்க்டாப் செயலி Next.js தனித்தியங்கும் சேவையகத்தை ஒரு துணைச் செயல்முறையாகத் தொடங்கி, அதை நோக்கி ஒரு `BrowserWindow`-ஐ அமைப்பதுடன், கணினித் தட்டு, தானியங்குப் புதுப்பிப்பான், IPC இணைப்புப் பாலம் மற்றும் உள்ளமைவு தேவையற்ற ரகசியத் தொடக்க அமைப்பு ஆகியவற்றையும் சேர்க்கிறது.

- `npm run build:mac-x64` / `build:mac-arm64` — ஒற்றைக் கட்டமைப்பியல் macOS கட்டமைப்புகள்
- `npm run pack` — உள்ளூர் சோதனைக்கான கோப்பகம்-மட்டும் கட்டமைப்பு (நிறுவி இல்லை)

## IPC இணைப்புப் பாலம் (`preload.js`)

முன்ஏற்றமானது `contextIsolation: true` மற்றும் `nodeIntegration: false` ஆகியவற்றுடன்
`contextBridge`-ஐப் பயன்படுத்தி, அனுமதிப்பட்டியலில் உள்ள API-ஐ `window.electronAPI`-இல் வெளிப்படுத்துகிறது.

```javascript
const VALID_CHANNELS = {
  invoke: [
    "get-app-info",
    "open-external",
    "get-data-dir",
    "restart-server",
    "check-for-updates",
    "download-update",
    "install-update",
    "get-app-version",
  ],
  send: ["window-minimize", "window-maximize", "window-close"],
  receive: ["server-status", "port-changed", "update-status"],
};
```

வெளிப்படுத்தப்பட்ட முறைகள்:

| ரெண்டரர் அழைப்பு                                                  | வகை                                      |
| ----------------------------------------------------------------- | ---------------------------------------- |
| `getAppInfo()` → `{ name, version, platform, isDev, port }`       | invoke                                   |
| `openExternal(url)`                                               | invoke                                   |
| `getDataDir()`                                                    | invoke                                   |
| `restartServer()`                                                 | invoke                                   |
| `getAppVersion()`                                                 | invoke                                   |
| `checkForUpdates()` / `downloadUpdate()` / `installUpdate()`      | invoke                                   |
| `minimizeWindow()` / `maximizeWindow()` / `closeWindow()`         | send                                     |
| `onServerStatus(cb)` / `onPortChanged(cb)` / `onUpdateStatus(cb)` | receive (disposer-ஐத் திருப்பியளிக்கும்) |

`removeAllListeners`-ஐச் சார்ந்திருப்பதற்குப் பதிலாக, receive உதவிச் செயல்பாடுகள் ஒரு
**disposer செயல்பாட்டை**த் திருப்பியளிக்கின்றன — React கூறுகள் மீண்டும் ஏற்றப்படும்போது
கேட்பான்கள் குவிவதை இது தடுக்கிறது.

## சேவையக வாழ்க்கைச் சுழற்சி

கணினியின் Node உடன் நேட்டிவ் தொகுதி ABI பொருந்தாமையைத் தவிர்ப்பதற்காக, Electron Node
இயக்கச் சூழலைக் கொண்டு Next.js தனித்த தொகுப்பை `main.js` நேரடியாகத் தொடங்குகிறது:

```js
spawn(process.execPath, [serverScript], {
  cwd: NEXT_SERVER_PATH,
  env: {
    ...serverEnv,
    PORT,
    NODE_ENV: "production",
    ELECTRON_RUN_AS_NODE: "1",
    NODE_PATH,
  },
  stdio: "pipe",
});
```

முக்கிய அம்சங்கள்:

- சாளரத்தைக் காட்டுவதற்கு முன் `waitForServer()` URL-ஐ 30 s வரை அவ்வப்போது சோதிக்கிறது (குளிர் தொடக்கத்தில் வெற்றுத் திரை இருக்காது).
- `stdio: "pipe"` ஆனது stdout/stderr-ஐப் பிடிக்கிறது; தயார் நிலையைக் குறிக்கும் சொற்றொடர்கள் (`Ready` / `listening`) IPC வழியாக `server-status: running`-ஐ வெளியிடுகின்றன.
- இயல்பான SIGTERM நிறைவுக்காக (WAL checkpoint) `before-quit` அதிகபட்சம் 5 s வரை காத்திருந்து, பின்னர் SIGKILL-ஐ அனுப்புகிறது.
- தட்டு மெனுவிலுள்ள போர்ட் மாற்றி (`20128`, `3000`, `8080`) சேவையகத்தை நிறுத்தி மீண்டும் தொடங்கிய பின் BrowserWindow-ஐ மீளேற்றுகிறது.

## கட்டமைப்பு இல்லாத ரகசியத் தொடக்க அமைப்பு

முதல் தொடக்கத்தின்போது, பிரதான செயல்முறை விடுபட்ட ரகசியங்களைத் தானாக உருவாக்கி, நிரந்தரமாகச் சேமிக்கிறது:

| ரகசியம்                  | மூலம்                                                                                               |
| ------------------------ | --------------------------------------------------------------------------------------------------- |
| `JWT_SECRET`             | `crypto.randomBytes(64).toString("hex")`                                                            |
| `STORAGE_ENCRYPTION_KEY` | `crypto.randomBytes(32).toString("hex")` (குறியாக்கப்பட்ட நற்சான்றுகள் ஏற்கனவே இருந்தால் மறுக்கும்) |
| `API_KEY_SECRET`         | `crypto.randomBytes(32).toString("hex")`                                                            |

`<DATA_DIR>/server.env` இல் நிரந்தரமாகச் சேமிக்கப்படுகிறது. `DATA_DIR` பின்வருமாறு தீர்மானிக்கப்படுகிறது:

- Windows: `%APPDATA%\omniroute`
- Linux: `$XDG_CONFIG_HOME/omniroute` அல்லது `~/.omniroute`
- macOS: `~/.omniroute`

## சாளரம் மற்றும் அமைப்புத் தட்டு

- `BrowserWindow`: 1400×900 (குறைந்தபட்சம் 1024×700), `backgroundColor: "#0a0a0a"`.
- macOS: `titleBarStyle: "hiddenInset"`, போக்குவரத்து விளக்கு `{ x: 16, y: 16 }` இடத்தில்.
- Windows/Linux: இயல்பமைவு தலைப்புப் பட்டை.
- மூடுதல் பொத்தான் சாளரத்தை அமைப்புத் தட்டில் சிறிதாக்குகிறது; அமைப்புத் தட்டு மெனுவில் **OmniRoute-ஐத் திற**, **டாஷ்போர்டைத் திற** (வெளிப்புற உலாவி), **சேவையகப் போர்ட்** துணைமெனு, **புதுப்பிப்புகளைச் சரிபார்**, **வெளியேறு** ஆகியவை உள்ளன.

## உள்ளடக்கப் பாதுகாப்புக் கொள்கை

`session.defaultSession.webRequest.onHeadersReceived` வழியாக அமைக்கப்படுகிறது. குறிப்பிடத்தக்க நெறிமுறைகள்:

- `frame-ancestors 'none'`, `object-src 'none'`, `child-src 'none'`
- `connect-src 'self' http://localhost:* http://127.0.0.1:* ws://localhost:* ws://127.0.0.1:* https://*.omniroute.online https://*.omniroute.dev`
- உருவாக்கப் பயன்முறை `script-src`-இல் மட்டும் `'unsafe-eval'`-ஐச் சேர்க்கிறது

## தானியங்குப் புதுப்பிப்பு

GitHub வழங்குநருடன் (`diegosouzapw/OmniRoute`) `electron-updater`-ஐப் பயன்படுத்துகிறது.

- `autoDownload = false`, `autoInstallOnAppQuit = true`
- நிகழ்வுகள் `update-status` IPC வழியாக ரெண்டரருக்கு அனுப்பப்படுகின்றன:
  `checking`, `available`, `not-available`, `downloading` (`percent` உடன்), `downloaded`, `error`
- `installUpdate()` சேவையகத்தை நிறுத்திவிட்டு, பின்னர் `autoUpdater.quitAndInstall()`-ஐ அழைக்கிறது
- உருவாக்கப் பயன்முறையில் (`!app.isPackaged`) தவிர்க்கப்படுகிறது

## கட்டுமானச் செயல்தொடர்

1. `npm run build` → `.next/standalone`-இல் Next.js standalone.
2. `prepare-electron-standalone.mjs` → `.next/electron-standalone`-இல் மீண்டும் நிலைப்படுத்தி, தொகுப்பை இடமாற்றக்கூடியதாக்க `server.js` + `required-server-files.json` ஆகியவற்றிற்குள் உள்ள முழுமையான பாதைகளை மீண்டும் எழுதுகிறது.
3. `electron-builder`, `main.js`, `preload.js`, `node_modules` மற்றும் `extraResources: { ../.next/electron-standalone → app }` ஆகியவற்றைத் தொகுப்பாக்குகிறது.

### கட்டுமான இலக்குகள்

| OS      | இலக்குகள்                                             |
| ------- | ----------------------------------------------------- |
| Windows | NSIS நிறுவி + எடுத்துச்செல்லக்கூடிய பதிப்பு (x64)     |
| macOS   | DMG (Intel + arm64, Applications-க்கு இழுத்துவிடுதல்) |
| Linux   | AppImage + DEB (x64 + arm64)                          |

NSIS அமைப்புகள்: `oneClick: false`, நிறுவல் கோப்பகத்தைத் தேர்ந்தெடுக்கப் பயனரை அனுமதிக்கிறது, மேலும் Desktop மற்றும் Start-Menu குறுக்குவழிகளை உருவாக்குகிறது.

## தொகுப்பாக்கப்பட்ட கட்டுமானத்தின் புகைச் சோதனை

```bash
npm run electron:smoke:packaged
```

`scripts/dev/smoke-electron-packaged.mjs`:

- தற்போதைய இயங்குதளத்திற்கான தொகுப்பாக்கப்பட்ட இயக்கக்கூடிய கோப்பை `electron/dist-electron/`-இல் தானாகக் கண்டறிகிறது.
- உருவாக்குநர் தரவைத் தொடாதவாறு, தனிமைப்படுத்தப்பட்ட `HOME`/`APPDATA`/`XDG_*` கோப்பகங்களுடன் தொடங்குகிறது.
- 45 வினாடிகளுக்குள் HTTP 200 கிடைக்கிறதா என `http://127.0.0.1:20128/login`-ஐத் தொடர்ந்து வினவுகிறது.
- கடுமையான பிழை வடிவங்களுக்காக (`Cannot find module`, `MODULE_NOT_FOUND`, `ERR_DLOPEN_FAILED`, `Failed to start server` போன்றவை) stderr/stdout-ஐக் கண்காணிக்கிறது.
- தயார்நிலைக்குப் பிறகு 2 வினாடிகள் நிலையான இயக்கத்திற்காகக் காத்திருந்து, பின்னர் SIGTERM-ஐ அனுப்பி, போர்ட் விடுவிக்கப்படும் வரை காத்திருக்கிறது.
- CI-இல், தானாகவே `--no-sandbox --disable-gpu`-ஐ அனுப்புகிறது (Linux-இல் `--disable-dev-shm-usage`-ஐயும் அனுப்புகிறது).

சூழல் மேலெழுதல்கள்: `ELECTRON_SMOKE_APP_EXECUTABLE`, `ELECTRON_SMOKE_URL`, `ELECTRON_SMOKE_TIMEOUT_MS`, `ELECTRON_SMOKE_SETTLE_MS`, `ELECTRON_SMOKE_DATA_DIR`, `ELECTRON_SMOKE_KEEP_DATA`, `ELECTRON_SMOKE_STREAM_LOGS`.

## குறியீட்டு கையொப்பமிடுதல்

`electron/package.json` கையொப்பமிடும் நற்சான்றுகளை நேரடியாக இணைப்பதில்லை. அவற்றை சூழல் மாறிகள் வழியாக `electron-builder`-க்கு வழங்கவும்:

### macOS

```bash
export APPLE_ID=<email>
export APPLE_APP_SPECIFIC_PASSWORD=<password>
export APPLE_TEAM_ID=<id>
export CSC_LINK=path/to/cert.p12
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:mac
```

### Windows

```bash
export CSC_LINK=path/to/cert.pfx
export CSC_KEY_PASSWORD=<cert-password>
npm run electron:build:win
```

### Linux

AppImage கையொப்பமிடுதல் விருப்பத்திற்குரியது — கையொப்பமிட வேண்டுமெனில் `LINUX_GPG_KEY`-ஐ அமைக்கவும்.
