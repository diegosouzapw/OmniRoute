**Claude Code** CLI (`claude`)-ஐ OmniRoute-க்கு — உள்ளூர் அல்லது தொலைநிலை VPS-க்கு —
Codex அமைப்பைப் பிரதிபலிக்கும் வகையில், ஒவ்வொரு மாடலுக்குமான சுயவிவரங்களுடன் இணைக்கவும்.

---

## விரைவான தொடக்கம்

```bash
# உள்ளூர் OmniRoute-உடன் Claude Code-ஐத் தொடங்கவும் (செயலில் உள்ள சூழலைத் தானாகக் கண்டறியும்)
omniroute launch

# தொலைநிலை OmniRoute-உடன் (`omniroute connect <host>`-க்குப் பிறகு இது தானாக நடக்கும்)
omniroute launch --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# ஒவ்வொரு மாடலுக்குமான சுயவிவரங்களை உருவாக்கி, பின்னர் ஒன்றைத் தொடங்கவும்
omniroute setup-claude            # ~/.claude/profiles/<name>/settings.json-இல் எழுதும்
omniroute launch --profile glm52  # OmniRoute வழியாக glm/glm-5.2-ஐப் பயன்படுத்தும் Claude Code
```

## Claude Code ஒரு நுழைவாயிலுடன் எவ்வாறு இணைகிறது

Claude Code, **Anthropic Messages API**-உடன் தொடர்புகொள்கிறது; மேலும் சூழல்
மாறிகள் மூலம் தனிப்பயன் முனைப்புள்ளிக்கு அனுப்பப்படுகிறது (இதில் `--base-url` கொடி இல்லை):

| மாறி                                         | நோக்கம்                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `ANTHROPIC_BASE_URL`                         | நுழைவாயிலின் மூல URL (Claude Code `/v1/messages`-ஐச் சேர்க்கும்). **`/v1` பின்னொட்டு இருக்கக்கூடாது.**             |
| `ANTHROPIC_AUTH_TOKEN`                       | `Authorization: Bearer …` ஆக அனுப்பப்படும் — உங்கள் OmniRoute அணுகல் டோக்கன் / API விசையைப் பயன்படுத்தவும்         |
| `ANTHROPIC_API_KEY`                          | மாற்று வழி: `x-api-key` ஆக அனுப்பப்படும். இரண்டும் அமைக்கப்பட்டிருந்தால், `ANTHROPIC_AUTH_TOKEN` முன்னுரிமை பெறும் |
| `ANTHROPIC_MODEL`                            | குறிப்பிட்ட மாடலைக் கட்டாயப்படுத்தும் (`/model` தேர்வியின் இயல்புநிலையை மீறும்)                                    |
| `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` | `1` → சொந்த `/model` தேர்வி, `/v1/models`-இலிருந்து `claude*`/`anthropic*` மாடல்களைப் பட்டியலிடும்                 |
| `CLAUDE_CODE_MAX_OUTPUT_TOKENS`              | ஒவ்வொரு பதிலுக்குமான வெளியீட்டு டோக்கன்களின் உச்சவரம்பு (எ.கா. `65536`)                                            |
| `CLAUDE_CODE_AUTO_COMPACT_WINDOW`            | தானியங்கு சுருக்கத்திற்கான டோக்கன் வரம்பு                                                                          |

> சூழல் மாறிகள் **தொடக்கத்தில் ஒருமுறை மட்டுமே** படிக்கப்படும் — அவற்றை மாற்றிய பிறகு Claude Code-ஐ மறுதொடக்கம் செய்யவும்.

`omniroute launch` இவை அனைத்தையும் உங்களுக்காக அமைக்கிறது: செயலில் உள்ள சூழலிலிருந்து
அடிப்படை URL + டோக்கனைத் தீர்மானிக்கிறது (எனவே `omniroute connect <vps>`-க்குப் பிறகு
`omniroute launch` நேரடியாகச் செயல்படும்), சேவையகத்தின் நலநிலையைச் சரிபார்த்து, `claude`-ஐ இயக்குகிறது.

## கண்டறிதல் மாற்றுப்பெயர்கள் — Claude அல்லாத மாடல்களை `/model` தேர்வியில் காட்டுதல்

Claude Code-இன் நுழைவாயில் மாடல் கண்டறிதல், `claude` அல்லது `anthropic` எனத் தொடங்கும்
id-களை மட்டுமே பட்டியலிடுகிறது. எனவே `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1`
அமைக்கப்பட்டிருக்கும்போது, சொந்த `/model` தேர்வி பொதுவாக OmniRoute-இன் Claude/Anthropic
மாடல்களை **மட்டுமே** காட்டும் — `kimi/kimi-k2.6` அல்லது `glm/glm-5.2` சரியாக வழிமாற்றப்பட்டாலும்,
அவை ஒருபோதும் தோன்றாது.

OmniRoute, செயல்படுத்தப்பட்ட எந்த மாடலையும் (மற்றும் சேர்க்கையையும்) `claude/…` id-இன் கீழ்
பிரதிபலிக்க முடியும்; இதனால் அது அந்த வடிகட்டலைக் கடந்து தேர்வியில் தோன்றும்:

```
kimi/kimi-k2.6            →  claude/kimi/kimi-k2.6      "Kimi K2.6 (OmniRoute)"
glm/glm-5.2              →  claude/glm/glm-5.2         "GLM 5.2 (OmniRoute)"
<combo "custo-otimizado"> →  claude/combo/custo-otimizado
```

Claude Code-இல் இவற்றில் ஒன்றைத் தேர்ந்தெடுக்கும்போது, OmniRoute வழிமாற்றுவதற்கு முன்
`claude/` உறையை அகற்றி, மீண்டும் உண்மையான id-ஐப் பயன்படுத்தும் — உண்மையான
`claude/<real-claude-model>` id (அசல் Claude OAuth வழங்குநர்) எப்போதும் மாற்றப்படாமல் விடப்படும்.

**இது இயல்பாக முடக்கப்பட்டிருக்கும்**; மேலும் மூன்று-நிலை கட்டுப்பாட்டால் நிர்வகிக்கப்படுகிறது
(மிகவும் குறிப்பிட்ட நிலையே முன்னுரிமை பெறும்). எனவே Claude Code-ஐப் பயன்படுத்தாத வாடிக்கையாளர்களுக்காக,
ஒரு சாதாரண OmniRoute அதன் பட்டியலை இரட்டிப்பாக்காது:

| நிலை      | இருப்பிடம்                                                                                  |
| --------- | ------------------------------------------------------------------------------------------- |
| மாடல்     | வழங்குநர் விவரப் பக்கம் → ஒவ்வொரு மாடலுக்குமான "Claude Code-இல் காட்டு" நிலைமாற்றி          |
| வழங்குநர் | வழங்குநர் விவரப் பக்கம் → வழங்குநர்-நிலை நிலைமாற்றி (அதன் அனைத்து மாடல்களையும் உள்ளடக்கும்) |
| உலகளாவிய  | அமைப்புகள் → அம்சக் கொடிகள் → `EXPOSE_CC_DISCOVERY_ALIASES` (இயல்பாக முடக்கப்பட்டிருக்கும்) |

`EXPOSE_CC_DISCOVERY_ALIASES` சூழல் மாறி, உலகளாவிய நிலையை கட்டாயமாகச் செயல்படுத்தி,
டாஷ்போர்டு மேலெழுதலைவிட முன்னுரிமை பெறுகிறது (அவ்வாறு இருக்கும்போது, அம்சக் கொடிகள் திரை
"சூழல் மாறி வழியாகச் செயலில் உள்ளது" என்ற குறிப்பைக் காட்டும்). ஒவ்வொரு வழங்குநர் மற்றும்
ஒவ்வொரு மாடலுக்குமான நிலைமாற்றிகள் இதை மேலும் நுணுக்கமாக்குகின்றன — எ.கா. உலகளாவிய நிலை
முடக்கப்பட்டு + Kimi வழங்குநர் இயக்கப்பட்டிருந்தால், Kimi-யின் மாடல்கள் மட்டுமே வெளிப்படுத்தப்படும்.

> ⚠️ **Claude அல்லாத மாடல்களில் சாளரப் பொருத்தமின்மை.** Claude Code, தனக்குத் தெரியாத எந்த id-க்கும்
> 200K சூழல் சாளரம் இருப்பதாகக் கருதுகிறது (`/v1/models`-இலிருந்து உண்மையான சாளர அளவை அதனால்
> படிக்க முடியாது). பெரிய சாளரம் கொண்ட மாடலுக்கு (எ.கா. Kimi K2-இன் 256K),
> `CLAUDE_CODE_AUTO_COMPACT_WINDOW`-ஐ மாடலின் உண்மையான சாளரத்தைவிடக் குறைவான மதிப்பாக அமைக்கவும்;
> இதனால் தானியங்கு சுருக்கம் முன்கூட்டியே செயல்படாது. மேலே உருவாக்கப்பட்ட சுயவிவரங்கள் ஏற்கனவே
> ஒவ்வொரு மாடலுக்கும் இதைச் செய்கின்றன.

## டாஷ்போர்டில் உள்ள ஆரம்ப அமைப்புத் தொகுதி

Claude கருவி அட்டை (**டாஷ்போர்டு → CLI குறியீடு**) இந்த instance-க்கான துல்லியமான `settings.json` பகுதியை, discovery-alias தகவல் பொத்தானுக்கு அருகில், நகலெடுக்கும் பொத்தானுடன் காண்பிக்கிறது:

```jsonc
{
  "env": {
    "ANTHROPIC_BASE_URL": "http://<உங்கள் OmniRoute>:20128",
    "ANTHROPIC_AUTH_TOKEN": "<உங்கள் OmniRoute API key>",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
  },
}
```

அடிப்படை URL என்பது அட்டையால் தீர்மானிக்கப்பட்ட URL ஆகும் (நீங்கள் உள்ளிட்ட தனிப்பயன் override உட்பட), மேலும் அது ஏற்கனவே இயல்பாக்கப்பட்டுள்ளது — `/v1` பின்னொட்டு இல்லை, இறுதியில் slash இல்லை. **Key ஒருபோதும் காண்பிக்கப்படாது**: இந்தத் தொகுதியில் placeholder மட்டுமே இடம்பெறும்; எனவே screenshot அல்லது ஒட்டப்பட்ட snippet மூலம் key கசிய முடியாது. அதன் மீது உங்கள் key-ஐ ஒட்டவும்.

உண்மையான context window 200K அல்லாத எந்த model-க்கும், அதே `env` தொகுதியின் கீழ் `CLAUDE_CODE_AUTO_COMPACT_WINDOW`-ஐச் சேர்க்கவும் — Claude Code தனக்குத் தெரியாத ஒவ்வொரு id-க்கும் 200K எனக் கருதுகிறது; எனவே இதைச் செய்யாவிட்டால் auto-compaction தவறான இடத்தில் செயல்படும் (முந்தைய பிரிவிலுள்ள எச்சரிக்கையைப் பார்க்கவும்). Snippet builder இந்த மதிப்பையும் ஏற்றுக்கொள்கிறது; எனவே இலக்கு model-இன் window அளவை அறிந்த caller அதை நேரடியாக வெளியிட முடியும்.

மூலம்: `src/shared/services/claudeCliConfig.ts::buildClaudeDiscoverySettingsSnippet` (`ClaudeGatewayOnboardingBlock` மூலம் காண்பிக்கப்படும், unit-test செய்யப்பட்ட pure builder).

## Profiles (`CLAUDE_CONFIG_DIR`)

Claude Code-இல் **சொந்த profile கோப்புகள் இல்லை** (Codex-இன் `~/.codex/<name>.config.toml` போலல்லாமல்).
வழக்கமான முறை `CLAUDE_CONFIG_DIR` ஆகும் — ஒவ்வொரு profile-க்கும் தனித்தனி config அடைவு; ஒவ்வொன்றிலும் அதற்குரிய `settings.json`, credentials, history மற்றும் cache இருக்கும்.

`omniroute setup-claude`, நேரடி `/v1/models` பட்டியலைப் பெற்று, ஒவ்வொரு model-க்கும் ஒரு profile-ஐ `~/.claude/profiles/<name>/settings.json` இல் எழுதுகிறது; இதில் **`setup-codex` பயன்படுத்தும் அதே பெயர்கள்** (`glm52`, `kimi-k27`, `deepseek-pro`, …) மீண்டும் பயன்படுத்தப்படுகின்றன:

```jsonc
// ~/.claude/profiles/glm52/settings.json
{
  "$schema": "https://json.schemastore.org/claude-code-settings.json",
  "model": "glm/glm-5.2",
  "effortLevel": "xhigh",
  "env": {
    "ANTHROPIC_BASE_URL": "http://192.168.0.15:20128",
    "ANTHROPIC_MODEL": "glm/glm-5.2",
    "CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY": "1",
    "CLAUDE_CODE_AUTO_COMPACT_WINDOW": "190000",
  },
}
```

> **Auth token ஒருபோதும் profile-இல் எழுதப்படாது.** `omniroute launch --profile <name>` மூலம் தொடங்கவும் (இது செயலில் உள்ள context-இலிருந்து `ANTHROPIC_AUTH_TOKEN`-ஐச் செலுத்துகிறது), அல்லது `ANTHROPIC_AUTH_TOKEN`-ஐ நீங்களே export செய்துவிட்டு
> `CLAUDE_CONFIG_DIR=~/.claude/profiles/<name> claude`-ஐ இயக்கவும்.

**Model discovery-க்குப் பிறகான auto-sync (விருப்பத் தேர்வு).** Provider model sync ஒன்று நேரடி catalog-ஐ மாற்றும் ஒவ்வொரு முறையும், இதே `~/.claude/profiles/<name>/settings.json` கோப்புகளை OmniRoute தானாக மீண்டும் உருவாக்க முடியும் — இதனால் command-ஐ மீண்டும் இயக்காமலேயே புதிய/மறுபெயரிடப்பட்ட model-களுக்கான profile-கள் கிடைக்கும். இது **இயல்பாக முடக்கப்பட்டிருக்கும்**: **CLI Code டாஷ்போர்டில்** இருந்து இதை மாற்றவும் ("CLI profile auto-sync" → Claude Code), அல்லது `OMNIROUTE_AUTO_SYNC_CLAUDE_PROFILES=true` என அமைக்கவும் (இது இயல்பாக இயக்கப்பட்டிருக்கும் `CLI_ALLOW_CONFIG_WRITES`-ஐயும் மதிக்கிறது). இயக்கப்பட்டிருக்கும்போது இது profile கோப்புகளை மட்டுமே எழுதும்; உங்கள் செயலில் உள்ள/இயல்புநிலை Claude config, auth அல்லது `~/.claude/settings.json`-ஐ ஒருபோதும் மாற்றாது.

### Profile-களை உருவாக்குதல் + பயன்படுத்துதல்

```bash
# உள்ளூர் OmniRoute
omniroute setup-claude

# தொலைநிலை VPS (ஒவ்வொரு profile-லும் VPS URL-ஐப் பதிக்கிறது)
omniroute setup-claude --remote http://192.168.0.15:20128 --api-key oma_live_xxx

# சில provider-கள் மட்டும்
omniroute setup-claude --only glm,kimi

# எழுதாமல் முன்னோட்டமிடுதல்
omniroute setup-claude --dry-run

# ஒரு profile-ஐத் தொடங்குதல்
omniroute launch --profile kimi-k27
```

## மாதிரி நிலைகள் (விருப்பத்தேர்வு)

Claude Code திறன் நிலைகளுக்கு வழிமாற்றுகிறது. ஒவ்வொரு நிலைக்கும் வெவ்வேறு வழங்குநர்களைப் பயன்படுத்த விரும்பினால், env /
அமைப்புகள் வழியாக அவற்றை OmniRoute மாதிரியுடன் பொருத்தவும்:

```bash
export ANTHROPIC_DEFAULT_OPUS_MODEL="glm/glm-5.2"
export ANTHROPIC_DEFAULT_SONNET_MODEL="kmc/kimi-k2.6"
export ANTHROPIC_DEFAULT_HAIKU_MODEL="glm/glm-4.7-flash"
```

இல்லையெனில், ஒரே `ANTHROPIC_MODEL` (சுயவிவரங்கள் அமைப்பது) அனைத்திற்கும் பயன்படுத்தப்படும்.

## தொலைநிலைப் பயன்முறை

நீங்கள் `omniroute connect <host>`-ஐ இயக்கியதும் ([தொலைநிலைப் பயன்முறை](./REMOTE-MODE.md)-ஐப் பார்க்கவும்), `omniroute launch` மற்றும் `omniroute setup-claude`
தானாகவே அந்தத் தொலைநிலைச் சேவையகத்தை இலக்காகக் கொண்டு, அதற்குரிய வரம்பிடப்பட்ட அணுகல் டோக்கனைப் பயன்படுத்தும் — கூடுதல்
கொடிகள் தேவையில்லை. ஒவ்வொரு அழைப்பிற்கும் `--remote` / `--api-key` மூலம் இதை மீறி அமைக்கலாம்.

## சிக்கல் தீர்த்தல்

**Claude Code நுழைவாயிலைப் புறக்கணிக்கிறது** — `ANTHROPIC_BASE_URL`-இல் **`/v1`
இல்லை** என்பதை உறுதிப்படுத்தி, `claude`-ஐ மறுதொடக்கம் செய்யவும் (தொடங்கும்போது env ஒருமுறை மட்டுமே வாசிக்கப்படும்). `omniroute launch`
இதை உங்களுக்காகக் கையாளும்.

**`/model` தேர்வி காலியாக உள்ளது / நுழைவாயில் மாதிரிகள் இல்லை** — Claude Code
v2.1.219+ மற்றும் `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY=1` தேவை. `claude*` /
`anthropic*` மாதிரி ID-கள் மட்டுமே தேர்வியில் தோன்றும்; வேறு எந்த மாதிரியையும்
`ANTHROPIC_MODEL=<id>` மூலம் கட்டாயப்படுத்தலாம் (சுயவிவரங்கள் இதைத்தான் செய்கின்றன).

**`400 Ambiguous model 'claude-…'`** — Claude Code எப்போதும் **முன்னொட்டு இல்லாத**
மாதிரி ID-களையே அனுப்பும் (எ.கா. `claude-opus-4-8`), எனவே Claude Code (`cc/…`) மற்றும்
Claude (`claude/…`) வழங்குநர்கள் இரண்டும் இணைக்கப்பட்டிருக்கும்போது, வெறும் id இரண்டு வழித்தடங்களுடன் பொருந்துவதால்
OmniRoute ஊகிக்க மறுக்கும். இதை இரு வழிகளில் ஏதேனும் ஒன்றால் சரிசெய்யலாம்: முன்னொட்டுடன் கூடிய id-ஐ
`ANTHROPIC_MODEL=cc/claude-opus-4-8` மூலம் நிலைநிறுத்தவும், அல்லது **முன்னொட்டு இல்லாத Claude மாதிரிகளுக்கு Claude Code-ஐ
விரும்பு** என்பதை இயக்கவும் — Claude வழங்குநர் பக்கத்திலுள்ள மாற்றி, அல்லது
`OMNIROUTE_PREFER_CLAUDE_CODE_FOR_UNPREFIXED_CLAUDE_MODELS=true` (இயல்பாக முடக்கப்பட்டுள்ளது;
[சூழல்](../reference/ENVIRONMENT.md)-ஐப் பார்க்கவும்) — இது வெறும் `claude-*`
ID-களை Claude Code-க்கு வழிமாற்றும். வெளிப்படையான வழங்குநர் முன்னொட்டுகளுக்கே எப்போதும் முன்னுரிமை.

**அங்கீகாரப் பிழைகள்** — சுயவிவரத்தில் டோக்கன் எதுவும் இல்லை. `omniroute launch --profile`-ஐப் பயன்படுத்தவும்
(அது டோக்கனைச் செலுத்தும்) அல்லது `ANTHROPIC_AUTH_TOKEN`-ஐ export செய்யவும்.

**சுயவிவரங்கள் தனிமைப்படுத்தப்படவில்லை** — ஒவ்வொரு சுயவிவரமும் தனித்துவமான `CLAUDE_CONFIG_DIR`;
அமர்வுக்குள் `echo $CLAUDE_CONFIG_DIR` என்பது
`~/.claude/profiles/<name>`-ஐச் சுட்டுகிறதா என்பதைச் சரிபார்க்கவும்.
