இந்த வழிகாட்டி OmniRoute-இல் Kiro (AWS-ஆல் ஹோஸ்ட் செய்யப்படும் AI நிரலாக்க உதவியாளர்) கணக்குகளைச் சேர்ப்பதை விளக்குகிறது,
குறிப்பாக அமர்வு முரண்பாடுகள் இல்லாமல் பல கணக்குகளை ஒரே நேரத்தில் இயக்குவதில் கவனம் செலுத்துகிறது.

---

## பின்னணி: Kiro கணக்குகள் ஏன் முரண்படலாம்

செயலில் உள்ள அமர்வுகளைக் கண்காணிக்க Kiro-வின் பின்புல அமைப்பு AWS SSO OIDC கிளையன்ட் பதிவுகளைப் பயன்படுத்துகிறது.
முக்கியமான கட்டுப்பாடு: **ஒவ்வொரு OIDC கிளையன்ட் பதிவும் ஒரே நேரத்தில் ஒரு செயலில் உள்ள
அமர்வை மட்டுமே ஆதரிக்கும்**. அதே பதிவு செய்யப்பட்ட கிளையன்ட்டைப் பயன்படுத்தி இரண்டாவது சாதனம் அல்லது பயனர்
அங்கீகரிக்கும்போது, முதல் கணக்கின் புதுப்பிப்பு டோக்கனைப் பின்புல அமைப்பு செல்லாததாக்குகிறது.

ஏற்கனவே மற்றொரு Kiro கணக்கு உள்நுழைந்துள்ள ஒரு கணினியில் `kiro-cli login`-ஐ
இயக்கும்போது சிக்கல்களை ஏற்படுத்தும் அதே செயல்முறை இதுவாகும் — புதிய உள்நுழைவு
முதல் கணக்கின் டோக்கனை ரத்து செய்கிறது.

## OmniRoute இதை எவ்வாறு தீர்க்கிறது (v3.8.0+)

v3.8.0 முதல், ஒவ்வொரு Kiro இணைப்பு இறக்குமதியின்போதும் OmniRoute `registerClient()`-ஐ
(AWS SSO OIDC) அழைக்கிறது. இதனால் ஒவ்வொரு OmniRoute இணைப்புக்கும் அதற்கே உரிய பிரத்யேக OIDC
கிளையன்ட் பதிவு கிடைக்கிறது. ஒவ்வொரு கிளையன்ட் பதிவும் சுயாதீனமாக இருப்பதால், ஒரு கணக்கைப் புதுப்பிப்பதோ
அல்லது மீண்டும் அங்கீகரிப்பதோ மற்ற எந்தக் கணக்கின் புதுப்பிப்பு டோக்கனையும் பாதிக்காது.

இந்தத் தனிமைப்படுத்தல் புதுப்பிப்பு-டோக்கன் இறக்குமதி முறைகளுக்குப் பொருந்துகிறது; மேலும் API-key அங்கீகாரம்
OIDC புதுப்பிப்பு அமர்வுகளை முழுமையாகத் தவிர்க்கிறது:

| இறக்குமதி முறை                                                         | தனிமைப்படுத்தல் நிலை                                                                                                                                  |
| ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| AWS Builder ID / IDC சாதனக்-குறியீட்டு ஓட்டம்                          | சாதனக்-குறியீட்டு ஓட்டம் அறிமுகப்படுத்தப்பட்டதிலிருந்து தனிமைப்படுத்தப்பட்டுள்ளது                                                                     |
| **டோக்கனை இறக்குமதி செய்** (புதுப்பிப்பு டோக்கனைக் கைமுறையாக ஒட்டுதல்) | v3.8.0 முதல் தனிமைப்படுத்தப்பட்டுள்ளது                                                                                                                |
| **Google / GitHub சமூக உள்நுழைவு**                                     | v3.8.0 முதல் தனிமைப்படுத்தப்பட்டுள்ளது                                                                                                                |
| **தானியங்கி இறக்குமதி** (kiro-cli SQLite)                              | v3.8.0 முதல் தனிமைப்படுத்தப்பட்டுள்ளது (SQLite பாதை ஏற்கனவே தனிமைப்படுத்தப்பட்டிருந்தது; SSO-cache மாற்று முறையும் இப்போது தனிமைப்படுத்தப்பட்டுள்ளது) |
| **API Key** (நீண்டகால CodeWhisperer விசை)                              | புதுப்பிப்பு அமர்வு இல்லை; விசை சரிபார்க்கப்பட்டு bearer நற்சான்றாகச் சேமிக்கப்படுகிறது                                                               |

## v3.8.0-க்கு முன் உருவாக்கப்பட்ட இணைப்புகளுக்கான இடம்பெயர்வு குறிப்பு

v3.8.0-க்கு முன் இறக்குமதி செய்யப்பட்ட இணைப்புகளுக்கு `providerSpecificData`-இல்
பிரத்யேக OIDC கிளையன்ட் பதிவு சேமிக்கப்பட்டிருக்காது. இந்த இணைப்புகள் தொடர்ந்து செயல்படும், ஆனால் பகிரப்பட்ட
சமூக-அங்கீகார புதுப்பிப்பு முனையத்தைப் பயன்படுத்தும்; இதனால் அத்தகைய இரண்டு இணைப்புகள் இன்னும் ஒன்றையொன்று
செல்லாததாக்கக்கூடும்.

**தனிமைப்படுத்தலைப் பெற:** **கட்டுப்பாட்டுப் பலகை → வழங்குநர்கள்** என்பதிலிருந்து பழைய இணைப்பை நீக்கி,
ஆதரிக்கப்படும் இறக்குமதி ஓட்டங்களில் ஏதேனும் ஒன்றைப் பயன்படுத்தி அதை மீண்டும் இறக்குமதி செய்யவும். புதிதாக உருவாக்கப்படும் அனைத்து இணைப்புகளும்
தானாகவே தங்களுக்கான கிளையன்ட் பதிவைப் பெறும்.

## இரண்டு Kiro கணக்குகளை அருகருகே சேர்த்தல்

### முன்தேவைகள்

- OmniRoute v3.8.0 அல்லது அதற்குப் பிந்தைய பதிப்பு.
- செயல்படும் ஒரு Kiro கணக்கு (மின்னஞ்சல் + கடவுச்சொல், Google அல்லது GitHub உள்நுழைவு).
- விருப்பமாக, இரண்டாவது Kiro கணக்கு.

### படி 1: முதல் கணக்கை இறக்குமதி செய்தல்

1. **கட்டுப்பாட்டுப் பலகை → வழங்குநர்கள் → வழங்குநரைச் சேர் → Kiro** என்பதைத் திறக்கவும்.
2. பின்வருவனவற்றில் ஒன்றைத் தேர்ந்தெடுக்கவும்:
   - **டோக்கனை இறக்குமதி செய்** — `aorAAAAAG` என்று தொடங்கும் புதுப்பிப்பு டோக்கனை ஒட்டவும்.
   - **API Key** — நீண்டகால Kiro / CodeWhisperer API விசையை ஒட்டவும்.
   - **Google / GitHub உள்நுழைவு** — உலாவியில் OAuth ஓட்டத்தை நிறைவு செய்யவும்.
   - **தானியங்கி இறக்குமதி** — பொத்தானைக் கிளிக் செய்யவும்; OmniRoute உள்ளூர் kiro-cli தரவுத்தளத்திலிருந்து அல்லது
     `~/.aws/sso/cache`-இலிருந்து நற்சான்றுகளைப் படிக்கும்.
3. இணைப்பு சேமிக்கப்படுகிறது. புதுப்பிப்பு-டோக்கன் ஓட்டங்கள் தானாகவே ஒரு பிரத்யேக
   OIDC கிளையன்ட்டைப் பதிவு செய்கின்றன. API-key ஓட்டங்கள் AWS மூலம் விசையைச் சரிபார்த்து, புதுப்பிப்பு டோக்கனைச் சேமிப்பதில்லை.

### படி 2: இரண்டாவது கணக்கை இறக்குமதி செய்தல்

இரண்டாவது கணக்கிற்குப் படி 1-ஐ மீண்டும் செய்யவும். ஒவ்வொரு இறக்குமதியும் தனியான OIDC
கிளையன்ட் பதிவை உருவாக்குவதால், இரண்டு இணைப்புகளும் முழுமையாகத் தனிமைப்படுத்தப்பட்டிருக்கும்.

### படி 3: இரு இணைப்புகளும் செயலில் உள்ளனவா என்பதைச் சரிபார்த்தல்

1. **கட்டுப்பாட்டுப் பலகை → வழங்குநர்கள்** — இரண்டு Kiro இணைப்புகளும் **செயலில் உள்ளது** என்ற நிலையைக் காட்ட வேண்டும்.
2. **கட்டுப்பாட்டுப் பலகை → ஆரோக்கியம்** — இரண்டு இணைப்புகளும் அவற்றின் டோக்கன் ஆரோக்கியச் சோதனையில் தேர்ச்சி பெற வேண்டும்.

### படி 4: கணக்குகளுக்கு இடையே வழிமாற்ற ஒரு காம்போவைப் பயன்படுத்துதல்

சுமையைச் சமநிலைப்படுத்த அல்லது அவற்றுக்கு இடையே மாற்று இணைப்பைப் பயன்படுத்த, இரு இணைப்புகளையும் இலக்குகளாகக் கொண்ட ஒரு காம்போவை உருவாக்கவும்:

```
kiro/kiro-dev → kiro/kiro-pro
```

காம்போ உள்ளமைவுக்கு [FEATURES.md](./FEATURES.md) மற்றும் வழிமாற்ற ஆவணங்களைப் பார்க்கவும்.

## நிறுவன / IDC பயனர்கள்

AWS IAM Identity Center (IDC) கணக்குகளுக்கு, **Dashboard → Providers → Kiro → Device Code** வழியாக **AWS Builder ID / IDC சாதனக் குறியீட்டு**
செயல்முறையைப் பயன்படுத்தவும். சாதனக் குறியீட்டுச் செயல்முறை எப்போதும் முழுமையாகத் தனிமைப்படுத்தப்பட்டுள்ளது.
இந்த இணைப்புகளை மீண்டும் இறக்குமதி செய்ய வேண்டியதில்லை.

இயல்புநிலையல்லாத AWS பிராந்தியத்தில் செயல்படும் நிறுவனப் பயனர்கள், Import Token API வழியாக
இறக்குமதி செய்யும்போது பிராந்தியத்தைக் குறிப்பிடலாம்:

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/import \
  -H "Content-Type: application/json" \
  -d '{"refreshToken": "aorAAAAAG...", "region": "eu-west-1"}'
```

`region` புலம் விடுபட்டிருந்தால், அதன் இயல்புநிலை `us-east-1` ஆகும்.

## API விசை இறக்குமதிச் செயல்முறை

API விசை அங்கீகாரம் என்பது நீண்டகாலப் பயன்பாட்டுக்கான Kiro / AWS CodeWhisperer bearer நற்சான்றுகளுக்கானது.
இது OAuth புதுப்பிப்பைப் பயன்படுத்தாததால், பகிரப்பட்ட OIDC அமர்வு செல்லாததாக்கப்படுவதைத் தவிர்க்கிறது.

### கட்டுப்பாட்டுப் பலகை

1. **Dashboard -> Providers -> Kiro** என்பதைத் திறக்கவும்.
2. **API Key** என்பதைத் தேர்ந்தெடுக்கவும்.
3. API விசையையும் விருப்பமான AWS பிராந்தியத்தையும் (இயல்புநிலையாக `us-east-1`) ஒட்டவும்.
4. OmniRoute விசையைச் சரிபார்த்து இணைப்பைச் சேமிக்கும்.

### API

```bash
curl -X POST http://localhost:20128/api/oauth/kiro/api-key \
  -H "Content-Type: application/json" \
  -d '{"apiKey": "kiro_or_codewhisperer_key", "region": "us-east-1"}'
```

### உள் ஒப்பந்தம்

API வழித்தடம் `KiroService.validateApiKey()`-ஐ அழைப்பதன் மூலம் விசையைச் சரிபார்க்கிறது; இது
பிராந்தியத்துடன் பொருந்தும் CodeWhisperer/Amazon Q முனைப்புள்ளிக்கு எதிராக `ListAvailableProfiles`-ஐப்
பயன்படுத்தி, ஒரு `profileArn`-ஐத் தீர்மானிக்கிறது.

சேமிக்கப்பட்ட இணைப்பு பின்வருவதைப் பயன்படுத்துகிறது:

```json
{
  "authType": "apikey",
  "providerSpecificData": {
    "authMethod": "api_key",
    "region": "us-east-1",
    "profileArn": "arn:aws:codewhisperer:..."
  }
}
```

இயக்க நேரத்தில், `KiroExecutor.buildHeaders()` விசையை
`Authorization: Bearer <key>` ஆக அனுப்பி, `tokentype: API_KEY`-ஐச் சேர்க்கிறது. ஒதுக்கீடு/சுயவிவர அழைப்புகள்
அதே குறியீட்டைப் பயன்படுத்துவதால், AWS அந்த bearer-ஐ OIDC அல்லது சமூக அணுகல் டோக்கனாகக் கருதாமல்,
நீண்டகால API விசையாகக் கருதுகிறது.

## OIDC கிளையன்ட் காலாவதி

AWS SSO OIDC பொது கிளையன்ட்கள் பொதுவாக 90 நாட்களுக்குப் பிறகு
காலாவதியாகும் (`clientSecretExpiresAt`). கண்காணிப்புத் திறனுக்காக OmniRoute இந்த நேர முத்திரையை
`providerSpecificData`-இல் சேமிக்கிறது. சுமார் 90 நாட்களுக்குப் பிறகு ஓர் இணைப்பு புதுப்பிக்கப்படுவது
நின்றுவிட்டால், புதிய OIDC கிளையன்ட் பதிவைப் பெற இணைப்பை மீண்டும் இறக்குமதி செய்யவும். காலாவதியாகும்போது
தானாக மறுபதிவு செய்வது எதிர்கால மேம்பாடாகக் கண்காணிக்கப்படுகிறது.

API விசை இணைப்புகள் AWS SSO OIDC வழியாகப் புதுப்பிக்கப்படாததால், அவற்றுக்கு OIDC கிளையன்ட்
காலாவதி இல்லை.

## சிக்கல் தீர்த்தல்

### இரண்டாவது கணக்கு தொடர்ந்து வெளியேற்றப்படுகிறது

- **Dashboard → Providers** என்பதில் இரு இணைப்புகளையும் சரிபார்த்து, ஒவ்வொன்றும் அதன் மூல JSON-இல்
  பூஜ்யமல்லாத `clientId`-ஐக் காட்டுவதை உறுதிப்படுத்தவும் (தகவல் சின்னம் வழியாகக் காணலாம்). ஏதேனும் ஓர் இணைப்பில்
  `clientId` இல்லையெனில், அது v3.8.0-க்கு முன் இறக்குமதி செய்யப்பட்டது — அதை மீண்டும் இறக்குமதி செய்யவும்.

### "Token validation failed" என்ற செய்தியுடன் இறக்குமதி தோல்வியடைகிறது

- புதுப்பிப்பு டோக்கன் `aorAAAAAG` என்பதுடன் தொடங்குவதை உறுதிப்படுத்தவும்.
- OmniRoute-ஆல் `https://oidc.us-east-1.amazonaws.com`-ஐ (அல்லது உள்ளமைக்கப்பட்ட
  பிராந்தியத்தை) அணுக முடிவதை உறுதிப்படுத்தவும். நீங்கள் நிறுவன proxy-க்குப் பின்னால் இருந்தால்,
  **Dashboard → Settings → Proxies** என்பதில் வழங்குநர்-நிலை proxy-ஐ அமைக்கவும்.

### API விசை இறக்குமதி தோல்வியடைகிறது

- அந்த விசை ஒரு Kiro / CodeWhisperer API விசைதான் என்றும், புதுப்பிப்பு டோக்கன் அல்ல என்றும் உறுதிப்படுத்தவும்.
- AWS பிராந்தியம் விசை/கணக்குடன் பொருந்துவதை உறுதிப்படுத்தவும். `us-east-1` என்பது இயல்புநிலை.
- விசையால் `ListAvailableProfiles`-ஐ அழைக்க முடிய வேண்டும்; இல்லையெனில் தேவையான
  `profileArn`-ஐ OmniRoute-ஆல் தீர்மானிக்க முடியாது.

பிற சிக்கல்களுக்கு, முதன்மை [TROUBLESHOOTING.md](./TROUBLESHOOTING.md)-ஐப் பார்க்கவும்.
