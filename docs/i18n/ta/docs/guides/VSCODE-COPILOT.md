## அமைத்தல்

1. **OmniRoute-ஐ இயக்குங்கள்** — `npm install -g omniroute && omniroute` (`http://localhost:20128`-இல் dashboard).
2. **நீட்டிப்பை நிறுவுங்கள்** — Extensions காட்சியில் "OmniRoute" என்பதைத் தேடுங்கள்.
3. **ஒரு மாடலைத் தேர்ந்தெடுங்கள்** — Copilot Chat → மாடல் தேர்வி → **Manage Models…** → **OmniRoute**, பின்னர்
   உங்களுக்குத் தேவையானவற்றைக் குறியிடுங்கள்.

OmniRoute இயல்புநிலை port-இல் இயங்கும்போது எதையும் உள்ளமைக்கத் தேவையில்லை. தொலைநிலை instance ஒன்றுக்கு,
**Activity Bar-இல் உள்ள OmniRoute icon-ஐ** திறந்து (அல்லது `OmniRoute: Manage Connection`-ஐ இயக்கி) பின்வருவனவற்றை அமைக்கவும்:

- **Server URL** — server root, எ.கா. `http://192.168.0.15:20128`. `/v1` suffix-ஐ
  நீட்டிப்பு சேர்க்கும்; அதைச் சேர்க்க வேண்டாம்.
- **API key** — server `REQUIRE_API_KEY`-ஐ அமைத்திருக்கும்போது மட்டும். இது VS
  Code SecretStorage வழியாக OS keychain-இல் சேமிக்கப்படும்; `settings.json`-இல் ஒருபோதும் சேமிக்கப்படாது.

## தேர்வி எதைக் காண்பிக்கும்

நீட்டிப்பு மூல `GET /v1/models` payload-ஐக் காண்பிப்பதில்லை — அதைச் சீரமைக்கிறது; மேலும் நீங்கள்
பார்க்கும் எண்ணிக்கை, திட்டமிட்ட இரண்டு காரணங்களால் catalog அளவைவிடக் குறைவாக இருக்கும்.

### ஒவ்வொரு மாடலுக்கும் ஒரு id-ஐக் கோருகிறது

`MODELS_CATALOG_PREFIX_MODE`-இன் இயல்புநிலை **`dual`** ஆகும்; இது ஒவ்வொரு மாடலையும் இருமுறை விளம்பரப்படுத்துகிறது — ஒன்று
குறுகிய alias prefix-இன் கீழும், மற்றொன்று canonical provider prefix-இன் கீழும் — இதனால் பழைய client
configs இரண்டு வடிவங்களிலும் தொடர்ந்து சரியாகத் தீர்மானிக்க முடியும்:

```
cc/claude-sonnet-4-6        ← alias prefix
claude/claude-sonnet-4-6    ← canonical prefix, அதே மாடல்
```

நீட்டிப்பு **`GET /v1/models?prefix=alias`**-ஐக் கோருவதால், உங்கள் பிற clients-க்கான server-wide
அமைப்பை மாற்றாமலேயே ஒவ்வொரு மாடலுக்கும் ஒரு id மட்டும் கிடைக்கிறது. ஓர் உதாரண instance-இல் இது
**2345 entries-ஐ 1396 ஆகக் குறைத்தது — 949 duplicates, இழந்த மாடல்கள் பூஜ்ஜியம்.**

இதை _ஒவ்வொரு_ client-க்கும் server-wide ஆகச் சரிசெய்ய விரும்பினால், dashboard-இல்
`MODELS_CATALOG_PREFIX_MODE` feature flag-ஐ `alias` ஆக அமைக்கவும். Query parameter மற்றும்
ஒவ்வொரு mode-க்குமான அட்டவணைக்கு [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix)-ஐப் பார்க்கவும்.

### அரட்டையிட முடியாத மாடல்களை மறைக்கிறது

Catalog-இல் image, video, audio, rerank, embedding மற்றும் moderation மாடல்களும் பட்டியலிடப்பட்டுள்ளன. எப்படியும் ஒரு
chat request-இல் அவை நிராகரிக்கப்படும்:

```
HTTP 400 — Model '<id>' என்பது image-generation மாடல்; இதை
/v1/chat/completions-இல் பயன்படுத்த முடியாது. அதற்குப் பதிலாக POST /v1/images/generations-ஐப் பயன்படுத்தவும்.
```

எனவே, தேர்வியை அடைவதற்கு முன் அவை அவற்றின் `type` field அடிப்படையில் வடிகட்டப்படுகின்றன. **Responses-API
மாடல்கள் வைத்துக்கொள்ளப்படுகின்றன** — ஒவ்வொரு Codex / GPT-5.x entry-யும் `supported_endpoints: ["responses"]` என அறிவிக்கிறது;
OmniRoute அவற்றை `/v1/chat/completions`-க்காக மாற்றுவதால், அவற்றை முழுமையாகப் பயன்படுத்தலாம்.

### நீங்கள் ஒருபோதும் உள்ளமைக்காத வழங்குநர்கள்

Catalog, **active connection** கொண்ட வழங்குநர்களின் மாடல்களுடன், அனைத்து **noAuth**
வழங்குநர்களையும் பட்டியலிடுகிறது — free tier-இன் பெரும்பகுதியை உருவாக்கும் keyless வழங்குநர்கள் அவை. இது திட்டமிட்ட நடத்தையே. அவற்றை மறைக்க,
dashboard settings-இல் உள்ள `blockedProviders`-க்கு அவற்றைச் சேர்க்கவும்; நீட்டிப்பில் எதுவும்
மாறாது.

## VS Code தாவலுக்குள் Dashboard

`omnicopilot.dashboardOpen: "editor"` என்பது வெளிப்புற உலாவிக்குப் பதிலாக Simple Browser வழியாக OmniRoute dashboard-ஐ editor தாவலில் காட்சிப்படுத்துகிறது. உட்பொதித்தல் என்பது **server-இல் விருப்பத் தேர்வாக இயக்கப்பட வேண்டியது**; இதற்காக `DASHBOARD_ALLOW_EMBED=vscode` பயன்படுத்தப்படுகிறது. இது இயல்புநிலை `frame-ancestors 'none'` +
`X-Frame-Options: DENY` என்பதற்குப் பதிலாக, HTML பக்கங்களை
`frame-ancestors 'self' vscode-webview:` என்பதுடன் வழங்குகிறது. API பரப்பு (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) எந்த நிலையிலும் கடுமையான headers-ஐத் தொடர்ந்து பயன்படுத்தும்.

> ⚠️ **இது build-time flag; runtime flag அல்ல.** Next.js, `headers()`-ஐ route
> manifest-இல் compile செய்வதால், bundle உருவாக்கப்படும்போதே `next.config.mjs` அந்த variable-ஐப் படிக்கிறது
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> ஏற்கெனவே build செய்யப்பட்ட server-ஐத் தொடங்குவதற்கு முன் இதை export செய்வதால் எந்த மாற்றமும் ஏற்படாது — headers ஏற்கெனவே உட்பொதிக்கப்பட்டிருக்கும்.

```bash
# variable, BUILD command-இல் கட்டாயம் இருக்க வேண்டும்
DASHBOARD_ALLOW_EMBED=vscode npm run build        # அல்லது npm run build:release
npm start
```

| நீங்கள் நிறுவிய விதம்      | உட்பொதித்தலை இயக்க முடியுமா?                                                                                                                                                   |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| source-இலிருந்து           | ✅ மேலே காட்டியபடி build command-இல் variable-ஐ அமைக்கவும்                                                                                                                     |
| `npm install -g omniroute` | ❌ வெளியிடப்பட்ட package, முன்பே build செய்யப்பட்ட bundle உடன் வருகிறது — அதற்குப் பதிலாக source-இலிருந்து build செய்யவும்                                                     |
| Docker image               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — Docker Hub-இல் உள்ள முன்பே build செய்யப்பட்ட image, உட்பொதித்தலை ஆதரித்து உருவாக்கப்படவில்லை |

உட்பொதித்தலை ஆதரிக்கும் build இல்லையெனில், page frame செய்யப்படுவதை மறுக்கும்; extension அதை response headers-இலிருந்து கண்டறிந்து வெளிப்புற browser-க்குத் தானாக மாறும் — எதுவும் செயலிழக்காது, மேலும் இது குறித்து ஒருமுறை தெரிவிக்கும்.
[`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) மற்றும் issue
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273) ஆகியவற்றைப் பார்க்கவும்.

[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md)-இல் விவரிக்கப்பட்டுள்ள அதே configs ஆகும். API key, command line-இல் ஒருபோதும் வழங்கப்படாமல்,
`OMNIROUTE_API_KEY` environment variable வழியாக CLI-க்கு வழங்கப்படுகிறது.

| picker-இல் OmniRoute models எதுவும் இல்லை                      | Server-ஐ அணுக முடியவில்லை. status-bar புள்ளி சாம்பல் நிறமாக மாறும்; `OmniRoute: Check Connection`-ஐ இயக்கவும். Discovery வடிவமைப்பின்படி அமைதியாக நடைபெறும்; கேள்வி கேட்பதற்குப் பதிலாக எந்த models-ஐயும் வழங்காது.                                                                                                       |
| ஒவ்வொரு model-உம் இருமுறை தோன்றுகிறது                          | நீங்கள் 1.0.1-ஐ விடப் பழைய OmniCopilot பதிப்பைப் பயன்படுத்துகிறீர்கள் — update செய்யவும். extension இப்போது `?prefix=alias`-ஐ கோருகிறது.                                                                                                                                                                                  |
| முன்பு பட்டியலிடப்பட்ட image/audio model இப்போது காணப்படவில்லை | 1.0.1 முதல் இது வேண்டுமென்றே செய்யப்பட்ட மாற்றம் — அதனால் chat request-க்கு ஒருபோதும் பதிலளிக்க முடியாது.                                                                                                                                                                                                                 |
| Activity Bar-இல் panel காணப்படவில்லை                           | VS Code, கூடுதல் view containers-ஐ Activity Bar-இன் அடிப்பகுதியில் உள்ள **"…"** overflow-க்குள் நகர்த்துகிறது; right-click மூலம் மறைக்கப்பட்ட container தொடர்ந்து மறைந்தே இருக்கும். Activity Bar-ஐ right-click செய்து → **OmniRoute**-ஐத் தேர்வுசெய்யவும், அல்லது `OmniRoute: Manage Connection` மூலம் அதைத் திறக்கவும். |
| `editor` mode இருந்தும் Dashboard browser-இல் திறக்கிறது       | server, `DASHBOARD_ALLOW_EMBED=vscode` உடன் **build** செய்யப்படவில்லை (மேலே பார்க்கவும்) — முன்பே build செய்யப்பட்ட install-இல் startup நேரத்தில் அதை அமைப்பதால் எந்த மாற்றமும் ஏற்படாது. தானாக மாறும் fallback திட்டமிட்ட நடத்தையாகும்.                                                                                  |
