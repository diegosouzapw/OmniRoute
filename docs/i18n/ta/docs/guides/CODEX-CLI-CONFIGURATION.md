OmniRoute-ஐ OpenAI-இணக்கமான பின்தளமாகப் பயன்படுத்துமாறு Codex CLI-ஐ அமைப்பதற்கான முழுமையான வழிகாட்டி.

---

> **TOML மட்டுமே செயல்படும் வடிவமாகும்.** நவீன Codex, `~/.codex/config.toml`-ஐ
> மட்டுமே வாசிக்கிறது (codex-cli 0.147.0-இல் சரிபார்க்கப்பட்டது: `codex --help`,
> `-c/--config` மேலெழுதல்கள் "`~/.codex/config.toml`-இலிருந்து ஏற்றப்படும்" என
> ஆவணப்படுத்துகிறது). பழைய `~/.codex/config.yaml`, மரபுவழி npm CLI-க்குச்
> சொந்தமானது; அது எந்த அறிவிப்புமின்றிப் புறக்கணிக்கப்படுகிறது.
> டாஷ்போர்டு உருவாக்கி (`/api/cli-tools/apply`, கருவி `codex`) கவனமான
> ஒன்றிணைப்புடன் TOML-ஐ எழுதுகிறது — ஏற்கெனவே உள்ள விசைகளும் பிற வழங்குநர்
> தொகுதிகளும் பாதுகாக்கப்படுகின்றன, API விசை `OMNIROUTE_API_KEY`-இல் இருக்கும்
> (ஒருபோதும் கோப்பில் இருக்காது), மேலும் மீதமுள்ள மரபுவழி `config.yaml`
> தொடப்படாமல், இடம்பெயர்வுக் குறிப்பாகத் தெரிவிக்கப்படுகிறது.

## நேரடியாக ஒட்டத் தயாரான config.toml

`<YOUR_HOST>` மற்றும் `<YOUR_KEY>` ஆகியவற்றை உங்கள் மதிப்புகளால் மாற்றவும்:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # ஒவ்வொரு கருவி அழைப்புக்குமான வரலாற்றுச் சேமிப்பு வரம்பு

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc அல்லது ~/.zshrc — உண்மையான விசை மதிப்பு, config.toml-இல் ஒருபோதும் இருக்கக்கூடாது
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: ChatGPT செயலிக்குள் தொகுக்கப்பட்ட Codex

ChatGPT டெஸ்க்டாப் செயலியின் வழியாக Codex-ஐ நிறுவியிருந்தால், `codex` பைனரி
செயலித் தொகுப்புக்குள் மட்டும் இருக்கக்கூடும்; இன்னும் உங்கள் shell `PATH`-இல்
இருக்காது. வளங்கள் கோப்பகத்தை உங்கள் shell தொடக்கக் கோப்பில் சேர்க்கவும்:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

புதிய shell-ஐத் திறந்து, பின்னர் சரிபார்க்கவும்:

```bash
command -v codex
codex --version
```

### அங்கீகாரம் தேவையில்லாத உள்ளூர் OmniRoute: தற்காலிக விசை போதுமானது

முதல் கோரிக்கை CLI-ஐ விட்டு வெளியேறும் **முன்பே**, `env_key` குறிப்பிடும்
சூழல் மாறி இருப்பதை Codex சரிபார்க்கிறது. உங்கள் **உள்ளூர்** OmniRoute
நிகழ்விற்கு அங்கீகாரம் தேவையில்லை என்றால், காலியாக இல்லாத எந்தத் தற்காலிக
மதிப்பும் செயல்படும்:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

உங்கள் OmniRoute சேவையகம் பாதுகாக்கப்பட்டதாகவோ தொலைநிலையில் உள்ளதாகவோ இருந்தால்,
அதற்குப் பதிலாக உண்மையான விசையைப் பயன்படுத்தவும்.

> **பொதுவான ஹோஸ்ட் விருப்பங்கள்**
>
> | அணுகல்          | URL                           |
> | --------------- | ----------------------------- |
> | உள்ளூர் பிணையம் | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | Loopback        | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — இது எல்லா மாதிரிகளுக்கும் ஏன் செயல்படுகிறது

Codex CLI, பிப்ரவரி 2026-இல் `wire_api = "chat"` (Chat Completions)-ஐ வழக்கொழிந்ததாக அறிவித்தது; தற்போது அது `wire_api = "responses"` (OpenAI Responses API)-ஐ **கட்டாயமாக்குகிறது**. v0.138 முதல் `wire_api = "chat"` என அமைப்பது தொடங்கியவுடன் உடனடி செயலிழப்பை ஏற்படுத்தும்.

GLM மற்றும் Kimi உள்ளிட்ட பல வழங்குநர்கள் இன்னும் Chat Completions முனைப்புள்ளியை மட்டுமே வழங்குகின்றனர். DeepSeek V4 தற்போது சொந்த Responses API-ஐயும் Anthropic-இணக்கமான முனைப்புள்ளியையும் வழங்குகிறது; OmniRoute இயல்பாக Responses-ஐப் பயன்படுத்துகிறது மற்றும் ஒவ்வொரு DeepSeek இணைப்பும் Anthropic இணக்கத்தன்மையைத் தேர்ந்தெடுக்க அனுமதிக்கிறது.

**OmniRoute இதை வெளிப்படையாகத் தீர்க்கிறது:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute வழங்குநரின் சொந்த நெறிமுறையைத் தேர்ந்தெடுத்து, தேவைப்படும்போது மொழிபெயர்க்கிறது
    → POST /responses (DeepSeek V4) அல்லது /chat/completions (Mistral / GLM / Kimi / மற்றவை)
```

OmniRoute-ஐப் பயன்படுத்தும்போது தனியான மொழிபெயர்ப்பு ப்ராக்ஸி உங்களுக்கு ஒருபோதும் தேவையில்லை. **எல்லா மாதிரிகளும் `wire_api = "responses"`-ஐப் பயன்படுத்துகின்றன** — மீதியை OmniRoute கையாளுகிறது.

> **`wire_api` இயல்புநிலை மதிப்பாகும்** — இந்தப் புலத்தின் இயல்புநிலை `"responses"` என்பதால், அதை `config.toml`-இலிருந்து முழுமையாகத் தவிர்க்கலாம். உங்கள் நோக்கத்தை ஆவணப்படுத்தும்போது மட்டுமே அதை வெளிப்படையாக அமைக்கவும்.

## சூழல் சாளரம் மற்றும் சுருக்கம்

### டோக்கன் உள்ளமைவுப் புலங்கள்

| புலம்                            | விளக்கம்                                                                                                                                                                                                                                  |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | செயலில் உள்ள மாடலுக்கான மொத்த டோக்கன் வரம்பு. மாடலுக்கு அறிவிக்கப்பட்ட வரம்பாக இதை அமைக்கவும்.                                                                                                                                            |
| `model_auto_compact_token_limit` | வரலாற்றைத் தானாகச் சுருக்கத் தூண்டும் வரம்பு. **அதிகபட்சம்: `model_context_window`-இன் 90%** — 90%-க்கு மேலான மதிப்புகள் எந்த அறிவிப்புமின்றிப் புறக்கணிக்கப்படும்.                                                                       |
| `tool_output_token_limit`        | ஒவ்வொரு கருவி அழைப்பின் வெளியீட்டுக்கும் வரலாற்றில் சேமிக்கப்படும் டோக்கன்களின் உச்சவரம்பு. ஒரே பெரிய கருவிப் பதில் முழுச் சாளரத்தையும் நிரப்புவதைத் தடுக்கிறது. **இது அதிகபட்ச வெளியீடு அல்ல** — இது வரலாற்றுச் சேமிப்பு உச்சவரம்பாகும். |
| `compact_prompt`                 | சுருக்கத்தின்போது பயன்படுத்தப்படும் அமைப்பு அறிவுறுத்தலுக்கான இன்லைன் மேலெழுதுதல் (v0.138+).                                                                                                                                              |

> **`model_max_output_tokens` குறித்த குறிப்பு**: இந்தப் புலம் **Codex CLI உள்ளமைவு ஸ்கீமாவின் பகுதியாக இல்லை** (Codex Rust கோட்பேஸில் காணப்படவில்லை). இது அமைக்கப்பட்டிருந்தால் எந்த அறிவிப்புமின்றிப் புறக்கணிக்கப்படும். இதைச் சார்ந்திருக்க வேண்டாம் — வரலாற்றில் எவ்வளவு கருவி வெளியீடு சேமிக்கப்பட வேண்டும் என்பதைக் கட்டுப்படுத்த `tool_output_token_limit`-ஐப் பயன்படுத்தவும்.

## பகுத்தறிதல் முயற்சி

பதிலளிப்பதற்கு முன் மாதிரி எவ்வளவு "சிந்திக்கிறது" என்பதைக் கட்டுப்படுத்துகிறது.

| மதிப்பு  | இதற்குப் பயன்படுத்தவும்                            |
| -------- | -------------------------------------------------- |
| `none`   | பகுத்தறிதல் இல்லை — நேரடியான பதில்                 |
| `low`    | எளிய பணிகள் (பெயர் மாற்றுதல், வடிவமைத்தல்)         |
| `medium` | குறிப்பிடப்படாதபோது **சேவையக இயல்புநிலை**          |
| `high`   | இடைநிலைப் பணிகள் (மறுசீரமைப்பு, பிழைநீக்கம்)       |
| `xhigh`  | கட்டமைப்பு, ஆழமான பகுப்பாய்வு, சிக்கலான சிக்கல்கள் |

```bash
# ஒவ்வொரு இயக்கத்திற்குமான மேலெழுதுதல்
codex -c model_reasoning_effort=low "x மாறியின் பெயரை count என மாற்றவும்"
codex -c model_reasoning_effort=xhigh "auth தொகுதியை வடிவமைக்கவும்"
```

மேலும், Desktop சிந்தனை உரையை (குறியாக்கப்பட்ட தரவுத் துண்டுகளை மட்டும் அல்லாமல்) காண்பிக்கக் கூடிய வகையில் பகுத்தறிதல் **சுருக்கத்தையும்** அமைக்கவும்:

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # அல்லது ஆதரிக்கப்படும்போது ultra
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### OmniRoute சிந்தனை வரம்பு (சேவையக அமைப்பு)

OmniRoute ஹோஸ்டில், Codex முயற்சி/சுருக்கம் அப்ஸ்ட்ரீமுக்குச் சென்றடைய **Settings → AI → Thinking Budget** என்பது **`passthrough`** ஆக இருக்க வேண்டும். **`auto` பயன்முறை அனைத்து கிளையன்ட் `reasoning` / `reasoning_effort` புலங்களையும் நீக்குகிறது**, மேலும் Codex சரியாக உள்ளமைக்கப்பட்டிருந்தாலும் சிந்தனைப் பலகைகளை வெறுமையாக்கும்.

முழுமையான வழிகாட்டி: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

சுருக்கமும் prompt cache-உம் தனித்தனியானவை; அவை `passthrough`-இன் கீழும் தொடர்ந்து செயல்படும்.

## சுயவிவரங்கள் — ஒவ்வொரு மாதிரி/பணிப்பாய்விற்குமான பெயரிடப்பட்ட உள்ளமைவுகள்

## `omniroute setup-codex` மூலம் தானாகவே சுயவிவரங்களை உருவாக்குதல்

நீங்கள் ஒரு VPS-இல் OmniRoute-ஐ இயக்கினால், நேரடி மாதிரிப் பட்டியலிலிருந்து சுயவிவரக் கோப்புகளைத் தானாக உருவாக்கலாம்:

```bash
# ஒரு VPS-இலிருந்து (port 20128-இல் உள்ளக OmniRoute-ஐப் பயன்படுத்துகிறது)
omniroute setup-codex

# எந்தக் கணினியிலிருந்தும் — உங்கள் VPS-ஐக் குறிப்பிடவும்
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# கோப்புகளை எழுதாமல் முன்னோட்டமிடவும்
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# GLM மற்றும் Kimi சுயவிவரங்களை மட்டும் உருவாக்கவும்
omniroute setup-codex --only glm,kimi

# தனிப்பயன் கோப்பகத்தில் எழுதவும்
omniroute setup-codex --codex-home /path/to/.codex
```

இந்தக் கட்டளை `/v1/models`-ஐப் பெறுகிறது, அறியப்பட்ட மாதிரிகளுக்கு மேம்படுத்தப்பட்ட சுயவிவரங்களைப் பயன்படுத்துகிறது, பிற இணக்கமான உரை மாதிரிகளுக்கு பட்டியல் மெட்டாடேட்டாவைப் பயன்படுத்துகிறது, மேலும் ஒவ்வொன்றுக்கும் `~/.codex/<name>.config.toml`-ஐ எழுதுகிறது. இது idempotent — மீண்டும் இயக்குவது பாதுகாப்பானது.

வழங்குநர் மாதிரியின் வெற்றிகரமான கண்டறிதல்/இறக்குமதி நேரடிப் பட்டியலை மாற்றிய பிறகு, இதே சுயவிவரக் கோப்புகளை OmniRoute **தானாக ஒத்திசைக்கவும்** முடியும். இது **விருப்பத் தேர்வாகும் மற்றும் இயல்பாக முடக்கப்பட்டிருக்கும்**: **CLI Code dashboard**-இலிருந்து இதை மாற்றவும் ("CLI profile auto-sync" → Codex), அல்லது `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` என அமைக்கவும் (இயல்பாக இயக்கப்பட்டுள்ள `CLI_ALLOW_CONFIG_WRITES`-ஐயும் இது மதிக்கிறது). இயக்கப்பட்டிருக்கும்போது, இது தனித்தனி `~/.codex/*.config.toml` சுயவிவரக் கோப்புகளை மட்டுமே எழுதும்; செயலில் உள்ள/இயல்புநிலை `~/.codex/config.toml`, Codex-lb அமைப்புகள், அங்கீகாரம் அல்லது வழங்குநர் தேர்வு ஆகியவற்றை ஒருபோதும் மாற்றாது.

## `omniroute launch-codex` மூலம் Codex-ஐத் தொடங்குதல்


## நீண்ட நேரம் இயங்கும் பணிகள்

இரண்டு OmniRoute இயல்புநிலைகள், பல மணிநேரம் நீடிக்கும் Codex CLI அமர்வுகளை எந்த அறிகுறியும் இன்றி பாதிக்கக்கூடும். இவை இரண்டுமே Codex CLI அமைப்புகள் அல்ல — இரண்டும் OmniRoute பக்கத்திலேயே உள்ளன. கணக்குகளை நிலையாக இணைத்து, செயலற்றநிலை துண்டிப்புகளை முடக்கும் upstream proxy-களிலிருந்து உள்ளமைவை மாற்றும் பயனர்கள், பெரும்பாலும் இந்த இரு சிக்கல்களையும் எதிர்கொண்டு OmniRoute-ஆல் “நீண்ட அமர்வைத் தொடர்ந்து நடத்த முடியாது” என முடிவு செய்கிறார்கள்.

| அறிகுறி                                                                                               | சாத்தியமான காரணம்                                                                      | கட்டுப்பாடு              |
| ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------ |
| அமர்வு தொடர்ந்து கணக்குகளை மாற்றுகிறது / முறைமைகளுக்கு இடையில் prompt-cache தொடர்ச்சி இழக்கப்படுகிறது | Session affinity TTL `0` ஆக உள்ளது (முடக்கப்பட்டுள்ளது)                                | `sessionAffinityTtlMs`   |
| கிளையன்டுக்குத் தெரியும் எந்த அறிவிப்பும் இல்லாமல் reasoning நடுவில் இணைப்பு துண்டிக்கப்படுகிறது      | upstream chunk எதுவும் வராமல் 10 நிமிடங்கள் கடந்ததால் stream idle watchdog செயல்பட்டது | `STREAM_IDLE_TIMEOUT_MS` |

தொடர்புடைய விவாதங்கள்: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (நீண்ட பணிகள் துண்டிக்கப்படுதல்), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (affinity ஏன் இயல்பாக முடக்கப்பட்டுள்ளது). கண்காணிப்பு: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Session affinity — ஒரு உரையாடலை ஒரே கணக்குடன் நிலையாக இணைத்தல்

**இயல்புநிலை:** `sessionAffinityTtlMs = 0` (முடக்கப்பட்டுள்ளது).

**எங்கே அமைப்பது**

- Dashboard → **Settings → Routing** → **Session affinity** → **Affinity TTL (seconds)** (`ComboDefaultsTab`)
- அல்லது **மில்லிவிநாடிகளில்** `sessionAffinityTtlMs` உடன் அமைப்புகளை PATCH செய்யவும் (Zod வரம்பு `0`–`86_400_000`, அதாவது 24 மணிநேரம் வரை)

> #7274-இல் Codex-க்கு மட்டும் உரிய `codexSessionAffinityTtlMs` என்பதிலிருந்து பெயர் மாற்றப்பட்டது. பழைய key இன்னும் படிக்க-மட்டுமான மாற்றுப்பெயராக ஏற்கப்படுகிறது; புதிய உள்ளமைவுகள் `sessionAffinityTtlMs`-ஐப் பயன்படுத்த வேண்டும். TTL `0`-க்கு மேல் இருந்தால், affinity இப்போது Codex-க்கு மட்டுமின்றி **எந்தவொரு** provider-க்கும் பொருந்தும் — [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Session affinity என்பதைப் பார்க்கவும்.

**இது 0 ஆகவே இருந்தால் என்ன செயலிழக்கும்**

பல முறைமைகளைக் கொண்ட Codex உரையாடலின் ஒவ்வொரு முறைமையும், செயலில் உள்ள combo strategy-யால் தனித்தனியாக வழிப்படுத்தப்பட்டு, **ஒவ்வொரு முறைமையிலும் வெவ்வேறு கணக்கில்** சென்றடையக்கூடும். இது upstream session / prompt-cache தொடர்ச்சியைச் சீர்குலைக்கிறது. TTL `0`-ஐ விட அதிகமாக இருக்கும்போது மட்டுமே OmniRoute, Codex session header-களையும் (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) `prompt_cache_key` / `session_id` போன்ற body புலங்களையும் பரிசீலிக்கிறது (`src/sse/services/auth.ts`-இல் உள்ள `extractSessionAffinityKey`).

**பல மணிநேரம் நீடிக்கும் ஒரே பணிக்கான பரிந்துரை**

பணியின் எதிர்பார்க்கப்படும் மொத்த நேரத்தைவிட **அதிகமாக** TTL-ஐ அமைக்கவும் (UI அதிகபட்சம் **86400 விநாடிகள்** = 24 மணிநேரம்):

| எதிர்பார்க்கப்படும் பணி நேரம் | Affinity TTL (UI, விநாடிகள்) | `sessionAffinityTtlMs` |
| ----------------------------- | ---------------------------- | ---------------------- |
| சில மணிநேரங்கள்               | `14400` (4h)                 | `14400000`             |
| இரவு முழுவதும் / ~12h         | `43200` (12h)                | `43200000`             |
| முழு நாள்                     | `86400` (24h, அதிகபட்சம்)    | `86400000`             |

இதனை விருப்பப்படி இயக்கும் முறை திட்டமிட்டே வழங்கப்பட்டுள்ளது: affinity-ஐ முடக்குவது கணக்குகளுக்கு இடையிலான சுமைச் சமநிலைப்படுத்தலுக்கு முன்னுரிமை அளிக்கிறது; அதை இயக்குவது ஒரு நீண்ட agent அமர்வின் தொடர்ச்சிக்கு முன்னுரிமை அளிக்கிறது. இந்த வழிகாட்டி இயல்புநிலையை **மாற்றாது** — நீண்ட Codex பணிகளை இயக்கும் நிர்வாகிகள் இதைத் தாங்களே இயக்க வேண்டும்.

### 2. Stream idle timeout — அமைதியான reasoning முறைமைகளை நிறுத்த வேண்டாம்

**இயல்புநிலை:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 நிமிடங்கள்). இது அமைக்கப்படாமல் இருந்தால் `REQUEST_TIMEOUT_MS`-இலிருந்து மதிப்பைப் பெறுகிறது; பகிரப்பட்ட அடிப்படை மதிப்பும் 600000 ஆகும். [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Timeouts என்பதைப் பார்க்கவும்.

**இயல்புநிலையில் என்ன செயலிழக்கும்**

10 நிமிடங்களுக்கும் மேலாக **உண்மையான upstream chunk எதுவுமின்றி** அமைதியாக இருக்கும் Codex reasoning / tool turn, SSE idle watchdog (`open-sse/utils/stream.ts`) மூலம் கட்டாயமாக மூடப்படும். Client பெரும்பாலும் எந்த விவரமும் இல்லாத connection drop-ஐ மட்டுமே காணும் — இது “எந்த அறிவிப்பும் இல்லாமல் தானாகவே நின்றுவிட்டது” என்பதுடன் பொருந்துகிறது.

முக்கிய விவரம்: OmniRoute-இன் செயற்கையான SSE **heartbeat, idle கடிகாரத்தை reset செய்யாது**. உண்மையான upstream body chunk மட்டுமே `lastChunkTime`-ஐப் புதுப்பிக்கும். இன்னும் “சிந்தித்துக்கொண்டிருக்கும்” அமைதியான model ஒன்று, watchdog-இன் பார்வையில் செயலிழந்த upstream போலவே தெரியும்.

தொடர்புடைய Undici body செயலற்ற நிலை: `FETCH_BODY_TIMEOUT_MS` (இதுவும் அதே 10 நிமிட அடிப்படை மதிப்பையே இயல்பாகக் கொண்டுள்ளது; `0` அதை முடக்கும்). Streaming-க்கு, `FETCH_TIMEOUT_MS` என்பது connection setup / முதல் headers வரை மட்டுமே பொருந்தும் — stream செயல்படத் தொடங்கியதும், செயலற்ற இடைவெளிகள் `STREAM_IDLE_TIMEOUT_MS` மற்றும் `FETCH_BODY_TIMEOUT_MS` மூலம் நிர்வகிக்கப்படுகின்றன.

**பல மணிநேரம் நீளும் ஒற்றைப் பணிக்கான பரிந்துரை**

OmniRoute process environment-இல் (`.env` / compose / systemd):

```bash
# நீண்ட reasoning turn-களுக்கான stream idle + body inactivity காலவரம்புகளை முடக்கு
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

அல்லது நீங்கள் எதிர்பார்க்கும் மிக நீண்ட அமைதியான இடைவெளியை விட அதிகமாக அவற்றை உயர்த்தவும் (மதிப்புகள் milliseconds-இல் உள்ளன):

```bash
# எடுத்துக்காட்டு: upstream chunk-களுக்கு இடையே 2 மணிநேரம் வரை அமைதியை அனுமதி
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

இந்த env vars-ஐ மாற்றிய பிறகு OmniRoute-ஐ restart செய்யவும்.

### நடைமுறை செய்முறை — பல மணிநேர Codex பணி

1. **Account-ஐ pin செய்யவும்:** Dashboard → Settings → Routing → Session affinity → Affinity TTL = `43200` (12h) அல்லது `86400` (அதிகபட்சம் 24h).
2. OmniRoute-இன் environment-இல் **idle காலவரம்புகளை உயர்த்தவும் / முடக்கவும்**:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. வழக்கமான Codex `config.toml`-ஐ (`wire_api = "responses"`, சரியான `base_url`, `OMNIROUTE_API_KEY`) வைத்திருக்கவும் — இந்த இரண்டு நடத்தைகளுக்கும் Codex பக்கத்தில் affinity/idle கட்டுப்பாடுகள் எதுவும் இல்லை.
4. OmniRoute-ஐ restart செய்து, பின்னர் நீண்ட Codex பணியைத் தொடங்கவும்.

### இயல்புநிலை முடிவு (#7287)

| கட்டுப்பாடு              | வெளியீட்டு இயல்புநிலை | இந்த வழிகாட்டியில் மாற்ற வேண்டுமா?                                                                                            |
| ------------------------ | --------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (முடக்கப்பட்டது)  | **இல்லை** — விருப்பத் தேர்வாகவே இருக்கும் (load-balancing எதிராக continuity; Discussion #5718-ஐப் பார்க்கவும்)                |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 நிமி)    | **இல்லை** — பொதுவான traffic-க்கு 10 நிமிடங்களாகவே இருக்கும்; நீண்ட Codex பணிகளை இயக்குபவர்கள் அதை உயர்த்தவோ முடக்கவோ வேண்டும் |

இவற்றில் ஏதேனும் ஒன்றின் இயல்புநிலையை உலகளாவிய அளவில் மாற்றுவது, Codex-க்கு மட்டுமல்லாமல் ஒரு instance-இன் ஒவ்வொரு client-இன் நடத்தையையும் மாற்றும். இந்தக் கட்டுப்பாடுகளை ஆவணப்படுத்தவும்; வெளிப்படையான operator முடிவு வேறுவிதமாகக் கூறும் வரை இயல்புநிலைகளை மாற்றாமல் விடவும்.

### Idle துண்டிப்புகளைக் கண்டறிதல்

Idle watchdog செயல்படும்போது, OmniRoute பின்வரும் வடிவில் ஒரு வரியை log செய்யும்:

```text
[STREAM] Idle timeout: no data from codex for 600000ms (model: cx/gpt-5.5)
```

`Idle timeout: no data from` என்பதை (அல்லது `stream_idle_timeout` code / `StreamIdleTimeoutError` error பெயரை) grep செய்யவும். Provider segment என்பது அந்த request-க்கு OmniRoute பயன்படுத்திய மதிப்பாகும் (`codex`, மற்றொரு provider id, அல்லது தெரியாவிட்டால் `provider`) — அது எப்போதும் `codex` என்ற நேரடி string ஆக இருக்காது.

## சிக்கல் தீர்வு

**`Error: wire_api = "chat" is no longer supported`**
உங்கள் உள்ளமைவிலிருந்து `wire_api = "chat"` என்பதை அகற்றவும். `wire_api = "responses"` என அமைக்கவும் அல்லது அந்தப் புலத்தைத் தவிர்க்கவும் (v0.138 முதல் இயல்புநிலை `"responses"` ஆகும்).

**`Error: model not found`**
சரியான முன்னொட்டுடன் அந்த model OmniRoute-இல் உள்ளதா என்பதைச் சரிபார்க்கவும். `omniroute models list` கட்டளையைப் பயன்படுத்தவும் அல்லது `/dashboard/providers/<provider>`-ஐத் திறக்கவும்.

**`Authentication error`**
`OMNIROUTE_API_KEY` export செய்யப்பட்டுள்ளதா என்பதை உறுதிப்படுத்தவும்: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
முதல் கோரிக்கையை அனுப்புவதற்கு முன் env var உள்ளதா என்பதை Codex சரிபார்க்கிறது. பாதுகாக்கப்பட்ட servers-க்கு உண்மையான key-ஐ export செய்யவும்; அல்லது உங்கள் **உள்ளமை** OmniRoute instance-க்கு authentication தேவையில்லை என்றால், `OMNIROUTE_API_KEY=local` போன்ற காலியாக இல்லாத placeholder-ஐப் பயன்படுத்தவும். இதை `~/.bashrc` அல்லது `~/.zshrc`-இல் சேர்த்திருந்தால் shell-ஐ மறுதொடக்கம் செய்யவும்.

**`Connection refused`**
OmniRoute இயங்குகிறதா என்பதையும், உங்கள் network-க்கு (local, Tailscale அல்லது VPS) ஏற்றவாறு `base_url` host/port சரியாக உள்ளதா என்பதையும் சரிபார்க்கவும்.

**Context வரம்பிற்கு அருகில் session செயலிழக்கிறது**
`model_context_window` மற்றும் `model_auto_compact_token_limit` ஆகியவற்றை வெளிப்படையாக அமைக்கவும். மேலே உள்ள context window அட்டவணையைப் பார்க்கவும்.

**Compaction மிகவும் தாமதமாகத் தொடங்குகிறது**
`model_auto_compact_token_limit`-ஐ window-வின் 80–85% ஆகக் குறைக்கவும். ஒருபோதும் 90%-க்கு மேல் அமைக்க வேண்டாம்.

**Profile ஏற்றப்படவில்லை (`-p <name>` அமைதியாகப் புறக்கணிக்கப்படுகிறது)**
கோப்பு `~/.codex/<name>.config.toml`-இல் உள்ளதா என்பதை உறுதிப்படுத்தவும் (`profile-` முன்னொட்டு இருக்கக்கூடாது). `ls ~/.codex/*.config.toml` கட்டளையை இயக்கவும்.

**நீண்ட Codex task இயக்கத்தின் நடுவில் துண்டிக்கப்படுகிறது / turns-க்கு இடையில் accounts மாறுகின்றன**
[நீண்ட நேரம் இயங்கும் tasks](#long-running-tasks) என்பதைப் பார்க்கவும். session affinity-ஐச் செயல்படுத்தி (TTL task நீளத்தைவிட அதிகமாக இருக்க வேண்டும்), `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS` ஆகியவற்றின் மதிப்பை உயர்த்தவும் அல்லது அவற்றை முடக்கவும். `Idle timeout: no data from` என்பதற்காக OmniRoute logs-இல் grep செய்யவும்.
