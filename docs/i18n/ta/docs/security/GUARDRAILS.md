> **உண்மையின் ஆதாரம்:** `src/lib/guardrails/`
> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-08-29 — v3.8.51 (Video Bridge உரைமாற்றத்தின் மூலச்சான்று அழைப்பாளரால் அறிவிக்கப்படுகிறது,
> இன்னும் சேவையகத்தால் சரிபார்க்கப்படவில்லை — #11661-இன்படி தெளிவுபடுத்தப்பட்டது)

OmniRoute-க்கும் மேல்நிலை வழங்குநர்களுக்கும் இடையிலான எல்லையில் பாதுகாப்பு, கொள்கை மற்றும் உள்ளடக்க மாற்றங்களை Guardrails செயல்படுத்துகின்றன. ஒவ்வொரு guardrail-உம் கோரிக்கை payload-களை (`preCall`) மற்றும் மேல்நிலை பதில்களை (`postCall`) ஆய்வு செய்து, விருப்பமாக அவற்றை நிராகரிக்கவோ, மாற்றவோ அல்லது குறிப்புரையிடவோ முடியும்.

இந்த அமைப்பு **fail-open** முறையில் இயங்குகிறது: செயல்பாட்டின்போது ஒரு guardrail பிழையை எறிந்தால், registry அந்தப் பிழையைப் பதிவுசெய்துவிட்டு, கோரிக்கையைத் தோல்வியடையச் செய்வதற்குப் பதிலாக அடுத்த guardrail-உடன் தொடரும். தடுத்தல் என்பது எப்போதும் வெளிப்படையான முடிவு (`block: true`); அது ஒருபோதும் தற்செயலாக நிகழாது.

### விஷன் பிரிட்ஜ் (`visionBridge.ts`) — மாடாலிட்டி பிரிட்ஜ் PR-1

**விஷன் அல்லாத மாடல்களை** இலக்காகக் கொண்ட படங்களைக் கொண்ட கோரிக்கைகளை இடைமறித்து, முழு கோரிக்கையையும் விஷன்-திறன் கொண்ட மாடலுக்கு மாற்றி அனுப்பும் அல்லது அப்ஸ்ட்ரீம் அழைப்பிற்கு முன் உள்ளமைக்கக்கூடிய விஷன் மாடலால் உருவாக்கப்பட்ட உரை விளக்கங்களுடன் படப் பகுதிகளை மாற்றும். இது உரை-மட்டும் வழங்குநர்களை மல்டிமோடல் பேலோடுகளை வெளிப்படையாகக் கையாள அனுமதிக்கிறது.

ஓட்டம்:

1. இலக்கு மாடல் ஏற்கனவே விஷனை ஆதரித்தால் தவிர்க்கவும் (அது `isVisionBridgeForcedModel` கட்டாய-பிரிட்ஜ் பட்டியலில் தோன்றாவிட்டால்).
2. `extractImageParts(messages)` (`visionBridgeHelpers.ts`) வழியாக படப் பகுதிகளைப் பிரித்தெடுக்கவும், இது `open-sse/utils/mediaParts.ts` இல் உள்ள **ஒருங்கிணைந்த மீடியா டிடெக்டரை** `detectMediaParts()` க்கு வழங்குகிறது — காம்போ இணக்கத்தன்மை வடிகட்டியுடன் பகிரப்பட்ட உண்மைகளின் ஒரே ஆதாரம். பிரித்தெடுத்தல் என்பது `replaceImageParts` மீண்டும் இணைக்கக்கூடிய வடிவங்களின் மேல்-நிலை பகுதிகளுக்கு அனுமதிக்கப்படுகிறது (extract↔replace ஒப்பந்தம்): OpenAI `image_url`, Anthropic base64 `source.type:"base64"`, Anthropic URL `source.type:"url"`, மற்றும் Responses API `input_image`. உள்ளமைக்கப்பட்ட ஹிட்ஸ் மற்றும் இண்டிகேட்டர்-மட்டும் வடிவங்கள் காம்போ-வடிகட்டி பொருள் மற்றும் ஒருபோதும் பிரித்தெடுக்கப்படாது. எதுவும் காணப்படவில்லை என்றால் தவிர்க்கவும்.
3. `resolveVisionBridgeRuntimeSettings()` (`src/shared/constants/modalityBridgeDefaults.ts`) வழியாக ரன்டைம் உள்ளமைவை தீர்க்கவும்: புதிய `modalityBridge*` அமைப்புகள் விசைகள் வெற்றி பெறும்; மரபு `visionBridge*` விசைகள் **ஒரு-சுழற்சி பின்னடைவாக** (ரோல்பேக் சாளரம்) இருக்கும். பிரிட்ஜ் முடக்கப்பட்டிருக்கும் போது எந்த மீடியா பயணத்திற்கும் முன் தவிர்க்கவும்.
4. பயன்முறை தேர்வாளர் (`modalityBridgeVisionMode`, கீழே உள்ள அட்டவணையைப் பார்க்கவும்) மறுவழிப்படுத்துவதா அல்லது விவரிப்பதா என்பதை தீர்மானிக்கிறது. மறுவழிப்படுத்துதல் `modifiedPayload` ஐ `model` மட்டும் மாற்றப்பட்டு, பிளஸ் மெட்டா `{ rerouted, fromModel, toModel, imagesKept }` உடன் வழங்குகிறது.
5. விவரிக்கும் பாதை: `maxImages` இல் படங்களை வரம்பிடவும், பணி-அறிவார்ந்த ப்ராம்ப்டை உருவாக்கவும், விவரிக்கும் தற்காலிக சேமிப்பகத்தைப் பார்க்கவும், விஷன் மாடலை **இணைந்து** அழைக்கவும் (`Promise.allSettled`), மற்றும் `[Image N]: <description>` உரைப் பகுதிகளை அவற்றின் இடத்தில் செருகவும். தோல்வியுற்ற விளக்கம் `null` ஐ வழங்குகிறது மற்றும் அசல் படப் பகுதி **பாதுகாக்கப்படுகிறது** (#4012) — காம்போ விவரிக்கும் பாதையில் ஒவ்வொரு விளக்கமும் தோல்வியுற்றால் தவிர, உறுதிப்படுத்தப்பட்ட விஷன் அல்லாத அப்ஸ்ட்ரீம் அதற்கு பதிலாக `(unavailable — no vision-capable provider connected)` ஸ்டப் ஐப் பெறுகிறது (#8430).
6. `modifiedPayload` + மெட்டா (`imagesProcessed`, `descriptions`, `processingTimeMs`, `visionModel`) ஐ வழங்கவும்.

#### பயன்முறை தேர்வாளர் (`modalityBridgeVisionMode`)

| பயன்முறை   | இயல்புநிலை | நடத்தை                                                                                                                                                                                                                                                                                                                        |
| ---------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `auto`     | ✔          | மரபுவழி ஹியூரிஸ்டிக், தொடப்படாதது (#6640/#7204): காம்போ அல்லாத/`auto/` மாடல்கள் சிறந்த விஷன் மாடலுக்கு மறுவழிப்படுத்துகின்றன, அசல் மாடலில் ஏற்கனவே பயன்படுத்தக்கூடிய நற்சான்றுகள் இல்லாவிட்டால் (பின்னர் விவரிக்கவும்); காம்போ இலக்குகள் எப்போதும் விவரிக்கின்றன.                                                             |
| `describe` |            | எப்போதும் விவரிக்கவும் — மறுவழிப்படுத்துதல் தொகுதி முற்றிலும் தவிர்க்கப்படுகிறது; பயனரின் தேர்ந்தெடுக்கப்பட்ட மாடல் எப்போதும் பதிலளிக்கும்.                                                                                                                                                                                   |
| `reroute`  |            | கட்டாய மறுவழிப்படுத்துதல்: நற்சான்றளிக்கப்பட்ட-மாடல் பாதுகாப்பாளர் புறக்கணிக்கப்படுகிறார். மறுவழிப்படுத்துதல்-**இலக்கு** நற்சான்று பாதுகாப்பாளர் இன்னும் பொருந்தும் — பயன்படுத்தக்கூடிய விஷன் இலக்கு இல்லாதபோது, கோரிக்கை விவரிப்பிற்கு செல்கிறது, இதனால் மூலப் படங்கள் ஒரு உரை-மட்டும் பின்தளத்தை ஒருபோதும் அடையாது (#8430). |

கட்டாயப்படுத்தப்பட்ட பயன்முறைகள் தானியங்கி ஹியூரிஸ்டிக் இயங்குவதற்கு **முன்** ஷார்ட்-சர்க்யூட் செய்கின்றன; `auto` நடத்தை PR-1 க்கு முந்தைய கார்ட்ரெயிலுக்கு பைட்டு-ஒத்ததாகும்.

#### பணி-அறிவார்ந்த விவரிக்கும் ப்ராம்ப்ட் (`modalityBridgeVisionTaskAware`)

இயல்புநிலை **true**. `composeVisionPrompt()` (`visionBridgeHelpers.ts`) **கடைசி பயனர் செய்தியின்** உரையை (500 எழுத்துக்களுக்கு சுருக்கப்பட்டது) அடிப்படை விவரிக்கும் ப்ராம்ப்டுடன் சேர்க்கிறது, விளக்கத்தை பயனர் உண்மையில் கேட்டதை நோக்கி செலுத்துகிறது (codex-vision-proxy பேட்டர்ன்) மற்றும் விஷன் மாடலை தெரியும் உரையை படியெடுக்க கேட்கிறது. கொடி முடக்கப்பட்டிருந்தால் — அல்லது பயனர் உரை இல்லை என்றால் — அடிப்படை ப்ராம்ப்ட் மாற்றப்படாமல் பயன்படுத்தப்படுகிறது.

சுய-சுழற்சியின் சொந்த OpenAI-இணக்கமான கோரிக்கை (`callVisionModelSingle()`
`visionBridgeHelpers.ts` இல்) எப்போதும் `image_url.detail: "high"` ஐக் கோருகிறது —
நிபந்தனையின்றி, ஒவ்வொரு அழைப்பாளர்/வழங்குநருக்கும், எந்த கிளையன்ட் சிக்னலிலும் கட்டுப்படுத்தப்படவில்லை.
குறைந்த-விரிவான மாதிரி, இந்த ப்ராம்ட் கேட்கும் உரை-படியெடுத்தல் பணிக்கு OCR துல்லியத்தை குறைக்கிறது,
எனவே விளக்க அழைப்பு எப்போதும் உயர் விவரங்களைக் கேட்கிறது, அசல் உள்வரும் கோரிக்கை எந்த விவர அளவைப் பயன்படுத்தினாலும்.
இது உள் விளக்க கோரிக்கை உடலை மட்டுமே பாதிக்கிறது;
முதன்மை கோரிக்கையில் அழைப்பாளரின் சொந்த `image_url.detail` ஐ OmniRoute எவ்வாறு அனுப்புகிறது என்பதை இது மாற்றாது —
அந்த இயல்புநிலை தனித்தனியாகவும், கண்டறியப்பட்ட OpenCode கிளையண்டுகளுக்கு மட்டுமே,
`defaultImageDetail()` (`open-sse/handlers/chatCore/upstreamBody.ts`) இல் பயன்படுத்தப்படுகிறது.
விளக்க சுய-சுழற்சியின் Anthropic வயர்-ஃபார்மட் கிளையில் `detail` புலம் இல்லை மற்றும் எந்த இயல்புநிலைகளாலும் பாதிக்கப்படாது.

#### வெளியீட்டு வரம்பை விவரிக்கவும் (`modalityBridgeVisionMaxChars`)

| Key                            | Default | Range            |
| ------------------------------ | ------- | ---------------- |
| `modalityBridgeVisionMaxChars` | `0`     | `0` or 100–50000 |

`0` (இயல்புநிலை) என்பது **வரம்பு இல்லை** என்பதைக் குறிக்கிறது — `callVisionModel()` ஆல் திரும்பப் பெறப்பட்ட விளக்கம் மாற்றப்படாமல் அனுப்பப்படுகிறது,
தற்போதுள்ள நடத்தையைப் பாதுகாக்கிறது. 100–50000 வரம்பில் உள்ள எந்த மதிப்பும் விளக்கத்தை `…` பின்னொட்டுடன் துண்டிக்கிறது,
அது `[Image N]: <description>` ஆக மீண்டும் இணைக்கப்படுவதற்கு முன்பு
(`VisionBridgeGuardrail.preCall()` `src/lib/guardrails/visionBridge.ts` இல்).
கீழ்நிலை மாதிரிக்கு முழு படியெடுத்தல் தேவைப்படும் விவரம்-அதிக OCR பணிகளுக்கு இதை அதிகரிக்கவும்;
அரட்டை அடிக்கும் பார்வை மாதிரிகளில் டோக்கன் பயன்பாட்டைக் கட்டுப்படுத்த இதை குறைக்கவும்.
டாஷ்போர்டு புலம் விஷன் தாவலின் மேம்பட்ட பேனலில் உள்ளது
(`modality-bridge-max-chars` `ModalityBridgeVisionTab.tsx` இல்) மற்றும் 1 மற்றும் 99 க்கு இடையில் உள்ள எந்த மதிப்பையும் 100 தளத்திற்கு மேல் கட்டுப்படுத்துகிறது,
அதே நேரத்தில் ஒரு வெளிப்படையான `0` ஐ தொடாமல் விட்டுவிடுகிறது — `0` என்பது அதன் சொந்த உரிமையில் ஒரு செல்லுபடியாகும் Zod மதிப்பு
(`z.union([z.literal(0), z.number().int().min(100).max(50000)])`), வெறுமனே "அமைக்கப்படாத" இயல்புநிலை அல்ல.

#### கேச் விவரிக்கவும் (`modalityBridge/bridgeCache.ts`)

விளக்க வெளியீடுகளுக்கான நினைவகத்தில் உள்ள LRU + TTL கேச், செயல்முறை முழுவதும் பகிரப்பட்டது.
Key = `sha256(imageRef + composedPrompt + configuredBridgeModel)` நீள-முன்னொட்டு கட்டமைப்பைக் கொண்டது (புல-எல்லை மோதல்கள் இல்லை).
மாதிரி கூறு என்பது **கட்டமைக்கப்பட்ட** பிரிட்ஜ் மாதிரி, உண்மையில் பதிலளித்த மாதிரி அல்ல —
`callVisionModel` உள்நாட்டில் பின்வாங்கலாம், மேலும் ஒவ்வொரு முயற்சிக்கும் முக்கியத்துவம் அளிப்பது கேச் ஐ துண்டாக்கும்.
தோல்வியுற்ற விளக்கங்கள் ஒருபோதும் கேச் செய்யப்படுவதில்லை. அமைப்புகள்:

| Key                             | Default | Range   |
| ------------------------------- | ------- | ------- |
| `modalityBridgeCacheEnabled`    | `true`  | —       |
| `modalityBridgeCacheTtlMinutes` | `60`    | 1–1440  |
| `modalityBridgeCacheMaxEntries` | `200`   | 10–5000 |

#### தொலைநிலை பட இயல்பாக்கம் (சுய-சுழற்சி விவரி/base64 பெறுதல்)

பிரிட்ஜ் ஒரு **தொலைநிலை** படத்தை தானே பெறும்போது — Anthropic விவரி சுய-அழைப்பு மற்றும் claude-wire-format base64 மாற்றம்
(`ensureBase64ImagesForClaudeWire`), இரண்டும் `visionBridgeHelpers.ts` இல் உள்ள `fetchRemoteImageAsDataUri()` வழியாக —
இதன் விளைவாக வரும் தரவு URI `normalizeDataUri()`
(`open-sse/utils/imageNormalize.ts`) வழியாக அனுப்பப்பட்டு, பின்னர் பார்வை-மாதிரி கோரிக்கையில் உட்பொதிக்கப்படுகிறது.
அதிகப்படியான படங்கள் **2048px நீளமான விளிம்பிற்கு** குறைக்கப்படுகின்றன (OpenAI/Anthropic ஏற்கனவே சர்வர் பக்கத்தில் பயன்படுத்தும் மறுஅளவீட்டு வரம்புடன் பொருந்துகிறது),
இது பார்வை மாதிரி பார்ப்பதை மாற்றாமல் பதிவேற்ற பைட்டுகள்/தாமதத்தை குறைக்கிறது.
மறுஅளவீடு `sharp` ஐப் பயன்படுத்துகிறது, இது டைனமிக் இறக்குமதி வழியாக ஏற்றப்படுகிறது:
அதன் சொந்த பைனரி ஏற்றப்படத் தவறினால், `normalizeDataUri()` **ஒருபோதும் பிழையை ஏற்படுத்தாது** —
அது அசல் பைட்டுகளின் பாஸ்-த்ரூக்கு பின்வாங்குகிறது, எனவே விவரி/base64-மாற்ற பாதை எப்போதும் தொடர்ந்து செயல்படும்.
படம் அல்லாத பைட்டுகள் (டீகோட் செய்யக்கூடிய படத்தை வழங்காத ஒரு பெறுதல்) தொடப்படாமல் அனுப்பப்படுகின்றன.
இந்த இயல்பாக்கம் பிரிட்ஜ் அதன் சொந்த சுய-அழைப்பிற்காக பெறும் படங்களுக்கு மட்டுமே வரையறுக்கப்பட்டுள்ளது —
இது அழைப்பாளரின் மூல பாஸ்-த்ரூ பேலோடில் ஒருபோதும் பயன்படுத்தப்படுவதில்லை,
தேர்வு-மட்டும் மாற்றக் கொள்கைக்கு இணங்க (கடின விதி #20).

#### அமைப்புகள் ஸ்கீமா + இடம்பெயர்வு

புதிய `modalityBridge*` விசைகள் `updateSettingsSchema` இல் Zod-சரிபார்க்கப்படுகின்றன
(`src/shared/validation/settingsSchemas.ts`): `modalityBridgeVisionEnabled`,
`modalityBridgeVisionMode`, `modalityBridgeVisionModel`,
`modalityBridgeVisionTaskAware`, `modalityBridgeVisionPrompt`,
`modalityBridgeVisionTimeout`, `modalityBridgeVisionMaxImages`,
`modalityBridgeVisionMaxChars`, `modalityBridgeCache*` மூவர், மற்றும் ஆடியோ பிரிட்ஜ் பயன்படுத்தும் `modalityBridgeAudio*` குழு.
இடம்பெயர்வு `141_modality_bridge_settings.sql` ஏற்கனவே உள்ள மரபு `visionBridge*` மதிப்புகளை பொருந்தும் புதிய விசைகளுக்கு நகலெடுக்கிறது
(இடம்போடென்ட், ஒருபோதும் ஆபரேட்டர்-அமைத்த `modalityBridge*` மதிப்பை மேலெழுதாது);
மரபு விசைகள் ஒரு வெளியீட்டு சுழற்சிக்கு வாசிப்பு பின்வாங்கலாக ஏற்றுக்கொள்ளப்படுகின்றன.

#### வெளிப்படைத்தன்மை தலைப்பு + புள்ளிவிவரங்கள்

விளக்க-மாற்றப்பட்ட பதில்கள் `x-omniroute-modality-bridge: image->text;model=<visionModel>;parts=<n>` ஐக் கொண்டுள்ளன
(`modalityBridge/bridgeStats.ts` இல் `buildModalityBridgeHeader()` ஆல் உருவாக்கப்பட்டது,
`src/sse/handlers/chatHelpers.ts` இல் `withModalityBridgeHeader()` ஆல் முத்திரையிடப்பட்டது).
மறுவழிக்கப்பட்ட கோரிக்கைகளுக்கு **தலைப்பு இல்லை** — பேலோட் தொடப்படாமல் இருந்தது மற்றும் மாதிரி மாற்றம் ஏற்கனவே பதிலின் உடலின் `model` புலத்தில் தெரியும்.

`GET /api/modality-bridge/stats` (மேலாண்மை அங்கீகாரம், `GET /api/settings` போன்ற அதே அடுக்கு)
நினைவகத்தில் உள்ள ஒவ்வொரு முறைமைக்கும் உள்ள கவுண்டர்களைத் திரும்பப் பெறுகிறது
`{ attempts, successes, bridged, cacheHits, failures, totalLatencyMs,
latencySamples, averageLatencyMs, lastUsedAt }` `vision`, `audio`, மற்றும் `video` க்காக.
`averageLatencyMs` அதன் வகுப்பியாக `latencySamples` ஐப் பயன்படுத்துகிறது, அனைத்து முயற்சிகளையும் அல்ல;
நேரமில்லாத ஒரு செயல்பாடு பூஜ்ஜிய-மில்லிசெகண்ட் மாதிரியை உருவாக்காது.
`bridged` வெற்றிகரமான மாற்றங்களுக்கான பின்னோக்கி-இணக்கமான மாற்றுப்பெயராக உள்ளது;
தோல்வியுற்ற முயற்சிகள் அதை அதிகரிக்காது.
கவுண்டர்கள் செயல்முறை மறுதொடக்கம் செய்யப்பட்டால் வடிவமைப்பால் மீட்டமைக்கப்படும்
(டெலிமெட்ரி, கணக்கியல் அல்ல).

#### டாஷ்போர்டு கட்டமைப்பு

பிரத்யேக டாஷ்போர்டு பக்கம்
`/dashboard/settings/modality-bridge`. அதன் URL-முகவரியிடக்கூடிய `Vision`, `Audio`,
மற்றும் `Video` தாவல்கள் `tab` மதிப்பை மாற்றும்போது வினவல் அளவுருக்களைப் பாதுகாக்கின்றன.
Vision தாவல் செயல்படுத்துதல், முறை, மாதிரித் தேர்வு (தானியங்கி இயல்புநிலை உட்பட),
பணி-அறிவார்ந்த தூண்டுதல், மேம்பட்ட காலக்கெடு/படம்/விளக்க-நீளம்/தற்காலிக சேமிப்பு
வரம்புகள், இயக்கநேர
கவுண்டர்கள் மற்றும் பாதுகாக்கப்பட்ட மாதிரி கோரிக்கையை வெளிப்படுத்துகிறது. Audio தாவலும் நேரலையில் உள்ளது: இது
செயல்படுத்துதல், ஆட்டோவுடன் கூடிய STT-மட்டும் மாதிரித் தேர்வு, காலக்கெடு/அதிகபட்ச-கிளிப் வரம்புகள், ஆடியோ
கவுண்டர்கள் மற்றும் `input_audio` மாதிரி சோதனையை வெளிப்படுத்துகிறது. Video தாவல் செயல்படுகிறது: இது
FFmpeg/ffprobe இயக்கநேர நிலையைப் புகாரளிக்கிறது — நான்கு வெளிப்படையான UI நிலைகளில் ஒன்று (`unknown`
ஆய்வு நடந்து கொண்டிருக்கும்போது அல்லது முடிக்க முடியாமல் போனால், `restricted` ஒரு லூப்-பேக் அல்லாத
டாஷ்போர்டு ஹோஸ்டில் ஆய்வு கிளையன்ட் பக்கத்தில் தவிர்க்கப்பட்டால், `unavailable` ஆய்வு செய்யப்பட்டு
காணாமல் போனது உறுதிசெய்யப்பட்டால், அல்லது `available` FFmpeg/ffprobe பதிப்புகளுடன்) —
செயல்படுத்து/மாதிரி/பிரேம்/வீடியோ/காலக்கெடு வரம்புகளை நிலைநிறுத்துகிறது, மாதிரித் தேர்வை பார்வை-திறன் கொண்ட
மாதிரிகளுக்கு வடிகட்டுகிறது, மற்றும் வீடியோ கவுண்டர்களை வெளிப்படுத்துகிறது.

AI அமைப்புகளின் கீழ் உள்ள முன்னாள் Vision Bridge அட்டை புதிய பக்கத்திற்கான இணக்கத்தன்மை இணைப்பு;
இது இனி படிவத்தின் இரண்டாவது நகலை வைத்திருக்காது. Media Providers ஆனது
Image-to-Text மற்றும் Speech-to-Text பணிப்பாய்வுகளை தொடர்புடைய Modality
Bridge தாவல்களுடன் இணைக்கிறது, தற்போதுள்ள Speech-to-Text பிளேகிரவுண்டை அகற்றாமல்.

**சுய-சுற்று அனுமதி புறக்கணிப்பு:** OmniRoute இன் சொந்த `/v1` சுய-சுற்று (தரமற்ற வழங்குநர் மாதிரி) வழியாக
விளக்க அழைப்பு செல்லும் போது, துணை-கோரிக்கை
`x-omniroute-admission-bypass: internal` ஐ அனுப்புகிறது மற்றும் தீர்க்கப்பட்ட
சுய-சுற்று நற்சான்றிதழுடன் அங்கீகரிக்கப்படுகிறது — உள்ளூர் பயன்முறையில் உள்ளூர் `sk_omniroute` சென்டினல்,
அல்லது ஆபரேட்டர்-கட்டமைக்கப்பட்ட `OMNIROUTE_API_KEY` / `ROUTER_API_KEY` env key (#1350)
ஆகவே `REQUIRE_API_KEY=true` வரிசைப்படுத்தல்கள் விளக்க அழைப்பை இன்னும் இயக்க முடியும்.
இந்த புறக்கணிப்பு அந்த சரியான நற்சான்றிதழ்களுக்கு மட்டுமே மதிக்கப்படுகிறது, எனவே வெளிப்புற கிளையன்ட்கள்
அனுமதியைத் தவிர்க்க தலைப்பைப் பயன்படுத்த முடியாது.

பழைய இயல்புநிலைகள் `src/shared/constants/visionBridgeDefaults.ts` இல் உள்ளன;
புதிய முறை/பணி-அறிவார்ந்த/தற்காலிக சேமிப்பு இயல்புநிலைகள் மற்றும் அமைப்புகள் தீர்வு
`src/shared/constants/modalityBridgeDefaults.ts` இல் உள்ளன. கார்ட்ரெயில் ஒரு
`deps` கன்ஸ்ட்ரக்டர் விருப்பத்தை வெளிப்படுத்துகிறது, இதனால் சோதனைகள் போலி `getSettings` மற்றும்
`callVisionModel` செயலாக்கங்களை செலுத்த முடியும்.

### ஆடியோ பிரிட்ஜ் (`audioBridge.ts`) — Modality Bridge PR-3

ஆடியோ உள்ளீட்டை ஏற்காத இலக்கை அடைவதற்கு முன் ஆடியோ-தாங்கும் அரட்டை கோரிக்கைகளை இடைமறிக்கிறது.
இது அரட்டை கோரிக்கையை ஒருபோதும் மறுவழியில் அனுப்பாது: ஆடியோ பகுதிகள் தற்போதுள்ள OpenAI-இணக்கமான
மல்டிபார்ட் எண்ட்பாயிண்ட் வழியாக படியெடுக்கப்படுகின்றன, மேலும் தேர்ந்தெடுக்கப்பட்ட அரட்டை மாதிரி உரை
படியெடுத்தல்களுடன் தொடர்கிறது.

ஓட்டம்:

1. `getResolvedModelCapabilities()` வழியாக `supportsAudio` ஐத் தீர்க்கவும். வெளிப்படையான
   வழங்குநர்-பதிவு மெட்டாடேட்டா வெற்றிபெறுகிறது, பின்னர் நிலையான மாதிரி மெட்டாடேட்டா, பின்னர் ஒத்திசைக்கப்பட்ட
   `modalities_input`. `audio` இல்லாத அறிவிக்கப்பட்ட உள்ளீட்டுப் பட்டியல் `false`;
   திறன் ஆதாரம் எதுவும் `null` ஆக உள்ளது. `false` மற்றும் `null` இரண்டும்
   பழமைவாத பாலத்தை செயல்படுத்துகின்றன, அதே நேரத்தில் `true` அதைத் தவிர்க்கிறது.
2. `modalityBridgeAudio*` அமைப்புகளைத் தீர்க்கவும் மற்றும் பகிரப்பட்ட `detectMediaParts()`
   டிடெக்டர் வழியாக ஒவ்வொரு செய்தியிலிருந்தும் பிளையக்கூடிய மேல்-நிலை ஆடியோ பகுதிகளைப் பிரித்தெடுக்கவும்.
   ஆதரிக்கப்படும் வயர் வடிவங்கள் OpenAI `input_audio`, `audio_url`, மற்றும்
   `source.media_type: "audio/*"`. உட்பொதிக்கப்பட்ட ஆடியோ ரூட்டிங்கிற்காக கண்டறியப்படுகிறது, ஆனால்
   பிளவு பாதையால் அகற்றப்படவில்லை. `modalityBridgeAudioMaxClips` ஆல் வேலை கட்டுப்படுத்தப்படுகிறது;
   பிந்தைய பகுதிகள் தொடப்படாமல் இருக்கும்.
3. கட்டமைக்கப்பட்ட `provider/model` ஐ மதிக்கவும், அல்லது `selectAudioBridgeModel()` ஐ
   `AUDIO_TRANSCRIPTION_PROVIDERS` ஐ நிலையான பட்டியல் வரிசையில் நடக்க அனுமதிக்கவும் மற்றும்
   பயன்படுத்தக்கூடிய செயலில் உள்ள வழங்குநர் நற்சான்றிதழுடன் முதல் மாதிரியைத் தேர்ந்தெடுக்கவும்.
4. `callAudioTranscription()` base64/data-URI ஆடியோவை ஒரு மல்டிபார்ட் `file` ஆக மாற்றுகிறது,
   அல்லது DNS பின்னிங் மற்றும் 25 MB வரம்புடன் பொது-மட்டும் வெளிச்செல்லும் காவலர் வழியாக தொலைநிலை
   `audio_url` ஐப் பதிவிறக்குகிறது. பின்னர் அது கோப்பு மற்றும் தேர்ந்தெடுக்கப்பட்ட மாதிரியை உள்ளூர்
   `/v1/audio/transcriptions` சுய-சுற்றுக்கு POST செய்கிறது, `resolveSelfLoopBearer()` உடன்
   அங்கீகரிக்கப்படுகிறது. தற்போதுள்ள டிரான்ஸ்கிரிப்ஷன் பாதை சாதாரண நற்சான்றிதழ் தேடல்,
   கூல்தவுன்/ரேட்-லிமிட் கையாளுதல் மற்றும் வழங்குநர் அனுப்பலைச் செய்கிறது.
5. வெற்றிகரமான அழைப்புகள் அவற்றின் பகுதிகளை `[Audio N]: <transcript>` உடன் மாற்றுகின்றன. அழைப்புகள்
   `Promise.allSettled` உடன் இயங்குகின்றன: ஒரு தனிப்பட்ட தோல்வி அந்த அசல்
   ஆடியோ பகுதியை பாதுகாக்கிறது (#4012 ஒப்பந்தம்). ஒவ்வொரு அழைப்பும் தோல்வியுற்றால் மற்றும் இலக்கு
   `supportsAudio === false` என்று நிரூபிக்கப்பட்டால், பகுதிகள்
   `[Audio N]: (கிடைக்கவில்லை — STT வழங்குநர் இணைக்கப்படவில்லை)` ஆக மாறும் (#8430 ஒப்பந்தம்).
   அறியப்படாத இலக்கிற்கு (`null`), அனைத்து-தோல்வி முடிவு தொடப்படாமல் இருக்கும்.
   பயன்படுத்தக்கூடிய STT நற்சான்றிதழ் இல்லாத நிரூபிக்கப்பட்ட உரை-மட்டும் இலக்கு அதே வெளிப்படையான
   ஸ்டப்பை நெட்வொர்க் அழைப்பை வெளியிடாமல் பெறுகிறது.

வெற்றிகரமான படியெடுத்தல்கள் செயல்முறை-அகல Modality Bridge LRU/TTL தற்காலிக சேமிப்பைப் பயன்படுத்துகின்றன.
முக்கியமானது ஆடியோ குறிப்பு, நிலையான `audio-transcription` செயல்பாட்டு லேபிள் மற்றும்
தேர்ந்தெடுக்கப்பட்ட STT மாதிரியை ஒருங்கிணைக்கிறது; தோல்விகள் ஒருபோதும் தற்காலிக சேமிப்பில் வைக்கப்படுவதில்லை.
ஆடியோ முயற்சிகள் பகிரப்பட்ட `bridged`, `cacheHits`, `failures`, மற்றும் `lastUsedAt`
கவுண்டர்களைப் புதுப்பிக்கின்றன. மாற்றப்பட்ட பதில்கள்
`x-omniroute-modality-bridge: audio->text;model=<sttModel>;parts=<n>` ஐக் கொண்டுள்ளன;
தொடப்படாத கோரிக்கைகள் ஆடியோ பிரிட்ஜ் பிரிவைப் பெறுவதில்லை.

இயக்கநேர அமைப்புகள் DB-ஆதரவு மற்றும் Zod-சரிபார்க்கப்பட்டவை:

| Key                           | Default | Range              |
| ----------------------------- | ------- | ------------------ |
| `modalityBridgeAudioEnabled`  | `true`  | —                  |
| `modalityBridgeAudioModel`    | `""`    | Auto அல்லது STT ID |
| `modalityBridgeAudioTimeout`  | `60000` | 1000–300000        |
| `modalityBridgeAudioMaxClips` | `3`     | 1–10               |

பகிரப்பட்ட தற்காலிக சேமிப்பு `modalityBridgeCacheEnabled`,
`modalityBridgeCacheTtlMinutes`, மற்றும் `modalityBridgeCacheMaxEntries` ஆல் கட்டுப்படுத்தப்படுகிறது.

### வீடியோ பிரிட்ஜ் (`videoBridge.ts`, `videoBridgePipeline.ts`)

அறியப்பட்ட நேட்டிவ் வீடியோ ஆதரவு இல்லாத இலக்கு அழைக்கப்படுவதற்கு முன், Chat Completions `messages` மற்றும் Responses API `input` இல் உள்ள உயர்மட்ட வீடியோ பகுதிகளை இடைமறிக்கிறது.
ஆதரிக்கப்படும் வடிவங்கள் `input_video`, `video_url`, `video_source`, HTTPS URLகள் மற்றும் `data:video/*;base64,...` தரவு URIகள். உரையில் உள்ள சாதாரண கோப்புப் பெயர்கள் வீடியோவாகக் கருதப்படுவதில்லை.

`VideoBridgeGuardrail.preCall` (`videoBridge.ts`) கோரிக்கை பயணம், திறன்/கொள்கை சரிபார்ப்பு, ஒரு-கோரிக்கை ஒருங்கிணைப்பு மற்றும் பதில் பேலோட் ஆகியவற்றைச் சொந்தமாக்குகிறது.
ஒரு-வீடியோ வேலை - கையகப்படுத்துதல், முழு-முடிவு கேச், ஒரு பிரேம் வரிசையை விவரித்தல் (இது அழைப்பாளர் அறிவித்த ஆடியோ டிரான்ஸ்கிரிப்டை இணைக்கிறது), மற்றும் ஒரு-முயற்சி அளவீடுகள்/ரத்து/சுத்தப்படுத்துதல் - `preCall` இன் லூப்பிற்குள் ஒரு வீடியோ பகுதிக்கு ஒருமுறை அழைக்கப்படும் `videoBridgePipeline.ts` இல் உள்ள `processVideoPart` க்குப் பின்னால் மறைக்கப்பட்டுள்ளது.
அந்த தொகுதி வெளிப்படையான போர்ட் எல்லைகளையும் வரையறுக்கிறது `VideoMediaBrokerPort` (பைட்டுகளைப் பெறுதல் மற்றும் மாதிரி பிரேம்களைப் பிரித்தெடுத்தல்), `VideoAudioTranscriptionPort` (அழைப்பாளர் அறிவித்த ஆடியோ டிரான்ஸ்கிரிப்டை மாதிரி தலைப்புகளுடன் இணைத்தல்), மற்றும் `VideoDrilldownPort` (பிரேம் டிரில்-டவுன் நிலைத்தன்மை எல்லை; இன்னும் `processVideoPart` உடன் இணைக்கப்படவில்லை - இன்று `/api/modality-bridge/video/drilldown` பாதை மட்டுமே டிரில்-டவுன் உள்ளீடுகளை எழுதுகிறது).

பொது `/v1` கோரிக்கை பாதை ஒருபோதும் துணை செயல்முறையை இறக்குமதி செய்யவோ அல்லது அழைக்கவோ இல்லை. தொலைதூர வீடியோக்கள் 50 MiB வரம்பிற்குள் பதிவிறக்கப்படுகின்றன; இன்லைன் base64 வீடியோக்கள் ஒரு பழமைவாத 36 MiB டிகோட் செய்யப்பட்ட ஒரு-வீடியோ வரம்பைக் கொண்டுள்ளன, இதனால் மாதிரி/செய்திகள்/பிரேமிங் உறை 50 MiB இன் பொது JSON கோரிக்கை அனுமதி வரம்பிற்குள் இருக்க முடியும். ஒதுக்கீட்டிற்கு முன் இன்லைன் நீளம் மற்றும் டிகோட் செய்யப்பட்ட அளவு மதிப்பீடுகள் சரிபார்க்கப்படுகின்றன. DNS பின்னிங்குடன் இருக்கும் பொது-மட்டும் வெளிச்செல்லும் காவலரைப் பயன்படுத்தி, ஆரம்ப தொலைநிலை URL மற்றும் ஒவ்வொரு வழிமாற்றிலும் HTTPS தேவைப்படுகிறது. பைட்டுகள் பின்னர் துல்லியமான உள் `POST /api/modality-bridge/video/extract` தரகர் எல்லையை கடக்கின்றன. அந்த பாதை `LOCAL_ONLY` மற்றும் `SPAWN_CAPABLE` இரண்டும் ஆகும், ஒரு செயல்முறைக்கு அங்கீகரிக்கப்பட்ட, நம்பகமான-லூப்பேக் கோரிக்கையை மட்டுமே ஏற்றுக்கொள்கிறது, மேலும் ஒரு URL, கோப்பு முறைமை பாதை, இயங்கக்கூடிய அல்லது வாதப் பட்டியலை ஒருபோதும் ஏற்றுக்கொள்வதில்லை. API உடல்-அளவு பைப்லைன் மற்றும் ஹேண்ட்லரின் அதிகரிக்கும் உடல் ரீடர் சுயாதீனமாக 50 MiB தரகர் உள்ளீட்டு வரம்பை செயல்படுத்துகின்றன. அதன் வரம்புக்குட்பட்ட வரிசை ஒரு நேரத்தில் ஒரு பிரித்தெடுப்பை இயக்குகிறது, நான்கு நிலுவையிலுள்ள வேலைகளை அனுமதிக்கிறது, மேலும் நிலுவையிலுள்ள உள்ளீட்டை 100 MiB ஆக வரம்புக்குட்படுத்துகிறது.

தரகருக்குள், `ffprobe` ஒரு தனிப்பட்ட உள்ளூர் கோப்பைப் படிக்கிறது; நிலையான வடிவ அனுமதிப்பட்டியல் பிளேலிஸ்ட் மற்றும் மேனிஃபெஸ்ட் வடிவங்களை விலக்குகிறது. அனுமதிக்கப்பட்ட MOV-குடும்ப கொள்கலன்களுக்கு, வெளிப்புற MOV தரவு குறிப்புகள் இயல்பாக முடக்கப்பட்டிருக்கும், மேலும் நிலையான கட்டளை அவற்றை தேர்வு செய்யாது. `ffprobe` மற்றும் `ffmpeg` இரண்டும் `file`-மட்டும் நெறிமுறை அனுமதிப்பட்டியல், ஒரு நூல், நிலையான வாத வரிசைகள், ஷெல் இல்லை, மற்றும் `PATH` இலிருந்து தீர்க்கப்பட்ட இயங்கக்கூடிய கோப்புகளைப் பயன்படுத்துகின்றன. இணைக்கப்பட்ட-படம் கவர் ஸ்ட்ரீம்கள் இயக்கக்கூடிய வேட்பாளர்கள் அல்ல. அனைத்து இயக்கக்கூடிய ஸ்ட்ரீம்களும் வரம்புகளை பூர்த்தி செய்ய வேண்டும், மேலும் ஒரு வெளிப்படையான இயல்புநிலை ஸ்ட்ரீம் தீர்மானகரமான குறைந்த-குறியீட்டு பின்னடைவுக்கு முன் விரும்பப்படுகிறது. வீடியோக்கள் 600 வினாடிகள், ஒரு பரிமாணத்திற்கு 8,192 பிக்சல்கள் மற்றும் 33,554,432 மூல பிக்சல்களுக்கு வரம்பிடப்பட்டுள்ளன. FFmpeg 1-16 நடுப்பகுதி JPEG பிரேம்களை மாதிரியாக்குகிறது, நீண்ட விளிம்பை அதிகபட்சம் 1,024 பிக்சல்களுக்கு குறைக்காமல் சிறிய உள்ளீடுகளை அதிகரிக்காமல், ஒருபோதும் URL ஐப் பெறுவதில்லை. மாதிரி இயல்பாக `uniform` ஆகும். விருப்பமான `scene_aware` மற்றும் சோதனை `segment_aware` கொள்கைகள் ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் ஸ்ட்ரீமில் ஒரு கூடுதல் நிலையான FFmpeg பாஸை செய்கின்றன, வரம்புக்குட்பட்ட `showinfo` காட்சி நேர முத்திரைகளைத் தேர்ந்தெடுக்கின்றன, மேலும் கண்டறிதல் தோல்வி, காலக்கெடு, தவறான வெளியீடு அல்லது ஒரு வெற்று வேட்பாளர் தொகுப்பில் அதே சீரான நடுப்பகுதிகளுக்கு தீர்மானகரமாக திரும்புகின்றன. பிரிவு-அறிவார்ந்த பயன்முறை சரிபார்க்கப்பட்ட காட்சி இடைவெளிகளுக்கு விகிதாசாரமாக நடுப்பகுதி மாதிரிகளை ஒதுக்குகிறது; பிரிவு-அறிவார்ந்த ஆதாரம் மற்றும் பின்னடைவு நடத்தை கீழே விவரிக்கப்பட்டுள்ளது. ஒவ்வொரு கொள்கையிலும் தேர்வு செய்த பிறகு கடினமான 16-பிரேம் வரம்பு
பயன்படுத்தப்படுகிறது. ஒரு காட்சி-அறிவார்ந்த கோரிக்கைக்கு ஒரு-பிரேம் பட்ஜெட் மட்டுமே இருக்கும்போது, அது செயலில் உள்ள முழு-வீடியோ அல்லது ஃபோகஸ் சாளரத்தின் சீரான நடுப்பகுதியைப் பயன்படுத்துகிறது மற்றும் `policyEffective: uniform` என்று தெரிவிக்கிறது: ஒரு தேர்ந்தெடுக்கப்பட்ட காட்சி பிரேம் தற்காலிக முனைகள் இரண்டையும் பாதுகாக்க முடியாது. ஒரு அழைப்பாளர் விருப்பமாக ஒரு வரையறுக்கப்பட்ட ஃபோகஸ் சாளரத்தை (`start`/`end` வினாடிகள்) வழங்கலாம்; வரம்புகள் மீடியா காலத்திற்கு இறுக்கப்படுகின்றன, தலைகீழான அல்லது வரையறுக்கப்படாத சாளரங்கள் நிராகரிக்கப்படுகின்றன, மேலும் அனைத்து மாதிரி கொள்கைகளும் இயல்பாக்கப்பட்ட இடைவெளிக்குள் மட்டுமே செய்யப்படுகின்றன. இதன் விளைவாக வரும் சாளரம் மாதிரி மெட்டாடேட்டாவிலும் மற்றும் நம்பத்தகாத விளக்க முன்னொட்டிலும் சேர்க்கப்பட்டுள்ளது, இதனால் கீழ்நிலை மாதிரிகள் முழு காலவரிசையிலிருந்து ஒரு கவனம் செலுத்திய பகுதியை வேறுபடுத்தி அறிய முடியும்.

செமண்டிக் தலைப்பு கவனம் ஒரு தனி, வெளிப்படையான அமைப்பு. இயல்புநிலை `full` பகுப்பாய்வு முறை இருக்கும் பிரேம் ப்ராம்ப்டைப் பாதுகாக்கிறது மற்றும் கோரிக்கை உரையை தலைப்பு மாதிரிக்கு ஒருபோதும் அனுப்பாது. `focused` பயன்முறையில், பாலம் அதே Chat அல்லது Responses கொள்கலனில் இருந்து சமீபத்திய வெற்று இல்லாத பயனர்-உருவாக்கிய `text`/`input_text` ஐ மட்டுமே படிக்கிறது, அதை NFC க்கு இயல்பாக்குகிறது, கட்டுப்பாட்டு எழுத்துக்கள் மற்றும் வெற்று இடங்களை சுருக்குகிறது, மேலும் அதை 500 யூனிகோட் குறியீட்டு புள்ளிகளுக்கு வரம்புக்குட்படுத்துகிறது. ஒரு வெற்று முடிவு துல்லியமான `full` ப்ராம்ப்டுக்கு திரும்புகிறது. ஒரு பயன்படுத்தக்கூடிய குறிப்பு ஒரு பிரத்யேக நம்பத்தகாத-பயனர்-சூழல் தொகுதியில் JSON ஆக வரிசைப்படுத்தப்படுகிறது மற்றும் கவனிக்கக்கூடிய விவரங்களுக்கு மட்டுமே முன்னுரிமை அளிக்கலாம்; இது மீடியாவில் தெரியும் அல்லது கேட்கக்கூடிய வழிமுறைகளைப் பின்பற்றுவதற்கு எதிரான தனி எச்சரிக்கையை மீற முடியாது. உரை கவனம் ஒருபோதும் `start`/`end` ஐ ஊகிக்காது அல்லது தற்காலிக மாதிரியை மாற்றாது.

#### FU-07 கட்டமைப்பு பிரிவு ஆதாரம்

`segment_aware` ஏற்கனவே சரிபார்க்கப்பட்ட உள்ளூர் வீடியோ ஸ்ட்ரீமில் ஒரு வரம்புக்குட்பட்ட முன்-பகுப்பாய்வு பாஸைப் பயன்படுத்துகிறது. நிலையான வடிகட்டி சங்கிலி முதலில் அதிகபட்சம் 320 பிக்சல்கள் அகலத்திற்கு அளவிடுகிறது, காட்சி மாற்றங்கள் மற்றும் உறைந்த இடைவெளிகளைக் கண்டறிகிறது, பின்னர் மங்கல்தன்மை, சராசரி லுமா மற்றும் இடஞ்சார்ந்த/தற்காலிக தகவல்களுக்கு ஒரு வினாடிக்கு 1 பிரேமில் மாதிரியாக்குகிறது. இந்த பாஸ் 600 கட்டமைப்பு மாதிரிகள், ஒரு FFmpeg/வடிகட்டி நூல், அதே `file`-மட்டும் நெறிமுறை மற்றும் கொள்கலன் அனுமதிப்பட்டியல்கள், ஒரு 1 MiB செயல்முறை-வெளியீட்டு வரம்பு மற்றும் தரகரின் பகிரப்பட்ட ரத்து/காலக்கெடுவுக்குள் அதிகபட்சம் 30 வினாடிகளுக்கு வரம்பிடப்பட்டுள்ளது. இது கோரிக்கையிலிருந்து ஒரு கட்டளை, வடிகட்டி, பாதை அல்லது URL ஐ ஒருபோதும் ஏற்றுக்கொள்வதில்லை.

கட்டமைப்பு மதிப்புகள் தீர்மானகரமான மாதிரி ஆதாரங்கள், சொற்பொருள் வீடியோ புரிதல் அல்ல. அவை பொருள்கள், செயல்கள், தலைப்புகள், பேச்சு அல்லது பயனர் நோக்கத்தை ஊகிக்கவில்லை. காட்சி மற்றும் உறைபனி எல்லைகள் பிரிவுகளை உருவாக்குகின்றன; உறைபனி கவரேஜ், மங்கல்தன்மை, வெளிப்பாடு, இடஞ்சார்ந்த விவரம் மற்றும் தற்காலிக மாற்றம் ஆகியவை ஏற்கனவே உள்ள 1–16 பிரேம் பட்ஜெட் எவ்வாறு ஒதுக்கீடு செய்யப்படுகிறது என்பதை மட்டுமே பாதிக்கின்றன. முழுமையாக உறைந்த ஒரு பிரிவு ஒரு பிரேமில் கட்டுப்படுத்தப்படுகிறது, அதே நேரத்தில் உறைபனியற்ற பிரிவுகள் மீதமுள்ள பட்ஜெட்டிற்காக போட்டியிடுகின்றன. எல்லைகள் பிரேம்களை விட அதிகமாக இருக்கும்போது, சீரான காலவரிசை கவரேஜ் தக்கவைக்கப்படுகிறது, இதனால் விரைவான ஆரம்ப வெட்டுகள் நீண்ட பின்வரும் பிரிவை மறைக்க முடியாது. உறைபனி எல்லையின் 1-வினாடி பகுப்பாய்வு தெளிவுத்திறனுக்குள் உள்ள காட்சி எல்லைகள் ஒன்றிணைக்கப்படுகின்றன.

காணாமல் போன வடிப்பான்கள், தவறான/வெற்று ஆதாரங்கள், ஒரு கண்டறிதல் பிழை அல்லது வரையறுக்கப்பட்ட முன்-பகுப்பாய்வு காலக்கெடு ஆகியவை துல்லியமான சீரான நடுப்பகுதி கொள்கைக்குத் திறக்கப்படுகின்றன. ஒரு அழைப்பாளர் ரத்து அல்லது தரகர் காலக்கெடு திறக்கப்படாது: அது செயல்பாட்டில் உள்ள துணை செயல்முறையை நிறுத்துகிறது, பின்னர் பிரேம் பிரித்தெடுப்பதைத் தடுக்கிறது, மேலும் தனிப்பட்ட தற்காலிக மரம் `finally` இல் அகற்றப்படுகிறது.

`scripts/perf/video-bridge-fu07-eval.ts` ஆனது போஸ்ட்-டிடூப் தலைப்பு-அழைப்பு சேமிப்புகள், அடர்த்தியான-இயக்க பட்ஜெட் ஒதுக்கீடு, மங்கல்தன்மை/வெளிப்பாடு/SI-TI ஆதாரங்கள், நீண்ட வால் கொண்ட விரைவான வெட்டுகள் மற்றும் படிப்படியாக மங்கலான தவறான நேர்மறைகளுக்கான தீர்மானகரமான உண்மையான FFmpeg சாதனங்களை உருவாக்குகிறது. இது முன்-பகுப்பாய்வு சுவர் நேரத்தையும், `/usr/bin/time` கிடைக்கும் இடங்களில், குழந்தை CPU மற்றும் உச்ச RSS ஐயும் பதிவு செய்கிறது. அதன் தரச் சோதனைகள் கட்டமைப்பு ஆரக்கிள்கள் மட்டுமே. இந்த ஹார்னஸுக்கு அங்கீகரிக்கப்பட்ட இறுதிப்புள்ளி அல்லது உறைந்த நீதிபதி இல்லாததால் உண்மையான தலைப்பு-மாதிரி தரம் `HOLD` ஆகவே உள்ளது. `--caption-cost-per-call-usd` ஒரு வெளிப்படையான நேர்மறை அழைப்புக்கான மதிப்பீட்டை வழங்காதவரை பணச் சேமிப்புகளும் `HOLD` ஆகவே இருக்கும்; ஸ்கிரிப்ட் ஒருபோதும் எந்த முடிவையும் உருவாக்காது.

ஒவ்வொரு பிரேமும் 4 MiB ஆகவும், அனைத்து மூல பிரேம்களும் சேர்ந்து 23 MiB ஆகவும், வரிசைப்படுத்தப்பட்ட தரகர் பதில் 32 MiB ஆகவும் கட்டுப்படுத்தப்பட்டுள்ளது. ஒரு தனிப்பட்ட தற்காலிக அடைவு `finally` இல் அகற்றப்படுகிறது. OmniRoute FFmpeg ஐ தொகுக்கவில்லை மற்றும் தனிப்பயன் இயக்கக்கூடிய பாதையை ஏற்கவில்லை. தலைப்பிடுவதற்கு முன், பாலம் ஒரு பழமைவாத காட்சி நகல் நீக்கப் படியை பயன்படுத்துகிறது: ஒவ்வொரு JPEG உம் 16×16 கிரேஸ்கேல் பஃபராகக் குறைக்கப்பட்டு, தக்கவைக்கப்பட்ட கடைசி பிரேமுடன் மட்டுமே ஒப்பிடப்படுகிறது. ஒரு பிரேமுக்கு மேல் கோரப்பட்ட தலைப்பு பட்ஜெட்டுக்கு, பிரித்தெடுப்பு அந்த பட்ஜெட்டை விட இருமடங்கு வரை மற்றும் 16 பிரேம்களுக்கு மேல் இல்லாத ஒரு வரையறுக்கப்பட்ட வேட்பாளர் தொகுப்பை வழங்குகிறது. கோரப்பட்ட வரம்பு நகல் நீக்கத்திற்குப் பிறகு மட்டுமே பயன்படுத்தப்படுகிறது, பட்ஜெட் குறைந்தபட்சம் இரண்டாக இருக்கும்போது இறுதி மெலிதாக்கலின் போது முதல் மற்றும் இறுதி தேர்ந்தெடுக்கப்பட்ட வேட்பாளர்கள் பாதுகாக்கப்படுகிறார்கள். பதிப்புப்படுத்தப்பட்ட `grayscale-16x16-mean-cells-v2` கொள்கையானது சராசரி லூமா டெல்டாவிற்கும், அதன் இயல்பாக்கப்பட்ட டெல்டா குறைந்தபட்சம் 0.05 ஆக இருக்கும் சிறுபட செல்களின் விகிதத்திற்கும் உள்ள பெரிய மதிப்பை பயன்படுத்துகிறது. நகல் வரம்பு நிலையான 0.04 ஆகும், இது இயக்கநேர அமைப்பாக வெளிப்படுத்தப்படுவதை விட கணிக்கக்கூடிய தன்மைக்காக தேர்ந்தெடுக்கப்பட்டது. இந்த இரண்டாம் நிலை உயர்-மாறுபட்ட சமிக்ஞை, சராசரி-மட்டும் ஒப்பீடு மறைக்கக்கூடிய சிறிய இயக்கம் மற்றும் புலப்படும்-உரை மாற்றங்களைப் பாதுகாக்கிறது. ஒப்பிடுபவர் அல்லது டிகோடர் பிழைகள் திறக்கப்பட்டு கவரேஜை வைத்திருக்கும். வெளியீட்டு மெட்டாடேட்டா பிரித்தெடுக்கப்பட்ட வேட்பாளர்கள், வெற்றிகரமாகப் பயன்படுத்தப்பட்ட பிரேம்கள் மற்றும் கைவிடப்பட்ட காட்சி நகல்களைப் பிரிக்கிறது.

வெளிப்படையாகக் குறிக்கப்பட்ட வீடியோ பகுதி ஒரு நேர முத்திரையிடப்பட்ட தொடர்புத் தாளைக் கோரலாம். பாலம் அதிகபட்சம் 4-கலம், 16-பிரேம் JPEG கட்டத்தை உருவாக்குகிறது. ஒவ்வொரு 512-பிக்சல் செல்லும் அதன் மூல நேர முத்திரையை ஒரு உயர்-மாறுபட்ட கீழ் பட்டியில் பொறிக்கிறது, அதே நேரத்தில் அதே நேர முத்திரைகள் கீழ்நிலை தொடர்பு மற்றும் தணிக்கைக்கான உரை மெட்டாடேட்டாவில் இருக்கும். முழுமையான JPEG 32 MiB ஆகவே கட்டுப்படுத்தப்பட்டுள்ளது. `sharp` கட்டத்தை டிகோட் செய்யவோ அல்லது உருவாக்கவோ முடியாவிட்டால், பாலம் தனிப்பட்ட JPEG பிரேம்களுக்குத் திரும்புகிறது; ஒரு கிளையன்ட் ரத்து இன்னும் தாள் செயல்பாட்டின் மூலம் பரவுகிறது.

பதவி உயர்வு ஆதாரம் செயற்கை கலவை மைக்ரோபெஞ்ச்மார்க்கிலிருந்து வேண்டுமென்றே பிரிக்கப்பட்டுள்ளது. `scripts/perf/video-bridge-contact-sheet-eval.ts` உண்மையான OpenAI-இணக்கமான பார்வை மாதிரிகளுக்கான ஸ்கீமா-பதிப்புப்படுத்தப்பட்ட A/B ஹார்னஸை வரையறுக்கிறது. இது வழங்குநர்-அறிவிக்கப்பட்ட டோக்கன்கள், எண்ட்-டு-எண்ட் சுவர் தாமதம் (தாள் கலவை உட்பட), மாதிரி-அழைப்பு எண்ணிக்கை மற்றும் வெளிப்படையாக வரையறுக்கப்பட்ட உண்மை தக்கவைப்பு ஆகியவற்றை அளவிடுகிறது. மூல மாதிரி பதில்கள் அறிக்கையில் எழுதப்படவில்லை; SHA-256 டைஜெஸ்ட்கள் மற்றும் பொருத்தப்பட்ட உண்மை ஐடிகள் மட்டுமே தக்கவைக்கப்படுகின்றன. `--execute-real` அனுப்பப்பட்டு `--model`, `OMNIROUTE_BASE_URL`, மற்றும் `OMNIROUTE_API_KEY` உள்ளமைக்கப்பட்டாலன்றி, ஹார்னஸ் எந்த நெட்வொர்க் அல்லது கட்டண மாதிரி அழைப்பையும் செய்யாது. அந்த வெளிப்படையான உண்மையான இயக்கம் இல்லாமல், அதன் இயந்திரம் படிக்கக்கூடிய தீர்ப்பு `HOLD` ஆகவே இருக்கும்; செயற்கை பேலோட்/அழைப்பு-எண்ணிக்கை அளவீடுகள் மட்டும் பதவி உயர்வு ஆதாரம் அல்ல.

அழைப்பாளர்கள் ஏற்கனவே சீரமைக்கப்பட்ட உரையை வைத்திருக்கும் போது, ஆதரிக்கப்படும் வீடியோ பகுதிக்கு விருப்பமான `transcript.cues` வரிசையை இணைக்கலாம். ஒவ்வொரு கியூவும் `text`, ஆய்வு செய்யப்பட்ட கால அளவின் உள்ளே ஒரு வரையறுக்கப்பட்ட `start`/`end` இடைவெளி, மற்றும் ஒரு வெள்ளைப் பட்டியலில் உள்ள `source` (`client`, `embedded`, அல்லது `audio-bridge`) ஆகியவற்றைக் கொண்டிருக்க வேண்டும்; `confidence` இயல்பாக `1` ஆக இருக்கும் மற்றும் `0` மற்றும் `1` க்கு இடையில் இருக்க வேண்டும். துல்லியமான நகல் கியூக்கள் சுருக்கப்படுகின்றன. OmniRoute இந்த மெட்டாடேட்டாவிலிருந்து ஒருபோதும் டிரான்ஸ்கிரிப்ஷனைத் தொடங்காது: சரிபார்க்கப்பட்ட கியூக்கள் மூல, நம்பிக்கை மற்றும் இடைவெளியுடன் விவரிக்கப்பட்ட முடிவில் நகலெடுக்கப்பட்டு, பிரேம் தலைப்புகளுடன் நம்பத்தகாத அவதானிப்புகளாக வழங்கப்படுகின்றன. தவறான, வரம்பிற்கு அப்பாற்பட்ட அல்லது ஆதாரமற்ற உரை நிராகரிக்கப்படுகிறது, தலைப்பு ஸ்ட்ரீமில் கலக்கப்படுவதில்லை. `source` புலம் தற்போது அழைப்பாளரால் அறிவிக்கப்பட்டது, சர்வரால் சரிபார்க்கப்படவில்லை: OmniRoute அனுமதிக்கப்பட்ட மூன்று சரங்களில் ஒன்றுதான் மதிப்பு என்பதை உறுதிப்படுத்துகிறது, ஆனால் `embedded` அல்லது `audio-bridge` லேபிள் உண்மையில் சர்வர்-சொந்தமான பிரித்தெடுப்பிலிருந்து வந்ததா என்பதை இன்னும் குறியாக்க ரீதியாக உறுதிப்படுத்தவில்லை. அந்த சரிபார்ப்பு வரும் வரை `source` ஐ நம்பத்தகாத குறிப்பாகக் கருதுங்கள்; அதன் அடிப்படையில் அங்கீகார முடிவுகளை எடுக்க வேண்டாம்.

மேம்பட்ட அழைப்பாளர் அதே வீடியோவிற்கான ஏற்கனவே அங்கீகரிக்கப்பட்ட `audioTranscript` டிராக்கை வழங்கலாம். ஃப்யூஷன் சீம் காட்சி மற்றும் ஆடியோ அவதானிப்புகளை ஒரே காலக்கெடு மற்றும் ரத்துசெய்யும் சிக்னலின் கீழ் இயக்குகிறது, அவற்றை ஒரு பொதுவான காலவரிசையில் வரிசைப்படுத்துகிறது, சரியான நகல்களை நீக்குகிறது, மேலும் ஒரு பக்கம் மட்டுமே வெற்றிபெறும்போது ஒரு பகுதி முடிவை அறிவிக்கிறது. ஒரு தவறான `audioTranscript` அந்த பகுதி முடிவுக்கு தரமிறக்கப்படுகிறது - காட்சி விளக்கம் வைக்கப்படுகிறது மற்றும் ஆடியோ கிளை ஒரு சுத்திகரிக்கப்பட்ட தோல்வி குறியீட்டைப் பதிவு செய்கிறது - முழு வீடியோவையும் தோல்வியடையச் செய்வதற்குப் பதிலாக. கிளைக்குரிய கிடைக்கும் தன்மை, பகுதி கொடி மற்றும் சுத்திகரிக்கப்பட்ட தோல்வி குறியீடுகள் விவரிக்கப்பட்ட முடிவில், கார்ட்ரெயில் மெட்டாடேட்டாவில் (`audioFusionRuns`/`audioFusionPartials`/`audioFusionFailureCodes`), முடிவு-தற்காலிக சேமிப்பு மெட்டாடேட்டாவில் மற்றும் பிரிட்ஜ் ஃப்யூஷன் கவுண்டர்களில் பாதுகாக்கப்படுகின்றன. இயல்புநிலை வீடியோ பிரிட்ஜ் பாதை பேச்சு-உரைக்கு அழைப்பதில்லை அல்லது இரண்டாவது மீடியா நகலைப் பதிவிறக்குவதில்லை; அந்த வெளிப்படையான டிராக் இல்லாமல், அது வீடியோ-மட்டுமேயாகவே இருக்கும்.

**டிரான்ஸ்கிரிப்ட் தக்கவைப்பு (#12150 P1).** வீடியோ பிரிட்ஜ் (தானாகவே தேர்வுசெய்யக்கூடியது) ஒரு டிரான்ஸ்கிரிப்ட் கியூவை வழங்கும்போது இது தானாகவே பொருந்தும் - தனித்தனி தக்கவைப்பு கொடி இல்லை. ஒரு கோரிக்கை எந்த டிரான்ஸ்கிரிப்ட் கியூவையும் (அழைப்பாளரால் அறிவிக்கப்பட்ட `transcript` அல்லது ஒரு ஃப்யூஸ் செய்யப்பட்ட `audioTranscript`) வழங்கும்போது, கார்ட்ரெயில் அதை `videoBridgeObserved` என்று குறிக்கிறது மற்றும் வீடியோ விளக்கத்தின் திருத்தப்பட்ட நிழலை உருவாக்குகிறது - ஒவ்வொரு கியூவின் இலவச-உரை உடலும் `[redacted-video-transcript]` ஆல் மாற்றப்படும் ஒரு ஒத்த ரெண்டரிங், சரம் அசெம்பிள் செய்யப்படுவதற்கு முன்பு கட்டமைக்கப்பட்ட கியூ புலத்தை மாற்றுவதன் மூலம் உருவாக்கப்பட்டது (ஒருபோதும் தட்டையான உரையை பகுப்பாய்வு செய்வதன் மூலம் அல்ல, எனவே எந்த கியூ உள்ளடக்கமும் - விரோதமான அல்லது சாதாரண, `]` போன்ற உடல்கள் உட்பட `[inaudible]`/`[music]` - தப்பிக்க முடியாது). நிலைநிறுத்தப்பட்ட அழைப்பு-பதிவு கோரிக்கை உடல், உள்ளடக்க சமத்துவத்தால் பொருத்தப்பட்ட அந்த திருத்தப்பட்ட நிழலுக்காக ஒவ்வொரு வீடியோ-பெறப்பட்ட உரை பகுதியையும் மாற்றுகிறது; `fullText` ஆங்கர் முடிக்கப்பட்ட முன்-அழைப்பு கார்ட்ரெயில் பேலோடில் இருந்து மீண்டும் படிக்கப்படுகிறது, எனவே பிந்தைய சங்கிலி கார்ட்ரெயில்கள் (PII மற்றும் சான்றுகள் மாஸ்கர்கள், முன்னுரிமைகள் 10/95) விளக்க உரையை இடத்திலேயே மீண்டும் எழுதும்போதும் மற்றும் கணினி-தூண்டுதல்/கைமாற்று/நினைவக ஊசி செய்தி வரிசையை மறுவடிவமைத்த பிறகும் பொருத்தம் இன்னும் வெற்றிபெறுகிறது. மாதிரிக்கு அனுப்பப்படும் உடல் மாறாமல் உள்ளது. ஒரு கவனிக்கப்பட்ட கோரிக்கை எந்த நீடித்த நினைவகத்தையும் நிரப்புவதில்லை (கோரிக்கை மற்றும் பதில்-பெறப்பட்ட பிரித்தெடுத்தல் இரண்டும் தவிர்க்கப்படுகின்றன), எனவே மாதிரியின் சொந்த பதில் டிரான்ஸ்கிரிப்ட் உரையை நினைவகத்தில் எதிரொலிக்க முடியாது.

கூடுதல் தக்கவைக்கப்பட்ட நகல்கள் அதே கவனிக்கப்பட்ட-கோரிக்கை சிக்னலைப் பயன்படுத்துகின்றன. கார்ட்ரெயிலுக்கு முந்தைய மூல கிளையன்ட்-கோரிக்கை ஸ்னாப்ஷாட், நினைவகத்தில் நிலுவையிலுள்ள கோரிக்கை மற்றும் ஆரம்ப நிராகரிக்கப்பட்ட-கோரிக்கை பதிவு ஆகியவை வீடியோ பாகங்களில் டிரான்ஸ்கிரிப்ட் புலங்களை கட்டமைப்பு ரீதியாக மாற்றுகின்றன; பைப்லைன் நிலைகள் மற்றும் சூழல் கைமாற்று மூலம் தொகுக்கப்பட்ட சரம் தூண்டுதல்கள் நிலைநிறுத்தப்பட்ட-கோரிக்கை-உடல் சிங்கில் திருத்தப்படுகின்றன. நிலைநிறுத்தப்பட்ட `video_content_removed` மார்க்கர் `previous_response_id` தொடர்ச்சியை வேண்டுமென்றே நிராகரிக்கப்பட்ட உரையை மீண்டும் உருவாக்குவதற்குப் பதிலாக மூடிய நிலையில் தோல்வியடையச் செய்கிறது. ஒரு கவனிக்கப்பட்ட கோரிக்கை பதிவு செய்வதற்கு முன்பு அதன் பகுதிக்குரிய திருத்த நிழலை இழந்தால், அல்லது பல வீடியோ நிழல்களில் ஒன்று பிந்தைய கோரிக்கை மாற்றங்களுக்குப் பிறகு பொருந்தத் தவறினால், தக்கவைக்கப்பட்ட கோரிக்கை உடல் பகுதியளவு திருத்தப்பட்ட டிரான்ஸ்கிரிப்டை தக்கவைப்பதற்குப் பதிலாக முழுமையாக தவிர்க்கப்படுகிறது.

ஒரு கவனிக்கப்பட்ட கோரிக்கைக்காக, ஒரு மாதிரி பதில் கட்டமைக்கப்பட்ட கியூ எல்லை இல்லாமல் டிரான்ஸ்கிரிப்டின் எந்தப் பகுதியையும் மேற்கோள் காட்டலாம். அதன் நிலைநிறுத்தப்பட்ட அழைப்பு-பதிவு `responseBody` எனவே ஒரு தவிர்க்கும் மார்க்கரால் மாற்றப்படுகிறது; விரிவான பைப்லைன் கலைப்பொருள் (இது அப்ஸ்ட்ரீம்/கிளையன்ட் உடல்கள் மற்றும் ஸ்ட்ரீம் சங்ஸ் ஆகியவற்றை உள்ளடக்கியது) தக்கவைக்கப்படுவதில்லை. செமண்டிக், ஐடெம்போடென்சி மற்றும் ரீசனிங்-ரீப்ளே கேச்சுகள் அந்தக் கோரிக்கைக்கான வாசிப்புகள் மற்றும் எழுதுதல்களைத் தவிர்க்கின்றன. வழங்குநர் கோரிக்கை மற்றும் கிளையன்ட்-தெரியும் பதில் மாறாமல் இருக்கும். விரிவான கலைப்பொருள் தவிர்க்கப்படும்போது தற்காலிக பஃபரில் இருந்து ஆரம்ப கீப்அலைவ் பைட்டுகள் வெளியேற்றப்படுகின்றன. கரோவின் தவறான EventStream எச்சரிக்கை பேலோட் பைட் எண்ணிக்கையை மட்டுமே அறிவிக்கிறது, அதன் உள்ளடக்கங்கள் அல்லது JSON பார்சரின் மூல பிழையை ஒருபோதும் அறிவிப்பதில்லை.
ஒவ்வொரு தொடர்பில்லாத வழங்குநர்/செருகுநிரல் கண்டறிதலும் தணிக்கை செய்யப்பட்டுள்ளது என்று இது கூறவில்லை; பரந்த தக்கவைக்கப்பட்ட-சிங்க் ஸ்வீப் #11658 இல் கண்காணிக்கப்படுகிறது.

ஒவ்வொரு முதன்மைக்கும் 16 உள்ளீடுகள் மற்றும் 64 MiB நியதி JPEG தரவு வரம்பிடப்பட்டுள்ளது. அந்த வரம்புகள் உலகளாவிய 64-உள்ளீடு/256 MiB உச்சவரம்பிலிருந்து சுயாதீனமானவை: உலகளாவிய LRU வெளியேற்றம் கருத்தில் கொள்ளப்படுவதற்கு முன்பு முதன்மை ஒதுக்கீடு அழுத்தம் அந்த முதன்மையின் மிகக் குறைந்த-சமீபத்தில் பயன்படுத்தப்பட்ட உள்ளீடுகளை மட்டுமே வெளியேற்றுகிறது. காலாவதியான உள்ளீடுகள் தற்காலிக சேமிப்பு செயல்பாட்டில் முதன்மை மற்றும் உலகளாவிய கணக்கியல் இரண்டிலிருந்தும் அகற்றப்படுகின்றன, அதே நேரத்தில் ரத்துசெய்தல் மற்றும் சரிபார்ப்பு தோல்வி ஒரு பகுதி மாற்றத்தை உறுதிப்படுத்துவதில்லை.

தற்காலிக சேமிப்பு நியதி அல்லாத Base64, அதிகப்படியான பேடிங், JPEG அல்லாத மீடியா, தவறான அல்லது துண்டிக்கப்பட்ட JPEGகள் மற்றும் வரம்புக்குட்பட்ட முழு-பட `sharp` டிகோட் போது எச்சரிக்கையை உருவாக்கும் JPEGகளை நிராகரிக்கிறது. இது ஏற்றுக்கொள்ளப்பட்ட ஒவ்வொரு படத்தையும் ஒரு நியதி JPEG ஆக மீண்டும் குறியாக்குகிறது, அழைப்பாளர் புலங்களை நம்புவதற்குப் பதிலாக டிகோட் செய்யப்பட்ட பைட்டுகளிலிருந்து அகலம் மற்றும் உயரத்தைப் பெறுகிறது, மேலும் எந்தவொரு பிந்தைய பாலி கிளாட் பைட்டுகளையும் தக்கவைப்பதற்குப் பதிலாக நிராகரிக்கிறது. வரம்புக்குட்பட்ட நியதி சுருக்கப்பட்ட பஃபர் மட்டுமே இரண்டு ஒதுக்கீடுகளுக்கும் வசூலிக்கப்படுகிறது. JSON வயர் வரம்பு 32 MiB டிகோட் செய்யப்பட்ட-உள்ளீட்டு உச்சவரம்பிற்கான Base64 ஓவர்ஹெட்டை உள்ளடக்கியது. ஒவ்வொரு சேமிக்கப்பட்ட பெறுதலும் அதன் சரிபார்க்கப்பட்ட JPEG வடிவம்/தெளிவுத்திறன், மாதிரி கொள்கை, பெறுதல் பதிப்பு, உருவாக்கும் நேரம், சர்வர்-கணக்கிடப்பட்ட உள்ளடக்க ஹாஷ் மற்றும் ஹாஷ் செய்யப்பட்ட பெற்றோர் குறிப்பு மற்றும் நம்பகமான அழைப்பாளரின் பெற்றோர்-உள்ளடக்க ஹாஷ் ஆகியவற்றை பதிவு செய்கிறது. அணு தற்காலிக சேமிப்பு உறுதிப்பாட்டிற்கு முன்பு ஒத்திசைவற்ற டிகோட்/ஹாஷ் கட்டங்களுக்கு இடையில் ரத்துசெய்தல் சரிபார்க்கப்படுகிறது.

இந்த டிரான்ச் இன்னும் ஒரு தயாரிப்பு தயாரிப்பாளரை வழித்தடத்துடன் இணைக்கவில்லை மற்றும் பல-தெளிவு மாறுபாடு தேர்வை வழங்கவில்லை. வெளிப்படையான வீடியோ பிரிட்ஜ் கோரிக்கை பாதைக்கு கூடுதல் வேலை எதுவும் இல்லை, அதே நேரத்தில் குத்தகைதாரர்-கட்டுப்பட்ட முதன்மை வழித்தோன்றல் மற்றும் முழு FU-08 பல-தெளிவு வாழ்க்கைச் சுழற்சி ஆகியவை முழுமையான நடத்தையாக ஆவணப்படுத்தப்படுவதற்குப் பதிலாக வெளிப்படையான பின்தொடர்தல் வேலையாகவே இருக்கின்றன.

பிரேம்கள் உள்ளமைக்கப்பட்ட வீடியோ மாதிரியுடன் வரிசையாக தலைப்பிடப்படுகின்றன. ஒரு வெற்று வீடியோ மேலெழுதல் விஷன் அமைப்பை மரபுரிமையாகப் பெறுகிறது; இரண்டும் காலியாக இருந்தால், விஷன் ஆட்டோ-ரூட்டர் பயனுள்ள விஷன்-திறன் கொண்ட மாதிரியைத் தேர்ந்தெடுக்கிறது. வெற்றிகரமான தலைப்புகள் அசல் பகுதியை ஒரு நிலையான `[Video description:` முன்னொட்டுடன் மாற்றுகின்றன, இது உரையை நம்பத்தகாத ஊடகத்திலிருந்து பெறப்பட்ட அவதானிப்பாகவும் குறிக்கிறது மற்றும் கீழ்நிலை மாதிரிகளுக்கு ஊடகத்தில் காணப்படும் வழிமுறைகளைப் பின்பற்ற வேண்டாம் என்று கூறுகிறது. பிரேம்-தலைப்பு கேச் விசைகளில் JPEG பைட்டுகள், ப்ராம்ட், டைம்ஸ்டாம்ப் மற்றும் பயனுள்ள மாதிரி ஆகியவை அடங்கும்; வெற்றிகரமான தலைப்புகள் மட்டுமே கேச் செய்யப்படுகின்றன. கேச் உள்ளீடுகள் உண்மையான வெற்றிகரமான தயாரிப்பாளர் மாதிரியைத் தக்கவைத்துக்கொள்கின்றன, இதில் ஒரு ஃபால்பேக் மாதிரியும் அடங்கும்; வெவ்வேறு பிரேம்கள் வெவ்வேறு மாதிரிகளால் தயாரிக்கப்பட்டால் பிரிட்ஜ் `mixed` என்று தெரிவிக்கிறது. ஒரு கேச் ஹிட், கோரப்பட்ட ரூட்டிங் திட்டமாக மறுபெயரிடுவதற்குப் பதிலாக அந்த தயாரிப்பாளர் அடையாளத்தை மீண்டும் பயன்படுத்துகிறது. முழு வீடியோ முடிவு கேச், வெளியீட்டை மாற்றும் ஒவ்வொரு உள்ளீட்டிலும் முக்கியப்படுத்தப்படுகிறது - ப்ராம்ட், பயனுள்ள மாதிரி, மாதிரி கொள்கை, பிரேம் எண்ணிக்கை, செமண்டிக் பகுப்பாய்வு முறை, இயல்பாக்கப்பட்ட ஃபோகஸ் குறிப்பின் SHA-256 கைரேகை, ஃபோகஸ் சாளரம், `transcript`, `audioTranscript`, மற்றும் தொடர்பு-தாள் கொடி - எனவே இந்த பரிமாணங்களில் ஏதேனும் ஒன்றை மாற்றுவது ஒரு கேச் மிஸ் ஆகும், ஒருபோதும் பழைய மறுபயன்பாடு அல்ல. காட்சி நீக்குதல் கொள்கை பதிப்பு, வரம்பு மற்றும் கட்டுப்படுத்தப்பட்ட வேட்பாளர்-பிரேம் எண்ணிக்கை ஆகியவை முடிவு-கேச் விசை மற்றும் மெட்டாடேட்டாவில் வெளிப்படையாக உள்ளன; எனவே ஒரு கொள்கை மாற்றம் ஒரு பழைய முழு-வீடியோ விளக்கத்தை மீண்டும் பயன்படுத்த முடியாது. முடிவு-கேச் v4 மெட்டாடேட்டா முறை மற்றும் கைரேகையை வைத்திருக்கிறது, ஒருபோதும் மூல பயனர் பணியை அல்ல. கார்ட்ரெயில் மெட்டாடேட்டா கோரப்பட்ட மற்றும் பயனுள்ள பகுப்பாய்வு முறைகள் இரண்டையும் தெரிவிக்கிறது; பயன்படுத்தக்கூடிய பயனர் உரை இல்லாத கோரப்பட்ட `focused` முறை பயனுள்ள `full` என்று அறிவிக்கப்படுகிறது.

கார்ட்ரெயில் ஆதரிக்கப்படும் ஒவ்வொரு வீடியோ பகுதியையும் பிரித்தெடுக்கிறது, ஆனால் `modalityBridgeVideoMaxVideos` ஐ விட அதிகமாக விவரிக்கவில்லை. `supportsVideo === false` என்று நிரூபிக்கப்பட்ட ஒரு இலக்குக்கு, தோல்வியுற்ற மற்றும் வரம்பை மீறிய வீடியோக்கள் வெளிப்படையான பாதுகாப்பான உரை குறிப்பான்களாக மாறும், எனவே மூல வீடியோ எதுவும் எஞ்சியிருக்காது. திறன் தெரியாதபோது, அந்த பகுதிகள் தொடப்படாமல் இருக்கும். `supportsVideo === true` கொண்ட இலக்குகள் பிரிட்ஜை புறக்கணிக்கின்றன. கிளையன்ட் கோரிக்கை ரத்துசெய்தல் சமிக்ஞை பதிவிறக்கம், ப்ரோக்கர் வரிசை, துணை செயல்முறைகள் மற்றும் தலைப்பு அழைப்புகள் வழியாக பரவுகிறது; ரத்துசெய்தல்கள் வீடியோக்களுக்கு இடையில் நிறுத்தப்படும் மற்றும் மூல ஊடகத்திற்கு ஒருபோதும் திறக்கப்படாது.

### PII மாஸ்கர் (`piiMasker.ts`)

**இரண்டு** நிலைகளிலும் இயங்குகிறது.

- **`preCall`** பேலோடை குளோன் செய்கிறது, `system`, `messages`, `input`, மற்றும் `prompt` (சாதாரண சரம் உருப்படிகள் உட்பட) வழியாக செல்கிறது, மேலும் `processPII()` ( `@/shared/utils/inputSanitizer` இலிருந்து) சரம் `content`/`text` புலங்களுக்குப் பயன்படுத்துகிறது. `PII_REDACTION_ENABLED=true` ஆக இருக்கும்போது, கண்டறியப்பட்ட PII வெளிச்செல்லும் பேலோடில் திருத்தப்படுகிறது. இது `INPUT_SANITIZER_MODE` (இது ப்ராம்ட்-இன்ஜெக்ஷன் கொள்கையை மட்டுமே கட்டுப்படுத்துகிறது) இலிருந்து சுயாதீனமானது. திருத்தம் முடக்கப்பட்டிருக்கும்போது, அழைப்பு உள்ளடக்கத்தை மீண்டும் எழுதாமல் கண்டறிதல் எண்ணிக்கையை பதிவு செய்கிறது.
- **`postCall`** பதிலின் ஆழமான குளோனை உருவாக்குகிறது, `sanitizePIIResponse()` மற்றும் Responses-API-வடிவ மாஸ்கரை (`maskResponsesOutput` — `output_text` மற்றும் `output[].content[].text` ஐ உள்ளடக்கியது) இயக்குகிறது. ஏதேனும் திருத்தம் ஏற்பட்டால், மாற்றியமைக்கப்பட்ட பதில் அசல் பதிலுக்கு பதிலாக அமைகிறது.

கார்ட்ரெயில் ஒருபோதும் தடுக்காது; அது குறிப்புரைகளை மட்டுமே சேர்க்கிறது (`meta.detections`, `meta.redacted`) அல்லது மீண்டும் எழுதுகிறது.

| தடுப்பு வரம்பு | `blockThreshold` option / `INPUT_SANITIZER_BLOCK_THRESHOLD` (alias `INJECTION_GUARD_BLOCK_THRESHOLD`) | `high`     | தடுக்கத் தேவையான குறைந்தபட்ச தீவிரம். இயல்புநிலையில் நடுத்தரம் என்பது கவனிப்பு-மட்டுமே.                                                                                                                                  |

**முறை முன்னுரிமை** (`getMode`): அழைப்பாளர் `options.mode` →
`INJECTION_GUARD_MODE` **DB அம்சக் கொடி மேலெழுதல்** (டாஷ்போர்டு → அமைப்புகள் →
அம்சக் கொடிகள்) → `INJECTION_GUARD_MODE` env → `INPUT_SANITIZER_MODE` env →
`warn`. எனவே, ஒரு டாஷ்போர்டு மேலெழுதல் env மாறிகளை விட முன்னுரிமை பெறும், இதனால் அம்சக் கொடிகள் UI இயங்கும் கார்டை நேரடியாகக் கட்டுப்படுத்துகிறது (மறுதொடக்கம் இல்லை). DB வாசிப்பு தோல்வி-பாதுகாப்பானது: அது பிழையாக இருந்தால், கார்ட் env-அடிப்படையிலான நடத்தைக்குத் திரும்பும், மேலும் மேலெழுதல் எதுவும் அமைக்கப்படாதபோது, நடத்தை env-மட்டுமே தீர்மானிப்பதற்கு ஒத்ததாக இருக்கும்.

கண்டறிதல் ஆதாரங்கள்:

1.  `@/shared/utils/inputSanitizer` இலிருந்து `sanitizeRequest()` (பைப்பலைனில் வேறு இடங்களில் பயன்படுத்தப்படும் பகிரப்பட்ட கண்டறிதல் தொகுப்பு).
2.  உள்ளமைக்கப்பட்ட `DEFAULT_GUARD_PATTERNS` (தற்போது `system_override_inline` மற்றும்
    `markdown_system_block`, இரண்டும் `high` தீவிரம்).
3.  கட்டமைப்பாளர் விருப்பங்கள் வழியாக அனுப்பப்படும் விருப்பமான `customPatterns` (சரங்கள், ரெஜெக்ஸ்,
    அல்லது `{ name, pattern, severity }` பதிவுகள்).

`mode === "block"` ஆக இருக்கும்போது **மற்றும்** குறைந்தபட்சம் ஒரு கண்டறிதல் தீவிர
வரம்பை பூர்த்தி செய்தால், `preCall` `{ block: true, message: "Request rejected:
suspicious content detected" }` என்பதைத் திருப்பி அனுப்பும். `warn`/`log` முறைகளில் கார்ட்ரெயில் பதிவு செய்யும் ஆனால்
அழைப்பை அனுமதிக்கும். பதிவேட்டின் வழியாகச் செல்லாமல் ப்ராம்ப்ட்களை மதிப்பிட வேண்டிய அழைப்பாளர்களுக்காக பகிரப்பட்ட உதவியாளர் `evaluatePromptInjection()` ஏற்றுமதி செய்யப்படுகிறது.

**ஸ்கேன் வரம்பு (v3.8.20):** கண்டறிப்பான் இணைக்கப்பட்ட ப்ராம்ப்ட் உரையின் **முதல் 16 KB** ஐ மட்டுமே ஆய்வு செய்கிறது — `src/shared/utils/inputSanitizer.ts` இல் `MAX_INJECTION_SCAN_BYTES = 16 * 1024` (16 384 பைட்டுகள்). `detectInjection()` மற்றும் `evaluatePromptInjection()` இரண்டும் பேட்டர்ன் லூப்பை இயக்குவதற்கு முன் `slice(0, MAX_INJECTION_SCAN_BYTES)` ஐப் பயன்படுத்துகின்றன. ஊசி வழிமுறைகள் ஒரு உள்ளீட்டின் மேற்பகுதியில் அமர்ந்திருப்பதால், இது பல நூறு KB பேலோடுகளில் ரெஜெக்ஸ் CPU/GC ஐக் கட்டுப்படுத்துகிறது, கண்டறிதலை பலவீனப்படுத்தாமல் (cf. #3932, #4041).

### சான்றளிப்பு மறைப்பான் (`credentialMasker.ts`)

**இரண்டு** நிலைகளிலும் இயங்குகிறது, இயல்புநிலை சங்கிலியில் கடைசியாக (முன்னுரிமை `95`). வெளிச்செல்லும் பேலோடில் (செய்தி உள்ளடக்கம், கருவி-அழைப்பு வாதங்கள், கருவி முடிவுகள்) **மற்றும்** வழங்குநர் பதிலில் இருந்து நன்கு அறியப்பட்ட API-விசை / ரகசிய-டோக்கன் வடிவங்களை நீக்குகிறது, இதனால் ஒரு ப்ராம்ப்டில் ஒட்டப்பட்ட (அல்லது ஒரு கருவி முடிவால் எதிரொலிக்கப்பட்ட) ஒரு சான்றளிப்பு மேல்நிலை வழங்குநருக்கு அல்லது கிளையண்டிற்கு கசியாது.

- **தேர்வு-மட்டுமே**, PII நீக்குதலுக்கு ஒத்த மரபு (கடின விதி #20-அருகில்): `settings.credentialRedactionEnabled === true` **அல்லது**
  `CREDENTIAL_REDACTION_ENABLED=true` ஆக இருந்தால் மட்டுமே இயக்கப்படும். இது முடக்கப்பட்டால், கார்ட்ரெயில் ஒரு நோ-ஆப் ஆகும் — அது ஒருபோதும் தடுக்காது மற்றும் ஒருபோதும் மறுஎழுதாது.
- `redactCredentials()` முழு பேலோட்/பதில் மரத்தை (`walkValue()`, புரோட்டோடைப்-மாசுபாட்டிலிருந்து பாதுகாப்பானது, `WeakSet` வழியாக சுழற்சி-பாதுகாப்பானது) கடந்து, பொருத்தங்களை `[REDACTED:<type>]` பிளேஸ்ஹோல்டரால் மாற்றுகிறது, உண்மையில் மாறிய கிளைகளை மட்டுமே குளோன் செய்கிறது.
- `CREDENTIAL_PATTERNS` ஆனது LLM வழங்குநர் விசைகள் (OpenAI, OpenAI-proj, Anthropic, Google, Hugging Face, Replicate), VCS/SaaS டோக்கன்கள் (GitHub, Slack, Linear, Notion, npm, Postman, Discord), கட்டண விசைகள் (Stripe, Square), கிளவுட் விசைகள் (AWS அணுகல் விசை, Twilio, SendGrid, Mailgun), தனிப்பட்ட விசைகள் / JWTகள், சான்றளிப்பு கொண்ட இணைப்பு சரங்கள் (`mongodb://user:pass@...`, முதலியன), மற்றும் ஒரு பொதுவான `Authorization`/`x-api-key`/`api-key`/`apikey` ஹெட்டர்-மதிப்பு வடிவத்தை உள்ளடக்கியது. ஹெட்டர் வடிவ விசைகள் (`authorization`, `x-api-key`, `api-key`, `apikey`) பொதுவான உரை ரெஜெக்ஸ் வழியாக அல்லாமல், கட்டமைப்பு ரீதியாக (மதிப்பு மட்டுமே, `Bearer `/`Basic ` போன்ற ஸ்கீம் முன்னொட்டு பாதுகாக்கப்படும்) நீக்கப்படுகின்றன.
- கார்ட்ரெயில் ஒருபோதும் தடுக்காது; அது மறுஎழுதுகிறது (`modifiedPayload` /
  `modifiedResponse`) மற்றும் குறிப்புரைக்கிறது (`meta.credentialsRedacted`, `meta.count`).

பின்னடைவு கார்ட்: `tests/unit/credential-masker-guardrail.test.ts`.

## அடிப்படை ஒப்பந்தம் (`base.ts`)

```typescript
class BaseGuardrail {
  enabled: boolean;
  name: string;
  priority: number;

  constructor(name: string, options?: { enabled?: boolean; priority?: number });

  async preCall(payload: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;

  async postCall(response: unknown, context: GuardrailContext): Promise<GuardrailResult | void>;
}

interface GuardrailResult<TValue = unknown> {
  block?: boolean; // true சங்கிலியை உடனடியாக நிறுத்துகிறது
  message?: string; // தடுக்கும்போது வெளிப்படுத்தப்படும்
  meta?: Record<string, unknown> | null;
  modifiedPayload?: TValue; // கோரிக்கையை மாற்றியமைக்க preCall மூலம் திருப்பி அனுப்பப்படும்
  modifiedResponse?: TValue; // பதிலை மாற்றியமைக்க postCall மூலம் திருப்பி அனுப்பப்படும்
}

interface GuardrailContext {
  apiKeyInfo?: Record<string, unknown> | null;
  disabledGuardrails?: string[] | null;
  endpoint?: string | null;
  headers?: Headers | Record<string, unknown> | null;
  log?: GuardrailLog | Console | null;
  method?: string | null;
  model?: string | null;
  provider?: string | null;
  signal?: AbortSignal;
  sourceFormat?: string | null;
  stream?: boolean;
  targetFormat?: string | null;
}
```

ஒரு guardrail, `void`, `{}`, அல்லது `{ block: false }` ஆகியவற்றில் ஒன்றைத் திருப்பி அனுப்புவதன் மூலம் "மாற்றம் இல்லை" என்பதைக் குறிக்கிறது. `modifiedPayload`/`modifiedResponse`-ஐத் திருப்பி அனுப்புவது, அடுத்தடுத்த guardrail-களுக்குச் சங்கிலி வழியாகச் செல்லும் மதிப்பை மாற்றுகிறது.
`signal?: AbortSignal`, அழைப்பவரின் வாழ்க்கைச் சுழற்சியை guardrail-களுக்குக் கொண்டு செல்கிறது. ஒரு கோரிக்கை கைவிடப்படுவது திட்டமிட்ட fail-open விதிவிலக்காகும்: இலக்கு மூல ஊடகத்தை ஆதரிக்காது என்று அறியப்பட்டிருந்தால், media bridge-கள் அதை மீட்டமைக்காமல் பணியை நிறுத்தி சுத்தப்படுத்துகின்றன.

## பதிவகம் (`registry.ts`)

singleton `guardrailRegistry` பின்வருவனவற்றை வெளிப்படுத்துகிறது:

- `register(guardrail)` — ஒரு guardrail-ஐச் சேர்க்கிறது (அல்லது இயல்பாக்கப்பட்ட பெயரின் அடிப்படையில் மாற்றுகிறது) மற்றும் ஏறுவரிசை `priority` அடிப்படையில் மீண்டும் வரிசைப்படுத்துகிறது.
- `clear()` / `list()` — நிர்வாக உதவிச் செயல்பாடுகள்.
- `runPreCallHooks(payload, context)` — செயலில் உள்ள guardrail-களை வரிசையாகச் செயல்படுத்தி, `modifiedPayload` வழியாக payload-ஐ அனுப்பி, முதல் `block: true`-இல் நிறுத்துகிறது.
- `runPostCallHooks(response, context)` — பதில் பக்கத்தில் அதே செயலோட்டத்தைப் பயன்படுத்துகிறது.
- `resetGuardrailsForTests({ registerDefaults })` — நிலையை அழித்து, சுத்தமான சோதனைத் தனிமைப்படுத்தலுக்காக விருப்பப்பட்டால் இயல்புநிலைகளை மீண்டும் பதிவு செய்கிறது.

இரண்டு இயக்கிகளும் `{ blocked, payload|response, results, guardrail?, message? }`-ஐத் திருப்பி அனுப்புகின்றன; இதில் `results` என்பது ஒவ்வொரு guardrail-க்கும் உரிய `blocked`, `skipped`, `modified`, `error`, மற்றும் `meta` புலங்களை உள்ளடக்கிய `GuardrailExecutionResult` பதிவுகளின் வரிசையாகும்; இது தடமறிதலுக்குப் பயனுள்ளதாக இருக்கும்.

### ஒவ்வொரு கோரிக்கைக்கும் Guardrail-களை முடக்குதல்

`resolveDisabledGuardrails({ apiKeyInfo, body, headers })`, தற்போதைய கோரிக்கைக்குத் தவிர்க்கப்பட வேண்டிய guardrail பெயர்களின் நகல் நீக்கப்பட்ட பட்டியலைத் தொகுக்கிறது. மூலங்கள் (அனைத்தும் விருப்பமானவை, அனைத்தும் ஒன்றிணைக்கப்படும்):

- `apiKeyInfo.disabledGuardrails`
- கோரிக்கை body-யின் `disabledGuardrails` (மேல்நிலை)
- கோரிக்கை body-யின் `metadata.disabledGuardrails`
- Header `x-omniroute-disabled-guardrails` (அல்லது பழைய
  `x-disabled-guardrails`)

மதிப்புகள் string-களின் array-களாகவோ அல்லது காற்புள்ளியால் பிரிக்கப்பட்ட string ஆகவோ இருக்கலாம்; பெயர்கள் lowercase kebab-case-க்கு இயல்பாக்கப்படுகின்றன (`pii_masker` → `pii-masker`). முடிவு `context.disabledGuardrails` வழியாகப் பதிவகத்திற்கு அனுப்பப்படுகிறது; அது பொருந்தும் guardrail-களைத் தவிர்க்கிறது (`results`-இல் `skipped: true`).

## செயல்படுத்தும் வரிசை

`src/sse/handlers/chat.ts` மற்றும்
`open-sse/handlers/chatCore.ts` வழியாகச் செல்லும் ஒவ்வொரு கோரிக்கைக்கும்:

1. `resolveDisabledGuardrails(...)` ஆனது API விசை, உடல் மற்றும் தலைப்புகளிலிருந்து தவிர்ப்புப் பட்டியலை உருவாக்குகிறது.
2. `guardrailRegistry.runPreCallHooks(body, ctx)` ஆனது முன்னுரிமையின் ஏறுவரிசையில் பாதுகாப்புக் கட்டுப்பாடுகளை இயக்குகிறது:
   - முடக்கப்பட்ட பாதுகாப்புக் கட்டுப்பாடுகள் `skipped` எனப் பதிவு செய்யப்படுகின்றன.
   - ஒவ்வொரு பாதுகாப்புக் கட்டுப்பாட்டின் `preCall` ஆனதும் `modifiedPayload` மூலம் தரவுச்சுமையை மாற்றி எழுதலாம்.
   - முதலில் வரும் `block: true`, சங்கிலியின் செயல்பாட்டை உடனடியாக நிறுத்துகிறது; மேலும் கையாளுநர் பாதுகாப்புக் கட்டுப்பாட்டு நிராகரிப்புப் பதிலை வழங்குகிறார்.
3. மாற்றி எழுதப்பட்டிருக்கக்கூடிய தரவுச்சுமை, கூட்டு வழிப்படுத்தல் மற்றும் அப்ஸ்ட்ரீம் அனுப்புதலுக்குள் செல்கிறது.
4. பதில் உருவாக்கப்பட்ட பிறகு, `guardrailRegistry.runPostCallHooks(...)` ஆனது பதிலின் மீது அதே சங்கிலியை இயக்குகிறது. இங்கு `block: true` என்பது அப்ஸ்ட்ரீம் பதிலைக் கைவிடுகிறது.

விதிவிலக்கை எறியும் பாதுகாப்புக் கட்டுப்பாடுகள் `error: <message>` என்பதுடன் பதிவு செய்யப்பட்டு, `logger.warn` மூலம் பதிவேட்டில் எழுதப்படுகின்றன; ஆனால் சங்கிலி தொடர்ந்து இயங்கும் — இது வடிவமைப்பிலேயே தடையின்றித் தொடரும் அணுகுமுறையாகும்.

## உள்ளமைவு

உள்ளமைக்கப்பட்ட பாதுகாப்புக் கட்டுப்பாடுகள் படிக்கும் சூழல் மாறிகள்:

| மாறி                                  | பயன்படுத்துவது               | விளைவு                                                                                                         |
| ------------------------------------- | ---------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `INPUT_SANITIZER_ENABLED`             | `prompt-injection`           | கண்டறிதலை முழுமையாக முடக்க `false` என அமைக்கவும்.                                                              |
| `INPUT_SANITIZER_MODE`                | `prompt-injection`           | உட்செலுத்தல் கொள்கை: `warn`, `block`, அல்லது `log`. பழைய மதிப்பான `redact`, உட்செலுத்தல் உரையை மாற்றி எழுதாது. |
| `INJECTION_GUARD_MODE`                | `prompt-injection`           | உட்செலுத்தல் பாதுகாப்பிற்கான பயன்முறை; இது env vars-ஐ **மேலெழுதும்** DB அம்சக் கொடியுமாகும் (DB > ENV).        |
| `INPUT_SANITIZER_BLOCK_THRESHOLD`     | `prompt-injection`           | `MODE=block` நிராகரிக்கும் குறைந்தபட்ச தீவிரம்: `high` (இயல்புநிலை), `medium`, அல்லது `low`.                   |
| `INJECTION_GUARD_BLOCK_THRESHOLD`     | `prompt-injection`           | `INPUT_SANITIZER_BLOCK_THRESHOLD` என்பதற்கான பழைய மாற்றுப் பெயர்.                                              |
| `PII_REDACTION_ENABLED`               | `pii-masker`                 | `true` ஆக இருக்கும்போது, கோரிக்கையிலுள்ள PII மறைக்கப்படுகிறது (உட்செலுத்தல் பயன்முறையைச் சாராதது).             |
| `PII_RESPONSE_SANITIZATION` / `_MODE` | `pii-masker` (டவுன்ஸ்ட்ரீம்) | பதில்-பக்க மறைப்பானின் நடத்தையைக் கட்டுப்படுத்துகிறது.                                                         |

Modality Bridge பாதுகாப்புக் கட்டுப்பாடுகள் env vars-இலிருந்து அல்லாமல், DB ஆதரவுள்ள அமைப்புக் களஞ்சியத்திலிருந்து (`getSettings()`) இயக்கநேர உள்ளமைவைப் படிக்கின்றன. Vision-இன் முதன்மை விசைகள்
`modalityBridgeVisionEnabled`, `modalityBridgeVisionMode`,
`modalityBridgeVisionModel`, `modalityBridgeVisionTaskAware`,
`modalityBridgeVisionPrompt`, `modalityBridgeVisionTimeout`,
`modalityBridgeVisionMaxImages`, `modalityBridgeVisionMaxChars`,
`modalityBridgeCacheEnabled`, `modalityBridgeCacheTtlMinutes`, மற்றும்
`modalityBridgeCacheMaxEntries` ஆகும். பழைய
`visionBridge*` விசைகள், ஆவணப்படுத்தப்பட்ட ஒரு-சுழற்சி வாசிப்பு மாற்றுவழியாக மட்டுமே ஏற்கப்படுகின்றன; டாஷ்போர்டு எழுதல்கள் முதன்மை விசைகளைப் பயன்படுத்துகின்றன. இயல்புநிலைகளும் மாற்றுவழித் தீர்மானிப்பானும் `src/shared/constants/modalityBridgeDefaults.ts` இல் உள்ளன; பழைய மாறிலிகள் `src/shared/constants/visionBridgeDefaults.ts` இல் தொடர்ந்து வைக்கப்பட்டுள்ளன.

Audio ஆனது `modalityBridgeAudioEnabled`, `modalityBridgeAudioModel`,
`modalityBridgeAudioTimeout`, மற்றும் `modalityBridgeAudioMaxClips` ஆகியவற்றையும், பகிரப்பட்ட

Video ஆனது `modalityBridgeVideoEnabled`, `modalityBridgeVideoAnalysisMode`,
`modalityBridgeVideoModel`,
`modalityBridgeVideoFrameCount`, `modalityBridgeVideoSamplingPolicy`,
`modalityBridgeVideoMaxVideos`, மற்றும்
`modalityBridgeVideoTimeout` ஆகியவற்றையும், பகிரப்பட்ட `modalityBridgeCache*` அமைப்புகளையும் பயன்படுத்துகிறது.
FFmpeg/ffprobe ஆகியவை விருப்பத் தேர்வுக்குரிய செயல்பாட்டுச் சார்புகள் என்பதாலும், சட்டகத் தலைப்பிடல் தாமதத்தையும் மாதிரிச் செலவையும் அதிகரிப்பதாலும், இது இயல்புநிலையில் முடக்கப்பட்டுள்ளது.

## தனிப்பயன் பாதுகாப்புத் தடுப்புகள்

```typescript
import { BaseGuardrail, guardrailRegistry } from "@/lib/guardrails";

class BudgetGuardrail extends BaseGuardrail {
  constructor() {
    super("budget", { priority: 50 });
  }

  async preCall(payload, ctx) {
    if (ctx.apiKeyInfo?.budgetExceeded) {
      return { block: true, message: "Daily budget exceeded" };
    }
    return { block: false };
  }
}

guardrailRegistry.register(new BudgetGuardrail());
```

படிகள்:

1. `BaseGuardrail`-ஐ நீட்டித்து `src/lib/guardrails/myGuardrail.ts`-ஐ உருவாக்கவும்.
2. `preCall` மற்றும்/அல்லது `postCall`-ஐச் செயல்படுத்தவும்.
3. இறக்குமதி செய்யும் நேரத்தில் பதிவுசெய்யவும் (`registerDefaultGuardrails`-இலிருந்து சேர்க்கவும்) அல்லது
   இயக்க நேரத்தில் `guardrailRegistry.register(...)`-ஐ அழைக்கவும் — அதே இயல்பாக்கப்பட்ட பெயரைக்
   கொண்ட முந்தைய பாதுகாப்புத் தடுப்பை பதிவகம் மாற்றிவிடும்.
4. `tests/unit/`-இன் கீழ் சோதனைகளைச் சேர்க்கவும் (தற்போதுள்ள எடுத்துக்காட்டுகள்:
   `tests/unit/guardrails-registry.test.ts`,
   `tests/unit/prompt-injection-guard.test.ts`,
   `tests/unit/guardrails/visionBridge.test.ts`).

## சோதனை

அறியப்பட்ட நிலையிலிருந்து தொடங்க, சோதனைகளுக்கு இடையே `resetGuardrailsForTests()`-ஐப் பயன்படுத்தவும்.
காலியான பதிவகத்துடன் தொடங்கி, சோதனையின் கீழுள்ள பாதுகாப்புத் தடுப்புகளை மட்டும்
பதிவுசெய்ய `{ registerDefaults: false }`-ஐ அனுப்பவும். Vision Bridge சார்பு
உட்செலுத்தலை (`deps.getSettings`, `deps.callVisionModel`) ஏற்கிறது; Audio Bridge,
அமைப்புகள், திறன்கள், STT மாதிரித் தேர்வு, நற்சான்றுச் சோதனைகள் மற்றும் படியெடுத்தல்
ஆகியவற்றுக்கான இணையான உட்புகும் புள்ளிகளை வழங்குகிறது. எனவே, சோதனைகள் DB அல்லது
பிணைய அணுகல் இல்லாமலேயே இரு ஓட்டங்களையும் பரிசோதிக்க முடியும்.

## Injection-guard வழித்தட உள்ளடக்கம் & red-team (கட்டம் 8 · தொகுதி D)

பயனர் prompts-ஐ ஏற்கும் அனைத்து வழித்தடங்களையும் injection-guard (`createInjectionGuard` / `withInjectionGuard`) உள்ளடக்குகிறது.
இது `INJECTION_GUARD_MODE`-ஐ மதிக்கிறது (இயல்புநிலை `warn` = பதிவு மட்டும்;
`block` = HTTP 400 `SECURITY_001`-ஐத் திருப்பியனுப்பும்).

| வகை                  | வழித்தடங்கள்                                                                                                                                         | இயல்புநிலை பயன்முறை |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| உரை (தற்போதுள்ளது)   | `/v1/chat/completions`, `/v1/completions`, `/v1/relay/chat/completions`                                                                              | warn                |
| உருவாக்கம் சார்ந்தது | `/v1/messages`, `/v1/responses`, `/v1/images/generations`, `/v1/images/edits`, `/v1/videos/generations`, `/v1/music/generations`, `/v1/audio/speech` | warn                |
| தரவு                 | `/v1/embeddings`, `/v1/rerank`, `/v1/search`, `/v1/moderations`                                                                                      | warn                |

உரைப் பிரித்தெடுத்தல் (`extractMessageContents`) `messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ஆகியவற்றை உள்ளடக்குகிறது.

**Red-team (இரவுதோறும், `nightly-llm-security.yml`):** `INJECTION_GUARD_MODE=block` நிலையில் ஒவ்வொரு வழித்தடமும்
OWASP-LLM corpus-ஐத் தடுக்கிறது என்பதை promptfoo சரிபார்க்கிறது; garak சோதனைத் தேடல்களை இயக்குகிறது (ரகசியம் இல்லாவிட்டால் தவிர்க்கும்).
ஒருமைத்தன்மைக்காக `moderations` சேர்க்கப்பட்டுள்ளது — block-mode-இல் உள்ள இயக்குநர்கள்
`resolveDisabledGuardrails` வழியாக இதற்கு விலக்கு அளிக்கலாம்.

இரவுநேர பணிப்பாய்வு (`.github/workflows/nightly-llm-security.yml`, cron + கைமுறை
dispatch) இரண்டு பணிகளைக் கொண்டுள்ளது:

- **`promptfoo-guard` (தடுக்கும்)** — `INJECTION_GUARD_MODE=block` உடன்
  `promptfoo eval -c promptfooconfig.yaml`-ஐ இயக்குகிறது. ஒவ்வொரு எதிர்மறைச் சோதனை நிலையும்
  (எ.கா. "முந்தைய அனைத்து அறிவுறுத்தல்களையும் புறக்கணிக்கவும்…", DAN-பாணி jailbreaks), பதிலில்
  `error.code === "SECURITY_001"` இருப்பதை உறுதிசெய்கிறது; அதாவது, பாதுகாப்புத் தடுப்பு உண்மையிலேயே கோரிக்கையை நிராகரித்தது.
- **`garak` (ஆலோசனை சார்ந்தது)** — உள்ளக OmniRoute instance-க்கு
  (`http://localhost:20128/v1`) எதிராக garak `--probes promptinject,dan,leakreplay`-ஐ இயக்குகிறது.
  இது வழங்குநர் ரகசியத்தை (`PROMPTFOO_PROVIDER_KEY`) சார்ந்தது; ரகசியம் இல்லாவிட்டால்
  சீராகத் தவிர்க்கப்பட்டு `|| true` பின்னொட்டுடன் இயக்கப்படும், எனவே CI-ஐத் தோல்வியடையச் செய்யாமல் அறிக்கையிடும்.

பாதுகாப்புத் தடுப்பு உதவிக்கருவியின் (`createInjectionGuard` / `withInjectionGuard`)
உள்ளடக்கம் prompt கொண்ட ஒவ்வொரு `/v1` வழித்தடத்தையும் உள்ளடக்குகிறது; prompt உரை
`src/shared/utils/inputSanitizer.ts`-இல் உள்ள `extractMessageContents()` மூலம்
`messages`/`input`/`prompt`/`query`+`documents`/`instructions`/`system` ஆகியவற்றிலிருந்து பெறப்படுகிறது.
