இந்த ஆவணம், `omniroute@3.8.5`-க்கு எதிராக எழுப்பப்பட்ட ஆறு
`AI-detected potential malware` கண்டுபிடிப்புகளுக்கும், `omniroute@3.8.6`-இல்
செயல்படுத்தப்பட்ட தணிப்பு நடவடிக்கைகளுக்கும் பராமரிப்பாளர் எழுதிய சான்றுறுதியாகும். இதன் நோக்கங்கள்:

1. கண்டுபிடிப்புகளை உண்மையான மூலக் குறியீட்டுடன் ஒப்பிட்டு மதிப்பிட வேண்டியபோது,
   பாதுகாப்பு பைப்லைன் இயக்குநர்கள் மேற்கோள் காட்டுவதற்கு ஒரே ஆதாரம் இருப்பது.
2. கொடியிடப்பட்ட ஒவ்வொரு பாதையும் திட்டமிடப்பட்டது, விருப்பத் தேர்வுக்குரியது மற்றும்
   ஆவணப்படுத்தப்பட்டது என்ற பராமரிப்பாளர் கையொப்பமிட்ட உறுதிப்பாட்டை எதிர்கால AI
   ஸ்கேனர்கள் கண்டறிய முடிவது.
3. ஒவ்வொரு அழைப்புத் தளமும் _ஏன்_ அந்த வடிவில் அமைக்கப்பட்டுள்ளது என்பதற்கான எழுத்துப்பூர்வப் பதிவு நம்மிடம் இருப்பது —
   இதனால், வேண்டுமென்றே அகற்றப்பட்ட ஒரு அடையாள வடிவத்தை எதிர்கால மறுகட்டமைப்பு
   தற்செயலாக மீண்டும் அறிமுகப்படுத்தாது.

v3.8.6 தணிப்பு நடவடிக்கைகள் வெளியிடப்பட்ட பிறகும், கீழேயுள்ள அழைப்புத் தளங்களில்
ஏதேனும் ஒன்றை மீண்டும் கொடியிடும் ஸ்கேனரை நீங்கள் இயக்கினால், ஸ்கேன் தடத்துடன்
ஒரு issue-ஐத் திறக்கவும்; அதற்கேற்ப இங்குள்ள சான்றுறுதியை நாங்கள் விரிவுபடுத்துவோம்.

## §1 — MITM மூல-CA நிறுவல் (`77484.js`)

**மூலக் கோப்புகள்**:

- `src/mitm/cert/install.ts` — பொது `installCert()` / `uninstallCert()`,
  இயங்குதளம் சார்ந்த `installCertWindows/Mac/Linux`.
- `src/mitm/systemCommands.ts` — நிறுவல் பாதைகள் பயன்படுத்தும் பகிரப்பட்ட `execFile` / `spawn` / PowerShell
  உதவிச் செயல்பாடுகள்.

**தூண்டுதல்**: பயனர் உள்ளூர் டாஷ்போர்டில்
`/dashboard/cli-tools/mitm` என்பதில் "MITM ப்ராக்ஸியை இயக்கு" என்பதைக் கிளிக் செய்கிறார். இந்த route, loopback-க்கு மட்டுமே உரியது — `CLAUDE.md`-இல் உள்ள கடுமையான விதி #17 மற்றும்
`src/server/authz/routeGuard.ts::isLocalOnlyPath()` ஆகியவற்றைப் பார்க்கவும். ஒரு tunnel மூலம் வெளிப்பட்ட
JWT-ஆல் இந்தக் குறியீட்டுப் பாதையைத் தூண்ட **முடியாது**.

**செயல்படுத்தப்படும் சிறப்புரிமை பெற்ற செயல்பாடுகள் (இயங்குதளம் வாரியாக)**:

| இயங்குதளம்             | கட்டளை(கள்)                                                                                                       |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | UAC வழியாக `certutil -addstore Root <cert>`                                                                       |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | ஒவ்வொரு profile-க்கும் `certutil -d sql:<profile>` வழியாக NSS DB புதுப்பிப்பு                                     |

இவை `mitmproxy`, Charles Proxy, Fiddler மற்றும்
Caddy பயன்படுத்தும் அதே கட்டளைகள். OmniRoute-இல் இவை இடம்பெற்றிருப்பது
`docs/security/STEALTH_GUIDE.md`-இல் ஆவணப்படுத்தப்பட்டுள்ளது.

**v3.8.6 தணிப்பு**:

- `runElevatedPowerShell()` இனி `-EncodedCommand <base64utf16le>`-ஐப் பயன்படுத்துவதில்லை.
  உயர்த்தப்பட்ட payload, ஒவ்வொரு அழைப்பிற்குமான தற்காலிக `.ps1` கோப்பில் (mode 0o600,
  ஒரு தனிப்பட்ட `mkdtempSync` கோப்பகத்திற்குள்) எழுதப்பட்டு, `-File` வழியாகக் குறிப்பிடப்படுகிறது. அந்தக்
  கோப்பு `finally`-இல் இணைப்புநீக்கம் செய்யப்படுகிறது. இது Socket.dev-இன் AI
  classifier கொடியிட்ட, PowerShell வழியான base64-உயர்த்தலின் வழக்கமான
  அடையாள வடிவத்தை அகற்றுகிறது.
- `installCertWindows`, இங்கு சுட்டிக்காட்டும் ஒரு inline `SECURITY-AUDITOR-NOTE:` தொகுதியைக்
  கொண்டுள்ளது.

**இதை ஏன் வைத்திருக்கிறோம்**: MITM ப்ராக்ஸி என்பது
`docs/security/STEALTH_GUIDE.md` மற்றும் `docs/frameworks/MITM-PROXY.md` ஆகியவற்றால் பயன்படுத்தப்படும் ஆவணப்படுத்தப்பட்ட அம்சமாகும். இதை அகற்றுவது
agent-bridge அம்சத் தொகுப்பைச் செயலிழக்கச் செய்யும்.

## §2 — Zed நற்சான்றிதழ் இறக்குமதி (`app/api/providers/zed/import/route.js`)

**மூலக் கோப்புகள்**:

- `src/app/api/providers/zed/discover/route.ts` _(v3.8.6-இல் புதிதாகச் சேர்க்கப்பட்டது)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(v3.8.6-இல் புதிதாகச் சேர்க்கப்பட்டது)_

**தூண்டுதல்**: உள்ளூர் டாஷ்போர்டின் Providers பக்கத்தில் பயனர் "Zed-இலிருந்து இறக்குமதி செய்" என்பதைக் கிளிக் செய்கிறார். இந்த முனைப்புள்ளி `requireManagementAuth` மூலம் கட்டுப்படுத்தப்படுகிறது. Zed எடிட்டரே தனது வழங்குநர் API விசைகளை, ஆவணப்படுத்தப்பட்ட சேவைப் பெயர்களின் கீழ் OS சாவிக்கொத்தில் எழுதுகிறது — https://zed.dev/docs/ai/llm-providers என்பதைப் பார்க்கவும்.

**v3.8.5 நடத்தை (Socket.dev சுட்டிக்காட்டியது)**:

`POST /import` நற்சான்றிதழ்களைக் கண்டறிந்து, ஒரே சுற்றுப் பயணத்தில் அவற்றை உள்ளூர் SQLite சேமிப்பகத்தில் தானாகச் சேமித்தது. ஒவ்வொரு கணக்கிற்குமான உறுதிப்படுத்தலும் இல்லை, கைரேகையும் இல்லை; "N டோக்கன்கள் கண்டறியப்பட்டன, அனைத்தும் இறக்குமதி செய்யப்பட்டன" என்பது மட்டுமே.

**v3.8.6 தணிப்பு — 2-படி உறுதிப்படுத்தல்**:

1. **`POST /api/providers/zed/discover`**
   `{ candidates: [{ provider, service, account, fingerprint }] }` என்பதைத் திருப்பி அனுப்புகிறது. மூல
   டோக்கன் **ஒருபோதும்** அனுப்பப்படுவதில்லை. கைரேகை
   `sha256(service|account|token).slice(0,16)` ஆகும்.
2. டாஷ்போர்டு தேர்வுநர்களின் பட்டியலைக் காட்டுகிறது; எந்தவற்றை இறக்குமதி செய்ய வேண்டும் என்பதை இயக்குநர் தேர்ந்தெடுத்து,
   `{ confirmedAccounts: [{ service, account, fingerprint }] }` என்பதை
   **`POST /api/providers/zed/import`**-க்கு அனுப்புகிறார்.
3. இறக்குமதி முனைப்புள்ளி **சேவையகத்தில் சாவிக்கொத்தை மீண்டும் வாசித்து**, அதன் பின்னர்
   `(service, account, fingerprint)` அடிப்படையில் வடிகட்டுகிறது. மாற்றப்பட்ட அல்லது மீண்டும் இயக்கப்பட்ட discover
   பதிலால், தொடர்பில்லாத ஒரு டோக்கனைச் சேமிக்குமாறு import முனைப்புள்ளியை ஏமாற்ற முடியாது —
   discover-க்குப் பிறகு நேரடி டோக்கன் மாறியிருந்தால், கைரேகை இனி பொருந்தாது;
   எனவே அந்த நற்சான்றிதழ் தவிர்க்கப்படும்.

தங்கள் தன்னியக்கத்தை இன்னும் புதுப்பிக்காத இயக்குநர்களுக்காக, `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` சூழல் கொடி v3.8.5 நடத்தையைத் தக்கவைக்கிறது. இது v3.9-இல் அகற்றப்படும்.

**இதை ஏன் தக்கவைத்துள்ளோம்**: ஏற்கனவே Zed-ஐப் பயன்படுத்தி, வழங்குநர் விசைகளை மீண்டும் ஒட்டாமல் OmniRoute-க்குப் பிரதியெடுக்க விரும்பும் பயனர்களுக்கு Zed இறக்குமதியே மிகவும் எளிமையான தொடக்கப் பாதையாகும்.

## §3 — `execFile` / `spawn` / உயர்த்தப்பட்ட PowerShell (`21843.js`)

**மூலக் கோப்புகள்**: `src/mitm/systemCommands.ts`.

**சுட்டிக்காட்டப்பட்டதற்கான காரணம்**: இந்தத் துண்டு `execFileWithPassword`,
`runElevatedPowerShell`, மற்றும் பகிரப்பட்ட `quotePowerShell` உதவிச்செயல்பாட்டை மீண்டும் ஏற்றுமதி செய்கிறது. Socket.dev-இன் AI வகைப்படுத்தி இவற்றைப் பொதுவான "ஹோஸ்ட் இயக்கம் + சிறப்புரிமை உயர்த்தல் கருவித்தொகுப்பு" எனக் கருதுகிறது. OmniRoute-க்குள், இவை MITM சான்றிதழ் நிறுவல் பாதையாலும் (§1), `sudo` கட்டளையை இயக்குவதற்கான `execFileWithPassword`-ஆலும் மட்டுமே பயன்படுத்தப்படுகின்றன.

**v3.8.6 தணிப்பு**:

- `runElevatedPowerShell` மறுசீரமைப்பு (§1-ஐப் பார்க்கவும்).
- `runElevatedPowerShell` மற்றும் `execFileWithPassword` ஆகிய இரண்டிலும் உள்ளமைக்கப்பட்டுள்ள `SECURITY-AUDITOR-NOTE:` தொகுதி, அனுமதிப்பட்டியலில் உள்ள அழைப்பாளர்களையும் நிலைநிறுத்தப்பட்ட இயக்கக்கூடிய கோப்புகளின் பட்டியலையும் ஆவணப்படுத்துகிறது.
- `execFileWithPassword`-இன் `spawn()` அழைப்பு, இந்த உதவிச்செயல்பாடு பெற அனுமதிக்கப்பட்டுள்ள இயக்கக்கூடிய கோப்புகளின் அனுமதிப்பட்டியலுடன் ஒரு `nosemgrep` குறிப்பைக் கொண்டுள்ளது — பயனர் உள்ளீட்டிலிருந்து `finalCommand`/`finalArgs`-க்குச் செல்லும் **பாதை எதுவும் இல்லை**.

## §4 / §6 — 9router சேவை மேற்பார்வையாளர் (`api/services/9router/{start,restart}/route.js`)

**மூலக் கோப்புகள்**:

- `src/app/api/services/9router/_lib.ts` — மேற்பார்வையாளர் தொழிற்சாலை.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — பொதுவான spawn / ஆரோக்கிய நிலை வாக்கெடுப்பு / பதிவேடு இடையகம்.

**தூண்டுதல்**: உள்ளூர் டாஷ்போர்டிலுள்ள உட்பொதிக்கப்பட்ட சேவைகள் பக்கத்தில் பயனர் "Install" / "Start" என்பதைக் கிளிக் செய்கிறார்.

**ஏற்கனவே நடைமுறையிலுள்ள பாதுகாப்புகள்**:

- `src/server/authz/routeGuard.ts`-இன்படி (கடுமையான விதி #17), அனைத்து `/api/services/*` வழித்தடங்களும் LOCAL_ONLY ஆகும். எந்த அங்கீகாரச் சரிபார்ப்புக்கும் முன்பே loopback அமலாக்கம் நடைபெறுகிறது — கசிந்த JWT மூலமாகவும் அவற்றை அணுக முடியாது.
- 9router DB வரிசை `status='not_installed', auto_start=0` எனத் தொடக்கத் தரவுடன் உருவாக்கப்படுகிறது (`src/lib/db/migrations/071_services.sql:19`-ஐப் பார்க்கவும்). முதல் தொடக்கத்தில் சேவை **தொடங்காது**.
- `src/lib/services/installers/ninerouter.ts`-இல் உள்ள `resolveSpawnArgs(apiKey, PORT)` திருப்பியளிக்கும் பைனரி பாதையுடன் `spawn()` அழைக்கப்படுகிறது; இது ஆதரிக்கப்படும் பைனரிகளின் நிலையான அனுமதிப்பட்டியலாகும்.
- Stdout/stderr நினைவகத்தில் இடையகப்படுத்தப்படுகிறது (5 MB வரம்பு, `_lib.ts`-ஐப் பார்க்கவும்) — டாஷ்போர்டிலிருந்து பயனர் பதிவேட்டைப் பதிவு செய்வதை இயக்காவிட்டால் வட்டில் எழுதப்படாது.

**v3.8.6 தணிப்பு**: செயல்பாட்டு மாற்றம் எதுவுமில்லை. சிறப்புரிமை பெற்ற பாதைகளைத் தொகுப்பிலிருந்து முற்றிலும் அகற்ற விரும்பும் பயனர்களுக்காக, குறைந்தபட்ச உருவாக்கச் சுயவிவரம் (`OMNIROUTE_BUILD_PROFILE=minimal`) `src/lib/services/installers/ninerouter.ts`-ஐ ஒரு போலிச் செயலாக்கத்தால் மாற்றுகிறது.

**இதை ஏன் தக்கவைத்துள்ளோம்**: 9router என்பது விருப்பத்தேர்வாக உள்ளூரில் நிறுவக்கூடிய ஒரு துணைச் சேவை (WordPress-பாணியிலான செருகுநிரலைப் போன்றது) — கடுமையான வெளிப்படையான ஒப்புதல் தேவை.

## §5 — OmniRoute Cloud Sync நற்சான்று மீளெழுதுதல் (`api/keys/[id]/route.js`)

**மூலக் கோப்புகள்**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — `syncKeysToCloudIfEnabled()`-ஐ அழைக்கிறது.

**தூண்டுதல்**: `isCloudEnabled()` ஆனது `true`-ஐத் திருப்பியளிக்கிறது (டாஷ்போர்டிலிருந்து அமைக்கப்பட்டது) **மற்றும்**
`CLOUD_URL` உள்ளமைக்கப்பட்டுள்ளது. இரண்டும் முடக்கப்பட்டிருக்கும்போது, Cloud முனைப்புள்ளிக்குச்
செல்லும் வெளிப்புற நெட்வொர்க் அழைப்பு எதுவும் மேற்கொள்ளப்படாது.

**v3.8.5 நடத்தை (Socket.dev சரியான முறையில் கண்டறிந்த பிழை)**:

`cloudUpdatedAt > localUpdatedAt` ஆக இருக்கும்போது, Cloud பதிலிலிருந்து
`accessToken`, `refreshToken`, மற்றும் `providerSpecificData` ஆகியவற்றை
`updateLocalTokens()` மேலெழுதியது. HMAC இல்லை, கையொப்பம் இல்லை, checksum இல்லை.
தவறாக உள்ளமைக்கப்பட்ட அல்லது தீங்கிழைக்கும் `CLOUD_URL` (அல்லது சேனலில் உள்ள MITM)
வழங்குநரின் OAuth டோக்கன்களை எச்சரிக்கையின்றி மாற்றக்கூடும்.

**v3.8.6 தணிப்பு**:

1. **HMAC சரிபார்ப்பு**: JSON-ஐப் பாகுபடுத்துவதற்கு முன் `X-Cloud-Sig`
   தலைப்பை (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) `verifyCloudSignature(rawBody, sigHeader)` சரிபார்க்கிறது.
   இரகசியம் அமைக்கப்பட்டிருந்தால், கையொப்பம் கட்டாயம். இல்லையெனில் (மரபு முறை),
   ஓர் எச்சரிக்கை பதிவுசெய்யப்பட்டு பதில் ஏற்றுக்கொள்ளப்படும் — v3.9 முதல்
   இரகசியம் கட்டாயமாக்கப்படும்.
2. **இரகசியப் புலங்களுக்கான வெளிப்படையான ஒப்புதல்**: `accessToken` / `refreshToken` /
   `providerSpecificData` ஆகியவை `OMNIROUTE_CLOUD_SYNC_SECRETS=true` ஆக
   இருக்கும்போது **மட்டுமே** மேலெழுதப்படும். இயல்புநிலை முறையில் நற்சான்று அல்லாத
   மெட்டாடேட்டா (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`) மட்டுமே ஒத்திசைக்கப்படும். தொலைநிலை டோக்கன்
   ஒத்திசைவைச் சார்ந்திருந்த பயனர்களுக்கு இது ஒரு **இணக்கத்தை முறிக்கும் மாற்றம்** —
   அவர்கள் வெளிப்படையாகத் தேர்வுசெய்து இயக்க வேண்டும்.

**இதை ஏன் வைத்திருக்கிறோம்**: OmniRoute Cloud குத்தகைதாரர் குழுவின்
நற்சான்றுகளை மையப்படுத்துவதற்கான ஒரே வழி Cloud Sync ஆகும். இந்தத் திருத்தம் அச்சுறுத்தல்
மாதிரியை நேர்மையானதாக்குகிறது:
"சேவையகம் கையொப்பமிடுகிறது, கிளையன் சரிபார்க்கிறது, இயக்குநர் தேர்வுசெய்து இயக்குகிறார்."

## கட்டுமானச் சுயவிவரம்: `minimal`

Socket-க்கு உகந்த கலைப்பொருள் தேவைப்படும் பயனர்கள், பின்வருமாறு கட்டமைக்கவும்:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

webpack `NormalModuleReplacementPlugin` நான்கு தொகுதிகளை stub-களுக்கு மாற்றுப்பெயரிடுகிறது:

| தொகுதி                                      | Stub                                             |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

ஒவ்வொரு stub-உம் அதே இடைமுகத்தை ஏற்றுமதி செய்கிறது, ஆனால் ஒவ்வொரு செயல்பாடும்
இயக்க நேரத்தில் `featureDisabledError(name)`-ஐ எறிகிறது. முடக்கப்பட்ட தொகுதியைச்
சார்ந்துள்ள வழித்தடங்கள், நுண்ணுணர்வுள்ள குறியீட்டுப் பாதையைச் செயல்படுத்துவதற்குப் பதிலாக
தெளிவான செய்தியுடன் HTTP 503-ஐத் திருப்பியளிக்கின்றன.

இதன் விளைவாக உருவாகும் தொகுப்பு `omniroute-secure` ஆக வெளியிடப்படுவதற்காக
வடிவமைக்கப்பட்டுள்ளது. வெளியீட்டு செய்முறைக்கு `docs/ops/PUBLISHING_SECURE.md`-ஐப் பார்க்கவும்.
