OmniRoute நிர்வாகச் செயல்கள், அங்கீகார நிகழ்வுகள், வழங்குநர் நற்சான்றிதழ் வாழ்க்கைச்சுழற்சி மாற்றங்கள் மற்றும் MCP கருவி அழைப்புகளை SQLite ஆதரவுள்ள தணிக்கை அட்டவணைகளில் பதிவு செய்கிறது. எவை பதிவு செய்யப்படுகின்றன, அவை எங்கே சேமிக்கப்படுகின்றன, எவ்வளவு காலம் தக்கவைக்கப்படுகின்றன, API விசைகள் எவ்வாறு பதிவிலிருந்து விலகலாம் மற்றும் தரவை எவ்வாறு வினவலாம் என்பதை இந்தப் பக்கம் விளக்குகிறது.

செயலாக்கம் `src/lib/compliance/index.ts` (T-43 — "இணக்கக் கட்டுப்பாடுகள்") மற்றும் `src/lib/compliance/providerAudit.ts` ஆகியவற்றில் உள்ளது. தணிக்கை எழுதல்கள் ஒருபோதும் பிழையை எறிவதில்லை: தணிக்கைப் பதிவு முதன்மைக் கோரிக்கை ஓட்டத்தைப் பாதிக்காமல் இருப்பதற்காக, ஏதேனும் தோல்வி ஏற்பட்டால் அழைப்பு எந்த அறிவிப்புமின்றி புறக்கணிக்கப்படுகிறது.

## என்னென்ன பதிவு செய்யப்படுகின்றன

### நிர்வாகத் தணிக்கை நிகழ்வுகள் (`audit_log`)

`logAuditEvent({ action, actor, target, details, ... })`-க்கான ஒவ்வொரு அழைப்பும் ஒரு வரிசையை உருவாக்குகிறது. செயல் சரங்கள் `domain.verb` (அல்லது `domain.verb.outcome`) வடிவத்தைப் பின்பற்றுகின்றன. மூலக் கட்டமைப்பில் உறுதிப்படுத்தப்பட்டுள்ள செயல் வகைகள்:

| செயல்                                | மூலம்                                   |
| ------------------------------------ | --------------------------------------- |
| `auth.login.success`                 | `src/app/api/auth/login/route.ts`       |
| `auth.login.failed`                  | `src/app/api/auth/login/route.ts`       |
| `auth.login.locked`                  | `src/app/api/auth/login/route.ts`       |
| `auth.login.error`                   | `src/app/api/auth/login/route.ts`       |
| `auth.login.misconfigured`           | `src/app/api/auth/login/route.ts`       |
| `auth.login.setup_required`          | `src/app/api/auth/login/route.ts`       |
| `auth.logout.success`                | `src/app/api/auth/logout/route.ts`      |
| `provider.credentials.created`       | `src/app/api/providers/route.ts`        |
| `provider.credentials.updated`       | `src/app/api/providers/[id]/route.ts`   |
| `provider.credentials.revoked`       | `src/app/api/providers/[id]/route.ts`   |
| `provider.credentials.batch_revoked` | `src/app/api/providers/route.ts`        |
| `sync.token.created`                 | `src/app/api/sync/tokens/route.ts`      |

| `compliance.cleanup`                 | `src/lib/compliance/index.ts`           |

ஒவ்வொரு உள்ளீடும் `action`, `actor` (இயல்புநிலை `"system"`), `target`, `details`/`metadata` (JSON), `ip_address`, `resource_type`, `status`, `request_id` மற்றும் `timestamp` ஆகியவற்றைப் பதிவு செய்கிறது. வரிசை எழுதப்படுவதற்கு முன், உணர்திறன் மிக்க விசைகள் (`apiKey`, `accessToken`, `refreshToken`, `password`, `*token`/`*secret`/`*apikey` ஆகியவற்றுடன் பொருந்தும் அனைத்தும் போன்றவை) சுழல்முறையில் `"[redacted]"` என மறைக்கப்படுகின்றன.

### கோரிக்கை / பயன்பாட்டுப் பதிவுகள்

இவை செயல்பாட்டுத் தொலைஅளவியல் தரவுகள் (கண்டிப்பாக நிர்வாகத் தணிக்கை அல்ல), ஆனால் அதே தக்கவைப்புச் செயல்முறையைப் பகிர்ந்துகொள்கின்றன:

- `usage_history` — ஒவ்வொரு கோரிக்கைக்குமான பயன்பாட்டுத் தொகுப்பு
- `call_logs` — ஒவ்வொரு கோரிக்கைக்குமான முழுப் பதிவு (வரிசை வரம்புக்கு உட்பட்டது; கீழே காண்க)
- `proxy_logs` — பதிலாள் போக்குவரத்துப் பதிவு (வரிசை வரம்புக்கு உட்பட்டது)
- `request_detail_logs` — மரபுவழி விரிவான கோரிக்கைப் பதிவு (இருந்தால் இன்னும் சீரமைக்கப்படும்)

## சேமிப்பகத் திட்டவடிவம்

முதன்முறையாகப் பயன்படுத்தும்போது `ensureAuditLogSchema()` மூலம் `audit_log` தேவைக்கேற்ப உருவாக்கப்படுகிறது:

```sql
CREATE TABLE IF NOT EXISTS audit_log (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  timestamp     TEXT NOT NULL DEFAULT (datetime('now')),
  action        TEXT NOT NULL,
  actor         TEXT NOT NULL DEFAULT 'system',
  target        TEXT,
  details       TEXT,
  ip_address    TEXT,
  resource_type TEXT,
  status        TEXT,
  request_id    TEXT,
  metadata      TEXT
);
```

`timestamp`, `action`, `actor`, `resource_type`, `status`, மற்றும் `request_id` ஆகியவற்றில் அட்டவணைக் குறியீடுகள் உருவாக்கப்படுகின்றன. பழைய தரவுத்தளங்களில் இல்லாத நிரல்கள், தேவைப்படும்போது `ALTER TABLE` மூலம் சேர்க்கப்படுகின்றன.

## தக்கவைப்பு & சுத்தப்படுத்துதல்

இரண்டு தனித்தனி தக்கவைப்புக் கால அளவுகள் பின்பற்றப்படுகின்றன:

| சூழல் மாறி                  | இயல்புநிலை | பொருந்துவது                                                       |
| --------------------------- | ---------- | ----------------------------------------------------------------- |
| `APP_LOG_RETENTION_DAYS`    | `7`        | `audit_log`, `mcp_tool_audit`                                     |
| `CALL_LOG_RETENTION_DAYS`   | `7`        | `usage_history`, `call_logs`, `proxy_logs`, `request_detail_logs` |
| `CALL_LOGS_TABLE_MAX_ROWS`  | `100000`   | `call_logs`-க்கான வரம்புக்கு மீறிய வரிசை நீக்கம்                  |
| `PROXY_LOGS_TABLE_MAX_ROWS` | `100000`   | `proxy_logs`-க்கான வரம்புக்கு மீறிய வரிசை நீக்கம்                 |

`cleanupExpiredLogs()` தக்கவைப்பு செயல்முறையை இயக்குகிறது. சேவையகம் தொடங்கும்போது `src/instrumentation-node.ts`-இலிருந்து இது அழைக்கப்படுகிறது. ஒவ்வொரு இயக்கமும், ஒவ்வொரு அட்டவணையிலும் நீக்கப்பட்ட எண்ணிக்கைகளுடன் ஒரு `compliance.cleanup` தணிக்கை நிகழ்வைப் பதிவு செய்கிறது. நீண்ட நேர எழுதுதல் பூட்டுகளைத் தவிர்க்க, ப்ராக்ஸி/அழைப்புப் பதிவு குறைப்பு தொகுதிகளாக (`BATCH_SIZE = 5000`) செய்யப்படுகிறது.

கைமுறையான கோரிக்கை-வரலாற்றுச் சுத்தப்படுத்துதல், தக்கவைப்பிலிருந்து தனியானது. Request Logs பக்கம் `POST /api/settings/purge-request-history`-ஐ அழைக்கிறது; இது `call_logs`, பழைய `request_detail_logs`, மற்றும் `${DATA_DIR}/call_logs/`-இன் கீழுள்ள உள்ளூர் கோரிக்கைச் சுவடுகளை நீக்குகிறது.

இயல்புநிலைகள் `src/lib/logEnv.ts`-இல் வரையறுக்கப்பட்டுள்ளன (`DEFAULT_APP_LOG_RETENTION_DAYS = 7`, `DEFAULT_CALL_LOG_RETENTION_DAYS = 7`).

## `noLog` விலகல் (ஒவ்வொரு API விசைக்கும்)

API விசைகளின் கீழ்நிலை அழைப்புப் போக்குவரத்து பதிவு செய்யப்படாதவாறு அவற்றைக் குறியிடலாம். இந்தக் குறியீடு `api_keys` அட்டவணையில் (`no_log INTEGER DEFAULT 0`) சேமிக்கப்பட்டு, விரைவான பாதைத் தேடல்களுக்காக நினைவகத் தொகுப்பிலும் பிரதிபலிக்கப்படுகிறது.

```bash
# பதிவு செய்யப்படாத விசையை உருவாக்குதல் (நிர்வாக அங்கீகாரம் தேவை)
curl -X POST http://localhost:20128/api/keys \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{"name": "Privacy key", "noLog": true}'
```

உதவிச் செயல்பாடுகள் (`src/lib/compliance/index.ts`):

- `setNoLog(apiKeyId, true|false)` — நினைவகப் பதிவை மாற்றுகிறது
- `isNoLog(apiKeyId)` — கோரிக்கைப் பாதையில் சரிபார்க்கப்படுகிறது; இல்லையெனில் `api_keys.no_log`-இலிருந்து 30 வினாடிகள் தேக்ககப்படுத்தப்பட்ட வாசிப்பைப் பயன்படுத்துகிறது
- `NO_LOG_API_KEY_IDS` (சூழல் மாறி, காற்புள்ளியால் பிரிக்கப்பட்டது) — தொடக்கத்தின்போது நினைவகத் தொகுப்பில் முன்கூட்டியே ஏற்றப்படுகிறது; நிரலை நேரடியாக மாற்ற முடியாதபோது இது பயனுள்ளதாக இருக்கும்

நிர்வாகத் தணிக்கை நிகழ்வுகள் (உள்நுழைவு, வழங்குநர் மாற்றங்கள், MCP கருவி அழைப்புகள் போன்றவை) `noLog`-ஆல் **பாதிக்கப்படுவதில்லை** — ஒவ்வொரு கோரிக்கைக்குமான போக்குவரத்துப் பதிவு மட்டுமே விலக்கப்படுகிறது.

### `/api/compliance/audit-log`-ஐ வினவுதல்

ஆதரிக்கப்படும் வினவல் அளவுருக்கள் (அனைத்தும் விருப்பத்திற்குரியவை; உரை
வடிப்பான்கள் அனைத்தும் `LIKE %value%` பொருத்தத்தைப் பயன்படுத்துகின்றன):

- `action`, `actor`, `target`, `resourceType` (அல்லது `resource_type`),
  `status`, `requestId` (அல்லது `request_id`)
- `from` / `since`, `to` / `until` — ISO நேரமுத்திரைகள்
- `limit` (இயல்புநிலை `50`, குறைந்தபட்சம் `1`, அதிகபட்சம் `500`)
- `offset` (இயல்புநிலை `0`, அதிகபட்சம் `10_000`)

பதில் ஒரு JSON அணியாகும். பக்கமிடல் மெட்டாடேட்டா பின்வரும் தலைப்புகளில் வழங்கப்படுகிறது:
`x-total-count`, `x-page-limit`, `x-page-offset`.

```bash
curl "http://localhost:20128/api/compliance/audit-log?action=provider.credentials&from=2026-05-01" \
  -H "Cookie: auth_token=..."
```

## முகப்புப்பலகை

முகப்புப்பலகை, தணிக்கைத் தரவை **`/dashboard/audit`**-இல்
(`src/app/(dashboard)/dashboard/audit/page.tsx`) வழங்குகிறது. இந்தப் பக்கத்தில் இரண்டு தாவல்கள் உள்ளன:

- **இணக்கப்பாடு** (`ComplianceTab.tsx`) — `/api/compliance/audit-log`-இலிருந்து
  நிர்வாகத் தணிக்கை நிகழ்வுகள். நிகழ்வு வகை, தீவிரத்தன்மை (தகவல் / எச்சரிக்கை
  / முக்கியமானது; செயல் + நிலையிலிருந்து பெறப்பட்டது), மற்றும் தேதி வரம்பு ஆகியவற்றின்படி வடிகட்டுகிறது. தீவிரத்தன்மை,
  செயல்/நிலைச் சரங்களிலிருந்து கிளையன்ட் பக்கத்தில் கணக்கிடப்படுகிறது.
- **MCP** (`McpAuditTab.tsx`) — `/api/mcp/audit`-இலிருந்து MCP கருவித் தணிக்கை;
  கருவிப் பெயர் மற்றும் வெற்றி/தோல்வி ஆகியவற்றின்படி வடிப்பான்களுடன்.

இரண்டு தாவல்களும் முறையே `50` (இணக்கப்பாடு) மற்றும் `25` (MCP) என்ற பக்க அளவுகளுடன் பக்கமிடுகின்றன.

## வழங்குநர் நற்சான்று உதவிச் செயல்பாடுகள்

`src/lib/compliance/providerAudit.ts`, நற்சான்று நிகழ்வுகளை வெளியிடும்போது
வழங்குநர்-மேலாண்மை வழித்தடங்கள் பயன்படுத்தும் வடிவமைப்பு உதவிச் செயல்பாடுகளை வழங்குகிறது:

- `summarizeProviderConnectionForAudit(connection)` — இணைப்பின் நகல்
  `details`-இல் எழுதப்படுவதற்கு முன் `apiKey`,
  `accessToken`, `refreshToken`, `idToken`, மற்றும்
  `providerSpecificData.consoleApiKey` ஆகியவற்றை நீக்குகிறது.
- `getProviderAuditTarget(connection)` — `target` புலத்திற்காக நிலையான
  `"<provider>:<name|id>"` சரத்தை உருவாக்குகிறது.
- `extractProviderWarnings(...payloads)` — வழங்குநர் பதில்களில் உள்ள
  கொள்கை/பாதுகாப்பு எச்சரிக்கைகளை (`[sanitizer]`, `prompt injection detected`,
  `content has been filtered`, `safety filter`, `policy violation`) தேடி,
  அதிகபட்சமாக 5 பொருத்தங்களை வெளிப்படுத்துகிறது; ஒவ்வொன்றும் 400 எழுத்துகளாகக் குறுக்கப்படும்.

## சிறந்த நடைமுறைகள்

- PII-ஐ (சட்டம், மருத்துவம் போன்றவை) கையாளும் API விசைகளை `noLog: true` கொண்டு குறியிடவும்.
- உங்கள் தரவுத் தக்கவைப்புக் கொள்கையைப் பூர்த்திசெய்ய `APP_LOG_RETENTION_DAYS` /
  `CALL_LOG_RETENTION_DAYS` ஆகியவற்றைச் சரிசெய்யவும். இயல்புநிலையான 7 நாட்கள் எச்சரிக்கையானவை.
- உங்கள் இணக்கப்பாட்டுத் திட்டம் கோரும் கால இடைவெளியில் தணிக்கை அட்டவணையைத் தளத்திற்கு வெளியே
  (`sqlite3 dump`) ஏற்றுமதி செய்யவும் — உள்ளமைந்த காப்பக வசதி இல்லை.
- முரட்டுவலுத் தாக்குதல் கண்டறிதலுக்காக `auth.login.failed` மற்றும்
  `auth.login.locked` எண்ணிக்கைகளைக் கண்காணிக்கவும்.
- புதிய நிர்வாக முனைப்புள்ளிகளைச் சேர்க்கும்போது, நிலையான
  `domain.verb.outcome` செயல் சரத்துடன் `logAuditEvent({ ... })`-ஐ அழைத்து,
  கோரிக்கைச் சூழலை `getAuditRequestContext(request)` வழியாக அனுப்பவும்; இதனால் IP மற்றும்
  `requestId` தானாகப் பதிவுசெய்யப்படும்.
