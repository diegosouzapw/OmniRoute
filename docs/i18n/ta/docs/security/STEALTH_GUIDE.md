அதிகாரப்பூர்வமற்ற கிளையன்ட்களைச் செயலில் கைரேகையிடும் விளிம்பு அமைப்புகளைக் கொண்ட வழங்குநர்களுடன் OmniRoute ஒருங்கிணைகிறது (TLS JA3/JA4, தலைப்பு வரிசைப்படுத்தல், JSON உடல் வடிவம், ஒருமைப்பாட்டு டோக்கன்கள்). OmniRoute வெளிப்படுத்தும் மறைநிலை மேற்பரப்புகளையும், அவை செயல்படுத்தப்பட்டுள்ள இடங்களையும் இந்தப் பக்கம் ஆவணப்படுத்துகிறது.

## சட்ட மற்றும் நெறிமுறை அறிவிப்பு

பயனருக்குச் சொந்தமான அதிகாரப்பூர்வ கணக்குகள் (Claude Code CLI, Codex, Antigravity, Cursor போன்றவை) மற்றும் OmniRoute-இன் ஒருங்கிணைந்த API ஆகியவற்றுக்கிடையே OmniRoute ஒரு இணக்கத்தன்மை அடுக்காகச் செயல்படுவதற்காகவே மறைநிலை அம்சங்கள் உள்ளன. அவை மோசடி கண்டறிதலைத் தவிர்ப்பதற்கோ, நற்சான்றுகளைப் பகிர்வதற்கோ, வழங்குநரின் சேவை விதிமுறைகளை மீறுவதற்கோ **அல்ல**. கணக்குகளை உருவாக்கும்போது ஏற்றுக்கொண்ட மேல்நிலை ToS-க்கு இயக்குநர்கள் இணங்க வேண்டும் எனப் பராமரிப்பாளர்கள் எதிர்பார்க்கின்றனர்.

## TLS கைரேகையிடல் அடுக்கு

### `open-sse/utils/tlsClient.ts` — wreq-js (Chrome 124)

ஒவ்வொரு கணக்கு வரம்புக்கும் தீர்க்கப்பட்ட ப்ராக்ஸிக்கும் நிலையான `wreq-js` அமர்வுகள் தேவைக்கேற்ப தாமதமாக உருவாக்கப்படுகின்றன. செயல்முறை முழுவதற்குமான `TlsClient`, Cloudflare-க்குப் பின்னால் உள்ள மேல்நிலைச் சேவைகளுக்காக **macOS-இல் Chrome 124** போன்று நடிக்கும் அதிகபட்சம் 128 அமர்வுகளைத் தொகுப்பில் வைத்திருக்கும். சொந்த இயக்கநேரம் கிடைக்காதபோது `TlsClient.fetch()` பாதுகாப்பாகத் தோல்வியடைகிறது; அழைப்பாளர் இந்தச் சுற்றுறைக்கு வெளியே ஒரு மாற்று வழியை வெளிப்படையாகத் தேர்ந்தெடுக்கலாம்.

- அமர்வு சுயவிவரம்: `browser: "chrome_124", os: "macos"`
- ப்ராக்ஸி தீர்மானம் (முன்னுரிமை): `HTTPS_PROXY` → `HTTP_PROXY` → `ALL_PROXY` (சிற்றெழுத்து வடிவங்களும் உட்பட)
- காலக்கெடு: `TLS_CLIENT_TIMEOUT_MS` (`FETCH_TIMEOUT_MS`-இலிருந்து பெறுகிறது, இயல்புநிலை 600000)
- `wreq-js` Response என்பது fetch-உடன் இணக்கமானது (`headers`, `text()`, `json()`, `clone()`, `body`).
- முதல்-பைட் கண்காணிப்பான் (`open-sse/utils/tlsFirstByteWatchdog.ts`, #12656): மேல்நிலைத் தலைப்புகள் வந்தவுடன் `TlsClient.fetch()` தீர்வடைகிறது; எனவே முதல் பைட்டையே ஒருபோதும் வழங்காத உடலை `TLS_CLIENT_TIMEOUT_MS` மட்டும் வரம்பிட முடியாது. `guardTlsFirstByte()` உடலின் முதல் `read()`-ஐ `TLS_FIRST_BYTE_WATCHDOG_MS`-க்கு எதிராகப் பந்தயப்படுத்துகிறது (இயல்புநிலை `10000`, `0` அதை முடக்குகிறது); ஆரோக்கியமான உடல் பாதிக்கப்படாது, ஆனால் நின்றுபோன உடல் wreq ரீடரை ரத்து செய்து, `proxyFetch`-இன் ஏற்கெனவே உள்ள TLS-மாற்றுவழித் தர்க்கத்தை நேரடி/ப்ராக்ஸி அனுப்புநருக்குச் செல்ல அனுமதிக்கிறது (மீண்டும் இயக்குவதற்குப் பாதுகாப்பற்ற கோரிக்கை, எ.கா. உடலுடன் கூடிய POST, அமைதியாக மீண்டும் முயற்சிக்கப்படுவதற்குப் பதிலாக இன்னும் பிழையை எழுப்பும்).

### வலை-குக்கீ வழங்குநர் போக்குவரத்து — wreq-js 3.2.0

`open-sse/services/tlsClientBase.ts` என்பது கீழே உள்ள ஐந்து சிறப்பாக்கப்பட்ட வலை-குக்கீ போக்குவரத்துகளுக்கான பகிரப்பட்ட அடாப்டர். ஒவ்வொரு மெல்லிய வழங்குநர் சுற்றுறையும் ஒரு உலாவி/OS சுயவிவரத்தைத் தேர்ந்தெடுக்கிறது. இந்த அடாப்டர், `open-sse/utils/tlsClient.ts`-இல் உள்ள ஒற்றை wreq இயக்கநேர ஏற்றியையும் போக்குவரத்துத் தொகுப்பையும் பயன்படுத்துகிறது; அவை சுயவிவரம் + OS + தீர்க்கப்பட்ட ப்ராக்ஸி ஆகியவற்றால் திறவுகோலிடப்படுகின்றன, அதே வேளையில் ஒவ்வொரு கோரிக்கையும் `cookieMode: "ephemeral"`-ஐப் பயன்படுத்துகிறது. எனவே கணக்குகளும் கோரிக்கைகளும் போக்குவரத்து-நிலை இணைப்புகளைப் பகிர்ந்துகொள்கின்றன; ஆனால் wreq அமர்வையோ குக்கீ ஜாரையோ ஒருபோதும் பகிர்வதில்லை.

| வழங்குநர்  | சுயவிவரம்     | பாவனை செய்யப்பட்ட OS | ஸ்ட்ரீம் EOF கொள்கை                       |
| ---------- | ------------- | -------------------- | ----------------------------------------- |
| Claude     | `chrome_146`  | Linux                | `[DONE]`-ஐச் சேர்க்கும்                   |
| Perplexity | `firefox_148` | macOS                | `event: end_of_stream`-ஐச் சேர்க்கும்     |
| Grok       | `chrome_146`  | Linux                | `[DONE]`-ஐ விலக்கும்                      |
| Notion     | `chrome_146`  | Windows              | `[DONE]`-ஐச் சேர்க்கும்                   |
| LMArena    | `chrome_146`  | Windows              | காவல் மதிப்பு இல்லை; சொந்த EOF-இல் மூடும் |

- ஸ்ட்ரீமிங், சொந்த பதிலின் `ReadableStream`-ஐ நேரடியாகப் பயன்படுத்துகிறது; தற்காலிகக் கோப்போ பக்கச்சேவையோ உருவாக்கப்படாது.
- ஒரு ஸ்ட்ரீமை வெளிப்படுத்துவதற்கு முன் தொடக்கத்தில் அதிகபட்சம் 256 பைட்டுகள் ஆய்வு செய்யப்படுகின்றன. SSE வழங்குநர்கள் SSE அல்லாத பிழைகளை இடையகப்படுத்துகின்றனர்; Grok/LMArena, Cloudflare சவால்களை `403`-க்கும் HTML இடைநிலைப் பக்கங்களை `502`-க்கும் வரைபடப்படுத்துகின்றன.
- சொந்த கோரிக்கைக் காலக்கெடு ஒரு முழுமையான JS கடினக் காலக்கெடுவால் தொடர்ந்து சுற்றுப்பொதியப்படுகிறது. ஒரு செயல்தடை, பாதிக்கப்பட்ட சுயவிவரம்/OS/ப்ராக்ஸி போக்குவரத்தை மட்டும் செல்லாததாக்கி மூடுகிறது; அடுத்த கோரிக்கை அதை மீண்டும் உருவாக்கும்.
- ப்ராக்ஸி தீர்மான முன்னுரிமை: ஒவ்வொரு அழைப்பிற்குமான `proxyUrl` → கோரிக்கை-வரம்புடைய கணக்கு/டாஷ்போர்டு சூழல் → `HTTPS_PROXY`/`HTTP_PROXY`/`ALL_PROXY` (சிற்றெழுத்து வடிவங்கள் உட்பட). தீர்மானப் பிழைகள் நேரடி இணைப்பைக் கசியவிடுவதற்குப் பதிலாக பாதுகாப்பாகத் தோல்வியடைகின்றன. LMArena திட்டமிட்டே `arena.ai`-க்கு எதிராகத் தீர்மானிக்கிறது.
- `byteResponse`, UTF-8 சிதைவு இல்லாமல் உள்ளடக்க வகை குறிப்பிடப்பட்ட `data:` URL-ஐத் திருப்பி அனுப்புகிறது.
- எல்லா 128 வரம்பிடப்பட்ட சுயவிவரம்/OS/ப்ராக்ஸி இடங்களும் செயலில் இருக்கும்போது அல்லது மூடப்பட்டுக்கொண்டிருக்கும்போது ஏற்படும் பிழைகள்: `TlsClientUnavailableError` (தொகுப்பு/துணைநிரல் கிடைக்கவில்லை), `TlsClientHangError` (காலக்கெடு மீறப்பட்டது), மற்றும் `WreqTransportCapacityError` (பகிரப்பட்ட அமர்வு-கொள்ளளவுப் பிழைக் குறியீடு).

மேலே உள்ள பொதுவான `TlsClient` அமர்வு, நிலையான உலாவி-ஆதரவு கொண்ட குக்கீ நிலைக்காகத் தொடர்ந்து சிறப்பாக்கப்பட்டுள்ளது. இரண்டு பாதைகளும் தற்காலிகச் சேமிப்பில் வைக்கப்பட்ட ஒரே wreq தொகுதி ஏற்றியையும் செயல்முறை வாழ்க்கைச்சுழற்சி கொக்கியையும் மீண்டும் பயன்படுத்துகின்றன; அவற்றின் குக்கீ ஆயுட்காலங்கள் திட்டமிட்டே வேறுபடுவதால் அவற்றின் தொகுப்புகள் தனித்தனியாகவே உள்ளன.

இந்தச் சுயவிவரங்கள் பதிப்பு நிலைநிறுத்தப்பட்ட தொகுப்பால் ஆதரிக்கப்படுகின்றன; ஆனால் உண்மையான WAF ஏற்புத்தன்மை, உள்ளூர் ஒப்பந்தச் சோதனைகளிலிருந்து தனித்தனியாக மாறக்கூடும். மேல்நிலை உலாவியுடன் சமநிலை இருப்பதாகக் கூறுவதற்கு முன், வெளிப்படையாக அங்கீகரிக்கப்பட்ட நேரடிக் கணக்கைப் பயன்படுத்தி கைரேகை மாற்றங்களைச் சரிபார்க்கவும்.

## Claude Code மறைமுகத் தொகுப்பு

`cliCompatMode` இயக்கப்பட்டிருக்கும்போது, வெளியே செல்லும் Claude கோரிக்கைகள் `claude-cli` போக்குவரத்திலிருந்து வேறுபடுத்த முடியாதவாறு OmniRoute அவற்றை மறுவடிவமைக்கிறது. மூன்று தொகுதிகள் இணைந்து செயல்படுகின்றன:

### `claudeCodeFingerprint.ts`

பில்லிங் தலைப்பில் உட்பொதிக்கப்பட்டுள்ள 3-எழுத்து `cc_version` கைரேகையைக் கணக்கிடுகிறது:

```
SHA256(SALT + msg[4] + msg[7] + msg[20] + version)[:3]
```

- `FINGERPRINT_SALT = "59cf53e54c78"` (நிரலில் நேரடியாகப் பதியப்பட்டது; அதிகாரப்பூர்வ கிளையண்டுடன் பொருந்துகிறது)
- உள்ளீடுகள்: முதல் பயனர் செய்தி உரையின் 4, 7, 20 ஆகிய சுட்டெண்களில் உள்ள எழுத்துகள் + பதிப்புச் சரம்
- வெளியீடு: 3-எழுத்து ஹெக்ஸ் முன்னொட்டு

### `claudeCodeCCH.ts` (கிளையண்ட் உள்ளடக்க ஹாஷ்)

அதிகாரப்பூர்வ Claude Code CLI, Bun/Zig வழியாகக் கணக்கிடும் சர்வர்-பக்க ஒருமைப்பாட்டுச் சரிபார்ப்பு. OmniRoute இதை `xxhash-wasm` கொண்டு மறுசெயலாக்குகிறது:

1. `cch=00000;` இடநிரப்பியுடன் body-ஐ வரிசைப்படுத்தவும்
2. `xxhash64(bytes, seed) & 0xFFFFF`
3. பூஜ்ஜியங்களால் நிரப்பப்பட்ட 5-எழுத்து சிற்றெழுத்து ஹெக்ஸ்
4. `cch=00000;` என்பதை கணக்கிடப்பட்ட டோக்கனால் மாற்றவும்

மாறிலிகள்:

- Seed: `0x6e52736ac806831e`
- வடிவமைப்பு: `/\bcch=([0-9a-f]{5});/`

### `claudeCodeObfuscation.ts`

மேல்நிலை வடிப்பான்கள் அவற்றை grep செய்ய முடியாதவாறு, "உணர்திறன் மிக்க" கிளையண்ட் பெயர்களின் முதல் எழுத்துக்குப் பிறகு Unicode **பூஜ்ஜிய-அகல இணைப்பியை** (`U+200D`) செருகுகிறது. இயல்புநிலைச் சொல் பட்டியல்:

```
opencode, open-code, cline, roo-cline, roo_cline, cursor, windsurf,
aider, continue.dev, copilot, avante, codecompanion
```

பயன்படுத்தப்படும் இடங்கள்: `system` தொகுதிகள், அனைத்து `messages[].content`, மற்றும் `tools[].description` / `tools[].function.description`. `setSensitiveWords()` மூலம் இயக்குநர் இதை மாற்றியமைக்கலாம்.

### `claudeCodeCompatible.ts` — `anthropic-compatible-cc-*` வழங்குநர்கள்

"உண்மையான Claude Code" போக்குவரத்தை மட்டுமே ஏற்கும் மூன்றாம் தரப்பு Anthropic ரிலேக்களுக்காக:

- `CLAUDE_CODE_COMPATIBLE_USER_AGENT = "claude-cli/2.1.258 (external, sdk-cli)"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_PACKAGE_VERSION = "0.112.1"`
- `CLAUDE_CODE_COMPATIBLE_STAINLESS_RUNTIME_VERSION = "v26.3.0"`
- இயல்பாக `anthropic-beta = "claude-code-20250219,interleaved-thinking-2025-05-14,effort-2025-11-24"`
- ஒரு CC Compatible மேல்நிலை குறிப்பாக மறைக்கப்பட்ட சிந்தனை ஸ்ட்ரீம்களை வேண்டும்போது, ஒவ்வொரு இணைப்பிற்குமான "Enable redact-thinking beta" மாற்றி `redact-thinking-2026-02-12` என்பதைச் சேர்க்கிறது
- ஒவ்வொரு இணைப்பிற்குமான "Enable summarized thinking display" மாற்றி `providerSpecificData.requestDefaults.summarizeThinking` என்பதைச் சேமித்து, ஏற்கெனவே காட்சி முறை அமைக்கப்படாத CC Compatible சிந்தனைக் கோரிக்கைகளில் `display: "summarized"` என்பதைச் சேர்க்கிறது
- `CONTEXT_1M_BETA_HEADER = "context-1m-2025-08-07"` (Opus/Sonnet 4.x குடும்பம்)
- இயல்புநிலைப் பாதை: `/v1/messages?beta=true`

அதே தொகுப்பிலுள்ள துணைத் தொகுதிகள்:

- `claudeCodeExtraRemap.ts` — கூடுதல் payload இயல்பாக்கம்

## Antigravity மறைமுகத்தன்மை

Antigravity கோரிக்கைகள் அழைப்பாளரின் உரையை byte-for-byte அப்படியே பாதுகாக்கின்றன. ஒரு IDE கிளையண்டைப் போல பாவனை செய்வதற்காக OmniRoute prompt-களில் பூஜ்ஜிய-அகல எழுத்துகளைச் செருகுவதோ, கருவிகளை மறுபெயரிடுவதோ/உட்செலுத்துவதோ இல்லை.

### `antigravityHeaderScrub.ts`

முன்னனுப்புவதற்கு முன் Stainless SDK அடையாளக் குறிகளை (`x-stainless-lang`, `x-stainless-package-version`, `x-stainless-os`, `x-stainless-arch`, `x-stainless-runtime`, `x-stainless-runtime-version`, `x-stainless-timeout`, `x-stainless-retry-count`, `x-stainless-helper-method`) அகற்றுகிறது.

### ⚠️ அபாயம்: `ANTIGRAVITY_CREDITS=always` (கணக்குத் தடை ஏற்படும் முக்கிய இடம்)

`ANTIGRAVITY_CREDITS=always` (`open-sse/executors/antigravity.ts` இதைப் பயன்படுத்துகிறது) என்பது Google-இன் இலவச அடுக்குக் quota கட்டுப்படுத்த அனுமதிப்பதற்குப் பதிலாக, **ஒவ்வொரு** கோரிக்கையையும் Antigravity AI Credit Overages (கட்டண Google credits) வழியாக அனுப்புகிறது. இது ஒரு அம்சமாக ஆவணப்படுத்தப்பட்டுள்ளது. ஆனால், இது **நாங்கள் காணும் ToS மீறல் அறிக்கைகளில் மிகவும் பொதுவான ஒற்றைக் காரணமாகும்** — `=always` உடன் சில மணி நேரங்கள் இயக்கிய பிறகு, பல Google Ultra கணக்குகள் `403 / "service disabled for ToS violation" / insufficient_quota` உடன் தடை செய்யப்பட்டுள்ளன.

மேல்நிலை அமலாக்கம் **Google தரப்பில்** நடைபெறுகிறது; அதை OmniRoute தடுக்க முடியாது. சூழல் மாறியின் பெயரும் தற்போதைய ஆவணங்களும் இதை இயக்குவது பாதுகாப்பான அமைப்பு போலத் தோன்றச் செய்கின்றன; ஆனால் அது பாதுகாப்பானதல்ல.

**இலவச அடுக்கு மட்டுமான பயன்பாட்டைவிட இது ஏன் முறைகேடு கண்டறிதலை அதிகத் தீவிரமாகத் தூண்டுகிறது:**

- ஒரே Google கணக்கில் தொடர்ச்சியான தானியக்கச் செலவினம், இலவச அடுக்கு quota-வை எட்டி நிற்கும் முறையிலிருந்து வேறுபட்ட விதத்தில் குறியிடப்படுகிறது.
- Credit overages-க்கு விகித உச்சவரம்பு இல்லை. எனவே தவறாக உள்ளமைக்கப்பட்ட கிளையண்ட் சில நிமிடங்களில் பல நூறு USD செலவழித்து, API-key மறுவிற்பனை அல்லது bot போக்குவரத்து போலத் தோன்றக்கூடும்.
- ஒரே வெளிப்புற IP-இலிருந்து பல OmniRoute பயனர்கள் இணையாக overage credits-ஐப் பயன்படுத்துவது அந்தச் சமிக்ஞையை மேலும் வலுப்படுத்துகிறது.

**பரிந்துரைக்கப்படும் அணுகுமுறை:**

1. இயக்குநர் கட்டண-credit மற்றும் கணக்கு-அமலாக்க அபாயத்தை வெளிப்படையாக ஏற்காத வரை, இயல்புநிலையான `ANTIGRAVITY_CREDITS=off` அமைப்பையே வைத்திருங்கள். `retry` முதலில் சாதாரணக் கோரிக்கையை அனுப்பி, தகுதியான quota 429 ஏற்பட்ட பிறகு அதிகபட்சம் ஒருமுறை credits-ஐ உட்செலுத்துகிறது; `always` முதல் கோரிக்கையிலேயே credits-ஐ உட்செலுத்துகிறது.
2. ஒரே Antigravity கணக்கை முழுத் திறனில் பயன்படுத்துவதற்குப் பதிலாக, **Auto-Combo மூலம் வழங்குநர்களிடையே சுமையைப் பகிருங்கள்** (`model: "auto"` அல்லது `kr/glm/etc`-combo).
3. Antigravity வழங்குநரின் திருத்தப் பக்கத்தில் **ஒவ்வொரு இணைப்பிற்குமான RPM வரம்புகளை அமைக்கவும்** (Dashboard → Providers → Antigravity → connection → rate limit). தொடர்ச்சியான பயன்பாட்டிற்கு 30–60 RPM என்பது நியாயப்படுத்தக்கூடிய உச்சவரம்பாகும்.
4. **நிலையான, இயக்குநரின் கட்டுப்பாட்டிலுள்ள மேல்நிலை நெட்வொர்க்கிங்கைப் பயன்படுத்துங்கள்**; தொடர்பில்லாத பயனர்கள் அல்லது பணிச்சுமைகளுக்கு இடையே ஒரே கணக்கைப் பகிர்வதைத் தவிர்க்கவும்.
5. **தடை செய்யப்பட்டால்**: Google அனுப்பிய சரியான `quota_exceeded` / `service disabled` பதில் body-உடன் `support.google.com` → "Restore Workspace/Account access" வழியாக மேல்முறையீடு செய்யவும். மீட்டமைப்பு உறுதியளிக்கப்படவில்லை.

ஒவ்வொரு credits முறையின் கணக்கு மற்றும் செலவுத் தாக்கங்களைச் சூழல் குறிப்பேடு ஆவணப்படுத்துகிறது.

தொடர்புடைய இடங்கள்:

- `open-sse/executors/antigravity.ts` — `process.env.ANTIGRAVITY_CREDITS` என்பதைப் படிக்கிறது
- `src/lib/oauth/providers/antigravity.ts` — நற்சான்று இணைப்பமைப்பு
- அசல் சம்பவ அறிக்கை: Discussion [#1183](https://github.com/diegosouzapw/OmniRoute/discussions/1183)

## CLI கைரேகைப் பதிவகம் — `open-sse/config/cliFingerprints.ts`

அதிகாரப்பூர்வ CLI-களின் mitmproxy தடங்களிலிருந்து பதிவு செய்யப்பட்ட **துல்லியமான** தலைப்பு வரிசையையும் JSON உடல் புல வரிசையையும் நிலைநிறுத்தும், வழங்குநர் வாரியான அட்டவணை. தற்போது பதிவுசெய்யப்பட்டவை: `codex`, `claude`; மேலும் `antigravity` மற்றும் `github` ஆகியவற்றுக்கான இயக்கநேரத்தில் பெறப்பட்ட சுயவிவரங்கள் `providerHeaderProfiles.ts`-இல் உள்ளன.

```ts
interface CliFingerprint {
  headerOrder: string[]; // எழுத்துப் பெட்டி உணர்திறன் கொண்டது
  bodyFieldOrder: string[]; // மேல்-நிலை JSON விசைகள்
  userAgent?: string | (() => string);
  extraHeaders?: Record<string, string>;
}
```

சுற்றுச்சூழல் மாறி மூலம் ஒவ்வொரு வழங்குநருக்கும் மாற்றியமைக்கலாம் (கீழே காண்க). முடக்கப்பட்டிருக்கும்போது, Node/JSON வழங்கிய எந்த வரிசையிலோ தலைப்புகள்/உடல் விசைகள் தோன்றும் — எளிதில் கைரேகை கண்டறியக்கூடியது.

## MITM பதிலாள் (Antigravity, Linux/macOS/Windows)

`OPENAI_BASE_URL` வழியாகத் திருப்பிவிட முடியாத இருமக் கோப்புகளைக் கொண்ட CLI-களுக்காக, OmniRoute ஒரு உள்ளூர் TLS-முடிவுறுத்தும் பதிலாளை இயக்குகிறது. இறுதிப்புள்ளிகள் `src/app/api/cli-tools/antigravity-mitm/`-இன் கீழ் உள்ளன.

| முறை   | இறுதிப்புள்ளி                           | நோக்கம்                                            |
| ------ | --------------------------------------- | -------------------------------------------------- |
| GET    | `/api/cli-tools/antigravity-mitm`       | நிலை — இயங்குகிறது, pid, dnsConfigured, certExists |
| POST   | `/api/cli-tools/antigravity-mitm`       | MITM-ஐத் தொடங்கு (`apiKey` + `sudoPassword` தேவை)  |
| DELETE | `/api/cli-tools/antigravity-mitm`       | MITM-ஐ நிறுத்து                                    |
| GET    | `/api/cli-tools/antigravity-mitm/alias` | மாதிரி மாற்றுப்பெயர்களைப் பட்டியலிடு               |
| PUT    | `/api/cli-tools/antigravity-mitm/alias` | ஒரு கருவிக்கான மாதிரி மாற்றுப்பெயர்களைச் சேமி      |

இடைமறிக்கப்படும் இலக்கு புரவலன்: **`daily-cloudcode-pa.googleapis.com`** (Antigravity-யின் மேல்நிலைச் சேவை).

### தொடக்க வரிசை (`src/mitm/manager.ts::startMitm`)

1. `selfsigned` வழியாக சுய-கையொப்பமிட்ட சான்றிதழை உருவாக்கு (RSA-2048, SHA-256, 1y) — `cert/generate.ts`
2. கணினியின் நம்பிக்கைச் சேமிப்பகத்தில் சான்றிதழை நிறுவு — `cert/install.ts`
3. `127.0.0.1 daily-cloudcode-pa.googleapis.com` புரவலர் பதிவைச் சேர் — `dns/dnsConfig.ts`
4. `ROUTER_API_KEY` + `MITM_LOCAL_PORT` (இயல்புநிலை `443`) உடன் `src/mitm/server.cjs`-ஐ உருவாக்கி இயக்கு
5. PID-ஐ `<DATA_DIR>/mitm/.mitm.pid`-இல் நிலையாகச் சேமி

### Linux இயக்கநேர நம்பிக்கைச் சேமிப்பகக் கண்டறிதல் — `cert/install.ts`

`getLinuxCertConfig()` முன்னுரிமைப் பட்டியலில் சென்று, முதலில் இருக்கும் கோப்பகத்தைத் தேர்ந்தெடுக்கிறது:

| விநியோகக் குடும்பம்      | கோப்பகம்                                    | புதுப்பிப்புக் கட்டளை    |
| ------------------------ | ------------------------------------------- | ------------------------ |
| Debian / Ubuntu          | `/usr/local/share/ca-certificates`          | `update-ca-certificates` |
| Arch / CachyOS / Manjaro | `/etc/ca-certificates/trust-source/anchors` | `update-ca-trust`        |
| Fedora / RHEL / CentOS   | `/etc/pki/ca-trust/source/anchors`          | `update-ca-trust`        |
| openSUSE                 | `/etc/pki/trust/anchors`                    | `update-ca-certificates` |

சான்றிதழ் கோப்புப்பெயர்: `omniroute-mitm.crt`. `getCertFingerprint()` மூலம் கைரேகைப் பொருத்தம் (DER-இன் SHA-1).

கூடுதலாக, `certutil` கிடைக்கும்போது `updateNssDatabases()` ஒவ்வொரு பயனருக்குமான NSS தரவுத்தளங்களில் நிறுவுகிறது: `~/.pki/nssdb`, `~/snap/chromium/.../nssdb`, அனைத்து Firefox சுயவிவரங்கள் (snap உட்பட); பயன்படுத்தப்படும் புனைப்பெயர் **`OmniRoute MITM Root CA`**.

### macOS / Windows

- **macOS:** `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain`
- **Windows:** உயர்த்தப்பட்ட PowerShell → `certutil -addstore Root`

### அங்கீகாரம்

அனைத்து MITM இறுதிப்புள்ளிகளுக்கும் நிர்வாக அங்கீகாரம் (`requireCliToolsAuth`) தேவை. sudo கடவுச்சொல் தொகுதிப் பரப்பில் தற்காலிகமாகச் சேமிக்கப்படுகிறது (`globalThis`-இல் ஒருபோதும் இல்லை), மேலும் `stopMitm()` அழைக்கப்படும்போது அழிக்கப்படுகிறது.

## வழங்குநர் மாற்றும்போது கைரேகைகளைப் புதுப்பித்தல்

1. `mitmproxy` மூலம் அதிகாரப்பூர்வ CLI போக்குவரத்தைப் பதிவு செய்யவும் (TLS இடைமறிப்பு + dump)
2. JA3/JA4 மற்றும் தலைப்புகளின் நேரடி வரிசையைப் பிரித்தெடுக்கவும்
3. தொடர்புடைய `CLI_FINGERPRINTS[...]` உள்ளீட்டைப் புதுப்பிக்கவும்
4. `.env.example`-இல் பொருந்தும் `*_USER_AGENT` இயல்புநிலையின் பதிப்பை உயர்த்தவும்
5. TLS கைகுலுக்கலே மாறியிருந்தால், தொடர்புடைய வழங்குநர் wrapper அல்லது wreq-js `browser:` விருப்பத்தைப் புதுப்பிக்கவும்
6. வழங்குநருக்குரிய TLS சோதனைகளையும், நேரடி வழங்குநருக்கு எதிரான கைமுறை canary சோதனையையும் இயக்கவும்
7. patch வெளியீடாக வெளியிட்டு, `CHANGELOG.md`-இல் ஆவணப்படுத்தவும்
