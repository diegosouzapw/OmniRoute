`devin-cli-agentic`, அதிகாரப்பூர்வ Devin CLI ஆனது ACP stdio வழியாக மாதிரி பதில்களை வழங்கும் நிலையில், உண்மையான Claude Code இயக்கச் சூழலை OmniRoute-இன் உள்ளக Anthropic
Messages endpoint-ஐப் பயன்படுத்த அனுமதிக்கிறது. இது ஏற்கனவே உள்ள Anthropic, Claude OAuth, Claude Web அல்லது `devin-cli` வழங்குநர்களை
மாற்றாது.

> **தற்போதைய நிலை: Claude Code `2.1.258` பதிப்பில் நிலைநிறுத்தப்பட்டுள்ளது; offline மற்றும் live சரிபார்ப்புகள் கடைசியாகப் பதிவு செய்யப்பட்டது
> `2.1.220`-இல்.** `2.1.220` பதிப்பு நிலைநிறுத்தம், Devin CLI
> `3000.2.17` மற்றும் `swe-1-7-lightning` மாதிரி வழியாக மூன்று தனிமைப்படுத்தப்பட்ட சூழ்நிலைகளை நிறைவுசெய்தது; அந்த இறுதி live இயக்கம் client-க்குச் சொந்தமான `Read`,
> `Edit` மற்றும் `Bash` சுற்றுகள், வெற்றிகரமான `npm test` முடிவுகள், திட்டக் கட்டளை மற்றும் திறன்
> கண்டறிதல், Devin-க்கு மட்டும் உரிய வழித்தடத் தேர்வு மற்றும் Claude-க்கான பூஜ்ஜிய வெளிச்செலுத்தல் ஆகியவற்றை உறுதிப்படுத்தியது. பின்னர் பதிப்பு `2.1.258`-க்கு உயர்த்தப்பட்டது
> (இது OmniRoute-இன் Claude அடையாளம் போலச் செயல்படும் CLI தலைமுறை மற்றும் Fable 5.1 அடுக்கை இயல்பாகவே வழங்கும்
> முதல் வெளியீட்டு வரிசை). புதிய பதிப்பில், நிலைநிறுத்தப்பட்ட அடிப்படை image-இல் நிறுவல் அடுக்கும் `claude --version`-உம்
> சரிபார்க்கப்பட்டன; மேலும் bridge unit suite, `compose config` மற்றும்
> நிலையான தனிமைப்படுத்தல் நிரூபணம் வெற்றிபெறுகின்றன — ஆனால் offline mock சூழ்நிலையும் live மூன்று-சூழ்நிலை
> suite-உம் இன்னும் மீண்டும் இயக்கப்படவில்லை. இந்தப் பதிப்புடன் bridge-ஐ நம்பிப் பயன்படுத்துவதற்கு முன் அவற்றை மீண்டும் இயக்கவும் ("நிலைநிறுத்தப்பட்ட கருவிகளைப் புதுப்பித்தல்" பகுதியைப் பார்க்கவும்).

## கட்டமைப்பு

```text
Claude Code 2.1.258 (தனிமைப்படுத்தப்பட்ட root அல்லாத Linux container)
  -> http://omniroute:20128/v1/messages
  -> devin-cli-agentic (Claude வடிவம், அங்கீகாரம் இல்லாத வழங்குநர்)
  -> devin acp --agent-type summarizer (அதிகாரப்பூர்வ ACP stdio, Devin கருவிகள் இல்லை)
  -> பிரத்யேக devin-auth volume-இல் உள்ள Devin கணக்கு
```

அதிகாரப்பூர்வ CLI-இன் இயல்புநிலை ACP agent அதன் சொந்தக் கருவிகளை இயக்க முடியும்; எனவே இந்த bridge அதைப்
பயன்படுத்தாது. இது கருவிகள் எதுவும் இல்லாத அதிகாரப்பூர்வ CLI பயன்முறையைக் கொண்ட, நிலையான `summarizer` ACP agent-ஐத் தொடங்கி,
தொடராக்கப்பட்ட Anthropic கோரிக்கையை ஓர் இயக்கத் தடமாக வடிவமைக்கிறது. Claude-க்குச் சொந்தமான மற்றொரு
செயல் தேவைப்படும்போது, பதிலில் துல்லியமாக ஒரு client tool envelope மட்டுமே இருக்க வேண்டும். எந்த ACP
`tool_call` அல்லது `tool_call_update`-உம் ஒரு பதிலை வெற்றிகரமானதாக அறிவிப்பதற்கு முன்பே நிராகரிக்கப்படும்.

`open-sse/executors/devin-agentic/serializer.ts`-இல் உள்ள serializer, `system`,
`text`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`, `tool_choice` மற்றும்
Claude Code வழங்கும் கருவிகளை மாற்றமின்றிப் பாதுகாக்கிறது. படங்களும் அறியப்படாத block-களும் வெளிப்படையாகத் தோல்வியடைகின்றன. பெரிய tool result-கள்
புலப்படும் truncation marker-ஐப் பயன்படுத்துகின்றன.

ஒவ்வொரு model turn-க்கும் தனியாக உள்ள ஒரு `<tool>{...}</tool>` envelope-ஐ parser ஏற்கிறது. இது
கோரிக்கையின் கருவிப் பட்டியலுடன் பெயரைச் சரிபார்த்து, அந்தக் கருவியின் JSON
Schema-க்கு எதிராக arguments-ஐச் சரிபார்த்து, narrative/action கலவைகளை நிராகரித்து, வரம்பிடப்பட்ட ஒரு திருத்தத்தை அனுமதிக்கிறது. பின்னர் Claude Code,
விளைவாக உருவான Anthropic `tool_use`-ஐ உள்ளகமாக இயக்கி, `tool_result`-ஐ OmniRoute வழியாக மீண்டும்
அனுப்புகிறது.

## தனிமைப்படுத்தலும் அச்சுறுத்தல் மாதிரியும்

host-இன் Claude நிறுவல், கணக்கு மற்றும் உள்ளமைவு ஆகியவை வரம்புக்கு வெளியே உள்ளவையாகவும்
தடைசெய்யப்பட்டவையாகவும் கருதப்படுகின்றன. Compose சேவைகள்:

- UID/GID `10001:10001` ஆக, படிக்க மட்டும் இயலும் root filesystem, நீக்கப்பட்ட capabilities மற்றும்
  `no-new-privileges` ஆகியவற்றுடன் இயங்குகின்றன;
- தனிப்பட்ட `/home/bridge`, பிரத்யேக Claude config volume, தனிமைப்படுத்தப்பட்ட OmniRoute data மற்றும்
  தனியான `devin-auth` volume ஆகியவற்றைப் பயன்படுத்துகின்றன;
- தற்காலிக `.sandbox` workspace-கள்/evidence ஆகியவற்றை மட்டுமே mount செய்கின்றன;
- host home, Keychain, SSH, cloud credentials அல்லது Docker socket ஆகியவற்றை mount செய்வதில்லை;
- வெளிப்படையான environment-களை உருவாக்கி, Anthropic API/OAuth/routing variable-களை நீக்குகின்றன;
- Claude Code inference-ஐ local-only key உடன் `http://omniroute:20128`-க்கு மட்டுமே வழிநடத்துகின்றன.

offline profile ஓர் internal network-ஐப் பயன்படுத்துகிறது. live profile-இல், OmniRoute அதிகாரப்பூர்வ
Devin endpoint-களை `network-guard` வழியாக மட்டுமே அணுகுகிறது; தொடர்பில்லாத destination-கள் மறுக்கப்படுகின்றன.
Claude Code-க்கு தனியான deny-all egress guard உள்ளது; மேலும் `NO_PROXY` வழியாக உள்ளக OmniRoute
service-ஐ மட்டுமே அது அணுக முடியும். Guard audit file-கள் அவற்றின் guard process மூலம் மட்டுமே mount செய்யப்படுகின்றன. token இல்லாத evidence-ஐ export செய்வதற்கு முன்,
script-கள் file ownership, mode, link count மற்றும் ஒவ்வொரு decision-ஐயும் சரிபார்க்கின்றன.

தனிமைப்படுத்தல் நிரூபணத்தைத் தனியாக இயக்கவும்:

```bash
./scripts/devin-bridge/verify-anthropic-isolation
```

இது topology, பெயரிடப்பட்ட mount-கள், root அல்லாத/read-only அமைப்புகள், வெளிப்படையான local routing,
முக்கியமான environment variable-கள் இல்லாமை, Docker socket இல்லாமை,
`api.anthropic.com` மற்றும் `claude.ai` ஆகியவற்றுக்கான தடுக்கப்பட்ட அணுகல், Devin-க்கு மட்டும் உரிய provider selection மற்றும்
ACP backend கிடைக்காதபோது ஏற்படும் வெளிப்படையான தோல்வி ஆகியவற்றைச் சரிபார்க்கிறது.

## முதல் முறை அமைப்பும் வழக்கமான பயன்பாடும்

நிலைப்படுத்தப்பட்ட image-ஐ build செய்யவும்:

```bash
./scripts/devin-bridge/build
```

தனிமைப்படுத்தப்பட்ட Devin volume-ஐ மட்டும் அங்கீகரிக்கவும்:

```bash
ENABLE_LIVE_DEVIN_TESTS=1 ./scripts/devin-bridge/login-devin
```

தொலைநிலை/container சூழல்களுக்காக வடிவமைக்கப்பட்ட அதிகாரப்பூர்வ manual-token நடைமுறையை login command பயன்படுத்துகிறது. மதிப்பு நேரடியாக CLI prompt-இல் உள்ளிடப்படுகிறது; அது process argument-ஆக அனுப்பப்படுவதோ, Git-இல் எழுதப்படுவதோ அல்லது host-இலிருந்து நகலெடுக்கப்படுவதோ இல்லை.

தனிமைப்படுத்தப்பட்ட Claude Code runtime-ஐத் தொடங்கவும்:

```bash
./scripts/devin-bridge/launch
```

container-மயமாக்கப்பட்ட Claude Code-ஐத் தொடங்குவதற்கு முன் `launch`, தனிமைப்படுத்தல், Devin அங்கீகாரம் மற்றும் model கண்டறிதல் ஆகியவற்றை மீண்டும் சரிபார்க்கிறது. இது host-இன் Claude executable-ஐ ஒருபோதும் இயக்காது. Model alias-களை `.env.devin-bridge`-இல் அமைக்கலாம்; உள்ளமைக்கப்பட்ட ஒவ்வொரு மதிப்பும் `devin-cli-agentic/` prefix-ஐத் தக்கவைத்திருக்க வேண்டும்.

## சரிபார்ப்புக் command-கள்

மீண்டும் உருவாக்கக்கூடிய offline பாதைக்கு Devin account தேவையில்லை; runtime Internet அணுகலும் இல்லை:

```bash
./scripts/devin-bridge/test-unit
./scripts/devin-bridge/test-contract
./scripts/devin-bridge/test-e2e-mock
```

ACP session-களை ஒரே நேரத்தில் அதிகளவில் திறப்பதைத் தவிர்க்க, live runner ஒவ்வொரு scenario-க்கும் இடையில் காத்திருந்து, உரை வடிவிலான கூற்றுகளை நம்புவதற்குப் பதிலாக கட்டமைக்கப்பட்ட Claude stream event-களைச் சரிபார்க்கிறது. அதன் மூன்று scenario-கள் பின்வருவனவற்றை நிரூபிக்கின்றன:

1. நேரடி project வாசிப்புகளும் defect பகுப்பாய்வும்;
2. உண்மையான `Edit`, client-க்குச் சொந்தமான `Bash` `npm test`, மற்றும் terminal முடிவு;
3. `/bridge-check` மற்றும் `bridge-proof` கண்டறிதல், project வாசிப்புகள், client-க்குச் சொந்தமான மற்றொரு வெற்றிகரமான `npm test`, மற்றும் நிலுவைப் பணி எதுவுமின்றி நிறைவு செய்தல்.

இறுதிக் gate, Devin network audit-ஐயும் சரிபார்த்து, Claude egress audit காலியாகவே இருக்க வேண்டும் எனக் கோருகிறது.

## நிலைப்படுத்தப்பட்ட கருவிகளைப் புதுப்பித்தல்

`docker/devin-bridge/Dockerfile`-இல் உள்ள image, Node, Claude Code மற்றும் Devin CLI ஆகியவற்றின் பதிப்புகளை நிலைப்படுத்துகிறது. புதுப்பிக்க:

1. வெளிப்படையாகக் குறிப்பிடப்பட்ட version-களை மாற்றவும்;
2. அதிகாரப்பூர்வ artifact-க்கான மதிப்புகளைக் கொண்டு architecture-க்கே உரிய இரு Devin archive checksum-களையும் மாற்றவும்;
3. மீண்டும் build செய்து, ஒவ்வொரு offline சரிபார்ப்புக் command-ஐயும் இயக்கவும்;
4. image-க்குள் உள்ள version-களை உறுதிப்படுத்தவும்;
5. அங்கீகரிக்கப்பட்ட மூன்று-scenario live suite-ஐ மீண்டும் இயக்கவும்.

இரு CLI-களில் எதையும் host-இல் global-ஆக install செய்ய வேண்டாம்; checksum சரிபார்ப்பைச் சரிபார்க்கப்படாத download-ஆல் மாற்றவும் வேண்டாம்.

## வரம்புகள்

- இந்த bridge, நிலையான கருவிகள்-இல்லாத `summarizer` role-ஐச் சார்ந்துள்ளது; ஏனெனில் Devin CLI `3000.2.17`, நடுநிலையான கருவிகள்-இல்லாத ACP agent-ஐ வெளிப்படுத்துவதில்லை. சுருக்க வடிவிலான இடைநிலைப் பதில்களை adapter ஈடுசெய்கிறது, ஆனால் வரம்புக்குட்பட்ட ஒரு பழுதுநீக்க முயற்சியும் வெளிப்படையாகத் தோல்வியடையலாம்.
- நேரடி ACP அழைப்புகள் தற்காலிகமான `502`/`504` பதில்களை வழங்கலாம். harness, scenarios-க்கு இடையில் கால இடைவெளி விடுகிறது; தொடர்ச்சியான தோல்வி ஏற்பட்டால், அது fail-closed நிலையில் நீடிக்கும் மற்றும் வேறொரு provider-ஐ ஒருபோதும் தேர்ந்தெடுக்காது.
- ஒவ்வொரு Anthropic request-இலிருந்தும் ACP context மீண்டும் உருவாக்கப்படுகிறது; process/session affinity எதுவும் இல்லை.
- ஒரு model response-க்கு ஒரு tool call மட்டுமே ஆதரிக்கப்படுகிறது; parallel calls நிராகரிக்கப்படுகின்றன.
- Images வெளிப்படையாக ஆதரிக்கப்படவில்லை. Vision, thinking output, effort controls மற்றும் 1M context window ஆகியவை விளம்பரப்படுத்தப்படுவதில்லை.
- SSE செல்லுபடியாகும் Anthropic lifecycle events-ஐப் பயன்படுத்துகிறது, ஆனால் வரம்புக்குட்பட்ட ACP turn சேகரிக்கப்பட்ட பிறகே வெளியிடப்படுகிறது; ACP chunks படிப்படியாக அனுப்பப்படுவதில்லை.
