OmniRoute தனது உள்ளூர் சேவையகத்தை (`http://localhost:20128`) மூன்று tunnel பின்தளங்கள் வழியாகப் பொது
இணையத்திற்கு வெளிப்படுத்த முடியும். இது பின்வருவனவற்றுக்குப் பயனுள்ளதாக இருக்கும்:

- பொதுவாக அணுகக்கூடிய redirect URL தேவைப்படும் cloud வழங்குநர்களின் (Antigravity, Gemini, Cursor)
  OAuth callback-கள்.
- VM ஒன்றை deploy செய்யாமல், உங்கள் உள்ளூர் instance-ஐ குழு உறுப்பினர்களுடன் பகிர்தல்.
- மொபைல், தொலைநிலை அல்லது வெவ்வேறு நெட்வொர்க்குகளுக்கு இடையிலான சோதனை.

மூன்று பின்தளங்களும் process-க்குள்ளேயே நிர்வகிக்கப்படுகின்றன — dashboard அல்லது REST API-இலிருந்து
அடிப்படை binary அல்லது SDK-ஐ OmniRoute தொடங்குகிறது/நிறுத்துகிறது. Reverse-proxy அல்லது systemd
அமைப்பு தேவையில்லை.

## 1. Cloudflare Tunnel (Quick Tunnel + Named Tunnel)

`src/lib/cloudflaredTunnel.ts`, `cloudflared`-ஐ ஒரு child process ஆக இயக்குகிறது. Named-tunnel config வழங்கப்பட்டுள்ளதா என்பதைப் பொறுத்து தேர்ந்தெடுக்கப்படும்
இரண்டு முறைகளை இது ஆதரிக்கிறது:

- **Quick tunnel (இயல்புநிலை).** `cloudflared tunnel --url
http://localhost:<apiPort>`-ஐ இயக்கி, ஒதுக்கப்பட்ட `*.trycloudflare.com` URL-ஐ
  stdout-இலிருந்து பிரித்தெடுக்கிறது. URL-கள் தற்காலிகமானவை; ஒவ்வொரு மறுதொடக்கத்திலும் மாறும்.
- **Named tunnel (விருப்பத்தேர்வு).** `CLOUDFLARED_CONFIG`, உள்ளூரில் நிர்வகிக்கப்படும்
  cloudflared `config.yml`-ஐச் சுட்டும்போது, OmniRoute `cloudflared tunnel --no-autoupdate
--config <path> run`-ஐ இயக்கி, உங்களுக்கு ஒரு **நிலையான, பெயரிடப்பட்ட hostname**-ஐ வழங்குகிறது. அந்த config,
  tunnel UUID, `credentials-file`, மற்றும் `ingress` routing ஆகியவற்றை வழங்குவதால்,
  `--url` அனுப்பப்படாது; Zero Trust dashboard token-மும் தேவையில்லை. `run`, config-இன் முழுமையான `credentials-file` path-இலிருந்து
  credentials-ஐப் படிக்கிறது — `cert.pem`
  தேவையில்லை (அது tunnel lifecycle நிர்வாகத்திற்கு மட்டுமே பயன்படுத்தப்படுகிறது).

முக்கிய நடத்தைகள்:

- **தானியங்கு நிறுவல்.** முதல் பயன்பாட்டின்போது, அதிகாரப்பூர்வ GitHub releases-இலிருந்து சமீபத்திய `cloudflared`
  binary-ஐ OmniRoute பதிவிறக்குகிறது (நிர்வகிக்கப்படும் நிறுவல்
  `DATA_DIR/cloudflared/`-இன் கீழ் இருக்கும்). பதிவிறக்கப்பட்ட asset-இன் SHA256, இயக்கப்படுவதற்கு முன்
  release manifest-க்கு எதிராகச் சரிபார்க்கப்படும்.
- **Process மேற்பார்வை.** Dashboard reload-களுக்கிடையிலும் status-ஐத் தொடர்வதற்காக,
  cloudflared PID மற்றும் கண்டறியப்பட்ட URL ஆகியவை
  `quick-tunnel-state.json`-இல் நிலையாகச் சேமிக்கப்படுகின்றன.

### Named tunnel அமைப்பு (நிலையான hostname)

1. Cloudflared CLI மூலம் உள்ளூரில் நிர்வகிக்கப்படும் tunnel ஒன்றை உருவாக்கவும் (ஒருமுறை மட்டும்):

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create omniroute
   cloudflared tunnel route dns omniroute ai.example.com
   ```

2. உங்கள் hostname-ஐ OmniRoute-இன் உள்ளூர்
   API port-க்கு (இயல்புநிலை 20128) route செய்யும் `~/.cloudflared/config.yml`-ஐ எழுதவும்:

   ```yaml
   tunnel: <UUID-from-create>
   credentials-file: /home/you/.cloudflared/<UUID>.json
   ingress:
     - hostname: ai.example.com
       service: http://127.0.0.1:20128
     - service: http_status:404
   ```

3. OmniRoute-ஐ அந்த config-ஐச் சுட்டுமாறு அமைத்து, tunnel-ஐ (மறு)தொடக்கம் செய்யவும்:

   ```bash
   export CLOUDFLARED_CONFIG="/home/you/.cloudflared/config.yml"
   # விருப்பத்தேர்வு — OmniRoute தெரிவிக்கும் hostname-ஐ மேலெழுதுகிறது; இல்லையெனில்
   # config-இன் முதல் ingress விதியிலிருந்து படிக்கப்படும்:
   # export CLOUDFLARED_HOSTNAME="ai.example.com"
   ```

   Quick tunnel-ஐ இயக்கும் அதே முறையில் tunnel-ஐ இயக்கவும் (கீழே உள்ள REST / dashboard / CLI
   வழியாக). Named tunnel-இலிருந்து பிரித்தெடுக்கக்கூடிய public URL வெளிவராது; எனவே cloudflared-இன் பதிவு செய்யப்பட்ட edge connection மூலம் தயார்நிலை கண்டறியப்படுகிறது. மேலும் `publicUrl`/`apiUrl` ஆகியவை
   `CLOUDFLARED_HOSTNAME`-இலிருந்து (அல்லது config-இன் முதல் ingress hostname-இலிருந்து) தெரிவிக்கப்படுகின்றன.

### REST வழியாக இயக்குதல் / முடக்குதல்

இந்த endpoint, தனித்தனி `start`/`stop` path-களுக்குப் பதிலாக `{action: "enable" | "disable"}` body-ஐப் பயன்படுத்துகிறது.
Management auth (admin session அல்லது admin API key) தேவை.

```bash
# இயக்கவும்
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# நிலை
curl http://localhost:20128/api/tunnels/cloudflared \
  -H "Cookie: auth_token=..."

# முடக்கவும்
curl -X POST http://localhost:20128/api/tunnels/cloudflared \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

அல்லது dashboard வழியாக: **Settings → Tunnels → Cloudflare**.

### விருப்ப env vars

| மாறி                                                 | நோக்கம்                                                                                                                                                                                                                    |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CLOUDFLARED_BIN`                                    | பைனரி பாதையை மேலெழுதுகிறது. இது அமைக்கப்பட்டு செல்லுபடியாக இருந்தால், பதிவிறக்குவதற்குப் பதிலாக OmniRoute இதைப் பயன்படுத்தும்.                                                                                             |
| `CLOUDFLARED_PROTOCOL` / `TUNNEL_TRANSPORT_PROTOCOL` | போக்குவரத்து நெறிமுறை (இயல்புநிலை `http2`; மேலும் `quic`, `auto`).                                                                                                                                                         |
| `CLOUDFLARED_CONFIG`                                 | உள்ளூரில் நிர்வகிக்கப்படும் cloudflared `config.yml` கோப்புக்கான பாதை. இது அமைக்கப்பட்டால், விரைவுச் சுரங்கத்திற்குப் பதிலாக OmniRoute ஒரு **பெயரிடப்பட்ட/நிரந்தரமான** சுரங்கத்தை (`tunnel --config <path> run`) இயக்கும். |
| `CLOUDFLARED_HOSTNAME`                               | பெயரிடப்பட்ட சுரங்கம் தெரிவிக்கும் பொது ஹோஸ்ட்பெயரை மேலெழுதுகிறது (எ.கா. `ai.example.com`). இது அமைக்கப்படாதபோது, கட்டமைப்பின் முதல் `ingress` ஹோஸ்ட்பெயரிலிருந்து படிக்கப்படும்.                                          |

## 2. ngrok

`src/lib/ngrokTunnel.ts` ஆனது **`@ngrok/ngrok` SDK**-ஐப் பயன்படுத்துகிறது (செயல்முறைக்குள்ளேயே இயங்கும்; CLI துணைச் செயல்முறை இல்லை). முன்கூட்டியே கட்டமைக்கப்பட்ட பைனரிகள் இல்லாத தளங்களில் செயலி தொடங்கும்போது செயலிழக்காமல் இருப்பதற்காக, முதல் தொடக்கத்தின்போது மட்டுமே நேட்டிவ் மாட்யூல் இறக்குமதி செய்யப்படுகிறது.

### முன்தேவைகள்

1. <https://ngrok.com> இல் பதிவு செய்யவும்.
2. ngrok டாஷ்போர்டிலிருந்து உங்கள் authtoken-ஐ நகலெடுக்கவும்.
3. பின்வரும் வழிகளில் ஏதேனும் ஒன்றின் மூலம் அதை வழங்கவும்:
   - `.env`: `NGROK_AUTHTOKEN=<token>`, அல்லது
   - டாஷ்போர்டு: **Settings → Tunnels → ngrok**, அல்லது
   - REST கோரிக்கை உடல் (ஒருமுறை மட்டும்): `{"action":"enable","authToken":"<token>"}`.

இவற்றில் எதுவும் உள்ளமைக்கப்படவில்லை என்றால், நிலை `phase: "needs_auth"` என்பதை வழங்கும்.

### REST வழியாக இயக்குதல் / முடக்குதல்

```bash
# இயக்குதல் (env-இலிருந்து NGROK_AUTHTOKEN-ஐப் பயன்படுத்துகிறது)
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable"}'

# இன்லைன் டோக்கனுடன் இயக்குதல்
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"enable","authToken":"2abc..."}'

# நிலை
curl http://localhost:20128/api/tunnels/ngrok \
  -H "Cookie: auth_token=..."

# முடக்குதல்
curl -X POST http://localhost:20128/api/tunnels/ngrok \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"action":"disable"}'
```

பதிலில் ஒதுக்கப்பட்ட `publicUrl` சேர்க்கப்பட்டிருக்கும் (எ.கா.
`https://abcd-1234.ngrok-free.app`). தனிப்பயன் டொமைன்கள், பிராந்தியங்கள் மற்றும் கொள்கை விதிகள்
ngrok டாஷ்போர்டில் உள்ளமைக்கப்பட வேண்டும் — OmniRoute ஆனது உள்ளூர் இலக்கு URL-ஐ
SDK-க்கு அனுப்புவது மட்டுமே செய்கிறது.

## 3. Tailscale Funnel

`src/lib/tailscaleTunnel.ts` ஆனது **Funnel** வழியாக உள்ளூர் API போர்ட்டை வெளிப்படுத்த,
கணினியின் `tailscale` CLI-ஐ ஒருங்கிணைக்கிறது (serve-க்கான Tailscale-இன் பொது இணைய வெளியேற்றம்).
நிறுவுதல், உள்நுழைதல், டீமனைத் தொடங்குதல், இயக்குதல், முடக்குதல் ஆகிய முழு வாழ்க்கைச் சுழற்சியையும் இது ஆதரிக்கிறது.

இந்தச் செயலாக்கம் `tailscale funnel --bg <port>`-ஐ (பின்னணிப் பயன்முறை) இயக்குகிறது.
பொது URL ஆனது `https://<machine>.<tailnet>.ts.net/` என்ற வடிவத்தைக் கொண்டுள்ளது.

### முன்தேவைகள்

1. Tailscale-ஐ நிறுவவும் (அல்லது OmniRoute அதைச் செய்ய அனுமதிக்கவும் — கீழே உள்ள `install` என்ட்பாயிண்டைப் பார்க்கவும்).
2. உள்நுழையவும் (`tailscale login` அல்லது OmniRoute-இன் `login` என்ட்பாயிண்ட் வழியாக).
3. Tailscale நிர்வாகக் கன்சோலில் உங்கள் tailnet-க்கான Funnel-ஐ இயக்கவும்:
   <https://login.tailscale.com/admin/settings/features>.

Linux மற்றும் macOS-இல் டீமனை (`tailscaled`) கட்டுப்படுத்த `sudo` தேவைப்படுகிறது.
POST என்ட்பாயிண்ட்கள் விருப்பத்திற்குரிய `sudoPassword` புலத்தை ஏற்கின்றன; அழைப்பின் கால அளவிற்கு
அது OmniRoute-இன் MITM கடவுச்சொல் தற்காலிகச் சேமிப்பகத்திற்கு (`getCachedPassword` / `setCachedPassword`)
அனுப்பப்படுகிறது. Windows ஆனது `C:\Program Files\Tailscale\tailscale.exe`-இல் உள்ள
இயல்புநிலை சேவை நிறுவலைப் பயன்படுத்துகிறது.

### REST என்ட்பாயிண்ட்கள்

நிறுவுதல், உள்நுழைதல், டீமன் மற்றும் டன்னல் ஆகியவை தனித்தனி செயல்பாடுகள் என்பதால்,
மற்ற பேக்கெண்ட்களைவிட Tailscale அதிக அம்சங்களைக் கொண்ட இடைமுகத்தை வழங்குகிறது.

| என்ட்பாயிண்ட்                         | முறை   | நோக்கம்                                                                                     |
| ------------------------------------- | ------ | ------------------------------------------------------------------------------------------- |
| `/api/tunnels/tailscale`              | `GET`  | ஒருங்கிணைக்கப்பட்ட டன்னல் நிலை (`phase`, `tunnelUrl`, `apiUrl` போன்றவை)                     |
| `/api/tunnels/tailscale/check`        | `GET`  | கீழ்நிலைச் சோதனை: நிறுவப்பட்டுள்ளதா? உள்நுழைந்துள்ளதா? டீமன் இயங்குகிறதா?                   |
| `/api/tunnels/tailscale/install`      | `POST` | Tailscale-ஐ நிறுவுதல் (SSE வழியாக ஸ்ட்ரீம் செய்யப்படும் முன்னேற்ற நிகழ்வுகள்) — Linux/macOS |
| `/api/tunnels/tailscale/start-daemon` | `POST` | Linux/macOS-இல் `tailscaled`-ஐத் தொடங்குதல்                                                 |
| `/api/tunnels/tailscale/login`        | `POST` | உள்நுழைவு ஓட்டத்தைத் தொடங்குதல்; உலாவியில் திறப்பதற்கான `authUrl`-ஐ வழங்கும்                |
| `/api/tunnels/tailscale/enable`       | `POST` | API போர்ட்டிற்கான Funnel-ஐத் தொடங்குதல்                                                     |
| `/api/tunnels/tailscale/disable`      | `POST` | Funnel-ஐ நிறுத்துதல்                                                                        |

அனைத்து Tailscale என்ட்பாயிண்ட்களுக்கும் மேலாண்மை அங்கீகாரம் தேவை (`routeUtils.ts ::
requireTailscaleAuth`-ஐப் பார்க்கவும்).

இயக்குவதற்கான எடுத்துக்காட்டு:

```bash
curl -X POST http://localhost:20128/api/tunnels/tailscale/enable \
  -H "Content-Type: application/json" \
  -H "Cookie: auth_token=..." \
  -d '{"sudoPassword":"<linux-pwd>","port":20128}'
```

நிர்வாகக் கன்சோலில் Funnel இயக்கப்படவில்லை என்றால், பதிலில்
`funnelNotEnabled: true` மற்றும் உலாவியில் திறப்பதற்கான `enableUrl` சேர்க்கப்பட்டிருக்கும்.

### விருப்பத்திற்குரிய env மாறிகள்

| மாறி            | நோக்கம்                                 |
| --------------- | --------------------------------------- |
| `TAILSCALE_BIN` | `tailscale` பைனரி பாதையை மாற்றியமைத்தல் |

## எண்ட்பாயிண்ட் சுருக்கம்

| எண்ட்பாயிண்ட்                         | முறை   | உடற்பகுதி                           | அங்கீகாரம் |
| ------------------------------------- | ------ | ----------------------------------- | ---------- |
| `/api/tunnels/cloudflared`            | `GET`  | —                                   | management |
| `/api/tunnels/cloudflared`            | `POST` | `{action: "enable" \| "disable"}`   | management |
| `/api/tunnels/ngrok`                  | `GET`  | —                                   | management |
| `/api/tunnels/ngrok`                  | `POST` | `{action, authToken?}`              | management |
| `/api/tunnels/tailscale`              | `GET`  | —                                   | management |
| `/api/tunnels/tailscale/check`        | `GET`  | —                                   | management |
| `/api/tunnels/tailscale/install`      | `POST` | `{sudoPassword?}` (SSE)             | management |
| `/api/tunnels/tailscale/start-daemon` | `POST` | `{sudoPassword?}`                   | management |
| `/api/tunnels/tailscale/login`        | `POST` | `{hostname?}`                       | management |
| `/api/tunnels/tailscale/enable`       | `POST` | `{sudoPassword?, hostname?, port?}` | management |
| `/api/tunnels/tailscale/disable`      | `POST` | `{sudoPassword?}`                   | management |

மையப்படுத்தப்பட்ட `/api/settings/tunnels` எண்ட்பாயிண்ட் எதுவும் இல்லை — ஒவ்வொரு பின்தளமும்
தனித்தனியாகச் செயல்படுகிறது.

## OAuth கால்பேக் தொடர்பான கருத்துகள்

ஒரு டன்னல் வழியாக OmniRoute-ஐ வெளிப்படுத்தும்போது, டாஷ்போர்டும் OAuth செயல்முறைகளும்
கால்பேக் URL-களை `localhost`-க்கு எதிராக அல்லாமல் **பொது** ஹோஸ்ட்பெயருக்கு எதிராக
உருவாக்க வேண்டும். இல்லையெனில், OAuth வழங்குநர் தனது சேவையகங்களால் அணுக முடியாத
ஒரு URL-க்கு பயனரைத் திருப்பிவிடுவதால், ஹேண்ட்ஷேக் தோல்வியடையும்.

டாஷ்போர்டு திருத்தங்களுக்கும் அமைப்புகளைச் சேமிப்பதற்கும் டன்னல் ஹோஸ்ட்பெயரை
`NEXT_PUBLIC_BASE_URL`-இல் நிலைநிறுத்த வேண்டியதில்லை. அங்கீகரிக்கப்பட்ட டாஷ்போர்டு,
அமர்வுடன் பிணைக்கப்பட்ட CSRF டோக்கனைக் கொண்டு அதே மூலத்திற்கான பாதுகாப்பற்ற
கோரிக்கைகளை அனுப்புகிறது. எனவே, உள்நுழைந்த பிறகு வழக்கமான UI நிர்வாகத்திற்கு
தற்காலிக Cloudflare Quick Tunnel ஹோஸ்ட்களையும் பயன்படுத்தலாம்.

இதை அமைக்கவும்:

```bash
NEXT_PUBLIC_BASE_URL=https://<your-tunnel-host>
```

OAuth-ஐத் தொடங்குவதற்கு முன் OmniRoute-ஐ மறுதொடக்கம் செய்யவும். தற்காலிக Cloudflare Quick
Tunnels-இல் ஒவ்வொரு மறுதொடக்கத்திற்குப் பிறகும் URL மாறுவதால், தயாரிப்புச் சூழல் OAuth
பயன்பாட்டிற்கு முன்பதிவு செய்யப்பட்ட டொமைனுடன் ngrok அல்லது Tailscale Funnel-ஐப்
பயன்படுத்துவது சிறந்தது.

## ஆரோக்கிய நிலையும் கண்காணிப்பும்

டாஷ்போர்டு, **Settings → Tunnels** என்பதன் கீழ் டன்னல் நிலையைக் காட்டுகிறது:

- செயலில் உள்ள பின்தளம் அல்லது பின்தளங்கள் மற்றும் தற்போதைய `phase` (`stopped`, `starting`, `running`,
  `needs_auth`, `error`).
- தற்போதைய பொது URL மற்றும் அதிலிருந்து பெறப்பட்ட API URL (`<publicUrl>/v1`).
- டன்னல் கோரிக்கைகளை அனுப்பும் உள்ளூர் இலக்கு URL.
- கடைசிப் பிழைச் செய்தி, ஏதேனும் இருந்தால்.

நிரல் வழிக் கண்காணிப்பிற்கு, ஒவ்வொரு பின்தளத்திற்குமான `GET` எண்ட்பாயிண்ட்களையும்
தொடர்ந்து வினவவும். ஒரே நேரத்தில் ஒன்றுக்கு மேற்பட்ட பின்தளங்களை இயக்கலாம்; OmniRoute
ஒவ்வொன்றையும் தனித்தனியாகக் கண்காணிக்கும்.

## சிக்கல் தீர்வு

### "cloudflared பைனரி கிடைக்கவில்லை"

முதல் பயன்பாட்டின்போது OmniRoute தானாக நிறுவ முயற்சிக்கிறது. நிறுவல் தடுக்கப்பட்டிருந்தால்
(கட்டுப்படுத்தப்பட்ட நெட்வொர்க், GitHub அணுகல் இல்லை), `cloudflared`-ஐ
<https://github.com/cloudflare/cloudflared/releases> இலிருந்து கைமுறையாகப் பதிவிறக்கி,
`CLOUDFLARED_BIN=/path/to/cloudflared` என அமைக்கவும்.

### "ngrok: authtoken தேவை"

`phase: "needs_auth"` என்பது authtoken எதுவும் கிடைக்கவில்லை என்பதைக் குறிக்கிறது.
`.env`-இல் `NGROK_AUTHTOKEN`-ஐ அமைக்கவும், டாஷ்போர்டு வழியாக அதை உள்ளமைக்கவும்,
அல்லது enable POST உடற்பகுதியில் `authToken`-ஐ அனுப்பவும்.

### "tailscale: funnel செயல்படுத்தப்படவில்லை"

enable பதிலில் `funnelNotEnabled: true` இடம்பெற்றிருந்தால், உங்கள் tailnet-க்கு Funnel
முடக்கப்பட்டுள்ளது. திருப்பியளிக்கப்பட்ட `enableUrl`-ஐ (அல்லது நிர்வாக கன்சோலின் அம்சப்
பக்கத்தை) திறந்து Funnel-ஐ இயக்கவும்.

### டன்னல் URL மாற்றங்கள் OAuth-ஐ செயலிழக்கச் செய்கின்றன

முன்பதிவு செய்யப்பட்ட டொமைனுடன் ngrok அல்லது Tailscale Funnel-ஐப் பயன்படுத்தவும்
(இரண்டுமே ஒவ்வொரு நோடுக்கும் நிலையானவை). Cloudflare Quick Tunnels வடிவமைப்பிலேயே
தற்காலிகமானவை; நீண்டகால OAuth கால்பேக்குகளுக்கு அவை பரிந்துரைக்கப்படுவதில்லை.

### Tailscale-க்கான Linux/macOS அனுமதி மறுக்கப்பட்டது

`tailscaled`-க்கு root அனுமதி தேவை. தொடர்புடைய POST எண்ட்பாயிண்டிற்கு
`sudoPassword`-ஐ வழங்கவும் அல்லது டீமானை நீங்களே இயக்கவும்
(`sudo systemctl start tailscaled`).
