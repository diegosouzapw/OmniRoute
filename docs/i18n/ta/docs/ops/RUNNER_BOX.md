## ஜானிட்டரை நிறுவுதல் (ஒருமுறை மட்டும், பெட்டியில்)

```bash
scp scripts/ops/runner-janitor.sh root@192.168.0.113:/opt/omniroute-ops/runner-janitor.sh
ssh root@192.168.0.113 'chmod +x /opt/omniroute-ops/runner-janitor.sh; apt-get install -y lsof'
# cron (root): ஒவ்வொரு 30 நிமிடத்திற்கும், /var/log/runner-janitor.log இல் பதிவுசெய்யவும்
*/30 * * * * MAX_ACTIVE_RUNNERS=6 /opt/omniroute-ops/runner-janitor.sh >> /var/log/runner-janitor.log 2>&1
```

`lsof` தேவைப்படுகிறது: ஒரு பாதையை அகற்றுவதற்கு முன் திறந்துள்ள
கோப்புகளின் ஒரே snapshot மூலம் அது செயலற்றிருப்பதை ஜானிட்டர் உறுதிசெய்கிறது; இந்தக் கருவி இல்லாமல் அது எதையும் அகற்றாது,
அதையும் தெரிவிக்கும்
(exit 1). எந்த மாற்றத்தையும் முதலில் `--dry-run` உடன் முயற்சிக்கவும் — அது என்ன
செய்யும் என்பதைத் துல்லியமாக அச்சிடும்; எதையும் மாற்றாது.

ஒவ்வொரு இயக்கத்திலும் இது செய்வது: **tmpfs இல் 3 மணிநேரத்திற்குப்** பிறகும் வட்டின்
`_work/_temp` இல் 24 மணிநேரத்திற்குப் பிறகும் நமது சொந்த எஞ்சியவற்றை (`runner-*`, `omniroute-*`,
`next-build*`, `e2e-build.tar.gz`) அகற்றுகிறது; 75 நிமிடங்களுக்கு மேல் பழைய `next-build` ஒன்றை
நிறுத்துகிறது (எந்தப் பணியும் அவ்வளவு நேரம் இயங்காது — 2026-08-27 அன்று GitHub அதன் பணி
இழக்கப்பட்டதாக அறிவித்த பிறகும் ஒன்று 70 நிமிடங்கள் இயங்கியது); unit **நிறுத்தப்பட்டுள்ள** ரன்னர்களின்
48 மணிநேரம் பழைய செக்அவுட்களை அகற்றுகிறது; வட்டு ≥ 85 %, நினைவக PSI
`full/avg60` ≥ 10 %, மற்றும் `MAX_ACTIVE_RUNNERS` ஐ விட அதிகமான லிஸ்னர்கள் இருந்தால் எச்சரிக்கிறது
(omniroute/மற்றவை என்ற பிரிவுடன்). Exit 1 = கவனம் தேவை; பதிவைப் படிக்கவும்.

## ரன்னர் யூனிட்டுகள்: KillMode

ரன்னரின் இயல்புநிலை `KillMode=process`, ஒரு யூனிட் நிறுத்தப்படும்போதோ மறுதொடக்கம் செய்யப்படும்போதோ `Runner.Worker → npm → next-build`-ஐ
இயங்கிக்கொண்டிருக்க விட்டுவிடுகிறது — எந்த ஜாப்புடனும் இணைக்கப்படாத ஓர் அனாதை பில்ட் தொடர்ந்து RAM மற்றும்
CPU-ஐப் பயன்படுத்திக்கொண்டிருக்கும். ஒவ்வொரு OmniRoute யூனிட்டிலும்
(`/etc/systemd/system/actions.runner.diegosouzapw-OmniRoute.<name>.service.d/10-killmode.conf`)
என்ற drop-in, `KillMode=mixed` உடன் உள்ளது: முதலில் listener-க்கு SIGTERM, பின்னர்
`TimeoutStop`-இல் முழு cgroup-க்கும் SIGKILL. யூனிட்டின் அடுத்த மறுதொடக்கத்தில் இது நடைமுறைக்கு வரும் — **ஒரு நேரத்தில் ஒரு ரன்னரை மட்டும்,
அது idle-ஆக இருக்கும்போது மட்டும்** மறுதொடக்கம் செய்யவும்; idle சரிபார்ப்பையும் மறுதொடக்கத்தையும் ஒரே command-இல் செய்யவும்.

  பதிவுசெய்தல் இல்லை): `ci.yml` `Build`, `npm-publish.yml` `publish`, இரண்டு

  `omniroute-113-5`-இல் இருக்க வேண்டும் (`docker info` என்பது publish
  ஜாப்பின் முதல் படி). முன்பு உச்சவரம்பு இரண்டு என இருந்தது; 31 GB-க்கு அது தவறானது:
