Cloudflare மூலம் நிர்வகிக்கப்படும் டொமைனுடன் ஒரு VM (VPS)-இல் OmniRoute-ஐ நிறுவி உள்ளமைப்பதற்கான முழுமையான வழிகாட்டி.

## முன்நிபந்தனைகள்

| உருப்படி   | குறைந்தபட்சம்                     | பரிந்துரைக்கப்படுவது |
| ---------- | --------------------------------- | -------------------- |
| **CPU**    | 1 vCPU                            | 2 vCPU               |
| **RAM**    | 1 GB                              | 2 GB                 |
| **வட்டு**  | 10 GB SSD                         | 25 GB SSD            |
| **OS**     | Ubuntu 22.04 LTS                  | Ubuntu 24.04 LTS     |
| **டொமைன்** | Cloudflare-இல் பதிவுசெய்யப்பட்டது | —                    |
| **Docker** | Docker Engine 24+                 | Docker 27+           |

**சோதிக்கப்பட்ட வழங்குநர்கள்**: Akamai (Linode), DigitalOcean, Vultr, Hetzner, AWS Lightsail.

## 1. VM-ஐ உள்ளமைக்கவும்

### 1.1 இன்ஸ்டன்ஸை உருவாக்கவும்

உங்களுக்கு விருப்பமான VPS வழங்குநரில்:

- Ubuntu 24.04 LTS-ஐத் தேர்ந்தெடுக்கவும்
- குறைந்தபட்சத் திட்டத்தைத் தேர்ந்தெடுக்கவும் (1 vCPU / 1 GB RAM)
- வலுவான root கடவுச்சொல்லை அமைக்கவும் அல்லது SSH விசையை உள்ளமைக்கவும்
- **பொது IP** முகவரியைக் குறித்துக்கொள்ளவும் (எ.கா., `203.0.113.10`)

### 1.2 SSH வழியாக இணைக்கவும்

```bash
ssh root@203.0.113.10
```

### 1.3 கணினியைப் புதுப்பிக்கவும்

```bash
apt update && apt upgrade -y
```

### 1.4 Docker-ஐ நிறுவவும்

```bash
# சார்புகளை நிறுவவும்
apt install -y ca-certificates curl gnupg

# அதிகாரப்பூர்வ Docker களஞ்சியத்தைச் சேர்க்கவும்
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | gpg --dearmor -o /etc/apt/keyrings/docker.gpg
chmod a+r /etc/apt/keyrings/docker.gpg
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] https://download.docker.com/linux/ubuntu $ (. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null
apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

### 1.5 nginx-ஐ நிறுவவும்

```bash
apt install -y nginx
```

### 1.6 Firewall-ஐ (UFW) உள்ளமைக்கவும்

```bash
ufw default deny incoming
ufw default allow outgoing
ufw allow 22/tcp    # SSH
ufw allow 80/tcp    # HTTP (திசைமாற்றம்)
ufw allow 443/tcp   # HTTPS
ufw enable
```

> **உதவிக்குறிப்பு**: அதிகபட்சப் பாதுகாப்புக்காக, 80 மற்றும் 443 போர்ட்களை Cloudflare IP முகவரிகளுக்கு மட்டும் கட்டுப்படுத்தவும். [மேம்பட்ட பாதுகாப்பு](#advanced-security) பகுதியைப் பார்க்கவும்.

## 2. OmniRoute-ஐ நிறுவவும்

### 2.1 உள்ளமைவு கோப்பகத்தை உருவாக்கவும்

```bash
mkdir -p /opt/omniroute
```

### 2.2 சூழல் மாறிகள் கோப்பை உருவாக்கவும்

```bash
cat > /opt/omniroute/.env << 'EOF'
# === பாதுகாப்பு ===
JWT_SECRET=CHANGE-TO-A-UNIQUE-64-CHAR-SECRET-KEY
INITIAL_PASSWORD=YourSecurePassword123!
API_KEY_SECRET=REPLACE-WITH-ANOTHER-SECRET-KEY
STORAGE_ENCRYPTION_KEY=REPLACE-WITH-THIRD-SECRET-KEY
STORAGE_ENCRYPTION_KEY_VERSION=v1
MACHINE_ID_SALT=CHANGE-TO-A-UNIQUE-SALT
OMNIROUTE_WS_BRIDGE_SECRET=REPLACE-WITH-WS-BRIDGE-SECRET  # production சூழலில் தேவை: Codex Responses WS bridge பயன்படுத்துகிறது

# === செயலி ===
PORT=20128
NODE_ENV=production
HOSTNAME=0.0.0.0
DATA_DIR=/app/data
APP_LOG_TO_FILE=true
AUTH_COOKIE_SECURE=true
REQUIRE_API_KEY=false

# === URL-கள் (உங்கள் டொமைனுக்கு மாற்றவும்) ===
# திட்டமிடப்பட்ட பணிகள் / சுயப் பெறுதல்களுக்கான உள் சேவையகத்திலிருந்து சேவையகத்திற்கான அடிப்படை URL.
BASE_URL=http://127.0.0.1:20128
# OAuth callback-கள், dashboard இணைப்புகள் மற்றும் உருவாக்கப்பட்ட பொது URL-களுக்குப் பயன்படுத்தப்படும் உலாவி நோக்கிய URL.
NEXT_PUBLIC_BASE_URL=https://llms.seudominio.com
# உருவாக்கப்பட்ட பொது asset URL-களுக்கான விருப்பமான வெளிப்படையான பொது origin override.
# OMNIROUTE_PUBLIC_BASE_URL=https://llms.seudominio.com

# === Cloud Sync (விருப்பத்தேர்வு) ===
# CLOUD_URL=https://cloud.omniroute.online
# NEXT_PUBLIC_CLOUD_URL=https://cloud.omniroute.online
EOF
```

> ⚠️ **முக்கியம்**: தனித்துவமான இரகசிய விசைகளை உருவாக்கவும்! ஒவ்வொரு விசைக்கும் `openssl rand -hex 32`-ஐப் பயன்படுத்தவும்.

### 2.3 container-ஐத் தொடங்கவும்

```bash
docker pull diegosouzapw/omniroute:latest

docker run -d \
  --name omniroute \
  --restart unless-stopped \
  --env-file /opt/omniroute/.env \
  -p 20128:20128 \
  -v omniroute-data:/app/data \
  diegosouzapw/omniroute:latest
```

### 2.4 அது இயங்குகிறதா என்பதைச் சரிபார்க்கவும்

```bash
docker ps | grep omniroute
docker logs omniroute --tail 20
```

இது `[DB] SQLite database ready` மற்றும் `listening on port 20128` ஆகியவற்றைக் காட்ட வேண்டும்.

## 3. nginx-ஐ உள்ளமைக்கவும் (Reverse Proxy)

### 3.1 SSL சான்றிதழை உருவாக்கவும் (Cloudflare Origin)

Cloudflare கட்டுப்பாட்டுப் பலகையில்:

1. **SSL/TLS → Origin Server** என்பதற்குச் செல்லவும்
2. **Create Certificate** என்பதைக் கிளிக் செய்யவும்
3. இயல்புநிலை மதிப்புகளை அப்படியே வைத்திருக்கவும் (15 ஆண்டுகள், \*.yourdomain.com)
4. **Origin Certificate** மற்றும் **Private Key** ஆகியவற்றை நகலெடுக்கவும்

```bash
mkdir -p /etc/nginx/ssl

# சான்றிதழை ஒட்டவும்
nano /etc/nginx/ssl/origin.crt

# தனிப்பட்ட விசையை ஒட்டவும்
nano /etc/nginx/ssl/origin.key

chmod 600 /etc/nginx/ssl/origin.key
```

### 3.2 Nginx உள்ளமைவு

```bash
cat > /etc/nginx/sites-available/omniroute << 'NGINX'
# இயல்புநிலைச் சேவையகம் — IP வழியான நேரடி அணுகலைத் தடுக்கிறது
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    server_name _;
    return 444;
}

# OmniRoute — HTTPS
server {
    listen 443 ssl;
    listen [::]:443 ssl;
    server_name llms.yourdomain.com;  # உங்கள் domain-க்கு மாற்றவும்

    ssl_certificate     /etc/nginx/ssl/origin.crt;
    ssl_certificate_key /etc/nginx/ssl/origin.key;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 100M;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket ஆதரவு
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        # SSE (Server-Sent Events) — ஸ்ட்ரீமிங் AI பதில்கள்
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
    }
}

# HTTP → HTTPS திருப்பிவிடல்
server {
    listen 80;
    listen [::]:80;
    server_name llms.yourdomain.com;
    return 301 https://$server_name$request_uri;
}
NGINX
```

Reverse proxy ஸ்ட்ரீம் காலாவதி நேரங்களை உங்கள் OmniRoute காலாவதி நேரச் சூழல் மாறிகளுடன் ஒத்திசைவாக வைத்திருக்கவும். நீங்கள்
`FETCH_TIMEOUT_MS` / `STREAM_IDLE_TIMEOUT_MS` மதிப்புகளை உயர்த்தினால், `proxy_read_timeout` / `proxy_send_timeout`
மதிப்புகளை அதே வரம்புக்கு மேல் உயர்த்தவும்.

OAuth callback-கள் மற்றும் உருவாக்கப்படும் பொது இணைப்புகளுக்கான உலாவி எதிர்கொள்ளும் அதிகாரப்பூர்வ origin ஆக OmniRoute, `NEXT_PUBLIC_BASE_URL`-ஐப் பயன்படுத்துகிறது. அங்கீகரிக்கப்பட்ட dashboard எழுதுதல் செயல்பாடுகள் same-origin கோரிக்கைகளையும் session-உடன் பிணைக்கப்பட்ட CSRF பாதுகாப்பையும் பயன்படுத்துவதால், அவற்றுக்கு நிலையான பொது base URL தேவையில்லை. மேலே உள்ள `X-Forwarded-*` header-கள் இன்னும் பயனுள்ள routing metadata ஆகும்; ஆனால் OAuth அல்லது உருவாக்கப்படும் உலாவி இணைப்புகளுக்கு வெளிப்படையான பொது URL தேவைப்படும்போது, அதை அமைப்பதற்கு இவை மாற்றாகாது. வாடிக்கையாளர்கள் OmniRoute-ஐ நேரடியாக அணுக முடியாமலும், உங்கள் proxy உள்வரும் forwarded header-களை அகற்றி/மீண்டும் உருவாக்குவதாகவும் இருந்தால் மட்டுமே `OMNIROUTE_TRUST_PROXY`-ஐ இயக்கவும்.

## குறைந்த நினைவகம் / சிறிய VPS மேம்படுத்தல்

சிறிய VPS அமைப்புகளில் (1 GB RAM அல்லது அதற்கும் குறைவானது) நிறுவுவதற்கு:

- **பின்னணிச் சேவைகளை முடக்கவும்** — scheduler, MCP server மற்றும் காலமுறைப் பராமரிப்புப் பணிகளைத் தவிர்க்க `OMNIROUTE_DISABLE_BACKGROUND_SERVICES=1` என அமைக்கவும். `docs/reference/ENVIRONMENT.md`-ஐப் பார்க்கவும்.
- **SQLite WAL பயன்முறையைப் பயன்படுத்தவும்** — இது இயல்பாகவே இயக்கப்பட்டிருக்கும்; ஒரே நேரத்தில் நடைபெறும் வாசிப்புகளின்போது உச்ச நினைவகப் பயன்பாட்டைக் குறைக்கும்.
- **V8 heap-க்கு உச்சவரம்பு அமைக்கவும்** — இயக்கநேரம் VM-ஐவிடப் பெரிய உச்சவரம்பைக் கணக்கிடாமல் இருக்க `OMNIROUTE_MEMORY_MB`-ஐ (எ.கா. `512`) அமைக்கவும். `docs/reference/ENVIRONMENT.md`-ஐப் பார்க்கவும்.
- **அதிக வளம் தேவைப்படும் கோரிக்கைகளுக்கான அனுமதி, heap உச்சவரம்பிற்கு ஏற்ப தானாக அளவிடப்படும்** -- மேலே `OMNIROUTE_MEMORY_MB` அமைக்கப்பட்டதும், உள்ளீட்டு byte வரம்பு (`OMNIROUTE_CHAT_MAX_INFLIGHT_BYTES`) அதே உச்சவரம்பிலிருந்து தானாகக் கணக்கிடப்படும். எனவே, நினைவகக் கட்டுப்பாடுள்ள VM கூடுதல் அமைப்புகள் எதுவுமின்றி ஒரே நேரத்தில் கையாளப்படும் கோரிக்கைகளுக்கான சிறிய வரம்பைப் பெறும்; அதிகப்படியான கோரிக்கைகள் நினைவகத்திற்குப் போட்டியிடுவதற்குப் பதிலாக, `Retry-After` உடன் மீண்டும் முயற்சிக்கக்கூடிய `503` பதிலைப் பெறும். இதற்கு மேலாகக் கோரிக்கை எண்ணிக்கைக்கு ஒரு கண்டிப்பான உச்சவரம்பு தேவைப்பட்டால் மட்டும், முந்தைய `OMNIROUTE_CHAT_MAX_HEAVY_IN_FLIGHT` கோரிக்கை-எண்ணிக்கை வரம்பை அமைக்கவும்.
- **VPS-இல் `next build` செய்வதைத் தவிர்க்கவும்** — உள்ளூரில் build செய்து, தனித்தியங்கும் வெளியீட்டை (`.next/standalone/`) நிறுவவும்.
- **`top` / `free -m` மூலம் கண்காணிக்கவும்** — 1 GB VM-இல் செயலற்ற நிலையில் OmniRoute பொதுவாக 200-400 MB RSS நினைவகத்தைப் பயன்படுத்தும்.
