> - இயங்கும் instance ஒன்றில் “பெரிய” கட்டம் தெரிவது பழைய build காரணமாகும், code காரணமாக அல்ல — கட்டத்தின் அளவு 32px; இது தளத்தில் உள்ளதைப் போலவே உள்ளது.
> - இருண்ட theme-இன் `--table-*` மதிப்புகள் மாற்றத்திற்கு முந்தைய hardcoded rgba மதிப்புகளுடன் byte அளவில் அப்படியே ஒத்தவை; வெளிர் theme சரிசெய்யப்பட்டது (செயல்படாத `var()` fallback-கள் காரணமாக அது தவறுதலாக எப்போதும் இருண்டதாக இருந்தது).

## 1. நோக்கம்

சந்தைப்படுத்தல் தளமும் (`viral.omniroute.online`, `why.omniroute.online`, `omniroute.online`) தயாரிப்பு டாஷ்போர்டும் **ஒரே தயாரிப்பைப்** போலத் தோன்ற வேண்டும். தளம் ஏற்கனவே டாஷ்போர்டிலிருந்து அதன் வண்ணத் தொகுப்பைப் பெற்றுள்ளது — அதன் `css/tokens.css`-இல் _"வண்ணத் தொகுப்பு OmniRoute டாஷ்போர்டைப் பிரதிபலிக்கிறது (src/app/globals.css)"_ என்றும் குறிப்பிடப்பட்டுள்ளது. எனவே, வண்ண அளவில் இரண்டும் ஏற்கனவே ~80% ஒருங்கிணைந்துள்ளன. டாஷ்போர்டில் இல்லாதவை:

1. ஒவ்வொரு பக்கத்திலும் தளம் பயன்படுத்தும் **வரைபடத் தாள் கட்ட வால்பேப்பர்**.
2. தளத்தில் உள்ள ஆனால் டாஷ்போர்டில் இல்லாத சில **பகிரப்பட்ட வடிவமைப்பு டோக்கன்கள்** (ஆர அளவுகோல், brand gradient, `surface-2`, mono எழுத்துரு).
3. **கூறு-நிலை சீர்மை** — பல டாஷ்போர்டு கூறுகள் hardcoded hex/rgba மதிப்புகளைப் பயன்படுத்தி theme டோக்கன்களைத் தவிர்க்கின்றன.

இந்த ஆவணம் பகுப்பாய்வையும் திட்டத்தையும் வழங்குகிறது.

## 2. கோட்பாடுகள்

- **உண்மைக்கான ஒற்றை மூலம் = `src/app/globals.css`.** தளம் டாஷ்போர்டைப் பிரதிபலிக்கும்; இதன் எதிர்திசையில் ஒருபோதும் அல்ல. புதிய டோக்கன்கள் முதலில் `globals.css`-இல் சேர்க்கப்படும்.
- **நேரடி மதிப்புகள் அல்ல, டோக்கன்களே.** கூறுகள் raw `#hex` மதிப்புகளுக்குப் பதிலாகச் சொற்பொருள் சார்ந்த டோக்கன்களை (`bg-surface`, `text-primary`, `border-border`) பயன்படுத்தும்.
- **நுட்பமாக இருக்க வேண்டும், வெளிப்படையாக அல்ல.** கட்டம் என்பது உள்ளடக்கத்துக்குப் பின்னால் அமையும் மெல்லிய வால்பேப்பர் — அது ஒருபோதும் உரையின் contrast-ஐக் குறைக்கவோ UI-யுடன் மோதவோ கூடாது.
- **Theme-க்கு ஏற்ப இயங்குதல்.** அனைத்தும் `.dark` (தயாரிப்பின் தனித்துவமான தோற்றம்) மற்றும் வெளிர் theme ஆகிய இரண்டிலும் இயங்கும்.
- **துல்லியமான படிப்படியான வெளியீடு.** முதலில் கட்டம் + டோக்கன்களை வெளியிடவும் (குறைந்த ஆபத்து, அதிகக் காட்சித் தாக்கம்); பின்னர் கூறுச் சீரமைப்புகளைப் பல கட்டங்களாகச் செய்யவும்.

### 3.3 தீமிங் செயல்முறைகள் (எதையும் சேதப்படுத்தாமல் இருப்பதற்காக)

- **Tailwind v4, CSS-முதன்மை** (`tailwind.config.*` இல்லை). டோக்கன்கள் `:root`/`.dark`-இல் வரையறுக்கப்பட்டு, `@theme inline` (`globals.css:130-179`) வழியாகப் பயன்பாட்டுக் கருவிகளுக்கு வெளிப்படுத்தப்படுகின்றன.
- `<html>`-இல் உள்ள **`.dark` வகுப்பு வழியாக இருண்ட பயன்முறை** (`globals.css:22`-இல் `@custom-variant dark`), தனிப்பயன் Zustand store (`src/store/themeStore.ts`) மூலம் மாற்றப்படுகிறது; இயல்புநிலை தீம் = `system` (`src/shared/constants/appConfig.ts:11`). அதற்கு மாறாக, தளம் `html[data-theme="light"]`-ஐப் பயன்படுத்துகிறது — **செயல்முறைகள் வேறுபடுகின்றன, ஆனால் ஒருபோதும் ஒன்றையொன்று சந்திப்பதில்லை** (தனித்தனி மூலங்கள்), எனவே முரண்பாடு இல்லை. டாஷ்போர்டின் `.dark` செயல்முறையைத் தொடர்ந்து பயன்படுத்துகிறோம்.
- **இயக்கநேர முதன்மை நிற மேலெழுதுதல்** உள்ளது (`themeStore.ts:85-97`, `COLOR_THEMES`-இல் முன்தொகுப்புகள்) — பயனர்கள் `--color-primary`-ஐ மாற்றலாம். `--color-primary`-ஐ மேற்கோளிடும் எந்தப் புதிய டோக்கனும் (சாய்வு போன்றவை) கூடுதல் மாற்றமின்றி அந்த மேலெழுதுதல்களைப் பெறும். ✅
- **Tailwind v4-இன் ஒதுக்கப்பட்ட ஆரப் பெயர்கள்:** `--radius-sm/md/lg/...` என்பவை `rounded-*` பயன்பாட்டுக் கருவிகளுக்கு அடிப்படையாக உள்ளன. அவற்றை மறுவரையறுப்பது ஏற்கனவே உள்ள ஒவ்வொரு `rounded-*`-ஐயும் பின்னோக்கி மாற்றும் (எ.கா., `rounded-sm` 12 கோப்புகளில் பயன்படுத்தப்படுகிறது). எனவே சிறிய ஆர மதிப்பும் கூறு மறுசுட்டலும், அவற்றைப் பயன்படுத்தும் கூறுகள் ஒன்றாக மாற்றப்படும் கட்டம் 2 வரை வேண்டுமென்றே ஒத்திவைக்கப்பட்டுள்ளன.

## 4. பகுதி A — கிராஃப்-பேப்பர் கட்டப் பின்னணி (முக்கிய கோரிக்கை) — செயல்படுத்தப்பட்டது (கட்டம் 1)

### 4.1 இது என்ன

தளத்திலிருந்து எடுக்கப்பட்ட துல்லியமான செய்முறை (`_mono_repo/omnirouteSite/css/base.css`): அனைத்து உள்ளடக்கத்திற்கும் பின்னால் `z-index:-1` இல் இருந்து, இரண்டு 1px கோட்டுச் சாய்வுகளை வரையும் ஒரு **நிலையான, முழுக் காட்சிப்பரப்பு போலி-உறுப்பு**.

```css
body::before {
  content: "";
  position: fixed;
  inset: 0;
  z-index: -1;
  pointer-events: none;
  background-image:
    linear-gradient(to right, var(--grid-line) 1px, transparent 1px),
    linear-gradient(to bottom, var(--grid-line) 1px, transparent 1px);
  background-size: var(--grid-size) var(--grid-size);
}
```

**`body`க்கு ஒளிபுகாத `background-color` இருந்தாலும் இது ஏன் செயல்படுகிறது:** `z-index:-1` கொண்ட `::before`, உறுப்பின் சொந்தப் பின்னணிக்கு _மேலாகவும்_, அதன் இயல்பான ஓட்டத்திலுள்ள உள்ளடக்கத்திற்குக் _கீழாகவும்_ வரையப்படுகிறது. எனவே `--color-bg` அடிப்படை நிரப்பாக இருக்கும், கட்டம் அதற்கு மேல் அடுக்கப்படும், மேலும் செயலி கட்டத்திற்கு மேலே காட்சியாகும்.

### 4.2 நிரல்தொகுப்பில் ஏற்கெனவே உள்ள முன்னுதாரணம்

`src/app/landing/page.tsx:16-26` **ஏற்கெனவே இதே கட்டத்தை ஒவ்வொரு பக்கத்திற்கும் செயல்படுத்துகிறது** — ஆனால் **சிவப்பு** கோடுகளுடன் (`#E54D5E`, ஒளிபுகாமை `0.06`) **50px** அளவில், மேலும் அசைவூட்டப்பட்ட உருண்டைகளுடன். எனவே இந்த முறை தயாரிப்பில் நிரூபிக்கப்பட்டுள்ளது; இந்தப் பணி அதை **உலகளாவிய, தீமுக்கு ஏற்ப மாறக்கூடிய** பின்னணியாக உயர்த்துகிறது.

### 4.3 சேர்க்கப்பட்ட டோக்கன்கள் (`globals.css` இல்)


`landing/page.tsx` அதன் செழுமையான அசைவூட்டப்பட்ட பின்னணியைத் தொடர்ந்து வைத்திருக்கிறது (உருண்டைகள் + விளிம்பு இருட்டாக்கம்) — அதன் சொந்த சந்தைப்படுத்தல் அறிமுகத் திரை (முடிவு D5 = அப்படியே விடவும்).

- **மூலைவளைவு மாற்றம் (கட்டம் 2) பரவலானது** — ஒவ்வொரு கார்டு/பொத்தான்/உள்ளீட்டையும் பாதிக்கிறது; ஒன்றிணைப்பதற்கு முன் நெரிசலான திரைகளை (அட்டவணைகள், மாதிரிச் சாளரங்கள்) பார்வையிட்டு சரிபார்க்கவும்.
- **அட்டவணைகள் (C3)** அதிகளவு நேரடியாகக் குறியிடப்பட்ட பாணியமைப்பையும், மிகப்பெரிய பின்னடைவு ஏற்படக்கூடிய பரப்பையும் கொண்டுள்ளன — அவற்றைத் தனி PR-இல் பிரித்து வைக்கவும்.
