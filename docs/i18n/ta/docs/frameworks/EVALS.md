வழிச்செலுத்தல் உள்ளமைவுகள், தனிப்பட்ட வழங்குநர்கள்/மாடல்கள் அல்லது தொகுப்பில் உள்ள "golden set" சோதனைத் தொகுப்புகளின் செயல்திறனை அளவிட நீங்கள் பயன்படுத்தக்கூடிய பொதுவான மதிப்பீட்டுக் கட்டமைப்பை OmniRoute வழங்குகிறது.
வழிச்செலுத்தல் மாற்றங்களைச் சரிபார்க்கவும், புதிய வழங்குநர்களைச் செல்லுபடியாக்கவும், வெளியீடுகளை உற்பத்திப் போக்குவரத்துக்கு உயர்த்துவதற்கு முன் அவற்றுக்கான அனுமதிக் கட்டுப்பாடுகளைச் செயல்படுத்தவும் இதைப் பயன்படுத்துங்கள்.

இந்தக் கட்டமைப்பு பின்வருமாறு செயல்படுத்தப்பட்டுள்ளது:

- நினைவகத்தில் உள்ளமைந்த சோதனைத் தொகுப்புகளைப் பதிவுசெய்து, எதிர்பார்க்கப்படும் அளவுகோல்களுக்கு எதிராக வெளியீடுகளை மதிப்பிட்டு, மதிப்பெண் அட்டைகளைத் தொகுக்கும் தூய இயக்கி (`src/lib/evals/evalRunner.ts`).
- தனிப்பயன் (பயனரால் வரையறுக்கப்பட்ட) சோதனைத் தொகுப்புகளையும் SQLite-இல் உள்ள வரலாற்று இயக்கங்களையும் நிர்வகிப்பதற்கான நிலைநிறுத்த அடுக்கு (`src/lib/db/evals.ts`).
- ஒவ்வொரு சோதனை நிகழ்வையும் `POST /v1/chat/completions`-க்கு உண்மையான அழைப்புகளை அனுப்புவதன் மூலம் இயக்கி, தாமதத்தையும் வெளியீடுகளையும் பதிவுசெய்து, இயக்கத்தை நிலைநிறுத்தும் ஒருங்கிணைப்பு அடுக்கு (`src/lib/evals/runtime.ts`).
- `/api/evals/*`-இன் கீழ் உள்ள REST முனைப்புள்ளிகள் (நிர்வாக அங்கீகாரம் மட்டும்).
- `Dashboard → Usage → Evals`-இல் உள்ள முகப்புப் பலகை இடைமுகம் (`EvalsTab.tsx`).

## கருத்தாக்கங்கள்

### சோதனைத் தொகுப்பு

ஒரு சோதனைத் தொகுப்பு என்பது `description` மற்றும் ஒன்று அல்லது அதற்கு மேற்பட்ட சோதனை நிகழ்வுகளைக் கொண்ட, பெயரிடப்பட்ட தொகுப்பாகும். சோதனைத் தொகுப்புகள் இரண்டு மூலங்களிலிருந்து வருகின்றன:

| மூலம்      | வரையறுக்கப்படும் இடம்                                         | இயக்கநேரத்தில் மாற்றக்கூடியதா?         |
| ---------- | ------------------------------------------------------------- | -------------------------------------- |
| `built-in` | தொடக்கத்தின்போது `registerSuite()` மூலம் பதிவுசெய்யப்படுகிறது | இல்லை (குறியீட்டால் வரையறுக்கப்பட்டது) |
| `custom`   | SQLite `eval_suites` + `eval_cases`-இல் சேமிக்கப்படுகிறது     | ஆம் (API/UI மூலம்)                     |

தற்போதைய உள்ளமைந்த சோதனைத் தொகுப்புகள் (`src/lib/evals/evalRunner.ts`-ஐப் பார்க்கவும்):

- `golden-set` — வாழ்த்து/கணிதம்/மொழிபெயர்ப்பு/பாதுகாப்பு ஆகியவற்றை உள்ளடக்கிய 10 அடிப்படைச் சோதனை நிகழ்வுகள்
- `coding-proficiency` — Python/JS/SQL/TS/பிழை கண்டறிதல்
- `reasoning-logic` — நியாயவாதங்கள், சொல் கணக்குகள், வடிவமுறை கண்டறிதல்
- `multilingual` — மொழிபெயர்ப்பும் மொழி கண்டறிதலும்
- `safety-guardrails` — PII, jailbreak, மறுப்பு, சார்பு விழிப்புணர்வு
- `instruction-following` — JSON மட்டும், எண்ணிடப்பட்ட பட்டியல்கள், மொழிக் கட்டுப்பாடுகள்
- `codex-comparison` — ஒப்பீட்டு முறைக்காக வடிவமைக்கப்பட்ட நேருக்கு நேர் நிரலாக்கப் பணிகள்

### சோதனை நிகழ்வு

ஒவ்வொரு சோதனை நிகழ்வும் பின்வருவனவற்றைக் கொண்டுள்ளது:

| புலம்      | விளக்கம்                                                                         |
| ---------- | -------------------------------------------------------------------------------- |
| `id`       | நிலையான அடையாளங்காட்டி (வெளியீடுகளையும் அளவீடுகளையும் திறவுகோலிடப் பயன்படுகிறது) |
| `name`     | மனிதர்கள் எளிதில் புரிந்துகொள்ளக்கூடிய அடையாளப் பெயர்                            |
| `model`    | இயக்கம் `suite-default` இலக்கிடலைப் பயன்படுத்தும்போது இயல்புநிலை மாடல்           |
| `input`    | `{ messages, max_tokens? }` — `/v1/chat/completions`-க்கு அனுப்பப்படுகிறது       |
| `expected` | `{ strategy, value }` — மதிப்பீட்டு வழிகாட்டி (கீழே காண்க)                       |
| `tags`     | விருப்பத்திற்குரிய அடையாளங்கள் (எ.கா. `safety`, `pii`, `jailbreak`)              |

### இலக்கு

ஒரே சோதனைத் தொகுப்பை வெவ்வேறு இலக்குகளுக்கு எதிராக இயக்கலாம். இலக்கு திட்டவடிவம்
`src/shared/validation/schemas.ts`-இல் உள்ள `evalTargetSchema` ஆகும்:

| இலக்கு வகை      | `id`             | நடத்தை                                                                                               |
| --------------- | ---------------- | ---------------------------------------------------------------------------------------------------- |
| `suite-default` | `null`           | ஒவ்வொரு சோதனை நிகழ்வும் அதனுடைய உள்ளமைந்த `model` புலத்தைப் பயன்படுத்துகிறது                         |
| `model`         | மாடல் பெயர்      | ஒவ்வொரு சோதனை நிகழ்வையும் ஒரு நேரடி மாடல் வழியாகக் கட்டாயமாக அனுப்புகிறது (எ.கா. `gpt-4o`)           |
| `combo`         | சேர்க்கைப் பெயர் | ஒவ்வொரு சோதனை நிகழ்வையும் ஒரே சேர்க்கை வழியாக இயக்குகிறது (வழிச்செலுத்தல் இயந்திரத்தைச் சோதிக்கிறது) |

`model` மற்றும் `combo` ஆகியவற்றுக்கு `id` புலம் கட்டாயமாகும் (Zod
`superRefine` மூலம் அமல்படுத்தப்படுகிறது). `compareTarget` வழங்கப்படும்போது, இரு இலக்குகளும் வேறுபட்டிருக்க வேண்டும் —
A/B ஒப்பீட்டிற்காக இயக்கி இரண்டு இயக்கங்களையும் ஒரே `runGroupId`-இன் கீழ் நிலைநிறுத்துகிறது.

## மதிப்பீட்டு அளவுகோல்கள்

`evaluateCase()`-இல் செயல்படுத்தப்பட்டுள்ளது (evalRunner.ts):

| உத்தி      | தேர்ச்சி பெறும் நிபந்தனை…                                                                   |
| ---------- | ------------------------------------------------------------------------------------------- |
| `exact`    | `actualOutput === expected.value`                                                           |
| `contains` | `actualOutput.toLowerCase().includes(expected.value.toLowerCase())`                         |
| `regex`    | `new RegExp(expected.value).test(actualOutput)` உண்மை மதிப்பாக இருந்தால்                    |
| `custom`   | `expected.fn(actualOutput, evalCase)` உண்மை மதிப்பை வழங்கினால் (உள்ளமைந்தவற்றுக்கு மட்டும்) |

**குறிப்பு:** செயல்பாடுகளை API வழியாகத் தொடரமைக்க முடியாததால், தனிப்பயன்-செயல்பாட்டு மதிப்பீடு குறியீட்டில் வரையறுக்கப்பட்ட (உள்ளமைந்த)
தொகுப்புகளுக்கு மட்டுமே ஒதுக்கப்பட்டுள்ளது. பயனர்கள் உருவாக்கும் தொகுப்புகளுக்கு
`evalCaseBuilderSchema` ஆனது `contains | exact | regex` என்பதை மட்டுமே
ஏற்கிறது.

தற்போது LLM-ஐ-நடுவராகக் கொண்ட அல்லது embedding-அடிப்படையிலான ஒற்றுமை மதிப்பீட்டுக் கருவி எதுவும் இல்லை — இது
`evaluateCase()`-இல் எளிதாக விரிவாக்கக்கூடிய இடமாக இருக்கும்.

## தரவுத்தளத் திட்டவடிவம்

மூன்று அட்டவணைகள் (`030_create_eval_runs.sql` மற்றும்
`031_create_eval_suites.sql` இடப்பெயர்வுகள்):

| அட்டவணை       | நோக்கம்                                                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `eval_suites` | தனிப்பயன் தொகுப்பின் மேனிலைத் தரவு (`id`, `name`, `description`)                                                                |
| `eval_cases`  | ஒவ்வொரு தொகுப்பிற்குமான நிகழ்வுகள் — `input_json`, `expected_*`, `tags_json`                                                    |
| `eval_runs`   | முந்தைய இயக்கங்கள் — `pass_rate`, `total`, `passed`, `failed`, `avg_latency_ms`, `summary_json`, `results_json`, `outputs_json` |

உள்ளமைந்த தொகுப்புகள் DB-இல் சேமிக்கப்படுவதில்லை. அவை நினைவகத்தில் இருந்து,
`evalRunner.ts` இறக்குமதி செய்யப்படும் ஒவ்வொரு முறையும் மீண்டும் பதிவுசெய்யப்படுகின்றன.

## REST API

அனைத்து இறுதிப்புள்ளிகளுக்கும் மேலாண்மை அங்கீகாரம் (`requireManagementAuth`) தேவை — அவை
பொது proxy பரப்பின் பகுதியாக இல்லை.

| இறுதிப்புள்ளி                 | முறை     | விளக்கம்                                                                                  |
| ----------------------------- | -------- | ----------------------------------------------------------------------------------------- |
| `/api/evals`                  | `GET`    | தொகுப்புகள் + சமீபத்திய இயக்கங்கள் + மதிப்பெண் அட்டை + இலக்குகள் + விசைகளைப் பட்டியலிடும் |
| `/api/evals`                  | `POST`   | ஒரு தொகுப்பை இயக்கும் (தனி அல்லது ஒப்பீடு) — திட்டவடிவம் `evalRunSuiteSchema`             |
| `/api/evals/{suiteId}`        | `GET`    | ஒரு தொகுப்பைப் பெறும் (உள்ளமைந்த அல்லது தனிப்பயன்)                                        |
| `/api/evals/suites`           | `POST`   | தனிப்பயன் தொகுப்பை உருவாக்கும் — திட்டவடிவம் `evalSuiteSaveSchema`                        |
| `/api/evals/suites/{suiteId}` | `GET`    | தனிப்பயன் தொகுப்பைப் பெறும்                                                               |
| `/api/evals/suites/{suiteId}` | `PUT`    | தனிப்பயன் தொகுப்பை மாற்றும் (நிகழ்வுகள் மீண்டும் செருகப்படும்)                            |
| `/api/evals/suites/{suiteId}` | `DELETE` | தனிப்பயன் தொகுப்பையும் அதன் நிகழ்வுகளையும் நீக்கும்                                       |

### ஒரு தொகுப்பை இயக்குதல்

```bash
curl -X POST http://localhost:20128/api/evals \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "suiteId": "golden-set",
    "target": { "type": "combo", "id": "my-combo" },
    "apiKeyId": "optional-api-key-uuid"
  }'
```

விருப்பப் புலங்கள்:

- `outputs` — முன்கூட்டியே கணக்கிடப்பட்ட வெளியீடுகளின் `Record<caseId, string>`. இது வழங்கப்பட்டால்,
  இயக்கி **அனுப்புதலைத் தவிர்த்து**, தற்காலிகச் சேமிப்பிலுள்ள வெளியீடுகளை மட்டும் மதிப்பிடும் (இணைப்பில்லா
  மதிப்பீட்டிற்குப் பயனுள்ளது).
- `compareTarget` — இணையாக இயக்க வேண்டிய இரண்டாவது இலக்கு; நேருக்கு நேர் பார்வைக்காக இரண்டு இயக்கங்களும்
  உருவாக்கப்பட்ட `runGroupId`-ஐப் பகிர்ந்துகொள்கின்றன.
- `apiKeyId` — அனுப்பப்படும் `/v1/chat/completions` அழைப்புகளை அங்கீகரிக்கப் பயன்படுத்தப்படும்
  உள் API விசை. `REQUIRE_API_KEY` இயக்கப்பட்டிருக்கும்போது இது கட்டாயம்.

### தனிப்பயன் தொகுப்பை உருவாக்குதல்

```bash
curl -X POST http://localhost:20128/api/evals/suites \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Production smoke",
    "description": "Quick sanity check before deploy",
    "cases": [
      {
        "name": "JSON shape",
        "model": "gpt-4o",
        "input": { "messages": [{ "role": "user", "content": "Reply with {\"ok\": true}" }] },
        "expected": { "strategy": "regex", "value": "\"ok\"\\s*:\\s*true" }
      }
    ]
  }'
```

## அனுப்புதல் பைப்லைன்

`runEvalSuiteAgainstTarget()` (`src/lib/evals/runtime.ts`):

1. தொகுப்பைத் தீர்மானிக்கிறது (உள்ளமைக்கப்பட்ட அல்லது தனிப்பயன்).
2. ஒவ்வொரு சோதனை நிகழ்வுக்கும், அந்த நிகழ்வின் `messages`, தீர்மானிக்கப்பட்ட `model`, `stream: false`, மற்றும் `max_tokens: 512`
   (அல்லது அந்த நிகழ்வுக்கான மேலெழுதப்பட்ட மதிப்பு) ஆகியவற்றுடன் `/v1/chat/completions`-க்கு ஒரு `Request`-ஐ உருவாக்குகிறது.
3. அரட்டை கையாளியை நேரடியாக அழைக்கிறது (அதே செயல்முறைக்குள் — கூடுதல் HTTP தாவல் இல்லை).
4. தாமதத்தைப் பதிவுசெய்து, `choices[0].message.content`
   அல்லது Responses-API-இன் `output[]` பேலோடு ஆகியவற்றில் ஏதேனும் ஒன்றிலிருந்து உரையைப் பிரித்தெடுக்கிறது.
5. `runSuite()` வழியாக அனைத்து வெளியீடுகளுக்கும் மதிப்பெண் வழங்கி, பின்னர் `saveEvalRun()` வழியாகச் சேமிக்கிறது.

சோதனை நிகழ்வுகள் **தொடர்ச்சியாக** இயங்குகின்றன. தற்போது ஒருங்குநிகழ்வுக்கான கொடி எதுவும் இல்லை.

## முகப்புப்பலகை

பயனர் இடைமுகம் `Dashboard → Usage → Evals`
(`src/app/(dashboard)/dashboard/usage/components/EvalsTab.tsx`) என்பதில் உள்ளது. அங்கிருந்து நீங்கள்:

- ஒவ்வொரு சோதனை நிகழ்வுக்குமான முன்னோட்டத்துடன் உள்ளமைக்கப்பட்ட மற்றும் தனிப்பயன் தொகுப்புகளை உலாவலாம்.
- சோதனை நிகழ்வு உருவாக்கியைக் கொண்டு தனிப்பயன் தொகுப்புகளை உருவாக்கலாம்/திருத்தலாம்/நீக்கலாம்.
- ஒரு இலக்கைத் (தொகுப்பு இயல்புநிலைகள் / மாடல் / சேர்க்கை) தேர்ந்தெடுத்து, விருப்பமாக இரண்டாவது
  `compareTarget`-ஐயும், விருப்பமாக ஒரு API விசையையும் தேர்ந்தெடுத்து, தேவைக்கேற்ப இயக்கலாம்.
- இயக்க வரலாறு, ஒவ்வொரு சோதனை நிகழ்வின் தேர்ச்சி/தோல்வி, தாமதம் மற்றும் பதிவுசெய்யப்பட்ட வெளியீடுகளை ஆய்வு செய்யலாம்.
- ஒவ்வொரு `(suite, target)` வரம்பிற்குமான சமீபத்திய இயக்கத்தின் அடிப்படையில் திரட்டப்பட்ட நகரும் மதிப்பெண் அட்டையைப் பார்க்கலாம்.

## தானியங்கு மதிப்பீட்டு RFC உடனான தொடர்பு

தனியான, குறுகிய நோக்கமுடைய மதிப்பீட்டுத் துணைஅமைப்பு `src/domain/assessment/`
என்பதில் உள்ளது (நேரடி மதிப்பீட்டு இயந்திரத்திற்கு [AUTO-COMBO.md](../routing/AUTO-COMBO.md)-ஐயும் பார்க்கவும்).
அந்தத் துணைஅமைப்பு Auto Combo இயந்திரத்தைக் குறிவைக்கிறது — மேல்நிலைச் சேவைகள் தோல்வியடையும்போது சேர்க்கைகள் தானாகவே மீட்கக்கூடியவாறு வழங்குநர்களுக்கும்
மாடல்களுக்கும் தானாக மதிப்பெண் வழங்குகிறது. அது தனக்கென ஒரு இயக்கி,
தனக்கென ஒரு வகைப்படுத்தி மற்றும் தனக்கென ஒரு மதிப்பீட்டுத் தர்க்கத்தைப் பயன்படுத்துகிறது.

இங்கே ஆவணப்படுத்தப்பட்டுள்ள Evals கட்டமைப்பு **பரந்த, பொதுப் பயன்பாட்டுக்கான
சோதனைத் தளம்** ஆகும். எந்தவகையான பின்னடைவு சோதனைத் தொகுப்புகள், A/B ஒப்பீடுகள்
மற்றும் ஒவ்வொரு வெளியீட்டிற்குமான புகைச் சோதனைகளுக்கும் இதைப் பயன்படுத்துவது விரும்பத்தக்கது. வழித்தடத் தீர்மானங்களைப் பாதிக்க
நிகழ்நேர வழங்குநர் நிலை தேவைப்படும்போது Auto-Assessment துணைஅமைப்பைப் பயன்படுத்தவும்.

## CI ஒருங்கிணைப்பு

தற்போது பிரத்யேகமான `eval:ci` npm ஸ்கிரிப்ட் எதுவும் இல்லை. eval முடிவுகளின் அடிப்படையில்
வெளியீடுகளைக் கட்டுப்படுத்த விரும்பினால் இரண்டு வழிகள் உள்ளன:

- **HTTP வழி**: சேவையகத்தைத் தொடங்கி, அறியப்பட்ட
  `suiteId` + `target` உடன் `POST /api/evals`-ஐ அழைத்து, பதிலில்
  `runs[].summary.passRate >= N` என்பதை உறுதிப்படுத்தவும்.
- **அதே செயல்முறைக்குள்ளான வழி**: ஒரு ஸ்கிரிப்டிலிருந்து
  `@/lib/evals/runtime`-இலுள்ள `runEvalSuiteAgainstTarget()`-ஐ இறக்குமதி செய்து, சோதனை DB-க்கு எதிராக இயக்கி,
  திருப்பியளிக்கப்படும் `PersistedEvalRun.summary`-ஐச் சரிபார்க்கவும்.

வழித்தடத்தையும் வரலாற்றையும் உள்ளடக்கும் சோதனைகள்
`tests/unit/evals-route.test.ts` மற்றும் `tests/unit/evals-history.test.ts` ஆகியவற்றில் உள்ளன.

## நீட்டிப்புப் புள்ளிகள்

பொதுவான மாற்றங்களும் அவற்றைச் செய்ய வேண்டிய இடங்களும்:

- **புதிய மதிப்பீட்டு உத்தி** — `evaluateCase()` (`evalRunner.ts`)-இல் உள்ள
  `switch (evalCase.expected.strategy)` தொகுதியை நீட்டித்து, `src/lib/db/evals.ts`-இல் உள்ள `EvalCaseStrategy` மற்றும் `schemas.ts`-இல் உள்ள `evalCaseBuilderSchema` ஆகியவற்றை விரிவாக்கவும்.
- **புதிய உள்ளமைக்கப்பட்ட தொகுப்பு** — ஒரு தொகுப்பு பொருளை வரையறுத்து,
  `evalRunner.ts`-இன் இறுதியில் `registerSuite()`-ஐ அழைக்கவும். அது `listSuites()` மூலம் தானாகக் கண்டறியப்படும்.
- **ஒருங்குநிகழ்வுடன் இயக்குதல்** — `runEvalSuiteAgainstTarget()`-இல் உள்ள தொடர்ச்சியான `for` சுழற்சியை வரம்பிடப்பட்ட `Promise.all` ஆக மாற்றவும் (தற்போது ஒருங்குநிகழ்வுக் கட்டுப்பாடு எதுவும் இல்லை).
- **ஸ்ட்ரீம்/கருவி-அழைப்பு சோதனை நிகழ்வுகள்** — தற்போது இயக்கி `stream: false`-ஐ கட்டாயப்படுத்துகிறது.
  ஸ்ட்ரீமிங் அல்லது கருவி-விழிப்புணர்வுள்ள மதிப்பீட்டிற்கு `runtime.ts`-இல் மாற்றங்கள் தேவைப்படும்
  (மதிப்பீட்டுக்கு முன் SSE துண்டுகளைப் பதிவுசெய்து திரட்ட வேண்டும்).
