OmniRoute **CLI கண்டறிதல்**, **நேட்டிவ் Agent Client Protocol**, மற்றும்
**பழைய stdio அடாப்டர்கள்** ஆகியவற்றைப் பிரிக்கிறது. நிறுவப்பட்ட பைனரியைக் கண்டறிவது மட்டும் அதன்
அங்கீகாரம், மாடல் இணக்கத்தன்மை அல்லது ஒரு ப்ராம்ப்டைக் கையாளும் தயார்நிலையை நிரூபிக்காது.

டாஷ்போர்டு இருப்புப் பட்டியல் மற்றும் தனிப்பயன் ஏஜென்ட் பதிவுக்காக `GET /api/acp/agents` மற்றும் `POST /api/acp/agents` ஆகியவற்றைப் பயன்படுத்துகிறது.
இவை உள்ளமை செயல்முறைகளைத் தொடங்குவதற்கோ ப்ராம்ப்ட்களைச் சமர்ப்பிப்பதற்கோ பயன்படும் பொது API அல்ல; உள்ளூர்-மட்டும் மேலாண்மை வழித்தடங்கள்.
உள்ளக `AcpManager` தானாகவே HTTP வழங்குநருக்கான மாற்று ஏற்பாடாக மாறாது.

## பதிவுசெய்யப்பட்ட ஒப்பந்தங்கள்

உள்ளமைக்கப்பட்ட தொடக்க பைனரிகள், வாதங்கள் மற்றும் பின்புல முறைகளுக்கான அதிகாரப்பூர்வ ஆதாரம்
`config/cli-tools-manifest.json` ஆகும். பதிவகம் அந்த மேனிஃபெஸ்டிலிருந்து தனது வரையறைகளைப் பெறுகிறது.
கண்டறிதல் 60 வினாடிகளுக்குத் தேக்ககப்படுத்தப்படுகிறது.

- `acp`: Gemini ஒப்பந்தம் `gemini --experimental-acp` ஐத் தொடங்கி,
  அதிகாரப்பூர்வ TypeScript SDK வழியாக புதியவரி-பிரிக்கப்பட்ட ACP JSON-RPC உடன் தொடர்புகொள்கிறது.
- `stdio-adapter`: பதிவுசெய்யப்பட்ட மற்ற ஒப்பந்தங்கள் பழைய புதியவரி-உள்ளீடு,
  stdout-வெளியீடு அடாப்டரைத் தொடர்ந்து பயன்படுத்துகின்றன. இரண்டு வினாடிகள் வெளியீடு செயலற்றிருந்தால் அதன் பதில் முடிவடைகிறது.
  இந்த அடாப்டர் அந்த CLI-களுக்கான நேட்டிவ் ACP ஆதரவை **சான்றளிப்பதில்லை**.

Gemini தொடக்கக் கொடியை அதன் [CLI மேற்கோளில்](https://geminicli.com/docs/cli/cli-reference/) ஆவணப்படுத்துகிறது.
துவக்கம், அமர்வு உருவாக்கம், ப்ராம்ப்ட் கோரிக்கைகள், அறிவிப்புகள் மற்றும் ரத்துசெய்தல் ஆகியவற்றுக்கு கிளையன்ட்
[அதிகாரப்பூர்வ ACP SDK](https://github.com/agentclientprotocol/typescript-sdk) ஐப் பயன்படுத்துகிறது.

தனிப்பயன்-ஏஜென்ட் வரையறைகள் நிர்வாகியின் கட்டுப்பாட்டிலுள்ள தொடக்க ஒப்பந்தங்களாகவே இருக்கும்.
ஒரு பைனரி மற்றும் வாதங்களைப் பதிவுசெய்வது, அந்தச் செயல்முறைக்கு சர்வர் பயனரின் உள்ளூர்
செயலாக்கச் சலுகைகளை வழங்குகிறது; பதிவு என்பது சாண்ட்பாக்ஸ் அல்ல. பதிப்புச் சோதனைகள்
பதிவுசெய்யப்பட்ட இயக்கக்கூடிய கோப்பு மற்றும் அங்கீகரிக்கப்பட்ட பதிப்புக் கொடியை மட்டுமே ஏற்கின்றன.

## உள்ளக தொடக்க API

```typescript
import { acpManager } from "@/lib/acp";

const session = acpManager.spawn("gemini", {
  cwd: process.cwd(),
  // இந்த ஏஜென்டுக்கு வேண்டுமென்றே ஒதுக்கப்பட்ட வழங்குநர் மாறிகளை மட்டும் அனுப்பவும்.
  env: {
    GEMINI_API_KEY: process.env.GEMINI_API_KEY,
  },
});

try {
  const response = await acpManager.sendPrompt(session.id, "இந்தத் திட்டத்தை விளக்கவும்", 120_000);
  // அழைக்கும் பயன்பாட்டில் பதிலைப் பயன்படுத்தவும்.
} finally {
  acpManager.kill(session.id);
}
```

`spawn(agentId, options)` பதிவுசெய்யப்பட்ட வரையறையிலிருந்து இயக்கக்கூடிய கோப்பையும் வாதங்களையும் கண்டறிகிறது.
அழைப்பவர் வழங்கக்கூடிய விருப்பங்கள் `cwd` மற்றும் `env` மட்டுமே; பழைய
`spawn(agentId, binary, args, env)` கையொப்பமும் இயக்கக்கூடிய கோப்புக்கான மேலெழுதல்களும்
நிராகரிக்கப்படுகின்றன. இந்த மேலாளரால் HTTP தொடக்க ஒப்பந்தங்கள் ஆதரிக்கப்படுவதில்லை.

CLI தொடக்கிகள் பயன்படுத்தும் அதே இயக்க முறைமை, டெர்மினல், மொழிப்பிரதேசம் மற்றும் சான்றிதழ்
அனுமதிப்பட்டியலைச் சேய் செயல்முறையும் மரபுரிமையாகப் பெறுகிறது. சர்வர்/வழங்குநர் ரகசியங்கள்
பெற்றோர் சூழலிலிருந்து நகலெடுக்கப்படுவதில்லை. தேர்ந்தெடுக்கப்பட்ட CLI-க்குத் தேவையான நற்சான்றுகள்
வெளிப்படையாக அனுப்பப்பட வேண்டும் அல்லது அந்த CLI-யின் சொந்த உள்ளூர் அங்கீகாரம் மூலம் வழங்கப்பட வேண்டும்.
சேய் செயல்முறைக்கு இன்னும் உள்ளூர் பயனரின் கோப்புமுறை அனுமதிகள் இருக்கும்; மேலும் அது தனது சொந்த உள்ளமைவைப் படிக்கலாம்.

## நேட்டிவ் வாழ்நிலைச் சுழற்சியும் வரம்புகளும்

1. பதிவுசெய்யப்பட்ட பைனரியைத் தொடங்கி, ACP-ஐத் துவக்கி, தேர்ந்தெடுக்கப்பட்ட பணிக் கோப்பகத்தை
   மூலமாகக் கொண்ட ஓர் அமர்வை உருவாக்கவும். துவக்கத்திற்கு பத்து வினாடி வரம்பு உள்ளது.
2. ஒரு ப்ராம்ப்டைச் சமர்ப்பித்து, அந்த அமர்வுக்கான உரை அறிவிப்புகளை மட்டும் சேகரிக்கவும்.
   நிறைவு என்பது ப்ராம்ப்ட் RPC பதிலாகும்; stdout அமைதியாக இருக்கும் காலப்பகுதி அல்ல.
3. முடிவடையாத துவக்கம் உட்பட, ஒரே ப்ராம்ப்ட் காலக்கெடுவைப் பயன்படுத்தவும்; இயல்புநிலை
   120 வினாடிகள். அதே செயல்முறையில் ஒரே நேரத்தில் வரும் ப்ராம்ப்ட்கள் நிராகரிக்கப்படுகின்றன.
4. நேட்டிவ் நேரம் முடிவடைந்தால், `session/cancel` ஐ முயன்று செயல்முறையை நிறுத்தவும்.
   வரம்பிடப்பட்ட 100 ms சாளரம், நிறுத்துவதற்கு முன் அறிவிப்பு வெளியேற்றத்தை முடிக்க அனுமதிக்கிறது.
5. துவக்கம் தோல்வியடையும் போது, இணைப்பு மூடப்படும் போது, செயல்முறை வெளியேறும் போது அல்லது அழைப்பவர்
   அதைக் கொல்லும் போது போக்குவரத்து நிலையை மூடி அமர்வை அகற்றவும்.

கருவி அனுமதிக் கோரிக்கைகள் மறுக்கப்படுகின்றன. எந்தக் கோப்புமுறை அல்லது டெர்மினல் கிளையன்ட்
திறன்களும் அறிவிக்கப்படுவதில்லை. இந்தக் கட்டுப்பாடுகள் சேய் பைனரியையே சாண்ட்பாக்ஸில் வைப்பதில்லை;
அல்லது CLI-யின் சொந்த அங்கீகார அமைப்புகளை மாற்றுவதில்லை.

நேட்டிவ் உரை மற்றும் பழைய stdout/stderr ஆகிய இரண்டும் அதிகபட்சமாக 1 MiB எழுத்துகளைத் தக்கவைத்து,
துண்டிக்கப்பட்ட அறிவிப்புடன் புதிய வெளியீட்டை வைத்திருக்கின்றன. SDK பாகுபடுத்தலுக்கு முன் தனிப்பட்ட நேட்டிவ்
கம்பிச் சட்டகம் 2 MiB பைட்டுகளுக்கு வரம்பிடப்படுகிறது. ஒவ்வொரு ப்ராம்ப்டுக்கும் இடையகங்கள் மீட்டமைக்கப்படுகின்றன.

`kill(sessionId)` SIGTERM-ஐ அனுப்புகிறது; ஐந்து வினாடிகளுக்குப் பிறகும் செயல்முறை வெளியேறவில்லை என்றால்
SIGKILL-ஐ அனுப்புகிறது. பழைய ப்ராம்ப்ட் நேரமுடிவுகள் கேட்பான்களையும் நேரங்காட்டிகளையும் விடுவிக்கின்றன;
ஆனால் மற்றொரு ப்ராம்ப்டுக்காக அமர்வைக் கிடைக்குமாறு வைத்திருக்கின்றன. முடிந்ததும் `kill()` அல்லது
`killAll()` ஐ அழைப்பதற்கு அழைப்பவர்களே பொறுப்பானவர்கள்.

## நிகழ்வுகளும் ஆய்வும்

மேலாளர் `stdout`, `stderr`, மற்றும் `exit` ஆகியவற்றை வெளியிடுகிறது; ஒவ்வொன்றிலும் `sessionId` இருக்கும்.
`sessionError` சுத்திகரிக்கப்பட்ட போக்குவரத்துப் பிழையை அறிக்கையிடுகிறது. இணக்கத்தன்மைக்கான `error`
நிகழ்வு சந்தாதாரர் இருக்கும்போது மட்டுமே வெளியிடப்படுகிறது; எனவே காணாமல் போன பைனரி கையாளப்படாத
EventEmitter பிழையை ஏற்படுத்த முடியாது.

- `getSession(sessionId)` நிர்வகிக்கப்பட்ட அமர்வை அல்லது `undefined` ஐத் திருப்பித் தருகிறது.
- `getActiveSessions()` நிறுத்தப்பட்ட அல்லது நிறுத்தப்பட்டுக் கொண்டிருக்கும் அமர்வுகளை விலக்குகிறது.
- `sendInput(sessionId, input)` இயங்கிக்கொண்டிருக்கும் பழைய அடாப்டருக்கு மட்டுமே கிடைக்கும்;
  அதன் JSON-RPC ஸ்ட்ரீமைப் பாதுகாக்க நேட்டிவ் ACP மூல உள்ளீட்டை நிராகரிக்கிறது.
- `killAll()` அந்த நிகழ்வுருவால் நிர்வகிக்கப்படும் ஒவ்வொரு அமர்வையும் நிறுத்துகிறது.

## சரிபார்ப்பு எல்லைகள்

நேட்டிவ் கைகுலுக்கல், உரை வெளியீடு, மறுக்கப்பட்ட அனுமதிகள், ரத்துசெய்தல், ஒரேநேரப் ப்ராம்ப்ட்கள்,
தோல்வியுற்ற துவக்கம், செயல்முறை வெளியேற்றம், வெளியீட்டு வரம்புகள் மற்றும் ரகசியத் தனிமைப்படுத்தல்
ஆகியவற்றை தீர்மானகரமான நிலைப்பொருட்கள் உள்ளடக்குகின்றன. ஏற்கனவே உள்ள பழைய இடையகம்/கேட்பான்
பின்னடைவு சோதனைகளும் தொடர்ந்து உள்ளடக்கப்படுகின்றன. இந்தச் சோதனைகள் நேரடி Gemini உள்நுழைவையோ
வெற்றிகரமான வழங்குநர் அனுமானத்தையோ நிரூபிப்பதில்லை; அவற்றிற்கு இலக்கு சூழலில் தனியாக
அங்கீகரிக்கப்பட்ட புகைச் சோதனை தேவை.
