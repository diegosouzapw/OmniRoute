> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-06-28 — v3.8.40 (frontmatter புதுப்பிப்பு; cursor-cloud உட்பட 4 agents)

OmniRoute, மூன்றாம் தரப்பு cloud-hosted coding agents-ஐ (Codex Cloud, Cursor,
Devin, Jules) நீண்ட நேரம் இயங்கும் பணிகளாக ஒருங்கிணைக்கிறது. ஒவ்வொரு agent-உம் ஒரே சீரான interface-க்குப் பின்னால் பொதியப்பட்டுள்ளதால்,
clients ஒரு prompt + repo URL-ஐச் சமர்ப்பித்து, provider-க்கு உரிய APIs-ஐக் கையாளாமலேயே
முடிவுகளைப் பெற முடியும்.

ஒரு Cloud Agent பணி என்பது வழக்கமான chat completion **அல்ல**. இது நிமிடங்கள் முதல் மணிநேரங்கள் வரை
எடுத்துக்கொள்ளக்கூடிய, நீடித்த, பல-படி வேலை அலகாகும்; இதன் artifact-ஆக ஒரு Pull Request-ஐ உருவாக்க முடியும்,
மேலும் இது follow-up messages மற்றும் (சில providers-இல்) plan approval gates ஆகியவற்றை ஆதரிக்கிறது.

## கட்டமைப்பு

```
Client (Dashboard / CLI / API)
  → POST /api/v1/agents/tasks (management auth தேவை)
    → CreateCloudAgentTaskSchema சரிபார்ப்பு (Zod)
    → registry.getAgent(providerId)
    → getCloudAgentCredentials(providerId)
      └─ getProviderConnections({ provider, isActive: true }) இலிருந்து பெறுகிறது
         (முதலில் apiKey, இல்லையெனில் accessToken)
    → agent.createTask({ prompt, source, options }, credentials)
      └─ upstream provider API-க்கு HTTP POST
      └─ அக id + externalId கொண்ட CloudAgentTask-ஐத் திருப்புகிறது
    → cloud_agent_tasks (SQLite)-இல் insertCloudAgentTask(...)

Polling (படிக்கும்போது lazy sync):
  GET /api/v1/agents/tasks/[id]
    → getCloudAgentTaskById(id)
    → agent.getStatus(externalId, credentials)  // status + activities-ஐப் புதுப்பிக்கிறது
    → புதிய status, result, completed_at ஆகியவற்றுடன் updateCloudAgentTask(...)
    → serialize செய்யப்பட்ட task-ஐத் திருப்புகிறது

Interactions:
  POST /api/v1/agents/tasks/[id]  body: { action: "approve" | "message" | "cancel" }
    → agent.approvePlan(externalId, credentials)        "approve"-க்காக
    → agent.sendMessage(externalId, message, credentials) "message"-க்காக
    → status "cancelled" என மாறுகிறது                    "cancel"-க்காக (local-only)
```

Sync **lazy** ஆகும்: ஒவ்வொரு `GET /tasks/[id]` கோரிக்கையின்போதும் upstream-இலிருந்து status புதுப்பிக்கப்படுகிறது.
Background poller எதுவும் இல்லை. புதுப்பித்த நிலை தேவைப்படும் Dashboards, பொருத்தமான இடைவெளியில் GET
endpoint-ஐ poll செய்ய வேண்டும்.

## `CloudAgentBase` இடைமுகம்

மூலம்: `src/lib/cloudAgent/baseAgent.ts`

```typescript
export interface AgentCredentials {
  apiKey: string;
  baseUrl?: string;
}

export interface CreateTaskParams {
  prompt: string;
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
}

export interface GetStatusResult {
  status: CloudAgentStatus;
  externalId?: string;
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
}

export abstract class CloudAgentBase {
  abstract readonly providerId: string;
  abstract readonly baseUrl: string;

  abstract createTask(p: CreateTaskParams, c: AgentCredentials): Promise<CloudAgentTask>;
  abstract getStatus(externalId: string, c: AgentCredentials): Promise<GetStatusResult>;
  abstract approvePlan(externalId: string, c: AgentCredentials): Promise<void>;
  abstract sendMessage(
    externalId: string,
    message: string,
    c: AgentCredentials
  ): Promise<CloudAgentActivity>;
  abstract listSources(
    c: AgentCredentials
  ): Promise<{ name: string; url: string; branch?: string }[]>;

  protected mapStatus(raw: string): CloudAgentStatus; // ஊக அடிப்படையிலான மேல்நிலைச் சரம் → enum
  protected generateTaskId(): string; // `task_<ts>_<rand>`
  protected generateActivityId(): string; // `act_<ts>_<rand>`
}
```

`CodexCloudAgent.approvePlan` வேண்டுமென்றே பிழையை எழுப்புகிறது — Codex Cloud தானாகவே திட்டமிடுகிறது, மேலும் அதில்
ஒப்புதல் நுழைவாயில் இல்லை. `CodexCloudAgent.listSources` ஆனது `[]` என்பதைத் திருப்பியளிக்கிறது.

`CursorCloudAgent`, Cursor-இன் Background / Cloud Agents-ஐ அதன் அதிகாரப்பூர்வ REST
API (`api.cursor.com/v0`) வழியாக, **பயனர் அல்லது சேவைக் கணக்கு API விசையைக்** கொண்டு இயக்குகிறது — இது Cursor IDE-இன் OAuth அமர்வை மீண்டும் பயன்படுத்துவதற்கான (தடை விதிக்கப்படும் அபாய எச்சரிக்கையைக் கொண்ட provider `cursor`) பாதுகாப்பான,
முதல்-தரப்பு மாற்றாகும். இது ஓர் எளிய REST adapter (`@cursor/sdk` native
சார்புநிலை இல்லை). `approvePlan` பிழையை எழுப்புகிறது (Cursor agents தன்னிச்சையாக இயங்குகின்றன); `listSources`,
விசையால் அணுகக்கூடிய repositories-ஐப் பட்டியலிடுகிறது. Cursor, UPPERCASE status enums-ஐ
(`CREATING`/`RUNNING`/`FINISHED`/`ERROR`) திருப்பியளிக்கிறது; அவை பகிரப்பட்ட
`CloudAgentStatus`-க்கு வெளிப்படையாகப் பொருத்தப்படுகின்றன. API version/path-ஐக் குறியீட்டு மாற்றமின்றி
திருத்தும் வகையில், ஒவ்வொரு credential-க்கும் `baseUrl`-ஐ மேலெழுதலாம்.

## கள வகைகள்

மூலம்: `src/lib/cloudAgent/types.ts`

```typescript
export const CLOUD_AGENT_STATUS = {
  QUEUED: "queued",
  RUNNING: "running",
  AWAITING_APPROVAL: "awaiting_approval",
  COMPLETED: "completed",
  FAILED: "failed",
  CANCELLED: "cancelled",
} as const;

export interface CloudAgentSource {
  repoName: string;
  repoUrl: string; // செல்லுபடியாகும் URL ஆக இருக்க வேண்டும்
  branch?: string;
}

export interface CloudAgentResult {
  prUrl?: string;
  prNumber?: number;
  commitMessage?: string;
  diffUrl?: string;
  summary?: string;
  duration?: number; // விநாடிகள், நேர்மறை முழு எண்
  cost?: number; // நேர்மறை மிதவை எண்
}

export interface CloudAgentActivity {
  id: string;
  type: "plan" | "command" | "code_change" | "message" | "error" | "completion";
  content: string;
  timestamp: string; // ISO 8601
  metadata?: Record<string, unknown>;
}

export interface CloudAgentTask {
  id: string; // அக `task_...` id
  providerId: "jules" | "devin" | "codex-cloud" | "cursor-cloud";
  externalId?: string; // மேல்நிலை provider-இன் id
  status: CloudAgentStatus;
  prompt: string; // 1..10000 எழுத்துகள்
  source: CloudAgentSource;
  options: {
    autoCreatePr?: boolean;
    planApprovalRequired?: boolean;
    environment?: Record<string, string>;
  };
  result?: CloudAgentResult;
  activities: CloudAgentActivity[];
  error?: string;
  createdAt: string;
  updatedAt: string;
  completedAt?: string;
}
```

சரிபார்ப்புத் திட்டவடிவங்கள் (`CreateCloudAgentTaskSchema`, `UpdateCloudAgentTaskSchema`)
வகைகளுடன் சேர்த்து ஏற்றுமதி செய்யப்படுகின்றன; மேலும் அவை route handlers-ஆல் பயன்படுத்தப்படுகின்றன.

## தரவுத்தளம்

மூலம்: `src/lib/cloudAgent/db.ts` — அட்டவணை
`createCloudAgentTaskTable()` வழியாகத் தேவைப்படும்போது உருவாக்கப்படுகிறது (`src/lib/cloudAgent/index.ts` இலிருந்து
தொகுதி இறக்குமதியின்போதும் அழைக்கப்படுகிறது).

```sql
CREATE TABLE IF NOT EXISTS cloud_agent_tasks (
  id           TEXT PRIMARY KEY,
  provider_id  TEXT NOT NULL,
  external_id  TEXT,
  status       TEXT NOT NULL DEFAULT 'queued',
  prompt       TEXT NOT NULL,
  source       TEXT NOT NULL,             -- JSON
  options      TEXT DEFAULT '{}',         -- JSON
  result       TEXT,                       -- JSON
  activities   TEXT DEFAULT '[]',          -- JSON
  error        TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at   TEXT NOT NULL DEFAULT (datetime('now')),
  completed_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_provider ON cloud_agent_tasks(provider_id);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_status   ON cloud_agent_tasks(status);
CREATE INDEX IF NOT EXISTS idx_cloud_agent_tasks_created  ON cloud_agent_tasks(created_at DESC);
```

SQL injection-ஐத் தடுப்பதற்காக `updateCloudAgentTask` ஒரு **நெடுவரிசை அனுமதிப்பட்டியலை** அமல்படுத்துகிறது:
`status`, `prompt`, `source`, `options`, `result`, `activities`, `error`,
`completed_at`. பகுதியளவு புதுப்பிப்பிலுள்ள வேறு எந்த விசையும் எச்சரிக்கையின்றி நீக்கப்படும்.

## REST API — பணியின் வாழ்க்கைச் சுழற்சி

**அங்கீகாரம்:** அனைத்து `/api/v1/agents/tasks*` முனைப்புள்ளிகளுக்கும் **நிர்வாக அங்கீகாரம்**
தேவை (`requireCloudAgentManagementAuth` ஆனது
`src/lib/api/requireManagementAuth` இலிருந்து `requireManagementAuth`-ஐச் சுற்றுகிறது). இது `588a0333`
commit-க்குப் பிறகு அமல்படுத்தப்படுகிறது
(_"fix(auth): முகவர் மற்றும் cooldown API-களுக்கு நிர்வாக அங்கீகாரத்தைக் கட்டாயமாக்கு"_).

| முறை    | பாதை                          | நோக்கம்                                                                      |
| ------- | ----------------------------- | ---------------------------------------------------------------------------- |
| OPTIONS | `/api/v1/agents/tasks`        | CORS முன்சோதனை                                                               |
| GET     | `/api/v1/agents/tasks`        | பணிகளைப் பட்டியலிடுதல் (வடிகட்டி: `provider`, `status`, `limit≤500`)         |
| POST    | `/api/v1/agents/tasks`        | பணியை உருவாக்குதல் (மேல்நிலைச் சேவைக்கு அனுப்பி நிலைநிறுத்துகிறது)           |
| DELETE  | `/api/v1/agents/tasks?id=...` | வினவல் id மூலம் பணியை நீக்குதல் (மேல்நிலைச் சேவையில் **ரத்து செய்யாது**)     |
| OPTIONS | `/api/v1/agents/tasks/[id]`   | CORS முன்சோதனை                                                               |
| GET     | `/api/v1/agents/tasks/[id]`   | பணியைப் படித்து, மேல்நிலைச் சேவையிலிருந்து நிலையைத் தேவைக்கேற்ப ஒத்திசைத்தல் |
| POST    | `/api/v1/agents/tasks/[id]`   | செயல்: `approve` / `message` / `cancel`                                      |
| DELETE  | `/api/v1/agents/tasks/[id]`   | பாதை id மூலம் பணியை நீக்குதல்                                                |

## REST API — Cloud வழங்குநர் இணைப்பமைப்பு

`src/app/api/cloud/` என்பதன் கீழுள்ள இந்தத் துணை endpoint-கள், வழங்குநர் இணைப்பு metadata-வைப் படிக்கவும் model alias-களைத் தீர்மானிக்கவும் தொலைநிலை client-களால்
(CLI, Electron app அல்லது sync worker-கள்) பயன்படுத்தப்படுகின்றன. இவை task endpoint-கள் பயன்படுத்தும் management auth-ஐ அல்லாமல், **வழக்கமான API key**-ஐ
(`validateApiKey` வழியாக) கொண்டு அங்கீகரிக்கப்படுகின்றன.

| முறை | பாதை                            | நோக்கம்                                                                            |
| ---- | ------------------------------- | ---------------------------------------------------------------------------------- |
| POST | `/api/cloud/auth`               | API key-ஐச் சரிபார்த்து, மறைக்கப்பட்ட இணைப்பு metadata + model alias-களை வழங்குதல் |
| PUT  | `/api/cloud/credentials/update` | `accessToken` / `refreshToken` / `expiresAt` ஆகியவற்றைப் புதுப்பித்தல்             |
| POST | `/api/cloud/model/resolve`      | ஒரு model alias-ஐ `{ provider, model }` ஆகத் தீர்மானித்தல்                         |
| GET  | `/api/cloud/models/alias`       | அனைத்து model alias-களையும் பட்டியலிடுதல்                                          |
| PUT  | `/api/cloud/models/alias`       | ஒரு model alias-ஐ அமைத்தல் (இயக்கப்பட்டிருந்தால் Cloud உடன் தானாக sync செய்தல்)    |

`/api/cloud/auth`, மூல `apiKey` / `accessToken` / `refreshToken` மதிப்புகளை ஒருபோதும் வழங்காது. இது
`hasApiKey`, `hasAccessToken`, `hasRefreshToken` மற்றும் மறைக்கப்பட்ட முன்னோட்டம்
(`maskedApiKey`: முதல் 4 + `****` + கடைசி 4) ஆகியவற்றை வழங்குகிறது.

## நற்சான்றுத் தீர்மானம்

`src/lib/cloudAgent/api.ts`-இல் உள்ள `getCloudAgentCredentials(providerId)`:

1. `getProviderConnections({ provider: providerId, isActive: true })` வழியாகச் செயலில் உள்ள வழங்குநர் இணைப்புகளை ஏற்றுகிறது.
2. ஒவ்வொரு இணைப்பிற்கும், `apiKey`-ஐ (trim செய்யப்பட்டு) முன்னுரிமைப்படுத்துகிறது. அது இல்லையெனில் `accessToken`-ஐப் பயன்படுத்துகிறது.
3. காலியாக இல்லாத முதல் token-ஐ `{ apiKey: token }` ஆகப் பொதிந்து வழங்குகிறது.
4. பயன்படுத்தக்கூடிய token எதுவும் கிடைக்கவில்லை என்றால் `null`-ஐ வழங்குகிறது — API பின்வரும் செய்தியுடன் `400`-ஐப் பதிலளிக்கும்:
   `"Cloud agent வழங்குநருக்குச் செயலில் உள்ள நற்சான்றுகள் எதுவும் உள்ளமைக்கப்படவில்லை: <id>"`.

இதன் பொருள், வழக்கமான LLM வழங்குநர்கள் பயன்படுத்தும் அதே Provider Connection அட்டவணையை Cloud Agent-களும் மீண்டும் பயன்படுத்துகின்றன.
Jules-ஐ இயக்க, `provider: "jules"` மற்றும் மதிப்பு நிரப்பப்பட்ட `apiKey` கொண்ட செயலில் உள்ள ஓர் இணைப்பை உருவாக்கவும்.

## Dashboard

பின்வருவனவற்றைச் செய்யும் `"use client"` React page:

## A2A உடனான ஒருங்கிணைப்பு

தனது `tasks/send` handler-ஐ `getAgent(...).createTask(...)`-க்குப் பிரதிநிதித்துவப்படுத்தி, A2A task நிலை நிகழ்வுகளை JSON-RPC 2.0 protocol-க்கு மாற்றும் ஓர் A2A skill-ஐப் பதிவு செய்வதன் மூலம் Cloud Agent-களை A2A skill-களாக வெளிப்படுத்தலாம். [A2A-SERVER.md](./A2A-SERVER.md)-ஐப் பார்க்கவும்.

## புதிய Cloud Agent-ஐச் சேர்த்தல்

1. `CloudAgentBase`-ஐ நீட்டிக்கும் `src/lib/cloudAgent/agents/<name>.ts`-ஐ உருவாக்கவும்.
2. `createTask`, `getStatus`, `approvePlan` (அல்லது பொருந்தவில்லை என்றால் பிழையை எழுப்பவும்),
   `sendMessage`, `listSources` ஆகியவற்றைச் செயல்படுத்தவும். நிலையை இயல்பாக்க `this.mapStatus(...)`-ஐப் பயன்படுத்தவும்.
3. நிலையான `providerId`-இன் கீழ் `src/lib/cloudAgent/registry.ts`-இல் பதிவு செய்யவும்.
4. `src/lib/cloudAgent/types.ts`-இல் உள்ள `providerId` literal union-ஐ
   (`CloudAgentTask.providerId` மற்றும் `CreateCloudAgentTaskSchema`) நீட்டிக்கவும்.
5. அதற்கு இணைப்புப் பதிவு தேவைப்பட்டால், வழங்குநரை `src/shared/constants/providers.ts`-இல் சேர்க்கவும்.
   OAuth அடிப்படையிலான வழங்குநர்களுக்கு `src/lib/oauth/providers/`-உம் தேவை.
6. `tests/unit/cloud-agent-*.test.ts`-இன் கீழ் test-களைச் சேர்க்கவும்.
7. இந்த ஆவணத்தையும் dashboard-இன் `CLOUD_AGENTS` constant-ஐயும் புதுப்பிக்கவும்.
