> **உண்மைக்கான ஆதாரம்:** `src/lib/plugins/` (`marketplace.ts`, `manager.ts`, `manifest.ts`,
> `scanner.ts`, `loader.ts`), `src/app/api/plugins/`, மற்றும்
> `src/app/(dashboard)/dashboard/plugins/`
> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-06-28 — v3.8.40

OmniRoute, WordPress பாணியிலான செருகுநிரல் அமைப்புடன் வழங்கப்படுகிறது. செருகுநிரல்கள் தன்னிறைவான
கோப்பகங்கள் — ஒவ்வொன்றிலும் ஒரு `plugin.json` மேனிஃபெஸ்ட் மற்றும் ஒரு நுழைவுக் கோப்பு இருக்கும் — அவை
கோரிக்கை செயலாக்கத் தொடரிலும் (`onRequest` / `onResponse` / `onError`), மேலும்
வாழ்க்கைச்சுழற்சி நிகழ்வுகளிலும் (`onInstall` / `onActivate` / `onDeactivate` / `onUninstall`)
இணைகின்றன.

**செருகுநிரல் சந்தை** என்பது அந்த அமைப்பின் மேலுள்ள கண்டறிதல் அடுக்காகும். இது
நிறுவக்கூடிய செருகுநிரல்களின் உலாவக்கூடிய பட்டியலை வழங்குகிறது. இயல்பாக, இந்தப் பட்டியல்
உள்ளமைந்த சிறிய தொடக்கப் பதிவகமாக இருக்கும்; ஓர் இயக்குநர் இதைத் தனிப்பயன் தொலைநிலைப்
பதிவக URL-க்குச் சுட்டிக்காட்டலாம். அப்படிச் செய்தால், DNS-தீர்மானிக்கும் SSRF பாதுகாப்பு
மூலம் பெறுதல் வலுப்படுத்தப்படும் ([பாதுகாப்பு](#security) என்பதைப் பார்க்கவும்).

ஒவ்வொரு செருகுநிரல் வழித்தடமும் **லூப்பேக் மட்டும்** (அடுக்கு 1 — `LOCAL_ONLY`): செருகுநிரல்கள்
துணைச் செயல்முறைகளில் குறியீட்டை ஏற்றி இயக்குவதால், அங்கீகாரத்தைப் பொருட்படுத்தாமல் லூப்பேக்
அல்லாத தோற்றுவாயிலிருந்து இந்த வழித்தடங்களை அணுக முடியாது.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) என்பதைப் பார்க்கவும்.

## இவை எவ்வாறு ஒன்றிணைந்து செயல்படுகின்றன

```
முகப்புப்பலகை (/dashboard/plugins)
  ├─ "நிறுவப்பட்டவை" தாவல் → GET /api/plugins            (listPlugins)
  │                         POST /api/plugins/scan      (pluginManager.scan)
  │                         POST /api/plugins/{name}/activate|deactivate
  │                         DELETE /api/plugins/{name}   (நிறுவல் நீக்கம்)
  └─ "சந்தை" தாவல்         → GET /api/plugins/marketplace
                              → listMarketplacePlugins()
                                ├─ தனிப்பயன் URL இல்லை → உள்ளமைந்த SEED_REGISTRY
                                └─ தனிப்பயன் URL → isSafeMarketplaceUrl() SSRF பாதுகாப்பு
                                                → safeOutboundFetch(guard:"public-only")
```

- **பதிவக அடுக்கு** — `src/lib/plugins/marketplace.ts`: பட்டியலைப் பட்டியலிடுகிறது /
  தேடுகிறது; ஏதேனும் தோல்வி ஏற்பட்டால் தொடக்கப் பதிவகத்தைப் பயன்படுத்துகிறது.
- **வாழ்க்கைச்சுழற்சி அடுக்கு** — `src/lib/plugins/manager.ts` (`pluginManager` சிங்கிள்டன்):
  நிறுவுதல், மேம்படுத்துதல், செயல்படுத்துதல், செயல்நீக்குதல், நிறுவல் நீக்குதல், ஸ்கேன் செய்தல்,
  தொடக்க ஏற்றுதல்.
- **மேனிஃபெஸ்ட் அடுக்கு** — `src/lib/plugins/manifest.ts`: `plugin.json`-க்கான Zod
  திட்டவடிவம் + இயல்புநிலைகள்.
- **ஸ்கேனர்** — `src/lib/plugins/scanner.ts`: செருகுநிரல் கோப்பகத்தின் கீழ் வட்டில் உள்ள
  செருகுநிரல்களைக் கண்டறிகிறது.
- **ஏற்றி** — `src/lib/plugins/loader.ts`: ஒவ்வொரு செருகுநிரலையும் தனிமைப்படுத்தப்பட்ட
  துணைச் செயல்முறையில் தொடங்கி, IPC வழியாக ஹுக் அழைப்புகளை இடைமுகப்படுத்துகிறது.

## சந்தைப் பட்டியல்

`listMarketplacePlugins()` (`src/lib/plugins/marketplace.ts`) `MarketplaceEntry`
பொருட்களின் பட்டியலை வழங்குகிறது:

| புலம்         | வகை      | குறிப்புகள்                                     |
| ------------- | -------- | ----------------------------------------------- |
| `name`        | string   | kebab-case செருகுநிரல் பெயர்                    |
| `version`     | string   | semver                                          |
| `description` | string   | சுருக்கமான விளக்கம்                             |
| `author`      | string   | ஆசிரியர் / நிறுவனம்                             |
| `license`     | string   | SPDX பாணியிலான உரிம அடையாளம்                    |
| `downloadUrl` | string   | மூலப் பதிவிறக்க URL (காலியாக இருக்கலாம்)        |
| `repository`  | string?  | விருப்பத்தேர்வு களஞ்சிய URL                     |
| `tags`        | string[] | தேடல்/வடிகட்டல் குறிச்சொற்கள்                   |
| `downloads`   | number   | பதிவிறக்க எண்ணிக்கை                             |
| `rating`      | number   | 0–5                                             |
| `verified`    | boolean  | பதிவு சரிபார்க்கப்பட்டதாகக் குறிக்கப்பட்டுள்ளதா |
| `lastUpdated` | string   | ISO போன்ற தேதி சரம்                             |

தனிப்பயன் பதிவக URL எதுவும் உள்ளமைக்கப்படாதபோது, பட்டியல் உள்ளமைந்த
`SEED_REGISTRY` ஆகும் (தற்போது `request-logger`, `rate-limiter`, `cost-tracker`, மற்றும்
`theme-manager`). தொடக்கப் பதிவகம் எப்போதும் கிடைக்கும் — உள்ளமைக்கப்பட்ட தொலைநிலைப்
பதிவகத்தை அணுக முடியாவிட்டாலோ, அது `200` அல்லாத நிலையை வழங்கினாலோ, அல்லது
அடையாளம் காணப்படாத உள்ளடக்கத்தை வழங்கினாலோ, `listMarketplacePlugins()` ஓர்
எச்சரிக்கையைப் பதிவுசெய்து தொடக்கப் பட்டியலைப் பயன்படுத்தும்.

> குறிப்பு: சந்தை **பட்டியல்** (உலாவுதல்/தேடுதல்) முழுமையாக ஒருங்கிணைக்கப்பட்டுள்ளது, ஆனால்
> பட்டியலிலிருந்து ஒரே கிளிக்கில் செய்யும் சந்தை **நிறுவல்** இன்னும் செயல்படுத்தப்படவில்லை —
> சந்தைப் பதிவிலுள்ள முகப்புப்பலகையின் "நிறுவு" பொத்தான் தற்போது
> "விரைவில் வருகிறது" என்ற அறிவிப்பைக் காட்டுகிறது. தற்போது நிறுவல், உள்ளூர் பாதை நிறுவல்
> செயல்முறை (`POST /api/plugins`) மற்றும் வட்டிலுள்ளவற்றைக் கண்டறிதல்
> (`POST /api/plugins/scan`) வழியாக நடைபெறுகிறது.

## REST API

அனைத்து endpoint-களுக்கும் மேலாண்மை அங்கீகாரம் (`requireManagementAuth`) தேவைப்படுகிறது, மேலும் அவை
loopback-க்கு மட்டும் உரியவை — `/api/plugins` மற்றும் `/api/plugins/` ஆகியவை
`LOCAL_ONLY_API_PREFIXES`-இல் (`src/server/authz/routeGuard.ts`) பட்டியலிடப்பட்டுள்ளன.

| Endpoint                         | முறை   | விளக்கம்                                                                    |
| -------------------------------- | ------ | --------------------------------------------------------------------------- |
| `/api/plugins`                   | GET    | நிறுவப்பட்ட plugin-களைப் பட்டியலிடும் (விருப்பமான `?status=` வடிகட்டி)      |
| `/api/plugins`                   | POST   | முழுமையான உள்ளூர் பாதையிலிருந்து ஒரு plugin-ஐ நிறுவும்                      |
| `/api/plugins/scan`              | POST   | plugin கோப்பகத்தை scan செய்து புதிய plugin-களைப் பதிவுசெய்யும்              |
| `/api/plugins/marketplace`       | GET    | marketplace catalog பதிவுகளைப் பட்டியலிடும்                                 |
| `/api/plugins/[name]`            | GET    | நிறுவப்பட்ட plugin விவரங்களைப் பெறும்                                       |
| `/api/plugins/[name]`            | DELETE | ஒரு plugin-ஐ நிறுவல் நீக்கும்                                               |
| `/api/plugins/[name]/activate`   | POST   | செயல்படுத்தும் (ஏற்றுதல் + hook-களைப் பதிவுசெய்தல்)                         |
| `/api/plugins/[name]/deactivate` | POST   | செயலிழக்கச் செய்யும் (`onDeactivate`-ஐ இயக்கி, hook-களின் பதிவை நீக்கும்)   |
| `/api/plugins/[name]/config`     | GET    | plugin உள்ளமைவு + உள்ளமைவு schema-வைப் பெறும்                               |
| `/api/plugins/[name]/config`     | PUT    | plugin உள்ளமைவைப் புதுப்பிக்கும் (schema-வுக்கு எதிராகச் சரிபார்க்கப்படும்) |

`GET /api/plugins`-இன் `status` வடிகட்டி
`installed` / `active` / `inactive` / `error` ஆகியவற்றில் ஒன்றை ஏற்கிறது. செல்லாத மதிப்பு `400`-ஐத் திருப்பும்.

### நிறுவப்பட்ட plugin-களைப் பட்டியலிடுதல்

```bash
curl http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..."
```

### உள்ளூர் பாதையிலிருந்து நிறுவுதல்

```bash
curl -X POST http://localhost:20128/api/plugins \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "path": "/absolute/path/to/my-plugin" }'
```

`path` **முழுமையானதாக** இருக்க வேண்டும்; அதில் `..` traversal segment-களோ
null byte-களோ இருக்கக்கூடாது (Zod மூலம் கட்டாயப்படுத்தப்படுகிறது). மூலக் கோப்பகத்தில் செல்லுபடியாகும்
`plugin.json` இருக்க வேண்டும் (அல்லது அது அத்தகைய கோப்பகத்தின் parent ஆக இருக்க வேண்டும்). வெற்றிபெற்றால், நிறுவப்பட்ட
plugin row-உடன் `201` response வழங்கப்படும்.

### marketplace-ஐ உலாவுதல்

```bash
curl http://localhost:20128/api/plugins/marketplace \
  -H "Cookie: auth_token=..."
```

### plugin உள்ளமைவைப் புதுப்பித்தல்

```bash
curl -X PUT http://localhost:20128/api/plugins/my-plugin/config \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{ "config": { "level": "debug", "maxItems": 100 } }'
```

`PUT .../config`, வழங்கப்பட்ட ஒவ்வொரு மதிப்பையும் plugin-இன்
`configSchema`-வுக்கு எதிராகச் சரிபார்க்கிறது (manifest-இல் அறிவிக்கப்பட்டது): `number` புலங்கள் `min`/`max`-ஐ மதிக்கின்றன;
`select` புலங்கள் அறிவிக்கப்பட்ட `enum`-உடன் பொருந்த வேண்டும். schema-வில் இல்லாத key-கள்
அனுமதிக்கப்படுகின்றன.

## உள்ளமைவு

### Plugin கோப்பகம்

Plugin-கள் OmniRoute தரவுக் கோப்பகத்தின் கீழ் உள்ளன:

```
~/.omniroute/plugins/<plugin-name>/
  ├─ plugin.json
  └─ index.js          # (அல்லது manifest.main சுட்டிக்காட்டும் வேறு ஏதேனும் கோப்பு)
```

`getDefaultPluginDir()` (`src/lib/plugins/scanner.ts`) அந்தக் கோப்பகத்தை
மூன்று படிகளில் தீர்மானிக்கிறது:

1. **`OMNIROUTE_PLUGINS_DIR`**, அமைக்கப்பட்டிருந்தால் — `HOME` என்ன சொன்னாலும், அப்படியே பயன்படுத்தப்படும். இது
   Docker/K8s-க்கான வெளிப்படையான கட்டுப்பாடாகும்; அங்கு plugin tree பொதுவாக container-இன் home கோப்பகத்துடன்
   தொடர்பில்லாத ஒரு பாதையில் bind-mount செய்யப்படுகிறது (#11827).
2. `<home>/.omniroute/plugins`; இங்கு `<home>` என்பது `HOME` / `USERPROFILE`
   சூழல் மாறிகளிலிருந்து பெறப்படுகிறது.
3. process எந்த home-ஐயும் export செய்யாதபோது, `/tmp/.omniroute/plugins`.

தீர்மானிக்கப்பட்ட கோப்பகம் startup-இல் `scanner.dir_resolved` என ஒருமுறை பதிவு செய்யப்படுகிறது; அதில்
தேர்வான input (`OMNIROUTE_PLUGINS_DIR`, `home`, அல்லது `no-home-fallback`) குறிப்பிடப்படும் — இதனால் ஒரு image
அமைதியாகப் படி 3-க்குச் சென்றால், வெற்று plugin பட்டியலை மட்டும் தெரிவிப்பதற்குப் பதிலாக அதையும் குறிப்பிடும்.
`POST /api/plugins/scan`, அங்கு செல்லுபடியாகும்
`plugin.json`-ஐக் கொண்டிருக்கும் எந்த subdirectory-யையும் கண்டறிந்து பதிவுசெய்கிறது; அதே கோப்பகமே
`pluginManager.install()` plugin-களை நகலெடுக்கும் root ஆகும், எனவே override ஒன்று discovery மற்றும்
installation ஆகிய இரண்டையும் ஒன்றாக நகர்த்தும்.

> **`OMNIROUTE_PLUGINS_DIR` என்பது `OMNIROUTE_PLUGIN_PATH` அல்ல.** பின்னையது
> `omniroute` subcommand-களைச் சேர்க்கும் `omniroute-cmd-*` npm package-களைக் கண்டறிவதற்காக CLI command-plugin loader (`bin/cli/plugins.mjs`) மூலம் மட்டுமே படிக்கப்படுகிறது —
> இங்கு விவரிக்கப்பட்டுள்ள runtime scanner மீது அதற்கு எந்தத் தாக்கமும் இல்லை.
> அந்தப் பகுதியைப் பற்றி அறிய [PLUGINS.md](./PLUGINS.md)-ஐப் பார்க்கவும்.

### தனிப்பயன் marketplace registry URL

marketplace catalog மூலம் `pluginMarketplaceUrl` setting-இலிருந்து படிக்கப்படுகிறது
(`src/lib/plugins/marketplace.ts`, `settings.pluginMarketplaceUrl`-ஐப் படிக்கிறது). அது
ஒரு `http(s)` URL-ஆக அமைக்கப்பட்டிருக்கும்போது, `listMarketplacePlugins()` அந்த URL-ஐப் பெற்று,
மேல் மட்ட JSON entry array ஒன்றையோ அல்லது `plugins` array கொண்ட object ஒன்றையோ ஏற்கிறது;
string `name` இல்லாத entry-கள் வடிகட்டப்படுகின்றன. அமைக்கப்படாதபோது (அல்லது fetch
SSRF guard-இல் தோல்வியடைந்தால் / தவறான response-ஐத் திருப்பினால்), உள்ளமைந்த seed registry
பயன்படுத்தப்படுகிறது.

dashboard-இன் "Marketplace" tab இந்த URL-க்கான புலத்தை வழங்குகிறது (`GET /api/settings`-இலிருந்து
மீண்டும் படிக்கப்படுகிறது).

> செயலாக்கக் குறிப்பு: dashboard-இன் "Save" செயல்
> `pluginMarketplaceUrl`-ஐ `PATCH /api/settings`-க்கு அனுப்புகிறது. இதை எழுதும் நேரத்தில், இந்த
> key `updateSettingsSchema`-வில் அறிவிக்கப்படவில்லை
> (`src/shared/validation/settingsSchemas.ts`), எனவே இதைச் சார்ந்திருப்பதற்கு முன் உங்கள்
> release-இல் persistence-ஐச் சரிபார்க்கவும் — settings store-இல் key வந்தவுடன் **read**
> பாதை (`getSettings()` →
> `listMarketplacePlugins()`) அதை மதிக்கிறது.

## பாதுகாப்பு

### வழித்தட அடுக்கு — loopback மட்டும்

Plugins தொடங்கப்பட்ட child processes-இல் குறியீட்டை இயக்குவதால், முழு `/api/plugins`
மேற்பரப்பும் `LOCAL_ONLY` (Tier 1) என வகைப்படுத்தப்பட்டுள்ளது. எந்த auth சரிபார்ப்புக்கும்
**முன்பாக** loopback அமலாக்கம் நிபந்தனையின்றி இயங்குகிறது; எனவே ஒரு tunnel வழியாக
கணினியை அடையும் கசிந்த management token-ஆலும் கூட ஒரு plugin-ஐ நிறுவவோ,
செயல்படுத்தவோ அல்லது நிறுவல் நீக்கவோ முடியாது.
[`docs/security/ROUTE_GUARD_TIERS.md`](../security/ROUTE_GUARD_TIERS.md) மற்றும்
Hard Rules #15 / #17 ஆகியவற்றைப் பார்க்கவும்.

### Marketplace registry SSRF பாதுகாப்பு

தனிப்பயன் registry URL என்பது தாக்குநரால் பாதிக்கப்படக்கூடிய configuration என்பதால்,
அதைப் பெறுவதற்கு முன் `listMarketplacePlugins()` இரண்டு அடுக்குகள் வழியாகச் சரிபார்க்கிறது:

1. **`isSafeMarketplaceUrl(url)`** (`src/lib/plugins/marketplace.ts`):
   - `http:` / `https:` அல்லாத எதையும் நிராகரிக்கிறது.
   - canonical `isPrivateHost`
     (`src/shared/network/outboundUrlGuard.ts`) மூலம் literal private/loopback/link-local/ULA hosts-ஐ
     (IPv4-mapped முகவரிகள் உட்பட IPv4 **மற்றும்** IPv6 இரண்டையும்) நிராகரிக்கிறது.
   - **`A` மற்றும் `AAAA` இரு வகைப் பதிவுகளையும்** resolve செய்து, resolve செய்யப்பட்ட
     முகவரிகளில் **ஏதேனும் ஒன்று** private என்றால் நிராகரிக்கிறது — இதனால்
     public-hostname → private-IP bypass மூடப்படுகிறது.
   - **தோல்வியின்போது பாதுகாப்பாக நிராகரிக்கிறது**: DNS resolution தோல்வியடைந்தால்
     URL நிராகரிக்கப்படுகிறது.
2. **`safeOutboundFetch(url, { guard: "public-only", timeoutMs: 5000 })`**
   (`src/shared/network/safeOutboundFetch.ts`): பெறும் நேரத்தில் public-only URL
   guard-ஐ மீண்டும் பயன்படுத்தி, **redirects-ஐத் தடுக்கிறது** (public → private `30x`
   pivot அனுமதிக்கப்படாது).

ஏதேனும் ஓர் அடுக்கில் URL தோல்வியடைந்தாலும் request நிறுத்தப்படாது — marketplace
அமைதியாக உள்ளமைக்கப்பட்ட seed registry-க்குத் திரும்பி, எச்சரிக்கையைப் பதிவு செய்யும்.

> A + AAAA இரண்டையும் குறிப்பாக resolve செய்யவும், IPv4-only சரிபார்ப்புக்குப் பதிலாக
> canonical `isPrivateHost`-ஐப் பயன்படுத்தவும் இந்த guard PR #3774-இல்
> வலுப்படுத்தப்பட்டது.

### Plugin இயக்கத் தனிமைப்படுத்தல்

- **Process தனிமைப்படுத்தல்** — `loadPlugin()` (`src/lib/plugins/loader.ts`) ஒவ்வொரு
  plugin-ஐயும் தனித்தனி Node.js child process-இல் தொடங்கி, IPC வழியாகத் தொடர்புகொள்கிறது.
  Hook அழைப்புகளுக்கு `SIGTERM` → `SIGKILL` தீவிரப்படுத்தலுடன் timeout உள்ளது.
- **Env அனுமதிப்பட்டியல்** — child process அனுமதிப்பட்டியலில் உள்ள environment
  variables-ஐ மட்டுமே பெறுகிறது; manifest `env` permission-ஐக் கோரும்போது மட்டுமே
  விரிவான தொகுப்பு வழங்கப்படுகிறது.
- **Path containment** — எந்த copy அல்லது recursive delete செயலுக்கும் முன்பாக,
  plugin directory மற்றும் `manifest.main` ஆகியவை நிர்வகிக்கப்படும் plugin root-ன்
  **உள்ளேயே** resolve ஆகின்றன என்பதை install/upgrade/uninstall செயல்கள் உறுதிப்படுத்துகின்றன
  (மாற்றியமைக்கப்பட்ட DB paths மற்றும் `manifest.main`-இல் உள்ள `../` traversal-க்கு
  எதிராகப் பாதுகாக்கிறது). செயல்படுத்தும்போது `realpath` வழியாக symlinks resolve
  செய்யப்படுகின்றன; plugin directory-யிலிருந்து வெளியேறும் entry point-ஐ ஏற்றுவது
  மறுக்கப்படுகிறது.
- **விருப்பத்திற்குரிய integrity pin** — manifest ஒன்றில் `integrity`
  (`sha256-<base64>`, SRI format) field-ஐ அறிவிக்கலாம். அது இருந்தால், loader
  load செய்யும் நேரத்தில் entry file hash-ஐச் சரிபார்த்து, பொருந்தாதபோது செயல்படுத்த
  மறுக்கிறது. இது விருப்பத்திற்குரிய tamper-detection மட்டுமே; **பாதுகாப்பு எல்லை
  அல்ல** — loopback-only routing மற்றும் permission model ஆகியவையே உண்மையான
  எல்லைகள்.

## Manifest (`plugin.json`)

`PluginManifestSchema` (`src/lib/plugins/manifest.ts`) மூலம் சரிபார்க்கப்படுகிறது:

| Field              | Type      | குறிப்புகள்                                                  |
| ------------------ | --------- | ------------------------------------------------------------ |
| `name`             | string    | கட்டாயம்; kebab-case (`^[a-z0-9-]+$`), 1–100 எழுத்துகள்      |
| `version`          | string    | கட்டாயம்; semver (`MAJOR.MINOR.PATCH`)                       |
| `description`      | string?   | ≤ 500 எழுத்துகள்                                             |
| `author`           | string?   | ≤ 200 எழுத்துகள்                                             |
| `license`          | string?   | இயல்புநிலை `MIT`                                             |
| `main`             | string?   | Entry file; இயல்புநிலை `index.js`                            |
| `source`           | enum?     | `local` \| `marketplace` (இயல்புநிலை `local`)                |
| `tags`             | string[]? | தேடல் tags                                                   |
| `requires`         | object?   | `{ omniroute?, permissions[] }`                              |
| `hooks`            | object?   | plugin செயல்படுத்தும் hooks-ஐ அறிவிக்கும் boolean மதிப்புகள் |
| `skills`           | object[]? | விருப்பத்திற்குரிய skill வரையறைகள்                           |
| `enabledByDefault` | boolean?  | நிறுவும்போது தானாகச் செயல்படுத்துதல்                         |
| `configSchema`     | object?   | config fields-இன் map (`string`/`number`/`boolean`/`select`) |
| `integrity`        | string?   | விருப்பத்திற்குரிய `sha256-<base64>` entry-file pin          |

Permissions பின்வரும் enum-இலிருந்து பெறப்படுகின்றன:
`network` / `file-read` / `file-write` / `env` / `exec`.

## வாழ்க்கைச்சுழற்சி ஓட்டம்

```
install (POST /api/plugins, பாதை)
  → manifest-ஐ ஸ்கேன் செய்து/சரிபார் → staging-க்குப் பிரதி செய் → main கோப்பகம் உள்ளேயே இருப்பதை உறுதிசெய்
  → ~/.omniroute/plugins/<name>-க்கு அணுவியல் முறையில் மறுபெயரிடு → DB வரிசையைச் சேர்
  → onInstall-ஐத் தூண்டு → enabledByDefault எனில்: செயல்படுத்து

activate (POST /api/plugins/{name}/activate)
  → realpath உள்ளடக்கச் சரிபார்ப்பு → loadPlugin() (துணைச் செயல்முறையைத் தொடங்கு)
  → அறிவிக்கப்பட்ட hooks-ஐப் பதிவுசெய் → status = "active" → onActivate-ஐத் தூண்டு

deactivate (POST /api/plugins/{name}/deactivate)
  → onDeactivate-ஐத் தூண்டு (பதிவுநீக்கத்திற்கு முன்) → hooks-ஐப் பதிவுநீக்கு
  → துணைச் செயல்முறையை நிறுத்து → status = "inactive"

uninstall (DELETE /api/plugins/{name})
  → செயலில் இருந்தால் செயல்நீக்கு → onUninstall-ஐத் தூண்டு
  → உள்ளடக்கச் சரிபார்ப்புடன் plugin கோப்பகத்தைச் சுழல்நிலையில் நீக்கு → DB வரிசையை நீக்கு
```

நிறுவப்பட்ட பதிப்பைவிட manifest பதிப்பு **கண்டிப்பாகப் புதியதாக** உள்ள ஒரு கோப்பகத்திற்கு எதிராக `install`-ஐ மீண்டும் இயக்குவது தானாக மேம்படுத்தும் (சுத்தமான மறுநிறுவல்; config இயல்புநிலைகளுக்கு மீட்டமைக்கப்படும்). அதே அல்லது பழைய பதிப்பு நிராகரிக்கப்படும்.

## கட்டுப்பாட்டுப் பலகம்

`/dashboard/plugins`-இல் உள்ள கட்டுப்பாட்டுப் பலகப் பக்கம்
(`src/app/(dashboard)/dashboard/plugins/page.tsx`) இரண்டு தாவல்களை வழங்குகிறது:

- **நிறுவப்பட்டவை** — நிறுவப்பட்ட plugins-ஐ அவை அறிவித்த hooks உடன் பட்டியலிடுகிறது; செயல்படுத்து/செயல்நீக்கு மாற்றி, நிறுவல்நீக்கு பொத்தான் மற்றும் "Plugins-ஐத் தேடு" செயல் ஆகியவற்றையும் வழங்குகிறது (`POST /api/plugins/scan`).
- **சந்தை** — தனிப்பயன் registry URL-ஐ அமைப்பதற்கான புலத்துடன் `GET /api/plugins/marketplace`-இலிருந்து பெறப்பட்ட பட்டியலைக் காட்டுகிறது.

ஒவ்வொரு plugin-க்குமான config பக்கம் `/dashboard/plugins/[name]/config`-இல் உள்ளது
(`src/app/(dashboard)/dashboard/plugins/[name]/config/page.tsx`).
