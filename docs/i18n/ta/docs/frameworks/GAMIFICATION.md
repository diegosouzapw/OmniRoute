இந்த அமைப்பு, **முக்கிய செயல்பாட்டுப் பாதையில் பூஜ்ஜியத் தாமதத்தைக் கொண்டிருக்குமாறு** வடிவமைக்கப்பட்டுள்ளது — விளையாட்டுமயமாக்கல் நிகழ்வுகள் கோரிக்கை செயலாக்கத் தொடரிலிருந்து அனுப்பிவிட்டு மறக்கப்படும் முறையில் அனுப்பப்படுகின்றன; மேலும் அவை ஒருபோதும் LLM பதிலைத் தடுப்பதில்லை.

## மேலோட்டம்

### நோக்கம்

காணக்கூடிய முன்னேற்றம் (XP, நிலைகள், பதக்கங்கள்), சமூகச் சான்று (தரவரிசைப் பட்டியல்கள்) மற்றும் பொருளாதார ஊக்கங்கள் (டோக்கன் பகிர்வு, அழைப்பு வெகுமதிகள்) ஆகியவற்றை வழங்குவதன் மூலம் பயனர் ஈடுபாட்டையும் தக்கவைப்பையும் அதிகரித்தல்.

### வரம்பு

| அம்சம்                  | விளக்கம்                                                                         |
| ----------------------- | -------------------------------------------------------------------------------- |
| XP & நிலைகள்            | ஒவ்வொரு செயலுக்கும் XP ஈட்டுதல்; பல்லுறுப்புக்கோட்டின் அடிப்படையில் நிலை உயர்தல் |
| பதக்கங்கள்              | 4 அரிதான நிலைகளைக் கொண்ட 5 வகைகளில் 20+ சாதனைகள்                                 |
| தொடர்கள்                | தற்போதைய/நீண்டகாலத் தொடருடன் தினசரி செயலில் உள்ள பயன்பாட்டைக் கண்காணித்தல்       |
| தரவரிசைப் பட்டியல்கள்   | உலகளாவிய, வாராந்திர, மாதாந்திர, டோக்கன் பகிர்வு மற்றும் பங்களிப்பு வரம்புகள்     |
| டோக்கன் பகிர்வு         | இரட்டைப் பதிவு பேரேட்டின் மூலம் பயனர்களுக்கிடையே கிரெடிட்களை மாற்றுதல்           |
| அழைப்பு & மீட்டெடுத்தல் | SHA-256 ஹாஷ் செய்யப்பட்ட சேமிப்பகத்துடன் பரிந்துரைக் குறியீடுகள்                 |
| சமூகச் சேவையகங்கள்      | வெளிப்புற OmniRoute நிகழ்வுகளுடன் கூட்டிணைதல்                                    |
| மோசடித் தடுப்பு         | சேவையகப் பக்க மதிப்பீடு, வீத வரம்பிடல், z-score முரண்பாடு கண்டறிதல்              |

### வடிவமைப்புக் கொள்கைகள்

1. **உள்ளூர்-முதன்மை** — அனைத்து நிலைகளும் SQLite-இல் உள்ளன; வெளிப்புறச் சேவைகள் தேவையில்லை.
2. **தடையற்றது** — நிகழ்வுகள் அனுப்பிவிட்டு மறக்கப்படும் முறையில் செயல்படுகின்றன; LLM பதில் பாதை
   ஒருபோதும் விளையாட்டுமயமாக்கல் தர்க்கத்தால் தாமதப்படுத்தப்படுவதில்லை.
3. **சேவையகமே அதிகாரபூர்வமானது** — XP சேவையகப் பக்கத்தில் மட்டுமே கணக்கிடப்படுகிறது; கிளையன்ட்களால்
   மதிப்பெண்களைச் செயற்கையாக அதிகரிக்க முடியாது.
4. **தனியுரிமையை மதிப்பது** — தரவரிசைப் பட்டியலில் பங்கேற்பது விருப்பத்தேர்வுக்குரியது; பயனர்கள்
   தங்கள் சுயவிவரத்தை மறைக்கலாம்.
5. **கூட்டிணைவுக்குத் தயார்** — கையொப்பமிடப்பட்ட API வழியாக சமூகச் சேவையகங்கள் மதிப்பெண்களைத் தள்ளலாம்;
   ஒத்திசைவு மேலெழுதும் முறையிலானது, கூட்டல் முறையிலானது அல்ல.

### உயர்நிலைச் செயலோட்டம்

```
கிளையன்ட் கோரிக்கை

      → மேல்நிலைப் பதில் கிளையன்டுக்கு அனுப்பப்படுகிறது
      → setImmediate (அனுப்பிவிட்டு மறக்கப்படும் முறை):
        → emitGamificationEvent()           [src/lib/gamification/events.ts]
          → awardXp()                       [src/lib/gamification/xp.ts]
          → updateStreak()                  [src/lib/gamification/streaks.ts]
          → evaluateBadges()                [src/lib/gamification/badges.ts]
```

## XP / நிலை அமைப்பு

**கோப்பு:** `src/lib/gamification/xp.ts`

### நிலை வளைவு

`n` ஆம் நிலையை அடையத் தேவையான XP, ஒரு பல்லுறுப்புக்கோவை வளைவைப் பின்பற்றுகிறது:

```
xp_for_level(n) = floor(100 * n^1.5)
```

| நிலை | அடுத்த நிலைக்கான XP | ஒட்டுமொத்த XP | பட்டம்          |
| ---- | ------------------- | ------------- | --------------- |
| 1    | 100                 | 100           | தொடக்கநிலையாளர் |
| 5    | 1,118               | 2,415         | தொடக்கநிலையாளர் |
| 10   | 3,162               | 10,523        | ஆய்வாளர்        |
| 25   | 12,500              | 86,024        | ஆய்வாளர்        |
| 50   | 35,355              | 345,529       | நிபுணர்         |
| 75   | 64,952              | 948,683       | வல்லுநர்        |
| 100  | 100,000             | 2,050,000     | புராண நாயகர்    |

### பட்டங்கள்

| நிலை வரம்பு | பட்டம்          |
| ----------- | --------------- |

| `request`         | 1   | OmniRoute வழியாக அனுப்பப்படும் ஒவ்வொரு API கோரிக்கைக்கும்                |
| `provider_switch` | 5   | வேறொரு வழங்குநருக்கு மாறுதல்                                             |
| `model_switch`    | 3   | வேறொரு மாதிரிக்கு மாறுதல்                                                |
| `combo_create`    | 10  | புதிய combo-ஐ உருவாக்குதல்                                               |
| `combo_use`       | 2   | ஒரு கோரிக்கைக்காக combo-ஐப் பயன்படுத்துதல்                               |
| `token_share`     | 1   | மற்றொரு பயனருடன் பகிரப்படும் ஒவ்வொரு 1 000 token-களுக்கும்               |

| `streak_bonus`    | 2   | தொடர்ச்சியான ஒவ்வொரு streak நாளுக்கும் (streak நீளத்தால் பெருக்கப்படும்) |
| `badge_unlock`    | 10  | badge-ஐத் திறத்தல்                                                       |

### வழங்கல் செயல்முறை

```typescript
export async function awardXp(
  apiKeyId: string,
  action: XpAction,
  metadata?: Record<string, unknown>
): Promise<{ xp: number; level: number; title: string; levelUp: boolean }>;
```

1. XP அளவைப் பெற `XP_REWARDS[action]`-ஐத் தேடவும்.
2. `checkRateLimit()` வழியாக அனுப்பவும் (மோசடித் தடுப்பு: ஒரு key-க்கு நிமிடத்திற்கு அதிகபட்சம் 1000 XP).
3. ஒரு transaction-ஐத் திறக்கவும்:
   - தற்போதைய `user_levels` row-ஐப் படிக்கவும்.
   - XP-ஐச் சேர்த்து, `levelFromXp(totalXp)` வழியாக நிலையை மீண்டும் கணக்கிடவும்.
   - நிலை மாறியிருந்தால், `levelUp = true` என அமைக்கவும்.
   - `user_levels` row-ஐப் புதுப்பிக்கவும்.
   - `xp_audit_log`-இல் செருகவும்.
4. முடிவைத் திருப்பி அனுப்பவும். அழைப்பாளர் அறிவிப்புகளைக் கையாளுகிறார்.

### உதவிச் செயல்பாடு: `levelFromXp(totalXp)`

ஒட்டுமொத்த XP ஆனது `totalXp`-ஐத் தாண்டும் வரை, நிலை 1..100 ஊடாகச் சென்று `xp_for_level(n)`-ஐக் கூட்டுகிறது. வரம்பைப் பூர்த்திசெய்யும் மிக உயர்ந்த நிலையைத் திருப்பி அனுப்புகிறது.
இது O(100) — நிலைகள் அதிகபட்சம் 100 ஆக வரம்பிடப்பட்டுள்ளதால் ஏற்றுக்கொள்ளத்தக்கது.

### மதிப்பீட்டுச் செயல்முறை

```
emitGamificationEvent(event)
  → evaluateBadges(apiKeyId, event)
    → getBadgeDefinitions()           # அனைத்து வரையறைகளும்
    → getUserBadges(apiKeyId)         # ஏற்கெனவே பெறப்பட்டவை (தவிர்க்கவும்)
    → பெறப்படாத ஒவ்வொரு badge-க்கும்:
       → matchesCriteria(badge, event, userState)
       → பொருந்தினால்: awardBadge(apiKeyId, badgeId)
         → அறிவிப்பு payload-ஐத் திருப்பி அனுப்பவும்
```

மதிப்பீடு **நிகழ்வு-சார்ந்தது** — இது ஒவ்வொரு gamification event-க்குப் பிறகும் இயங்குகிறது, ஆனால் event action-உடன் `criteria.type` பொருந்தும் badge-களை மட்டுமே சரிபார்க்கிறது. இது மதிப்பீட்டை வேகமாக வைத்திருக்கிறது (பெரும்பாலான event-களுக்கு < 5ms).

### `matchesCriteria(badge, event, userState)`

## தொடர் கண்காணிப்பான்

**கோப்பு:** `src/lib/gamification/streaks.ts`

### தரவு மாதிரி

தொடர்கள், பெயர்வெளியிடப்பட்ட விசைகளின் கீழ் `key_value` அட்டவணையில் (பகிரப்பட்ட பயன்பாட்டு அட்டவணை) சேமிக்கப்படுகின்றன:

| விசை                          | மதிப்பு                          | விளக்கம்                |
| ----------------------------- | -------------------------------- | ----------------------- |
| `gamification:streak:{keyId}` | `{current},{longest},{lastDate}` | செயலில் உள்ள தொடர் தரவு |

### தர்க்கம்

```typescript
export async function updateStreak(
  apiKeyId: string
): Promise<{ current: number; longest: number; milestone: boolean }>;
```

1. `key_value` இலிருந்து தொடர் பதிவைப் படிக்கவும்.
2. `{current}`, `{longest}`, `{lastDate}` (ISO தேதி சரம்) ஆகியவற்றைப் பகுப்பாய்வு செய்யவும்.
3. `lastDate === today` எனில் — மாற்றமில்லை (இன்று ஏற்கனவே கணக்கிடப்பட்டது).
4. `lastDate === yesterday` எனில் — `current` மதிப்பை அதிகரிக்கவும்; தேவைப்பட்டால் `longest` மதிப்பைப் புதுப்பிக்கவும்.
5. `lastDate < yesterday` எனில் — `current = 1` என மீட்டமைக்கவும் (தொடர் முறிந்தது).
6. புதுப்பிக்கப்பட்ட பதிவை எழுதவும்.
7. மைல்கற்களைச் சரிபார்க்கவும்: 7, 14, 30, 60, 90, 180, 365 நாட்கள். ஏதேனும் ஒன்றைக் கடந்திருந்தால்,
   `milestone = true` என அமைக்கவும் (அழைப்பாளர் XP வழங்கி, பதக்கங்களைச் சரிபார்ப்பார்).

### விளிம்பு நிலைகள்

- **நேர மண்டலம்**: தொடர்கள் UTC தேதிகளைப் பயன்படுத்துகின்றன (`new Date().toISOString().slice(0, 10)`).
  இது திட்டமிட்டதே — ஒரே நிலையான நேர மண்டலம், நேர மண்டலங்களுக்கு இடையே மாறுவதன் மூலம்
  அமைப்பைத் தவறாகப் பயன்படுத்துவதைத் தடுக்கிறது.
- **புதிய பயனர்கள்**: தொடர் பதிவு எதுவும் இருக்காது; முதல் கோரிக்கை அதை
  `current=1, longest=1, lastDate=today` என்ற மதிப்புகளுடன் உருவாக்கும்.
- **ஒரு நாளில் பல கோரிக்கைகள்**: UTC நாளின் முதல் கோரிக்கை மட்டுமே
  தொடரை அதிகரிக்கும்.

### தரவரிசைக் கணக்கீடு

தரவரிசைகள் சேமிக்கப்படுவதில்லை; அவை **படிக்கும் நேரத்தில் கணக்கிடப்படுகின்றன**. இது காலாவதியான தரவரிசைத் தரவைத் தவிர்த்து,
குறிப்பிட்ட கால இடைவெளிகளில் தரவரிசையை மீண்டும் கணக்கிடும் பணிகளுக்கான தேவையை நீக்குகிறது.

```typescript
export async function getLeaderboard(
  scope: LeaderboardScope,
  period: string,
  limit: number,
  offset: number
): Promise<{ entries: LeaderboardEntry[]; total: number }>;
```

வினவல் முறை:

```sql
SELECT api_key_id, score,
       RANK() OVER (ORDER BY score DESC) as rank
FROM leaderboard
WHERE scope = ? AND period = ?
ORDER BY score DESC
LIMIT ? OFFSET ?
```

### காலச் சுழற்சி

வாராந்திர மற்றும் மாதாந்திர முன்னிலைப் பட்டியல்கள் தானாகச் சுழல்கின்றன:

1. **காப்பகப்படுத்துதல்**: கால எல்லையில், தற்போதைய உள்ளீடுகளைக் கால அடையாளத்துடன்
   `leaderboard_archive` என்பதற்கு நகலெடுக்கவும்.
2. **மீட்டமைத்தல்**: காலாவதியான காலத்திற்கான உள்ளீடுகளை நீக்கவும்.
3. **தூண்டுதல்**: ஒவ்வொரு `updateLeaderboard()` அழைப்பின்போதும் சரிபார்க்கப்படும்; புதிய காலத்தின் முதல் கோரிக்கை
   சுழற்சியைத் தூண்டும்.

இதன் மூலம் வாராந்திரப் பட்டியல்கள் ஒவ்வொரு திங்கட்கிழமையும் 00:00 UTC-க்கு மீட்டமைக்கப்படுவதும், மாதாந்திரப் பட்டியல்கள்
ஒவ்வொரு மாதத்தின் 1-ஆம் தேதியிலும் மீட்டமைக்கப்படுவதும் உறுதிசெய்யப்படுகிறது.

## டோக்கன் பகிர்வு

**கோப்பு:** `src/lib/gamification/sharing.ts`

### இரட்டைப் பதிவு பேரேடு

ஒவ்வொரு பரிமாற்றமும் `token_ledger`-இல் இரண்டு வரிசைகளை உருவாக்குகிறது:

| வரிசை | `from_key_id` | `to_key_id` | `amount` |
| ----- | ------------- | ----------- | -------- |
| பற்று | அனுப்புநர்    | பெறுநர்     | +தொகை    |
| வரவு  | பெறுநர்       | அனுப்புநர்  | -தொகை    |

பொறுங்கள் — பின்பற்றப்படும் மரபு இதுதான்:

| வரிசை      | `from_key_id` | `to_key_id` | `amount` | பொருள்                              |
| ---------- | ------------- | ----------- | -------- | ----------------------------------- |
| அனுப்புதல் | அனுப்புநர்    | பெறுநர்     | +தொகை    | அனுப்புநரிடமிருந்து வெளியேறும் தொகை |
| பெறுதல்    | பெறுநர்       | அனுப்புநர்  | +தொகை    | பெறுநருக்கு உள்வரும் தொகை           |

இருப்பு இவ்வாறு கணக்கிடப்படுகிறது:

```sql
SELECT
  COALESCE(SUM(CASE WHEN to_key_id = ? THEN amount ELSE 0 END), 0)
  - COALESCE(SUM(CASE WHEN from_key_id = ? THEN amount ELSE 0 END), 0)
  AS balance
FROM token_ledger
WHERE from_key_id = ? OR to_key_id = ?
```

### பரிமாற்றச் செயல்முறை

```typescript
export async function transferTokens(
  fromKeyId: string,
  toKeyId: string,
  amount: number,
  idempotencyKey: string
): Promise<{ success: boolean; balance: number }>;
```

1. **சரிபார்த்தல்**: `amount > 0`, `fromKeyId !== toKeyId`.
2. **ஒருமுறைச் செயலாக்கம்**: `idempotency_key` ஏற்கெனவே பேரேட்டில் உள்ளதா எனச் சரிபார்க்கவும்.
   இருந்தால், தற்காலிகச் சேமிப்பிலுள்ள முடிவைத் திருப்பியளிக்கவும்.
3. **பரிவர்த்தனை** (ஒற்றை SQLite பரிவர்த்தனை):
   a. அனுப்புநரின் இருப்பைக் கணக்கிடவும்.
   b. `balance < amount` எனில், நிறுத்தவும் (போதுமான நிதி இல்லை).
   c. அனுப்புதல் வரிசையைச் சேர்க்கவும் (`from=sender,` என்பதைத் திருப்பியளிக்கவும்.

### வீத வரம்பிடல்

- ஒவ்வொரு API விசைக்கும் நிமிடத்திற்கு அதிகபட்சம் 10 பரிமாற்றங்கள்.
- ஒரு தனிப்பட்ட பரிமாற்றத்திற்கு அதிகபட்சம் 10,000 டோக்கன்கள்.
- ஒவ்வொரு API விசைக்கும் ஒரு நாளில் அதிகபட்சம் 100,000 டோக்கன்களைப் பரிமாற்றலாம்.

## அழைப்பு மற்றும் டோக்கன் மீட்பு

### குறியீட்டு வடிவம்

- **குறியீடு**: மனிதர்கள் எளிதில் படிக்கக்கூடிய, பயனருக்குக் காட்டப்படும் 8-எழுத்து எண்மக் குறியீடு (எ.கா., `A3K9-X7M2`).
- **டோக்கன்**: 32-பைட் சீரற்ற டோக்கன், SHA-256 ஹாஷாகச் சேமிக்கப்படும். நிரல்முறை மீட்பிற்குப் பயன்படுத்தப்படுகிறது (எ.கா., URL இணைப்புகள்).

| `code`       | `A3K9X7M2` (தனித்துவமானது, அட்டவணைப்படுத்தப்பட்டது) |
| `token_hash` | SHA-256(raw_token)                                  |

மூல டோக்கன் உருவாக்கப்படும்போது சரியாக ஒருமுறை மட்டுமே பயனருக்குத் திருப்பியளிக்கப்படுகிறது. OmniRoute அதை மீண்டும் ஒருபோதும் சேமிப்பதோ காட்டுவதோ இல்லை — ஹாஷ் மட்டுமே தொடர்ந்து நிலைத்திருக்கும்.

### சுயப் பரிந்துரைத் தடுப்பு

ஒரு பயனர் குறியீட்டை மீட்டெடுக்கும்போது, அமைப்பு பின்வருவனவற்றைச் சரிபார்க்கிறது:

1. குறியீடு வேறொரு `api_key_id`-க்குச் சொந்தமானது.
2. மீட்டெடுக்கும் பயனர் அதே பரிந்துரையாளரிடமிருந்து எந்தவொரு குறியீட்டையும் முன்பு மீட்டெடுக்கவில்லை (`invite_tokens` + மீட்புப் பதிவில் இணைக்கப்படுகிறது).

இந்தச் சரிபார்ப்புகளில் ஏதேனும் ஒன்று தோல்வியடைந்தால், தெளிவான பிழைச் செய்தியுடன் மீட்பு நிராகரிக்கப்படும்.

### காலாவதி மற்றும் வரம்புகள்

- இயல்புநிலை `max_uses`: 10 (உருவாக்கும்போது உள்ளமைக்கக்கூடியது).
- இயல்புநிலை `expires_at`: உருவாக்கியதிலிருந்து 30 நாட்கள்.
- காலாவதியான அல்லது பயன்பாடுகள் தீர்ந்துவிட்ட குறியீடுகள் HTTP 410 Gone என்பதைத் திருப்பியளிக்கும்.

## சமூக சேவையகக் கூட்டமைப்பு

**கோப்பு:** `src/lib/gamification/servers.ts`

### இணைத்தல்

தொலைநிலை சேவையகம் வழங்கும் அழைப்பு டோக்கன் மூலம் ஒரு சமூக சேவையகம் பதிவுசெய்யப்படுகிறது. உள்ளூர் நிறுவல்:

1. அழைப்பு டோக்கனைப் பெறுகிறது (எ.கா., டாஷ்போர்டில் ஒட்டப்படுகிறது).
2. டோக்கனைச் சரிபார்த்து தற்போதைய முன்னிலைப் பட்டியலைப் பெற, தொலைநிலை சேவையகத்தில் `POST /api/gamification/federation/leaderboard` ஐ அழைக்கிறது.
3. சேவையகப் பதிவை `status: connected` உடன் சேமிக்கிறது.

### ஒத்திசைவு மாதிரி

கூட்டமைப்பு கூட்டல் ஒத்திசைவைப் பயன்படுத்தாமல், **மேலெழுதும் ஒத்திசைவைப்** பயன்படுத்துகிறது:

```
உள்ளூர் நிறுவல்                  சமூக சேவையகம்
     │                              │
     ├── மதிப்பெண்ணை அனுப்பு ─────►│  POST /federation/score
     │   { api_key_id, score }      │  (சேவையகம் டோக்கன் ஹாஷைச் சரிபார்க்கிறது)
     │                              │
     ├── முன்னிலைப் பட்டியலைப் பெறு ►│  GET /federation/leaderboard
     │◄── முதல்-N பதிவுகள் ─────────┤  (உள்ளூர் தற்காலிகச் சேமிப்பை மேலெழுதுகிறது)
     │                              │
     └── நிலைச் சரிபார்ப்பு ────────►│  GET /federation/health
         (ஒவ்வொரு 60s-க்கும், காலக்கெடு 5s) │
```

### அங்கீகாரம்

கூட்டமைப்புக் கோரிக்கைகளில் பின்வருபவை அடங்கும்:

```
Authorization: Bearer <raw_token>
X-Federation-Version: 1
```

தொலைநிலை சேவையகம் டோக்கனை ஹாஷ் செய்து, அதற்குப் பொருந்தும் `community_servers` வரிசையைத் தேடுகிறது. இது சேமிக்கப்பட்ட ஹாஷைப் பரிமாற்றுவதைத் தவிர்க்கிறது.

### நிலை கண்காணிப்பு

ஒவ்வொரு சேவையகப் பதிவும் பின்வருவனவற்றைக் கண்காணிக்கிறது:

| புலம்       | விளக்கம்                                                 |
| ----------- | -------------------------------------------------------- |
| `status`    | `connected`, `degraded`, `unreachable`                   |
| `last_sync` | கடைசியாக வெற்றிகரமாக ஒத்திசைக்கப்பட்டதன் ISO நேரமுத்திரை |
| `failures`  | தொடர்ச்சியான நிலைச் சரிபார்ப்புத் தோல்விகள்              |

தொடர்ந்து 5 தோல்விகளுக்குப் பிறகு, நிலை `unreachable` என மாறுகிறது; கைமுறை நிலைச் சரிபார்ப்பு வெற்றிபெறும் வரை ஒத்திசைவு இடைநிறுத்தப்படுகிறது.

## மோசடித் தடுப்பு

**கோப்பு:** `src/lib/gamification/antiCheat.ts`

### சேவையகப் பக்க மதிப்பெண் கணக்கீடு

அனைத்து XP கணக்கீடுகளும் `src/lib/gamification/xp.ts` இல் நடைபெறுகின்றன. கிளையன்ட்கள் ஒருபோதும் மதிப்பெண்ணைச் சமர்ப்பிப்பதில்லை — அவை செயல்களைச் சமர்ப்பிக்கின்றன, சேவையகம் XP-ஐக் கணக்கிடுகிறது. `leaderboard.score` நெடுவரிசையில் சேவையகப் பக்கக் குறியீட்டால் மட்டுமே எழுத முடியும்.

### வீத வரம்பிடல்

| வரம்பு                                 | மதிப்பு | வரையெல்லை        |
| -------------------------------------- | ------- | ---------------- |
| நிமிடத்திற்கு அதிகபட்ச XP              | 1,000   | API விசைக்கு     |
| நிமிடத்திற்கு அதிகபட்சப் பரிமாற்றங்கள் | 10      | API விசைக்கு     |
| அதிகபட்சப் பரிமாற்றத் தொகை             | 10,000  | பரிமாற்றத்திற்கு |
| அதிகபட்சத் தினசரிப் பரிமாற்றங்கள்      | 100,000 | API விசைக்கு     |

வீத வரம்புகள் நினைவகத்திலுள்ள நகரும் சாளரத்தைப் பயன்படுத்துகின்றன (`open-sse/services/` இல் உள்ள `RateLimitManager` போன்ற அதே வடிவமைப்பு). செயல்முறை மறுதொடக்கம் செய்யப்பட்டால், SQLite ஆதரவுள்ள எண்ணிகளுக்கு மாறுகிறது.

### Z-மதிப்பெண் முரண்பாடு கண்டறிதல்

ஒவ்வொரு API விசைக்கும், ஒரு மணிநேரத்திற்கு ஈட்டப்பட்ட XP-க்கான நகரும் 7 நாள் சாளரத்தை அமைப்பு பராமரிக்கிறது. ஒவ்வொரு XP வழங்கலின்போதும்:

1. பயனரின் தற்போதைய மணிநேர XP வீதத்தைக் கணக்கிடுகிறது.
2. மொத்தக் குழுவின் சராசரி மற்றும் திட்ட விலக்கத்தைக் கணக்கிடுகிறது.
3. `z = (user_rate - mean) / stddev` என்பதைக் கணக்கிடுகிறது.
4. `z > 3.0` (3 திட்ட விலக்கங்கள்) எனில், அதை முரண்பாடாகக் குறிக்கிறது.

முரண்பாடுகள் `action = 'anomaly_detected'` உடன் `xp_audit_log` இல் பதிவுசெய்யப்பட்டு, நிர்வாக டாஷ்போர்டில் காட்டப்படுகின்றன.

### தணிக்கைத் தடம்

ஒவ்வொரு XP வழங்கல், பரிமாற்றம், பதக்கம் ஈட்டல் மற்றும் முரண்பாடு கண்டறிதலும் பின்வரும் புலங்களுடன் `xp_audit_log` இல் பதிவுசெய்யப்படுகிறது:

| புலம்        | விளக்கம்                                      |
| ------------ | --------------------------------------------- |
| `api_key_id` | யார்                                          |
| `action`     | என்ன நடந்தது (xp_award, transfer, anomaly, …) |
| `xp_awarded` | தொகை (XP அல்லாத நிகழ்வுகளுக்கு 0)             |
| `metadata`   | சூழலுடன் கூடிய JSON (செயல் வகை, இலக்கு, …)    |
| `created_at` | எப்போது (ISO 8601)                            |

நிர்வாகிகள் `GET /api/gamification/anomalies` வழியாக முழுத் தணிக்கைத் தடத்தையும் வினவலாம்.

## கட்டுப்பாட்டுப் பலகைப் பக்கங்கள்

### `/dashboard/leaderboard`

- மேடை காட்சி (அவதாரங்கள் மற்றும் XP உடன் முதல் 3 பேர்).
- வரம்புத் தேர்வி: உலகளாவிய / வாராந்திர / மாதாந்திர / பகிரப்பட்ட டோக்கன்கள் / பங்களிப்புகள்.
- தரவரிசை, பெயர், மதிப்பெண், நிலை, பட்டம் ஆகியவற்றுடன் பக்கமிடப்பட்ட அட்டவணை (ஒரு பக்கத்திற்கு 25).
- SSE நிகழ்நேரப் புதுப்பிப்புகள் — தரவரிசை மாற்றங்கள் அசைவூட்டப்படுகின்றன.
- தற்போதைய பயனர் அட்டவணையில் "உங்கள் தரவரிசை" என்ற நிலையான வரிசையுடன் தனிப்படுத்திக் காட்டப்படுகிறார்.

### `/dashboard/profile`

- தற்போதைய நிலை மற்றும் அடுத்த நிலைக்கான வரம்புடன் XP முன்னேற்றப் பட்டை.
- பட்டப் பதக்கம் முக்கியமாகக் காட்டப்படும்.
- பதக்கத் தொகுப்பு — பெற்ற தேதியுடன் பெற்ற பதக்கங்கள், சாம்பல் நிறத்தில் பெறப்படாத பதக்கங்கள்
  (மறைக்கப்பட்ட பதக்கங்கள் பெறப்படும் வரை "???" எனக் காட்டப்படும்).
- தீச்சுடர் சின்னத்துடன் தொடர் எண்ணிக்கை; தொடர் நாள்காட்டி (கடந்த 30 நாட்கள்).
- XP வரலாற்று வரைபடம் (கடந்த 30 நாட்களுக்கான தினசரி XP).

### `/dashboard/tokens`

- டோக்கன் இருப்பு (முக்கியமாக, பக்கத்தின் மேலே).
- பரிமாற்றப் படிவம்: பெறுநர், தொகை, உறுதிப்படுத்தல் உரையாடல்.
- வடிப்பான்களுடன் பரிமாற்ற வரலாற்று அட்டவணை (அனுப்பியவை/பெற்றவை/அனைத்தும்).
- அழைப்புப் பிரிவு: செயலில் உள்ள குறியீடுகள், புதியதை உருவாக்குதல், இணைப்பைப் பகிர்தல்.
- சமூக சேவையகங்கள்: ஆரோக்கிய நிலையுடன் கூடிய பட்டியல், இணைத்தல்/துண்டித்தல்.

### `/dashboard/gamification/admin`

- தீவிரம், பயனர், நேரமுத்திரை, z-score ஆகியவற்றுடன் முரண்பாட்டுப் பட்டியல்.
- வடிப்பான்களுடன் தணிக்கைப் பதிவுப் பார்வையகம் (செயல் வகை, பயனர், தேதி வரம்பு).
- அமைப்புப் புள்ளிவிவரங்கள்: வழங்கப்பட்ட மொத்த XP, செயலில் உள்ள பயனர்கள், பதக்கம் பெறும் விகிதங்கள்.
- கூட்டமைப்புச் சேவையக ஆரோக்கிய மேலோட்டம்.

## பைப்லைன் ஒருங்கிணைப்பு

### ஒருங்கிணைப்புப் புள்ளி

கேமிஃபிகேஷன் `open-sse/handlers/chatCore.ts` இல் உள்ள கோரிக்கை பைப்லைனில் ஒரே ஒரு புள்ளியில்
இணைக்கப்படுகிறது:

```typescript
// கிளையண்டுக்கு பதில் அனுப்பப்பட்ட பிறகு:
setImmediate(() => {
  emitGamificationEvent({
    type: "request.completed",
    apiKeyId,
    metadata: {
      provider: selectedProvider,
      model: selectedModel,
      comboId: resolvedCombo?.id,
      compressionUsed: compressionStats?.applied,
      skillUsed: skillExecution?.name,
    },
  }).catch(() => {
    // அனுப்பிவிட்டு மறத்தல்: பதிவுசெய்யவும், ஆனால் கிளையண்டுக்கு ஒருபோதும் பரப்ப வேண்டாம்
  });
});
```

### நிகழ்வு வகைகள்

| நிகழ்வு வகை         | எப்போது வெளியிடப்படுகிறது                                            |
| ------------------- | -------------------------------------------------------------------- |
| `request.completed` | வெற்றிகரமான LLM பதில் அனுப்பப்பட்டது                                 |
| `provider.switch`   | வழங்குநர் மாற்றப்பட்டார் (காம்போ மாற்று முயற்சிகளும் கணக்கிடப்படும்) |
| `combo.created`     | புதிய காம்போ உள்ளமைவு சேமிக்கப்பட்டது                                |
| `combo.used`        | காம்போ இலக்கு வெற்றிகரமாக அடையப்பட்டது                               |
| `badge.earned`      | பதக்க மதிப்பீடு ஒரு பொருத்தத்தைக் கண்டறிந்தது                        |
| `streak.milestone`  | தொடர் வரம்பு கடக்கப்பட்டது                                           |
| `transfer.sent`     | டோக்கன் பரிமாற்றம் முடிக்கப்பட்டது                                   |
| `referral.redeemed` | அழைப்புக் குறியீடு வெற்றிகரமாக மீட்டெடுக்கப்பட்டது                   |
| `compression.used`  | தூண்டல் சுருக்கம் பயன்படுத்தப்பட்டது                                 |
| `skill.executed`    | திறன் செயலாக்கம் முடிக்கப்பட்டது                                     |
| `model.first_use`   | கடந்த 7 நாட்களில் மாதிரி பயன்படுத்தப்படவில்லை                        |

### தடை செய்யாத உத்தரவாதம்

`setImmediate` + `.catch(() => {})` முறை பின்வருவனவற்றை உறுதிசெய்கிறது:

1. கேமிஃபிகேஷன் இயங்குவதற்கு முன் பதில் முழுமையாக அனுப்பப்படுகிறது.
2. கேமிஃபிகேஷன் பிழைகள் ஒருபோதும் கிளையண்டுக்குத் தெரியப்படுத்தப்படுவதில்லை.
3. நிகழ்வுச் செயலாக்கம் நேரடியாக அல்லாமல், அடுத்த மைக்ரோடாஸ்க்கில் இயங்குகிறது.

### அங்கீகாரத் தேவைகள்

- **பொது** (அங்கீகாரம் இல்லை): `GET /leaderboard`, `GET /stream` (படிக்க மட்டும்
  அனுமதிக்கும் முன்னிலைப் பலகைகள்).
- **API விசை தேவை**: அனைத்து எழுதும் செயல்பாடுகள், சுயவிவரம், பரிமாற்றங்கள், அழைப்புகள்.

- **கூட்டமைப்பு**: `Authorization` தலைப்பில் மூல டோக்கனைப் பயன்படுத்தும் தனி அங்கீகாரப்
  பாதை, சேமிக்கப்பட்ட SHA-256 ஹாஷுடன் ஒப்பிட்டுச் சரிபார்க்கப்படும்.

- பிழைப் பாதைகள் சோதிக்கப்பட வேண்டும் (போதுமான இருப்பு இல்லாமை, காலாவதியான குறியீடுகள், விகித வரம்புகள்).

## எதிர்காலப் பரிசீலனைகள்

- **பருவகால நிகழ்வுகள்**: குறிப்பிட்ட காலத்திற்கு மட்டுமான பேட்ஜ் தொகுப்புகள் மற்றும் முன்னிலைப் பட்டியல் பருவங்கள்.
- **குழு முன்னிலைப் பட்டியல்கள்**: நிறுவனம் அல்லது சேர்க்கையின் அடிப்படையில் பயனர்களைக் குழுவாக்குதல்.
- **XP பெருக்கிகள்**: விளம்பரக் காலங்களில் XP-ஐ அதிகரித்தல்.
- **சாதனைப் பகிர்வு**: பகிரக்கூடிய பேட்ஜ் அட்டைகளை (OpenGraph படங்கள்) உருவாக்குதல்.
- **மொபைல் புஷ் அறிவிப்புகள்**: பேட்ஜ்/நிலை நிகழ்வுகளுக்கான webhook அடிப்படையிலான அறிவிப்புகள்.
- **முன்னிலைப் பட்டியல் API**: மூன்றாம் தரப்பு ஒருங்கிணைப்புகளுக்கான பொது API.
