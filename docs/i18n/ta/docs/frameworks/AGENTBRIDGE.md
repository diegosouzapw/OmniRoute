AgentBridge என்பது IDE AI முகவர்களிடமிருந்து வரும் HTTPS போக்குவரத்தை இடைமறித்து, OmniRoute-இன் ஒருங்கிணைந்த வழித்தட இயந்திரத்தின் மூலம் அதை மறுவழிப்படுத்தும் OmniRoute-இன் MITM (Man-in-the-Middle) ப்ராக்ஸி ஆகும். இது **10 IDE முகவர்களை** ஆதரிக்கிறது — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code மற்றும் Trae (ஆய்வில் உள்ளது) — இதனால் சந்தையில் AI குறியீட்டு உதவியாளர்களுக்கான மிகப் பரந்த ஆதரவைக் கொண்ட MITM ப்ராக்ஸியாக OmniRoute விளங்குகிறது.

**டாஷ்போர்டு இருப்பிடம்:** `/dashboard/tools/agent-bridge`
**பக்கப்பட்டி குழு:** கருவிகள் (Cloud Agents-க்குப் பிறகு)
**மேலும் காண்க:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — இடைமறிக்கப்பட்ட அனைத்து போக்குவரத்தையும் நிகழ்நேரத்தில் கண்காணிக்கவும்; `docs/security/MITM-TPROXY-DECRYPT.md` (git; `/docs`-இல் தொகுக்கப்படவில்லை) — `/api/tools/agent-bridge/tproxy` வழித்தடத்தால் இயக்கப்படும் Linux TPROXY வெளிப்படையான மறைகுறியீடு நீக்கப் பிடிப்பு பயன்முறை.

## §1 கண்ணோட்டம்

### AgentBridge என்றால் என்ன?

ஒரு IDE முகவர் (எ.கா., GitHub Copilot, Cursor, Claude Code) API அழைப்பை மேற்கொள்ளும்போது, அது மேல்நிலை AI வழங்குநருடன் (OpenAI, Anthropic போன்றவை) நேரடியாக இணைகிறது. எந்த முகவர் உள்ளமைவு மாற்றமும் தேவையில்லாமல், TLS மட்டத்தில் அந்த இணைப்பை AgentBridge வெளிப்படையாக இடைமறித்து, கோரிக்கையை OmniRoute வழியாக மீண்டும் எழுதுகிறது.

இதன் மூலம் நீங்கள்:

- **எந்த முகவரையும் எந்த வழங்குநருக்கும் மறுவழிப்படுத்தலாம்**: Copilot, OpenAI உடன் தொடர்புகொள்கிறதா? அதை Anthropic Claude, Gemini அல்லது OmniRoute-இன் 352 வழங்குநர்களில் ஏதேனும் ஒன்றிற்கு திருப்பிவிடலாம்.
- **மாதிரி பொருத்தங்களைப் பயன்படுத்தலாம்**: கையாளுநர் மட்டத்தில் `gemini-3-flash` → `claude-sonnet-4.7` என்பதை வெளிப்படையாகப் பொருத்தலாம்.
- **அனைத்து முகவர் போக்குவரத்தையும் கண்காணிக்கலாம்**: இடைமறிக்கப்படும் ஒவ்வொரு கோரிக்கையும் [போக்குவரத்து ஆய்வியில்](./TRAFFIC_INSPECTOR.md) வெளியிடப்படுகிறது.
- **OmniRoute-இன் மீள்திறனைப் பயன்படுத்தலாம்**: சேர்க்கை வழித்தடம், சுற்றுத் துண்டிப்பான்கள், மாற்று வழிகள் மற்றும் செலவுக் கண்காணிப்பு ஆகியவை IDE முகவர் போக்குவரத்திற்கும் செயல்படும்.

    │
    ▼

    │  Host தலைப்பின் SNI மூலம் இலக்கைத் தீர்மானிக்கிறது
    │  AgentBridge CA-ஆல் கையொப்பமிடப்பட்ட ஒவ்வொரு-SNI-க்குமான TLS சான்றிதழை உருவாக்குகிறது

    │               ├── கோரிக்கை உடல்/தலைப்புகளில் maskSecrets()
    │               ├── TrafficBuffer.push() — போக்குவரத்து ஆய்விக்குப் பதிப்பிக்கிறது

    └── பொருத்தம் இல்லையா? → TCP நேரடி அனுப்பல் (மறைகுறியாக்க நீக்கம் இல்லை)

### 2.2 MITM சேவையகம் (`src/mitm/server.cjs`)

மைய MITM சேவையகம் Node.js CJS சேய் செயல்முறையாக இயங்குகிறது (ஏற்கனவே உள்ள CJS குறியீட்டுத்தளத்தை மீண்டும் எழுதுவதைத் தவிர்ப்பதற்காக). இது:

- போர்ட் 443-இல் செவிமடுக்கிறது (சிறப்புரிமை அல்லது `authbind`/`setcap` தேவை)
- OS-இலிருந்து CONNECT சுரங்கங்களைப் பெறுகிறது (`/etc/hosts` DNS திசைமாற்றம் வழியாக)
- AgentBridge CA (`DATA_DIR/mitm/ca.crt`) மூலம் கையொப்பமிடப்பட்ட ஒவ்வொரு-SNI-க்குமான TLS சான்றிதழ்களை உருவாக்குகிறது
- `targets/index.ts` பதிவகத்தின் வழியாக Host தலைப்பைப் பயன்படுத்தி இலக்கு முகவரைத் தீர்மானிக்கிறது
- HTTP வழியாக `http://127.0.0.1:20128`-இல் உள்ள TypeScript கையாளுநர் அடுக்கிற்கு அனுப்புகிறது

`TARGET_HOSTS`, `DATA_DIR/mitm/targets.json`-இலிருந்து ஏற்றப்படுகிறது (தொடக்கத்தின்போது `targets/index.ts` மூலம் எழுதப்படுகிறது); இதனால் CJS சேவையகத்தை மறுதொடக்கம் செய்யாமல் மாறும் புதுப்பிப்புகளைச் செய்ய முடியும்.

> **Root-CA மாதிரி (#6684).** மேலே விவரிக்கப்பட்ட ஒவ்வொரு-SNI-க்குமான-CA-கையொப்பமிட்ட-சான்றிதழ் அணுகுமுறை,
> #6684-இல் சேர்க்கப்பட்ட நிலைபேறான root-CA மாதிரியாகும் (`src/mitm/cert/rootCa.ts` +
> `src/mitm/_internal/rootCaShim.cjs`; `src/mitm/tproxy/dynamicCert.ts`-இல்
> TPROXY-க்காக ஏற்கனவே நிரூபிக்கப்பட்ட CA/இலை மறையியலை மீண்டும் பயன்படுத்துகிறது) — இது
> வட்டில் வெறும் `server.crt`/`server.key` இணை இருப்பதால் குறிக்கப்படும் பழைய ஒற்றை நிலையான
> சுய-கையொப்பமிட்ட இலைச் சான்றிதழை (`src/mitm/cert/generate.ts`, இன்னும்
> antigravity புரவலர்களுக்கு மட்டும் வரையறுக்கப்பட்டது) மாற்றுகிறது. **இடம்பெயர்வு நடத்தை**:
> புதிய நிறுவல் (முந்தைய `server.crt` இல்லாதது) root-CA மாதிரியைத் தானாகப் பெறும்;
> பழைய நிலையான இலைச் சான்றிதழை ஏற்கனவே நம்பிய நிறுவல், இயக்குநர்
> `MITM_ROOT_CA_ENABLED=true` என்பதை அமைத்து bridge-ஐ மறுதொடக்கம் செய்யும் வரை
> அதையே தொடர்ந்து பயன்படுத்தும் (`src/mitm/cert/migration.ts`
> என்பது தூய தீர்மானச் செயல்பாடு — **எந்தவொரு** புரவலருக்கும் இலைச் சான்றிதழில் கையொப்பமிடக்கூடிய
> நம்பகமான MITM CA, பழைய நிலையான-SAN இலைச் சான்றிதழைவிடக் கணிசமாக அதிக சக்தி கொண்டது;
> எனவே ஏற்கனவே நம்பிக்கை அளிக்கப்பட்ட நிறுவலில் இந்த மாற்றம் எப்போதும் அமைதியாக நடைபெறாது).
> பழைய இலைச் சான்றிதழ் பயன்படுத்திய அதே `omniroute-mitm.crt` நம்பிக்கை-களஞ்சிய இடத்தில்
> CA சான்றிதழ் நிறுவப்படுகிறது (`cert/install.ts::installCaCert`) — இரட்டை-நம்பிக்கை
> சுத்தப்படுத்தல் தேவையில்லை.

### 2.3 கையாளுநர் அடித்தளம் (`src/mitm/handlers/base.ts`)

அனைத்து முகவர் கையாளுநர்களும் `MitmHandlerBase`-ஐ விரிவாக்குகின்றன:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // பாதுகாக்கப்பட்ட உதவிகள்: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

ஒவ்வொரு கையாளுநரும் பதிலாள் அனுப்புதலுக்கு முன் `hookBufferStart()`-ஐயும், நிறைவடையும்போது `hookBufferUpdate()`-ஐயும் அழைக்கிறது. இவை `InterceptedRequest` உள்ளீடுகளை `globalTrafficBuffer`-க்குள் செலுத்துகின்றன ([போக்குவரத்து ஆய்வி](./TRAFFIC_INSPECTOR.md) §4-ஐப் பார்க்கவும்).

### 2.4 இலக்குகள் பதிவகம் (`src/mitm/targets/`)

ஒவ்வொரு முகவருக்கும் ஒரு அறிவிப்பு-முறை இலக்குக் கோப்பு உள்ளது:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

பதிவகம் (`targets/index.ts`) `ALL_TARGETS`-ஐ ஏற்றுமதி செய்து, தொடக்கத்தின்போது `DATA_DIR/mitm/targets.json`-ஐ வெளியிடுகிறது.

### 2.5 நேரடி அனுப்பல் மற்றும் தவிர்ப்புப் பட்டியல் (`src/mitm/passthrough.ts`)

**தவிர்ப்புப் பட்டியல்** (இலக்குப் பொருத்தத்தைவிட முன்னுரிமையுடன் முதலில் சரிபார்க்கப்படுகிறது):

- இயல்புநிலை வடிவங்கள்: வங்கி புரவலர்கள், `.gov.`, OAuth/SSO வழங்குநர்கள் (Okta, Auth0), போன்றவை
- பயனர் வடிவங்கள்: `agent_bridge_bypass` தரவுத்தள அட்டவணையில் சேமிக்கப்படுகின்றன
- தவிர்க்கப்பட்ட புரவலர்கள் வெளிப்படையான TCP சுரங்கத்தைப் பெறுகின்றனர் — TLS மறைகுறியாக்கம் **ஒருபோதும் நீக்கப்படாது**

**இயல்புநிலை நேரடி அனுப்பல்** (இலக்குப் பொருத்தமும் இல்லை, தவிர்ப்புப் பட்டியலிலும் இல்லை):

- இதுவும் TCP சுரங்கத்தைப் பெறுகிறது — இணைப்புகள் ஒருபோதும் துண்டிக்கப்படுவதில்லை
- பொதுவான கணினி HTTPS போக்குவரத்தை AgentBridge சீர்குலைப்பதைத் தடுக்கிறது

திசைவிப்பு முன்னுரிமை:

```
தவிர்ப்புப் பட்டியல் → இலக்குப் பொருத்தம் → நேரடி அனுப்பல்
```

### 2.6 மேல்நிலை CA சான்றிதழ் (`src/mitm/upstreamTrust.ts`)

தனிப்பயன் CA கொண்ட நிறுவன வலைப்பின்னல் சூழல்களுக்கு:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

இது அமைக்கப்பட்டிருக்கும்போது, கூடுதல் CA சான்றிதழுடன் `undici`-இன் உலகளாவிய அனுப்பியை உள்ளமைக்கிறது; இதனால் நிறுவன TLS முடித்தல் பதிலாள்கள் வழியாக மேல்நிலை வழங்குநர்களை AgentBridge அணுக முடியும்.

### 2.7 இரகசிய மறைத்தல் (`src/mitm/maskSecrets.ts`)

சுயாதீனமான clean-room வருடி, கோரிக்கை உடல்களுக்கும் நற்சான்றுத் தலைப்புகளுக்கும்
போக்குவரத்து ஆய்வி இடையகத்திற்கோ எந்தப் பதிவிற்கோ அவை நுழைவதற்கு **முன்பே** பயன்படுத்தப்படுகிறது. இது ஒற்றை நேரியல் கடப்பைச் செய்கிறது:

- `sk-` / `ak-` / `pk-` முன்னொட்டுள்ள அடையாளக்குறிகள் (OpenAI/Anthropic பாணி)
- RFC 6750 `Authorization: Bearer <token>` நற்சான்றுகள்; முழு அடையாளக்குறிக்கு முன்னுரிமை
- பொதுவான நீண்ட ஒளிபுகா அடையாளக்குறிகள் (≥40 எழுத்துகள்), புள்ளியிட்ட மற்றும் நிரப்பப்பட்ட வடிவங்கள் உட்பட

`sanitizeHeaders()` தக்கவைக்கப்பட்ட பெயர்களைச் சிற்றெழுத்துகளாக மாற்றுகிறது, அணிவரிசை மதிப்புகளைத் தீர்மானகரமாக இணைக்கிறது, பகிரப்பட்ட hop-by-hop/சட்டகமிடல் மறுப்புப் பட்டியலை (பதிலாள் அங்கீகாரம் உட்பட) நீக்குகிறது, `cookie` மற்றும் `set-cookie`-ஐ முழுமையாக மறைக்கிறது, மேலும் நற்சான்று மதிப்புகளை வருடியிடம் ஒப்படைக்கிறது.

### 3.1 MITM சேவையகத்தைத் தொடங்குதல்/நிறுத்துதல்

`/dashboard/tools/agent-bridge`-இல் உள்ள AgentBridge சேவையக அட்டையைப் பயன்படுத்தவும்:

| செயல்                       | விளக்கம்                                                                                                |
| --------------------------- | ------------------------------------------------------------------------------------------------------- |
| சேவையகத்தைத் தொடங்கு        | port 443-இல் `src/mitm/server.cjs`-ஐத் தொடங்குகிறது                                                     |
| சேவையகத்தை நிறுத்து         | துணைச் செயல்முறையை முறையாக நிறுத்துகிறது                                                                |
| சேவையகத்தை மறுதொடக்கம் செய் | நிறுத்து + தொடங்கு (இலக்கு மாற்றங்களைப் பயன்படுத்துகிறது)                                               |
| சான்றிதழை நம்பு             | `DATA_DIR/mitm/ca.crt`-ஐ OS நம்பகக் களஞ்சியத்தில் நிறுவுகிறது                                           |

### 3.2 சான்றிதழை நம்புதல்

IDE-கள் MITM இணைப்பை ஏற்றுக்கொள்வதற்கு முன், AgentBridge CA சான்றிதழை OS நம்ப வேண்டும்.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

அல்லது dashboard-இல் உள்ள "சான்றிதழை நம்பு" பொத்தானைப் பயன்படுத்தவும் (தேவைப்பட்டால் sudo கோரிக்கையுடன், உங்கள் OS-க்கு ஏற்ற கட்டளையை இயக்கும்).

#### Electron-அடிப்படையிலான IDE-கள் OS நம்பகக் களஞ்சியத்தைப் புறக்கணிக்கின்றன (`NODE_EXTRA_CA_CERTS`)

சில IDE-கள் — குறிப்பாக **Antigravity IDE** மற்றும் பிற Electron / VS Code-இலிருந்து பெறப்பட்ட செயலிகள் — வெளியே செல்லும்
`fetch`/HTTPS இணைப்புகளுக்கு **OS நம்பகக் களஞ்சியத்தைப் பயன்படுத்தாத** தங்களுடைய சொந்த Node.js இயக்கச் சூழலைத் தொகுப்பாகக் கொண்டுள்ளன.
OS/NSS மட்டத்தில் CA-ஐ நம்புவது, IDE-இன் சொந்த **பின்தளத்திற்கு**
(எ.கா. OS CA தொகுப்பைப் பயன்படுத்தும் Go மொழிச் சேவையகம்) போதுமானது; ஆனால் **Electron முன்தளம்**
TLS-இல் தொடர்ந்து தோல்வியடையும் — MITM பதிவில் பின்தளத்தின் தொடக்க அழைப்புகள் `200`-ஐத் திருப்புவதாகக் காட்டினாலும்,
செயலி _வெளியேற்றப்பட்டதாக_ அல்லது _"இணைப்புப் பிழை"_ காட்டுவதாக இது வெளிப்படும். இரண்டு படிகள்
தேவை, இரண்டுமே முக்கியமானவை:

1. CA-ஐ இயக்கச் சூழலுக்கு வெளிப்படையாகச் சுட்டிக்காட்டவும்:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **அந்த shell-இலிருந்து IDE-ஐத் தொடங்கவும்.** desktop icon / Dock / Start menu-இலிருந்து அதைத் தொடங்குவது
   shell export-களைப் பெறாது; மேலும் `~/.config/environment.d/*.conf` என்பது
   புதிய graphical login-க்குப் பிறகே பொருந்தும். முதலில் IDE-இலிருந்து முழுமையாக வெளியேறவும் — Electron-இன் singleton lock காரணமாக,
   இரண்டாவது தொடக்கம் ஏற்கனவே உள்ள செயல்முறையை முன்னிலைப்படுத்துவது மட்டுமே; புதிய environment புறக்கணிக்கப்படும்.

மேலே உள்ள OS நம்பிக்கை + NSS படி தொடர்ந்து அவசியமானது (சில அங்கீகாரப் பாய்வுகள் பயன்படுத்தும் Chromium
network stack, பயனர்-சார்ந்த NSS களஞ்சியத்தைப் படிக்கிறது; மேலும் `*.googleapis.com`-க்கான அதன் சொந்த நிலையான pin-களை
உள்நாட்டில் நம்பப்பட்ட CA மேலெழுதுகிறது). இதனுடன் கூடுதலாக Node `fetch` பாதையை `NODE_EXTRA_CA_CERTS` உள்ளடக்குகிறது.

### 3.3 DNS வழித்தடம்

நீங்கள் இடைமறிக்க விரும்பும் ஒவ்வொரு முகவருக்கும், அதன் API host(கள்) `127.0.0.1`-க்கு resolve ஆக வேண்டும். அமைப்பு வழிகாட்டியில் ஒரு முகவருக்கான DNS-ஐ மாற்றும்போது, `/etc/hosts` பதிவுகளை AgentBridge தானாக நிர்வகிக்கிறது.

GitHub Copilot-க்கான எடுத்துக்காட்டு `/etc/hosts` பதிவுகள்:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 மாதிரி பொருத்தம்

மூலம் → இலக்கு பொருத்தங்களை வரையறுக்க, ஒவ்வொரு முகவர் அட்டையிலும் உள்ள மாதிரிப் பொருத்த அட்டவணையைப் பயன்படுத்தவும்:

| மூல மாதிரி (முகவரின் சொந்த மாதிரி) | இலக்கு மாதிரி (OmniRoute) |
| ---------------------------------- | ------------------------- |
| `gpt-4o`                           | `claude-sonnet-4.7`       |
| `*` (wildcard)                     | `claude-haiku-4.7`        |

Wildcard `*`, அடையாளம் காணப்படாத எந்த மாதிரியையும் குறிப்பிடப்பட்ட இலக்குடன் பொருத்துகிறது. இது `agent_bridge_mappings` அட்டவணையில் நிலையாகச் சேமிக்கப்படுகிறது.

> **உதவிக்குறிப்பு — முகவரின் உண்மையான மாதிரி ID-களைக் கண்டறியவும்.** ஓர் IDE, அதன்
> UI label-களிலிருந்து வேறுபடும் மற்றும் முக்கியப் பதிப்புகளுக்கு இடையே மாறும் மாதிரிப் பெயர்களை அனுப்பக்கூடும். எடுத்துக்காட்டாக, **Antigravity 2**
> `gemini-3.1-pro-low`, `gemini-pro-agent`, மற்றும் `gemini-3.1-flash-lite` ஆகியவற்றை இணைப்பு வழியாக அனுப்புகிறது —
> பழைய ஆவணங்களில் காட்டப்படும் `gemini-2.5-pro`-ஐ அல்ல. பொருந்தும் mapping எதுவும் இல்லாமல் ஒரு chat-ஐ அனுப்பவும்: MITM,
> உள்வரும் சரியான `model:` மதிப்பைப் பதிவு செய்து, கோரிக்கையை அப்படியே அனுப்பும். அந்த நேரடி மதிப்பை map செய்த பிறகு,
> அடுத்த கோரிக்கை இடைமறிக்கப்பட்டு உங்கள் இலக்குக்கு வழிமாற்றப்படும்.

### 3.5 அபாய அறிவிப்பு

மேல்நிலை வழங்குநர்களுடன் அங்கீகரிக்க IDE பயன்படுத்தும் நற்சான்றுகளை (OAuth token-கள், API key-கள்) AgentBridge இடைமறிக்கிறது. இவை **பதிவுசெய்வதற்கு முன் மறைக்கப்படுகின்றன** (§2.7-ஐப் பார்க்கவும்), ஆனால் OmniRoute-இன் MITM அடுக்கிற்குத் தெரியும். ஒவ்வொரு முகவரையும் முதன்முறையாகச் செயல்படுத்தும்போது, மூடக்கூடிய அபாய அறிவிப்பு modal காட்டப்படும்.

### 3.6 பராமரிப்பும் கண்டறிதலும்

முன்பு UI இல்லாத செயல்பாட்டு MITM route-களைக் காட்டும் **பராமரிப்பும் கண்டறிதலும்** அட்டையை (`AgentBridgeMaintenanceCard`, `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`-இல்) dashboard வழங்குகிறது. அதன் துணைத்தலைப்பு: _"பிடிப்பு pipeline-ஐச் சுயமாகச் சோதிக்கவும், மீதமுள்ள system state-ஐச் செயல்தவிர்க்கவும், உங்கள் அமைப்பை இயந்திரங்களுக்கு இடையே நகர்த்தவும்."_ அட்டையின் client helper-கள் `src/lib/inspector/agentBridgeMaintenanceApi.ts`-இல் உள்ளன.

| பொத்தான்                    | வழித்தடம்                              | அது என்ன செய்கிறது                                                                                                                                                                                                                                           |
| --------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **கண்டறி**                  | `GET /api/tools/agent-bridge/diagnose` | பிடிப்புச் செயலாக்கத் தொடரின் சுய-சோதனையை இயக்கி, ஒவ்வொரு சரிபார்ப்புக்குமான அறிக்கையைக் காட்டுகிறது (✓/✗ + சரிசெய்தல் குறிப்பு).                                                                                                                            |
| **பழுதுபார்**               | `POST /api/tools/agent-bridge/repair`  | செயலிழப்பு அல்லது SIGKILL காரணமாக எஞ்சியுள்ள ஆதரவற்ற MITM அமைப்பு நிலையை (DNS போலியாக்கப் பதிவுகள், ரூட் CA, கணினி ப்ராக்ஸி) நீக்குகிறது. மீண்டும் இயக்கினாலும் பாதிப்பில்லாதது — நிலை சுத்தமாக இருக்கும்போது "பழுதுபார்க்க எதுவுமில்லை" எனத் தெரிவிக்கிறது. |
| **CA-ஐ அகற்று**             | `DELETE /api/tools/agent-bridge/cert`  | OS நம்பகச் சேமிப்பிலிருந்து MITM ரூட் CA மீதான நம்பிக்கையை நீக்கி, அதனை அகற்றுகிறது (வெளிப்படையானது, மீண்டும் இயக்கினாலும் பாதிப்பில்லாதது). CA தற்போது நம்பகமானதாக இருக்கும்போது மட்டுமே காட்டப்படும்; வரியிடையே "CA-ஐ அகற்றவா?" என்ற உறுதிப்படுத்தல் தேவை. |
| **உள்ளமைவை ஏற்றுமதி செய்**  | `GET /api/tools/agent-bridge/config`   | எடுத்துச் செல்லக்கூடிய உள்ளமைவு JSON-ஐப் பதிவிறக்குகிறது (§3.7-ஐப் பார்க்கவும்).                                                                                                                                                                             |
| **உள்ளமைவை இறக்குமதி செய்** | `POST /api/tools/agent-bridge/config`  | முன்பு ஏற்றுமதி செய்யப்பட்ட உள்ளமைவு JSON-ஐப் பதிவேற்றுகிறது (§3.7-ஐப் பார்க்கவும்).                                                                                                                                                                         |

**கண்டறிதல் சரிபார்ப்புகள்** (`src/mitm/inspector/diagnostics.ts`-இல் உள்ள `summarizeDiagnostics()`). வழித்தடம் ஒவ்வொன்றுக்கும் பக்கவிளைவுள்ள ஆய்வை இயக்கி, பூலியன் மதிப்புகளைத் தூய சுருக்கச் செயல்பாட்டிற்கு வழங்குகிறது; ஒற்றை `healthy` தீர்ப்புடன் ஒவ்வொரு தோல்விக்குமான குறிப்பும் திருப்பித் தரப்படுகிறது:

| சரிபார்ப்புப் பெயர் | அது எதைச் சரிபார்க்கிறது                                      | தோல்விக்கான குறிப்பு                                                                                                                                                          |
| ------------------- | ------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`    | MITM சேவையகச் செயல்முறை செயலில் உள்ளது                        | "MITM சேவையகம் இயங்கவில்லை. AgentBridge தாவலிலிருந்து அதைத் தொடங்கவும்."                                                                                                      |
| `server-reachable`  | MITM சேவையகம் அதன் போர்ட்டில் இணைப்புகளை ஏற்கிறது (TCP ஆய்வு) | "MITM சேவையகம் அதன் போர்ட்டில் இணைப்புகளை ஏற்கவில்லை. போர்ட் பயன்பாட்டில் இல்லாமல் இருப்பதையும், அதனுடன் பிணைப்பதற்கான சிறப்புரிமைகள் உங்களிடம் இருப்பதையும் சரிபார்க்கவும்." |
| `cert-exists`       | MITM சான்றிதழ் வட்டில் உருவாக்கப்பட்டுள்ளது                   | "இதுவரை MITM சான்றிதழ் எதுவும் உருவாக்கப்படவில்லை. AgentBridge தாவலிலிருந்து ஒன்றை உருவாக்கவும்."                                                                             |
| `cert-trusted`      | MITM ரூட் CA, OS நம்பகச் சேமிப்பில் உள்ளது                    | "MITM ரூட் CA-ஐ OS நம்பகச் சேமிப்பு நம்பவில்லை, எனவே TLS இடைமறிப்பு தோல்வியடையும். AgentBridge தாவலிலிருந்து சான்றிதழை நம்பகமானதாக்கவும்."                                    |
| `dns-configured`    | இலக்கு புரவலன்பெயர்கள் `/etc/hosts`-இல் போலியாக்கப்பட்டுள்ளன  | "இலக்கு புரவலன்பெயர்கள் /etc/hosts-இல் போலியாக்கப்படவில்லை, எனவே போக்குவரத்து ப்ராக்ஸியை ஒருபோதும் அடையாது. நீங்கள் பிடிக்க விரும்பும் முகவர்களுக்கான DNS-ஐ இயக்கவும்."       |

**ஆதரவற்ற-நிலை பதாகை:** செயலிழப்பால் எஞ்சியுள்ள நிலையை (DNS போலியாக்கம் / CA / கணினி ப்ராக்ஸி) பக்கம் கண்டறியும்போது, அட்டை ஓர் ஆம்பர் நிறப் பதாகையைக் காட்டுகிறது — _"முந்தைய அமர்வு கணினி நிலையை எஞ்சவிட்டுள்ளது (DNS போலியாக்கம், CA அல்லது கணினி ப்ராக்ஸி). அதைச் சுத்தம் செய்ய பழுதுபார்ப்பை இயக்கவும்."_ — மேலும் **பழுதுபார்** பொத்தானை முன்னிலைப்படுத்துகிறது. `Repair` என்பது ProxyBridge-இன் `--cleanup` கொடிக்கு பயன்பாட்டு-அடுக்கு ஒப்பானது (இது `src/mitm/manager.ts`-இல் உள்ள `repairMitm()`-க்குப் பணியை ஒப்படைக்கிறது).

> மீண்டும் மீண்டும் sudo அனுமதிக் கோரிக்கைகள் தோன்றுவதைத் தவிர்க்க, நிறுத்துதல்/தொடங்குதல் ஆகியவற்றுக்கு இடையிலும் MITM ரூட் CA நிறுவப்பட்ட நிலையிலேயே வைக்கப்படுகிறது
> (mitmproxy/Charles போன்ற அதே நடத்தை); எனவே, நிறுத்தும்போது தானாக நிகழும் ஒன்றாக இல்லாமல்,
> அதை அகற்றுவது ஒரு வெளிப்படையான **CA-ஐ அகற்று** செயலாகும்.

### 3.7 எடுத்துச் செல்லக்கூடிய உள்ளமைவு இறக்குமதி/ஏற்றுமதி

ஒரு அமைப்பை வெவ்வேறு கணினிகளில் பிரதியெடுக்க ஏதுவாக, **இயக்குநர் மாற்றியமைக்கக்கூடிய** நிலையைப் பதிப்பிடப்பட்ட JSON தரவுத் தொகுப்பாக AgentBridge வரிசைப்படுத்த முடியும். வரிசைப்படுத்தி `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`) ஆகும்; இது `AgentBridgeConfigSchema` மூலம் சரிபார்க்கப்படுகிறது.

ஏற்றுமதியில் சரியாக மூன்று பகுதிகள் உள்ளன (உள்ளமைந்த இயல்புநிலைகள் வேண்டுமென்றே ஏற்றுமதி செய்யப்படுவதில்லை; இதனால் இறக்குமதி செய்வது அவற்றை ஒருபோதும் நகலெடுக்கவோ முரண்படவோ செய்யாது):

| புலம்            | மூலம்                                                               | குறிப்புகள்                                                                     |
| ---------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| `bypassPatterns` | பயனர் வரையறுத்த தவிர்ப்பு வடிவங்கள் (`agent_bridge_bypass`)         | இயல்புநிலை bank/gov/okta வடிவங்கள் விலக்கப்படுகின்றன                            |
| `customHosts`    | Traffic Inspector தனிப்பயன் புரவலன்கள் (`inspector_custom_hosts`)   | ஒவ்வொன்றும்: `{ host, kind: "llm"\|"app"\|"custom", label? }`                   |
| `agentMappings`  | ஒவ்வொரு முகவருக்குமான மாதிரி பொருத்தங்கள் (`agent_bridge_mappings`) | பொருத்தங்களைக் கொண்ட ஒவ்வொரு முகவருக்கும் `{ [agentId]: [{ source, target }] }` |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**இறக்குமதி நடத்தை** (`POST /api/tools/agent-bridge/config`): தவிர்ப்பு வடிவங்களும் ஒவ்வொரு முகவருக்குமான பொருத்தங்களும் **முழுமையாக மாற்றியமைக்கப்படுகின்றன**; தனிப்பயன் புரவலன்கள் **மீண்டும் சேர்த்தாலும் பாதிப்பில்லாத வகையில்** (`INSERT OR IGNORE`) சேர்க்கப்படுகின்றன. ஒவ்வொரு வகையிலும் எத்தனை பயன்படுத்தப்பட்டன என்பதைப் பதில் தெரிவிக்கிறது:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

உள்ளமைவில் **இல்லாதவை**: சேவையகத்தின் இயங்கும் நிலை, சான்றிதழ் பாதைகள், ஒவ்வொரு முகவரின் DNS நிலை, அப்ஸ்ட்ரீம் CA பாதை மற்றும் TPROXY அமைப்புகள் — இவை மாற்றத்தக்க விருப்பத்தேர்வுகள் அல்ல; ஹோஸ்ட்/இயக்கநேர நிலையாகும்.

### அமைவு வழிகாட்டி படிகள் (ஒவ்வொரு முகவருக்கும்)

ஒவ்வொரு முகவர் அட்டையிலும் 3-படி அமைவு வழிகாட்டி உள்ளது:

1. **முன்தேவைகளைச் சரிபார்க்கவும்** — சேவையகம் இயங்குகிறதா? சான்றிதழ் நம்பப்பட்டுள்ளதா? IDE நிறுவப்பட்டுள்ளதா (தானாகக் கண்டறியப்படுமா)?
2. **DNS ஐ இயக்கவும்** — `/etc/hosts` உள்ளீடுகளைச் சேர்க்கிறது (sudo தேவை). எந்த வரிகள் சேர்க்கப்படும் என்பதைத் துல்லியமாகக் காட்டுகிறது.
3. **மாதிரிகளை வரைபடமாக்கவும்** — விருப்பமான மாதிரி வரைபட அட்டவணை. வைல்ட்கார்டுகள் ஏற்கப்படும்.

### முகவர் கண்டறிதல்

1–8 முகவர்களுக்கு, AgentBridge IDE நிறுவலைத் தானாகக் கண்டறிய முயற்சிக்கிறது:

```ts
export async function detectAgent(agentId: AgentId): Promise<DetectionResult>;
// திருப்பி அளிப்பது: { installed: boolean, version?: string, path?: string }
```

கண்டறிதல் OS-க்கேற்ற பாதைகளையும் பைனரி சரிபார்ப்புகளையும் பயன்படுத்துகிறது (எ.கா., Copilot-க்கு `code --list-extensions | grep github.copilot`, Antigravity-க்கு `~/.config/antigravity/`).

### முக்கிய ஹோஸ்ட்களுக்கான பைபாஸ் பட்டியல்

நிதி நிறுவனங்கள், OAuth/SSO வழங்குநர்கள் மற்றும் பிற முக்கிய ஹோஸ்ட்கள் **ஒருபோதும் மறைகுறிநீக்கம் செய்யப்படாமல்** இருப்பதை பைபாஸ் பட்டியல் உறுதிசெய்கிறது. அவற்றின் TLS போக்குவரத்து வெளிப்படையான TCP சுரங்கமாகக் கடந்து செல்கிறது — OmniRoute ஒருபோதும் எளிய உரையைப் பார்க்காது.

இயல்புநிலை பைபாஸ் வடிவங்கள்:

- `*.bank.*`, `*.gov.*` (நிதி/அரசு)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/அடையாளம்)
- `*.apple.com`, `*.icloud.com` (Apple அமைப்புச் சேவைகள்)

பயனர் சேர்த்த பைபாஸ் வடிவங்கள் `agent_bridge_bypass` அட்டவணையில் சேமிக்கப்பட்டு, மற்ற அனைத்தையும் விட முன்னுரிமை பெறுகின்றன.

### ரகசிய மறைத்தல்

`src/mitm/maskSecrets.ts` இலிருந்து `maskSecrets()` பயன்படுத்தப்படுகிறது:

- `TrafficBuffer.push()`-க்கு முன் ஒவ்வொரு கோரிக்கை உடலிலும்
- பதிவுசெய்தல் அல்லது ஒலிபரப்புக்கு முன் ஒவ்வொரு தலைப்பிலும்

வடிவங்கள்: `sk-`/`ak-`/`pk-` முன்னொட்டுடன் கூடிய டோக்கன்கள், `Bearer` டோக்கன்கள் மற்றும் ≥40 எழுத்துகள் கொண்ட பொதுவான டோக்கன்கள்.

### அப்ஸ்ட்ரீம் CA சான்றிதழ்

`AGENTBRIDGE_UPSTREAM_CA_CERT` அமைக்கப்பட்டிருக்கும்போது, தொடக்கத்தில் கோப்பு படிக்கப்படுகிறது. பாதை இருந்தும் கோப்பைப் படிக்க முடியாவிட்டால், AgentBridge தெளிவான பிழையைப் பதிவுசெய்து தொடங்க மறுக்கிறது (நிறுவனச் சூழல்களில் அமைதியான TLS தோல்விகளைத் தடுக்கிறது).

### அறியப்பட்ட வரம்புகள்

- **Port 443-க்கு சிறப்புரிமை தேவை**: Linux-இல், Node பைனரியில் AgentBridge-க்கு `setcap 'cap_net_bind_service=+ep'` தேவை, அல்லது `authbind` வழியாக இயக்க வேண்டும். அமைவு வழிகாட்டி OS-க்கேற்ற வழிமுறைகளைக் காட்டுகிறது.
- **IDE-ஐ மறுதொடக்கம் செய்ய வேண்டும்**: DNS திருப்பிவிடலுக்குப் பிறகு, புதிய ஹோஸ்ட் தீர்மானம் செயல்பட IDE-ஐ மறுதொடக்கம் செய்ய வேண்டும்.
- **நிலையாகக் குறியிடப்பட்ட OAuth டோக்கன்கள்**: சில முகவர்கள் (Kiro, Antigravity) OAuth புதுப்பிப்பு டோக்கன்களை உள்ளூரில் சேமிக்கின்றனர். இவை AgentBridge-க்கு வெளிப்படையானவை — ஒவ்வொரு கோரிக்கையிலும் உள்ள Bearer டோக்கனை அது காண்கிறது; பதிவுசெய்வதற்கு முன் அந்த டோக்கன் மறைக்கப்படுகிறது.
- **Electron முன்புறங்களுக்கு `NODE_EXTRA_CA_CERTS` தேவை**: தொகுக்கப்பட்ட Node/Electron இயக்கச்சூழலில் முன்புறம் இயங்கும் IDE-கள் OS/NSS நம்பக சேமிப்பகத்தைப் புறக்கணிக்கின்றன; எனவே `NODE_EXTRA_CA_CERTS` அமைக்கப்பட்ட shell-இலிருந்து அவற்றைத் தொடங்க வேண்டும் (§3.2 ஐப் பார்க்கவும்). இது இல்லாதபோதைய அறிகுறி: IDE பின்புறம் அங்கீகரிக்கப்படுகிறது (MITM `200`-களைக் காட்டுகிறது), ஆனால் UI வெளியேறிய நிலையிலேயே இருக்கும்.
- **ஒரே IDE-யின் பல நிறுவல்கள் ஒன்றுக்கொன்று சார்பற்றவை**: அமைப்பு நிறுவல் (எ.கா. `/usr/share/antigravity/antigravity`) மற்றும் பயனர்-உள்ளூர் "Full" நிறுவல் (எ.கா. `~/AntigravityIDE_Full/antigravity-ide`) ஆகியவை தத்தமது இயக்கச்சூழல்களுடன் தனித்தனி செயல்முறைகள் — ஒவ்வொன்றையும் CA செலுத்தப்பட்ட நிலையில் மீண்டும் தொடங்க வேண்டும். மீண்டும் தொடங்குவதற்கு முன், எது இயங்குகிறது என்பதை அதன் பைனரி பாதையால் கண்டறியவும்.
- **அடையாளத்தை நிர்ணயிப்பது முகவரின் system prompt; வழிச்செலுத்தப்பட்ட மாதிரி அல்ல**: ஒரு முகவரின் மாதிரியை வேறு வழங்குநருக்கு மாற்றி வரைபடமாக்கினாலும், பதில் அந்த முகவரின் இயல்பான அடையாளத்தையே கூறும் (எ.கா. Antigravity, "I am powered by Gemini" எனப் பதிலளிக்கும்), ஏனெனில் IDE அதை system prompt-இல் செலுத்துகிறது. மாதிரியிடம் அது யார் என்று கேட்பதற்குப் பதிலாக, உண்மையான பின்தளத்தை `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`) இல் உறுதிப்படுத்தவும்.

## §6 சிக்கல் தீர்வு

### Port 443 முரண்பாடு

வேறொரு செயல்முறை ஏற்கனவே port 443-இல் கேட்பில் இருந்தால் (வலைச் சேவையகம், VPN போன்றவை):

```bash
lsof -i :443          # செயல்முறையைக் கண்டறியவும்
sudo fuser -k 443/tcp  # வலுக்கட்டாயமாக நிறுத்தவும் (கவனமாகப் பயன்படுத்தவும்)
```

மாற்றாக, AgentBridge அமைப்புகளில் சிறப்புரிமை தேவையில்லாத ஒரு port-ஐ உள்ளமைத்து, `iptables` / `pf` திசைமாற்ற விதிகளை அமைக்கவும்.

### சான்றிதழ் நம்பப்படவில்லை

AgentBridge-ஐத் தொடங்கிய பிறகு IDE TLS பிழைகளைக் காட்டினால்:

1. சான்றிதழ் நிறுவப்பட்டுள்ளதா என்பதைச் சரிபார்க்கவும்: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) அல்லது `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. சில செயலிகள் தங்களுக்கென தனி நம்பகக் களஞ்சியத்தைப் பராமரிக்கின்றன (Firefox, Linux-இல் Chrome). "Trust Cert"-ஐ மீண்டும் இயக்கி, NSS/Firefox-க்கான குறிப்பிட்ட சான்றிதழ் களஞ்சியத்தைச் சரிபார்க்கவும்.
3. நம்பகமாக்கிய பிறகு IDE-ஐ மறுதொடக்கம் செய்யவும் — தற்போது நடைபெறும் TLS அமர்வுகள் பழைய நம்பக நிலையைப் பயன்படுத்துகின்றன.

### நம்பகமான CA இருந்தும் IDE வெளியேற்றப்பட்டது / "connection error"

அறிகுறி: DNS-ஐத் திசைமாற்றி, CA-ஐ நம்பகமாக்கிய பிறகு, Electron-அடிப்படையிலான IDE (எ.கா. Antigravity)
**வெளியேற்றப்பட்ட நிலையில்** திறக்கிறது அல்லது அங்கீகார/இணைப்புப் பிழையைக் காட்டுகிறது; ஆனால் MITM பதிவில்
தொடக்க அழைப்புகள் (`loadCodeAssist`, `fetchAvailableModels`, …) `200` எனத் திரும்புவது தெரிகிறது.

காரணம்: IDE-யுடன் **தொகுக்கப்பட்ட Node/Electron இயக்கச்சூழல் OS நம்பகக் களஞ்சியத்தைப் புறக்கணிக்கிறது**. இயல்புநிலை
பின்தளம் (Go மொழிச் சேவையகம்) OS CA-ஐ நம்பி அங்கீகரிக்கிறது; ஆனால் Electron முன்தளம்
அவ்வாறு செய்வதில்லை — எனவே UI இணைய இணைப்பு இல்லையெனக் கருதுகிறது.

தீர்வு (இரண்டு படிகளும்): `NODE_EXTRA_CA_CERTS=<ca.crt>`-ஐ export செய்து, desktop icon-இலிருந்து அல்லாமல் **அந்த
shell-இலிருந்தே IDE-ஐ மீண்டும் தொடங்கவும்**. முதலில் IDE-ஐ முழுமையாக மூடவும் — Electron-இன் singleton lock காரணமாக,
இரண்டாவது தொடக்கம் ஏற்கனவே இயங்கும் செயல்முறையை முன்னிலைப்படுத்த மட்டுமே செய்யும்; புதிய சூழல் புறக்கணிக்கப்படும். §3.2-ஐப் பார்க்கவும்.
இது, ஒரு தனித்த agent MITM வழியாகச் செயல்பட்டாலும் அதே அமைப்பில் IDE
மாறுபாடு தோல்வியடைவதாகக் கூறும் திறந்த upstream அறிக்கையை ஒத்திருக்கிறது.

### DNS பரவவில்லை

`/etc/hosts` புதுப்பிக்கப்பட்டுள்ளதா என்பதைச் சரிபார்க்கவும்:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

DNS தற்காலிகச் சேமிப்பை அழிக்கவும்:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE கண்டறியப்படவில்லை

தானியங்குக் கண்டறிதல் பொதுவான நிறுவல் பாதைகளைப் பயன்படுத்துகிறது. கண்டறிதல் தோல்வியடைந்தாலும் IDE நிறுவப்பட்டிருந்தால்:

- IDE binary தரமற்ற இடத்தில் உள்ளதா எனச் சரிபார்க்கவும்
- Setup Wizard தொடர்ந்து செயல்படும் — கண்டறிதல் தோல்வி என்பது badge நிறுவல் பாதையைக் காட்டாது என்பதையே குறிக்கிறது

### Handler பிழைகள் (upstream fetch தோல்வியடைகிறது)

AgentBridge இடைமறித்தாலும் அனைத்து கோரிக்கைகளும் தோல்வியடைந்தால்:

1. `/dashboard/providers`-இல் குறைந்தது ஒரு provider இணைக்கப்பட்டுள்ளதா என்பதை உறுதிப்படுத்தவும்
2. OmniRoute சேவையகப் பதிவுகளைச் சரிபார்க்கவும்: `.env`-இல் `APP_LOG_LEVEL=debug`
3. `OMNIROUTE_BASE_URL` சரியான router endpoint-ஐச் சுட்டுகிறதா என்பதை உறுதிப்படுத்தவும் (இயல்புநிலை: `http://127.0.0.1:20128`)

## §8 திட்ட வரைபடம்

### Trae ஆய்வு

Trae ஒப்பீட்டளவில் புதிய AI நிரலாக்க உதவியாளர். ஒரு handler-ஐச் செயல்படுத்துவதற்கு முன்:

1. VS Code / JetBrains சந்தைகளிலோ அல்லது தனித்த செயலியாகவோ binary/extension-ஐ அடையாளம் காணவும்
2. API host-களையும் endpoint வடிவங்களையும் கண்டறிய mitmproxy மூலம் போக்குவரத்தைப் பதிவு செய்யவும்
3. அங்கீகாரச் செயல்முறையைத் தீர்மானிக்கவும்
4. TOS மற்றும் API-ஐக் கண்டறியும் சாத்தியத்தின் அடிப்படையில் செயல்படுத்தலாமா வேண்டாமா என்பதை மதிப்பிடவும்

ஆய்வு முடிவடையும் வரை, dashboard-இல் உள்ள Trae அட்டை, "சாத்தியக்கூற்றைப் புகாரளிக்கவும்" என்ற இணைப்புடன் "ஆய்வில் உள்ளது" என்ற badge-ஐக் காட்டும். `src/mitm/handlers/trae.ts`-இல் உள்ள handler stub, கட்டமைக்கப்பட்ட `இன்னும் செயல்படுத்தப்படவில்லை` பிழையை எழுப்பும்.

### நிலுவையிலுள்ள agent-கள் (MITM தேவை — தனிப்பயன் base URL ஆதரவு இல்லை)

பின்வரும் கருவிகள் அவற்றின் தற்போதைய பதிப்புகளில் தனிப்பயன் base URL-களை ஆதரிக்காததால், MITM மட்டுமே இடைமறிப்பிற்கான ஒரே வழியாக உள்ளது. சாத்தியக்கூறு மதிப்பீடு நிலுவையில் உள்ளது:

- **Windsurf** (Codeium/Cognition)
- **Amp** (Sourcegraph)
- **Amazon Q / Kiro CLI** (AWS Bedrock — Kiro IDE-இலிருந்து வேறுபட்டது)
- **Cowork** (Anthropic desktop)

குறிப்பு: GitHub Copilot CLI ≥v1.0.19, `COPILOT_PROVIDER_BASE_URL`-ஐ ஆதரிக்கிறது — அந்தக் கருவிக்கு MITM-க்குப் பதிலாக நேரடி config-ஐப் பயன்படுத்தவும்.
