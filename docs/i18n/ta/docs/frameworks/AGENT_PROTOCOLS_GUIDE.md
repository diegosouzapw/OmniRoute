OmniRoute முகவர்கள் தொடர்பான மூன்று வெவ்வேறு இடைமுகங்களை வழங்குகிறது. முதல் பார்வையில் அவை ஒரே மாதிரியாகத் தோன்றினாலும், வெவ்வேறு சிக்கல்களைத் தீர்க்கின்றன. சரியான ஒன்றைத் தேர்ந்தெடுக்க இந்தப் பக்கத்தைப் பயன்படுத்தவும்.

## சுருக்கமாக

| இடைமுகம்                            | இதற்கு மிகவும் ஏற்றது                                                                                                                                   | பரிமாற்ற முறை                        | தரநிலை                           |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------ | -------------------------------- |
| **A2A — முகவரிலிருந்து முகவருக்கு** | A2A நெறிமுறையைப் பயன்படுத்தும் சக முகவர்களுடன் முகவர்களுக்கு இடையிலான ஒத்துழைப்பு                                                                       | HTTP வழியான JSON-RPC 2.0             | A2A v0.3 (திறந்த விவரக்குறிப்பு) |
| **ACP — CLI முகவர்கள் பதிவகம்**     | பயனரின் கணினியில் நிறுவப்பட்டுள்ள CLI நிரலாக்க முகவர்களைக் கண்டறிதல் / பதிவுசெய்தல் / தொடங்குதல் (Cursor, Cline, Codex CLI, Claude Code, Aider போன்றவை) | HTTP REST                            | OmniRoute-க்கே உரியது            |
| **Cloud முகவர்கள்**                 | வெளிப்புற கிளவுட் சேவைகளுக்குப் (Codex Cloud, Devin, Jules, Cursor Cloud) நீண்ட நேரம் இயங்கும் நிரலாக்கப் பணிகளைச் சமர்ப்பித்தல்                        | HTTP REST + தரவுத்தள ஆதரவுள்ள பணிகள் | OmniRoute-க்கே உரியது            |

இந்த மூன்றும் ஒன்றுக்கொன்று சார்பற்றவை — எந்தத் துணைத்தொகுப்பையும் தேர்ந்தெடுக்கலாம்.

## முடிவு மரம்

```
இந்தக் கணினிக்கு வெளியே பணிசெய்ய ஒரு கிளவுட் சேவை தேவையா (Codex Cloud / Cursor Cloud / Devin / Jules)?
├─ ஆம் → Cloud முகவர்கள் (POST /api/v1/agents/tasks)
└─ இல்லை → தொடரவும்
    │
    A2A நெறிமுறையைப் பயன்படுத்தி ஒத்துழைக்க விரும்பும் சக முகவர் உங்களிடம் உள்ளதா?
    ├─ ஆம் → A2A (POST /a2a)
    └─ இல்லை → தொடரவும்
        │
        உள்நாட்டில் நிறுவப்பட்டுள்ள CLI நிரலாக்க முகவர்களைப் பட்டியலிட / உள்ளமைக்க வேண்டுமா?
        ├─ ஆம் → ACP (GET /api/acp/agents)
        └─ இல்லை → சாதாரண /v1/chat/completions-ஐப் பயன்படுத்தவும்
```

## 1. A2A — முகவரிலிருந்து முகவருக்கு

**விவரக்குறிப்பு:** [A2A v0.3](https://a2a-protocol.org)
**OmniRoute முனைப்புள்ளி:** `POST /a2a` (JSON-RPC 2.0)
**முகவர் அட்டை:** `GET /.well-known/agent.json`

### எப்போது பயன்படுத்த வேண்டும்

- OmniRoute சக முகவர்களில் ஒன்றாக இருக்கும் பல்முகவர் அமைப்பை உருவாக்கும்போது
- Google ADK போன்ற கட்டமைப்புகள் அல்லது பொதுவான முகவர் வலைப்பின்னல்களில் உள்ள முகவர்களுக்கு OmniRoute-இன் வழிச்செலுத்தல் நுண்ணறிவை (நுண்ணறிவு வழிச்செலுத்தல், ஒதுக்கீடு மேலாண்மை போன்றவை) வழங்கும்போது
- தரநிலையான கண்டறிதல் + அழைப்பு இடைமுகத்துக்குப் பின்னால் OmniRoute-ஐப் பொதியும்போது

### முறைகள்

- `message/send` — ஒரு செய்தியைச் சமர்ப்பித்து, ஒத்திசைவான பதிலைப் பெறுதல்
- `message/stream` — சமர்ப்பித்து + SSE வழியாக ஸ்ட்ரீம் செய்யப்படும் முன்னேற்ற நிகழ்வுகளைப் பெறுதல்
- `tasks/get` — ID மூலம் பணியைப் படித்தல்
- `tasks/cancel` — இயங்கிக்கொண்டிருக்கும் பணியை ரத்துசெய்தல்

### உள்ளமைந்த திறன்கள் (6)

- `smart-routing` — உகந்த சேர்க்கை வழியாக ஒரு தூண்டுதலை வழிச்செலுத்துதல்
- `quota-management` — ஒவ்வொரு வழங்குநருக்குமான ஒதுக்கீட்டு நிலையை அறிக்கையிடுதல்
- `provider-discovery` — நிறுவப்பட்ட வழங்குநர்களை அவர்களின் திறன்களுடன் பட்டியலிடுதல்
- `cost-analysis` — ஒரு கோரிக்கை/உரையாடலின் செலவை மதிப்பிடுதல்
- `health-report` — ஒவ்வொரு வழங்குநருக்குமான பிரேக்கர்/காத்திருப்பு/பூட்டுநிலையைத் தொகுத்தல்
- `list-capabilities` — முகவருக்குக் கிடைக்கும் திறன்களையும் மேனிலைத்தரவையும் பட்டியலிடுதல்

### விரிவான விளக்கம்

பரிமாற்ற விவரங்கள், முகவர் அட்டை அமைப்பு, பணி TTL உள்ளமைவு மற்றும் புதிய திறன்களைச் சேர்ப்பதற்கான வார்ப்புரு ஆகியவற்றுக்கு [A2A-SERVER.md](./A2A-SERVER.md)-ஐப் பார்க்கவும்.

## 2. ACP — CLI முகவர்கள் பதிவகம்

**OmniRoute முனைப்புள்ளி:** `GET /api/acp/agents`
**மூலம்:** `src/lib/acp/{index,manager,registry}.ts`

### இது என்ன

ACP என்பது OmniRoute-இன் **உள்ளக CLI முகவர் பட்டியல்**. ஹோஸ்டில் நிறுவப்பட்டுள்ள நிரலாக்க CLI-களை (Cursor, Cline, Claude Code, Codex CLI, Continue போன்றவை) இது கண்டறிந்து, அவற்றின் பதிப்புகளைத் தீர்மானித்து, ஒவ்வொரு CLI-யையும் OmniRoute-ஐச் சுட்டுமாறு பயனர் இணைக்கக்கூடிய வகையில் அவற்றை டாஷ்போர்டில் காட்டுகிறது.

இது வெளிப்புற நெறிமுறை அல்ல — இது "CLI Tools" பயனர் இடைமுகத்தையும் CLI கைரேகைக் கண்காணிப்பையும் இயக்கும் அகப் பதிவகம் ([CLI-TOOLS.md](../reference/CLI-TOOLS.md)-ஐப் பார்க்கவும்).

### இது என்ன செய்கிறது

- நிறுவப்பட்டுள்ள CLI பைனரிகளுக்காக ஹோஸ்டைச் சோதிக்கிறது (OS-க்கு ஏற்ப `which` / `where`-ஐப் பயன்படுத்துகிறது)
- ஒவ்வொரு CLI-யின் பதிப்பையும் படிக்கிறது (`<bin> --version`-ஐ அழைக்கிறது)
- விருப்பத்திற்கேற்ப பயனர் வரையறுத்த தனிப்பயன் முகவர்களை ஏற்கிறது (பைனரி பாதை + பதிப்புச் சோதனை + தொடக்க அளவுருக்கள்)
- தனிப்பயன் முகவர்களை அமைப்புகளில் நிலையாகச் சேமிக்கிறது
- ஒருங்கிணைக்கப்பட்ட பட்டியலை டாஷ்போர்டுக்குத் திருப்பித் தருகிறது

### REST API

| முனைப்புள்ளி      | முறை | விளக்கம்                                                                                      | அங்கீகாரம் |
| ----------------- | ---- | --------------------------------------------------------------------------------------------- | ---------- |
| `/api/acp/agents` | GET  | கண்டறியப்பட்ட + தனிப்பயன் முகவர்களைப் பட்டியலிடுகிறது (நிறுவப்பட்ட/மொத்த எண்ணிக்கைகள்)        | API விசை   |
| `/api/acp/agents` | POST | தனிப்பயன் முகவரைச் சேர்க்கிறது/புதுப்பிக்கிறது/நீக்குகிறது (உள்ளடக்கத்தில் செயல் வேறுபடுத்தி) | API விசை   |

POST-க்கான உள்ளடக்க வடிவம் (`src/app/api/acp/agents/route.ts`-இல் உள்ள `customAgentBodySchema`):

```json
{
  "action": "add|update|remove",
  "id": "cursor",
  "name": "Cursor",
  "binary": "/usr/local/bin/cursor",
  "versionCommand": "--version",
  "providerAlias": "cursor",
  "spawnArgs": ["--api-base", "http://localhost:20128"],
  "protocol": "stdio"
}
```

### பயன்பாட்டு நிலைகள்

- டாஷ்போர்டின் "CLI Tools" பக்கம் நிறுவப்பட்டுள்ளவற்றைப் பட்டியலிட்டு, ஒவ்வொன்றையும் OmniRoute-ஐச் சுட்டுமாறு அமைக்க உதவுகிறது
- OmniRoute இயல்பாக அறியாத அக/தனியுரிம CLI-களை மேம்பட்ட பயனர்கள் பதிவுசெய்ய தனிப்பயன் முகவர்கள் உதவுகின்றன
- கண்டறிதல் முடிவு `cli-tools` கைரேகை அணியை உருவாக்கப் பயன்படுகிறது

### ACP-ஐ எப்போது பயன்படுத்தக்கூடாது

- ACP பணிகளை _இயக்காது_. இது CLI-களைக் கண்டறிந்து + உள்ளமைப்பதை மட்டுமே செய்கிறது. ஒரு CLI-யை உண்மையில் செயல்படுத்த, OmniRoute வழங்கும் சூழல் மாறிகளுடன் (`OPENAI_BASE_URL`, `OPENAI_API_KEY` போன்றவை) அதை நீங்களே தொடங்க வேண்டும்.

## 3. கிளவுட் முகவர்கள்

**OmniRoute முனைப்புள்ளிகள்:** `/api/v1/agents/tasks/*` (வாழ்க்கைச் சுழற்சி) + `/api/cloud/*` (அடிப்படை இணைப்பமைப்பு)
**மூலம்:** `src/lib/cloudAgent/`

### இது என்ன

மூன்றாம் தரப்பு கிளவுட் நிரலாக்க முகவர்களுக்கான ஒரே மாதிரியான இடைமுகம். நீங்கள் ஒரு அறிவுறுத்தல் + களஞ்சிய URL-ஐச் சமர்ப்பிக்கிறீர்கள்; OmniRoute அதைச் சரியான கிளவுட் முகவருக்கு அனுப்பி, நிலையைத் தொடர்ந்து சரிபார்த்து, முடிவுகளைத் திருப்பித் தருகிறது.

### ஆதரிக்கப்படும் முகவர்கள் (4, அனைத்தும் `src/lib/cloudAgent/agents/`-இல் உறுதிப்படுத்தப்பட்டவை)

- `codex-cloud` — OpenAI Codex Cloud
- `devin` — Cognition Devin
- `jules` — Google Jules

### வாழ்க்கைச் சுழற்சி

```
POST /api/v1/agents/tasks
  → ஒவ்வொரு முகவர் வகுப்பிற்கும் BaseAgent.createTask()
  → வெளிப்புறச் சேவை பணியைத் தொடங்குகிறது
  → DB-இல் பணி வரிசை உருவாக்கப்படுகிறது (cloud_agent_tasks)
  ↓
GET /api/v1/agents/tasks/[id]
  → வழங்குநரிடமிருந்து தேவைக்கேற்ப நிலை ஒத்திசைவு
  → தற்போதைய நிலை + திட்டம் + செயல்பாட்டுப் பதிவைத் திருப்பித் தருகிறது
  ↓
POST /api/v1/agents/tasks/[id]   (செயல்: "approve" | "message" | "cancel")
  → வழங்குநருக்கு அனுப்புகிறது (அல்லது உள்ளகமாக ரத்துசெய்யப்பட்டதாகக் குறிக்கிறது)
  ↓
DELETE /api/v1/agents/tasks/[id]
  → உள்ளக ரத்துசெய்தல்
```

### அங்கீகாரம்

⚠️ **அனைத்து `/api/v1/agents/tasks/*` முனைப்புள்ளிகளுக்கும் மேலாண்மை அங்கீகாரம் தேவை** (commit `588a0333`). v3.8.0 முதல் Bearer-ஐ மட்டுமே பயன்படுத்தும் அழைப்பாளர்கள் 401 பதிலைப் பெறுவார்கள்.

### ஆழமான விளக்கம்

`CloudAgentBase` ஒப்பந்தம், ஒவ்வொரு முகவருக்குமான விவரங்கள், திட்டவடிவ விவரங்கள் மற்றும் நற்சான்று இணைப்பமைப்பு முனைப்புள்ளிகளுக்கு [CLOUD_AGENT.md](./CLOUD_AGENT.md)-ஐப் பார்க்கவும்.

## ஒப்பீடு: A2A மற்றும் Cloud Agents

இரண்டிலும் "நீண்ட நேரம் இயங்கும் பணிகள்" உள்ளன, ஆனால் வெவ்வேறு அடுக்குகளில்:

| அம்சம்                | A2A                                                                                        | Cloud Agents                                                   |
| --------------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------------- |
| தரநிலை                | திறந்த A2A v0.3                                                                            | OmniRoute-க்கே உரியது                                          |
| கணக்கீடு இயங்குமிடம்  | OmniRoute-க்குள் (உள்ளமைக்கப்பட்ட சேர்க்கைகளைப் பயன்படுத்துகிறது)                          | வெளிப்புறம் (Codex / Devin / Jules சேவையகங்கள்)                |
| பணி கால அளவு          | இயல்புநிலை TTL 5 நிமிடங்கள் (`TaskManager`-இல் உள்ளமைக்கலாம்)                              | நிமிடங்கள் முதல் மணிநேரங்கள் வரை                               |
| களஞ்சிய விழிப்புணர்வு | இல்லை (தூண்டுதல்களை மட்டும் அனுப்புகிறது)                                                  | ஆம் (களஞ்சிய URL + கிளை)                                       |
| பயன்பாடு              | முகவர்களுக்கிடையேயான கூட்டுப்பணி, சேவையாக நுண்ணறிவு வழிப்படுத்தல்                          | "களஞ்சியம் Y-இல் அம்சம் X-ஐச் செயல்படுத்து" என்பதை ஒப்படைத்தல் |
| அங்கீகாரம்            | `/a2a`-க்கு விருப்பத்திற்குரிய `OMNIROUTE_API_KEY`; `/api/a2a/*` REST உதவிகளுக்கு மேலாண்மை | எப்போதும் மேலாண்மை                                             |

## ஒருங்கிணைப்பு எடுத்துக்காட்டுகள்

### OmniRoute-இன் A2A திறன்களைக் கண்டறிதல்

```bash
curl http://localhost:20128/.well-known/agent.json
```

அனைத்து 6 திறன்கள், போக்குவரத்து முறைகள் மற்றும் பதிப்புடன் கூடிய Agent Card-ஐ வழங்குகிறது.

### OmniRoute-ஐ A2A முகவராக அழைத்தல்

```bash
curl -X POST http://localhost:20128/a2a \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "method": "message/send",
    "params": {
      "messages": [{"role": "user", "content": "Route this prompt"}],
      "skill": "smart-routing"
    },
    "id": 1
  }'
```

### ACP வழியாக நிறுவப்பட்ட CLI முகவர்களைப் பட்டியலிடுதல்

```bash
curl http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>"
```

### தனிப்பயன் CLI முகவரைச் சேர்த்தல்

```bash
curl -X POST http://localhost:20128/api/acp/agents \
  -H "Authorization: Bearer <api-key>" \
  -H "Content-Type: application/json" \
  -d '{
    "action": "add",
    "id": "my-custom-cli",
    "name": "My Custom CLI",
    "binary": "/opt/mycli/bin/mycli",
    "versionCommand": "--version",
    "providerAlias": "openai"
  }'
```

### Cloud Agent பணியைச் சமர்ப்பித்தல்

```bash
curl -X POST http://localhost:20128/api/v1/agents/tasks \
  -H "Cookie: auth_token=..." \
  -H "Content-Type: application/json" \
  -d '{
    "providerId": "devin",
    "prompt": "Implement feature X in repo Y",
    "source": {
      "repoName": "user/repo",
      "repoUrl": "https://github.com/user/repo",
      "branch": "main"
    }
  }'
```

### Cloud பணியின் நிலையைச் சரிபார்த்தல்

```bash
curl http://localhost:20128/api/v1/agents/tasks/<task-id> \
  -H "Cookie: auth_token=..."
```
