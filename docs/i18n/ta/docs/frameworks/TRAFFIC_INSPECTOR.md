Traffic Inspector என்பது OmniRoute-இன் உட்பொதிக்கப்பட்ட HTTPS போக்குவரத்துப் பிழைத்திருத்தி — இது Charles Proxy / mitmweb / HTTP Toolkit போன்ற ஒரு கருவி; மேலும் இது **LLM-aware** மற்றும் **agent-aware** ஆகும். இது `/dashboard/tools/traffic-inspector` என்ற இடத்தில் உள்ளது மற்றும் ஒரே நேரத்தில் அதிகபட்சம் 5 பிடிப்பு மூலங்களிலிருந்து நேரடி போக்குவரத்தைப் பெறுகிறது.

**Dashboard இருப்பிடம்:** `/dashboard/tools/traffic-inspector`
**Sidebar குழு:** Tools (AgentBridge-க்குப் பிறகு)
**மேலும் காண்க:** [`AGENTBRIDGE.md`](./AGENTBRIDGE.md) — AgentBridge என்பது பிடிப்பு முறை 1.

### ஒரே பத்தியில் கட்டமைப்பு

`TrafficBuffer` (`src/mitm/inspector/buffer.ts`) என்பது பகிரப்பட்ட நினைவகத்திலுள்ள ring buffer ஆகும் (இயல்புநிலையாக 1000 பதிவுகள்; `INSPECTOR_BUFFER_SIZE` வழியாக உள்ளமைக்கலாம்). அனைத்து பிடிப்பு மூலங்களும் `push()` வழியாக அதில் எழுதுகின்றன. buffer ஒவ்வொரு பதிவையும் `kindDetector.ts`-ஐப் பயன்படுத்தி வகைப்படுத்துகிறது (அது ஒரு LLM கோரிக்கையா என்பதைத் தீர்மானிக்கிறது), ஒரு `contextKey`-ஐக் கணக்கிடுகிறது (system prompt-இன் SHA-256 கைரேகை), மேலும் `globalTrafficBuffer.subscribe()` வழியாக அனைத்து WebSocket சந்தாதாரர்களுக்கும் ஒலிபரப்புகிறது. dashboard ஆனது `GET /api/tools/traffic-inspector/ws` வழியாக இணைந்து, இணைக்கும்போது ஒரு snapshot-ஐப் பெறுகிறது; அதைத் தொடர்ந்து `new`/`update`/`clear` நிகழ்வுகளைப் பெறுகிறது.

## §2 கைப்பற்றல் முறைகள்

Traffic Inspector **ஒரே நேரத்தில் 5 கைப்பற்றல் மூலங்களை** ஆதரிக்கிறது. ஒவ்வொன்றையும் தனித்தனியாக இயக்கவோ முடக்கவோ முடியும். ஒவ்வொரு `InterceptedRequest`-இலும் (`src/mitm/inspector/types.ts`) உள்ள `source` புலம் `"agent-bridge"`, `"custom-host"`, `"http-proxy"`, `"system-proxy"`, அல்லது `"tproxy"` ஆகியவற்றில் ஒன்றாக இருக்கும்.

### முறை 1 — AgentBridge (இயல்புநிலை, எப்போதும் இயக்கத்தில்)

**மூலம்:** AgentBridge கையாளிகள் (`src/mitm/handlers/base.ts`)
**செயல்முறை:** `MitmHandlerBase`-இல் உள்ள ஒவ்வொரு `intercept()` அழைப்பும், அனுப்புவதற்கு முன் `hookBufferStart()`-ஐயும் நிறைவடைந்ததும் `hookBufferUpdate()`-ஐயும் அழைக்கிறது. கூடுதல் உள்ளமைவு எதுவும் தேவையில்லை — AgentBridge இயங்கத் தொடங்கியவுடன் இது செயல்படும்.
**அணுகல் வரம்பு:** AgentBridge-இல் உள்ளமைக்கப்பட்டுள்ள 9 IDE முகவர்கள்
**குறிப்பு:** `InterceptedRequest`-இல் உள்ள `source` புலம் = `"agent-bridge"`

### முறை 2 — தனிப்பயன் ஹோஸ்ட்கள் (DNS திசைமாற்றம்)

**மூலம்:** பயனர் வரையறுத்த ஹோஸ்ட் பட்டியல் (`inspector_custom_hosts` அட்டவணை)
**செயல்முறை:** UI வழியாக ஒரு ஹோஸ்டைச் சேர்ப்பது, `/etc/hosts`-இல் `127.0.0.1 <host>`-ஐச் சேர்க்கிறது (sudo தேவை). ஏற்கெனவே உள்ள AgentBridge MITM சேவையகம் (போர்ட் 443), புதிய ஹோஸ்டுக்கான SNI சான்றிதழை இயக்கநேரத்தில் உருவாக்குகிறது.
**அணுகல் வரம்பு:** சேர்க்கப்பட்ட ஹோஸ்டைப் பயன்படுத்தும் எந்தப் பயன்பாடும் — பயன்பாட்டு உள்ளமைவில் மாற்றம் தேவையில்லை
**குறிப்பு:** `source` = `"custom-host"`

பயன்பாட்டு எடுத்துக்காட்டுகள்:

- Python ஸ்கிரிப்ட்களிலிருந்து `api.openai.com`-ஐக் கண்காணித்தல்
- `my-internal-llm.company.com`-ஐப் பிழைத்திருத்துதல்
- அதே பிணையத்திலுள்ள மொபைல் சாதனங்களின் போக்குவரத்தைக் கைப்பற்றுதல் (ARP ஏமாற்றுதல் வழியாக — மேம்பட்டது)

### முறை 3 — HTTP_PROXY கேட்பான் (போர்ட் 8080)

**மூலம்:** `HTTP_PROXY`/`HTTPS_PROXY` சூழல் மாறிகளைப் பயன்படுத்தும் பயன்பாடுகள்
**செயல்முறை:** போர்ட் 8080-இல் உள்ள இரண்டாம் நிலைக் கேட்பான் (`src/mitm/inspector/httpProxyServer.ts`), நிலையான வெளிப்படையான HTTP/HTTPS ப்ராக்ஸியாகச் செயல்படுகிறது. `CONNECT` சுரங்கங்களையும் (HTTPS), நேரடி HTTP கோரிக்கைகளையும் ஏற்கிறது.
**அணுகல் வரம்பு:** `HTTP_PROXY` சூழல் மாறியை மதிக்கும் எந்தப் பயன்பாடும் — DNS மாற்றமும் sudo-வும் தேவையில்லை
**குறிப்பு:** `source` = `"http-proxy"`

```bash
# ஒரே கட்டளைக்கான விரைவான கைப்பற்றல்:
HTTPS_PROXY=http://127.0.0.1:8080 curl https://api.openai.com/v1/models

# ஷெல் அமர்வில் தொடர்ச்சியான கைப்பற்றல்:
export HTTP_PROXY=http://127.0.0.1:8080
export HTTPS_PROXY=http://127.0.0.1:8080
```

**TLS வரம்பு:** HTTPS `CONNECT` சுரங்கங்கள் இயல்பாக மேனிலைத் தகவல்களாக மட்டுமே (ஹோஸ்ட், போர்ட், நேர அளவீடு) கைப்பற்றப்படுகின்றன — TLS உள்ளடக்கம் மறைகுறிநீக்கம் செய்யப்படாது. முழு உள்ளடக்க ஆய்வுக்காக "ப்ராக்ஸி முறையில் HTTPS-ஐ மறைகுறிநீக்கு" நிலைமாற்றியை இயக்கவும் (விருப்பத் தேர்வு; AgentBridge சான்றிதழ் நம்பப்பட்டிருக்க வேண்டும்).

**போர்ட் முரண்பாடு:** போர்ட் 8080 பயன்பாட்டில் இருந்தால், AgentBridge கட்டமைக்கப்பட்ட பிழையுடன் 409-ஐ வழங்கும். `INSPECTOR_HTTP_PROXY_PORT` சூழல் மாறி வழியாகப் போர்ட்டை மாற்றவும்.

### முறை 4 — கணினி முழுவதுமான ப்ராக்ஸி (மேம்பட்டது, விருப்பத் தேர்வு)

**மூலம்:** இயக்க முறைமை அளவிலான ப்ராக்ஸி அமைப்புகள் (கணினியிலுள்ள அனைத்துப் பயன்பாடுகளுக்கும் பொருந்தும்)
**செயல்முறை:** அனைத்து HTTP/HTTPS போக்குவரத்தையும் HTTP_PROXY கேட்பான் வழியாகத் திசைமாற்ற இயக்க முறைமை API-களைப் பயன்படுத்துகிறது:

- **macOS:** `networksetup -setwebproxy / -setsecurewebproxy`
- **Linux:** `gsettings set org.gnome.system.proxy` + `/etc/environment`
- **Windows:** `netsh winhttp set proxy 127.0.0.1:8080`
  **அணுகல் வரம்பு:** கணினியின் ப்ராக்ஸி அமைப்புகளை மதிக்கும், அந்தக் கணினியிலுள்ள ஒவ்வொரு பயன்பாடும்
  **குறிப்பு:** `source` = `"system-proxy"`

**பாதுகாப்பு வழிமுறைகள்:**

- தானாக முடக்கும் நேரக்கணிப்பான் (இயல்பாக 30 நிமிடங்கள்; `INSPECTOR_SYSTEM_PROXY_GUARD_MINUTES` வழியாக உள்ளமைக்கலாம்)
- முந்தைய கணினி ப்ராக்ஸி நிலை DB-இல் சேமிக்கப்பட்டு, மீட்டமைக்கும்போது மீண்டும் நிறுவப்படும்
- இது செயலில் இருக்கும்போது பயனர் வேறு பக்கத்திற்குச் சென்றால், கட்டுப்பாட்டகம் "கணினி ப்ராக்ஸி மீட்டமைக்கப்படுகிறது" என்ற அறிவுறுத்தலைக் காட்டும்
- UI-இல் `⚠ மேம்பட்டது` அடையாளம் + வெளிப்படையான உறுதிப்படுத்தல் தேர்வுப்பெட்டி காட்டப்படும்

### முறை 5 — TPROXY வெளிப்படையான மறைகுறிநீக்கம் (Linux, root, விருப்பத் தேர்வு)

**மூலம்:** கர்னல் TPROXY + கொள்கை வழிப்படுத்தல் (`src/mitm/tproxy/`)
**செயல்முறை:** இலக்குப் போர்ட்டிற்கான (இயல்புநிலை `443`) புதிய உள்ளூர் வெளிச்செல்லும் TCP இணைப்புகளை `mangle OUTPUT`-இல் குறியிடுகிறது; ஒரு `ip rule`, குறியிடப்பட்ட பாக்கெட்டுகளை உள்ளூர் வழங்கலுக்கு மாற்றி வழிப்படுத்துகிறது; மேலும் `mangle PREROUTING`-இன் `TPROXY` இலக்கு, அவற்றை வெளிப்படையான (**IP_TRANSPARENT**) கேட்பானிடம் (இயல்புநிலை போர்ட் `8443`) ஒப்படைக்கிறது. கேட்பான், இயக்கநிலை CA மூலம் **ஒவ்வொரு SNI ஹோஸ்ட்பெயருக்கும் தேவைக்கேற்ப** வழங்கப்பட்ட இலைச் சான்றிதழைக் கொண்டு TLS-ஐ முடிவுறுத்தி, மறைகுறிநீக்கப்பட்ட பரிமாற்றத்தைக் கைப்பற்றி, கோரிக்கையை மீண்டும் மறைகுறியாக்கி அசல் இலக்கிற்கு அனுப்புகிறது.
**அணுகல் வரம்பு:** இலக்குப் போர்ட்டிலுள்ள **எந்தவொரு** இலக்கு ஹோஸ்ட்களும் — `/etc/hosts` ஏமாற்றுதல் இல்லை, `HTTP_PROXY` சூழல் மாறி இல்லை, கணினி முழுவதுமான ப்ராக்ஸி மாற்றம் இல்லை. இடைமறிக்கப்படும் செயல்முறைக்கு உள்ளமைவு மாற்றம் தேவையில்லை; ஆனால் அது இயக்கநிலை CA-ஐ நம்ப வேண்டும்.
**குறிப்பு:** `source` = `"tproxy"`

**தேவைகள்:** Linux மட்டும் (**IP_TRANSPARENT** என்பது Linux-க்கு மட்டுமே உரியது), **CAP_NET_ADMIN** திறன் (root), மற்றும் C கருவித்தொகுப்பைப் பயன்படுத்தி உருவாக்கப்பட வேண்டிய இயல்நிலை N-API துணைநிரல் (`npm run build:native:tproxy`). இவை கிடைக்காதபோது, "TPROXY மறைகுறிநீக்கத்திற்கு Linux + root + இயல்நிலை துணைநிரல் தேவை" என்ற கருவிக்குறிப்புடன் கட்டுப்பாட்டக நிலைமாற்றி முடக்கப்பட்டிருக்கும். ஃபயர்வால் விதிகள் பரிவர்த்தனை முறையில் பயன்படுத்தப்பட்டு/மீட்டமைக்கப்படுகின்றன (செயலிழப்பு ஒருபோதும் `mangle` விதியை எஞ்சவிடாது); மறுதொடக்கத்தின்போது அவை அகற்றப்படும். SO_MARK அடிப்படையிலான சுழற்சி-தடுப்பு, ப்ராக்ஸியால் மீண்டும் மறைகுறியாக்கப்பட்டு அனுப்பப்படும் போக்குவரத்து மறுபடியும் இடைமறிக்கப்படுவதைத் தடுக்கிறது.

இது தனக்கென ஒரு பிரத்யேக இயக்குநர் வழிகாட்டியைக் கொண்ட கணிசமான துணைஅமைப்பாகும் — முழுமையான ஃபயர்வால் செய்முறை, ஒவ்வொரு SNI-க்குமான இயக்கநிலை CA + நம்பகக் களஞ்சிய நிறுவி, உள்ளூர்-மட்டும் வழி, சுழற்சி-தடுப்பு விவரங்கள் மற்றும் உள்ளமைவுத் திட்டம் ஆகியவற்றுக்கு `docs/security/MITM-TPROXY-DECRYPT.md`-ஐப் பார்க்கவும் (git; `/docs`-இல் தொகுக்கப்படவில்லை). நிலைமாற்றி `GET / POST / DELETE /api/tools/agent-bridge/tproxy` மூலம் கட்டுப்படுத்தப்படுகிறது (குறிப்பு: பாதை Traffic Inspector முன்னொட்டின் கீழ் அல்லாமல், AgentBridge முன்னொட்டின் கீழ் உள்ளது).

| Host வடிகட்டி         | `host` புலத்தில் substring பொருத்தம்                                                                  |
| முகவர் வடிகட்டி       | Dropdown: அனைத்தும் / ஒவ்வொரு முகவரும்                                                                |
| நிலை வடிகட்டி         | அனைத்தும் / 2xx / 3xx / 4xx / 5xx / பிழை                                                              |
| மூல வடிகட்டி          | அனைத்தும் / agent-bridge / custom-host / http-proxy / system-proxy / tproxy                           |

### 3.5 அளவுமாற்றக்கூடிய பலகங்கள்

- பட்டியலும் விவரப் பலகமும் இழுக்கும் கைப்பிடியால் பிரிக்கப்பட்டுள்ளன
- பட்டியல் அகலம்: குறைந்தபட்சம் 280px, அதிகபட்சம் 720px, `localStorage`-இல் (`inspector.listWidth`) நிலையாகச் சேமிக்கப்படும்
- 48px தண்டவாளமாகச் சுருக்கலாம் (icon மட்டும்); விரிவாக்க தண்டவாளத்திலுள்ள ஒரு வரிசையைக் கிளிக் செய்யவும்

## §4 LLM-அறிவுள்ள அம்சங்கள்

### 4.1 வகை கண்டறிவான் (`src/mitm/inspector/kindDetector.ts`)

4 சமிக்ஞைகளைப் பயன்படுத்தி ஒவ்வொரு கோரிக்கையையும் `"llm"`, `"app"` அல்லது `"unknown"` என வகைப்படுத்துகிறது:

1. **ஹோஸ்ட் பதிவகம்** — அறியப்பட்ட சுமார் 18 LLM API ஹோஸ்ட் பெயர்கள் (OpenAI, Anthropic, Gemini, Groq, Mistral, Together, Fireworks, Cohere, Perplexity, Hugging Face, OpenRouter, xAI, Moonshot போன்றவை)
2. **பாதை வடிவங்கள்** — `/v1/chat/completions`, `/v1/messages`, `/generateContent`, `/v1/responses` போன்றவை
3. **உள்ளடக்க அமைப்பு** — `messages[]` (OpenAI/Claude), `contents[]` (Gemini), `prompt`, `input` புலங்களைக் கண்டறிகிறது
4. **பயனர்-முகவர் குறிப்புகள்** — UA சரத்தில் `codex`, `claude`, `gemini`, `antigravity`, `kiro`, `copilot`, `cursor`

Mode 2 வழியாகச் சேர்க்கப்பட்ட தனிப்பயன் ஹோஸ்ட்கள், படிவ உள்ளீட்டிலிருந்து அவற்றின் `kind`-ஐப் பெறுகின்றன (இயல்புநிலை `"custom"`).

### 4.2 SSE ஒன்றிணைப்பான் (`src/mitm/inspector/sseMerger.ts`)

**சார்பற்ற clean-room செயலாக்கம்.** நிகழ்வு பகுப்பாய்வு
[WHATWG server-sent events algorithm](https://html.spec.whatwg.org/multipage/server-sent-events.html#parsing-an-event-stream)-ஐப் பின்பற்றுகிறது;
மறுகட்டமைப்பு பொதுவில் கிடைக்கும் [OpenAI](https://platform.openai.com/docs/api-reference/chat/create),
[Anthropic](https://platform.claude.com/docs/en/build-with-claude/streaming), மற்றும்
[Gemini](https://ai.google.dev/api/generate-content#method:-models.streamgeneratecontent)
ஸ்ட்ரீமிங் திட்டவடிவங்களைப் பின்பற்றுகிறது.

மூல SSE டெல்டா நிகழ்வுகளிலிருந்து இறுதி உதவியாளர் செய்தியை மறுகட்டமைக்கிறது:

- **Anthropic**: `content_block_delta`-ஐ அட்டவணைக் குறியீட்டின்படி திரட்டுகிறது; `text_delta`, `input_json_delta` (கருவி அழைப்புகள்), `thinking_delta` ஆகியவற்றைக் கையாளுகிறது
- **OpenAI**: Chat Completions தேர்வுகள்/கருவி அழைப்புகள் மற்றும் Responses API வெளியீட்டு உருப்படிகளை அட்டவணைக் குறியீட்டின்படி திரட்டுகிறது
- **Gemini**: `candidates[i].content.parts`-ஐத் திரட்டுகிறது
- **அறியப்படாதது**: மூல நிகழ்வுகளை மாற்றமின்றித் திருப்பியளிக்கிறது

Response தாவல் ஒரு நிலைமாற்றியைக் காட்டுகிறது: **"மூல நிகழ்வுகள் ↔ ஒன்றிணைக்கப்பட்டது"**.

### 4.3 உரையாடல் இயல்பாக்கி (`src/mitm/inspector/conversationNormalizer.ts`)

**சார்பற்ற clean-room செயலாக்கம்.** இயல்பாக்கம் உள்ளூர் black-box
ஒப்பந்தங்கள் மற்றும் பொதுவில் கிடைக்கும் OpenAI, Anthropic, Gemini செய்தித் திட்டவடிவங்களால் வரையறுக்கப்படுகிறது; எந்த upstream
செயலாக்கத்தின் மூலமும் பயன்படுத்தப்படவில்லை.

காட்சிப்படுத்துவதற்கு முன் OpenAI, Anthropic மற்றும் Gemini செய்தி வடிவங்களை ஒரே `NormalizedConversation`-ஆக மாற்றுகிறது:

```ts
interface NormalizedConversation {
  request: NormalizedTurn[]; // கோரிக்கை உள்ளடக்கத்திலிருந்து messages / contents / prompt
  response: NormalizedTurn[]; // உதவியாளர் பதில் (sseMerger வழியாக ஒன்றிணைக்கப்பட்டது)
  contextKey: string | null; // SHA-256 அமைப்பு-prompt கைரேகை
}
```

தொகுதி வகைகள்: `text`, `tool_use`, `tool_result`. வழங்குநர் எதுவாக இருந்தாலும் Conversation தாவல் இந்த அமைப்பைப் பயன்படுத்துகிறது.

### 4.4 சூழல் விசை வண்ணமயமாக்கல் (`src/mitm/inspector/contextKey.ts`)

- அமைப்பு prompt-இன் `SHA-256`-ஐக் கணக்கிடுகிறது (முதல் `role:system` செய்தி, அல்லது `system` புலம், அல்லது Gemini `systemInstruction`)
- 12-எழுத்து hex முன்னொட்டைத் திருப்பியளிக்கிறது (`"a3f9c2..."`)
- இடது-எல்லைப் பட்டைக்காக frontend, விசையை ஒரு நிர்ணயிக்கப்பட்ட HSL நிறத்துடன் பொருத்துகிறது
- **"அதே சூழல்" வடிகட்டி**: `ctx #a3f` chip-ஐக் கிளிக் செய்வது, அதே கைரேகையைக் கொண்ட கோரிக்கைகளை மட்டும் காட்ட ஒரு வடிகட்டியைச் சேர்க்கிறது

ஒரே முகவர் அமர்வில் இயங்கும் வெவ்வேறு "ஆளுமைகள்" அல்லது பணிகளைப் பார்வையால் எளிதில் வேறுபடுத்த இது உதவுகிறது.

### 4.5 LLM மெட்டாதரவு பிரித்தெடுத்தல்

LLM கோரிக்கைகளுக்கு, LLM Details தாவல் பின்வருவனவற்றைப் பிரித்தெடுக்கிறது:

```ts
interface LlmMetadata {
  provider: string | null; // "openai" | "anthropic" | "gemini" | ...
  apiKind: string | null; // "chat.completions" | "messages" | "embeddings" | ...
  model: string | null; // கோரிக்கை உள்ளடக்கம் அல்லது பதிலிலிருந்து
  messages: number; // சுற்றுகளின் எண்ணிக்கை
  tokensIn: number | null; // usage.prompt_tokens / usage.input_tokens
  tokensOut: number | null; // usage.completion_tokens / usage.output_tokens
  streamed: boolean; // SSE பதிலாக இருந்தால் true
  mappedTo: string | null; // x-omniroute-mapped தலைப்பு
  costEstimateUsd: number | null; // OmniRoute விலை நிர்ணயத்தின் அடிப்படையிலான மதிப்பிடப்பட்ட செலவு
}
```

### 4.6 செயலிலுள்ள கோரிக்கைகளுக்கான நேரடி வடிகட்டி

கோரிக்கையின் `status` புலம் `number | "in-flight" | "error"` ஆகும் — கோரிக்கை தொடங்கும் தருணத்திலேயே ஓர் பதிவு
`"in-flight"` எனச் சேர்க்கப்பட்டு, பதில் (அல்லது பிழை) வந்தவுடன் **அதே இடத்தில் புதுப்பிக்கப்படுகிறது**.
கருவிப்பட்டையின் **"நேரடி"** நிலைமாற்றி
(`liveOnly`, i18n விசை `trafficInspector.liveOnly`), பட்டியலை `status === "in-flight"` ஆக உள்ள பதிவுகளுக்கு
மட்டும் வரம்பிடுகிறது; இதனால் திறந்த இணைப்புகளை நிகழ்நேரத்தில் கண்காணிக்கலாம்.

இந்த வடிகட்டி,
`src/lib/inspector/matchesTrafficFilter.ts`-இல் உள்ள தூய client-side predicate ஆகும்:

```ts
if (f.liveOnly && req.status !== "in-flight") return false;
```

நிலைமாற்றியின் நிலை `useTrafficFilters`-இல் (inspector dashboard hooks) இருந்து,
மற்ற வடிகட்டிகளுடன் (profile, host, agent, source, status, context) இணைந்து செயல்படுகிறது.

### 4.7 செயல்முறை மூலத்தைக் கண்டறிதல் (Linux)

Linux-இல், இடைமறிக்கப்பட்ட ஒவ்வொரு கோரிக்கையையும் அதைத் **தொடங்கிய உள்ளூர்
செயல்முறையுடன்** தொடர்புபடுத்த முடியும். `InterceptedRequest`-இல் விருப்பத்திற்குரிய இரண்டு புலங்கள் சேர்க்கப்படுகின்றன:

```ts
pid?: number;          // தொடங்கிய செயல்முறையின் id (Linux மட்டும்)
processName?: string;  // தொடங்கிய செயல்முறையின் பெயர் (Linux மட்டும்)
```

`src/mitm/inspector/processAttribution.ts`, இணைப்பின் _client_
தற்காலிக port-ஐ PID + பெயருடன் பின்வருமாறு பொருத்துகிறது:

1. அந்த port-க்கான socket inode-ஐக் கண்டறிய `/proc/net/tcp` மற்றும் `/proc/net/tcp6`-ஐப்
   படிக்கிறது (`parseProcNetTcpForInode`, fixture மூலம் சோதிக்கக்கூடிய தூய parser).
2. `socket:[<inode>]`-க்கான symlink-ஐக் கண்டறிய `/proc/<pid>/fd/`-ஐ ஸ்கேன் செய்கிறது.
3. `/proc/<pid>/comm`-இலிருந்து செயல்முறையின் பெயரைப் படிக்கிறது.

1-வினாடி TTL cache, அதிக சுமையின் கீழ் procfs ஸ்கேன் செலவைக் கட்டுப்படுத்துகிறது. மூலத்தைக் கண்டறிதல்
**இயன்றவரை முயற்சிக்கப்படும்** — எந்தத் தோல்வியும் `null` ஆகத் தீர்க்கப்படும்; capture-ஐ ஒருபோதும் தடுக்காது.
macOS/Windows-இல் இந்தச் செயல்பாடு `null`-ஐத் திருப்பியளிக்கிறது (stub; `lsof`/`GetExtendedTcpTable`
ஆதரவு பின்னர் சேர்க்கப்பட வேண்டியது).

## §5 அமர்வுகள்

### 5.1 ஓர் அமர்வைப் பதிவுசெய்தல்

1. கருவிப்பட்டியில் உள்ள **"● அமர்வைப் பதிவுசெய்"** என்பதைக் கிளிக் செய்யவும் → ஒரு பெயரை உள்ளிடவும் (விருப்பத்தேர்வு)
2. நேரடி தொடர் வழக்கம்போலத் தொடரும்; சிவப்பு நிறத்தில் துடிக்கும் ஒரு காட்டி `◉ பதிவு · <name> · 00:42 · 23 கோரிக்கைகள்` எனக் காட்டும்
3. **"⏹ நிறுத்து"** என்பதைக் கிளிக் செய்யவும் → அமர்வின் நிலைப்படம் `inspector_sessions` + `inspector_session_requests` என்பவற்றில் சேமிக்கப்படும்

### 5.2 பதிவுசெய்யப்பட்ட அமர்வைப் பார்வையிடுதல்

கருவிப்பட்டியில் உள்ள **அமர்வுகள்** கீழ்தோன்றும் பட்டியல் சேமிக்கப்பட்ட அமர்வுகளைப் பட்டியலிடுகிறது. ஒன்றைத் தேர்ந்தெடுக்கும்போது:

- அமர்வின் நிலைப்படத்தை ஏற்றுகிறது (உறைந்த நிலை)
- ஒரு பதாகை இவ்வாறு காட்டும்: `பதிவுசெய்யப்பட்ட அமர்வு "<name>" பார்க்கப்படுகிறது — [நேரலைக்குத் திரும்பு]`
- Recharts திரட்டுகளுடன் புள்ளிவிவரங்கள் தாவல் கிடைக்கும்

### 5.3 ஏற்றுமதி வடிவங்கள்

ஒவ்வோர் அமர்வையும் பின்வரும் வடிவங்களில் ஏற்றுமதி செய்யலாம்:

| வடிவம்                     | பயன்பாடு                                                                                                       |
| -------------------------- | -------------------------------------------------------------------------------------------------------------- |
| **HAR** (HTTP Archive 1.2) | Chrome DevTools, Charles, Fiddler ஆகியவற்றுடன் இணக்கமானது — இணைப்பில்லாப் பகுப்பாய்வுக்காக இறக்குமதி செய்யலாம் |
| **JSONL**                  | ஒவ்வொரு வரியிலும் ஓர் `InterceptedRequest` — `llm-interceptor` வடிவத்துடன் இணக்கமானது                          |

`GET /api/tools/traffic-inspector/sessions/{id}/export.har` வழியாகவோ அல்லது அமர்வுகள் கீழ்தோன்றும் பட்டியலில் உள்ள ⬇ பொத்தான் வழியாகவோ ஏற்றுமதி செய்யவும்.

## §6 பாதுகாப்பு

Traffic Inspector, அங்கீகாரத் தலைப்புகள் மற்றும் கோரிக்கை உடல்கள் உட்பட, **இடைமறிக்கப்பட்ட அனைத்து HTTPS போக்குவரத்தையும்** காட்டுகிறது. பின்வரும் கட்டுப்பாடுகள் நடைமுறையில் உள்ளன:

| கட்டுப்பாடு                            | விவரங்கள்                                                                                                                                                                                                                           |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **LOCAL_ONLY**                         | எல்லா வழித்தடங்களும் WebSocket முனைப்புள்ளியும் உள்ளூர் சுழற்சிக்கு மட்டுமே உரியவை (அங்கீகாரத்திற்கு முன் `routeGuard.ts`-இல் அமல்படுத்தப்படுகிறது)                                                                                 |
| **ரகசிய மறைப்பு**                      | நேரியல் `maskSecret()` வருடி, RFC 6750 Bearer நற்சான்றுகள், வழங்குநர் முன்னொட்டுள்ள திறவுகோல்கள் மற்றும் நீண்ட தெளிவற்ற டோக்கன்களை `TrafficBuffer.push()`-க்கு முன் மறைக்கிறது                                                      |
| **உடல் அளவு வரம்பு**                   | `INSPECTOR_MAX_BODY_KB`-ஐ விடப் பெரிய உடல்கள் (இயல்புநிலை 1024 KB), `"(செயல்திறனுக்காகத் துண்டிக்கப்பட்டது)"` என்ற அறிவிப்புடன் துண்டிக்கப்படுகின்றன                                                                                |
| **தலைப்புத் தூய்மைப்படுத்தல்**         | பெயர்கள் சிற்றெழுத்துகளாக மாற்றப்படுகின்றன; சட்டகமாக்கல்/தாவலுக்கு-தாவல் மற்றும் பதிலி-அங்கீகாரத் தலைப்புகள் நீக்கப்படுகின்றன; குக்கீகள் முழுமையாக மறைக்கப்படுகின்றன; நற்சான்று மதிப்புகள் `maskSecret()`-க்கு ஒப்படைக்கப்படுகின்றன |
| **CSP**                                | செலுத்தப்பட்ட பதில் உடல்கள் வழியான XSS-ஐத் தடுக்க Traffic Inspector பக்கங்களில் கடுமையான Content Security Policy பயன்படுத்தப்படுகிறது                                                                                               |
| **இயல்புநிலையில் நிலைநிறுத்தம் இல்லை** | `TrafficBuffer` நினைவகத்தில் மட்டுமே இருக்கும்; சேவையகம் மறுதொடக்கம் செய்யப்படும்போது இழக்கப்படும். வெளிப்படையாகப் பதிவுசெய்யப்படும்போது மட்டுமே அமர்வுகள் நிலைநிறுத்தப்படுகின்றன                                                   |

### பயன்படுத்தப்படும் கடுமையான விதிகள்

| விதி                              | பயன்பாடு                                                                                              |
| --------------------------------- | ----------------------------------------------------------------------------------------------------- |
| **#12** `sanitizeErrorMessage`    | Traffic Inspector வழித்தடங்களிலிருந்து வரும் அனைத்து HTTP பிழைப் பதில்களும் தூய்மைப்படுத்தப்படுகின்றன |
| **#15 + #17** `isLocalOnlyPath()` | `/api/tools/traffic-inspector/` என்பது LOCAL_ONLY + SPAWN_CAPABLE (கணினிப் பதிலி கட்டளைகள்)           |

### அறியப்பட்ட வரம்புகள்

- **கணினி முழுவதுமான பதிலிப் பயன்முறை**, VPN கிளையன்ட்கள் மற்றும் SSO உட்பட, கணினியிலுள்ள அனைத்து பயன்பாடுகளையும் பாதிக்கிறது. தானாக முடக்கும் நேரங்காட்டியுடன் எப்போதும் பயன்படுத்தவும். பகிரப்பட்ட கணினிகளில் பயன்படுத்த வேண்டாம்.
- **CONNECT சுரங்க HTTPS**: TLS இடைமறிப்பு இயக்கப்பட்டிருக்காவிட்டால், பயன்முறை 3 (HTTP_PROXY) HTTPS இலக்குகளுக்கான சுரங்க மேனிலைத் தரவை மட்டுமே கைப்பற்றும். இது வடிவமைப்பின்படியானது — அந்தப் பயன்பாடுகள் AgentBridge சான்றிதழை நம்பாமல் இருக்கும்போது, வெளிப்படையான கைப்பற்றல் அவற்றின் TLS சரிபார்ப்பை முறிக்கும்.
- **சில கூறுகளில் நேரடியாகக் குறியிடப்பட்ட சரங்கள்**: சில UI கூறுகளில் (F7/F8), இன்னும் i18n திறவுகோல்களால் உள்ளடக்கப்படாத சிறிய எண்ணிக்கையிலான நேரடியாகக் குறியிடப்பட்ட சரங்கள் உள்ளன. இவை i18n இடைவெளி அறிக்கையில் அறியப்பட்ட வரம்பாக ஆவணப்படுத்தப்பட்டுள்ளன; தொடர்ச்சியான அடுத்த கட்டத்தில் இவை மாற்றப்படும். பாதிக்கப்பட்ட சரங்கள், செயல்பாட்டுப் பயன்பாட்டிற்கு மொழிபெயர்ப்பு தேவையில்லாத UI அலங்காரச் சிட்டைகள் ஆகும்.

## §7 சிக்கல் தீர்வு

### WebSocket இணைப்பு துண்டிப்பு

நேரலைப் பதிவில் "இணைப்பு துண்டிக்கப்பட்டது" எனக் காட்டப்பட்டால்:

1. சேவையகம் இன்னும் இயங்குகிறதா என்பதைச் சரிபார்க்கவும்: `GET /api/tools/traffic-inspector/capture-modes`
2. பக்கத்தை மீண்டும் ஏற்றவும் — WebSocket மீண்டும் இணைந்து புதிய snapshot-ஐப் பெறும்
3. சேவையகம் மறுதொடக்கம் செய்யப்பட்டிருந்தால், நினைவக buffer அழிக்கப்பட்டிருக்கும் — session ஒன்று பதிவு செய்யப்பட்டிருந்தால் தவிர, பழைய பதிவுகள் இழக்கப்பட்டிருக்கும்

### Port 8080 முரண்பாடு

HTTP_PROXY பயன்முறை தொடங்கத் தவறினால்:

```bash
lsof -i :8080    # செயல்முறையைக் கண்டறியவும்
```

Port-ஐ மாற்றவும்:

```bash
# .env
INSPECTOR_HTTP_PROXY_PORT=8888
```

### System proxy மீட்டமைக்கப்படவில்லை

கணினி முழுவதற்குமான proxy பயன்முறை செயலில் இருக்கும்போது OmniRoute செயலிழந்தால்:

**macOS:**

```bash
networksetup -setwebproxystate Wi-Fi off
networksetup -setsecurewebproxystate Wi-Fi off
```

**Linux (GNOME):**

```bash
gsettings set org.gnome.system.proxy mode 'none'
```

**Windows:**

```cmd
netsh winhttp reset proxy
```

அடுத்த முறை dashboard ஏற்றப்படும்போது, proxy செயலில் இருந்ததாக DB நிலை குறிப்பிடுவதை அது கண்டறிந்தால், "System proxy-ஐ மீட்டமை" என்ற விருப்பத்தையும் வழங்கும்.

### Buffer நிரம்பியுள்ளது

Buffer, `INSPECTOR_BUFFER_SIZE` அளவை (இயல்புநிலை 1000) அடையும்போது, புதிய பதிவுகள் மிகப் பழைய பதிவுகளை வெளியேற்றும். முக்கியமான கோரிக்கைகள் இழக்கப்பட்டால்:

- `INSPECTOR_BUFFER_SIZE` அளவை அதிகரிக்கவும் (எ.கா., 5000) — இது தக்கவைப்பை அதிகரிப்பதற்காக அதிக நினைவகத்தைப் பயன்படுத்தும்
- தொடர்புடைய காலச் சாளரத்தை DB-இல் நிலையாகச் சேமிக்க ஒரு session-ஐப் பதிவு செய்யவும்
