> **உண்மைக்கான ஆதாரம்:** `src/lib/skills/` மற்றும் `src/app/api/skills/`
> **கடைசியாகப் புதுப்பிக்கப்பட்டது:** 2026-06-28 — v3.8.40

OmniRoute, மொழி மாதிரிகளும் (மற்றும் இயக்குநர்களும்) மீண்டும் பயன்படுத்தக்கூடிய திறன்களை ஒருங்கிணைக்க உதவும் விரிவாக்கக்கூடிய Skills கட்டமைப்பை வழங்குகிறது — கோப்புமுறை வாசிப்புகள் மற்றும் HTTP கோரிக்கைகள் முதல் தனிமைப்படுத்தப்பட்ட குறியீடு இயக்கம் மற்றும் தேர்ந்தெடுக்கப்பட்ட marketplace skills வரை.

ஒரு skill என்பது பதிப்பிடப்பட்ட, schema-வால் வரையறுக்கப்பட்ட பணியின் அலகாகும். OmniRoute, வெளியே செல்லும் கோரிக்கைகளில் skills-ஐ tool வரையறைகளாகச் செலுத்தவும், மாதிரியிலிருந்து திரும்பி வரும் tool அழைப்புகளை இடைமறிக்கவும், பொருந்தும் handler-ஐ இயக்கவும், உரையாடல் தொடரும் வகையில் முடிவை மீண்டும் மாதிரிக்கு வழங்கவும் முடியும். மாதிரி ஒருபோதும் செயலாக்க விவரங்களைக் காணாது — அது tool இடைமுகத்தை மட்டுமே காணும்.

## Agent Skills மற்றும் Omni Skills

OmniRoute-இல் தனித்தனியான, ஆனால் ஒன்றுக்கொன்று துணைபுரியும் இரண்டு skill அமைப்புகள் உள்ளன:

| பரிமாணம்                 | **Omni Skills** (இந்த ஆவணம்)                                                      | **Agent Skills**                                                                            |
| :----------------------- | :-------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------ |
| நோக்கம்                  | LLM tool செலுத்தல் + தனிமைப்படுத்தப்பட்ட இயக்கம்                                  | வெளிப்புற agents கண்டறிந்து பயன்படுத்துவதற்கான SKILL.md பட்டியல்                            |
| உண்மைக்கான ஆதாரம்        | `src/lib/skills/` + marketplace                                                   | `src/lib/agentSkills/` + `skills/` அடைவு                                                    |
| இயக்கநேர முறை            | வெளியே செல்லும் கோரிக்கைகளில் செலுத்தப்பட்டு, tool-call நிகழ்வுகளில் இயக்கப்படும் | நிலையான markdown பட்டியல் + REST/MCP/A2A கண்டறிதல் முனைப்புள்ளிகள்                          |
| இதைப் பயன்படுத்துபவர்கள் | OmniRoute தானே (combo routing, உள்வரும் LLM அழைப்புகள்)                           | வெளிப்புற agents, MCP clients, A2A orchestrators                                            |
| எண்ணிக்கை                | மாறக்கூடியது (marketplace-ஆல் இயக்கப்படுகிறது)                                    | 45 பட்டியல் உள்ளீடுகள் (23 API + 21 CLI + 1 config)                                         |
| வடிவம்                   | tool schema + handler கொண்ட `SkillDefinition`                                     | `SKILL.md` frontmatter + markdown உள்ளடக்கம்                                                |
| கண்டறிதல்                | `/api/skills/*` REST + `omniroute_skills_*` MCP tools                             | `/api/agent-skills/*` REST + `omniroute_agent_skills_*` MCP tools + A2A `list-capabilities` |

**Omni Skills** என்பது இயக்க இயந்திரமாகும் — ஒரு LLM ஒரு tool-ஐ அழைக்கும்போது OmniRoute _என்ன செய்ய முடியும்_ என்பதை அவை வரையறுக்கின்றன.

**Agent Skills** என்பது ஆவணப் பட்டியலாகும் — agent prompts-இல் நேரடியாக வழங்கக்கூடிய கட்டமைக்கப்பட்ட SKILL.md கோப்புகளுடன், OmniRoute-இன் REST API மற்றும் CLI-ஐ _எவ்வாறு பயன்படுத்துவது_ என்பதை அவை வெளிப்புற agents-க்கு விளக்குகின்றன.

Agent Skills பட்டியல், generator, MCP tools மற்றும் A2A skill பற்றிய விவரங்களுக்கு, [docs/frameworks/AGENT-SKILLS.md](./AGENT-SKILLS.md)-ஐப் பார்க்கவும்.

## கருத்தாக்கங்கள்

### Skill மூலங்கள்

ஒரே registry-இல் மூன்று skill மூலங்கள் இணைந்து செயல்படுகின்றன:

1. **உள்ளமைக்கப்பட்ட skills** (`src/lib/skills/builtins.ts`) — OmniRoute உடன் வழங்கப்படுகின்றன. பொதுவான பயன்பாடுகளை உள்ளடக்குகின்றன:
   - `file_read`, `file_write` — `<DATA_DIR>/skills/workspaces/<hashed-key>/`-இன் கீழ் ஒவ்வொரு API key-க்கும் தனித்தனியான sandbox பணியிடம்
   - `http_request` — `guard: "public-only"` உடன் `safeOutboundFetch` வழியாக வெளிச்செல்லும் HTTP
   - `web_search` — caching உடன் மாற்றியமைக்கக்கூடிய தேடல் வழங்குநர் (`executeWebSearch`)
   - `eval_code` — Docker-இல் தனிமைப்படுத்தப்பட்ட `node` அல்லது `python` இயக்கம்
   - `execute_command` — Docker-இல் தனிமைப்படுத்தப்பட்ட shell command
   - `browser` — Playwright ஆதரவுடைய அடிப்படைக் கட்டமைப்பு, இயல்பாக முடக்கப்பட்டுள்ளது (`builtin/browser.ts`)
2. **SkillsMP** (OmniRoute Marketplace) — `https://skillsmp.com/api/v1/skills/search`-இலிருந்து பெறப்படுகிறது. Settings-இல் `skillsmpApiKey` தேவை.
3. **SkillsSH** (`skills.sh` சமூகப் பட்டியல்) — `https://skills.sh/api/search`-இலிருந்து பெறப்படுகிறது. அங்கீகாரம் தேவையில்லை; SKILL.md உள்ளடக்கம் GitHub raw-இலிருந்து பெறப்படுகிறது.

dashboard எந்தப் பட்டியலிலிருந்து நிறுவுகிறது என்பதை ஒற்றை "செயலில் உள்ள provider" கட்டுப்படுத்துகிறது (`src/lib/skills/providerSettings.ts`). **Settings → Memory & Skills** என்பதன் கீழ் அதை மாற்றவும். இயல்புநிலை: `skillsmp`.

### Skill அடையாளம்

நினைவக registry-இல் skills, `name@version` மூலம் திறவிடப்படுகின்றன (`src/lib/skills/registry.ts`). Version கட்டாயம் semver வடிவில் (`^\d+\.\d+\.\d+$`) இருக்க வேண்டும். `resolveVersion()`, `^`, `~`, `>`, `>=`, `<`, `<=`, `==` மற்றும் துல்லியப் பொருத்தக் கட்டுப்பாடுகளைப் புரிந்துகொள்கிறது.

### Skill முறை

ஒவ்வொரு skill-க்கும், அது எப்போது செலுத்தப்படும் என்பதைக் கட்டுப்படுத்தும் ஓர் இயக்கநேர முறை உள்ளது:

| முறை   | செயல்பாடு                                                                                                                |
| ------ | ------------------------------------------------------------------------------------------------------------------------ |
| `on`   | எப்போதும் tool வரையறையாகச் செலுத்தப்படும்                                                                                |
| `off`  | ஒருபோதும் செலுத்தப்படாது, ஒருபோதும் இயக்க முடியாது                                                                       |
| `auto` | உள்வரும் கோரிக்கைக்கு எதிராக மதிப்பிடப்படும்; மதிப்பெண் ≥ `AUTO_MIN_SCORE` (இயல்புநிலை 3) என்றால் மட்டுமே செலுத்தப்படும் |

marketplace-இலிருந்து நிறுவப்பட்ட skills-க்கு `auto` இயல்புநிலையாகும். `enabled=true` மற்றும் `mode="off"` ஆகியவை ஒன்றாக இருந்தால் "பதிவுசெய்யப்பட்டுள்ளது, ஆனால் செயலற்றது" என்று பொருள் — பழைய codepaths-உம் சீராக இருக்க, மரபுவழி column மூலம் `enabled`-ஐ மாற்றுவது `mode`-ஐயும் புதுப்பிக்கும் (`src/app/api/skills/[id]/route.ts`).

### நிலை (இயக்கங்கள்)

Skill இயக்கங்கள், பின்வரும் நிலைகளுடன் `skill_executions` அட்டவணையில் கண்காணிக்கப்படுகின்றன (`src/lib/skills/types.ts`):

```ts
enum SkillStatus {
  PENDING = "pending",
  RUNNING = "running",
  SUCCESS = "success",
  ERROR = "error",
  TIMEOUT = "timeout",
}
```

### Registry Cache

`SkillRegistry` என்பது 60-விநாடி TTL cache கொண்ட singleton ஆகும் (`registry.ts:14`). `loadFromDatabase()` idempotent ஆகும்; மேலும் `pendingLoad` மூலம் ஒரே நேரத்தில் நிகழும் அழைப்புகளில் உள்ள நகல்களை நீக்குகிறது. எந்தவொரு எழுதுதல் செயல்பாடும் (`register`/`unregister`/`unregisterById`) cache-ஐ செல்லாததாக்குகிறது. பதிப்புகளை `getSkillVersions(name)` மற்றும் `resolveVersion(name, constraint)` மூலம் தேடவும்.

### Provider-ஐ அறிந்த செலுத்தல்

`src/lib/skills/injection.ts`-இல் உள்ள `injectSkills()` என்பது பதிவுசெய்யப்பட்ட skills-ஐ provider-சார்ந்த tool வரையறைகளாக மாற்றும் நுழைவுப் புள்ளியாகும்:

- **OpenAI** — `{ type: "function", function: { name, description, parameters } }`
- **Anthropic** — `{ name, description, input_schema }`
- **Google (Gemini)** — `{ name, description, parameters }`

மாதிரி அதை மீண்டும் அழைக்கும்போது, கையாளி சரியான பதிப்பைத் தேர்ந்தெடுக்க ஏதுவாகக் கருவியின் பெயர் `name@version` எனக் குறியாக்கப்படுகிறது.

| சைகை                                                                             | புள்ளிகள்           |
| -------------------------------------------------------------------------------- | ------------------- |
| திறனின் பெயர் சூழலில் அப்படியே இடம்பெறுகிறது                                     | +6                  |
| பெயரின் ஒவ்வொரு சொற்கூறும் சூழலின் சொற்கூறுடன் பொருந்துகிறது                     | +2                  |
| ஒவ்வொரு குறிச்சொல் துணைச்சரமும் சூழலுடன் பொருந்துகிறது                           | +3                  |
| விளக்கத்தின் ஒவ்வொரு சொற்கூறும் சூழலுடன் பொருந்துகிறது                           | +1                  |
| பின்னணிக் காரணம் பெயரின் சொற்கூறுடன் பொருந்துகிறது                               | ஒரு சொற்கூறுக்கு +2 |
| பின்னணிக் காரணம் குறிச்சொல்லுடன் பொருந்துகிறது                                   | ஒரு சொற்கூறுக்கு +2 |
| குறிச்சொற்களில் உள்ள வழங்குநர் குறிப்பு, கோரிக்கையின் வழங்குநருடன் பொருந்துகிறது | +2 / −2             |

`score >= AUTO_MIN_SCORE = 3` கொண்ட முதல் `AUTO_MAX_SKILLS = 5` திறன்கள் உட்செலுத்தப்படுகின்றன. சமநிலைகள் முதலில் `installCount` (இறங்குவரிசை), பின்னர் அகரவரிசைப் பெயர் (`injection.ts:225-235`) ஆகியவற்றின் அடிப்படையில் தீர்க்கப்படுகின்றன.

### கருவி அழைப்பு இடைமறிப்பு

மேல்நிலைச் சேவை கருவி அழைப்பு பதிலை வழங்கிய பிறகு, அரட்டை கையாளியால் `src/lib/skills/interception.ts` இல் உள்ள `handleToolCallExecution()` அழைக்கப்படுகிறது:

1. `extractToolCalls()` வழங்குநருக்குரிய வடிவங்களைப் படிக்கிறது (OpenAI `tool_calls` / Responses `function_call`, Anthropic `tool_use`, Gemini `functionCalls`).
2. உள்ளமைந்த கருவி மாற்றுப்பெயர்கள் (எ.கா. `omniroute_web_search` → `web_search`) முதலில் தீர்க்கப்படுகின்றன. உள்ளமைந்த கையாளிகள் அதே இடத்தில் இயங்குகின்றன.
3. மற்ற அனைத்தும் `skillExecutor.execute(name@version, args, { apiKeyId, sessionId })` வழியாக அனுப்பப்படுகின்றன.
4. முடிவுகள் பொருத்தமான வகையில் பதிலுக்குள் மீண்டும் இணைக்கப்படுகின்றன — `tool_results`, `function_call_output` உருப்படிகள் அல்லது Anthropic `tool_result` தொகுதிகள்.

பயனர் வரையறுத்த கையாளிகளை வெளிப்படையாக முடக்கும் கோரிக்கைப் பாதைகளில் பயன்படுத்தப்படுவது போல, உள்ளமைந்த இடைமறிப்பை மட்டும் அனுமதிக்கச் செயலாக்கச் சூழலில் உள்ள `customSkillExecutionEnabled` என்பதை `false` ஆக அமைக்கலாம்.

## Docker சாண்ட்பாக்ஸ்

உள்ளமைக்கப்படாத குறியீட்டுப் பாதைகள் (`eval_code`, `execute_command`) `SandboxRunner` (`src/lib/skills/sandbox.ts`) வழியாக Docker-க்குள் இயங்குகின்றன. ஒவ்வொரு கண்டெய்னரும் பின்வரும் அமைப்புகளுடன் தொடங்கப்படுகிறது:

```
--rm --network none|bridge --cap-drop ALL
--security-opt no-new-privileges --pids-limit 100
--cpus <cpuLimit/1000> --memory <memoryLimit>m
--tmpfs /tmp:rw,noexec,nosuid,size=64m
--tmpfs /workspace:rw,noexec,nosuid,size=64m
--read-only (readOnly=true ஆக இருக்கும்போது)
```

இயல்புநிலைகள் (`SandboxRunner.DEFAULT_CONFIG`):

| புலம்            | இயல்புநிலை      | குறிப்புகள்                                                          |
| ---------------- | --------------- | -------------------------------------------------------------------- |
| `cpuLimit`       | 100 (= 0.1 CPU) | `--cpus`-க்கு அனுப்புவதற்கு முன் 1000-ஆல் வகுக்கப்படுகிறது           |
| `memoryLimit`    | 256 MB          | கடின வரம்பு                                                          |
| `timeout`        | 30000 ms        | `SIGTERM` + `docker kill` வழியான மென்மையான நிறுத்தம்                 |
| `networkEnabled` | `false`         | `--network none` ஆகிறது                                              |
| `readOnly`       | `true`          | மூல FS வாசிப்புக்கு மட்டும்; `/tmp` மற்றும் `/workspace` tmpfs ஆகும் |

நிறுத்துவதற்காக `SandboxRunner.kill(id)` மற்றும் `killAll()` வெளிப்படுத்தப்பட்டுள்ளன; இயங்கும் கண்டெய்னர்கள் `runningContainers: Map<string, ChildProcess>`-இல் கண்காணிக்கப்படுகின்றன.

### சாண்ட்பாக்ஸ் சூழல் மாறிகள்

`src/lib/skills/builtins.ts`-இல் `process.env` வழியாக உள்ளமைக்கப்படுகின்றன:

| சூழல் மாறி                        | இயல்புநிலை       | நோக்கம்                                                                                                                  |
| --------------------------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `SKILLS_MAX_FILE_BYTES`           | `1048576` (1 MB) | `file_read` மற்றும் `file_write`-க்கான வரம்பு                                                                            |
| `SKILLS_MAX_HTTP_RESPONSE_BYTES`  | `256000`         | `http_request` பதில் உடலுக்கான வரம்பு                                                                                    |
| `SKILLS_MAX_SANDBOX_OUTPUT_CHARS` | `100000`         | அழைப்பவருக்குத் திருப்பப்படும் stdout/stderr-க்கான வரம்பு                                                                |
| `SKILLS_SANDBOX_TIMEOUT_MS`       | `10000`          | சாண்ட்பாக்ஸ் கட்டளைகளுக்கான இயல்புநிலை நேர வரம்பு; அதிகபட்சம் 60 s                                                       |
| `SKILLS_SANDBOX_NETWORK_ENABLED`  | `false`          | வெளியேறும் போக்குவரத்துக்கான முதன்மைத் தடை. ஒவ்வொரு அழைப்பிலும் தேர்ந்தெடுத்து அனுமதிக்க `1` அல்லது `true` என அமைக்கவும் |
| `SKILLS_ALLOWED_SANDBOX_IMAGES`   | (கீழே காண்க)     | காற்புள்ளியால் பிரிக்கப்பட்ட அனுமதிக்கப்பட்ட Docker படங்களின் பட்டியல்                                                   |

இயல்பாக அனுமதிக்கப்பட்ட படங்கள்: `alpine:3.20`, `node:22-alpine`, `python:3.12-alpine`. `SKILLS_ALLOWED_SANDBOX_IMAGES` வழியாகச் சேர்க்கப்படும் படங்கள் இயல்புநிலைப் பட்டியலுடன் ஒன்றிணைக்கப்படுகின்றன; அறியப்படாத படங்கள் `normalizeImage()` மூலம் நிராகரிக்கப்படுகின்றன.

> குறிப்பு: தனியான `SKILLS_EXECUTION_TIMEOUT_MS` சூழல் மாறி இல்லை. சாண்ட்பாக்ஸ் அல்லாத கையாளியின் நேர வரம்பு `SkillExecutor`-இல் (`executor.ts:13`) 30 s என நேரடியாகக் குறியிடப்பட்டுள்ளது; ஆனால் இயக்க நேரத்தில் `skillExecutor.setTimeout(ms)` வழியாக அதை மாற்றலாம்.

### பணியிடத் தனிமைப்படுத்தல்

`file_read` மற்றும் `file_write` ஒவ்வொரு பாதையையும் `<DATA_DIR>/skills/workspaces/<sha256(apiKeyId).slice(0,24)>/`-இல் உள்ள, ஒவ்வொரு API விசைக்கும் தனிப்பட்ட பணியிடத்தைச் சார்ந்ததாகத் தீர்மானிக்கின்றன. எந்தவொரு வட்டு I/O-க்கும் முன், பாதை ஊடுருவல் (`..`) மற்றும் தடைசெய்யப்பட்ட பகுதிகள் (`.env`, `.git`, `.ssh`, `.omniroute`, `.codex`, `secrets`) நிராகரிக்கப்படுகின்றன.

### HTTP பாதுகாப்பு வலுப்படுத்தல்

`http_request` (`builtins.ts:257`):

- அனுமதிக்கப்பட்ட முறைப் பட்டியல்: `GET, HEAD, POST, PUT, PATCH, DELETE`
- தடுக்கப்பட்ட வெளிச்செல்லும் தலைப்புகள்: `host, connection, content-length, cookie, set-cookie, authorization, proxy-authorization`
- திசைமாற்றங்கள் முடக்கப்பட்டுள்ளன (`allowRedirect: false`)
- `guard: "public-only"` உடன் `safeOutboundFetch` வழியாக அனுப்பப்படுகிறது (தனிப்பட்ட/லூப்பேக் வரம்புகள் தடுக்கப்படுகின்றன)
- பதில் `SKILLS_MAX_HTTP_RESPONSE_BYTES` அளவில் துண்டிக்கப்படுகிறது; கிளையன்ட் `truncated: true` என்பதைக் காண்கிறது

## கலப்பு செயலாக்கி (முன்னோட்டம்)

`src/lib/skills/hybrid.ts`, ஒவ்வொரு அழைப்பிற்கும் `direct` (செயல்முறைக்குள்) மற்றும் `sandbox` செயலாக்கத்திற்கு இடையே முடிவெடுக்கும் ஒரு `HybridExecutor`-ஐ வரையறுக்கிறது; காலக்கெடு/நினைவகப் பிழைகள் ஏற்பட்டால் `autoUpgrade` மறுமுயற்சிப் பாதையையும் கொண்டுள்ளது. இணைக்கப்பட்டுள்ள `directExecutor` / `sandboxRunner` செயலாக்கங்கள் தற்காலிக நிரப்பு அமைப்புகள் (`executeDirect`, `executeInSandbox` ஆகியவை தற்காலிக நிரப்பு பொருட்களைத் திருப்பியளிக்கின்றன) — இந்தத் தொகுதியை உருவாக்கப்பட்டுக் கொண்டிருக்கும் ஓர் ஒப்பந்தமாகக் கருதவும். உண்மையான செயலாக்கம் இன்னமும் `skillExecutor` + `SandboxRunner` வழியாகவே நடைபெறுகிறது.

## REST API

அனைத்து முனைப்புள்ளிகளும் `src/app/api/skills/`-இன் கீழ் உள்ளன. மேலாண்மை முனைப்புள்ளிகளுக்கு (`/api/skills`, `/api/skills/[id]`, `/api/skills/install`) `requireManagementAuth()` வழியான **மேலாண்மை அங்கீகாரம்** தேவை. சந்தை/நிறுவல் செயலோட்டங்கள் எளிய `isAuthenticated()`-ஐப் பயன்படுத்துகின்றன (அமர்வு அல்லது API விசை).

| முனைப்புள்ளி | முறை | நோக்கம் |
| --------------------------------- | ------ | ------------------------------------------------------------------------ | --- | ------------------------ | -------- | ------------------ |

```bash
  }'
```

`handlerCode` சரம் என்பது **கையாளுநர் பெயரைக் கண்டறியும் தேடல்** — செயலாக்கக்கூடிய குறியீடு அல்ல. செயலாக்கி அதை `skillExecutor.registerHandler(name, fn)` மூலம் பொருத்துகிறது (`executor.ts:25`). சந்தை நிறுவல்கள் SKILL.md உரையை இந்தப் புலத்தில் ஆவணமாகச் சேமித்து, மாதிரியால் உருவாக்கப்பட்ட கருவி அழைப்புகள் வழியாகச் செயலாக்கத்தை வழிநடத்துகின்றன. பயனரால் தன்னிச்சையாக வழங்கப்பட்ட மூலக் குறியீடு eval செய்யப்படுவதில்லை.

- **குறிப்பிட்ட படிமங்களை அனுமதிக்கவும்:** அனுமதிப்பட்டியலை நீட்டிக்க `SKILLS_ALLOWED_SANDBOX_IMAGES="myorg/sandbox:1.0,node:22-alpine"`-ஐ அமைக்கவும்.

## செயல்படுத்தல் வாழ்க்கைச் சுழற்சி (v3.8.16+)

`SkillExecutor` (`src/lib/skills/executor.ts`) என்பது ஒவ்வொரு திறன் அழைப்பையும் நிர்வகிக்கும் ஒரு **singleton** ஆகும். காலக்கெடுக்கள், மறுமுயற்சிகள் மற்றும் செயல்படுத்தல் நிலையைப் பிழைத்திருத்தம் செய்வதற்கு அதன் வாழ்க்கைச் சுழற்சியைப் புரிந்துகொள்வது மிகவும் முக்கியம்.

### 5-கட்ட வாழ்க்கைச் சுழற்சி

```
   execute() அழைக்கப்பட்டது
        │
        ▼
  ┌─────────────┐
  │  PENDING    │  ← வரிசையில் உள்ளது, இன்னும் தொடங்கவில்லை (DB வரிசை உருவாக்கப்பட்டது)
  └──────┬──────┘
         │ handler-ஐத் தொடங்கு
         ▼
  ┌─────────────┐
  │  RUNNING    │  ← காலக்கெடுவுடன் handler அழைக்கப்பட்டது
  └──────┬──────┘
         │
    ┌────┴────┬──────────┬──────────┐
    │         │          │          │
    ▼         ▼          ▼          ▼
  SUCCESS   ERROR     TIMEOUT   (வேறு பாதை இல்லை — parent-ஆல் நிறுத்தப்பட்டது)
    │         │          │
    └────┬────┴──────────┘
         │
         ▼
   நிலை, வெளியீடு, durationMs ஆகியவற்றுடன் DB வரிசை புதுப்பிக்கப்பட்டது
```

### இயல்புநிலை உள்ளமைவு

| அமைப்பு      | இயல்புநிலை     | இதன் மூலம் உள்ளமைக்கலாம்             |
| ------------ | -------------- | ------------------------------------ |
| `timeout`    | `30000` (30வி) | `skillExecutor.setTimeout(ms)`       |
| `maxRetries` | `3`            | `skillExecutor.setMaxRetries(count)` |

> **முக்கியம்**: executor ஒரு singleton ஆகும் — `setTimeout()`-ஐ அழைப்பது அதற்குப் பிறகான அனைத்து அழைப்புகளையும் உலகளவில் பாதிக்கும். ஒவ்வொரு திறனுக்குமான தனித்தனி காலக்கெடுக்கள் தற்போது ஆதரிக்கப்படவில்லை; ஒவ்வொரு திறனுக்கும் வெவ்வேறு காலக்கெடுக்கள் தேவைப்பட்டால், தனித்தனி செயல்முறைகளைச் சமர்ப்பிக்கவும் அல்லது executor-ஐ fork செய்யவும்.

### நிலை மதிப்புகள்

`src/lib/skills/types.ts`-இலிருந்து:

```ts
enum SkillStatus {
  PENDING = "pending", // வரிசையில் உள்ளது, இன்னும் தொடங்கவில்லை
  RUNNING = "running", // Handler அழைக்கப்பட்டது
  SUCCESS = "success", // Handler செல்லுபடியாகும் வெளியீட்டைத் திருப்பியது
  ERROR = "error", // Handler ஒரு விதிவிலக்கை எறிந்தது
  TIMEOUT = "timeout", // Executor-இன் காலக்கெடுவை மீறியது
}
```

> **குறிப்பு**: `TIMEOUT` நிலை enum-இல் வரையறுக்கப்பட்டுள்ளது, ஆனால் தற்போதைய executor செயலாக்கத்தால் அது **உண்மையில் DB-இல் எழுதப்படுவதில்லை** — காலக்கெடுக்கள் `"Skill execution timed out"` என்ற செய்தியுடன் `ERROR` ஆக வெளிப்படுகின்றன. இந்த நிலை enum எதிர்காலப் பயன்பாட்டிற்காக ஒதுக்கப்பட்டுள்ளது.

### செயல்படுத்தல்களை ஆய்வு செய்தல்

```ts
import { skillExecutor } from "omniroute/skills/executor";

// ID மூலம் ஒரு குறிப்பிட்ட செயல்படுத்தலைப் பெறவும்
const exec = skillExecutor.getExecution("exec-uuid-123");
if (exec) {
  console.log(`${exec.skillName}: ${exec.status} in ${exec.durationMs}ms`);
}

// API key-க்கான அண்மைய செயல்படுத்தல்களைப் பட்டியலிடவும்
const recent = skillExecutor.listExecutions("api-key-id", 50, 0);
for (const e of recent) {
  console.log(`${e.skillName} → ${e.status} (${e.durationMs}ms)`);
}

// மொத்த செயல்படுத்தல்களை எண்ணவும்
const total = skillExecutor.countExecutions("api-key-id");
```

### மறுமுயற்சி நடத்தை

`maxRetries` அமைப்பு சேமிக்கப்படுகிறது, ஆனால் executor-இன் `execute()` method-ஆல் **தற்போது பயன்படுத்தப்படவில்லை** — அது ஒரே ஒரு முயற்சியை மட்டுமே மேற்கொள்கிறது. `maxRetries` மதிப்பு எதிர்காலச் செயலாக்கத்திற்காகவும், அதைப் படிக்க விரும்பும் hooks-க்காகவும் வெளிப்படுத்தப்பட்டுள்ளது.

தற்போதைக்கு, மறுமுயற்சிகள் skill handler-க்குள்ளேயே செயல்படுத்தப்பட வேண்டும். உள்ளமைந்த
திறன்கள் executor-உடன் பதிவுசெய்யப்படுகின்றன (எ.கா. `registerBuiltinSkills(executor)`
/ `src/lib/skills/builtin/`-இல் உள்ள `registerBrowserSkill(executor)`); நீங்கள் பதிவு செய்யும் எந்த handler-உம்
அதன் சொந்த மறுமுயற்சி loop-ஐச் சுற்றிக்கொள்ளலாம்:

```ts
// ஒரு skill handler-க்குள்
async function handler(input, ctx) {
  const maxRetries = 3;
  let lastError: Error | null = null;

  for (let attempt = 1; attempt <= maxRetries; attempt++) {
    try {
      return await fetchSomething(input);
    } catch (err) {
      lastError = err as Error;
      if (attempt < maxRetries) {
        await new Promise((r) => setTimeout(r, 1000 * attempt));
      }
    }
  }
  throw lastError;
}
```

```ts
enum SkillMode {

  MANUAL = "manual", // பயனரின் வெளிப்படையான கோரிக்கையால் மட்டுமே செயல்படுத்தப்படும்
  HYBRID = "hybrid", // AUTO மதிப்பீடு + கைமுறை மேலெழுதுதல்
}
```

> **குறிப்பு**: கோட்பேஸ் `SkillMode`-ஐ (AUTO/MANUAL/HYBRID) வரையறுக்கிறது; ஆனால் `Skill.mode` புலம் வேறுபட்ட வடிவமைப்பைப் (`"on" | "off" | "auto"`) பயன்படுத்துகிறது. அவை தொடர்புடையவை, ஆனால் ஒரே மாதிரியானவை அல்ல — `SkillMode` என்பது செயல்படுத்தல் கொள்கைக்கானது; `Skill.mode` என்பது ஒவ்வொரு திறனையும் இயக்குவதற்கானது.

### ஒவ்வொரு முறையையும் எப்போது பயன்படுத்த வேண்டும்

| முறை     | LLM நடத்தை                                                                                      | பயன்பாட்டு நிலை                                                       |
| -------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `AUTO`   | தேவையெனக் கருதும்போது LLM திறனை அழைக்கலாம்                                                      | பொதுப் பயன்பாட்டுத் திறன்கள் (கோப்புகளைப் படித்தல், HTTP கோரிக்கைகள்) |
| `MANUAL` | LLM திறனை அழைக்க முடியாது; வெளிப்படையான `executeSkill` API அழைப்பு மட்டுமே அதைச் செயல்படுத்தும் | உணர்திறன் மிக்க செயல்பாடுகள் (தரவுத்தள எழுதல்கள், பணம் செலுத்தல்கள்)  |
| `HYBRID` | LLM திறனைப் பரிந்துரைக்கலாம்; பயனர் உறுதிப்படுத்த வேண்டும்                                      | பக்க விளைவுகளைக் கொண்டிருந்தாலும் ஆபத்தானவையாக இல்லாத திறன்கள்        |

### AUTO மதிப்பீடு

`AUTO` முறை செயலில் இருக்கும்போது, ஒவ்வொரு பரிசீலனைத் திறனும் கோரிக்கைச் சூழலுடன் ஒப்பிட்டு
`src/lib/skills/injection.ts`-இல் உள்ள `scoreAutoSkill()` மூலம் மதிப்பிடப்படுகிறது — இது ஒரு கூட்டல்
முழு எண் புள்ளி அமைப்பாகும் (திறன்-பெயர் பொருத்தம், பெயர்/குறிச்சொல்/விளக்கச் சொற்கூறு ஒற்றுமை,
பின்னணி-காரணக் குறிப்புகள், வழங்குநர்-குறிப்பு கூடுதல் புள்ளி/அபராதம்). `score >= AUTO_MIN_SCORE = 3`
கொண்ட முதல் `AUTO_MAX_SKILLS = 5` திறன்கள் அழைக்கக்கூடிய கருவிகளாகச் சேர்க்கப்படுகின்றன;
சமநிலைகள் முதலில் `installCount` மூலமும், பின்னர் பெயர் மூலமும் தீர்க்கப்படுகின்றன. முழுமையான புள்ளி அட்டவணைக்கு,
இந்த ஆவணத்தில் முன்னர் உள்ள [**கருவி ஸ்கீமா உருவாக்கம் → AUTO மதிப்பீடு**](#auto-scoring)
பகுதியைப் பார்க்கவும்; float `0.6`-பாணி வரம்பு எதுவும் இல்லை, மேலும் `registry.ts` மதிப்பீடும் இல்லை.

## உள்ளமைக்கப்பட்ட திறன்களின் பட்டியல்

OmniRoute, `src/lib/skills/builtin/`-இல் தேர்ந்தெடுக்கப்பட்ட உள்ளமைக்கப்பட்ட திறன்களின் தொகுப்புடன் வழங்கப்படுகிறது. மிகவும் பொதுவானவை:

### உலாவி தானியக்கமாக்கல் திறன்

உலாவித் திறன் (`src/lib/skills/builtin/browser.ts`), Playwright/Puppeteer வழியாகத் திரையற்ற உலாவி தானியக்கமாக்கலை வழங்குகிறது. **இது செயல்படுத்தப்பட்டுள்ளது, ஆனால் இயல்புநிலை திறன்களின் பட்டியலில் இல்லை** — இதைப் பயன்படுத்த, உலாவி நீட்டிப்பு செருகுநிரலைத் தனியாக நிறுவவும்.

```ts
// உங்கள் உள்ளமைவில் இயக்கவும்
const config: SkillConfig = {
  enabled: true,
  mode: SkillMode.MANUAL, // எப்போதும் வெளிப்படையான செயல்படுத்தலைக் கோரவும்
  allowedSkills: ["browser"],
  timeout: 60000, // பக்க ஏற்றங்களுக்கு 60 வினாடிகள்
  maxRetries: 1,
};
```

### பிற உள்ளமைக்கப்பட்ட வகைகள்

| வகை                    | திறன்கள்                                                  | முறை   |
| ---------------------- | --------------------------------------------------------- | ------ |
| கோப்பு I/O             | `file_read`, `file_write`                                 | AUTO   |
| HTTP                   | `http_request`                                            | AUTO   |
| தேடல்                  | `web_search`                                              | AUTO   |
| குறியீடு செயல்படுத்தல் | `eval_code` (தனிமைப்படுத்தப்பட்ட JavaScript/Python)       | HYBRID |
| அமைப்பு                | `execute_command` (தனிமைப்படுத்தப்பட்ட CLI செயல்படுத்தல்) | MANUAL |

### தனிப்பயன் திறனைச் சேர்த்தல்

செருகுநிரல் அமைப்பு வழியாகத் தனிப்பயன் திறனை எவ்வாறு சேர்ப்பது என்பதை அறிய [செருகுநிரல் SDK மற்றும் திறன்கள் ஒருங்கிணைப்பு](./PLUGIN_SDK.md) பகுதியைப் பார்க்கவும்.
