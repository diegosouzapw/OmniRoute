1. ஏற்கனவே உள்ள ஒற்றை-விசை semaphore ஒப்பந்தத்தையும் புதிய அணுவியல் பல-விசை
   ஒப்பந்தத்தையும் கவனம் செலுத்தப்பட்ட சோதனைகள் மூலம் உறுதிப்படுத்தவும்: பகுதியளவு முன்பதிவுகள் இல்லை, FIFO வரிசைப்படுத்தல், இடைநிறுத்தம்,
   காலக்கெடு, வரிசை-நிரம்பியது, பலமுறை அழைத்தாலும் ஒரே விளைவைத் தரும் விடுவிப்பு, புள்ளிவிவரங்கள் மற்றும் தூய்மைப்படுத்தல்.
2. ஏற்கனவே உள்ள கணக்கு semaphore-ஐ அதே இடத்தில் பொதுமைப்படுத்தவும். `acquire()`-ஐ
   `acquireMany()`-ஐச் சுற்றியுள்ள பின்னோக்கிய இணக்கத்தன்மை wrapper-ஆக வைத்திருக்கவும்; இரண்டாவது scheduler-ஐயோ
   dependency-ஐயோ சேர்க்க வேண்டாம்.
3. `chatCore`-இல் உள்ள கணக்குக்கு மட்டும் உரிய பெறுதலை, `withRateLimit`-க்கு உடனடியாக முன்பு செய்யப்படும் ஒருங்கிணைந்த
   global/provider/account பெறுதலால் மாற்றவும்.
   கணக்கு சுழற்சி இணைப்பை மாற்றும் ஒவ்வொரு முறையும் முழுத் தொகுப்பையும் மீண்டும் பெறவும்,
   மேலும் streaming நிறைவடையும் வரை விடுவிப்பைத் தக்கவைக்கவும்.
4. ஏற்கனவே உள்ள resilience அமைப்புகள் pipeline-ஐ (வகைகள், இயல்புநிலைகள்,
   normalization, schema, API பதில், UI மற்றும் மொழிபெயர்ப்புகள்) global
   மற்றும் provider உச்சவரம்புகளுடன் விரிவுபடுத்தவும். பழைய Bottleneck concurrency கட்டுப்பாட்டை
   connection/quota-scope concurrency என மறுபெயரிட்டு, அதன் உண்மையான வரம்பை வெளிப்படையாக்கவும்.
5. கவனம் செலுத்தப்பட்ட சோதனைகள், lint, typecheck, நிலையான சோதனைகள் மற்றும் முழு சோதனைத் தொகுப்பை இயக்கவும்;
   நடத்தை மாற்றத்தை changelog-இல் ஆவணப்படுத்தவும்.

வேண்டுமென்றே மாற்றமின்றி பாதுகாக்கப்படும் நடத்தை: பூஜ்ஜியம்/null concurrency ஒரு gate-ஐத் தவிர்க்கும்,
கணக்குக்கு மட்டும் உரிய அழைப்பாளர்கள் தொடர்ந்து `acquire()`-ஐப் பயன்படுத்துவர், தடுக்கப்பட்ட-கணக்கு கட்டுப்பாடுகள்
தங்களின் விசை வடிவத்தையும் API-ஐயும் தக்கவைத்துக்கொள்ளும், மேலும் provider rate-limit வரிசை நடத்தை
மாற்றமின்றி இருக்கும்.
