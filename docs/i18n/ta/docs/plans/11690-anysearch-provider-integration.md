வார்ப்புரு: xquik #11370 (release/v3.8.51-இல் ஒன்றிணைக்கப்பட்டது). நிலைப்பாடு: `fallbackOnly`.
மேல்நிலை முன்மொழிவு: issue diegosouzapw/OmniRoute#11637.

## 1. சேவையின் உறுதிப்படுத்தப்பட்ட உண்மை நிலை (அதிகாரப்பூர்வ ஆவணங்கள், குறுக்குச் சரிபார்க்கப்பட்டது)

- அடிப்படை URL: `https://api.anysearch.com` (REST) + `POST /mcp` (MCP, JSON-RPC 2.0).
- `POST /v1/search` - அளவுருக்கள்: `query` (கட்டாயம்), `max_results` (1-10, இயல்புநிலை 10), `tag` (`{domain}.{sub_domain}` செங்குத்து வழிச்செலுத்தல்), `zone` (cn/intl), `language`, `params` (கட்டமைக்கப்பட்ட செங்குத்துப் புலங்கள்), `format` (json/markdown).
- `GET /v1/sub-domains?domain=...` - திறன்களின் பட்டியல், ஒதுக்கீட்டில் கணக்கிடப்படாது.
- `POST /v1/extract` - `{url, title, content}`-ஐப் பெறுகிறது/பிரித்தெடுக்கிறது; கண்டிப்பான JSON கோரிக்கை உடல், 16 KiB வரம்பு.
- `POST /v1/auth/email/register` - ஒற்றை அழைப்புப் பதிவு, ஒருமுறை மட்டுமே காட்டப்படும் எளிய உரை விசையான `as_sk_...`-ஐ வழங்குகிறது.
- அங்கீகாரம்: விருப்பத்திற்குரிய `Authorization: Bearer <as_sk_...>`; பெயரில்லா அணுகல், தினசரி இலவச ஒதுக்கீட்டைப் பயன்படுத்தும் IP-அடிப்படையிலான வரம்புகளுக்குத் தரம் குறைக்கப்படும்; தவறான விசை 401/403-ஐ வழங்கும், அமைதியான பெயரில்லா மாற்றுவழி எதுவும் இல்லை.
- இலவச அடுக்கு: நாளொன்றுக்கு 1000 கோரிக்கைகள், ஒரு விசைக்கு 20 QPS. கட்டண அடுக்கு: விலை நிர்ணயிக்கப்படவில்லை (விரைவில் வருகிறது).
- பதில் உறை: வெற்றி `{code: 0, message: "success", request_id, data}`; தோல்வி `{code: -1, message}`. அங்கீகார/ஒதுக்கீட்டுப் பிழைகளில் கட்டமைக்கப்பட்ட `error_code` இல்லை (செய்தி உரையே குறிகாட்டி); பிரித்தெடுப்புக்கே உரிய பிழைகளில் `error_code` இருக்கும் (`invalid_extract_url`, `extract_failed`). 429-இல் `Retry-After` தலைப்பு இல்லை.

## 3. முடிவுகள் (அனைத்தும் 2026-08-26 அன்று எடுக்கப்பட்டவை)

1. **ரூட்டிங் நிலைப்பாடு: `fallbackOnly`.** காரணம்: கட்டணம் 0 கொண்ட இலவச வழங்குநர், தானியக்கச் செலவு அடிப்படையிலான ரூட்டிங்கில் ஒருபோதும் ஆதிக்கம் செலுத்தக்கூடாது; வெளிப்படையான தேர்வும் தோல்விக்குப் பிந்தைய திரும்புதலும் பாதிக்கப்படாது. முன்னுதாரணம்: ஒன்றிணைக்கப்பட்ட xquik பதிவு.
2. **செயல்பாட்டு வரம்பு: v1-இல் `POST /v1/extract` வழியாக webSearch + webFetch.** இது tavily/exa-வின் இரட்டைத் திறன் மன மாதிரியுடன் ஒத்துப்போகிறது. செங்குத்து சார்ந்த வசதிகள் (`tag`, `sub-domains`, `batch_search`) செயல்பாட்டு வரம்பிற்கு வெளியேயே இருக்கும் — செங்குத்து அளவுருக்களுக்கான IR தற்போது இல்லை.
3. **ஒதுக்கீட்டுக் காட்சி: `freeMonthlyQuota: 0`** (xquik பாணியிலான எச்சரிக்கையான காட்சி). உண்மையான அனுமதி வரம்பு (ஒரு நாளுக்கு 1000 கோரிக்கைகள், தினசரி மீட்டமைப்பு) அதற்குப் பதிலாக UI பட்டியலின் `authHint` உரையில் குறிப்பிடப்படுகிறது. காரணம்: ஒதுக்கீட்டுக் காட்சி, மீட்டமைப்பு நடைமுறையுடன் பொருந்த வேண்டும்; தினசரி உச்சவரம்பை மாதாந்திர நிகராக (30000) மாற்றுவது, UI-ஆல் நிறைவேற்ற முடியாத தவறான வாக்குறுதியாகும்.
4. **searchTypes: `["web"]` மட்டும்.** AnySearch API-இல் செய்திகள்/படங்களுக்கான தனிப் பிரிவு இருப்பதற்கான பொது ஆதாரம் இல்லை; ஆவணப்படுத்தப்பட்ட தனிப் பிரிவு இல்லாத API-களை ஒருங்கிணைக்கும் நுழைவாயில்கள் (எ.கா. Google Custom Search), news -> web என்று மறைமுகமாக மேப்பிங் செய்வதற்குப் பதிலாக web-ஐ மட்டும் வெளிப்படுத்துகின்றன.
5. **விசை நிலைப்பாடு:** விசை இல்லாமலும் செயல்படும்; தவறான விசை 401/403-ஐத் திருப்பியளிக்கும், மேலும் அது ஒருபோதும் மறைமுகமாக அநாமதேய அணுகலாகத் தரமிறக்கப்படாது (மேல்நிலை ஒப்பந்தத்தைப் பிரதிபலிக்கிறது).
6. **திட்டமிட்ட விலக்குகள்:** `FETCH_BACKEND_TO_PROVIDER` / `FetchInterceptionBackend` (அரட்டை இடைமறிப்பு firecrawl/jina/tavily-லேயே தொடரும்); `ANONYMOUS_CAPABLE_WEB_FETCH_PROVIDERS` (அநாமதேய தொலைநிலை முனைப்புள்ளிகள், ஒவ்வொரு வெளியேற்ற IP-க்கும் IP-வரம்பிடப்பட்ட ஒரே தொகுப்பைப் பகிர்கின்றன; எனவே விசையில்லா extract என்பது விருப்பத் தேர்வே தவிர, தானியக்க ரூட்டிங்கிற்கான வேட்பாளர் அல்ல); `QUOTA_STATUS_PROVIDERS` (AnySearch ஒதுக்கீட்டு நிலையைக் 402/403 நிலை வழியாக அல்லாமல், 429/உறை வழியாகக் குறிப்பிடுகிறது).
