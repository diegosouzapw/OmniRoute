## கண்ணோட்டம்

Quota Sharing Engine, ஒரே இணைப்பைப் பகிரும் பல API விசைகளுக்கு வழங்குநரின் நேர அடிப்படையிலான ஒதுக்கீட்டை (எ.கா. Codex
5 மணிநேரச் சாளரம், Kimi 1500 req/h) நியாயமாகப் பகிர்ந்தளிக்கிறது.

**இது தீர்க்கும் சிக்கல்:** OmniRoute, ஒரே upstream வழங்குநர் கணக்கின் வழியாகப் பல API விசைகளுக்குப் பதிலியாகச் செயல்படுகிறது. பகிர்வு தர்க்கம் இல்லையெனில், A விசையிலிருந்து வரும் திடீர் கோரிக்கை அதிகரிப்பு அந்த மணிநேரத்திற்கான வழங்குநர் ஒதுக்கீட்டை முழுமையாகத் தீர்த்துவிடக்கூடும்; இதனால் சாளரம் மீட்டமைக்கப்படும் வரை B மற்றும் C விசைகள் தடுக்கப்படும்.
இந்த இயந்திரம் இதை பின்வரும் முறைகளில் தடுக்கிறது:

1. ஒவ்வொரு விசையின் சுழலும் நுகர்வையும் ஒவ்வொரு பரிமாணத்தின் அடிப்படையில் (%, கோரிக்கைகள், டோக்கன்கள், $) கண்காணித்தல்.
2. பணி-பாதுகாப்பு நியாயப் பகிர்வு வழிமுறையைப் பயன்படுத்துதல்: உலகளாவிய தொகுப்பு நிறைவடையாத வரை, ஒரு விசை செயலற்ற பங்குகளிலிருந்து கடன் பெறலாம்.
3. கோரிக்கை upstream executor-ஐ அடைவதற்கு முன், hot path-இல் (`chatCore.ts`) முடிவை அமல்படுத்துதல்.

## வழிமுறை: பணி-பாதுகாப்பு நியாயப் பகிர்வு

`src/lib/quota/fairShare.ts`-இல் செயல்படுத்தப்பட்டுள்ளது.

### பயன்முறைகள்

| நிபந்தனை                                   | பயன்முறை      | செயல்பாடு                                                           |
| ------------------------------------------ | ------------- | ------------------------------------------------------------------- |
| `globalUsedPercent < saturationThreshold`  | **தாராளம்**   | நுகரப்பட்ட மொத்தத்தைக் கழித்த உலகளாவிய வரம்பு வரை விசை கடன் பெறலாம் |
| `globalUsedPercent >= saturationThreshold` | **கண்டிப்பு** | தனிப்பட்ட நியாயப் பங்கை கண்டிப்பாக அமல்படுத்தும்                    |

இயல்புநிலை `saturationThreshold = 0.5` (env `QUOTA_SATURATION_THRESHOLD`).

### ஒவ்வொரு பரிமாணத்திற்குமான முடிவு

தொகுப்பில் செயலிலுள்ள ஒவ்வொரு பரிமாணத்திற்கும், இயந்திரம் பின்வருவனவற்றைக் கணக்கிடுகிறது:

```
fairShareAllowed = poolLimit × (allocationWeight / 100)
consumed        = இந்த விசைக்கான தற்போதைய சுழலும் மதிப்பு (QuotaStore.peek-இலிருந்து)
remaining       = fairShareAllowed - consumed
```

பின்னர்:

- **`policy = hard`**: `consumed > fairShareAllowed` மற்றும் பயன்முறை கண்டிப்பானதாக இருந்தால் → **தடு**.
- **`policy = soft`**: `consumed > fairShareAllowed` மற்றும் பயன்முறை கண்டிப்பானதாக இருந்தால் → **அபராதம் விதி** (combo-இல் முன்னுரிமையைக் குறைக்கும்; ஒருபோதும் முழுமையாகத் தடுக்காது).
- **`policy = burst`**: நியாயப் பங்கைப் பொருட்படுத்தாமல், உலகளாவிய கொள்ளளவு இருக்கும் வரை அனுமதி.

### முழுமையான உச்சவரம்பு

ஒதுக்கீட்டில் உள்ள `capValue` + `capUnit` என்பது பயன்முறை அல்லது
கொள்கையைச் சாராத கண்டிப்பான உச்சவரம்பாகும். `consumed >= capValue` ஆக இருக்கும் எந்தப் பரிமாணமும் கோரிக்கையை எப்போதும் **தடுக்கும்**.

### பல பரிமாணச் சரிபார்ப்பு

தொகுப்பிலுள்ள **ஏதேனும்** ஒரு பரிமாணம் கோரிக்கையைத் தடுக்குமானால், அந்தக் கோரிக்கை தடுக்கப்படும். பரிமாணங்கள் ஒன்றுக்கொன்று சார்பற்றவை — 5h% தீர்ந்துவிடுவது weekly% பரிமாணத்தைப் பாதிக்காது.

### கடன் பெறுதல்

தாராளப் பயன்முறையில், தனது ஒதுக்கீட்டைவிடக் குறைவாக நுகர்ந்துள்ள ஒரு விசை, மற்ற விசைகளுக்கு ஒதுக்கப்படாத பங்குகளிலிருந்து உபரியைப் பயன்படுத்தலாம். அதற்கான சூத்திரம்:

```
maxAllowed = globalLimit - consumedByOtherKeys
```

இங்கே `consumedByOtherKeys = consumedTotal - consumedByThisKey`. உலகளாவிய உச்சவரம்பு
(அந்தப் பரிமாணத்திற்கான தொகுப்பு `limit`) எப்போதும் கண்டிப்பான உச்சவரம்பாக இருக்கும்.

## நகரும் சாளர எண்ணி

`src/lib/quota/sqliteQuotaStore.ts` மற்றும் `redisQuotaStore.ts` ஆகியவற்றில் செயல்படுத்தப்பட்டுள்ளது.

ஒவ்வொரு `(apiKeyId, dimensionKey)`-க்கும் இரண்டு bucket-கள்:

- `curr`: தற்போதைய bucket (`floor(nowMs / windowMs)`)
- `prev`: முந்தைய bucket (`curr - 1`)

பயனுள்ள சுழலும் மதிப்பு:

```
effectiveBucketIndex = floor(nowMs / windowMs)
bucketStartMs        = effectiveBucketIndex × windowMs
elapsed              = nowMs - bucketStartMs
weight               = 1 - elapsed / windowMs

effective = prev × weight + curr
```

**துல்லியம்**: ~99% துல்லியமானது. bucket-களுக்கு இடையிலான எல்லையில், பிழையானது சாளர அளவின் அதிகபட்சம் 1% ஆகும் (இது 2-bucket தோராயமாக்கலின் இயல்பான தன்மை).

### ஒரேநேரச் செயலாக்கம்

SQLite driver: ஒவ்வொரு `(apiKeyId | dimensionKey)` விசைக்குமான நினைவக mutex, read-modify-write race ஏற்படுவதைத் தடுக்கிறது. இந்த முறை `src/sse/services/auth.ts`-இன் anti-thundering-herd முறையை ஒத்துள்ளது.

Redis driver: அணுக்க increment-க்கான Lua EVAL script — ஒரே Redis command-ஆக இயங்குகிறது.

## இயக்கிகள்

### SQLite (இயல்புநிலை, நிறுவல் தேவையில்லை)

- அட்டவணை: `quota_consumption` (`073_quota_pools.sql` / `074_quota_consumption.sql` இடமாற்றத்தைப் பார்க்கவும்).
- ஒற்றை நிகழ்வு நிறுவல்களுக்கு மிகவும் பொருத்தமானது.
- அனைத்து நிலைத்த சேமிப்பும் ஏற்கனவே உள்ள OmniRoute SQLite தரவுத்தளத்தில் (`DATA_DIR/storage.sqlite`) உள்ளது.

### Redis (விருப்பத்தேர்வு, பல நிகழ்வுகள்)

- `ioredis` npm தொகுப்பு தேவை.
- எண்ணிகள் Redis-இல் சேமிக்கப்படும்; மெட்டாடேட்டா (தொகுப்புகள்/ஒதுக்கீடுகள்) தொடர்ந்து SQLite-இல் சேமிக்கப்படும்.
- எண்ணிகள் பகிரப்பட வேண்டிய பல பிரதி நிறுவல்களுக்கு மிகவும் பொருத்தமானது.

### இயக்கிகளை மாற்றுதல்

அமைப்புகள் UI (`/dashboard/settings` → ஒதுக்கீட்டு சேமிப்பகம்) வழியாக அல்லது சூழல் மாறிகள் வழியாக:

```bash
QUOTA_STORE_DRIVER=redis
QUOTA_STORE_REDIS_URL=redis://localhost:6379
```

சூழல் அமைப்பைவிட தரவுத்தள அமைப்பிற்கே முன்னுரிமை உண்டு. `driver=redis` என இருந்தாலும் URL இல்லாவிட்டால் அல்லது
`ioredis` நிறுவப்படவில்லை என்றால், factory SQLite-க்குத் திரும்பி ஓர் எச்சரிக்கையைப் பதிவு செய்யும்.

இயக்கி தேர்வு வரிசை:

1. தரவுத்தள அமைப்பு `quotaStore.driver`
2. சூழல் மாறி `QUOTA_STORE_DRIVER`
3. இயல்புநிலை: `sqlite`

## பல பரிமாணம்

ஒரு தொகுப்பில் பல பரிமாணங்கள் இருக்கலாம். ஒவ்வொரு பரிமாணமும் தனித்துவமாகச் செயல்படும்:

```ts
QuotaDimension {
  unit: "percent" | "requests" | "tokens" | "usd",
  window: "5h" | "hourly" | "daily" | "weekly" | "monthly",
  limit: number,  // இந்தப் பரிமாணத்திற்கான உலகளாவிய தொகுப்பு உச்சவரம்பு
}
```

**எடுத்துக்காட்டு: Codex திட்டம்** (5h% + weekly%):

```json
[
  { "unit": "percent", "window": "5h", "limit": 100 },
  { "unit": "percent", "window": "weekly", "limit": 100 }
]
```

அனுமதிக்கப்படுவதற்கு ஒரு கோரிக்கை அனைத்து பரிமாணங்களையும் பூர்த்தி செய்ய வேண்டும்.

## திட்டத் தீர்மானிப்பான்

`src/lib/quota/planResolver.ts`-இல் செயல்படுத்தப்பட்டுள்ளது.

முன்னுரிமை (அதிகபட்சத்திலிருந்து குறைந்தபட்சம் வரை):

1. **கைமுறை தரவுத்தள மேலெழுதுதல்** — ஒவ்வொரு `connectionId`-க்கும் `provider_plans` அட்டவணை.
2. **அறியப்பட்ட பட்டியல்** — `src/lib/quota/planRegistry.ts` (தரவு மட்டும்).

## செயலாக்கத் தொடருடன் ஒருங்கிணைப்பு

### PRE hook (`open-sse/handlers/chatCore.ts`)

அங்கீகாரம் மற்றும் கொள்கைச் சரிபார்ப்புகளுக்குப் பிறகு, upstream executor-க்கு முன் இயங்கும்:

```
resolveComboTargets / handleSingleModel
  → enforceQuotaShare(apiKeyId, connectionId, provider, estimatedCost)
      → ஒவ்வொரு பரிமாணத்திற்கும் getQuotaStore().peek()
      → fairShare.decideFairShare()
      → தடுக்கப்பட்டால் → 429-ஐத் திருப்பியனுப்பு (buildErrorBody, கடுமையான விதி #12)
      → அனுமதி + முன்னுரிமைக் குறைப்பு என்றால் → candidate-இல் quotaSoftPenalty=true என அமை
  → executor.execute()
```

**தோல்வியின்போதும் அனுமதி**: `enforceQuotaShare` பிழையை எழுப்பினால், `pino.warn` பதிவுடன்
கோரிக்கை அனுமதிக்கப்படும். ஒதுக்கீட்டு இயந்திரத்தின் ஒரு பிழை அனைத்து போக்குவரத்தையும் தடுப்பதை இது
தடுக்கிறது.

### POST hook (நுகர்வைப் பதிவுசெய்தல்)

வெற்றிகரமான பதிலுக்குப் பிறகு:

```
executor வெற்றியைத் திருப்பியனுப்புகிறது
  → spendRecorder.recordConsumption(apiKeyId, connectionId, provider, actualCost)
      → ஒவ்வொரு பரிமாணத்திற்கும் getQuotaStore().consume()
      → தோல்வியின்போதும் அனுமதி: பிழைகள் pino.warn ஆகப் பதிவுசெய்யப்படும், கிளையண்டுக்கு ஒருபோதும் அனுப்பப்படாது
```

**விலகல் குறிப்பு**: பதிலுக்குப் பிறகு `consume` தோல்வியடைந்தால், நகரும் எண்ணி குறைவாகக் கணக்கிடும்.
வழங்குநரிடமிருந்து வரும் நிறைவுநிலைச் சிக்னல் (எ.கா. `anthropic-ratelimit-unified-5h-utilization`)
அடுத்த கோரிக்கையில் உலகளாவிய மதிப்பீட்டைச் சரிசெய்யும்.

### சேர்க்கை மென் அபராதம் (`open-sse/services/combo.ts`)

`decision.deprioritize === true` ஆக இருக்கும்போது:

```ts
if (candidate.quotaSoftPenalty) {
  score *= QUOTA_SOFT_DEPRIORITIZE_FACTOR; // இயல்புநிலை 0.7
}
```

மற்ற அனைத்து மதிப்பீட்டுக் காரணிகளுக்குப் பிறகும் அபராதம் பயன்படுத்தப்படும். இது ஒரு நிறைவடைந்த விசையை
முழுமையாகத் தடுக்காமல், தானியங்கி சேர்க்கை அதைத் தேர்ந்தெடுக்கும் நிகழ்தகவைக் குறைக்கிறது.

## சிக்கல் தீர்வு

### Redis உள்ளமைக்கப்பட்டுள்ளது, ஆனால் இணைக்கப்படவில்லை

`ioredis` நிறுவப்பட்டுள்ளதா (`npm ls ioredis`) என்றும் `QUOTA_STORE_REDIS_URL`
அணுகக்கூடியதா என்றும் சரிபார்க்கவும். இணைப்புத் தோல்வியின்போது தொழிற்சாலை SQLite-க்கு மாறுகிறது (`warn`
நிலையில் பதிவுசெய்யப்படும்).

### `peek` பழைய தரவை வழங்குகிறது / தோல்வியின்போது அனுமதிக்கிறது

`peek` பிழையெறிந்தால், `enforceQuotaShare` முடிவை "அனுமதி" எனக் கருதுகிறது (தோல்வியின்போது அனுமதி).
மூலக் காரணத்தைக் கண்டறிய `quota:enforce` மற்றும் `quota:factory` உள்ளீடுகளுக்கான
`pino` பதிவுகளைச் சரிபார்க்கவும்.

### நுகர்வு எண்ணி விலகல்

உண்மையான வழங்குநர் பயன்பாடு எண்ணிகளிலிருந்து வேறுபட்டிருந்தால், அது எதிர்பார்க்கப்பட்டதே —
2-தொகுதி நகரும் சாளரம் சாளர எல்லைகளில் ~1% பிழையைக் கொண்டுள்ளது, மேலும் `consume`
பதில் அனுப்பப்பட்ட பின்னர் முடிவுக்காகக் காத்திராமல் செயல்படுகிறது. செறிவுக் குறிகை (`saturationSignals.ts`)
உண்மையான வழங்குநர் பயன்பாட்டை 30 வினாடி TTL உடன் வாசித்து, அதற்கேற்ப `globalUsedPercent`
ஐச் சரிசெய்கிறது.

### நுகர்வு விகிதத்திற்கு பூல் "தரவு இல்லை" எனக் காட்டுகிறது

`computeBurnRate` க்கு குறைந்தது 2 வரலாற்று மாதிரிகள் தேவை. முந்தைய
`consume` அழைப்புகள் இல்லாத புதிய பூல்கள் `tokensPerSecond: 0` மற்றும் `timeToExhaustionMs: null` எனக் காட்டும்.

## localStorage-இலிருந்து இடமாற்றம்

`/dashboard/costs/quota-share` முதன்முதலில் ஏற்றப்படும்போது, `useLocalStoragePoolMigration`
ஹுக் பின்வருவனவற்றைச் சரிபார்க்கிறது:

1. `localStorage.getItem("omniroute:quota-share:pools")` காலியாக இல்லை.
2. `GET /api/quota/pools` ஆனது `[]` என்பதைத் திருப்பித் தருகிறது (DB காலியாக உள்ளது).

இரண்டும் உண்மையாக இருந்தால், ஒவ்வொரு பழைய பூலையும் தொகுப்பாக `POST /api/quota/pools`-க்கு அனுப்பி,
பின்னர் localStorage விசையை அகற்றுகிறது. இந்த இடமாற்றம் idempotent தன்மை கொண்டது: நிபந்தனை 2
மீண்டும் இடமாற்றம் செய்யப்படுவதைத் தடுக்கிறது.

## உள்துறை உத்தி வகைப்பாடு

`quota-share` என்பது ஓர் **உள்துறைப் பயன்பாட்டிற்கு மட்டும்** உரிய வழிப்படுத்தல் உத்தி
(`src/shared/constants/routingStrategies.ts`-இல் உள்ள `INTERNAL_ROUTING_STRATEGY_VALUES`).
இது கணினியால் உருவாக்கப்படும் `qtSd/` பூல் சேர்க்கைகளால் மட்டுமே பயன்படுத்தப்படுகிறது. UI அல்லது
API-இல் பயனர் தேர்ந்தெடுக்கக்கூடிய விருப்பமாக ஒருபோதும் தோன்றாத வகையில், இது வேண்டுமென்றே
`ROUTING_STRATEGY_VALUES`-இலிருந்து விலக்கப்பட்டுள்ளது.

## DB திட்டவடிவச் சுருக்கம்

`078`, `079` மற்றும் `085` இடமாற்றங்கள் மூலம் மூன்று அட்டவணைகள் சேர்க்கப்பட்டுள்ளன:

- `quota_pools` + `quota_allocations` — பூல் வரையறைகள் மற்றும் ஒவ்வொரு விசைக்குமான ஒதுக்கீடுகள்.
- `quota_consumption` — ஒவ்வொரு `(apiKeyId, dimensionKey)`-க்குமான சுழலும் 2-பக்கெட் கணக்கீடுகள்.
- `provider_plans` — கைமுறை வழங்குநர் திட்ட மேலெழுதல்கள் (ஒவ்வொரு connectionId-க்குமான dimensions JSON).

அனைத்து அட்டவணைகளும் idempotent தன்மை கொண்ட `CREATE TABLE IF NOT EXISTS` இடமாற்றங்கள் வழியாகச் சேர்க்கப்பட்டுள்ளன.
