> விருப்பத் தேர்வாக இயக்கக்கூடியது; இயல்புநிலையில் முடக்கப்பட்டிருக்கும் (`modelVisibilityAllowlist`/`modelVisibilityDenylist` இரண்டும் காலியாக இருந்தால்
> `/v1/models` பட்டியலும் ஒவ்வொரு `auto/*` candidate pool-உம் byte அளவில் அப்படியே இருக்கும்). செலவுடன் தொடர்பில்லாத
> காரணங்களுக்காகத் தேர்ந்தெடுக்கப்பட்ட model பட்டியலை விரும்பும் operators-க்கான
> `hidePaidModels`/`hideAutoCombos`-இன் (`src/lib/db/settings.ts`) sibling அமைப்பு.

## இது ஏன் உள்ளது

`hidePaidModels` என்பது "இந்த model இலவசமா?" என்பதற்கும், `hideAutoCombos` என்பது "`auto/*`
virtual ids-ஐ விளம்பரப்படுத்த வேண்டுமா?" என்பதற்கும் பதிலளிக்கின்றன — ஆனால் ஒரு operator தன்னிச்சையான
models துணைத்தொகுப்பைத் தேர்ந்தெடுக்க இவற்றில் எதுவும் அனுமதிப்பதில்லை (எ.கா., விலை நிர்ணயத்தைச் சாராமல்,
குறிப்பிட்ட Claude Code / OpenCode client பார்க்க வேண்டிய models-ஐ மட்டும் துல்லியமாகக் காட்டுவது).
#11481 இதை இரண்டு தனித்தனி, விருப்பத் தேர்வாக இயக்கக்கூடிய string-array settings ஆகச் சேர்க்கிறது.

## அமைப்புகள்

| விசை                       | வகை        | இயல்புநிலை | பொருள்                                                                                     |
| -------------------------- | ---------- | ---------- | ------------------------------------------------------------------------------------------ |
| `modelVisibilityDenylist`  | `string[]` | `[]`       | candidate-உடன் பொருந்தும் entries அதை catalog/candidate pool-இலிருந்து மறைக்கும்.          |
| `modelVisibilityAllowlist` | `string[]` | `[]`       | காலியாக இல்லாதபோது, candidate-உடன் பொருந்தும் entries மட்டுமே வெளிப்படுத்தப்பட்டிருக்கும். |

இரண்டிலும் அதிகபட்சம் தலா 200 எழுத்துகள் கொண்ட 500 entries வரை ஏற்கப்படும்
(`src/shared/validation/settingsSchemas.ts`-இல் Zod மூலம் சரிபார்க்கப்படும்). ஓர் entry பின்வருவனவற்றில் ஒன்று:

- துல்லியமான catalog id — `"gpt-4o"` (தனித்த model id) அல்லது `"openai/gpt-4o"` (provider prefix கொண்டது), அல்லது
- `*`/`?` பயன்படுத்தும் glob pattern — எ.கா. `"openai/gpt-4*"` அல்லது `"anthropic/*"` — ஏற்கனவே
  `ModelRoutingSection`-இன் ஒவ்வொரு model-க்குமான combo mappings மற்றும் `freeModels.ts::matchesOnlyPaidModels`
  ஆகியவற்றால் பயன்படுத்தப்படும் அதே பகிரப்பட்ட `globToRegex()` matcher (`src/shared/utils/globPattern.ts`) மூலம் தீர்மானிக்கப்படும்.

முன்னுரிமை: denylist முதலில் சரிபார்க்கப்படும் (மறுக்கப்பட்ட entry allowlist-உடனும் பொருந்தினாலும்
எப்போதும் மறைக்கப்படும்); allowlist காலியாக இல்லாதபோது, அதனுடன் பொருந்தும் entries மட்டுமே தக்கவைக்கப்படும்.

## ஒன்று அல்ல, இரண்டு chokepoints

#6512-இலிருந்து கிடைத்த பாடம் (combo candidate pool தனியாக உருவாக்கப்பட்டதால்,
`hidePaidModels` மட்டும் பயன்படுத்திய catalog filter, `auto/*`-ஐ இன்னும் கட்டண model-க்கு route செய்ய அனுமதித்தது)
இங்கும் அதேபோலப் பொருந்துகிறது. பொருத்தத்தைச் சோதிக்கும் `isModelExposureAllowed()`
(`src/shared/utils/modelExposureList.ts`) பின்வரும் இரு இடங்களிலிருந்தும் அழைக்கப்படுகிறது:

- `src/app/api/v1/models/catalog.ts` — `/v1/models` பட்டியலிலேயே, `shouldHidePaid()` ஏற்கனவே gate செய்யும்
  ஒவ்வொரு source-க்குமான அதே 5 chokepoints-இல் (நிலையான `PROVIDER_MODELS`, ஒத்திசைக்கப்பட்ட provider rows,
  custom rows, alias ஆதரவு கொண்ட rows, managed-fallback rows).
- `open-sse/services/autoCombo/modelExposureFilter.ts::filterModelExposureCandidates()` — அதற்கு இணையான
  `filterPaidOnlyCandidates()` அழைப்புக்குப் பிறகு உடனடியாக `virtualFactory.ts::buildPreparedPool`-இலிருந்து
  அழைக்கப்படுகிறது; எனவே மறுக்கப்பட்ட model ஒருபோதும் `auto/*` candidate pool-க்குத் தேர்ந்தெடுக்கப்படாது.

## எவை filter செய்யப்படுவதில்லை

`hideAutoCombos`-இன் தற்போதைய நடத்தையைப் பிரதிபலிக்கிறது: **வெளிப்படையாக** அனுப்பப்பட்ட model id (`auto/*`
வழியாக அல்லாமல், catalog பட்டியல் மூலம் கண்டறியப்படாமலும்) dispatch நேரத்தில் ஒருபோதும் தடுக்கப்படாது —
விளம்பரப்படுத்தப்படுவதும் candidate-pool membership-உம் மட்டுமே filter செய்யப்படும். இது `hidePaidModels`-இலிருந்து
சுயாதீனமானது; செலவுடன் தொடர்பில்லாத காரணங்களுக்காக ஓர் operator தேர்ந்தெடுக்கப்பட்ட தொகுப்பை விரும்பக்கூடும்,
எனவே `catalog.ts`-இல் ஏற்கனவே உள்ள பல-flag சேர்க்கையைப் போலவே, இரு settings-உம் சுயாதீனமான
AND முறையில் இணைக்கப்பட்ட filters ஆகச் செயல்படும்.

Settings export (`GET /api/settings/export-json`), மற்ற எந்த settings field-ஐப் போலவே, இரு arrays-ஐயும்
மாற்றமின்றி உள்ளடக்கும் — `hidePaidModels`-இன் combo-step export filter போலல்லாமல், இங்கு re-hydration
ஆபத்து இல்லை: export செய்யப்பட்ட combo step-இல் உட்பொதிக்கப்பட்ட மறுக்கப்பட்ட id என்பது operator-இன் சொந்த
வெளிப்படையான routing தேர்வு; export boundary நீக்க வேண்டிய ஒன்றல்ல.
