`copilot-m365-web` (`m365copilot` என்ற மாற்றுப்பெயர்) OpenAI வடிவ அரட்டை கோரிக்கைகளை,
`m365.cloud.microsoft/chat`-இல் அங்கீகரிக்கப்பட்ட Microsoft 365 Copilot BizChat உலாவி அமர்வு வழியாக அனுப்புகிறது. இது அதிகாரப்பூர்வமற்ற ஒருங்கிணைப்பு ஆகும்.

> **Web Cookie வழங்குநர்களுக்கு புதியவரா?**
>
> இந்த வழங்குநருக்கான குறிப்பிட்ட வழிகாட்டியைப் பின்பற்றுவதற்கு முன், பொதுவான அமைவுச் செயல்முறை, அங்கீகார வழிகாட்டுதல், வரம்புகள் மற்றும் சிக்கல் தீர்த்தல் ஆகியவற்றுக்கு **`docs/getting-started/WEB-COOKIE-GUIDE.md`**-ஐப் படிக்கவும்.
>
> **முக்கியம்:** இந்த வழங்குநருக்கான நற்சான்று **cookie அல்ல**. `m365.cloud.microsoft`-இலிருந்து
> cookies-ஐ நகலெடுக்க வேண்டாம். நற்சான்று என்பது WebSocket URL வினவல்
> அளவுரு மற்றும் பாதைப் பகுதியாகும்; இவை இரண்டும் DevTools Network தாவலிலிருந்து படிக்கப்படுகின்றன.

## முன்தேவைகள்

- `m365.cloud.microsoft/chat`-இல் BizChat-ஐ அணுகக்கூடிய Microsoft 365 கணக்கு
- DevTools WebSocket ஆய்வுக்கான Chromium அடிப்படையிலான உலாவி (Chrome, Edge)
- M365 Copilot உரிமம் (பல Microsoft 365 Business/Enterprise திட்டங்களுடன் சேர்க்கப்பட்டுள்ளது)

## நற்சான்றைப் பெறுதல் (WebSocket முறை)

1. `https://m365.cloud.microsoft/chat`-இல் உள்நுழைந்து ஓர் உரையாடலைத் தொடங்கவும்.
2. **DevTools → Network**-ஐத் திறக்கவும்.
3. **WS** (WebSocket) மூலம் வடிகட்டவும்.
4. Chathub WebSocket இணைப்பைக் கிளிக் செய்யவும். பின்வருமாறு தொடங்கும் URL-ஐத் தேடவும்:
   `wss://substrate.office.com/m365Copilot/Chathub/`.
5. அதன் **Request URL**-இலிருந்து பின்வருவனவற்றை நகலெடுக்கவும்:
   - `access_token` வினவல் அளவுருவின் மதிப்பு (குறுகிய ஆயுட்காலமுள்ள JWT).
   - `/Chathub/`-க்குப் பிந்தைய Chathub பாதைப் பகுதி (எ.கா. `<oid>@<tenant>`).

முழுமையான URL பின்வரும் வடிவத்தில் இருக்கும்:

```
wss://substrate.office.com/m365Copilot/Chathub/<oid>@<tenant>?...&access_token=<jwt>
```

6. OmniRoute-இல், **Providers → Add Provider** என்பதற்குச் சென்று, **Microsoft 365 Copilot
   (BizChat)**-ஐத் தேர்ந்தெடுத்து, நற்சான்றைப் பின்வரும் வடிவத்தில் ஒட்டவும்:

```
access_token=<jwt>; chathubPath=<oid>@<tenant>
```

7. **Test Connection** என்பதைக் கிளிக் செய்து, பின்னர் **Save** என்பதைக் கிளிக் செய்யவும்.

## நற்சான்றைப் பெறுதல் (HAR இறக்குமதி)

WebSocket URL-இலிருந்து மதிப்புகளை கைமுறையாக நகலெடுப்பதற்குப் பதிலாக, DevTools HAR
கோப்பை ஏற்றுமதி செய்யலாம்:

1. **DevTools → Network**-ஐத் திறக்கவும்.
2. BizChat உரையாடலைத் தொடங்கவும் அல்லது தொடரவும் (இது WebSocket இணைப்பைத் தூண்டும்).
3. Network பலகையில் வலது கிளிக் செய்து, **Save all as HAR with content** என்பதைத் தேர்ந்தெடுக்கவும்.
4. OmniRoute-இல், வழங்குநர் இணைப்பு உரையாடல் பெட்டியில் உள்ள **Import .har file** பொத்தானைப் பயன்படுத்தவும்.

OmniRoute, Chathub WebSocket URL-க்காக HAR-ஐ வருடி, `access_token` மற்றும்
`chathubPath`-ஐப் பிரித்தெடுத்து, நற்சான்றுப் புலங்களைத் தானாக நிரப்புகிறது. HAR
இறக்குமதி JWT காலாவதியாகும் நேரத்தை மறைகுறிநீக்கம் செய்து, மீதமுள்ள token ஆயுட்காலத்தைக் காட்டுகிறது.

> **உண்மையான HAR ஏற்றுமதி, access token அல்லது refresh token-ஐ ஒருபோதும் commit செய்ய வேண்டாம்.** சோதனை மற்றும்
> ஆவண மதிப்புகள் எப்போதும் இடநிரப்பிகளாகவே இருக்க வேண்டும்.

## Token ஆயுட்காலம் மற்றும் புதுப்பித்தல்

`access_token` குறுகிய ஆயுட்காலமுள்ளது (பொதுவாக **~75 நிமிடங்கள்**). அது காலாவதியான பிறகு, வழங்குநர்
இணைப்புப் பிழையை அறிவிக்கும்; நீங்கள் நற்சான்றை மீண்டும் பெற வேண்டும்.

### `refreshToken` மூலம் தானியங்கி புதுப்பித்தல்

கைமுறையாக மீண்டும் பெறுவதைத் தவிர்க்க, இணைப்பின்
**Advanced Settings → providerSpecificData**-இல் Microsoft refresh token-ஐச் சேமிக்கலாம்:

| புலம்          | விளக்கம்                                                                |
| -------------- | ----------------------------------------------------------------------- |
| `refreshToken` | `substrate.office.com/sydney` scope-க்கான Microsoft OAuth refresh token |
| `tier`         | `individual` (இயல்புநிலை), `edu`, அல்லது `enterprise`                   |

`substrate.office.com/sydney`-க்கு scope செய்யப்பட்ட Microsoft device-code அல்லது authorization-code flow-இலிருந்து
refresh token-ஐப் பெறவும். `refreshToken` அமைக்கப்பட்டிருந்தால், ஒவ்வொரு கோரிக்கைக்கும் முன் OmniRoute
`access_token`-ஐ முன்கூட்டியே புதுப்பிக்கும்; எனவே ஒவ்வொரு ~75 நிமிட காலாவதிக்குப் பிறகும்
நீங்கள் அதை மீண்டும் பெற வேண்டியதில்லை.

`refreshToken` அமைக்கப்படவில்லை என்றால், ஒவ்வொரு காலாவதிக்குப் பிறகும் WebSocket நற்சான்றை
கைமுறையாக மீண்டும் பெற வேண்டும்.

### Tier தேர்வு

| Tier         | மாற்றுப்பெயர்  | பயன்பாட்டுப் பரப்பு     |
| ------------ | -------------- | ----------------------- |
| `individual` | _(இயல்புநிலை)_ | நுகர்வோர் M365 Copilot  |
| `edu`        | `included`     | கல்விக்கான M365 Copilot |
| `enterprise` | `work`         | பணிக்கான M365 Copilot   |

**Advanced Settings → providerSpecificData → tier**-இல் tier-ஐ அமைக்கவும். இந்த tier,
BizChat வழிப்படுத்தல் மற்றும் model அணுகலைப் பாதிக்கிறது.

## பாதுகாப்பு மாதிரி

- **அதிகாரப்பூர்வமற்ற ஒருங்கிணைப்பு.** இந்த வழங்குநர் BizChat WebSocket
  நெறிமுறையைப் பின்னாய்வு செய்கிறது. Microsoft இறுதிப்புள்ளியை மாற்றும்போது, எந்த முன்னறிவிப்புமின்றி இது செயலிழக்கக்கூடும்.
- `subscriptionRisk: true` கொடி, இந்த ஒருங்கிணைப்பு ஆவணப்படுத்தப்படாத
  இறுதிப்புள்ளியைச் சார்ந்திருப்பதைக் குறிக்கிறது. கணக்குக் கட்டுப்பாடுகள் ஏற்படலாம், ஆனால் அது உறுதிப்படுத்தப்படவில்லை.
- அணுகல் டோக்கன் குறுகிய காலம் மட்டுமே செல்லுபடியாகும் JWT ஆகும். அதைக் கடவுச்சொல்லைப் போலக் கையாளுங்கள்: அதை commit செய்யவோ,
  பதிவுகளில் சேமிக்கவோ அல்லது பகிரவோ வேண்டாம்.
- புதுப்பிப்பு டோக்கன் BizChat இடைமுகத்திற்கு நீண்டகால அணுகலை வழங்குகிறது. அதை
  API key ஒன்றைப் போலவே கவனமாகச் சேமிக்கவும்.

## சிக்கல் தீர்வு

### அங்கீகாரம் உடனடியாகத் தோல்வியடைகிறது

- நீங்கள் XHR/Fetch கோரிக்கையிலிருந்து அல்லாமல், **WebSocket URL**-லிருந்து நகலெடுத்துள்ளீர்கள் என்பதை உறுதிப்படுத்தவும்.
  நற்சான்று Chathub WebSocket இணைப்பின் `access_token` வினவல் அளவுருவில்
  உள்ளது — `Authorization: Bearer` தலைப்பில் அல்ல.
- `chathubPath`, URL
  பாதையிலுள்ள முழுமையான `<oid>@<tenant>` பகுதியையும் உள்ளடக்கியுள்ளதை உறுதிப்படுத்தவும்.

### டோக்கன் ~75 நிமிடங்களுக்குப் பிறகு காலாவதியாகிறது

இது எதிர்பார்க்கப்பட்டதே. `refreshToken` இல்லாமல், அணுகல் டோக்கன் குறுகிய காலம் மட்டுமே செல்லுபடியாகும். பின்வருவனவற்றில் ஒன்றைச் செய்யவும்:

- DevTools-லிருந்து நற்சான்றை மீண்டும் கைப்பற்றவும், அல்லது
- தானியங்கிப் புதுப்பிப்பிற்காக Advanced Settings-ல் `refreshToken`-ஐ உள்ளமைக்கவும்.

### Test Connection வெற்றிபெறுகிறது, ஆனால் அரட்டை 401-ஐத் திருப்புகிறது

சரிபார்ப்புக்கும் முதல் கோரிக்கைக்கும் இடையில் டோக்கன் காலாவதியாகியிருக்கலாம். புதிய
நற்சான்றை மீண்டும் கைப்பற்றவும்.
