IDE அமர்வு இல்லாமல் Cursor-ஐ OmniRoute-க்குப் பின்னால் அமைக்க இரண்டு வழிகள் உள்ளன:

1. **`cursor-api` வழங்குநர்** (அட்டை "Cursor API", மாற்றுப்பெயர் `cua`): Cursor பயனர் API விசையை (`crsr_…`, `https://cursor.com/dashboard/api` இல் உருவாக்கப்பட்டது) வைத்திருக்கும் API-விசை வழங்குநர். பின்னர் எந்த OmniRoute கிளையண்டும் வழக்கமான ஒதுக்கீடு, மாற்றுவழி மற்றும் பதிவேற்ற அடுக்குகளுடன் `/v1/chat/completions` வழியாக `cursor-api/<model>` அல்லது `cua/<model>` என Cursor மாடல்களை அணுகும். IDE வழங்குநர் (`cursor`, OAuth/IDE அமர்வு) மாற்றமின்றி இருக்கும்.
2. **Cursor CLI நேரடி அனுப்புதல்**: Cursor CLI (`agent`)-ஐ OmniRoute-ஐ நோக்கி அமைக்கவும். இதனால் CLI செய்யும் ஒவ்வொரு RPC-யும் OmniRoute API விசையைக் கொண்டு அங்கீகரிக்கப்பட்டு, `cursor-api` இணைப்பின் நற்சான்றுடன் Cursor-க்கு அனுப்பப்பட்டு, Logs பக்கத்தில் பதிவுசெய்யப்படும்.

## விசை ஏன் பரிமாற்றப்படுகிறது

மூல `crsr_…` விசையை Bearer டோக்கனாக வழங்கும்போது `api2.cursor.sh` அதை நிராகரிக்கிறது (401). Cursor CLI முதலில் விசையை `/auth/exchange_user_api_key`-க்கு POST செய்து, ஒரு மணி நேரத்திற்குப் பிறகு காலாவதியாகும் அமர்வு JWT-ஐப் பெறுகிறது; திருப்பி அனுப்பப்படும் `refreshToken` அதே `exp`-ஐக் கொண்டிருப்பதால், புதுப்பித்தல் என்பது விசையை மீண்டும் பரிமாற்றுவதாகும்.
`open-sse/services/cursorApiKeyAuth.ts` அந்தப் பரிமாற்றத்தைச் செய்து, ஒவ்வொரு விசைக்கும் ஒரு அமர்வு டோக்கனைத் தேக்கி வைத்து, காலாவதியாக ஐந்து நிமிடங்கள் இருக்கும் முன்பு மீண்டும் பரிமாற்றுகிறது; மேலும் Cursor 401 எனப் பதிலளிக்கும்போது தேக்கப்பட்ட டோக்கனை நீக்குகிறது. `cursor-api` இணைப்புகளுக்கான மேல்நிலை ஸ்ட்ரீமைத் திறப்பதற்கு உடனடியாக முன்பு `CursorExecutor` அதை அழைக்கிறது.

## `cursor-api` வழங்குநர்

பதிவகம்: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor`-இன் அதே `format`, `baseUrl` மற்றும்
`models`). பட்டியல் அட்டை:
`src/shared/constants/providers/apikey/specialty-media.ts`. செயலாக்கி வரைபடம்:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

Dashboard: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

பின்னர்:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

குறிப்புகள்:

- `cursor-api`-க்கான மாடல் பட்டியல் நிலையான Cursor பதிவகத்திலிருந்து வருகிறது (IDE வழங்குநர் மாற்றுவழியாகப் பயன்படுத்தும் அதே பட்டியல்); OmniRoute ஹோஸ்டில் `cursor-agent` நிறுவ வேண்டியதில்லை.
- `POST /api/providers/{id}/refresh-cursor` என்பது `cursor` IDE வழங்குநருக்கு மட்டுமே; `cursor-api` இணைப்புகளில் புதுப்பிக்க வேண்டிய IDE அமர்வு இல்லை.

## Cursor CLI நேரடி அனுப்புதல்

வழித்தடம்: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. கையாளி அதன் சொந்த அங்கீகாரத்தைச் செயல்படுத்துவதால் `/api/cursor-cli/` முன்னொட்டு
`src/shared/constants/publicApiRoutes.ts` இல் பதிவுசெய்யப்பட்டுள்ளது:

| பாதை                                                                                                                               | CLI-யிடமிருந்து எதிர்பார்க்கப்படும் அங்கீகாரம் | OmniRoute செய்வது                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `POST /auth/exchange_user_api_key`                                                                                                 | `Bearer <OmniRoute API key>`                   | விசையைச் சரிபார்த்து, 1 மணிநேர HS256 JWT-ஐ (`JWT_SECRET` மூலம் கையொப்பமிடப்பட்டதை) உருவாக்கி அதைத் திருப்பி அனுப்புகிறது                                                                               |
| மற்ற அனைத்து பாதைகளும் (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                            | வழங்குநர்/பயனாளர்/காலாவதி விவரங்களைச் சரிபார்த்து, செயலில் உள்ள `cursor-api` இணைப்பைத் தேர்ந்தெடுத்து, Authorization தலைப்பை பரிமாற்றப்பட்ட Cursor டோக்கனால் மாற்றி, பதிலை மீண்டும் ஸ்ட்ரீம் செய்கிறது |

CLI தனக்குக் கிடைக்கும் எந்த டோக்கனிலிருந்தும் `exp`-ஐப் பிரித்தறிகிறது. எனவே அதற்கு வெளிப்படையற்ற டோக்கனை வழங்கினால், கிட்டத்தட்ட ஒவ்வொரு கோரிக்கைக்கும் முன்பும் அது மீண்டும் பரிமாற்றம் செய்யும்; உருவாக்கப்பட்ட JWT இதைத் தவிர்க்கிறது. OmniRoute-இலிருந்து 401 கிடைத்தால், CLI மீண்டும் பரிமாற்றம் செய்யும்.

### அமைப்பு

1. OmniRoute API விசை (Dashboard → API keys) மற்றும் `cursor-api` இணைப்பை உருவாக்கவும்.
2. முகவர் ஸ்ட்ரீமுக்கு HTTP/1.1-ஐப் பயன்படுத்துமாறு CLI-க்கு அறிவுறுத்தவும்.
   `~/.cursor/cli-config.json` இல்:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   இது இல்லையெனில், CLI தனியாக உள்ளமைக்கப்பட்ட முகவர் ஹோஸ்டிற்கு HTTP/2 வழியாக முகவர் செயல்பாட்டைத் திறக்கும்; கட்டுப்பாட்டுத் தள RPC-கள் மட்டுமே endpoint வழியாகச் செல்லும்.

3. OmniRoute-ஐ நோக்கி CLI-ஐ இயக்கவும்:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ஒவ்வொரு கட்டமும் வழங்குநர் `cursor-api`, கோரிக்கை வகை `cursor-cli`, பாதை `/api/cursor-cli/<rpc>` என Logs-இல் பதிவாகிறது; மேலும் அது OmniRoute API விசைக்கும் அதற்குச் சேவையளித்த இணைப்புக்கும் ஒதுக்கப்படுகிறது.

### தோல்வி நிலைகள்

| சூழ்நிலை                                                          | CLI-க்கான பதில்                                                        |
| ----------------------------------------------------------------- | ---------------------------------------------------------------------- |
| அறியப்படாத OmniRoute விசை மற்றும் `REQUIRE_API_KEY=true`          | பரிமாற்றத்தில் 401 `unauthenticated`                                   |
| `REQUIRE_API_KEY=false`                                           | அநாமதேய அமர்வு (`/v1/*` நடத்தையைப் பிரதிபலிக்கிறது)                    |
| காலாவதியான / அந்நிய / மாற்றப்பட்ட அமர்வு JWT                      | 401, CLI மீண்டும் பரிமாற்றம் செய்கிறது                                 |
| பரிமாற்றத்திற்குப் பிறகு OmniRoute API விசை திரும்பப் பெறப்பட்டது | அடுத்த RPC-இல் 401                                                     |
| செயலில் உள்ள `cursor-api` இணைப்பு இல்லை                           | 503 `unavailable`                                                      |
| இணைப்பின் விசையை Cursor நிராகரிக்கிறது                            | 401 `unauthenticated`, தற்காலிகச் சேமிப்பிலுள்ள அமர்வு நீக்கப்படுகிறது |
| மேல்நிலை சேவையை அணுக முடியவில்லை                                  | 502 `unavailable` (தூய்மைப்படுத்தப்பட்ட செய்தி)                        |
| `JWT_SECRET` அமைக்கப்படவில்லை                                     | பரிமாற்றத்தில் 503                                                     |
