IDE அமர்வு இல்லாமல் Cursor-ஐ OmniRoute-க்குப் பின்னால் வைப்பதற்கான இரண்டு வழிகள்:

1. **`cursor-api` வழங்குநர்** (அட்டை "Cursor API", மாற்றுப்பெயர் `cua`): Cursor பயனர் API விசையை (`crsr_…`, `https://cursor.com/dashboard/api` இல்
   உருவாக்கப்பட்டது) வைத்திருக்கும் API-விசை வழங்குநர். பின்னர் எந்த OmniRoute கிளையண்டும்
   வழக்கமான ஒதுக்கீடு, மாற்றுவழி மற்றும் பதிவிடல் அடுக்குகளுடன்
   `/v1/chat/completions` வழியாக `cursor-api/<model>` அல்லது
   `cua/<model>` என Cursor மாடல்களை அணுகலாம். IDE
   வழங்குநரில் (`cursor`, OAuth/IDE அமர்வு) எந்த மாற்றமும் இல்லை.
2. **Cursor CLI நேரடி அனுப்பல்**: Cursor CLI (`agent`) ஐ OmniRoute-ஐ நோக்குமாறு அமைக்கவும்; இதனால்
   CLI செய்யும் ஒவ்வொரு RPC-யும் OmniRoute API விசையால் அங்கீகரிக்கப்பட்டு,
   `cursor-api` இணைப்பின் நற்சான்றுடன் Cursor-க்கு அனுப்பப்பட்டு,
   Logs பக்கத்தில் பதிவுசெய்யப்படும்.

## விசை ஏன் பரிமாறப்படுகிறது

`api2.cursor.sh` ஒரு மூல `crsr_…` விசையை Bearer டோக்கனாக நிராகரிக்கிறது (401). Cursor
CLI முதலில் அந்த விசையை `/auth/exchange_user_api_key`-க்கு POST செய்து, ஒரு மணி நேரத்திற்குப்
பிறகு காலாவதியாகும் அமர்வு JWT-ஐப் பெறுகிறது; திருப்பி அளிக்கப்படும் `refreshToken` அதே
`exp`-ஐக் கொண்டிருப்பதால், புதுப்பித்தல் என்பது விசையை மீண்டும் பரிமாறுவதாகும்.
`open-sse/services/cursorApiKeyAuth.ts` அந்தப் பரிமாற்றத்தைச் செய்து, ஒவ்வொரு விசைக்கும் ஓர் அமர்வு
டோக்கனைத் தேக்கி வைத்து, காலாவதியாக ஐந்து நிமிடங்கள் இருக்கும்போது மீண்டும் பரிமாறி, Cursor 401 என்று
பதிலளிக்கும்போது தேக்கப்பட்ட டோக்கனை நீக்குகிறது. `CursorExecutor`, `cursor-api`
இணைப்புகளுக்கான அப்ஸ்ட்ரீம் ஸ்ட்ரீமைத் திறப்பதற்கு முன்பாகவே இதை அழைக்கிறது.

## `cursor-api` வழங்குநர்

பதிவகம்: `open-sse/config/providers/registry/cursor/index.ts`
(`cursor_apiProvider`, `authType: "apikey"`, `cursor` போலவே அதே `format`, `baseUrl` மற்றும்
`models`). பட்டியல் அட்டை:
`src/shared/constants/providers/apikey/specialty-media.ts`. செயலாக்கி வரைபடம்:
`open-sse/executors/index.ts` (`"cursor-api"` / `cua` →
`new CursorExecutor("cursor-api")`).

டாஷ்போர்டு: Providers → Cursor API → Add API key.

REST:

```bash
curl -sS -X POST http://localhost:20128/api/providers \
  -H "Content-Type: application/json" \
  -d '{"provider":"cursor-api","name":"cursor-api-key","apiKey":"crsr_…","priority":1}'
```

பின்னர்:

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer <omniroute-api-key>" \
  -H "Content-Type: application/json" \
  -d '{"model":"cursor-api/auto","messages":[{"role":"user","content":"say PONG"}]}'
```

குறிப்புகள்:

- `cursor-api`-க்கான மாடல் பட்டியல் நிலையான Cursor பதிவகத்திலிருந்து வருகிறது (IDE
  வழங்குநர் மாற்றுவழியாகப் பயன்படுத்தும் அதே பட்டியல்); OmniRoute ஹோஸ்டில் `cursor-agent` நிறுவல்
  தேவையில்லை.
- `POST /api/providers/{id}/refresh-cursor` என்பது `cursor` IDE வழங்குநருக்கு
  மட்டுமே; `cursor-api` இணைப்புகளில் புதுப்பிக்க வேண்டிய IDE அமர்வு இல்லை.

## மூல மாடல் ID-களும் முயற்சி அளவும்

`cursor` / `cu` மற்றும் `cursor-api` / `cua` ஆகியவற்றிற்கு, பகிரப்பட்ட Claude-effort இயல்பாக்கி
கோரப்பட்ட மாடல் ID-ஐ மாற்றாமல் விடுகிறது. OmniRoute முயற்சி மாற்றுப்பெயராக அல்லாமல்,
உண்மையான மாடல் ID-இன் ஒரு பகுதியாக `-low` போன்ற பின்னொட்டை Cursor அறிவிக்கலாம்.
Cursor செயலாக்கி, நிகழ்நேரப் பட்டியலிலுள்ள துல்லியமான பொருத்தத்தைப் பாதுகாக்கிறது; பொருத்தம்
இல்லாதபோது, அதன் தற்போதைய மாடல் தீர்மானிப்பான் பின்னொட்டிலிருந்து அளவுருவுக்கான மாற்றுவழியைக் கையாளுகிறது.

இது நேரடி Claude, Claude-இணக்கமான அல்லது Vertex வழிகளுக்கான முயற்சி இயல்பாக்கத்தை
மாற்றாது. கிடைக்கும் தன்மை இன்னும் தேர்ந்தெடுக்கப்பட்ட Cursor கணக்கின் பட்டியல் மற்றும்
உரிமையைச் சார்ந்துள்ளது.

## Cursor CLI பாஸ்த்ரூ

வழி: `src/app/api/cursor-cli/[...path]/route.ts` →
`open-sse/handlers/cursorCliProxy.ts`. `/api/cursor-cli/` முன்னொட்டு
`src/shared/constants/publicApiRoutes.ts`-இல் பதிவுசெய்யப்பட்டுள்ளது, ஏனெனில் ஹேண்ட்லர்
தனது சொந்த அங்கீகாரத்தைச் செயல்படுத்துகிறது:

| பாதை                                                                                                                               | CLI-இலிருந்து எதிர்பார்க்கப்படும் அங்கீகாரம் | OmniRoute செய்வது                                                                                                                                                                               |
| ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/exchange_user_api_key`                                                                                                 | `Bearer <OmniRoute API key>`                 | விசையைச் சரிபார்த்து, 1 மணிநேர HS256 JWT-ஐ (`JWT_SECRET` மூலம் கையொப்பமிடப்பட்டது) உருவாக்கி, அதைத் திருப்பியளிக்கிறது                                                                          |
| மற்ற எல்லாப் பாதைகளும் (`/aiserver.v1.*`, `/agent.v1.AgentService/RunSSE`, `/aiserver.v1.BidiService/BidiAppend`, `/v1/traces`, …) | `Bearer <that JWT>`                          | வழங்குநர்/பெறுநர்/காலாவதியைச் சரிபார்த்து, செயலில் உள்ள `cursor-api` இணைப்பைத் தேர்ந்தெடுத்து, Authorization தலைப்பை பரிமாற்றப்பட்ட Cursor டோக்கனுடன் மாற்றி, பதிலை மீண்டும் ஸ்ட்ரீம் செய்கிறது |

CLI, தான் பெறும் எந்த டோக்கனிலிருந்தும் `exp`-ஐ டிகோட் செய்கிறது; எனவே அதற்கு ஓர் ஒளிபுகா
டோக்கனை வழங்கினால், ஏறக்குறைய ஒவ்வொரு கோரிக்கைக்கும் முன்பும் அது மீண்டும் பரிமாற்றம் செய்யும்;
உருவாக்கப்பட்ட JWT இதைத் தவிர்க்கிறது. OmniRoute-இலிருந்து வரும் 401, CLI-ஐ மீண்டும் பரிமாற்றம் செய்ய வைக்கிறது.

### அமைப்பு

1. ஓர் OmniRoute API விசையையும் (டாஷ்போர்டு → API விசைகள்), ஒரு `cursor-api`
   இணைப்பையும் உருவாக்கவும்.
2. ஏஜென்ட் ஸ்ட்ரீமுக்கு HTTP/1.1-ஐப் பயன்படுத்துமாறு CLI-க்கு அறிவுறுத்தவும்.
   `~/.cursor/cli-config.json`-இல்:

   ```json
   { "network": { "useHttp1ForAgent": true } }
   ```

   இது இல்லையெனில், CLI தனியாக உள்ளமைக்கப்பட்ட ஏஜென்ட் ஹோஸ்டுக்கு HTTP/2 வழியாக ஏஜென்ட்
   சுற்றைத் திறக்கும்; கட்டுப்பாட்டுத் தள RPC-கள் மட்டுமே இந்த எண்ட்பாயிண்ட் வழியாகச் செல்லும்.

3. OmniRoute-க்கு எதிராக CLI-ஐ இயக்கவும்:

   ```bash
   export CURSOR_API_ENDPOINT=http://localhost:20128/api/cursor-cli
   export CURSOR_API_KEY=<omniroute-api-key>
   agent -p --trust "Reply with exactly OK"
   ```

ஒவ்வொரு ஹாப்பும் வழங்குநர் `cursor-api`, கோரிக்கை வகை `cursor-cli`,
பாதை `/api/cursor-cli/<rpc>` எனப் பதிவுகளில் இடம்பெற்று, OmniRoute API விசைக்கும் அதைச்
சேவையளித்த இணைப்புக்கும் உரியதாகக் குறிக்கப்படும்.

### தோல்வி நிலைகள்

| சூழ்நிலை                                                       | CLI-க்கான பதில்                                                        |
| -------------------------------------------------------------- | ---------------------------------------------------------------------- |
| அறியப்படாத OmniRoute விசை மற்றும் `REQUIRE_API_KEY=true`       | பரிமாற்றத்தின்போது 401 `unauthenticated`                               |
