இந்த ஆவணம் [Issue #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854)-க்கான செயலாக்கத் தீர்மானத்தைப் பதிவு செய்கிறது. பொதுப் பயன்பாட்டுத் தயாரிப்புகள் நான்கு வழங்குநர் குடும்பங்களாகக் குறிப்பிடப்படுகின்றன. பிராந்தியம் என்பது இணைப்புத் தரவு; அது ஒரு தனித் தயாரிப்பு அல்ல.

## தீர்மானம்

| வழங்குநர் குடும்பம்                                    | OmniRoute ID            | உலகளாவிய பிராந்தியம் | சீனப் பிராந்தியம் |
| ------------------------------------------------------ | ----------------------- | -------------------- | ----------------- |
| Alibaba Cloud Model Studio (பயன்பாட்டிற்கேற்ப கட்டணம்) | `alibaba`               | சிங்கப்பூர்          | பெய்ஜிங்          |
| Alibaba Cloud Token Plan                               | `bailian-coding-plan`   | சிங்கப்பூர்          | பெய்ஜிங்          |
| Qwen Cloud (பயன்பாட்டிற்கேற்ப கட்டணம்)                 | `qwen-cloud`            | உலகளாவியது           | பெய்ஜிங்          |
| Qwen Cloud Token Plan                                  | `qwen-cloud-token-plan` | சிங்கப்பூர்          | பெய்ஜிங்          |

ஏற்கனவே உள்ள `alibaba-cn` ID, சேமிக்கப்பட்ட இணைப்புகள், மாதிரி வழித்தடங்கள், சேர்க்கைகள் மற்றும் வரலாற்றுப் பயன்பாடு ஆகியவற்றுக்கான இயக்கநேரப் பின்னோக்கிய இணக்கத்தன்மை மாற்றுப் பெயராகத் தொடர்கிறது. அதன் கட்டுப்பாட்டுப் பலகை அட்டை `alibaba`-இல் ஒருங்கிணைக்கப்படுகிறது; தரவுத்தளத்தை மீண்டும் எழுத வேண்டியதில்லை.

Qwen Cloud-இன் பயன்பாட்டிற்கேற்பக் கட்டணத் திட்டமும் Alibaba Cloud Model Studio-வும் தற்போது DashScope-இணக்கமான இயக்கநேர ஹோஸ்ட்களைப் பகிர்ந்துகொள்கின்றன. ஆனால் பயனர்கள் வெவ்வேறு தயாரிப்பு இடைமுகங்கள் வழியாக விசைகளைப் பெற்று கணக்குகளை நிர்வகிப்பதால், அவை தனித்தனி வழங்குநர் அடையாளங்களாகவே தொடர்கின்றன. Alibaba மற்றும் Qwen Cloud Token Plan தயாரிப்புகள் வெவ்வேறு முனைப்புள்ளி குடும்பங்களைப் பயன்படுத்துகின்றன; எனவே நான்கு தயாரிப்புகளும் தனித்தனி வழங்குநர் ID-களாகவே தொடர்கின்றன.

API விசையும் முனைப்புள்ளியும் ஒரே தயாரிப்பையும் பிராந்தியத்தையும் சேர்ந்தவையாக இருக்க வேண்டும். ஒரு பிராந்தியத்தைத் தேர்ந்தெடுப்பது, சரிபார்ப்பு மற்றும் வழக்கமான கோரிக்கைகள் பயன்படுத்தும் முன்னமைக்கப்பட்ட முனைப்புள்ளியை மாற்றுகிறது.

## இணைப்பு ஒப்பந்தம்

புதிய இணைப்புகள் நிலையான பிராந்திய விசையை `providerSpecificData`-இல் சேமிக்கின்றன:

```json
{
  "region": "global-sg"
}
```

அனுமதிக்கப்பட்ட மதிப்புகள் `global-sg` மற்றும் `china-beijing` ஆகும். முனைப்புள்ளி, வழங்குநர் ID மற்றும் பிராந்தியத்தின் அடிப்படையில் மையமாகப் பெறப்படுகிறது. முன்னமைக்கப்படாத `providerSpecificData.baseUrl`, வெளிப்படையான இயக்குநர் மேலெழுதலாகத் தொடர்வதுடன் முன்னுரிமை பெறுகிறது; அதே நேரத்தில் பழைய சேமிக்கப்பட்ட முன்னமைவு URL-கள் மீண்டும் பிராந்திய அணிக்கு இயல்பாக்கப்படுகின்றன.

இது இணைப்புத் திட்டவடிவத்தை விரிவாக்கக்கூடியதாக வைத்திருக்கிறது: மற்றொரு வழங்குநர் அட்டையை உருவாக்காமலும் சேமிக்கப்பட்ட வழங்குநர் ID-களை மாற்றாமலும் மற்றொரு பிராந்தியத்தைத் தீர்வியில் சேர்க்க முடியும்.

## இணக்கத்தன்மை மற்றும் வெளியீடு

1. பிராந்திய endpoint resolver-ஐச் சேர்த்து, தற்போதைய உலகளாவிய இயல்புநிலைகளைத் தக்கவைக்கவும்.
2. `alibaba`, அதன் `alibaba-cn` இணக்கத்தன்மை ID மற்றும் `qwen-cloud` ஆகியவற்றுக்கு நேரடி பிராந்திய DashScope `/models` கண்டறிதலைப் பயன்படுத்தவும். பொதுவான endpoint படம், வீடியோ, ஆடியோ, embedding மற்றும் பிற chat அல்லாத மாடல்களையும் திருப்பித் தருவதால், அவற்றின் பதில்கள் முதலில் ஒரு உரை உருவாக்கல் வடிகட்டியைக் கடக்கின்றன. அதன் பின்னர் `qwen-cloud`, அதன் provider registry-இல் அறிவிக்கப்பட்டுப் பராமரிக்கப்படும் allowlist-ஐப் பயன்படுத்துகிறது. Alibaba Model Studio மற்றும் Qwen Cloud தற்போது ஒரே runtime host-களைப் பகிர்ந்தாலும், தனித்தனியாகத் தேர்ந்தெடுத்த catalog-களை வைத்திருக்கின்றன.
3. தற்போதைய Token Plan உரை-மாடல் allowlist உடன் `qwen-cloud-token-plan`-ஐப் பதிவு செய்யவும்.
4. இணைப்பைச் சேர்க்கும்/திருத்தும் உரையாடல்களில் வகையிடப்பட்ட பிராந்தியத் தேர்வியைச் சேர்க்கவும்.
5. நகல் `alibaba-cn` card-ஐ மறைத்து, அதன் தற்போதைய இணைப்புகளை `alibaba` provider பக்கத்தில் சேர்க்கவும்.
6. மேம்பட்ட மற்றும் workspace-சார்ந்த deployment-களுக்குத் தனிப்பயன் endpoint override-கள் தொடர்ந்து கிடைக்குமாறு வைத்திருக்கவும்.

Token Plan ஊடக மாடல்கள் பிரத்யேக endpoint-களைப் பயன்படுத்துவதால், அவை chat catalog-க்கு வெளியேயே இருக்கும்.
`wan2.7-image` மற்றும் `wan2.7-image-pro` ஆகியவை `open-sse/config/imageRegistry.ts`-இல் பதிவு செய்யப்பட்டுள்ளன;
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` மற்றும் `happyhorse-1.1-r2v` ஆகியவை
`open-sse/config/videoRegistry.ts`-இல் பதிவு செய்யப்பட்டுள்ளன. இரண்டு registry-களும் `qwen-cloud-token-plan` இணைப்பு அடையாளத்தையும் அதன் பிராந்தியத்திற்குரிய credential-களையும் மீண்டும் பயன்படுத்துகின்றன.

வழக்கமான Qwen Cloud, `qwen-cloud` அடையாளத்தின் கீழ் தனித்தனியான பயன்பாட்டுக்கேற்பக் கட்டணம் செலுத்தும் image மற்றும் video catalog-களைக் கொண்டுள்ளது. அதன் image மாடல்கள் `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` மற்றும் `z-image-turbo` ஆகும். அதன் video
மாடல்கள் `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` மற்றும்
