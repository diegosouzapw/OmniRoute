`chatgpt-web-codex` (`cgpt-codex` என்ற மாற்றுப்பெயர்) அங்கீகரிக்கப்பட்ட ChatGPT உலாவி அமர்வு வழியாக Codex Responses திருப்பங்களை இணைக்கிறது. இது நிறுத்தப்பட்ட பொதுவான `chatgpt-web` வழங்குநரிலிருந்து தனிப்பட்டது மற்றும் upstream v4.0.7 commit `b59d7dc51b84fb1f465ff1d00f5207f3b2b4a494` வழியாகப் புதுப்பிக்கப்பட்ட, `open-sse/vendor/codex-chatgpt-web/`-இன் கீழுள்ள MIT அறிவிப்புடன் கூடிய செயலாக்கத்தைப் பயன்படுத்துகிறது.

## பொதுவான வழங்குநரின் நிறுத்தம்

முன்னைய பொதுவான வழங்குநர் ID-களான `chatgpt-web` மற்றும் `cgpt-web` இனி விநியோகிக்கப்படுவதில்லை; ஏனெனில் அவற்றின் முன்-விசை/வேலைச் சான்றுச் செயலாக்கத்தின் மூலத்தை உறுதிப்படுத்த முடியவில்லை. சாய்வுக்கோட்டால் முன்னொட்டிடப்பட்ட மாதிரி ID-கள் மற்றும் சேமிக்கப்பட்ட மாற்றுப்பெயர்கள் உட்பட, இவ்விரு ID-களில் ஏதேனும் ஒன்றைத் தெளிவாகக் கோரும் கோரிக்கைகள், எந்த upstream கோரிக்கையும் செய்யப்படுவதற்கு முன்பே HTTP `410` மற்றும் **PROVIDER_RETIRED** குறியீட்டுடன் பாதுகாப்பாகத் தோல்வியடையும்.

இடம்பெயர்வு `168_retire_chatgpt_web.sql`, பொருந்தும் வழங்குநர் இணைப்புகளை tombstone செய்து, அவற்றின் செயலில் உள்ள அமர்வுக் குத்தகைகளைச் செல்லாததாக்குகிறது. இது இணைப்பு வரலாறு மற்றும் API-key அனுமதிப்பட்டியல்களைப் பாதுகாக்கிறது; மாற்று அணுகலை அனுமதிப்பட்டியலில் சேர்க்காது. Codex வழங்குநரும் அதன் இணைப்புகளும் இந்த நிறுத்தத்தால் பொருத்தப்படுவதில்லை.

## முன்தேவைகள்

- உள்நுழைந்துள்ள ChatGPT அமர்விலிருந்து முழுமையான Cookie header;
- npm, systemd மற்றும் PM2 நிறுவல்களுக்காக Chrome அல்லது Chromium மற்றும் வரைகலை அமர்வு அல்லது Xvfb காட்சி;
- Docker `web` profile உடன், `docker-compose.yml`-இலிருந்து உள்ளக Chromium சேவை;
- உள்ளக Codex கருவிகளுக்காக OpenAI `tunnel-client` v0.0.13 மற்றும் ChatGPT தனிப்பயன் connector.

கருவித் திருப்பங்களுக்கு மட்டுமே tunnel தேவைப்படுகிறது. `pro` உட்பட பட்டியலிடப்பட்ட ஒவ்வொரு route-உம், tunnel மற்றும் connector கட்டமைக்கப்பட்டிருக்கும்போது அதே திருப்பத்துடன் பிணைக்கப்பட்ட உள்ளகக் கருவித் திறனைப் பயன்படுத்தலாம்.

## Dashboard அமைப்பு

1. **ChatGPT Web (Codex)** வழங்குநரைத் திறந்து ஓர் இணைப்பைச் சேர்க்கவும்.
2. முழுமையான ChatGPT Cookie header, tunnel ID, runtime key மற்றும் தனிப்பயன் connector பெயரை ஒட்டவும். புதிய கருவித் திறனுள்ள அமைப்புகள், துல்லியமாக `OmniRoute Codex v2` என்று பெயரிடப்பட்ட புதிதாக உருவாக்கப்பட்ட connector-ஐப் பயன்படுத்த வேண்டும்; அதில் Authentication என்பது None என்றும் Permissions என்பது Allow all actions என்றும் அமைக்கப்பட்டிருக்க வேண்டும்.
3. இணைப்புச் சரிபார்ப்பை இயக்கவும். OmniRoute உலாவி ஆதரவுள்ள Temporary Chat-ஐத் திறந்து, அந்தக் கணக்கிற்கு Sol மற்றும் Pro கிடைக்கின்றனவா என்பதைக் கண்டறியும்.
4. இணைப்பைச் சேமிக்கவும். OmniRoute ஒட்டப்பட்ட cookie-ஐச் சரிபார்க்கப்பட்ட Playwright storage state-ஆல் மாற்றி, மறைகுறியாக்கப்பட்ட credential abstraction வழியாக runtime key உடன் அதைச் சேமிக்கிறது.

வெற்றிகரமாகச் சேமித்த பிறகு மூல cookie தக்கவைக்கப்படாது. அமர்வு காலாவதியாகும்போது, இணைப்பைத் திறந்து, புதிய முழுமையான Cookie header-ஐ ஒட்டி, சரிபார்ப்பை மீண்டும் இயக்கவும். திருத்த உரையாடலில் உள்ள doctor நிலை, உலாவி, storage state, உள்நுழைவு, Temporary Chat, tunnel, connector மற்றும் கருவிச் சுற்றுப்பயணம் ஆகியவற்றைத் தனித்தனியாக அறிக்கையிடுகிறது.

> உண்மையான cookie, runtime key, storage state அல்லது capability token-ஐ ஒருபோதும் commit செய்யாதீர்கள். சோதனை மற்றும்
> ஆவண மதிப்புகள் எப்போதும் placeholder-களாகவே இருக்க வேண்டும்.

## மாதிரிகள் மற்றும் combo-கள்

நிலையான மாதிரி route-கள்:

- `chatgpt-web-codex/luna` — GPT-5.6 Luna, குறைந்த முயற்சி
- `chatgpt-web-codex/think` — GPT-5.6 Luna, நடுத்தர முயற்சி
- `chatgpt-web-codex/instant`
- `chatgpt-web-codex/medium`
- `chatgpt-web-codex/high`
- `chatgpt-web-codex/extra-high`
- `chatgpt-web-codex/pro`

வேறு எந்த மாதிரியையும் போல, இவற்றில் ஒன்றை ஒரு combo-வில் சேர்க்கவும். Codex செயலி வழக்கமான Responses endpoint ஆன `/v1/responses`-க்கு combo பெயரை `model` ஆக அனுப்புகிறது; தனியான Codex endpoint அல்லது mode switch எதுவும் இல்லை.

Free/Go கணக்குகள் Luna route-களை வழங்குகின்றன. Sol திறனுள்ள கணக்குகள் Instant முதல் High வரை வழங்குகின்றன; Pro திறனுள்ள கணக்குகள் கூடுதலாக Extra High மற்றும் Pro-ஐ வழங்குகின்றன. ஒவ்வொரு route-க்கும் நிலையான backend model மற்றும் reasoning effort உள்ளன; முரண்படும் வெளிப்படையான Responses effort, தேர்ந்தெடுக்கப்பட்ட உலாவி mode-ஐ அமைதியாக மாற்றுவதற்குப் பதிலாக பாதுகாப்பாகத் தோல்வியடையும்.

பழைய `Codex Native` அல்லது `OmniRoute Codex` connector-ஐ மறுபெயரிடவோ மீண்டும் பயன்படுத்தவோ வேண்டாம். ChatGPT, connector அடையாளத்தின் அடிப்படையில் பொது MCP contract-ஐ cache செய்கிறது; அதேவேளையில் புதுப்பிக்கப்பட்ட bridge ஒரு புதிய நேரடி turn-token contract-ஐப் பயன்படுத்துகிறது. runtime அந்தப் பழைய அடையாளங்களை நிராகரித்து, புதிய `OmniRoute Codex v2` connector-ஐக் கட்டாயப்படுத்துகிறது.

## பாதுகாப்பு மாதிரி

- நேட்டிவ் பாதைக்கு ஒரு Responses கோரிக்கையும், அங்கீகரிக்கப்பட்ட Codex கிளையண்டும், பொருந்தும்
  thread மற்றும் turn அடையாளங்களும் தேவை.
- Workspace, sandbox, ஒப்புதல் கொள்கை மற்றும் கருவிப் பட்டியல் ஆகியவை நேட்டிவ் Codex shell-இலிருந்து வருகின்றன;
  கட்டற்ற வடிவிலான prompt உரை அவற்றுக்கான அதிகாரம் அல்ல.
- ஒவ்வொரு turn-க்கும் குறுகிய காலம் மட்டுமே செல்லுபடியாகும் capability-ஐ ChatGPT பெறுகிறது. அந்தத் துல்லியமான
  turn-இல் Codex வழங்கிய கருவிகளை மட்டுமே MCP broker ஏற்கிறது.
- **Allow once** என்பதைத் தானாக உறுதிப்படுத்துவது, கருவிக் கோரிக்கையை Codex-க்குத் திருப்பி அனுப்புவது மட்டுமே. ஒப்புதல் மற்றும்
  செயல்படுத்தல் குறித்து Codex மட்டுமே முடிவெடுக்கிறது.
- முதல் output-க்கு முன், ஒரு சேர்க்கை வேறொரு இணக்கமான target-க்கு மாறக்கூடும். Output
  தொடங்கிய பிறகு, turn முடியும் வரை provider, model, connection மற்றும் browser turn ஆகியவை நிலையாகப்
  பிணைக்கப்பட்டிருக்கும்.
- Cookies, runtime keys, storage state மற்றும் capability tokens ஆகியவை provider
  responses அல்லது request logs-இல் தோன்றாது.

## காட்சித்திரையற்ற VPS மற்றும் Docker

npm, systemd மற்றும் PM2 நிறுவல்களுக்கு, பொதுவான Chrome மற்றும் Chromium பாதைகளை OmniRoute கண்டறிகிறது.
மாற்றாக, `CHATGPT_WEB_CODEX_CHROME_PATH` என்பதை அமைக்கவும். ChatGPT உண்மையான headless browser வடிவத்தை
நிராகரிப்பதால், runtime turn-கள் திட்டமிட்டே UI-உடன் கூடிய Chrome-ஐப் பயன்படுத்துகின்றன. எனவே காட்சித்திரையற்ற host ஒன்று
தனிப்பட்ட Xvfb display-உடன் OmniRoute-ஐ இயக்க வேண்டும்; Chrome பாதையை மட்டும் அமைப்பது display-ஐ வழங்காது.

Docker `web` profile, உள் Compose network-இல் `chatgpt-web-codex-browser`-ஐத்
தொடங்குகிறது. Sidecar, Xvfb-க்குள் UI-உடன் கூடிய Chrome-ஐ இயக்குவதால், இயற்பியல் display தேவையில்லை. அதன் CDP
port host-இல் வெளியிடப்படாது. பாதுகாக்கப்பட்ட browser profile volume,
OmniRoute data volume-இலிருந்து தனியாக உள்ளது; மேலும் browser-க்குப் போதுமான shared memory வழங்கப்படுகிறது. உள் CDP proxy,
Compose network-க்குள் உள்ள port `9223`-இல் மட்டுமே கேட்கிறது; sidecar-இல் Chrome தொடர்ந்து loopback-உடன்
பிணைக்கப்பட்டிருக்கும்.

`DATA_DIR`-இன் கீழுள்ள supervisor lease, பல OmniRoute செயல்முறைகள் ஒரே tunnel மற்றும்
broker state-ஐ உரிமையாக்குவதைத் தடுக்கிறது. முரண்பாடு ஒன்று doctor மூலம் அறிவிக்கப்படுகிறது.

## ஊடாடும் மீட்பு

தானியக்க Docker பாதையில் host-க்குப் புலப்படும் window இல்லை; ஆனால் தனிப்பட்ட Xvfb
display-க்குள் Chrome UI-உடன் இயங்குகிறது. ChatGPT-க்கு ஊடாடும் sign-in அல்லது challenge தேவைப்படும்போது, ஏற்கனவே உள்ள VNC
browser உட்கட்டமைப்பை மீட்புக்குப் பயன்படுத்தலாம். Browser UI மற்றும் CDP ஆகியவை loopback,
அங்கீகரிக்கப்பட்ட management connection அல்லது SSH tunnel வழியாக மட்டுமே அணுகக்கூடியதாக இருக்க வேண்டும்; இயல்பான செயல்பாட்டின்போது noVNC முடக்கப்பட்டிருக்கும்.

## WebSocket மாற்றுவழி

ஒரு சேர்க்கையில் ChatGPT Web (Codex) இருக்கும்போது, Responses WebSocket bridge ஆனது
upstream-உடன் இணைவதற்கு முன் HTTP/SSE மாற்றுவழியைக் கோருகிறது. பின்னர் பரிமாற்றம்
`/v1/responses` வழியாகச் செல்கிறது.
