Web Cookie வழங்குநர்கள், API key-க்கு பதிலாக உங்களுடைய தற்போதைய உலாவி அமர்வைப் பயன்படுத்தி OmniRoute ஓர் AI சேவையைப் பயன்படுத்த அனுமதிக்கின்றனர். ஒரு சேவையின் வலைத்தளத்தின் மூலம் உங்களுக்கு ஏற்கனவே அணுகல் இருந்து, அதே அங்கீகரிக்கப்பட்ட அமர்வை OmniRoute பயன்படுத்த வேண்டும் என நீங்கள் விரும்பும்போது இவை பயனுள்ளதாக இருக்கும்.

API-key வழங்குநர்களைப் போலல்லாமல், Web Cookie வழங்குநர்கள், வலைத்தளத்திற்கு உங்கள் உலாவி அனுப்பும் நற்சான்றுகளைப் பயன்படுத்தி அங்கீகரிக்கின்றனர்.

# தொடங்குவதற்கு முன்

> **முக்கியம்:** நற்சான்றுகளை எப்போதும் உங்கள் உலாவியின் cookie சேமிப்பகத்திலிருந்து அல்லாமல், **நேரடி network request** ஒன்றிலிருந்து நகலெடுக்கவும்.

தவறான இடத்திலிருந்து cookies-ஐ நகலெடுப்பதால் பல அங்கீகாரச் சிக்கல்கள் ஏற்படுகின்றன.

## Cookie சேமிப்பகத்திலிருந்து நகலெடுக்க வேண்டாம்

பெரும்பாலான உலாவிகள் சேமிக்கப்பட்ட cookies-ஐப் பின்வரும் வழியில் காட்டுகின்றன:

```
DevTools
→ Application (அல்லது Storage)
→ Cookies
```

இந்த cookies சரியாகத் தோன்றினாலும், அவை:

- காலாவதியானவையாக இருக்கலாம்
- முழுமையற்றவையாக இருக்கலாம்
- அங்கீகரிக்கப்பட்ட requests-இல் மட்டும் அனுப்பப்படும் cookies இல்லாமல் இருக்கலாம்

இந்த மதிப்புகள் செல்லுபடியாகத் தோன்றினாலும், அவற்றைப் பயன்படுத்துவது அங்கீகாரத் தோல்விகளை ஏற்படுத்தக்கூடும்.

## நேரடி Request ஒன்றிலிருந்து நகலெடுக்கவும்

அதற்குப் பதிலாக, வெற்றிகரமான request ஒன்றிலிருந்து cookies-ஐப் பயன்படுத்தவும்:

```
DevTools
→ Network
→ பக்கத்தைப் புதுப்பிக்கவும்
→ chat அல்லது conversation request ஒன்றைத் திறக்கவும்
→ Request Headers
→ Cookie
```

உங்கள் உலாவி வெற்றிகரமாகப் பயன்படுத்திய துல்லியமான அங்கீகாரத் தகவல் `Cookie` request header-இல் உள்ளது.

பெரும்பாலான Web Cookie வழங்குநர்களுக்கு, OmniRoute-இல் ஒட்ட வேண்டிய மதிப்பு இதுவாகும்.

# பொதுவான அமைப்பு

பெரும்பாலான Web Cookie வழங்குநர்களுக்கு அமைவுச் செயல்முறை ஒரே மாதிரியாக இருக்கும்.

1. வழங்குநரின் வலைத்தளத்தில் உள்நுழையவும்.
2. உலாவியின் Developer Tools-ஐத் திறக்கவும்.
3. **Network** tab-ஐத் திறக்கவும்.
4. பக்கத்தைப் புதுப்பிக்கவும்.
5. அங்கீகரிக்கப்பட்ட chat அல்லது conversation request ஒன்றைத் திறக்கவும்.
6. தேவையான அங்கீகார நற்சான்றுகளை நகலெடுக்கவும்.
7. OmniRoute-ஐத் திறக்கவும்.
8. **Providers → Add Provider** என்பதற்குச் செல்லவும்.
9. உங்கள் Web Cookie வழங்குநரைத் தேர்ந்தெடுக்கவும்.
10. நற்சான்றுகளை ஒட்டவும்.
11. **Test Connection** என்பதைக் கிளிக் செய்யவும்.
12. வழங்குநரைச் சேமிக்கவும்.

தேவைப்படும் துல்லியமான நற்சான்றுகள் வழங்குநரைப் பொறுத்து மாறுபடும்.

# வழங்குநர் நற்சான்று வடிவங்கள்

வெவ்வேறு வலைத்தளங்கள் அங்கீகாரத் தகவலை வெவ்வேறு விதங்களில் சேமிக்கின்றன. சிலவற்றுக்கு cookies மட்டும் தேவைப்படும்; மற்றவற்றுக்கு கூடுதல் headers அல்லது tokens தேவைப்படலாம்.

| வழங்குநர்                       | நற்சான்று வடிவம்              | வழங்குநர் வழிகாட்டி              |

| ChatGPT Web (Codex)             | முழு Cookie header            | `docs/providers/CHATGPT_WEB.md`  |

| Microsoft 365 Copilot (BizChat) | WS access_token + chathubPath | `docs/providers/COPILOT-M365.md` |
| Grok Web                        | _(சரிபார்க்கவும்)_            |                                  |
| ...                             | ...                           | ...                              |

> புதிய Web Cookie வழங்குநர்கள் சேர்க்கப்படும்போதோ அல்லது ஏற்கனவே உள்ள வழங்குநர்களின் அங்கீகாரத் தேவைகள் மாறும்போதோ இந்த அட்டவணையைப் புதுப்பிக்கவும்.

## NoTrack (notrack-web)

NoTrack ([notrack.ai](https://notrack.ai)) என்பது பதிவுசெய்தல் தேவையில்லாத இலவச நுகர்வோர் அரட்டைத் தளமாகும் — முதல் வருகையின்போது அமர்வு அநாமதேயமாக உருவாக்கப்பட்டு, `uid`, `si_usr_id`, மற்றும் `si_ses_id` ஆகிய மூன்று குக்கிகள் வழியாகத் தொடர்கிறது. OmniRoute, ஒற்றை மாதிரி ஐடி (`notrack-c`, மாற்றுப்பெயர் `ntw`) மூலம் அதே `/api/dispatch` முனைப்புள்ளியைப் பதிலாளியாக்குகிறது.

### இணைப்பதற்கான படிகள்

1. உங்கள் உலாவியில் [notrack.ai](https://notrack.ai)-ஐத் திறந்து, அநாமதேய அமர்வு குக்கி அமைக்கப்பட அனுமதிக்கவும்.
2. **DevTools → Network**-ஐத் திறந்து, பக்கத்தைப் புதுப்பித்து, ஏதேனும் `/api` கோரிக்கையைக் கிளிக் செய்யவும்.
3. **Request Headers** பகுதியில், முழுமையான `Cookie` தலைப்பு மதிப்பை நகலெடுக்கவும்.
4. OmniRoute-இல், **Providers → Add Provider → NoTrack Web (Free)** என்பதற்குச் செல்லவும்.
5. குக்கி சரத்தை `apiKey` புலத்தில் ஒட்டி, **Save** என்பதைக் கிளிக் செய்யவும்.

ஒட்டப்பட்ட சரத்திலிருந்து `uid`, `si_usr_id`, மற்றும் `si_ses_id` ஆகியவற்றை OmniRoute பிரித்தெடுத்து, அந்த இணைகளைக் கொண்டு மட்டும் ஒரு சுத்தமான `Cookie` தலைப்பை மீண்டும் உருவாக்குகிறது — மேலும், அது இருந்தால் `nt_session`-ஐயும் (உள்நுழைந்த கணக்குகளுக்காக அமைக்கப்படும் `ntk_…` டோக்கன்) சேர்க்கிறது. இந்த மூன்றில் ஏதேனும் ஒன்று இல்லாவிட்டால், மாற்று வடிவமைப்புகளுடன் இயக்குநர்கள் பரிசோதிக்க ஏதுவாக, ஒட்டப்பட்ட மூலச் சரம் மாற்றமின்றி அனுப்பப்படுகிறது.

### மாதிரி ஐடிகள்

| மாதிரி ஐடி  | காட்சிப் பெயர் | குறிப்புகள்                                                            |
| ----------- | -------------- | ---------------------------------------------------------------------- |
| `notrack-c` | NoTrack C      | இயல்புநிலை — மேல்நிலை அனுப்பீட்டு மாதிரி `C`.                          |
| `C`         | NoTrack C      | `notrack-c`-க்கான மாற்றுப்பெயர் (மூல மேல்நிலை அனுப்பீட்டுக் குறியீடு). |
| `notrack`   | NoTrack C      | `notrack-c`-க்கான மாற்றுப்பெயர்.                                       |
| `ntw`       | NoTrack C      | `notrack-c`-க்கான குறுகிய மாற்றுப்பெயர்.                               |

நான்கு மாதிரி ஐடிகளும் ஒரே மேல்நிலை அனுப்பீட்டு மாதிரியுடன் (`C`) இணைக்கப்படுகின்றன.

### கோரிக்கை விருப்பங்கள்

கோரிக்கை உடற்பகுதியில் பின்வரும் விருப்பப் புலங்களை இயக்கி ஏற்றுக்கொள்கிறது:

| உடற்பகுதிப் புலம்     | இயல்புநிலை | நோக்கம்                                                                           |
| --------------------- | ---------- | --------------------------------------------------------------------------------- |
| `notrack_mode`        | `usual`    | அனுப்பீட்டு முறை (கட்டற்ற வடிவிலான சரம்; மேல்நிலை `usual`, … ஆகியவற்றை ஏற்கிறது)  |
| `notrack_max_turns`   | `6`        | பதிலளிப்பதற்கு முன் மேல்நிலை மேற்கொள்ளக்கூடிய உள் சுற்றுகளின் எண்ணிக்கை.          |
| `notrack_chat_id`     | `null`     | ஏற்கெனவே உள்ள மேல்நிலை அரட்டையைத் தொடரவும் (புதிய அரட்டைக்கு இதைத் தவிர்க்கவும்). |
| `notrack_attachments` | `[]`       | மேல்நிலை இணைப்பு விவரிப்பான்களின் நேரடி கடத்தல் வரிசை.                            |
| `notrack_regenerate`  | `false`    | முந்தைய சுற்றுக்கான பதிலை மீண்டும் உருவாக்கக் கோர, `true` என அமைக்கவும்.          |

### திறன்கள்

- **ஸ்ட்ரீமிங் மற்றும் ஸ்ட்ரீமிங் அல்லாத** அரட்டை நிறைவுகள்.
- **கருவி அழைப்பு** — கோரிக்கையில் `tools: [...]` என்பதை அமைக்கவும்; இயக்கி அவற்றை ஒரு கருவி-அழைப்பு உறை ஒப்பந்தமாகத் தொடராக்கம் செய்து, மாதிரியின் பதில்களை மீண்டும் OpenAI `tool_calls` ஆகப் பகுத்தறிகிறது.
- **`response_format`** — `json_object` மற்றும் `json_schema` ஆதரிக்கப்படுகின்றன. மாதிரியின் பதிலிலிருந்து முதல் JSON பொருளை இயக்கி பிரித்தெடுத்து, திருப்பியனுப்பும் முன் அதைச் சரமாக்குகிறது.
- **பகுத்தறிதல் குறிப்பு** — மேல்நிலை ஒரு `thinking` நிகழ்வை அனுப்பும்போது, இயக்கி ஒரு `reasoning` டெல்டாவை வெளியிடுகிறது.

### வரம்புகள்

- மேல்நிலை அநாமதேயப் பயன்பாட்டு ஒதுக்கீடுகளை அமல்படுத்துகிறது — வரம்பு எட்டப்படும்போது, இயக்கி பயனருக்கு ஏற்ற செய்தியுடன் 429-ஐ வெளிப்படுத்துகிறது.
- அனைத்து மாதிரி ஐடிகளும் ஒரே மேல்நிலை அனுப்பீட்டு மாதிரிக்கே தீர்மானிக்கப்படுகின்றன; ஒவ்வொரு மாதிரிக்கும் தனித்தனி மாற்றி இல்லை.
- இயக்கி மேல்நிலையின் `/api/chats` முனைப்புள்ளியை அழைப்பதில்லை, எனவே அரட்டை வரலாறு / அமர்வுகள் தானாக நிர்வகிக்கப்படுவதில்லை. ஏற்கெனவே உள்ள மேல்நிலை அரட்டையைத் தொடர `notrack_chat_id`-ஐப் பயன்படுத்தவும்.

# வலைக் குக்கி வழங்குநர்களால் என்ன செய்ய முடியும் மற்றும் என்ன செய்ய முடியாது

வலைக் குக்கி வழங்குநர்கள் ஒரு இணையதளத்தின் அரட்டை இடைமுகத்தை மீண்டும் பயன்படுத்துகின்றனர். அவை அதிகாரப்பூர்வ API-களைப் போன்ற அதே திறன்களை **வழங்குவதில்லை**.

## ஆதரிக்கப்படுபவை

- உங்கள் தற்போதைய உலாவி அமர்வைப் பயன்படுத்தி அங்கீகரித்தல்
- உங்கள் கணக்கின் மூலம் கிடைக்கும் மாடல்களை அணுகுதல்
- அரட்டை பதில்களை ஸ்ட்ரீம் செய்தல்
- API விசை தேவையில்லை

## ஆதரிக்கப்படாதவை

- செயல்பாடு அழைத்தல்
- கருவி அழைத்தல்
- தானியங்கி கோப்புத் திருத்தம்
- தன்னாட்சி முகவர் சார்ந்த IDE பணிப்பாய்வுகள்
- API-க்கு மட்டும் உரிய அம்சங்கள்

இது எதிர்பார்க்கப்படும் நடத்தையாகும்; இது ஒரு பிழை **அல்ல**.

உங்களுக்குக் கருவிச் செயலாக்கம், தானியங்கி கோப்புத் திருத்தம் அல்லது பிற முகவர் பணிப்பாய்வுகள் தேவைப்பட்டால், Web Cookie வழங்குநருக்குப் பதிலாக **API-key provider** ஒன்றைப் பயன்படுத்தவும்.

# சரிபார்ப்பு தொடர்பான எச்சரிக்கை

வெற்றிகரமான **Test Connection** அல்லது குக்கீ சரிபார்ப்பு, வழங்கப்பட்ட நற்சான்றுகள் எதிர்பார்க்கப்படும் வடிவமைப்பில் இருப்பதாகத் தோன்றுவதை மட்டுமே உறுதிப்படுத்துகிறது.

Issue #7857 தீர்க்கப்படும் வரை, வெற்றிகரமான சரிபார்ப்பு, வழங்குநரால் வெற்றிகரமாக அங்கீகரிக்க முடியும் என்பதற்கு **உத்தரவாதம் அளிக்காது**.

அங்கீகாரம் தொடர்ந்து தோல்வியடைந்தால், உலாவியின் குக்கீ சேமிப்பகத்திலிருந்து நற்சான்றுகளை நகலெடுக்காமல், செயலிலுள்ள ஒரு பிணையக் கோரிக்கையிலிருந்து அவற்றை நகலெடுத்தீர்களா என்பதைச் சரிபார்க்கவும்.

# சிக்கல் தீர்த்தல்

## அங்கீகாரம் தோல்வியடைகிறது

நற்சான்றுகள் பின்வரும் இடத்திலிருந்து நகலெடுக்கப்பட்டனவா என்பதைச் சரிபார்க்கவும்:

```
Network
→ Request Headers
→ Cookie
```

பின்வரும் இடத்திலிருந்து **அல்ல**:

```
Application
→ Cookies
```

## அமர்வு காலாவதியானது

Web Cookie வழங்குநர்கள் உங்கள் தற்போதைய உலாவி அமர்வைப் பயன்படுத்துகின்றனர்.

உங்கள் உலாவி அமர்வு காலாவதியானாலோ அல்லது நீங்கள் வெளியேறினாலோ, புதிய நற்சான்றுத் தொகுப்பை நகலெடுக்க வேண்டும். ஆதரிக்கப்படும் இணைய வழங்குநர்களுக்கான குக்கீ புதுப்பிப்பைத் தானியக்கமாக்க, துணைக் கருவியான [Browser Session Sync Extension](../guides/SESSION-SYNC-EXTENSION.md)-ஐப் பார்க்கவும்.
