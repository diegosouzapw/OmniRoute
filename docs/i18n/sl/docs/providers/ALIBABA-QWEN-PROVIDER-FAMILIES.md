Ta dokument beleži odločitev o implementaciji za
[težavo #7854](https://github.com/diegosouzapw/OmniRoute/issues/7854). Javni izdelki so
predstavljeni kot štiri družine ponudnikov. Regija je podatek o povezavi in ne ločen izdelek.

## Odločitev

| Družina ponudnika                              | ID OmniRoute            | Globalna regija | Regija Kitajska |
| ---------------------------------------------- | ----------------------- | --------------- | --------------- |
| Alibaba Cloud Model Studio (plačilo po porabi) | `alibaba`               | Singapur        | Peking          |
| Alibaba Cloud Token Plan                       | `bailian-coding-plan`   | Singapur        | Peking          |
| Qwen Cloud (plačilo po porabi)                 | `qwen-cloud`            | Globalno        | Peking          |
| Qwen Cloud Token Plan                          | `qwen-cloud-token-plan` | Singapur        | Peking          |

Obstoječi ID `alibaba-cn` ostaja združljivostni vzdevek med izvajanjem za shranjene povezave, poti
modelov, kombinacije in preteklo uporabo. Njegova kartica na nadzorni plošči je združena v `alibaba`;
prepis podatkovne zbirke ni potreben.

Qwen Cloud s plačilom po porabi in Alibaba Cloud Model Studio si trenutno delita izvajalna
gostitelja, združljiva z DashScope, vendar ostajata ločeni identiteti ponudnikov, ker uporabniki
pridobivajo ključe in upravljajo račune prek različnih vmesnikov izdelkov. Izdelka Alibaba in Qwen
Cloud Token Plan uporabljata različne družine končnih točk, zato vsi štirje izdelki ostajajo ločeni
ID-ji ponudnikov.

## Matrika končnih točk

| Družina ponudnika       | `global-sg`                                                              | `china-beijing`                                                      | Žični format |
| ----------------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------- | ------------ |
| `alibaba`               | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `bailian-coding-plan`   | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/apps/anthropic/v1`  | `https://token-plan.cn-beijing.maas.aliyuncs.com/apps/anthropic/v1`  | Anthropic    |
| `qwen-cloud`            | `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`                 | `https://dashscope.aliyuncs.com/compatible-mode/v1`                  | OpenAI       |
| `qwen-cloud-token-plan` | `https://token-plan.ap-southeast-1.maas.aliyuncs.com/compatible-mode/v1` | `https://token-plan.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` | OpenAI       |

Ključ API in končna točka morata pripadati istemu izdelku in regiji. Izbira regije spremeni
prednastavljeno končno točko, ki se uporablja za preverjanje veljavnosti in običajne zahteve.

## Pogodba povezave

Nove povezave shranjujejo stabilni ključ regije v `providerSpecificData`:

```json
{
  "region": "global-sg"
}
```

Dovoljeni vrednosti sta `global-sg` in `china-beijing`. Končna točka se centralno izpelje iz
ID-ja ponudnika in regije. Neprednastavljeni `providerSpecificData.baseUrl` ostaja izrecna
preglasitev upravljavca in ima prednost, medtem ko se stari shranjeni URL-ji prednastavitev
normalizirajo nazaj na regionalno matriko.

Tako ostaja shema povezave razširljiva: razreševalniku je mogoče dodati drugo regijo brez
ustvarjanja nove kartice ponudnika ali spreminjanja shranjenih ID-jev ponudnikov.

## Združljivost in uvedba

1. Dodajte razreševalnik regionalnih končnih točk in ohranite trenutne globalne privzete nastavitve.
2. Uporabite sprotno regionalno odkrivanje DashScope `/models` za `alibaba`, njegov združljivostni
   ID `alibaba-cn` in `qwen-cloud`. Njihovi odgovori najprej prestanejo filter za generiranje
   besedila, ker splošna končna točka vrača tudi modele za slike, video, zvok, vdelave in druge
   modele, ki niso namenjeni klepetu. `qwen-cloud` nato uporabi vzdrževani seznam dovoljenih
   modelov, deklariran v njegovem registru ponudnikov. Alibaba Model Studio in Qwen Cloud ohranjata
   ločena skrbno izbrana kataloga, čeprav trenutno uporabljata iste izvajalne gostitelje.
3. Registrirajte `qwen-cloud-token-plan` s trenutnim seznamom dovoljenih besedilnih modelov za Token Plan.
4. V pogovorna okna za dodajanje/urejanje povezav dodajte izbirnik regije z določenim tipom.
5. Skrijte podvojeno kartico `alibaba-cn` in vključite njene obstoječe povezave na stran ponudnika
   `alibaba`.
6. Ohranite možnost preglasitve končnih točk po meri za napredne uvedbe in uvedbe, specifične za delovni prostor.

Predstavnostni modeli Token Plan ostajajo zunaj kataloga za klepet, ker uporabljajo namenske
končne točke. `wan2.7-image` in `wan2.7-image-pro` sta registrirana v
`open-sse/config/imageRegistry.ts`; `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` in
`happyhorse-1.1-r2v` so registrirani v `open-sse/config/videoRegistry.ts`. Oba registra ponovno
uporabljata identiteto povezave `qwen-cloud-token-plan` in njene poverilnice, specifične za regijo.

Običajni Qwen Cloud ima ločena kataloga slik in videov s sprotnim plačevanjem pod identiteto
`qwen-cloud`. Njegovi slikovni modeli so `wan2.7-image-pro`, `wan2.7-image`, `qwen-image-3.0-pro`,
`qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0-2026-03-03` in `z-image-turbo`. Njegovi video
modeli so `happyhorse-1.1-i2v`, `happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`,
`happyhorse-1.0-video-edit`, `wan2.7-t2v`, `wan2.7-i2v`, `wan2.7-r2v-2026-06-12` in
`wan2.7-videoedit`. Ti modeli ponovno uporabljajo samo običajno povezavo `qwen-cloud` in regionalno
predstavnostno končno točko DashScope. Registra za Token Plan in sprotno plačevanje ne podedujeta
ali združujeta seznamov modelov drug drugega.

Identiteta `bailian-coding-plan` ima tudi lastna seznama dovoljenih predstavnostnih modelov:
`wan2.7-image`, `wan2.7-image-pro`, `qwen-image-2.0` in `qwen-image-2.0-pro` za generiranje
slik ter
`happyhorse-1.1-i2v`, `happyhorse-1.1-t2v` in `happyhorse-1.1-r2v` za generiranje
videov. Uporablja samo povezavo Bailian Coding Plan in regionalno končno točko Coding Plan.
Njegova registra slik in videov ne podedujeta ali se združujeta z nobenim od ponudnikov Qwen Cloud.

Običajna identiteta `alibaba` ima ločena seznama dovoljenih slikovnih in video modelov. Njeni
slikovni modeli so `qwen-image-3.0-pro`, `qwen-image-2.0-pro-2026-06-22`, `qwen-image-2.0`,
`z-image-turbo` in `wan2.6-t2i`. Njeni dodani video modeli so `happyhorse-1.1-i2v`,
`happyhorse-1.1-t2v`, `happyhorse-1.1-r2v`, `happyhorse-1.0-video-edit`,
`wan2.7-i2v-2026-04-25`, `wan2.6-i2v-flash`, `wan2.7-t2v-2026-06-12`,
`wan2.7-r2v-2026-06-12` in `wan2.7-videoedit`. Ti modeli uporabljajo samo povezavo Alibaba Model
Studio in njeno izbrano regionalno predstavnostno končno točko; niso dodani v noben register Coding
Plan ali Qwen Cloud.

Katalog klepetalnih modelov Qwen Cloud Token Plan sledi seznamu dovoljenih besedilnih modelov
Individual plan z natančnim ujemanjem nizov:
`qwen3.8-max-preview`, `qwen3.7-max`, `qwen3.7-plus`, `qwen3.6-flash`, `glm-5.2` in
`deepseek-v4-pro`. Vnosi Wan in HappyHorse pripadajo ločenim API-jem za generiranje slik/videov.

Alibaba Token Plan izpostavlja istih šest trenutnih ID-jev modelov za generiranje besedila prek
končne točke, združljive z Anthropic. Njegova možnost Singapur shranjuje obstoječi ključ regije
`global-sg`; od družin ponudnikov, ki regijo imenujejo Global, se razlikuje samo uporabniško vidna
oznaka.

Običajni katalog klepetalnih modelov Qwen Cloud je namenoma ožji od celotnega sprotnega besedilnega
odziva. Njegov vzdrževani seznam dovoljenih modelov je v
`open-sse/config/providers/registry/qwen-cloud/index.ts`; sprotno odkrivanje vrne samo ID-je, ki so
prisotni tako v odzivu nadrejene storitve kot na tem seznamu registra.

Alibaba Model Studio uporablja isto pravilo sprotnega preseka s svojim neodvisno vzdrževanim
seznamom dovoljenih modelov v `open-sse/config/providers/registry/alibaba/index.ts`. Združljivostni
ponudnik `alibaba-cn` ponovno uporablja ta katalog, odkrivanje pa razrešuje prek pekinške končne
točke.
