Ta dokument je potrdilo avtorja in vzdrževalca za šest ugotovitev
`AI-detected potential malware`, zaznanih pri `omniroute@3.8.5`, ter za
omilitvene ukrepe, izvedene v `omniroute@3.8.6`. Njegov namen je:

1. Upravljavcem varnostnih cevovodov zagotoviti enoten vir, na katerega se
   lahko sklicujejo pri presoji ugotovitev glede na dejansko izvorno kodo.
2. Prihodnjim pregledovalnikom z umetno inteligenco omogočiti, da zaznajo
   trditev, podpisano s strani vzdrževalca, da je vsaka označena pot namerna,
   izbirna in dokumentirana.
3. Zagotoviti pisni zapis o tem, _zakaj_ je vsako mesto klica oblikovano tako,
   kot je — da prihodnja predelava kode ne bi pomotoma znova uvedla prstnega
   odtisa, ki je bil namerno odstranjen.

Če upravljate pregledovalnik, ki po izdaji omilitvenih ukrepov v v3.8.6 znova
označi katero koli spodaj navedeno mesto klica, odprite težavo s sledjo
pregleda in tukaj bomo razširili potrdilo.

## §1 — Namestitev korenskega overitelja potrdil za MITM (`77484.js`)

**Izvorne datoteke**:

- `src/mitm/cert/install.ts` — javni `installCert()` / `uninstallCert()`,
  `installCertWindows/Mac/Linux` za posamezne platforme.
- `src/mitm/systemCommands.ts` — skupni pomožni mehanizmi `execFile` / `spawn` /
  PowerShell, ki jih uporabljajo namestitvene poti.

**Sprožilec**: uporabnik na lokalni nadzorni plošči na
`/dashboard/cli-tools/mitm` klikne »Omogoči posredniški strežnik MITM«. Pot je
omejena samo na povratno zanko — glejte strogo pravilo št. 17 v `CLAUDE.md` in
`src/server/authz/routeGuard.ts::isLocalOnlyPath()`. Razkriti JWT, izpostavljen
prek tunela, **ne more** sprožiti te poti kode.

**Izvedena privilegirana opravila (glede na platformo)**:

| OS                     | Ukaz(i)                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Windows                | `certutil -addstore Root <cert>` prek UAC                                                                         |
| macOS                  | `sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain <cert>`                     |
| Linux                  | `sudo cp <cert> <distro-trust-dir>` + `sudo update-ca-certificates` (Debian) / `sudo update-ca-trust` (RHEL/SUSE) |
| Linux+Firefox/Chromium | posodobitev zbirke podatkov NSS za posamezen profil prek `certutil -d sql:<profile>`                              |

To so isti ukazi, ki jih uporabljajo `mitmproxy`, Charles Proxy, Fiddler in
Caddy. Dejstvo, da so prisotni v OmniRoute, je dokumentirano v
`docs/security/STEALTH_GUIDE.md`.

**Omilitveni ukrepi v v3.8.6**:

- `runElevatedPowerShell()` ne uporablja več
  `-EncodedCommand <base64utf16le>`. Vsebina za izvedbo s povišanimi
  privilegiji se zapiše v začasno datoteko `.ps1` za posamezen klic (način
  0o600, znotraj zasebnega imenika `mkdtempSync`) in se navede prek `-File`.
  Datoteka se v bloku `finally` izbriše. S tem se odstrani značilen vzorec
  poviševanja privilegijev prek PowerShell z uporabo base64, ki ga je označil
  klasifikator umetne inteligence storitve Socket.dev.
- `installCertWindows` vsebuje vdelan blok `SECURITY-AUDITOR-NOTE:`, ki kaže
  sem.

**Zakaj to ohranjamo**: posredniški strežnik MITM je dokumentirana funkcija,
ki jo uporabljata `docs/security/STEALTH_GUIDE.md` in
`docs/frameworks/MITM-PROXY.md`. Njegova odstranitev bi okrnila nabor funkcij
mostu za agente.

## §2 — Uvoz poverilnic Zed (`app/api/providers/zed/import/route.js`)

**Izvorne datoteke**:

- `src/app/api/providers/zed/discover/route.ts` _(novo v v3.8.6)_
- `src/app/api/providers/zed/import/route.ts`
- `src/lib/zed-oauth/keychain-reader.ts`
- `src/lib/zed-oauth/credentialFingerprint.ts` _(novo v v3.8.6)_

**Sprožilec**: uporabnik klikne »Uvozi iz Zed« na strani Ponudniki na lokalni
nadzorni plošči. Dostop do končne točke je omejen z `requireManagementAuth`. Urejevalnik Zed
sam zapisuje svoje ključe API ponudnikov v shrambo poverilnic operacijskega sistema pod dokumentiranimi
imeni storitev — glejte https://zed.dev/docs/ai/llm-providers.

**Vedenje v3.8.5 (tisto, ki ga je označil Socket.dev)**:

`POST /import` je odkril poverilnice in jih samodejno shranil v lokalno
shrambo SQLite v enem samem povratnem klicu. Brez potrditve za posamezen račun, brez
prstnega odtisa, samo »najdenih N žetonov, vsi uvoženi«.

**Omilitev v3.8.6 — potrditev v 2 korakih**:

1. **`POST /api/providers/zed/discover`** vrne
   `{ candidates: [{ provider, service, account, fingerprint }] }`. Neobdelani
   žeton se **nikoli** ne prenese. Prstni odtis je
   `sha256(service|account|token).slice(0,16)`.
2. Nadzorna plošča prikaže seznam kandidatov, upravljavec izbere, katere želi
   uvoziti, in pošlje `{ confirmedAccounts: [{ service, account, fingerprint }] }`
   na **`POST /api/providers/zed/import`**.
3. Končna točka za uvoz **znova prebere shrambo poverilnic na strežniku** in filtrira po
   `(service, account, fingerprint)`. Prirejen ali ponovno predvajan odgovor
   odkrivanja ne more zavesti končne točke za uvoz, da bi shranila nepovezan žeton —
   če se je aktivni žeton od odkrivanja spremenil, se prstni odtis ne ujema več
   in poverilnica se preskoči.

Okoljska zastavica `OMNIROUTE_ZED_IMPORT_LEGACY_ONE_STEP=true` ohrani vedenje
v3.8.5 za upravljavce, ki še niso posodobili svoje avtomatizacije. Odstranjena
bo v v3.9.

**Zakaj to ohranjamo**: uvoz iz Zed je uporabniku najprijaznejši način začetne nastavitve za uporabnike,
ki že uporabljajo Zed in želijo svoje ključe ponudnikov preslikati v OmniRoute
brez ponovnega lepljenja.

## §3 — `execFile` / `spawn` / PowerShell s povišanimi pravicami (`21843.js`)

**Izvorne datoteke**: `src/mitm/systemCommands.ts`.

**Zakaj označeno**: paket znova izvozi `execFileWithPassword`,
`runElevatedPowerShell` in skupni pomožni program `quotePowerShell`. Klasifikator
UI storitve Socket.dev jih prepozna kot splošni »komplet orodij za izvajanje na gostitelju in povišanje
pravic«. Znotraj OmniRoute se uporabljajo samo na poti za namestitev potrdila MITM
(§1) in v `execFileWithPassword` za izvajanje ukazov `sudo`.

**Omilitev v3.8.6**:

- Preoblikovanje `runElevatedPowerShell` (glejte §1).
- Vgrajeni blok `SECURITY-AUDITOR-NOTE:` pri
  `runElevatedPowerShell` in `execFileWithPassword` dokumentira klicatelje na seznamu dovoljenih
  in fiksni seznam izvedljivih datotek.
- Klic `spawn()` v `execFileWithPassword` vsebuje oznako `nosemgrep` s
  seznamom dovoljenih izvedljivih datotek, ki jih pomožna funkcija sme prejeti —
  **uporabniški vnos nima nobene poti do `finalCommand`/`finalArgs`**.

## §4 / §6 — Nadzornik storitve 9router (`api/services/9router/{start,restart}/route.js`)

**Izvorne datoteke**:

- `src/app/api/services/9router/_lib.ts` — tovarna nadzornika.
- `src/app/api/services/9router/{start,stop,restart,status,install,update,auto-start}/route.ts`.
- `src/lib/services/ServiceSupervisor.ts` — splošni zagon / preverjanje zdravja / medpomnilnik dnevnika.

**Sprožilec**: uporabnik klikne »Namesti« / »Zaženi« na strani vdelanih storitev na
lokalni nadzorni plošči.

**Že uvedeni zaščitni ukrepi**:

- Vse poti `/api/services/*` so LOCAL_ONLY skladno z
  `src/server/authz/routeGuard.ts` (strogo pravilo št. 17). Uveljavljanje povratne zanke
  se izvede pred vsakim preverjanjem pristnosti — razkriti JWT jih ne more doseči.
- Vrstica 9router v zbirki podatkov je inicializirana kot `status='not_installed', auto_start=0` (glejte
  `src/lib/db/migrations/071_services.sql:19`). Storitev se ob prvem zagonu
  **ne** zažene.
- `spawn()` se pokliče s potjo binarne datoteke, ki jo vrne
  `resolveSpawnArgs(apiKey, PORT)` v `src/lib/services/installers/ninerouter.ts`,
  kar je fiksni seznam dovoljenih podprtih binarnih datotek.
- Stdout/stderr se shranjujeta v medpomnilnik v pomnilniku (omejitev 5 MB, glejte `_lib.ts`) — brez zapisovanja
  na disk, razen če uporabnik omogoči beleženje dnevnika na nadzorni plošči.

**Omilitev v3.8.6**: brez funkcionalnih sprememb. Minimalni profil gradnje
(`OMNIROUTE_BUILD_PROFILE=minimal`) nadomesti
`src/lib/services/installers/ninerouter.ts` z nadomestkom za uporabnike, ki želijo,
da so poti s povišanimi pravicami fizično odstranjene iz paketa.

**Zakaj to ohranjamo**: 9router je izbirna spremljevalna storitev, ki jo je mogoče namestiti lokalno
(podobno kot vtičnik za WordPress) — izključno na podlagi izrecne privolitve.

## §5 — Povratni zapis poverilnic OmniRoute Cloud Sync (`api/keys/[id]/route.js`)

**Izvorne datoteke**:

- `src/lib/cloudSync.ts` — `syncToCloud()` / `updateLocalTokens()`.
- `src/app/api/keys/[id]/route.ts` — prikliče `syncKeysToCloudIfEnabled()`.

**Sprožilec**: `isCloudEnabled()` vrne `true` (nastavljeno na nadzorni plošči) **in**
`CLOUD_URL` je konfiguriran. Ko sta obe možnosti izklopljeni, se odhodni omrežni
klic do končne točke Cloud ne izvede.

**Vedenje različice v3.8.5 (napaka, ki jo je Socket.dev pravilno zaznal)**:

`updateLocalTokens()` je prepisal `accessToken`, `refreshToken` in
`providerSpecificData` iz odgovora Cloud, kadar je veljalo
`cloudUpdatedAt > localUpdatedAt`. Brez HMAC-a, podpisa ali kontrolne vsote.
Napačno konfiguriran ali zlonameren `CLOUD_URL` (oziroma napadalec MITM v kanalu)
bi lahko neopazno zamenjal ponudnikove žetone OAuth.

**Omilitev v različici v3.8.6**:

1. **Preverjanje HMAC**: `verifyCloudSignature(rawBody, sigHeader)` preveri
   glavo `X-Cloud-Sig` (`HMAC-SHA256(OMNIROUTE_CLOUD_SYNC_SECRET,
rawBody)`) pred razčlenjevanjem JSON-a. Če je skrivnost nastavljena, je podpis
   obvezen. Če ni (podedovani način), se zabeleži opozorilo in odgovor se
   sprejme — v različici v3.9 bo skrivnost obvezna.
2. **Izrecna vključitev skrivnih polj**: `accessToken` / `refreshToken` /
   `providerSpecificData` se prepišejo **samo**, kadar je
   `OMNIROUTE_CLOUD_SYNC_SECRETS=true`. Privzeti način sinhronizira samo
   metapodatke, ki niso poverilnice (`expiresAt`, `status`, `lastError*`,
   `rateLimitedUntil`, `updatedAt`). To je **nezdružljiva sprememba** za uporabnike,
   ki so se zanašali na oddaljeno sinhronizacijo žetonov — izrecno jo morajo vključiti.

**Zakaj to ohranjamo**: Cloud Sync je edini način, da najemnik OmniRoute Cloud
centralizira poverilnice ekipe. Popravek jasno opredeljuje model groženj:
»strežnik podpiše, odjemalec preveri, upravljavec izrecno privoli.«

## Profil gradnje: `minimal`

Uporabniki, ki potrebujejo artefakt, prijazen do Socket, naj ga zgradijo z:

```bash
OMNIROUTE_BUILD_PROFILE=minimal npm run build
```

Webpackov `NormalModuleReplacementPlugin` štiri module preusmeri na nadomestke:

| Modul                                       | Nadomestek                                       |
| ------------------------------------------- | ------------------------------------------------ |
| `src/mitm/cert/install.ts`                  | `src/mitm/cert/install.stub.ts`                  |
| `src/lib/zed-oauth/keychain-reader.ts`      | `src/lib/zed-oauth/keychain-reader.stub.ts`      |
| `src/lib/cloudSync.ts`                      | `src/lib/cloudSync.stub.ts`                      |
| `src/lib/services/installers/ninerouter.ts` | `src/lib/services/installers/ninerouter.stub.ts` |

Vsak nadomestek izvaža enak vmesnik, vendar vsaka funkcija med izvajanjem sproži
`featureDisabledError(name)`. Poti, ki so odvisne od onemogočenega modula,
vrnejo HTTP 503 z jasnim sporočilom, namesto da bi aktivirale občutljivo
izvajalno pot.

Nastali paket je namenjen objavi kot `omniroute-secure`. Navodila za objavo so v
`docs/ops/PUBLISHING_SECURE.md`.
