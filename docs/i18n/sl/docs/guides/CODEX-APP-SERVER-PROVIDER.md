OmniRoute ponuja **dva** načina uporabe OpenAI Codex:

| Ponudnik               | Kako komunicira z OpenAI                                                                                                                                                                         | Opozorilo glede uporabe                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| **`codex`**            | Vaš žeton OAuth za ChatGPT/OpenAI neposredno posreduje API-ju Responses                                                                                                                          | **Da** — uradna seja ni pooblaščena za uporabo prek posredniškega strežnika/usmerjevalnika |
| **`codex-app-server`** | Upravlja **lastni `codex app-server` orodja Codex CLI** prek JSON-RPC/WebSocket; CLI upravlja in samodejno osvežuje svoj OAuth (`~/.codex/auth.json`) povsem enako kot interaktivna seja `codex` | **Ne** — OmniRoute žetona nikoli ne posreduje API-ju                                       |

Ker `codex-app-server` nikoli ne posreduje žetona, zanj ne velja
opozorilo glede uporabe zaradi posredovanja seje. Zahteva pa, da je **Codex CLI
dosegljiv na konfiguriranem URL-ju app-serverja** in da je ta CLI **prijavljen**.

---

## 1. Arhitektura

```
┌─ Aplikacija OmniRoute ───────────┐        ┌─ Spremljevalni vsebnik codex-app-server ┐
│  CodexAppServerExecutor          │  WS    │  codex app-server                       │
│  ws://codex-app-server:1456 ─────┼───────▶│  --listen ws://0.0.0.0:1456             │
│  (+ žeton zmogljivosti)          │  JSON  │  --ws-auth capability-token             │
│                                  │  RPC   │  samostojno upravlja OpenAI OAuth        │
└──────────────────────────────────┘        │  (~/.codex/auth.json, samodejno osveževanje) │
        │ souporablja (nosilci compose)      └─────────────────────────────────────────┘
        ▼
  codex-appserver-token   → žeton zmogljivosti WS (priklopljen v oba)
  codex-appserver-home    → ~/.codex (auth.json zapiše nadzorna plošča,
                             prebere pa ga codex app-server v spremljevalnem vsebniku)
```

- Spremljevalni vsebnik posluša **samo** v notranjem omrežju compose
  (`ws://codex-app-server:1456`), zaščiten z žetonom zmogljivosti. **Nikoli** ni
  objavljen gostitelju ali internetu.
- Codex CLI je vključen v `omniroute:base`, zato ob zagonu spremljevalnega
  vsebnika namestitev codex v gostitelju ali uporabnikovem računalniku ni potrebna.

## 2. Zagon

```bash
# Zaženite sklad Z vključenim profilom spremljevalnega vsebnika codex app-server:
docker compose --profile base --profile codex-app-server up -d
# (podman: podman compose --profile base --profile codex-app-server up -d)
```

Spremljevalni vsebnik ob prvem zagonu ustvari svoj žeton zmogljivosti WS (v
nosilcu v skupni rabi `codex-appserver-token`), aplikacija pa isti žeton prebere
prek `OMNIROUTE_CODEX_APPSERVER_WS_TOKEN_FILE`. Ročno povezovanje žetona ni
potrebno.

## 3. Povezava in prijava

1. Na nadzorni plošči dodajte povezavo za **OpenAI Codex (App-Server)**. Ključ
   API ali žeton ni potreben (to je ponudnik brez lastnega preverjanja
   pristnosti — za preverjanje pristnosti skrbi spremljevalni vsebnik).
2. Če Codex CLI spremljevalnega vsebnika **še ni prijavljen**, preverjanje
   zdravja povezave prikaže _»izvaja se, vendar ni prijavljen«_ (in ne rdeče
   napake preverjanja pristnosti). Uporabite **Prijava s ChatGPT**: s tem se v
   brskalniku izvede standardni OAuth naprave za Codex, nato pa možnost
   **Uporabi podatke za preverjanje pristnosti** zapiše `~/.codex/auth.json` v
   nosilec v skupni rabi (ista prijava se uporablja za ponudnika `codex` in
   `codex-app-server`).
3. Po prijavi preverjanje zdravja postane zeleno (preveri tako `/readyz` **kot**
   `account/read` — torej, ali se storitev izvaja _in_ ali je prijavljena) in
   začne delovati.

Nadzorna plošča nikoli ne prepiše zdrave obstoječe datoteke
`~/.codex/auth.json` — zapisuje samo, kadar datoteka manjka ali je njen žeton
zastarel (vedno se ustvari varnostna kopija).

## 4. Scenariji uvedbe

- **Upravljavec z že prijavljenim Codex CLI** — priklopite gostiteljski
  `~/.codex` v spremljevalni vsebnik (`codex-appserver-home`) in preskočite
  korak prijave.
- **Javni uporabnik brez lokalno nameščenega codex** — to ni pomembno:
  spremljevalni vsebnik vsebuje CLI. Uporabnik preverjanje pristnosti opravi
  samo prek nadzorne plošče.
- **OmniRoute neposredno na strojni opremi (brez spremljevalnega vsebnika, codex
  v gostitelju)** — nastavite `OMNIROUTE_CODEX_APPSERVER_WS` na svoj
  `codex app-server` in zagotovite, da je codex v gostitelju prijavljen; če
  izvršilna datoteka manjka, se prikaže namig »codex ni nameščen«.

## 5. Stanovanjski izhod / izhod UDP (dodatek upravljavca, ni priložen)

Zgornji splošni spremljevalni vsebnik uporablja običajno omrežje vsebnika za
izhodni promet. Upravljavec, ki potrebuje izhod prometa Codex prek
**stanovanjskega izhoda** (npr. spremljevalnega vsebnika tailscale s TUN, ki
prenaša TCP + UDP/QUIC), ga zažene kot ločeno preglasitev compose; ta namenoma
**ni** del priloženega profila `codex-app-server`. Navodila za to nastavitev so
v internem operativnem priročniku.
