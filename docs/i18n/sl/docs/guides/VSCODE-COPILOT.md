**OmniCopilot** doda vsak model, ki ga ponuja vaš OmniRoute, v _izvorni_ izbirnik modelov za GitHub Copilot Chat.
Brez druge stranske vrstice, brez ločenega uporabniškega vmesnika za klepet — Copilotov način agenta, klicanje orodij,
strežniki MCP in navodila po meri še naprej delujejo, le da se izvajajo z modelom, ki ga izberete.

|                            |                                                                                                                                                 |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| **Namestitev (VS Code)**   | [Marketplace → `diegosouzapw.omnicopilot`](https://marketplace.visualstudio.com/items?itemName=diegosouzapw.omnicopilot)                        |
| **Namestitev (različice)** | [Open VSX](https://open-vsx.org/extension/diegosouzapw/omnicopilot) — Cursor, Windsurf, VSCodium, Theia, code-server, Gitpod, Antigravity, Kiro |
| **Izvorna koda / težave**  | [github.com/diegosouzapw/OmniCopilot](https://github.com/diegosouzapw/OmniCopilot) (MIT)                                                        |
| **Zahteva**                | VS Code 1.104+                                                                                                                                  |

> **Naročnina na Copilot ni potrebna.** Od različice VS Code 1.122 ponudnik jezikovnega modela deluje
> brez prijave v GitHub in brez kakršnega koli paketa Copilot. Sprotna dopolnjevanja in
> funkcije, ki temeljijo na vdelavah, ostajajo zunaj ponudnikovega API-ja in še vedno zahtevajo Copilot.

## Nastavitev

1. **Zaženite OmniRoute** — `npm install -g omniroute && omniroute` (nadzorna plošča je na `http://localhost:20128`).
2. **Namestite razširitev** — v pogledu Extensions poiščite »OmniRoute«.
3. **Izberite model** — Copilot Chat → izbirnik modelov → **Manage Models…** → **OmniRoute**, nato označite
   želene modele.

Ko OmniRoute deluje na privzetih vratih, ni treba nastaviti ničesar. Za oddaljeni primerek odprite
**ikono OmniRoute v vrstici dejavnosti** (ali zaženite `OmniRoute: Manage Connection`) in nastavite:

- **URL strežnika** — korenski naslov strežnika, npr. `http://192.168.0.15:20128`. Pripono `/v1`
  doda razširitev; ne vključite je.
- **Ključ API** — samo kadar je na strežniku nastavljen `REQUIRE_API_KEY`. Shranjen je v sistemski zbirki ključev prek
  VS Code SecretStorage, nikoli v `settings.json`.

## Kaj bo prikazal izbirnik

Razširitev ne prikaže neobdelanega koristnega tovora `GET /v1/models` — preoblikuje ga, zato je prikazano
število manjše od velikosti kataloga iz dveh namernih razlogov.

### Zahteva en ID za vsak model

Privzeta vrednost `MODELS_CATALOG_PREFIX_MODE` je **`dual`**, kar vsak model objavi dvakrat — enkrat
s kratko predpono vzdevka in enkrat s kanonično predpono ponudnika — tako da starejše konfiguracije
odjemalcev še naprej razrešujejo obe obliki:

```
cc/claude-sonnet-4-6        ← predpona vzdevka
claude/claude-sonnet-4-6    ← kanonična predpona, isti model
```

Razširitev zahteva **`GET /v1/models?prefix=alias`**, zato za vsak model prejme en ID, ne da bi
spremenila nastavitev strežnika za druge odjemalce. Na referenčnem primerku se je število tako zmanjšalo
z **2345 vnosov na 1396 — 949 dvojnikov, brez izgubljenih modelov.**

Če bi to raje popravili na ravni strežnika za _vsakega_ odjemalca, nastavite zastavico funkcije
`MODELS_CATALOG_PREFIX_MODE` na `alias` na nadzorni plošči. Za poizvedbeni parameter in tabelo
posameznih načinov glejte [API_REFERENCE → prefix](../reference/API_REFERENCE.md#model-id-prefixes-prefix).

### Skrije modele, ki ne podpirajo klepeta

Katalog vključuje tudi modele za slike, videoposnetke, zvok, ponovno razvrščanje, vdelave in moderiranje. Ti so
pri zahtevi za klepet v vsakem primeru zavrnjeni:

```
HTTP 400 — Model '<id>' je model za ustvarjanje slik in ga ni mogoče uporabiti na
/v1/chat/completions. Namesto tega uporabite POST /v1/images/generations.
```

zato so na podlagi polja `type` izločeni, preden dosežejo izbirnik. **Modeli Responses-API
se ohranijo** — vsak vnos Codex / GPT-5.x navaja `supported_endpoints: ["responses"]`,
OmniRoute pa jih prevede za `/v1/chat/completions`, zato so povsem uporabni.

### Ponudniki, ki jih niste nikoli konfigurirali

Katalog vključuje modele ponudnikov z **aktivno povezavo** in vse ponudnike **noAuth** —
tiste brez ključa, ki predstavljajo velik del brezplačne ravni. To je namerno. Če jih želite skriti,
jih dodajte v `blockedProviders` v nastavitvah nadzorne plošče; v razširitvi se ne spremeni
nič.

## Nadzorna plošča znotraj zavihka VS Code

`omnicopilot.dashboardOpen: "editor"` prikaže nadzorno ploščo OmniRoute v zavihku urejevalnika prek
preprostega brskalnika namesto v zunanjem brskalniku. Vdelava je **omogočena izrecno v strežniku** prek
`DASHBOARD_ALLOW_EMBED=vscode`, zaradi česar so strani HTML posredovane z
`frame-ancestors 'self' vscode-webview:` namesto s privzetima `frame-ancestors 'none'` +
`X-Frame-Options: DENY`. Površina API-ja (`/api`, `/v1`, `/v1beta`, `/a2a`, `/healthz`) v obeh
primerih ohrani stroge glave.

> ⚠️ **To je zastavica časa gradnje, ne časa izvajanja.** Next.js prevede `headers()` v manifest
> poti, zato `next.config.mjs` prebere spremenljivko med gradnjo paketa
> (`next.config.mjs` → `resolveDashboardEmbedMode`, `scripts/build/dashboardEmbed.mjs`).
> Če jo izvozite pred že zgrajenim strežnikom, se ne spremeni nič — glave so vgrajene.

```bash
# spremenljivka mora biti prisotna v ukazu BUILD
DASHBOARD_ALLOW_EMBED=vscode npm run build        # ali npm run build:release
npm start
```

| Način namestitve           | Ali lahko omogočite vdelavo?                                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Iz izvorne kode            | ✅ nastavite spremenljivko v ukazu za gradnjo, kot je prikazano zgoraj                                                                        |
| `npm install -g omniroute` | ❌ objavljeni paket vsebuje vnaprej zgrajen paket — namesto tega gradite iz izvorne kode                                                      |
| Slika Docker               | ✅ `docker build --build-arg DASHBOARD_ALLOW_EMBED=vscode -t omniroute:embed .` — vnaprej zgrajena slika v Docker Hubu nima omogočene vdelave |

Brez gradnje z omogočeno vdelavo stran zavrne prikaz v okvirju, razširitev to zazna iz
glav odgovora in uporabi zunanji brskalnik — nič se ne pokvari, o tem pa vas enkrat obvesti.
Glejte [`ENVIRONMENT.md`](../reference/ENVIRONMENT.md) in težavo
[#10273](https://github.com/diegosouzapw/OmniRoute/issues/10273).

## Konfiguriranje drugih orodij znotraj VS Code

**`OmniRoute: Configure Coding CLI`** uporablja vmesnik CLI `omniroute` za zapis profilov, pripravljenih
za uporabo z orodji Codex CLI, Claude Code, Cline, Continue, Cursor, Aider, OpenCode, Goose, Crush, Qwen Code,
Kilo in Roo — gre za iste konfiguracije, opisane v
[`CLI-INTEGRATIONS.md`](CLI-INTEGRATIONS.md). Ključ API je vmesniku CLI posredovan prek
okoljske spremenljivke `OMNIROUTE_API_KEY`, nikoli prek ukazne vrstice.
