> **Na kratko**: OmniRoute razvršča svoje **brezplačne** ponudnike glede na kakovost modelov z uporabo **Arena AI
> (v slogu LMArena) ocen ELO**. V nadzorni plošči odprite stran **Razvrstitev brezplačnih ponudnikov**,
> da preverite, kateri brezplačni ponudniki ponujajo najzmogljivejše modele za vašo nalogo —
> skupno ali filtrirano po kategoriji (programiranje, pregled, dokumentacija, odpravljanje napak).

---

## Kaj je to

OmniRoute registrira 329 ponudnikov, vključno s 155 vnosi v katalogu, označenimi kot **brezplačni/brez avtentikacije**
(brez avtentikacije,
OAuth z brezplačno ravnjo ali ključ API z brezplačno ravnjo — glejte
[vodnik po brezplačnih ravneh](../getting-started/FREE-TIERS-GUIDE.md) in celoten
[imenik brezplačnih ravni](../reference/FREE_TIERS.md)). Težava je v tem, da se kakovost modelov
brezplačnih ponudnikov močno razlikuje. Ponudnik brez avtentikacije, ki ponuja najsodobnejši model, je veliko uporabnejši
od ponudnika, ki ponuja majhen zastarel model.

**Razvrstitev brezplačnih ponudnikov** odgovarja na vprašanje »**kateri brezplačni ponudnik mi ponuja najboljši model?**« tako,
da katalog vsakega brezplačnega ponudnika poveže z **množično pridobljenimi ocenami kakovosti** z
**lestvice Arena AI** (ELO na podlagi človeških preferenc, enaka zamisel kot pri
areni klepetalnih botov LMArena). Ponudniki so nato razvrščeni glede na zmogljivost svojega **najboljšega brezplačnega modela**.

Razvrstitev se izračuna iz treh dejanskih virov:

1. Seznami brezplačnih ponudnikov — `NOAUTH_PROVIDERS` ter vnosi `OAUTH_PROVIDERS` /
   `APIKEY_PROVIDERS`, označeni s `hasFree`
   (`src/shared/constants/providers.ts`).
2. Katalog modelov vsakega ponudnika iz registra ponudnikov
   (`open-sse/config/providerRegistry.ts`).
3. Ocene primernosti za naloge, izpeljane iz ELO in shranjene v tabeli zbirke podatkov `model_intelligence`, ki jih zapisuje
   mehanizem za sinhronizacijo Arena ELO (`src/lib/arenaEloSync.ts`).

Logika povezovanja je v `src/lib/freeProviderRankings.ts`.

## Dostop

### Stran nadzorne plošče

Odprite nadzorno ploščo in pojdite na **Stroški → Razvrstitev brezplačnih ponudnikov** ali pa neposredno odprite:

```
/dashboard/free-provider-rankings
```

Stran (`src/app/(dashboard)/dashboard/free-provider-rankings/page.tsx`) prikazuje:

- **Zmagovalni oder za najboljše tri** (🥇 🥈 🥉) najvišje uvrščene brezplačne ponudnike.
- Celotno **razvrstitveno tabelo** s stolpci: **Uvrstitev**, **Ponudnik**, **Najboljši model**,
  **Ocena**, **Povprečna ocena**, **Modeli**, **Vrsta**.
- **Gumbe za filtriranje kategorij**: _Vse kategorije_, _Privzeto_, _Programiranje_, _Pregled_,
  _Dokumentacija_, _Odpravljanje napak_.

Značka **Vrsta** pri vsakem ponudniku pove, na kakšen način je brezplačen:

| Značka   | Pomen                                                   |
| -------- | ------------------------------------------------------- |
| `NOAUTH` | Vedno brezplačno, poverilnice niso potrebne             |
| `OAUTH`  | Ponudnik OAuth z brezplačno ravnjo (`hasFree`)          |
| `APIKEY` | Ponudnik s ključem API in brezplačno ravnjo (`hasFree`) |

Ocene so prikazane kot človeku razumljive oznake (npr. _Elitno_, _Odlično_, _Zelo dobro_,
_Dobro_, _Povprečno_) namesto neobdelanih števil, saj je osnovna vrednost relativna
ocena kakovosti razvrstitve in ne odstotek.

### Končna točka API

Stran uporablja javno končno točko za branje
(`src/app/api/free-provider-rankings/route.ts`):

```
GET /api/free-provider-rankings
GET /api/free-provider-rankings?category=coding
GET /api/free-provider-rankings?category=coding&limit=20
```

Parametri poizvedbe (preverjeni z Zod):

| Parameter  | Vrsta  | Privzeto | Opombe                                                                                                           |
| ---------- | ------ | -------- | ---------------------------------------------------------------------------------------------------------------- |
| `category` | string | (brez)   | Ena od vrednosti `default`, `coding`, `review`, `documentation`, `debugging`. Izpustite za združeno razvrstitev. |
| `limit`    | number | `50`     | Omejeno na razpon `1–100`.                                                                                       |

Oblika odgovora:

```json
{
  "rankings": [
    {
      "id": "<provider-id>",
      "name": "<provider name>",
      "icon": "<icon>",
      "color": "<hex color>",
      "textIcon": "<short label>",
      "category": "noauth | oauth | apikey",
      "topModel": {
        "modelId": "<registry model id>",
        "modelName": "<model display name>",
        "score": 0.0,
        "eloRaw": 0,
        "confidence": "high | medium | low",
        "category": "<task category>"
      },
      "averageScore": 0.0,
      "modelCount": 0
    }
  ]
}
```

`eloRaw` je izvirna vrednost Arena ELO; `score` je normalizirana vrednost primernosti za nalogo
(glejte spodaj). Ponudniki brez ocenjenih modelov so izpuščeni iz odgovora.

## Kako delujejo ocene

### Vir: lestvica Arena AI

Mehanizem za sinhronizacijo Arena ELO (`src/lib/arenaEloSync.ts`) pridobi dve lestvici — `text`
in `code` — iz API-ja lestvice Arena AI
(`https://api.wulong.dev/arena-ai-leaderboards/v1/leaderboard`). Vsak vnos na lestvici
vsebuje ime modela, ponudnika, ELO `score`, interval zaupanja in število glasov.

Kategorije lestvice se preslikajo v kategorije opravil OmniRoute:

| Lestvica Arena | Kategorije opravil OmniRoute                      |
| -------------- | ------------------------------------------------- |
| `text`         | `default`, `review`, `documentation`, `debugging` |
| `code`         | `coding`                                          |

### Normalizacija (ocena primernosti za opravilo)

Neobdelane ocene ELO se za vsako lestvico normalizirajo v **vrednost primernosti za opravilo v območju `[0.4, 0.98]`**:

```
taskFit = 0.4 + 0.58 * ((elo - minElo) / (maxElo - minElo))
```

Ocena nikoli ne doseže `0` ali `1`, s čimer ostane prostor za uporabniške preglasitve. To je
polje `score`, ki ga vidite v odzivu API-ja, in oznaka, prikazana na nadzorni plošči.

### Zaupanje

Vsak vnos dobi raven zaupanja glede na število glasov v Areni:

| Zaupanje | Glasovi |
| -------- | ------- |
| `high`   | ≥ 5.000 |
| `medium` | ≥ 1.000 |
| `low`    | < 1.000 |

### Shranjevanje in svežina

Normalizirani vnosi se zapišejo v tabelo podatkovne zbirke `model_intelligence` z
`source = "arena_elo"` (`src/lib/db/modelIntelligence.ts`). Vnosi **potečejo po
7 dneh**, zato ponudnik, ki se preneha sinhronizirati, sčasoma izgine, namesto da bi
ponujal zastarele podatke.

Sinhronizacija se **privzeto izvaja**:

- Izvede se enkrat ob zagonu strežnika in nato periodično glede na časovnik
  (`src/lib/arenaEloSync.ts`, povezano iz `src/instrumentation-node.ts`).
- Je **neblokirajoča in nikoli usodna** — če pridobivanje podatkov iz nadrejenega vira ne uspe, OmniRoute še naprej
  deluje, lestvice pa preprosto prikazujejo zadnje veljavne podatke (ali prazno stanje).

Nadzirata jo dve spremenljivki okolja (dokumentirani v
[`docs/reference/ENVIRONMENT.md`](../reference/ENVIRONMENT.md)):

| Spremenljivka             | Privzeto       | Namen                                                        |
| ------------------------- | -------------- | ------------------------------------------------------------ |
| `ARENA_ELO_SYNC_ENABLED`  | `true`         | Nastavite na `false`, da onemogočite izhodno sinhronizacijo. |
| `ARENA_ELO_SYNC_INTERVAL` | `86400` (24 h) | Interval sinhronizacije v sekundah.                          |

### Ročna sinhronizacija / stanje / brisanje

Preverjena upravljavska končna točka operaterjem omogoča ročni nadzor
(`src/app/api/intelligence/sync/route.ts` — zahteva preverjanje pristnosti za upravljanje):

```
GET    /api/intelligence/sync          # trenutno stanje sinhronizacije (enabled, lastSync, nextSync, intervalMs)
POST   /api/intelligence/sync          # sproži ročno sinhronizacijo; telo: { "dryRun": true } za predogled brez zapisovanja
DELETE /api/intelligence/sync          # izbriše vse sinhronizirane vnose podatkov arena_elo
```

Če je stran z lestvicami prazna, jo ročni `POST /api/intelligence/sync` (ali preprost
ponovni zagon strežnika) znova napolni.

### Ujemanje modelov z lestvico

ID-ji modelov v registru in imena modelov v Areni se ne ujemajo vedno natančno. Razvrščanje uporablja
prilagodljivo ujemanje (`findMatchingIntelligence` v `src/lib/freeProviderRankings.ts`):

1. Natančno ujemanje z normaliziranim ID-jem modela.
2. Ujemanje po odstranitvi končne pripone različice (npr. `kimi-k2.6` → `kimi-k2`).
3. Ujemanje predpone (ime modela na lestvici je predpona ID-ja v registru).

Na strani sinhronizacije se znane predpone ponudnikov (`anthropic/`, `openai/`, `google/`, …)
odstranijo, majhen zemljevid vzdevkov pa razširi kanonična imena v različice, ki jih OmniRoute uporablja
interno, zato je modele mogoče najti pod katerim koli imenom.

### Kako se ponudnik razvrsti

Za vsakega brezplačnega ponudnika mehanizem oceni vsak model v njegovem katalogu, nato pa določi:

- **Najboljši model** = model ponudnika z najvišjo oceno.
- **Povprečna ocena** = povprečna ocena vseh ocenjenih modelov tega ponudnika.
- **Modeli** = število modelov ponudnika, ki so imeli oceno Arena.

Ponudniki so razvrščeni najprej po **oceni najboljšega modela**, nato pa po povprečni oceni. Tako je
nagrajen ponudnik, ki ponuja vsaj en zmogljiv brezplačen model.

## Uporaba za izbiro brezplačnih ponudnikov

1. **Izberite pravo kategorijo.** Uporabite filter **Kodiranje** za agentske/programerske delovne obremenitve ali
   pa za splošni klepet pustite izbrano možnost **Vse kategorije** / **Privzeto**. Isti ponudnik se lahko
   v različnih kategorijah uvrsti drugače, saj se njegov najboljši model razlikuje glede na lestvico.
2. **Za enkratne nastavitve dajte prednost najboljšim trem.** Če želite povezati le enega ali dva brezplačna
   ponudnika, začnite z najbolje uvrščenimi v svoji kategoriji.
3. **Preverite oznako vrste.** Ponudnike `NOAUTH` je mogoče povezati najhitreje (brez
   poverilnic). Brezplačne ravni `OAUTH` / `APIKEY` zahtevajo hitro registracijo, vendar pogosto omogočajo
   dostop do zmogljivejših modelov. Navodila za povezavo najdete v [Vodniku po brezplačnih ravneh](../getting-started/FREE-TIERS-GUIDE.md).
4. **Povežite več ponudnikov in prepustite odločitev funkciji Auto-Combo.** Isti podatki Arena ELO, ki omogočajo delovanje
   te strani, se uporabljajo tudi za **faktor primernosti za nalogo** mehanizma za ocenjevanje Auto-Combo
   (`open-sse/services/autoCombo/taskFitness.ts`, vrstni red razreševanja
   `user_override → arena_elo → models_dev_tier → static table`). Ko torej povežete
   najboljše brezplačne ponudnike, bo usmerjanje z `model: "auto"` (npr. `auto/coding`)
   pri vsaki zahtevi samodejno dalo prednost kakovostnejšim brezplačnim modelom. Celoten sistem ocenjevanja s 16 faktorji je opisan v dokumentaciji
   [Auto-Combo](../routing/AUTO-COMBO.md).
