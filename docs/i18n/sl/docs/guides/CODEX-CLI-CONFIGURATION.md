Popoln vodnik za uporabo Codex CLI, usmerjenega na OmniRoute kot zaledje, združljivo z OpenAI.

---

> **TOML je edina učinkovita oblika zapisa.** Sodobni Codex bere izključno
> `~/.codex/config.toml` (preverjeno s codex-cli 0.147.0: `codex --help` navaja,
> da preglasitve `-c/--config` »loaded from `~/.codex/config.toml`«). Stara datoteka
> `~/.codex/config.yaml` je pripadala opuščenemu npm CLI in je brez opozorila prezrta.
> Generator na nadzorni plošči (`/api/cli-tools/apply`, orodje `codex`) zapisuje TOML
> s previdnim združevanjem — obstoječi ključi in drugi bloki ponudnikov se ohranijo,
> ključ API ostane v `OMNIROUTE_API_KEY` (nikoli v datoteki), preostala podedovana
> datoteka `config.yaml` pa je navedena kot opomba za selitev, ne da bi bila spremenjena.

## config.toml, pripravljen za lepljenje

Zamenjajte `<YOUR_HOST>` in `<YOUR_KEY>` s svojimi vrednostmi:

```toml
# ~/.codex/config.toml
model                          = "cx/gpt-5.5"
model_provider                 = "omniroute"
model_reasoning_effort         = "xhigh"
model_context_window           = 400000
model_auto_compact_token_limit = 350000
tool_output_token_limit        = 32768    # omejitev shranjevanja zgodovine na posamezen klic orodja

[model_providers.omniroute]
name                 = "OmniRoute"
base_url             = "http://<YOUR_HOST>:20128/v1"
env_key              = "OMNIROUTE_API_KEY"
requires_openai_auth = false
wire_api             = "responses"
```

```bash
# ~/.bashrc ali ~/.zshrc — dejanska vrednost ključa, nikoli v config.toml
export OMNIROUTE_API_KEY="<YOUR_KEY>"
```

### macOS: Codex, vključen v aplikacijo ChatGPT

Če ste Codex namestili prek namizne aplikacije ChatGPT, lahko izvršljiva datoteka
`codex` obstaja samo znotraj paketa aplikacije in še ni na poti `PATH` vaše lupine.
Dodajte imenik z viri v zagonsko datoteko lupine:

```bash
export PATH="/Applications/ChatGPT.app/Contents/Resources:$PATH"
```

Odprite novo lupino in nato preverite:

```bash
command -v codex
codex --version
```

### Lokalni OmniRoute brez preverjanja pristnosti: nadomestni ključ zadostuje

Codex preveri, ali okoljska spremenljivka, določena z `env_key`, obstaja,
**preden** prvi zahtevek zapusti CLI. Če vaša **lokalna** instanca OmniRoute
ne zahteva preverjanja pristnosti, zadostuje katera koli neprazna nadomestna vrednost:

```bash
export OMNIROUTE_API_KEY="${OMNIROUTE_API_KEY:-local}"
```

Če je vaš strežnik OmniRoute zaščiten ali oddaljen, namesto tega uporabite pravi ključ.

> **Pogoste možnosti gostitelja**
>
> | Dostop          | URL                           |
> | --------------- | ----------------------------- |
> | Lokalno omrežje | `http://192.168.0.1:20128/v1` |
> | Tailscale       | `http://100.x.x.x:20128/v1`   |
> | Povratna zanka  | `http://localhost:20128/v1`   |

## `wire_api = "responses"` — zakaj deluje za vse modele

Codex CLI je februarja 2026 opustil `wire_api = "chat"` (Chat Completions) in zdaj **zahteva** `wire_api = "responses"` (OpenAI Responses API). Nastavitev `wire_api = "chat"` od različice v0.138 povzroči takojšnjo zrušitev ob zagonu.

Številni ponudniki, vključno z GLM in Kimi, še vedno ponujajo samo končno točko Chat Completions. DeepSeek V4 zdaj poleg končne točke, združljive z Anthropic, ponuja tudi izvorni Responses API; OmniRoute privzeto uporablja Responses in vsaki povezavi DeepSeek omogoča izbiro združljivosti z Anthropic.

**OmniRoute to rešuje pregledno:**

```
Codex CLI
  → wire_api = "responses"
  → POST /v1/responses (OmniRoute)
    → OmniRoute izbere izvorni protokol ponudnika in ga po potrebi prevede
    → POST /responses (DeepSeek V4) ali /chat/completions (Mistral / GLM / Kimi / drugi)
```

Pri uporabi OmniRoute nikoli ne potrebujete ločenega posredniškega strežnika za prevajanje. **Vsi modeli uporabljajo `wire_api = "responses"`** — OmniRoute poskrbi za vse ostalo.

> **`wire_api` je privzeta nastavitev** — privzeta vrednost polja je `"responses"`, zato ga lahko iz datoteke `config.toml` v celoti izpustite. Izrecno ga nastavite samo, če želite dokumentirati namen.

## Kontekstno okno in strnjevanje

### Polja za konfiguracijo žetonov

| Polje                            | Opis                                                                                                                                                                                                              |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `model_context_window`           | Skupna omejitev žetonov za aktivni model. Nastavite jo na omejitev, ki jo navaja ponudnik modela.                                                                                                                 |
| `model_auto_compact_token_limit` | Prag, ki sproži samodejno strnjevanje zgodovine. **Največ: 90 % vrednosti `model_context_window`** — vrednosti nad 90 % so brez opozorila prezrte.                                                                |
| `tool_output_token_limit`        | Omejitev števila žetonov, shranjenih v zgodovini za posamezen izhod klica orodja. Preprečuje, da bi en sam velik odziv orodja zapolnil okno. **To ni največji izhod** — gre za omejitev shranjevanja v zgodovini. |
| `compact_prompt`                 | Vgrajena preglasitev sistemskega poziva, uporabljenega med strnjevanjem (v0.138+).                                                                                                                                |

> **Opomba glede `model_max_output_tokens`**: To polje **ni del konfiguracijske sheme Codex CLI** (v kodni zbirki Codex Rust ga ni). Če je nastavljeno, je brez opozorila prezrto. Ne zanašajte se nanj — uporabite `tool_output_token_limit` za nadzor količine izhoda orodij, shranjenega v zgodovini.

## Intenzivnost sklepanja

Nadzira, koliko model »razmišlja« pred odgovorom.

| Vrednost | Uporaba za                                                      |
| -------- | --------------------------------------------------------------- |
| `none`   | Brez sklepanja — neposreden odgovor                             |
| `low`    | Preprosta opravila (preimenovanje, oblikovanje)                 |
| `medium` | **Privzeta vrednost strežnika**, če ni določena                 |
| `high`   | Srednje zahtevna opravila (preoblikovanje kode, razhroščevanje) |
| `xhigh`  | Arhitektura, poglobljena analiza, kompleksne težave             |

```bash
# Prepis nastavitve za posamezen klic
codex -c model_reasoning_effort=low "preimenuj spremenljivko x v count"
codex -c model_reasoning_effort=xhigh "zasnuj modul za preverjanje pristnosti"
```

Nastavite tudi **povzetek** sklepanja, da lahko namizna aplikacija prikaže besedilo razmišljanja (in ne le šifriranih podatkovnih blokov):

```toml
# ~/.codex/config.toml
model_reasoning_effort = "xhigh"   # ali ultra, kadar je podprto
model_reasoning_summary = "detailed"  # auto | concise | detailed | none
```

### Proračun razmišljanja OmniRoute (nastavitev strežnika)

Na gostitelju OmniRoute mora biti možnost **Settings → AI → Thinking Budget** nastavljena na **`passthrough`**, da intenzivnost/povzetek Codex dosežeta ponudnika v zaledju. Način **`auto` odstrani** vsa odjemalčeva polja `reasoning` / `reasoning_effort`, zato bodo plošče za razmišljanje prazne, tudi če je Codex pravilno konfiguriran.

Celoten vodnik: [THINKING_BUDGET.md](./THINKING_BUDGET.md).

Stiskanje in predpomnilnik pozivov sta neodvisna in še naprej delujeta z nastavitvijo `passthrough`.

## Profili — poimenovane konfiguracije za posamezen model/delovni tok

Profili omogočajo preklapljanje med modelom in kontekstnim oknom z eno samo zastavico. Vsak profil je navadna datoteka
`~/.codex/<name>.config.toml`, katere nastavitve se uporabijo čez osnovno datoteko `config.toml`.

> **Pravilo poimenovanja (Codex CLI v0.137+):** datoteka mora biti `~/.codex/<name>.config.toml` — **brez predpone `profile-`**.
> CLI preslika `-p kimi-k27` v `~/.codex/kimi-k27.config.toml`. Če datoteke ne najde, se brez opozorila uporabi privzeta nastavitev.

```bash
codex --profile kimi-k27 "analiziraj 10.000 vrstic te kodne zbirke"
codex -p glm52 "pregled arhitekture"
codex --profile deepseek-flash "preimenuj spremenljivko"   # hitro, poceni
```

### Profili intenzivnosti (isti model, različna intenzivnost)

```bash
codex -p low      # cx/gpt-5.5, intenzivnost=low
codex -p medium   # cx/gpt-5.5, intenzivnost=medium
codex -p high     # cx/gpt-5.5, intenzivnost=high
codex -p xhigh    # cx/gpt-5.5, intenzivnost=xhigh (privzeto)
codex -p chat     # cx/gpt-5.5, intenzivnost ni nastavljena (privzeta nastavitev strežnika)
```

## Samodejno ustvarjanje profilov z `omniroute setup-codex`

Če OmniRoute uporabljate na strežniku VPS, lahko datoteke profilov samodejno ustvarite iz aktualnega kataloga modelov:

```bash
# Iz strežnika VPS (uporablja lokalni OmniRoute na vratih 20128)
omniroute setup-codex

# Iz katerega koli računalnika — usmerite na svoj VPS
omniroute setup-codex --remote http://100.x.x.x:20128 --api-key sk-xxx

# Predogled brez zapisovanja datotek
omniroute setup-codex --remote http://100.x.x.x:20128 --dry-run

# Ustvari samo profila GLM in Kimi
omniroute setup-codex --only glm,kimi

# Zapiši v imenik po meri
omniroute setup-codex --codex-home /path/to/.codex
```

Ukaz pridobi `/v1/models`, uporabi prilagojene profile za znane modele, za druge združljive besedilne modele uporabi metapodatke kataloga ter za vsakega zapiše `~/.codex/<name>.config.toml`. Ukaz je idempotenten, zato ga lahko varno znova zaženete.

OmniRoute lahko te iste datoteke profilov tudi **samodejno sinhronizira**, ko uspešno odkrivanje/uvoz modelov ponudnika spremeni aktualni katalog. To je **izbirna možnost, ki je privzeto izklopljena**: vklopite jo na nadzorni plošči **CLI Code** (»Samodejna sinhronizacija profilov CLI« → Codex) ali nastavite `OMNIROUTE_AUTO_SYNC_CODEX_PROFILES=true` (upošteva tudi `CLI_ALLOW_CONFIG_WRITES`, ki je privzeto omogočen). Ko je možnost omogočena, zapisuje samo ločene datoteke profilov `~/.codex/*.config.toml`; nikoli ne spremeni aktivne/privzete datoteke `~/.codex/config.toml`, nastavitev Codex-lb, preverjanja pristnosti ali izbire ponudnika.

## Dolgotrajna opravila

Dve privzeti nastavitvi OmniRoute lahko neopazno sabotirata večurne seje Codex CLI. Nobena od njiju ni nastavitev Codex CLI — obe sta na strani OmniRoute. Uporabniki, ki selijo konfiguracijo iz posredniških strežnikov višje v verigi, ki pripnejo račune in onemogočijo prekinitve zaradi nedejavnosti, pogosto naletijo na obe težavi in sklenejo, da OmniRoute »ne more vzdrževati dolge seje«.

| Simptom                                                                                         | Verjetni vzrok                                                                                      | Nastavitev               |
| ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | ------------------------ |
| Seja nenehno preklaplja med računi / neprekinjenost predpomnilnika pozivov se med koraki izgubi | TTL afinitete seje je `0` (onemogočeno)                                                             | `sessionAffinityTtlMs`   |
| Povezava se prekine sredi sklepanja brez poziva, vidnega odjemalcu                              | Nadzornik nedejavnosti toka se je sprožil po 10 minutah brez dela podatkov iz nadrejenega strežnika | `STREAM_IDLE_TIMEOUT_MS` |

Povezane razprave: [#7126](https://github.com/diegosouzapw/OmniRoute/discussions/7126) (prekinitve dolgih opravil), [#5718](https://github.com/diegosouzapw/OmniRoute/discussions/5718) (zakaj je afiniteta privzeto izklopljena). Spremljanje: [#7287](https://github.com/diegosouzapw/OmniRoute/issues/7287).

### 1. Afiniteta seje — pripnite en pogovor na en račun

**Privzeto:** `sessionAffinityTtlMs = 0` (onemogočeno).

**Kje jo nastaviti**

- Nadzorna plošča → **Nastavitve → Usmerjanje** → **Afiniteta seje** → **TTL afinitete (sekunde)** (`ComboDefaultsTab`)
- Ali posodobite nastavitve z zahtevo PATCH in `sessionAffinityTtlMs` v **milisekundah** (razpon Zod `0`–`86_400_000`, tj. do 24 ur)

> V #7274 preimenovano iz nastavitve `codexSessionAffinityTtlMs`, namenjene samo Codexu. Stari ključ je še vedno sprejet kot vzdevek samo za branje; nove konfiguracije naj uporabljajo `sessionAffinityTtlMs`. Afiniteta zdaj velja za **katerega koli** ponudnika, ko je TTL večji od `0`, ne samo za Codex — glejte [`docs/architecture/RESILIENCE_GUIDE.md`](../architecture/RESILIENCE_GUIDE.md) → Afiniteta seje.

**Kaj se pokvari, če vrednost ostane 0**

Vsak korak večkoračnega pogovora Codex se neodvisno usmeri glede na aktivno kombinirano strategijo in lahko pri vsakem koraku pristane na **drugem računu**. To prekine neprekinjenost seje oziroma predpomnilnika pozivov pri nadrejenem ponudniku. OmniRoute upošteva glave seje Codex (`x-codex-session-id` / `x-session-id` / `x-omniroute-session`) in polja telesa, kot sta `prompt_cache_key` / `session_id`, samo kadar je TTL večji od `0` (`extractSessionAffinityKey` v `src/sse/services/auth.ts`).

**Priporočeno za večurno posamezno opravilo**

TTL nastavite **nad pričakovano dejansko trajanje opravila** (največja vrednost v uporabniškem vmesniku je **86400 sekund** = 24 ur):

| Pričakovano trajanje opravila | TTL afinitete (uporabniški vmesnik, sekunde) | `sessionAffinityTtlMs` |
| ----------------------------- | -------------------------------------------- | ---------------------- |
| Nekaj ur                      | `14400` (4 h)                                | `14400000`             |
| Čez noč / ~12 h               | `43200` (12 h)                               | `43200000`             |
| Ves dan                       | `86400` (24 h, največ)                       | `86400000`             |

Izrecna vključitev je namerna: onemogočanje afinitete daje prednost uravnoteženju obremenitve med računi, omogočanje pa neprekinjenosti ene dolge seje agenta. Ta vodnik **ne** spreminja privzete nastavitve — skrbniki, ki izvajajo dolgotrajna opravila Codex, jo morajo izrecno omogočiti.

### 2. Časovna omejitev nedejavnosti toka — ne prekinjajte tihih korakov sklepanja

**Privzeto:** `STREAM_IDLE_TIMEOUT_MS = 600000` (10 minut). Če ni nastavljeno, podeduje vrednost iz `REQUEST_TIMEOUT_MS`; skupna izhodiščna vrednost je prav tako 600000. Glejte [`docs/guides/SETUP_GUIDE.md`](SETUP_GUIDE.md) → Časovne omejitve.

**Kaj se pokvari pri privzeti nastavitvi**

Obrat sklepanja/orodja Codex, ki ostane tih več kot 10 minut **brez dejanskega izvornega segmenta**, prisilno zapre nadzornik nedejavnosti SSE (`open-sse/utils/stream.ts`). Odjemalec pogosto zazna le prekinitev povezave — kar ustreza opisu »samodejno se je ustavilo brez kakršnega koli obvestila«.

Ključna podrobnost: sintetični SSE **heartbeat** storitve OmniRoute ne ponastavi časovnika nedejavnosti. Vrednost `lastChunkTime` posodobi samo dejanski segment izvornega telesa. Tih model, ki še vedno »razmišlja«, je z vidika nadzornika videti enako kot zastal izvorni tok.

Povezana nedejavnost telesa Undici: `FETCH_BODY_TIMEOUT_MS` (prav tako ima privzeto enako osnovno vrednost 10 minut; `0` jo onemogoči). Pri pretakanju `FETCH_TIMEOUT_MS` zajema samo vzpostavitev povezave/prve glave — ko je tok aktiven, zastoje nadzorujeta `STREAM_IDLE_TIMEOUT_MS` in `FETCH_BODY_TIMEOUT_MS`.

**Priporočilo za eno večurno opravilo**

V okolju procesa OmniRoute (`.env` / compose / systemd):

```bash
# Onemogoči prekinitve zaradi nedejavnosti toka in telesa pri dolgih obratih sklepanja
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

Lahko pa ju nastavite nad najdaljše pričakovano obdobje tišine (vrednosti so v milisekundah):

```bash
# Primer: dovoli do 2 uri tišine med izvornimi segmenti
STREAM_IDLE_TIMEOUT_MS=7200000
FETCH_BODY_TIMEOUT_MS=7200000
```

Po spremembi teh okoljskih spremenljivk znova zaženite OmniRoute.

### Konkreten postopek — večurno opravilo Codex

1. **Pripnite račun:** Nadzorna plošča → Nastavitve → Usmerjanje → Afiniteta seje → TTL afinitete = `43200` (12 h) ali `86400` (največ 24 h).
2. **Povečajte/onemogočite časovne omejitve nedejavnosti** v okolju OmniRoute:

```bash
STREAM_IDLE_TIMEOUT_MS=0
FETCH_BODY_TIMEOUT_MS=0
```

3. Ohranite običajno datoteko Codex `config.toml` (`wire_api = "responses"`, pravilen `base_url`, `OMNIROUTE_API_KEY`) — na strani Codex ni nastavitev afinitete/nedejavnosti za ti dve vedenji.
4. Znova zaženite OmniRoute in nato zaženite dolgo opravilo Codex.

### Odločitev glede privzetih vrednosti (#7287)

| Nastavitev               | Privzeto ob izdaji | Spremeniti v tem vodniku?                                                                                |
| ------------------------ | ------------------ | -------------------------------------------------------------------------------------------------------- |
| `sessionAffinityTtlMs`   | `0` (izklopljeno)  | **Ne** — ostaja izbirna možnost (uravnoteženje obremenitve proti neprekinjenosti; glejte Razpravo #5718) |
| `STREAM_IDLE_TIMEOUT_MS` | `600000` (10 min)  | **Ne** — za splošni promet ostaja 10 minut; upravljavci dolgih opravil Codex jo povečajo ali onemogočijo |

Globalna sprememba katere koli privzete vrednosti bi spremenila vedenje za vsakega odjemalca primerka, ne le za Codex. Dokumentirajte nastavitve; privzete vrednosti pustite nespremenjene, dokler izrecna odločitev upravljavca ne določi drugače.

### Diagnosticiranje prekinitev zaradi nedejavnosti

Ko se sproži nadzornik nedejavnosti, OmniRoute zabeleži vrstico naslednje oblike:

```text
[STREAM] Časovna omejitev nedejavnosti: ni podatkov od codex že 600000ms (model: cx/gpt-5.5)
```

Poiščite `Idle timeout: no data from` (ali kodo `stream_idle_timeout` oziroma ime napake `StreamIdleTimeoutError`). Segment ponudnika je tisti, ki ga je OmniRoute uporabil za to zahtevo (`codex`, ID drugega ponudnika ali `provider`, če ni znan) — ni vedno dobesedni niz `codex`.

## Odpravljanje težav

**`Error: wire_api = "chat" is no longer supported`**
Iz konfiguracije odstranite `wire_api = "chat"`. Nastavite `wire_api = "responses"` ali izpustite polje (od različice v0.138 je privzeta vrednost `"responses"`).

**`Error: model not found`**
Preverite, ali model obstaja v OmniRoute in ima pravilno predpono. Uporabite `omniroute models list` ali odprite `/dashboard/providers/<provider>`.

**`Authentication error`**
Preverite, ali je spremenljivka `OMNIROUTE_API_KEY` izvožena: `echo $OMNIROUTE_API_KEY`.

**`ERROR: Missing environment variable: OMNIROUTE_API_KEY`**
Codex pred izvedbo prve zahteve preveri, ali okoljska spremenljivka obstaja. Izvozite
pravi ključ za zaščitene strežnike ali neprazno nadomestno vrednost, kot je
`OMNIROUTE_API_KEY=local`, kadar vaš **lokalni** primerek OmniRoute ne
zahteva preverjanja pristnosti. Če ste jo dodali v `~/.bashrc` ali `~/.zshrc`, znova zaženite lupino.

**`Connection refused`**
Preverite, ali se OmniRoute izvaja in ali sta gostitelj/vrata v `base_url` pravilna za vaše omrežje (lokalno, Tailscale ali VPS).

**Seja se sesuje blizu omejitve konteksta**
Izrecno nastavite `model_context_window` in `model_auto_compact_token_limit`. Oglejte si zgornjo tabelo kontekstnih oken.

**Strnjevanje se sproži prepozno**
Znižajte `model_auto_compact_token_limit` na 80–85 % okna. Nikoli ga ne nastavite nad 90 %.

**Profil se ne naloži (`-p <name>` je tiho prezrt)**
Preverite, ali datoteka obstaja na poti `~/.codex/<name>.config.toml` (brez predpone `profile-`). Zaženite `ls ~/.codex/*.config.toml`.

**Dolgotrajno opravilo Codex se med izvajanjem prekine / med koraki preklaplja med računi**
Oglejte si [Dolgotrajna opravila](#long-running-tasks). Omogočite afiniteto seje (TTL naj bo daljši od trajanja opravila) ter povečajte ali onemogočite `STREAM_IDLE_TIMEOUT_MS` / `FETCH_BODY_TIMEOUT_MS`. V dnevnikih OmniRoute z ukazom grep poiščite `Idle timeout: no data from`.
