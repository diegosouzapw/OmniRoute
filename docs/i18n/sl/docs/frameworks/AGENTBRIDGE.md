AgentBridge je posredniški strežnik MITM (Man-in-the-Middle oziroma »človek v sredini«) storitve OmniRoute, ki prestreza promet HTTPS iz agentov umetne inteligence v razvojnih okoljih IDE in ga preusmerja prek enotnega usmerjevalnega mehanizma OmniRoute. Podpira **10 agentov IDE** — Antigravity, Kiro, GitHub Copilot, GHE Copilot, OpenAI Codex, Cursor, Zed, Claude Code, Open Code in Trae (v preučevanju) — zaradi česar je OmniRoute posredniški strežnik MITM z najširšo podporo za pomočnike za programiranje z umetno inteligenco na trgu.

**Lokacija nadzorne plošče:** `/dashboard/tools/agent-bridge`
**Skupina v stranski vrstici:** Orodja (za Cloud Agents)
**Glejte tudi:** [`TRAFFIC_INSPECTOR.md`](./TRAFFIC_INSPECTOR.md) — spremljajte ves prestreženi promet v realnem času; `docs/security/MITM-TPROXY-DECRYPT.md` (git; ni prevedeno v `/docs`) — način zajema s preglednim dešifriranjem Linux TPROXY, ki ga upravlja pot `/api/tools/agent-bridge/tproxy`.

## §1 Pregled

### Kaj je AgentBridge?

Ko agent IDE (npr. GitHub Copilot, Cursor ali Claude Code) izvede klic API-ja, se neposredno poveže z nadrejenim ponudnikom umetne inteligence (OpenAI, Anthropic itd.). AgentBridge to povezavo pregledno prestreže na ravni TLS — brez kakršne koli spremembe konfiguracije agenta — in zahtevo preusmeri prek storitve OmniRoute.

To pomeni, da lahko:

- **Preusmerite katerega koli agenta h kateremu koli ponudniku**: Copilot komunicira z OpenAI? Preusmerite ga na Anthropic Claude, Gemini ali katerega koli od 352 ponudnikov storitve OmniRoute.
- **Uporabite preslikave modelov**: `gemini-3-flash` → `claude-sonnet-4.7` pregledno na ravni upravljalnika.
- **Opazujete ves promet agentov**: vsaka prestrežena zahteva je objavljena v orodju [Traffic Inspector](./TRAFFIC_INSPECTOR.md).
- **Uporabite odpornost storitve OmniRoute**: kombinirano usmerjanje, odklopniki, nadomestne možnosti in spremljanje stroškov delujejo tudi za promet agentov IDE.

## §2 Arhitektura

### 2.1 Pregled komponent

```
Agent IDE (VS Code / Cursor / itd.)
    │  HTTPS (vrata 443)
    ▼
/etc/hosts — 127.0.0.1 api.githubcopilot.com   ← preusmeritev DNS
    │
    ▼
src/mitm/server.cjs  (vrata 443, podrejeni proces CJS)
    │  razreši cilj na podlagi SNI glave Host
    │  ustvari potrdilo TLS za posamezen SNI, podpisano s CA AgentBridge
    ├── Ujemanje s seznamom za obhod? → neposredni prehod TCP (brez dešifriranja)
    ├── Ujemanje s ciljem? → fetch → usmerjevalnik OmniRoute (vrata 20128)
    │       └── handler.intercept() — TypeScript
    │               ├── maskSecrets() v telesu/glavah zahteve
    │               ├── TrafficBuffer.push() — objavi v pregledovalniku prometa
    │               └── fetchRouter() → /v1/chat/completions
    └── Brez ujemanja? → neposredni prehod TCP (brez dešifriranja)
```

### 2.2 Strežnik MITM (`src/mitm/server.cjs`)

Jedrni strežnik MITM se izvaja kot podrejeni proces Node.js CJS (da se izogne prepisovanju obstoječe kodne osnove CJS). Strežnik:

- Posluša na vratih 443 (zahteva privilegije ali `authbind`/`setcap`)
- Prejema tunele CONNECT iz operacijskega sistema (prek preusmeritve DNS v `/etc/hosts`)
- Ustvarja potrdila TLS za posamezen SNI, podpisana s CA AgentBridge (`DATA_DIR/mitm/ca.crt`)
- Razreši ciljnega agenta na podlagi glave Host prek registra `targets/index.ts`
- Posreduje zahteve sloju obravnavalnikov TypeScript prek HTTP na `http://127.0.0.1:20128`

`TARGET_HOSTS` se naloži iz `DATA_DIR/mitm/targets.json` (datoteko ob zagonu zapiše `targets/index.ts`), kar omogoča dinamične posodobitve brez ponovnega zagona strežnika CJS.

> **Model korenskega CA (#6684).** Zgoraj opisani model potrdila za posamezen SNI,
> podpisanega s CA, je trajno shranjeni model korenskega CA, dodan v #6684
> (`src/mitm/cert/rootCa.ts` + `src/mitm/_internal/rootCaShim.cjs`, ki ponovno
> uporablja kriptografijo CA/listnega potrdila, že preverjeno za TPROXY v
> `src/mitm/tproxy/dynamicCert.ts`) — nadomešča starejše enojno statično samopodpisano
> listno potrdilo (`src/mitm/cert/generate.ts`, ki je še vedno omejeno samo na
> gostitelje antigravity), na katerega kaže prisotnost para `server.crt`/`server.key`
> na disku. **Obnašanje pri selitvi**: nova namestitev (brez predhodnega
> `server.crt`) samodejno prejme model korenskega CA; namestitev, ki že zaupa
> staremu statičnemu listnemu potrdilu, ga uporablja še naprej, dokler skrbnik ne
> nastavi `MITM_ROOT_CA_ENABLED=true` in znova zažene mostu
> (`src/mitm/cert/migration.ts` je čista odločitvena funkcija — zaupanja vreden
> MITM CA, ki lahko podpiše listno potrdilo za **katerega koli** gostitelja, je
> bistveno zmogljivejši od starega listnega potrdila s fiksnim SAN, zato preklop
> pri namestitvi, ki mu že zaupa, nikoli ni tih). Potrdilo CA se namesti v isto
> mesto shrambe zaupanja `omniroute-mitm.crt`, ki ga je uporabljalo staro listno
> potrdilo (`cert/install.ts::installCaCert`) — čiščenje dvojnega zaupanja ni potrebno.

### 2.3 Osnova obravnavalnika (`src/mitm/handlers/base.ts`)

Vsi obravnavalniki agentov razširjajo `MitmHandlerBase`:

```ts
export abstract class MitmHandlerBase {
  abstract readonly agentId: AgentId;

  abstract intercept(
    req: IncomingMessage,
    res: ServerResponse,
    body: Buffer,
    mappedModel: string
  ): Promise<void>;

  // Zaščitene pomožne metode: fetchRouter, pipeSSE, hookBufferStart, hookBufferUpdate
}
```

Vsak obravnavalnik pred posredovanjem pokliče `hookBufferStart()`, ob zaključku pa `hookBufferUpdate()`. Ti metodi potisneta vnose `InterceptedRequest` v `globalTrafficBuffer` (glejte [Pregledovalnik prometa](./TRAFFIC_INSPECTOR.md) §4).

### 2.4 Register ciljev (`src/mitm/targets/`)

Vsak agent ima deklarativno datoteko cilja:

```ts
// src/mitm/targets/copilot.ts
export const COPILOT_TARGET: MitmTarget = {
  id: "copilot",
  name: "GitHub Copilot",
  hosts: ["api.githubcopilot.com", "copilot-proxy.githubusercontent.com"],
  port: 443,
  endpointPatterns: ["/chat/completions", "/v1/chat/completions"],
  defaultModels: [{ id: "gpt-4o", name: "GPT-4o", alias: "gpt-4o" }],
  handler: () => import("../handlers/copilot"),
  riskNoticeKey: "providers.riskNotice.oauth",
};
```

Register (`targets/index.ts`) izvozi `ALL_TARGETS` in ob zagonu ustvari `DATA_DIR/mitm/targets.json`.

### 2.5 Neposredni prehod in seznam za obhod (`src/mitm/passthrough.ts`)

**Seznam za obhod** (preveri se najprej in ima prednost pred ujemanjem s ciljem):

- Privzeti vzorci: bančni gostitelji, `.gov.`, ponudniki OAuth/SSO (Okta, Auth0) itd.
- Uporabniški vzorci: shranjeni v tabeli zbirke podatkov `agent_bridge_bypass`
- Gostitelji za obhod prejmejo transparentni tunel TCP — TLS se **nikoli ne dešifrira**

**Privzeti neposredni prehod** (ni ujemanja s ciljem in gostitelja ni na seznamu za obhod):

- Prav tako prejme tunel TCP — povezave se nikoli ne prekinejo
- Preprečuje, da bi AgentBridge motil splošni sistemski promet HTTPS

Prednostni vrstni red usmerjanja:

```
seznam za obhod → ujemanje s ciljem → neposredni prehod
```

### 2.6 Potrdilo CA za nadrejeno povezavo (`src/mitm/upstreamTrust.ts`)

Za poslovna omrežna okolja s CA po meri:

```bash
AGENTBRIDGE_UPSTREAM_CA_CERT=/path/to/corporate-ca.pem
```

Ko je nastavljen, konfigurira globalni razpošiljevalnik knjižnice `undici` z dodatnim potrdilom CA, kar AgentBridge omogoča dostop do nadrejenih ponudnikov prek poslovnih posredniških strežnikov za prekinjanje TLS.

### 2.7 Maskiranje skrivnosti (`src/mitm/maskSecrets.ts`)

Neodvisni pregledovalnik, razvit po načelu čiste sobe, se uporabi za telesa zahtev in glave s poverilnicami,
**preden** vstopijo v medpomnilnik pregledovalnika prometa ali kateri koli dnevnik. Izvede en sam linearni prehod:

- Žetoni s predpono `sk-` / `ak-` / `pk-` (v slogu OpenAI/Anthropic)
- Poverilnice RFC 6750 `Authorization: Bearer <token>`, pri čemer ima prednost celoten žeton
- Splošni dolgi neprosojni žetoni (≥40 znakov), vključno z oblikami s pikami in zapolnitvijo

`sanitizeHeaders()` pretvori ohranjena imena v male črke, deterministično združi vrednosti polj, odstrani
skupni seznam prepovedanih glav za posamezni skok/uokvirjanje (vključno s preverjanjem pristnosti posredniškega strežnika), v celoti zakrije `cookie` in
`set-cookie` ter vrednosti poverilnic prepusti pregledovalniku.

## §3 Nastavitev

### 3.1 Zagon/zaustavitev strežnika MITM

Uporabite kartico strežnika AgentBridge na `/dashboard/tools/agent-bridge`:

| Dejanje                 | Opis                                                                                                   |
| ----------------------- | ------------------------------------------------------------------------------------------------------ |
| Zaženi strežnik         | Zažene `src/mitm/server.cjs` na vratih 443                                                             |
| Zaustavi strežnik       | Nadzorovano zaustavi podrejeni proces                                                                  |
| Ponovno zaženi strežnik | Zaustavitev + zagon (upošteva spremembe ciljev)                                                        |
| Zaupaj potrdilu         | Namesti `DATA_DIR/mitm/ca.crt` v shrambo zaupanja vrednih potrdil operacijskega sistema                |
| Prenesi potrdilo        | Prenese `ca.crt` za ročno namestitev                                                                   |
| Znova ustvari potrdilo  | Ustvari nov par ključev overitelja CA (vsa obstoječa potrdila posameznih agentov postanejo neveljavna) |

### 3.2 Zaupanje potrdilu

Operacijski sistem mora potrdilu overitelja CA AgentBridge zaupati, preden bodo IDE-ji sprejeli povezavo MITM.

**Linux (NSS — Chrome/Firefox):**

```bash
certutil -A -d sql:$HOME/.pki/nssdb -n "OmniRoute AgentBridge" -t CT,, -i ~/.omniroute/mitm/ca.crt
```

**macOS (Keychain):**

```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/.omniroute/mitm/ca.crt
```

**Windows (certmgr):**

```powershell
certutil -addstore -f Root $env:USERPROFILE\.omniroute\mitm\ca.crt
```

Lahko uporabite tudi gumb »Zaupaj potrdilu« na nadzorni plošči (izvede ustrezen ukaz za vaš operacijski sistem in po potrebi prikaže poziv za sudo).

#### IDE-ji, ki temeljijo na Electronu, prezrejo sistemsko shrambo zaupanja (`NODE_EXTRA_CA_CERTS`)

Nekateri IDE-ji — zlasti **Antigravity IDE** in druge aplikacije, izpeljane iz Electrona / VS Code — vključujejo
lastno izvajalno okolje Node.js, ki za odhodne zahteve `fetch`/HTTPS **ne uporablja sistemske shrambe zaupanja**.
Zaupanje overitelju CA na ravni operacijskega sistema/NSS zadostuje za izvorno **zaledje** IDE-ja
(npr. jezikovni strežnik Go, ki uporablja sistemski sveženj overiteljev CA), vendar bo
**čelni del Electron** pri TLS še vedno odpovedal — aplikacija je videti, kot da je uporabnik _odjavljen_,
ali pa prikazuje _»napako povezave«_, čeprav dnevnik MITM kaže, da začetni klici zaledja vračajo `200`. Potrebna
sta dva koraka in oba sta pomembna:

1. Izvajalno okolje izrecno usmerite na overitelja CA:
   ```bash
   export NODE_EXTRA_CA_CERTS=/path/to/omniroute-agentbridge-ca.crt
   ```
2. **IDE zaženite iz te ukazne lupine.** Če ga zaženete prek ikone na namizju / Docka / menija Start,
   **ne** podeduje izvoženih spremenljivk ukazne lupine, datoteke `~/.config/environment.d/*.conf` pa se uporabijo
   šele po novi grafični prijavi. IDE najprej popolnoma zaprite — Electronovo zaklepanje enega primerka pomeni,
   da drugi zagon zgolj postavi obstoječi proces v ospredje, novo okolje pa je prezrto.

Zgornji korak zaupanja na ravni operacijskega sistema + NSS je še vedno potreben (Chromiumov omrežni sklad,
ki ga uporabljajo nekateri postopki preverjanja pristnosti, bere uporabniško shrambo NSS in ima lastne statične
pripete vrednosti za `*.googleapis.com`, ki jih lokalno zaupanja vreden overitelj CA preglasi).
`NODE_EXTRA_CA_CERTS` poleg tega pokriva pot Node `fetch`.

### 3.3 Usmerjanje DNS

Za vsakega agenta, ki ga želite prestrezati, se morajo njegovi gostitelji API razrešiti v `127.0.0.1`. AgentBridge samodejno upravlja vnose v `/etc/hosts`, ko v čarovniku za nastavitev vklopite DNS za agenta.

Primer vnosov v `/etc/hosts` za GitHub Copilot:

```
127.0.0.1 api.githubcopilot.com
127.0.0.1 copilot-proxy.githubusercontent.com
```

### 3.4 Preslikava modelov

V kartici posameznega agenta uporabite tabelo za preslikavo modelov, da določite preslikave izvor → cilj:

| Izvorni model (izvoren za agenta) | Ciljni model (OmniRoute) |
| --------------------------------- | ------------------------ |
| `gpt-4o`                          | `claude-sonnet-4.7`      |
| `*` (nadomestni znak)             | `claude-haiku-4.7`       |

Nadomestni znak `*` preslika vsak neprepoznan model v navedeni cilj. Preslikava je trajno shranjena v tabeli `agent_bridge_mappings`.

> **Nasvet — odkrijte dejanske ID-je modelov agenta.** IDE lahko pošilja imena modelov, ki se razlikujejo od
> oznak v njegovem uporabniškem vmesniku in se spreminjajo med glavnimi različicami. **Antigravity 2** na primer
> po omrežju pošilja `gemini-3.1-pro-low`, `gemini-pro-agent` in `gemini-3.1-flash-lite` — ne pa
> `gemini-2.5-pro`, prikazanega v starejši dokumentaciji. Pošljite eno sporočilo klepeta brez ustrezne preslikave:
> MITM zabeleži natančno dohodno vrednost `model:` in zahtevo prepusti naprej. Preslikajte to dobesedno vrednost,
> nato bo naslednja zahteva prestrežena in usmerjena do vašega cilja.

### 3.5 Obvestilo o tveganju

AgentBridge prestreza poverilnice (žetone OAuth, ključe API), ki jih IDE uporablja za preverjanje pristnosti pri ponudnikih višje ravni. Te so **pred beleženjem zakrite** (glejte §2.7), vendar so vidne plasti MITM sistema OmniRoute. Ob prvi aktivaciji posameznega agenta se prikaže modalno okno z obvestilom o tveganju, ki ga je mogoče opustiti.

### 3.6 Vzdrževanje in diagnostika

Nadzorna plošča vsebuje kartico **Vzdrževanje in diagnostika** (`AgentBridgeMaintenanceCard`, v `src/app/(dashboard)/dashboard/tools/agent-bridge/components/`), ki prikazuje operativne poti MITM, za katere prej ni bilo uporabniškega vmesnika. Njen podnaslov je: _»Samodejno preizkusite cevovod za zajemanje, razveljavite preostalo stanje sistema in prenesite svojo nastavitev med računalniki.«_ Odjemalske pomožne funkcije kartice so v `src/lib/inspector/agentBridgeMaintenanceApi.ts`.

| ------------------------ | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Diagnosticiraj**       | `GET /api/tools/agent-bridge/diagnose` | Zažene samopreizkus cevovoda za zajem in prikaže poročilo za vsako preverjanje (✓/✗ + namig za odpravo težave).                                                                                                                                                  |
| **Popravi**              | `POST /api/tools/agent-bridge/repair`  | Razveljavi osirotelo sistemsko stanje MITM (vnose za lažno predstavljanje DNS, korenski CA, sistemski posredniški strežnik), ki je ostalo po zrušitvi ali signalu SIGKILL. Operacija je idempotentna — ko je stanje čisto, sporoči »Ničesar ni treba popraviti«. |
| **Odstrani CA**          | `DELETE /api/tools/agent-bridge/cert`  | Prekliče zaupanje in odstrani korenski CA MITM iz shrambe zaupanja operacijskega sistema (izrecno, idempotentno). Prikazano samo, ko je CA trenutno zaupanja vreden; zahteva sprotno potrditev »Odstranim CA?«.                                                  |
| **Izvozi konfiguracijo** | `GET /api/tools/agent-bridge/config`   | Prenese prenosljivi konfiguracijski JSON (glejte §3.7).                                                                                                                                                                                                          |
| **Uvozi konfiguracijo**  | `POST /api/tools/agent-bridge/config`  | Naloži predhodno izvoženi konfiguracijski JSON (glejte §3.7).                                                                                                                                                                                                    |

**Diagnostična preverjanja** (`summarizeDiagnostics()` v `src/mitm/inspector/diagnostics.ts`). Pot za vsako preverjanje izvede s stranskimi učinki povezano preizkušanje in logične vrednosti posreduje čisti funkciji za povzemanje; vrnjena sta enotna ocena `healthy` in namig za vsako neuspešno preverjanje:

| Ime preverjanja    | Kaj preverja                                                    | Namig ob neuspehu                                                                                                                                                                |
| ------------------ | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `server-running`   | Proces strežnika MITM je dejaven                                | »Strežnik MITM se ne izvaja. Zaženite ga na zavihku AgentBridge.«                                                                                                                |
| `server-reachable` | Strežnik MITM sprejema povezave na svojih vratih (preizkus TCP) | »Strežnik MITM ne sprejema povezav na svojih vratih. Preverite, ali so vrata prosta in ali imate dovoljenja za vezavo nanje.«                                                    |
| `cert-exists`      | Potrdilo MITM je bilo ustvarjeno na disku                       | »Potrdilo MITM še ni bilo ustvarjeno. Ustvarite ga na zavihku AgentBridge.«                                                                                                      |
| `cert-trusted`     | Korenski CA MITM je v shrambi zaupanja operacijskega sistema    | »Korenski CA MITM ni zaupanja vreden v shrambi operacijskega sistema, zato prestrezanje TLS ne bo uspelo. Potrdilu zaupajte na zavihku AgentBridge.«                             |
| `dns-configured`   | Ciljna imena gostiteljev so lažno predstavljena v `/etc/hosts`  | »Ciljna imena gostiteljev niso lažno predstavljena v /etc/hosts, zato promet nikoli ne doseže posredniškega strežnika. Omogočite DNS za agente, katerih promet želite zajemati.« |

**Pasica osirotelega stanja:** ko stran zazna stanje, ki je ostalo po zrušitvi (lažno predstavljanje DNS / CA / sistemski posredniški strežnik), kartica prikaže jantarno pasico — _»Prejšnja seja je za seboj pustila sistemsko stanje (lažno predstavljanje DNS, CA ali sistemski posredniški strežnik). Za čiščenje zaženite Popravi.«_ — in poudari gumb **Popravi**. `Repair` je na ravni aplikacije ustreznik zastavice `--cleanup` orodja ProxyBridge (izvajanje prepusti funkciji `repairMitm()` v `src/mitm/manager.ts`).

> Korenski CA MITM ostane nameščen med zaustavitvami in zagoni, da se izognete
> ponavljajočim se pozivom sudo (enako obnašanje kot pri mitmproxy/Charles), zato je njegova odstranitev izrecno
> dejanje **Odstrani CA**, ne pa nekaj, kar bi se ob zaustavitvi zgodilo samodejno.

### 3.7 Uvoz/izvoz prenosljive konfiguracije

AgentBridge lahko stanje, **ki ga lahko prilagaja upravljavec**, serializira v različicami označen blok JSON, tako da je nastavitev mogoče podvojiti na drugih računalnikih. Serializator je `src/lib/inspector/configPortability.ts` (`exportConfig()` / `importConfig()`), veljavnost pa preverja `AgentBridgeConfigSchema`.

Izvoz vključuje natanko tri dele (vgrajene privzete vrednosti namenoma **NISO** izvožene, zato jih uvoz nikoli ne podvaja in z njimi ne prihaja v navzkrižje):

| Polje            | Vir                                                                      | Opombe                                                                     |
| ---------------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- |
| `bypassPatterns` | uporabniško določeni vzorci obhoda (`agent_bridge_bypass`)               | privzeti vzorci za banke/državne ustanove/Okto so izključeni               |
| `customHosts`    | gostitelji po meri v orodju Traffic Inspector (`inspector_custom_hosts`) | vsak: `{ host, kind: "llm"\|"app"\|"custom", label? }`                     |
| `agentMappings`  | preslikave modelov za posameznega agenta (`agent_bridge_mappings`)       | `{ [agentId]: [{ source, target }] }` za vsakega agenta, ki ima preslikave |

```jsonc
// GET /api/tools/agent-bridge/config
{
  "version": 1,
  "bypassPatterns": ["*.internal.example.com"],
  "customHosts": [{ "host": "api.example.com", "kind": "llm", "label": null }],
  "agentMappings": {
    "copilot": [{ "source": "gpt-4o", "target": "claude-sonnet-4.7" }],
  },
}
```

**Obnašanje pri uvozu** (`POST /api/tools/agent-bridge/config`): vzorci obhoda in preslikave za posamezne agente se **v celoti nadomestijo**; gostitelji po meri se dodajo **idempotentno** (`INSERT OR IGNORE`). Odgovor sporoči, koliko elementov vsake vrste je bilo uporabljenih:

```jsonc
{ "ok": true, "bypassPatterns": 1, "customHosts": 1, "agents": 1 }
```

Kaj **NI** vključeno v konfiguracijo: stanje izvajanja strežnika, poti do potrdil, stanje DNS posameznega agenta, pot do nadrejene overiteljske ustanove in nastavitve TPROXY — to so stanja gostitelja/izvajalnega okolja, ne prenosljive nastavitve.

### Seznam izjem za občutljive gostitelje

Seznam izjem zagotavlja, da finančne ustanove, ponudniki OAuth/SSO in drugi občutljivi gostitelji **niso nikoli dešifrirani**. Njihov promet TLS je posredovan kot transparenten predor TCP — OmniRoute nikoli ne vidi nešifrirane vsebine.

Privzeti vzorci izjem vključujejo:

- `*.bank.*`, `*.gov.*` (finance/vlada)
- `*.okta.com`, `*.auth0.com`, `*.microsoft.com` (SSO/identiteta)
- `*.apple.com`, `*.icloud.com` (Applove sistemske storitve)

Vzorci izjem, ki jih doda uporabnik, so shranjeni v tabeli `agent_bridge_bypass` in imajo prednost pred vsem drugim.

### Maskiranje skrivnosti

Uporabi se `maskSecrets()` iz `src/mitm/maskSecrets.ts`:

- Za vsako telo zahteve pred `TrafficBuffer.push()`
- Za vsako glavo pred beleženjem ali oddajanjem

Vzorci: žetoni s predponami `sk-`/`ak-`/`pk-`, žetoni `Bearer` in splošni žetoni z najmanj 40 znaki.

### Potrdilo CA nadrejenega strežnika

Ko je nastavljena spremenljivka `AGENTBRIDGE_UPSTREAM_CA_CERT`, se datoteka prebere ob zagonu. Če pot obstaja, vendar datoteke ni mogoče prebrati, AgentBridge zabeleži jasno napako in zavrne zagon (s tem prepreči tihe napake TLS v poslovnih okoljih).

### Znane omejitve

- **Vrata 443 zahtevajo privilegije**: V Linuxu AgentBridge zahteva `setcap 'cap_net_bind_service=+ep'` za izvršljivo datoteko Node ali zagon prek `authbind`. Čarovnik za nastavitev prikaže navodila, specifična za operacijski sistem.
- **Potreben je ponovni zagon IDE-ja**: Po preusmeritvi DNS je treba IDE znova zagnati, da začne veljati novo razreševanje gostiteljev.
- **Trdo kodirani žetoni OAuth**: Nekateri agenti (Kiro, Antigravity) lokalno shranjujejo osvežitvene žetone OAuth. Ti so za AgentBridge transparentni — v vsaki zahtevi vidi žeton Bearer, ki je pred beleženjem zamaskiran.
- **Odjemalci Electron potrebujejo `NODE_EXTRA_CA_CERTS`**: IDE-ji, katerih odjemalski del se izvaja v vgrajenem izvajalnem okolju Node/Electron, prezrejo shrambo zaupanja operacijskega sistema/NSS in jih je treba zagnati iz lupine z nastavljeno spremenljivko `NODE_EXTRA_CA_CERTS` (glejte §3.2). Simptom, kadar manjka: zaledni del IDE-ja se overi (MITM prikazuje odgovore `200`), vendar uporabniški vmesnik ostane odjavljen.
- **Več namestitev istega IDE-ja je med seboj neodvisnih**: sistemska namestitev (npr. `/usr/share/antigravity/antigravity`) in uporabniška lokalna namestitev »Full« (npr. `~/AntigravityIDE_Full/antigravity-ide`) sta ločena procesa z lastnima izvajalnima okoljema — vsakega je treba znova zagnati z vstavljenim potrdilom CA. Pred ponovnim zagonom po poti izvršljive datoteke ugotovite, kateri se izvaja.
- **Identiteto določa sistemski poziv agenta, ne preusmerjeni model**: ko model agenta preslikate na drugega ponudnika, odgovor še vedno navaja izvorno identiteto agenta (npr. Antigravity odgovori »Poganja me Gemini«), ker IDE to vstavi v sistemski poziv. Dejansko zaledje preverite v `call_logs` / `proxy_logs` (`provider`, `model`, `target_format`), ne tako, da model vprašate, kdo je.

## §6 Odpravljanje težav

### Spor na vratih 443

Če drug proces že posluša na vratih 443 (spletni strežnik, VPN itd.):

```bash
lsof -i :443          # poišče proces
sudo fuser -k 443/tcp  # prisilno konča proces (uporabljajte previdno)
```

Lahko pa v nastavitvah AgentBridge nastavite neprivilegirana vrata in konfigurirate pravila za preusmerjanje `iptables` / `pf`.

### Potrdilo ni zaupanja vredno

Če IDE po zagonu AgentBridge prikazuje napake TLS:

1. Preverite, ali je bilo potrdilo nameščeno: `security find-certificate -c "OmniRoute AgentBridge"` (macOS) ali `certutil -L -d sql:$HOME/.pki/nssdb` (Linux/NSS)
2. Nekatere aplikacije vzdržujejo lastno shrambo zaupanja (Firefox, Chrome v Linuxu). Znova zaženite »Trust Cert« in preverite shrambo potrdil, specifično za NSS/Firefox.
3. Po nastavitvi zaupanja znova zaženite IDE — aktivne seje TLS uporabljajo staro stanje zaupanja.

### IDE je odjavljen / »napaka povezave« kljub zaupanja vrednemu CA

Simptom: po preusmeritvi DNS in nastavitvi zaupanja za CA se IDE, ki temelji na Electronu (npr. Antigravity), odpre **odjavljen** ali prikaže napako preverjanja pristnosti/povezave, čeprav dnevnik MITM kaže, da so zagonski klici (`loadCodeAssist`, `fetchAvailableModels`, …) vrnili `200`.

Vzrok: **vgrajeno izvajalno okolje Node/Electron ne upošteva sistemske shrambe zaupanja**. Izvorno zaledje (jezikovni strežnik v Go) zaupa sistemskemu CA in uspešno preveri pristnost, vendar sprednji del Electron ne — zato uporabniški vmesnik meni, da nima povezave.

Rešitev (oba koraka): izvozite `NODE_EXTRA_CA_CERTS=<ca.crt>` **in znova zaženite IDE iz te ukazne lupine**, ne prek ikone na namizju. Najprej povsem zaprite IDE — zaradi Electronovega zaklepa enega primerka drugi zagon zgolj prestavi fokus na obstoječi proces, novo okolje pa se ne upošteva. Glejte §3.2. To ustreza odprtemu poročilu v izvornem projektu, v katerem samostojni posrednik deluje prek MITM, različica IDE pa pri isti nastavitvi ne deluje.

### DNS se ni uveljavil

Preverite, ali je bila datoteka `/etc/hosts` posodobljena:

```bash
grep "omniroute\|127.0.0.1.*github\|127.0.0.1.*cursor" /etc/hosts
```

Počistite predpomnilnik DNS:

```bash
# macOS
sudo dscacheutil -flushcache && sudo killall -HUP mDNSResponder
# Linux (systemd-resolved)
sudo systemctl restart systemd-resolved
# Windows
ipconfig /flushdns
```

### IDE ni zaznan

Samodejno zaznavanje uporablja običajne namestitvene poti. Če zaznavanje ne uspe, čeprav je IDE nameščen:

- Preverite, ali je izvršljiva datoteka IDE na nestandardnem mestu
- Čarovnik za nastavitev še vedno deluje — neuspešno zaznavanje pomeni le, da značka ne bo prikazala namestitvene poti

### Napake obdelovalnika (pridobivanje iz izvornega strežnika ne uspe)

Če AgentBridge prestreza zahteve, vendar vse spodletijo:

1. Preverite, ali je na `/dashboard/providers` povezan vsaj en ponudnik
2. Preverite dnevnike strežnika OmniRoute: `APP_LOG_LEVEL=debug` v `.env`
3. Preverite, ali `OMNIROUTE_BASE_URL` kaže na pravilno končno točko usmerjevalnika (privzeto: `http://127.0.0.1:20128`)
