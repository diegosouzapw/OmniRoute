> **TL;DR**: Nastavite model na `auto` in OmniRoute bo za vsako zahtevo samodejno izbral najboljšega ponudnika umetne inteligence. Konfiguracija ni potrebna.

---

## Kaj počne

Namesto da izberete določen model umetne inteligence (kot sta GPT-4o ali Claude), lahko prepustite OmniRoute, da za vsako zahtevo **samodejno izbere najboljšega**. Upošteva:

- **Stanje** — Ali ponudnik trenutno deluje?
- **Hitrost** — Kako hiter je?
- **Stroški** — Koliko stane?
- **Kakovost** — Ali je primeren za to vrsto naloge?
- **Zmogljivost** — Ali ima še razpoložljivo kvoto?

OmniRoute oceni vse vaše povezane ponudnike in izbere najboljšega. Če ta ne uspe, samodejno poskusi naslednjega.

---

## Hitri začetek

**1. korak**: V svojem IDE-ju ali CLI-ju nastavite model na `auto`:

```
model: "auto"
```

**2. korak**: To je vse! OmniRoute poskrbi za preostalo.

**3. korak** (izbirno): Za določene naloge uporabite različico:

```
model: "auto/coding"    # Najboljše za kodo
model: "auto/fast"      # Najhitrejši odziv
model: "auto/cheap"     # Najcenejša možnost
```

---

## Kateri »auto« naj uporabim?

| Če želite ...             | Uporabite      | Najprimernejše za                | Kako deluje                                          |
| ------------------------- | -------------- | -------------------------------- | ---------------------------------------------------- |
| **Najboljše na splošno**  | `auto`         | Splošna vprašanja, klepet        | Uravnoteži hitrost, stroške in kakovost              |
| **Najboljše za kodo**     | `auto/coding`  | Pisanje kode, razhroščevanje     | Izbere modele, primerne za programerske naloge       |
| **Najhitrejši odziv**     | `auto/fast`    | Hitri odgovori, nizka zakasnitev | Prednost daje hitrosti pred vsem drugim              |
| **Najcenejša možnost**    | `auto/cheap`   | Varčevanje                       | Izbere najcenejšega ponudnika                        |
| **Najpametnejši model**   | `auto/smart`   | Kompleksne naloge                | Kakovost na prvem mestu + preizkušanje novih modelov |
| **Najbolj razpoložljivo** | `auto/offline` | Ko so ponudniki zasedeni         | Izbere ponudnike z največ razpoložljive zmogljivosti |

### Primeri

```bash
# Splošni klepet — uravnoteženo
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto","messages":[{"role":"user","content":"Hello!"}]}'

# Ustvarjanje kode — kakovost na prvem mestu
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/coding","messages":[{"role":"user","content":"Write a Python function"}]}'

# Hiter odgovor — hitrost na prvem mestu
curl http://localhost:20128/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"auto/fast","messages":[{"role":"user","content":"What is 2+2?"}]}'
```

## Kako deluje (preprosta različica)

Ko pošljete zahtevo z `model: "auto"`, OmniRoute:

1. **Pregleda vse vaše povezane ponudnike** — Vsakega ponudnika, ki ste ga dodali (OpenAI, Anthropic, Google itd.)
2. **Oceni vsakega od njih**, pri čemer med drugim upošteva:
   - Ali deluje? (stanje)
   - Ali ima razpoložljivo zmogljivost? (kvota)
   - Koliko stane? (cena)
   - Kako hiter je? (hitrost)
   - Ali je primeren za to nalogo? (kakovost)
3. **Izbere najboljšega** — Ponudnik z najvišjo oceno prejme vašo zahtevo
4. **Samodejno obnovi delovanje** — Če ponudnik ne uspe, OmniRoute samodejno poskusi naslednjega

### Sistem ocenjevanja

Vsak ponudnik prejme oceno od 0 do 1. Višja kot je ocena, primernejši je ponudnik.

| Dejavnik          | Utež | Kaj pomeni                                      |
| ----------------- | ---- | ----------------------------------------------- |
| Stanje            | 20%  | Ali ponudnik deluje? (stanje odklopnika)        |
| Kvota             | 15%  | Ali ima še razpoložljivo zmogljivost?           |
| Stroški           | 15%  | Kako drag je? (cenejši = višja ocena)           |
| Hitrost           | 12%  | Kako hiter je? (nižja zakasnitev = višja ocena) |
| Ustreznost nalogi | 8%   | Ali je primeren za to vrsto naloge?             |
| Stabilnost        | 5%   | Ali je dosleden? (nizka stopnja napak)          |
| Raven             | 5%   | Raven računa (Ultra > Pro > Free)               |
| Drugo             | 20%  | Sorodnost konteksta, gostota povezav itd.       |

### Kako različice spremenijo ocenjevanje

Vsaka različica uporablja različne uteži:

| Različica      | Prednost daje            | Ključne uteži                   |
| -------------- | ------------------------ | ------------------------------- |
| `auto`         | Uravnoteženosti          | health=20%, quota=15%, cost=15% |
| `auto/coding`  | Kakovosti                | taskFit=37%, stability=15%      |
| `auto/fast`    | Hitrosti                 | latency=32%, health=28%         |
| `auto/cheap`   | Stroškom                 | cost=37%                        |
| `auto/smart`   | Kakovosti + raziskovanju | taskFit=37%, exploration=10%    |
| `auto/offline` | Zmogljivosti             | quota=37%, health=28%           |

## Kako obravnava napake

OmniRoute ima **tri ravni zaščite**:

### 1. Samodejni preklop

Če najboljši ponudnik odpove, OmniRoute samodejno poskusi naslednjega. Storiti vam ni treba ničesar.

### 2. Samodejno odpravljanje težav

Če ponudnik nenehno odpoveduje:

- **Ocena < 0,2** → Izključen za 5 minut
- **Odklopnik je odprt** → Samodejno izključen
- **Več kot 50 % ponudnikov ne deluje** → Način incidenta (brez raziskovanja)

### 3. Rezervna možnost v sili

Če odpovejo vsi ponudniki, OmniRoute kot zadnjo možnost preusmeri zahteve k stabilnim brezplačnim ponudnikom (kot sta Kiro ali Qoder).

---

## Podpora za več računov

Če imate več računov pri istem ponudniku (npr. dva ključa OpenAI), OmniRoute vsakega obravnava kot **ločenega kandidata**. To pomeni:

- Račun A ima še razpoložljivo kvoto → uporabi ga
- Za račun B velja omejitev hitrosti → preskoči ga
- Račun C je cenejši → daj mu prednost

Vsak račun je ocenjen neodvisno glede na svoje stanje, kvoto in hitrost.

---

## Raziskovanje z metodo bandit

OmniRoute občasno **raziskuje** nove ponudnike, da odkrije boljše možnosti:

- **Privzeto**: 5 % zahtev je poslanih naključnim ponudnikom
- **Auto/smart**: 10-odstotna stopnja raziskovanja
- **Onemogočeno**, ko več kot 50 % ponudnikov ne deluje pravilno

To sistemu OmniRoute pomaga ugotoviti, kateri ponudniki najbolje ustrezajo vašim vzorcem uporabe.

## Pogosta vprašanja

### »Ali bo vedno izbral najdražji model?«

**Ne.** Cena privzeto predstavlja le 15 % ocene. Poceni, hiter in zanesljiv ponudnik lahko premaga dražjega. Če želite dati še večjo prednost ceni, uporabite `auto/cheap`.

### »Kaj se zgodi, če ponudnik preneha delovati?«

OmniRoute ga samodejno preskoči in poskusi naslednjega. Če ponudnik nenehno odpoveduje, je začasno izključen (za 5–30 minut). Storiti vam ni treba ničesar.

### »Ali lahko vidim, kateri ponudnik je bil uporabljen?«

Preverite glave odgovora — OmniRoute v vsak odgovor vključi uporabljenega ponudnika in model.

### »Ali se uči iz moje uporabe?«

Da! Sistem ocenjevanja uporablja zgodovinske podatke (zakasnitev, stopnje napak in stopnje uspešnosti), da sčasoma sprejema boljše odločitve.

### »Kakšna je razlika med `auto` in `auto/smart`?«

- `auto` — Uravnoteženo, 5 % raziskovanja
- `auto/smart` — Kakovost na prvem mestu (enake uteži kot pri `auto/coding`), 10 % raziskovanja

Uporabite `auto/smart`, ko želite najboljšo kakovost in vas občasno raziskovanje ne moti.

### »Ali lahko vsilim določenega ponudnika?«

Da! Namesto `auto` uporabite kombinacijo s strategijo `priority`, nato pa kot polje `model` pošljite **točno ime** kombinacije (npr. `model: "my-combo"` — ne `auto`). Za podrobnosti glejte [tehnično dokumentacijo](../routing/AUTO-COMBO.md).

### »Kako se to razlikuje od krožnega razporejanja?«

Krožno razporejanje izmenično izbira ponudnike po vrstnem redu. Samodejna kombinacija **oceni vsakega ponudnika** in izbere najboljšega. Je pametnejša — upošteva stanje, hitrost, ceno in kakovost.
