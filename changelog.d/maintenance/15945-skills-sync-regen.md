- **fix(skills):** regenerate the 20 `SKILL.md` files that had drifted from their generator (#15945). `check:agent-skills-sync` was failing on the `release/v3.8.52` tip, which blocked every PR into the branch rather than just one: `.mergify.yml` names `Merge integrity (changelog + generated skills)` as the always-on anchor that must be an affirmative `check-success`, and the only failure it tolerates is `Build (advisory)`. The cause was #14381 (`4df9ceae03`), which extracted the curl examples out of `src/lib/agentSkills/generator.ts` into the new `apiOperationExample.ts` and replaced the hardcoded `https://localhost:20128` with `resolveOmniRouteBaseUrl()`, whose default is `http://localhost:20128`; the committed files were never regenerated, so every generated example disagreed with the generator from that commit onward. This is the mechanical output of `node --import tsx/esm scripts/skills/generate-agent-skills.mjs --apply` with no base-url env vars set — the documented default and the environment CI runs in — so the diff is the `https:` → `http:` scheme change plus the endpoint-reference content that moved with it. No instruction text is added or edited, which matters because `skills/**/SKILL.md` is an agent-instruction surface. The gate goes from 20 drifted to 0 (`Generated: 0 · Unchanged: 46 · Errors: 0`), with `check:changelog-integrity` and `check:docs-all` also clean. One latent cause is deliberately left alone: `apiOperationExample.ts` and `cliConfigurationExample.ts` resolve the base URL from `process.env` (`OMNIROUTE_BASE_URL`, `BASE_URL`, `NEXT_PUBLIC_BASE_URL`, `PORT`, …), so anyone running `--apply` with one of those set re-bakes their own host into the committed artifact and re-opens this drift. Making generation env-independent touches shared runtime code used by the A2A skills, the MCP internal fetch and two API routes, so it belongs in its own PR rather than a base-red drain.
