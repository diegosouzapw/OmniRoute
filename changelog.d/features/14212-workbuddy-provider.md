- **feat(providers):** WorkBuddy (`www.workbuddy.ai`, Tencent) is now a first-class provider with its own device-flow OAuth module, catalog entry and token refresh. It is a separate product from CodeBuddy CN (different host, account system and catalog, and a credential from one is not valid on the other), so it deliberately does not alias the CodeBuddy OAuth module — aliasing would point the state request at `copilot.tencent.com` and mint the wrong credential. The gateway is OpenAI-compatible but accepts only a single-turn request: it rejects the replayed history an agent client sends from turn two on, and reports each violation as a generic code that reads like a transport fault (`11148 tool_call_sequence_broken`, `11155 reasoning content from the previous turn must be passed back`, `11128 Illegal API invocation from an unapproved channel`, `11101` non-stream rejected). The repair therefore lands in core as two opt-in `RegistryEntry` flags — `strictChatHistory` and `bodyStringReplacements` — honoured by the existing `transformRequest` hook and inert for every provider that does not declare them, so no sidecar proxy is required. The catalog is left `models: []` with `passthroughModels: true` and discovered from the authenticated `GET /v3/config` the official CLI itself uses, because WorkBuddy serves no OpenAI-shaped `/models` endpoint (`/v1/models` and `/v2/models` both 404). That payload is an authenticated `GET /v3/config`, which returns 22 chat models (observed live via the desktop app's own log); that list replaces the membership of the 26-entry catalogue the CLI ships in `cli/product.json` rather than extending it, so the image and video entries that exist only in the built-in file are kept out of a chat roster by their capability tags.
