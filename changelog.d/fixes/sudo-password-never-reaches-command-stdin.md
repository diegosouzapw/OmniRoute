- **Security (GHSA-cqwr-7mqw-chr9):** the MITM / Agent Bridge sudo helper wrote the operator's sudo password and the command's data to the same stdin. When sudo did not prompt (a `NOPASSWD` rule, or a credential still cached from an earlier sudo), `sudo -S tee -a /etc/hosts` appended the **sudo password to the world-readable `/etc/hosts`**. The password now goes only to `sudo -S -v` (validate, runs no command), and the elevated command runs as `sudo -n <cmd>` with only its own data on stdin; hosts that never cache credentials (`timestamp_timeout=0`) fall back to a single `sudo -S` call, where sudo is certain to consume the password line. Reported by @adevwithpurpose.
