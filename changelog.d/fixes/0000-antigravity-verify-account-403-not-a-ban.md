- **fix(providers):** A Google Cloud Code / Antigravity `403 VALIDATION_REQUIRED` ("Verify your account to continue") no longer permanently bans the connection — the phrase was in `ACCOUNT_DEACTIVATED_SIGNALS`, so a single transient occurrence parked a healthy, fully-quota'd account as `banned` (`permanent: true`, 1-year cooldown, never auto-recovers). Measured on a live deployment: one Antigravity connection returned 33 of these 403s inside 10 minutes and stayed `active`, while a sibling holding 100 % of its quota on all 17 windows was banned by exactly one — the only difference being which attempt happened to be served. The phrase now lives in a new non-terminal `ACCOUNT_VERIFICATION_REQUIRED_SIGNALS` table (`open-sse/services/errorClassifier.ts`, home of the 403 branch that consumes it) and classifies as recoverable `PROJECT_ROUTE_ERROR`, which also un-blocks the cloud-code project-route recovery added for Gemini Code Assist (#868, #6452) — it was unreachable for this wording because `accountDeactivated` is evaluated first. Genuine Antigravity ban wording (`this service has been disabled in this account for violation`) still terminalizes, and a body carrying both still bans.
