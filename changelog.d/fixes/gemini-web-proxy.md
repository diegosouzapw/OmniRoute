- **fix(providers):** `gemini-web` now opens its browser context through the proxy the request resolved to (per-key, connection, provider, combo or global, the one fetch-based providers use), and outside a request context through the provider or global proxy, as `claude-web` and `chatgpt-web` do through the browser pool. A request sent direct stays direct. A request whose proxy is an edge relay (vercel, deno, cloudflare), whether it comes from the request or from the provider or global setting, now fails with a 503 that says why, since Chromium cannot use a relay (`PROXY_FAIL_OPEN=true` keeps the direct load). A SOCKS5 proxy with a username and password now fails the request instead of loading Gemini directly, since Chromium has no SOCKS5 authentication. A proxy set only through `HTTP_PROXY`, `HTTPS_PROXY` or `ALL_PROXY` is still not passed to Chromium, as before. Its own Chromium lease ignored every proxy, so Gemini was always loaded directly and failed where `gemini.google.com` is blocked (#15076)
