- **fix(chat):** stop strict Anthropic-shape upstreams failing image/document requests with `500 "Non-base64 digit found"`. Some backends decode `source.data` strictly (Python `pybase64` with `validate=True`) and reject the whole request when the payload carries a data-URL prefix (`data:image/png;base64,....`) or line-wrapped whitespace — a request like that fails on every retry because the broken image stays in the conversation history. Adds `sanitizeBase64Sources()` (`open-sse/utils/base64SourceSanitize.ts`), invoked at the top of `handleChatCore` before any downstream stage (cache hash, translation, dispatch) sees the body: it strips a leading data-URL prefix and internal whitespace from `image`/`document` base64 sources in `messages[]`, including screenshots nested inside `tool_result` content arrays. Clean base64 is left byte-identical, so prompt-cache prefixes are undisturbed.
