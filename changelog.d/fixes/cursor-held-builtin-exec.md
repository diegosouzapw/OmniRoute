- **fix(cursor):** an agent harness no longer loops on the same step. When Cursor asked to run one of its built-in tools (Read / Shell / Write), OmniRoute bridged it to the declared client tool but told Cursor the exec had been **rejected** — so the model believed its own tool never ran and retried the same step on the next turn (reported as an agent re-reading a missing file forever). Those execs are now held open and answered with a typed success carrying the client's actual output (`ReadResult.success`, `ShellResult.success`, `WriteResult.success`), the way Cursor's own CLI does. Grep, Ls, Write and Fetch built-ins also gained bridges, and the decoder now keeps their arguments (`GrepArgs.pattern/path/glob`, `WriteArgs.file_text`) instead of dropping them.
