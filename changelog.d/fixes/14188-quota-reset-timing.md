- **fix(api):** API-key usage, budget, token, request-rate, provider-account and combo-exhaustion errors now expose the earliest known reset as structured `retry_after` seconds and an ISO `reset_at`, with the matching `Retry-After` header, so clients can tell users exactly how long to wait instead of reporting an opaque unavailable error; non-Anthropic usage-limit responses now use `429`, while Anthropic `/v1/messages` deliberately keeps `400` to avoid Claude Code misclassifying quota exhaustion as an authentication failure.
