- **fix(codex):** stop synthesizing a session/thread/turn identity envelope for Codex requests whose client never presented one. A request without Codex identity headers (OpenAI-compatible SDKs, non-Codex harnesses) previously received a fabricated `x-codex-turn-metadata` including a `sandbox:"none"` claim that no real Codex client emits; the ChatGPT backend rejects tool-bearing turns on the newest models with `This request was blocked by our safety systems. Reason: Potentially unintended activity.` Session/full fingerprint convergence now applies only when the client already carries a Codex identity — an identity header or a body session (`prompt_cache_key` / `session_id` / `conversation_id`) — and the fabricated envelope fields are gone. Device-level installation identity is unchanged, and a client-supplied `x-codex-turn-metadata` is still merged rather than replaced.
