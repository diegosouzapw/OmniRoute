- **fix(images):** image combo success responses keep the full OpenAI Images envelope — `fetchImageEndpoint()` (open-sse/handlers/imageGeneration.ts) already normalized provider responses to `{ created, data: [...] }`, but the combo success path unwrapped the payload a second time and returned a **bare array** `[{"b64_json": …}]`, so every spec-compliant client (official OpenAI SDKs, the Hermes omniroute image plugin, anything reading `response.data`) rejected combo-generated images as "no image data" while raw `curl` worked — and dashboards that read `data?.data || []` silently showed nothing. The success path now returns the normalized envelope unchanged (the direct, non-combo route always did), with the image count still computed at the envelope level. Backport note: `release/v3.8.51` already normalized this via #12268; this fixes the `release/v3.8.50` line.
