- **fix(usage):** Non-streaming responses from every Claude-format provider now store the full prompt total, not only responses served under the `claude`/`anthropic`/`vertex*`/`anthropic-compatible*` ids ([#XXXXX](https://github.com/diegosouzapw/OmniRoute/pull/XXXXX)). Notable affected providers: kimi-coding, deepseek, xiaomi-mimo, zai, github (Claude through `/v1/messages`), poe, agentrouter, bailian-coding-plan, and opencode-go/opencode-zen models that target the Claude format. Anthropic `usage.input_tokens` excludes prompt-cache reads and writes. Those bodies fell through to the Responses API branch of the usage extractor, which stored `input_tokens` alone next to the cache counters. The cost calculator then subtracted the cache from an input that never contained it, so fresh input tokens were billed at $0 and stored input did not match the streaming path. The extractor now recognises an Anthropic Messages body (`type: "message"`) by its shape and stores input + cache read + cache creation, as the streaming path already did. Semantic-cache replays of OpenAI answers cached for Claude clients also recover their full prompt total. Providers that report no cache counters (e.g. devin-cli-agentic) keep them as N/A instead of 0. Responses API usage (whose `input_tokens` already includes the cache), OpenAI chat and Gemini usage are unchanged.
