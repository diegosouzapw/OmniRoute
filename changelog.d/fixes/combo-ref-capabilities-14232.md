- **fix(api):** `/v1/combos` (and the VS Code import surfaces) now compute combo capabilities from the combo's actual resolved targets — combo-ref steps expand through `resolveNestedComboTargets`, the same resolver the routing runtime and `/v1/models` use, so a nested combo whose leaves are all vision-capable advertises `capabilities.multimodal: true` instead of a hardcoded `false` that contradicted `/v1/models` for the same combo ([#14232](https://github.com/diegosouzapw/OmniRoute/issues/14232)). Unresolvable refs (dangling names, cycles) and callers that don't pass the collection keep the previous conservative `false`.
