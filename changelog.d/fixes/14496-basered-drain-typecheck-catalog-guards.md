The preview now goes through the same lossy-request policy as the runtime, so it shows what an ordinary request actually runs.
- **CLIProxyAPI account health (regression from #14544):** with only `CLIPROXYAPI_MANAGEMENT_KEY` set, the health probe targeted `http://undefined:<port>` and reported a correctly configured local CLIProxyAPI as unreachable (also the `typecheck:core` TS2322 on the release tip). It now falls back to the documented `127.0.0.1`.
