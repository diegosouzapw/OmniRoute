- **fix(compression):** RTK no longer drops diagnostic lines at truncation because of three disagreeing severity vocabularies. The engine hard cap (`index.ts::defaultPriorityPatterns`), the filter priority set built from `preserve.errorPatterns` / `preserve.summaryPatterns`, and `rawOutput.ts::isLikelyFailureOutput` each carried its own word list, and the keep stage fed by `rules.includePatterns` truncated before any priority pattern was consulted — so a `2026-09-20 12:07:04 FATAL deployment aborted - rollback required` line was classified as failure output worth retaining while the compressed body dropped it, and a bare `TS2345` line was protected by the filter layer but not by the engine. They now derive from one shared vocabulary (`engines/rtk/severityVocabulary.ts`, 23 words), and diagnostic lines bypass the keep stage without populating a filter's EMPTY `includePatterns` (which would switch the stage on and newly drop every non-severity line). Measured through `processRtkText` at the live `maxCharsPerResult` on ~250-char lines: 0/55 builtin filters kept all eight severity words before, 55/55 after. Token impact is neutral — same output length, only _which_ lines survive. Reported in [#14648](https://github.com/diegosouzapw/OmniRoute/issues/14648).
