- **fix(compression):** stop the CCR engine (and the session-dedup fuzzy pass) replacing prompt content with `[CCR retrieve hash=…]` markers for callers that can never resolve them. The retrieve tool is only exposed through OmniRoute's own MCP server, so every plain OpenAI-compatible/Anthropic caller (GLM provider, OpenCode, Claude Code in openai-compatible mode) received a context of markers and 200-char preambles and answered as if the conversation were empty — while codex requests were unaffected because native Responses passthrough bypasses compression entirely. `ccrEngine.apply` now returns the body unchanged unless the caller advertises `omniroute_ccr_retrieve` in `tools[]`, and the session-dedup fuzzy pass is gated the same way; the #7746 200-char preamble band-aid is superseded (it still discarded all but the first 200 chars of real agent prompts, whose task sits at the end). The compression studio preview route accepts an optional `tools[]` passthrough so MCP-capable configurations can still preview marker output, and the benchmark harness advertises the tool so engine benchmarks keep measuring the replacement mechanics.
